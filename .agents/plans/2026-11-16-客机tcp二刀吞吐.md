# 客机 TCP 二刀吞吐:发送窗消费、多段在途与 RPC 多段化(设计)

Type: plan
Status: done
Updated: 2026-11-16

一句话说明:承 [首刀](2026-11-15-客机tcp深研首刀.md)(入站大段容忍)与 [NET-01](../../research/NET-01-客机TCP栈深研与裁决-v1.0.md)/[NET-02](../../research/NET-02-客机TCP首刀落地与对抗复验-v1.0.md) 的三合取裁决,本设计波定二刀的全部几何与语义:TCP_DATA_MAX 128→250(inline 帽下的域顶,非 255)、MSS 维持 128(dlen u8 硬顶下单抬空转)、在途环 TX_SLOTS=4 定槽 + Go-Back-N 最小正确重传 + 对端窗口记账、收窗通告不联动;吞吐模型自算上限 250B/RTT≈0.5-2.1KB/s,10KB/s 域修正为需后续 op 间流水线(四刀)。

## 背景

十四波实测(全证据见 NET-01/NET-02,此处只列设计输入):停等吞吐客户端 486/469 B/s(4KB/16KB 对拍,rtt 124-470ms/107-497ms,每 op 均值 263/273ms)、服务端 echo 309 B/s;上限来自协议模型(MSS=128 + in-flight=1 + 每 op 恰一段 + 串行 RPC)。首刀已解除入站大段黑洞(RX_SEG_MAX=1460/Sess.rx 2048/IOB 1600/准入宁拒不腐化),发送面零改动。本波三合取:①发送窗消费;②in-flight>1(多段在途+队列重传+部分 ACK);③RPC 多段化(op 对外语义不变)。

设计波两个新一手事实(本波核出,净面工作树现刻锚点):

- **通道 inline 帽是 dlen 的真域顶**:chanface `CHAN_MSG_MAX=256`(chanface/src/lib.rs L46,单一事实源,kernel channel.rs 消费);ROUNDTRIP 会话形请求 = `[op][dlen][data][sid u32]` = 2+dlen+4B(berry-netdproto encode L436-439 + append_session L488-496),恰满 256 ⇒ **dlen ≤ 250**;vnet serve 请求缓冲 `[0u8; 256]`(main.rs L852)同帽。probe 推演的「dlen u8 域顶 255」在通道几何下不成立。
- **vnet 侧数据段重传现刻 = trap 而非真重发**:berry-tcp 零拷约(Action::Data{seq,len} 调用方持字节),而 vnet 两处 RTO 到期路径 step L362-364 与 pump_timers L696-698 均 `act(ev.action, &[])`,act Data 臂「data.len() != len 即 trap」(tcp.rs L455-459)——SLIRP 即时 ACK 域结构性不触发(NET-01 界),harness h02/h14 证的是状态机层;in-flight>1 落地前必须补重传载荷源,否则多段窗下丢一段 = trap 服务死。

## 裁决

### 1. MSS 取值:维持 128,「抬升」改判落 TCP_DATA_MAX

- 几何域:dlen 单字节编码(netdproto encode L229/L297 as u8)⇒ 每 op 载荷 ≤255;inline 帽再压到 250(见背景)。串行 RPC 下吞吐 = 每 op 载荷/RTT,与分段数无关——**MSS ≥ 250 使 ROUNDTRIP 退回一段/op**(in-flight>1 在链上结构性不可达),MSS ∈ [128,250) 段数同为 2(ceil(250/128)=2)吞吐无差,MSS < 128 只增段数与 40B/段头开销。抬 MSS 到 536/1460 在 250B op 域零吞吐收益,反吃 vnet 栈预算(SEG_BUF_SZ/scratch 随动)。
- 结论:**bt::MSS=128 不动**(tests/state.rs L476 钉板随之不动);三合取第③条的「抬升」对象改判为 `TCP_DATA_MAX` 128→**250**(dlen 域内取满 inline 几何:会话形 2+250+4=256 恰满,零浪费)。MSS 真抬升(op 载荷基数 >250 的流水线波)记边界。
- 连带:vnet tcp.rs L89 交汇断言 `TCP_DATA_MAX == bt::MSS` 换锚为**双向几何钉**(见点位表 P4)——单侧抬 MSS 或单侧缩环即编译期炸响(A-4 const assert 同族)。

### 2. 在途窗上限 N 与结构:TX_SLOTS=4 定槽环,TxSlot 三形统一,载荷暂存归 vnet

- **结构**:berry-tcp `Conn` 内 `[Option<TxSlot>; TX_SLOTS] + head/len` 定槽 FIFO(AcceptQueue L451-503 同款家法;GenericArray 仓内零使用,零依赖纪律);`TxSlot = {seq: u32, kind: Syn|Data{len: u32}|Fin}` 三形统一替换现 InFlight 单槽(L118-126)——SYN/SYN-ACK/FIN/数据同环排队,close 不再覆盖在途数据(见裁决 3)。Conn 36B→约 104B(+68B/conn;部署面 8 表槽+session-0+AcceptQueue 2 ≈ 11 份 ≈ +750B 静态,可忽略)。
- **N=4 定值**:一段 op 需 ceil(250/128)=2 槽,+FIN 排队 1 槽,+余量 1 ⇒ 4;环容量 4×128=512 ≥ TCP_DATA_MAX(机器钉)。流水线波 K op 需 2K 槽,届时重开几何。
- **重传载荷源(本刀核心正确性件)**:vnet `Sess` 增 `tx: [u8; TCP_DATA_MAX] + tx_len + tx_seq0` 暂存——op 首段发送时整批拷入(≤250B,拷贝成本相对 8KB 帧可忽略),重发按 `(seq − tx_seq0, len)` 切片组帧;berry-tcp 维持零拷约纯状态机。替代案否决:berry-tcp 内置载荷环(破「状态机不持数据」分层);引用调用方缓冲(pump_timers 全表泵无调用方上下文,结构性不可行);复用 Sess.rx 保守存(DRAIN 先于 echo ACK 释字节,时序耦合腐化面)。静态成本 8 槽+session-0 ≈ 9×250B ≈ +2.3KB .bss,表 17KB 面可忽略。
- **vnet 单臂 Arm 结构保留**:臂语义升级为「覆盖全环最晚段尾」——act 每个 Syn/Data/Fin 出段即重挂 `Arm{end: 段尾, deadline: now+rto_ms(backoff)}`,部分 ACK 不清臂只缩不改(snd_una 推进后 arm_settled 判全环清);RTO 到期重发队头后按 backoff+1 重挂。按段臂集/按段退避否决(单臂+GBN 队头语义下冗余,真网卡域再议)。

### 3. 重传语义:Go-Back-N 最小正确实现

- **RTO 到期**:重发**队头最老未确认段**(snd_una 起)+ backoff+1(到帽 3 转Closed 清环,语义同今);后续段不随发——各自到期各自重发,接收侧乱序丢弃+当前 ACK 语义兜底正确性。整窗重发否决(丢段域 SLIRP 结构性不触发,风暴面无收益)。
- **部分 ACK**:ACK 覆盖段尾的槽从环头弹出(straddling 段保槽整段重发,h14 语义不变);跨段覆盖一次弹多头;有任何覆盖进度(snd_una 推进)即 backoff 归零。RTO 时钟不因部分 ACK 重启(可能略早重发队头 = 无害重复段,接收侧丢弃)。
- **close 排队**:数据在途直接 close → FIN **排队尾**(不再覆盖单槽——lib.rs L242-243 注释与 vnet main.rs L1183-1186 注释同批改写;tests/state.rs close_overrides_data_inflight L452-471 改义钉板,见测试矩阵)。TIMEOUT 后 CLOSE 收口路径同样受益(FIN 排在未确认数据后,挥手四帧语义不变)。
- **快重传(dup-ACK 计数)不做**:乱序/准入拒已回 dup-ACK(信号在),但 SLIRP 即时 ACK 域结构性积不起三连;RTO 3s 队头重发已保正确,计数收益域=真网卡,与 RTT 自适应 RTO 同批重开(边界)。
- **重发载荷接线**:act Data 臂改双面——初次发送(调用方 data 非空,len 恰等)拷入暂存再组帧;重发(data 空)按 (seq−tx_seq0) 切暂存组帧,越界/无暂存 trap loud 保留。step L362-364 与 pump_timers L696-698 两处 RTO 路径由此获得真载荷。

### 4. 收窗通告:不联动,维持定值 512

- 通告几何零改动:WINDOW=512 恒通告(send_seg L156 encode_tcp 硬引 bt::WINDOW),实际收缓冲 2048 首刀已解耦——低通告安全(欠通告无害),SLIRP 按 512 限对端在途(NET-02 实证)与本波 250B/op 几何无冲突。
- 联动(动态通告 = RX_SESS_BUF−rx_len)是流水线波前置:K×250 > 512 即 K ≥ 3 时 SLIRP 将按旧通告节流——记边界,本波不动零回归面最小。
- **发送窗消费(①的落点)与通告无关**:`Conn.snd_wnd: u16` 记账对端通告——握手 SYN-ACK/第三步 ACK 及此后一切携 ACK 段(on_seg_open ①)更新 snd_wnd = seg.window;send 门控「在途(snd_nxt−snd_una)+ 新段 ≤ snd_wnd」,零窗即拒(零窗停发);持续零窗无探针,窗更新 ACK(纯 ACK 亦走①)解锁,丢失 = 相位帽 TIMEOUT(v1 已知限制,SLIRP 大窗域结构性不触发)。h06「零窗照发」毛刺由此关闭。

## op 契约不变式(八 op 对外语义红线)

1. 八 op 集合、请求/应答字节形状、恰长执法、尾随 session 编码、v1 session-0 字节逐字节相同、烘焙线(非 OK 恒不携 data/sid/addr)——**零改动**。
2. 唯一变量:TCP_DATA_MAX 容量定值 128→250(接受域 1..=250)。互操作矩阵:旧客户端(≤128)对新服务端逐字节不变;新客户端 dlen ∈ 129..=250 对旧服务端 = parse 拒 → ST_BAD(树内双侧同批锁步,无混布面)。
3. ROUNDTRIP 语义「发一段收等长回显」细化「发一批(≤250B,TCP 层内部分段)收等长回显」——分段对 RPC 面透明,回显仍严格等长,对拍归 client 不变。
4. inline 帽 256 是硬界:一切帧形(含会话形 256 恰满)≤ CHAN_MSG_MAX,P2 机器钉——抬 TCP_DATA_MAX 的唯一后续路径是先抬通道帽(kernel 面,非本波属地)。

## 吞吐推演(设计自算,口径=十四波实测分布)

模型:串行 RPC 下吞吐 = O/RTT_eff,O = min(N×M, 每 op 载荷 P);RTT_eff 取十四波逐 op 实测(已含 TCG 泵开销):4KB 趟 [124..470]ms 均值 263ms、16KB 趟 [107..497]ms 均值 273ms。模型校验:今 P=128 ⇒ 487 B/s@263ms,与实测 486/469 吻合(误差 <4%)。

| 配置 | 在途 O | @124ms | @263ms | @470ms |
|---|---|---|---|---|
| 今(N=1×M=128,P=128) | 128B | 1032 | 487(实测 486) | 272 |
| 本波(N=4×M=128,P=250) | 250B | 2016 | **951** | 532 |
| 流水线 K=4(四刀) | 1000B | 8065 | 3802 | 2128 |
| 流水线 K=11(四刀) | 2750B | 22177 | 10456 | 5851 |

- **本波预期**:客户端 4KB = 17 op × ~263ms ≈ 4.5s ⇒ ~910 B/s 量级(全域 532-2016 随 RTT 分布);服务端 echo 309→~600 B/s 量级(RPC 次数减半)。N=4 对串行吞吐无贡献(P 才是杠杆)——N 是能力面与 FIN 排队余量,此为设计与「抬 N 提速」直觉的显式分界。
- **10KB/s 域修正(NET-01 §5.1-1 量级结论)**:三合取上限 = 250/RTT ≈ 0.5-2.1KB/s——VNC 10KB/s(@10fps)需 K ≥ 11@263ms(K ≥ 5@124ms),30KB/s 需 K ≥ 32;且 K ≥ 3 即撞 WINDOW=512 通告节流(收窗联动成前置)。故「三刀合取进 10KB/s 域」修正为「三合取进 KB/s 域,10KB/s 域需四刀 op 间流水线 + 通告窗联动 + 环扩(N≥2K)」。
- 口径:TCG 多会话重载,数字为量级证据非基准成绩(NET-01 口径沿用);对拍必须同 fixture 同时段基线趟+本波趟取比值。

## 边界

- 工具边界承 NET-01:段级丢/乱/重/迟对 guest↔SLIRP 半段结构性不可注入——GBN/部分 ACK 的段级对抗只在宿主 harness 域,客机对抗面限于应用层字节几何。
- 快重传(dup-ACK 计数)与按段退避不做;RTT 自适应 RTO 不做(恒 3s×2 退避)——收益域=真网卡,届时同批重开。
- 乱序重组不做(SLIRP 代理域已重组字节流);序号回绕 plain 比较、未来 ACK 越界接受维持已知限制(NET-01 清单)。
- 持续零窗无探针:窗更新丢失 = 相位帽 TIMEOUT;SLIRP 大窗域结构性不触发。
- 收窗通告不联动(恒 512):K ≥ 3 流水线时成节流前置,四刀联动。
- op 间流水线(libc 面改形)不做——10KB/s 域的唯一剩余路径,连同通告窗抬升、N ≥ 2K 环扩、通道帽抬升评估(kernel 属地)归四刀。
- 服务面三项(泵节奏/槽空闲超时/请求序号)不进本刀(NET-01 §5.1-3,三刀)。
- 栈预算无实测数据:增量 = serve 局部 Sess +~256B、调用链 scratch +~370B、step pbuf 1460 已在用——boot 冒烟+全链标记复核兜底;爆栈预案 = session-0 tx 暂存移表侧静态专槽(不进栈),记偏差启用。

## 偏差

- 波任务书三合取③「MSS 抬升」裁决为不抬:dlen u8 + inline 帽 256(会话形 2+dlen+4 ≤ 256)双硬顶下,MSS ≥ 250 退化为单段/op 且零吞吐收益——抬升对象改判 TCP_DATA_MAX 128→250(恰满 inline 几何)。此为对三合取第③条的再诠释,证据=CHAN_MSG_MAX 单源与会话形帧长派生。
