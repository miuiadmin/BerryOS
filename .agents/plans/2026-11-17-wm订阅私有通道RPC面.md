# wm 订阅私有通道 RPC 面（guifbd 表跟随的正拓扑）

Type: plan
Status: done
Updated: 2026-11-18

一句话说明：批B 对抗审查 CONFIRMED 共享 wm 客户端队列双消费者应答互截（dup(WMD_CLI_DUP) 使 guifbd 与 launcher/gfxdemo/[ui] apps 同端点单 FIFO，无相关性 ID）后 wm 面收线的持久修复刀——让订阅者的私有通道承载 TABLE_GET 请求应答，恢复 wmd「单 wm 客户端串行」设计前提，guifbd 表跟随由此复活；因果见[批B 实施笔记](../notes/implemented/2026-11-17-波3批B-guifbd带合成v1与wm面收线.md)。

## 1. 问题与约束

现树 wmd 应答面 = 单条 wm_srv 队列：一切 wm 域请求（CREATE/SET/TABLE_GET/中继 present/hdi ack）按处理序落同一客户端接收队列，先 recv 者得、无请求号。两路实证：

- 批B 对抗审查 CONFIRMED（架构推演）：曾以 svcmgr 交接 dup(WMD_CLI_DUP) 给 guifbd 作第二消费者——在途 recv 弹走他客户端应答（携 handle 应答撞 null 出参窗 = EINVAL 误判通道死）且孤儿快照毒化后续 RPC；guest 侧无耐受修法（通道无 unread/push-back，消费即毒化）。
- **批B QEMU 验证实抓（既有缺陷，与 guifbd 无关）**：gui8 Boot A 点击 spawn 的 APPDEMO 打 `appdemo: wm getinfo rep bad st=0` 后 park——其 GETINFO（期望 12B rep）吞到 launcher 点击重绘时经中继的 SUBMIT ack（8B 形 st=0）；send 侧唤醒纯广播无按等待者路由（kernel syscall.rs），launcher 与 spawn 应用并发阻塞 recv 于同一 ChannelEnd 即互截。即：**现树任何点击拉起的应用都可能随机吞错首应答而 park**（时序彩票，TCG 下几乎必中）。gui8 既有三元组门（CLICK/LAYOUTW/APPDEMO up）不含 app 帧证据，故此破长期不可见。

约束：gui-wmd 与 berry-guiproto wire 均冻结面（本刀须 owner 开 gui-wmd 面；wire 零改——TABLE_GET req 4B 与快照 rep 编解码已在库）。TABLE_WAIT 冻结律不动（表跟随仍走通知+拉取）。

## 2. 方案骨架

1. wmd `subscribe()`（table.rs:530-547）建订阅对时，订阅者通道升格为其**完整 RPC 面**：sweep_evt（现 drains-and-ignores 订阅者帧，table.rs:552-571 附近）识别 TABLE_GET req 后在订阅者通道应答快照（复用现 encode 面）。
2. 初始 SUBSCRIBE 仍经共享 wm_srv 发出——由 svcmgr 在 wmd arm 后、任何他客户端 arm 前的静默窗代发（svcmgr 现不 RPC wmd；时序先例 = gfxdemo 阻塞 reap 先于 launcher arm 的既有串行化，svcmgr gfxdemo arm 注〔F122 后现场约 :1501〕）。ack 随行订阅端 handle 经 fbx 交接对投 guifbd（批B 已撤的 'm' 形态复活，通道语义变为纯私有）。
3. guifbd 重建 wm 面：WmFace 接 evt/rpc 合一私有端（Active/Disabled 两态即可——无共享队列即无互截面）；WM_EVT_TABLE 通知驱动 TABLE_GET 异步拉表（死锁红线不变：SUBMIT/COMMIT 处理路径内零 wm 通道操作）；快照真值接入 classify/plan_bands——WinBand/WinApp/Hidden 三档激活、顶带入带集。
4. WMSUB 标记可随面复活（恰一次 latch，gui8/smoke-image 门同批恢复）。
