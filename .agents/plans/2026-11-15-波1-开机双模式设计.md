- 实施地点 = worktree `.dsh-worktrees/boot-events/`（wip/boot-events-knife6），主树单次 merge 收口——六波方案步骤 2 既定。
- 模式开关：图形模式为默认形态；verbose 相 = fbinfo 第 6 域 gui_mode 的既有双档投影（内核 mirror 滚屏至 splash::detach ＋ guifbd poll_console 剥 `\x01` 续滚至 `LAUNCH ok` 停绘），切换入口挂 berry CLI `--boot-mode`（刀1 入口统一下既有条目）。bootparams 键（boot.splash）不新增：现役 bootparams 词表两键（sched_slice_hz/intent_default）为内核消费面，双模式属用户态视觉面，走 fbinfo/gui_mode 既有链即达，不占内核词表。
- 内核热路径禁插值判例（7fd1709c）保持：本文全部算法只活 guifbd serve 循环；内核 splash 相语义零改动（刀6 §内核侧）。

## §1 Logo：BerryOS 词标生成链

**视觉裁决**：黑底白色「BerryOS」词标，HD 字模原生渲染（非 8×16 蜂格放大）——owner 原话「Logo=BerryOS 字母大一点」，词标高度取屏高约 1/9（1080×1920 档 ≈ 214px，字模 32×48 按整数倍近似缩放），纵向中心落在屏高 2/5（刀6 几何口径 ly=h*2/5 的延续），水平居中。白 #FFFFFF、无描边无阴影——与胶囊条同色系，构成 macOS 式「白件 on 黑」单色调。

**生成链**：新增 `tools/gensplashlogo.py` 烘词标行 RLE 段表，一次烘焙双产物：

- `kernel/src/splash_logo.rs`：内核 splash 相消费（rescue/ux-splash 形态合入后的绘制面）。
- `user/berry-gfx/src/splash_logo_data.rs`：guifbd 过渡屏消费（过渡屏自绘直写 FB_VA，不经 berry-ui 树——过渡屏期无 damage/blit 面，刀6 §guifbd 侧既定）。

字源 = berry-gfx 既有 HD 字模（`user/berry-gfx/src/font_data_hd.rs`，Noto Sans CJK SC 32×48，ASCII 32..126）取「BerryOS」七字符拼排；RLE 行段表（每行 `[(x_start, run_len); …]` 白段序列）产物定容、零运行时分配。两产物头部互钉黄金 SHA256（同字源双消费防漂移——`hdfont` 黄金 selftest 先例，挂 `just test-host`）。

**不作**：位图 PNG/asset 文件（rootfs 不加条目）、矢量字库运行时光栅化（boot 期无堆分配纪律）、berry-ui Text 节点（过渡屏不经 UI 树）。

## §2 胶囊条：行 LUT 两端半圆绘制

**视觉裁决**：macOS 风白色长椭圆形加载条（非矩形）——全宽 7/10（刀6 几何 bar_w=w*7/10 延续），高 `bar_h = max(h/150, 12)`（1080×1920 档 = 14px；800×600 档 = 12px 下限），y = h*2/3，水平居中；槽色 `#2A2A2E`、填充纯白——刀6 §guifbd 侧 TRACK 色延续，六波方案既定参数，本文不改。

**绘制面**：行宽 LUT（per-row span table）两端半圆——半径 r = bar_h/2，对每行 dy ∈ [0, bar_h) 预计算两端半圆内缩 `inset(dy) = r - ceil(sqrt(r² - (dy - r + 0.5)²))`，存 `[u8; bar_h_max]` 两张同值 LUT（左端右端对称共用一张）。每行绘制 = 中段整行填充 ＋ 两端按 inset 收窄：

- 槽：`fill(x0+inset, y, w_bar-2*inset)` 槽色。
- 填充：`fill(x0+inset, y, w_fill-2*inset_dy)` 白色，w_fill = w_bar * P_disp / 1000；当 w_fill < 2*inset(dy) 时该行按 max(0, …) 收零（进度极低时胶囊头从中间行先长出，两端行后到——与 macOS 观感一致的圆头生长）。

LUT 在 guifbd 启动期按实际 bar_h 一次算妥（≤ 32 项、u8、栈上），零逐像素圆方程、零浮点（sqrt 在启动期一次性用整数牛顿法或查表）；bar_h 档位 > 32 的未来分辨率升 LUT 帽（现在 1080 档 14px，帽 32 覆盖到 4800px 屏高）。局部重绘纪律：每拍只写条区行段 ＋ 百分比格（§3），不整屏重画（刀6「本相位独占屏幕」但波1 条区局部重绘 = 六波方案明文「只写条区」）。

**百分比文本**：fbcon 8×16 文本 `<pct>%` 置条下（pct = P_disp/10），HD 字模共享化挂账照旧（刀6 已知边界三），不因本文升格。

## §3 平缓算法：事件刻度 + 一阶惯性追逐 + 补满揭幕

三层混合承 XNU 形态（[Apple 调研](../research/2026-11-14-apple启动视觉双模式调研.md)：固件事件为主刻度 + 内核时间蠕动平滑 + 用户态真实事件接管），BerryOS 落位：

**第一层：真实事件为主刻度。** 26 格词汇表（刀6 唯一权威）逐格映射目标值：`P_tgt = min(cell * 1000 / 26, 961)`（千分制，26 格满 = 1000，但事件面封顶 96.1%——末 3.9% 留给桌面揭幕，对齐调研裁决「90% 封顶 + launcher drawn 直接揭幕防卡 99%」，WebKit 终值 0.9 封顶同构）。事件行到达即更新 P_tgt，永不回退（接受 cell > 当前才更新——刀6 clamp 天然 never-decrement）。

**第二层：时间蠕动平滑。** 显示值 P_disp 对 P_tgt 做一阶惯性追逐（低通滤波）：

```text
每拍：P_disp += (P_tgt - P_disp) * dt / TAU   （整数近似，截断误差向下取整）
```

- `TAU = 600ms`（六波方案既定；事件间隔典型数百 ms，600ms 惰性使条在两事件间平滑爬升、事件突发时不过冲）。
- `dt` = 距上拍墙钟差（berry_clock_read MONOTONIC）；整数近似取 `step = (P_tgt - P_disp) * dt / TAU`（u32 算术），`step == 0 且 P_disp < P_tgt` 时补 1（防整数截断卡死在渐近尾）。
- **单调不减**：P_disp 只升不降（结构保证：P_tgt 单调 + 追逐增量恒非负）。
- 重绘节拍 `≥ 66ms`（15fps 下限）：serve 循环 deadline 的 vsync min 臂天然分频，超速拍跳过绘制只推进 P_disp。
- 平滑只活 guifbd（7fd1709c 判例：内核热路径禁插值——内核 splash 格制仍逐格跳变，guifbd 过渡屏接手后平滑；交接角 = guifbd 首帧 seed = 7 格，刀6 既定静态契约）。

**第三层：用户态接管收尾（flicker-free 揭幕）。** 解析到 `desktop-tree`（格 25，P_tgt 顶 961）置 armed；armed 后首个 present SUBMIT 在既有 blit **前**先补满帧（P_disp = 1000，画满格胶囊）再 blit——满格帧先画后揭、同一 handler 内至少可见一个刷新周期，桌面首帧直接覆盖 = flicker-free（Android `service.bootanim.exit` 补满判例 + XNU IOProgressBackbuffer 快照交接的对齐：BerryOS 无背缓冲快照需求，blit 本身零协议、覆盖即交接）。`LAUNCH ok` 行到达即置 done 兜底（desktop-tree 行被 fb pipe 丢弃时，splash 形条停 96.1% 由 blit 覆盖无害；verbose 形靠它停绘防滚日志盖桌面——刀6 既定）。

**验证向量（host 单测挂 guifbd lib 纯函数面）**：事件推进（cell→P_tgt 映射表全 26 值）、时间平滑（固定 dt 序列的 P_disp 轨迹单调不减、收敛到 P_tgt）、满仓判定（armed→补满→1000）、封顶（P_tgt 恒 ≤ 961）；LUT 对称性（inset(dy) == inset(bar_h-1-dy)）与收窄合法性（inset ≤ r）。
