## 背景

三路分析产物综合：A1（berry-gfx 光栅化管线 alpha 能力定谳）、A2（guifbd 合成器层叠架构定谳）、A3（[Android 12 edge-to-edge 机制调研](../research/2026-11-17-Android12-edge-to-edge系统栏机制调研.md)）。三路结论高度互洽，唯一实质分歧在「透明像素是否导致整个 IconFace 不渲染」——A1 判定管线无罪，A2/A3 引用 [2026-11-16 三件套笔记](../notes/implemented/2026-11-16-桌面沉浸化三件套.md)的实测记录主张需复测定位。本裁决对该分歧做了代码直核（下节），其余关键行号均已逐处验证。架构基线 = [波3 桌面三栏与系统窗实施设计](2026-11-15-波3桌面三栏与系统窗实施设计.md)（Status: active，§4 带合成设计与 §8 未完成清单是本裁决②档二的直接依据）。

## 定谳：透明管线能力（三路分歧的裁决）

**裁决：2026-11-16 笔记「客机管线无 alpha 合成，透明像素使整个 IconFace 不渲染」是误判——管线无罪，真因在资产生产路径。** 证据链（本日代码直核）：

1. `argb_blit` 是逐像素 1-bit 透明键：`p >> 24 != 0` 才写、A==0 跳过（`user/berry-gfx/src/raster.rs:452-458`），代码中不存在任何「面内含透明像素则整面拒绝」的逻辑；`scaled_argb_blit` 同律（raster.rs:499-505）。
2. 现网双先例直接反证「整面不渲染」：状态栏 `SIGNAL_PX` 是全透明底 + 白图形的静态面（`user/berry-appshell/src/status_icons.rs:6` 起），现网正常浮于壁纸；`nav_face` 圆角外 A==0（`user/berry-appshell/src/icons.rs:440-455`），现网导航键圆角生效——圆角外穿透到的是 Rect 底块的深青黑而非壁纸，恰恰证明透明在工作、挡路的是底块。
3. 当时「实测图标整体消失」的真因可在同篇笔记内自证：记录写明「OH SVG 的 Sketch 嵌套结构（defs/mask/use）经 resvg 光栅化 + alpha 阈值后大面积坍缩白块」，且 icons.rs:111-121 注释留痕「位图 id 被渲染面按 BYI1 解码（BadMagic [0,0,0,0] → 桌面死）」——静态库位图资产坍缩或位图 id 误入 BYI1 解码产生全 0 面，argb_blit 逐像素全跳过即表现为「整体消失」。**面数据全 0 与「管线不支持透明」是两件事。**
4. `smooth_argb_blit` 确有整像素阈值（四采样 alpha 加权 ≥128 才写，raster.rs:564），但该臂只在 `smooth_scale` 特例面触发，现网仅 `WALLPAPER` 一例（icons.rs:680-682）——导航键 66→96 缩放走 `ScaledArgb` 最近邻臂，不经阈值。

处置：三件套笔记按规范不改写（决策因果留档）；本篇为该争议的现行结论，后续工作以本篇为准。A2/A3 的「复测定位」诉求收缩为 P0 验收项（步骤 2）而非阻塞项——静态推理与现网先例已闭环，但 2026-11-16 实测未留像素锚日志，保留一次针对性复测以终局封案。

**现行管线 alpha 能力定谳表**（A1 结论全数验证采信）：FillRect/DrawLine/LoadOp::Clear 恒不透明；Argb/ScaledArgb = 1-bit 透明键（A==0 穿透、A!=0 全覆写、alpha 字节丢弃）；SmoothArgb = RGB 双线性但 alpha 二值化；BYI1 解码与 IconFace/ICON_DATA 数据面全程保留 A 位不消费。8-bit blend 全管线不存在，v1 铁律（cmd.rs:61-64「以新变体/字段演进，绝不挪用保留字节」）不变。

## 方案①：图标透明渲染（分层最小改动）

按「数据格式 → 光栅化 → paint 发射 → 资产建树」四层裁决，前三层零改动，唯一改动层在资产与建树侧：

| 层 | 位置 | 裁决 | 依据 |
|---|---|---|---|
| 数据格式 | BYI1 解码（berry-gfx/src/icon.rs:223-292）/ IconFace（berry-appshell/src/icons.rs:233-237）/ ICON_DATA 静态库（icon_data/mod.rs:11） | 零改动 | A 位全链透传：解码「ARGB 原样——A 位不消费不丢弃」，静态库本就是 &[u32] ARGB 直供（不经 BYI1） |
| 光栅化 | argb_blit / scaled_argb_blit / smooth_argb_blit（raster.rs:425-587） | 零改动 | 1-bit 键已工作（定谳节）；SmoothArgb 阈值不经由导航键路径 |
| paint 发射 | emit_image（berry-ui/src/paint.rs:1697-1747）/ submit 恰长门（queue.rs:92-111） | 零改动 | Argb 直发、缩放自动分档；恰长门只检 px.len()==w*h 不检 alpha |
| 资产建树 | NAV_BASE_BG / 按压 Rect 底块 / 测试钉板 | **唯一改动层** | 3 处 + 1 可选，见改动清单 P0-① |

要点：诉求①（白符号直浮壁纸）**不需要 8-bit blend**——底块透明后圆角内外都是 A==0 穿透壁纸，与状态栏图标同语义。armed 态（关机确认）保留不透明暗红作警示。按压反馈的替代先例 = `set_power_face` 换 Icon id（frameloop.rs:449-460，power 键已在用）；接受无反馈亦是一档，默认换面。glyph 1px 深描边（键影等价，亮壁纸对比度兜底）为可选项，实现在 nav_face 生成循环内，不引 scrim。

## 方案②：系统栏常驻与颜色跟随（两档）

### 档一：最小落地（常驻几何对齐，1-2 天量级）

- guifbd 裁带常量对齐现值：band (132, 190) → (117, 135)——顶部 15px 缝与底部 55px 壁纸色空隙同批消失（成因链：导航条实高 NAV_BAR_H_BIG=135，裁带停在旧值 190，应用帧被截在 y=1730 而 fb 残留区间 [1730,1785) 露壁纸）。
- 同批修 wmd SYSTEM 窗高像素域误用（39 是 vp 值，像素应为 117）。
- 防线：跨 crate 无共享 const 面，档一以注释互指 + 测试互钉防再漂移；几何真单源化归档二 inset 协议。
- 局限（明说）：带仍是 launcher 帧残留——不跟应用颜色（诉求②只解「常驻与空隙」半边）、launcher 挂则带冻结、多窗并发互踩依旧。这是止痛不是治病。

### 档二：完全正确（波3 §4 落地 + 三增补）

1. guifbd 带合成 v1：surface_id = wmd window_id 激活、wm 客户端订阅面（WM_EVENT_TABLE 通知驱动 TABLE_GET 异步拉快照，死锁红线照波3 §4）、SYSTEM/SERVICE 路 blit 双写带缓存（静态定容）、APP SUBMIT 后按 SERVICE>SYSTEM>APP 序重放 damage ∩ 带.rect——「常驻」由此成立（应用呈现后系统带必然盖回，launcher 挂了带也活）。
2. **增补一（本裁决对波3 批B 的唯一实质修正，采 A3 核心发现）：带缓存重放必须按 1-bit 透明键跳写（A==0 不写 fb）**——若按「带像素原样回拷」实现，透明系统栏的 0 像素会把应用内容涂黑；重放只在 glyph 处落笔 = 应用内容透出 = 「跟随应用颜色」以透明达成，与 ① 的资产形态闭环。
3. launcher 双窗化（波3 批C 原件）：状态栏/导航条各自 SYSTEM 窗、带 damage 提交；带内容瘦身为纯 glyph、背景 A==0。
4. 增补二：WM_GETINFO/TABLE_GET 扩四边 inset 域（add-only）+ appshell 消费（safe_top/safe_bottom）——应用可选避让或 edge-to-edge 画满自知留白；带 rect = wmd eff 几何快照，132/190/117/135/39 五值分叉归一（增补三 = 几何单源化）。
5. 对齐 Android 15 终点形态（A3 裁决采信）：不建时代 A 的「应用给系统栏上色」op——那是 Google 自己拆掉的过渡态；应用显式铺底需求由 inset 域 + 应用规范立法承载。
6. 边界（诚实）：仍是单 fb 轻合成，非 per-window surface 的 SurfaceFlinger 化——单全屏应用假设内正确，多 APP 窗 Z 序互踩是下一阶段命题；波3 §9 风险面（TABLE_WAIT 冻结、新鲜度窗口、「先并波1 再落波3」硬前置、128KiB 平像帽）照旧适用。

## 依赖关系与优先级

依赖链：① 零依赖（不碰协议、不碰 guifbd/wmd）可立即开工；②档一 零依赖可与①同批；②档二 前置 = ①（透明资产是透明带重放的前置）+ 波1 合并序 + 波3 §8 未完成件。①对②档二是资产前置关系，先行落地另有独立价值（桌面自身沉浸）。

- **P0（1-2 天量级）**：①全项 + ②档一 band 对齐，同批——两诉求「今天就能看见」的部分：白符号直浮壁纸 + 空隙消失。
- **P1（波3 收口量级）**：②档二——guifbd 带合成（批B）→ launcher 双窗化（批C）→ inset 协议面，重放跳写增补随批B 落。
  现状注记（2026-11-24，desktop 机真机验证，色值原始记录见[应用出窗诊断](../research/2026-11-24-应用点开不出窗与窗口自消失诊断.md)「导航带与状态带色值事实」节）：无空隙与导航键在应用之上已验证通过——BROWSER 窗开着时状态带 y 0..116 与导航带 y 1785..1919 的 12 个采样点全部与桌面基线逐像素相同，导航键白字形 `#f0f0f4` 在位（x=544、y=1852）；带背景仍是启动器壁纸色而非应用色（状态带 `#009ac3`…`#01beda`、导航带 `#006cc7`…`#0055c9`，内容区才是应用色 BROWSER `#f1f3f5` / SETTINGS `#000000`）——机制为 guifbd `band_geometry` big 档 (117, 135) 裁掉 app 帧的带区后从带缓存回放 launcher 像素，即档一「带仍是 launcher 帧残留、不跟应用颜色」的局限仍在，档二的「重放跳写 A==0」与批C 双窗化（带内容瘦身为纯 glyph、背景 A==0）尚未落地。
- **P2（对齐 Android 12 兜底）**：三键态轻 scrim 双档；图标明暗随内容（guifbd 采底带亮度 → set_props 换面，power armed 先例）。
- **明确不做**：WM_SET_NAV_COLOR 类 op（时代 A 过渡态，Android 15 已废）；predictive back、caption bar、cutout 专用协议面（insets 四边域已覆盖）。
