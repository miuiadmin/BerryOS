一句话说明:承 [NET-03 §6](../../research/NET-03-客机TCP二刀吞吐与对抗复验-v1.0.md) 四刀立项与 2026-11-16 probe 裁决(SLIRP 通告窗直测 65535 无 WScale,NET-03 §2「snd_wnd=128」实证被 wire 证伪),本设计定四刀全部几何与语义:真杠杆改判为客机内同步等待/唤醒量子栈,四拆同步落地——libc K=2 op 间流水线窗 + vnet serve 多 op 化/arm 门容量化 + netdproto 尾随 seq u8 请求配对 + tx_send 批量完成;WScale 降级入站面专属,环扩与通道帽记边界;验收线同窗交错 A/B ≥ 2.0× 且常态绝对 ≥ 1000 B/s(probe 模型 K=2 域 1000-4000 B/s)。

## 背景

2026-11-16 probe(/tmp/berry-adv/probe-W.pcap/probe-W-marks.pcap/probeW-serial.log,NET-04 素材待 owner 归档)重写物理基础,三钉:

- **拆闸序列与基线**:只拆 libc ≈ 0 增益(serve 单请求到底+arm 门拦截);libc+vnet serve/arm 同拆(K=2 恰满环 512B 无需扩环)→ per-op 塌到 1-2 唤醒量子 → 1000-4000 B/s 域;K ≥ 3 需环扩(750 > 512)。同窗实测(宿主 5 QEMU 负载,结构证据非基准):串行链 128B op rtt[223..367]ms thru=432 B/s、250B op rtt[393..622]ms thru=487 B/s(bad=0 close=OK)。

## 裁决

### 1. 真杠杆重排:量子栈四拆同步律

优先序改判(probe 证据):①op 间流水线仍居首但物理基础改写——不是窗/RTT 而是客机内同步等待/唤醒量子栈;⑤**新增 tx_send 批量完成入刀**(整环 poster 单次 poll)——不批量则每段一帧完成量子,K 窗收益被逐段串行等待吃掉,它是①的必要件兼串行路径即刻受益件;②WScale 对出站零杠杆(窗已 65535 无缩放)降级入站/服务面专属;③环扩降为 K≥3 前置;④通道帽与本瓶颈无关出局(留作 op 载荷 >250 的另一条路径,边界)。

四拆同步律(缺一即哑):**(a)** libc Client 臂 K 窗——issue/harvest 两相(K 个请求在途,应答按 seq 配对收割);**(b)** vnet serve 多 op 化——session-0 RT 臂改「入环即注册挂起 op、完成即应答」,命名 RT 臂改「入环即应答」(去 drive_until arm_idle),完成收割挂到泵;**(c)** arm 门容量化——`tx_inflight()!=0` 独占拒改环容量准入(空槽 < ceil(len/MSS) → ST_BUSY 背压,同 seq 重发);**(d)** tx_send 批量——整批帧单次页写/单门铃/单 poll。berry-tcp 零改动:环/GBN/窗机制二刀已在位,四拆全在其上;服务面借泵节奏最小面(挂起 op 在席时 idle wait 从 SVC_IDLE 10s 缩短 tick——三刀既挂账「泵节奏」的借用非交付,槽空闲超时仍不进)。

语义细化两处(可扩不可破):命名 RT ST_OK 细化「入环受纳,ACK 归泵收口」——应答字节形状/成功判据零漂移,仅时序提前(消费者可观察面不变);session-0 RT 应答判据不变(echo 齐 + 本 op ACK 到),变化仅在 K 窗重叠。

### 2. K 值:K=2,恰满现环

K=2 定值三几何:发送侧 2×250=500 ≤ 环容 TX_SLOTS×MSS=512(恰 4 段满环,零扩环);入站侧 echo 流 ≤ guest 自通告 WINDOW=512(K=2 恰在界内;K=3 即 750 > 512 双面撞——环扩+通告窗联动双前置,见边界);配对侧 seq u8 回绕 256 ≫ K=2 无歧义。稳态环占用 2-4 段振荡:op k+1 准入时 op k 已完成(应答 = echo 齐+ACK 到 → 槽已弹),BUSY 只在超时残留/防御面出现。K ≥ 3(环扩 TX_SLOTS=8)/K=4 记边界——3802 B/s(K=4@263ms 旧模型)只作静默窗天花板不作门。

### 3. 请求序号形态:u8 尾随旁路,RT 专属,请求/应答双面

**形态 = u8 尾随旁路**:请求 `[op][dlen][data][seq u8]`(session-0 RT 专属,≤ 3+250=253 ≤ CHAN_MSG_MAX 256);应答 `[st][dlen][data][seq]`(≤ 253)/`[st][seq]`(2B)。长度歧义消解同 session 尾随先例(v1 恰长优先,再试 +1 尾随):3+dlen 永不合法 v1 长(2+dlen' 需 dlen'>250 越帽被拒),歧义结构不存在。

**载荷域内嵌否决三由**:服务端面 seq 字节进回显流破 echo 逐字节契约;应用载荷契约污染(EVS/SKT 同源载荷将被改约);有效载荷 250→249 白损。旁路两胜:载荷域纯净(回显对拍零感知);服务端面流水线届时可平移(先解 257>256 几何,见边界)。

**值域与配对**:u8 全域 0..=255 滚动(回绕距 256 ≫ K);陈值判定 = 收割时 seq ∉ 在途集即弃——迟到/错配应答可辨可弃,wave10/14 双登记债在单客户端 K 窗面收窄清偿(dup 通道并发多消费者仍越界,见边界)。ST_BUSY 应答必携原 seq,客户端同 seq 退避重发(帽内)。超时收口双向:libc 侧 op 超时后其迟到应答按陈值弃;vnet 侧挂起 op 记录保留至 echo 收齐才弃置(流位对齐——迟到 echo 字节不致错位下一 op,对抗必测)。

### 4. netdproto 兼容面

八 op v1 字节形状零改动;无 seq 请求 → 无 seq 应答(bsh/advcli 等旧消费者零漂移——不发 seq 形则永不见 seq 应答);DNS/OPEN/CLOSE/LISTEN/ACCEPT/POLL/DRAIN 七面不携 seq(全八 op 中唯 RT 双面扩形)。互操作矩阵(树内锁步无混布):旧客户端(无 seq)对新服务端逐字节不变;新客户端 seq 形对旧服务端 = parse 拒 → ST_BAD(与二刀 TCP_DATA_MAX 129..=250 同款矩阵)。API 面:encode 侧新 `encode_rt_seq_request(out, data, seq)`(libc 专用),既有 `encode_tcp_s_request`/`encode_tcp_request` 签名零改动(bsh/vnet 既有调用零触碰);parse 侧 `parse_tcp_s_request` 扩 seq 出参(vnet 唯一请求消费点+测试跟随),应答 `encode_tcp_reply`/`parse_tcp_reply` 扩 seq 形——单源纪律:不出第二套恰长执法。几何钉扩族:`3+TCP_DATA_MAX ≤ CHAN_MSG_MAX`(253)与 `TCP_REP_MAX+1 ≤ CHAN_MSG_MAX`(253),超帽编译期炸;named RT 携 seq 的 257>256 几何阻死钉为单测(encode 收 seq+sid 形 = None)。

## op 契约不变式(八 op 对外语义红线)

1. 八 op 集合、v1 请求/应答字节形状、恰长执法、尾随 session 编码、v1 session-0 逐字节、烘焙线(非 OK 恒不携 data/sid/addr)——零改动;唯二扩面:RT 请求/应答各增 +1B 尾随 seq 形(长度歧义消解,裁决 3)与命名 RT ST_OK 语义细化(裁决 1)。
2. ROUNDTRIP「发一批(≤250B)收等长回显」不变——K 窗是 libc 实现面,每 op 应答仍严格等长携本 op 回显,对拍归 client 不变。
3. ST_BUSY 域扩为 RT 环容量背压码(既有码位,旧消费者按既有分诊面);ST_TIMEOUT 语义不变(帽到应答、会话保命、在途环残留唯 CLOSE 可收口)。
4. inline 帽 256 硬界保持:一切帧形(含 seq 形 253)≤ CHAN_MSG_MAX,P1 几何钉扩族机器钉。

## 吞吐模型与验收线(probe 模型定)

模型(probe 实测口径,宿主 5 QEMU 负载,结构证据非基准):串行链基线 128B op thru=432 B/s rtt[223..367]ms、250B op thru=487 B/s rtt[393..622]ms;相位拆解 = 每 op 墙钟 2-3 个同步等待/唤醒量子(tx_send 逐帧 1 + echo/ACK 泵收 1-2),wire RTT 0.12-0.3ms 可忽略。四拆后:批量 tx(整批单 poll)+ session-0 完成即应答(K 窗重叠 echo 等待)+ 命名臂入环即应答 → 每 2-op 批 ≈ 2-3 量子 → 500B/(0.12-0.75s) ≈ 700-4200 B/s,取常态域 1000-4000 B/s。验收线:客户端 4KB 同窗交错 A/B ≥ 2.0×(A=四刀链,B=同窗串行基线链)且常态绝对 ≥ 1000 B/s;16KB 比值同门;服务端 echo 16KB ≥ 1.5× 同窗(serve 改造模型 2× 域取下界)且零回归;绝对 2500 B/s 与静默窗 3802 B/s(K=4@263ms)只留档不作门。吞吐复测必须同窗交错对拍(NET-03 方法论,本窗负载数字只作结构证据)。

## 边界

- ②WScale/通告窗联动:降级入站/服务面专属(guest 自通告 512 是 K≥3 的 echo 流节流前置);本刀 K=2 恰在界内零触碰,通告几何不动。
- ③环扩(TX_SLOTS=8/K=4):不做——K=2 验收线足;K≥3 需环扩+通告窗联动双前置。④通道帽抬升评估(kernel 属地):与本瓶颈无关,留作 op 载荷 >250 的另一条路径。3802 B/s(K=4@263ms)只作静默窗天花板。
- 服务端面(named RT)流水线:不做——seq 请求形 257>256 几何受阻(取 dlen 249 或通道帽,届时再裁);本刀只收 serve 改造的串行收益(裁决 1 语义细化)。
- dup netd 通道并发多消费者:seq 使迟到/错配可检测可弃,但多客户端并发消费配对仍越界——wave10/14 已知债收窄非清偿。
- 槽空闲超时:三刀既挂账(NET-01 §5.1-3)不进本刀;量测规避=新鲜 boot+首连接形+连接间 settle(NET-03 §3 编排教训:rstopen 臂最后跑)。
- 工具边界承 NET-01:段级丢/乱/重/迟只宿主 harness 域可注入;客机对抗面限应用层字节几何+毒臂。
- fixture 纪律:kernel/rootfs 同树同源(混代=shell 槽 netd RPC 死);console 输入面死,驱动走 bsh 位直驱 auto 形;私有高位口自起自收,不碰 18080-18083。
