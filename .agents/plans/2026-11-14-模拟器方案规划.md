# 模拟器方案规划（QEMU 降级 / HVF 修通 / Apple VZ 产品窗口）

Type: plan
Status: active
Updated: 2026-11-14

一句话说明：模拟器分三层定位——QEMU+TCG 降级为 CI/regression 形态、QEMU+HVF 修通为日常验证主力（快 ~50×）、Apple Virtualization.framework（VZ）做产品级窗口与 GPU 加速显示；前置 §A149〔注：该判例现只在 sdk2-berryerr 未合线裔的雷册拷贝，树内雷册无此节——系统审计 2026-11-17 标注，合流后需改链〕 修刀与修窗五件先清。

## 背景

owner 2026-11-14 裁定：模拟器初始体验即 1080P 横屏不妥协、要用 GPU 加速、Mac 端先行、「启动就用我们自己的窗口」（不再开 QEMU 散窗）。同日实测链：

- TCG 形态 boot 分钟级 + 调度饿死（launcher bc0 面包屑都不达——098ca8bf 研究定谳：boot 演示常驻面永不退出 + tickless 机构被饿死；修窗五件：件 1（demo-face fw_cfg 门控）已落闭合（沿革 :6546）——2026-11-17 系统审计销账；余四件在册未落，见 `docs/阶段沿革.md`「调度优化轮三」节）。
- HVF 形态 `user_svcmgr_pager` 死于 I-abort@PC=0x106a8（自身代码段取指失败 = demand paging 页入失败）→ pager 死 → 内核 copy_to_user EL1 memcpy D-abort fatal——§A149 判例（sdk2-berryerr worktree `docs/雷册-判例库.md` §A149 在册：HVF EL1 写 EL0 用户页 permission fault，五级取证定谳非页表/PAN/TLB/表基，HVF 后端对该 desc 形态 EL1 写检查 UNPREDICTABLE 实然实现；取证臂存档 git stash `case6-diag-arms`）。
- 现役 gpu-1080p lane 已落 virtio-gpu 2D 显示加速 guest 半主体（B1-a/b/c：berry-gpuproto 协议 crate 冻结、guifbd 双后端 vgpu 主链 + ramfb 红线、ScanoutMap D-Bus 实证）——与 VZ 的 VZVirtioGraphicsDevice 协议同源，半成品直接对上。
- 外部先例：NetBSD 2025 走通 VZ `VZEFIBootLoader` → 标准BOOTAA64.EFI → ACPI 设备发现整链（无需 FDT）。

## 三层定位

| 层 | 形态 | 速度 | 角色 |
|---|---|---|---|
| L0 | QEMU+TCG | ~50× 慢 | CI/regression、ktest 全量执法形态 |
| L1 | QEMU+HVF | 接近原生 | 日常验证主力 |
| L2 | Apple VZ | 同 HVF 级 + 苹果设备模型 | 产品窗口（GPU 加速显示 + 自有窗口 + EFI 链复用） |

## 刀序（P0 → P2）

### P0-1 修窗五件（调度饿死根治）
首刀 = boot 演示常驻面 fw_cfg 门控（owner 域）；预期 idle→~0%、launcher 不再饿死。详见 `docs/阶段沿革.md` 调度优化轮三节「修窗五件」。验收：TCG 形态 launcher bc 面包屑全达、首帧截屏非黑。

### P0-2 §A149 修刀（HVF EL1 写 EL0 用户页）
按判例规避路径落刀：HW 加速档 boot 尾段用户程序域的 syscall copy-out 出参路径降级——EL0 调用方 out 指针改经 EL0 自取（wait_one 返回值面）或该域标 HW 档已知红。验收：HVF 形态 boot 全链绿、pager 存活、无 fatal。
（判例全文：sdk2-berryerr worktree `docs/雷册-判例库.md` §A149——判例随 lane 合并回主干后改指主干雷册。）

### P1 VZ 可行性 spike（时间盒 2-3 天）
- 目标：BERRYBOOT.EFI → `VZEFIBootLoader` → 内核 handoff 通、串口与 `opt/berry/*` 注入链迁移方案定稿（virtio-console 或磁盘约定）。
- 非目标：GPU 显示、多核、性能定标。
- GO/NO-GO 判据：EFI 链通 + 串口迁移方案有单源答案。

### P2 VZ 产品后端（GPU 加速显示 + 自有窗口）
- `VZVirtioGraphicsDeviceConfiguration` + guest 半 B1 系（guifbd vgpu 后端、ScanoutMap）对接：宿主侧真实渲染、60fps@1080P。
- berry CLI 窗口统一：`--backend vz`（产品档）vs `--backend qemu`（开发档）。
- QEMU 散窗清退：shell 默认走 VZ 窗口，不再多窗黑屏。
- 非目标：真机、其他宿主 OS。

## 依赖与风险

- P0-1/P0-2 完成前，VZ 大概率同样炸 §A149（同为 Apple hypervisor）——P1 时间盒内第一验证项就是 §A149 规避是否在 VZ 下同样成立。
- VZ 无 PL011/fw_cfg——串口/注入链迁移是真实成本，P1 定案。
- VZ API 仅 macOS 13+；Linux 宿主保持 QEMU 路径不变。
- sdk2-berryerr lane 未合主干前，判例引用指向该 worktree 拷贝（合并后改链）。

## 验收标准

- P0-1：TCG boot→桌面首帧全链（面包屑+截屏）。
- P0-2：HVF boot 全链绿、`FB ok vgpu` 在场、无 fatal。
- P1：spike 报告落 `research/`（GO/NO-GO + 迁移方案单源）。
- P2：VZ 后端 boot→桌面 60fps@1080P、自有窗口、多窗黑屏清零。
