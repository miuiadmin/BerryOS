## 背景

用户路线指令「先把 TCP 协议研究出来」已完成 probe 与对抗实测两波,产物落家根 [NET-01 客机 TCP 栈深研与裁决](../../research/NET-01-客机TCP栈深研与裁决-v1.0.md)(仓内先例 SCHED-01/SEC-01 系「编号-主题-版本」命名;check-docs 默认面不含根 research/,无门禁冲突,不启用 .agents/research/ 兜底)。三层证据:宿主段级 harness 15/15(状态机宣告语义域内无证伪)、客机在环五网络标记全绿后七毒臂对抗、静态走查全一手行号。

裁决所依赖的关键实测(全部见 NET-01,此处只列结论):

- 停等吞吐:客户端 486/469 B/s(4KB/16KB 对拍)、服务端 echo 309 B/s——上限来自协议设计(MSS=128 + in-flight=1 + 每 op 恰一段 + 串行 RPC),与 VNC 帧流差 21-64 倍。
- 入站 >MSS 单段黑洞(本刀对象):对端单写超 128B 时 SLIRP 按 MTU 拼段(不遵守我方 MSS=128 通告),三例实证(256B 回显 0B 交付 + close TIMEOUT、160B 回显 0B、≤128B 小块对照全通)——拒收后对端重传同形大段永拒,连接死锁且 FIN 路径连坐。
- 多会话:整 8 槽(1 listen + 7 数据)精确实证;SLIRP hostfwd 全关 FIN 不达,无超时服务槽泄漏;POLL 数据可见性受 RPC 节拍束缚(空闲窗 10s 一帧 + POLL/DRAIN/ACCEPT 不收帧)。
- 工具边界:段级丢/乱/重/迟对 guest↔SLIRP 半段结构性不可注入(SLIRP 是 TCP 代理,RTO/乱序臂只有宿主 harness 证据);macOS 无 root 不可 raw 注入。

本波为 design 裁决波:定首刀范围、文件改动清单(符号锚点)、测试矩阵与验收标准;实施属后续执行波,净面属地(berry-tcp/berry-netdproto/drivers/bins/vnet/user/berry-libc net.rs/justfile TCP 段)现刻静默。

## 裁决

四层裁决,每层给动作与理由:

1. **berry-tcp 状态机:维持。** harness 15/15 在宣告语义域内无一处证伪(RTO 退避 3/6/12s 到帽放弃、重复段不二次交付、乱序丢弃回当前 ACK、RST 七态全转、挥手全臂、部分 ACK 保槽重发);41 宿主单测全绿。两毛刺(未来 ACK 越 snd_nxt 被接受、零窗照发)列已知限制——LAN/SLIRP 域无害,真网卡域到来时再议。资产不动。
2. **收发面:extend,分三刀。** 首刀(本 plan)=入站大段容忍与准入一致性——修正确性死锁;二刀=发送窗消费 + in-flight>1 + MSS/RPC 多段化(吞吐从 486 B/s 域进 10KB/s 域,三刀合取才够 VNC);三刀接收侧随二刀联动(若发送 MSS 抬升则接收几何再核)。首刀选入站黑洞而非任务示例的「最简重传/RTO 或乱序缓冲」,理由:重传/RTO 臂 harness 已证正确且客机域结构性不可再注入(SLIRP 即时 ACK 撑不出真丢段),修无可修;乱序重组在 SLIRP 代理域结构性不发生(代理已重组字节流),价值只在真网卡域,后置;入站黑洞是三例实证的正确性死锁,任何入站大块(VNC 剪贴板/文件/bursty 流)必踩,且修法面窄(vnet IO 层几何 + 准入预检,berry-tcp 逻辑臂零改动)、对抗复验臂现成(px-dup)。
3. **服务面(vnet serve/netdproto):patch,后置不进首刀。** 泵节奏提频或推模型(交互延迟 <100ms)、会话空闲超时(FIN 不可达槽泄漏)、netdproto 请求序号(迟到字节错配债,头注自认)——三项与黑洞正交,混入会扩大回归面。
4. **VNC 服务化:后置到二刀后重评。** 首刀解除入站黑洞后,停等吞吐 486 B/s 仍差 VNC 帧流(1KB@10fps=10KB/s)21 倍以上;系统内建 VNC 服务的前提(客机 TCP 承载 KB 级帧流 + 交互级延迟)在二刀前不成立。

## 首刀范围

修「对端单写超 128B 即整连接死锁」:入站几何整链抬升(帧缓冲/pbuf/拒收线/会话收缓冲)叠加会话准入预检(收缓冲放不下整段时拒段回当前 ACK,靠对端重传,永不截断交付)。

机制归因(两道闸,同形致死):黑洞第一道闸可能在 main.rs L588 帧长拒(段 payload >190 时帧超 RX_BUF_SZ=256,DMA 收帧即丢)或 tcp.rs parse_gw_tcp L519 段拒(payload >MSS=128,帧已进但段被拒)——取决于 SLIRP 拼段尺寸;首刀整链同步抬升,两道全解。核心正确性件:现 `rx_push`(tcp.rs L183-191)溢出策略是「丢新字节 + loud 打印」,其注释防御假设「SLIRP 遵守通告」已被实测证伪(SLIRP 不理 WINDOW/MSS 通告);而状态机交付时 rcv_nxt 已推进,截断即字节永久丢失 + ACK 谎报 = 静默数据腐化面。预检必须在喂状态机之前。

首刀后语义:对端任意单写(≤1460B,以太 MTU 域)字节全达;会话收缓冲满时丢整段回当前 ACK,对端(host TCP 栈)重传,DRAIN 腾空后到达——不腐化、不死锁。

### 不动面边界

- 发送面几何零改动:in-flight=1、每 op 恰一段、TCP_DATA_MAX=128、MSS 发送帽——吞吐三刀属二刀。
- `berry-tcp/src/lib.rs` 逻辑臂零改动(仅 tests 补测);`berry-netdproto` 八 op 契约零改动(DRAIN 128B 拉模型天然多次拉取大收缓冲);`user/berry-libc/src/net.rs` 零改动;justfile recipe 链零改动。
- 通告几何不动:MSS 通告 128 与 WINDOW 512 保持(窗口消费/滑窗是二刀);本刀只抬「实际能收」上限,通告继续偏小——超规格接收无害,且 SLIRP 反正不读。
- 服务面三项(泵节奏/槽超时/请求序号)不进首刀。
- 已知限制保持不动(NET-01 非阻塞清单):未来 ACK 越界接受、零窗照发、序号回绕 plain 比较、无 RST 回陌生四元组、RST 不可区分拒绝与不可达。

## 文件改动清单(符号锚点)

**A. `drivers/bins/vnet/src/main.rs`**

- A1(L76-81 RX 几何):`RX_BUF_SZ` 256 → 1600(12B vnet_hdr + 1514 满以太帧 + 余量);`RX_BUFS` 16 → 5(5×1600=8000 ≤ RX_BUF_PAGE 8192,「单页内零重排、rx 单描述符整收」几何结论保持);重写 L77-80 注释:拼段归因(SLIRP 不遵守我方 MSS 通告,按 MTU 拼,链 NET-01)+ 页内排布推导。L588 `len > RX_BUF_SZ` 检查自动放宽,不动。权衡注:RX_BUFS 16→5 使并发收帧容量为 5×1600=8000B/泵;1ms 轮询泵每趟清空 used,发送面停等 128B 段远低此线,非瓶颈。

**B. `drivers/bins/vnet/src/tcp.rs`**

- B1:新本地常量 `RX_SEG_MAX: usize = 1460`(满 MTU TCP 段 payload 上限;放 vnet 侧,berry-tcp 不动——发送帽与收段上限解耦)。
- B2(L58-64 const assert 区):断言改为钉 `RX_SEG_MAX + 帧开销 66 + 12 ≤ RX_BUF_SZ`(替换原「对端按我方通告回的最大段」版——该假设已证伪)。
- B3(L371 与 L671 两处 pbuf):`[0u8; bt::MSS as usize]` → `[0u8; RX_SEG_MAX]`。
- B4(parse_gw_tcp L519 拒收线):`n > bt::MSS as usize` → `n > RX_SEG_MAX`(`n > pbuf.len()` 保留);L504-507 doc 注释同步(「宁拒勿断」语义保留,拒收线换锚)。
- B5(会话准入预检,本刀核心):route_seg 喂 `s.conn.on_seg(seg)` 之前(约 L565-575,槽已定位后),加 `s.rx_len + seg.payload.len() > s.rx.len()` → 不喂状态机,直接 `s.act(..., Action::Ack, &[])`(当前 rcv_nxt 的重复 ACK)+ 注释「宁拒不腐化:rcv_nxt 不推进,对端重传兜底;截断交付 = rcv_nxt 已推进 + 字节丢 = ACK 谎报」。
- B6(rx_push L183-191):溢出分支改防御 trap(预检后结构性不可达,保留 loud;删「SLIRP 遵守通告」假设句)。
- B7(Sess.rx 扩容,L170/L177 两处构造 + L108 字段):`rx: [u8; bt::WINDOW as usize]` → `[0; RX_SESS_BUF]`(2048:容纳 1×1460 大段 + 余量;新常量,与 WINDOW 通告解耦并注明)。`static mut TCPTABLE`(L476)表尺寸 8 槽约 5KB → 约 19KB,注明静态段增量;boot 冒烟列入验收(128M 帧边敏感,见 NET-01 环境战记)。
- B8(step 匹配臂/session-0 客户端,L375-381):同样预检 `seg.payload.len() > rcv.len()` → 拒段回 ACK 跳过 on_seg。客户端 RT op 契约仍是收等长 ≤128B 回显;大回显语义外 = 保持 TIMEOUT(不再有截断腐化面),行为变化仅为消除腐化可能。

**C. `user/berry-tcp/tests/state.rs`**(仅测试,`src/lib.rs` 零改动)

- C1:补 2 测——1460B 大段按序交付且 rcv_nxt 推进正确;大段后续接常规段,序号衔接与交付序正确(防几何回归钉)。

**D. 零改动面(显式):** `user/berry-netdproto/`、`user/berry-libc/src/net.rs`、justfile、smoke 链、markers。

## 边界与偏差

- 工具边界(承 NET-01):真丢段域的 RTO/乱序臂仍结构性不可注入,首刀对抗面限于应用层字节几何;准入预检的「对端重传恢复」在 SLIRP 域依赖 host TCP 栈重传(实测支持:r1 丢字节后 SLIRP 重传行为可见)。
- SLIRP 拼段尺寸分布未穷尽:1460 上限是 MTU 推理(以太帧 1514 + vnet_hdr 12 = 1526 ≤ RX_BUF_SZ 1600 留 74B 余量);若实测出现带 IP/TCP 选项的超限帧,拒收线仍兜底(不死锁,回当前 ACK)。
- 五标记链若被并行 smoke 会话占 18080-18083,复验走私有高位口等价链并记偏差(形态同 research 波,归属等价:同一 vnet/tcp.rs 代码路径,仅 hostfwd 端口映射不同)。
- 现行树已知回归不在本刀面:demo-face=off 下 vnet 定时器停摆、>128M 内存面 bug、bsh 自验链 u2 起挂起——验收环境固定 demo-ON + 128M(同 NET-01 最终可用配置)。
- 首刀不做吞吐承诺:486 B/s 停等上限不变(发送面零改动);吞吐进阶属二刀。
