# am（应用生命周期与五级弹性内存回收总管）总体设计

Type: spec
Status: active
Updated: 2026-11-22
Version: 2.0.0

一句话说明：`am`（承载于用户态生命周期与资源监督中枢 `appd` 及协议库 `berry-amproto`）是 BerryOS 的多核应用生命周期与弹性内存总管——以「失焦 3 秒自动冰封 + 资源活跃度真凭实据豁免 + LZ4/Zstd 压缩匿名页换出 + `BerryFS` 加密持久化无限墓碑 + 无感归档瘦身」五级确定性梯度，让 128MiB–8GiB 设备跑出两倍物理内存的并发驻留体感。

## 背景

本模块 v0.5.0 阶段已完成单核冻结（`0x3E process_suspend`、`FROZEN ok`）、唤醒即解冻（`SIGNAL_WAKE_PENDING`、`WAKE ok`）、RAM 8 槽原型墓碑（`TOMB ok`）及缺页等页停顿压力信号（`AM2B-K`、`DPGPRESS ok`）机制验证。但如 [全栈 25 模块跨界接缝与深水区六盲点复核审计](../../research/2026-11-18-全栈25模块跨界接缝与深水区六盲点复核审计.md) 所示，旧版受限于单核假设与「RAM 8 槽定长墓碑表」，尚未与 16 核无大锁莓核 2.0、[sched-rt-gfx 总体设计](../sched-rt-gfx/design.md) 焦点状态机、[storage-image 总体设计](../storage-image/design.md) `BerryFS` 加密存储、[media 总体设计](../media/design.md) 音频活跃流证据及 [backup-sync 总体设计](../backup-sync/design.md) 跨机墓碑克隆合龙。本 2.0.0 版在完整保留 v0.5 已验内核原语契约的基础上，确立全栈终态生命周期规格。

## 范围

- **覆盖**：16 核 SMP 一致性进程树（`Job`）挂起与唤醒解冻协议；五级内存与生命周期回收梯度（L0 `DISCARDABLE` 瞬时弃页 → L1 冻结态压缩换出池 → L2 失焦自动冰封 → L3 `BerryFS` 加密持久化墓碑与视觉快照无缝恢复 → L4 协同 `pkgmgr` 保数据卸包归档）；与音频、定位、通话及统一后台经纪 `workmgr` 的「资源活跃度实证豁免」联动；应用主线程与生命周期回调超时联动 [cbox 总体设计](../cbox/design.md) 触发 ANR 取证。
- **不覆盖**：底层页表项解映与 `0x22 pager_op_range` 物理帧摘除机制本身（归 [mm 总体设计](../mm/design.md)）；安装包文件增删（归 [pkgmgr 总体设计](../pkgmgr/design.md)）。

## 契约

### 一、终态五级弹性处置梯度契约

| 梯度 | 触发水位与条件 | 执行动作（内核机制 + `appd` 策略） | 物理内存收益 | 用户切回恢复体感 |
| :--- | :--- | :--- | :--- | :--- |
| **L0 瞬时弃页** | 轻度内存水位或应用刚切后台 | 内核直接回收标记 `VMO_OPT_DISCARDABLE` 的字形缓存、解码图片缓存与闲置交换链备槽 | 立即释放 30%–60% 图形/缓存页 | `< 2ms`（已在内存进程按需重填） |
| **L1 冻结态压缩换出** | 应用已处 L2 冰封态且 PSI 等页压力上升 | `appd` 协同用户态压缩 `pager` 经 `0x22 pager_op_range(PAGER_OP_EVICT)` 将冰封进程的私有脏匿名页以 `LZ4` 高速压缩存入受临时会话随机密钥加密的交换池（受每日闪存写寿命配额保护） | 释放 70%–85% 私有堆/栈物理页 | `< 15ms`（解冻后按需批供缺页解压） |
| **L2 多核原子冰封** | 窗口完全遮挡或退后台超自适应防抖窗（默认 **3s**，内存紧缺时 **0s**）且无实证后台租约 | 限时 200ms 投递 `OnBackground` 通知刷缓冲后，持 `SuspendToken` 冻结目标 `Job` 全线程（跨 16 核 IPI 同步停于安全点，定时器与后台 CPU 唤醒归 **0**） | 锁死内存不涨，CPU 功耗归 **0** | **`< 1ms`**（关闭 Token 瞬时满血续跑） |
| **L3 杀进程 + 持久加密墓碑** | 重度内存压力（L0–L1 仍不足）或驻留应用超上限 | 采集合成器 `0.5x` 缩略帧与导航栈结构化状态（`StateVmo ≤ 256KiB`，CRC32C 校验）经 FBE CE 密钥加密落入 `/data/system_ce/<uid>/tombstones/<app_id>.tomb`（突破旧版 RAM 8 槽上限，支持百级历史任务跨重启与跨机克隆保留！），随即调用 `0x44 job_kill` 100% 回收进程全部页表与物理帧 | **100% 释放**进程全部 RAM | `< 120ms`（合成器先亮快照帧遮盖，新进程异步重放状态树无缝衔接） |
| **L4 冷应用无感瘦身** | 90 天未启动且磁盘空间紧张 | 移交 [pkgmgr 总体设计](../pkgmgr/design.md) 执行 `App Offload`：清退只读包体与缓存，完整保留 `/app/data` 与 L3 墓碑档 | 释放磁盘包体空间 | 点击图标流式重拉包体后原地复活 |

建造清单（DAG 节验收面——全勾才配双戳）：

- [x] 梯度决策核首刀：`user/berry-amgrad`（五级表单源 [`choose`]——RAM 谱系 L0<L2<L1<L3 升格 + L4 磁盘正交；实证租约豁免压制冰封与深化〔契约二.1 联动〕；防抖窗双钉值 3s/0s；无触发即 `None` 禁默认动作；「刚切后台」窗宽占位常量归 appd 配置刀）——host 8 测绿（`just test-host` berry-amgrad 腿，2026-11-22）
- [ ] 执行机构接线：L0 弃页（`VMO_OPT_DISCARDABLE` 标记面）/L1 pager 压缩换出（`0x22 PAGER_OP_EVICT`）/L2 `SuspendToken` 冻结/L3 `0x44 job_kill` + 墓碑/L4 pkgmgr offload（涉内核 mm/pager/job 面与 appd 服务——owner 边界声明队列）

### 二、零谎言「资源活跃度实证豁免」与 IPC 唤醒防风暴契约

1. **废除口头自报保活，只认系统服务实证租约**：任何应用不能仅凭清单声明常驻后台——`appd` 仅接受来自四大权威服务的实时活跃度背书：
   - `audiod` 出具「非静音真实音频流正在输出/录音」租约（静音填零超 5 秒自动撤证！）；
   - `locationd` / `callmgr` 出具「活跃语音导航胶囊或正在通话」租约；
   - `berry-link` / `pkgmgr` 出具「用户主动发起的跨端投送或下载传输进行中」租约；
   - `workmgr` 出具「当前正处于系统合并维护窗口（限时 30 秒）」租约。一旦全部租约归零，3 秒内必入 L2 冰封。
2. **唤醒即解冻与风暴熔断**：沿用并升级已验 `SIGNAL_WAKE_PENDING` 闭环——发往冰封进程合法会话通道（如用户点击通知或 `intentd` 路由跳入）的消息入队触发 `WAKE_PENDING` 唤醒 `appd` 即刻解冻处理；若某异常客户端每分钟触发被动解冻超 12 次（Wake-Flood），`appd` 自动切入节流退避并记入 [power-thermal 总体设计](../power-thermal/design.md) 异常耗电台账。
3. **生命周期死锁触发 ANR 取证**：若应用在收到前台 `Launch`、`Resume` 或 `PauseSave` 指令后超过阈值（前台交互 5 秒、后台保存 2 秒）未应答，`appd` 先触发 [cbox 总体设计](../cbox/design.md) 抓取该进程全部线程 `.eh_frame` 调用栈与 IPC 阻塞边生成 `ANR` 诊断报告，随后果断终止清理，绝不让假死进程挂住监督器。

## 验收标准

1. **多核零唤醒冰封门禁**：在 8 核 SMP 配置下并发打开 12 个含内部高频定时器线程的 GUI 应用并逐一切入后台，3 秒后后台 11 个应用的 CPU 利用率与 `WAKESRC` 定时器唤醒计数在 10 分钟观测期内严格恒为 **`0`**；任意点开第 1 个应用在 1 帧内瞬时响应。
2. **百应用墓碑跨重启复活验证**：连续打开并操作 30 个应用并注入极端内存压力迫使前 25 个进入 L3 落盘墓碑态，执行优雅重启解锁后，从最近任务视图点开第 1 个应用仍能 100% 恢复重启前的页面栈、滚动偏移与表单草稿。
3. **静音假保活猎杀验证**：测试音乐应用切入后台后持续向音频环灌入全零静音帧企图逃避冻结，5 秒后 `audiod` 准时撤销活跃租约，`appd` 在第 8 秒将其成功冰封。

## 适用边界

- 用户在最近任务视图手动「上滑划掉（Force Dismiss）」某应用卡片时，代表用户明确意图彻底关闭重来——`appd` 在终止该 `Job` 的同时销毁其当前 L3 临时运行期墓碑档（不触碰 `/app/data` 持久用户文档），下次点击图标干净回到应用首页。
