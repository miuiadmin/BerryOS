# VNC 第十波「LAN 远程桌面」实施计划（--lan 单口代理/终端 QR/qrcodegen 引入）

Type: plan
Status: done
Updated: 2026-11-15

一句话说明：把 `berry vnc web` 从环回单机形态扩成 LAN 直开形态——`--lan` 让 berry 作唯一 LAN 入口（单口绑 0.0.0.0，页面资产照旧、`/ws` 路径转明文字节管道代理到 QEMU 的环回 ws 口），终端 QR（qrcodegen 1.8.0，本波唯一新 Rust 依赖）用剥掉 `#password=` fragment 的完整页面 URL 配对，手机/平板连同一 Wi-Fi 直开 BerryOS 桌面——兑现 [wave9 笔记](../notes/implemented/2026-11-14-vnc-web-polish-wave9.md)登记的 QR 重启条件。

## 背景

VNC 九波已收官（工作树态，未 commit；单测 100 绿、四门全绿、check-docs 0 告警）：对外暴露与认证（非环回强制自动口令的 wave1 策略）、noVNC/TLS/审计/口令生命周期、三平台打包与 TPN 单源、两轮遗漏检查、rustls TLS 客户端 + https 页 + wss 终止代理（双口：https 页口 + wss 代理口）、ws 客户端自检、沿革节号唯一化治理、第九波网页产品化（自有壳页 `index.html`/`berry.js`/`berry.css`/logo/铃音，默认页 + `/novnc/vnc.html` 逃生门，`--open` 剥 fragment，自动重连/工具栏五键/移动紧凑档；单口三形态 URL：`path=` 或 host/port/encrypt 形态——契约见 [wave9 计划](2026-11-14-vnc-web-polish-wave9.md)）。

wave9 砍 QR 时登记的重启条件（笔记第 14 行）：「LAN 绑定模式立项时随批评估，届时 QR 内容必须用剥掉 `#password=` fragment 的 URL（口令不进可扫实体）」——本波就是兑现它。

本波定性：手机/平板连同一 Wi-Fi 直开 BerryOS 桌面。架构方向已定（细节本计划裁）：`berry vnc web --lan` = berry 作唯一 LAN 入口——页面与浏览器 ws 代理同口绑定 0.0.0.0（path 路由 `/` 与 `/ws`，单口对手机最简），ws 代理转发到 QEMU 的 loopback ws 口（QEMU 不暴露 LAN；明文 ws 代理为字节管道，VNC DES 口令认证端到端透传）。QEMU 侧仍按 run 现状（`--vnc on --vnc-ws on` 起，ws 绑 loopback）。

本波前置 probe（2026-11-15，仓库零写入，QR 实验产物留档 `/tmp/qrprobe`、LAN 代理原型 `/tmp/lanproxy`）五面定音，构成本计划的外事实依据（design 阶段已逐项复核关键件）：

- **f1（QR 依赖）**：qrcodegen 1.8.0 为 crates.io 最新且唯一稳定版（2022-04 发布，1164 万下载，上游稳定不动）；MIT；无 rust-version、无 edition 声明（2015 版）即 MSRV 极低；`cargo tree` 实测零传递依赖（Cargo.lock 单条，design 复核 `/tmp/qrprobe/Cargo.lock` 确认）；源码单文件 lib.rs 1302 行，API 面 = `QrCode::encode_text(&str, QrCodeEcc)` + `version().value()` + `size()` + `get_module(x,y)`，终端渲染完全够用；发布 crate 内无 `#[test]`（向量在上游仓库）；探针两例（56 字符 URL → v4/33×33、`Hello, world!` → v1/21×21，均 Ecc::Medium）经纯 stdlib PNG + macOS Vision（VNDetectBarcodesRequest）解码 payload 逐字节一致。
- **f2（LAN 地址解析）**：本机三路实测——`scutil --get LocalHostName` → `MIUIMacBook-Pro`（无 `.local` 后缀，拼 URL 需补）、`hostname` → `MIUIMacBook-Pro.local` 自带；接口 IP 无依赖方案 = `ipconfig getifaddr en0` → `192.168.1.105`（单行输出零解析成本），接口枚举 `ifconfig -l` 过滤 `en*`（本机 en0-en6 仅 en0 有 IPv4，另有 utun/awdl/bridge 干扰面）；`dscacheutil` 可解析 `.local`（mDNS 本机可解，但 Android 对 `.local` 支持不稳，URL 主形态应取裸 IP）；纯 std 的 `UdpSocket` connect 8.8.8.8 惯用法在本机返回 `198.18.0.1`（VPN fake-ip 默认路由劫持）——该惯用法被实证否决。
- **f3（单口 /ws 路由）**：`web.rs` 切入点 = `handle_conn_budget` 在 parse_request_line + sanitize_path 之后（现 `/ws` 落静态树 404）；活体实验（隔离 BERRY_HOME，QEMU 11.0.3）：QEMU ws 口对 `GET /` 回 101 + ws 二进制帧内 `RFB 003.008\n`，对 `/ws` 与 `/foo` 均 404（**路径改写是硬需求**）；LAN IP 直连 QEMU ws 口被拒（环回绑定，**代理是架构必需**）；`/tmp/lanproxy/lanproxy.py` 原型（0.0.0.0 单口，`/` 静态页、`/ws` 改写转发管道）经 127.0.0.1 与 192.168.1.105 两路拨 `ws://…:18123/ws` 均得 101 + RFB banner；permessage-deflate 无协商错位（101 原样回、QEMU 不收扩展、浏览器跟随服务端）。浏览器侧零改动：自有壳页 [berry.js](../../tools/berry/web/berry.js) Form 1 `path=<ws uri>` 原样消费（`new URL().href` 保 `/ws` 路径），页为 http 时 scheme 不被改写。
- **f4（可测性）**：Chrome headless 经 LAN IP（192.168.1.105）可用——页面内 `WebSocket('ws://192.168.1.105:18123/ws')` 在 `--virtual-time-budget` 下拿到 `OPEN` + `MSG:RFB 003.008`（真引擎经 LAN IP 完成 Upgrade + 首帧）；QR 解码器盘点：zbar/zxing/pyzbar 全缺，但 macOS Vision 经 swift 脚本零新依赖可用且已实证两例解码——验证途径 = 单测钉矩阵向量（确定性）+ Vision 样张解码（手工验收面），无解码器平台按矩阵向量比对降级。
- **f5（门与沿革）**：cargo test 基线 100 通过 0 失败；三冒烟全绿（隔离 BERRY_HOME 自起自收）；check-docs 0 告警；TLS run 的 ws 口为 loopback wss-only（活体 lsof：两口均 127.0.0.1 LISTEN，明文 Upgrade 被 RST，wave5 探针已钉）——`--lan` 对 TLS run 无明文上游可转。沿革节号纪律：探针时点文末实数 = 二百六十一（基准二百六十二）；design 复核时文末已为并行会话续写的「一百零六轮」UI 节——**实现落笔以实时重读文末为准**。

冻结面声明：`window.rs`/`profile.rs` 为并行会话未提交 M 态零触碰；`main.rs` 仅许动 VNC 布线区（`VncWebCmd` 与 dispatch）；`arch/`/`kernel/`/`sched/`/`user/`/`research/`/`docs/调度*` 与 `显示*`/沿革已提交内容零触碰。

## qrcodegen 决策

按 [wave5 计划](2026-11-13-vnc-complete-wave5.md)「rustls 决策」节的同型格式，独立成节。

### 为什么是 qrcodegen（候选四案）

- **qrcodegen 1.8.0（入选）**：Nayuki 系纯 Rust 单文件 MIT crate，零传递依赖（`cargo tree` 实证，Cargo.lock 只增一条）；API 四函数（`encode_text`/`version`/`size`/`get_module`）与终端渲染需求严丝合缝；1164 万下载、2022-04 后上游不动（引版即终版风险低）；探针已闭环「编码 → 纯 stdlib PNG → Vision 解码 payload 逐字节一致」两例。
- **自写最小 QR（落选）**：约 400 行（wave9 估，本波维持）——v6 起多块交织，中 correctness 风险，且须自备向量测试 + Vision 解码验收，成本与风险均高于引库；QR 是配对糖不是安全件，但错了就是整刀砍项。
- **vendored qrcode-generator 1.4.4（落选，且案不存在）**：wave9 QR 三案之一；probe 检索证实本仓 noVNC 树无该文件（vendor 下只有 pako）——案前提不成立；即便引入也非 ESM、需 NOTICE 登记，无优势。
- **nayuki 上游剥 TS 类型 / 更重的 QR 库（落选）**：前者 = 改 vendored 文件违红线；后者（qrcode/image 系）为 UI 渲染面设计，依赖面远超「终端半块字符」需求。

### 版本、许可与依赖面

- 版本：qrcodegen **1.8.0**（crates.io 最新且唯一稳定版；`[dependencies]` 写 `qrcodegen = "1.8"`）。
- 传递依赖：**零**（lock 单条；与 rustls 先例的 12+ 条形成对照）。
- MSRV：crate 无 `rust-version` 声明（2015 edition），低于仓级钉版 1.97.0（[rust-toolchain.toml](../../rust-toolchain.toml)），零工具链风险。
- 许可：MIT——在纪律「Apache-2.0/ISC/MIT 系」内，无 subtle 式例外。
- 已知实现边界：发布 crate 无 `#[test]`（测试向量住上游仓库，不在发布物内）——正确性兜底不能靠「跑上游测试」，见下。

### 测试兜底（发布 crate 无 #[test]）

三层：①确定性样例单测——固定输入钉 version/size 与模块矩阵（探针两例 `Hello, world!` → v1/21×21、56 字符 URL → v4/33×33，均 Ecc::Medium，作为 golden vector 入单测）；②渲染纯函数单测——半块折叠维度、quiet zone 全亮、边框在位；③实扫验收——终端样张截图/PNG 化后经 macOS Vision 解码，payload 与剥 fragment 的 URL 逐字节相等（无解码器平台降级为 ①+②，如实记录）。

## 契约

### 1 `--lan` 语法与旗标族

```
berry vnc web [--run <id>] [--port N] [--max-conns N]
              [--lan [--host <addr>] [--qr | --no-qr]] [--open] [--json]
```

- `--lan`：单口 LAN 模式——页面与 ws 代理同口绑 `0.0.0.0`（path 路由，见契约 2）；URL 的 host 段与打印 URL 用 LAN 地址（解析见契约 3）；QR 默认开启（见契约 5）；serving 行如实打印 `0.0.0.0:<port>`。
- `--host <addr>`：覆盖自动解析，值原样入 URL（裸 IPv6 经 `addr_host` 语义补括号）。校验：非空、不含空白、不含 `/` 与 `\`——违者 rc=2（usage-error 语义，对齐 `parse_max_conns` 先例）。**依赖 `--lan`**：无 `--lan` 给 `--host` → rc=2。
- `--qr` / `--no-qr`：QR 显式开/关；默认值 = `--lan` 在场时开、缺席时关。**两者都依赖 `--lan`**：无 `--lan` 给任一 → rc=2（理由：环回 URL 的 QR 对手机是死路——wave9 f4 的既有结论，提前拦住误导性实体；hint 指明「QR 内容是 LAN 地址，只在 --lan 模式有意义」）。
- `--open` 语义不变（macOS `open`、剥 fragment）；`--json` 语义见契约 4。

### 2 单口 path 路由代理（`/ws`）

**绑定**：[web.rs](../../tools/berry/src/web.rs) `serve` 的绑址参数化（现硬编码 `127.0.0.1`）——签名增 `bind_host: &str` 与 `lan: Option<LanUpstream>`（携带上游拨号地址）；环回调用方传 `("127.0.0.1", None)`，`--lan` 传 `("0.0.0.0", Some(upstream))`。`--lan` 与 TLS 面互斥（契约 6），故 `lan.is_some()` 时 `tls` 必为 `None`（debug_assert + 契约保证）。

**路由判定**（`handle_conn_budget` 内，在 method 检查与 sanitize_path 之后、双树解析之前）：sanitize 后 `rel == "ws"` **且** method == GET **且**原始头块含 `Upgrade: websocket`（头名大小写不敏感）**且**含 `Sec-WebSocket-Key:` → 走代理分支；仅 `rel == "ws"` 而无 Upgrade 头 → 落静态树 404（现状语义，`ws` 文件不存在）。`//ws` 形态被 sanitize 的空段折叠自动覆盖。判定需要原始头块字节——`read_head` 增返原始头字节（现只返 `(method, target)`；既有测试适配，行为零变化）。

**代理路径**（明文字节管道，lanproxy.py 原型已实证）：

1. 拨上游 `vnc_cfg::addr_host(vnc_cfg::dial_host(&listen.host), ws_port)`（QEMU 环回 ws 口），`connect_timeout` 10s（对齐 `vnc check` 的 10s 连接纪律）；失败 → stderr 一行诊断（wss 代理 F30 先例：建链失败必须有声，否则页面无感而死）+ 断开浏览器侧连接。
2. 请求行改写：原始头块首行的 target（`/ws` 及其 query 变体）整体替换为 `/`（QEMU ws 只认根路径，probe f3 硬需求），**其余头字节逐字节原样**（含 Host/Key/版本行/扩展头）——纯函数 `rewrite_ws_request_head(raw: &[u8]) -> Option<Vec<u8>>`（malformed → None → 断开），不重序列化头。
3. 双向字节管道：改写头块写上游后，两侧 socket 摘除读写超时（OS 语义——桌面会话可存活数小时；wss 代理同款），两线程对泵、任一方向 EOF/错 → 双侧 `shutdown(Both)` 拆链（`proxy_conn` 同型，纯 TCP 无 TLS 层）。
4. **CONN_BUDGET 豁免**：识别为代理分支即退出 30s 连接预算（该预算防慢滴攻击，只该管 HTTP 头阶段；长连接语义与 `serve_wss_proxy` 数据面一致）；准入仍走同口 `max_conns` 计数（RAII 槽随连接生命周期，over-limit 照旧 503 + stderr 行）。
5. permessage-deflate 不协商：101 原样回流、QEMU 不收扩展、浏览器跟随服务端（probe f3 实证）；代理对头字节零干预故天然成立，边界节如实登记。

**非 `--lan` 模式行为逐字节照旧**：环回服务 `lan=None`，`/ws` 判定不激活（回归面最小；环回页面的 `path=` 直拨 QEMU ws，无代理环节）。

### 3 LAN 地址解析（顺序与跨平台）

```
resolve_lan_host(explicit: Option<&str>) -> LanHost { Addr(String) | FallbackLoopback }
```

解析顺序（`--host` 缺席时）：

1. **macOS**：`ipconfig getifaddr en0` → 空则 `ifconfig -l` 枚举 `en*`（排序后）逐个 `ipconfig getifaddr <if>` 取首个非空。
2. **Linux**：`hostname -I` 输出按空白切分，纯函数 `pick_lan_ipv4(fields)` 取首个「解析为 IPv4 且非环回（127/8）且非链路本地（169.254/16）」的字段。
3. **Windows**：`powershell -NoProfile -Command` 走 `Get-NetIPAddress -AddressFamily IPv4`，过滤 Loopback 与 169.254 取首个 Address（ipconfig 输出有本地化风险，不取）。
4. **全链失败**：回退 `127.0.0.1` + 一次性 stderr 警告（hint：`--host <addr>` 显式指定）——rc 仍 0、服务继续起（绑定仍 0.0.0.0，用户可手动用本机 IP 访问）。

裁决记录（偏离功能规格预草案处见「偏差」1）：

- **URL 与 QR 主形态 = 裸接口 IPv4**：全平台最大公约数；`.local` 主机名不进 URL（Android 对 mDNS 支持不稳，probe f2）；mDNS 注册本就是非目标（wave9 沿革既定边界），不做 `.local` 打印备选——少一条分叉，iOS/Android 均可消费裸 IP。
- **UDP connect 8.8.8.8 惯用法明确否决**：本机 VPN fake-ip 实证返回 198.18.0.1（probe f2），不能作 LAN IP 来源。
- 子进程纪律与 `vnc certs` 壳出 openssl 同款：零新依赖、失败容忍（子进程缺失/超时按该平台链路失败处理，落入回退）、输出只作解析输入。
- Linux/Windows 分支本机不可测：纯函数面（字段挑选）入单测，实机行为如实登记为未验证面（见「边界」）。

### 4 URL 构造与输出形态

**URL 构造**：新 builder `build_page_url_lan(lan_host: &str, web_port: u16, password: Option<&str>)`——`http://{lan}:{port}/?autoconnect=true&path={pct(ws://{lan}:{port}/ws)}&resize=scale` + 可选 `#password=` fragment（fragment 规则、percent-编码与既有三 builder 逐字节同构）。ws URI 的 host = 同一 LAN 地址同口（`/ws` 路径）——berry.js Form 1 原样消费（`new URL().href` 保路径），**浏览器侧零改动**。既有 `build_page_url`/`_https`/`_tls` 三 builder 零变化（单测逐字节钉死防回归）。

**文本输出**（顺序与要素为契约、措辞实现期可微调）：

```
<LAN URL 含 fragment>
serving <root> on 0.0.0.0:<port> (LAN 模式：页面与 ws 代理同口, max N connections, Ctrl-C to stop)
note: LAN 暴露——明文 http 页 + 经典 VNC 认证(DES)是弱防线, 仅在可信 Wi-Fi 内使用; 建议重启时显式 --vnc-pass
<QR 半块渲染块>
hint: 手机扫码打开页面, 口令在页面弹窗中手动输入
```

`--lan` 模式**不打印**环回模式的 `berry vnc check --ws` hint（该命令直拨 QEMU 环回口、不经 LAN 代理，印了会误导「已验代理路径」）。

**JSON 输出**：既有键全保 + 增 `"lan": {"bind": "0.0.0.0", "host": "<addr>", "qr": <bool>}`；QR 不渲染（JSON 面保持机器可解析）；`url` 用 LAN 地址。

### 5 QR 渲染与开启时机

- **开启时机**：`--lan` 在场默认开；`--qr` 显式开（冗余但利于脚本明示）；`--no-qr` 关；无 `--lan` 给 `--qr`/`--no-qr` → rc=2（契约 1）。
- **内容**：`strip_fragment(页面 URL)`——完整页面 URL 剥 `#password=`（wave9 重启条件的兑现原文）；口令不进可扫实体。无口令 run 到不了这里（契约 7 的 rc=2 先拦），故扫码后页面必走凭据弹窗，口令从终端 URL 行或 `berry vnc passwd` 读取后手动输入——README 配对指引按此写。
- **编码**：`QrCode::encode_text(url, QrCodeEcc::Medium)`；ECC 定 M（屏幕扫码有摩尔纹与极性反转余量，M 比 L 稳、比 Q 小——101 字符级 URL 落 v6/41×41，终端渲染无压力）；编码失败（DataTooLong，实际不可达）→ stderr 警告一行 + 不渲染，服务不受影响。
- **渲染**：4 模块 quiet zone（spec 下限）+ 半块字符折叠（两模块行一物理行：`█`/`▀`/`▄`/空格 四态，奇数尺寸补亮行）+ 一圈 box-drawing 边框；纯函数 `render_qr(text) -> Option<String>`，维度与 quiet zone 单测钉死。
- **极性边界**：半块字符按「前景 = dark 模块」渲染；深底浅字终端里矩阵极性反转——多数解码器（Vision 含）可读反转码，验收以实扫样张为准，如实登记（见「边界」）。

### 6 TLS run 与 `--tls` 的裁决

- **TLS run（`vnc.listen` 的 `tls=true`）+ `--lan` → rc=2 拒绝**。依据：QEMU ws 端点为 loopback wss-only（probe f5 活体 lsof + wave5 已钉），明文字节管道无上游可转；要做需 rustls 客户端终止上游（`proxy_conn` 去服务端 TLS 的变体，新面不小），且手机侧自签证书墙会直接打死 https 形态——两条路都不值得首版背。hint：`不带 --vnc-tls 重启后用 --lan（TLS run 请用既有 https 双口环回模式）`。重启条件登记：「`--lan` × TLS run（rustls 客户端上游 + http 页）」入 Agent Note。
- **明文 run + 显式 `--tls` + `--lan` → rc=2 互斥**。依据：`--tls` 强制 https 页绑 0.0.0.0，手机先撞自签墙；且该分支页面用 host/port 形态指向 QEMU 的 ws 口——QEMU ws 绑环回，手机根本不可达，架构性死路。hint：`--lan 与 --tls 互斥（--lan 是明文 run 的 LAN 形态；TLS 需求走环回 https 模式）`。
- **非环回 bind 的 run（如 `--vnc 0.0.0.0`）+ `--lan` → 允许 + 照实警告**：QEMU ws 口此时已直接对外，berry 代理不是唯一 LAN 入口——警告行明示该事实 + DES 边界；代理本身仍工作（上游经 `dial_host` 回环拨打）。

### 7 安全策略矩阵

纯函数 `lan_admission(listen, tls_flag, has_pass, lan) -> Admission`（单测钉矩阵；`Allow` 携带 `warn_extra: bool`）：

| 输入态 | 裁决 |
|---|---|
| `lan=false` | `Loopback`（行为照旧，本波零变化） |
| `lan=true` 且 `listen.tls` | `Reject`（rc=2，restart-without-vnc-tls hint，契约 6） |
| `lan=true` 且 `tls_flag` | `Reject`（rc=2，互斥 hint，契约 6） |
| `lan=true` 且明文且 `has_pass=false` | `Reject`（rc=2，hint：`restart with --vnc-pass`——wave1 非环回策略对齐：LAN 绑定即非环回暴露面，无口令的明文 RFB 不许上 LAN） |
| `lan=true` 且明文且 `has_pass=true` 且 `listen.host` 环回 | `Allow`（打印一次性 DES 强度边界提醒，契约 4 的 note 行） |
| `lan=true` 且明文且 `has_pass=true` 且 `listen.host` 非环回 | `Allow` + 双重警告（QEMU ws 已直接对外 + DES 边界） |

`has_pass` 来源 = `vnc_cfg::read_pass(run)`（run 的实际认证态；非环回 run 被 wave1 策略自动生成口令，故「无口令」仅出现在环回默认 run——矩阵与既有策略自洽）。口令纪律沿既有口径：fragment 只进 stdout URL 行（用户信任面）、不进 argv（`--host` 等新旗标不含口令）、不进日志与错误信息、不进 QR 实体。

## 边界（非目标）

- 不做公网暴露与 TLS 页面 on LAN：明文 http 页 + 同源 ws，LAN 假定可信 + VNC DES 端到端（架构既定；TLS run 的 LAN 形态被契约 6 拒绝并登记重启条件）。
- 不做 UPnP/端口映射、mDNS 注册（仅不使用 hostname.local——裸 IP 是全平台最大公约数）。
- 不做 SASL/剪贴板/SetDesktopSize/remote 缩放档（wave5/6/9 沿）。
- `vnc check --ws` 不经 LAN 代理（直拨 QEMU 环回口，语义零变化；`--lan` 模式不打印其 hint）。
- permessage-deflate 不协商（101 字节透传，QEMU 不收扩展，probe f3 实证；代理对头字节零干预）。
- QR 不做页面内渲染（终端实体唯一）；不做 QR 的 inverted/极性自适应（深底终端的反转码依赖解码器容错，Vision 实证可读，如实登记）。
- Linux/Windows 的 LAN 解析分支本机不可测：纯函数面单测覆盖，实机行为登记为未验证面（README 如实标注平台成熟度：macOS 实测、Linux/Windows 尽力解析 + `--host` 兜底）。
- QR 解码验证途径的平台差异：macOS 走 Vision 实扫；无解码器平台降级为矩阵向量 + 固定样张比对（任务规格既定降级路径，不虚报验证层级）。
- 沿革已提交内容不回改（新节文末追加）；`.agents/research/` 零触碰。

## 偏差

写作时点已知的与任务功能规格直直觉的出入（implement 阶段如有新增在此续记）：

1. **LAN 地址解析顺序推翻规格预草案**：规格草案「`--host` 显式 > hostname.local 形式 > 接口 IPv4 > 127.0.0.1」→ 本计划裁为「`--host` 显式 > 平台接口 IPv4 > 127.0.0.1+警告」，`.local` 不进 URL 也不打印——依据 probe f2 实证（Android 对 mDNS 支持不稳；裸 IP 全平台可消费；mDNS 注册本就是非目标）；UDP connect 惯用法被实证否决（本机 VPN fake-ip 返回 198.18.0.1）。
