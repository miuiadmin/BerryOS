# 启动产物与状态体系全面建设计划

Type: plan
Status: active
Updated: 2026-11-15

一句话说明：把「半套体系」建成完整体系——配置递送三轨制定型、宿主全启动方式统一留痕、客机可写持久层、可观测读口兑现，五阶段每步钉到代码锚点与验收判据。

## 背景

现状裁决与证据见 [2026-11-15-启动产物配置与日志AI可读性调研](../research/2026-11-15-启动产物配置与日志AI可读性调研.md)；四个形态问题已拍板（失败留成功删、终态并轨 berry CLI、ARM64 优先、确定性面与持久面分流），见 [2026-11-15-启动产物与状态体系四个形态拍板](../notes/implemented/2026-11-15-启动产物与状态体系四个形态拍板.md)。本版规划由五路行号级代码核实支撑：fw_cfg 全键清单（20 键）、fsmgr 树与 FAT 接入机制、settings/bsh 落盘最短路径、berry CLI 改动锚点、内核日志与 telemetry 现状——核实结论已融入下文各步的「锚点」与「风险」。

与相邻方案的分工：[2026-11-14-模拟器体验统一分刀方案](2026-11-14-模拟器体验统一分刀方案.md)与[2026-11-14-模拟器方案规划](2026-11-14-模拟器方案规划.md)管五入口体验与性能分层（TCG/HVF/VZ），本计划管启动产物、状态与日志体系；阶段四与其合流，不重迭刀口。

## 设计原则

1. **确定性面与持久面分流**：smoke/CI 依赖每次重造盘与 blank vars 的零残留（`qemu.rs:351` 注释明示 "deterministic clean boot state"），持久化只走设备壳 profile 路径（`shell` / `desktop` / `berry device start`），按启动方式分流。
2. **宿主留痕单形态**：`~/.berry/run/<id>/` 目录体系是唯一留痕形态；B 族直跑过渡期先 tee 落 `out/logs/`，阶段四并轨后归一。
3. **配置递送三轨制**（核心架构裁决，详见「体系总规格」）：build 期镜像定值 → rootfs 内 `etc/boot-params.toml`（cpio 承载，EFI 路可达，`kernel/src/bootparams.rs` 已裁决在案）；宿主运行期注入 → fw_cfg `opt/berry/*`（QEMU 路专属）；客机运行时可写持久 → FAT 卷根 8.3 文件族。三轨各管一段，不互抢。
4. **客机配置文件面遵循现网事实模式**：FAT 卷根平面 8.3 单段名（`SETTINGS.JSN` / `LAYOUT.JSN` 先例），v1 不做多段路径写（小写/多段构造性落 RAM 树、掉电即失，`fat.rs:16-20`）；`/cfg` 目录挂载依赖 FAT 子目录写面（官方 v2 推迟项），本计划只立 v2 蓝图不抢跑。
5. **AI 视图与文件本体同源**：`berry logs/events/doctor --json` 是视图不是第二份事实；键表、索引、日志全部单源可机器读。
6. **ABI add-only 纪律**：读口复用在册号 0x84 `telemetry_open`（`tools/abi.toml:693-695`），翻真须 abi.toml、ktest B 段、berry-sys abi_gen 三面同批同步。

## 体系总规格（终态契约）

### 配置递送三轨制

| 轨 | 承载 | 生命周期 | 现状 |
|---|---|---|---|
| 镜像定值 | rootfs 内 `etc/boot-params.toml`，内核 boot 期 cpio 定址读取 | 随镜像不可变 | 已落（`kernel/src/bootparams.rs`，消费 sched_slice_hz / intent_default） |
| 宿主注入 | fw_cfg `opt/berry/*` 具名键（20 键在册） | 单次启动有效，不跨 boot | 已落但键表无单源、极性无公约 |
| 可写持久 | FAT 数据盘卷根 8.3 文件族（SETTINGS.CFG 等） | 跨 boot 存活 | 半落（theme_io / layout_io 先例，数据盘每次重造抵消了持久） |

裁决依据：fw_cfg 递送产品配置已被 [2026-11-12-g5-bootparams 笔记](../notes/implemented/2026-11-12-g5-bootparams-kernel-consumer.md) 否决（EFI 路无 fw_cfg 具名文件 = 真机不可达），本计划沿用该裁决——fw_cfg 只做 QEMU 路宿主动态注入，不做产品配置通道。

### 宿主留痕契约

- run 目录字段维持现结构（meta.json / state.json / serial.log / qemu.log / events.jsonl / vnc.*），本计划只改保留策略与加索引，不改字段。
- 保留策略：`berry run` / `berry shot` 失败（marker 未中、超时、QEMU 先退、取帧失败）自动 `run.keep()`，成功默认删；`--keep` 显式保留不变。
- 历史索引 `~/.berry/run/index.jsonl`：逐 run 追加 `{v,run,label,profile,started,end_state}` 单行 JSON；O_APPEND 单行写；**容忍不全**（宿主崩溃必漏记，枚举以扫目录兜底）；不复制 meta.json 已有字段，引用 run 目录。
- `events.jsonl` 维持单写者（`control.rs:669` 唯一入口），不开第二写者。

### 持久化契约（设备壳 profile 路径专属）

- 数据盘：berry 挂载侧已是复用制（`BERRY_DATA_DISK` 非 snapshot 只挂不造，`qemu.rs:246-260`），改动只在 justfile 侧——造盘点从每次 `mkfat.py out/gui-data.img` 改为 `~/.berry/data/<profile>.img` 存在即复用；smoke/CI 路径保持每次重造。
- vars.fd：保持每次 blank 重造为默认（确定性优先）；可选持久模式（`~/.berry/vars/<profile>.fd` 存在即跳过）**默认关闭**、按 profile 分桶——跨 run 继承 UEFI 脏状态是特性开关不是默认。
- EFI 路语义分叉明示：`just run-efi` 与真机挂盘路无 fw_cfg，一切门键天然缺席；其持久配置通道 = 镜像定值轨（boot-params）+ FAT 盘（数据盘照挂）。

### 可观测契约

- 新内核日志行统一 `klog!(lvl, ...)` 宏形态：`[ns][I|W|E] msg` 整行单窗发射；存量 473 处 `uart_puts` 不强制迁移（渐进债）。
- 串口行首自动时间戳注入：默认关，fw_cfg `opt/berry/klog-ts` 键 opt-in——保护 smoke 逐行零漂移与 `tele:` 行首契约（`tools/advisor.py` 只认行首 `tele:`）。
- 客机自读面：内核静态字节环（镜像串口流）+ 0x84 `telemetry_open` 只读批读 + bsh `dmesg` 内建命令。
- marker 协议 `X ok n=` 与 smoke 断言面不动。

## 阶段计划

### 阶段一：止血——AI 取证面（三件小改动）

1. **B 族直跑日志落盘**：justfile 六入口（`run` / `run-el2` / `run-smp` / `run-rootfs` / `run-x86` / `run-efi`）的 QEMU 行外包 `2>&1 | tee out/logs/$(basename 该入口)-$(date +%s).log`。锚点：`justfile:441-445`（run）、`:446`（run-el2）、`:454`（run-smp）、`:516` 起（run-rootfs）、`:564`（run-release）、`:1235`（run-x86）、`:1715`（run-efi）。验证：每入口启动后 `out/logs/` 出现含启动 marker 的日志文件；smoke 面零改动零漂移。
2. **berry run / shot 失败自动保留**：`commands.rs` 的 `run()` 在 qemu 先退分支（`:169-177`）与超时分支（`:178-187`）的 `return Err` 前插 `run.keep()`；`shot()` 在 qemu 先退（`:248-251`）、超时（`:253-258`）、取帧失败（`:266-270`）三处 return Err 前与 png 写失败传播点（`:272`）补 keep。顺手修空 marker 文案（`:173-174`）。验证：`berry run --marker 不存在` 退出后 run 目录仍在且 serial.log 完整；成功路径行为不变（目录照删）。
3. **smoke 失败必留**：`tools/smoke.sh` 收尾段（`:313-326`）改为失败路径不 `rm -f` 串口日志与辅助日志（echod/evsclient/sktclient），打印保留路径；`SMOKE_KEEP_LOG=1` 语义不变。验证：人为注错跑 smoke，日志留在盘上且 stderr 报路径；绿跑行为不变。

### 阶段二：实例状态地基（客机可写持久层）

4. **数据盘复用制（justfile 侧）**：`just desktop` 的造盘行改前先查 `~/.berry/data/desktop.img`，存在即跳过 mkfat（BERRY_DATA_DISK 指向它）；首次缺席才 `mkfat.py` 造。锚点：`justfile` desktop recipe（`python3 tools/mkfat.py out/gui-data.img` 行）。验证：连续两次 `just desktop`，第二次客机可见第一次写入的 FAT 文件；`berry doctor` 报数据盘路径。
5. **vars.fd 可选持久模式（默认关）**：`qemu.rs create_vars`（`:352-360`）调用点（`commands.rs:208-209`、`device.rs:73-74`）加环境开关 `BERRY_VARS_PERSIST=<path>`——设了且文件存在即复用，否则维持 blank 重造。默认行为零漂移。验证：设开关连续两跑，UEFI 启动项修改留存；不设开关行为与今完全一致。
6. **存储布局 spec 补条目**：[../../docs/存储布局与沙箱设计-v1.0.md](../../docs/存储布局与沙箱设计-v1.0.md) §8 的 v1 现状行已增补「跨 boot 持久层 v1 落点 = FAT 数据盘卷根 8.3 文件族」条目（含旧 `SETTINGS.JSN` 迁移与 v2 迁树不迁语义的意图）。验证：spec 合入且 smoke/docs-guard 通过。
7. **首启标记**：实现为「配置档缺席即首启」——SETTINGS.CFG 缺席 = 首 boot（settings_io 三约束的缺席默认即首启语义），不设独立 FIRSTBOOT 标记件（少一件、语义等价；v2 迁树时同律）。验证随第 8 步：全新盘首启 settings 默认档可工作、复用盘读回。

### 阶段三：垂直切片——证明体系可用

8. **settings 六键落盘**：扩 `theme_io.rs` 为 settings_io（或并存），路径从 `SETTINGS.JSN` 升 `SETTINGS.CFG`（8.3 合规，卷根单段走 FAT 落盘面），canonical 从两键扩六键 JSON（wifi/bt/bright/sync/dark/layout，~60B 远小于 2048B 单簇帽）；`build()` 六初值改吃装载值（现字面量 `main.rs:423/447/491/519/545`）；`run()` 事件臂补 EV_WIFI / EV_BT / EV_SYNC 归集（现读取即弃，`main.rs:818-827`）+ close 即 commit 落盘（put_file 范本 `theme_io.rs:156`）。守住三约束：缺席默认 / 坏件自愈 / 写失败非致命；解析守「不自造第二套解析器」。验证：改开关、重启、值保持；坏档自愈回默认。
9. **bsh 读用户配置**：`interactive()` 开头（`main.rs:371`，Editor::new 前）读 `BSHRC.CFG`（卷根 8.3，k=v 行），注入 shell vars；fs 礼物缺席（fs_h()==0）静默跳过不死 shell；勿挂 main() 开头（fat 相 park 挡断）。验证：改 BSHRC.CFG 后新会话生效；无盘路零回归。

### 阶段四：宿主统一并轨

10. **run 历史索引**：`RunDir::create`（`run_dir.rs:38`）尾插 index.jsonl 追加行；run/shot 终态（成功删/失败留/超时）与 device stop（`device.rs:314,324` 的 state.json 口径对齐）各追加终结行。O_APPEND 单行写；容忍不全。验证：`berry logs --run <已退出id>` 可读（find_run 带 id 已支持死 run，`commands.rs:2216-2226`）；索引文件可被 `jq` 消费。
11. **find_run 自动发现修正**：无 id 自动挑最新时（`commands.rs:2228-2243`）的过滤条件从「有 vnc 端点文件」改为「索引在册或 meta.json 存在」，让 berry run 类 run 目录可被自动发现（现状它们永远进不了候选，核实风险 1）。验证：`berry logs`（无参）在仅有 run 类 run 目录时不再报 no running device。
12. **doctor 键差集报告**：先把宿主注入键抽成常量表（`qemu.rs:265-290` 的四键三条件），再给 `doctor.rs` Report 加 `fwcfg` 字段（静态推演将要构造的 argv，不真 spawn，守 no-side-effects）；区分「条件性缺席」（display 依 mode、accel 依非 TCG、rtc 依系统时间）与「该注未注」。验证：`berry doctor --json` 输出注入键清单；人为注错键可被差集暴露。
13. **与模拟器体验统一刀合流**：五入口统一时把「生成物统一」一并收口（B 族 tee 日志归档进 run 目录体系）；对齐方式与该方案 owner 协商，本计划不单方面改其刀口。

### 阶段五：可观测深化

14. **klog! 宏**：新增 `macro_rules! klog`（kernel 内），拼 `[ns][I|W|E] msg` 整行、单 PRINT_LOCK 窗发射；ns = `cntvct()` + `ticks_to_ns()`（boot 早期可用，16ns/tick，`timer.rs:202-280`）。新代码一律用宏；高价值路径（watchdog / DPG / power）渐进迁；panic / lockdep 绕锁通道不动。验证：新宏行带时间戳与级别；smoke 逐行零漂移（存量未动）。
15. **行首自动时间戳（opt-in）**：fw_cfg 新键 `opt/berry/klog-ts`（string=1 开）——`uart_putc`（`uart.rs:73`）行首检测注入 `[ns]` 前缀；行首状态 per-CPU（裸打路径不取 PRINT_LOCK，跨核共享状态会误判，核实风险 2）；默认缺席 = 零漂移。验证：开键后全量串口行带戳、`tele:` 与 marker 行的收割面不受损（advisor.py 认行首 `tele:`，故注入点必须在标记行首之前拼 ns 时保序——验收含 advisor.py 消费回归）；不开键与今逐字节一致。
16. **klog ring + 0x84 telemetry_open 翻真**：内核静态定长字节环（`static mut` + head/tail + lost 计数，RX_RING 同款先例 `uart.rs:153-166`），写点挂 uart_putc（与串口同序全量覆盖）；0x84 号翻真（abi.toml stage v3 → implemented、ktest B 段断言、berry-sys abi_gen 三面同批），先落 klog 快照 op 域（copy_out 先例 `syscall.rs:454`）；SwitchRec / WakeRec 环读口随后续波次补。验证：abi 三面同步绿；ktest 在册未实现断言不红。
17. **bsh dmesg 内建**：BUILTINS 名单（`bsh/main.rs:3389`）+ render_cmd（`:3408` 链）+ help 加 `dmesg`，经 0x84 读 klog 环尾部打 stdout（uptime `:3529` 同款 libc/syscall 消费先例）。验证：客机内 `dmesg` 可见本次启动以来的内核日志尾部；无 0x86 依赖。
18. **fwcfg-keys 单源**：`tools/fwcfg-keys.toml` 落键表全 20 键（键名 / 形态 string|file / 注入方与 spawn 点 / 消费方 / 极性），定极性公约（在位=开为默认，例外显式标注 noktest / demo-face / trace）；一键一注入方纪律成文；rwake 死键收编（补注入面或注记手拼专递）；两 spawn 点（`spawn_image` 注 4 键 vs `spawn_kernel` 零键，`qemu.rs:161-176`）行为差异入表。验证：键表与 `qemu.rs` 常量表、justfile 注入点三方对拍脚本零漂移；doctor 12 步的差集报告以本表为期望清单。

## 风险与已裁决事项

- **时间戳撕收割面**（阶段五最大坑）：`tele:` 行首契约与 smoke 逐行零漂移是硬约束——裁决为默认关 + opt-in 键 + 宏先行，存量 473 点零改动。
- **ABI 冻结**：0x84 翻真即公共 ABI，SwitchRec / WakeRec 定宽冻结先例在前；三面（abi.toml / ktest / abi_gen）不同批同步就是隐性漂移。
- **帽预算**：RAM 树 FILE_COUNT_MAX=9（8 用户 + 1 mtab）、DIR_COUNT_MAX=17（16 用户 + 1 etc，`fsproto/src/lib.rs:138-149`）——`/cfg` v2 预建要动保留槽记账并同步 fsproto 注释，否则静默收窄用户面。
- **8.3 大写名字空间**：FAT 面只认 `[A-Z0-9]` 单段（`berry-fatfs/src/lib.rs:447`），v1 全部配置文件名受此约束；LFN 不支持。
- **SeqRead 单流约束**：boot 序 rootfs 多卷拼装会话中不得插入任何 fw_cfg 访问（`fwcfg.rs:132`）——阶段五新键的内核读点必须排在既有位置惯例之外。
- **EFI 路语义分叉**：门键在 EFI 路天然缺席，产品配置已裁走 boot-params 轨；新增启动形态（VZ 层）沿用三轨制分工，不给 fw_cfg 加产品语义。
- **范围蠕变**：级别全量化 = 473 处逐点判级，明示为渐进债不在本计划承诺面。
