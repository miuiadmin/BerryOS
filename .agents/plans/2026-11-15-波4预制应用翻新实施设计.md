## 3. 横切件

### 3.1 启动序与 GUI 通道授权

- **裁决 A（GUI 通道授权，侦察 §二 缺口首裁）**：manifest `[capabilities]` 增 `ui = ["wm","input"]` 词（作用域字符串数组，`fs` 词同型文法）——svcmgr `app_launch` ui 词在场 = extra_gifts 在现 fs 双端（GIFT_H[0]/[1]）后随增两枚：wm 客户端端（WMD_CLI_DUP 同源 dup）+ inputd 端（INPUT_A 同源 dup，launcher_assemble :6935-6991 同柄纪律）；env gift 位序立法进 appshell crt0 解析（固定位、错位即 assert loud）；授权 = 持通道能力即权限（微内核纪律）。落选案：APP_SPAWN 应答随行 gift（应答通道单向、无法承载反向事件流）/ appshell 经 launcher 中继（launcher 成单点 Broker，违框架是库不是层）。berry-manifest 增量 = 新可选键（缺省 None = 现行为零漂移）；未知键拒策略在册（lib.rs:1108 `unknown key`）→ 含 ui 词新包遇旧 manifest 库 = bad manifest 拒载（本仓自产自销、rootfs 同批重造，无跨版场景，§5 如实）。
- **裁决 B（boot 批与常驻应用调和）**：现 boot 批全槽拉起 + 同步串行 reap（svcmgr main.rs:2107-2148）以秒退壳为前提——常驻 GUI 应用会挂死 boot；调和 = ui 词兼作批判别：全槽 bap_scan→manifest→双守卫照走，ui 词在场（七应用 + APPDEMO）→ 入册不拉起（串口诊断行小写形 `app <id> gui deferred`，非 marker 形态），无 ui 词（APPQUIET）→ 拉起 + reap 现状；`APP ok n=9` 保全（九槽全验语义不变、拉起子集收口），`APPUI ok n=` 同批零漂；附带收益 = boot 到桌面更快（七个 stub 拉起收口退役）。
- **启动链（改造后）**：桌面点击 → launcher `encode_spawn_request`（frameloop.rs:856）→ svcmgr `app_serve_spawn` 串行处置：注册表定位 → APP_SPAWN_LIVE_MAX=4 槽位预检（:7281-7299，满表 ACK err=1 不拉起）→ `p3_sig_guard` 装载期验签 → `app_launch`（ui gifts，裁决 A）→ `spawn_rootfs_elf` → ACK 先发（M-C 真异步形，回执不冻 echo/监督）→ app crt0 → appshell 建窗（CREATE AVOID_SYS 或 IMMERSIVE）→ 首帧 SUBMIT。**<2s 预算** = 点击至首帧，TCG/HVF 双档判读（HVF 权威档、TCG 参考档，总纲 :34 TCG 慢速风险条对仗）；启动期 fs 读限一次（conf 键读），FAT RPC 串行链延迟实测记账。
- **监督回收与满槽反馈**：应用根页 back = 优雅退出（exit 0 + 窗 DESTROY + BACK_ACK）→ collect_eof 60s + reap 30s 异步收口 → `app_supervise` O(4) 表扫回槽（:7446-7456）；第五应用点击 = ACK err=1 → launcher 桌面短驻留提示条（Toast 同款形态、launcher 窗内 Overlay，新增小件）+ 不拉起；验收 = 四应用并存 → 第五拒 → 退一 → 第五可再开（槽真回收可判）。
- **/apps 预建时序**：launcher 启动 APP_LIST 真流收完后 → mkdir 循环（严格串行单会话，layout_io 纪律）；不等它出桌面首帧、失败非致命（§2.2 裁决）。
