# boot 事件细化刀 6 实施设计（服务级进度事件流）

Type: plan
Status: active
Updated: 2026-11-14

一句话说明：splash 图标模式的启动进度从 noktest 15 格（实际四态显示）细化到 26 格服务级——svcmgr 在既有 console 文本流上发结构化 SPLASH 事件行，guifbd 过渡屏解析驱动进度条与百分比，verbose 模式同一事件流天然滚日志（一事件流两投影）。

## 背景

owner 诉求（姊妹方案刀 6）：进度条「虚拟进度对应真实启动事件，越细越好」。现状离它很远：noktest 形态格序推演（splash.rs:136 只进不退）为 init 起画 2/15 → `step(9)`@kernel/src/main.rs:801 跳 11/15≈73% → `step(10)`@:856 12/15=80% → `step(13)`@:1704 15/15=100%——补位格 1/2/3（:808/:855/:885）全被无条件的 bench 格盖过成 no-op，条早早到 100% 后 guifbd 收尾帧（user/bins/guifbd/src/main.rs:915-918）清屏只留一行 `BerryOS starting...`，桌面首帧前数十秒静止。设计输入：调研 [BOOT-01 启动视觉与事件驱动进度业界深研](../../research/BOOT-01-启动视觉与事件驱动进度业界深研-2026-11.md) §五裁决（铁律 1 同一事件流两种投影；事件锚点 + 显示端整形；单调不回退、结束必达 100%；Android 退出补满判例；分段所有权）；落点侦察 `KNIFE6-RECON`（`.dsh-worktrees/boot-events/KNIFE6-RECON.md`，仓外 worktree 文件不入链）（基线 worktree wip/boot-events-knife6 @ 7fd1709c，本文 file:line 均相对该 worktree 根）。实施只在 worktree 做，主树不碰。

## 目标

- noktest GUI 形态总格 26（骨架区间 22-26 取上沿），全链可见爬升 ≥20 格：内核相位格 1-7 + 服务级事件格 8-25 + 终局补满格 26。
- 手段零新通道：svcmgr 各服务 ready 点在既有 console 流上发一行结构化事件 `\x01SPLASH <累计格> <label>\n`；内核 task_console fan-out（kernel/src/main.rs:3259-3277）原样转发零改动；guifbd `poll_console`（guifbd main.rs:375-408）加前缀解析分支驱动过渡屏。事件字节本就全部到达 guifbd（GUI 模式 :399-401 只是被视觉面丢弃），本刀补的就是消费端。
- 同一事件流两种投影：splash 形解析事件驱动进度条 + 百分比；verbose 形该行剥离控制前缀后作为日志自然滚动。
- 侦察裁决吸收：noktest 内核编号须理顺（bench 格挪门内 + 调用点重编号 + 少量新增内核相位格），splash.rs 本体零改动。

## 事件行协议

- 行格式：`\x01SPLASH <累计格十进制> <label>\n`；前缀控制字符定 `\x01`（SOH）——纯可打印前缀（侦察示例 `EV `）有与普通日志撞形的理论面，SOH 一字节即消歧，且内核 verbose 镜像的行缓冲只收可打印区（splash.rs:161-166）不会渲染出乱码；guifbd verbose 投影剥掉 `\x01` 后整行照滚。
- `<累计格>` 为 26 格制的绝对值（1-26），非增量；guifbd 只接受大于当前值的行（clamp 天然 never-decrement），同格多事件（见词汇表 25 格三事件）为合法的粒度外信息行。
- `<label>` 小写 kebab-case、无空格、长度 ≤24；发射一律在对应 ready 的 Ok 路（`eco:` 降级路不发射）。
- 载体与顺序：发射走各进程既有 `send_retry(console)` / `println!` → task_console → 串口 + fb pipe（guifbd）双扇出；fb pipe 为 best-effort（满丢 + fb_drop 计数），丢行只损该格粒度（条在下个事件跳 2 格），单调性与终值不受损——进度语义不建立在可靠传输上。
- 互非子串纪律：label 与整行不得包含任何现役标记字面（`SVC ok`、`BLKD ok n=`、`FBW ok`、`FBSERVE ok`、`GFX ok`、`GFXF ok n=`、`WM ok`、`LAUNCH ok`、`PAGE ok n=`、`BSH ok`、`ROOTFS ok src=`、`NET ok`、`INPUT ok`、`STD ok`、`EXIT ok` 等，tools/markers.sh:16/:23-24、tools/smoke-image.sh:187、tools/gui8-smoke.py:80-92 断言面）；小写 kebab 无 ` ok` 形态即结构性避开（grep -qF 大小写敏感）。
- 内核零新串口输出纪律保持：内核相位格仍走 `splash::step`（splash 形画条 / verbose 形 mirror 上屏，均不落串口）；串口上的 SPLASH 行全部来自用户态（svcmgr/guifbd/launcher）。

## 实施改造面

### 内核侧（kernel/src/main.rs，splash.rs 零改动）

只动调用点与 set_total 参数：两处新格（rootfs/user-image 插点）、五处 noktest arm 重编号（:1703 先例形态的 `if noktest { step(N) } else { step(旧号) }`）、bench 格挪门内、`set_total(26, 0)`。格制语义（只进不退、`min(total)`、disp 64 倍尺度、整帧重画）一字不动；插值泵不复活（7fd1709c 已删判例），进度细化全部由事件密度承担。

### svcmgr 侧（user/bins/svcmgr/src/main.rs）

加 `boot_ev(console, cell, label)` 帮助函数（栈上拼 `\x01SPLASH <cell> <label>\n` + `send_retry`，eco_skip :897-908 同款无堆形态），按词汇表插 16 个发射点。svcmgr 自身可观测的 ready 全部覆盖；guifbd/wmd 内部就绪与 launcher 首帧由消费方自发射（13/14/17/25 desktop-tree/26）。

### guifbd 侧（user/bins/guifbd/src/main.rs）

- 过渡屏自绘：:915-918 收尾帧改为 `draw_boot_screen(cell, label)`——`write_volatile`/行 `copy_nonoverlapping` 直写 FB_VA（px() :106-111 与 SUBMIT 行直写 :595-601 先例）画 8×8 B 点阵 logo + 进度条槽与填充，几何沿用内核口径（bar_w=w*7/10、bar_h=max(h/150,8)、y=h*2/3、x=(w-bar_w)/2、logo cell=max(w/60,3)、ly=h*2/5-4*cell、TRACK=0xFF2A2A2E/WHITE，对齐 splash.rs:292-317）；文案与百分比走 `con.put_str`（fbcon 8×16 文本，如 `BerryOS starting...` 与 `<pct>% <label>` 两行，pct=cell*100/26）。不给 berry-fbcon 加 rect API、不动 present/wmd 协议。初始 seed = 7（内核段末格，静态契约）。
- 事件解析：`poll_console` 加行组装缓冲（256B 消息可能含多行/半行），按 `\n` 切行后判 `\x01SPLASH ` 前缀；命中且格值大于当前 → 更新 + splash 形整屏重画（本相位独占屏幕，blit 未到，无 damage 面）；不命中则维持现状（splash 形不上屏——防盖桌面纪律 :397-401 保持）。Srv 增补状态：模式（splash/verbose）、累计格、armed/done 旗、行缓冲。
- 终局状态机（Android 补满判例）：解析到 `desktop-tree`（格 25）置 armed；armed 后首个 present SUBMIT 在既有 blit 前先发 `\x01SPLASH 26 desktop-frame` 行 + splash 形画满格帧（先画后 blit，同一 handler 内，满格帧至少可见一个刷新周期）再揭幕，置 done；`LAUNCH ok` 行到达即置 done（兜底——desktop-tree 行被 fb pipe 丢弃时，splash 形条停在 96% 由 blit 覆盖无害，verbose 形靠它停绘防滚日志盖桌面）。armed 前的 SUBMIT（gfxdemo 自测帧）照旧不触发。present 路先于 console 路轮询（:953-960）的竞态窗内，launcher 帧回调后紧邻 `LAUNCH ok`（frameloop.rs:522-530 串行于下一帧 SUBMIT 前），不会出现满格帧盖桌面。
- verbose 投影（gui_mode6==2）：guifbd main.rs:915 区加交接动作——清屏一次 + 锚行 `[berry] services console`（对称内核首行锚 kernel/src/main.rs:476），此后 poll_console 全量 `put_str` 续滚（剥 `\x01`），done 后停绘交桌面。内核段（mirror 滚屏至 :865 detach）与 guifbd 段构成 EFI 首行到桌面首帧的全程滚动；detach 到 guifbd 首行之间为静态内核残屏（非黑屏、时长为内核镜像装载段）。

## 验收

- TCG boot 串口可见 ≥20 个 SPLASH 事件行（`grep -a -c $'\x01SPLASH'` ≥20，健康 boot 全事件路径）。
- splash 形进度条多格爬升非两档跳：noktest 目标形态全程 26 格、单步最大跳 1 格（丢行容错下至多 2 格）；截图非黑屏。
- verbose 形 EFI 第一行到桌面首帧全程滚日志无黑屏空白段（交接一次清屏为视觉接续）。
- smoke 既有门零回归：`just smoke`/`just smoke-image`/`just gui8-smoke` 全绿，现役服务标记一字不动，新增行守互非子串纪律。

## 边界与禁区

- 与姊妹七刀方案（[模拟器体验统一分刀方案](./2026-11-14-模拟器体验统一分刀方案.md)）的分工：刀 1 管入口统一与 splash 双模式合入（宿主面），本文只做刀 6 的 boot 事件半件（guest 面事件流与进度细化）；OOBE 半件依赖刀 3 berry-ui 组件层，另案不在本文。
- 禁区遵守：不新增内核 syscall/ABI/邮箱（事件行复用既有 console 通道与 fb pipe，fbinfo VMO 48B 六域布局不动）；不复活插值泵（无定时器，纯事件驱动）；kernel/src/splash.rs 格制语义零改动（只动 main.rs 调用点）；不碰主树任何文件（实施只在 worktree）。
- 已知边界一：ktest∧GUI 组合（今日 smoke-image/gui8-smoke/desktop，EFI 路无 noktest 键 ktest 照跑）交接处有一次 46%（11/24）→27%（7/26）的视觉回落——非本刀验收面；根因是 berry CLI GUI 入口不注 `opt/berry/noktest`，缓解归刀 1 入口面（见未完成事项）。
- 已知边界二：fb pipe best-effort 丢行时粒度受损（条跳 2 格）、极端连丢时 verbose 停绘依赖 `LAUNCH ok` 兜底；两者皆不破坏单调性与揭幕正确性（blit 本身零协议）。
- 已知边界三：guifbd 自验三步（:866-907）会短暂覆写内核 splash 后由过渡屏重画（既有行为，不另处理）；过渡屏百分比用 fbcon 文本，与内核 HD 字模存在交接字体降级（HD 共享化挂账）。
