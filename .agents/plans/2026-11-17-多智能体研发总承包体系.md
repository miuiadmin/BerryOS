## 背景

仓主 mandate（2026-11-17）：全权代管 BerryOS 研发——产品、软件总管、研发负责人一体；操纵 DSH 与 Claude Code，用 goal / workflow / plan 模式拆解任务、多线派工、派人评审与核代码。

这不是从零发明：本仓已有多 lane 实战存量——仓根 lane 交付物（A / C / DARK / PORT / SPRING / W3A / W4 等八波以上，RECON / IMPL / VERIFY / REVIEW 四角色形态），[berryos-dev 技能](../skills/berryos-dev/SKILL.md) §四 §五 已沉淀并行纪律与 workflow 判例；[AM 域落地笔记](../notes/implemented/2026-11-08-am-domain-landing.md)与[波 3 appshell 笔记](../notes/implemented/2026-11-15-波3-berry-appshell抽取落地.md)记录了流水线裸奔窗口与共享树清场两类事故的修法。本件把散落判例收编成组织、流水线与门禁，并判定 DSH 插件可行性。

## 组织编制

| 角色 | 载体 | 职责 | 护栏 |
|---|---|---|---|
| 总办 | DSH 主线会话 | 立项、分刀、派工、集成、终验、统一提交、文档落账、goal 续航 | 提交权集中；agent 交付必复核 |
| 侦察科 RECON | DSH subagent（只读） | 现场解剖、行号锚点、对账裁决输入 | 禁写代码；产出带行号级证据 |
| 实施科 IMPL | DSH subagent 或 Claude Code 无头（`claude -p`） | 按任务书落码 | 文件域白名单；独立 worktree；禁 push |
| 评审科 REVIEW | 跨引擎对评 | 对抗性代码评审 | 异构模型互评（Claude 评 DSH 产出、反之亦然）；只报证据 |
| 核验科 VERIFY | DSH subagent | 分层验证链实跑、日志取证 | 断言须实跑，禁假设形态 |
| 审计科 AUDIT | DSH subagent | 文档账实、状态链、check-docs | 只读 |

并发帽由总办按波裁：重构建 lane 初帽 2-3（TCG boot 3-10 分钟且宿主负载敏感），只读 lane 放开。

## 调度机制

- goal 模式：长目标建档跨轮续航，试点波点火时建，objective 为波交付物清单。
- workflow 模式：大扇出（审计、多文件核验）；脚本按 berryos-dev 技能 §五形态写——parallel() 失败项串行 await 补跑，全灭换 subagent 通道；模板字符串转义坑照技能条 20。
- subagent / subagent_fork：单点深任务；fork 用于需继承本对话上下文的分叉。
- Claude Code 无头：`claude -p --permission-mode acceptEdits` 形态（2026-11-17 实测在装）；CLAUDE.md 与 .claude/skills 桥为符号链接已验，worker 直接吃本仓规则与技能。
- todo_write：波内看板，站间流转以看板为准。

## 流水线（一刀的七站生命周期）

1. 立项：总办写波计划入 plans/——分刀、文件域矩阵、验证判据。
2. 侦察：RECON 只读解剖，产出 `<WAVE>-RECON.md`（仓根惯例位）。
3. 定刀：总办按侦察锚点出每刀任务书——目标、文件域、禁令、验收。
4. 实施：多 lane 并行，每 lane 独立 worktree + 隔离 CARGO_TARGET_DIR；产出即落盘即提交（worktree 内、显式路径）——封 AM 域笔记的裸奔窗口。
5. 评审：跨引擎对评，产出 `<WAVE>-REVIEW.md`；high 项回炉。
6. 核验：验证链快到慢——fwcfg-check / abi-check / check-docs 秒级，berry CLI 测试与 just test-host 分钟级，SMOKE_PHASES=boot 与 just build 十分钟级；rootfs 相与长跑只在低载窗（口径见 berryos-dev 技能 §三）。
7. 集成落账：总办合并集成分支、统一验证、显式路径提交（AGENTS 规则 7 全条），note 与状态翻转同批。

门禁：无任务书不开工；无 RECON 锚不定刀；无 VERIFY 证据不合入；无总办复核不提交；产物归属地先于落笔——工具链产物不进产品仓（2026-11-17 判例：berryos-orchestra 插件曾误入本仓 tools/，同日迁出独立成仓 ~/Documents/code/berryos-orchestra）。

## DSH 插件判定（回答「能不能做 dsh 插件」）

能，机制已在，以下 2026-11-17 实查：

- DSH 自述为「插件束补丁层叠栈」；profile 目录（`~/.dsh/profiles/acp/`）是 pnpm 工作区，package.json 的 `dsh.profile.bundles` 列 @deepseek-ai/dsh-base、@deepseek-ai/dsh-acp-app、@jacklika/dsh-memory 三束。
- `dsh plugin --profile <name> add <pkg>` 装、remove 卸，pnpm 代管。
- 第三方插件先例在装：@jacklika/dsh-memory 一族（含 dsh-tool-* 工具束），本会话记忆库工具即其所供。
- 补丁层 cordis.patch.yml 为整条替换语义；`dsh --profile acp --dump-config-schema` 可枚举条目形态（id / name / config / inject / isolate）。

未核实（Phase 2 spike 项）：插件能否注册会话 skills、子代理模板或 MCP 服务。二期提案：`berryos-orchestra` bundle——装进 acp profile 即得 berryos-dev 技能、波任务书模板、验证链 runner；spike 先花一日吃透 entry 类型全集，再做最小束走通装载。

## 成功判据

- 试点波七站产物齐备（RECON / 任务书 / REVIEW / VERIFY / note），合入主线且验证链全绿。
- 并行 lane 零未授权越权（git log 逐文件归属核全过）。
- 主线复核暴露的问题全部闭环后才合入。
- Phase 2：最小 bundle 在 acp profile 装载成功且贡献至少一个可用面。

## 适用边界

- workflow parallel() 不稳是常态，串行兜底为既定形态，不算事故。
- 时序断言在宿主高载下属环境面，长跑只排低载窗；环境面判定须对照证据。
- agent 评审降险不免险：终审与提交权集中在总办。
- token 成本随 lane 数线性上涨：lane 数服务于波目标，不追「越多越好」。
