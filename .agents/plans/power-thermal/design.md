# power-thermal（有向图优雅关机编排、每应用毫安时能耗归因账本与多温区热失控闭环）总体设计

Type: spec
Status: active
Updated: 2026-11-18
Version: 1.0.0

一句话说明：`power-thermal`（由整机电源与能耗守护进程 `powerd` 2.0、多温区闭环热管理服务 `thermald` 2.0 及电池健康度引擎组成）终结早期无门控直接断电与粗放调频状态——建立「零丢数有向图优雅关机重启、精确到每个应用的毫安时功耗账本、80% 旁路长寿充电与六级平滑热保护闭环」。

## 背景

[全栈 25 模块跨界接缝与深水区六盲点复核审计](../../research/2026-11-18-全栈25模块跨界接缝与深水区六盲点复核审计.md) 对照 [abi.toml](../../../tools/abi.toml) 查明：现役 `0x88 power_off` 处于无门控直调 PSCI `SYSTEM_OFF` 裸奔状态，一旦文件服务与数据库处于活跃写入中途点击关机即等同于暴力拔电源；同时存量 `berry-power` 与 `berry-thermal` 仅具调度利用率拉取骨架，尚缺面向用户的每应用 `mAh` 能耗归因排行榜、异常耗电哨兵、电池健康度估算与多子系统协同热降级闭环。本规格依据 [跨模块 ABI 合龙与进程外 JIT 及深水区六子系统裁决](../../notes/proposed/2026-11-18-跨模块ABI合龙与进程外JIT及深水区六子系统裁决.md)，立定旗舰级电源与热控契约。

## 范围

- **覆盖**：收紧 `0x88 berry_power_off` 与新增 `0x8A berry_system_suspend`（支持 S3 深睡、正常重启与带 `boot_reason` 切入 `BerryRecovery` 重启）的 `PowerResourceCap` 唯一门控；五阶段有向图限时优雅关机与重启编排协议；基于硬件能效表（`berry-em`）与外设占用记账的每应用 `mAh` 功耗归因账本与后台偷电熔断哨兵；库仑计电池健康度建模、自适应夜间慢充与 80% 桌面旁路供电护电池策略；NTC 多温区 PID 滤波与跨 CPU/GPU/AI/屏幕/充电六级热失控保护闭环。
- **不覆盖**：CPU 单次选核的 EAS 边际能量计算数学（归 [sched-rt-gfx 总体设计](../sched-rt-gfx/design.md) 与 [调度器设计](../../../docs/调度器设计-v1.2.md)）；板级单个 LDO/Clock 寄存器门控细节（归 [soc-peripherals 总体设计](../soc-peripherals/design.md) `plat-pm`）。

## 契约

### 一、唯一门控与五阶段有向图限时优雅关机/重启契约

```mermaid
flowchart LR
    Req["用户双击关机 / 低电保护 / OTA 重启请求"] --> P1["阶段 1 (≤150ms): 合成器播关机过渡动画 + appd 冻结后台并通知前台应用保存 64KiB 墓碑"]
    P1 --> P2["阶段 2 (≤300ms): audiod 静音斜坡防爆音 + netd 优雅挥手 + keystored 封存计数器"]
    P2 --> P3["阶段 3 (≤400ms): powerd 抽取新熵写入下轮 seed.bin + BerryFS 提交终态只读超级块"]
    P3 --> P4["阶段 4 (≤150ms): nvmed / vblk 向物理闪存下发硬件 CACHE FLUSH 屏障确认落盘"]
    P4 --> P5["阶段 5: powerd 凭唯一 PowerResourceCap 调用 0x88 power_off 或 0x8A system_suspend(Reboot)"]
```

1. **封堵任意进程越权断电**：废除 `0x88` 无门控历史例外——`0x88 berry_power_off(power_res)` 与 `0x8A berry_system_suspend(power_res, mode, arg)` 强制校验内核根派生的 `PowerResourceCap`（全系统仅 `powerd` 持有，普通应用或被攻破组件调用一律返 `-EBADF`/`-EACCES`）。
2. **硬时限防卡死兜底（总耗时 $\le 1.0\text{s}$）**：每阶段均设独立单调时钟死线；若某个顽固用户应用在阶段 1 超 150ms 未交回墓碑，监督器立即强杀不阻塞后续文件系统同步；阶段 3–4 保证 `BerryFS` 与块设备控制器 100% 完成写缓存落盘并将磁盘置为 `CleanUnmounted` 态，彻底根绝关机损盘与音箱「砰」声冲击。

### 二、每应用精细毫安时（`mAh`）功耗归因账本与电池寿命契约

1. **五维全栈能耗分摊模型（Battery Attribution Ledger）**：`powerd` 每 60 秒聚合一次全系统硬件功耗分量并精确归因到所属 `Job`（即每个应用与系统服务）：
   - **CPU 分量**：读取内核按频点（OPP）与簇统计的每进程周期账单，乘以 `berry-em` 各频点实测毫瓦系数 $\sum \text{cycles}_{p, f} \cdot P_{\text{cpu}}(f)$；
   - **GPU 与显示分量**：由合成器上报每应用本窗口触发的 GPU 着色微秒数及像素平均发光亮度（OLED 面板按子像素 APL 发光面积折算功率！）；
   - **网络与无线射频分量**：由 `netd` / `wifid` / `btd` 按实际唤醒射频尾态（Radio Tail）的收发包时间窗归因（揪出频繁发心跳包把基带拖在高功耗态的元凶）；
   - **AI 与多媒体分量**：由 `airtd`、`audiod`、`camerad`、`locationd` 按会话租约时长分摊 NPU、ISP 与 GNSS 功耗；
   - **系统设置可视化与异常熔断**：向「设置 → 电池」输出过去 24 小时 / 10 天精确到 `0.1 mAh` 的前后台耗电曲线；若某应用在息屏后台连续 15 分钟占用超过整机 3% 电量且无用户可见实时胶囊，`powerd` 主动推送高耗电告警卡片供用户一键关入严格深度冻结笼。
2. **电池健康度与旁路供电（Bypass Charging）**：结合库仑计充放电积分与开路电压内阻曲线实时估算电池最大可用容量百分比（Battery Health %）与循环次数；PC/平板长期插电办公或手机高负载游戏开启「80% 护电池 / 旁路直供模式」时，电源芯片直接由 Type-C 输入向主板供电而停止对电芯涓流浮充，从电化学根源延缓锂枝晶与鼓包老化。

### 三、NTC 多温区 PID 热失控六级平滑保护契约（`thermald` 2.0）

以外壳体感温度（Skin Temp $\le 43^\circ\text{C}$）与 SoC 结温（$T_j$）双闭环 PID 控制器驱动平滑无骤降的六级温控阶梯：

| 温控档位 | 壳温 / 结温典型阈值 | 系统级跨模块协同动作（滞回曲线防乒乓震荡） |
| :--- | :--- | :--- |
| `Nominal (0)` | $T_{\text{skin}} < 38^\circ\text{C}$ | 全核最高睿频开放、120Hz+ 满刷、`airtd` 满并发、满速快充 |
| `Light (1)` | $38^\circ\text{C}..40^\circ\text{C}$ | 暂停 `workmgr` 闲时索引与 `backupd` 后台云同步，快充功率下调 25% |
| `Moderate (2)` | $40^\circ\text{C}..42^\circ\text{C}$ | 限制超大核最高 OPP 频点上限 15%，`airtd` 后台批次减半 |
| `Severe (3)` | $42^\circ\text{C}..44^\circ\text{C}$ | 协同 [刷新率体系规范](../../../docs/刷新率体系规范-v1.0.md) 将高刷平滑锁顶 60Hz，面板峰值 HDR 亮度限幅 70%，停止电芯充电转纯旁路供电 |
| `Critical (4)` | $44^\circ\text{C}..46^\circ\text{C}$ 或 $T_j \ge 98^\circ\text{C}$ | 冻结一切后台应用、关闭移动热点与 5G 载波聚合退守基础通信，屏幕弹出高温降温提示 |
| `Emergency (5)` | $T_j \ge 108^\circ\text{C}$ | 立即记入持久故障原因并触发上述五阶段 **1 秒紧急优雅关机**，保护硅片与电池绝对物理安全 |

## 验收标准

1. **越权断电拦截与零损盘关机门禁**：普通用户进程直接调用 `0x88` / `0x8A` 100% 返回权限拒绝；在 50MB/s 文件持续写入中途触发 `powerd` 优雅关机，重启后文件系统超级块 `CleanUnmounted == true` 且零未落盘事务丢失，全程关机耗时 $\le 1.0\text{s}$。
2. **能耗归因守恒门禁**：各应用与系统服务分摊耗电量之和与库仑计总放电量误差在 $\pm 8\%$ 以内（未归属基带底噪单独透明列为「待机基础功耗」，严禁向应用虚摊假账）。
3. **温控阶梯闭环验证**：在模拟器通过 `sim` 通道注入连续升温与降温正弦曲线，`thermald` 严格按 0→5→0 档位平滑联动调度器频点帽、合成器刷新率帽与 `workmgr` 开关，零乒乓抖动；触及 `108°C` 时 1 秒内安全落盘关机。

## 适用边界

- 硬件级过温硬切断（如 $120^\circ\text{C}$ PMIC 纯硬件比较器直接拉低 `PS_HOLD`）由主板硬件电路独立保底，不受任何软件状态影响。
