# 终端与命令行全栈体验深度体检报告

Type: survey
Status: current
Updated: 2026-11-18

一句话说明：针对「不依赖图形界面，仅凭莓核微内核与命令行终端能否交付完整操作系统体验与全栈在机调试闭环」问题，对仓库控制台、Shell、启动协议、服务发现、libc I/O 及命令行工具链开展源码级逐行体检，定位 4 大域共 22 项阻断真人日常使用的结构性断层。

## 问题

在图形桌面尚处演进期的现实约束下，BerryOS 若收敛火力走「微内核 + 极致命令行工作站 / AI 原生沙箱 OS」路线，现役内核控制台、[bsh](../../user/bins/bsh/src/main.rs)、[berry-libc](../../user/berry-libc/src/io.rs)、[berry-exec](../../user/berry-exec/src/lib.rs) 与 [rootfs-manifest.toml](../../tools/rootfs-manifest.toml) 在真实人类交互操作、脚本自动化、文件编辑、网络通信与在机故障诊断上存在哪些精确代码级障碍。

## 方法与来源

基于 `main` 分支最新基线（含莓核 2.0 总体规格提交 `cb6165597`），对 [kernel/src/main.rs](../../kernel/src/main.rs)、[user/bins/bsh/src/main.rs](../../user/bins/bsh/src/main.rs)、[user/bins/bsh/src/editor.rs](../../user/bins/bsh/src/editor.rs)、[user/berry-libc/src/io.rs](../../user/berry-libc/src/io.rs)、[user/berry-exec/src/lib.rs](../../user/berry-exec/src/lib.rs)、[user/bins/ps/src/main.rs](../../user/bins/ps/src/main.rs)、[user/bins/berryctl/src/main.rs](../../user/bins/berryctl/src/main.rs)、[user/berry-complete/src/lib.rs](../../user/berry-complete/src/lib.rs)（及 `sched-1.1` 线 `berry-termio`）、[tools/rootfs-manifest.toml](../../tools/rootfs-manifest.toml) 与 [shell 设计](../../docs/shell设计-v1.1.md)、[可观测性设计](../../docs/可观测性设计-v1.0.md) 执行全量交叉审计。

## 结论

现役命令行栈虽已跑通自动化 smoke 自检（21 个内建命令、23 个 uutils 裁剪命令、基础管道与 `&&`/`||` 短路链），但其底层模型仍是「面向批处理自测的静态单路管道壳」，真人上机在 3 分钟内即会撞上以下四大核心瓶颈：

1. **控制台与伪终端层缺位（T1–T5）**：无用户态伪终端（PTY）与行规控制，内核线程逐字节发 IPC、128B 粘贴即丢字、无窗口尺寸（`winsize`）与 Raw/Cooked 切换、后台日志与前台 TUI 混流糊屏、单串口无法多开会话。
2. **进程 I/O 与服务发现断裂（N1–N5）**：外部子进程无 `stdin` 且 `stdout` 必须等进程退出攒满内存后才一次性打印（彻底阻断一切交互程序与流式实时输出）；`ps` 与 `berryctl` 因缺 `/svc` 命名空间服务发现在 `bsh>` 手敲直接报 `no svcmgr gift` 失败。
3. **Shell 词法语法与行编辑残缺（S1–S6）**：光标焊死行尾无法左移改字、历史仅 8 条且重启即失；无引号、转义、`${}`、`$()`、通配符、`2>&1`/`<` 重定向、函数与 `.sh` 脚本执行；内建命令无法进管道；无 `& / jobs / fg / bg / kill` 作业控制。
4. **终端生产力与在机调试工具链空白（U1–U6）**：无全屏编辑器与分页器，无法在机改写脚本或翻阅长日志；无 `free / top / lscap / btrace / bdbg` 在机观测与交互调试器；无 `ping / curl / nc / ip / ssh` 网络与跨机传文件命令；叠加莓核 v1 进程槽 64 硬顶与 Channel/页表泄漏，长跑脚本必触资源枯竭。

## 证据与出处

### 一、控制台与终端会话域（T1–T5）

- **T1（P0）内核线程 `task_console` 逐字节 `svc` 转发与 128B 粘贴丢字**：[kernel/src/main.rs](../../kernel/src/main.rs) 第 3545–3700 行在 EL1 内核线程内手调 `svc6(NR_CHANNEL_SEND, ..., 1)`，每输入 1 个字节发起一次系统调用推入深度 8 的 `bsh` 通道，仅靠 128 字节 `fring`（第 3574 行）缓冲；用户在终端粘贴超过 136 字节的命令或脚本片段时，`fwd_drop` 静默丢弃后续全部字节。
- **T2（P0）无用户态伪终端（PTY）主从抽象与 `termios / winsize` 契约**：全仓无 PTY 服务与控制协议，客户端程序无法查询终端行列尺寸（`TIOCGWINSZ` 等价物）、无法感知宿主终端缩放（`SIGWINCH` 等价事件）、无法在行缓冲回显（Cooked）与原始按键透传（Raw）模式间切换，导致全屏编辑器、分页器与 `top` 类 TUI 在架构上无法着陆。
- **T3（P0）全局单 `CONSOLE_H` 致内核日志、守护进程诊断与前台屏幕混流撕裂**：[user/berry-libc/src/io.rs](../../user/berry-libc/src/io.rs) 第 27–28 行与 [kernel/src/main.rs](../../kernel/src/main.rs) 第 3586–3658 行让全机守护进程、`stdout`、`stderr` 与内核诊断共用同一串口直写流，无备用屏幕缓冲（Alternate Screen）与 `klog` 静默分流机制，任何后台打印都会直接砸碎前台交互界面。
- **T4（P1）终端转义解释面仅支持极简行环，无 VT100 二维网格与色彩**：现役 [editor.rs](../../user/bins/bsh/src/editor.rs) 第 84–110 行与 `sched-1.1` 线 `berry-termio` 仅处理 `\b`、上下键与 `ESC[2J` 清屏，丢弃光标绝对定位（`ESC[row;colH`）、局部擦除（`ESC[K`）、滚动区与 ANSI 16/256/TrueColor SGR 属性，不支持全屏终端应用复用。
- **T5（P1）单串口物理链路无多会话复用器**：通过 `berry console`（[CLI-first 设计](../../docs/Berry设备平台-CLI-first设计-v1.9.md) 第 14 行）接入串口时只有唯一前台 `bsh` 实例，运行长耗时任务时无法切换第二窗口查看日志或杀进程。

### 二、启动协议、I/O 流与服务发现域（N1–N5）

- **N1（P0）`run_output` 剥夺子进程 `stdin` 且攒批阻塞 `stdout`**：[user/bins/bsh/src/main.rs](../../user/bins/bsh/src/main.rs) 第 3842–3865 行明文规定「子进程无 stdin（read 即 EOF）」且必须等子进程退出收齐 EOF 后才把 `Vec<u8>` 一次性写向终端，彻底封死一切交互式 CLI 程序及 `ping`、`tail -f`、`dmesg -w` 等流式持续输出场景。
- **N2（P0）缺 `/svc` 能力服务发现致 `ps` 与 `berryctl` 在交互终端必败**：[user/bins/ps/src/main.rs](../../user/bins/ps/src/main.rs) 第 42–46 行与 [user/bins/berryctl/src/main.rs](../../user/bins/berryctl/src/main.rs) 第 72–77 行硬依赖 `svcmgr` 自测时注入的 `gift2_h()` 一次性句柄；用户在交互式 `bsh>` 下执行 `ps` 或 `berryctl ps/mem/ver` 时 `gift2_h() == 0`，100% 报 `no svcmgr gift` 并以退出码 1 失败。
- **N3（P0）`GIFT_H` 位置槽高度过载与 `ARGV_STR` 256B 硬帽**：[user/berry-libc/src/io.rs](../../user/berry-libc/src/io.rs) 第 29–56 行将 `GIFT_H[6]` 同一物理下标在 `bsh`、`fsmgr`、`guifbd`、`gui-wmd`、`launcher` 间复用七重不同语义，且 `ARGV_STR` 硬限 256 字节、最多 16 个参数，展开稍长的文件列表即截断或失败。
- **N4（P1）`stdout` 与 `stderr` 同道无隔离**：[user/berry-libc/src/io.rs](../../user/berry-libc/src/io.rs) 第 5–6 行将 `fd 1` 与 `fd 2` 合并为同一 `CONSOLE_H` 别名，外部子进程的错误诊断与标准数据无法独立重定向（如 `cmd > out.txt 2> err.txt` 或 `2>&1`）。
- **N5（P1）持久化挂载树与工作目录契约割裂**：[文件系统设计](../../docs/文件系统设计-v1.0.md) 第 78 行记录当前 RAM 树上限 9 文件×16KiB、FAT12 根无子目录写与真删除，且无统一 `/bin`、`/etc`、`/tmp`、`/userdata`、`/dev` 虚拟挂载层级，环境变量与历史记录无法跨重启自然落盘。

### 三、Shell 语言、行编辑与作业控制域（S1–S6）

- **S1（P0）行编辑器光标锁死行尾且历史环仅 8 条**：[user/bins/bsh/src/editor.rs](../../user/bins/bsh/src/editor.rs) 第 24–26、96–103 行硬编码 `HIST_CAP = 8`、`LINE_CAP = 256`，除上下键外吞掉全部 CSI 序列（左右箭头、`Home`、`End`、`Delete` 全无效），敲错行首一个字符必须退格删空整行重打，无 `Ctrl-R` 历史搜索。
- **S2（P0）无统一词法分词器与引号/转义/展开体系**：[user/bins/bsh/src/main.rs](../../user/bins/bsh/src/main.rs) 第 3545–3624 行直接用 `strip_prefix` 与 `split_whitespace` 切词，不支持单引号 `'...'`、双引号 `"..."`、反斜杠转义、`${VAR:-def}` 参数展开、`$(cmd)` 命令替换、`$((1+2))` 算术求值与 `*` 通配符展开，连含空格的文件名或 `grep "foo bar"` 都无法表达。
- **S3（P1）内建命令被排斥在管道与输入重定向之外**：[user/bins/bsh/src/main.rs](../../user/bins/bsh/src/main.rs) 管道执行器 `do_pipe` 仅允许 `bin/` 外部 ELF 入段，`dmesg | grep err`、`env | sort`、`history | tail` 等最高频诊断组合全部报错不可用；同时缺少 `<` 输入重定向与 `<<EOF` Here-Doc。
- **S4（P1）无控制流语法、函数与 `.sh` 脚本解释能力**：`bsh` 仅支持单行命令与 `KEY=VALUE` 形态配置，不支持 `if/elif/else/fi`、`for/in/do/done`、`while`、`case`、Shell 函数、`source` 及 `#!/bin/bsh` 可执行脚本，用户无法在系统内编写自动化运维与测试脚本。
- **S5（P1）无后台作业与任务挂起/恢复控制**：缺少 `&` 后台启动、`jobs` 列表、`fg`/`bg` 前后台切换、`wait` 同步等待、`Ctrl-Z` 挂起（内核已有 `0x3E process_suspend` `SuspendToken` 却未接入 Shell）以及按作业号或进程 ID 的 `kill`。
- **S6（P2）`bsh` 自测逻辑与生产交互二进制耦合**：[user/bins/bsh/src/main.rs](../../user/bins/bsh/src/main.rs) 逾 6,700 行源码中超过 3,400 行为开机串行自测桩，子 Shell 须靠 `--no-selftest` 绕过，既拖慢交互拉起又增大常驻体积。

### 四、生产力、网络与在机调试工具链域（U1–U6）

- **U1（P0）零全屏文本编辑器与零交互分页器**：[tools/rootfs-manifest.toml](../../tools/rootfs-manifest.toml) 第 35–107 行无任何文本编辑器（`vi`/`nano`/`bed`）与分页器（`less`），用户在机内无法修改配置文件、编写脚本或翻阅超过一屏的 `dmesg`/崩溃日志。
- **U2（P0）零微内核能力内省与实时系统监控工具**：缺少 `free`（内存/VMO/Slab 水位）、`btop`（多核利用率、意图调度带、进程实时内存与 IPC 速率）、`lscap`（查看进程持有的 Capability 句柄、Rights、Badge 与对端连接拓扑）；微内核最核心的能力与调度优势在终端里处于黑盒不可见状态。
- **U3（P0）零在机系统调用追踪器与命令行交互调试器**：[devtools 总体设计](../plans/devtools/design.md) 规划了宿主机侧 `berry debug / perf`，但当用户纯靠串口或远程终端操作客机时，客机内缺少类似 `strace` 的实时系统调用/IPC 追踪器（`btrace`）、在机交互式断点与内存/栈检视器（`bdbg`）以及在机黑匣子解码器（`cboxctl`）。
- **U4（P1）零日常网络诊断与文件传输 CLI**：虽有 `vnet` 与 [net-conn 总体设计](../plans/net-conn/design.md)，但终端内无 `ip`、`ping`、`dig`、`nc`、`curl` 以及免重打镜像的主客机双向文件传输工具（`bscp`）与加密远程登录终端服务（`bsshd`）。
- **U5（P1）CLI 输出缺少统一 `--json` 结构化契约**：[user/bins/berryctl/src/main.rs](../../user/bins/berryctl/src/main.rs) 第 2 行明文挂账 `--json`，AI Agent 或自动化脚本在终端内调用系统工具仍需脆弱的字符串切割。
- **U6（P0）内核 v1 资源泄漏与硬顶制约长稳运行**：如 [莓核全核深度体检报告](2026-11-18-莓核全核深度体检报告.md) I1/I2/M5 所示，Channel 双端环引用泄漏、退出页表未全回收与 `PROCESS_MAX = 64` 静态上限会导致重度 Shell 脚本循环在百次派生后耗尽物理帧或进程槽，终端上层完备化必须以莓核 2.0 底座落地为先决地基。

## 适用边界

本报告聚焦「纯内核 + 命令行终端全栈自给自足操作与在机调试体验」的代码事实核查；对应架构裁决见 [终端优先全栈闭环架构六大核心裁决](../notes/proposed/2026-11-18-终端优先全栈闭环架构六大核心裁决.md)，分模块契约见 [pty 总体设计](../plans/pty/design.md)、[bsh 总体设计](../plans/bsh/design.md) 与 [cli-suite 总体设计](../plans/cli-suite/design.md)。
