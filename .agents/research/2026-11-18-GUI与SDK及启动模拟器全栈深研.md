# BerryOS GUI、SDK、显示合成、开机引导与模拟器全栈深研

Type: survey
Status: current
Updated: 2026-11-18

一句话说明：对 BerryOS 现行用户面与开发者面全栈（显示渲染与窗口合成、应用 SDK 与 UI 引擎、开机引导与服务编排、桌面壳层、虚拟机启动与宿主模拟器）进行源码级只读审计，锁定 36 项结构性缺陷与实现漏洞，作为终态重构的事实底册。

## 问题

在微内核与调度底座推进重构的同时（见 [全栈架构与代码缺陷深研](2026-11-18-全栈架构与代码缺陷深研.md)），BerryOS 的图形界面、应用 SDK、开机体验、桌面启动与宿主模拟器仍停留在单应用验证期的过渡形态。本调研回答三个核心问题：现行代码从上电、虚拟机启动、服务拉起、帧合成渲染到应用开发的真实数据流与控制流是什么；哪些缺陷属于局部实现漏洞、哪些属于无法靠打补丁修复的底层架构死胡同；迈向 120fps 真多窗合成与现代化应用生态的量化瓶颈在哪里。

## 方法与来源

只读核查当前主工作树全部相关源码与现行规范文档，遵循 Curia 状态解析纪律（先核头块 `Type:` 与 `Status:`，不将规划态目标当作已落地现状）。核查范围覆盖引导器 [lib.rs](../../bootloader/berryboot/app/src/lib.rs)、内核早启显示 [splash.rs](../../kernel/src/splash.rs)、根服务管理器 [svcmgr/main.rs](../../user/bins/svcmgr/src/main.rs)、显示服务 [guest.rs](../../user/bins/guifbd/src/guest.rs)、窗口管理器 [gui-wmd/main.rs](../../user/bins/gui-wmd/src/main.rs) 与 [table.rs](../../user/bins/gui-wmd/src/table.rs) 与 [relay.rs](../../user/bins/gui-wmd/src/relay.rs)、输入驱动 [gui-inputd/main.rs](../../drivers/bins/gui-inputd/src/main.rs)、图形光栅库 [raster.rs](../../user/berry-gfx/src/raster.rs)、UI 引擎 [berry-ui/lib.rs](../../user/berry-ui/src/lib.rs) 与 [paint.rs](../../user/berry-ui/src/paint.rs) 与 [anim.rs](../../user/berry-ui/src/anim.rs) 与 [pattern.rs](../../user/berry-ui/src/pattern.rs)、应用壳层 [pump.rs](../../user/berry-appshell/src/pump.rs)、C 运行时句柄层 [io.rs](../../user/berry-libc/src/io.rs)、桌面与代表性应用（[berry-launcher/main.rs](../../user/bins/berry-launcher/src/main.rs)、[frameloop.rs](../../user/bins/berry-launcher/src/frameloop.rs)、[settings/main.rs](../../user/bins/settings/src/main.rs)、`settings-app/main.rs`（件已移除——合并死链清偿）、[berry-term/main.rs](../../user/bins/berry-term/src/main.rs)）以及宿主模拟器 CLI（[qemu.rs](../../tools/berry/src/qemu.rs)、[window.rs](../../tools/berry/src/window.rs)、[ram.rs](../../tools/berry/src/display/ram.rs)）。

## 结论

### 一、跨层头号致命架构病灶（IPC 会话与能力注入层）

1. **多客户端共享单一 WM 通道导致 RPC 应答互截（D-IPC-01）**：`svcmgr` 仅创建一对窗口管理通道，将同一客户端端点 `WMD_CLI_DUP` 直接 `berry_handle_duplicate` 分发给 `berry-launcher` 与所有带 `[ui]` 节的应用（[svcmgr/main.rs](../../user/bins/svcmgr/src/main.rs) `:824, 1477, 6834-6853`）。内核通道为无连接双端 FIFO，`berry-guiproto` 无请求相关性 ID 且无每客户端独立会话通道；当桌面进程（如时钟刷新或导航键查表）与前台应用并发发起 `WM_*` 或 `SUBMIT` RPC 时，双方请求混入同一队列，谁先调用 `recv` 谁就截走对方的应答帧，直接引发解析错误与进程挂死（[guest.rs](../../user/bins/guifbd/src/guest.rs) `:108-111, 1334-1336` 注释已证实此缺陷阻断多应用并发）。
2. **多客户端共享单一输入通道导致事件抢夺与定向路由缺位（D-IPC-02）**：`svcmgr` 同样将单一输入客户端端点 `INPUT_A` 复制给桌面与所有 GUI 应用（[svcmgr/main.rs](../../user/bins/svcmgr/src/main.rs) `:6835, 6864`）。后台桌面未停止 `INPUT_POLL`，与前台应用在同一队列争抢指针与键盘帧，造成手势 `DOWN` 与 `UP` 跨进程撕裂；同时 `gui-inputd` 虽拉取窗口表执行 `wm_hit_test`，却仅累加内存统计计数而不改变出向路由（[gui-inputd/main.rs](../../drivers/bins/gui-inputd/src/main.rs) `:790-831`），键盘事件亦无焦点窗口门控（[pump.rs](../../user/berry-appshell/src/pump.rs) `:168-175`）。
3. **`GIFT_H` 4 槽位置编码触顶且极易引发句柄类型混淆（D-IPC-03）**：启动协议靠单条 `env` 消息随行最多 8 枚句柄（4 枚固定基础柄 + 至多 4 枚 `extras`，[io.rs](../../user/berry-libc/src/io.rs) `:29-51`）。因缺乏类型化标签，带 `fs` 能力的 GUI 应用布局为 `[rootfs, fs, wm, input]`（WM 在槽 2 `wm_present_h()`），不带 `fs` 的应用竟将 WM 放在槽 0（`wm_cli_h()`）并重复复制两份 WM 句柄填塞槽 1/2 占位以凑齐槽 3 的 `input`（[svcmgr/main.rs](../../user/bins/svcmgr/src/main.rs) `:6836-6900`）。应用一旦增删 `fs` 权限就会把 VMO 误作 Channel 发送导致崩溃（[berry-term/main.rs](../../user/bins/berry-term/src/main.rs) `:24-27`），且 8/8 满载彻底锁死了同时授予网络、电源、音频等能力的空间。
4. **`gui-wmd` 单线程同步中继导致全系统窗口管理队头阻塞（D-IPC-04）**：`gui-wmd` 在 `relay::relay` 中采用单线程同步阻塞转发 `present/hdi` 请求并死等 `guifbd` 应答，超时帽高达 300 秒（[relay.rs](../../user/bins/gui-wmd/src/relay.rs) `:34, 64-117`）；在途帧等待期间，`gui-wmd` 无法处理任何窗口查询、焦点切换或返回键超时兜底。
5. **窗口表无客户端身份鉴权（D-IPC-05）**：`WmTable` 的窗口项不绑定创建者会话身份（[table.rs](../../user/bins/gui-wmd/src/table.rs) `:57-71`），任何持有共享 `wm_cli` 句柄的进程均可伪造 `wid` 销毁或篡改任意其他应用的窗口，也可随意创建 `WM_LAYER_SYSTEM` 系统级置顶窗。

### 二、显示服务与窗口合成管线缺陷（`guifbd` / `gui-wmd` / `berry-gfx`）

6. **无每窗口离屏后备缓冲的“单帧缓冲直写 + 系统带重放”伪合成（D-DISP-01）**：`guifbd` 不维护每窗口独立表面纹理，仅持有一块全局物理扫描缓冲与顶/底系统栏条带缓存（[guest.rs](../../user/bins/guifbd/src/guest.rs) `:100-116, 1288-1390`）。应用提交时直接覆写全局帧缓冲再把系统栏像素盖回，导致非全屏浮窗移动、多应用重叠遮挡恢复、窗口缩放/淡入淡出转场与实时多任务缩略图在架构上不可实现。
7. **全屏尺寸 VMO 强制分配造成巨额物理内存浪费（D-DISP-02）**：无论窗口实际有效尺寸多大，现行客户端骨架（[pump.rs](../../user/berry-appshell/src/pump.rs) `:220-226`、`settings-app/main.rs`（件已移除——合并死链清偿） `:148-157`）一律按全屏物理分辨率（1080×1920×4 ≈ 8.29MB）创建并提交帧 VMO；仅桌面与 4 个并发应用的表面缓冲即消耗逾 41MB 内存。
8. **合成侧逐行系统调用拷贝而非共享虚拟内存映射（D-DISP-03）**：`guifbd` 读取客户端提交的帧 VMO 时未使用 `berry_vmar_map` 建立只读共享映射，而是通过 16KB 行弹舱 `bounce`（`ROW_BOUNCE_MAX = 16384`，且锁死了 > 4096px 宽度的分辨率扩展）逐行发起 `berry_vmo_read` 系统调用拷入内核再拷回用户态（[guest.rs](../../user/bins/guifbd/src/guest.rs) `:197-200, 577`）。
9. **单缓冲深度 `≤ 1` 同步串行提交阻塞渲染流水线（D-DISP-04）**：客户端每帧严格串行执行 `SUBMIT → FRAME_CALLBACK → RELEASE` 三次同步 IPC 往返，在途帧恒 `≤ 1`（[pump.rs](../../user/berry-appshell/src/pump.rs) `:18-20, 31-35`），应用 CPU 下一帧绘制与显示端扫描/传输完全无法双缓冲重叠。
10. **全管线缺失 8-bit Alpha 混合与抗锯齿原语（D-DISP-05）**：`berry-gfx` 软光栅将 `0xAARRGGBB` 的 Alpha 通道退化为 `A != 0` 的 1-bit 透明键（[raster.rs](../../user/berry-gfx/src/raster.rs) `:414-420, 452-458`），无预乘 `SrcOver` 混合、无渐变画刷、无高斯阴影或背景模糊，圆角采用无覆盖率权重的整数牛顿阶梯内缩（[raster.rs](../../user/berry-gfx/src/raster.rs) `:34-45, 128-186`），斜线与圆弧锯齿明显，PNG 半透明边缘经 BYI1 编码后退化为硬边杂色。
11. **软光栅热路径逐像素标量边界重检开销巨大（D-DISP-06）**：`fill_rect` 与 `fill_rect_rounded` 在已完成 `rect.intersect(clip)` 裁剪后，内层循环仍逐像素调用 `put_px`，对每个像素重复执行 6 次边界比较、`usize::try_from` 转换与 4B `to_le_bytes` 拷贝（[raster.rs](../../user/berry-gfx/src/raster.rs) `:85-186`），无行级 `u32` Span 填充与 SIMD 向量化；`smooth_argb_blit` 每像素执行 `i64` 除法（`:540-582`），1080p 全幅耗时达 ~13.7ms。
12. **系统栏几何常量跨多仓文件手工同步易漂移（D-DISP-07）**：状态栏 117px 与导航栏 135px 分别散落在 `berry-appshell`、`berry-launcher` 与 `guifbd`（[guest.rs](../../user/bins/guifbd/src/guest.rs) `:224-233`、[桌面沉浸式设计规范-v1.0.md](../../docs/桌面沉浸式设计规范-v1.0.md) `:89-100`），无协议级动态 `Insets` 单一事实源，曾多次引发像素/vp 单位混用与裁带露底裂缝。
13. **静态分辨率锁死，不支持运行时旋转与热切档（D-DISP-08）**：几何在启动期由 `WM_GETINFO` 一次性拉取缓存（[relay.rs](../../user/bins/gui-wmd/src/relay.rs) `:184-198`），`guifbd` 未消费 `virtio-gpu` 配置变更中断或 EDID，切换横竖屏或分辨率必须整机重启（[frameloop.rs](../../user/bins/berry-launcher/src/frameloop.rs) `:566-571`）。
14. **内核忙核定时精度倒挂制约高刷锁拍（D-DISP-09）**：如 [刷新率体系规范-v1.0.md](../../docs/刷新率体系规范-v1.0.md) `:124` 登记，忙核睡眠受 10Hz 时间片节拍制约，最迟唤醒误差达 100ms，尚不足以支撑 60Hz/120Hz `latch-at-vsync` 亚毫秒锁拍呈现。

### 三、SDK、UI 引擎与应用生态缺陷（`berry-ui` / `berry-appshell` / `berry-libc`）

15. **原生 41 `ViewKind`（1x 硬编码）与 `pattern.rs`（3x 配方）双轨分裂（D-SDK-01）**：`berry-ui` 内建组件的几何尺寸（`BUTTON_H=48`、`TOGGLE_W=52, H=32`、`CHECK_W=24`）与字号（`FontSize::S8x16`）全部按 1x 物理像素硬编码（[berry-ui/lib.rs](../../user/berry-ui/src/lib.rs) `:144-240`、[paint.rs](../../user/berry-ui/src/paint.rs) `:88-104`），在 1080×1920@3x 主屏上缩成 1/3 大小不可直用；真圆角默认被进程级 `AtomicBool` `TRUE_CORNERS = false` 关闭（[paint.rs](../../user/berry-ui/src/paint.rs) `:166`）。开发者被迫依赖 3,114 行的 [pattern.rs](../../user/berry-ui/src/pattern.rs) 拼装组合槽，或如 `settings-app/main.rs`（件已移除——合并死链清偿） `:173-250` 直接绕过 UI 引擎手算像素绘图。
16. **定容 Arena 多处静态硬上限过小且无虚拟化列表（D-SDK-02）**：`MAX_NODES = 512`、`TEXT_INLINE = 64`（超 64B 文本直接报错）、`INPUT_TEXT_MAX = 8`（全局至多 8 个输入框文本槽）、`ANIM_MAX = 16`、`A11Y_MAX = 40`（曾因 34 条目超旧值 32 致 1080p 桌面建树失败恒黑）、`SCRATCH_GLYPHS = 1024`（超量字符静默截尾不绘）（[berry-ui/lib.rs](../../user/berry-ui/src/lib.rs) `:81-94, 219, 251`；[pump.rs](../../user/berry-appshell/src/pump.rs) `:90`）。引擎无 `VirtualList` 视口按需实例化机制，无法承载百条以上联系人、文件列表或长网页。
17. **布局引擎缺失真弹性伸缩与响应式断点（D-SDK-03）**：`Spacer` 在 `Row/Col` 内测量恒为 `0×0` 且不参与主轴余量分配（应用被迫手算像素宽度构造假占位容器，[settings/main.rs](../../user/bins/settings/src/main.rs) `:244-250`）；缺乏完整 `flex_grow`/`flex_shrink`/`wrap` 与视口变更免拆树自适应重排（`SwipePager` 页宽在建树期冻结）。
18. **封闭组件枚举阻碍第三方自定义控件扩展（D-SDK-04）**：全部控件焊死在 `ViewKind` 41 变体枚举与巨型 `match` 分支中（`desc.rs` 3,251 行、`paint.rs` 2,197 行），外部应用无法在引擎内注册拥有独立测量、布局、绘制与手势状态机的自定义组件。
19. **全系统零 UTF-8 多语种与零 CJK 矢量文字渲染能力（D-SDK-05）**：文字栈仅支持 ASCII `32..=126` 共 95 枚 1-bit 点阵字模，无 TrueType/OpenType 轮廓解析与灰度图集缓存，中文及国际化 UI 文案、终端中文输出全部无法显示（[berry-term/main.rs](../../user/bins/berry-term/src/main.rs) `:89`）。
20. **输入法守护进程 `softimed` 与组合文本协议缺位（D-SDK-06）**：软键盘仅停留在规划稿，`user/bins/` 下无 `softimed` 实现，协议缺失 `preedit` 组合串、光标矩形上报与软键盘安全区动态避让，文本输入控件在无物理键盘设备上无法完成闭环输入。
21. **手势识别器缺失长按、双击、多指捏合与惯性滚动（D-SDK-07）**：`hit.rs` 手势裁判仅支持单指点击与线性锁轴拖拽，无 `LongPress`、`DoubleTap`、`Pinch/Zoom` 与物理摩擦衰减的列表惯性滚动（Fling Scroll）。
22. **应用事件循环封闭且百行底层样板代码泛滥（D-SDK-08）**：`berry-appshell::pump` 将 `wait_many` 锁死在 WM 与 Input 两路句柄，导致需监听子进程管道的 [berry-term/main.rs](../../user/bins/berry-term/src/main.rs) `:29-32` 无法复用 SDK 而被迫重写整套帧循环；仓内并存 `settings`/`settings-app` 等 7 对分裂应用目录，每个应用均需重复编写 `CRT0_SEED`、固定虚拟地址 `FRAME_VA = 0x5100_0000` 与原始字节数组 RPC 循环。
23. **运行时堆/环境容量逼仄且打包门禁过度苛刻（D-SDK-09）**：`berry-libc` 静态堆仅 `256KiB`（[应用API全景-v1.0.md](../../docs/应用API全景-v1.0.md) `:33`）、环境变量限 `256B / 16 项`（[io.rs](../../user/berry-libc/src/io.rs) `:58-66`）；`mkapp.py` 强制源码 `manifest.toml` 与规范重序列化逐字节相等，连一行 `#` 注释或空行都直接报错拒收（[应用开发指南.md](../../docs/应用开发指南.md) `:85-88`）；且缺乏剪贴板、系统级文件选择器（Picker）与跨应用 Intent 分享服务。

### 四、开机引导、服务编排与桌面壳层缺陷（`berryboot` / `splash` / `svcmgr` / `berry-launcher`）

24. **UEFI 引导硬编码 128MB 内存窗且首屏无模式优选与品牌预绘（D-BOOT-01）**：[berryboot/lib.rs](../../bootloader/berryboot/app/src/lib.rs) `:13, 85-89` 硬编码 `DRAM_TOP = 0x4800_0000`，且仅 `QueryMode` 不主动切换原生高分屏 GOP 或绘制首帧画面，导致固件阶段至内核初始化间存在黑屏与分辨率跳变。
25. **内核 `splash.rs` 假平滑空循环与每次全屏清黑造成严重闪烁（D-BOOT-02）**：`splash::step()` 在无任何时间间隔的同步紧循环内连算 8 次 `disp += delta / 8` 后才调用一次 `redraw(s)`（[splash.rs](../../kernel/src/splash.rs) `:151-160`），无真实帧间平滑效果；而 `redraw(s)` 首行直接调用 `clear_screen(s)` 将整块单缓冲屏幕涂黑再重绘 Logo 与进度条（`:326-328`），每次步进均引发全屏闪烁；多任务启动后内核立即 `detach()`（`:210-215`），用户态服务拉起期间进度条彻底停滞。
26. **8,576 行单体 `svcmgr` 耦合开机自检阻塞启动且并发应用帽仅 4 个（D-BOOT-03）**：[svcmgr/main.rs](../../user/bins/svcmgr/src/main.rs) 将根监督、全局 32 槽调页器、进程表、黑匣子、`appd` 与十余项耗时自检硬编码在同一串行启动流中；并发存活应用硬上限 `APP_SPAWN_LIVE_MAX = 4`（`:862`）；图形链路句柄在启动期静态一次性编织，`guifbd` 或 `gui-wmd` 一旦崩溃整条桌面会话即永久断链不可自愈，各组件遇错普遍调用 `park()` 假活挂起。
27. **桌面正常开机被强插自动化翻页测试污染用户体验（D-DESK-01）**：[frameloop.rs](../../user/bins/berry-launcher/src/frameloop.rs) `:318-370` 的 `Selftest` 状态机未加 `smoke` 门控，每次正常开机呈现桌面首帧后都会强制自动注入两轮滑动手势翻至第 2 页再弹回第 0 页。
28. **单体 Launcher 混装系统栏/桌面/内置设置页造成职责膨胀与双写（D-DESK-02）**：状态栏、壁纸、分页网格、Dock、底部导航键及一套重复的系统设置页（`syspages.rs`）全挤在 `berry-launcher` 同一棵 512 节点树内，既挤压节点与无障碍配额，又与独立 `SETTINGS.bap` 形成功能双写。
29. **返回键强杀应用窗口与伪多任务键缺失应用切换能力（D-DESK-03）**：点击底部返回键直接向焦点窗发送 `OP_WM_DESTROY` 外部强拆窗口（[frameloop.rs](../../user/bins/berry-launcher/src/frameloop.rs) `:506-531`），未走 `OP_WM_BACK` 协议通知应用内部导航栈后退；多任务键仅缓存单条最近启动 ID 并 `take()` 重拉一次（`:545-552`），无多任务卡片视图；点击图标启动应用无 Starting Window 与图标展开过渡动画。

### 五、虚拟机启动与宿主模拟器缺陷（`tools/berry`）

30. **VNC 通道受制于 33fps 结构性帧率上限（D-EMU-01）**：宿主 Web 壳与 VNC 连接受 QEMU VNC 服务端 30ms 定时器硬顶制约，最高帧率锁死在 ~33fps，无法兑现 60Hz/120Hz 流畅交互目标（[显示与加速体系设计-v1.1.md](../../docs/显示与加速体系设计-v1.1.md) `:36-38, 79`）。
31. **`RamSource` 每帧 8.29MB `pread` 全量拷贝且 4,050 像素稀疏采样漏检吞帧（D-EMU-02）**：共享内存源 [ram.rs](../../tools/berry/src/display/ram.rs) `:136-179` 每 16ms 执行全帧 `pread` 系统调用与双循环逐像素字节重排；其静态帧跳过签名步长为 `len / 4 / 512`（1080p 下每隔 4,050 个像素才采样 1 点），导致光标闪烁、单字输入回显、小控件状态变化极易漏过采样网格而被直接丢帧不显示。
32. **原生窗口遗留 `0.55/0.9` 缩小补丁且内置工具栏字模残缺乱码（D-EMU-03）**：[window.rs](../../tools/berry/src/window.rs) `:204-245` 未兑现 1:1 逻辑尺寸开窗；`:63-83` 的手写 5×7 点阵 `glyph()` 仅定义 15 个大写字母（缺失 `A, D, G, K, M, V, Y, Z` 等），导致弹出 Profile 菜单（`:145`）时 `"DESKTOP"` 显示为 `" ES T P"`、`"DEFAULT"` 显示为 `" EFA LT"`、`"TABLET"` 显示为 `"T BLET"`。
33. **`spawn_kernel` 与 `spawn_image` 双启动路径配置割裂且拓扑脆弱（D-EMU-04）**：`spawn_kernel` 不注入任何 `fw_cfg` 键（漏注 `opt/berry/accel` 导致 HVF 直启必触发内核 FPSR 自检崩溃，[qemu.rs](../../tools/berry/src/qemu.rs) `:201-217`）；`virtio-tablet`、双串口 `simdev`、`virtio-gpu` 与 `ramfb` 声明序均存在“差一参即黑屏/挂死/D-abort”的脆弱耦合。
34. **x86_64 与 Windows 宿主困于纯软件 TCG 慢速模拟（D-EMU-05）**：`berry` 硬编码仅查找 `qemu-system-aarch64`（[qemu.rs](../../tools/berry/src/qemu.rs) `:106-110`），在 x86_64 Linux/Windows 宿主上只能回退慢 10–50 倍的 TCG 软件翻译，未联动仓内 `x86_64` 原生架构目标启用 KVM/WHPX；且非 Unix 平台缺失双向串口套接字支持（`:182-189`）。
35. **缺失 VM 快照亚秒级速启（QuickBoot）与内置盘初始化（D-EMU-06）**：每次打开模拟器均需经历完整 UEFI 固件自检与冷启动全流程；且 `berry` CLI 不内嵌 FAT12 造盘逻辑（[qemu.rs](../../tools/berry/src/qemu.rs) `:298-302`），脱离 `just desktop` 独立运行时若无预置数据盘便静默降级为无盘模式，致使桌面丢失应用列表与输入能力。
36. **模拟器生产力桥接能力缺失（D-EMU-07）**：宿主窗口与客机之间缺乏双向剪贴板同步、宿主文件拖拽导入、VirtIO-Sound 音频输出、触控板双指连续像素滚动映射及实时帧率/脏区调试叠加层（HUD）。
