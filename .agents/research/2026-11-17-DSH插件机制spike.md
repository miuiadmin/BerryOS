# DSH 插件机制 spike 调查（bundle 解剖 / entry 全集 / 注册面）

Type: survey
Status: current
Updated: 2026-11-17

一句话说明：为 berryos-orchestra 最小 bundle 立项而做的 DSH 插件机制实查——bundle 解剖、entry 类型全集、工具与技能两条注册面的 API 形态，全部结论带实读路径与行号；版本锚定 dsh 0.2.2-rc.1。

## 问题

DSH 插件能不能做、注册面有哪些、最小 bundle 需要什么形态——为 berryos-orchestra（BerryOS 流水线插件）立项提供机制底账。

## 方法与来源

2026-11-17 实机实读（macOS，dsh 经 homebrew 装于 /opt/homebrew/lib/node_modules/@deepseek-ai/dsh，版本 0.2.2-rc.1；profile 树在 ~/.dsh/profiles/acp）：`dsh --help` / `dsh plugin --help` / `dsh --profile acp --dump-config` / `--dump-config-schema` 四条 CLI 面，加三个包的源码直读——@jacklika/dsh-memory（第三方 bundle 在装实例）、@deepseek-ai/dsh-skill-filesystem、@deepseek-ai/dsh-tools（官方注册面实现）。未联网查文档，全部以本机源码为准。

## 结论

1. **bundle 解剖**：DSH profile 是 pnpm 工作区（nodeLinker: hoisted），package.json 的 `dsh.profile.bundles` 列 bundle 包名；bundle 本体是普通 npm 包，`dsh.bundle.patch` 字段指向包内 cordis.patch.yml（@jacklika/dsh-memory package.json 实例）；patch 只允许 insert（瀑布序）与按 id 的整条替换，官方明示 config 不深合并。
2. **安装通道**：`dsh plugin --profile <name> add <pkg>` 原样转发 pnpm；第三方先例 @jacklika/dsh-memory 全家（含 dsh-tool-* 六包）经此通道在装。
3. **entry 类型全集**（--dump-config 实枚举，specifier 一律 Cordis 插件模块）：llm 提供方（dsh-llm-deepseek-api-key）、工具（dsh-tool-bash/fs/fs-search/jobs/skill/subagent/workflow/todo/goal/web）、技能（dsh-skill + dsh-skill-filesystem + dsh-tool-skill）、命令（dsh-commands）、goal / plan-mode / subagent / workflow 编排面、session / storage / otel / sandbox / approval 平台面、agent-loop（config.agents 数组）与 dsh-agent-preset-registry（预设智能体注册面，v1 候选）。
4. **工具注册面 API**：插件模块导出 `name` / `inject: ['tools']` / 可选 `Config`（schemastery）/ `apply(ctx, config)`；`ctx.effect(() => ctx.tools.register(tool))`。defineTool 只是薄包装：参数 spec→JSON Schema 转换 + args 校验（dsh-tools lib/index.js :310-345）；register 只断言 output 形态与 `assertSupportedJsonSchema(output.schema)`（:433-440），parameters 原样透传给模型（projectToolSchema :366-375）。
5. **schema 形态判例（本 spike 抓到的第一个坑）**：作者 DSL `{type:'json'}` 的编译目标是空注解节点 `{}`（dsh-tools :160-163 json case），零依赖手注册必须直接给原始形态——写 `{type:'json'}` 会被 register 断言打爆。
6. **技能注入面**：dsh-skill-filesystem 是 ctx.skills 的 provider，Config 含 `customSkillDirs`（数组）与 `includeDefaultRoots`（bool）（skill-filesystem lib/index.js :30-44，roots() :160-197）——bundle 可插第二个实例（providerName 区分、关默认根、只扫包内 skills/）实现零 JS 技能注入；默认扫描根为项目 `.dsh/skills` / `.agents/skills`（rank 100/200）与用户侧 ~/.dsh、~/.agents（rank 400/500），用户级技能实证住 ~/.agents/skills（~/.claude/skills 为喂 Claude Code 的副本）。
7. **模块解析判例**：profile node_modules 内 resolve 不到 @deepseek-ai/dsh-tools（MODULE_NOT_FOUND），但依赖它的 @jacklika 工具在运行时正常——插件模块的外部 specifier 由 harness 侧解析，不走朴素 node 语义；因此最小插件模块写成零外部依赖（仅 node 内建）最稳，link: 活链安装下也能解析。
8. **测试台**：~/.dsh/profiles/headless 是最小 profile（bundles 仅 dsh-base + dsh-headless、deps 空），克隆后加装 bundle 即得端到端 boot 试验台；acp profile 的 app 是 stdio ACP 服务无无头模式。LLM 密钥不在 shell 环境，boot 测试须从活 dsh 进程环境借（ps eww）。

## 证据与出处

- bundle 解剖与安装通道：~/.dsh/profiles/acp/package.json（dsh.profile.bundles 三束）、@jacklika/dsh-memory/package.json（dsh.bundle.patch 字段）、`dsh plugin --help`。
- entry 全集：`dsh --profile acp --dump-config` 全量输出（约 150 entry）。
- 工具 API：@deepseek-ai/dsh-tools/lib/index.js :160-163（json case）、:264-283（spec→schema 转换）、:310-345（defineTool）、:366-375（projectToolSchema）、:433-445（register 断言）；@jacklika/dsh-tool-memory-filesystem/lib/index.js :793-820（apply + ctx.tools.register 实例）。
- 技能面：@deepseek-ai/dsh-skill-filesystem/lib/index.js :30-44（Config）、:76-107（apply/provider）、:160-197（roots 与 rank）。
- 解析判例：node createRequire 实测（profile 内 dsh-tools MODULE_NOT_FOUND、schemastery 可解析）。

## 适用边界

- 版本锚定 0.2.2-rc.1：entry 集合与 Config 形态随 dsh 升级会漂，用前以 `--dump-config` 复核。
- 未核实面：MCP 服务注册、PTC executor 侧工具、agent-preset 条目 config 形态、插件发包上 npm 的发布面——均超出最小 bundle 需要，留 v1。
- customSkillDirs 的可移植写法（包内相对路径 / js 表达式）未验证，v0 用绝对路径（本机装法）。
- 本调查不做行为背书：bundle 装载与生效以 orch-test 试验台 boot 实测为准（进行中，另见计划书 Phase 2 条目）。
