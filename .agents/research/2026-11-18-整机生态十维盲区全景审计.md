# 整机生态十维盲区全景审计

Type: survey
Status: current
Updated: 2026-11-18

一句话说明：对照现代主力级 AI 原生手机、PC 与穿戴操作系统的完整工程版图，系统盘点 BerryOS 在完成微内核、调度、渲染、桌面与存储 2.0 规格立项之后仍处于空白或桩态的十大整机核心维度及代码实证。

## 问题

在微内核底座（`meihe`、`mm`、`ipc`、`hal`）、对数与单拍实时调度（`sched-rt-gfx`）、生命周期与崩溃黑匣（`am`、`cbox`）、CoW 存储与镜像（`storage-image`）、图形与真 GPU 卸载（`gfx`、`gpu-accel`、`compositor`）、响应式 SDK 与桌面启动（`ui-sdk`、`desktop`、`desktop-boot`）以及宿主模拟器（`emulator`）共 15 份模块总体设计落盘之后，若将 BerryOS 作为一台真实交付终端用户日常主力使用的现代 AI 原生多端操作系统审视，还有哪些关键子系统完全缺位、仅存留名空壳或尚未建立架构契约？

## 方法与来源

1. 全量核查 [文档索引](../../docs/索引.md) 登记的 128 篇存量设计、标准与实施草案，交叉比对 `.agents/plans/*/design.md` 既有 15 个模块的职责覆盖范围与「不覆盖」排除项。
2. 直接审计用户态工作区 [Cargo.toml](../../user/Cargo.toml) 下辖全部库与应用进程目录（含 [berry-tls](../../user/berry-tls/Cargo.toml)、[berry-crypto](../../user/berry-crypto/src/lib.rs)、[berry-ksproto](../../user/berry-ksproto/src/lib.rs)、[browser](../../user/bins/browser)、[camera](../../user/bins/camera)、[photos](../../user/bins/photos)），以及内核系统调用分发表与 `arch/`、`tools/berry/` 硬件外设支持面。
3. 以「端到端用户真实使用闭环、零信任隐私安全、AI 原生算力兑现、第三方开发者工具链闭环、真机量产救砖」五把标尺定位系统级结构盲区。

## 结论

审计确认 BerryOS 现行架构版图之外存在 **10 个尚未立项设计的核心整机盲区**；任一盲区缺失均会导致真实产品体验断链：

| 编号 | 缺失维度 | 现役代码与文档实态 | 断链后果 | 对应新建规格 |
| :--- | :--- | :--- | :--- | :--- |
| 1 | 端侧 AI 原生推理与加密记忆库 | 有 [AI 调度设计](../../docs/AI调度设计-v1.0.md) 与桌面语义场景总线，但全仓零张量推理引擎、零模型权重共享 VMO、零本地向量记忆库 | 「AI 原生」仅有手脚与神经末梢，缺少本地大脑与长期记忆，离线状态或隐私场景下智能能力归零 | [ai-runtime 总体设计](../plans/ai-runtime/design.md) |
| 2 | 低延迟音频、硬编解码与相机管线 | 全仓零音频驱动（无 `virtio-snd`/I2S）、零混音服务、零音视频编解码；`camera-app` 与 `photos-app` 为静态 UI 壳 | 整机完全无声、无法播放音视频、无法采集真实图像流，音画同步与相机隐私指示硬门禁悬空 | [media 总体设计](../plans/media/design.md) |
| 3 | 现代安全网络、无线栈与跨端软总线 | `berry-tls` 实为 ELF 线程局部存储而非传输层加密；仅支持 QEMU SLIRP 下基础 IPv4 TCP，零 TLS 1.3/HTTPS、零 IPv6、零 Wi-Fi/BLE、零跨设备总线 | 无法握手任何真实 `https://` 站点；穿戴与移动设备脱离蓝牙与 Wi-Fi 无法配对联网；多端定位缺少无缝接力协同 | [net-conn 总体设计](../plans/net-conn/design.md) |
| 4 | 内核熵池、静态加密、密钥库与锁屏 | `berry-crypto` 仅有 Ed25519/SHA-512 验签，`berry-ksproto` 仅为协议帧壳，零 CSPRNG、零 FBE 落盘加密、零 Keyguard 锁屏与生物认证 | 缺乏密码学真随机根基；设备丢失拆焊闪存即可明文读取全部个人数据；缺少锁屏门禁与多用户隔离 | [security 总体设计](../plans/security/design.md) |
| 5 | 跨应用协同、能力剪贴板与 Web/Wasm | [应用规范](../../docs/应用规范-v1.0.md) 仅有原则条文，无 `notifyd`、无剪贴板/拖拽协议、无 Intent 路由、无 RTC 后台经纪、无真实 Web 内核与 Wasm 沙箱 | 应用沦为信息孤岛；传统全局剪贴板存在后台偷窥隐患；缺少 WASI 组件生态加速早期跨语言应用供给 | [app-interop 总体设计](../plans/app-interop/design.md) |
| 6 | 真实 SoC 总线、传感器中枢与触觉引擎 | 仅支持 `virtio-mmio` 与 PL011/PL061；零 PCIe/MSI-X、零 USB/xHCI、零 IMU/环境光/心率传感器中枢、零线性马达触觉反馈、零 PMIC 深睡树 | 无法驱动 PC/VMware 及真机高速外设；无自动旋转、抬腕亮屏与物理振感反馈；真机无法进出 S3 低功耗深睡 | [soc-peripherals 总体设计](../plans/soc-peripherals/design.md) |
| 7 | 源码级调试器、PMU 火焰图与 UI 检视 | 仅有死后崩溃黑匣子 `cbox`，无在机断点单步调试通道、无 DWARF/紧凑展开表栈回溯、无硬件 PMU 采样火焰图、无实时场景树检视器 | 第三方开发者与内核工程师只能靠打日志盲调并发死锁与性能退化，研发效率受限 | [devtools 总体设计](../plans/devtools/design.md) |
| 8 | 全球化排版、精准时区与无障碍读屏 | 实时钟为 `EPOCH_BASE(0) + mono`，无 NTS 网络授时与 IANA 时区库，无多语言复数格式化与 RTL 双向镜像，无读屏 TTS 服务 | 系统时间无法跨时区与夏令时准确流转，中东 RTL 语言排版错乱，视障用户无法独立操作设备 | [i18n-a11y 总体设计](../plans/i18n-a11y/design.md) |
| 9 | 独立救援恢复模式、硬件自检与产线注入 | 虽规划 GPT A/B 双槽回滚，但缺乏独立于主系统分区的紧急图形救援环境、受控救砖刷机协议、工厂 CIT 自检与产线密钥熔丝封签 | 双槽同时损毁或忘记锁屏密码时设备彻底变砖；无法支撑真实工厂产线自动化测试与唯一身份注入 | [recovery 总体设计](../plans/recovery/design.md) |
| 10 | 基于 CoW 快照的端到端加密备份与同步 | `BerryFS` 已规划 CoW B+Tree，但尚未构建应用与整机级时间点快照导出、零知识加密增量备份、近场换机克隆与多端 CRDT 状态同步 | 用户换机、误删文件或大版本回退时面临数据丢失风险，无法释放 CoW 存储引擎的天然时间机器红利 | [backup-sync 总体设计](../plans/backup-sync/design.md) |

## 证据与出处

1. **网络加密与协议栈缺口实证**：[berry-tls/Cargo.toml](../../user/berry-tls/Cargo.toml) 第 6–20 行明确声明其职责为 `BerryOS copy-style TLS placement pure functions (tls_place/find_ptls/template globals)`（即线程局部存储而非网络 TLS）；[berry-crypto/src/lib.rs](../../user/berry-crypto/src/lib.rs) 第 74–80 行仅导出 `admit`、`ed25519`、`envelope`、`fe`、`ge`、`ledger`、`sc` 与 `sha512`，不含对称 AEAD、密钥交换 X25519 及 X.509 证书链验证；[文档索引](../../docs/索引.md) 第 226 行明确记录网络面尚无现行规范承接 `vnet/netdproto`。
2. **密钥库与安全底座桩态实证**：[berry-ksproto/src/lib.rs](../../user/berry-ksproto/src/lib.rs) 第 5–18 行注明「day-one 缝 = 冻结数据面，不是实现密钥库；本库不含任何密码学算法」，且 [系统调用 ABI 设计](../../docs/系统调用ABI设计-v1.0.md) 登记 `0x85 attest` 恒返回 `-ENOTSUP`。
3. **多媒体与传感器缺席实证**：检视 `user/` 与 `user/bins/` 全目录，不存在任何 `audio`、`snd`、`codec`、`sensor`、`haptic`、`bluetooth`、`wifi`、`usb`、`pcie` 或 `debugserver` 模块；[事件循环 A7-2 实施设计草案](../../docs/事件循环A7-2实施设计草案-v1.0.md) 证实 `CLOCK_REALTIME` 当前仅由 `EPOCH_BASE(0) + mono` 合成，无持久 RTC 同步与时区表。
4. **可观测与生态协同挂账实证**：[可观测性设计](../../docs/可观测性设计-v1.2.md) 标注常驻 trace 服务挂账 v2；[应用 API 全景](../../docs/应用API全景-v1.0.md) 与 [路线图](../../docs/路线图-v1.2.md) 第 143–150 行证实 Phase 8 真机电源、传感器与产线闭环尚待细化规格。

## 适用边界

- 本审计聚焦整机功能版图与架构契约缺口，作为新建十大模块 `design.md` 总体规格、[整机十维缺失拼图全栈终态架构裁决](../notes/proposed/2026-11-18-整机十维缺失拼图全栈终态架构裁决.md) 与 [整机十维补全终态实施总计划](../plans/2026-11-18-整机十维补全终态实施总计划.md) 的事实基线。
- 既有 15 个已立项模块（微内核、内存、IPC、HAL、调度、图形、合成、SDK、存储等）的内部缺陷归各自既有深研报告与总体设计管辖，本文不重复展开。
