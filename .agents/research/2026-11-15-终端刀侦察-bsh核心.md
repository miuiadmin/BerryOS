# 终端刀侦察：bsh 命令执行核心的事实底册

Type: survey
Status: current
Updated: 2026-11-15

## 问题

计划中的两刀——(a) 把 bsh 的命令执行核心抽成可复用 crate（供未来 GUI 终端应用同源消费，纪律「不长第二套」）；(b) 补齐用户可用的内建命令（clear/history/uname 等）——在动手前需要一份当前状态的事实底册：核心引擎的函数地图与行界、核心逻辑与宿主（console/berry-libc/std）的耦合面、用户可见的命令全集与缺口、抽库改动的回归风险面、以及 smoke 对 bsh 输出的行为契约。本文即该底册。

## 方法与来源

对 `user/bins/bsh/src/main.rs`（5627 行）与 `user/bins/bsh/src/editor.rs`（283 行）做全文检索加分段精读（函数清单用 `grep -n "^fn "` 现场列出，关键段逐行读）；行为契约读 `tools/smoke.sh`、`tools/smoke-image.sh`、`tools/markers.sh`；rootfs 构成读 `tools/rootfs-manifest.toml` 与 `justfile`；分卷帽读 `tools/mkcpio.py`；标记归属用 `grep -rn 'println!…ok'` 对 `user/`、`drivers/` 全量定位后逐一归主；体积用 `ls -l` 实测。所有行号以 2026-11-15 读到的工作树为准（bsh 两文件不在并行会话改动清单内；`git status` 里改的是 kernel/svcmgr/tools/berry 家族，未动 bsh）。

## 结论

### 1. main.rs 结构地图：核心执行引擎

词法与切行层（自上而下依次分派）：`run_line`（main.rs:3293）按 `&&` 切段顺序执行、非零短路（sh 语义），每段执行时才展开变量；`exec_one`（main.rs:3310）单段命令的总分派序 = trim → 赋值形检测（`assignment_of` main.rs:3241，在原始文本上，值落表时才展开）→ `|` 管道检测（原始文本）→ `>` 重定向检测（原始文本）→ `expand` 展开（用进入时的 `$?`）→ `render_cmd` 分派；`expand`（main.rs:3259）做 `$NAME`/`$?` 展开，按字节扫描、未定义变量展开为空串，无 `${}`/引号/转义面；`get_var`（main.rs:3233）变量表 rev 查最新（覆盖写语义）。操作符识别一律在展开前的原始文本上（对抗审查实抓的纪律，main.rs:75-78 头注）。

管道与重定向层：`do_pipe`（main.rs:4524）解析段名（v1 各段裸名无 `/`，违规 usage 2）、调 `pipe_capture`、回放数据与警告（no EOF/dropped）；`PipeSeg`（main.rs:4563）= 名 + argv[1..]；`PipeFail`（main.rs:4569）= NotFound/SpawnFail 两态；`pipe_capture`（main.rs:4593）是拉起/收集/回收真身——全段 `cpio_find` fail-fast、相邻段间 `channel_pair`、首段装 fs gift、先 collect 末段再逐段 reap 的死锁序铁律、交互态经 `collect_fg` 武装 Ctrl-C。重定向面只有 `do_redirect`（main.rs:3787）+ `split_redirect`（main.rs:3772）——**没有** `do_redirect_append`：`>>` 被 `split_redirect` 的 `>` 计数不等于 1 自然排除为 usage 2，`|`+`>` 组合先撞管道分支（main.rs:3329-3331 注释，v1 文档化面）。

内建分发层：`render_cmd`（main.rs:3347）是内建/外部统一渲染面，返回 `(Vec<u8>, i32)`——数据字节交调用方定向（直出打 stdout / 重定向 put_file 入文件），诊断与 usage 打 `out`（stderr 语义）。各 `*_output` 函数：`cat_output`（main.rs:3822）、`ls_output`（main.rs:3843，裸 ls = opendir("/")）、`ls_path_output`（main.rs:3859）、`mkdir_output`（main.rs:3879）、`rm_output`（main.rs:3899）、`cd_output`（main.rs:3920）、`inputpoll_output`（main.rs:1123，GUI input 域 POLL 消费端）。fs 工具族（内建与重定向共用的 libc 皮）：`valid_path`（main.rs:3597）、`cpath`（main.rs:3620）、`get_file`（main.rs:3632）、`put_file`（main.rs:3669）、`dir_lines`（main.rs:3705）、`stat_of`（main.rs:3733）、`mkdir_of`（main.rs:3747）、`unlink_of`（main.rs:3759）、`errno`/`errno_text`/`errno_code`（main.rs:3561/3571/3583）。

外部 spawn 族：`run_output`（main.rs:3469）是 `run <name>` 与裸名派发共用的渲染面（cpio 查档 → spawn_rootfs_elf → collect/collect_fg → reap，返回数据字节与真码）；自验侧变体全家：`run_capture`（main.rs:5297，无 gift）、`run_capture_fs`（main.rs:5366）/`run_capture_fs_cap`（main.rs:5373，装 fs gift 四元）、`run_capture_gifts`（main.rs:5394）/`run_capture_gifts_cap`（main.rs:5405，泛 gift + 宽帽）；gift 装配器 `fs_gifts`（main.rs:5322，rootfs READ dup + fs SEND|RECV dup）、`net_gifts`（main.rs:5349，三元加 netd dup）；收集器三态：`collect`（main.rs:5454，10s 活动帽）、`collect_cap`（main.rs:5464，宽帽版，uu_cp 实测 17s 定标 30s）、`collect_fg`（main.rs:5514，交互态 wait_many 三项 `[out:READABLE, proc:TERMINATED, stdin:READABLE]` 的 Ctrl-C 杀链收集）；`now`（main.rs:5621）时钟。网络/RPC 辅助：`netd_rpc`（main.rs:909）、`netd_rpc_tcp`（main.rs:953）、`input_rpc`（main.rs:972）。

console 读主循环与交互态：`main`（main.rs:195）= 自验链（见下）+ 交互循环；交互循环（main.rs:344-393）持 `stdin().lock()` 逐字节 `read`，先消化 `typeahead_pop`（main.rs:183，FIFO）再阻塞读，空读（fd0 的 10s 帽 EOF 化）静默续读不重刷 prompt；`ed.feed(c, &mut src)` 三态——`Flow::Continue(echo)` 回显、`Flow::Line(line)` 补 `\n` 后进 `run_line`、`Flow::Interrupt` 打 `^C` 重显 prompt。交互态全局：`INT_MODE`（main.rs:157，`static mut` + `int_armed`/`int_arm` 访问器 main.rs:159/164，单线程纪律）、`TYPEAHEAD`（main.rs:176，打字-ahead 暂存 + push/pop main.rs:178/183）。Tab 真源 `RealSrc`（main.rs:401，impl TabSource at main.rs:403）：命令位 = 12 内建常量（main.rs:405-408）∪ cpio `bin/` 直读，路径位 = libc opendir。

### 2. 与宿主的耦合点与抽库评估

输出通道：`out: &mut std::io::Stdout` 作为参数出现在 13 个签名（rg 计数，含 run_line/exec_one/render_cmd/run_output/do_pipe/do_redirect 及各 `*_output`）；数据面与诊断面物理共用 stdout（fd1/fd2 = console 别名，头注 main.rs:4-6；「诊断打 out 不随 `>` 进文件」的 stderr 语义约定在 main.rs:26-28）——语义分流不是物理通道。另有 128 处 `println!`/103 处 `eprintln!` 直打（绝大多数在 23 个 selftest、collect_fg 的 `^C` 回显 main.rs:5575、main 的 `BSH ok`）。console 出口在 berry-libc：`console_write` 192B 分片 + EBUSY 阻塞等 WRITABLE（user/berry-libc/src/io.rs:455-479）。抽 crate 的输出抽象面很小：一个 `write_all + flush` 的 `Write` 泛型（或 dyn trait）即可覆盖 `out` 参数；但 selftest 的 println/eprintln 直打面若随迁，需要同一输出 trait 注入或留在宿主壳。

console 输入：editor.rs **自身不读任何 handle**——它是纯喂键状态机（`feed(b: u8, src: &mut dyn TabSource)`，editor.rs:75），回显字节经 `Flow` 交调用方写。读环全在 main：`stdin().lock()` 逐字节 read（main.rs:344-369），底层是 musl fd0 → berry-libc `read` → `STDIN_H` channel recv + 空队 wait READABLE 10s 帽超时 EOF 化（io.rs:686-724）；fd0 = boot 手搭的 bsh-stdin 对端（console 转发键盘完整行，Cargo.toml 头注与 main.rs:4-6）。**结论：editor 的行编辑（历史环 8 条 newest-first、ESC 状态机、Ctrl-U、Tab 补全经 `TabSource` 注入、Ctrl-C `Flow::Interrupt`）已经与 console 读解耦**——复用只需宿主供字节流与回显 write 面；`TabSource`（editor.rs:29-37）已是 trait，真源 `RealSrc` 持 rootfs/libc 依赖留在宿主侧即可。一处双写要注意：提示符字面量 `"bsh> "` 同时硬编码在 main.rs:355（循环重显）与 editor.rs:22（`PROMPT` 常量，多候选列示后重显用）——抽库时应单源化。

对 berry-libc/berry-sys/berry-exec 的直接依赖面（main.rs:83-108 的 use 块）：berry-libc io 访问器 8 个（`rootfs_h/fs_h/stdin_h/netd_h/input_h/read/write/close`）、berry-libc fs 族（`chdir/closedir/getcwd/mkdir/open/opendir/readdir/stat/statfs/unlink` + `O_*`/`Stat`/`Statfs`）、errno 常量 10 个；berry-sys syscall 直调约 15 个（channel recv/send、clock_read、event_create、handle_close/duplicate、object_signal、wait_one/wait_many、process_terminate、signal_send 及信号/权利常量）；berry-exec 6 项（`channel_pair/cpio_find/cpio_names/spawn_rootfs_elf/ChildHandles/SpawnSpec`）；berry-fsproto 只剩 4 个帽常量（`FILE_SIZE_MAX/NAME_MAX/PATH_DEPTH_MAX/PATH_MAX`）；berry-complete（editor）、berry-poll/berry-netdproto/berry-guiproto（selftest 专用）。另有 `static mut INT_MODE/TYPEAHEAD` 与 `berry_libc::park()` 的 loud-death 惯例贯穿 selftest。

抽库（如 `user/berry-sh`）的参数化面评估：纯逻辑核（`run_line/exec_one/assignment_of/get_var/expand/split_redirect/render_cmd` 的分发骨架 + editor 全件）只依赖输出 `Write` 面，最容易先动；fs 面（`get_file/put_file/dir_lines/stat_of/mkdir_of/unlink_of/valid_path`）是 libc 直调薄皮，可收成一个 FsBackend trait 或整族保留直调；最大的宿主耦合在 spawn 面（`run_output/pipe_capture` 直用 berry-exec `SpawnSpec/spawn_rootfs_elf` + berry-sys handle 操作 + `collect/collect_cap/collect_fg`），GUI 终端复用时这层要么参数化成 Spawner trait（查档 + 拉起 + 收集 + 回收四步），要么 crate 内保留 guest 实现而让 GUI 侧注入不同 gift 装配。selftest 建议留在宿主壳（bsh bin）不进 crate：23 个 selftest 消费 `run_capture*`/`fs_gifts`/`net_gifts` 等 guest 专面，且其标记是 smoke 契约（见第 5 节），拆动即扩大回归面。

### 3. 内建命令全集 + 外部派发 + 用户可用命令面与缺口

内建 12 个（render_cmd 分发序，main.rs:3352-3436）：`help`（3352，两行清单文案 3353-3363）、`exit`（3365，std::process::exit(0)）、`env`（3369，变量表回显）、`echo <text>`/`echo`（3380/3384）、`run <name>`（3386/3389，调 run_output）、`cat <file>`（3391/3394）、`ls`/`ls <dir>`（3396/3398）、`mkdir <dir>`（3403/3406）、`rm <path>`（3408/3411）、`cd <dir>`（3413/3417，裸 cd = usage）、`pwd`（3419，getcwd 渲染）、`inputpoll`（3434）。裸命令无参一律 usage 2。外部派发（3437-3457）：非内建首词不含 `/` 即查 `bin/<name>`（`cpio_find`），命中 `run_output(name, rest)` 拉起、余词作 argv[1..]；未命中 `bsh: <cmd>: not found` 127。内建优先：裸名 echo/cat/ls/mkdir/rm/cd/pwd/env 被内建分支先吃，uu 同名 GNU 全量面经 `run <name>` 取（3438-3443 注释明文）。

rootfs 实际 bin 集（tools/rootfs-manifest.toml `[entries]` 共 61 条，其中 `bin/` 51 条）：uu 家族 23 件（cat/cp/cut/date/df/du/echo/env/false/head/ls/mkdir/mv/pwd/rm/rmdir/sort/tail/touch/tr/true/uniq/wc，路径 `bins/uu/cargo-target/…musl/release/`）+ 平台件 28 件（bench1/berry-launcher/berry-power/berry-thermal/berry-verify/berryctl/bsh/dpgx/fail/find/fsmgr/gfxdemo/grep/gui-inputd/gui-wmd/guifbd/hello/hexyl/netprobe/policydemo/ps/sigchild/simbattery/stdhello/vblk/vnet/vprobe/which）+ `app/*.bap` 9 件 + `selftest/APPTOMB.bap`。`user/bins/` 目录里另有 abuser/appstub/talker/thrchild/dpgp 等不在 manifest（svcmgr 直拉的自验件，不经 bsh 裸名面）。**用户经 bsh 裸名可跑的命令面** = 12 内建 ∪ 51 件 bin/（扣掉 bsh 自身与 gui-inputd/gui-wmd/guifbd/vblk/vnet/vprobe/fsmgr 这类服务件后，交互常用的有：cat/cp/mv/touch/rm/rmdir/mkdir/ls/pwd/echo/env/head/tail/cut/sort/uniq/wc/tr/true/false/date/df/du/grep/find/which/ps/hexyl/bench1/netprobe/berryctl/stdhello/hello/fail/gfxdemo/sigchild/simbattery/berry-launcher）。

缺口清单（POSIX 常用、逐个核实）：`clear` **无**（不在内建 12，manifest 无 bin/clear；console 是串口透传，需 ANSI 清屏序列或 console RPC）；`history` **无**（editor 有 8 条历史环 editor.rs:24 但无命令面）；`uname` **无**；`uptime` **无**；`free` **无**；`kill` **无**（bsh 内部有 `berry_process_terminate`（main.rs:5578）但无命令面；v1 注释明言「kill/监督随 v2」main.rs:4522）；`which` **有**（bin/which 进 rootfs，u4_selftest 在用）；`type` **无**；`sleep` **无**（libc nanosleep 真身已被 clk_selftest 验通但无 bin）；`date` **有**（uu date，u4 自验 `date -u -d @0` 在档）。另注：`>>` 追加重定向无（见第 1 节）、`export` 无（头注 main.rs:71-73，argv 块无 env 面）。

### 4. 抽库改动的回归风险面

selftest 钉面：23 个 `*_selftest` 函数 + main 内联 hexyl 自验全部钉在 main.rs（共占约 3900 行，main.rs 5627 行的近七成）；它们打 23 个 smoke 标记（见第 5 节清单），任一重组若改变链序（fat 前后契约）、`INT_MODE` 武装时机（main.rs:350-352）、或 `collect` 纯净路径（boot 自验不走 collect_fg 的 C-4r 契约，main.rs:4681-4687），标记面即红。这些必须零回归。

体积面（2026-11-15 实测）：`rootfs.cpio` = 35,663,872 B（34 MiB 整档）；分卷产物 `rootfs0.cpio` = 33,554,432 B（恰 32 MiB 满卷）+ `rootfs1.cpio` = 2,109,440 B（约 2.01 MiB）。单卷帽 = 32 MiB（`mkcpio --split 32`，justfile:349-352；与内核 fwcfg 单卷帽同口径，justfile:353-357 注释）——即当前归档已越帽分成 2 卷，末卷距帽余量 33,554,432 − 2,109,440 = 31,445,992 B（约 30 MiB）。bsh 二进制 454,144 B（约 443.5 KiB，`user/cargo-target/aarch64-unknown-linux-musl/release/bsh`，opt-level="z" + LTO + strip，Cargo.toml profile）——抽库本身不加条目（bsh 仍一件），内建命令扩充若走内建则只影响 bsh 体积（余量充裕），若新增 uu bin 则每件占 manifest 一条 + 末卷余量。

### 5. 行为契约：smoke 对 bsh 输出的断言面

标记面：`tools/markers.sh` ROOTFS_MARKERS 54 项中 **23 项由 bsh 打印**——BSH ok、PIPE ok、FS ok n=、FAT ok n=、FATW ok n=、DIR ok n=、CD ok、U2 ok、U3 ok、B1 ok n=4、DF ok、U4 ok、TAB ok、INT ok、POLL ok、EVS ok n=2、SKT ok n=3、EPL ok n=8、NETS ok n=2、MMP ok n=9、CLK ok n=6、SIG ok n=6、M3DEMO ok n=5（markers.sh:23）；非 bsh 的相邻标记归属：EXIT ok/U1 ok/PS ok n=/BC ok/THR ok/INPUT ok = svcmgr（user/bins/svcmgr/src/main.rs:4873/4938/2830/3123/3144/7554），LSN ok n=7 = vnet（drivers/bins/vnet/src/tcp.rs:1190），HEXYL ok = svcmgr。`assert_marker` 有两个特判与 bsh 直接相关（smoke.sh:454-467）：DEMO ok 需前邻非 I、**TAB ok 需前邻非 G**（防 boot 期 `TAGTAB ok` 子串假阳性）——改 TAB 自验的打印措辞会破此断言形态。掉电相 PWR_MARKERS（smoke.sh:1730）含 bsh 的 5 标记（FS ok n=/FAT ok n=5000/FATW ok n=3000/DF ok/CD ok）。smoke-image.sh ECO_MARKERS（smoke-image.sh:312）含 bsh 的 13 标记（BSH ok/PIPE ok n=/FS ok n=/U2 ok/U3 ok/B1 ok n=4/U4 ok/TAB ok/INT ok/POLL ok/MMP ok n=9/CLK ok n=6/SIG ok n=6）。

## 适用边界

本文是 2026-11-15 工作树快照：行号随并行会话推进会漂（本仓库 git status 显示 kernel/svcmgr/tools/berry 家族有未暂存改动，bsh 两文件与 smoke 三件当前干净，但 smoke-image.sh 与 markers.sh 未逐一比对 git 状态）；rootfs*.cpio 与 bsh 二进制大小是当次构建产物，随 build-user 重产即变；rootfs40/400/401.cpio 与 rootfs1.dpg*.cpio 是历史/专项产物不在 32 MiB 帽讨论内；`.dsh-worktrees/` 与 `.claude/worktrees/` 下的同名文件是并行会话工作树，本文一律未采。缺口清单只论「bsh 内建 ∪ rootfs bin/」这一命令面，不预言 v2 的 `>>`/export/kill 落法；抽库评估是耦合面测量不是实施方案——trait 切法（FsBackend/Spawner/输出 Write）属设计决策，归后续 plans 文档。
