# VNC 直通绝对坐标判例驳斥（A/B 实验）

Type: evidence
Status: current
Updated: 2026-11-20

一句话：well-formed RFB 客户端（发 SetEncodings——浏览器 noVNC 恒发）经 QEMU VNC 直通的 PointerEvent 绝对坐标直达客机（拖拽翻页屏幕实变实拍）——「QEMU 11 VNC 丢绝对坐标」判例被驳。

## 定谳链

判例声称机制（btn/sync 在、abs 恒缺席）的真相：berry 自家裸 RFB 客户端（tools/berry/src/display/vnc.rs，Input-only 形）从不发 SetEncodings → QEMU vs->absolute 保持假 → pointer_event 走 REL 分支 → virtio-tablet 无 REL handler 静默丢弃。审计对照 QEMU 11.0.0 源码定谳：vs->absolute 由 set_encodings 触发 check_pointer_type_change 依设备侧 handler 图置位（virtio-tablet 在席即真），与客户端版本无关。当日观测极可能在裸客户端形态取得并被错误外推到浏览器路。

## 实验记录（2026-11-20）

- 场：desktop 档 1088x1920 无密码（fb=1088x1920 自 ServerInit 实拍——32 对齐实几何）
- Arm1 QMP 拖拽（对照）：变（对照成立）
- Arm2 直通（带 SetEncodings RAW）拖拽：变——判例被驳
- Arm2b 直通单击图标：未命中（页态伪影——拖拽已翻页至空页，非通路失败）

## 实验三陷阱（复现者记）

RFB PointerEvent 无 pad 字节（type+mask+x+y 共 6B，多写一字节推歪协议流即被踢）；帧更新须后台排水（screendump 弄脏屏幕后 QEMU 推全幅 RAW 更新，不读则输出缓冲超帽被踢）；unix vnc.sock 形态异常关闭（TCP 口正常——ws 形态待 A1 复验）。

## 后果（架构）

拦截器 + QMP 注入链 + 双注入 socket + 五套失败语义 + 当日坐标分母修复全链可退役；坐标单源链 = QEMU 表面几何 → 设备 ABS_INFO → inputd 归一，宿主零客机几何知识。裸客户端（ram.rs 原生窗口路）补一发 SetEncodings 即可入正路。证据链立法（架构裁决须携可复现工件入库）随根设计刀1 落地。
