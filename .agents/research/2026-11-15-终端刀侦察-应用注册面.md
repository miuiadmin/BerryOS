# 终端刀侦察（berry-term 新增 GUI 应用的注册面与打包面底册）

Type: survey
Status: current
Updated: 2026-11-15

> 定位：计划新增 GUI 终端应用（工作名 berry-term）前，对「新增一个 GUI 应用」要动的完整文件面做只读侦察——应用注册链（manifest → .bap → svcmgr → launcher 图标 → APP_SPAWN gifts）、spawn 路径与窗口几何、打包链与 rootfs 余量、svcmgr/launcher 工作树脏面归属、berry-appshell 现状。全部结论带 file:line（本日现场直核）。

## 问题

终端刀要给桌面加一个可点击拉起的终端应用。动手前需摸清六件事：① 应用从 manifest 声明到桌面图标出现的全链与逐文件改动面；② APP_SPAWN 在 svcmgr 的处理位置、窗口几何由谁定、boot 批与点击批的差别、appdemo/appquiet/appstub 家族注册差异；③ 打包链（workspace members、justfile build-user、mkcpio）与 rootfs 32MiB 帽的真实余量、musl std GUI 应用的体积依据；④ svcmgr 未暂存改动属哪个并行工作、终端刀要不要动 svcmgr；⑤ launcher 家族脏面与「加桌面图标是否要改 launcher 源码」；⑥ 波 3 计划抽取的 berry-appshell 是否已存在。

## 方法与来源

## 结论

**一、注册链全貌（manifest → 桌面图标 → spawn）**

应用的声明载体是 .bap 包内 TOML manifest（解析器 = user/berry-manifest 纯函数 crate，svcmgr 兼任 appd 消费；内核零「应用」概念）。manifest 字段面（user/berry-manifest/src/lib.rs:10-106 头注立法）：`[app]` 五键必填 id/version/entry/type/intent；`[compat]` 可省（min/target/compile/min_level/abi_revision）；`[capabilities]` 必填 console，可选 fs（词表仅 "rootfs"）与 net（parser 收、svcmgr loud 拒）；`[runtime]` stack_pages（缺省 8）；`[security]` 三键（签名信封回声源）；`[ui]` 三键独立可选 icon（包内 icons/ 前缀 .byi）/label（≤32B 可打印 ASCII）/views；`[agent-actions]`/`[blob]` 占位。**没有 wm 键、没有 spawn 模式键、没有任何窗口几何字段**。实例：user/bins/appdemo/manifest.toml:1-28（全字段形）、user/bins/appstub/apps/SETTINGS/manifest.toml:1-24（占位 GUI 形，[ui] 齐 + console=false）、user/bins/appquiet/manifest.toml:1-18（静默形，无 [ui]）。

链路顺序：staging 目录 {manifest.toml, bin/<ELF>, icons/*.png, views/*} → tools/mkapp.py 打包（PNG 宿主侧编码 BYI1、五道门禁、SHA256SUMS）产 userbins/app/<ID>.bap → tools/rootfs-manifest.toml [entries] 登记 `"app/<ID>.bap" = "userbins/app/<ID>.bap"` → mkcpio 入 rootfs.cpio。开机 svcmgr run_rootfs_child 主走查收集 `app/` 前缀 .bap 条目入 APP_SLOTS_TBL（帽 APP_SLOTS=9，user/berry-manifest/src/lib.rs:154；超帽条目 `eco: app too many` 可见降级，user/bins/svcmgr/src/main.rs:823-827 注释），走查毕 boot 批全量拉起并同步收口打 `APP ok n=`（user/bins/svcmgr/src/main.rs:2107-2177）。launcher 起后 icons::init 经 app_cli 通道发 APP_LIST_REQ（user/bins/berry-launcher/src/main.rs:234-237、icons.rs:151-166），svcmgr app_serve_list 流式回 N × ENTRY{id,label,w,h,blob_len} + 192B 分片 + END（user/bins/svcmgr/src/main.rs:7112 起），launcher 解码 BYI1 建 AppEntry 注册表与稠密图标 id（icons.rs:1-29、102-113）。桌面格 = 布局文件 cells 与注册表的交集：布局来自 FAT12 数据盘卷根 LAYOUT.JSN（缺席/损坏回默认布局 = 注册表序铺格，user/bins/berry-launcher/src/layout_io.rs:111-152），desktop build 逐 cell 查 reg 命中才建可点击格（user/bins/berry-launcher/src/desktop.rs:513-536）。点击命中格 → registry 取 id → encode_spawn_request 经 app_cli 发 svcmgr（user/bins/berry-launcher/src/frameloop.rs:845-897）。

**APP_SPAWN 的 gifts 面（关键缺口）**：svcmgr app_launch（user/bins/svcmgr/src/main.rs:5957 起）给 .bap 应用的端点只有两类——stdout（console=true 直通串口 / false 建私有对收集）与 fs 词在场时的两元 [rootfs RO dup, fsmgr 对 dup]（user/bins/svcmgr/src/main.rs:6065-6127）。**wm（gui-wmd 客户端端）、input（gui-inputd 客户端端）、gfx 通道均不在 app 域授予面**——GUI 服务端点只授给 svcmgr 亲自 spawn 的常驻进程：launcher_assemble 给 launcher 的 lgifts=[wm fresh, fs, app 通道对端, input dup]（user/bins/svcmgr/src/main.rs:6935-7046），guifbd/gfxdemo/gui-wmd 亦是预拉硬编码直递。即当前架构下 .bap 应用（含 APP_SPAWN 点击拉起的）拿不到任何窗口系统端点——berry-launcher/gfxdemo/gui-wmd 都不是 .bap 应用，是 rootfs 裸 bin + svcmgr 硬编码预拉。**终端刀要窗口就必须在 svcmgr 立法「app 域 GUI 授能」**（见结论四）。

图标资产位置：app 图标 = .bap 包内 icons/<stem>.byi（mkapp 从 staging PNG 编码，源不入包，tools/mkapp.py:33-45 头注）；launcher 内建图标（状态栏三面、dock 四面、导航六面）是 status_icons.rs 内嵌像素/程序化自绘（user/bins/berry-launcher/src/icons.rs:46-85），与 app 图标域无关，加新 app 不碰。

**新增 berry-term 的逐文件清单**（.bap 注册路）：新建 user/bins/berry-term/Cargo.toml（独立小工作区 [workspace] + musl 链配置 + berry-libc/berry-guiproto/berry-ui 等依赖）与 src/main.rs（与 appdemo 同形：`#[used] static CRT0_SEED` 锚 + ExitCode 退出；与 gfxdemo 同形的 wm 建窗待 svcmgr 授能落地）；新建 manifest.toml（entry = "bin/berry-term"）与 icons/icon.png（BYI1 编码由 mkapp 代办）、views/ 视需；改 justfile build-user 加构建段（照 appdemo 段 justfile:163-170）与 staging+mkapp 段（照 justfile:301-312）；改 tools/rootfs-manifest.toml [entries] 加一行。**另有两处结构性硬点**：① APP_SLOTS 9/9 恰满（rootfs-manifest 在册 9 个 .bap：APPDEMO/APPQUIET/BROWSER/CAMERA/CONTACTS/MMS/FILES/PHOTOS/SETTINGS，tools/rootfs-manifest.toml:36-44），加第 10 个要么抬帽（berry-manifest 常量 + mkapp.py 镜像 + svcmgr 槽表与 `APP ok n=` 单数字位 assert（user/bins/svcmgr/src/main.rs:2165）三面联动）要么撤一个占位 .bap；② app 域 GUI 授能（svcmgr + manifest 词表扩词）——终端应用要窗口就绕不开。

**二、spawn 路径与几何**

APP_SPAWN 处理链：稳态循环 app_serve_one 收帧分派（user/bins/svcmgr/src/main.rs:7056-7101，op 门先行）→ parse_spawn_request 校 25B 帧 → app_serve_spawn（user/bins/svcmgr/src/main.rs:7267）：记账表 APP_SLOTS_TBL 按定位 id → 槽位预检（APP_SPAWN_LIVE_MAX=4 活子上限，main.rs:782-784；满表拒新 err=1 打 `eco: app slots`）→ p3_sig_guard 验签 → app_launch 全守卫复用（bap_scan → manifest parse → type/console/compat/net/fs 守卫 → spawn_rootfs_elf）→ 拉起成立即入 APP_CHILDREN、ACK ok=1 即返（退出码归 eco 行与 ps 账本，异步收口在 app_supervise，main.rs:7447）。id 不在册 err=2。

窗口几何由**应用客户端自己申请**：WM_CREATE 请求 16B 自带 layer/flags/parent/group/x/y/w/h（user/berry-guiproto/src/lib.rs:1492-1529 encode_wm_create_req），gui-wmd 按 AVOID_SYS 避让裁剪后回 window_id；manifest 无几何字段、launcher 只传 id（encode_spawn_request `[op][id 24B NUL 补齐]`，user/berry-appproto/src/lib.rs:16-19）、svcmgr 不传几何。berry-term 的窗格位置尺寸完全自定于应用源码内。

「常驻被拉起」与「点击 spawn」的分野：.bap app 无常驻形态——boot 批是走查毕全量拉起 + 同步 reap 的瞬态批（`APP ok n=` 要求全部退出真码 0，main.rs:2131-2141）；点击批走 APP_SPAWN 异步监督。真正常驻的 GUI 进程（launcher/guifbd/gui-wmd/gui-inputd）全部是 svcmgr 预拉硬编码，不经 app 域。家族注册差异：appdemo（musl std，console=true + fs=rootfs，boot 批瞬态 + GUI 验收双件之一，argv0 断言 + mtab fs 自证）；appquiet（musl std，console=false 静默退出，无 [ui]，GUI 验收双件之二）；appstub（aarch64-unknown-none 静默壳 4912B，justfile:329-338 循环复制为 7 个占位 app 的 bin/<name>，各带 [ui] icon/views 但点击拉起即静默退出）；apptomb（musl，selftest/ 前缀打包不入 bap_scan 收集——lifecycle 验收件不占 APP_SLOTS）；berry-launcher/gfxdemo/guifbd/gui-wmd（rootfs 裸 bin，不在 app 域，svcmgr 各自预拉 arm）。

**三、打包链与余量**

user/Cargo.toml members 只含纯函数 crate 与 none target bins（svcmgr/hello/echo/berry-verify 等，user/Cargo.toml:131），exclude 明列 stdhello/appdemo/appquiet/apptomb（user/Cargo.toml:133）；berry-launcher/gfxdemo/guifbd/bsh/ps 等所有 musl std bin 都是「独立小工作区」——不在 members 也不在 exclude，由 justfile build-user 逐个显式构建（berry-launcher 段 justfile:246-248）。**berry-term 照此形态建独立小工作区，不动 user/Cargo.toml members**。构建链：cargo build --release --target aarch64-unknown-linux-musl + RUSTFLAGS 指向 tools/berry-ld（剥 musl crt、-zmax-page-size=4096）；.bap 面：staging 组装后 tools/mkapp.py 产包（门禁五道含 entry==bin 唯一文件、规范形重序列化逐字节相等、ELF 魔数）；rootfs 面：tools/mkcpio.py ../rootfs.cpio --manifest ../tools/rootfs-manifest.toml --split 32（justfile:349-351），.bap 的伴生 .bap.sig 由 mkcpio sig_companions 同名自动收编（rootfs-manifest.toml:29-32 注释），签名链 sign-user 对 rootfs-manifest 的 app/*.bap 循环签发（justfile:403-411）。

**32MiB 是单卷帽不是总量帽**：--split 32 产 rootfs0（恰 33554432B = 32MiB 满）+ rootfs1（2109440B ≈ 2MiB），单档 rootfs.cpio 总 35663872B ≈ 34MiB；内核 fw_cfg 多卷装载按 opt/berry/rootfs0..9 连续前缀拼装、总量帽 128MiB（kernel/src/main.rs:96-99、151-159）。**当前有效余量 = rootfs1 卷内 ~30MiB**，新增一个 GUI 应用毫无压力。体积依据（本日产物 ls -l）：berry-launcher 774536B（berry-ui 全链 + 内嵌壁纸/图标资产 + 帧循环，musl std GUI 形态的上界参考）；gui-wmd 336720B；gfxdemo 349544B；appdemo 332624B（musl std 最小形态）。berry-term 类 launcher 形态（berry-ui + guiproto + 自有字形表）预估 0.5-1.0MiB；再叠 manifest/SHA256SUMS/icon.byi 的 .bap 容器开销（百字节级 + 图标 RLE KB 级），rootfs 增量约 1MiB 量级。

**四、svcmgr 未暂存改动归属与终端刀撞面**

git diff 两文件：link-user.ld（+19/-7）= pager 钉位 0x1E000→0x28000、栈顶 0x20000→0x29000、帽 128→160KiB 的 CP-08 扩容；main.rs（+66）= run_rootfs_child 内 vnet 后新增 berry-power/berry-thermal 双服务预拉 arm（cpio_find + spawn + `eco: berry-power up` 观测行）。同批未暂存 kernel/src/user.rs（USER_CODE_MAX 160KiB，kernel/src/user.rs:88）与 kernel/src/main.rs 钉位同值双改，未跟踪笔记 .agents/notes/implemented/2026-11-15-cp08-d3-cap-pm-prepull.md 在册。**归属 = CP-08 电源管理闭合刀（D3 帽扩容 + PM 预拉），不是波 1/波 3/wave11**——wave11 是 vnc-lan（脏面在 tools/berry 家族 + justfile vnc 段），波 3 是桌面三栏（脏面在 berry-ui）。

**终端刀动 svcmgr 的必要性：有**，两个独立理由：① APP_SLOTS=9 恰满（见结论一）——不动 svcmgr 就得撤一个占位 .bap；② app 域 GUI 授能缺位——终端要窗口就要在 app_launch（或其调用侧）给 .bap app 授 wm/input（gfx 面 guifbd 经 wm 中继，应用可零直连）端点，这必然改 svcmgr 的 app_serve_spawn/app_launch 装配段与 APP_SPAWN 监督面，且大概率要 manifest capabilities 加 GUI 词（berry-manifest 解析器 + mkapp.py 镜像双侧同步）。**svcmgr 注册表是纯数据驱动的（.bap 收集无硬编码 app 名单），「注册」本身零改动；必动的是「帽」与「GUI 授能」两处。** 与 CP-08 未暂存改动的物理撞面：同在 run_rootfs_child 函数内，但 CP-08 段是纯新增 arm 块且笔迹已录，先落 CP-08 再起终端刀即无合并冲突。

**五、launcher 脏面与图标改动面**

git status：berry-launcher 家族（src 七文件 + Cargo）**零脏**，波 3 未在 launcher 开工。唯一相邻脏面是 berry-ui crate（desc.rs/layout.rs/lib.rs/paint.rs 四文件，+215/-41）——diff 内容自称「批 F（末刀三件）：Gauge/Qr/DragReorder——41 kind 收口」，属 berry-ui widget 批量刀，是波 3 appshell 的依赖底座而非 launcher 面。

**终端刀加桌面图标不需要动 launcher 源码**（网格格数据驱动：APP_LIST → registry → 布局交集建格），三个例外要记：① 想进底部 dock 常驻四格要改 DOCK_IDS（user/bins/berry-launcher/src/desktop.rs:163）；② 想从官方桌面隐藏（如 APPDEMO/APPQUIET 验收件待遇）要改 TEST_IDS（desktop.rs:161，official_present 逻辑 desktop.rs:521-525）；③ **LAYOUT.JSN 持久化陷阱**——数据盘已有健康布局文件时 load 直接采用不并入新册 app（layout_io.rs:128-152 的 Bytes+Ok 分支无合并逻辑），berry-term 上桌要么删数据盘 LAYOUT.JSN 触发自愈回默认布局、要么改写布局文件纳入新 id，否则新 app 注册在册却无格。

**六、berry-appshell 现状**

user/ 目录 26 个 crate 全列无 berry-appshell（ls 直核）；波 3 计划（并行会话 in-flight 件 .agents/plans/2026-11-15-波3桌面三栏与系统窗实施设计.md，落库前行级引用悬空风险自担——§6 模块抽取清单）明确它是「新 crate user/berry-appshell」待抽取（launcher 五模块抽应用壳 + Dialog/Menu/Toast v1，APPDEMO 升格首个消费者）。**当前不存在 ⇒ 终端应用只能基于 berry-ui + berry-guiproto 自建骨架**（与 appdemo/gfxdemo 同形：独立小工作区 + 自写帧循环/RPC 半程）。与波 3 有时序耦合：若 berry-appshell 先落，终端应改为其消费者，避免自建骨架后被二次迁移——终端刀排期应与波 3 对齐取先后。
