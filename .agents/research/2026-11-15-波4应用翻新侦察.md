## 问题

波 4 要把 7 个占位 app（SETTINGS/FILES/PHOTOS/CAMERA/CONTACTS/MMS/BROWSER）从秒退壳翻新为真 UI 应用（模板 = launcher 五模块 + berry-appshell，顺序 Settings→Files→Contacts→Photos→Camera→MMS→Browser，appdemo 改控件画廊），验证面 = 逐应用 VNC 截图、`APP ok n=` 零回归、串行 spawn ≤4、包体合计不破 rootfs 32MiB 帽、文案限 ASCII（总纲 :19/:27）。动手前需要七项底册：七应用现状、spawn 约束、rootfs 预算、持久化先例、波 2 冻结名、波 3 消费面、ASCII 词汇表。

## 结论

### 一、七个预制应用现状（user/bins/）

**appstub 共用秒退壳**：`user/bins/appstub/src/main.rs` 全 37 行——no_std/no_main，`_start(env)` 收 env 块（argv0 + extras 全收只清队列，:13-20），console=false 的 stdout 需零长 EOF（`berry_channel_send(hs[0], …)` EBUSY 自旋，:23-30），随后 `berry_process_exit(0)`（:31）。头注自述「单包体 ~数 KB，8 个占位 app 不破 rootfs 32MiB 帽，真 app 内容后续替换」（:4-5）。ELF 实测 4,912 B（aarch64-unknown-none，opt-level z + lto + strip，Cargo.toml:13-17）。七个 app 共用同一 ELF，按 manifest `entry` 串拷进各 staging 为 `bin/<name>`（justfile:324-334：SETTINGS:settings/FILES:files/PHOTOS:photos/CAMERA:camera/CONTACTS:contacts/MMS:messages/BROWSER:browser）。

**staging 三件套形态**：每 app 目录 = `{manifest.toml, icons/icon.png, views/main.bui}`（user/bins/appstub/apps/<ID>/）。manifest 范例（apps/BROWSER/manifest.toml 全文）：`[app]` id/version/entry=`bin/browser`/type=app/intent=utility；`[capabilities] console = false`；`[runtime] stack_pages = 8`；`[security]` 三键（profile=ed25519-main/key_lineage=berryos-dev/integrator=berryos）；`[ui]` icon=`icons/icon.byi`/label=`Browser`/views=`views/main.bui`。七 app manifest 仅 id/entry/label 三处不同（label 已是英文短词：Browser/Camera/Contacts/Files/Messages/Photos/Settings）。views/main.bui = 单行注释占位（`// OpenHarmony visual-fill appstub placeholder view`）。

**打包与能力面**：mkapp.py 打包 `.bap`（cpio newc：manifest.toml + 唯一 bin/ ELF + SHA256SUMS + icons/*.byi + views/*，mkapp.py:46-49），icons/ PNG 源由 mkapp 编码为 BYI1 入包（源不入包，:54-56），帽 = ICON_FILES_MAX 4（:194）/VIEWS_FILES_MAX 4（:195）/ICON_DIM_MAX 1024（:196）/ICON_PIXELS_MAX 65536（:197）。单包 ≤ BAP_MAX 4MiB（berry-manifest lib.rs:146）。能力授予全在 svcmgr `app_launch`（svcmgr main.rs:5957）：console=true → stdout=console 原值（appdemo 的 `app APPDEMO up` 落串口面）；false → `channel_pair` 私有对（:6052-6062）；fs 词在场 → rootfs RO dup（RIGHT_READ|RIGHT_TRANSFER）+ fsmgr SEND|RECV dup 双 gift（:6063-6104，env hs[4]/hs[5] → GIFT_H[0]/[1] → berry-libc `rootfs_h()`/`fs_h()`）；net 词 loud 拒「net unserved」（:6038-6041）。

**图标资产现状**：每 app icons/icon.png = 108×108 RGBA PNG（genohicons.py:2-4 生成，外轮廓 = OH `ohos_icon_mask.png`，源 = user/bins/appstub/ohassets/{raw,glyphs}；实测 apps/BROWSER 9,045 B）。launcher 经 APP_LIST 流拿 icon 分片（appp APP_ENTRY 头 + CHUNK 流 + END，berry-appproto lib.rs:16-27；svcmgr app_serve_list :7138-7252）。占位包体实测（user/userbins/app/，2026-11-15 构建）：BROWSER 94,208 / MMS 77,824 / CAMERA 57,344 / PHOTOS 57,344 / CONTACTS 61,440 / SETTINGS 61,440 / FILES 49,152 B——七包合计 458,752 B（≈448 KiB，ELF 仅 4.9KiB，余为 BYI 图标 + cpio 框架）。

**族内其余成员**：appdemo（user/bins/appdemo/）= std+berry-libc 形真 main（main.rs:26-47）：argv0 断言 `bin/appdemo` → `println!("app APPDEMO up")` → fs 词自证读 `/etc/mtab` 断言 `"/dev/root / fat rw 0 0\n"` → `app APPDEMO fs ok 23` → exit 0；manifest console=true + `fs = ["rootfs"]` + `[compat]` 三值 min_level=1；ELF 332,624 B、.bap 385,024 B；icons/icon.png 在、views/main.bui = GUI-7 声明式资源位占位注释件（头两行自述 v1 不解释）。appquiet = console=false 静默件 + lifecycle absent 探针（appquiet main.rs:1-11、:41-42；.bap 348,160 B）。apptomb = lifecycle 三口自验件，打包走 `selftest/APPTOMB.bap` 专用位不入 boot 批（justfile:341-347、rootfs-manifest.toml:106；.bap 352,256 B）。abuser = 裸相 eco 测试件（内核 spawn，非 .bap、不在 rootfs-manifest）。GUI-8 桌面验收双件 = APPDEMO+APPQUIET（desktop.rs:160-163 TEST_IDS），Dock 常驻四件 = CONTACTS/PHOTOS/SETTINGS/MMS（desktop.rs:164 DOCK_IDS，OH PhonePresetDockItem 官方序）。

**串口标记面**：`APP ok n=` = rootfs 相第 23 标记（markers.sh:24 ROOTFS_MARKERS），svcmgr boot 批打印（main.rs:2107-2170）：全槽 bap_scan→manifest→双守卫→拉起→EOF/reap 真码 0 全过才打，`APP_SLOTS < 10` 编译期钉单数字位（:2165-2168）；`APPUI ok n=` = 第 24 标记，[ui] 面全验过才打（:2173-2181）。boot 批先于 bsh 拉起、单 app 串行收口（:2107-2113、:2143-2148）。gui8-smoke 另断言点击 spawn 后新增 `app APPDEMO up` 恰 1 行（gui8-smoke.py:23-39、:83 MARK_APP_DEMO_UP）。

### 二、spawn 约束

**APP_SPAWN_LIVE_MAX=4 执法点**（svcmgr main.rs）：常量定义 :784；`APP_CHILDREN: [Option<AppSpawnTail>; 4]` 静态表 :789-790。三处执法——① GUI 相 SPAWN 槽位预检在 spawn 前：满表先拒不打拉起，`eco: app … app slots` + ACK err=1（:7281-7299）；② serve 循环 wait 集宽度 = 2+2×4=10（svc + 4 子 × 2 信号，:476、:532-536）；③ 稳态 `app_supervise` 表扫 O(4)（:7446-7456，take→回表形非阻塞 drain + TERMINATED poll reap）。boot 批不受此帽（批内同步串行 reap，槽即收即还，:2143-2148）。

**串行 spawn 现状**：svcmgr 单线程 echo 循环 = APP_SPAWN 请求一次一个串行处置；拉起成立即刻入表 + ACK 先发（M-C 真异步形，:7255-7266），collect_eof 60s + reap 30s 收口归 app_supervise 异步兑现——回执不冻 echo/监督。即：spawn 请求串行、存活 app 可至 4 并存异步收口；boot 批则逐个 spawn→reap 全串行（:2107-2148）。

**应用启动链**：launcher frameloop 点击命中 → `encode_spawn_request`（frameloop.rs:856，`app_cli_h()!=0` 门控）→ svcmgr `app_serve_spawn`（:7267）→ 注册表定位（APP_SLOTS_TBL 走查单源，:7270-7280）→ 槽位预检 → `p3_sig_guard` 装载期验签（:7310）→ `app_launch`（:5957）全守卫链：bap_scan（STEP_WIN 512B 流式步进，:5969）→ manifest parse → type=app 守卫（:5997）→ id↔文件名/entry↔包内条目双守卫（:6001-6009）→ compat min/min_level 装载期检查（:6019-6033）→ net 拒（:6038）→ ui_face（:6044）→ console 分岔（:6056）→ fs 双 gift（:6072-6104）→ `spawn_rootfs_elf(SpawnSpec{name=entry 串, data_off=bap 内 ELF 偏移, stdout, stack_pages, extra_gifts=fs})`（:6108-6128）。bootstrap 句柄 = env 块：子进程 `_start(env: Handle)` 单句柄起步（appstub 形）或 berry-libc crt0 解析 argv/gifts（appdemo/apptomb 形）；argv[0] = manifest entry 串（错值 = app 侧 assert 炸 = 标记缺失 loud，appdemo main.rs:14-20 注记）。

**波 4 缺口（GUI 通道授权缺位）**：现 app_launch 的 extra_gifts 恰 fs 两枚（:6107、:6123）——GUI 应用要开窗还需 wm 客户端端/inputd 端，现无授权路径；对照 launcher 独享 extras [wm, fs, app_cli, input] 四件（`launcher_assemble` :6935-6991，wm_fresh = WMD_CLI_DUP 别名、in_dup = INPUT_A 别名）。波 4 设计需裁决 app 侧 wm/input gift 面（候选：APP_SPAWN 应答随行 gift / 新 env 槽 / appshell 经 launcher 中继），否则真 UI 应用无窗可开。

### 三、rootfs 预算

**32MiB 帽执法点（帽分家）**：单卷帽 `ROOTFS_MAX = 32 << 20`（kernel/src/main.rs:94）——fw_cfg 多卷发现序 opt/berry/rootfs0..9 逐卷执法（:161-174，越帽/空卷 = 整源降级「无 rootfs」存活）；旧名单单卷路 `opt/berry/rootfs` 同帽（:596-599）；handoff 单 blob 同帽（:553）。总量帽 `ROOTFS_TOTAL_MAX = 128 << 20`（:99，:175-177）。产链侧 = mkcpio `--split 32`（justfile:349-351；mkcpio.py `split_volumes` :106-115），rootfs0 在席走多卷名、缺席回落单卷名（smoke.sh:547-557）。

**当前余量（2026-11-15 实测）**：rootfs.cpio 单档 35,663,872 B（34.0 MiB，已超单卷帽——只能走多卷路）；rootfs0.cpio 33,554,432 B（恰满 32MiB 卷界）+ rootfs1.cpio 2,109,440 B。余量口径：总量帽 128MiB − 34.0MiB ≈ 94MiB；末卷余 ≈ 29.9MiB（再长自动出 rootfs2，rootfs0..9 十卷上限）。总纲 :27「包体合计不破 rootfs 32MiB 帽」按现行法 = 单卷帽经 `--split 32` 自动分卷消化，实质硬界是 128MiB 总量帽。

**真 UI 包体估算依据**（全静态 musl 链、无共享库——应用模型已定）：参考系实测 ELF——launcher 774,536 B（libc+berry-ui+fsclient+guiproto+五模块全链，真 UI 应用上界锚点）；guifbd 345,696 B / gui-wmd 336,720 B（服务件）；appdemo 332,624 B（libc 无 berry-ui）；appstub 4,912 B（no_std 壳）。估算法：真 UI stub ≈ launcher 级 − 桌面特化（网格/壁纸/dock 留 launcher）+ appshell 抽取件，落 0.6-0.8 MiB/个；七 app 合计 ≈ 4-6 MiB 增量（现 448 KiB → Δ≈+4-5 MiB），加 appdemo 画廊化 ~0.8 MiB，rootfs 总量 34.0 → ≈39-40 MiB，128MiB 帽内宽裕、32MiB 单卷由分卷自动满足；每包仍受 BAP_MAX 4MiB 独立帽。风险位：svcmgr 128KiB 平像帽（波 3 §9 已挂账复测，波 4 若动 appp 帧面同批核）。

### 四、持久化先例（波 3 BOOT.JSN 同款）

**layout_io.rs 三约束 + canonical 单簇原子写**（user/berry-launcher/src/layout_io.rs，589 行）：责任 = FAT12 卷根 `LAYOUT.JSN` 读 → berry-layout parse → Owned 镜像（:1-7）。三约束 = 缺席回默认 + 读/解析失败回默认重写自愈 + 写失败非致命（launcher 不死常驻纪律）。写路径纪律（:13-17）：单簇 ≤2048B 近原子（`LAYOUT_BYTES_MAX` 单源——berry-layout lib.rs:82，FAT 单簇文件掉电三态近原子）；严格串行单 RPC 会话（fsclient 单读者协议，一次只持一个 fd，open→…→close 不重叠）；**close 即 commit**（TRUNC 游标两段式，bsh put_file 同款）。`save`（:354-356）= encode canonical ≤2048 → open(O_WRONLY|O_CREAT) → write 循环 → close；`read_file` 超 2048 即停归 Oversize（:320、:344）；`heal` 自愈（:297）；冻结相 `fs_h()==0` 显式早退零 RPC（:131-135）。canonical 形态（:32-36）：`{"schema":1,"cells":[{"app":"…","page":n,"row":n,"col":n},…]}`。波 3 BOOT.JSN = appshell::conf 同款（波 3 稿 :98、:106——宿主读回复用 tools/gui8-smoke.py FAT12 读回实现）。

**FAT 挂载与 /apps 树真读能力**：fsmgr = RAM 树 + FAT12 读写层（fsmgr main.rs:17-22——多段子目录链读面、MKDIR/UNLINK 纯 RAM 面、FAT 建删目录不在 C-0 盒）；`/etc/mtab` 启动预建定值（:70-76）。应用侧真读通道 = berry-fsclient（open/close/read/write/lseek/stat/opendir/readdir/chdir/getcwd 组装，fsclient lib.rs:20；READDIR 子名 blob 逐名迭代 :815-817、dirent 无 d_type :45；berry-libc fs.rs:744 目录族三件套）；授权面 = manifest fs 词 → fsmgr 对 SEND|RECV dup（appdemo `/etc/mtab` 真往返自证，appdemo main.rs:35-45）。

**/apps 树缺口（波 4 Files 项前置裁决）**：v1 无 /apps 树——`.bap` 增删推送是 v2 前提（berry-appproto lib.rs:18、:63「v1 rootfs 静态 cpio 无」）；fsmgr 不挂 rootfs cpio 为文件树（仅 RAM + FAT12 数据盘），rootfs 内容由 svcmgr 流式走查独占。总纲 :27 Files 项「真读 /apps 树」现无载体——候选裁决：svcmgr APP_LIST 元数据扩展 / fsmgr 新面（rootfs cpio 只读树）/ FAT 镜像目录，波 4 设计稿需显式定其一。
