### 二、guifbd 窗口/提交链（user/bins/guifbd/src/）

**blit-at-SUBMIT 现状（无合成）**：present 域 SUBMIT 分发在 guest.rs:502-511 → submit():597-729，形态 = 处理内同步 CPU blit——damage 逐 rect 行弹 vmo_read 进 bounce 缓冲再直写 FB_VA（guest.rs:641-668），无 pending 帧状态机，squash / DISCARDED / SUBMIT_F_UNSQUASHABLE 是死路径（guest.rs:595-596 头注、629-630）。FRAME_CALLBACK 应答即 latch（token 环 8 槽，guest.rs:137-138、513-543）；credits = 在途未 RELEASE 别名数 ≤ CREDITS_MAX=2（guest.rs:145-146、624-627）；「无 damage 不提交」两条 ST_BAD 服务端立法（K>0∧FULL 同设 / K=0∧无 FULL，guest.rs:617-621）；SUBMIT 后还有 7 点抽样对拍仪表（guest.rs:676-710）。

**WM/SUBMIT 协议消费分家**：guifbd 只消费 present 域六 op（handle_present，guest.rs:477-593）+ hdi 域四 op（handle_hdi，guest.rs:732-827）+ console 路；wm 域六 op 的消费在 gui-wmd（table.rs:352-381）。wmd 把 wm 客户端的 present/hdi 请求帧字节级透传给 guifbd（relay.rs:64-117；main.rs on_wm 分发表 :136-157——present 1..=6 / hdi 0x40..=0x43 / wm 0x60..=0x7F / 其余一切 op 含 input 域错投 = ST_BAD）。

**layer 概念现状**：guifbd 零窗口零 layer 概念——单 fb、单 vgpu 资源 VIO_RES=1 单 scanout（guest.rs:898-901）；SUBMIT 的 surface_id 被忽略（guest.rs:503 `surface_id: _`），几何门假定 buffer 与 fb 同几何同 stride（guest.rs:606-613）。layer 只存在于 wmd 表（WM_LAYER_APP=0 / WM_LAYER_SYSTEM=1，berry-guiproto lib.rs:104-106）且只是避让与命中的策略元数据，无任何渲染语义。这是波 3 带合成 v1 要从零立的面。

**AVOID_SYS 避让机制**（wmd 侧，guifbd 零感知）：WM_CREATE_F_AVOID_SYS 旗（berry-guiproto lib.rs:107-108）→ table.rs 不变量式重算 recompute:187-216——对 layer=SYSTEM 的**可见**窗求差集、单矩形保形裁剪 clip_rect:47-77（四条剩余带取面积最大者；全覆盖 → w/h=0 恒不中；隐藏系统窗不挖坑）→ 有效几何回显快照（table.rs:153-165）；申请几何 req 与有效几何 eff 分域在案（table.rs:30-45）。

**console fan-out**：用户态 stdout / 内核 console 字节流经 svcmgr 转发进 guifbd pipe（gift3_h，guest.rs:1643-1649）→ poll_console:435-473——GUI 模式只记账不上屏（gui 旗，guest.rs:459-466，防日志盖桌面），非 GUI 恒同步直写（A2-a 立法：文本路禁入 vsync 排队呈现）；每条消息 = 一次 FULL 纯记账（console_full_n++ 与 present_seq 共享抬高，guest.rs:470-471），不占 credits 不发 token。

**vgpu 双后端（B 系 guest 半，已落地）**：boot 交接单字节 'w'/'n'（lib.rs:41-44；guest.rs:1520-1526）→ vio_init 四命令链 GET_DISPLAY_INFO → CREATE_2D → ATTACH_BACKING（backing = fb 窗同一物理段，ramfb/vgpu 双设备同屏一致）→ SET_SCANOUT（guest.rs:1411-1512）；v2 帧批 = per-rect K×TRANSFER_TO_HOST_2D + 单 FLUSH 包络 + fence 回显，异步发车 2-deep（lib.rs:247-288 frame_flush_batch；guest.rs:1274-1402 submit_frame、1194-1256 reap）；ramfb 相 None 恒短路零漂移（红线，guest.rs 头注 :58-72）。

**B 系边界与波 3 合成 v1 不撞法**：[显示与加速体系设计 v1.1](../../docs/显示与加速体系设计-v1.1.md) 刀序表——刀 5 = guest 半 virtio-gpu 2D（02 号 B1-a，已落）；刀 6 = **B1-b 壳半 GPU 呈现 β-0**（winit+wgpu 呈现骨架 + Frame damage 载荷 + GPU 缩放合成/工具栏 + 截图 readback，文件面 = tools/berry/src/display + window）；刀 7 = **B1-c 动态分辨率 + density 事件流**（SET_SCANOUT 动态几何 + events/EDID 消费 + info VMO density 域 + 壳 Resize 接窗）；刀 8 = B1-d β-1 收尾（B1-b/B1-c 定义原文见 [02 号](../../research/显示与加速体系设计/02-virtio-gpu-2D档-GPU加速路径兑现设计-v1.0.md) :139-140）。波 3 带合成 v1 = guifbd serve 循环内缓存 SYSTEM/SERVICE 带、APP SUBMIT 后按 SERVICE>SYSTEM>APP 重放带缓存（六波实施方案 :26）——纯 guest 侧 CPU 合成、文件面在 guifbd guest.rs 的 Srv/submit，与 B1-b/B1-c 的宿主壳半（tools/berry）文件面互斥，天然不撞。两处硬约束承重：①六波实施方案 :19「7fd1709c 判例否决内核热路径进度插值（平滑算法只活 guifbd、条区局部重绘）」——合成算法同理只活 guifbd serve 循环 + 局部重绘；②guifbd 服务状态全静态定容（guest.rs:53-55；行弹舱 ROW_BOUNCE_MAX=16384 启动门执法 :139-142、1637-1642）——带缓存也须静态定容、守零唤醒不变量（guest.rs:55-56）。与已落 vgpu 后端的接缝：现钩子位置 = CPU blit 落 fb 后、抽样前（guest.rs:669-675），带缓存重放的定序要在此缝内裁决。**标签错位注记**：guifbd 头注（guest.rs:58、lib.rs:1-2）与 [09 号复核](../../research/显示与加速体系设计/09-B1bc复核.md) 把 vgpu 双后端称「B1-b+c」，与 02 号 §6 刀序表「B1-a=guest 半 / B1-b=壳半 / B1-c=动态分辨率」（02 号 :138-140）标签冲突——波 3 对齐以 docs 标准刀序行为准，勿被代码头注的 B1-b/c 字面误导。

### 三、wmd（user/bins/gui-wmd/src/）

**窗口管理现状**：权威窗口表 WmTable 静态定容（WM_WINDOWS_MAX=15 项，table.rs:79-117）；wm 域六 op = GETINFO / CREATE / DESTROY / SET / TABLE_GET / TABLE_WAIT（table.rs:352-381）。CREATE 默认可见 + 接焦、parent≠0 须在册、表满 ST_FULL、应答 8B ack(window_id)（table.rs:251-283）；SET 掩码式 GEOM/VIS/Z 同帧原子（table.rs:304-329）；DESTROY 摘窗保建序 + 持焦归还（table.rs:285-302）。version = epoch u8<<24 | counter u24、恒 ≥1（空表初始化即 ≥1，冷启动 WAIT(0) 恒立即答；table.rs:7-11、91-117、119-128）；快照 252B 单帧 ≤ CHAN_MSG_MAX（table.rs:175-182）。wmd 启动序五步与两路 poll-first serve 见 main.rs:173-245。

**table.rs:15 TABLE_WAIT 单车位语义注记原文**（table.rs:12-16，总纲风险 :34 点名波 3 动手前先核的那段）：

> **parked**：单车位 TABLE_WAIT（应答通道 + 其 last_seen）。**单车位语义钉死（R2 备注⑦）：后到 WAIT 现答现快照并覆盖 parked 不排队**——位移者立即以现快照应答（防悬挂；v1 两客户端面各自严格串行 RPC 结构性不可达，后刀多客户端注意）；表变更向**当前** parked 应答全表快照并清空（消息序 = 表序，无竞面）。

波 3 相关性：launcher 双窗化 + TabBar/应用窗后 wm 客户端面将超过「两客户端」假设；wait() 实现在 table.rs:339-348（后到 WAIT 先现答旧 parked 再占位）。同批还有新鲜度结构注记——wmd serve 单线程中继期间表不可能变的论证只在「v1 wm 客户端恰一个」下成立，main.rs:29-35 明文「后刀第二 wm 客户端注意：中继阻塞期间对端可变更表 → TABLE_GET 应答快照与『请求到达时』表态可能有出入（新鲜度窗口 = 一次中继时长），届时须评估 per-request 快照戳或拆线程，勿直接加客户端」。两注记都在波 3 触达范围。

**焦点概念有无**：表侧已有——focus: Option<u16>（table.rs:82）；快照位 WM_WIN_F_FOCUSED（berry-guiproto lib.rs:121-122；table.rs:150-152 置位）；CREATE 新窗接焦（table.rs:277）；SET_F_VIS SHOW 接焦 / HIDE 持焦归还（table.rs:315-321）；摘窗 refocus_after_removal = 表序最末可见窗接焦、无可见窗则无焦点（table.rs:234-236）。但**没有主动焦点 op 与返回键路由**——OP_WM_FOCUS / OP_WM_BACK 是波 2 wire 面（见 §五），wmd 分发臂未接（主树 guiproto 无此 op、table.rs handle_wm 六 op 之外 ST_BAD）；I2 返回键路由（Nav 栈 pop / 根页优雅退出 / 500ms 无响应兜底 DESTROY）整块归波 3（六波实施方案 :26）。

### 四、状态栏素材与真值

**电池图标现状**：静态满电 OH 几何复刻位图 BATTERY_PX 64×45（status_icons.rs:435-437；整个文件由 tools/genohstatus.py 生成勿手改，status_icons.rs:1-2）；a11y label「battery simulated 100」（desktop.rs:483）——纯模拟值，无任何真值接线。

**simbattery 现状**：rootfs 相由 svcmgr 预拉的 sim-S1 电池快照注入服务（simbattery/src/main.rs:1-19；rootfs-manifest.toml:93）——收 UART1 转发帧 → StreamDecoder 解码 → seq 防重放状态机 → 9B ACK 回程 → 仅 ST_OK 打 `SIMBAT ok seq=N` 标记（main.rs:52-78、128-154；echo 形直收 + 1h 长帽重臂 :85-105）。帧内 BatterySnapshot 14 字段含 capacity_pct / status / voltage_mv / ac_online 等（berry-pwproto/src/lib.rs:106-124；DEV_BATTERY=1 :61）**已解码但无任何发布面与消费面**——真值停在 simbattery 进程内，launcher 与 simbattery 之间现无通道。波 3「battery 接 simbattery 真值」（六波实施方案 :26）需要新建值通道，这是波 3 设计稿要给的一条边界。

**时钟 advance 双口径**：主时钟真值链 = 宿主 berry 启动镜像时把当下 epoch 秒（十进制 ASCII）注入 fw_cfg `opt/berry/rtc` → 内核 rtc.rs boot 期单次消费（epoch_s×1e9 + (now_mono − 锚) 双 AtomicU64，此后只读；kernel/src/rtc.rs:1-14 头注、kernel/src/main.rs:268-272 挂链）→ CLOCK_REALTIME 随单调钟持续前进。状态栏消费口径 = launcher main 单取 REALTIME 换算 "HH:MM"（UTC 口径，hhmm_utc 恒 5B 等长，desktop.rs:253-267；main.rs:264-274 首摆 + `launcher: clock … utc (realtime)` 证据行）→ frameloop 稳态每 10s（IDLE 帽醒）读 REALTIME，分钟字变才 set_text 等长换文（纯 PAINT）+ a11y in-place 覆写 + wake（frameloop.rs:282-284、302-321）。模拟/占位口径 = 注入缺席（-kernel 冒烟拓扑无 fw_cfg 具名件）时 REALTIME 恒 -ENOTSUP → 建树回退 12:00 静态占位 STATUS_CLOCK、UTC 角标空文本（desktop.rs:127-129、399-403），frameloop 续摆面静默、零 advance（frameloop.rs:283 注记）。时区换算挂账波二（desktop.rs:138）。
