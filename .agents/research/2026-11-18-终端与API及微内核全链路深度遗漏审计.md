# 终端与 API 及微内核全链路深度遗漏审计

Type: survey
Status: current
Updated: 2026-11-18

一句话说明：针对「终端命令行、系统调用 API 与微内核底层机制」三大核心基座，开展代码级与架构规格交叉对拍审计，定位并收口跨组件接缝中的 13 项关键设计遗漏（涵盖 PTY 前台 Job 绑定、GUI 终端光栅化管线、OSC 52 剪贴板安全、ABI 号位对撞消歧、批量端口等待、硬件 PAN 用户拷贝、Pager 调页死锁免疫、内核栈保护页与跨核优先级继承）。

## 问题

随着 BerryOS 架构版图封顶为 40 个子系统并确立 ABI v2 号段总表，系统顶层设计已高度完备。然而，在代码实装与工程分刀推进期，终端（Terminal/PTY/Shell）、API（Syscall ABI/Capability/Errno）与内核（Microkernel/MM/IPC/HAL）这三大基座之间是否存在未被察觉的隐性接缝遗漏？例如：
1. 终端在微内核纯能力模型下如何知道该向哪个进程树发送 `Ctrl-C` / `Ctrl-Z`？GUI 桌面下终端高频刷新是否会冲垮场景图合成器？
2. 主线已落地的 DMA 缓存维护系统调用与 Master ABI v2 总表号位是否存在局部错位？高吞吐 I/O 驱动是否存在单事件轮询瓶颈？
3. 外置按需调页（Demand Paging）是否会在极端内存紧张时发生调页服务端自死锁？内核栈溢出如何从硬件上阻断静默踩踏？

本审计交叉检索并核验了以下核心事实源：

## 结论

审计在三大领域共定位出 13 项关键接缝遗漏，具体归类如下：

| 领域 | 编号 | 遗漏定性 | 潜在破坏性 / 架构风险 | 治理对策与收口方案 |
| :--- | :--- | :--- | :--- | :--- |
| **终端** | `T-GAP-1` | PTY 前台缺少显式 `Job` 能力绑定接口 | 按 `Ctrl-C` 无法准确杀死复合管道子进程组，或误杀后台作业 | 确立 `PTY_SET_FOREGROUND_JOB(job_cap)` 协议，前台退出自动回滚至根 Shell |
| **终端** | `T-GAP-2` | GUI 桌面下终端高频滚屏缺乏图元批处理契约 | 高速输出时产生海量 `SceneIR` 细碎节点，击穿合成器队列 | 确立字形图集（Glyph Atlas）+ 行级脏掩码，或直通 `Swapchain` 双缓冲 blit |
| **终端** | `T-GAP-3` | 终端缺少 ANSI OSC 52 剪贴板安全拦截 | 恶意 CLI 脚本可通过转义静默污染系统剪贴板，窃取私密数据 | 桥接系统剪贴板服务，仅在前台聚焦且有用户交互授权时放行 |
| **终端** | `T-GAP-4` | 全屏程序异常崩溃后 PTY 缺少自动 Cooked 兜底 | `bed` / `less` 崩溃退出后残留 Raw 模式，导致终端字符不回显 | `ptyd` 监听从端句柄生命周期，在会话进程退出时自动复位 Sanity Termios |
| **终端** | `T-GAP-5` | 纯 `spawn` 架构下子 Shell `(...)` 状态序列化缺失 | 无法原生执行复合脚本块与局部目录环境隔离 | 规范基于 `ProcessArgs v2` 的紧凑环境块序列化与子 Shell 复用机制 |
| **API** | `A-GAP-1` | `0x1C` 号位在 `abi.toml` 与 Master 规格间对撞 | 运行代码已占用 `0x1C vmo_cache_op`，主规格误将 `0x1C` 标为 `vmo_create_child` | 立即校正合龙总纲：`0x1C` 固化为 `vmo_cache_op`，`0x1D` 分配给 `vmo_create_child` |
| **API** | `A-GAP-2` | 异步端口缺少批量等待原语 `berry_port_wait_batch` | 高吞吐网络与块设备驱动每次单取 1 包，上下文切换成为性能瓶颈 | 分配号位 `0x5C berry_port_wait_batch`，单次最高弹出 32/64 个事件包 |
| **API** | `A-GAP-3` | 用户态指针入参缺少硬件 PAN 与规范化校验 | 恶意用户传入内核高半区地址可能引发特权穿透或内核 Panic | 建立 `copy_from_user` 严格三防线：高位非规范地址拦截 + 8B 对齐 + 缺页防 Panic |
| **API** | `A-GAP-4` | 负数系统调用 Errno 缺少跨语言单源 IDL 导出 | 内核写死 `-22`，libc 与用户态手工定义易产生常数漂移 | 在 `tools/abi.toml` 补齐 `[[errno]]` 节，自动生成 C/Rust 负数错误常量 |
| **内核** | `K-GAP-1` | 外置 Pager 调页服务端缺乏物理内存钉死契约 | Pager 处理缺页时自身若缺页，将引发致命的微内核环路死锁 | 铁律：Pager 服务端线程栈与代码必须 `PINNED`，供给快照路径零分配 |
| **内核** | `K-GAP-2` | 内核线程 16KiB 栈底缺少硬件保护页（Guard Page） | 深度调用栈或大局部变量溢出时，静默踩踏破坏相邻内核 Slab 堆 | 为每个内核线程栈底强制映射 4KiB 未映射保护页，溢出即触发同步异常并抓栈 |
| **内核** | `K-GAP-3` | 跨核优先级继承（PI）缺少核间无锁推挤机制 | 跨核调用若持有双核队列锁将引发 ABBA 死锁，不更新则实时失效 | 确立 `SGI_PRIO_BOOST` 机制：原子 CAS 更新 `prio_boost` + 发送 SGI 本地重排 |
| **内核** | `K-GAP-4` | 16KiB Ramoops 持久区缺乏二进制魔数与自校验头 | 热重启后若内存残留随机噪音，恢复程序将解析崩溃引发二次 Panic | 规范 `struct BerryRamoopsHeader`（魔数 `0x42525950`、CRC32C、时标、单调序号） |

## 证据与出处

### 一、终端子系统深度遗漏细查（`T-GAP-1` 至 `T-GAP-5`）

1. **`T-GAP-1`：PTY 前台作业能力绑定漏口**：
   - 出处：[plans/pty/design.md](../plans/pty/design.md) 第 52 行提到「直接向当前绑定在该 PTY 上的 fg_notify 端口投递结构化控制包」。
   - 盲点：在 Unix 中由 `tcsetpgrp(fd, pgrp)` 完成前台进程组指派；但 BerryOS 彻底废除了全局进程组与 Session ID，任务管理全基于能力沙箱 `Job`。若无明确的 `PTY_SET_FOREGROUND_JOB(job_handle)` IPC 协议，`ptyd` 无法获知当前由哪个复合管道 `Job` 独占前台，导致 `Ctrl-C` 只能杀死最外层 Shell，或无法清理深层派生的子进程。
2. **`T-GAP-2`：GUI 桌面终端的渲染性能雪崩风险**：
   - 出处：[plans/compositor/design.md](../plans/compositor/design.md) 规定原生应用默认采用 `SurfaceMode::SceneStream` 提交结构化矢量指令。
   - 盲点：在 120Hz 视网膜屏幕下，终端以 100 列 × 40 行呈现密集文本时，单屏包含 4,000 个文字单元。如果高频编译或 `dmesg` 滚屏时每一帧都全量遍历生成 4,000 个带颜色、背景矩形与字符排版的 `SceneIR` 节点，序列化和 IPC 开销将吞噬 60% 以上 CPU。必须制定专门的终端光栅化管线契约——采用固定字形图集（Glyph Atlas）+ 行级脏标记，或直接复用 `SurfaceMode::Swapchain` 双缓冲共享 VMO 进行直写。
3. **`T-GAP-3`：ANSI OSC 52 剪贴板安全穿透防护缺位**：
   - 出处：现代终端普遍支持 `\x1b]52;c;<base64>\x07` 允许命令行工具无感设置系统剪贴板。
   - 盲点：BerryOS 建立了全系统「零偷窥剪贴板（`PasteButton`）」安全防线。若 `ptyd` 盲目放行 OSC 52，后台恶意脚本或不信任的 SSH 远程会话便可在用户不知情的情况下静默改写剪贴板（替换为恶意命令或支付地址）。必须在 `ptyd` 中对 OSC 52 注入权限校验，仅当终端窗口处于前台激活焦点且近期存在物理按键/鼠标事件时才允许写入。

### 二、系统调用 API 与契约接缝细查（`A-GAP-1` 至 `A-GAP-4`）

1. **`A-GAP-1`：`0x1C` 系统调用号位对撞事实**：
   - 出处：[tools/abi.toml](../../tools/abi.toml) 第 485 行明文登记并已由提交 `fceb03ff3` 实装：
     ```toml
     [[group.syscall]]
     num = 0x1C
     name = "vmo_cache_op"
     ```
     而在 [全系统 40 模块终态合龙总纲](../plans/2026-11-18-全系统31模块终态合龙总纲与ABI号段总表.md) 第二章表格中，`0x1C` 却被写成了 `berry_vmo_create_child`，而 `0x1D` 标为了 `berry_vmo_cache_op`。
   - 纠偏：代码现实已在册消费 `0x1C` 作为 `vmo_cache_op`，合龙总纲必须无条件顺应现实，将 `0x1C` 固化为 `vmo_cache_op`，将尚未实装的 `vmo_create_child` 顺延调整至 `0x1D`。
2. **`A-GAP-2`：超高速 I/O 下单个事件弹出瓶颈**：
   - 出处：[plans/ipc/design.md](../plans/ipc/design.md) 与合龙总纲仅分配了 `0x5A berry_port_wait`（单次入参单个 `out_pkt` 指针）。
   - 盲点：在 10GbE/100GbE 虚拟网卡 `vnet` 或高并发异步存储完成队列中，每次产生突发 32–64 个完成事件包。逐个调用 `berry_port_wait` 将导致每秒发生数万次用户-内核上下文切换。必须增补 `0x5C berry_port_wait_batch` 批量弹出原语。
3. **`A-GAP-3`：硬件 PAN 与非规范地址校验防御断层**：
   - 出处：[kernel/src/syscall.rs](../../kernel/src/syscall.rs) 中多处直接对用户传入的指针调用内存拷贝。
   - 盲点：ARM64 支持特权不可访问（Privileged Access Never, PAN）。若微内核在关闭 PAN 时直接解引用指针，恶意应用传入 `0xFFFF_8000_0000_0000`（内核直映区或页表物理帧基址）可能引发内核越权读取或局部写入。必须强制执行静态范围检视（`ptr < USER_VIRT_MAX`）与硬件 PAN 快速翻转。

### 三、微内核底层架构硬墙细查（`K-GAP-1` 至 `K-GAP-4`）

1. **`K-GAP-1`：外置 Pager 服务端缺页死锁隐患**：
   - 出处：[kernel/src/dpg.rs](../../kernel/src/dpg.rs) 与 [plans/mm/design.md](../plans/mm/design.md) 确立了用户态按需调页。
   - 盲点：当用户进程 P 触发缺页陷入内核后，内核挂起 P 并唤醒调页守护进程（`fsmgr` 或 `pkgmgr`）。如果该调页服务进程自身的执行代码段、私有堆栈或临时变量缓冲也是 demand 懒加载页，调页服务运行时自身再次触发缺页；或者在调页服务处理期间触发了内存回收流程，内核将无法分配物理页给调页服务，形成全系统闭锁死等。必须在规格中锁死「Pager 启动即全量物理页锁定（`VMO_CONTIGUOUS` / `PINNED`）与供给路径零堆分配」。
2. **`K-GAP-2`：内核线程 16KiB 栈溢出静默踩踏**：
   - 出处：[sched/src/task.rs](../../sched/src/task.rs) 第 26–28 行使用堆分配 `Box<[u8; 16384]>` 作为内核执行栈。
   - 盲点：堆内存分配器分配的内存块在物理上紧邻后续对象。一旦内核由于极端深调用、中断嵌套或局部大结构体导致栈深度超过 16KiB，栈指针（SP）将直接向下越界写入相邻的内核堆对象或线程控制块，引发难以复现的内存静默坏块。必须在虚拟地址空间中将每个内核栈分配在隔离 VMAR 中，栈底留出 4KiB 未映射保护页（Guard Page）。
3. **`K-GAP-3`：跨核优先级继承无锁化推挤断裂**：
   - 出处：[kernel/src/pi.rs](../../kernel/src/pi.rs) 仅遍历本核就绪队列。
   - 盲点：多核场景下，CPU 0 上的高优线程通过 Channel 调用 CPU 1 上正在执行的服务端线程。CPU 0 不能直接获取 CPU 1 的运行队列自旋锁（否则引发双核锁序死锁）。必须建立基于核间中断的 `SGI_PRIO_BOOST` 机制，CPU 0 原子更新服务端线程的 `prio_boost` 字段后发射 SGI，由 CPU 1 在本地安全窗口重平衡红黑树。
4. **`K-GAP-4`：Ramoops 持久区脏数据自愈防御缺失**：
   - 出处：[plans/hal/design.md](../plans/hal/design.md) 预留 16KiB 物理内存作为崩溃日志区。
   - 盲点：冷启动上电时，未初始化的 RAM 中残留随机电荷噪音；硬件异常断电时内存可能发生局部半写。如果无防伪魔数与完整性校验，开机解析 Ramoops 将把垃圾噪音当作 Panic 日志而触发二次崩溃。必须定义强类型 `BerryRamoopsHeader` 并集成 CRC32C 校验。

## 落地指引

针对上述 13 项关键接缝遗漏，本批次采取如下闭环动作：
1. **规格收口**：在 [全系统 40 模块终态合龙总纲](../plans/2026-11-18-全系统31模块终态合龙总纲与ABI号段总表.md) 中修正 `0x1C/0x1D` 对撞，增补 `0x5C berry_port_wait_batch`，并明确硬件 PAN 规范；
2. **终端升级**：在 [pty 总体设计](../plans/pty/design.md) 增补 `PTY_SET_FOREGROUND_JOB`、GUI 图元批处理与 OSC 52 防御契约；
3. **内核升格**：在 [meihe 总体设计](../plans/meihe/design.md) 与 [mm 总体设计](../plans/mm/design.md) 补充 Pager 物理锁定与内核栈 Guard Page 铁律；
4. **决策入册**：立定 [终端与 API 及微内核全链路接缝收口架构裁决](../notes/proposed/2026-11-18-终端与API及微内核全链路接缝收口架构裁决.md)。
