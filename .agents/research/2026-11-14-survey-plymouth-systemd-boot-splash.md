# Plymouth 加 systemd 启动 splash 与事件面调研（BerryOS 引导视觉设计弹药）

Type: survey
Status: current
Updated: 2026-11-14

一句话说明：为 BerryOS「统一模拟器入口 + 引导视觉（verbose 滚日志 / 图形 logo 遮罩 + 真实事件进度条）」设计，对 Linux 发行版标配启动 splash（Plymouth master b79b178，2026-10-30）与 systemd 事件面做的一手源码级调研：plymouthd 架构与主题插件、事件折算进度的真实算法（时间渐近插值 + 跨启动校准，而非 unit 计数）、一次典型启动的事件点数量实证、ESC 切换 details 与密码交互、BGRT 固件无缝交接、各主流主题「真进度 vs 假进度」判定，附可直接抄的机制清单。

## 问题

BerryOS 要设计两种引导视觉模式：verbose 模式（详细滚动启动日志，滚完进桌面）与图形模式（logo 遮罩 + 进度条，进度映射系统真实启动事件，粒度越细越好）。本调研回答六个问题：① plymouthd 架构（renderer、主题插件、事件面）；② 事件怎么折算成 0..1 进度——是「已启动 unit 数比总数」还是插值，systemd 侧谁发事件；③ 粒度实证——一次典型启动有多少事件点，fsck 进度怎么进画面；④ detail 模式——ESC 切文本/图形、change-mode、密码交互的机制；⑤ 固件交接——BGRT 如何做到固件 splash 到 OS splash 无缝；⑥ 常用主题（Ubuntu 点阵、Fedora spinner 等）的进度形态，哪些是假进度哪些是真事件。只取一手材料（freedesktop.org 源码与文档、kernel.org、systemd 与 PackageKit 源码、发行版打包仓库），逐条带出处。

## 结论

### ① plymouthd 架构：双进程 + 抽象套接字协议 + 可插拔 renderer 与主题

两个二进制：plymouthd（daemon，画 splash、抓日志）与 plymouth（客户端，发命令）。通信是 Linux 抽象域套接字 /org/freedesktop/plymouthd（旧路径 /ply-boot-protocol），单字母命令行协议：「U」update status、「C」change-mode、「u」system-update 百分比、「S」sysinit、「R」newroot、「Q」quit、「A/a」进度暂停/恢复、「*」问密码、「K」监听按键等（src/ply-boot-protocol.h）。客户端命令面（src/client/plymouth.c）：update --status=、update-root-fs --new-root-dir=/ --read-write、change-mode --boot-up|--shutdown|--reboot|--updates|--system-upgrade|--firmware-upgrade|--system-reset、system-update --progress=N、ask-for-password/ask-question（--dont-pause-progress）、display-message、watch-keystroke、pause-progress/unpause-progress、deactivate/reactivate、quit --retain-splash。daemon 有 7 种模式（ply-boot-splash-plugin.h 的 ply_boot_splash_mode_t：boot-up/shutdown/reboot/updates/system-upgrade/firmware-upgrade/system-reset），由 plymouthd --mode= 指定。

renderer 是 dlopen 插件，类型 AUTO 时按序尝试 renderers/x11.so（开发用）→ renderers/drm.so（含 simpledrm）→ renderers/frame-buffer.so（ply-renderer.c 的 known_plugins 表）。设备发现靠 udev：ply-device-manager.c 用 udev_monitor 过滤 drm + graphics(fb) + input 三个子系统，每张卡建一个 renderer 多屏同画，同时接管键盘（libinput/xkb）。图形设备 8 秒不出现（plymouthd.defaults 的 DeviceTimeout=8）就落到文本主题。上游默认配置 src/plymouthd.defaults：Theme=spinner、ShowDelay=0、DeviceTimeout=8。文本路径有独立插件：text（VT 步进条）、tribar（三色条）、details（纯日志）。

主题 = 引擎插件 .so + INI 风格 .plymouth 配置（按模式分节 [boot-up]/[shutdown]/[updates]...）。当前树内引擎：two-step（spinner/bgrt/spinfinity 三主题共用，支持背景/水印/对话框/密码子弹/进度条/帧动画）、fade-throbber（fade-in）、space-flares（solar）、script（脚本引擎，Ubuntu 旧主题用）、text、tribar、details、console-viewer（新，专门显示启动日志的图形主题）。主题插件接口约 20 个回调（ply_boot_splash_plugin_interface_t）：create/destroy、show/hide_splash、update_status、on_boot_progress（30Hz 推 (time, percent)）、on_root_mounted、become_idle、display_password/question、display_message、system_update（直接收整数百分比）、on_boot_output（控制台/kmsg 文本流）、validate_input。

### ② 事件到进度：ply_progress 是「时间渐近插值 + 跨启动事件校准」，不是 unit 计数

核心在 src/libply/ply-progress.c，全文 328 行，模型极简：进度不是「已启动 unit / 总 unit」——systemd 从不向 plymouth 报告 unit 事件。四个字段干完全部工作：start_time、scalar（速度倒数）、last_percentage、dead_time。默认 scalar = 1/60（DEFAULT_BOOT_DURATION=60 秒，假定一分钟启动）。ply_progress_get_percentage 的插值公式：percentage = last + ((t - last_t) * scalar / (1 - (last_t - dead_time) * scalar)) * (1 - last)——双曲线式逼近 1，时间驱动永远到不了 100%（护栏 (t-dead)*scalar < 0.999，超了直接判 1.0），即「越接近满越慢、绝不抢跑」。还有一个防跑偏分支：若当前值超前 next_message_percentage 超过 1/scalar 秒，就降到 1/600 的慢速并把超出的时间记进 dead_time。daemon 以 30Hz（UPDATES_PER_SECOND）tick，每次调 ply_progress_get_percentage 后把 (time, percent) 推给主题的 on_boot_progress（ply-boot-splash.c 的 ply_boot_splash_update_progress）。

事件锚点机制：客户端发「U」update status 字符串后（ply-boot-server.c → plymouthd_handle_update → ply_progress_status_update），daemon 拿该字符串去上一启动的缓存表里查——查到就做标量混合 scalar = (scalar + 该事件历史时刻/当前耗时) / 2，并把 next_message_percentage 设为缓存中下一条事件的时刻；重复字符串禁用。缓存在 plymouth quit 时落盘（plymouthd_handle_quit → plymouthd_progress_save_cache）：每条事件写成「归一化时刻:字符串」（%.3lf:%s，时刻 = 事件时间/总启动时间），boot-up 模式写 /var/lib/plymouth/boot-duration，shutdown/reboot 写 /var/lib/plymouth/shutdown-duration，四个 update 类模式无缓存（plymouthd-progress.c 的 get_cache_file）。下次启动 ply_progress_load_cache 读回（initrd 阶段先读 initrd 内副本，切根时 plymouthd_handle_newroot 重新 chroot 并重读真根的缓存）。即：进度 = 少量离散事件做跨启动「锚点校准」+ 平时纯时间插值平滑连点。

谁发事件：现代发行版默认几乎没人发「U」。plymouth 自带的 systemd 单元全集（systemd-units/ 目录 10 个 .service）只有：plymouth-start（plymouthd --mode=boot + show-splash，After=systemd-udevd）、plymouth-read-write（plymouth update-root-fs --read-write，After=local-fs.target）、plymouth-switch-root（plymouth update-root-fs --new-root-dir=/sysroot）、plymouth-quit / plymouth-quit-wait（plymouth quit，在 display-manager 之后）、plymouth-reboot/halt/poweroff/kexec（plymouthd --mode=shutdown）、systemd-ask-password-plymouth.path/service（密码代理）。systemd 本体不调 plymouth update --status。而且注意：newroot（R）与 sysinit（S）都不进 ply_progress——newroot 只重载缓存、sysinit 只触发日志与 SIGRTMIN+20。所以原生 Fedora/Ubuntu 启动中进度锚点事件数为 0，进度条全程是时间插值（下文适用边界注明实测样本未取）。真正直接给百分比的通道是 updates 系模式：plymouth system-update --progress=N（0..100 整数）→ ply_boot_splash_system_update → 主题的 system_update 回调，绕过 ply_progress、无跨启动学习（PackageKit 用它，见⑥）。另外问密码时客户端默认先发 A 暂停进度、答完再 a 恢复（plymouth.c on_password_request 的 pause = !dont_pause），用户输入期间进度不走字。

### ③ 粒度实证：一次典型启动约 4-6 个控制事件 + 两条连续文本流；fsck 只进文本不进进度条

按 plymouth 自带单元排的时序，一次典型启动打到 daemon 的协议事件：plymouthd 起来（1）→ show-splash（2）→ [可选] ask-for-password 若干（加密盘时，暂停/恢复各 1）→ update-root-fs --new-root-dir（3）→ update-root-fs --read-write（4）→ quit（5，触发 become_idle：进度直接置 1.0 并保存缓存）。「U」status 事件默认 0 条。也就是说 Plymouth 的进度面在设计上就是「粗粒度里程碑 + 时间插值」，粒度上限受限于谁愿意发 status——引擎支持任意多条，生态上没人发。

真正细粒度的是两条与进度无关的连续流，喂给 verbose 显示：其一内核流——ply_kmsg_reader 打开 /dev/kmsg（O_RDWR|O_NONBLOCK）后 lseek 到末尾只取增量，解析出 priority/facility/sequence/timestamp（微秒）四元组（ply-kmsg-reader.c/.h），daemon 把 message 逐条追加显示；其二控制台流——ply_terminal_session 用 TIOCCONS 劫持 /dev/console 输出（attach-to-session 时重定向到日志），systemd 的 unit 状态行（show-status 打开的「Started foo.service」）与用户态进程打印都从这走。两路汇进 plymouthd_handle_kmsg / handle_session_output → 主题的 on_boot_output。这条流每条 kernel 消息/每行 unit 状态都是一个显示事件，粒度远细于进度面。

fsck 进度：现代 systemd（main 分支 src/fsck/fsck.c 的 process_progress）把 fsck -C 管道里的 pass/cur/max 解析成百分比，以 \r「%s: fsck %3.1f%% complete...」写到 /dev/console，节流 50ms 一次、多设备用 flock 只留一个计数器，且仅在存在 /run/systemd/show-status 时显示——因此 fsck 百分比今天只能以控制台文本行的形式出现在 splash 的日志区，不进任何进度条。历史机制完全不同：systemd v218-v220 的 systemd-fsckd 直连 plymouth 套接字，把多设备全局百分比（取各设备 MIN）以「U」命令发字符串 fsckd:<设备数>:<百分比>:<本地化消息>，变化阈值 0.1%，并用 watch-keystroke 注册 Ctrl+C 取消检查；fsckd 于 2015-04-28 被移除（commit 96d9117，"remove fsckd again, but keep the door open for external replacement"），此后再无内建 fsck→进度条通道，Ubuntu 旧点阵主题里那行 fsck 文案就是解析这个协议的遗物。

### ④ detail 模式：ESC 换主题插件 + 信号让 systemd 开始打 unit 行

ESC 在 daemon 内部处理（不经协议）：每个键盘注册 escape handler（plymouthd.c on_escape_pressed），按 ESC 时校验当前不是密码输入态（validate_prompt_input）且存在 VT 控制台，然后 plymouthd_toggle_details：卸载当前主题插件、加载 details 文本主题并整屏重放已缓冲的全部启动日志（boot_buffer），再实时流式续写；再按 ESC 换回配置主题（plymouthd-display.c）。切换的同时 plymouthd 给 PID 1 发 SIGRTMIN+20：systemd manager.c 的分发表把它映射为 manager_override_show_status(SHOW_STATUS_YES)——systemd 开始向控制台逐行打印 unit 启动状态；脱离 details 时发 SIGRTMIN+21 关掉。这是 Plymouth 与 systemd 唯一的专有握手（ Plymouth 源码内 PLY_ENABLE_SYSTEMD_INTEGRATION），verbose 的「内容」由 systemd show-status 供给。man plymouth(8) 与 plymouthd-policy.c 给出默认选择：内核命令行无 splash/rhgb 参数、或带 single/1/s/S/-S、或控制台是串口时，直接进 details/文本而非图形。另有可配置的「额外 ESC 键」（XkbExtraEscButton，默认注释掉，示例 XF86PowerOff）。

新机制把 verbose 搬进了图形模式：console-viewer 主题与 two-step 的控制台日志区共用 ply_console_viewer——用户态终端模拟器（ply-terminal-emulator，行数=屏高/字高、列数=屏宽/字宽-1），吃上面的 kmsg+console 双流逐行滚动渲染，内核参数 plymouth.prefer-fbcon 关闭、文本渲染不可用自动降级。密码交互：systemd 的 /run/systemd/ask-password 目录协议（freedesktop PasswordAgents）由 systemd-ask-password-plymouth.path 监听并转发给 plymouth；图形主题画对话框 + 每字符一颗子弹（bullet.png）+ capslock/键盘布局图标；进度条默认暂停。

### ⑤ 固件交接：BGRT 让 OS splash 原样复用固件 logo

BGRT（Boot Graphics Resource Table）是 ACPI 5.0 表，固件把开机 logo 位图交给 OS。内核在 /sys/firmware/acpi/bgrt/ 暴露 image（32 位 BMP）、status（bit0 有效位；bit1-2 旋转角，ACPI 6.2 起）、type、version、xoffset/yoffset（像素），内核 ABI 文档明说目的就是给 boot splash 应用「避免生硬切换」。two-step 插件的 ply_bgrt_info_load 读 status/xoffset/yoffset，背景直接 ply_image_new("/sys/firmware/acpi/bgrt/image") 加载 BMP，按 status 旋转位旋转、按 offset 定位到固件画它的同一位置——固件 logo 在 plymouth 接管后原样在屏，主题只在下方加 spinner/进度条，实现「固件 splash → OS splash」像素级无缝；无 BGRT 时回落主题自带 bgrt-fallback.png（Ubuntu 打包即如此），源码还处理了联想 2-in-1 预旋转图等怪癖。Fedora 30 的 FlickerFreeBoot 变更把它产品化：i915 fastboot（不重设显示模式）+ 内嵌固件 splash 的新主题（取代旧 charge 主题），整链无黑屏无跳变。链路两端：入口端 plymouthd 尽早启动用 KMS 原生模式不重设；出口端给桌面管理器 plymouth deactivate（释放 DRM master）/reactivate、plymouth quit --retain-splash（退出时不擦屏，把最后一帧留给 DM 接手），daemon 重启期间由 plymouthd-fd-escrow 进程持有 DRM fd 防止内核熄屏。

### ⑥ 主题进度形态盘点：启动画面几乎全是「假进度」，真进度只在 update 场景

Fedora（上游默认 Theme=spinner；Fedora 打包 plymouth-theme-spinner 提供 plymouth(system-theme)，bgrt 作为 spinner 的固件背景变体随包附带）：boot-up 模式 = 36 帧循环 spinner（throbber-00xx，30fps）+ 消息行，配置里根本没有 UseProgressBar——不确定动画（indeterminate）；updates/system-upgrade/firmware-upgrade/system-reset 四模式 = 真进度条 + ProgressBarShowPercentComplete + Title/SubTitle（spinner.plymouth.desktop），百分比来自 PackageKit 逐包推送（client/pk-offline-update.c：percentage 回调里发 plymouth system-update --progress=%i、>10% 时 display-message、结束 change-mode --reboot、开场 change-mode --updates）。bgrt 主题同 spinner，仅 boot-up 加 UseFirmwareBackground=true。

其余主题：spinfinity（two-step）boot-up 开 UseProgressBar=true——显示的正是②的时间插值进度（假进度，视觉上像真的），1920 宽 16 高贴底；fade-in（fade-throbber）logo 渐显 + 星点，无百分比；solar（space-flares）彗星太阳耀斑，无进度；glow 用 33 帧 progress-00..32.png 图序列由真实 fraction 驱动；charge（Fedora 旧默认，F30 退役）电池充能式；text 主题在 VT 上画步进条（wwoods 平滑后的 fraction）；tribar 三色文本条。Ubuntu 双代：旧 ubuntu-logo（script 引擎，xenial patch 实证）5 颗点阵循环，animate_progress_indicator(progress, time) 里 progress 仅当时间基准用（`global.progress_time = progress`），数值完全不影响画面——纯假进度，附带解析 fsckd: 协议的专门 fsck 文案行与密码子弹；现代 Ubuntu（ubuntu/devel 打包）默认已换成 spinner 变体（debian/rules 拷 debian/local/spinner/* + ubuntu-logo-text-dark.png 当水印 + bgrt-fallback.png），行为同 Fedora spinner。总结论：Linux 生态里「真实事件驱动的启动进度条」从来不是主流——主流要么不确定动画（spinner/点阵），要么时间插值伪装（spinfinity/text），只有 update/upgrade 类模式因为存在确切的 0..100 事务进度才是真进度。

## 适用边界

其一，boot-duration 缓存文件的实测样本未取证（本机无 Linux 启动环境，网搜通道不可用）：「现代默认启动 status 事件为 0、缓存通常为空」是从机制与单元全集推出的强推断，未见实物文件内容反例也未见样本；BerryOS 若要参考应实测 cat /var/lib/plymouth/boot-duration。其二，「Fedora 当前各 spin 默认主题究竟是 spinner 还是 bgrt」只证实到打包层（theme-spinner 提供 system-theme、bgrt 随包附带），kickstart 层的逐 spin 设置未取到（pagure fedora-kickstarts raw 路径 404）。其三，Plymouth 取 master（2026-10-30，b79b178）：该树已完成 plymouthd 拆分重构（plymouthd-actions/-progress/-session 等新文件），与 0.9.x 发行版布局不同，函数名在旧版可能对不上；fedora dist-git 无 plymouthd.defaults 覆盖即用上游默认 Theme=spinner，但 distro 装机脚本可能改。其四，Hans de Goede 的 flicker-free 原始博文（dreamwidth）本网络不可达，固件无缝的产品叙述以 Fedora Changes 页与 plymouth/kernel 源码为准；GRUB 隐藏菜单等引导器侧配合未展开。其五，本文只调研不改代码，BerryOS 侧落地设计（事件面怎么定、模拟器 BGRT 怎么造）属后续 plans；姊妹篇见 [OpenHarmony 调研](2026-11-14-survey-openharmony-boot-animation-events.md) 与 [Apple 调研](2026-11-14-apple启动视觉双模式调研.md)。
