# Apple 启动视觉双模式调研（进度条 + verbose）

Type: survey
Status: current
Updated: 2026-11-14

一句话说明：为 BerryOS「统一模拟器入口 + 引导视觉（verbose 滚日志 / logo 遮罩 + 虚拟进度条）」设计取材，深挖 Apple 在 macOS 与 iOS 上图形进度与 verbose 双模式的共存、切换、驱动机制与故障语义，全部结论落到一手出处（XNU 源码、Apple Platform Security、Apple 支持页、Asahi 逆向文档）。

## 问题

三个问题。其一，macOS 的图形模式（Apple logo + 进度条）与 verbose 模式（Cmd+V / NVRAM boot-args -v 滚动日志）如何共存与切换，verbose 滚完如何进桌面，FileVault 解锁阶段进度表现如何。其二，进度条映射什么：走到哪里代表哪个阶段（固件 → 内核 → launchd → 登录窗 / 桌面），卡住的位置如何用于诊断。其三，iOS 的 SecureROM → iBoot → XNU → launchd → SpringBoard 链上进度条阶段如何映射，恢复 / 更新模式进度条行为如何，以及进度是否单调、大版本升级首启的表现。

## 方法与来源

优先一手材料：XNU 开源代码（apple-oss-distributions/XNU，main 分支，2026-11-14 拉取全仓 grep 核对行号）、Apple Platform Security Guide（support.apple.com/guide/security）、Apple 支持页（support.apple.com/en-us）、Asahi Linux 逆向文档（AsahiLinux/docs）。检索通道说明：会话内 web_search 后端认证故障不可用，改用 web_fetch 直取已知 URL + r.jina.ai 渲染 + 多引擎兜底；DuckDuckGo / Mojeek / Bing 均触发反爬，theiphonewiki.com 全程 504（CloudFront 故障），theapplewiki.com 无此文——iOS 民间逆向的进度条逐段百分比映射因此缺失，本文明确标注「未证实」。Apple 支持页正文经 r.jina.ai 抓取，引用以 Apple 原 URL 为准。

## 结论

**双模式由引导器（booter）单点裁决，内核只消费标志位。** XNU 的 boot_args 有专门的 UI 模式位：kBootArgsFlagBlack（1<<2）、kBootArgsFlagBlackBg（1<<6）、kBootArgsFlagLoginUI（1<<7）、kBootArgsFlagInstallUI（1<<8）、kBootArgsFlagRecoveryBoot（1<<10），以及两个 uint16 字段 bootProgressMeterStart / bootProgressMeterEnd（pexpert/pexpert/i386/boot.h:134-195）。安装场景下固件把进度条限制在整条的子区间内：内核把 [start,end] 从 16bit/65535 折算到 0..1024 内部刻度（osfmk/console/video_console.c vcattach，`bootProgressMeterStart * kProgressMeterMax / 65535`）。verbose 则由 booter 以 GRAPHICS_MODE=1 / FB_TEXT_MODE=2 的 Video.v_display 传给内核（同头文件 :107-108）——文本模式下内核直接在 framebuffer 上跑 VT100 字符控制台（video_console.c 的 gc_* 前端），logo 与进度条根本不画。

**进度驱动是三层混合：固件事件 → 内核时间蠕动 → 用户态真实事件。** 内核侧 macOS 专用 progress meter（CONFIG_VC_PROGRESS_METER_SUPPORT，仅 XNU_TARGET_OS_OSX）默认 kProgressMeterKernel=3 模式：一个 thread_call 每 tick 把计数器加上一段增量，`pos = count >> 13`（8192 计数一格），增量表 8 段递减 `{10000, 10000, 8192, 4096, 2048, 384, 384, 64}`——条在初期快、越接近满格越慢，pos 上限 kProgressMeterEnd=512（满刻度 kProgressMeterMax=1024），即时间驱动永远走不满，等真实事件接管。tick 基准 1000/8=125 ms，再乘 256/vc_progressmeter_diskspeed 缩放；磁盘速度在根文件系统挂载时实测写入（bsd/vfs/vfs_subr.c:1303-1313）：虚拟盘 128、HDD 256、SSD 7*256=1792——SSD 上条爬得快 7 倍，体感与真实 IO 速度挂钩。用户态接管走 sysctl：IOPMrootDomain.cpp:1244-1290 注册 kern.progressmeterenable / kern.progressmeter（值 0..1024 直接由用户态写入，即真实启动事件），另有 kern.consoleoptions 与 kern.progressoptions（CTLFLAG_ANYBODY）。vc_set_progressmeter 在内核蠕动模式下拒绝用户写值（`kProgressMeterKernel == enable` 时不画），保证谁在画不打架。内核另有独立「旋转指示器」（spinner，vc_progress_initialize，帧动画参数由图片描述符的 time/count 字段给出，1x/2x/3x 三套位图），默认 vc_progress_withmeter=3 两者并存，boot-arg `meter` 可覆盖（vcattach 里 PE_parse_boot_argn("meter", ...)）。

**flicker-free 交接三件套：同 framebuffer + 资产随设备树传递 + 背缓冲快照。** 其一，booter 只把 framebuffer 地址 / 宽高 / 深度塞进 boot_args（Boot_Video），内核映射同一块显存续画，全程不切显示模式。其二，启动美术资产经设备树 /chosen/memory-map 从 booter 传给内核：BootCLUT（调色板）、Pict-FailedBoot、FailedCLUT / FailedImage（找不到启动盘时的「禁止 / 文件夹」失败图标），内核 root 挂载失败时用 PE_display_icon(0, "noroot") 绘制（pexpert/i386/pe_init.c:126-165；video_console.c noroot_icon_test）。其三，当图形栈（IOKit / WindowServer 侧）要接管时，内核把进度条矩形像素存档：IORecordProgressBackbuffer 把背缓冲与配色主题写进设备树 /chosen 的 IOProgressBackbuffer / IOProgressColorTheme 属性（iokit/Kernel/IOStartIOKit.cpp:216-229；键名 iokit/IOKit/IOKitKeysPrivate.h:56-57），接管者从快照续画同一条 bar——消费方（loginwindow / WindowServer 引导屏）闭源，具体读取代码未证实。verbose 的收尾同理：文本控制台一直滚到图形栈 acquire 屏幕为止，社区实测 verbose「显示进度直到 UI 启动那一刻」，之后登录窗直接替换画面。

**Apple 官方的进度条语义刻意粗粒度，但「卡在哪一屏」是官方诊断语言。** 102535：Apple logo 出现 = 「找到了内置或外置启动盘」；随后出现进度条（可有可无 logo），且「这一屏可能与黑屏交替数次」。升级 / 更新期间 logo+进度条可能持续远超平时，条会缓慢移动并长时间停顿，Apple 建议晚间开始安装过夜完成。卡死处置：长按电源 10 秒 → 拔外设 → recoveryOS 修盘 → 重装。102675 给出启动卡死的完整画面分类学（问号文件夹 = 找不到启动盘、禁止符号 = 系统不兼容、地球叹号 = 网络恢复失败、logo+进度条、灰 / 黑 / 蓝屏、齿轮 Options、恢复助理等八类）。iOS 侧：118106 明确「Apple logo 数分钟且无进度条」本身是进恢复模式的指征（正常 iOS 启动只有 logo 不带条，条只在更新 / 恢复 / 抹掉后出现，102317）；102317 还证实 iOS 更新进度条「可能走完后再从头来一遍」（多趟，非全局单调）与「缓慢或看似静止都正常」。

**verbose 切换：Intel 一键、Apple Silicon 走 NVRAM、运行时另有调试口。** 官方 102603 只在 Intel 段落写 Command-V「以 verbose 模式启动」；Apple Silicon 段只有长按电源进启动选项屏。社区通行做法是 `sudo nvram boot-args="-v"`（Apple Silicon 同样适用，但 Asahi 逆向的 LocalPolicy 字段含 `sip3`「boot-args 过滤禁用」开关，说明 iBoot 默认对 boot-args 有过滤；个别用户报告 M1 上 -v 无效，discussions.apple.com/thread/252338595，未证实孰是）。清除用 `sudo nvram boot-args=` 或删键或重置 NVRAM。安装器场景下 verbose 会被安装 UI 主动切回图形（MacRumors 论坛实测）。运行中：图形进度条可经 sysctl kern.progressmeter / kern.progressmeterenable 由特权进程推进或关闭，kern.progressoptions 任何人可读写——这是把「假进度」与「真事件」在同一根条上混合的官方调试面。

**启动链与阶段划分（一手出处齐）。** Apple Silicon Mac：Boot ROM（芯片内 ROM，硬件信任根）→ LLB（加载系统配对固件 + LocalPolicy，向 Boot Progress Register 锁定启动模式）→ iBoot（加载静态信任缓存 / 设备树 / Boot Kernel Collection / AuxKC，校验 SSV 根哈希）→ XNU → launchd → 登录窗 / 桌面；任何签名失败落 recoveryOS（Apple Platform Security secac71d5623、sec10869885b；Asahi fw/boot.md 补充 Stage 0 SecureROM → Stage 1 LLB/iBoot1（NVRAM boot-volume、iSCPreboot 上 LocalPolicy、Preboot /boot 目录下 iBoot.img4）→ Stage 2 iBoot2，及 SEP 侧 boot mode 表 macOS/1TR/recoveryOS/kcOS/restoreOS）。Intel+T2：T2 Boot ROM → T2 iBoot 验内核与 UEFI → Intel CPU 经 eSPI 取固件 → UEFI 验 boot.efi → boot.efi 验 immutablekernel → XNU；失败落 Recovery / T2 DFU（sec5d0fab7c6）。iOS：Boot ROM →（A9 及更早多一级 LLB）→ iBoot → XNU；Boot ROM 加载失败落 DFU（A12+ 由 Boot ROM 置 BPR），LLB / iBoot 失败落 Recovery（A10/S2+ 由 iBoot 置 BPR）（secb3000f149）。FileVault：开启后「凭据在引导过程中被要求」，登录窗输入即解锁卷，恢复密钥在登录窗按 Shift-Option-Return 代密码（sec4c6dc1b6e、102675）——即解锁发生在 logo+进度条之后的登录窗阶段，官方文档未给出该阶段进度条的独立区间，未证实。

**慢启动（大版本升级首启）。** 102655：安装期间「Mac 可能重启并显示进度条数次，屏幕可能连续数分钟空白」；102535：升级后首启 logo+进度条可能远超平时、条缓慢且长时间停顿。这与 XNU 的 InstallUI 子区间机制（bootProgressMeterStart/End）互为印证：安装器把整个安装切成多趟，每趟只占条的一段。Apple 未公布具体秒数，标称时长未证实。

## 适用边界

iOS 民间逆向常用的「进度条百分比 ↔ iBoot / 内核 / SpringBoard 阶段」精确映射表未能取证（theiphonewiki 全程 504、无 Wayback 快照、theapplewiki 无此处迁移），标注未证实；Apple 官方对 iOS 正常启动的表述只到「logo 无条、条 = 更新 / 恢复」。loginwindow / WindowServer 引导屏读取 IOProgressBackbuffer 的具体代码闭源未证。Apple Silicon 上 nvram boot-args=-v 的有效性存在社区矛盾样本。Apple 不公开启动时长数字。本 survey 只取证不改码；检索通道异常（web_search 后端 401、DDG / Mojeek / Bing 反爬）导致搜索引擎覆盖窄，已在「方法与来源」说明。
