# 终端刀侦察：GUI 输入与渲染的事实底册

Type: survey
Status: current
Updated: 2026-11-15

## 问题

计划新建一个 GUI 终端应用（黑底命令行窗口：文本行缓冲显示 + 键盘输入 + 命令执行），输入先走宿主键盘（VNC/窗口键盘经 gui-inputd 注入）。动刀前需要五份事实：(1) berry-guiproto input 域的事件 wire 格式与三个 op 的语义，及 launcher/appdemo 的消费先例；(2) berry-ui 波2 后 Input/Edit/Canvas/Text 的能力面、字体现状，与「行缓冲文本显示用什么控件」的评估底册；(3) GUI 应用从零到出窗的最小骨架与文件面；(4) 输入焦点链——事件怎么决定发给哪个窗、应用收 key 事件需要什么、OP_INPUT_INJECT 能否用于自测；(5) 帧循环怎么同时等多个事件源，以及 GUI 应用 spawn 子进程收 stdout 的先例。本文即该底册，与 [2026-11-15-终端刀侦察-bsh核心.md](./2026-11-15-终端刀侦察-bsh核心.md)、[2026-11-15-终端刀侦察-应用注册面.md](./2026-11-15-终端刀侦察-应用注册面.md) 同族。

## 结论

### 1. input 域事件面：只有 PointerEvent，key/text 仅存在于入向 INJECT 协议缝

**op 表与设备类**。input 域三个 op：OP_INPUT_SUBSCRIBE=0x20（订阅 + 投递模式声明）、OP_INPUT_POLL=0x21（拉事件批，可阻塞）、OP_INPUT_INJECT=0x22（授权注入，波2 add-only，`user/berry-guiproto/src/lib.rs:76-78,112`）。设备类三值：DEV_POINTER=0、DEV_KEYBOARD=1（key 事件：code = ASCII 可打印字节或控制键）、DEV_TEXT=2（IME 提交面，payload = ASCII 串）（lib.rs:117-123）。投递模式两值：DELIVERY_BATCHED=0、DELIVERY_IMMEDIATE=1，且 v0 服务端允许把 IMMEDIATE 降级为 BATCHED（lib.rs:270-273）。

**事件 wire 格式 = PointerEvent 一种**。结构字段：phase/device_id/buttons/flags u8 各一、pointer_id u16、timestamp_ns u64、x/y u32、pressure u16（0..=1000 或 0x8000 哨兵）、contact_major/minor u16（v1 恒 0）、history 定容数组 + history_len（`user/berry-guiproto/src/lib.rs:511-531`）。wire 布局：定长头 32B + (n-1)×16B 历史采样，n ∈ 1..=INPUT_SAMPLES_MAX=4（lib.rs:495-506,292）。帧帽 INPUT_EVT_MAX_LEN=80 = 32+16×3（lib.rs:303，const assert 钉板 lib.rs:1981）；INPUT_POLL 应答帽 INPUT_REP_MAX=244 = 4+3×80，单批事件数帽 INPUT_EVENTS_MAX=3（lib.rs:294,305）。编解码函数：encode_pointer_event（lib.rs:545，恰长写入，值域野值返回 None）、parse_pointer_event（lib.rs:589，sample_count 定帧长 + 恰长执法）、批应答 encode_input_events_rep（lib.rs:1139，头 4B `[st=0][count][r16]` + 事件串接）、parse_input_events_rep（lib.rs:1202，三态分离：None=畸形、Some(Err(st))=合法 1B 错误、Some(Ok)=事件批，空批走 1B `[ST_EAGAIN]` 形）。**库里不存在 KeyEvent 结构，也不存在 key/text 事件的出向（inputd→应用方向）编解码函数**——key/text 只出现在 OP_INPUT_INJECT 的入向载荷：encode_input_inject_req / parse_input_inject_req，帧形 `[op][dev_kind][payload ≤24B][r16]`，键盘 = 1B key code、文本 = ASCII 串（lib.rs:1942-1975）。INPUT_EVT wire 上也没有窗口 id 字段——事件不携目标窗。

**三个 op 的服务端语义**（gui-inputd 侧）：SUBSCRIBE 恰 4B `[op][delivery][r16]`，服务端只记账 delivery 并打一行日志，**不是 POLL 的前置门**（不订阅直接 POLL 合法；`drivers/bins/gui-inputd/src/main.rs:906-921`）；POLL 恰 4B，max_events 域 1..=3，服务端阻塞服务：1ms 步进收割直到泵有货应答 ≤max_events 事件，或 30s 帽（POLL_BLOCK_CAP_NS，main.rs:79-81）到点回 1B ST_EAGAIN（serve_poll，main.rs:799-848）；INJECT **服务端未实现**——serve 的 op 分派只认 SUBSCRIBE/POLL 两 op，其余（含 INJECT）回 1B ST_BAD（main.rs:905-933，「input 域只此两 op」注释在 main.rs:930）。协议注释自述 INJECT 的授权面（谁可注入）执法在 inputd 服务端（lib.rs:109-111），即当前授权面也不存在。

**消费先例**。launcher 是唯一真实消费者：main 经 `input_h()`（env extras[3]/gift[7] 的 input 客户端端 dup，`user/berry-libc/src/io.rs:401-410`）把端柄传入 frameloop（`user/bins/berry-launcher/src/main.rs:284`）。拉批模式是「挂起-非阻塞收-重臂」三段：input_arm 挂一轮 POLL（encode_input_poll_req 带 INPUT_EVENTS_MAX，send 遇 -EBUSY 等 WRITABLE 重试，`user/bins/berry-launcher/src/frameloop.rs:669-692`）；循环头非阻塞 recv 排空应答（-EAGAIN = 事件尚未到、poll 仍在服务端阻塞），parse_input_events_rep 后逐事件 view.event(i) → PtrEvent::from_wire → ui.push_pointer，与合成注入共用同口（frameloop.rs:326-379，from_wire 调用 349-357）。launcher 从不发 SUBSCRIBE。**appdemo 不是 GUI 应用、没有任何输入订阅面**——它是 appd 管理的 console demo（argv0 自检 + /etc/mtab 读回 + 单行输出即退出，`user/bins/appdemo/src/main.rs:25-42`），任务书对它的预期与现状不符，GUI 输入消费先例实际只有 launcher 一家。

### 2. berry-ui 现状：焦点面已接线，多行文本与自绘面缺席

**ViewKind 全集 34 kind**（`user/berry-ui/src/desc.rs:170-212`）：Root/Rect/Text/Col/Row/Pad/Image/Icon/Grid/Button/Toggle/Slider/Progress/Scroll/List/Tabs/Stack/Spacer/Divider/Check/Radio/Step/Seg/Badge/Sbar/Select/Input/Edit/Canvas/Tip/Refresh/SwipeItem/DatePick/TimePick/Collapse/Chip/Fab/Card/Gauge/Qr/DragReorder。

**Input/Edit（波2 批 D）**。数据层：InputProps{placeholder, max_len, input_kind: Text/Number/Password}（desc.rs:531-538）；EditProps{placeholder, max_len, max_lines, readonly}（desc.rs:544-553）——实际文本内容不走 Props，走引擎侧表。运行时 API：set_focus（lib.rs:1631-1663，目标限定 Input/Edit 他 kind NodeBad，置焦同帧 damage 焦点环面）、focus()（lib.rs:1666）、input_text 读侧表（lib.rs:1671）、set_input_text 写侧表（lib.rs:1682-1719，max_len 域执法且**同时受 TEXT_INLINE=64B 硬帽**（lib.rs:1696），侧表容量 INPUT_TEXT_MAX=8 节点（lib.rs:179））。点击自动置焦已接线（lib.rs:1852-1854）。渲染：白底框（INPUT_BG）+ 边/焦点环（无焦灰 INPUT_BORDER、有焦蓝 INPUT_FOCUS_RING，paint.rs:108-113）+ placeholder 灰字（INPUT_PLACEHOLDER，paint.rs:115）+ caret 2×16 竖线（INPUT_CARET_W=2，paint.rs:116-117；Input caret 尾置近似 x = max(8, len×8)，paint.rs:1062-1065；Edit caret 按 len/24 行、len%24 列的**固定 24 字符宽折行近似**定位，paint.rs:1086-1089）。注意 caret 定位与文本渲染都用固定 8px 字宽假设（S8x16 档口径），不随 style.scale。

**Canvas**：数据层只有 paint_ops 计数（CanvasProps，desc.rs:559-562）；渲染 = 整面 CANVAS_BG 浅灰底一块 fill（paint.rs:1092-1094），注释明说「自绘协议挂后续刀——paint_ops 计数面」（paint.rs:1029）。**当前 Canvas 没有任何自绘内容通道**（无 set_paint_ops、无 op 流 API——lib.rs 全文无此类开口）。

**Text 多行能力：无**。TextProps.text 是内联 TextBuf（≤TEXT_INLINE=64B，lib.rs:80；TextBuf 构造超帽 TextTooLong，desc.rs:810-821）；渲染是单条 glyph run 逐字形按 advance 推进，一个 y 坐标，**没有 \n 分行逻辑**（paint.rs:622-656）。Edit 的内容渲染同样单行 emit（paint.rs:1083-1085），max_lines/折行只体现在 caret 的近似行号上。set_text 支持等长换文纯 PAINT 优化（lib.rs:1296，时钟续摆先例 frameloop.rs:311）。

**字体现状**。FontSize 四档：S8x16/S16x32/S24x48/S32x48，cell_w/cell_h 单源在 berry-gfx（`user/berry-gfx/src/font.rs:150-186`：8×16、16×32、24×48、32×48）——前三档加 S32x48 点阵全部**等宽**（genfbfont 自绘等宽 art，advance 缺省恒 cell_w，font.rs:134-141）；另有 HD 档 = 32×48 Noto Sans OFL 原生光栅化的**比例**字源（font.rs:157-158，advance 读烘焙表 ADVANCE_HD，font.rs:283-308）。测量缝 TextMetrics：MonospaceTextMetrics（宽 = len×cell_w）与 ProportionalTextMetrics（逐字形 advance 累计，三档点阵下与等宽恒等）（`user/berry-ui/src/metrics.rs:46-82`）。**没有独立「等宽字体文件」概念——点阵档天然等宽，等宽语义由 FontSize 档位保证**；行高 = cell_h（16/32/48），字宽 = cell_w（8/16/24/32），终端用 S8x16 档即 8×16 像素单元格。

**行缓冲显示选型评估**（基于上述现状）：(a) 多行 Text——不可行，Text 单行且 ≤64B；(b) Edit 多行——名不符实，内容单行渲染、折行只是 caret 近似，且 max_len 同受 64B；(c) Canvas 自绘——无自绘协议，需先给 berry-ui 开绘制通道（新刀）；(d) **逐行 Text 数组**——现成可行：每行一个 Text 节点（≤64B/行，超长行需应用侧截断），Col 容器叠行，等宽点阵 + 逐行等长换文（纯 PAINT）契合滚动更新模式；代价是 Ui arena 容量（launcher 用 Ui<512> 形态，每行一节点 + a11y 不必逐行挂）与 64B 行帽；(e) 绕开 berry-ui 走 gfxdemo 式 raw berry-gfx 自绘（glyph run + fill_rect 直写帧 VMO）——自由度最高（黑底、任意行列、自管滚动），代价是放弃 berry-ui 的 damage/脏区/帧循环设施。若走 berry-ui 路线，(d) 是当前能力面内的唯一现成解；(e) 是「黑底终端」视觉最短路径，gfxdemo 全链即模板。

### 3. GUI 应用骨架：两份模板与「从零到出窗」最小文件面

**模板 A：gfxdemo（raw berry-gfx，无 berry-ui，一次性跑完即退）**。链路：降级门 wm_cli_h()==0 → 一行诊断 + exit(0)（main.rs:218-222）→ WM_GETINFO 断言 version/wmax/disp（232-247）→ WM_CREATE 建全屏 APP 层窗（WmCreateReq{layer: WM_LAYER_APP, flags: WM_CREATE_F_AVOID_SYS, x/y/w/h}，ack 携 window_id≠0，251-266）→ WM_SET(GEOM) 1B OK（270-281）→ TABLE_GET 快照对拍（287-307）→ present GETINFO 断言（312-326）→ 帧缓冲 VMO 三连 create→commit→map @FRAME_VA=0x5100_0000（333-356，libc mmap 禁用——SUBMIT 随行须 VMO 的 fresh READ dup 别名）→ CommandEncoder 软渲（fill_rect + draw_glyph_run，358-413）→ SUBMIT 随行别名（424-452）→ FRAME_CALLBACK 断 PRESENTED（456-467）→ RELEASE 收别名即关（469-481）→ VOTE/POWER_MODE 1B（487-502）。RPC 半程：rpc() 严格串行单趟（send -EBUSY → 等 WRITABLE 重臂；recv -EAGAIN → 等 READABLE，RPC_CAP_NS=300s 帽）（main.rs:143-192）、expect_ok 1B 应答收口（196-210）。CRT0_SEED 静态锚防 crt0 死码消除（main.rs:64-65）。

**模板 B：launcher（berry-ui 常驻帧循环全貌）**。main.rs：降级门 + park（206-210，常驻进程用 park 不用 exit）→ WM_GETINFO → icons/layout 装配 → UiMain 堆置 Box::leak（250-251，栈预算 256KB 下构造中间体 ~29KB 落栈，头注 246-249）→ set_text_metrics 供件（257-258）→ desktop::build 建树（277-280）→ frameloop::run（284）。RPC 半程族拆 send/recv 两半（rpc_send 116-140 / rpc_recv 147-166 / rpc 172-181）供流式会话复用。frameloop.run：present GETINFO 校验 + 几何对拍（183-204）→ RELEASE_WAIT 跨代清账（212-219）→ VMO 三连 + glyph scratch 堆置（221-258）→ 帧循环：收 input 批（326-391）→ pump_input 分发 Msg（394-424）→ render_frame（damage 空集跳过提交，426-431）→ SUBMIT（fresh dup 别名随行，446-473）→ FRAME_CALLBACK 断言 PRESENTED（482-493）→ note_presented 重同步 credits（496-501）→ RELEASE 归还（503-519）→ vote 票面变化才发（533-546）→ wait_many 稳态等待（617-641，见 §5）。a11y 注册：set_a11y(node, role, label)（lib.rs:1407，容量 A11Y_MAX=32，ROLE_TEXT=2 等 lib.rs:211-219），launcher 建树挂 32 条、翻页 rehang 重挂（desktop.rs 头注裁决八）。

**最小文件面清单**（新 GUI 应用从零到出窗需要抄的东西）：单 main.rs 即可起步——降级门（wm_cli_h()==0 的出口形态按常驻/一次性选 park 或 exit）、RPC 半程族（从 launcher main.rs 116-199 抄，约 90 行）、WM_GETINFO/WM_CREATE 断言链（gfxdemo 232-266）、present GETINFO + VMO 三连 + FRAME_VA（frameloop 183-253）、帧链三连 + vote（frameloop 426-546 精简）、CRT0_SEED 锚；走 berry-ui 则加 UiMain::new + 建树 + render_frame/pump_input/wake 循环（launcher 250-251,289-431）。Cargo.toml 依赖面：raw 路线 = berry-libc + berry-sys + berry-gfx + berry-guiproto（gfxdemo 同款）；berry-ui 路线再加 berry-ui。栈预算：berry-ui 链需 stack_pages=64（svcmgr launcher 装配定值，R5 仪器定谳 8 页即穿栈，svcmgr main.rs:7015-7020 注）；raw 路线 gfxdemo 8 页可活。**硬前提：wm 客户端端礼物**——当前只有 svcmgr 预拉直递（gfxdemo arm extras[0] / launcher WMD_CLI_DUP 现.dup）；普通 app 经 app_launch spawn 只授 fs 词礼物（rootfs RO dup + fs 通道 dup，svcmgr main.rs:6061-6107），**不给 wm 端也不给 input 端**——终端应用要出窗收输入，svcmgr 的 app 装配面必须先扩（这是本刀最大的装配缺口）。

### 4. 输入焦点链：事件不按窗路由，键盘链在 guest 侧断线

**事件分发模型 = 单消费者广播**。gui-inputd 收割 virtio 输入 → 泵聚合成 PointerEvent → INPUT_POLL 应答给**拉批的那个客户端**，wire 上无窗口 id，服务端不做按窗分发。窗口感知仅到「命中旁注」：inputd 经 wmd↔inputd 推送对（inputd 发 OP_WM_TABLE_WAIT，wmd park 至表版本新于 last_seen 应答全表快照；inputd 侧 wm_send_wait/wm_on_reply 常驻重臂，`drivers/bins/gui-inputd/src/main.rs:698-739`，serve 两路 poll-first 860-986）持有窗口表快照缓存（超龄 10s 视同缺席，SNAPSHOT_STALE_CAP_NS main.rs:94），drain 后逐事件 wm_annotate：DOWN → guiproto 单源 wm_hit_test（可见窗参选、layer 降序、z 降序、半开矩形、平局表序靠前，`user/berry-guiproto/src/lib.rs:1871-1888`）锁 pointer_id 目标窗，MOVE 全投锁定窗，UP/CANCEL 解锁（main.rs:656-693）——**但旁注结果只进 n_hit/n_miss 记账，不改 wire 事件、不路由**（main.rs:652-655 注释「不改 wire 事件」）。

**wmd 焦点表现状**。wmd 表内部维护 focus: Option<u16>：CREATE 新窗自动接焦（table.rs:277）、WM_SET 显窗（VIS_SHOW）接焦、隐窗持焦则归还（table.rs:316-320）、DESTROY 持焦归还 + refocus_after_removal（table.rs:296-297,234-235）；快照条目带 WM_WIN_F_FOCUSED 位（table.rs:150-151，位定义 lib.rs:145-146）。**对外焦点协议 OP_WM_FOCUS(0x66)/OP_WM_BACK(0x67) 服务端未分派**：wmd 的 handle_wm 只认六 op（0x60..0x65），0x66..=0x7F 未定形一律 1B ST_BAD（`user/bins/gui-wmd/src/table.rs:350-376`）；wm_srv 帧分发表把 0x60..=0x7F 全部转本地表处理（gui-wmd main.rs:149-151）。即客户端现在**无法主动申请/让出焦点**，焦点只随建窗/显隐被动变化。

**应用收 key 事件需要什么**：现状答案是「收不到」。(1) 端点面：input 客户端端礼物全系统只 dup 出一份给 launcher（launcher_assemble 的 lgifts[3] = INPUT_A dup，且仅交互相 [wm,fs,app,input] 满配时，svcmgr main.rs:6971-6990）；input 域 channel 是严格串行 RPC（深度 1），两个消费者 dup 同一端会应答混流——**多应用分 input 需要 inputd 侧新分发机制，不是再 dup 一份了事**。(2) 事件面：即使拿到端点，INPUT_POLL 只有 PointerEvent；键盘 EV_KEY 字母/控制键码在 inputd 泵里进 ignored 计数（feed 分支只认 BTN_LEFT/TOUCH/RIGHT/MIDDLE + ABS_X/Y + EV_SYN，其余 `_ => self.ignored += 1`，`drivers/bins/gui-inputd/src/lib.rs:389-436`）。(3) 协议面：DEV_KEYBOARD/DEV_TEXT 注入与 key 事件出向 wire 均未立法到可用（§1）。

**OP_INPUT_INJECT 自测可用性**：不可用——终端应用（或任何进程）向 input 域发 INJECT 会收 1B ST_BAD（inputd 分派面 main.rs:929-933）。宿主侧注入面存在且独立于 INJECT：宿主 berry 窗口把 winit 键盘转 X11 keysym 发 QEMU VNC（`tools/berry/src/window.rs:816-820`）；CLI `berry input key <qcode>` / `berry input text <str>` 同走 VNC keysym（`tools/berry/src/commands.rs:363-385`）；QMP 面有 send-key 与 input-send-event 绝对指针（`tools/berry/src/qmp.rs:250-270`）。但 guest 设备拓扑只有 `-device virtio-tablet-device` 一件输入设备（`tools/berry/src/qemu.rs:262`），inputd 也只认领 did=18 的恰一个 input 设备（main.rs:220-221）——**宿主键盘 keysym 注入后 guest 侧没有键盘设备与解码路径接它，整链现状是断的**（virtio-tablet 只产 ABS/BTN 指针事件）。终端刀的键盘输入要通，guest 侧至少要：QEMU 加 virtio-keyboard（或复用 tablet 之外的设备）+ inputd 认领并解码 key 码 + input 域 wire 扩 key 事件出向 + 按窗分发或焦点路由——四件都还没有。

### 5. 帧循环 poll 集与 spawn 先例：launcher 双源等待 + bsh 完整 spawn/collect 模板

**launcher 的 wait_many 双源模式**（终端事件循环的直接模板）：稳态等待 berry_object_wait_many，等待集 hs = [hw(wm 通道), hi(input 通道)] 条件入列——input poll 在途（input_pending）才入第二项，n=1 或 2，信号全 SIGNAL_READABLE，deadline = min(ui.next_wakeup(), now+IDLE_CAP_NS=10s, power_armed 窗)（`user/bins/berry-launcher/src/frameloop.rs:617-641`）；TIMEDOUT 是正常醒（渲染下一拍或睡回）。配合 input 的「挂起-非阻塞收-重臂」三段（§1）实现零服务端主动 push 下的双活。内核 wait_many 有 n≤16 上限；超 16 路或多源聚合有 berry-poll crate（进程内 PollSet：批切分 + poll-first 收割 + LT 复报，`user/berry-poll/src/lib.rs` 头注），当前树 bsh 已接线（`user/bins/bsh/src/main.rs:751` SysWaitMany 真实现、804 PollSet 冒烟），launcher 未用。

**spawn 子进程收 stdout 的先例：bsh 是全系统唯一用户态直接 spawn 的模板**（console 应用；GUI 应用无 spawn 先例——launcher 的应用拉起全走 svcmgr APP_SPAWN RPC（frameloop.rs:848-872 encode_spawn_request → svcmgr app_launch），appdemo 无 spawn）。bsh 的 run_capture 家族：cpio_find 定位 → channel_pair 建子 stdout 对 → SpawnSpec{name, data_off/len, stdout: 对端, stack_pages: 32, stdin_feed, args, extra_gifts} → berry_exec::spawn_rootfs_elf(rootfs_h(), spec)（`user/bins/bsh/src/main.rs:5405-5447`）→ collect 收集（recv 满分片入队，-EAGAIN 等 READABLE 活动帽，零长消息 = EOF 终点，5460-5486）→ child.reap() 收退出码 → 关对（5448-5459）。交互版 collect_fg 是终端交错的直接模板：**wait_many 三项 [out:READABLE, proc:TERMINATED, stdin:READABLE]**，三分支处理数据到/子死无 EOF（v1 被杀者不走 exit 族无 EOF，只能靠 TERMINATED 项收口）/stdin Ctrl-C（5487 起头注与实现）。依赖前提：spawn 方需持 rootfs VMO（rootfs_h()）——GUI 应用 manifest 声明 fs = ["rootfs"] 时 app_launch 授 rootfs RO dup + fs 通道（svcmgr 6061-6107），rootfs_h() 可得，spawn 机制面即通。

**终端应用的交错结论**：命令执行的子 stdout 通道可以像 launcher 的 hi 一样**条件入列 wait_many**（有活子进程才加 [out:READABLE] 与 [proc:TERMINATED] 两项，两项 + wm + input = 4 路，远在 16 限内），收集循环复用 bsh collect 形态；命令输出追加进行缓冲后走 set_text 逐行换文（等长纯 PAINT）或整帧 FULL 重绘。无需 berry-poll，除非未来等待源超过 16。
