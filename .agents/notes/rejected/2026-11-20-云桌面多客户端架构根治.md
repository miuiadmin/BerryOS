# 云桌面多客户端架构根治（present 单飞仲裁 + 输入焦点路由）否决

Status: rejected —— 真机触控死因是「新靴活、放久楔死」的输入链时变楔死，与本刀无关（回退版同死实锤）；本刀自身另有 svcmgr input 通道创建 trap 杀 init 实锤；终局全量回退 a1371e508 基线，方案留档按件重做

## Problem

用户全天测试的失败时间线（每修一层下一层又漏——七连修后仍卡）：数据盘缺失→input=0（造盘）；launcher×app 共享 wm 队列互截→submit ack bad（K1 per-app 通道化）；svcmgr 占位柄缺 TRANSFER→init crash（掩码补位）；spawn 槽耗尽（覆盖收盖+loud）；RELEASE count=0→launcher park 永死（宽容）；输入多 poller 互截→导航三键死（撤 app input 端）；修完后用户点了几回又卡。核心诊断：v1 GUI 架构不支撑多客户端——(A) guifbd present 域单客户端几何（held 全局单表 CREDITS=2、pending/cb_park/rel_park 单槽）多 app 并存时跨代 RELEASE 排空他人在途别名；(B) 输入单订阅者（inputd 单 FIFO 全投一个通道）——撤 app input 端后 app 成静态页；(C) 无合成器共享 fb 像素互盖。

## Decision

三面分治，**身份在哪层修在哪层**：

1. **（A）present 域单飞仲裁修在 wmd**（`gui-wmd/src/presarb.rs` 新模块 + main.rs 分发层）。定谳：guifbd 只见一条 present 通道（wmd 中继换手件）、wire 无会话标识——RELEASE_WAIT 无身份域，guifbd 结构性不可能分辨「该客户端自己的别名」；客户端身份（来源通道）只存在于 wmd 分发层。仲裁语义：事务 = SUBMIT..RELEASE_WAIT（SUBMIT/RELEASE 是边界 op）；owner 单槽——他客户端事务在途（租约 5s 内）ST_BUSY 快答不转发（随行别名关收，**alias 未达 guifbd = 零孤儿面**）；属主挂死租约帽外或通道死亡 → wmd 代发 RELEASE_WAIT 清场（`relay::drain_orphans`——held/parked 残留全量回收）再放行（抢占自愈上界 ≈ 租约 5s + 一帧）。不变量：owner=None ⇒ guifbd 无在途事务 ⇒ held 只剩孤儿 ⇒ drain 恰好只回收孤儿——**跨代排空活客户端别名的窗口结构性消失**（活客户端的别名只存在于它自己 SUBMIT..RELEASE 之间，而此时它是 owner、他人的 RELEASE 全被 BUSY 挡在 wmd）。跨客户端 squash（B 的 SUBMIT 压弃 A 的 pending 帧→A 的 FRAME_CALLBACK 得 DISCARDED→fail→park 永死）与 credits 全局耗尽（ST_FULL 连坐全桌面）同因消失。drain 毒化门：present 域 poisoned（陈旧应答在途）时禁发（reply mismatch = 协议腐化红线），归 serve 顶既有清淤路自愈；drain 自身帽到点也标毒化。死亡对账：serve 每轮顶 owner 属主通道被摘表/DETACH（`table.app_alive`）即清主+drain；wm_srv（launcher 端）除外——其死亡走 poll trap→wmd 监督重启既有链。**guifbd 本体零改动**（最关键服务零风险面；单客户端几何在仲裁不变量下恢复正确）。
2. **（B）输入焦点路由 = launcher 代答**（`berry-launcher/src/inputfeed.rs` 新模块 + frameloop 挂钩 + svcmgr 通道对 + appshell pump 三新钩子）。拓扑维持单订阅者（inputd 不动——input 域单 FIFO 多 poller 互截是实锤缺陷形）；app 的输入改 per-app 私有通道对：svcmgr `app_launch` 建对（cli 随 gift 尾位 extras[3]→libc `input_h()`——!wants_fs 形两枚 RIGHT_TRANSFER 占位 dup 撑前缀，资源败=静态页降级不拒起），srv 端（Feeder）经 APP_SPAWN ack 随行迁 launcher（`send_retry_handles`；boot 批/GUI deferred 形恒无）。launcher 路由：事件 y 落**应用带**（状态栏/导航带之间——几何镜像 guifbd `band_geometry` 三源注）→ 投最新注册的 feeder（v1 单可见 app：最后 spawn 者即像素可见者）；手势粘滞（DOWN 锁→UP/CANCEL 解，inputd Q10 同构）；带外恒 launcher（**导航三键覆盖态逃生门恒活**）。「回桌面」复位：back/home/覆盖收盖拍 `retire()`（开关断+手势清）——桌面回前台后应用带点击不再喂不可见 app。代答面：app 的 INPUT_POLL 在席即答（单事件 `encode_input_events_rep`，inputd 应答同帧形），未在席缓冲 4 深满丢最旧；**不代答 EAGAIN**（app 立即重挂=busy 环）；无事件 poll 驻留（app 阻塞等待，inputd 阻塞批拉同语义）。feeder 满表（4=APP_SPAWN_LIVE_MAX）关新柄 loud；通道错码摘除。pump 三新钩子：`on_input`（引擎 push 前路由门——全批被路由走则不 wake）、`aux_handles`（feeder 入 wait_many——app poll 到达即醒，无 10s IDLE 帽迟滞）、`on_aux`（每轮回环顶 drain poll+flush 缓冲，全非阻塞）。现役 app（messages/files 等自带 input_h() 输入循环、不在本刀作用域）零改动即恢复交互。
3. **（A'）pump 宽容 ST_BUSY**（`berry-appshell/src/pump.rs`）：SUBMIT（fresh dup 每轮重试——wmd Busy 快答已关收上次别名）与 FRAME_CALLBACK 1B ST_BUSY 步进重试（100ms 步进，帽 8s > 租约 5s——到帽前属主事务必已收口或被抢占）。非 pump 客户端（contacts-app 形单发 fail）自有路径：其 SUBMIT 时 owner=None 或 self（launcher 在 spawn 守卫 3s 内 render_hold 让位）恒放行。
4. **（C）零新代码**：带合成（批B guifbd 带裁剪/带缓存/带重放）已是隔离层——app 帧 AppCompat 档裁进应用带、launcher 分钟摆字 damage 恒在顶带内（小 rect 不触 FULL），像素互盖面维持既有缓解。

## Alternatives considered

per-client held 表修在 guifbd（弃——wire 冻结下 RELEASE_WAIT 无身份域，结构性不可分辨归属；且动最关键显示服务）；guifbd 帧严格串行化拒收（弃——拒绝面把 ST_BUSY/ST_FULL 直接砸给无重试的 app=新冻结面；wmd 挡在身份层快答+客户端重试才是闭环）；inputd 焦点路由（弃——inputd 单 FIFO 应答无法寻址到正确客户端，除非给 inputd 加 per-app 通道面=新协议面）；wmd 事件帧推 app（弃——app 的严格串行 RPC 层会把非请求帧误读为应答，协议腐化）；方案 D 单应用模型（弃——体验差且不治 (A) 的孤儿/抢占面）。

## Consequences

验证全绿：gui-wmd host 36 测（presarb 真值表 4 + drain 毒化门/帽 1 新）+ musl check；berry-appshell host 27 测（单线程跑法——并行跑法有存量 host.rs 全局绑定竞态，与本刀无关）+ musl check；berry-launcher musl check+--tests 编译（host 链 berry-libc asm 不兼容 apple-darwin=存量限制，纯逻辑测试随 musl 编译面）；svcmgr none-target check；guifbd/gui-inputd musl check（零改动面复验）；berry-gfx/berry-ui host 全绿；`gui8-smoke.py --self-test` PASS（标记面零扰动——swipe 注入直进引擎不经 on_input 门，CLICK ok/click ready 路径未动）。行为：多 app 并存时呈现事务串行化（帧率由分时摊薄，单 app 常态不变）；app 恢复输入交互（messages 的 chips/翻页/滚动全活）；导航三键/状态栏恒 launcher。已知残余：launcher 分钟摆字帧与超慢（>3s 守卫窗）app boot 的清账并发（ST_BUSY 单发 fail→app park 静态页，桌面不连坐——概率 ≈ 每分钟 1 帧 × 超慢 boot 窗）；hdi 域 mutating op（PREPARE/COMMIT/VBLANK 族）未入闸门（桌面客户端只用 PANEL_CAPS 即答面——bench 族直连面）；feeder 与 wid 无映射（多 app 并存时应用带事件全投最新 spawn 者——v1 单可见 app 模型下正确，真 z 序路由挂合成器刀）。Related：[per-app wm 通道化与导航键排雷](../implemented/2026-11-19-per-app-wm通道化与导航键排雷.md)（K1 通道化只治 wm 面）、[应用内全冻与导航三键零反应根治](../implemented/2026-11-20-应用内全冻与导航三键零反应根治.md)（前刀消费侧避让的本刀架构化收口）、[wmd 监督一次重启 I2](../implemented/2026-11-19-wmd监督一次重启I2.md)（wmd 死亡承接面）。

## 回退与真因（2026-11-20 深夜补记）

终局否决，本篇随迁 rejected/：本刀实施后 gui8 自测全绿，但真机场放久触控全死，全天七轮修复无效；终局全量回退 GUI 四面（gui-wmd / svcmgr / launcher frameloop / appshell pump）到 a1371e508 基线。回退由并行 G0G1 会话随 14a9b16fa 入库（该会话把工作树里的回退一并收拢）；presarb.rs 以死文件留在树中（lib.rs 已无 mod 声明），完整实现存 8a0065f10 可取回；inputfeed.rs 未跟踪在树归本刀属地。

回退的直接动因：svcmgr app_launch 的 per-app input channel_pair() 在内核通道对象面 -9 时 trap() 杀 init（D-abort PC=0xd004 x0=-9 实抓）→ APP_SPAWN 无应答 → gui8 红盘；8a0065f10 先行回退该面后 gui8 复绿但真机仍死，遂全量回退。

真因与本刀无关（回退版同样死，定谳）：回退稳定版镜像上 QMP 注入 abs/btn 与键盘事件客机全零反应、screendump 像素对比零变化；而 system_reset 新靴后约 30 秒内注入即时生效（屏幕实变）。定性：输入链「新靴活、放久楔死」。每靴 inputd 的 wm TABLE_WAIT 都悬挂一次（42s / 18s 实抓，I3 强制重发后 inputd 永久沉默）为头号嫌疑；同病前档见[主线基座输入差異调查](../../research/2026-11-16-主线基座输入差異.md)。gui8 全绿的盲区正在此：armed 即测即退，永远测不到放久楔死。

重做门（下刀验收）：任何输入面修复必须过「armed 后放置十分钟以上再注入」的 live 门；gui8 应补 aged 注入用例。三面分治方案文档价值保留，重做按件分刀合入，不再一步到位。
