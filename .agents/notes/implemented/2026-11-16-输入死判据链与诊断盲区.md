# 输入死排障判据链与两个诊断盲区（字母流定性/input_logged 旗）

Status: implemented

## Problem

LAN 演示夜间排障「画面在、点击无响应」时两次误判：先把串口永续字母流当「开机自测失控」（据此写进分层诊断与沿革的定谳）；又把输入无响应单一归因冷页楔死。真因始终未定谳——故障机日志已失，现有池全部是活机。需要把正确的判读知识与判据链固化，防下次再错。

## Decision

- **字母流 = 设计态常驻活性矩阵，永续非失控**：`A`/`B`=内核忙环 task_a/task_b（kernel/src/main.rs，每 2M 迭代一字符）；`u/s/C/W/p/P`=六个 EL0 模板；`S`=abuser；`d`=talker 稳态；`v`=svcmgr 稳态回环（svcmgr:483）；`switches=N kl=0`=调度金丝雀每 100 次切换一行（sched/src/sched.rs `SOAK_PRINT_EVERY=100`）。会终止的只有 FILE/STD/HEXYL 等套件行（svcmgr `_start` 硬编码串行链、全帽、无重试）。**「串口安静」在活机上不可能——安静反而是异常**（矩阵死/被停）。主线已落 demo-face 总门关停舰队（kernel `DEMO_FACE_PROBE_NAME` + svcmgr `USER_ENV_DEMO_OFF`）；berry CLI 侧布线 2026-11-16 补（fwcfg_plan 加键）。
- **输入死四层判据链（按序 grep，零新代码）**：① `gui-inputd: up slot=`（活）/ park 诊断行（死——serve 前卡）；② `LAUNCH v= … input=N`（N=0=gift 缺）；③ `INPUT ok`（非 GUI 形自验）；④ bsh `inputpoll`（绕过 launcher 直捣 inputd 的唯一探针：absent / rpc 无应答 / no events 三分诊）。
- **launcher input_logged 盲区 bug（knife6 系实锤；主线同病在身——2026-11-16 入库前勘正）**：armed 行先占用 `input_logged` 旗（pump.rs:342-345），其后 events/EAGAIN 行的旗门恒假永不打印——**「events 行缺席」是系统性假阴性，不可为证**。修复归属：主线未修——旗正是 wave 3 提交 b9e7d4b64 本身引入（`git log -S input_logged` 全史唯一命中，无清旗路径），events 行缺席假阴性在主线 HEAD 照样成立（与本批 [research 稿](../../research/2026-11-16-主线基座输入差異.md)裁决一致；原稿「主线已随波 3 消失/重写已消」系误断言，入库前勘正）；knife6 系不再修（基座退役）。
- **inputd park 假设的实证裁决与适用域**：2026-11-16 审计对现有活机池（两台现代机）grep——`up slot=30` 全在、park 零命中：**对当前池否证**；当晚故障机日志已失，「当晚输入死真因」无定论，任何文档不得写成已定谳。嫌疑按审计裁决移向 armed 后分发环节（launcher poll/wmd 队列）或宿主注入通道。

## Alternatives considered

- 继续追「当晚真因」：否——故障样本已失（0 字节/被停/活机），无尸可验；判据链留给下次复现。
- 修 knife6 的 input_logged 盲区：否——knife6 基座退役在即；但主线 pump.rs 同款旗门未修（见 Decision 第三条），欠账开放、归主线。
- 把 park 假设写回定谳：否——审计实证降级，按「判据保留、定谳撤回、假设降候选」裁决执行。

## Consequences

- 分层诊断/1080p 会审/沿革同批勘正（勘正注沿 f4 先例）；kernel main.rs 头注「每 50 次」勘正为 100。
- 演示基座切主线源码（输入判据三件套主线更全）；berry 补 demo-face 注入后 GUI demo 档获舰队让位。
- knife6 worktree 的 WTDIE 法证笔记回合时随批带回主仓（当前主仓检索不可达）。
