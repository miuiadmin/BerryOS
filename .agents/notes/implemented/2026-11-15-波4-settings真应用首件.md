# Agent Note: 波 4 Settings 真应用首件（appstub 秒退壳的垂直切片替换）

Status: implemented

## Problem

波 2 把 berry-ui 41 ViewKind 可用率推到 100%（[批 F 收口](2026-11-15-波2控件底座批F落地-41kind收口.md)），但全树唯一 berry-ui 消费者仍是 berry-launcher——组件面「通电」从未被第二个真实 app 消费过。SETTINGS 现为 appstub 共用秒退壳（`_start` 清 env 队列后 `berry_process_exit(0)`，`波4应用翻新侦察（未入库稿，行内注）` §一）。需要首个真实 GUI app 做垂直切片验证：设置页（标题 + Toggle×2 + Slider + Check）、组件可交互（点击翻转/拖动变值）、窗口常驻不退出。

## Decision

新建 `user/bins/settings/`（全量新文件、零改现有代码——避免与兄弟会话冲突）：berry-launcher 镜像的 musl std 独立小工作区（空 `[workspace]` + berry-libc shim + CRT0 链接种子 + berry-ld 链），单文件 main.rs 三段式：

- **建树**：根 Col → 顶留白 → 内容 Col（标题 Text + Divider + 四行 Row）。每行 = [定宽标签列, 定宽推位, 组件]——**不用 Spacer**：Row/Col 游标容器里 Spacer 测量恒 0×0 不吃余量（flex 分配挂 berry-ui 后续布局刀），推位用定宽 Col（launcher 状态栏 spacer 同形）；亮度行尾件两枚（值 Text 定宽列 + Slider），行内缝数进推位算式（`gap × 子数-1`）保行内总宽恒 content_w、组件 x 钉位不随文案宽抖动。
- **交互**：零手写命中几何——Toggle/Check 点击翻转、Slider 拖动跟值全走引擎内建 `widget_react`（`pump_input` 期同拍，经 set_props 单漏斗视觉同帧脏）；app 面 `take_events` 消费 on_change：亮度事件驱动百分值 Text `set_text`（`pct_bytes` 手折 `n%`，值同跳过 set_text 零冗余脏帧）。事件比对锚 = node id + 事件 ID（EV_* 常量随 props 携载走 wire 面）。
- **帧循环**：launcher frameloop 食谱的 app 最小形——present GETINFO 轻断言 + ReleaseWait 跨代清账 + 帧缓冲 VMO 三连（FRAME_VA 同位）+ SUBMIT→FRAME_CALLBACK→RELEASE 严格内联串行（在途 ≤1）+ vote 票面变化才发 + `wait_many` 稳态帽 10s（三态停帧：damage 空集零提交零 RPC）。输入 = input_h() INPUT_POLL 批拉逐条 `push_pointer`；礼物缺席（hi==0）静态页常驻，arm 失败永久降级 hi=0（launcher 段④同形）。
- **降级门**：`wm_cli_h()==0` → 单行诊断 + `park()` 常驻（launcher「wm absent」同形）——**不折衷成 exit(0) 秒退**：appstub 壳的秒退语义就此退役，礼物到位前窗口义务以「常驻待礼物」形态保持。

manifest = `user/bins/settings/manifest.toml`（appstub SETTINGS 版逐字段同，唯一实质差 `stack_pages 8 → 64` = launcher R5 仪器定谳同值：UiMain 构造中间体 ~29KB 落栈 + 每帧 CommandEncoder ~18KB）；icons/views 资产装配面继续复用 `appstub/apps/SETTINGS/` 原件（图标/AppUI 验收零漂移）。

## Alternatives considered

- **WM_CREATE 开自管窗（AVOID_SYS 避让 + surface_id=wid）**：wmd 窗口表已实现（table.rs create/destroy/set/快照），但 guifbd present 域 `surface_id: _` 忽略（guest.rs——v1 单面全幅 blit 模型）且输入仍无窗路由；波 3 稿（SYSTEM 窗/返回路由）仍 draft、冻结点未到。弃：本切片按任务书钦定的 launcher 镜像走 surface_id=0 全幅，窗口生命周期封装归 berry-appshell（波 3 冻结后）。
- **任务书草签 Cargo.toml 原样照抄**（`version.workspace = true`、无 berry-libc/berry-guiproto）：独立小工作区无上游 `[workspace.package]` 可继承（L-SYS 规则/14 全体 musl bin 字面版本同款）；无 berry-libc 则 std bin 无 crt0/env 块消费面（wm_cli_h/input_h/park 全在此），无 berry-guiproto 则 wire 编解码无源（berry-ui 只引类型不 re-export 收发）。按仓库惯例改形，偏差三处记在 Cargo.toml 注释。
- **在 app_launch 里现挂 wm/input gift**：能立刻点亮真窗口，但动 svcmgr 现有代码（本切片约束禁止），且授权面（应答随行 gift/新 env 槽/appshell 中继三候选）是波 4 设计稿首裁项——单侧先动等于替设计稿拍板。弃，缺口如实落 Consequences。

## Consequences

- **运行期点亮挂在波 4 首裁项上**（侦察 §二「GUI 通道授权缺位」）：svcmgr `app_launch` extra_gifts 现恰 fs 两枚，wm/input 对 app 无授权路径——本 app 在 wiring 落地前恒走降级门（一行诊断 + park 常驻，不秒退不崩）。app 侧全链已备好：礼物到位 wm 门自然放行、input 面自然点亮。**这不是 berry-ui API 缺口**——引擎面（widget_react/take_events/render_frame/三态停帧）完整够用；缺的是 svcmgr 侧通道授权（具体：`app_launch` SpawnSpec.extra_gifts 需仿 `launcher_assemble` 增 WMD_CLI_DUP 与 INPUT_A 的 dup 两枚）。
- **装配接线挂账**（本刀不动 justfile）：build-user 的 appstub for-循环里 SETTINGS 出列——build 行（musl + berry-ld RUSTFLAGS，同 berry-launcher 形）+ staging 四件（本 crate manifest.toml / settings ELF → bin/settings / appstub 的 icons+views）+ mkapp；已在 mkapp 门禁实走验证（ASCII 无注释 manifest、491,520B .bap、stack=64 域检过）。注意 mkapp 拒 manifest 注释与非 ASCII（本刀实测两道拒面）。（兑现注记 2026-11-17：已由刀 A 落地——e7bae2f5a，SETTINGS 接线出列 build-user 构建循环 + appstub ELF 退役、七槽全数真 crate；详见 [刀A应用槽合流与计数锁数](2026-11-15-刀A应用槽合流与计数锁数.md)。）
- **包体**：ELF 435,448B / .bap 491,520B（appstub 版 61,440B，Δ+420KiB）——侦察 §三预算模型（7 app 合计 +4-5MiB、128MiB 总量帽）内宽裕。
- **组件内在几何镜像**：TOGGLE_W/SLIDER_W/CHECK_W 按 berry-ui pub(crate) 非契约面值镜像（52/200/24，注释注单源）——样式系统落地后随迁。
- 后续 6 个 stub app（Files/Contacts/Photos/Camera/MMS/Browser）可复用本文件为模板；appdemo 画廊化时 `app APPDEMO up` 断言面重裁（侦察挂账项）与本切片无交集。
