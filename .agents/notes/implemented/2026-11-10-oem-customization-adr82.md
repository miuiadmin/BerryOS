# 厂商定制面立法 ADR #82：组装不 fork 终裁

Status: implemented

## Problem

厂商定制化对 BerryOS 是必然到来的命题（用户判断：后面肯定会有这个事），必须在 v1 及早把架构弄对。核心三问：其他厂商能否拿 BerryOS 定制自己的系统？会怎么定制？如何避免安卓 OEM 定制老路（fork 整树深改→碎片化→兼容性差→升级地狱）？

## Decision

经三轮 workflow（研究两轮 10 稿 + 拍板波三审 3 稿 + 终裁/复核 2 稿），终裁落库 ADR #82（docs/架构决策.md 文末节）：

- **定制 = 组装，不是 fork**：OEM 全部合法定制 = 平台预留组装点上投放产品包（配置）/服务包（替换）/扩展包（新增）三类交付物，全走 .bap + 签名链轨道；四层定制面（配置/扩展/替换/禁改），禁改面 = 内核/IPC 核心/syscall ABI/wire 语义/能力模型/intent 词表。
- **五公理**：定制面必须是合同 / 平台与产品正交 / 个性出口收敛大槽位 / 平台保升级主权 / 执法先于开放。
- **硬闸（生死判据）**：产品配置层 + 签名链 + BCTS 三件套全绿必须先于 P8 真机与任何 OEM 接触窗——违者 OEM 接入必以 fork 形态发生（05 号死因学 N5）。
- **A 档预埋 16 项**（V1–V16，附录一登记表 25 行含 D 组已兑现 9 行）：按五道闸（SDK 外发/SDK-2 开刀/OTA 开刀/P8 真机/handoff 冻结）各自闸前必做，非「现在一律做」；全部零内核改动。红队修正采纳：V1 加 svcmgr 过滤同刀、V10 改尾追加 + HANDOFF_VERSION 1→2、V11 降治理行、V14/V16 拆半。
- **十三问裁定**（附录二）：Q1 星状 lineage 永不入信任判定路径；Q4 BCTS = 冻结件回放制 + v0 门禁宿主钉死现役 just + OEM 自测平台裁决、工具开源免费；Q5 负面承诺现在裁（不设商业准入类杠杆）；Q10 blob 三案分层（B 默认/C 随 IOMMU/A 守禁改面）；Q12 N 公式今裁数值延后。两处不可逆点最晚重议：Q6 账本 schema = SDK-2 P0 合入前；Q3 信封格式 = 首个编队 OTA 实现合入前。

## Alternatives considered

- 安卓 AOSP fork 模式（02 号否决：交付形态只给改源码一条路且无稳定边界 = 碎片化机制根因）。
- 完全锁死（WP 铁幕，05 号否决：饿死）；完全放开（WM，乱死）——中间路线必要条件集 N1–N7，架构只保 N1/N2/N3/N5，N4/N6/N7 是治理与时机命题。
- 树状 lineage（09/12 号否决：翻案要拆已发信任链，星状回退便宜）。
- V11 oem: 词表封位（红队否决：防撞名按构造不可能，与域键文法错配）。
- G12a 机器执法（终裁降级：登记表人工对账钉死 #83/#84 落册与季检时点，避免执法工具自身成新债）。

## Consequences

- ADR #82/#83（预留：产品配置层 + 槽位合同）/#84（预留：BCTS）号位注册；#71–#74 空置不回填。
- AGENTS.md 冻结常量新增定制行（3047/3400 字符，警线上）；「70 ADR」三处口径同步 71。
- 首个 OEM 接入的失败判据进法：交付物是源码分支而非三包 = fork 既成，不可逆。
- V1–V16 实施刀待开（13 号 §5 刀序表：立即桶 12 项）；BCTS 空集风险（07 号 §8.1：只抄 freeze/thaw 结构而无 tier 政策 = 冻结空集）随 #84 立项解。
