# 驱动波 1 三件套：分区表 + DriverTrait 框架 + 键盘消费面

Status: implemented

## Problem

[驱动子系统综合研究报告](../../research/2026-11-18-驱动子系统综合研究报告.md)定谳的近期缺口在 2026-11-20 同日收口三件，共性是纯用户态、零内核改动、全部落在「近期做制度」带内：P0-2「块设备栈太浅」第一断层——全仓无分区表解析器，fsmgr 卷定位是约定式探测、vblk 把整盘当一个分区暴露；§4.1 P1 结构性缺口的框架层——全仓驱动无统一生命周期契约，vprobe 白名单外 did 直接 trap，新驱动各自长 probe/起停胶水；键盘链最后一环——gui-inputd 键泵与 appshell `on_key` 分流面已随 [2026-11-17 键盘物理链刀](2026-11-17-命令行终端优化-键盘物理链与berry-term.md)立法在席，但 launcher 一直是默认空实现，键帧到桌面壳即被静默吞掉。

## Decision

三件各自成刀、同批验收；刀面细节归各单件笔记（一事实一归属），本篇只记整体取舍：

1. **分区表** = 新增 `user/berry-partition`（no_std 纯函数 crate，读盘注入闭包，MBR/GPT 全病态域 loud 拒）——报告波 1 交付物 1.4 的先行解析器刀，vblk 多分区暴露与 fsmgr `first_lba` 定卷消费面留后续刀。见[单件笔记](2026-11-20-berry-partition分区表解析crate.md)。
2. **DriverTrait** = 新增 `user/berry-driver`（probe/start/stop 三口生命周期 trait + `probe_all` 全记录不仲裁 + `DriverError` 值不炸）——报告 P1 框架件、波 2.2 berry-drv SDK 的先行形状刀。见[单件笔记](2026-11-20-berry-driver统一Driver-trait框架crate.md)。
3. **键盘面** = launcher `on_key` 覆写 + keynav ESC 序列重组单步状态机（箭头 UP/DOWN 翻桌面 pager，覆盖态与系统页态保守吞）——键帧覆载约定立法刀留的消费端空窗收口，不动 `Router` 结构避同文件并行刀混装。见[单件笔记](2026-11-20-launcher键盘消费面on_key与keynav序列重组.md)。

## Alternatives considered

三件串行排队（弃——三件刀面零交叠、零内核依赖，并行推进不互锁，同批验收一次锁基线）；等波 1 全套 devmgr 主体落地再动（弃——devmgr 是千行级主体件，三件均为二三百行级可控带内件，先行收口即早消缺口）；汇总笔记取代三篇单件笔记（弃——单件留刀面与备选细节，本篇只收整体取舍与验收面，重叠互链）。

## Consequences

2026-11-20 主仓工作树验收全绿：`just build-user` 全链通过（rootfs.cpio x61 ELF 三查全过）；`cargo test --release -p berry-partition -p berry-driver --target aarch64-apple-darwin` 计 23 测零败（berry-partition 16 + berry-driver 7）。新增源文件 8 件（berry-partition 2 + berry-driver 5 + launcher keynav.rs 1），两 crate 均入 user/ workspace members；键盘面其余改动落在 berry-launcher 既有件。下一刀（各单件笔记已记）：vblk 接分区表暴露多分区、vblk/vnet 迁新 trait + vprobe trap 面收口、键盘词汇 v2 扩 LEFT/RIGHT。
