# 回收循环泄漏止血批——spawn 失败路径三站补漏+NO_MEMORY 部分降级

Status: implemented

## Problem

[总攻批3 生命周期终态](./2026-11-22-总攻批3生命周期终态.md)（commit 3ae47c81a）后 20 轮连点门（同 id 反复回收再拉）4~5 轮即 svcmgr trap 红盘——回收循环存在资源泄漏（commit 8ed8844b4）。对象账本审计（18 项三形对账）排嫌定谳：嫌疑① svcmgr 侧句柄漏关——排除（零漏关）；嫌疑② REAPQ 积压——排除（1.16M 切换静默早清）；真泄漏 = 帧面——每轮回收后子映像 VMO（~1.5MB）+栈 VMO（256KB）的后备物理帧未归还内核池（vmo.rs/vmar.rs 三处账目不对称嫌疑；28 轮×1.75MB≈49MB 耗尽 45MB 帧池与实测精确吻合）。且 trap 崩点在 spawn 链 create 族的 -12（NO_MEMORY）——berry-exec「syscall 面失败自陷」纪律把内核资源枯竭升格为 svcmgr 全服务连灭（init 族连坐）。本批 = 止血（失败路径三站补漏+枯竭降级），帧不归还本体修另立内核刀。

## Decision

- **berry-exec `channel_pair_try`**：`channel_create` 返 -ENOMEM（per-Process channel 配额帽/两端 CHAN_DEPTH×Message ≈2.7KB 队列预储的内核堆分配败——帧池枯竭的第一个可见死法）→ 返 None（调用方拒起新 app 不 trap）；其余非 0 仍自陷（options=0 无 EINVAL 面，表满/gen 尽属系统级异常，链断 loud 纪律不变）。
- **三站接入+全量回收 `spawn_nomem_exit`**：env 对、stdin 对、process_start（-12 = try_prepare_user 装配败——Task Box+16KiB 内核栈）三站 -12 早退形全量 best-effort 回收已建子面对象后 Err 拒起。回收序 = reap 减 wait/read 两刀（子未 start 无退出面）：demand 槽注销先于 unmap/close（防句柄值复用后 pager 误供新主）→ unmap 窗/栈/MMIO（mapcnt 归零——Vmo::Drop 还帧判据）→ close svmo/窗 VMO/ht/hv/hp → 通道面（env 两端+in_s）；全程 `let _ =`（降级路零 trap——再 trap 即止血面自灭）。`#[inline(never)]` 文件尾（位置敏感纪律——批 3 同款：spawn 大函数增量钉 match 臂级 <500B，回收体不进热路径）。
- **NO_MEMORY 分诊旗（Fresh/Migrated 两形）**：`Result<_, ()>` 不改签名（~30 调用面零扰动），static `SPAWN_NOMEM` 侧口（spawn 入口恒清陈值，`spawn_nomem_take` 读后即清）——Fresh（env send 前早退：gifts 原值都在调用方表，照旧全量显式关）/Migrated（process_start 装配败，env send 后退场：gifts 已随 channel_send 迁移进通道消息，调用方旧值 close=-EBADF 即 trap，零收口——通道两端关闭即终结）；env_c 经内核失败回滚「值可变语义存活」（close 或 -EBADF best-effort 吞之，残余账归内核刀实验设计）。
- **svcmgr `app_launch` 失败形回收补齐**：out 对/wm 对两站 `channel_pair_try` 失败 → 已建面 best-effort 回收（fs dup 两枚/out 对两端/wm 对未建面零动作）+ eco `nomem` 行（5B ≤ 24B 帽）+ 拒起返 None（SPAWN 形 err=1 回执——「拒点击」而非全服务连灭）；spawn Err 臂按 `spawn_nomem_take` 分诊（nomem/elf bad 分诊行）+ Migrated 形 skip_gifts（rootfs_dup/fs_dup/wm_cli/in_dup/gui 占位别名零收口）；wm_det 两形恒 DETACH 回收 wmd apps 槽（nomem 形 attach 已成，不收即每拒一次漏 1 帽位）。

## Alternatives considered

- **先修内核帧归还本体再谈降级**：本体修 = vmo.rs droppable_pages/vmar.rs Vmar::Drop mapcnt 不对称——已立[内核帧归还刀](../../plans/mm/2026-11-22-内核帧归还刀实施设计.md)（诊断已产、实施有 boot 崩 bug 待修，长周期）；止血批先封「枯竭升格全服务连灭」放大面，两刀正交不互斥。
- **Err 扩型 `Result<_, NoMemE>`**：~30 调用面签名扰动——分诊旗侧口零扰动达同效，弃。
- **Migrated 形也强收 gifts**：已迁移旧值 close=-EBADF → trap——止血面自灭，禁。
- **全错码降级（不只 -12）**：表满/gen 尽等属系统级异常（链断 loud 纪律）——只降 ABI 合法运行时条件的资源枯竭面，弃全降。

## Consequences

- 20 轮连点门 4~5 轮→14 轮（3× 改善——失败路径确实在漏）；但 svcmgr 仍于第 14 轮 trap：崩点 = vmo_commit/vmar_map 的 -12 trap 面（eager 映射站未入降级——枯竭本体归内核刀根治，逐站铺降级不治本）。止血效果 = 触发点后移+拒点击降级，非根治。
- 帧不归还本体修的实证配方（20 轮连点门+帧水位逐轮打点：修前期望 14 轮崩、修后期望 20 轮全过+帧级净失归零+残余仅表树帧 4-8 页/轮）见[内核帧归还刀实施设计](../../plans/mm/2026-11-22-内核帧归还刀实施设计.md)。
- gui8 PASS（回归面零扰）。
- eco 分诊面新增 `nomem` 行（与 it/alive/killed/elf bad 同面——内核枯竭拒起与坏 ELF 可分诊）。
