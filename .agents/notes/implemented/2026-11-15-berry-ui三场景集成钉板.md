# berry-ui 三场景集成钉板:多组件协作的真实页面验证

Status: implemented

## Problem

berry-ui 41 ViewKind 各自的单元/钉板测试全绿(widgets×7/gallery2 等 315 测),但组件面从未被组合成「真实页面」验证过——跨组件接缝(容器混排的布局协作、一帧 DisplayList 里多类 op 并存、widget_react 事件驱动另一组件换字的重绘链)只在单件测试里各拍一段。settings 真应用(波 4 首件)证明了单页可消费,但它只用了 6 个 kind 且跑在 guest 里,host 侧没有可回归的多组件协作钉板。

## Decision

新建 `user/berry-ui/tests/scenes.rs`(host 集成测试,11 测全绿,零告警):三个真实 UI 场景各答四问——能否编译、布局是否合理(尺寸/位置值级)、渲染 op 是否完整、交互是否串通。通道 = gallery2/offscreen 同位先例(`Ui::paint` → `CommandEncoder` → `Queue::submit` → RGBx 软光栅帧缓冲,逐像素探针;光栅落盘字节序 [b,g,r,x] 探针换序回 RGB):

- 场景 1 设置页(spec 树:标题/Divider×2/双 Toggle 行/Slider+值行/Check×3/Save):布局逐件值级 + 页面直系子全扫不重叠、行距恒 gap;渲染字形总数恰 52(七文本面) + Toggle/Slider/Check/Button 填充值级 + 像素探针;交互全链 = 点 Toggle 翻转(events 值 + damage 非空 + 滑块像素换位)→ Slider 拖动(DragStart 跳位 144/DragMove 600)→ app `set_text("60%")` 纯 PAINT 换字。
- 场景 2 列表详情页做两版:**spec 直译版**(Root Col 三段竖排)实测钉板组合限制——Scroll 主轴可用高 = 子内在高,取 content_height 整高把 TabBar 推出视口(y=817 ≥ 640,渲染剔除);**可工作版** = Stack 叠层(底 Rect + Scroll 全幅 + AppBar/Divider/Tabs 浮层 `set_offset` 钉位,launcher 同形)+ List 行 tiling 经单一内容 Col + Card[标题/正文/Chip×2] + Progress。布局/渲染(含视口剔除:offset 0 折叠区 Card 面整件不在册,滚到底 4 圆角 op 进册)/交互(命中分层穿透浮层、点 Tab 切页换指示条像素、点 Chip 翻选中、app 驱动 set_props 滚动)全链绿。
- 场景 3 对话框:Stack[底层文件列表 Col, 全幅弹层 Col[顶占位, Card[文案, Row[Cancel, Delete]]]]——z 序(Card 面盖底层文本行)、模态(全幅弹层容器吞 Card 外命中,v1 无透传面 = 天然 scrim)、remove 关闭后底层恢复命中 + 像素退场;直角/真圆角双档对拍(Card 双底 FillRect↔FillRectRounded,`set_true_corners` 进程级开关 + Mutex 串行 + Drop 还原守卫)。

六条组件组合限制实测钉板(scenes.rs 文件头单源):①Spacer 0×0 不推位(Row 里尾件贴前件,真实 settings app 用定宽占位 Col 代位);②Scroll/List 主轴吃子内在高不吃「剩余高」(Col 竖排三段破);③List 直接挂多行子全叠 (0,0)(place `_` 臂),行 tiling 须内容 Col 承载;④StackAlign 摆位未实装(弹层居中用 cross=Center Col + 定高占位);⑤文本按字节绘制(GlyphPos.ch = u8,CJK 乱码,文案须 ASCII);⑥paint scratch 全帧共享按发射序消耗、Text run 截尾静默——文本重页(AppBar 浮层画在长列表之后)scratch 须给足(settings 真应用 256 对 ~40 字形富余;scenes.rs 用 2048)。

## Alternatives considered

- 只跑 guest 侧真应用(settings/launcher)验证:能证端到端但不可回归钉板化、单场景组件覆盖窄;选 host 离屏钉板 + 真应用互证。
- 把组合限制当 bug 修(如 Spacer flex 分配、Scroll 剩余高):各有明确挂账刀位(flex 布局刀/消费面),本批先值级钉板现状防漂移,修刀落地后测试随改。

## Consequences

- berry-ui host 台账 +11 测(全套 315 绿),多组件协作面有首个可回归钉板;后续布局刀(flex/剩余高/StackAlign)落地时 scenes.rs 的限制段会红——即「限制已修」信号,届时同步改断言并翻本笔记。
- 场景 2 的 Stack 浮层形(AppBar/TabBar 盖在 Scroll 上 + 内容顶/底占位让位)成为长列表页的可复制食谱;真应用侧(波 4 应用翻新)可直接取用。
- scratch 容量从「settings 注释里的经验值」升为钉板事实:文本重页的 embedder 义务 = 按visible 字形峰给 scratch,否则末段 run 静默截空(视觉缺失不炸)。
