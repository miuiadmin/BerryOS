# E 面制度落地：runner 宪法单源与 punch-list 落位

Status: implemented

## Problem

工程纪律升级阶段 6 需要「无人值守会话遇决策不停下来等人、但触碰仓规的决策不越权、阻塞有去处、运行不碰集成分支」的制度载体——问题是在 Curia 的家里这些各归何处，且 Hermes 侧已有四 lane 舰队（w1/w2/w3/review，W1 已 693+ 轮）在各自克隆的 `.hermes-loop/LOOP.md` 里各持宪法，新制度不能造成第六家或第二份宪法源。

## Decision

2026-11-22 落位：宪法唯一家 = `.agents/skills/berryos-runner/SKILL.md`（每轮循环改造自 W1 已验证形态，叠加 decide-then-report——`A: (run decision, DATE) <choice>. Reversal: <cost>` 落 PR body 固定节、五类硬停、park 必落 punch-list 禁 silently defer-and-forget）；punch-list = 活跃计划的「未完成事项」节（Curia 原生机制复用，载体 `plans/2026-11-22-e面运营.md`），不发明新文件形态；人向接入手册 RUNBOOK.md 与 SKILL.md 同目录（skills 双文件既有分工）；git 机器面 = pre-push bot 身份闸（`git config berryos.bot-email` 驱动，未配置静默跳过，bot 只准推 `wip/auto-*`/`hermes/*`）；cron prompt 一句指针，宪法随仓演进。

## Alternatives considered

- 新建 `.agents/` 第六家 ops/ 放运行台账：否——决策因果归 notes/、规则归 SKILL.md、运行流水归 lane 克隆 LOG、任务队列归活跃计划未完成事项节，一事实一归属已覆盖，加家只制造双写面。
- 改造 W1-W3 现有 LOOP.md 直接承载新制度：否——四 lane 宪法是各 lane 的作战面（路径边界/任务选择各异），E 面制度是横切 overlay；先立单源新 lane，存量 lane 是否采纳 overlay 留 owner 裁决（punch-list 在案）。
- 决策账本独立文件（answers.md 形态）：否——impossible-os 用独立账本是因为它无 PR 基础设施；BerryOS 有 `hermes-auto` PR 队列，A: 行落 PR body 即可追溯，触及仓规的再升格 notes/。

## Consequences

- E lane 未建：仓内侧（宪法/手册/punch-list/身份闸）已落地，owner 机配置照 RUNBOOK 五步走；首跑验收三件未发生（punch-list 首两条在案）。
- gate-selftest 增腿 h（bot 推集成分支拒/wip-auto 过），八腿全绿——身份闸判据固化。
- 规则/16 §5 的「随 E 面刀落地」注记随本刀兑现。
