# Agent Note: 波 4 GUI 通道授权 app 侧接线——app_launch 追授 wm/input 两端（settings 点亮前置）

Status: implemented

## Problem

`波4应用翻新侦察（未入库稿，行内注）`「GUI 通道授权缺位」：svcmgr `app_launch`（user/bins/svcmgr/src/main.rs）的 `SpawnSpec.extra_gifts` 恰 fs 两枚（wants_fs 时 `[rootfs, fs]`，否则空），wm 客户端端与 inputd 端对 app 无授权路径——launcher 独享 `launcher_assemble` 的 `[wm, fs, app_cli, input]` 四件。[settings 首件](2026-11-15-波4-settings真应用首件.md)已备好全链但恒走降级门（`wm_cli_h()==0` → 诊断 + park），本刀落 svcmgr 侧授权让它真点亮。

## Decision

在 `app_launch` 的 fs 装配块后、gift 绑定前插 GUI 追授段，三件决策：

- **门 = `[ui]` 词在场 ∧ `WMD_CLI_DUP≠0`**。manifest type 无 gui 分类（app/driver 两值域，ADR #82），`[ui]` 节是现行最近似的 GUI 判别位；`WMD_CLI_DUP==0`（rootfs 形/裸相 wmd 未起）恒缺席 = rootfs smoke 现行为零漂。**不能对所有 app 统一授**（任务书 v1 简化候选）：APPQUIET 的 lifecycle absent 探针断言 `GIFT_H[0]==0`（berry-libc lifecycle.rs 零义务兼容律），槽位一占即 assert 炸连坐 `APP ok n=`——APPQUIET 恰无 `[ui]`，门天然排除它。console app（APPDEMO 带 `[ui]`）照授，app 侧无访问器即惰性无害。
- **slot 布局守前缀紧致律与 libc 按位落种的对偶**（berry-exec「零 0 洞」send 预检 + io.rs GIFT_H 映射：extras[0]→`wm_cli_h()`/`rootfs_h()`、[1]→`fs_h()`、[3]→`input_h()`）。wants_fs（APPDEMO）：`[rootfs, fs]` 双端不动、wm/input 尾追 `[2]/[3]`——`GIFT_H[0]/[1]` 语义零漂，wm 落 [2] 暂无 app 侧访问器（波 4 裁决 A appshell 位）、input 固定位 [3] 直接可消费。!wants_fs（settings）：wm 落 `[0]`（`wm_cli_h()`——settings 链 berry-launcher 镜像位）+ input 固定位 `[3]`，`[1]/[2]` 为**占位端 = wm 同源别名**：input 到 [3] 需满前缀（洞 = send 预检 0 值 -EBADF 自陷），占位复用已授权的 wm 端 = 零新授权面，且错位消费（未来 app 误调 `fs_h()`）= 对 wmd 发帧得错误应答 loud，非对死通道的静默死等。
- **失败纪律随 app_launch 本体**：dup 半途失败 = 已 dup 面（wm/占位 ×2/input）全量回收 + fs dup 连带 + out 对清理 + `eco: app … gui dup` 降级返回（fs「fs dup」路同形，不 trap——本函数全链是 app 级守卫降级纪律，保持 svcmgr 活）；spawn Err 臂未 take 四 dup 全量回收；Ok 臂随 env 块迁移勿关（注释义务）。`stdin_feed` 判据从 wants_fs 改 gifts 非空——berry-exec 契约 extras 非空须 stdin 槽在席，GUI 面 !wants_fs 也须 `Some(&[])`。INPUT_A==0（inputd 未起）= 尾截断，app 侧静态页降级（launcher input 缺席截断同款）。

dup 口径全件 `RIGHT_SEND|RIGHT_RECV|RIGHT_TRANSFER`（launcher_assemble wm_fresh/in_dup 同款；TRANSFER = 随 env 块迁移的 send 预检保位）。波 4 裁决 A（`ui = ["wm","input"]` 能力词 + appshell crt0 位序立法）落地时本面整体换轨退役。

## Alternatives considered

- **对所有 app 统一授权（v1 简化，任务书候选）**：APPQUIET absent 探针 assert `GIFT_H[0]==0`，统一占位即炸 `APP ok n=9`。弃，改 `[ui]` 判别。
- **占位用 fs 对（rootfs/fs dup 填 [1]/[2]）**：对未声明 fs 词的 app 授 fs RPC + rootfs 读 = 能力面扩张，且同函数三行之上有 `net unserved` loud 拒先例——自反。弃。
- **占位用 app 私有死通道对**：零能力但全新礼物形态无先例，且错位消费 = 对无读者通道静默死等（send 成功 recv 永等），不 loud。弃。
- **dup 失败 trap（launcher_assemble 形）**：launcher 理由是「零清理面」；app_launch 此处已有清理面且全函数是 eco 降级纪律。弃，随本体。

## Consequences

- **settings 点亮链路通**：桌面点击 → `app_serve_spawn` → `[ui]` 门 → 四 dup（wm + 占位 ×2 + input）→ settings 的 `wm_cli_h()`/`input_h()` 双放行，组件交互（widget_react）面通电。rootfs 相（`just smoke`）零漂：WMD_CLI_DUP==0 恒缺席；GUI/冻结相 boot 批的 appstub 族（七包全带 `[ui]`）获四枚但清队列秒退零漂，APPQUIET 无 `[ui]` 不入面。
- **已知相（非本刀缺口）**：真 settings ELF 入 rootfs（justfile 打包块重写另挂）后，boot 批同步 `app_reap_tail` 会遇 park 常驻——`park()` EOF 先行故 `collect_eof` 即返，`child.reap()` 30s 帽 Err → `app reap` 行 → `APP ok n=` 缺 = 波 4 裁决 B（boot 批 ui 词判别/`app <id> gui deferred`）落地前的已知行为，本刀不拌和。
- **占位端成本**：每次 !wants_fs GUI spawn 多 2 枚冗余 wm 端别名（子表随进程退出回收）——裁决 A 换轨位序重立法时消。
- **验证命令修正**：svcmgr 是 no_std none-target 二进制（rootfs 内嵌件），`--target aarch64-unknown-linux-musl` 检查不适用（musl 属 settings/bsh/launcher 等 std 链）；正确检查 = `RUSTFLAGS="" cargo check --manifest-path user/bins/svcmgr/Cargo.toml --release`（吃根 .cargo/config.toml 默认 aarch64-unknown-none，RUSTFLAGS 清空还原用户仓 NEON codegen——justfile build-user 同款）。本刀实测绿（唯一 warning 为存量 unused_assignments）。
- settings 的 .bap 装配（justfile SETTINGS 出列 appstub、mkapp 门禁）仍挂[首件笔记](2026-11-15-波4-settings真应用首件.md)账上，与本刀正交。
