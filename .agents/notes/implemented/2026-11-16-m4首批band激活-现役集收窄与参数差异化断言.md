# M4 首批 band 激活: band_enabled ×4→×2 收窄与首个真调度差异化

Status: implemented

## Problem

调度深水区收官任务②（Intent M4 band 激活）。任务书判词「M4 骨架落但 band_enabled 恒 false（默认全关）」与树内实际不符——[骨架刀](2026-11-15-intent-m4-band-骨架纯面.md)落的 `band_enabled` 是 ×4 集判（`matches!(code, 0x01..=0x04)`，0x01–0x04 全 true，iprofile/src/lib.rs:469 原）
；真实缺口是**激活语义无分层**：词汇面 ×4 全开既非「全关」也非「首批保守激活」，且「两带任务在同 runqueue 有不同 quantum/权重」零断言——`class_fair_intent` 外侧零调用方（12 号复核 + 本刀复扫），参数差异化停留在「可构造」而无机器执法。任务书目标真值表明确：interactive(0x02)+utility(0x03) 两带 on、其余四带（UNSPECIFIED/LC/BG/MAINT）off（保守激活——入场券纪律），即对树内现状是**收窄**（LC 0x01/BG 0x04 从 true→false）非「从 false→true」。

## Decision

三件（2026-11-16，只动任务书域内文件）：

1. **band_enabled 收窄 ×4→×2**（iprofile/src/lib.rs:477-489）：`matches!(code, 0x02 | 0x03)`——恰 interactive+utility 两带现役（最小可验对：两带参数差异可断言）；LC/BG 首批外（×4 全集是 M4 终态非首批形态，随入场券逐批开）、MAINT 编码冻结、UNSPECIFIED 无专带的旧立法全部保留。`band_of_intent`/`band_id_of_intent` 消费同门自动随迁（工厂 Some 集收窄）。表本体六行不动（同键域完整化纪律），行 [1] LC 注「首批激活范围外——行随表在，启用门在 band_enabled」。
2. **ktest BANDM4 五段断言**（kernel/src/ktest.rs:7284-7410，末位新号——ktest done 前 Registration；BAND 族定义体在 test_band 后）：M4A 现役集恰两带 / M4B 工厂门（两带 Some、四带 None=回落单带 Fair）/ M4C **参数差异生效**——两带 quantum/权重包络/latency_target 三轴 assert_ne + 方向钉板（interactive 短片、包络整体更高——u8 越小档越高的阶梯投影）/ M4D **FairBand::new 参数从 IntentBand 表读取**（工厂输出与显式 `new(档, 表行)` 逐字段同、band_id 恒等映射）/ M4E **同 runqueue 共存**——两带实例各 enqueue 一任务进同一本地环、两带任务同环出选互不吞并（集合断言，等权 EEVDF 首见序归 ringface 钉板）。
3. **kernel 直依赖 berry-iprofile**（kernel/Cargo.toml，Cargo.lock +1 边）：M4D 断言需直名 `INTENT_BAND_TABLE` 表本体——经 sched 的 transitive 面不可 use，berry-wqmatch 同款 Cargo 直依赖惯例；sched lib.rs 零改动（EppHint 型 re-export 路径不动，函数 re-export 避开 API 参考计数面）。

注释随迁四处（行为零改）：class.rs M4 段头 + `FairBand::band_id` 字段注 + `class_fair_intent` 工厂注；policy.rs `snap_insert`/`band_of` 两注（「×4 现役集 0x01..=0x04」→「首批现役集 = 0x02/0x03——band_enabled 单源，×4 全集随入场券逐批开」）；sched.rs `spawn_intent` 集成窗注。**不做面（如实注）**：task→band 赋值（spawn 时 manifest intent→band 选择）需 svcmgr/kernel spawn 面协同归后续刀；band 位消费（v3 `policy_bind` 写路）归 v3——ktest 文档头与 class.rs 预留窗注两处明记。

## Alternatives considered

- 按 ×4 全开不收窄（否：任务书明令首批恰两带——保守激活是入场券纪律的激活面兑现；且「首批」概念本身需要现役集能收窄，×4 全开等于激活语义永不分层）。
- FairBand trait 行为真差异化（per-band quantum 在 tick 执法 / priority() 带序映射，否：那是 M4 并线面，入场券（v1 遥测实证+loadgen+尾延迟断言）未过，骨架刀立法「trait 行为与 Fair 逐位一致」仍有效；本刀差异化落在**带参数轴**——「两带任务不同 quantum/权重」经工厂参数生效并 ktest 钉板，与任务书「最小可验」口径一致）。
- sched lib.rs re-export `INTENT_BAND_TABLE` 替代 kernel 直依赖（否：函数 re-export 扩 sched API 影子面；wqmatch 判例已立直依赖惯例）。
- 改 ADR #42 / 调度器设计 §3.8 的 ×4 表述（否：×4 是 M4 终态立法非现役描述，收窄不改立法只加激活分层——设计文档零动）。

## Consequences

- iprofile host 23 测绿（`band_enabled_is_active_four`→`band_enabled_is_first_batch_two`、`band_of_intent_maps_and_gates` 两测改形，计数不变）；`cargo check`/`cargo build` 内核绿；QEMU 双重验证：隔离 overlay（HEAD+本刀 hunks，同骨架刀归因干净先例）与共享树各一靴——boot 相 32/32 标记到齐 + **`BANDM4 ok n=2`**（ktest done 前末位）双绿；共享树首靴曾踩并行①号刀（timer slack）bootparams 在途红 panic（「BP：slack 坏值 abc 须拒」），①号修复后复靴即绿——非本刀回归，隔离靴先行佐证。
- **运行面影响 = 零**：`class_fair_intent`/`FairBand` 外侧零调用方（复扫全仓），收窄只改词汇门真值——对现运行系统逐位无差；「首个真调度差异化」的落点 = 带实例参数差异从「可构造」升「ktest 机器执法」，热路径行为分化（per-band quantum/权重执法）仍是 M4 并线面。
- 残留：LC(0x01)/BG(0x04) 现役化随入场券逐批开（届时只改 band_enabled 一处——单源设计的目的）；polface `BAND_SEL_NONE` 文档注仍枚举「×4 现役带 id 0x01..=0x04」（域外文件未碰，词汇门指针 band_enabled 单源在——归 owner 后续 sweep）；API 参考 v1.8 `class_fair_intent` 条目同枚举旧集（文档影抄面，随下一次升版对拍）。
- `docs_guard` PASS、`writable_globals` ok（82 条不变）、`node .agents/tools/check-docs.mjs` 0 告警。
