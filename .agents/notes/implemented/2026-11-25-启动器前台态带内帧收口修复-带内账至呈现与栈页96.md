# 启动器前台态带内帧收口修复——前台态只还回带内改文矩形、带内账留到呈现、启动器栈页 96

Status: implemented

## Problem

v1 没有合成器，启动器与五个现役应用（BROWSER / CONTACTS / PHOTOS / SETTINGS / TERMINAL）共用帧缓冲：启动器任何一次整帧重绘都会盖掉应用内容区（[应用点开不出窗与窗口自消失诊断](../../research/2026-11-24-应用点开不出窗与窗口自消失诊断.md)「窗口自消失是谁移除的」与 Q3）。整帧的来源有三条：时钟分钟换字——[frameloop.rs](../../../user/bins/berry-launcher/src/frameloop.rs) `on_head` 的 `set_text(clock)` 走 berry-ui A 面 `mark_ancestors_dirty` 推脏到根，`render_frame` 内 relayout 的 `place` 把根的整视口新旧界加进 damage（[berry-ui lib.rs](../../../user/berry-ui/src/lib.rs)、[layout.rs](../../../user/berry-ui/src/layout.rs)）；拉起应用前后的加载灯亮 / 熄翻字（熄为空文本零宽）；任意一下点击的首 MOVE 事件 damage 为空、`wake` 置 FULL（[pump.rs](../../../user/berry-appshell/src/pump.rs) 617 → lib.rs 2339-2343 → 2613-2615）。五个应用都不向窗口服务建窗、全以 `surface_id: 0` 兼容档提交（诊断篇 Q1），启动器的覆盖判据 `covering_app_win` 查 wmd 窗表里「非自窗 ∧ APP 层 ∧ 可见」的表项，对它们恒为 `None`——「换字前加 `covered_by_app` 门」这类短修不可达（诊断篇 Q2）。结果是应用窗存活到下一个分钟沿加 ≤10 s 的 Idle 帽，任意 tap 也能把它抹掉；返回 / 主页键对这五个应用只触发一次整帧重绘，不结束也不隐藏应用（诊断篇 Q4）。

第二颗雷是启动器自身的栈预算：主函数约 196 KB 的栈帧常驻（符号已剥，疑为 `main`，具体局部未证实），64 页 = 256 KB 下帧循环只剩约 60 KB；本修的 `flush_band` 多调用一处 `ui.layout()`，LLVM 不再把 `relayout` 内联进 `render_frame`，20 KB 的重排帧叠在 36 KB 的渲染帧上，首帧路径峰值高约 16 KB 越过保护页——只改 frameloop.rs 的首版起机即 `launcher died`（诊断篇 Q6：PC=0x7ad030 栈探针 `str xzr,[sp]`，FAR=SP，`LAUNCH ok` 零次）。

## Decision

[frameloop.rs](../../../user/bins/berry-launcher/src/frameloop.rs) 新增前台态 `app_fg: Option<AppFg>`（123 行），只用现有信号、不新增树节点、不改 berry-ui / berry-appshell / guifbd。

置位只有一处：`flush_pending_spawn`（854 行）在 `spawn_by_id_inner` 返回 `SpawnOut::Spawned`（APP_SPAWN 真拉起成功）时置 `Some { win_seen: false }`、`fg_next_ns = t_now + 1 s`，先于熄灯改文（865-879 行），熄灯矩形才能以带内帧还回；同处对 pager 做同页 `snap_to`（875 行，复审③——进前台态后 pager 不再吃消息，拖拽中的手势收不到 DragEnd 会把 track 悬在跟手偏移上；SwipePager 无拖拽态公开读面，故无条件调用，非拖拽态为幂等重落）。拉起失败（`SpawnOut::Failed`，`spawn_by_id_inner` 1281 / 1321 / 1325 / 1337 行四个失败口）与已活聚焦形（`AliveFocus`，ack `(false, 3)`）不置位：共享帧缓冲下 FOCUS 不重渲，应用像素并不在屏，桌面须保持可交互。

清除四路：返回 / 多任务 / 主页三个导航键分支首行 `leave_fg`（1120 / 1175 / 1186 行；原 DESTROY 批、翻页、归位逻辑照旧）；`on_head` 的 1 Hz 表查拍（389-408 行）——窗口化应用见过可见非自 APP 窗之后表空即退场或被回收；启动器重启回初值。表查走三态面 `app_cover_state`（741 行，复审①）：快照正常且有覆盖窗 `Some(true)`、快照正常且表空 `Some(false)`、RPC 查败或应答畸形 `None`；只有 `Some(false)` 且 `win_seen` 才清态，坏应答跳过本拍裁定、拍距已推进下一拍重查。原两态调用面（`on_key` 门、呼吸拍）经 `covered_by_app`（729 行）fail-open 到 false，语义不变。

每拍帧收口 `flush_band`（807 行，`on_tick` 末位 553-555 行、render 前最后一位）：先 `ui.layout()` 就地消费 layout_dirty（render 内 relayout 全缓存命中早退，不再把根界加进 damage），再 `drain_damage` 丢弃本拍一切 damage（整视口、翻页跟手包络、按压反馈格、空集唤醒的 FULL），然后对 `band_dirty` 逐槽 `invalidate`——Err 的槽剔除、不计入「有改动」（复审②）；有 Ok 则置 `band_pending` 并 `wake`（damage 非空，不置 FULL）。带内节点由 `mark_band`（756 行）记账：时钟（461 行）、呼吸灯（425 / 432 行）、加载灯（879 行）、关机键（443 / 1240 / 1246 行），帽 `BAND_DIRTY_MAX = 4`（116 行）——全 launcher 的 `set_text` / `set_props` 只有这四个节点。灯熄灭字改 `LAMP_OFF = b" "`（902 行，单空格一格宽——空文本零宽会让 `invalidate` 零面积、damage 空、`wake` 置 FULL；右组本就为两灯各预留一字格，[scene.rs](../../../user/berry-appshell/src/scene.rs) 296-302）。无带内改动不起振：damage 空集 `render_frame` 跳过帧零 SUBMIT。

带内账留到呈现（复审 M1）：`band_dirty` 不 take，登记成功的槽逐拍重登记，直到 `on_presented`（558-565 行）见到 `band_pending` 才清账；`leave_fg`（781 行）同清。原因：泵的 B2 落画节流拍（[pump.rs](../../../user/berry-appshell/src/pump.rs) 636-648 行 `pace_beat`——距上次落画 <33.3 ms ∧ 本拍无输入 ∧ 无动画 ∧ 视口 >1.5M px，来源刀见[1080P 渲染提速双帽](2026-11-20-1080P渲染提速双帽.md)）整拍不进 `render_frame`，而 damage 只在 `render_frame` 内被消费（lib.rs 2494-2508）；若登记后即清空，下一拍 `flush_band` 的 drain 会把滞留的灯熄矩形丢掉且不再 invalidate——熄灯字写进节点却不上屏，直到 `leave_fg` 的 FULL。TCG 一帧 100-400 ms 不触发节流拍，所以落地一路的实跑是绿的；HVF 下必中（见 Consequences 的 A / B 对照）。

输入面：`on_msgs` 前台态下非导航点击整击吞掉（485-493 行，不落 spawn 面、不翻 sys 页）、pager 门加 `app_fg.is_none()`（527-529 行）、tab 位吞掉（1106 行）；`on_key` 门加前台态（706 行）；`extra_deadline`（675 行）纳入表查拍。`leave_fg` = 清态 + 清账 + drain + 空集 `wake` 置 FULL——应用残留像素靠整帧覆盖（home 批 / back 收窗同款正统重画路）。

[svcmgr main.rs](../../../user/bins/svcmgr/src/main.rs) 8584 行 `launcher_assemble` 的 `stack_pages: 64` 改 `96`（96 页 = 384 KB），注释（8572-8583 行）同批改写：保留 R5 的 64 页实测定值来历，写明 64→96 的原因（上文第二颗雷）与本处直接填入派生规格 SpawnSpec、不经清单页数域检（manifest 1..=64）。

门（[gui8-smoke.py](../../../tools/gui8-smoke.py)）：`--recycle-gate` 二击段由「同图标再击、等 `eco: app BROWSER alive`」改为「QMP 点击多任务键、等新 `it` 行、`alive` 行先到即败」（1885-1901 行）；`verify_recycle_gate`（1135 行）期望 it 恰三、recycle / killed 各恰二、alive 零，行序链 `it < recycle < killed < it < recycle < killed < it`；self-test 回收门样本改正样本两轮回收、新增「alive 在席」负样本。三要素——动作：多任务键是前台态下重拉同一应用的入口（`on_nav_click` recents 分支先 `leave_fg` 再 `queue_spawn_app(from_recents = true)`，走同一 `flush_pending_spawn` / `spawn_by_id_inner`，到 svcmgr 同一「同 id 命中」分支）；期望：BROWSER 不建 wmd 窗，svcmgr 已活判据「可见 APP 窗 ≥ 2」恒假，同 id 重拉恒走回收再开（`recycle` → `killed` → `it 03`），`alive` 不可达；等价性：新语义下同图标再击到不了 spawn 面（前台态吞击），而原「二击 = already-alive 聚焦路」在未打补丁的镜像上本也拿不到它等的行（改门一路在干净 origin/main 上实跑同一步同形红）。首击、三击段、双 boot、常态隔离、`main()` 分派未动。

## Alternatives considered

时钟换字前加 `covered_by_app` 门（诊断篇「未定位点」第 4 条的短修）——弃：五个应用不建窗，该门恒假、永不开（诊断篇 Q2）。给 launcher 开 berry-ui `s7` 特性让 `set_text` 走 ChangeMask 增量——弃：在 berry-ui 领地，且不解决「点击空集 wake 置 FULL」与灯熄零宽两条。`flush_band` 登记后 `mem::take` 清空（R8 与 R9 落地稿）——弃：复审 M1 证其在上文节流拍下丢熄灯帧，HVF A 镜像实测灯常亮。门二击改走「先按返回键回桌面再击图标」（[方案](../../plans/2026-11-24-启动器前台态带内帧收口修复方案.md)给的另一例）——弃：可行但多一个按键，多任务键更贴近「前台态下重拉同一应用」的用户路径；「多任务键 + 取屏等窗现 + 仍等 alive」的 α 方案——弃：实测应用窗现后按多任务键仍 `recycle` 先到，`alive` 对 BROWSER 不可达。无窗应用退场无信号的三条路（方案「设计取舍」A / B / C）——owner 裁决取 C，见 Consequences。svcmgr 侧根修启动器主函数 196 KB 栈帧——未做：归启动器 owner，加页只是缓解。

## 门的闭环（r11）
