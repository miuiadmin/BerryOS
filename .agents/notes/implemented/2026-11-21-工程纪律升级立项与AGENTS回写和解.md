# 工程纪律升级立项与 AGENTS 回写和解

Status: implemented

## Problem

调研 [impossible-os 工程纪律](../../research/2026-11-21-survey-impossible-os工程纪律.md)后 owner 裁决四面采纳（规划双戳/门禁与数字自证/判据单源/决策账本+runner），其中 check-docs 升格提交硬门槛必须改写 AGENTS.md 规则 8；但 AGENTS.md 在 2026-11-12 有「纯 1:1 上游、任何情况不回写」终裁（docs/规则/README.md 与 规则/13 多处立法），且该终裁已被现实侵蚀（现行 46 行中规则 7 并行会话、规则 10 跨根拓扑均为本地追加内容）——直接改写将造成宪法自相矛盾。

## Decision

2026-11-21 改裁：AGENTS.md 定位为「骨架 1:1 + 规则条目允许本地追加与最小修订」，G1 ≤200 行 / G6 ≤3400 字符帽继续执法防膨胀。规则 8 改写为硬门槛语义（暂存区快照 `--strict` + 印记闸 + install.sh），细节正文收口新第 16 规则域 [规则/16](../../../docs/规则/16-工程纪律.md)。BerryOS 本地纪律全部本地化，`.agents/README.md`（Curia 上游）零改动。E 面 runner 底座收编 Hermes 既有四 lane 舰队（w1/w2/w3/review），宪法单源 `.agents/skills/berryos-runner/SKILL.md`，cron prompt 只许一句指针。六阶段实施（立法、判据单源、门禁、数字自证、双戳、E 面）以[纪律升级总体设计](../../plans/纪律升级/design.md)验收 checklist 为准。

## Alternatives considered

- 维持 1:1 终裁、硬门槛只写 规则/16 不动 AGENTS.md：否——AGENTS.md 是所有 CLI 会话的自动注入面，硬门槛不入注入面则新会话看不见，防线名存实亡。
- 给 Curia 上游提 PR 把硬门槛做成本家：否——Curia 是通用可移植规范，「钩子归采用方」是其明文分工，BerryOS 专属纪律不该污染上游。
- 新建 `.agents/` 第六家 ops/ 放运行台账：否——决策因果归 notes/、规则归 规则/16 与 SKILL.md、运行流水归 runner 工作区 LOG，一事实一归属已覆盖，加家只会制造双写面。

## Consequences

- AGENTS.md 与 Curia 上游模板从此在条目面有意分叉；上游演进时骨架三节手工对拍合并，G3 探针串与 G1/G6 帽兜底。
- 钩子/脚本/制品分批落地（本笔记只记立法与改裁）；落地期间 规则/16 第 6 节「分期落地注记」标明进度锚。
- owner 排除清单：跨模型评审 pin、docs 覆盖棘轮、站点漂移检查、OS Comparison 表、loopx。
