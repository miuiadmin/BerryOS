# vblk 启动自检顺序缺陷：分区表探测前移到一切写之前，有表即跳过 LBA1 自验写

Status: implemented

## Problem

vblk `main()` 的启动序原为「读 LBA0 验印章 → 写 LBA1 自验 pattern → 读回对拍 → 分区表探测」。写 LBA1 无条件，而 LBA1 恰是 GPT 主头所在，也可能是 MBR 首分区（`lba_start=1`）的引导扇区：带分区表的盘开一次机，主头被 16B pattern 加 IOB 里残留的 LBA0[16..512) 整扇区覆盖（上一轮 GPT 盘真机打出 `vblk: 分区表解析 bad GPT signature (EFI PART) at LBA1`；MBR 盘分区行虽对，首分区引导扇区已毁）。探测在写之后，解析成功也无济于事。[vblk 接入 berry-partition](2026-11-20-vblk接入berry-partition启动分区探测.md) Decision 1 把插点定在「自验之后」——当时探测只打日志，无人核对它与写面的先后；[vblk 死亡面加固](2026-11-24-vblk死亡面加固与display接线.md)的未覆盖面写明非空分区表输出只有 host 对拍，起机盘是 super floppy。

## Decision

同文件 `drivers/bins/vblk/src/main.rs`，三点：

1. **探测前移到一切写之前**：`berry_partition::parse` 的读盘闭包只发 `BLK_T_IN`，整块挪到协商、建队、盘容断言、DRIVER_OK 之后、LBA0 读与 LBA1 写之前。启动期唯一的盘写仍是 LBA1 自验（`BLK_T_OUT`），且只在无表时发生。
2. **跳写判定只看 LBA0 自身事实，不看解析结论**：新增 `fn lba0_table_type(sector: &[u8]) -> Option<u8>`——尾签名 0x55AA 在且 4 个 MBR 槽任一 type 非零（含 0xEE 保护条）即有表，返回首个非零槽 type；否则 `None`。LBA0 魔数验无条件保留（只读）；有表 → 打 `vblk: LBA0 带 MBR 分区表（槽 type=0xNN），跳过 LBA1 自验写`，不写任何扇区；无表 → 照旧写 LBA1 并读回对拍。分区行、空表行、失败行的 `match parts` 与 `VBLK ok` 格式逐字不变。
3. **为什么不以解析项数为键**：第一版实现（r6b-vblk 路）用「解析成功的项数 ≠ 0」判有表，复审在真机上推翻——svcmgr 的 BLKD 自验每次开机无条件写 LBA5（`user/bins/svcmgr/src/main.rs` 的 `BLKD_TEST_LBA = 5`），落在标准 GPT 条目区 LBA2..33；同一块 GPT 盘第二次开机，解析器把被写坏的条目 13 当已用条目，`Err(BadEntrySpan{index:13})` → 项数按 0 计 → 走写分支 → 主头被盖（复审实测：跳过行 0 条，停机后 LBA1 首 16B 为 `berryos-vblk-w1!`）。空 GPT（合法头 + 条目全零）解析为 `Ok(空)` 同理。解析失败 ≠ 无表，判定只能看 LBA0 的事实。smoke 与 mkfat 整盘 FAT 盘 LBA0 无 0x55AA，仍走写路径，主路径零扰动。

## Alternatives considered

以解析成功的项数为跳写键（弃——第一版实现，GPT 盘第二次开机主头仍被盖，见 Decision 3）；看 LBA1 前 8 字节是否 `EFI PART`（弃——只护 GPT，MBR 首分区自 LBA1 起的盘仍被写，且要多一次读）；解析失败也 trap（弃——smoke 印章盘是 superfloppy 合法面，会杀 rootfs 相第 13/14 标记链）；跳过行挪到分区行之后（复审建议项，未做——纯阅读顺序，保持本轮已验的行序）；同批改 svcmgr BLKD 自验为「读原扇区 → 写 → 读回 → 写回」（弃——svcmgr 属并行会话领地，登记研究报告 §3.4 遗留）。

## Consequences

编译门：`just build-user` exit 0（尾行 `tlsscan: rootfs.cpio x62 ELF 全过`），日志有 `Compiling vblk`；`cargo check --release --target aarch64-unknown-linux-musl -p vblk` exit 0，vblk 零 warning（berry-libc 3 条既有）。

端到端（desktop profile、QEMU TCG、256 MiB；数据盘三张共四台，串行、起机前确认上一台已停）：

- 整盘 FAT 盘（`tools/mkfat.py` + 印章，带 virtio-gpu 后端即不设 `BERRY_NO_VGPU`；run `1795470798-432305000-59482-host`）：分区行 `vblk: 分区表解析 bad MBR signature (0x55AA) at LBA0（按整盘服务）`，跳过行 0 条，`VBLK ok cap=2048 slot=31`、`BLKD ok n=512`、`LAUNCH ok`；停机后 LBA1 首 16B `berryos-vblk-w1!`——smoke 主路径逐字不变。分区行第 119 行、`VBLK ok` 第 120 行、`BLKD ok` 第 205 行、`LAUNCH ok` 第 304 行（起机 +211 s）。
- MBR 盘（生成器 `/tmp/r6-part/gen_disk.py`：槽 0 status 0x80 type 0x0e start 1 sectors 2047；run `1795471142-769288000-78575-host`）：跳过行 `vblk: LBA0 带 MBR 分区表（槽 type=0x0e），跳过 LBA1 自验写`；分区行 `vblk: MBR 1 partition: [1] type=0x0e 1-2047`；停机后 LBA1 全扇区与原盘相同（全零，不含印章），整盘仅 LBA5（510 B，BLKD 自验）与 LBA17、19、21、38、42（FAT 区写入）有改写。`VBLK ok` 第 120 行、`BLKD ok` 第 203 行、`LAUNCH ok` 第 305 行（起机 +231 s）。
- GPT 盘同一块连开两次（生成器：保护 MBR 0xEE、头 `EFI PART`、条目 1 `root` 34-2047；run `1795471472-687060000-22087-host` 与 `1795471779-323836000-61558-host`）：第一次跳过行 `vblk: LBA0 带 MBR 分区表（槽 type=0xee），跳过 LBA1 自验写`，分区行 `vblk: GPT 1 partition: [1] root 34-2047`，停机后仅 LBA5（510 B，BLKD 自验）与 LBA2047（43 B，EDK2 备份头）有改写、LBA1 与原盘相同；第二次跳过行仍在，分区行变为 `vblk: 分区表解析 partition #13 bad LBA span [13880518889389229799,13301797506684681951]（按整盘服务）`，停机后 LBA1 仍与原盘相同（`EFI PART` 头完好，不含印章），相对第一遍零扇区差异——`#13` 行是 BLKD 自验写 LBA5 落进条目区所致，属研究报告 §3.4 第六项遗留，不在本刀。第一遍 `VBLK ok` 第 127 行、`BLKD ok` 第 203 行、`LAUNCH ok` 第 304 行（起机 +216 s）；第二遍第 120、203、302 行（起机 +216 s）。两次 `FS ok` 之外另有既知的 `fsmgr: fat init failed: bpb`（fsmgr 只探 LBA0/LBA16，GPT 盘卷首在 LBA50，与本刀无关）。

四台共同：`VBLK ok cap=2048 slot=31`、`BLKD ok n=512`、`VIRTIO ok`、`FB ok`、`FBSERVE ok`、`GFX ok` 均在席，`INPUT ok` 0 次（desktop 机按设计缺席）；devmgr 行 MBR/GPT 三台为 `3 devices: [slot 29] input → gui-inputd ✓, [slot 30] input → gui-inputd ✓, [slot 31] blk → vblk ✓`，FAT 机带 virtio-gpu 后端为 `4 devices` 多一项 `[slot 28] gpu → guifbd ✓`；异常计数四台相同：`wm WAIT 在途悬挂` 2、`err=-13` 0、`wmd died` 0、`respawn` 0、panic 0、`vblk died` 0、gui-inputd 死亡/重启 0、`put_desc 拒` 0、`trap 前 slot` 0；每台两条 `EXCEPTION` 均为 ktest 内嵌用户程序（`user_rogue_ptr`、`user_child`），与基线机同位。四张截图均为 1088×1920 RGB8、非黑 99.77%，沉浸像素回归四点与参考值逐位相同（`px(100,20)=#01a186`、`px(200,600)=#06a896`、`px(500,600)=#05b67d`、`px(272,1830)=#0065c3`），x=544 列 y∈[1600,1800) 的 R>250 计 0。

未覆盖面：真分区盘 LBA0 无 `BERRYOSVBLK!` 印章仍 trap「LBA0 魔数不符」（行为最小变化，未动）；空 MBR 表（0x55AA 在、4 槽全 0）按代码走写路径，空 GPT（合法头 + 条目全零）按代码走跳写路径，本轮均无此盘，未实测；hvf 加速未跑；画面内容只做结构解码与像素统计，未证实。
