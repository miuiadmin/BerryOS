# Agent Note: 模块设计固定形态改为启用（2.3 全量接入，翻转当日否决）

Status: implemented

## Problem

同日早先的 [2.3 升级笔记](2026-11-06-upgrade-curia-23.md) 以「60+ 存量版本化文档双轨风险」为由裁决 `plans/<模块>/design.md` 固定形态**不启用**；仓主随后拍板「彻底接入」——上游更新的全部机制必须真正落地，不能防御性关闭。

## Decision

翻转前裁为**启用**，口径经一主题一承载点律校准后两律并存：

- **新模块**总体设计默认走 `.agents/plans/<模块>/design.md`（`Type: spec` + `Version: MAJOR.MINOR.PATCH` 头块、免日期前缀、`ls .agents/plans/*/design.md` 即全模块索引、`rg '^Version:'` 即版本清单）。
- **存量主题**（GUI/调度器/IPC/FS 等 60+ 份 `名-v主.次.md`）承载点留 `docs/` 原地演进，不迁移、不另建 `plans/` 副本——同主题仍只有一个现行承载点，不违反 2.3 的承载点律。
- 上游规则集三变化随规范全文已生效：规则 2 模块设计句、规则 4 翻状态即取代动作（同批补链改引用）、规则 9 用前先解析状态（检索命中先读头块 `Status:`，`superseded` 追链到终点再当依据）。
- GLOSSARY 补 2.3 制度 5 词（取代链/现行态/一主题一现行承载点/模块设计文档/更新「取代」条）。

## Alternatives considered

- **维持不启用**（前裁）：被仓主否决——「彻底接入」要求机制真实生效，防御性关闭使 2.3 半接入；且经口径校准（存量主题原地演进 + 新模块新形态）双轨风险本可消除，前裁的否决理由不成立。
- **存量全量迁移到固定形态**：仍被拒——违反存量只读纳管（不为合规批量迁移），且 `Version:` 语义与 `名-v主.次.md` 已冗余。

## Consequences

- 下一个新模块的总体设计即首次实战（固定头块四行：标题/`Type: spec`/`Status:`/`Updated:` + `Version:`）；检查器对 `design.md` 免日期前缀、要求 SEMVER。
- 存量主题演进继续在 `docs/` 原地改并升版本号——两种形态按「存量/新模块」分界并存，同主题永不双轨。
- 规则 9 成为 agent 检索纪律：rg 命中先看状态再当依据（配方 7 一次带出命中文件头块）。
