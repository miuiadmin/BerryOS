# 跨根合并防线：main 与 wip/sched-1.1 无共同祖先的三层闸（348 冲突判例）

Status: implemented

## Problem

2026-11-16 17:41 一个并行会话试图把 main 与 wip/sched-1.1 用 `--allow-unrelated-histories` 直接合并，撞出 348 个 add/add 冲突后 abort。两线无共同祖先（merge-base 为空）是仓库既定状态：main 根 `f7eb5535`（2026-08-03 初始仓库），wip/sched-1.1 根 `afd68392`（2026-11-14，1135 文件 31.5 万行一次性插入的整树孤立导入）。此前该状态只写在 berryos-dev 技能第 16 条一句话里，未读规约的会话照样会撞，且无任何机器防线。

## Decision

三层机器闸落在版本化的 `.githooks/`（`core.hooksPath` 指向），统一 owner 逃生阀 `BERRYOS_ALLOW_CROSSROOT=1`，判跨根不写死根 OID（判据 = 多亲提交的相邻两亲 merge-base 为空，任意两条不相关历史通用）：

- `pre-commit`：MERGE_HEAD 在场且与 HEAD 无共同祖先即拒绝——冲突态解完想提交时拦下；原 `.git/hooks/pre-commit` 的 Curia 文档关卡逐字节保留在内。
- `reference-transaction`：`refs/heads/*` 与 `refs/tags/*` 指向跨根合并提交的更新一律拒绝——兜住 `--no-verify` 绕过与无冲突自动合并（两者都不经过 pre-commit）；ORIG_HEAD/AUTO_MERGE 等记账伪引用不拦，否则 `git reset --hard` 回收跨根合并会被误伤。
- `pre-push`：把跨根合并提交推向 `refs/heads/main` 即拒绝——origin 在 GitHub 装不了服务端钩子，本地 push 是最后闸口；lane 推 wip/* 不受影响。

沙盒双孤儿根仓库实测八项全绿：同根合并放行、普通提交与普通 push 放行、冲突跨根提交拦、`--no-verify` 兜底拦、自动跨根合并拦、跨根推 main 拦、逃生阀全链通、reset 记账不误伤。两个实抓 git 坑：Apple Git 2.50 把 reference-transaction 的事务状态作为位置参数传入（`REF_TRANSACTION_STATE` 环境变量为空，两种传法都要认）；`git rev-parse --verify "$oid^@"` 对多亲提交输出为空（`-q` 吞掉「需要单一版本」错），多亲提取必须用 `git rev-list --parents -n1`。

## Alternatives considered

- 只靠技能宣贯：第 16 条早已在册仍被漏读，判例证明纯宣贯不够，弃。
- 服务端 pre-receive：origin 是 GitHub 仓库装不了，只能在本地 push 层兜，弃。
- `git replace --graft` 把 sched 根接回 main 历史：两树在导入点就差 660 文件（+6038/-115986 行），接出的 merge-base 是假基、冲突面一分不减，弃。

## Consequences

任何会话再试图跨根整树合并或直推 main，会在 commit、ref、push 三层之一被机器拦下并附指引；owner 收口用 `BERRYOS_ALLOW_CROSSROOT=1` 走阀。两线收敛的实测基线（merge-tree 空树基模拟）：整树硬合 348 冲突全为 add/add（user 142、tools 65、docs 61、kernel 22、其余 58），owner 专属；定向净增量重放冲突面 = main 15 提交 66 文件与 sched 线 835 改动文件的交集 35 文件，lane 可执行。`core.hooksPath` 是本机仓库配置，其他克隆需各自设置一次（`.githooks/` 已随仓库分发）。
