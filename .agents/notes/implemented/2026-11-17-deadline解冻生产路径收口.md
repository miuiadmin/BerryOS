# Agent Note: S5-c deadline 解冻生产路径收口——pick_next_filtered 补 lazy_unthrottle（04 号审计附记一）

Status: implemented

## Problem

`research/内核深度进化/04-调度热路径-Top5优化机会-v1.0.md` 附记一（推断·正确性缺口，审计自定优先级高于全部性能项）：`lazy_unthrottle_deadlines`（sched/src/class.rs:173——S5-c 逐任务 deadline 预算的唯一解冻点，CBS 同形语义「每期至多 budget CPU 时长、超了等下期」的实现半边）只被 trait `Fair::pick_next`（class.rs:251）调用；而生产代码全部八个出选点（sched.rs:1519/1710/2759/3173/3499/3995/4158/4230）走 `pick_next_filtered`（class.rs:424），后者不含解冻调用；trait `pick_next` 的调用面全在 ktest（POLICY/PV3/PBS/DV/RING2 族直调）。净效果：生产（非 ktest boot）中 deadline 任务（可经 sys_sched_setattr policy=3 进入，syscall.rs:1627/1653-1654）预算耗尽被置 HELD_THROTTLE 后，无任何路径解冻——任务永限流；`DL_ON_RING` 计数门与账本（runqueue.rs:84-115）在生产也成死账面。

## Decision

单源收口：`pick_next_filtered` 头部补 `unsafe { lazy_unthrottle_deadlines(rq) }`——与 trait `pick_next` 同头同函数，语义逐位一致（非第二实现）。成本面：`dl_on_ring()` 全局账本门 0 时一次 Relaxed 读 + 早退（v1 常态全员 fair 门常闭，生产零 deadline 任务时零扫描成本）；非 0 时扫一圈 deadline 判（与 pick_next 侧同款顺带扫——is_deadline 一比较快路径，非 deadline 任务一跳过）。钉板面：ktest test_deadline 尾部补 B3 双用例——B3-1 生产路径对拍（B1 同款置位面 rr.tick → pick_next_filtered 出选 → 解冻清 THROTTLE + dl_refill 授新预算 slice=100 + EDF 带最先出：THROTTLE 位在 ScanAcc 过滤前置（ringface/scan.rs:100「FROZEN/THROTTLE 不占带」），解冻先于扫描使 deadline 任务恢复带竞争资格，必胜出 fair 陪跑）；B3-2 全 fair 环出选不牵连（ktest 本地环使 DL_ON_RING 只增不减、门恒开，验证门开时多扫一圈零命中后 fair 出选照常——零语义差）。注：B3-2 不能钉「门 0 早退」——ktest 全局账本被先前用例污染恒非 0，生产门常闭形态由 dl_on_ring 单边安全注释承载（runqueue.rs:96-105）。

## Alternatives considered

- 每次出选点各自补调（八点散调）——弃：八处复制调用序易漂移，且与 trait 面形成两套头序；单源头部一次补齐覆盖未来新增出选点。
- 把解冻搬进 scan_filtered 环走查（与 band lazy_enforce 同位）——弃：解冻需要 now（cntvct 读）与整环视角，且 scan_filtered 契约是纯投影扫描（offer 面零 Task 写），解冻写 THROTTLE/slice 违反该面纯度；band lazy_enforce 是逐节点双向对账形态与解冻的整环到期判语义不同族。
- 生产侧改调 trait pick_next——弃：八点消费 my_cur 裸指针参数（过滤 Running-elsewhere），trait 面无此参数，改动面远大于一行调用且扰动既有 ktest 面。
