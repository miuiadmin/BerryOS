# Agent Note: 刀 C 波 3 补缺三件落地

Status: implemented

## Problem

两轮全 campaign 遗漏清点（2026-11-15-全campaign遗漏清点.md P0-3、遗漏清点二轮.md）均证实：六波总纲步骤 4 的 Dialog/Menu/Toast v1、softimed 软键盘、battery 真值三件全库无刀无挂账、无人认领——波 3 的其余件（合成/双窗/返回路由）有分支载体，独此三件悬空；gui8-smoke 的 SYSBAR/BACK 验收门同样零存在。

## Decision

本会话认领并直接实施（commit 030095971，wip/land-c）：①新 crate berry-appshell 承载 Dialog/Menu/Toast v1（in-app overlay 形态：Card 面板 + scrim 遮罩 + Button 按压，零手拼；SERVICE 层接线点注释在源，随波 3 wm_layer_known 收宽落地）；②新 crate berry-softime 承载 softimed 引擎半件（QWERTY-lite 键位 + DEV_TEXT/DEV_KEYBOARD 注入编码走 guiproto 单源 + Shift 单发档 + Face 显隐状态机；SERVICE 底窗 bin 随波 3）；③simbattery 增真值发布面（每接受帧发 `BATT ok pct=N state=S` 标记）；④smoke 门收 BATT 标记（RX_MARKERS + SIMBAT 相在场断言）。launcher 一个字不碰——主树 launcher 与 wip/ui-wave3 重写漂移 224+/17−，先动必冲突；battery 消费通道（svcmgr channel 礼物对设计）挂账随波 3 launcher 重写同批接线。

## Alternatives considered

- **cherry-pick wave3 抽取版 appshell**：落选——抽取版是 launcher 五模块骨架（单笔 19 文件重写 launcher 四件）且不含 Dialog/Menu/Toast 三件，C-RECON §五裁决不取；并主时抽取版骨架吸收本 widget 模块（纯增量）。
- **workflow 子代理实施（r1/r2 形态）**：两轮阵亡——r1 脚本漏 await（实施者孤儿 Promise，验收审查跑空树，其「不通过」结论反而正确）；r2 实施代理本体失败（impl: null，疑与并行会话抢全局子代理帽）。终局本会话直做。
- **launcher 直改接 battery 真值**：落选——与 wave3 分支必然冲突，且通道基建（svcmgr 礼物对）属跨服务面，随 launcher 重写批更省。

## Consequences

波 3 三件悬空清零（全库最后三件无主件）；Dialog/Toast 可被波 4 应用消费（pattern 族外首个 overlay 组件源）；softime 引擎零改动等 SERVICE 接线；BATT 标记成为 battery 真值在场的常驻回归门。挂账四笔：softimed bin/镜像装配、launcher 消费通道、SYSBAR/BACK 完整门（随波 3 特性并主）、theme on_scrim token 收编 toast 恒色对（豁免台账在 C-IMPL §一）。
