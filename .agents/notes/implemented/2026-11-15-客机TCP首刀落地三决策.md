# Agent Note: 客机 TCP 首刀落地——入站大段容忍与准入「宁拒不腐化」三决策

Status: implemented

Type: note
Updated: 2026-11-15

一句话说明:客机 TCP 首刀(入站 >MSS 单段黑洞修复)落地过程的三个「为什么」——预检为何必须前移到状态机喂入之前、几何为何整链五点同抬、rx_push 溢出分支为何改防御 trap;附实施中发现的 plan 缺环(IOB 链)与 SLIRP 分段行为的实测精化。

## 为什么预检前移到 on_seg 之前

原 `rx_push` 溢出策略是「丢新字节 + loud」,注释防御假设「SLIRP 遵守我方通告」。[NET-01 深研](../../../research/NET-01-客机TCP栈深研与裁决-v1.0.md) §3.3 已实证该假设不成立;更本质的问题是时序:状态机 `on_seg` 交付时 `rcv_nxt` **已经推进**——截断发生在交付侧等于「字节永久丢 + 后续 ACK 按推进后的 rcv_nxt 谎报」,是静默数据腐化面而非单纯丢数据。所以闸门必须前移:喂状态机之前判 `rx_len + seg_len > rx 容量`,放不下整段就不喂、回当前 ACK(重复 ACK),`rcv_nxt` 不动,靠对端重传;DRAIN 腾空后重传段到达——不腐化、不死锁。本波 8KB 压满臂实证该路径:拒段打印两次(`rx_len=2048 seg=128 cap=2048`)+ 全量恢复逐字节对拍通过。

## 为什么几何整链五点同抬

黑洞有两道闸,取决于 SLIRP 拼段尺寸:第一道在 `main.rs recv_frame` 的 `len > RX_BUF_SZ` 检查(帧超 256B 时 DMA 收帧即丢),第二道在 `tcp.rs parse_gw_tcp` 的 `n > MSS` 拒收线。只抬一道不解整链,所以五点同步:RX_BUF_SZ 256→1600(12B vnet_hdr + 1514 满以太帧 + 余量)/RX_BUFS 16→5(5×1600=8000 ≤ RX_BUF_PAGE 8192,单页零重排结论保持)/RX_SEG_MAX=1460 新拒收锚(满 MTU 段域,与 bt::MSS 发送帽解耦)/Sess.rx 512→2048(1×1460 大段 + 余量,与 WINDOW=512 通告解耦)/IOB_SZ 512→1600。通告几何(MSS 128/WINDOW 512)刻意不动:窗口执法与滑窗属二刀,本刀只抬「实际能收」。

## 实施中发现的两件 plan 外事实

- **IOB 链是 plan 缺环**:plan 锚点清单没列 IOB_SZ,但 `recv_frame` 把 ≤RX_BUF_SZ 的整帧 vmo_read 进 IOB——RX_BUF_SZ 抬到 1600 而 IOB 停在 512 就是静态缓冲溢出。补:IOB_SZ 同抬 1600 + 全部 7 处硬编码 `[u8; 512]` 类型标注换 `[u8; IOB_SZ]` + 新 const assert `RX_BUF_SZ ≤ IOB_SZ` 机器钉住(防 v2 再漏)。
- **SLIRP 分段行为精化**(对 NET-01 §3.1「SLIRP 不理通告」的收窄):本波 8KB 压满臂观测到拒段 `seg=128`——服务端路径上 SLIRP 按我方 MSS=128 通告分段、按 WINDOW=512 限在途;NET-01 观测的数百 B 大段拼段发生在特定形态(其 px-dup 臂 256B 单段实证)。结论不变(拒收线锚 1460 覆盖一切观测形态),但「SLIRP 恒不理通告」过强,收窄为「部分形态不理,分段策略未穷尽」。

## rx_push 为何改防御 trap

预检前置后,`rx_push` 溢出结构性不可达(喂状态机之前已保证放得下)。保留「丢新字节」分支反而是留一条到达即已腐化的静默路径(rcv_nxt 已推进,截断即谎报);改 loud trap:到达 = 预检有洞 = 必须炸响修预检,不能带着腐化面继续跑。与「宁拒不腐化」同一决策的两面:可恢复错误走拒段重传,不可达错误走 trap。
