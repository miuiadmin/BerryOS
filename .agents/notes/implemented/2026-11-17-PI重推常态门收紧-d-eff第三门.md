# PI 重推常态门收紧——donor 判据 d_eff>0 第三门

Status: implemented
Type: note
日期: 2026-11-17
轨道: W3（kernel/sched/ipc）

## 为什么

02 号 IPC 审计（`research/内核深度进化/02-IPC快路径-Top5优化机会-v1.0.md` 机会二刀 a）定谳：PI 全图重推的门控（P2 双计数）只看「存在等派生位睡眠者」，而常驻服务恰好常态睡在派生位上（console 稳态等 READABLE；wait_many 哨兵不豁免同键真等者）。门恒开 ⇒ 全系统每次 send/recv 唤醒都付清零两遍 + 不动点至多 8 跳 + KL 取放的全量重推成本，即便全员 prio 0、永无捐赠可传播。

数学面：传播环的捐赠条件是 `d_eff > cand.pi_inherited`，d_eff=0 时恒假——prio 0 的 donor 恒无捐赠可传。把 d_eff>0 并入 donor 判据即让全零稳态（v1 常态）门常闭。

## 干了什么

判据单源 `berry-wqmatch::keyroute`（W3-Q75 纪律延续），三件套：

1. `pi_donor_candidate(obj, signals, d_eff)`：第三门 `d_eff > 0`（d_eff = max(prio_effective, pi_inherited)，与传播环取值同构）。
2. sched `pi_count_add/sub` 携带 `prio_effective` 入判（与 pi_inherited 取 max 后传判据）。
3. kernel `pi.rs` 重推尾趟双 recount：新 `pi_derived_recount`（①）与既有 `pi_boost_recount`（②）同点——逐睡眠者按入队同款判据重数回写。

## 关键设计：配对安全（欠账必补）

收紧后的破绽面：睡眠者入队时 d_eff=0 不入账 ①，睡眠中被传播抬 pi 后 d_eff>0——若出队时按出队值减 ① 会误减下溢。

消灭路径 = recount 语义：d_eff 睡眠期 0→正 的唯一路径是重推传播写 pi_inherited（prio_effective 睡眠期冻结——写者只有重推尾趟 refresh_effective 和 pick 面 apply，后者只对 runnable；prio_base 睡眠期零写者——sched_setattr 只写 sched_attr 影子，deadline 路写点在 spawn 前），而重推必跑尾趟——尾趟重登 ① 后，出队减法基于重登后的计数，配平成立。计数短暂虚高只致门常开（性能损失非正确性损失），与 ② recount 同款劣化方向。

## 测试

- keyroute host 钉板 21→23：d_eff 门四象限全表对拍（eff/pi 各含极值）；欠账形态 max(0,pi) 过门；recount 累加器与入队判据逐字同源（同一函数消费）+ 全零稳态端到端。
- ktest J9 三钉板：A 全零稳态门闭行为锚（pi_recompute_needed == false）；B 真 donor 门开→受捐→离队冻结（②撑门）→清零→门闭闭环；C 欠账必补链式中转活体（mid 入队 d_eff=0 睡派生位、被传播 20 成真 donor 再传 low；mid 离队减 ① 配平不误减）。
- J 段既有语义零破坏：全部在册 donor prio>0（c0=32/c1=24/c2=20/l1=32/t3a=5/t3b=3/g8=40/c8=36/c10=30/J4 链头 40），门开维持；J8 清零面由 ② 冻结 boost 撑门，不受 ① 收紧影响。
