# 收口遗漏审计清偿：六路 workflow 盘点与七件修复

Status: implemented

## Problem

跨根收口合并（ec0dc637b）推送后，用六路并行 workflow 审计员对最终权威做遗漏盘点：main 增量保全（A1）、对方独立解遗漏（A2）、门禁覆盖（A3）、断链引用（A4）、测试面缺口（A5）、CI 对账（A6）。审计揪出七件待修。

## Decision

逐件清偿：①ADR 台账补行——立法三件 #66/#67/#68（热管理 berry-thermal / 挂起停钟+SLEPT 双钟 / 电源 SDK 契约）与 #85（版本管理总纲）在对账合并时被整取调度线版丢失，从对方独立解 104c0a7a0 补回（三表行 + 一附录节），索引随迁 75 条口径；②svcface REGISTRY 补 0x42 cbox_drain 与 0x84 telemetry_open（吸收 lane PR #411 差分重放），svc_registry_check 45 号三方对拍复绿——0x84 为收口前存量债、0x42 为收口带入半件；③断链改指九处（架构决策 4 / 双语 README 2 / 规则索引 2 / 雷册 1，v1.0/v1.1 旧名全部改指现行版）；④kernel/src/cbox.rs 引用的 WTDIE 取证笔记从未合线裔（e58c94ccf 非 tip 祖先）——整篇移植入库；⑤genfbfont/genwycheproof 两漂移守卫（--check 形态）此前零自动接线，按 a-3 U4「有自检零执法」判例补入 test-host；⑥L-SYS 版本治理两件回批值（gfxdemo/svcmgr）；⑦sleepq 笔记两节（Alternatives/Related）与模拟器分刀方案 boot-mode bullet 自对方解移植。

验证：check-docs 389 篇零警 + docs-guard + svc 45 号 + writable 88 + fwcfg 25 键 + abi 五面六门全绿；test-host 全套 EXIT=0（含 berry-ui 358 / tools-berry 160 / gui-wmd / guifbd / appshell 与 48 项自检）。

## Alternatives considered

- 只报不修（挂 owner 队列）：审计件全部小而机械、证据行级在握，直接清偿成本低于转述成本，弃。
- 直接 merge PR #411：其基线 stale（含已修复的 img-boot 红）且与 tip 冲突——差分重放更快，弃。

## Consequences

审计清白面确认：main 三日增量零丢失（A1 行级验证）、CI 无新未归因红（A6）。挂账三件：①运行时相族（rootfs 56 标记/RX/FAT/B4/smoke-smp/gui8-smoke/smoke-image 产链）待低载窗正式跑——本机双跑同码一绿一红判例在案，属环境面待静窗；②代码注释裸名断链已批量清偿（2026-11-17 workflow 五域并行 179 处/121 文件改指现行版，含主线补 README/.ld 域外 3 处）；③berry-launcher 源内 16 例单测在 host 不可编（berry-libc 内联汇编 ELF 形态 vs Mach-O GOT 约束）——其测试跑法归 launcher lane 裁定。
