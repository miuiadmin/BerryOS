# VNC 第十波：LAN 远程桌面——--lan 单口代理/终端 QR/壳页底栏设备面板

Status: implemented

## Problem

wave9 收官后网页桌面对手机是死路：页面服务与 QEMU ws 都只绑环回，手机扫码打开的是它自己的 127.0.0.1；wave9 砍 QR 时登记的重启条件（LAN 绑定模式立项时随批评估，届时 QR 内容必须用剥掉 `#password=` fragment 的 URL）随本波立项兑现。要把「手机连同一 Wi-Fi 直开 BerryOS 桌面」做成第一形态，同时 owner 追加需求：页面下方要一排设备按键（菜单/返回/多任务/关机/重启/截图/全屏）。约束：wave10 计划冻结 `web/` 全树（「浏览器侧零改动」），而底栏按键恰恰要动壳页——计划边界与 owner 需求正面冲突。

## Decision

- **单口 path 路由代理**（计划契约 2 原样落地）：`--lan` 让 berry 绑 0.0.0.0 单口，`/ws` 的 GET+Upgrade 判定后只改写请求行 target 为 `/`（QEMU ws 只认根路径），其余头字节逐字节透传，双线程明文字节管道对泵至 EOF；代理分支结构性豁免 30s 连接预算（数据面与 wss 代理同语义）。QEMU 永远只绑环回。
- **底栏设备面板 = 计划外扩展，动 `web/` 三件自有资产**：deviation 登记进计划的「偏差」节而不是砍需求——owner 的直接需求优先于 wave10 自己划的冻结面，且改动只落在自有资产（index.html/berry.js/berry.css），vendored `novnc/` 树仍零触碰。
- **控制 API 设计成空体 POST**（`POST /api/power/<reboot|off>`）：action 走路径不走 body——head 读取阶段就是唯一读取阶段，彻底避开「BufReader 缓冲了 head 之后的 body 字节、drop 后丢失」的坑；这个坑对本波是真实威胁（API 若带 JSON body，慢客户端半包即丢字节）。
- **API 口令门与 run 认证等强**：run 有口令（LAN 模式必选）时要求 `X-Berry-Pass` 匹配 vnc.pass（常数时间比较）；无口令 run 只存在于环回模式，API 免门但只听 127.0.0.1。另加 Host 头防线（须为 IP 字面量或 localhost 形态，否则 403）——挡 DNS 重绑定把 evil.com 指到 127.0.0.1 后调用免门口令的关机端点。
- **导航键诚实落法（2026-11-15 晚修订：从键码注入改为代点真导航条）**：初版把主页/菜单/返回/多任务映射为标准 X11 keysym 注入——实测客机根本无键盘设备（gui-inputd 仅 virtio-tablet），四键完全无效果。修订为按客机 launcher 五键导航条的真实几何（desktop.rs 常量：大屏键 160px/间隔 48/条高 190，紧凑 44/12/44，条居中贴底，序为 返回/多任务/主页/旋转/关机）在页面侧合成 mousedown/mouseup 事件**代点客机自己的导航条**——真客机语义（返回=翻页、主页=回 page 0、多任务/旋转=launcher 真行为），走 noVNC canvas 公开事件面（不碰私有方法），坐标按 canvas 分辨率自适应两档几何；`berry input tap` 以同指针通道实测 recents 键坐标命中（画面变化实证）。菜单键取消（客机无此概念），加旋转键。口令持久化放宽为 sessionStorage（tab 关即清，非 localStorage）：纯内存方案下刷新页面必重输口令，owner 实测抱怨；sessionStorage 与内存副本同信任级、刷新免输。
- **截图走客户端 canvas**（`canvas.toBlob` → PNG 下载）：手机上即存即得，零服务端往返；比服务端 `berry screenshot` 临时文件再回传少一个面，且截的正是用户所见（缩放档无关）。
- **关机双击 3s 确认**：对齐窗口快捷栏 OFF 键先例，防手机上误触。

## Alternatives considered

- **双口（页面口 + 独立代理口）**：否——对手机要复制两个地址/端口，单口 path 路由是 probe f3 已实证的最简形态（lanproxy.py 原型两路 101+RFB banner）。
- **API 带 JSON body**：否——见上文 BufReader 丢字节坑；路径携带 action 后 head 即全部输入，且 curl/页端 fetch 都更短。
- **API 免口令（LAN 明文页反正弱）**：否——那会把「LAN 暴露 = VNC DES 等强」的 wave1 姿态撕开一个无认证的电源开关口子；X-Berry-Pass 让控制面与桌面同强度，页端口令本来就在内存里（fragment 或凭据弹窗）。
- **导航键映射成客机现有手势**（如返回=左滑注入）：否——发明映射等于撒谎，且 berry-ui 六波（体验大改造）正在给客机长真导航语义，等它落。
- **服务端截图回传**：否——多一个临时文件面 + 手机下载链路更绕；canvas 抓帧是 noVNC 页面天然能力。
- **QR 自写或引重库**：维持 wave10 计划决策——qrcodegen 1.8 唯一稳定版、零传递依赖、MIT，golden 向量（v1/21、v4/33）+ Vision 实扫两层兜底；自写最小 QR 否（v6+ 交织块正确性风险，约 400 行换一个整刀砍项风险）；wave9 三案中的 vendored qrcode-generator 案前提不成立（probe 检索 noVNC 树无该文件，vendor 下只有 pako）。
- **hostname.local 进 URL/打印**：否——probe f2 实证 Android 对 mDNS 解析不稳，裸接口 IPv4 是全平台最大公约数（mDNS 注册本就是非目标）；UDP connect 8.8.8.8 取出口 IP 的惯用法同被实证否决（本机 VPN fake-ip 返回 198.18.0.1，不是 LAN 地址）。
- **TLS run 的 LAN 形态（rustls 客户端终止上游 + http 页）**：否——QEMU ws 端点 wss-only，明文字节管道无上游可转；rustls 客户端上游是新面，且手机侧自签证书墙打死 https 形态；硬拒 rc=2 + restart hint，重启条件登记于计划契约 6。

## Consequences

- `serve`/`serve_listener` 签名参数化为 `ServeCtx`（root/lan/ctl 三合一）而非计划原文的两个散参——文件改动清单的措辞偏差，实质同构（deviation 已登记）。
- **并行会话竞写实录**（本波最大过程坑）：wave10 计划的另一实现会话与本会话同时动 `tools/berry/src`，Cargo.toml 出现重复 qrcodegen 块、web.rs 出现两套同名 LAN 函数、lan.rs/qr.rs 被对向覆盖。收敛策略=采纳对方的 lan.rs/qr.rs 整体（其 LanAdmission{msg,hint} 与数字排序枚举更贴计划），web.rs 保本会话的 ServeCtx 集成并切除对方死块，以 cargo test 113 全绿为唯一裁判。教训：计划文件被两个会话同时认领时，动手前先 `find -newermt` 探测近期写入。
- 触摸即指针：手机触摸经 noVNC gesturehandler→VNC PointerEvent→客机 virtio-tablet，与真机触摸同事件面（wave9 既有），`/ws` 代理只是字节管道，零语义损耗——LAN 通道等价性由 Chrome 真引擎经 192.168.1.105 实连证明。
- 多指手势与 VNC 协议同界（单指针），SetDesktopSize 仍不支持（wave5/6 沿）——分辨率走 `berry display`。
- 重启经 QMP system_reset 后 VNC 短暂断开，壳页自动重连指数退避接回——实测可用；关机后页面转重连态失败属预期（设备已停，CLI 重启会话）。
- **1080p 桌面不上屏的边界实测（2026-11-15 晚，对 GUI 六波有价值）**：portrait/fullhd/phone+display-mode 三路 1080×1920（fb 8.3MB）全部 FB ok + LAUNCH ok 但帧缓冲恒黑；480×1000（1.9MB）与 tablet 800×1280（4.0MB）壁纸/导航条/点击全通——与 README「buddy 4MB 连续块」帽吻合，1080p 桌面缺的是 >4MB 连续 fb 分配支持（guest 侧活，历史 1080p 截图来自更老构建）。LAN 演示当前最高可用档 = tablet 800×1280。另：HVF 快档被在制品内核两处回归挡住（FP FPSR 自检、首用户进程 EL0 D-abort），berry 侧 GUI 家族 `noktest` 注入已铺好（qemu.rs，六波 owner 裁决的落地），内核稳后即享。
