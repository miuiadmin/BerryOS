# svg2icons 双门守卫（源资产在席检查 + 参数分发宽容化）

Status: implemented

## Problem

[svg 图标位图库直进](./2026-11-16-svg图标位图库直进.md)落地的 tools/svg2icons.py 有两处叠加成事故的结构缺陷：其一，参数分发是 `sys.argv[1] == '--selftest'` 精确匹配，无参与任何未知参数都静默落入 build()；其二，build() 无前置守卫直接覆写 icon_data/ 全部 4 文件。二者相乘——源资产 /tmp/icons-src（fetch_material 产物，属易失 tmp 目录）缺席时任何人敲错参数或裸跑脚本，就会把 12.8 万行位图产物刷成空壳。该事故已实际触发过一次清库。本刀补两道门，属事故复盘后的防线固化。

## Decision

- **门一（源资产守卫）**：build() 入口先查 `SRC.is_dir() and any(SRC.rglob('*.svg'))`——rglob 递归命中源三族真实所在层级（svg 均在子目录，浅 glob 会恒假）；缺席即 SystemExit 报错（rc 1），错误信息附补救指路（先跑 fetch_material.py）。守卫放在 build() 函数体首行而非 main() 分发处：任何调用路径（含未来 import 复用）都被保护。
- **门二（分发宽容化）**：`__main__` 重构为 main(argv)——参数 strip 前导 '-' 且小写后匹配 `selftest` / `build`（`-selftest`、`---build`、`--SELFTEST` 等变体均收口）；无参、多参、未知参数一律打印 usage 到 stderr 退出 rc 2，不再隐式 build。build 必须显式 `--build`。
- CLI 契约收紧前置排查：仓内唯一调用点 justfile:1260 只用 `--selftest`（行为不变），无参 build 无调用点——收紧零破坏面。

## Alternatives considered

- **只加门一不动分发**：守卫能挡源缺失，但敲错参数仍会真跑一次全量光栅化管线（源在席时直接覆写产物）——静默落入 build 的分发缺陷独立存在，治标不治本，弃。
- **argparse 重写分发**：功能等价但引入依赖面与样板；selftest 路径「零依赖」是该工具的设计原则（PIL 惰性导入同源），两行 lstrip 匹配更贴此约束，弃。

## Consequences

- 无参不再隐式 build：对人类是防呆收紧，代价是重产必须显式 `--build`——docstring 用法节已随改。
- 守卫查询是 rglob 短路扫描，源在席时首个 .svg 命中即过，不构成管线可感知的开销。
- 正产物路径不变：`--selftest` 输出与 justfile 接线行为逐字不变（348 枚注册钉板仍绿）。
- 后续若新增生成器（gen*.py 族），两道门模式（易失源守卫 + 显式子命令）可复用为先例。
