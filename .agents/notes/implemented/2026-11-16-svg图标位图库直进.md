# svg 图标位图库直进（svg2icons 批量管线 + icon_data 三源注册表 + 状态栏/dock 位图面）

Status: implemented

## Problem

[ADR #63](../../../docs/架构决策.md) 追记（2026-11-06）钦定状态栏 signal/wifi 取 applications_systemui 官方 SVG、dock 按 OH 官方资产复刻——但仓内只有程序化几何内建面与 genohstatus.py 单件生成器，缺一条可批量复用的「SVG 源 → 客机可渲染 ARGB 位图」管线，也缺独立于内建 id 的位图 id 域（防撞内建语义）。

## Decision

- **tools/svg2icons.py（genohstatus.py 先例的批量版）**：resvg 光栅化 66×66（透明底）→ PIL 读 RGBA → alpha≥128 二值化（前景 0xFFF0F0F4 / 背景全透明）→ ARGB u32 数组；源三族均 Apache-2.0（Material outlined/filled 24px、OH sysResource media、OH systemui 组件 media），经 fetch_material/稀疏 clone 收敛 /tmp/icons-src 的洁净边界不变。产物 user/berry-appshell/src/icon_data/{material,oh_sysres,oh_systemui}.rs + mod.rs（ICON_DATA 全量注册表，约 12.8 万行，独立 id 域由 BITMAP_ID_BASE 起）。
- **icons.rs 位图域**：bitmap_id(name) 按名查 / bitmap_entry(id) 反查像素面，建树侧「位图优先、程序化内建面兜底」；STATUS_BITMAP_NAMES 三槽——状态栏前两位（signal/wifi）位图优先取 OH systemui 官方面，缺名回退程序化内建面，第三位电池恒程序化（名槽留空）。
- **scene.rs 两口径合一**：status_dims 成为布局宽与渲染 spec 的单一真相源（原两处独立取 DIM 会分叉）；status_icon_spec 收位图库 id，66×66 方源等比缩至状态栏图标高 45。
- **desktop.rs**：dock 位消费位图域（位图优先、程序化兜底）；导航键命中区 big 160→96（owner 回调——原「大点」过度）。

## Verification

- build-user 全链冷跑绿（隔离 CARGO_TARGET_DIR）：mkapp 全件产出（icons=1 views=1）、mkcpio 重装 44564480B×62 条目、tlsscan 全过。
- check-docs 全绿。

## Consequences

- 状态栏 signal/wifi 从程序化面升级为 OH 官方资产位图面（ADR #63 追记 SVG 面落地）；dock 应用图标获得真位图源。
- 资产管线可批量复用：新增图标源 = svg2icons 扫新目录 + 重生成，无手写像素面。
- a11y 口径不变：模拟值退位决策（视觉保留、a11y 不入表）不受换源影响。
- 挂账：gui8 QEMU 冒烟未跑（位图面实机渲染人工复核待办）；NAV_KEY_PX_BIG 96 实机手感回访。
