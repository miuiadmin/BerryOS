# 波3 wmd 焦点与返回路由落地（表冻结/事件通道/500ms 兜底）

Status: implemented
Type: note
Date: 2026-11-15

为什么：波3 设计稿《2026-11-15-波3桌面三栏与系统窗实施设计》§3/§9（主树 .agents/plans/ 在册、本工作树未含——引用按名不按链）把 I2 返回键路由的 wmd 侧、焦点维护与 TABLE_WAIT 多客户端语义收口判给本刀，执行序归[六波实施方案](../../plans/2026-11-15-体验大改造六波实施方案.md)步骤 4；[波2 批A 笔记](2026-11-15-波2控件底座批A落地.md)「服务端执法挂波3」的 wmd 半在此落地（guifbd 半归 SA）。本文记三项裁决与两个坑，供 SA（guifbd 订阅面）/SC（launcher/appshell 消费面）与波4/波5 接线。

## 裁决

- **TABLE_WAIT 冻结（§9 立法落地）**：单车位 parked 语义零改动（后到覆盖不排队、表变更向当前 parked 应答快照），唯一合法驻留者仍是 inputd push 面；多客户端表跟随一律走事件通道 WM_EVENT_TABLE 通知 + TABLE_GET 快照——通知非阻塞 send 满即丢，真值恒经 TABLE_GET。新鲜度窗口（一次中继时长）接受为 v1 语义。
- **无窗订阅者走新 op 而非 parked**：guifbd 表快照「通知驱动 + 异步拉取」需要事件源但 guifbd 不建窗——新增 OP_WM_SUBSCRIBE=0x68（add-only，ack 1B OK + 随行恰 1 订阅者通道端），而不是让 guifbd 去 wm_srv 上 TABLE_WAIT（会位移 inputd 的 parked 单车位 = §9 明令禁止的乒乓自旋面）。订阅帽 WM_EVT_SUBS_MAX=4 静态定容。
- **事件帧型独立带 0x90..=0x92**：WM_EVT_BACK=0x90（4B `[kind][wid u16][r]`）/ WM_EVT_TABLE=0x91（5B `[kind][version u32]`）/ WM_EVT_BACK_ACK=0x92（1B）落在全部 op 带（present 1..=6 / input 0x20..=0x22 / hdi 0x40..=0x43 / wm 0x60..=0x7F）之外——错投任一请求分发面恒 ST_BAD，结构性防错投（wm 带互斥 Q1 同法）。
- **BACK 兜底是唯一可靠网**：内核 v1 通道无对端死亡检测（channel.rs「诚实缺口」——send/recv 对死端表现如常），事件通道 send 成功 ≠ 客户端活着；500ms 单槽软定时（`WMD_BACK_FALLBACK_NS`）到点兜底 DESTROY 是状态机的承重面，不依赖错码分支。事件投递恒非阻塞：满即丢同武装（客户端可能只是没排空），余错码才关闭通道降级「无通道窗」。
- **表变更解除兜底按设计字面**：任何 bump（CREATE/DESTROY/SET/FOCUS）清 pending_back——客户端以 DESTROY（优雅退出序）/SET 自证存活即不再需要兜底；无关窗的表变更也清槽是设计 §3 R2「无 BACK_ACK 且无表变更」的字面落地，v1 接受（挂单槽语义下无法区分变更来源）。
- **CREATE gift 降级不炸**：内核通道资源拒绝时建窗照常、ack 零随行（无通道窗）——BACK 对无通道窗直接 DESTROY（设计 §3「返回语义仍正确」立法），比 trap 整个桌面更诚实。
- **FOCUS 策略**：win=0 让出（焦点清空）；win≠0 须在册（ST_NOENT）且可见（ST_BAD——持焦窗恒可见不变量；ST_BAD 作策略拒码有 OP_INPUT_INJECT 先例）。
- **wm_layer_known 收宽落地**：波2 R1 立法「拒点从 2 移钉 3」本工作树此前未落（谓词仍 ≤1）——本刀收宽至 ≤WM_LAYER_SERVICE=2，CREATE/快照双侧对称，值域收宽不升版（VER_WM 恒 1）。SERVICE 不挖 AVOID_SYS 坑（§5 覆盖语义），层序 SERVICE>SYSTEM>APP 由 hit-test layer 降序天然覆盖零算法改动。

## 坑

- **gui-wmd 升双面 crate 才能跑 host 单测**：berry-libc 的 crt0 inline asm（adrp BERRY_ARGV）在 aarch64-apple-darwin 不编译，bin crate 直测死路——按 gui-inputd 先例拆 lib（纯策略核 + Port 缝，`#![cfg_attr(not(test), no_std)]`）+ bin（ChanPort 壳，berry-libc 按 `cfg(target_os = "linux")` 门控、host 空壳 main）。berry-sys 全平台可编译（只引类型不引调用点）。
- **wait_many 帽 16 vs 事件通道上界 21**：2 请求面 + 15 属主 + 4 订阅者超 WAIT_MANY_MAX=16——越窗截断 + 100ms 短帽重询兜底（截断面的 BACK_ACK 至多迟一帽，兜底 500ms 网更外层），不做分线程。
- **serve 每轮顶先 tick+收割再 poll 请求面**：若事件通道收割排在请求面 continue 之后，持续 wm 流量会饿死 BACK_ACK 收割——500ms 兜底会误摘已应答的窗。
