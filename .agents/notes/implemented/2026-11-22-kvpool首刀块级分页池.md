# ai-runtime §三.1 首刀：KvBlock 池 berry-kvpool

Status: implemented

一句话说明：E lane R4（DAG `ai-runtime §3` 有界片段）——契约三.1「块级分页 KV-Cache」的池语义落地：新 crate `user/berry-kvpool`，16-Token KvBlock 定容池（const 泛型 CAP 零分配）+ 前缀 Copy-on-Write 共享（fork_prefix 引用计数 +1、物理块恒一份——「系统提示词跨会话共享只读块」的机器形态）+ 共享尾块禁原地写执法（SharedTail loud 拒）+ 显式回收口（no_std 无 Drop 消费边）；host 9 测。开发期测试抓到并修掉一处真语义伤：满尾块（含共享满尾）滚新块是非原地写、不属 COW 执法面——判序错了则 fork 出的会话永远无法续写（主用例崩）。注意力 score 面与缺页重装归 airtd 运行时刀。

## 裁决与判例

- **COW 执法面收窄到「原地写」**：共享块的不可变性执法点是突变写——满块滚动新块不触碰旧块字节，放行；有空间且共享的尾块续写才拒。判序（先查满、再查共享、后写）是主用例（fork 满前缀系统提示词后继续生成）的生死线，测试钉板。`A: (run decision, 2026-11-22) COW 执法面=原地突变写（满尾滚新块放行）. Reversal: append 判序单点改。`
- **显式回收口（drop_by）而非 Drop**：no_std 无运行时 Drop 消费边，且会话回收需要 pool 双引用（块级 -1）——RAII 面留消费侧包装；池层只给对称的 fork/drop_by 对。
- **定容静态槽（const 泛型 CAP）**：零分配纪律的家形延伸——池容量是消费侧编译期决策（airtd 按内存水位定），运行时帽尽 loud 报（PoolFull）不静默驱逐（驱逐策略归 airtd 与 am 紧缺联动面）。
