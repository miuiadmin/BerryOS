# F0-4：物理连续钉死 DMA VMO、`0x1C vmo_cache_op`、`vnet` 安全缓冲几何与 VirtIO 自动复位

Status: implemented

## Problem

全栈审计检出用户态 VirtIO DMA 链路存在三处直接危害物理内存完整性的根源缺陷：

1. [main.rs](../../../drivers/bins/vnet/src/main.rs) 将 `RX_BUFS = 5`、`RX_BUF_SZ = 1600`（合计 `8000B`）误与偏移量 `RX_BUF_PAGE = 8192` 比较，而实际分配给 RX 缓冲区的空间仅有 `[8192, 12288)` 单页 `4096B`，且此前 `vmo_commit` 逐页弹出非连续 order-0 物理页：一方面 `rx_buf_pa + i * 1600` 在 `i = 2..4` 处跨出首页直接把以太网入站 DMA 写穿到相邻任意物理帧（静默写坏内核或其他进程内存），另一方面 `vmo_read` 从偏移 `11392..16192` 越界踩入 `TX_BUF_PAGE`（`12288`）。
2. 内核与 `berry-sys` 缺少物理连续且钉死的 DMA VMO 分配原语与非一致性 ARMv8 PoC 数据缓存维护原语（`dc cvac` / `dc civac`），驱动无法在真实非一致性总线上安全收发。
3. 用户态 MMIO 驱动异常崩溃退出且未主动执行 `reset_device` 时，VirtIO 传输槽保持 `DRIVER_OK` 且队列仍指向旧物理地址，一旦物理页回收重用即构成异步 DMA Use-After-Free。

## Decision

1. 在 [abi.toml](../../../tools/abi.toml) 新增 `vmo_create` 选项 `VMO_OPT_CONTIGUOUS`（`1 << 1`）与 `VMO_OPT_PINNED`（`1 << 2`），以及系统调用 `0x1C vmo_cache_op(vmo, op, offset, len)`（`VMO_CACHE_OP_CLEAN` 门控 `RIGHT_READ` 执行 `dc cvac` + `dsb sy`；`INVALIDATE` / `CLEAN_INVALIDATE` 门控 `RIGHT_WRITE` 执行 `dc civac` + `dsb sy`，按 [lib.rs](../../../memface/src/lib.rs) `ctr_dmin_line` 步进），经 [gen_abi.py](../../../tools/gen_abi.py) 与 [lib.rs](../../../svcface/src/lib.rs) 五面单源同步。
2. 在 [lib.rs](../../../vmoledger/src/lib.rs) 与 [vmo.rs](../../../kernel/src/vmo.rs) 落地 `PageLedger::new_contiguous` 与 `Vmo::create_contiguous_global`：按 `npages.next_power_of_two()` 一次经 `ALLOC_LOCK` 弹出伙伴阶块并清零预提交，运行期 `decommit` 一律拒 `-ENOTSUP`，无映射销毁时由 `contig_drop_block` 整阶归还伙伴分配器（严禁拆为 order-0 双还）。
3. 在 [mmu.rs](../../../arch/aarch64/src/mmu.rs) 与 `Vmo::Drop` 实装 `reset_virtio_mmio_window`：无残留映射的 MMIO VMO 销毁时自动扫描交集内 `0x200` 对齐槽位，凡 `MagicValue == "virt"`、`DeviceID != 0` 且 `Status != 0` 者立即经高半 Device-nGnRnE 直映写 `Status = 0` 并 `dsb sy`。
4. 修正 [main.rs](../../../drivers/bins/vnet/src/main.rs) `DMA_LEN = 20480`（5 页：`RX_BUF_PAGE = 8192` 独占两整页连续区间 `[8192, 16384)` 容纳 `8000B`，`TX_BUF_PAGE = 16384`）并加编译期 `const assert` 与运行期物理连续校验；将 `vnet`、[vblk](../../../drivers/bins/vblk/src/main.rs) 与 [gui-inputd](../../../drivers/bins/gui-inputd/src/main.rs) 全部切入 `VMO_OPT_CONTIGUOUS | VMO_OPT_PINNED` 及 `berry_vmo_cache_op` PoC 同步。

## Alternatives considered

- 在 `vmo_cache_op(INVALIDATE)` 中使用裸 `dc ivac`：拒绝——若用户传入非缓存行对齐的 `offset` 或 `len`，裸 `dc ivac` 会丢弃首尾半行内相邻 CPU 脏数据；EL1 统一采用 `dc civac` 兼具脏行写回与失效语义，对纯接收缓冲零副作用且对非对齐边界绝对安全。
- 将 `vnet` 拆成每页独立描述符而继续使用非连续匿名页：拒绝——`1600B` 满以太帧无法整除 `4096B` 页宽，第 3 个缓冲必然跨页边界，物理连续阶块既是 VirtIO 单描述符零拷贝的自然要求，也为后续多队列驱动提供通用 DMA 底座。

## Consequences

彻底根除 `vnet` 跨页物理 DMA 越界写坏相邻物理页与踩踏 `TX_BUF_PAGE` 的内存破坏漏洞，补齐 ARMv8 PoC DMA 缓存同步与 MMIO 销毁自动停机防线，第一波（F0-1 至 F0-4）四把硬件与并发止血手术刀全部收口。`gen_abi --selftest`（69/69）、`berry-vmoledger`（22/22）、`berry-memface`（12/12）、`berry-svcface`（7/7）、`ktest` `test_f0_4` 及双核 QEMU SLIRP 真网卡 `NET ok` / `DNS ok` / `TCP ok` 全绿。
