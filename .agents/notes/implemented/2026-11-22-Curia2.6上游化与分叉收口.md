# Curia 2.6.0 上游化与 BerryOS 分叉收口

Status: implemented

## Problem

工程纪律六面刀把 check-docs.mjs（Curia 载荷件）改出三刀本地差异（--selftest/--verify-facts/双戳机检）——不回流则每次上游演进都要手工对拍，AGENTS.md 1:1 终裁之痛会在载荷件上重演；同时该刀踩出的通用坑（检测器好坏夹具对调、根相对判定打穿、快照语义、本地条目无合法落点）对所有 Curia 采用方有价值却锁在单仓里。

## Decision

2026-11-22 分层上游化为 Curia 2.6.0（miuiadmin/curia-md，commit ba162be + tag curia-v2.6.0）：收四件——check-docs `--selftest`（检测器自检律）、模块设计「节级完成态」双戳可选协议（戳在场即受检/存量零回填/机检三条）、钩子样例两档化（对拍档判暂存区快照）、template/AGENTS.md「本地追加」节；不收 --verify-facts（数字自证是采用方面，上游按「倾向砍」记为扩展模式）。每件过 guide/04 元判据（信号一「门禁漏真问题」的实测伤当门票），红线核过零内部专名。BerryOS 侧 check-docs 随即追上游 2.6 逐字版并回植 --verify-facts（d3e537332）——分叉从三刀散装收敛为一件显式登记的扩展。

## Alternatives considered

- 四件全收（含 --verify-facts）：否——facts 制品是项目选择不是规范义务，收进去违反解耦判据。
- 只回流 check-docs 消分叉、规范不动：否——双戳协议与本地追加节是「规范漏了真实形态」的根治位（完成态无约定、本地条目无落点），文档层不立则机检无家可引。
- BerryOS 长期分叉共存：否——对拍税随上游演进单调上涨。

## Consequences

- BerryOS .agents/README.md（规范副本）仍为 2.5 版、AGENTS.md 规则 8 修订未挪本地追加节——采用 2.6 文本面挂 punch-list（G3/G6 联动小刀）。
- 上游维护义务新增：check-docs 双语 README 同批改、每版 release 制品（tarball + sha512）与验收十条——本次全跑在案。
- berry-agent 等其他采用方升级 2.6 时自动获得自检律与双戳；第二个采用方出现前双戳保持「可选」措辞不升格。
