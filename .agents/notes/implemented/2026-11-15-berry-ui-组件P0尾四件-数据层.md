# berry-ui 组件 P0 尾四件：ViewKind 25→29 数据层落地

Status: implemented

## Problem

组件清单（`docs/UI组件清单与实施规划-v1.0.md` §二 P0 公集合）在 `user/berry-ui` 继 Phase 1 七件、P1 九件后收尾最后 4 个 kind 件（Select/Input/Edit/Canvas），P0 主集合 kind 件自此齐账。约束与前两批同款：只动数据结构层、TLV tag add-only、拒面两面同律（流面 + builder 面）。拦路四问：Input/Edit 的文本内容放哪（清单明示依赖输入焦点协议——Phase 2 才接线，数据层载什么）；Select 的空选项集怎么拒（Tabs/Seg 零段是 BadValue 拒面，空下拉是否同律）；Canvas 的绘制内容要不要走子节点（自绘面语义特殊）；四件的容器/叶分界与前两批占位纪律怎么对齐。

## Decision

1. **TLV tag add-only 追加（协议零变更，前两批同法）**：kind 字节域 25..=28 顺延钉四件（`KIND_SELECT..=KIND_CANVAS` pub const）——旧流值域 0..=24 不受扰，25..=28 旧读端本就 `UnknownKind` 拒。props 域逐件定死：Select 12B（option_count·selected·on_change 三 u32 LE）、Input 变长 6..=70（len u8 + placeholder + max_len u32 LE + input_kind u8）、Edit 变长 10..=74（同 Input 前缀 + max_lines u32 LE + readonly u8）、Canvas 4B（paint_ops u32 LE）。
2. **Input/Edit 内容不入 Props（清单「依赖输入焦点协议」的落法）**：数据层只描述外观和约束——placeholder（内联 `TextBuf` ≤ `TEXT_INLINE`，Button label 同款零 alloc Copy 纪律）+ max_len + input_kind（Text/Number/Password，wire u8 0/1/2）+ max_lines（0 = 无限制）+ readonly。实际文本内容走输入焦点协议 Phase 2 接线；Canvas 同构：paint_ops 只记绘制操作计数，实际 op 流走绘制协议——数据层单字段记数供 damage/telemetry 预算面消费。
3. **Select 空选项集不与 Tabs/Seg 零段同律（本批唯一值域新律）**：`option_count == 0` 合法 = 空选择器（空下拉有义，selected 恒 0）；拒面只有 `selected >= option_count`（option_count > 0 时）→ 复用 `AstError::BadValue`（变体零新增，got = selected）。两面同律：parse_props 流面 + builder begin 面（`validate_p0_four`——`validate_phase1`/`validate_p1_nine` 同型第三批）。Input/Edit 的 placeholder 长度帽在 `TextBuf` 构造面（值面即拒 TextTooLong）、input_kind/readonly 枚举域在 wire 编解码面（域外 UnknownProp）——均不入 validate。
4. **四件全叶（Canvas 立法钉：绘制内容不是子节点）**：Select（选项内容是数据不是子节点——option_count 计数面）/Input/Edit（文本内容走协议不走树）入「叶带子拒面」（AST build_node 与 DescBuilder::begin 两面同扩）。§8.2 块×kind 表不扩：四件全拒 SIZE/ALIGN 块，A11Y 块全 kind 合法照旧。
5. **layout/paint 占位不做半实现（前两批同纪律）**：intrinsic 四件一律 (0,0)（Select 选项行高/Input 单行高/Edit max_lines 聚合/Canvas 随绘制协议定——全挂 Phase 2 布局刀）；final_size 一律随父 (avail,avail)；paint 两处穷尽 match（cull_walk/emit_walk_all）扩列入「无视觉容器臂」，子仍走查、组件自身零渲染。
6. **测试钉板 `tests/tlv5.rs`（tlv4 同款双轨，五轨不并常量）**：GOLDEN_V5_STREAM 字面量钉四件齐流样本树现产物（含 A11Y×Select、Col 带子）+ 对称值档 roundtrip（Select 零项/Input Password 空占位/Edit readonly 四行帽/Canvas paint_ops=0）+ BadValue（含零项正例对照）/UnknownProp（input_kind/readonly 域外）/TextTooLong（placeholder 超长）/截断（四件各钉一刀）/新四叶带子/SIZE×新 kind 拒面矩阵（两面同律）+ add() 命令面烟囱。`tests/reconcile.rs` 未知 kind 绊线 25→29 让位新域界（第四次同款挪法）。

## Alternatives considered

- Input/Edit 文本内容入 Props（TextBuf 字段随节点走）：否——清单明示依赖输入焦点协议；内容随 Props 走会在 set_props/编码面引入「内容与约束混流」（改一字重编整节点流），且多行内容撞 `TEXT_INLINE` 64B 内联帽。数据层只载外观与约束，Phase 2 协议接线时内容另有归宿。
- Select option_count == 0 拒面（Tabs/Seg 零段同律）：否——空页签/零段是无内容可用区（结构无义），空下拉是有义初态（待填充的选择器）；数据层拒空会强迫 app 先有选项再建 UI，与声明式先建后填的用法相逆。
- Select 选项逐个子节点化（选项 = 子 Rect/Text）：否——选项是数据不是视图（无独立布局/绘制语义）；计数面 option_count 与 Tabs 内容区子面板不同源——Tabs 的子是用户内容区，Select 的选项是控件自数据。
- Canvas 绘制内容走子节点（每个 op 一子）：否——绘制 op 不是视图节点（无布局/hit/a11y 语义），入树会把绘制协议的流式 op 碎成节点管理面；叶子立法 + paint_ops 计数是数据层与绘制协议的正交分界。
- 顺带收编 lib.rs 命令面（add 容器白名单/set_props kind 门加四对）：否——前两批已钉为已知边界（超数据层授权面），本批照钉；边界合并到 Phase 2 接线刀一并收编。
- Edit readonly 用独立 kind（Edit/EditReadOnly 两件）：否——只读是属性不是种类（同构不同态），wire 单 u8 子域堪载；kind 分裂会让 set_props/调和面翻倍。

## Consequences

- **命令面边界（lib.rs 未动，钉为现行为）**：add() 可建四新 kind 节点（spec.kind 只拒 Root）但作父位全拒 BadParent；set_props 对四件一律 NodeBad（kind_ok 门不含四对）——Select 换选、Input/Edit 内容回填、Canvas op 流挂 Phase 2 收编（届时扩 lib.rs 门 + mask.rs props_diff 四臂——catch-all 已保守返全置，不炸不漏）。
- 事件 ID（Select on_change）纯数据面，hit 层派发未接线；Input 输入焦点、Edit 滚动/光标、Canvas 绘制协议（op 流/damage 联动）同挂 Phase 2。
- 值域执法仍只落两面（流面 + builder 面）：add() 命令面产物可能带越界值，编码可过、对端 apply_desc 拒——loud 在解码侧（前两批同状）。
- wire 域界自此 0..=28，未知 kind 绊线在 29；P0 主集合 kind 件齐账（20 主组件中 kind 件全落），剩余为服务件（Dialog/Menu overlay）与模式件（AppBar/Nav）——后续批继续顺延 add-only，旧流逐字节不变由 GOLDEN_V1..V5 五轨共保。
- 验证：`cargo check -p berry-ui`（默认与 `--features s7` 两口径）绿；`cargo test -p berry-ui --target aarch64-apple-darwin` host 全绿（tlv5 新钉 7 测）；下游 berry-launcher check 绿（仅构造 Props，无穷尽 match 涟漪）。
