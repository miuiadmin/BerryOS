# 双击与长按 referee 语义——输入链 P2 缺陷 4/5 清偿

Status: implemented

## Problem

总审计 input-chain 路两项 P2（新发现，用户问及项含长按）：① 无双击语义——referee 每次 UP 无条件产 Click（user/berry-ui/src/hit.rs:424-429「不拖=Release+Click」无二次点击窗），与覆盖态点击门互作用出闪现：双击图标第二击若应用窗已建表走 on_covered_tap DESTROY 刚开的窗、未建表则第二次 APP_SPAWN 撞 svcmgr 同 id 回收（terminate 旧实例重开）——两条路都是应用闪现；② 长按零识别——referee 纯事件驱动状态机无定时面（PtrGesture 无计时字段），DOWN 后静止保持到 UP 只产 Press+Click，长按 800ms 与长按 50ms 抬起不可区分，引擎 Msg 枚举无 LongPress 语义。

## Decision

主修锚 user/berry-ui/src/hit.rs（总攻批 2；Msg-only ADR #52 形态不动，add-only 扩域不劫持既有 Click 面）：

- PtrGesture 增 `down_ts`（DOWN 事件时戳——长按时序判据起算点）+ `long_press`（本手势已产 LongPress 消费位），DOWN 时随手势重开复位。
- 双击：Gesture 级 `last_click_ts`/`last_click_node` 锚（上一 Click 的 UP 时戳与命中槽）——同节点二次 Click 的 UP 间隔 ≤ 300ms（`DOUBLE_TAP_WINDOW_NS`，Android ViewConfiguration DOUBLE_TAP_TIMEOUT 同值，含界）在该 UP 的 Click 后追加 `Msg::DoubleClick`；首击二击 Click 照产（取舍见 Alternatives）；成对清锚（三连击 = 新窗首击，四击重新成对）；异节点不成对；空白按压/拖拽不断链（v1 简化——DoubleClick 是附加语义，消费端可自行加严）。
- 长按：MOVE 臂 slop 判据先行（越圈 = 拖拽胜出，长按语义整体失效）；slop 内静止超 450ms（`LONG_PRESS_NS`，Android ViewConfiguration 400-500ms 域取中，严格超阈）产 `Msg::LongPress`——静止期有事件流（微抖 MOVE——未出手势即仍在按下点语义域）随流早发（一次手势至多一发），零事件流场景由 UP 收尾兜底（held 超阈即证）；长按已消费的 UP 只产 Release 不再产 Click（Release 照产保按压视觉还原链——press_react 还原臂不断）。
- Msg 枚举扩 DoubleClick/LongPress 两变体（desc.rs 七变体→九变体，紧随 Click 分组）；穷举匹配无通配的消费面同批补 no-op 臂：引擎内 lib.rs press_react/widget_react 两处 + pattern.rs 五处 on_msg + swipe.rs on_msg，引擎外 contacts/messages/appdemo/files 四 app（launcher/browser/photos/camera 有 `_` 通配天然免疫，零改动）。Msg 为引擎内运行时消息不入 wire/TLV 编码——协议面（PtrEvent、INPUT_EVENTS_MAX、AST TLV）零扰动。
- 钉板 user/berry-ui/tests/click_timing.rs 七测：双击窗含界恰达 300ms/300ms+1ns 出窗/异节点不成对/成对清锚三连击；长按阈两侧 450ms 恰达（阈下 Click 链不变）与 450ms+1ns（事件流早发 + UP 兜底两面各钉）/越 slop 拖拽胜出/空白按压全程零 Msg。

## Alternatives considered

- 双击产序二选一（任务书给定）：首 Click+二 Click+DoubleClick（add-only，选定）vs 抑制第二次 Click——抑制形对只消费 Click 的存量组件（Toggle/Check/Step 快速连点=两次真实击活）结构性丢第二次激活，违零回归底线，弃；双击闪现的消费端半刀（launcher 对 DoubleClick 的幂等/忽略——审计 fix 文的另一半选项）挂消费端后续刀。
- 双击窗锚定拍：UP→UP（Click 产拍，选定）vs Android 的上一 UP→本 DOWN——事件已带 UP 时戳零新增状态面，且与「二次 Click」语义同拍；代价是慢击（按住 400ms 再抬）也计入窗——长按面已在同 UP 抑 Click，慢击不产 Click 自然不入窗，两语义无交叠。
- 长按定时面：帧拍驱动（pump_input_at 每拍探活跃槽超时）语义最优——真零事件流也能保持期触发；但需在 lib.rs pump 环加 referee 定时钩子（超出本刀名下文件界的结构改动），且 v1 零消费端（桌面图标长按菜单挂账中）早发收益无处兑现，弃；事件时戳驱动 + UP 兜底零新钩子即达「长按与单击可区分 + 长按不吃 Click」验收面，帧拍形挂 v2（配消费面一并）。
- 新变体带坐标/时戳载荷：Msg 族风格语义最简（Click 无坐标面前例），双击/长按消费端（图标菜单类）只需节点身份，弃载荷。

## Consequences

- 桌面快速双击图标：两次 Click 照发（行为不变）+ DoubleClick 附加可消费——闪现根修的消费端半刀（launcher on_click 对同格幂等或改吃 DoubleClick）挂账，与审计缺陷 6（重开=聚焦语义）同面。
- 长按 450ms+ 抬起不再产 Click（Button/Toggle 等长按不误触发 on_tap/on_change——widget_react 对 LongPress no-op）；长按中 UI 反馈（菜单类）v1 仅设备流有静止期事件时早发，纯零流设备退化为抬起时发。
- Msg 扩域全工作区九个消费面已同步（host 门 `cargo test -p berry-ui --target aarch64-apple-darwin` 364 测全绿 = 既有 357 零回归 + 新 7；contacts/messages/appdemo/files/launcher/browser/photos/camera musl `cargo check` 全绿）；无通配的显式列臂风格使后续 Msg 扩域仍被编译器强制清点全部消费面——此为有意设计（add-only 不免清点）。入库序补记（2026-11-22）：lib.rs/desc.rs 随批 2 入库；pattern.rs 五处臂随[总攻批3 生命周期终态](./2026-11-22-总攻批3生命周期终态.md)清偿入库（批 2 提交漏装）；swipe.rs 臂与 click_timing.rs 七测为工作树在途件，随代码侧收尾入库。
- 遗留挂账：桌面图标长按动作（菜单/重排）消费面未建（审计 fix 文「配套桌面图标长按动作后续挂账」维持）；双击窗锚不随空白按压/拖拽断链的加严面留消费端裁量。
