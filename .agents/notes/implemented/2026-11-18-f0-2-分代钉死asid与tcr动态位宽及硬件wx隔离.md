# F0-2：分代位图钉死 ASID、`TCR_EL1.AS` 动态激活、四态 W^X 与 `TTBR1` 直映 `PXN`

Status: implemented

## Problem

全栈审计检出地址空间标识、用户缓冲权限与页表硬件执行隔离五处结构性缺陷：

1. [asid.rs](../../../mm/src/asid.rs) 仅用裸递增计数器分配 ASID，回卷时盲目把仍存活常驻服务（如 `svcmgr` 的 `ASID=1`）或正驻留对核 `TTBR0_EL1` 的活跃号重发给新子进程，导致两存活地址空间共享同一硬件 ASID、TLB 互相串表。
2. [mmu.rs](../../../arch/aarch64/src/mmu.rs) 在 16 位 ASID 硬件上未置 `TCR_EL1.AS`（bit 36），使硬件实际只消费 8 位 ASID；而在 8 位 ASID 硬件（如 Apple Silicon HVF）上又把 ASID 错移 `<< 56` 写入 `TTBR0_EL1[63:56]` RES0 域（架构 8 位与 16 位起始位均为 bit 48），且写 `CONTEXTIDR_EL1` 后缺 `isb`。
3. [lib.rs](../../../aokface/src/lib.rs) `leaf_admits` 将 ARMv8 Stage-1 `AP[2:1]` 编码反读——既放行了 EL0 对 `AP=00/10` 纯内核页的混淆代理人读写，又误拒了 `AP=11`（`UserRo`/`UserRx`）只读页的合法 `copy_from_user`。
4. 用户页表与 `TTBR1` 内核高半表完全未置 `PXN`/`UXN`：内核 `.text` 与 `.rodata` 可写，全部 `.data`/`.bss`/栈/直映物理帧与用户页均可被 EL1 直接取指执行，且 `sys_vmar_map` / `sys_vmar_protect` 不支持 `UserRo` / `UserRx` 亦未拦截 `WRITE | EXECUTE`。

## Decision

1. 新建纯逻辑 crate `asidface/src/lib.rs`（`berry-asidface`），以 1024 字位图（`bit 0` 永久保留）+ 单调游标 + 回卷代号 + 在跑核活跃 ASID 钉死掩码实现 `AsidState`，满载诚实返 `None`（`sys_process_create` 折 `-ENOMEM`），根 `Vmar::Drop` 失效该号 TLB 后归还位图；同时收敛 `ASID_SHIFT = 48` 与 `tcr_as_config` 动态解码。
2. 在 [mmu.rs](../../../arch/aarch64/src/mmu.rs) 物理分离 `BOOT_L1` 与 `KERNEL_L1`：`enable_mmu` 按 `ID_AA64MMFR0_EL1.ASIDBits` 动态置 `TCR_EL1.AS`，`activate_ttbr0_regs` 跟踪每核活跃 ASID 并在写 `CONTEXTIDR_EL1` 后补齐 `isb`；`KERNEL_L1` 在开 MMU 前就地构建前 8MiB 4KiB 细粒度表（`.text` 为 `AP_RO | UXN`、`.rodata` 为 `AP_RO | PXN | UXN`、其余与全部后续 RAM 直映块及 MMIO 块全置 `PXN | UXN`），零 Break-Before-Make 风险。
3. 修正 [lib.rs](../../../aokface/src/lib.rs) `leaf_admits` 对齐 ARM DDI 0487 Table D8-42：仅准入 `AP[1]==1` 的 EL0 页，写操作额外要求 `AP[2]==0`。
4. 在 [vmar.rs](../../../kernel/src/vmar.rs) 与 [syscall.rs](../../../kernel/src/syscall.rs) 落地 `Perm::{Rw, Ro, UserRo, UserRw, UserRx, UserRwxCompat}`（全用户态页恒置 `PXN=1` 开启硬件 SMEP），`sys_vmar_map` / `sys_vmar_protect` 原生支持 `READ`（`UserRo`）、`READ|EXECUTE`（`UserRx` 含 PoU 同步）并严拒 `WRITE|EXECUTE`（`-EINVAL`）。

## Alternatives considered

- 在 F5-2 标准 PIE ELF 段级装载落地前强行将平铺单 VMO 镜像也标为只读 `UserRx`：拒绝——存量 `elf2flat` 平铺镜像把 `.text` 与 `.data`/`.bss` 压入同一 VMO，在 F5-2 拆段前盲目置只读会导致 `svcmgr` 首写全局变量即故障；保留 `UserRwxCompat`（仍强制 `PXN=1`）作平铺兼容态，同时对栈页、数据页、MMIO 页与显式 `UserRo`/`UserRx` 立即启用严格硬件 NX/RO，F5-2 退役 `elf2flat` 时顺势删除兼容态。
- 在高半运行期原地将 `KERNEL_L2_RAM` 2MiB 块描述符改写为 L3 表描述符：拒绝——运行中原地裂解活跃代码所在块违背 ARMv8 Break-Before-Make 规范；改为在 `build_boot_pt` 关 MMU 阶段直接构建独立 `KERNEL_L1/L2/L3` 最干净安全。

## Consequences

彻底根除 ASID 回绕撞号、8 位移位错位、16 位 `TCR.AS` 漏置与 `aokface` 混淆代理人漏洞；内核 `.text` 不可写、`.rodata` 不可写不可执行、全直映 RAM 与用户页对 EL1 不可执行（`PXN/SMEP`）。开启硬件只读与根 `Vmar` 归还位图后，在 `-smp 2` 双核实测中当场捕获并清偿两处潜伏内核缺陷：一是 [smp.rs](../../../arch/aarch64/src/smp.rs) `SMP_SEC_STACK` 原误声明为不可变 `static` 被链入 `.rodata` 且在 Rust 函数体内改 `sp`，已迁入 `.bss` 并在 `.Lsmp_final` 入口前切栈（顺带缩减 ROM 镜像 16KiB）；二是 [user.rs](../../../kernel/src/user.rs) `UserProcess::build` 原在栈上映射局部 `Vmo` 后按值搬移并任由 `rust_main` 局部块析构根 `Vmar`，已改为固定堆槽持有并在 `UserProcess::Drop` 守住常驻根 `Vmar`。`berry-asidface` 千轮回绕压测、`berry-aokface` 17 项矩阵单测、双核 `ASIDR` 回卷及内核 `ktest` 硬件异常探针全绿。
