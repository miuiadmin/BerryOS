# Agent Note: 四刀双记账合并与净增量重放——patch-id 消解判据成文与重放完整性挂账

Status: implemented

## Problem

2026-11-16 跨根收口窗口，客机 TCP 四刀六笔在两侧平行记账：owner 本地 wip/sched-1.1 一侧六笔（四刀①-⑥），origin 侧另有四笔同补丁复本——四刀①至④各存在两枚同题同刻不同哈希的提交，`git patch-id --stable` 逐对相同（① `a9e641784`/`d56933817` = `55e22806…`；② `6f812ac5b`/`970583d97` = `93790c5b…`；③ `14e1ef855`/`8d00c54a0` = `a5cdf1e0…`；④ `a1eddf293`/`7982b2e27` = `a03ae942…`）；四刀⑤文档链两枚（`04352812d`/`39d23a3ac`）patch-id 不同——docs/阶段沿革.md 两侧节文分叉是分叉点；四刀⑥（`87880c9c8`，justfile）单笔；跨根防线笔同样双记账（`d792c53f3`/`8acdc756c`，patch-id 同为 `ad88cea2…`）。消解与重放经 `51f6d8fdc`/`4b82e3a7f` 两笔合并把双份谱系都收进历史（任一双枚皆是现 HEAD 祖先），①-④因 patch-id 相同在合并内容面自然消解，⑤⑥与防线三笔按净增量重放收口（`499d5bcf9`「absorb tcp4」其后续流）。事件判据与三笔重放清单此前全仓零文档承载（唯一痕迹为沿革一句「初稿曾被 7531d6430 裹入其提交」）——本篇补档。

## Decision

判据成文：双记账消解以 `git patch-id --stable` 对拍为准——patch-id 相同的双侧提交合并时内容零冲突自然消解，无需逐字人工对拍；patch-id 不同者（本例⑤）必须净增量重放 + 对拍 tip 后再合（AGENTS.md 规则 10「真源重建 + 增量补丁 + 两向审计」的操作判据）。重放完整性（重放提交与原提交内容逐字一致、重放过程无静默丢改动）分两层口径：代码路 sweep 对拍已绿（survey 同批登记——四刀六文件「本地预合并=HEAD=origin tip」四向一致，「重放不丢改动」成立），独立二次核销（重放件逐字审计）则截至本篇仍未做过——沿革三组逐字重复行（「06 号评估终局兑现」/「v3 四动作测试」/「审计完成判定」，docs F97 面）与 4fb56494c 修复的 v1.8/v1.9 并存（重放链丢 git mv 删除侧）互证：该事件族的重放/合并确实存在静默损改史，独立核销与沿革撞号清理同归撞号收口刀，不以本篇「已消解」结论预支。

## Alternatives considered

- 逐字 diff 对拍六笔重放件：成本高且大部分已被四轮 sweep 对拍覆盖——patch-id 相同者理论零差异，只对 patch-id 不同者（⑤）做重放对拍即可锁定风险面。
- 不补档、只留沿革一句：判据不可考——后续跨线合并遇同形分叉时无判例可循，正是「一事实一归属」要堵的洞。

## Consequences

跨线平行记账的分叉消解从此有单一判据（patch-id 对拍）与判例链可引；「patch-id 同 = 安全消解」仅对内容面成立，历史面双枚提交仍在（git log 会看到同题双笔，属预期非事故）。重放完整性挂账显式化：撞号收口刀清偿沿革前，任何引用「沿革二百八十三/二百八十五」等撞号节的指称都需按 survey F96/F98 的歧义化警告理解。后续同形事件（并行 lane 双侧落同一刀）先跑 patch-id 对拍再选合并或重放。
