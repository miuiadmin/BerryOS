# tools 自检 CI 执行面（selftest_guard --run）

Status: implemented

## 现象

判例族「有 selftest 零自动执法」（7 连发：echod/evsclient、genwycheproof、gensourceindex、fastlane_sim、gui8-smoke、bcts-run.sh、shvarcheck）在 CI 侧有同款缺口：`tools/**` 正是 CI-light 轻道的触发路径（paths: docs/**, .agents/**, '**.md', tools/**, deny.toml），但轻道六门（docs-guard/check-docs/writable-globals/原语 grep/unsafe 台账/shvarcheck）不含任何自检真跑——只动 tools/*.py 的 PR 全绿合入，而受影响工具的自检从未在 CI 执行过。`selftest_guard.py` 执法扫描只保证「justfile 有接线行」，不保证「行被执行」：`just test-host` 全量只在本地/worker 侧跑，CI 侧无消费。

## 为什么缺口长期不可见

轻道立项（2026-11-10 路径分流）时自检接线还在补漏期，六门先落地；后续每刀自检接线（dns-stub/parkprobe/hostfwdprobe/sync-public/selftest_guard 自身）都只动 justfile + 07 口径行，PR 触发的是轻道，轻道不跑 justfile——「接线行增加、CI 面不变」的自证盲区。worker 侧 test-host 全绿给了「已验证」的错觉，但 owner 直推（不走 PR）与合入后 base 均无自检执法。

## 修法（W1-Q20，PR 单一增量）

`selftest_guard.py` 加 `--run` 执行面：接线行从 justfile 单源提取（`WIRE_LINE_RE`，注释剔除同执法面）逐行真跑，`{{BASH}}` 占位按 just 同序探测展开（homebrew → local → /bin/bash），首红即停、逐行记账。注册表仍是 justfile——一事实一归属，本工具不持第二份清单；新增自检接线后 `--run` 自动带上，与执法扫描门互锁（有自检必有接线行 → 接线行必被执行）。

挂载点 = ci-light.yml 轻道第七门（`python3 tools/selftest_guard.py --run`）。实测 44 行全绿 17.7s（自建 runner 同量级），轻道 10min 帽内宽裕。

## 判定锚

- `--run` 输出 `PASS（N 行接线自检全绿）`——N 活树实测 44（含 selftest_guard 自身接线行，元自证）。
- 红分支：合成 justfile 首红即停 + 罪犯行指认（selftest S8 钉板）。
- `{{BASH}}` 展开错 = .sh 件静默走 shebang 兜底而非显式 bash 调起——S9 钉板展开前缀形。

## 边界与不做

- 不进重道 ci.yml：重道 smoke 面 tools 改动被 bcts/QEMU 长跑覆盖度低（自检秒级vs全链分钟级），轻道已是对称触发面。
- 不改 justfile：test-host 已含全部门（自检 + cargo test）；CI 侧只补「tools 路径触发时自检真跑」这一缺口，避免与并行 lane 的 justfile 冲突面（轨道分派纪律）。
- host cargo test 面（2030 测）仍不进轻道——Rust 构建非零依赖面，轻道保持纯 python3/node 门禁形态；那是另一个缺口的另一个裁决。
