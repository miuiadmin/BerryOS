# VNC 收官收口刀（F44 凭据门/F45 沿革二次收口/F49·F58 重打包/F59 落账清单）

Status: implemented

## Problem

十二波收官报告三件优先事项经用户明示「处理」授权全落，加一件文档沿革事务共四面：①F44——`web.rs` /api/power 对无口令 run 整体跳过 X-Berry-Pass 门（`ctl.pass=None` 分支），而 Host 防线仅防 DNS rebinding 且放行 IP 字面量，无自定义头的 POST 属 CORS simple request 免预检，任意网站可对无口令环回 run drive-by POST reboot/off（Firefox/Safari 可达）；②F45——wave8 治理（d0105a060）后 12 分钟起并行线连续撞 mover 段，census 实得 arabic 七组（259~265）+ 轮族一百零九轮一组双占；③F49/F58——Desktop.app 与 AppImage 未随 wave10 TPN 单源加行（qrcodegen）重打包，且三包内 berry 二进制全部过期于现刻源码；④F59——`2026-11-14-vnc提交拆分清单.md` 已按自设失效条件过期仍标 Status: current。

## Decision

- F44 采 owner 实测定案的 token-in-fragment 方案，服务端三行 + 前端两小面：`vnc_web` 在 ctl 构建前 `password.is_none().then(vnc_cfg::generate_password)` 铸随机 token（复用 /dev/urandom 熵源，零新依赖），`ctl.pass = password.clone().or(api_token.clone())` 恒 Some——web.rs 校验面零改动，现有 ct_eq 403 门自动对无口令 run 生效；四个 build_page_url 增 `apikey: Option<&str>` 形参，仅无口令时附 `#apikey=`（与 `#password=` 同信任通道：URL 打印面交付 + fragment 读后即抹，二者互斥、有口令时口令优先）；berry.js fragment 块同构读 `apikey` 并镜像 sessionStorage（刷新不丢电力键），powerAction 头改 `password || apiKey || ''`。
- F44 的 --open 皱褶按「禁用态无条件实现」收：QR 与 --open 都 strip_fragment，无凭据到达页面的电力键只能 403——`updatePowerKeys()` 在无 password 且无 apiKey 时禁用重启/关机两键（title 说明缺段），在凭据缓存变化点（凭据对话框提交、VNC 认证失败置空）重算；403 文案区分「口令被拒」与「本页无凭据（--open 剥除段）」。有口令 run 行为零变化（口令即 token，改动面全在 None 分支）。
- F45 二次收口按 wave8 算法脚本化：七组 arabic 后发者（全部为调度线、全部晚于 wave8 治理落笔，git log -S 逐标题核时序）按文件序顺延至三百三十二~三百三十八；轮族后发者 :6182 顺延至一百一十七轮（110~116 已全占）；mover 标题不加「原撞 N」尾注——本刀纪律明文只改节号文字。三重自验全过：复 census arabic 266 节/266 唯一号、轮族 32 节 0 撞；改前改后 489 行对拍仅 8 标题行差异且节号 token 外逐字相同；git diff 8 增/8 删全为标题行。治理笔记追加「二次收口」节承载权威记录。
- F49/F58 全链重建（重打包必须先重建二进制——只换 TPN 不换码是假重打包）：`just berry-build`（host，含 F44）→ `build-linux-binary.sh`（musl 静态 ELF）→ `build-appdir.sh`（BERRY_BIN=musl 出 AppDir-linux，check-appdir 40 ok/0 warn/0 fail）→ `build-appimage-docker.sh`（orb start 唤醒容器链）→ `macos/build.sh`（BERRY_IMAGE=portrait + BERRY_BUNDLE_ID=desktop 出 BerryOS-Desktop.app，codesign 过）→ host 检查档 AppDir 重建（39 ok/1 warn/0 fail，warn=host Mach-O 预期形态）。三包内档 TPN 实测均 4cf7879f… 与单源同一——AppImage 宿主无 unsquashfs，以容器 unsquashfs -o 196992（hsqs 魔数定位）直检；Desktop.app 镜像哈希与 portrait.img 一致、web 资产含 F44 berry.js（与仓库逐字节同）。docs/Berry平台-剩余缺口.md 基线两句与 tools/berry/README.md 打包链句同批回刷。
- F59 按 Curia 出后继篇：新建 `research/2026-11-15-vnc落账清单.md`（Type: reference）承载最终 commit 计划（每笔意图集+混合文件处置），旧拆分清单翻 superseded 并 Superseded-by 指向后继，治理笔记 Related 链同批改指。

## Alternatives considered

- F44 等价备选「无口令 run 不建 ctl（404）+前端禁用电力键」：更简（服务端零新概念）但环回无口令电力键功能全灭，与 owner 实测方向（token-in-fragment）相悖，仅留档；其前端禁用态组件被本刀无条件吸收（--open/QR 到达页同样无凭据，该态在主方案下也必需）。
- F44 token 其他通道：query 参数会进服务器日志与浏览器历史；cookie 需引入 cookie 管道且引 CSRF 同族问题；页面构建时注入 custom header 无通道可达。fragment 与 `#password=` 同信任级、读后即抹，且 QR/--open 的 strip_fragment 纪律天然外溢覆盖 token，选它零新增面。
- F45 采修复分支 d27046dad 的映射：merge-base 实证非 HEAD 祖先，且只覆盖六组旧撞（250/253/254/259/260/261）不含 262~265 最新四组，照 cherry-pick 无意义——以执行刻复 census 现算为准。
- F45 mover 加尾注（d27046dad 先例「原撞二百五十九·物理序在后让号」式）：与本刀纪律「重排只改标题行节号文字」冲突，弃；空隙号 339 与跳号（340/341 已被并行线占用）按 wave8 既定代价（号段与日期脱钩）同等对待。
- F49/F58 只刷 TPN 不重建二进制：三包内 berry 全部过期（Desktop 11-14 12:51/AppDir-linux 11-15 03:17/AppImage 11-14 12:50 vs 源码当日 12:58+），假重打包不可取，全链重建。

## Consequences

- 正面：/api/power 门对全部 run 形态生效（无口令环回 run 的 drive-by POST 现必 403，e2e 三态实测）；沿革 arabic+轮族双零撞，号→节 grep 恢复确定；三包 TPN 与二进制均与时点源码一致；提交面纯度经 git diff --cached --stat 逐笔核对。
- 代价：无口令 run 的页面 URL 现恒带 `#apikey=` 段（打印面同 #password= 信任级）；QR/--open 到达页面电力键禁用（有口令 run 的 QR/--open 行为不变，仍可经凭据对话框输入）；沿革空隙号 339 与号段跳号延续 wave8 脱钩代价。
- 后续：并行线再撞 mover 段时复用 /tmp/census_f2.py 思路重 census 现算（脚本在本刀已第三次验证）；门禁提案（续族 11 组）仍待裁。
