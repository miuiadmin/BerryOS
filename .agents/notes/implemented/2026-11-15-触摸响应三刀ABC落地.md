# Agent Note: 触摸响应三刀 A′/B′/C′ 落地——首触 damage 收敛、spawn 后置、重采样目标新鲜化

Status: implemented

## Problem

docs/触摸响应设计-v1.0.md §4 定谳的三个呈现路径病灶全在消费侧时序：其一，launcher/settings 帧循环旧序 = `push_pointer → wake() → pump_input`，wake 时输入还在缓冲、damage 必空 → 条件化 FULL 兜底触发，随后 pump 里 press_react 标出的精确按压矩形（~36KB 级）被 FULL 整屏语义吞掉（800×600 整屏 blit ≈1.92MB，段 4 预算被放大数十倍）；其二，`Msg::Click` 分发在渲染之前同迭代执行 APP_SPAWN 阻塞 RPC（send→等回执严格串行），按压反馈帧（PRESSED_BG）要等几十 ms 级回执后才渲染提交；其三，`pump_input(last_expected)` 用上一帧 expected 轨做重采样目标——稳态陈旧一个 period，idle 长睡（10s 帽）醒来后是远古值：跨度帽 >20ms 直接拒采、外推帽失义，拖跟预测整体静默失效。

## Decision

1. **A′+C′ 合并为引擎新面 `pump_input_at(now_ns)`**（berry-ui lib.rs）：内部先 `expected = next_vsync_tick(now, period, phase)`（与 render_frame 内部自算 expected 同式同源，C′ 目标新鲜）再 `pump_input(expected)`（target_from_expected 单源推导不双轨），**有输入事件才自动 `wake(now)`**（A′ 内建 pump→wake 时序：press_react/widget_react 先标精确 damage，wake 的条件化 FULL 只命中空集；零事件泵不 wake——Idle 稳态睡事件的非燃 CPU 契约不破）。launcher/settings 两消费方删掉 recv 段的 `ui.wake(now())` 并全部换用本面——生产面从此不存在「wake 排在 pump 前」的自由度。`wake()` 契约注记同步补「输入驱动 wake 不放大 damage」条款（规则 15 铁律 3 的引擎侧收尾）。
2. **B′：spawn 后置记账**（launcher frameloop.rs）：Click 分发处只查表记账 `PendingSpawn::{Slot,Recents}`（Slot = app 格点击——真 smoke 门 + spawn_ok 记账 + 成功后记多任务键记忆；Recents = 多任务键重拉——静默 + 失败诊断），本迭代照常 render+SUBMIT+FRAME_CALLBACK+RELEASE+vote，**呈现完成后（vote 后、wait_many 前）才执行阻塞 spawn RPC**。同批多击取最新覆盖（设计许可——旧语义本就幂等重拉）。回执记账 / `CLICK ok n=1` 恰一次门 / 失败 eprintln 诊断面与分发处直调逐字一致（只挪时序不改语义）。
3. **`pump_input(expected)` 旧签名保留为 host 测试确定性裸缝**（注记「生产面禁用」）：设计 §5.3 曾提退役旧签名，但 berry-ui tests/ 30+ 处直调显式 target 做值级断言（合成场景手工钉 target 的逻辑真线），且任务约束「现有测试全过」——收口生产消费面（全系统仅 launcher/settings 两处）已达成「消费方不可能搞错顺序」的目标，无需拆测试面。
4. **三处非输入 wake 语义保持**：boot 起振 wake（首帧 FULL 是设计意图）、时钟摆字 wake（set_text 已先标 damage，顺序本就正确）、inject_swipe 显式 wake（合成事件在本迭代泵之后入缓冲，若无 wake 则稳态 wait 睡 10s 帽饿死队列事件——首验定谳注释在案；且 swipe 全视口平移，FULL 语义本就尺寸相符，非 A′ 病灶面）。

## Alternatives considered

- **消费方手工搬序一行**（wake 移到 pump 调用之后——设计 §5.1 原案）：否——launcher/settings 两消费方各持顺序自由度，后续新 embedder 仍可能搞错；pump_input_at 收口后该错误从结构上不可达。
- **`pump_input` 本体内部自动 wake**（任务给出的「更好方案」字面形）：否——20+ 测试文件直调 pump_input 做确定性断言（press.rs「未映射 trigger 的 Press 零 damage」等），内建 wake 会在事件泵路径无条件置 FULL/Run 污染全部既有测试语义；把自动 wake 放进 pump_input_at（生产唯一入口）两全。
- **spawn 转独立线程**（否——launcher 单线程帧循环是现状架构契约 S1 判词，设计 §5.2 已否决，RPC 阻塞点后置已够）。
- **C′ 走 launcher 侧 `pump_input(next_vsync_tick(t_now, VSYNC_NS, 0))`**（设计 §5.3 备选）：否——推导逻辑落消费方 = 每个新 embedder 要复制一遍拍点推导；进引擎单源后 target_from_expected 与 next_vsync_tick 都只有一处消费。

## Consequences

- 首触帧 damage 收敛：A′ 正例（pump_input_at → wake 保矩形）出 `damage_full=false ∧ count=1` 精确按压矩形；负例对照（旧序 wake→pump）仍 FULL——两形均钉板在 berry-ui tests/touchresp.rs。
- C′ 值级钉板：事件窗 [t0+2ms, t0+6ms] + now 恰在拍沿（含沿不欠拍 → expected = 本拍）布出 target = now−5ms 恰落窗内，末 MOVE 括点插值 x=30 唯一钉死推导；陈旧目标对照（pump_input(t0−40ms)）拒采直通原始坐标（resampled=false）。
- 验证：berry-ui host 全测绿（既有全过 + touchresp 3 测新增）；berry-launcher/settings musl `cargo check` 零警告；smoke 标记族零漂移（LAUNCH ok / PAGE ok n=2 / CLICK ok n=1 / click ready 判据链未动——CLICK 行现于按压帧呈现之后打出，恰为 B′ 验收序「按压帧呈现打点先于 spawn 回执行」）。
- 遗留（非本刀）：T′-4 验收刀（触摸→呈现打点收口 + §3 预算表回填实测值）未做；设计 §5.3 的 pump_input 旧签名退役改以注记收口（见 Decision 3）。
