Status: implemented

为什么：六波方案步骤 3（[2026-11-15-体验大改造六波实施方案.md](../../plans/2026-11-15-体验大改造六波实施方案.md)）裁定 berry-ui 控件底座分五批接线；本文记批 A 的裁决与坑，供后续批与波3/波4 消费。

## 裁决

- **Tabs 双角结构**：Tabs 是「有自身视觉的容器」——页签条（48px 底 + active 段指示条 + 段间分隔线）自 paint 发射，内容区子经 place_children 专属臂全幅叠放（y 下移 48）；active 面板由 app 摆子序控制（后插者盖上），引擎不做面板切换。
- **Scroll 随父 + offset 摆位**：Scroll = 视口容器随父填充（Root 直子 = viewport），内在 (子宽, content_height) 供聚合；offset_y 经 place_children 臂子上移（rel_y = -offset）。**offset_y 必须入 props_geom_equal 几何面**——纯绘误判会让子钉在旧 offset（测试抓出）。
- **Badge 三档**：count=0 且无 dot = 0×0 隐藏；dot = 16×16；数字胶囊宽 = 位档×8+8（1/2/3 位，>99 显 99+）；字形经 emit_widget_text 共核居中。
- **press 视觉单源在 paint**：组件件（Button/Check/Radio/Tabs/Seg/Step）的 press 暗化不走 props 换底（props 无 bg 字段、TLV add-only 不能加）——press_map 扩容登记 + `pressed_snapshot()` 抽 active visual 槽值传入 paint::paint（内部签名 add-only），Button Filled 发射时查表换 ACCENT_PRESSED。press_react 的组件臂只置 active + damage，不碰 props。
- **press_map 帽 16→28**：launcher 建树尾全量登记需求（图标格 + Dock + 导航键）；tests/press.rs 帽断言随迁。
- **theme.rs = 语义色单源**：OH 官方表 light/dark 两套预混；paint.rs 旧「组件 v1 固定色板」是过渡豁免，全量收编挂后续刀。
- **pattern.rs = 模式件值面**：TopBar 56vp/BottomTabs 48vp/ListItem 48vp 五态/NavStack 页栈（纯数据，子树操作归消费面）——不新建 ViewKind，零 paint 改动。
- **guiproto add-only 焦点协议**：OP_WM_FOCUS=0x66 / OP_WM_BACK=0x67 / OP_INPUT_INJECT=0x22 / WM_LAYER_SERVICE=2 / DEV_POINTER·KEYBOARD·TEXT 三值域；只增常量与编解码，零既有字节面改动；服务端执法（wmd/guifbd）挂波3。

## 坑

- 并行会话同文件互踩：批 A 实施中被另一会话吸收重做（SBAR_LONG 100→200 等改进），测试期望须按最终常量对拍而非实施初值。
- oct3 圆点三片形状断言用中片 `(0, h/4, d, d/2)`，非整底。
- List/Scroll 是随父容器（Root 直子 = viewport），内在只在聚合语境（Col/Row 内）生效——测试期望别按内在写。
