# P0 两项落地：导航键透明化 + guifbd 裁带对齐

Status: implemented

## Problem

owner 两项核心反馈：① 导航键有黑色不透明底块——要白色符号直接浮在壁纸上；② 应用打开后底部有 55px 空隙（guifbd 裁带 190px vs 导航条实际 135px）且导航栏不跟随应用颜色。

## Decision

- **导航键透明化（P0-①）**：根因不在光栅化管线（1-bit 透明键已工作——状态栏图标即先例），在资产建树侧的两层不透明底块。改动：`icons.rs` NAV_BASE_BG → `0x0000_0000`（argb_blit A==0 跳过）；`desktop.rs` 撤按压面 Rect 底块（`nav_icon` 返回值从 (NodeId, NodeId) 简化为 NodeId）。armed 态暗红保留（警示需要醒目）。测试钉板同步（底块断言改 A==0 + 常量钉板防回退）。
- **guifbd 裁带对齐（P0-②）**：`guest.rs` band (132,190) → (117,135)——与 launcher 实际值（状态栏 39vp×3=117px、导航条 NAV_BAR_H_BIG=135px）对齐。同批修 `main.rs` SYSTEM 窗高 39→117（vp 值误入像素域）。注释互指真源（scene.rs:34 OH_STATUS_H / desktop.rs:151 NAV_BAR_H_BIG）。55px 底缝 + 15px 顶缝同批消失。

## Alternatives considered

- **8-bit alpha blend 原语**：否——白符号浮壁纸不需要 blend，1-bit 键语义充分（裁决 0aeb01814）；blend 只在 scrim/毛玻璃/抗锯齿边缘时必要
- **底色换壁纸色近似**：否——只是颜色近似不透明，本质还是覆写壁纸；真透明（A=0 跳过）一步到位
- **波3 带合成 v1**：正确但不阻塞 P0——band 对齐先消空隙，带合成（系统栏常驻+应用色透出）是 P1
- **建 set-bar-color 协议面**：否——Android 15 已废此 API（「Draw proper background behind insets instead」），BerryOS 直接落时代 C 终点形态

## Consequences

- 导航键 = 白色符号直浮壁纸，无任何底色块（像素验收：底色区 (272,1830)=(0,101,195) 壁纸蓝系混合渐变，全画面 0x032428 深蓝灰像素 = 0）
- 应用底部 55px 空隙消失（band 对齐后应用内容延伸至 y≈1788，导航条从 y≈1789 起——紧贴无断裂）
- 顶部 15px 缝同消
- 按压反馈暂无（Rect 撤除后无替代）——后续迭代可用 glyph 亮度变化（`set_power_face` 换面先例）
- `nav_icon` 返回值简化、`NavNodes.faces` 字段撤除—— berry-launcher 内部接口变化，`press_map` 同步瘦身（25→20 对）
