# 任务 DAG 依赖图系统落地（todo-DAG 吸收——owner 裁决「学就学一步到位」）

Status: implemented

## Problem

owner 裁决跟上 impossible-os 的 todo-DAG 依赖图（此前排除案翻案——理由：项目将越来越大，一步到位学最好的）。DAG 解决「机器自动判断什么任务现在能做」：不靠人排序，靠依赖图算可建造集。

## Decision

2026-11-22 三阶段 workflow 建造（Study 精读原型 864+831 行 → 三车道并行 Build → 逐车道对抗验收全 pass）：①tools/task-graph.py（图构建器——表解析/环检 Tarjan SCC/悬空检/自依赖检/next 可建造集/DOT 可视化/JSON 缓存，17 腿自检）；②tools/task-oracle.py（三态分类 DONE/NEEDS_WORK/BLOCKED——双戳判 DONE、Deferred awaiting 令牌判 BLOCKED 且答案落盘自动重开、其余 NEEDS_WORK，与 check-docs VERIFIED_RE 同源不造第二份正则）；③消费面改造（pack-work 开工包带 DAG 可建造集且 hint 优先 DAG 活——live 实跑已指「ai-runtime §1」；e-guard fixpoint 第二门升级为双轨判空 punch-list AND DAG 都清才准停）。设计核心：不建 impossible-os 式 todo/ 平行语料（违反 Curia 一事实一归属），任务表在 plan 文档内 opt-in、状态框由 sync 机器写、Curia 头块/双戳/punch-list 全兼容。

## Alternatives considered

- 全套 todo/ 目录树：否——235 文件平行语料在 BerryOS 是双写面；我们用 Curia plans/ 文档内表格。
- 只做 punch-list 不做 DAG：否（owner 裁决翻案）——punch-list 是短队列（20 分钟粒度），DAG 是长路线（模块建造序），两轨并存互补。

## Consequences

真仓实跑：图面空（无表=诚实空集非拒判）、oracle 正常（216 节 41 文档全 NEEDS_WORK——正确，还没盖戳）、pack-work hint 已指 DAG 首项。后续：给 plans/ 文档逐步加实施顺序表（design.md 加表→punch-list 条目加 ID+依赖注记），DAG 面自然丰化。验收员三条 P3 观察在案（否决旗也重开/子号节接缝/措辞差）。
