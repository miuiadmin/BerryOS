# F1-2：进程退出两阶段自动拆页表、L3/L2/L1 页表帧全回收、废除 `leak = true` 与创建侧内联助推排水

Status: implemented

## Problem

全栈底座审计检出进程退出与能力表排空路径存在四项永久性资源泄漏与潜在生命周期竞态：

1. 子进程内部通过 `berry-mmap` 动态分配的匿名堆 VMO 与 `pthread` 线程栈 VMO 仅存在于子进程自身句柄表 `proc.ht`，父进程没有句柄无法替其调 `vmar_unmap`；退出排空时 [handle.rs](../../../kernel/src/handle.rs) `HandleTable::drain()` 检测到 `r.refs == 1 && (v.any_mapped() || v.demand_mapped())` 即置 `leak = true` 整对象跳过递减，导致所有退出的动态堆/多线程进程的 `ObjRef` 与全部物理帧永久泄漏。
2. [aspace.rs](../../../kernel/src/aspace.rs) 分配的 L1 根页表帧与 L2/L3 中间页表帧在进程退出后从未归还伙伴分配器。
3. [lib.rs](../../../user/berry-exec/src/lib.rs) `ChildHandles::reap()` 被迫要求父进程在 `wait(SIGNAL_TERMINATED)` 后手工逐窗调 `berry_vmar_unmap`；且若父进程先于子进程崩溃退出并排空父句柄表，裸 `*mut Vmo` 在缺乏地址空间级对象保活计数时会引发跨进程解映射 UAF。
4. 双核后台满载计算使 `idle` 长时间不运行 `ht_drain_flush()` 时，`HT_DRAINQ` 待排空死进程占住 `PROCESS_LIVE` 计数，使前台连续 `sys_process_create` 在远未耗尽真内存时撞上 `PROCESS_MAX` 假性 `-ENOMEM`。

## Decision

1. 在 [handle.rs](../../../kernel/src/handle.rs) 将 `ObjRef` 引用计数升级为单 `AtomicU64` 组合状态（低 32 位为句柄与对象钉住计数 `refs`，高 32 位为地址空间页级映射保活计数 `map_refs`）：仅当 64 位组合态原子归零（`refs == 0 && map_refs == 0`）时销毁 `Box<ObjRef>`，不影响活进程 `close`/`replace` 对 `refs == 1` 的 `-EBUSY` 门控，**彻底删除 `HandleTable::drain()` 的 `leak = true` 分支**，并在父先于子退出或同表任意槽序排空时实现 100% 零 UAF 与零泄漏。
2. 在 [aspace.rs](../../../kernel/src/aspace.rs)、[syscall.rs](../../../kernel/src/syscall.rs) 与 [process.rs](../../../kernel/src/process.rs) 落地两阶段确定性销毁：
   - **第一阶段（末线程退场同步拆表）**：`task_exit_hook` 在 `live_threads` 归零且唤醒任何 `SIGNAL_TERMINATED` 等待者之前，立即执行幂等的 `proc.aspace.teardown()`——在 `pt_lock` 内置位 `torn_down`（封死后续对已释放表根的写入，同时对旧式收割器 `unmap` 保持幂等兼容）、切离本核残留 `TTBR0`、注销 `DEMAND_ROOTS`、全树清叶并执行 `untrack_map` / `untrack_demand` / `ObjRef::release_map`、发单次 Inner Shareable 按 ASID 跨核 TLB 失效屏障，最后将 `page_tables` 全部 L3/L2/L1 物理帧 100% 归还伙伴分配器并释放 ASID。
   - **第二阶段（能力表排空）**：`drain_pinned_process` 经 `HT_DRAINQ`（或内联）执行 `proc.ht.drain()` 逐槽 `ObjRef::release`，释放全部子进程私有堆/栈 VMO 物理帧与内核对象。
3. 在 [process.rs](../../../kernel/src/process.rs) 新增 `ht_drain_assist_below(limit)` 并接入 [syscall.rs](../../../kernel/src/syscall.rs) `sys_process_create`：当 `process_live() >= PROCESS_MAX` 且 `HT_DRAINQ` 非空时当场内联助推排空待回收死进程，根除忙核假 `-ENOMEM`。
4. 简化 [lib.rs](../../../user/berry-exec/src/lib.rs) `ChildHandles::reap_with_timeout()`：移除父侧手工逐窗与栈/MMIO `berry_vmar_unmap` 循环，等待 `SIGNAL_TERMINATED` 并读取退出码后直接关闭全部句柄。

## Alternatives considered

- 把阶段一 `aspace.teardown()` 一并推迟到 `HT_DRAINQ` 异步执行：拒绝——若 `SIGNAL_TERMINATED` 先唤醒父进程而 `HT_DRAINQ` 尚未在 `idle` 排水，父进程立即 `handle_close(stack_vmo)` 会因 `mapcnt > 0` 偶发撞上 `-EBUSY` 竞态；将微秒级的页表拆解置于 `wake_matching(SIGNAL_TERMINATED)` 之前，可在数学上保证父进程观测到 `TERMINATED` 的瞬间一切共享 VMO 映射钉已归零。
- 仅在 `drain()` 中调整槽扫描顺序而不引入 `ObjRef` 高 32 位 `map_refs`：拒绝——同表两遍扫只能解决同一句柄表内的槽位顺序，无法解决「父进程仅在父表持 VMO 句柄、映入子空间后父进程先崩溃退出」的跨进程生命周期倒挂；64 位单字原子组合计数以零额外内存字节同时闭合两类场景。

## Consequences

彻底终结 BerryOS 自 v1 以来的子进程动态堆/线程栈物理页泄漏与 L1/L2/L3 页表帧泄漏，卸除用户态父进程手工逐窗 `unmap` 负担，消除后台双核满载下的 `PROCESS_MAX` 假性 `-ENOMEM`。`ktest` `test_f1_2` 实测零 `idle` 排水下连续生灭 2000 个跨多级页表且含私有动态堆/按需 VMO 的子进程全程零 `-ENOMEM`，跑毕 `mm::allocated_pages()` 与起跑基线逐页严格相等（0 页泄漏），父先于子退出的反向生命周期对账同样 0 页泄漏。
