# Agent Note: 客机 TCP 二刀吞吐——载荷帽抬升、在途环与重传语义的裁决

Status: implemented

一句话说明：二刀吞吐刀为什么选「TCP_DATA_MAX 128→250 + MSS 不动 + TX_SLOTS=4 定槽环 + Go-Back-N + 重传载荷源放 vnet」这组几何，而不是抬 MSS 阶梯、按段臂集、选择性重传或本刀就联动收窗。

## Problem

十四波实测停等吞吐客户端 486/469 B/s（4KB/16KB）、服务端 echo 309 B/s，上限来自协议模型（MSS=128 + in-flight=1 + 每 op 恰一段 + 串行 RPC），与 VNC 帧流 10-30KB/s 差 21-64×。[首刀](2026-11-15-客机tcp深研首刀.md)解了入站大段黑洞但发送面零改动。任务书三合取③写着「MSS 抬升」，但抬什么、在途结构选什么、重传语义选什么、收窗联不联动——四个裁决位各有多条真实候选，选错几何会吃掉 vnet 栈预算或把正确性做歪。

## Decision

- **抬升对象改判 TCP_DATA_MAX 128→250（MSS 不动）**：通道 inline 帽 chanface CHAN_MSG_MAX=256 下会话形请求 = 6+dlen ≤ 256 ⇒ dlen ≤ 250 恰满零浪费；dlen u8 域顶 255 与通道帽 256 双硬顶下，串行 RPC 吞吐 = 每 op 载荷/RTT 与分段数无关——抬 MSS 零吞吐收益。netdproto 落 CHAN_MSG_MAX 镜像 + 断言族（超帽编译期炸），vnet 落双向几何钉（TCP_DATA_MAX > MSS 与 TX_SLOTS×MSS ≥ TCP_DATA_MAX）。
- **在途结构 = TX_SLOTS=4 定槽 FIFO**：TxSlot 三形（Syn/Data/Fin）统一进环（AcceptQueue 同款家法，零分配），close FIN 排队尾不再覆盖在途数据；4 = 2 槽/250B op + 1 FIN + 1 余量。
- **重传 = Go-Back-N 最小正确实现**：RTO 重发环头最老段 + backoff，部分 ACK 弹覆盖槽（straddling 保段整段重发）；重传载荷源放 vnet Sess.tx 暂存（op 首段整批拷入、重发按 seq−tx_seq0 切片），berry-tcp 维持零拷贝纯状态机——这修掉了旧 vnet 两处 RTO 路径 `act(ev.action, &[])` 的结构性 trap 面（丢段即服务死）。
- **收窗通告不联动（恒 512），但发送窗消费落地**：Conn.snd_wnd 记账对端通告（一切携 ACK 段更新），send 门控「在途 + 新段 ≤ snd_wnd」零窗停发——h06「零窗照发」毛刺由此关闭。
- **实测落点（裁决的域边界）**：活链实证 QEMU SLIRP 对 guest 通告窗 128B——多段在途逻辑（harness 合成窗全绿）在活链无窗可用，吞吐 1.23× 未达 1.8× 门；这不是实现缺陷而是模型前提（250B/op 单 RTT）在 SLIRP 域不成立，窗协商/op 间流水线归四刀。

## Alternatives considered

- **MSS 阶梯抬升（256/536/1460）**：否决——250B op 域零吞吐收益（MSS ≥ 250 退回一段/op，MSS ∈ [128,250) 段数同 2 无差），反吃 vnet 栈预算（SEG_BUF_SZ/scratch 随动）；真抬升待 op 载荷基数 >250 的流水线波，与通道帽抬升（kernel 属地）同批评估。
- **单槽维持 / 按段臂集**：单槽 in-flight=1 正是吞吐帽本体，否决；按段臂集 + 按段退避在「单臂 + GBN 队头」语义下冗余（丢段域 SLIRP 结构性不触发），臂语义升级为「覆盖全环最晚段尾、只进不退」即够，真网卡域再议。
- **Go-Back-N vs 选择性重传（SR）**：SR 需乱序重组缓存 + 按段 ACK 记账，而 SLIRP 代理域已重组字节流、段级丢包结构性不可注入（NET-01 界）——收益域 = 真网卡；GBN 队头重发 + 接收侧乱序丢弃 + 当前 ACK 兜底是最小正确实现。
- **收窗联动（动态通告 = RX_SESS_BUF−rx_len）本刀就做**：后置——联动是流水线前置（K ≥ 3 撞 WINDOW=512 节流）但本刀 250B/op 几何与 512 通告无冲突，零回归面最小原则下不动。
- **重传载荷源三候选**：berry-tcp 内置载荷环（破「状态机不持数据」分层）、引用调用方缓冲（pump_timers 全表泵无调用方上下文，结构性不可行）、复用 Sess.rx 保守存（DRAIN 先于 echo ACK 释字节的时序耦合腐化面）——均否决，落 vnet Sess.tx 暂存（+2KB .bss，表 17KB 面可忽略）。

## Consequences

- 能力面真实落地：多段在途/跨段部分 ACK/close 排队/零窗停发四能力由 harness h16-h19 与树内 8 新测钉板；压满准入两栈对照（基线 4KB 突发 wedge vs 二刀 DRAIN 收口）实证容量提升。
- 吞吐验收线未达如实入账：706 < 850、1.23× < 1.8×、547 逼近 550 未稳跨——模型对账方法论（同窗基线对拍 + 逐 op 探针）固化为后续复测口径；四刀任何吞吐预期按活链窗 128 自算。
- 代码面风险（后续工作前置）：二刀五件（与首刀同裹）未随 commit 落库——08:01 风波卷离后已由 tag `tcp-knives-1-2-backup`（钉 `4e638bd6b`）摘取回树并三路复验（与快照逐字一致，实况见 [NET-03 §7](../../../research/NET-03-客机TCP二刀吞吐与对抗复验-v1.0.md)）；后续任何 TCP 工作前先确认五件已由 owner 显式路径落账——落账前工作树是唯一载体，tag 只钉快照不保树。
- 四刀立项建议：op 间流水线优先（独立于对端窗），窗协商/通告窗联动次之。
