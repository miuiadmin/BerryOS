# CP-09 EAS M2 收口: overutilized 去域 0 硬编码 + EM cost 派生列 + LC/BG 四带全开

Status: implemented

## Problem

06 号 §2 Top-3 定谳的三件 EM/域修复+带扩展（CP-09 EAS M2 批次）：

1. **overutilized 域 0 硬编码**：`sched/src/util.rs` `overutilized()` 用 `em_max_capacity(0)` 取容量基准——多域（大小核）拓扑下语义错：小核域 CPU 按域 0（大核）容量判会漏判 over（EAS 该回退时不回退）。单域 QEMU 零漂移，但代码正确性须闭合。
2. **EM cost 派生列缺位**：Linux `em_perf_state.cost`（功耗按容量归一的效率系数）是 EAS 决策的效率指标，berry-em 头注自记「系数化留 CP-09 接线窗裁」——本批即接线窗。
3. **LC/BG 带未激活**：[首批激活刀](2026-11-16-m4首批band激活-现役集收窄与参数差异化断言.md)按入场券纪律收窄 ×2（interactive+utility）；ADR #42 第二段 ×4 终态未兑现——LC(0x01) 低延迟带 / BG(0x04) 后台带仍回落 unit Fair（声明了档位却无带参数分化）。

## Decision

三件（2026-11-17，只动任务书域内文件 + 注释随迁）：

1. **overutilized 按实际 CPU 所在域取容量**：`sched/src/em.rs` 新增 `em_max_capacity_of_cpu(cpu)`（扫注册域取首个 cpu_mask 含位域的极值桥——与 `berry_em::eas_pick_cpu` 的 `domain_of` 同口径）；`sched/src/util.rs:120` `overutilized()` 改消费之。cap 0（无域/未注册）语义归 `overutil_judgment` 钳 1 保守回退不变。ktest `OU-5`（kernel/src/ktest.rs `test_overutil`）：双域表（域 0=CPU0 容量 1024 / 域 1=CPU1 容量 512），双核泵同值 util 423 → CPU0 不判（≤819）/ CPU1 判（>409）——同 util 异判即 per-CPU 域容量判别面，旧硬编码下 CPU1 漏判即红。**OU-5 收口的域 1 处置**：EM 无注销 API，死掩码（0b100=CPU2 位，v1 双核外）重注册 = 语义注销——EM_VALID[1] 仍 true 但对全部 2-CPU 消费面（eas_place 候选/overutil 门/energy 记账只计 cpu_mask 成员）惰性，后续 EAS 族 ktest 与 boot `em_register_qemu_virt` 零漂移。
2. **berry-em cost 派生列**：`user/berry-em/src/lib.rs` 新增 `em_cost_of(&EmPoint) -> u64 = power_mw×1024/capacity`（u64 中间积，floor；capacity 0 钳 1 防除零——同 `energy_of` 纪律）。**派生列不落形状**：EmPoint 三字段（berry-emface 单源）不动，读面恒与 power/capacity 同源无第二事实；头注「cost 域不落」节同步改记「派生读面已落」。host 钉板 `cost_derived_column`：QEMU 表 12/20/50、Linux Example 2 little 301/450/600 / big 800/1066/1700 逐位、零容量防御、u32 顶值不溢出、与 power/capacity 比值弱同序（floor 单调）。
3. **LC/BG 激活 ×2→×4**（`iprofile/src/lib.rs`）：`band_enabled` `matches!(code, 0x02|0x03)` → `matches!(code, 0x01..=0x04)`——ADR #42 第二段 ×4 终态兑现。表行零改（骨架刀已落全行）：LC=低延迟带（四带最短 quantum 5ms + 最高包络 512..1024 + 最紧 SLO 1ms）/BG=后台带（四带最长 quantum 40ms + 最低包络 1..64 + 250ms），与 interactive/utility 差异化——数值推断【推】标注随行。host 测 `band_enabled_is_first_batch_two` 改形 `band_enabled_is_active_four`（恢复骨架刀旧名）、`band_of_intent_maps_and_gates` 扩四档 Some。
4. **ktest BANDM4 四带扩展**：M4A 现役集四带/M4B 工厂门四 Some/M4C 参数阶梯（quantum·latency 严格递增、low_weight 严格递降、相邻包络互异 + LC 低延迟位/BG 后台位方向钉板）/M4D 表源执法四带/M4E 同环共存四带集合断言/M4F spawn 面 **五任务**（四带 + UNSPECIFIED 对照回落 Unit——原 BG 对照随激活换位）+ spawn 面四带 quantum 阶梯/包络分化断言/G 段前置断言扩四带槽默认关、收尾行 `n=2`→`n=4`。**G 段行为驱动保持 IA/UT 代表对**（12ms 跑段介于 10/20ms 之间是 G1 quantum 律断言前提，四带全跑无单值跑段可满足——LC/BG 行为面归 LOADGEN/带专项，测试头注明记）。
5. **注释随迁**（行为零改，同前刀先例）：class.rs M4 段头/band_id 字段/工厂注/TaskClass 注/class_of_task 注；sched.rs enqueue_with_kick 集成窗注与 spawn_intent 注；policy.rs snap_insert/band_of 两注——「首批 0x02/0x03」枚举全部改指四带现役集（词汇门 `band_enabled` 单源不动）。

## Alternatives considered

- OU-5 用「重注册域 0 掩码留双域」而非死掩码收口（否：域 1 留 CPU1 成员会改 boot 后 eas_place 的候选/记账面——policy hint 绑定后放置漂移；死掩码域对 2-CPU 消费面全惰性才是真零漂移）。
- cost 落 EmPoint 第四字段（否：形状单源在 berry-emface，扩字段=动 emface + ktest EM-1 逐位对拍全改；派生读面零存储扩、恒一致）。
- M4G 四带全跑（否：G1 断言前提「跑段介于两带 quantum 之间」在 5/10/20/40ms 四带下无单值可满足；IA/UT 对已覆盖四 API 机械面，LC/BG 行为面有 LOADGEN 载体）。
- 跳过 sched.rs/policy.rs 注释随迁（否：三处注释直引「首批 0x02/0x03」现役集，激活后即事实错；注释随迁是前刀先例且词汇门单源未动）。

## Consequences

- iprofile host 23 测绿（计数不变）；berry-em host 9 测绿（+1 cost）；`cargo build` 内核绿（预存 2 警告在 SLACK-SMP/LOADGEN 段，域外）；fwcfg 25 键/abi-check 40 号/docs_guard 0 警/writable-globals 88 条四门绿；boot 相 smoke 32 标记 + `BANDM4 ok n=4` + `OVERUTIL ok` QEMU 实靴绿（详见验证段）。
- **运行面行为变化（本刀有意面）**：BG(0x04) 声明任务（boot it_mid/it_slow、user appquiet/apptomb）现得 FairBand 实例——tick 走带参数（quantum 40ms/预算期 250ms/配额 40ms 每期=16% duty 上限）；IPC 阻塞型任务运行账微小不触限流。LC(0x01) 配额 5ms/1ms 期（>100%）结构性不可越线。`[band]` boot 行新增 LC/BG 任务条目（it_mid/it_slow——QEMU 日志 ×4 证据面）。偷取带感知序零漂移（LC/BG 落 STEAL_RANK_COMPAT=Unit 同档）。
- 首批激活刀的两处「残留」预言兑现：LC/BG 现役化只改 `band_enabled` 一处（单源设计目的达成）；polface `BAND_SEL_NONE` 文档注的「×4 现役带 id 0x01..=0x04」枚举由过时转为现役正确（域外文件仍未碰）。
- 残留：OU-5 死掩码域 1 在 EM 增加注销 API 前长存（对 v1 双核全惰性；EM 注销 API 归 CP-19 拓扑演进窗）；cost 的 EAS 决策消费面（选核效率比较）归 CP-09 后续接线；M4 真数字经启动配置参数表覆盖通道不变（ADR #42「数字进启动配置不写死」）。
