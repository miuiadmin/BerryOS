# Agent Note: klog 环并发设计与 0x84 翻真三裁决

Status: implemented

## Problem

阶段五（klog 环 + 0x84 telemetry_open + bsh dmesg）实施中暴露三个设计级问题：klog 环首版 per-char seqlock 在高频写流下读者饿死；ktest 横幅断言隐含「环未追尾」形态假设会炸 smoke 主面；QEMU 验证的内核路径取自全局陈旧 target 造成 -95 假象。三者都不改变「做什么」的决策，但决定了「怎么做才对」。

## Decision

1. **klog 环并发模型**：写侧 fetch_add 独占分配槽位 + 普通数据 store（无 per-char seqlock 包络）；读侧 pos 快照 + 热尾丢弃容错窗（HOT_TAIL=128B）无版本校验。依据：槽位由 fetch_add 独占分配写者互不覆盖，唯一缺口是「已分配未落字」的指令级嵌套窗——远小于 128B；dmesg 是 best-effort 语义，撕裂最坏读到旧环残值。per-char seqlock 的教训：写压与读重试成功率成反比，稳态矩阵洪流下读者 64 次恒撞写窗。
2. **ktest 断言边界**：静默盖只保 ABI 契约面（非空/换行/ASCII/op 域外/len 边界），内容镜像断言（如「含 boot 横幅」）不进 ktest——它隐含形态假设（环未追尾只在裸跑成立，rootfs 形态矩阵灌环必炸）；镜像正确性由 rootfs 相 e2e 承担（判据=尾窗自洽：快照以调用前最新串流为尾——五轮审计证实初版「boot 标记行回放再现」判据验证的是修正前 bug 行为，已废）。
3. **验证内核路径纪律**：QEMU 验证必须用构建实际 target 目录的内核——`bash tools/paths.sh kernel` 指全局 ~/.cargo-target，在 EPERM 坑驱动的 workspace-local target（target-klog 等）工作流下是陈旧内核，会产出「syscall 返 -ENOTSUP」类版本错配假象。

## 五轮追尾修正补记（2026-11-16）

五轮审计抓到首版快照锚定 bug 并同批修正：`snapshot_into` 的 start 原锚在截断的 avail——追尾覆盖后返回第一圈旧段 [SIZE-take, SIZE) 而非最新尾窗（逐字节模拟实锤）；修正为 `start = pos - take`（pos ≥ avail ≥ take 恒成立），并把 put 的 fetch_add 改 Release 收口跨核可见性（读者 Acquire 配对）。修正后双判据复验：快照含 128 处最新洪流特征、已追尾的 boot 行不再回放。

## Alternatives considered

- **双计数器（alloc_pos/commit_pos）严格序**：读者只见已提交字节——但同核 IRQ 嵌套写者的 commit 乱序使承诺失真，且复杂度买不回 best-effort 语义下的任何决策力；落选。
- **ktest 打探针串自证镜像**：探针落在热尾丢弃窗内断言必假，扩探针超窗又丑；且任何额外输出都顶撞 smoke 逐行零漂移；落选（e2e 承担）。
- **横幅断言改成「仅裸跑形态生效」**：给 ktest 加形态分叉是契约复杂化，负收益；落选。

## Consequences

dmesg 在任何写压下可用（安静期读到一致窗、洪流期读到热尾外的一致窗）；ktest 静默盖跨形态稳定；后续 Anyone 在新 target 目录工作流下跑 QEMU 前须核对内核路径（README 环境坑注记已含 EPERM 面，路径坑补记在本笔记）。0x84 已翻真为公共 ABI（op=0 klog 快照域冻结），后续环读口（SwitchRec/WakeRec）按 op 域扩展不再加号。
