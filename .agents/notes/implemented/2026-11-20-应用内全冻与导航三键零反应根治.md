# 应用内全冻与导航三键零反应根治（present 全局 held 互吞 + 输入多 poller 互截）

Status: implemented

## Problem

实抓现场（/Users/murongcheng/.berry/run/1795109150-222265000-77355-host/serial.log，2026-11-20 云桌面手跑）：用户能进应用（spawn 修复生效）后「点了几下就卡住」——app UI 冻结，返回/主页/多任务三键完全零反应。关键行：`eco: app MMS it 03` + `eco: app FILES it 03`（两 app 背靠背拉起）→ `launcher: release count=0 nh=0`（launcher fail→park 永死——park 非 crash，launcher_supervise 的 TERMINATED 探活永不命中，无重启）→ `gui-inputd: wm 快照超龄/缺席（旁注 hit=14 窗=3 stale=48 gone=0 miss=48）`。fin5w.log（宿主 VNC 转发）证实指针事件全数到达 QEMU——事件在 guest 侧被吞。

## Decision

定谳三因（前轮「MMS 卡在内核 pre-first-frame」为误诊：app fail=park 的 10s 周期内核睡眠恰呈「blocked 非 spinning、UTILITY picks 冻结」假象；`MMS ok` 是旧 mms-app 标记，现役 bin/messages 从不打印）：

1. **guifbd present 域是单客户端几何**：`held` 是进程级全局单表（CREDITS=2）、RELEASE_WAIT 应答=全量排空迁给任意请求者、pending/cb_park/rel_park 全单槽。K1 per-app wm 通道后 present 域多客户端并存，任一客户端的 RELEASE（含新客户端 boot 跨代清账）把他人在途别名随应答迁走——被迁方 RELEASE 得 count=0，各客户端 `count<1 → fail` 断言把 launcher（桌面/导航键/输入泵）与 app（UI 冻结）整批 park。
2. **输入单 FIFO 多 poller 互截**：inputd input 域=严格串行 RPC（事件应答投回 INPUT_A 唯一队列），svcmgr 给每个 [ui] app 交 INPUT_A dup，app 自己 INPUT_POLL——launcher 与 app 并发 poll 时应答随机落进任一 dup 持有者（dup(WMD_CLI_DUP) 单 FIFO 应答互截同款实锤缺陷形），app 卡住即事件无人收。v1 输入拓扑=单订阅者（指针事件恒全投 launcher，导航三键=系统级保留面恒 launcher 消费），app 直投是拓扑违例。
3. **导航三键死因=launcher 本体死**：三键 handler 全在 launcher frameloop，launcher park 后无人消费任何指针事件。

四件修复（作用域=berry-appshell/berry-launcher/svcmgr）：

1. **appshell pump 宽容 RELEASE**（`release_round`，boot 清账与帧尾共用）：count==0 合法（别名=本端 VMO 的 READ|TRANSFER dup，原柄在本表，对方 close=纯引用计数下降；本帧 PRESENTED 已先断言——早归还良性）；1B 拒答（ST_BUSY=他客户端 parked RELEASE 占 rel_park 单槽）步进重试帽 10s；随行 handle 不论归属全量 close。杀 `count<1 → fail` 断言（launcher 永死实抓本体）。
2. **svcmgr app gift 撤 input 端**：app_launch 的 in_dup + !wants_fs 占位双 dup（gui_ph0/1）全撤——gift 尾截断在 [cli]，app 侧 input_h()==0 走各 app 既有「静态页降级」路径；launcher/bsh 的 INPUT_A dup 不动。占位柄 TRANSFER 位缺陷面（G1.5 -13 反杀）随之结构性消失。focus 门控真投递归波 3 后续刀。
3. **launcher spawn 窗守卫**（SPAWN_GUARD_NS=3s，成功 APP_SPAWN 才起算）：窗内新 spawn（槽位/列表行/多任务重拉）让位消费不落 spawn 面——防连环 tap 两 app 并发 boot 的 present 互踩；覆盖收盖/导航键在守卫之**前**恒活（退出路不受限）。
4. **appshell pump render_hold 钩子**（launcher 覆写=守卫窗内 true）：launcher 渲染半程让位（damage 留脏不消费）——app boot/首帧呈现链独占 guifbd present 单飞槽；守卫截止入 extra_deadline 到点醒重渲。分钟摆字至多迟 3s（视觉面可忽略）。

## Alternatives considered

改 guifbd per-client held/pending（弃——guifbd 不在本刀作用域，且单飞几何是其单客户端时代立法）；apps 侧撤 count 断言（弃——messages/files 等七 app 不在作用域，gift 截断+守卫+宽容三面已把并发呈现压到近零）；svcmgr 阻塞串行化 APP_SPAWN 等 app 首帧（弃——svcmgr 无 app 呈现可观测面，等待=卡死单线程 serve 拖连 echo/fs；launcher 侧守卫同效且不占服务线程）；launcher 不 poll 输入改 app poll（弃——导航三键在 launcher，恒消费=单订阅者拓扑的必然）。

## Consequences

验证：`cargo check -p berry-appshell`/`-p svcmgr`（user 工作区）+ berry-launcher musl `cargo check --release`（含 --tests 面）全绿（存量警告零新增）；host 测 berry-appshell 6 绿、berry-gfx 60 绿、berry-ui 118 绿。行为：gui8 标记零扰（CLICK ok n=1/click ready 路径未动——守卫只在首例成功 spawn 之后生效）；app 交互面降级为静态页是 v1 单订阅者模型的显式化（此前「能点」本就是互截缺陷的随机面）。已知残余：守卫窗外 launcher 分钟摆字帧与超慢 app boot 并发（概率≈每分钟 1 帧 × ~1s 窗，app 侧 count 断言仍在作用域外）= app 偶发不出现/park——导航键恒活可收盖重开（不再全灭）；wmd 侧 present 毒化清淤面（relay 30s 帽）不连坐 wm 域。Related：[inputd 在途悬挂强制重发 I3](2026-11-19-inputd在途悬挂强制重发I3.md)（wm WAIT 悬挂行=安静表 I3 探测环常态，非 wmd 停摆——本轮误诊源）、[per-app wm 通道化与导航键排雷](2026-11-19-per-app-wm通道化与导航键排雷.md)（K1 通道化只治 wm 面，present 面单飞几何本刀补齐消费侧避让）。
