# user/bins 孤儿源文件退役标注（launcher icons 三件套 + gui-wmd presarb）

Status: implemented

一句话说明：清偿[驱动两波架构债清理](2026-11-20-驱动两波架构债清理.md)挂账的孤儿源文件——berry-launcher icons.rs 及其 #[path] 伴生件 status_icons.rs/wallpaper.rs 三件加注释退役，全量扫描另揪出 gui-wmd/presarb.rs 一并退役，四件皆不删。

## Problem

挂账三项待清：其一，`user/bins/berry-launcher/src/icons.rs` 是波 3 抽取 appshell 时未删的原件——main.rs mod 表无 icons（`crate::icons` 经 `pub use appshell::icons` 解析），且 `use crate::{rpc_recv, rpc_send}` 在 crate 根无此符号，挂回编译必红。其二，其 `#[path]` 携带的 status_icons.rs/wallpaper.rs 是否同样无主待查。其三，user/bins/ 下是否还有其他被跟踪但不在模块树里的源文件。

核查法：脚本自各 crate 根（lib/main/tests/examples/build.rs + Cargo.toml 自定义 path）沿 mod 声明与 `#[path]`/`include!` 建模块树，与 `git ls-files` 对账。结论：status_icons.rs/wallpaper.rs 唯一引用主就是孤儿 icons.rs，与 appshell 现役副本逐字节相同，且生成器（tools/genohstatus.py/genohwallpaper.py）波 3 起产物已改指 appshell——连生成链都不再触达，纯遗留副本。全量扫描另揪出 `user/bins/gui-wmd/src/presarb.rs`（lib.rs 仅声明 relay/table 两模块）——系[云桌面多客户端架构刀](../rejected/2026-11-20-云桌面多客户端架构根治.md)终局否决、全量回退后的死文件，彼笔记已定谳「以死文件留在树中，完整实现存 8a0065f10 可取回」。uu/ 下 23 个成员 `src/main.rs` 是 workspace 成员 crate 根，属扫描器折叠假阳性，非孤儿。

## Decision

四件被跟踪孤儿一律不删（AGENTS 规则 4），文件头部加统一退役标记「// 孤儿文件（不参与编译）——保留供历史参考，待归档」，并各附成因行：launcher 三件注明现役版本在 `user/berry-appshell/src/`（生成链同指）；presarb 注明取回锚 git 8a0065f10 与定谳笔记路径。未跟踪孤儿不碰（本域未发现）；uu 假阳性不动。

## Alternatives considered

- 直接删除四文件（弃——工作区永不删除纪律；presarb 的 rejected 定谳明文「以死文件留在树中」）。
- 挂回编译复用（弃——icons.rs 参与编译必红；status_icons/wallpaper 与 appshell 副本逐字节相同，挂回即二重供给，违「一事实一归属」）。
- 移入 `.agents/archive/`（弃——彼处是文档冷历史属地；代码文件原地退役保留最短 git 取回路径，也免动 rejected 笔记已定谳的树中位置）。

## Consequences

- 四孤儿原地退役有标记：后续清理刀与机械扫描可据头注串「孤儿文件（不参与编译）」识别；实体归档留待统一归档刀。
- [驱动两波架构债清理](2026-11-20-驱动两波架构债清理.md)的待清债挂账闭环。
- 验证：`just build-user` 全绿（SETTINGS/FILES/PHOTOS/CAMERA/CONTACTS/MMS/BROWSER/TERMINAL 八 .bap 全量 mkapp + mkcpio 双卷 ≤32MiB + tlsscan x62 ELF 全过）。首跑一次 `cp userbins/app-stage/FILES` 失败系并行 lane 在共享产物目录 userbins/ 的瞬时清场（配方首行即 `rm -rf userbins/app-stage`，两会话交错即互清），重跑即绿——共享工作区跑 build-user 需留意此竞态。
