# Agent Note: W3-Q105 G1.5 配对悬账收口 + icount 十项基线自立实施记录

Status: implemented

## Problem

QUEUE 尾梯度件「svc_roundtrip icount 基线 --update 自立」（bench.rs 十项在册而基线文件仅六项，pick_scan/switch_pair/send_recv_pair/svc_roundtrip 四项缺席，门禁对缺席只提示不红）首跑即炸出 base 债：`python3 tools/bench.py --icount` 在 -icount 虚拟时钟下 boot 尾 KERNEL PANIC `kernel/src/user.rs:1892 G1.5 FAIL: 遥测环未跟上（total=990 < switches_tt=1249）`，BENCHWAKE done 标记结构性缺席，1800s 帽 loud 红——基线无法自立。

根因 = 04 号 sbench 纪元刀（2026-11-17）自记的「配对悬账」：`kernel/src/bench.rs` `run_sched_epoch` 头注明文「SWITCHES_TT 在钩子缺席期也计……G1.5 断言将差本纪元切换数（≈259）；须随本刀在 sched 侧配对修复」。机制：icount 通道恒递 fw_cfg `opt/berry/sbench` 键 → `run_sched_epoch` 在 `telemetry::init`（钩子注册）前的纪元窗 spawn A/B 测量对走 ≈259 次任务↔任务切换——`note_switch` 的 SWITCHES_TT 分母在钩子缺席期照计，而遥测环写经钩子结构性零写 → boot 尾 G1.5 断言 `tel >= switches_tt` 差恰纪元切换数必炸。实时通道（rt/smoke）不递 sbench 键 = 纪元窗不spawn = 债不显形，故债潜伏至 icount 首复跑。

## Change

- `sched/src/sched.rs` `note_switch`：SWITCHES_TT 自增移入 `SWITCH_HOOK` 在位分支内——分母与环写同生同灭（钩子在 = 计数+环写同点；钩子缺席 = 双双零），G1.5 配平律在所有断言窗恒成立。trace_off 面注释钉明：钩子在位早退（on_switch 头 `trace_off()` return）——tt 照计而环零写，但 G1.5 断言块随记录面整体让位（user.rs 同步门），无比对面。
- `kernel/src/bench.rs` `run_sched_epoch` 头注：「配对悬账（主线收）」改留档态（已收，含实测炸点数据）。
- `tools/bench_baseline_icount.txt`：`--icount --update` 立基十项（prove 五跑 verdict=exact max_dev=0.000% → ICOUNT_TOL=0.0 维持；BENCHWAKE 五跑逐字节同 n=694）。四新项首录：pick_scan=125 / send_recv_pair=1168 / svc_roundtrip=50 / switch_pair=304（修复前 310 = 计数移分支的小指令流差）。三项旧值漂移归因入 `tools/bench_baseline_icount.notes.md` 史档：alloc4k/64k 37→82 = 在册 {37,82} 布局骰轨道族；commit1p 396→441 = 11-17 基线笔后树前进的指令流漂移。
