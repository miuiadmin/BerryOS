# Agent Note: AM 域全日落地收官（机制面）

Status: implemented

## Problem

AM 域（应用后台处置，通称墓碑模式）从零起步：2026-11-08 一日内走完 AM-01 调研 → design v0.1→v0.4.0 → app-1 段 a/b（FROZEN/TOMB ok）→ AM-1.5 wake-pending（WAKE ok）→ AM-2b 压力出口（AM2B-K）→ AM-2e 真注入（DPGPRESS），叠加同日 AM-2a 等页台账——等页感知→窗口折卷→阈值→事件→用户态观测全机制面落齐，策略消费面未启（am 服务未成形）。本篇只沉淀决策因果：为什么这么裁、放弃了什么、后续要盯什么；实证流水归沿革 §157–§172，三裁决依据归旧笔记，不重复。

## Decision

- **①墓碑形态采 Fuchsia、否决 WP 式墓碑文件**：AM-01 总判断——最先进形态不在 Android：墓碑不是特例机制，是「VMO + 用户态 pager + 持久存储」的自然推论，与 BerryOS 架构**同构**（杀进程零序列化、恢复按页惰性支付）；WP 式墓碑文件（State 字典 ≤5 配额 + 10s 限时）是低内存年代强制手段，两级模型（dormant→tombstone）出现后无人复刻——不建特例，省一条只服务特例的协议面。
- **②五级梯度（L0 discardable 收割→L1 压缩换出→L2 冻结→L3 杀+墓碑→L4 归档）+ 策略在用户态**：全部被调研系统收敛到「时间尺度 × 代价」分层，无一系统用单一墓碑覆盖全尺度；梯度选择与阈值全在 am，内核只供机制（freeze/VMO/遥测）——SCHED-01 教训「策略不进快路径」的贯彻；压力信号取体验级指标（等页停顿占比）弃固定 minfree 水位（内核态 LMK 反面教训）。
- **③Q1–Q3 三裁决当日进实证闭环**：Q1-c「唤醒即解冻」从裁决直落 AM-1.5 内核机制（wake-pending + 按进程钉键广播，零新 syscall）再到 WAKE ok 用户态闭环——裁决不再停在纸面。**冻结谓词双残影是意外但必然**：立法时无人测过睡眠者（睡在 syscall 内的任务把 svc_mask/held_locks 记账位带进 SLEEPQ——位是残影、锁已放），app-1 段 a-1 十六试全拒才暴露；谓词立法与首个真实消费者之间的检验空窗结构性存在——首个消费者即首个测试者，这条判据对后续所有「先立法后消费」的机制面通用。
- **④AM-2b 出口取候选①、机制先于消费链**：am 未成形也先把内核出口钉死（系统压力 Event boot 建立 + 静态 retain + svcmgr 表定值第 8 插 0x0001_0008 迁交，RX_EV 先例全链复用）——机制与消费解耦，ABI 面（零新号、0x84 telemetry_open 不动）不等消费链成形；六裁决（dpg 三计值点惰性折卷/θ_p=10% 占比判据/用户位 1<<40-41/am 边沿自清恢复协议）一次落定，am 拉起刀只剩 env gift 接线。
- **⑤v1/v2 边界按依赖与测量环境划**：L3 真触发挂 GUI 线/v2（前台判定依赖 GUI，v0 = 显式自验触发）；θ_p/窗长定标挂 v2（TCG 数字不可外推）；L4 归档挂 v2（月级低频路径不阻塞机制面）；跨核冻结一致性挂 v2（单核三重正交谓词已防停摆）；全量 checkpoint 不是挂账是直接不做（kill criteria 立法）。

## Alternatives considered

- **AM-2b 候选②派生位（WAKE_PENDING 推广）**：被否——WAKE_PENDING 成立的两支柱（事件有天然属主对象 + 按属主钉键单点广播一跳全收）在系统级事件不成立：压力无天然属主、电平派生语义与惰性翻卷冲突（恢复沿要求内核持续跑）、任一进程可等则契约面全进程扩大。
- **AM-2b 候选③查询口**：不可行如实记——v1 无内核遥测查询面（0x84 在册 stage v3、0x07 stage v2 均未实现），开查询口即破零新号约束；0x84 前向激活留作候选①数值面补全的独立刀。
- **wait_many 扩柄（AM-2e 观测桥）**：三点击退——现役面语义保护，观测桥改 svcmgr 稳态 poll 探针形（命中 1<<40 打 eco 行自清）。
- **CRIU 式全量 checkpoint**：性能数字否决（dump 22.35GiB≈54s、GB 级盘、特权 parasite 注入）——AM-01 kill criteria：任何「为恢复体验而全量序列化进程内存」的提案引用 §③ 数字即否，秒级延迟对移动日常是负资产。
- **am 独立守护进程**：被否——应用模型 §4.1 已立法 appd 承载生命周期分级（active→freeze→tombstone→not running），AM-01 结论与该立法原文独立同构、互证；am 作该域模块设计（梯度契约 + 策略层），消费链落 appd（规则/05 监督域），避免监督双头。

## Consequences

- **定标债**：θ_p=10% 与 70ms 窗均【推】值，DPGPRESS 实测（n=248 c=880312）是 TCG 值不可外推——complete 700ms 窗与 full 判据（需 waiter 深度跟踪）随 am 拉起刀同批定标。
- **缺口在册**：共享端点双冻结主归首冻结主（v1 单主保守缺口，channel.rs 字段注）；深睡降级路无 token 不通知（语义自洽，知悉即可）。
- **挂账**：GOP 相实跑（smoke-image 被 G10 共享门拦，候并行未登草稿落库）；L3 真触发随 GUI 线；wake-flood 遥测（解冻频次 HDR 分位 + 升级处置）随 am 成形。
- **workflow 编排教训（§A146 三度 sweep 实证）**：AM-1.5 A 路产出被并行大扫冲失（主会话重做）、AM-2b A 路被并行 stash（pop 救回）、AM-2e B 路两遭（蒸发重施加 + 收口前吞并入库）——workflow agent 产出与主会话收口之间是裸奔窗口，异步 lane 越活跃窗口越危险；修法 = 立即收口（产出即落盘即提）+ 逐文件 git log 归属核，编排设计须把收口动作排进波内而非留到批尾。
