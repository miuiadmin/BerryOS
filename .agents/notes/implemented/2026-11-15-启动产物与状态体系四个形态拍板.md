# Agent Note: 启动产物与状态体系四个形态拍板

Status: implemented

## Problem

调研（[2026-11-15-启动产物配置与日志AI可读性调研](../../research/2026-11-15-启动产物配置与日志AI可读性调研.md)）确认宿主侧半套体系、客机侧零体系后，建设形态有四个问题悬而未决：失败现场保留策略、直跑族并轨形态、x86/EFI 面是否同期、持久化适用面。不先定形态，阶段规格无法细化。

## Decision

用户于 2026-11-15 授权「做，彻底规划好」，四案按建议定并于同日四批落地（M1 止血三件 + M2 宿主/客机持久层九步 + 两轮审计修复批，见[全面建设计划](../../plans/2026-11-15-启动产物与状态体系全面建设计划.md)落地记录节）：

1. 保留策略：失败自动保留、成功默认删——`berry run`/`berry shot` 在 marker 失败、超时、QEMU 先退、取帧失败分支自动保留 run 目录（首批 `run.keep()`，第三批起统一为 `keep_fail()` 带 stderr 路径提示；device start 第三条 QEMU 路径二轮补齐，bind-race 重试成功不误保留）；smoke 失败必留日志（`trap 'cleanup $?'`）。无 marker 的交互 run 仅异常退出算失败（正常退出不堆目录）。
2. 并轨形态：过渡形态已落（justfile 七直跑入口 tee 落 `out/logs/`，pipefail 保退出码）；终态全量走 berry CLI 起 QEMU 在阶段四第 13 步与模拟器体验统一刀合流（待排期）。
3. ARM64 主线优先；x86/EFI 面随阶段四顺手收，不单独开路。
4. 确定性面与持久面按启动方式分流：smoke/CI 路径保持每次重造盘与 blank vars 的零残留（确定性是测试根基）；持久化只走设备壳 profile 路径——`just desktop` 数据盘改为 `~/.berry/data/desktop.img` 存在即复用；vars.fd 维持 blank 重造为默认，`BERRY_VARS_PERSIST` 可选持久按需启用。

## Alternatives considered

- **全保留（不删任何 run 目录）**：磁盘无限增长，shot 类高频操作很快堆满；落选。
- **维持即焚 + 人手动 --keep / SMOKE_KEEP_LOG=1**：调研证实失败现场恰是人最想不到要留的时候丢的；落选。
- **B 族另造第二套留痕目录**：调研裁决即「两套体系并立」是病根，再发明第二种形态违背宿主留痕单形态原则；落选。
- **全量持久化不分流**：破坏 smoke/CI 的确定性根基（零残留是被 315 测试与 marker 谓词依赖的特性）；落选。
- **x86 同期全套**：面铺太大拖慢 ARM64 主线；落选。
- **vars.fd 无条件复用**：与 blank 重载的确定性干净启动设计前提（qemu.rs create_vars 注释）直接冲突；落选为默认，改为 opt-in。

## Consequences

AI 取证面从「设备壳半边」扩到全启动方式（直跑族 `out/logs/`、设备壳 run 目录失败必留、smoke 失败必留）；客机获得跨启动状态（settings 五键落盘 SETTINGS.CFG + bsh BSHRC.CFG，FAT 卷根 8.3 文件族 v1 落点）；run 历史留痕（index.jsonl + find_run 两级回落）；fw_cfg 键治理单源化（fwcfg-keys.toml 21 键 + doctor 键报告 + fwcfg-check 对拍）。代价：过渡期 justfile tee 与 berry run 目录两套留痕形态并存（阶段四消除）；BSHRC 正向 e2e 已于第六批关账过关（两轮共盘实证）；settings 运行时验证判据已随缺省盘软化改写（见计划未完成事项）。
