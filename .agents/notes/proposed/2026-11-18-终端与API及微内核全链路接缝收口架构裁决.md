# 终端与 API 及微内核全链路接缝收口架构裁决

Status: proposed

## 背景

在全系统 40 模块规格与分波实施计划合龙就绪后，依据 [终端与 API 及微内核全链路深度遗漏审计](../../research/2026-11-18-终端与API及微内核全链路深度遗漏审计.md)，全栈三大底座（终端命令行、系统调用 API、微内核底层）在跨层调用、高并发吞吐、硬件内存安全与前台控制流中仍存在 13 项关键接缝断层（如 PTY 前台作业识别、GUI 终端渲染性能、OSC 52 剪贴板安全、`0x1C` 号位在册对撞、批量端口等待、硬件 PAN 用户内存拷贝、Pager 调页自死锁防线、内核栈底保护页与跨核优先级继承）。本裁决正式立定这 13 项接缝的架构解决方案，并在合龙总纲、`pty` 与 `meihe` 规格中同步闭环。

## 裁决

### 一、终端与命令行接缝裁决（T-1 至 T-4）
1. **PTY 前台作业能力绑定与异常 Cooked 自愈（[pty 总体设计](../../plans/pty/design.md) `1.2.0`）**：
   - 确立 `PTY_SET_FOREGROUND_JOB(job_handle)` 协议，由 Shell 将前台作业沙箱绑定至 PTY 会话；`0x03` / `0x1A` 信号精准投递至目标 Job；前台退出后自动将 PTY 前台归属回滚至根 Shell；
   - 监听 PTY 从端句柄生命周期；当检测到全屏应用异常退出或被强杀时，`ptyd` 必须在 1ms 内自动强制复位 `Sanity Termios (ICANON=1, ECHO=1, ISIG=1)` 并切回主屏幕缓冲，彻底消除乱码死锁。
2. **GUI 桌面终端渲染批处理与 OSC 52 剪贴板防御**：
   - GUI 终端 `berry-term` 严禁为每个字符生成独立 `SceneIR` 节点；必须基于预焙字形图集（Glyph Atlas）+ 行级脏掩码（Dirty Row Mask）批处理，大面积滚屏时切入 `Swapchain` 双缓冲直写，保证 CPU 开销 $\le 3\%$；
   - 支持 ANSI OSC 52 剪贴板设置协议，但强制施加前台激活焦点与最近 500ms 内存在物理按键交互的双重门禁，阻断后台恶意脚本劫持系统剪贴板。

### 二、系统调用 API 与契约接缝裁决（A-1 至 A-3）
3. **消除系统调用号位撞车与扩充批量等待（[全系统 40 模块终态合龙总纲](../../plans/2026-11-18-全系统31模块终态合龙总纲与ABI号段总表.md) `3.1.0`）**：
   - 尊重主线已落地代码事实：将 `0x1C` 固化为已运行的 `berry_vmo_cache_op`，将尚未实装的 CoW 切片子 VMO 系统调用顺延分配至 `0x1D berry_vmo_create_child`；
   - 新增 `0x5C berry_port_wait_batch(port, deadline, out_pkts, cap, *actual)`，单次系统调用支持批量弹出最多 `cap` 个异步事件包，消除超高速网络与存储驱动的频繁上下文切换开销。
4. **硬件 PAN 内存安全拷贝与负数 Errno 全局单源**：
   - 所有入参指针必须经非规范地址检查（`ptr + len <= 0x0000_7FFF_FFFF_FFFF`）与结构体自然对齐核验；
   - 开启硬件特权防穿透（ARM64 PAN / x86 SMAP）；内核在密封汇编块执行用户拷贝，缺页安全返回 `-EFAULT` 绝不 Panic；
   - 全系统一律采用 Linux 兼容的负数错误码（`-EINVAL=-22`、`-EBADF=-9`、`-ENOMEM=-12` 等），单源生成 C/Rust 常量。

### 三、微内核底层架构硬防线裁决（K-1 至 K-3）
5. **Pager 异步调页死锁免疫（[meihe 总体设计](../../plans/meihe/design.md) `2.2.0`）**：
   - 确立铁律：承载按需调页的外置 Pager 守护进程（`fsmgr`、`pkgmgr`），其代码段、全局变量与所有处理线程栈必须在启动时全量设置为 `VMO_CONTIGUOUS | VMO_PINNED`，禁止按需换出；供给内核快路径严禁触发动态堆分配，彻底拔除调页环路死锁隐患。
6. **内核线程 16KiB 堆栈 Guard Page 物理守卫**：
   - 在内核虚拟地址空间中为每个内核线程执行栈分配独立 VMAR，栈底 4KiB 物理帧强制置为未映射（Unmapped Guard Page）；溢出即触发同步异常并被黑匣子捕获，阻断内存踩踏破坏相邻堆对象。
7. **跨核优先级继承 `SGI_PRIO_BOOST` 无锁推挤**：
   - 跨核 IPC 阻塞时，调用方核禁止直接跨核获取被调用方核的 `RunqueueLock`；通过原子 CAS 更新目标任务 `prio_boost` 字段并向对端发射 `SGI_PRIO_BOOST` 核间中断，由目标核在本地安全窗口重排红黑树。

- **全仓门禁**：全仓 40 份规格与文档体检必须 100% 保持 `node .agents/tools/check-docs.mjs --strict` 与 `python3 tools/docs_guard.py` 0 告警通过。
