# Agent Note: 终端优先（CLI-First）全栈闭环架构六大核心裁决

Status: proposed

## Problem

在图形界面尚处打磨阶段的现实条件下，BerryOS 需要率先以「微内核 + 命令行终端」形态交付一套 100% 完整、顺手、可日常干活、可在机深度调试的独立操作系统体验。[终端与命令行全栈体验深度体检报告](../../research/2026-11-18-终端与命令行全栈体验深度体检报告.md) 揭示现役命令行栈存在 22 项阻断性断层：内核线程 `task_console` 逐字节发 IPC 且 128B 粘贴丢字、全系统无伪终端（PTY）与 Raw/Cooked/`winsize` 契约、外部子进程无 `stdin` 且 `stdout` 退出后攒批打印、缺 `/svc` 服务发现导致 `ps`/`berryctl` 在交互 Shell 必败、`bsh` 无词法语法树/光标移动/脚本与作业控制、且机内完全缺失文本编辑器、分页器、终端多路复用器、网络命令与在机能力/IPC/断点调试工具链。若靠零散打补丁修补 `task_console` 与 `GIFT_H` 位置槽，不仅无法跑起全屏编辑器与实时监控器，还会破坏微内核纯能力边界。

## Proposal

确立「CLI-First 微内核原生终端工作站」终态架构，在不引入任何内核态 POSIX TTY 历史包袱与 `fork/ptrace` 污染的前提下，拍板以下六大核心裁决：

1. **纯用户态伪终端与控制台会话中枢（`consoled` + `ptyd` + `berry-vt`）**：彻底废除内核 `task_console` 线程与全局混流 `CONSOLE_H`。内核仅保留极薄早期 `ramoops`/panic 串口直写与 `0x84` `klog` 环；日常串口（PL011 / `virtio-console`）由持 `Interrupt` 对象的用户态 `consoled` 接管，后台服务日志统一汇入 `traced / klog` 绝不直涂前台终端。新建用户态 `ptyd` 服务：每场终端会话由一对能力句柄 `(PtyMasterCap, PtySlaveCap)` 表达，数据面采用双 `64KiB` 共享内存无锁 `IoRing VMO`（消除逐字节 IPC 系统调用与 128B 粘贴丢字），控制面经 `PtyCtl` 通道承载 `Termios`（Raw/Cooked/Echo/ISIG）、`Winsize { cols, rows, xpixel, ypixel }` 及 `SIGNAL_PTY_WINCH / SIGNAL_PTY_HUP` 事件；纯逻辑收敛于零依赖 `berry-vt`（完整支持 VT100/xterm-256color/TrueColor、备用屏幕缓冲 `?1049h` 与括号粘贴 `?2004h`），同时复用于单串口多窗复用器 `bmux` 与后续 GUI `berry-term`。
2. **`ProcessArgs v2` 类型化能力表与全双工流式 `IoStream` 取代 `GIFT_H` 与攒批捕获**：废除 `berry-libc` 静态 `ARGV_STR[256]`、`GIFT_H[6]` 位置复用与 `bsh` `run_output` 攒满 `Vec<u8>` 才打印的反交互路径。对齐底座 `ProcessArgs v2`，由只读启动 VMO（最高 `1MiB` `argv/envp`）加类型化 `HandleEntry { kind, arg, handle }` 表显式交付 `PA_FD(0/1/2)`（`stdin/stdout/stderr` 三流物理分离）、`PA_CWD_DIR`、`PA_SVC_DIR`、`PA_PTY_CTL`、`PA_PROC_SELF`、`PA_VMAR_SELF`、`PA_JOB_SELF`。前台交互命令默认直接继承 `PtySlave` 双工流实现零中转实时输入输出；管道与 `$()` 命令替换采用 `64KiB` 流式环形通道边产边消。
3. **基于 `ServiceDir` 能力的 `/svc` 命名空间与零特权沙箱裁剪（`bsh sandbox`）**：由 `rootmgr` 向交互登录会话注入 `/svc` 目录能力句柄（涵盖 `/svc/proc`、`/svc/fs`、`/svc/net`、`/svc/pty`、`/svc/trace`、`/svc/power`、`/svc/cbox`、`/svc/debug`），`ps`、`btop`、`free`、`berryctl`、`ping`、`curl`、`btrace` 统一经 `berry_svc::connect("/svc/...")` 建立每客独立会话，彻底消灭 `no svcmgr gift`；同时在 `bsh` 原生提供 `sandbox` 能力裁剪前缀命令（例如 `sandbox --no-net --ro /userdata/work -- untrusted_tool`），在派生子进程前于用户态构造收窄后的子 `ServiceDir` 与子目录句柄，把微内核纯能力最小特权变成一行可敲的日常命令。
4. **`bsh` 3.0 完整词法/AST 脚本引擎、二维 UTF-8 行编辑器与 `Job + SuspendToken` 原生作业控制**：将开机自测桩从 `bsh` 主二进制剥离至独立 `bsh-selftest` 测试件；新建纯核 `berry-line` 提供完整光标移动、词跳、撤销、Emacs/Vi 键位、`Ctrl-R` 增量历史搜索、4096 条持久化历史、实时语法着色与上下文补全；新建纯核 `bsh-syntax` 实现零回溯词法/AST（引号、转义、`${}`、`$()`、`$(( ))`、通配符、`2>&1`/`<`/`<<EOF`、内建与函数自由进管道、`if/for/while/case/fn` 与 `#!/bin/bsh` 脚本执行）；作业控制完全抛弃 Unix 进程组 ID 与 `SIGSTOP/SIGCONT` 模拟，直接将一个管道映射为一棵莓核 `ObjType::Job(11)`：`Ctrl-C` 调 `job_kill` 原子终止整棵管道树，`Ctrl-Z` 调 `0x3E` 持 `SuspendToken(12)` 原子冰封整棵作业树，`fg/bg` 关闭令牌即刻零损解冻恢复。
5. **纯 Rust 零外部依赖终端生产力套件（`bed`、`less`、`bmux`、`bscp` 与网络全家桶）**：依托 `berry-vt` 与 `BerryFS` 交付全屏 UTF-8 编辑器 `bed`（多缓冲、无限撤销树、正则搜索替换、语法高亮、断电交换恢复，体积 `< 120KiB`）、零拷贝 VMO 映射分页器 `less`（瞬开大日志、正则检索、`F` 实时追尾）、单串口多窗分屏与断线保活复用器 `bmux`、免重启主客机双向文件传输 `bscp`，以及基于 `netd` 2.0 + `berry-netsec` 的 `ip / ping / dig / nc / curl` 与远程加密终端守护进程 `bsshd`。
6. **微内核独有在机全栈观测与交互式源码/能力调试闭环（`btop`、`lscap`、`btrace`、`bdbg` + `--json` 铁律）**：发挥微内核结构优势，提供超越传统 Linux CLI 的在机内省与排障四件套：`btop`（16 核负载、意图调度带、VMO/Slab 账本与 IPC 吞吐实时面板）、`lscap`（透视进程句柄表、64 位 Rights、内联 Badge、Channel 对端图与 VMO 物理驻留页）、`btrace`（在机实时追踪目标进程 `berry_*` 系统调用、解码 Channel RPC 协议帧并统计尾延迟直方图）、`bdbg`（基于 `ProcessDebugCap` 与 `berry-unwind` 的在机命令行断点/观察点/调用栈/内存交互调试器，无需宿主机挂载 GDB 亦可在串口内直接断案）与 `cboxctl`（在机解码 `CBOX.LOG` 及 `ramoops` 内核崩溃黑匣子）；所有系统查询与诊断工具强制支持 `--json` 纯净机器可读输出。

## Alternatives considered

- **把 TTY 行规与伪终端塞进莓核内核态（仿 Linux `n_tty` / `/dev/ptmx`）**：数千行转义与行缓冲状态机进入 EL1 特权态不仅违背莓核微内核极简隔离宪章、抬高 `unsafe` 攻击面，且无法被用户态按会话热重启；用户态 `ptyd + IoRing VMO` 兼具同等吞吐与零特权故障隔离，故否决内核态 TTY。
- **直接交叉移植 GNU bash + GNU nano + tmux + OpenSSH（C 代码搬运）**：GNU bash/readline 为 GPLv3 触发仓库协议红线，且全套重度依赖 POSIX `fork()`、`sigprocmask`、内核进程组 `tcsetpgrp` 与庞大 C 桩层；强行在用户态模拟假 `fork` 代价极高且丧失对 `Job`、`SuspendToken`、`ServiceDir` 能力模型的原生表达力，故否决。
- **继续保留 `bsh` `run_output` 缓冲捕获，仅加一个 `run -i` 交互开关**：同一命令在带不带开关时行为割裂，用户敲 `bed a.txt`、`less log`、`ping`、`btop` 时被迫记忆特殊前缀，违背直觉肌肉记忆；直接打通 `ProcessArgs v2` 流式 `PtySlave` 继承才是正统根治方案，故否决。

## Consequences

- **正面收益**：无需等待重型 GUI 成熟，BerryOS 仅凭串口、`berry console` 或网络 `bsshd` 即可提供一套完整的类 Unix 肌肉记忆操作体验，同时亮出微内核独有的 `sandbox`、`lscap`、`btrace` 与 `--json` 原生杀手锏，满足人类开发者日常编写运行脚本、管理服务、在机调试排障与 AI Agent 自动化闭环的全部需求。
- **工程代价与约束**：需严格前置莓核 2.0 内存/IPC/Job 底座落地（消除频繁派生子进程时的页表与 Channel 泄漏），并同步完成 `berry-libc` 向 `ProcessArgs v2` 的平滑过渡（保留烟雾测试期兼容垫片直至全仓迁移收口）。
