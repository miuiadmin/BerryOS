# Agent Note: 23 号 Veda GUI 六条启示挂账（启示八 urgent——协议位窗口在关）

Status: proposed

## Problem

遗漏审计发现 research/23 号（原 20 号）Veda GUI 八条启示中六条三无悬空（GUI 线全部文档停在报告产出前）；其中**启示八与帧率意图位「同批落」的协议位预留已脱批**——GUI-2 消费侧已实施、berry-guiproto 帧率意图位已在 wire，而 buffer 对象的「可被服务端直接采样」能力位缺失，窗口正在关闭（C1 拍板时点名的同类协议破裂风险）。

## Proposal

六条逐条挂账（吸收或否决随 GUI 线各刀裁定，出处一律 research/23 号 §对照）：

1. **启示八（urgent）**：berry-guiproto buffer 对象预留「可被服务端直接采样」能力位——与帧率意图位同批的伙伴位，建议随 GUI 线下一个 wire 变更刀补位（add-only）。**2026-11-08 已落位（本刀）**：`PREPARE_F_SERVER_SAMPLABLE`（bit0，hdi 域 buffer 对象 `PrepareReq.flags`）——位认领 + 语义冻结 0（既有「flags v1 恒 0」双侧执法即冻结面，零 wire 行为变更），激活路径 = 值域收宽（scene_known 先例）；测试钉板默认 0/双侧拒。
2. **启示三**：gui-inputd 未开工——outbox 四条事件合并规则（输入事件必须合并的四种情形）可直接进其验收断言。
3. **启示二**：SETTLE 停帧语义三则（「处理过输入的帧之后再画一帧」/重复设 idle 不重置计时/计时起点含停止保活时刻）——随 GUI-3 状态机刀对账。
4. **启示五**：keep_awake 三条件 + user_active 语义模板——PM 线（berry-power/thermal）语义表挂账。
5. **启示七**：virgl 九条 workaround 表——S1 spike（GPU 线）kill criteria 逐条对照的前置阅读件。
6. **启示四**：gui-wmd（ADR #61 独立窗口守护）持系统 chrome 绘制权 = 挂死韧性——GUI-8 线评估。

## Alternatives considered

- 现在直接全吸收：被拒——六条分属 GUI/PM/S1 三条线，跨线抢刀违背并行纪律；本笔记只固化挂账防丢失（尤其启示八的时限性）。

## Consequences

23 号八条启示全部有归宿（一/六互证性质留在报告，二~八挂本账）；启示八若 GUI 线下一刀未处理，升级为独立提案。
