# Agent Note: BerryOS 全栈底座彻底重构架构裁决（规范先行 · 拒绝补丁）

Status: proposed

## Problem

[全栈架构与代码缺陷深研](../../research/2026-11-18-全栈架构与代码缺陷深研.md) 对 Meihe 微内核、内核调度器与用户态体系进行了完整设计先行审计，确认当前系统存在 15 项设计文档层结构缺陷、14 项契约空心化与 24 项源码级致命缺陷。这些问题的共性在于早期单核 MVP 阶段的临时折中（内核不拆页表靠父进程手工 `unmap`、多路等待挂全局 `WAIT_ANY` 哨兵、单客户端通道 `duplicate` 全系统共用、AI 权重直改严格抢占优先级、用策略分歧率 `< 0.1` 充当自动转正判据、8571 行无监督单体 `svcmgr`、`elf2flat` 全页 RWX 固定基址）在双核 SMP 与动态应用负载下已触及数学与安全死胡同，继续在原框架上打局部补丁只会制造更多锁序死锁与状态撕裂。

## Proposal

遵循「规范先行、方案先行、不计代价追求最彻底最优雅终态」原则，立定 [微内核与全栈底座彻底重构规格](../../plans/2026-11-18-微内核与全栈底座彻底重构规格.md) 与 [全栈底座彻底重构实施计划](../../plans/2026-11-18-全栈底座彻底重构计划.md)，执行七项根本性架构升格：

1. **硬件与内存生命周期正本清源**：落地分代钉死位图 ASID、严格硬件 W^X 与直映区 `PXN`、`DCZID_EL0` 清零与代码页 PoU 指令缓存同步；将 `AddressSpace` 与 `Vmar` 解耦，由内核在末线程退出时执行两阶段确定性页表拆解与 L3/L2/L1 表帧全回收，永久删除 `HandleTable::drain()` 的 `leak = true`。
2. **IPC 升格为「无环 `ChannelShared` + 一等 `Port` + 同步 `channel_call/reply`」三件套**：以每对象侵入式 `ObserverList` 和 `Port` 彻底废除 `WAIT_ANY` 全局哨兵；以零分配一次性 `ReplyToken` 打通跨核多跳精确 PI 树、即时回落与 `Task` 级精确代工计费；以 `SIGNAL_PEER_CLOSED` 闭合服务崩溃感知。
3. **纯对象能力根封口**：引入根 `Job` 树（配额、派生权、策略天花板、原子杀树）与细分 `Resource`（电源、策略、遥测、单槽 MMIO、SPI 中断、连续安全 DMA），升级 `BERRY_PLATFORM_LEVEL = 2` 消灭全部零句柄特权后门与每 VMO 全局共享调页池。
4. **调度器回归正统数学**：严格分离五层调度类与 `Fair` 层内双正交参数 $(w_i, r_i)$，AI 与 `Intent` 仅调节加权 EEVDF 份额权重与请求量子，根绝饥饿；以加权虚拟时钟 $V(t)$ 与有界衰减滞后量实现跨核零偏置迁移；补齐 CBS 到达不等式与 Tickless 硬件重充唤醒源；以四槽 RAII `PolicyReadGuard` 和基于 `CpuHdr`/零违约的金丝雀看门狗取代分歧率晋升律。
5. **用户态拆解与每客能力会话化**：将单体 `svcmgr` 拆分为 `rootmgr`、`devmgr`（全中断驱动）与 `appd`（强制验签拒载 + AM 闭环）；`fsmgr`、`gui-wmd`、`vnet` 全面迁入基于 `Port` 的每客户端独立会话通道，兑现不可逃逸的 `$appdata` 根句柄沙箱。
6. **兼容层与装载器现代化**：`berry-libc` 全量线程安全化，并以支持段级 W^X 与 ASLR 的标准 `ET_DYN` PIE ELF 装载器彻底取代 `elf2flat`。

## Alternatives considered

- **方案 A（局部止血打补丁）**：保留 `WAIT_ANY`、保留父进程手工 `unmap`、仅给共享 `FS_A` 换随机数 `txid`、仅把 `policy.rs` 3 槽改 4 槽而不改优先级合成公式、仅调大 `EREQ` 与 `HT_DRAINQ` 容量。否决原因：完全无法解决子进程动态 `mmap` 堆与 `pthread` 栈永久泄漏、无法恢复常驻服务在线时的全局 IPC fastpath 与多跳 PI、无法阻止共享通道跨进程窃听与吞包毒死，属于典型的叠床架屋。
- **方案 B（推倒重写单一巨型提交）**：一次性在单分支推翻全部内核与用户态代码再联调。否决原因：违背可验证工程纪律，一旦在硬件缓存、SMP 锁序与协议切换三处同时引入变动，故障定位成本极高；采用六波二十刀拓扑递进（每刀 `*face` 宿主机性质测试先行 + 独立回滚点）既不妥协终态纯度，又保证全程主干可跑可验。
- **方案 C（保留 `elf2flat` 仅扩 `USER_CODE_MAX` 上限）**：继续调大平铺二进制尺寸墙至 512KiB。否决原因：平铺格式天然抹平 `.text`、`.rodata` 与 `.data` 段边界，从根本上阻塞硬件 W^X 与 ASLR 落地，必须直接演进至标准 PIE ELF。

## Consequences

- **正面收益**：微内核隔离边界、动态负载零内存泄漏、O(1) 高并发服务多路复用、跨核软实时确定性与比例公平调度全部达到量产级微内核理论闭环，消除 QEMU TCG 与 Apple HVF / 真机 ARMv8-A 之间的隐性语义鸿沟。
- **工程代价**：平台 ABI 升至 `BERRY_PLATFORM_LEVEL = 2`，原零句柄系统管理调用与共享通道客户端需随第三至第五波同步迁移；`svcmgr` 拆分与 PIE 切换涉及构建脚本与启动编排改造，由二十把原子刀分阶段消化。
- **后续同步义务**：待各波次实施完成后，本笔记状态翻转为 `implemented`，并同批升版 `docs/` 下对应设计标准与 [架构决策](../../../docs/架构决策.md)。
