# Agent Note: 整机十维缺失拼图全栈终态架构裁决

Status: proposed

## Problem

在完成微内核底座、对数实时图形调度、场景图 GPU 卸载、响应式桌面与 CoW 文件系统共 15 份模块总体设计之后，[整机生态十维盲区全景审计](../../research/2026-11-18-整机生态十维盲区全景审计.md) 证实：若以一台真正能交付终端用户日常主力使用的现代 AI 原生操作系统衡量，BerryOS 仍存在十块结构性真空——缺少端侧模型推理与本地记忆库、缺少音频与相机编解码实时管线、缺少传输层加密 TLS 1.3/IPv6/Wi-Fi/BLE 与跨端软总线、缺少内核熵池与 FBE 静态落盘加密及锁屏门禁、缺少防偷窥剪贴板/通知/后台经纪与 Web/Wasm 生态引擎、缺少 PCIe/USB/传感器/触觉马达与真机 S3 深睡拓扑、缺少源码级断点调试器与 PMU 火焰图工具链、缺少安全校时/时区/RTL 双向排版与读屏无障碍服务、缺少独立救砖恢复环境与产线注入闭环、以及缺少基于 CoW 快照的端到端加密备份与多端状态同步。

## Proposal

秉持「方案先行、规范先行、零历史包袱一步到位」准则，一次性补齐十份正交终态模块规格（`Version: 1.0.0`）与总控实施计划，完成 BerryOS 整机顶层设计的全栈闭环：

1. **端侧智能大脑与零外泄记忆（[ai-runtime 总体设计](../../plans/ai-runtime/design.md)）**：由 `airtd` 以只读按需映射 VMO 跨全系统单份共享 `.bmod` 模型权重页，构建 CPU SIMD / 宿主 `wgpu` Compute 半虚拟化 / 真机 NPU 三阶算子后端、Paged KV-Cache 与有限状态机语法约束解码，并配套受 FBE 与域能力保护的本地加密向量记忆库 `berry-vault`。
2. **硬实时零拷贝视听与物理隐私互锁（[media 总体设计](../../plans/media/design.md)）**：以无锁零分配 EDF 硬实时音频图 `audiod` 实现 $\le 8\text{ms}$ 交互音效与焦点自动闪避；以沙箱 `mediad` 输出 `NV12`/`P010` 硬件表面零拷贝直交合成器上屏；将 `camerad`/`audiod` 采集帧门与合成器顶栏隐私指示灯在硬件/驱动层强制互锁。
3. **仅现代加密协议的全栈互联与跨端软总线（[net-conn 总体设计](../../plans/net-conn/design.md)）**：以共享环零拷贝 `netd` 2.0 承载 IPv4/IPv6 双栈与细粒度 `NetCap` 能力防火墙；纯 Rust 实现仅支持 TLS 1.3 与 QUIC/HTTP3 的 `berry-netsec`；补齐 WPA3 `wifid`、BLE/LE Audio `btd` 以及支持原生矢量 `SceneStream` 跨屏投射的 `berry-link` 分布式软总线。
4. **从真随机源到锁屏即擦除的纵深静态安全（[security 总体设计](../../plans/security/design.md)）**：内核汇聚硬件熵驱动每核无锁 ChaCha20 CSPRNG；在 `BerryFS` 原生内建 DE（直通启动）与 CE（锁屏/关机即销毁内存密钥）双级文件静态加密；落地 `keystored` 三档安全后端与 `0x85 attest`；建立最高 Z 序 `Keyguard` 锁屏与防伪造签名 `HardwareAuthToken`。
5. **零偷窥跨应用协同与 WASI 0.2 双核生态（[app-interop 总体设计](../../plans/app-interop/design.md)）**：由合成器仲裁安全 `PasteButton` 单次派发只读 VMO 根绝剪贴板偷窥；落地「Picker 即单对象句柄权限」、三档投稿 `notifyd` 与统一合并唤醒 `workmgr`；构建站点隔离轻量 `berry-webview` 与天然纯句柄同构的 **WASI 0.2 WebAssembly 组件运行时** `berry-wasm`。
6. **IOMMU 圈禁的用户态真机外设、传感器与触觉物理栈（[soc-peripherals 总体设计](../../plans/soc-peripherals/design.md)）**：`devmgr` 2.0 结合 SMMUv3/VT-d 页表隔离运行 PCIe/NVMe/USB xHCI 用户态驱动；落地 `sensord` 姿态/环境光/健康融合中枢、与 VSync 动画微秒级锁拍的 `hapticsd` 线性马达波形引擎，以及真机电源轨引用树与 S3 逆序挂起恢复协议。
7. **无 `ptrace` 纯能力调试与全栈可观测工具链（[devtools 总体设计](../../plans/devtools/design.md)）**：以进程 `DebugExceptionChannel` 支撑宿主 LLDB/GDB 源码断点与硬件内存观察点；以零分配 `.eh_frame` 展开库 `berry-unwind`、硬件 PMU 火焰图 `berry perf`、Perfetto 时间线服务 `traced` 与 `berry ui-inspect` 赋能全栈排障。
8. **全链路逻辑方向全球化与原生 AI 无障碍（[i18n-a11y 总体设计](../../plans/i18n-a11y/design.md)）**：`timed` 融合 RTC 与加密 NTS 授时并共享只读 `tzdb.vmo`；`berry-i18n` 实现 `.blp` 零拷贝热切换与 UAX #9 BiDi 自动 RTL 镜像；`a11yd` 联动 `airtd` 实现超低延迟读屏、实时字幕与合成器色觉矫正。
9. **4MiB 独立不死砖救援与产线封签（[recovery 总体设计](../../plans/recovery/design.md)）**：物理隔离的 `< 4MiB` `BerryRecovery` 支撑双槽全毁联网/USB 签名重刷与 100ms 密码学擦除恢复出厂，强制执行「Bootloader 解锁必毁密钥」铁律并内建工厂 CIT 自检与熔丝注入。
10. **榨干 CoW 红利的零知识时间机器与多端同步（[backup-sync 总体设计](../../plans/backup-sync/design.md)）**：基于 `BerryFS` 毫秒级只读代数快照、代数差量剪枝与客户端 XChaCha20-Poly1305 零知识加密实现无停顿云备份、升级连数据一键回退、扫码满速克隆换机与 `berry-crdt` 多端无冲突实时同步。

## Alternatives considered

- **备选一（端侧 AI 完全依赖云端 API 转发，不在系统内建 `airtd` 推理与本地记忆库）**：落选原因——断网场景、飞行模式及高隐私个人数据（短信、相册、无障碍实时读屏与输入法语音）绝不允许强制上云且无法承受百毫秒级公网往返抖动；系统级统一权重共享 VMO 是唯一能在有限终端内存跑通多应用 AI 的解法。
- **备选二（沿用传统全局可读剪贴板 + 弹窗询问权限，沿用 POSIX `ptrace` 调试接口）**：落选原因——弹窗询问导致用户疲劳盲点同意，而合成器安全粘贴控件从物理交互层即可无感杜绝偷读；`ptrace` 强行篡改进程父子拓扑且存在大量信号竞态漏洞，纯 Capability 异常通道更契合莓核架构。
- **备选三（为兼容老旧服务器在网络加密栈保留 TLS 1.0/1.1/CBC，或直接静态链接 C 语言 OpenSSL/FFmpeg 进特权服务）**：落选原因——历史降级协议与非内存安全 C 解码器是过去二十年移动系统远程代码执行（0-click RCE）头号温床；砍断 TLS 1.2 以下遗留面并将媒体编解码与网页渲染关入零句柄纯沙箱进程，才能实现架构级免疫。
- **备选四（不做 WASI 0.2 组件运行时，第三方跨语言应用完全等待完整 Linux 容器兼容层）**：落选原因——重型兼容层启动慢、内存开销大且权限粒度粗；WASI 0.2 组件模型天然具备纯句柄安全边界与毫秒级冷启动特性，能以极小代价迅速引入多语言插件与轻量应用生态。

## Consequences

- **全栈版图彻底闭合**：至此 BerryOS 共拥有 **25 份边界正交、互相咬合的模块总体设计（`plans/*/design.md`）**，从微内核一行汇编启动直至端侧大模型、真 GPU 合成、4K 多媒体、TLS 1.3/BLE/跨端总线、FBE 加密锁屏、LLDB 火焰图、无障碍读屏、救砖恢复与时间机器备份无一遗漏。
- **执行承接**：十大新模块按基础依赖分为六个演进波次（Wave E0–E5 共 24 刀），统一收敛于 [整机十维补全终态实施总计划](../../plans/2026-11-18-整机十维补全终态实施总计划.md) 分步推进，不冲击正在执行的内核与图形首波地基刀序。
