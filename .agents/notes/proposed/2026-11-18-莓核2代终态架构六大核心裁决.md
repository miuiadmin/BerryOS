# Agent Note: 莓核二代终态架构六大核心裁决

Status: proposed

## Problem

[莓核全核深度体检报告](../../research/2026-11-18-莓核全核深度体检报告.md) 揭示莓核（Meihe）存在结构性代差：上层调度与可观测纯核外迁已达量产水准，但底层内存回收、多路复用唤醒、锁粒度与硬件抽象仍停留在单核/双核早期过渡态，引发 9 项 P0 级隐患（TLB 对飞死锁、ASID 撞号破隔离、退出泄漏致后台回收归零、`WAIT_ANY` 哨兵废除 IPC 快路径、全局 `KERN_LOCK` 与 `u8` 锁位图卡死 2 核上限、`policy.rs` 三槽 RCU 满槽风险、计费串账与能力门控破口）及真机落地障碍（GICv2 锁死、轮询驱动、无守卫页、EL1 panic 跨重启丢失、内核逆向依赖 `user/`）。需要在不背离 [架构综合纲领](../../../docs/架构综合纲领.md) 单一中心与排除 8 问的前提下，一次性锁定最优雅、最强大的终态内核设计。

## Proposal

确立莓核 2.0 六大核心架构裁决，统一收口于 [meihe 总体设计](../../plans/meihe/design.md) 并按 [莓核五波十六刀演进实施计划](../../plans/2026-11-18-莓核五波十六刀演进实施计划.md) 推进：

1. **裁决一（文档与契约治理：双层正交模型）**：以 `.agents/plans/meihe/design.md`（`Type: spec`，`Version: 2.0.0`）作为微内核内部总体设计的唯一权威承载点；`docs/` 下五大跨层契约（ABI、能力、IPC、内存、安全隔离）遵守「`standard` 只写已生效现行契约」原则，在对应波次代码验收同批原地升格为 `Type: standard` 并修正存量漂移，杜绝超前承诺伪造现行态。
2. **裁决二（多路复用与同步 RPC：`Port` 观察者链 + `channel_call` 定向让片）**：引入 Zircon 同构的 `ObjType::Port` 对象与可等待对象头部内嵌侵入式观察者链表，`object_wait_async` O(1) 投递定长 `PortPacket`，兼容保留的 `object_wait_many`（≤16 路）改用内核栈帧局部观察节点挂链，彻底废除 `WAIT_ANY` 全局哨兵（推翻 [sleepq per-key 唤醒链笔记](../implemented/2026-11-12-sleepq-per-key-wake-chain.md) 中保留全局哨兵兜底的过渡假设），使全系统 Channel Fastpath 稳态恢复 100% 生效并统一桥接 `berry-libc` 的 `epoll`/`poll`/定时器/信号；同时新增 `channel_call` 原语（内核级请求-应答 `txid` 配对 + 同带剩余时间片定向借予对端线程），解决同优先级常规 RPC 0% 直切与 `MsgBilling` 请求/应答不分两道难题；PM/AI/遥测热路径同步补齐真共享 VMO 环形映射。
3. **裁决三（权限派生、多客鉴别与撤销：`Job` 树 + 内联 `Badge` + `RevokeEpoch`）**：实装 `ObjType::Job(11)` 构成严格进程与资源容器树，`process_create` 强制验父 `Job` 的 `RIGHT_MANAGE`，沿父链原子核算物理内存字节（覆盖匿名页、ZFOD 与页表帧）、活进程数与能耗账；在 `HandleTable` 槽位内联不可伪造的 64 位 `badge`（经 `handle_mint` 一次性烙印，服务端 `recv` 随包获知内核认证身份，单通道零拷贝服务任意多客户端）；引入单调 64 位 `RevokeEpoch` 纪元槽实现 O(1) 无跨表锁的会话级/子树级能力撤销（失配即返 `BERRY_ERR_DEAD = -52`），协同确定性退出页表/VMO 拆卸与 [am 后台处置 Q1–Q3 裁决](../implemented/2026-11-08-am-q1q2q3-rulings.md) 闭合五级内存回收环。
4. **裁决四（多核并发与目标规模：无全局大锁细粒度分层 + 一步锚定 `MAX_CORES = 16`）**：剥离高频路径上的全局 `KERN_LOCK` 与 `0x2E` 全核队列预取，改为 `AtomicUsize` 对象引用计数、每进程句柄表锁、每通道对锁、每核 Slab Magazine（支持空页退还 buddy）与每核 Buddy PCP 弹匣；将 `Task::held_locks: u8` 拆分为纯调度标志位与核无关锁秩栈，跨核双队列严格按核号升序加锁；用单寄存器位图 `CpuMask(u16)` 一步支撑 `MAX_CORES = 16`（覆盖 8–12 核异构手机与 16 核桌面 PC）；`policy.rs` 快照槽数定为 `MAX_CORES + 2`（18 槽）且出窗立清 `HAZARD[cpu]`；`REAPQ` 与 `HT_DRAINQ` 改为每核本地排空。
5. **裁决五（工作区拓扑与 `unsafe` 收敛：`faces/` 聚拢 + 独立 `ipc/` + 零逆向依赖）**：把 `berry-em` 与点阵字形核下沉至内核纯逻辑层，立法严禁内核层 crate 依赖 `user/` 或 `drivers/`；将仓根平铺的 39 个 `*face` crate 收拢入 `faces/<name>/`（Cargo 包名不变），落成独立 `ipc/` 核心 crate，拆分巨型 `main.rs`/`syscall.rs`；以 `PerCpu<T>`、`StaticOnce<T>`、`PinnedObj<T>` 安全原语替代散落裸指针与 `static mut`，将内核生产面 `unsafe` 密度从 10.54% 压降至 3% 以下。
6. **裁决六（真机硬件底座与节奏：五大窄 `berry-hal` Trait + GICv2/v3 双栈 + `Interrupt` 直通 + `ramoops`）**：抽取零 `unsafe` 的 `berry-hal` 五大窄接口（CPU、MMU 含 W^X/PAN/VIPT I-cache/动态 `IPS`、IRQ 含 GICv2/GICv3 自适应与 APIC、Timer、SMP），让 `arch/x86_64` 直接链接真实 `berry-kernel`；实装 `ObjType::Interrupt(8)` 驱动 `vblk`/`vnet`/`gui-inputd` 全面告别睡眠轮询；划定物理内存顶端 16KiB 免清零 `ramoops` 持久崩溃区（CRC32C 校验）使 EL1 panic 跨热重启落盘 `CBOX.LOG`；推进节奏采「四件套规范即刻立宪 → Wave 0 P0 止血首刀紧接实施」。

## Alternatives considered

- **在 `WAIT_ANY` 上建专用哨兵哈希桶而非引入 `Port`**：只能把全表扫描缩减为扫全部多路等待服务（`console`/`guifbd`/`wmd` 仍每次被无关通道虚假惊醒，且 `find_single_waiter_locked` 仍因无法排除哨兵监听同一端点而废除 Fastpath，`epoll` 超 16 路分批轮转缺陷亦无解），治标不治本，弃。
- **照搬 seL4 全局双向能力派生树（CDT）做 `revoke`**：每次 `duplicate`/`transfer`/`close` 均需跨进程句柄表加锁维护双向指针链，与多核细粒度无大锁目标正面冲突且锁序极重；`Job` 树 + `RevokeEpoch` 以原子代号比对即可 O(1) 无锁达成会话与驱动热换撤销，弃全局 CDT。
- **`MAX_CORES` 仅扩至 4 或 8，或一步拉到 64+**：4/8 核不足以覆盖 10–16 核现代桌面/工作站处理器（违 PC 高性能支柱），64+ 核则令核位图跨出 `u16`/单缓存行并引入 NUMA 复杂度税（违排除项「不缴服务器极限吞吐税」）；16 核是 `u16` 单指令位图与手机/PC 双端全覆盖的最优解。
- **不立 `plans/meihe/design.md` 而直接把未实现的 2.0 特性写进 `docs/` `standard`**：违反 Curia 2.5「只写当前状态」与「未做进 `plans/`、现行进 `docs/` 标准」的铁律，会导致文档再次超前代码形成虚假契约，弃。

## Consequences

- **收益**：一次性在架构层闭环全部 9 项 P0 隐患，打通「压力感知 → L0/L1/L2/L3 真实物理页回收」、「O(1) `Port` 多路唤醒 + 100% Channel Fastpath + 同带微秒级 `channel_call`」、「无全局大锁 16 核线性扩展」与「GICv3 + 中断驱动真 Tickless + EL1 panic 跨重启不丢账」四大核心能力。
- **代价与约束**：新增约 6–8 个 add-only 系统调用号（`port_*`、`channel_call`、`handle_mint`、`job_*`），严格遵守既有号签名零破坏；`faces/` 目录搬迁需同步根 `Cargo.toml` 与路径脚本，排入 Wave 4 独立原子提交以免干扰并行会话。
- **后续盯防点**：Wave 0 落地 `W^X` 页表权限前，须先核验用户态 ELF 段对齐（确保 `.text` 与 `.data`/`.bss` 不共处同一 4KiB 页），防止只读可执行页误拦合法数据写。
