# Agent Note: BerryOS 图形合成、SDK、开机桌面与模拟器终态架构裁决（规范先行 · 一步终态）

Status: proposed

## Problem

[GUI 与 SDK 及启动模拟器全栈深研](../../research/2026-11-18-GUI与SDK及启动模拟器全栈深研.md) 证实，BerryOS 用户面与开发者面栈存在 36 项互相锁死的结构性缺陷：多进程共享单客户端通道（`WMD_CLI_DUP` / `INPUT_A`）引发 RPC 应答互截与输入抢夺、`GIFT_H` 4 槽位置编码触顶错位、`guifbd` 无每窗离屏表面的“单帧缓冲直写 + 系统栏带重放”伪合成、全管线无 8-bit Alpha 混合与抗锯齿、`berry-ui` 1x 硬编码控件与 3x `pattern.rs` 双轨撕裂、零 UTF-8/CJK 矢量文字与缺位 IME、内核紧循环清黑闪烁 Splash、Launcher 正常开机强插自动翻页自测、以及宿主模拟器 VNC 33fps 硬顶与 `RamSource` 稀疏采样吞帧。在底座线已立定 [meihe 总体设计](../../plans/meihe/design.md) 与 [ipc 总体设计](../../plans/ipc/design.md)（提供 `Port`、`channel_call/reply`、`SIGNAL_PEER_CLOSED`、`ProcessArgs v2`、`Interrupt` 零轮询与 PIE ELF）的前提下，继续沿用单帧缓冲直写、1-bit 透明键与手抄百行样板代码的过渡方案将彻底锁死 BerryOS 的用户体验与第三方应用生态上限。

## Proposal

遵循「规范先行、方案先行、不计代价直接建成最彻底最优雅终态」原则，立定顶层现行契约 [GUI 合成与 SDK 终态标准](../../../docs/GUI合成与SDK终态标准-v2.0.md)、四大子系统模块总体设计（[compositor](../../plans/compositor/design.md)、[ui-sdk](../../plans/ui-sdk/design.md)、[desktop-boot](../../plans/desktop-boot/design.md)、[emulator](../../plans/emulator/design.md)）与 [GUI 与 SDK 及模拟器彻底重构计划](../../plans/2026-11-18-GUI与SDK及模拟器彻底重构计划.md)，执行八项根本性架构升格：

1. **窗口管理、显示合成与输入分发合一为单进程场景图合成器（`berry-compositor`）**：淘汰 `gui-wmd` 同步阻塞中继 `guifbd` 的双进程串行跳板与单 FB 带缓存补丁，对齐 Wayland / macOS WindowServer / Fuchsia Flatland 正统模型——由单一 `compositor` 进程通过内核 `Port` 承载所有客户端独立 `SurfaceSession`，统一执掌分层场景图（SceneGraph）、每窗口离屏双/三缓冲交换链（Swapchain + Acquire/Release Fence）、从前向后遮挡剔除、脏矩形增量合成、系统全局手势竞技场与焦点定向输入路由，将“输入→目标应用”与“应用提交→上屏合成”严格收敛为零中继 **1 跳**。
2. **确立 8-bit 预乘 Alpha（Premultiplied RGBA8888）与 Span+SIMD 抗锯齿渲染管线**：彻底废除全管线 1-bit 透明键限制，在 `berry-gfx` v2 实装行级 Span 化与 AArch64 NEON / x86 SSE2 向量化的 `SrcOver` 预乘混合、SDF 解析覆盖率抗锯齿圆角、解析高斯盒阴影、渐变画刷与合成器侧 Dual-Kawase 实时背景模糊，同时保持显式 `RenderPass / CommandBuffer` 窄接口以便无感挂载未来 Vulkan/Venus 硬件后端。
3. **内置纯 Rust `no_std` 矢量字体光栅化与 UTF-8/CJK + 真 `softimed` 输入法栈**：引入紧凑 TrueType/OpenType 轮廓光栅与 8-bit 灰度 LRU 字形图集（`berry-text`），一步打通中英文混排、多字重任意字号缩放与 Unicode 断行；同步落地独立 `SERVICE` 层 `softimed` 守护进程与 `preedit/commit/cursor_rect` 双向输入法协议。
4. **统一 `vp` 响应式信号 UI 引擎（终结双轨控件分裂与小容量硬帽）**：废除 1x 物理像素内建几何与 `TRUE_CORNERS` 开关，将 `berry-ui` v2 全部组件统一收敛至逻辑单位 `vp`、单遍约束布局（完整 Flex/Grid/`Insets`/三档断点）、细粒度 `Signal<T>` 响应式重绘、开放 `Widget` 扩展 Trait 与 `VirtualList` 视口虚拟化复用，解除 `512` 节点、`64B` 文本与 `8` 输入框静态硬顶。
5. **零样板 `berry-sdk` 与编译型包工程体验**：构建基于内核 `Port` 的统一异步 `AppLoop`（UI 帧钟、窗口事件、定时器、网络/文件异步通道与子进程管道同环 O(1) 复用），以 `#[berry_sdk::app]` 宏封装 `ProcessArgs v2` 能力提取、交换链握手与冻结/墓碑状态序列化；清理 7 对双胞胎应用目录；升级 `mkapp` 支持带注释的标准源码 `manifest.toml` 编译产出规范签名 `.bap`。
6. **UEFI → `bootsplashd` → `compositor` 全链路零清屏无缝启动交接**：`berryboot` 动态解析 UEFI 内存图、优选原生 GOP 模式并绘制首帧品牌徽标；内核态彻底退出动画循环，由 `rootmgr` 首拍拉起用户态 `bootsplashd` 原位增量绘制 60Hz 平滑进度，最终经 `compositor` 执行 Splash 图层至桌面的交叉溶解揭幕；一切自检探针 100% 剥离出生产开机路径。
7. **微壳层解耦桌面（`berry-shell`）与预测性返回/真多任务视图**：将系统状态栏与控制中心、桌面图标网格与 Dock、多任务卡片视图（实时消费窗口表面纹理与墓碑快照缩略图）模块化分离，打通图标到窗口连续弹簧形变（Hero Morph）与 `OP_WM_BACK` 全栈预测性返回手势。
8. **宿主模拟器 `wgpu` + D-Bus 共享图 120fps 呈现、双架构原生加速与亚秒级 QuickBoot**：以 QEMU `-display dbus,p2p=on` 共享内存纯 damage 流配合宿主 `wgpu` GPU 合成取代 33fps VNC 与 `RamSource` 轮询，重塑完整高分屏悬浮工具栏与剪贴板/文件/音频生产力桥接，支持 x86_64 宿主原生运行 `x86_64 + KVM/WHPX` 镜像，并引入 Golden Snapshot 实现 `< 500ms` 秒开进桌面。

## Alternatives considered

- **方案 A（保留 `gui-wmd` 与 `guifbd` 双进程分离，仅给 `gui-wmd` 加每客通道并继续用带缓存重放）**：否决。窗口焦点、Z 序变换动画、脏区遮挡计算与输入命中在物理上共享同一棵实时场景树；双进程分离迫使每一帧 `SUBMIT` 额外跨一次进程中继或异步拉表（存在固有快照撕裂窗口），且单帧缓冲带重放永远无法支持非全屏浮窗、窗口缩放转场与多任务实时缩略图。
- **方案 B（直接移植第三方重型 C++ 图形栈如 Skia / Mesa-Virgl / Flutter Embedder）**：否决。违背 BerryOS 全栈纯 Rust 自研、最小可信计算基（TCB）与确定性编译门禁（ADR #51）；数百万行外部 C++ 依赖会摧毁微内核客户端的轻量内存足迹与可审计性。自研 Span+SIMD 2D 矢量混合核 + 轻量 `no_std` TTF 光栅器在 < 8,000 行纯安全 Rust 内即可满足全部现代桌面与移动 UI 需求。
- **方案 C（保留 `ViewKind` 1x 像素常量以维持旧单元测试哈希不变，仅外包一层缩放包装器）**：否决。为迁就过渡期测试夹具而保留错误抽象正是导致 `ViewKind` 与 `pattern.rs` 双轨撕裂的根源；应直接以 `vp` 响应式契约重建 v2 组件规范并刷新 golden 基准。
- **方案 D（在内核定时器中断里做开机进度条 60Hz 动画插值）**：否决。内核态在多核调度下抢写帧缓冲既违反微内核最小机制边界（7fd1709c 判例），又无法与用户态合成器做交叉溶解过渡；由早期用户态 `bootsplashd` 持有帧缓冲直至移交 `compositor` 才是同 Plymouth / Android BootAnimation 一致的正统解。

## Consequences

- **正面收益**：彻底消除多应用并发互截与输入错乱，内存占用从“每窗固定全屏 8.29MB”降至按实际窗口尺寸 + 冷后台 `DISCARDABLE` 零驻留；视觉表现一步跃升至真抗锯齿圆角、柔和阴影、毛玻璃、中英文矢量排版与 120fps 跟手弹簧转场；第三方开发者仅需数十行声明式 Rust 代码即可构建完整沙箱应用；模拟器日常启动压缩至亚秒级。
- **工程代价**：`berry-guiproto` 升级至 v2 面向会话与交换链的新契约（旧 `SYS_SURFACE_ID=0xFFFF` 与全局共享句柄退役），`gui-wmd` 与 `guifbd` 合流重构为 `berry-compositor`，`berry-ui` golden 像素哈希随真圆角与 8-bit 混合切换需成批重钉；全部改造由六波二十四把原子刀按拓扑依赖渐进交付。
- **既有过渡计划处置**：本裁决及配套终态计划生效后，前期阶段性计划（波 1/波 3/波 4 及图标透明局部止痛案）中已完成部分留存史实，未完成的过渡补丁项整体并入终态计划统一清偿。
