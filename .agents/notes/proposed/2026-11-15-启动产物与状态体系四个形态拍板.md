# Agent Note: 启动产物与状态体系四个形态拍板

Status: proposed

## Problem

调研（[2026-11-15-启动产物配置与日志AI可读性调研](../../research/2026-11-15-启动产物配置与日志AI可读性调研.md)）确认宿主侧半套体系、客机侧零体系后，建设形态有四个问题悬而未决：失败现场保留策略、直跑族并轨形态、x86/EFI 面是否同期、持久化适用面。不先定形态，阶段规格无法细化。

## Proposal

用户于 2026-11-15 授权「做，彻底规划好」，四案按建议定：

1. 保留策略：失败自动保留、成功默认删——`berry run/shot` 在 marker 失败、超时、panic 分支自动触发 run 目录保留；smoke 失败必留日志。
2. 并轨形态：终态全量走 berry CLI 起 QEMU；过渡形态（justfile 直跑入口包 tee 落 `out/logs/`）先行，阶段四收口时并轨。
3. ARM64 主线优先；x86/EFI 面随阶段四顺手收，不单独开路。
4. 确定性面与持久面按启动方式分流：smoke/CI 路径保持每次重造盘的零残留（确定性是测试根基），持久化（数据盘复用、vars.fd 复用、/cfg 首启铺开）只走设备壳 profile 路径（shell / desktop / berry device start）。

## Alternatives considered

- **全保留（不删任何 run 目录）**：磁盘无限增长，shot 类高频操作很快堆满；落选。
- **维持即焚 + 人手动 --keep / SMOKE_KEEP_LOG=1**：调研证实失败现场恰是人最想不到要留的时候丢的；落选。
- **B 族另造第二套留痕目录**：调研裁决即「两套体系并立」是病根，再发明第二种形态违背宿主留痕单形态原则；落选。
- **全量持久化不分流**：破坏 smoke/CI 的确定性根基（零残留是被 315 测试与 marker 谓词依赖的特性）；落选。
- **x86 同期全套**：面铺太大拖慢 ARM64 主线；落选。

## Consequences

AI 取证面从「设备壳半边」扩到全启动方式；客机获得跨启动状态，从演示机走向日用机；smoke 确定性不受影响；代价是 berry CLI 与 justfile 双入口在过渡期并存两套留痕形态（阶段四消除），且设备壳路径的测试需要补「复用盘二启可见一启写入」类新断言。
