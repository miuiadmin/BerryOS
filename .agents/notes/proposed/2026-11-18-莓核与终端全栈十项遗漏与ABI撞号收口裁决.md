# Agent Note: 莓核 2.0 与终端全栈十项遗漏及 ABI 撞号收口裁决

Status: proposed

## Problem

在完成莓核 2.0 四模块规格与终端优先（CLI-First）三模块规格合入 `main` 后，针对全系统 40 模块合龙总纲、[tools/abi.toml](../../../tools/abi.toml) 跨分支实况与纯命令行独立操作/全栈调试场景执行拉网复核，发现 10 项遗漏与接缝冲突：

1. **ABI 系统调用两处撞号**：`berry_channel_call` 拟用的 `0x57` 在集成分支 `wip/sched-1.1` 已被已上线的 `channel_recv_n`（批量收消息）占用；中断组 `0x72 / 0x74` 在 [abi.toml](../../../tools/abi.toml)（`0x72 = bind_irq`）、[hal 总体设计](../../plans/hal/design.md)（`0x74 = interrupt_ack`）与合龙总纲（`0x72 = interrupt_ack`、`0x74 = bti_create`）三处定义矛盾。
2. **新内核对象缺 `BERRY_OBJ_*` 枚举号**：`Port`、`Epoch`、`Pager`、`Bti`、`Pmt`、`Guest`、`Vcpu` 七类 2.0 对象尚未分配唯一类型号，阻碍 `0x07 object_get_info` 与 `lscap` 统一解码。
3. **无头纯终端启动（Headless Boot）缺口**：现役启动链强绑 GUI 与 `virtio-tablet` 认领门，无屏幕或无鼠标拓扑会直接卡死。
4. **用户态接管串口后的内核死锁逃生盲区**：日常串口移交用户态 `consoled` 后，若用户态整体死锁将丧失串口内核排障入口。
5. **路径执行与 `$PATH` 跨卷搜索缺口**：漏定 `./script.sh` 相对/绝对路径直跑与跨读写 `BerryFS` + 只读 `BerryROFS` 的 `$PATH` 检索。
6. **管道破裂（`EPIPE/SIGPIPE`）与强杀 `EOF` 闭环缺口**：下游 `head` 早退时上游未默认按 `141` 收敛，被强杀进程关闭写端唤醒下游 `0 (EOF)` 的跨层契约未显式钉死。
7. **单串口动态窗口缩放（`WINCH`）与二进制传文件（`bscp`）带外复用缺口**：仅靠启动期被动查询无法感知运行期宿主窗口拖拽，裸串口传文件易与可见字符混流。
8. **中文宽字符列宽多源漂移隐患**：`berry-vt`、`berry-line`、`bed`、`less` 与 `berry-libc` 缺共享 `utf8width` 单一事实源。
9. **系统级命令行运维缺 4 组工具**：缺服务与包控制（`svcctl / pkg`）、归档压缩校验（`tar / zstd / sha256sum`）、外设中断与电源时钟控制（`lsdev / lsirq / powerctl / timedatectl`）及内核白盒自检锁账工具（`kctl`）。
10. **全局路径、术语表与索引接缝**：持久日志路径需与合龙总纲 `/data/system_de/log/` 统一，新核心术语与标准版本需同步入册 [GLOSSARY.md](../../GLOSSARY.md) 与 [索引.md](../../../docs/索引.md)。

## Proposal

一次性在规格、标准与合龙总纲层彻底封死全部 10 项缺口：

1. **锁定零碰撞 ABI 号位与 `BERRY_OBJ_*` 枚举（`13..=19`）**：保留 `0x57` 给 `berry_channel_recv_n`，将 `berry_channel_call` 定位于 `0x5C`（与 `0x5B berry_channel_reply` 成对）；保留 `0x71 berry_interrupt_create`、`0x72 berry_interrupt_bind`、`0x73 berry_map_device_memory`、`0x74 berry_bti_create`、`0x75 berry_bti_pin`，将 `berry_interrupt_ack` 定位于 `0x7A`；统一冻结 `BERRY_OBJ_PORT = 13`、`BERRY_OBJ_EPOCH = 14`、`BERRY_OBJ_PAGER = 15`、`BERRY_OBJ_BTI = 16`、`BERRY_OBJ_PMT = 17`、`BERRY_OBJ_GUEST = 18`、`BERRY_OBJ_VCPU = 19`。
2. **确立 `boot.mode = headless` 极速无头启动与内核紧急串口 `BREAK` 逃生钩子**：启动参数指定 `headless=1` 或探测无 GOP 显示/无指针设备时，`rootmgr` 跳过全部 GUI 组件，`< 150ms`、`< 8MiB` 内存直拉 `consoled + ptyd + bmux/bsh`；在 `dev` 解锁模式下，HAL 串口中断入口拦截硬件 `BREAK + 单键`（`t` 16 核回溯 / `l` 八秩锁表与 PI 边 / `m` 内存账本 / `r` 写 `ramoops` 热重启），即使用户态全冻仍可一秒断案。
3. **闭合单串口多路复用、`utf8width` 单源、路径执行与 `SIGPIPE(141)` 管道语义**：优先经第二路 `virtio-console` 控制口（`berry-ctlport`）承载实时 `Winsize` 与 `bscp` 数据帧，单路物理 UART 自动回退 OSC `777/778` 分帧协议；下沉零依赖 `faces/utf8width` 供终端、编辑器与 `libc` 五处同源计算字符列宽；`bsh` 支持含 `/` 的相对/绝对路径直跑与跨 `/userdata/home/bin:/bin` 的 `$PATH` 检索；`berry-libc` 向 `PEER_CLOSED` 管道/PTY 写入收到 `-EDEAD` 时默认以退出码 `141` 终止（除非显式忽略 `SIGPIPE`），内核 `Teardown-Before-Drain` 回收句柄确保下游读者立即收到 `0 (EOF)`。
4. **补齐 4 组系统运维 CLI 并对齐全局路径与术语台账**：在 `cli-suite` 纳入 `svcctl / pkg`、`tar / zstd / sha256sum`、`lsdev / lsirq / powerctl / timedatectl` 与 `kctl`；持久系统日志统一归 `/data/system_de/log/`，编辑器交换区归 `/userdata/home/.cache/bed/`；同步更新合龙总纲、`GLOSSARY.md`、`docs/索引.md` 与终端实施计划刀号映射。

## Alternatives considered

- **强行覆盖 `0x57` 或把 `interrupt_bind` 与 `interrupt_create` 合并删掉 `0x72`**：覆盖 `0x57` 会在双线合流时直接破坏已落地 `channel_recv_n` 调用方；删改在册 `0x72` 违背 [tools/abi.toml](../../../tools/abi.toml) 单源冻结纪律，分配空号 `0x5C` 与 `0x7A` 零历史包袱，故否决改旧号。
- **无头环境仍拉起虚拟帧缓冲空跑 GUI 全家桶**：白白吃掉数十 MB 内存与启动耗时，违背嵌入式网关与轻量 AI 沙箱定位，故否决。

## Consequences

- 全仓 40 模块合龙总纲、莓核 2.0 规格、`abi.toml` 与双分支已落地号位实现 100% 零碰撞闭环。
- 纯命令行形态从「开机引导 → 日常编码运维 → 服务包管理 → 用户态/内核态死锁现场断案」不再留任何功能盲区，且在里程碑 `M-Alpha` 完成后即可独立先行交付，无需等待重型图形桌面。
