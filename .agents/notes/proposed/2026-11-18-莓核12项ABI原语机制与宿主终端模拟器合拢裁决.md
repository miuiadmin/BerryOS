# Agent Note: 莓核 12 项 ABI v2 原语内部机制补完、宿主模拟器合拢与 `berry-libc` 零改兼容裁决

Status: proposed

## Problem

在第一轮十项遗漏与 ABI 撞号收口后，使用跨规格自动化脚本对全系统 40 模块合龙总纲、莓核四模块规格、[emulator 总体设计](../../plans/emulator/design.md)、[fwcfg-keys.toml](../../../tools/fwcfg-keys.toml) 与 `berry-libc` 标准库支撑面开展二次拉网核查，定位 6 项深层遗漏：

1. **内核四模块缺 12 个已归口 ABI v2 原语的内部机制**：合龙总纲已将 `vmo_seal(0x1E)`、`vmar_query(0x1F)`、`pager_create(0x25)`、`object_get_info(0x07)`、`futex_wait/wake(0x55/0x56)`、`timer_create/set(0x62/0x63)`、`bti_pin(0x75)`、`resource_create(0x76)` 以及 `restricted_enter/kick(0x4A/0x4B)`、`guest/vcpu(0x77..0x79)` 归口至 `meihe/mm/ipc/hal`，但对应内核规格与五波十六刀计划尚未定义其内部数据结构、锁序与落刀排期。
2. **宿主模拟器与 `fw_cfg` 尚未合拢客机终端协议**：[fwcfg-keys.toml](../../../tools/fwcfg-keys.toml) 已有键 `opt/berry/bootmode`，无头模式应直接扩充其枚举而非另起新键；且宿主侧 `emulator/design.md` 尚未登记 `--boot-mode headless`、`berry console` 挂载 `berry-ctlport` 实时转发宿主 `SIGWINCH`、`berry push/pull` 与 `berry ssh`。
3. **`berry-libc` 缺支撑 Rust `std::process::Command` 与全屏工具的 6 项映射**：`posix_spawn` 文件动作转 `PA_FD`、`pipe2`、`dup2/fcntl`、基于 `Port` 跨类型统一 `poll/select/epoll` 与 `BerryFS` `S_IXUSR` 可执行位尚未落契约。
4. **终端特权分级与无 SUID 提权模型缺口**：需区分管理员会话（`OperatorSession`）与普通受限用户会话，并提供 `whoami / id / elevate` 纯能力提权机制。
5. **机内离线手册（`man`）、默认环境变量与宿主机剪贴板互通（OSC 52）缺口**：缺少开箱即用的 `man <cmd>`、登录四大环境变量与跨端选中即复制的 OSC 52 通路。
6. **存量跨模块错链笔误**：[compat 总体设计](../../plans/compat/design.md) 将文件系统通道误链至崩溃黑匣子 `cbox`。

## Proposal

1. **补齐莓核 12 项 ABI v2 原语机制并排入五波十六刀计划**：
   - 在 [mm 总体设计](../../plans/mm/design.md) 定义 `0x1E vmo_seal`（校验 `writable_mapcnt == 0` 原子封死写/扩缩容）、`0x1F vmar_query`（48B `VmarRegionInfo`）与 `0x25 pager_create`（`ObjType::Pager(15)` 独立 `Port` 异步投递缺页包）；
   - 在 [ipc 总体设计](../../plans/ipc/design.md) 定义 `0x07 object_get_info` 六大权威 `topic`（`HANDLE_BASIC / PROCESS_STATS / PROCESS_HANDLES / JOB_STATS / VMO_INFO / KMEM_STATS`）与 `0x55/0x56 futex_wait/wake`（共享 VMO `(vmo_koid, off)` 与私有页 `(aspace_koid, va)` 统一 64 散列桶键 + PI 衔接）；
   - 在 [hal 总体设计](../../plans/hal/design.md) 与 [meihe 总体设计](../../plans/meihe/design.md) 定义 `0x62/0x63 Timer`（每核最小堆 + `slack` 合并唤醒）、`0x75 bti_pin`（返回 `IOVA` 与析构自动解映刷 IOTLB 的 `Pmt` 令牌）、`0x76 resource_create`（八域非重叠区间树）以及调试/受限态/EL2 窄口内核职责边界。
2. **宿主 `emulator` 与客机 `pty/cli-suite` 双向闭环**：统一使用既有 `opt/berry/bootmode=headless` 键驱动无头启动；在 [emulator 总体设计](../../plans/emulator/design.md) 登记 `--boot-mode headless`、`berry console` 双端口自动转发宿主 `SIGWINCH` 与 OSC 52 剪贴板、`berry push/pull` 及 `berry ssh`。
3. **锁定 `berry-libc` 六大兼容原语、双级会话 `elevate` 与 `man`/OSC 52 体验**：打通 Rust `std::process::Command` 零改映射与 `Port` 统一 `poll/epoll`；确立 `OperatorSession` + `elevate <cmd>` 无 SUID 提权契约；补齐 `whoami / id / man`、登录标准环境与 OSC 52 剪贴板回传，并勘正 `compat` 错链。

## Alternatives considered

- **为无头模式新增独立 `opt/berry/headless` 键**：与已存在且语义正交的 `opt/berry/bootmode`（`default | verbose | headless`）重复造键，增加 bootloader/kernel/berry 三端对拍负担，故否决。
- **沿用 Unix `chmod u+s` SUID 二进制提权**：SUID 程序继承调用者不可信环境变量、文件描述符与工作目录，是 Unix 五十年本地提权漏洞温床；由 `elevate` 向 `rootmgr` 申请干净环境与显式能力子会话从根源免疫此类攻击，故否决 SUID。

## Consequences

- 合龙总纲第二章登记的全部 ABI v2 系统调用在莓核四模块规格中 100% 拥有精确的数据结构、锁秩与实施落刀锚点。
- 标准 Rust CLI 生态（含 `std::process::Command`、多线程同步与多路 `poll`）具备源码级零改编译运行契约，宿主 `berry` 工具与客机终端形成严丝合缝的双向闭环。
