## §0 一页结论（四路 + 裁决 + 收口判定）

1. **PM-13（厂商 SoC 平台）**：「驱动申报电源档 + 唤醒延迟，OS 只投票、远程执行者裁决」不是 BerryOS 的发明，是手机 SoC 十年验证的行业共识——高通每驱动投 corner/level 票（rpmhpd 源码 `rpmhpd_aggregate_corner()` 取 max），SDM845 起聚合执行全下放硬件加速器与 AOP 固件（PM-13 §0-1，高）。真实量级：轨/簇级唤醒 0.75–4.4 ms、收益门槛（min-residency）7–10 ms（sm8550.dtsi 实数）——`wake_latency_ns` 必须成对加 `min_residency_ns`，只报前者会让仲裁器在短窗里做亏电决策（PM-13 §3-1，高）。vendor perf 十年拉锯（perflock→uclamp→ADPF）终局全部收敛「应用只报目标+实际时延，OS 决定频与核」，与带内纪律同构（PM-13 §0-3，高）。
2. **PM-14（充电与电池）**：行业终态一句话——**算法和安全兜底全在硬件，OS 只做三件事：诚实汇报、限值仲裁、状态机联动**（PM-14 §0，高）。限值仲裁语义 = Fuchsia ChargeLimitArbiter 原文 "the vote that charges least wins"（充得最少者赢、只许收紧不许放宽）；Android 十几年无公开充电限值 API 导致厂商碎片是「应用契约 day-one 定对、窗口一次性」的又一正面依据（PM-14 §2.4，高/中-高）。落法 = 用户态 chargerd + P11 充电限值票 + BatteryInfo 增量五件 + sim-battery 三断言，充电域无任何理由进内核（PM-14 §4.5，高）。
3. **PM-15（电源 API 对照与 berry-sys 草案）**：现代三家全部收敛「窄入口 + 白名单/配额 + 系统校验」，且每家的 API 形状就是它的滥用面（PM-15 §1，高）。六面（定时/推送/长时任务/传感器/热/电池）合计**新增 syscall = 0**——全部走服务 op + 能力位 + 配额显式，precise(wake) 闹钟内核面落 v2 已预留的 0x62/0x63 timer（PM-15 §4.1，高）。产出三件可实施物：六面 berry-sys 风格签名草案（照 berry-psproto 先例新增 berry-pwproto 纯协议 crate）、能力位词表增量、默认值/配额初值表（全部「初值+策略表项可调+遥测导出」）。
4. **PM-16（sim 设备族与九断言挂 G0–G5）**：sim 实现路径裁决 = **Tier-0「零 QEMU 改动」先行**——fork QEMU 的真实成本在双端构建管线不在设备代码，而九断言的注入需求 Tier-0 通道全覆盖（PM-16 §1.1/§3-6，高）。本地 QEMU 11.0.3 DTB 实证修正 PM-10「virt 无唤醒源」：有 PL061 GPIO3 电源键（免 fork 可注入唤醒线）+ 第二 UART（字节流注入通道），真正缺的只是「QEMU 级挂起态唤醒」（TCG 无 SYSTEM_SUSPEND，PM-16 §0-2，高）。三设备契约 = 用户态服务 + 单一契约头文件（消息层原子快照+递增 seq，构造性消灭 goldfish 逐字段写的顺序坑），九断言分三批挂 G0–G5，判据全部状态谓词零竞速。
5. **刀 1 前置裁决（pm-notes/刀1-*）**：PM-12 §3.3 两件硬前置全部收口——源 id 与名字映射采 abi.toml 单源 add-only 静态枚举（u8，名全归用户态）；导出通道采混搭「刀 1 零通道 × 快照烘焙只读 VMO × 仓内号位 0x84 改挂」（B 案漏检 0x84 在册 v3 预留是新证据）；WakeRec 保 32B 环形（source 吃 _pad[0]）+ per-source 64B×32 计数槽 + 不随 trace_off 关的独立总账 WAKE_ACCT_N；记账钟 = CNTVCT 原始周期 + 快照头 slept_ns/suspend_count + 槽内 ts_domain:u8；**刀 1 零号消耗**（39 定义/38 注册/v1 在册 35 全不动，帽 45 出 ADR #11，裁决 §4，高）。八件前置全部可即刻执行，**可立即开写判定 = 是**（裁决 §5）。
6. **收口判定：研究侧收口，不开四期**。三期后全部「形状问题」（协议位/契约/归属/验证路径）都有了带证据的裁决；剩余开放问题全部是**实施驱动**（随刀裁、随 spike 回填、随真机线）而非研究驱动——唯一两处残余研究价值（真机 SoC 电源域带、pushd 云端对端）分别被 PM-00 §7-5 真机线与产品层裁决预占位，PM-13 §4-9 的 sim-pd 建议已把厂商域验证压进 QEMU 可达范围。若再开轮次，主题应是「实施回头看」（回填表执行核验）而非新域调研。

### 3.3 排序裁决与理由

1. **刀 1 先行不变**（PM-00 §5.4/§7 已裁）：纯内核面零服务依赖，是全部后续治理的验收地基；两问已裁、判定=是，无任何剩余阻塞。
2. **sim 刀 S1 提前与刀 1 后半并行**：S1 唯一内核触碰是 IRQ 常量+派发分支（同 M2 形状），契约 crate 纯用户态；提前的理由是 S2 的 A4 断言吃刀 1 source 位、A2 吃 sched-1.1 收尾——S1 尽早落可以解锁第一批断言全部三挂点。
3. **L1 先于 L2/L3**：热边界是 sim-thermal 消费面（thermal_level 归属）与 P11 出票方的前提；且无代码依赖可纯文档并行推进，机会成本最低。
4. **L2 挂起刀排在 S3 之后**：停钟/SLEPT 的累加机制裁决需要 PSCI 三档现实表（TCG=无真挂起 → 累加只能记账面先行）；刀 1-M5 已把快照头表示法预冻，挂起刀只填机制不碰 ABI。
5. **L3 随 ABI 冻结窗口收口**：豁免位/P11/六面签名全部是「窗口一次性」契约（day-one 定对）；berry-pwproto（S1）先行为其提供协议 crate 载体。
6. **每步验收纪律**（AGENTS 维护合同「能在 QEMU 独立验证的里程碑单独成提交」）：表内验收面全部状态谓词零竞速（判例 A32）；时序敏感项（A3/A1 icount 对拍）一律挂 B-2 `-icount` 相；挂起循环类至少两轮（pm_test「二跑才炸」+ A110 双证）。
7. **明确不做**：不 fork QEMU 起步（T1/T2 押后，立项判据=「断言需求清单盖过构建管线成本」）；不为深睡做 TCG 假实现；不往 smoke 塞功耗绝对值断言；不在 EFI/AAVMF 相挂 GPIO3 断言（ACPI 分流坑）；sim 契约文件不留仿真专用分支（绿传递律排他）。

### 4.2 三期新增开放问题（按风险排序）

1. **executor 位与 REMOTE_PROC 失联重同步的策略域**：manifest 执行者位决定故障面（REMOTE_PROC/REMOTE_HW 域必须声明「执行者失联」策略，对齐 qmi_tmd 服务重启重同步）——重同步语义归 berry-power 层还是驱动服务自恢复，随 berry-power 域仲裁刀裁（PM-13 §4-2，高）。

3. **chargerd 的 off-mode 最小系统形态**：无 berry-power/无 FS 时 chargerd 仍出充电 UI 骨架（PM-14 §3-5）——涉启动序与监督退化，开 chargerd 刀前必须裁；Power Reserve 式保留态（BLE 定位/交通卡最小域）与 PM-00 L3 低功耗域同族，规划窗口待定（PM-14 §2.5/§4.3，中）。
