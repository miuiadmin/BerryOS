## §0 结论速览（七条，全部两源）

1. **A/B 同场景三面全测完，vgpu 与 ramfb 的 guest/host CPU 面在 TCG 满核背景下不可分辨**：桌面档（1080×1920,gui=1）idle 60s 段 QEMU user = vgpu 56.54s/56.8s（99.5% 单核）vs ramfb 56.82s/57.3s（99.2%）——07 号 §0-1 的 idle 满核税 **vgpu 档不消失**（07 号 §5-③ 对照收口：ramfb 设备面排除出归因候选）；滚屏档（800×600,gui=0）滚屏段 QEMU user 67.1s/67.5s（99.4%）vs 68.9s/69.1s（99.7%）、guest 滚屏速率 19.0 vs 18.9 行/s——**B1 的全部变化在传输/呈现侧，渲染侧（guest CPU 软光栅）分毫未动**，10 号题①「传输+呈现卸载」判定的同场定量侧写 [高·实测]。
2. **传输字节面 β-0 已赢五个数量级**：滚屏档 vgpu 面 VNC 出口实测稳态 **3 updates/s、2.1KB/s**（字符格 16×10 矩形流，75.7s 窗 204 updates/10.0MB——大额全帧仅 boot 相 3 次）；同场 ramfb console 面 VNC **3 次更新后恒静死**（固件相打完即黑，09 号 §4 同判），而现役壳轮询面 = 60Hz 全帧 pread（800×600 档折 115MB/s、07 号 §3 表）——增量推送 vs 盲轮询的带宽比 ≈ **2.1KB/s : 115MB/s ≈ 1:55000** [高·实测]。
3. **机制定谳（QEMU v11.0.3 源码）：v1 全帧 flush 不放大 VNC 出口字节——VNC 服务端自带内容差分**。链路：`resource_flush` 把 flush 矩形∩scanout 交给 `dpy_gfx_update`（记账进 guest dirty bitmap）→ VNC 定时器（`vnc_refresh_server_surface`）对 dirty 段做 guest fb vs server fb 的 **memcmp 差分**，只把内容真变的段（横向粒度 `VNC_DIRTY_PIXELS_PER_BIT=16px`）拷进 server fb 并置客户端脏 → 出口矩形 = 内容变化集，**与 guest 的 flush 粒度解耦**。实测对拍：guifbd console 相每消息 `flush_full`（全帧 FLUSH，guest.rs :447-451）但出口只发 16×10 字符格 [高·源码+实测双源]。
4. **60fps 新硬顶：VNC 出口刷新定时 30ms = 33fps 上限**——`GUI_REFRESH_INTERVAL_DEFAULT=30ms`（空闲退避到 3000ms），β-0 VNC 通道对 60fps 交互**结构性不够**（差 1.8×），与 v1/v2 的 flush 粒度无关；这是 β-1（D-Bus 直推通道）最强的定量论据，也是 02 号 §2 β-0/β-1 二分之外本轮新增的硬判据 [高·源码；压顶实测未做——无 60fps 帧源，如实标]。
5. **每帧成本四段分解定谳（1080×1920 满帧口径，全锚实测/源码）**：段 G 光栅（guest CPU,不变量——10 号实测典型帧 0.059–0.31ms）→ 段 T 帧提交（vgpu 新增 2×`cmd_sync`:门铃走 `qemu_bh_schedule` **BH 异步**,guest poll 首查难即中、1ms 步进,guest.rs :1088-1115——推断每帧 2–4ms,占 16.67ms 预算 12–24%）→ 段 Q QEMU 处理（vgpu 新增:TRANSFER 整宽快路单发 `iov_to_buf` 全帧 memcpy **0.119ms**〔本机 69.5GB/s 定标〕+ VNC 30ms 定时全帧 memcmp **0.167ms/周期**——60fps 满帧假想合计 ≈7.8% 单核）→ 段 H 宿主呈现（**现状 = 双通道并存**：B1-b 壳半未落地,berry host 仍 60Hz pread 全帧 + virtio-gpu 增量通道并行付双份；β-0 落地后 = VNC 增量直收 2.1KB/s 级）[高/中混合,逐段标注]。
6. **v2 per-rect 收益模型（修正 02 号 §4.2 语义）**：真收益 = 段 Q 两面随脏区率 r 线性缩（TRANSFER memcpy 8.29MB→r×8.29MB;memcmp 面 v1 恒全帧 276MB/s@33 周期 → v2 只查 r 面）——r=5% 时段 Q 从 ≈1.3ms/帧 → 0.065ms/帧（**20×**）;**VNC 出口字节收益 ≈ 0**（已被 memcmp 收敛,题 3 机制）;段 T 反而**恶化**——per-rect 提交 K 矩形 = K+1 条同步命令（02 号 §3.2 Linux 形:per-rect TRANSFER + 包络单 FLUSH）,同步 poll 模型下 K=8 即 ~9–18ms 逼近预算爆线 → **v2 必须改异步提交（发车不等回执,回执走次帧收割）或砍 poll 步进**,这是 v2 刀的新设计输入 [中·模型,锚实测]。
7. **60fps 差距排序定谳（桌面交互路径,当前 vs 目标）**：①**VNC 33fps 出口硬顶 = 1.8× 差距**（结构性,β-1 才解）；②段 G 光栅在 HVF 档已过线（10 号:余量 8–280×,TCG 1.7× 税仍宽裕）——非当前瓶颈；③段 T 帧提交 2–4ms/帧（12–24% 预算,推断）——v2 同步模型会放大,须异步化；④段 Q <8% 单核（v1 满帧）→ v2 后 <0.5%——非瓶颈；⑤段 H 双通道并存税待 β-0 壳半退役（6% 静帧轮询 + 变化帧四遍遍历,07 号 §3 表）。**B1 兑现了传输与呈现的结构（β-0 字节面已赢五个数量级）,60fps 的下一刀不在传输面在出口通道（β-1）与段 T 异步化**。

## §3 每帧成本模型（四段分解——vgpu 改善了哪段、恶化了哪段）

### 3.1 段 T（guest 帧提交,vgpu 新增段）

`flush_full`（guest.rs :1137-1157）= 2 条 `cmd_sync`（TRANSFER+FLUSH,lib.rs :150-163 钉板序）。每条：编帧+`berry_vmo_write`（cmd ≤56B + 间接表 + ring 整页 4096B）→ `dmb ish` → MMIO 门铃 → poll used.idx。**门铃异步定谳**：QEMU `virtio_gpu_handle_ctrl_cb` = `qemu_bh_schedule(g->ctrl_bh)`（virtio-gpu.c）——命令在 QEMU 主循环 BH 执行,不在 vCPU 线程同步完成 → guest 首查 used 大概率未前进,按 `VIO_POLL_STEP_NS=1ms` 步进睡（guest.rs :893/:1088-1115）→ **每命令 ≈1–2ms guest 墙钟,每帧 2 命令 ≈2–4ms**[中·推断——机制源码 [高],毫秒值未实测（50ms 时戳粒度上限）,TCG 下 guest sleep 不占 QEMU CPU 故 §2 不可见自洽]。ramfb 相此段 = 0（fb 直写即达）——**vgpu 恶化段**。

### 3.2 段 Q（QEMU 处理,vgpu 新增段;ramfb 相 = 0——fb 即 DRAM,设备零动作）

| 面 | v1 全帧（现状） | 机制锚 |
| --- | --- | --- |
| TRANSFER memcpy | 1080p **0.119ms/帧**（整宽快路单发 `iov_to_buf(stride×h)`——virtio-gpu.c transfer 函数 else 分支;800×600 0.024ms） | §2.3 实测 + 源码双源 |
| FLUSH 记账 | flush 矩形∩scanout → `dpy_gfx_update`（bitmap_set,轻） | 源码 |
| VNC 定时差分 | guest.dirty 有脏时每 30ms 周期全帧 memcmp **0.167ms**（v1 全帧 flush 使 dirty 恒全帧——**即使 1 字形变也付全帧比对**）→ 33 周期/s = 5.5ms/s = 0.55% 单核 | `vnc_refresh_server_surface` 源码 + §2.3 |
| worker 编码发送 | 按 server dirty 增量字节 raw 拷贝发送 | §2.2 实测（2.1KB/s 稳态） |

60fps 满帧假想合计 ≈（0.119+0.167）×60 ≈ **17ms/s ≈ 1.7% 单核**——非瓶颈;但注意满帧变化帧时 memcmp 面与发送面同步涨（全帧 raw 497MB/s 局域网可行、CPU 编码 ~7%）[中·模型,锚实测]。

### 3.3 段 G（guest 光栅）与段 H（宿主呈现）

- 段 G 两档同（渲染 100% 留 guest——10 号定谳;本轮 A/B 滚屏速率与 QEMU CPU 双面无差为同场侧写 [高·实测]）。成本面引 10 号 §3.2 host 定标表（fill 1.97ms/典型交互帧 0.059–0.31ms/SmoothArgb 13.7ms 红线）。
- 段 H **现状 = 双通道并存**：berry host 60Hz pread 全帧轮询（窗口形态 7–9% 单核 + 变化帧四遍全帧遍历,07 号 §0-4/§3 表——**vgpu 档壳代码未动,该面原样保留**,推断:壳未变直接适用;headless 形态不跑已 §2.1 实测）与 virtio-gpu→VNC 增量通道并行——**B1 付了段 Q 新成本,段 H 旧成本尚未退役**;β-0 壳半落地后段 H 换 VNC 增量直收（2.1KB/s 级,§2.2 实测同构）。

### 3.4 四段对照总表（每变化帧,1080×1920）

| 段 | ramfb 链（07 号基线） | vgpu 链 v1（现状） | 判 |
| --- | --- | --- | --- |

## §4 v2 预期模型（per-rect flush 的增量收益——修正与放大两向）

### 4.1 字节/CPU 面（r = 脏区率）

- 段 Q memcpy:8.29MB → **r×8.29MB**（TRANSFER 矩形化,行循环分支已在源码在席）;r=5% → 0.41MB=0.006ms。
- 段 Q memcmp:v1 恒全帧（276MB/s@33 周期）→ v2 只查 flush 包络内段 → 随 r 近线性。
- **VNC 出口字节收益 ≈ 0**：出口已被 memcmp 收敛到内容变化集（§3-2 机制）——02 号 §4.2「宿主 CPU 面只乘 damage 面积系数」在 VNC 通道下的精确语义 = **QEMU 内部面乘 r,出口面已 ≤ damage**;v2 的出口收益只在 β-1（D-Bus UpdateMap 纯矩形,免 memcmp 差分面）兑现。
- 合计:r=5% 时段 Q 1.3ms/帧 → 0.065ms/帧（**20×**,02 号 §4.2 预判的实测+机制版）。

### 4.2 帧率上限推演

- VNC 通道（β-0）:出口 33fps 硬顶（30ms 定时,源码）——**r 与 v1/v2 均无关,60fps 不可达**;调优路径（定时器加密/强制增量请求）未在本轮范围,如实标。
- β-1 通道（D-Bus UpdateMap 直推）:无 30ms 定时面,出口帧率上限 = guest 提交率;此时段 T 的 2–4ms 成同步瓶颈之一。
- 段 G/段 T 不随 r 缩（光栅/提交固定）——满帧最坏场景 v2 后仍 ≈段 G 主导（10 号判:已过线）。

### 4.3 v2 设计新输入（本轮发现的爆点）

per-rect 按 Linux 形（02 号 §3.2）= K×TRANSFER + 1×FLUSH 包络（K≤8,guifbd DAMAGE_MAX）;**同步 cmd_sync 模型下 = K+1 次 1ms 步进 poll ≈ 9–18ms@K=8——逼近/超 16.67ms 预算**[中·模型]。对策二选一（v2 刀内裁决）:①异步提交——命令连续发车不等待,回执（RESP/RELEASE 语义）走下一 tick 收割（guifbd serve 循环 poll-first 形天然可容）;②中断替代轮询（virtio-mmio 中断面在席,gui-inputd/vblk 家族先例）。**不改则 v2 在多 damage 帧上反而倒退**——此判为 v2 排刀前置条件。

## §6 环境限制如实

- **TCG 单档**:B1 镜像 HVF 档 boot ktest fatal（09 号 §3-4/07 号 §4-2 既有缺口族）——HVF 档 vgpu 对比未测;段 G 的 HVF 结论引 10 号 host 定标（近原生外推,推断标注）。
- **boot 首帧墙钟与交互变化帧两指标不可比**:现行树 TCG 下 LAUNCH ok 饿死（09 号 §3-3 既有,本轮 s1A1/s1B1 双档 LAUNCH v= 到位、LAUNCH ok 均未到）——07 号 §5-①② 的正式重测挂镜像侧修复后补;本轮以 S2 滚屏替代实证变化帧流。
- **段 T 毫秒值未实测**:50ms 串口时戳粒度 + TCG 满核背景下不可分离;机制（BH 异步+1ms 步进）源码定谳,数值标推断——B-2 icount 通道（02 号 §6 B1-d）建成后回填。
- **60fps 压顶未实测**:guest 侧无 60fps 帧源（launcher 饿死、gfxdemo 一次性、滚屏 ~19 行/s）——33fps 硬顶为源码定谳非实测压顶;v2 模型全为锚实测的推演。
- **背景负载**:owner 在跑 HVF 会话全程在场（一核）;A/B 同窗对比不受扰,绝对值抬底 ~1 核。
- **instrs/cycles 采样面**:`ri_instrs/ri_cycles` 对子进程不可靠更新（busy 子进程恒 0）——放弃硬件计数器口径,如实记。
- **S2 固件相混入**:s2A1 的 10.0MB 总字节含 boot 相全帧 ×3 与固件文本相（09 号 §4 同源流）——稳态窗（t+31s 后 26–32 updates/10s）已剥离该面;滚屏段 QEMU user 含 TCG 翻译主项,vpio 增量不可分离（§2.2 判读列如实分账）。
