## §0 结论速览（终裁五条）

1. **「GPU 加速」语义终裁（三段重述）**：B1 兑现的是**管道不是画笔**——传输段已卸载（稳态 2.1KB/s vs 旧盲轮询 115MB/s ≈ 1:55000，12 号 §0-2）；呈现段 QEMU 侧增量自动在场（09 号 §4）而**宿主 GPU 尚未参与任何一段**（壳半 B1-b 未落地、双通道并存付双份，12 号 §3.3）；渲染段 100% 留 guest CPU 且 virtio-gpu 2D 档**结构性不可能**卸载（14 条命令零渲染 op + 下推四路全断 + virgl Mac 出局，10 号 §1）。「GPU 加速」在模拟器档的准确说法 = 显示通道加速；真 GPU 渲染住第三档 Vulkan（真机）。
2. **60fps 路线图修订（数据重排）**：VNC 出口 30ms 刷新定时 = 33fps 结构硬顶（12 号 §0-4），与 flush 粒度无关——β-0 定性为**过渡档**；新排刀 = **B1-b 壳半（β-0 收尾）→ β-1 D-Bus 通道 → v2 per-rect+段 T 异步化 → a1 光栅 span 化 → a2 NEON 视需**（§2）。10 号 §5 原排刀（v2 传输面居首）按 12 号两新判修正：VNC 通道下 v2 出口收益 ≈ 0（memcmp 已收敛），v2 满收益须 β-1 在场兑现。
3. **β-1 Mac 通道终裁**：**立为 Mac 呈现终态通道**——p2p 免 daemon、QMP 喂 fd、RegisterListener、ScanoutMap 共享图 mmap、UpdateMap、输入反走六环节全链本机实收（11 号 §2）；memfd→mac = mkstemp 匿名文件 + MAP_SHARED 语义完整（11 号 §2.3）；02 号 §6 降档线**不触发、退役**；VNC 降为诊断通道（QEMU 多 display 并存合法）。β-1+v1 现状即可过 60fps（出口上限 = guest 提交率，段 T 2–4ms → 250–500fps 量级，12 号 §4.2 推断）——v2 收益在 CPU 面与增量粒度，非帧率面。
4. **v2 新设计输入三条**（12 号 §4.3 + 本文合成）：①**段 T 异步化 = v2 前置条件**（同步 per-rect K=8 = 9–18ms 逼近/超 16.67ms 预算，不改则 v2 多 damage 帧倒退）；②v1 全帧 flush 在 β-1 下 = 每变化帧全帧 UpdateMap → 壳全帧 write_texture 8.29MB ≈ 0.12ms/帧（算术+锚：12 号 §2.3 的 69.5GB/s；机制 = 10 号 §1.2 flush∩scanout→console_update × 11 号 §2.2 console→UpdateMap 两篇互证）——非瓶颈但 v2 后随脏区率 r 缩；③SmoothArgb 全帧每帧路径禁令须遥测执法（帧耗时桶挂 GUI-9 四桶归因，10 号 §6）。
5. **开放问题四族带触发器**（§4）：idle 满核税归因（两后端同在）、HVF 档对比未测族（镜像侧 ktest fatal + LAUNCH 饿死既有缺口）、段 T 毫秒值未实测（B-2 icount 回填）、D-Bus 手写客户端 UnknownObject 竞态（β-1 壳半首刀排查）。

## §1 「GPU 加速」语义重述——传输/合成/渲染三段（用户语言：什么快了什么没快）

| 段（干什么） | ramfb 旧链（07 号基线） | B1 落地后现状 | 快了吗 |
| --- | --- | --- | --- |
| **渲染**：算出每个像素什么颜色（fill/文字/贴图/缩放） | guest CPU berry-gfx 软光栅 | **同码原地**——A/B 同镜像实测滚屏速率 19.0 vs 18.9 行/s、QEMU CPU 不可分辨（12 号 §0-1） | **没快，也快不了**：virtio-gpu 2D 命令集 14 条全部是资源管理/传输/呈现通知，零画图原语；QEMU 侧只分配 pixman、纯拷贝、发通知（10 号 §1.1–1.2）；自加渲染 op 四路全断、virgl/venus/gfxstream 宿主渲染器 Mac 构建出局（10 号 §1.3–1.4） |
| **传输**：画好的像素搬进宿主 | 宿主每 16ms 全帧 pread 盲轮询——静止帧也读（800×600 档折 115MB/s，07 号 §3 表） | DMA 环按需搬运 + flush 边界；VNC 出口稳态 **3 updates/s·2.1KB/s**（滚屏实测，12 号 §0-2） | **快了五个数量级**（≈1:55000）；damage 语义协议级保真（ramfb 边界蒸发 → flush 矩形端到端，10 号 §2 表）；v1 全帧 flush 不放大出口字节——VNC 服务端 memcmp 内容差分兜底（12 号 §0-3） |
| **合成呈现**：宿主窗口上屏 | 全帧逐像素标量转换 + CPU 缩放合成 + softbuffer 写窗（每变化帧 ≥4 次全帧遍历，01 号 §3） | QEMU 侧增量自动在场（gpu console 面 76+ 帧/30s 小矩形，09 号 §4）；**壳半未接**——berry host 旧轮询照跑，双通道并存付双份（12 号 §3.3） | **半成品**：QEMU 半已快；壳半待 B1-b 落地（damage 载荷 + wgpu 骨架）；宿主 GPU 参与挂 β-1（wgpu/Metal 合成，11 号 §4） |
| 代价（新付的） | — | 段 T 帧提交 +2–4ms/帧（推断，12 号 §3.1）；段 Q QEMU 处理 <8% 单核@60fps 满帧（12 号 §3.2）；boot 固件相 2.7×（VirtioGpuDxe，一次性的，12 号 §2.2） | 换通道的过路费，均非 60fps 卡点（§2） |

一句话版本：**快的是「搬运与通知」——静止不再白读、变化只送变化、宿主合成将进 GPU；没快的是「画」——每个像素仍是 guest CPU 算的，且在 2D 协议档结构性无解；这正好够 60fps 交互（渲染余量 8–280×，10 号 §5），「华丽」（任意变换/着色器）住第三档真机 Vulkan**——与规划 :187「前两档流畅/正确、第三档华丽」的分工对榫。措辞执法：01 号 §5「把光栅搬出 CPU 链」「宿主 GPU 加速 2D 光栅」两处在 v1.0 升版时按 10 号 §0-3 纠偏为「把传输与呈现搬出 CPU 链、宿主 GPU 加速合成」（§5 清单）。

## §2 桌面 60fps 路线图修订——优先序按数据重排

差距定量（12 号 §5 表，当前 → 60fps 按大小排）：**①出口通道 VNC 33fps 硬顶（差 1.8×，结构性）→ ②段 T 同步提交 2–4ms（占预算 12–24%，推断）→ ③段 H 壳旧税未退役（双通道并存）→ ④idle 满核税（体验面）**；段 G 光栅 HVF 档已过线（典型帧 0.059–0.31ms 余量 8–280×，最坏全帧重绘 1.9–2.0ms 余量 8.4×，唯一红线 = 每帧全帧 SmoothArgb 13.7ms——10 号 §3.2/§5）。修订排刀：

| 序 | 刀 | 内容与验收 | 60fps 判据（数据） | 依据 |
| --- | --- | --- | --- | --- |
| 1 | **B1-b 壳半（β-0 收尾）** | Frame damage 载荷 + wgpu 呈现骨架 + console 绑定序（gpu 先于 ramfb 声明）+ berry host pread 轮询退役；验收 = 07 号 §5 四指标同法重测 | 退役双通道旧税（壳 115MB/s 级盲轮询 + 变化帧四遍遍历，12 号 §3.3）；wgpu 骨架 = β-1 的复用投资，一刀两通道 | 12 号 §3.3/§5；09 号注记二；11 号 §4-1 |
| 2 | **β-1 D-Bus p2p 通道** | 壳半八步（11 号 §4-2：QMP 喂 fd → p2p → RegisterListener → ScanoutMap mmap → UpdateMap 驱动 write_texture → Metal 合成 → 输入反走）；验收 = QEMU 实连 + ScanoutMap 实收断言（11 号 §5-5） | **解 33fps 结构硬顶**（30ms 定时与 flush 粒度无关，12 号 §4.2）；β-1+v1 出口上限 = guest 提交率（段 T 2–4ms → 250–500fps 量级，推断）——60fps 达标且余量 4–8× | 11 号 §2/§4；12 号 §0-4/§4.2 |
| 3 | **v2 per-rect + 段 T 异步化** | damage K≤8 逐矩形 TRANSFER+包络 FLUSH + berry-gfx dirty K 透传；**异步提交（发车不等回执）或中断替代轮询 = 本刀前置**；验收 = 像素共识对拍 + 场景帧时线 | 段 Q 两面随 r 线性缩（r=5% 省 20×，12 号 §4.1）；β-1 下壳 write_texture 增量化（§0-4-②）；防同步 K=8 的 9–18ms 爆线（12 号 §4.3）——**不改则此刀倒退** | 12 号 §4；10 号 §4-b |
| 4 | **a1 光栅 span 化** | fill/clear 行内快路 + 行写口纪律 + 像素共识对拍同批；验收 = host 定标复测（10 号 §3.2 场景） | fill 1.97→0.11–0.2ms（**10–17×**，行循环锚 0.053 ns/px 为地板，10 号 §4-a1）——段 G 已过线，此刀为 4K/多应用/余量而排，非 60fps 必需 | 10 号 §4/§5 |
| 5 | **a2 NEON（视需）** | glyph/Argb/双线性向量化；ADR #34 不挡用户态 SIMD（10 号 §4-a2） | 触发条件 = 4K、TCG 性能敏感档、多应用并发；**仅为 60fps 则可缓**（典型帧已 0.35% 预算，10 号 §5） | 10 号 §4-a2/§5 |

排序裁决说明：10 号 §5 原推荐「b（v2 per-rect）居首」是在光栅面/传输面两维里的排序；12 号同批新增两判将其重排——①VNC 通道下 v2 的出口字节收益 ≈ 0（memcmp 已收敛到内容变化集，12 号 §0-3/§4.1），v2 的满收益（UpdateMap 增量 + QEMU 段 r 缩的消费者）须 β-1 在场；②33fps 硬顶是任何 flush 粒度优化都解不了的结构面（12 号 §4.2）——故 60fps 目标下 β-0 壳半与 β-1 前置、v2 随后、光栅两面（a1/a2）按 10 号判已过线而殿后。终态全链账（β-1+v2 假想，算术+锚）：典型帧 = 段 G 0.059–0.31ms + 段 T 异步化后≈0（回执次帧收割）+ 段 Q r×0.119ms + 段 H r×0.12ms 级 + GPU 合成（Metal）——**单帧 <1ms 量级、出口无定时顶，帧率上限回到 guest 提交率**（12 号 §4.2 骨架的外推，推断）。

## §3 β-1 Mac 通道终裁

**终裁：β-1（`-display dbus,p2p=on` + Listener/Unix.Map 共享图 + wgpu/Metal 呈现）立为 Mac 呈现终态通道，β-0 为过渡档**。依据四条：

1. **可行性全链实证 [高]**（11 号 §2，C/GDBus 客户端实跑）：p2p 免 daemon（QEMU 不连不监听总线，QMP `getfd`+`add_client(@dbus-display)` 喂 fd）→ 主连接对象面实读（Console_0/Keyboard/Mouse/MultiTouch）→ `RegisterListener` 应答 → **ScanoutMap 共享图 fd 实收 mmap 读通**（pixman x8r8g8b8 与现役 BGRX 同族零转换）→ UpdateMap 纯 16B 矩形 → 输入反走发送成功。memfd→mac 定谳 = mkstemp 匿名临时文件 + unlink + MAP_SHARED（lsof 活体 4096000B = stride×h 互证）——02 号 §7 两条 [中] 风险（D-Bus 可行性、memfd 后备）双双闭账，§6 降档线不触发、退役。
2. **定量论据 [高·源码]**：VNC 出口 30ms 刷新定时 = 33fps 上限（12 号 §0-4）——60fps 目标下 β-0 结构性不够；β-1 无定时面，出口上限 = guest 提交率。这是 02 号 §2 β-0/β-1 二分之外本轮新增的硬判据。
3. **三通道对照定谳**（11 号 §3 表）：D-Bus p2p（零编码零拷贝、宿主 CPU 面 = damage 矩形级）＞ VNC raw 直收（增量已实证但每 update 付 RFB 解析 + 逐像素标量转换 + 全帧 Frame clone）＞ cocoa（owner 已裁出局）。
4. **实现输入就位**（11 号 §5 尖角五条 + §4-2 八步 + 上游 `dbus-display-test.c` 参照骨架）：报文头数组偏移 12 布局、fd-list 变体、Listener 客户端角色、Interfaces 自报、手写一致性风险——验收断言用「QEMU 实连 + ScanoutMap 实收」勿只做回环自测。壳侧新增估 1–1.5k 行（02 号 §3.3，置信度受 §5-5 竞态影响，11 号 §6）。

附带裁决：VNC 退役为诊断通道（`-display dbus` + `-vnc` 同挂合法，11 号 §4-2）；Linux 的 ScanoutDMABUF2 零拷贝缝不进 mac 产品路径（同构升级位保留）；DMABUF/多 Listener 扇出面按 11 号 §6 开放项记。
