## 1. 现状解剖:状态栏谁画的、画了什么

### 1.1 谁画的:launcher 进程,不是 wmd 系统窗

状态栏/壁纸 = berry-launcher 窗口内容层,非 wmd 系统窗——`user/bins/berry-launcher/src/desktop.rs:17-18`(裁决四-e:D3 单 wm 客户端不变量保持)。guifbd 是纯呈现服务:present 域 SUBMIT 处理内同步 CPU blit(`user/bins/guifbd/src/main.rs:530-657`),无多窗合成器概念;gui-wmd 只管窗口表几何/焦点/避让(`user/bins/gui-wmd/src/table.rs:350-380` 六 op),自己一笔不画。所以「状态栏谁画的」唯一答案:launcher 自己画进自己提交的帧里。

### 1.2 画了什么:透明叠壁纸 + 白图标 + 静态 12:00

桌面建树时状态栏结构固定(`desktop.rs:254-341`):左组 signal(65×45px)+wifi(47×45px)图标、右组 battery 图标+时钟文本,左右 24vp padding、图标间距 15px,布局序照抄 OH systemui StatusbarConfig LayoutGroups 1/3(`desktop.rs:268-269`)。高度:OH phone 档 39vp×3=117px、紧凑档(800×600)44px(`desktop.rs:74-75,213`)。时钟是编译期常量 `STATUS_CLOCK = b"12:00"`(`desktop.rs:102-103`),头注明示「TODO(W2):真时钟经 berry_clock_read 摆字」——framelopo 全循环无任何时钟更新代码(`user/bins/berry-launcher/src/frameloop.rs` 全文核对)。图标是 OH 官方资产:signal/wifi 取 applications_systemui 官方 SVG 光栅化的 1-bit 白形,battery 按 OH batteryPic 官方几何复刻(`user/bins/berry-launcher/src/status_icons.rs:1-5`;`docs/第三方资产清单-v1.0.md:34,40` 带 commit/SHA;生成器 `tools/genohstatus.py`)。a11y label 钉死假值:`signal full`/`wifi full`/`battery 100`(`desktop.rs:321,323,339`)——运行期没有任何数据源能改它。

### 1.3 两个口径差与一个陈旧注释(小账)

其一,高度口径:代码可见高 39vp(注释:phone statusbar float;launcher 布局保留 44vp,`desktop.rs:74-75`),而规范条文写「状态栏 44vp 顶部常驻」(`docs/应用规范-v1.0.md:139`)——39/44 两值各有出处,实施波应择一钉板。其二,desktop.rs 头注 :11-16 仍描述旧「三 Rect 带状壁纸(含状态栏黑带顶)」形态,而现行代码是 OH 官方壁纸 Icon 全幅(:225-237)+无黑带——文档-代码漂移,建议随刀更新注释。其三,紧凑档 Dock 宽高给 Some(0)(`desktop.rs:525-526`),800×600 下 dock 整体不可见,是「桌面看起来缺件」的另一来源。

## 2. 为什么用户说「信号图标电池都没有」「沉浸式不懂」

### 2.1 解释 A(权重最高,推断):用户看到的根本不是 launcher 桌面

gfxdemo 是每次 GUI boot 必跑的 wm/present 自测件(svcmgr 预拉,`user/bins/svcmgr/src/main.rs:1245-1261`;「gfxdemo 先活后死、launcher 后活」,:1540-1543)。它画的是确定性测试图案:全屏深蓝灰底 0x101828 + 顶部 h/3 色带 0x7F0000(暗红)+ 底部绿条 + 左上 (16,16) 白字「GFX」(`user/bins/gfxdemo/src/main.rs:339-376`),然后退出。guifbd 无合成器,gfxdemo 退出后其最后一帧留在 fb 上,直到 launcher 首帧 FULL SUBMIT 才被覆盖——若 launcher 起不来/起得慢/用户在 boot 早期观察,屏幕停在这帧:无状态栏、无信号/电池、无导航键,恰是 ②③④ 的合并观感。11-06 视觉基线(commit 4c2e0a02)修复过 R/B 通道互换 bug——bug 期 gfxdemo 顶带 0x7F0000 显示为深蓝 0x00007F、蓝灰底显示为土棕(`guifbd/main.rs:839-848` 注释自认「桌面蓝灰显示成土棕(截图实证)」)。OH 官方资产(signal/wifi/battery 图标+官方壁纸)2026-11-06 才入树(commit ccc80954);若用户实测镜像早于此,桌面上确实一个状态图标都没有。以上为推断:本仓无法拿到用户实测镜像版本号,建议 00 总览对时(让用户报 `berryctl ver` 输出)。

### 2.2 解释 B(现役真缺口,与 A 并存):画了,但三处不像「状态栏」

即便用户看到的是现行桌面:①时钟恒 12:00(§1.2),一眼假;②图标是白色 1-bit 形恒满格,无任何状态变化,且叠加在青绿渐变壁纸(wallpaper.rs 像素 0xFF00997B 系,`user/bins/berry-launcher/src/wallpaper.rs:4-6`)上无衬底/scrim——对比度按规范 §3.2 非文本 ≥3:1 需复测;③「沉浸式」现状 = 状态栏透明、壁纸直接透出,这正是 Android 12+ edge-to-edge 的形态(§5.1),但 launcher 既无说明也无 scrim 渐变,用户无从辨认「这是状态栏」——「沉浸式不懂」的直译就是看不懂这层是什么。

### 2.3 解释 C(结构性将爆):真应用一起来,状态栏整条消失

规范已立「应用不得自绘系统 UI 区域(状态栏/Dock)」+「内容避让 = wmd 避让区」(`docs/应用规范-v1.0.md:139,176`;ADR #61 两层窗立法)。但现实:wmd 的 AVOID_SYS 避让机制(`table.rs:184-216`)只对 layer=SYSTEM 的可见窗生效,而全仓没有任何进程创建过 SYSTEM 窗——launcher 把状态栏画在自己内容层(裁决四-e),机制空转。应用规范 §4.1 又定「GUI 应用退出 = 回桌面(v1 全屏独占窗语义)」(`docs/应用规范-v1.0.md:185,246`):第一个真 GUI 应用全屏独占那天,状态栏被应用内容整条盖掉,且无合成器救场(guifbd 后 SUBMIT 者覆盖一切)。这是 ④ 的未来时根因,比 A/B 更硬。

## 3. ③④合并查:「应用顶栏蓝色+左上角英文」来源考证

排查全部候选,证据链如下:(a)berry-ui 声明面无 appbar/title/topbar/chrome/header 任何原语(`user/berry-ui/src/` 全目录 grep 零命中)——不存在「应用模板顶栏样式源」;(b)gui-wmd 窗口表无 title 域(`table.rs:33-45` Win 结构:id/parent/group/req/eff/layer/z/vis/avoid_sys),wmd/guifbd 均不绘制窗口装饰——「左上角英文」不是窗口标题;(c)点开的「应用」全是壳:appdemo 是纯控制台程序(`user/bins/appdemo/src/main.rs:25-41`),appstub 收 env 即 `berry_process_exit(0)` 秒退(`user/bins/appstub/src/main.rs:15-32`)——点击后屏幕无变化(这同时是痛点⑤「能触摸点击了吗」观感差的来源之一:点击链真通,freameloop `Msg::Click`→APP_SPAWN 真发,`frameloop.rs:696-733`,但被点 app 无任何视觉存续);(d)宿主 berry 窗口自带英文元素:标题「BerryOS — {profile}」(`tools/berry/src/window.rs:418`)与底部深灰工具栏五英文键 SHOT/RES/BOOT/OFF/FULL(`window.rs:26-28,147-176`)——但它在底部且非蓝,不匹配「顶栏蓝」;(e)唯一同时满足「顶栏色带+左上英文」的 = gfxdemo 自测帧(§2.1):左上白字 GFX、顶部 h/3 带,底色深蓝灰。结论(推断):用户看到的「应用顶栏」= gfxdemo 开机帧或旧镜像残帧;现行树里不存在任何蓝色应用顶栏。修复面归 01(boot 视觉秩序)与 03(视觉基线):建议 B1——gfxdemo 退出前提交一帧纯黑(或 svcmgr 在 launcher 首帧标记前保持黑屏/启动 LOGO),消灭「测试图案当桌面」的窗口期;并把「顶栏蓝」对时问题并入 00 总览的用户镜像版本核对。

## 4. 导航现状:全无的确证(痛点②)

逐层核对,确证 guest 内无任何系统导航面:(1)launcher:SwipePager 左右翻页 + 槽位点击 spawn,无返回/无 Home/无最近任务/无关机(`desktop.rs` + `frameloop.rs` 全文;翻页判据 = ≥500px/s 或位移 >40%,`docs/应用规范-v1.0.md:254`);(2)gui-wmd:六 op = GETINFO/CREATE/DESTROY/SET/TABLE_GET/TABLE_WAIT(`table.rs:350-380`),无 back 键概念、无窗口装饰、无系统导航事件;(3)gui-inputd:只消费指针相位 PHASE_DOWN/MOVE/UP/CANCEL(`drivers/bins/gui-inputd/src/main.rs:659-677`),无 Home/Back 系统键注入路径——即便想加三键导航,guest 侧今天没有承载系统键的输入语义;(4)berryctl 仅 ver|ps|mem 三子命令(`user/bins/berryctl/src/main.rs:50-55`),无 poweroff/reboot;(5)关机唯一入口 = 宿主 berry 工具栏 OFF 键 → ACPI 电源键 + 5s 宽限(`tools/berry/src/device.rs:242`;`window.rs:26-28`)——用户说「关机都没有」指的是 guest 桌面内无入口,属实。(6)回桌面唯一机制 = 应用自己退出(§2.3),而 app 秒退或挂死时用户无任何夺回手段。痛点②本质:导航所有权缺位——系统壳没有系统导航面,wmd 两层窗立法(ADR #61)留了 SYSTEM 层但从未使用。

## 5. 成熟对照

### 5.1 Android 12+/15:系统栏沉浸 = 透明系统栏 + 应用内容延展,系统栏归系统

Android 15 起对 targetSdk 35 强制 edge-to-edge:系统栏透明、应用绘制到系统栏之后,靠 WindowInsets 避让(官方行为变更页 [Behavior changes: Android 15](https://developer.android.com/about/versions/15/behavior-changes-15);edge-to-edge 指南 [Display content edge-to-edge](https://developer.android.com/develop/ui/views/layout/edge-to-edge)——两页均 JS 渲染,本文只引 URL 与机制框架,未引具体数值)。Material 3 顶栏文档(静态源,[Top app bars(MDC-Android)](https://raw.githubusercontent.com/material-components/material-components-android/master/docs/components/TopAppBar.md);[M3 组件页](https://m3.material.io/components/app-bars/overview))给出与本议题直接同构的分工:顶栏是应用 chrome(标题/导航图标/动作,容器色 colorSurface,非蓝色系统栏),而状态栏透明、让顶栏背景色透上来形成无缝衔接——即「应用顶栏」与「系统状态栏」是两层各归其主的表面。对照结论:BerryOS 现状把状态栏画进 launcher 内容层(裁决四-e),形态上恰是 edge-to-edge 透明态,缺的是系统所有权(§2.3 的 SYSTEM 窗)与应用 chrome 规范(berry-ui 无顶栏原语)。

### 5.2 模拟器信号/电池:成熟系统全用「注入的假值」,且有先例背书

Android Emulator = QEMU fork + goldfish 自有设备族(battery/sensors),模拟电池与真机走同一 battery HAL 接口;emulator console 可脚本注入 `power ac on|off`/`power capacity <n>` 等(`research/PM-10-无真机电源验证-v1.0.md:59-64`【高】,原始官方文档 [Emulator console](https://developer.android.com/studio/run/emulator-console))。BerryOS 已有同构通道:simbattery 快照注入服务(UART1 帧通道+seq 状态机,`user/bins/simbattery/src/main.rs:1-30`),launcher 只是尚未消费。iOS Simulator 侧:状态栏时间恒 9:41、信号/电池为占位显示,Xcode 提供状态栏覆盖菜单——此条为常识性事实,本会话未能抓到可引的静态官方页(Apple 文档全 JS),标「推断」,仅作方向参照不作数值依据。对照结论:「模拟器里信号/电池图标显示静态满格+如实标注模拟态」是两大生态的通行做法,不是凑合。

### 5.3 导航:三键导航是可用性兜底,手势是现代态

Android 保留三键导航(返回/主屏/最近)作为无手势兜底,手势导航(返回边缘滑、底部上滑回主屏)为现代默认;Material 3 将「返回」上升为预测性返回动画。HarmonyOS 手机档无实体导航键、纯手势。对照结论:BerryOS v1 最小刀取「桌面内三键」而非手势,与 Android「三键兜底」同构;手势导航列中期(wmd/inputd 需先有系统键语义,§4(3))。此节无静态 URL 可引(Android 帮助页 JS),结论按 M3/Android 开发者文档体系间接支撑,标「中」确定度。

## 6. 修法分层

### 6.1 最小刀(纯 launcher 层,不动协议/服务,全部桌面内生效)

M1 状态栏补真感:①真时钟——现有 berry_sys 只有 CLOCK_MONOTONIC(`user/berry-sys/src/abi_gen.rs:70`),无 CLOCK_REALTIME/RTC(全仓 grep 无 rtc 驱动),最小刀先做「宿主时间 boot 期注入」(fw_cfg/内核启动参数带 epoch,launcher 换算+MONOTONIC 差值摆字),真 RTC 列中期;②电池/信号保持静态满格但加充电标+模拟态如实标注(a11y label 从 `battery 100` 改 `battery simulated full` 一类,视觉角标可选)——先诚实,再仿真;③状态栏加 8-12px 半透明黑 scrim(自绘 Rect)或换图标衬底,保非文本 ≥3:1(`docs/应用规范-v1.0.md:149`)并让「这是状态栏」可辨认。M2 导航条三键:launcher 层底部三按钮(返回=无应用时空操作/有应用时请求 appd 终止;桌面=锚回 page 0+焦点复位;关机=确认对话框→见 M3)。落点全在 `desktop.rs` 建树+`frameloop.rs` on_click,零协议改动。M3 关机最小闭环:guest 内 berryctl 增 `power` 子命令→svcmgr 走既有 PSCI SYSTEM_OFF(QEMU 支持,`research/PM-10:76`)+关机确认 UI(launcher 对话框)——用户「关机都没有」的直接止痛。注意边界:三键导航画在 launcher 内容层,应用全屏独占时同样会被覆盖(§2.3),最小刀只在桌面态有效,须在验收口径里写明。

### 6.2 中期(结构刀)

I1 状态栏升系统窗(④根治):launcher(或独立 systemui 进程)wm CREATE 一枚 layer=SYSTEM 顶条窗,AVOID_SYS 避让立即从空转变执法(`table.rs:184-216` 现成);present 侧需多窗呈现序(单 blit 通道下可先「systemui 独占提交状态条带」或扩 guifbd 两带合成,协议改动面另立设计)。I2 系统键语义:inputd/guiproto 增 Home/Back 系统事件位,wmd 分发;之后才有应用内返回与手势导航(底部上滑回桌面/边缘滑返回,判据可抄 SwipePager 现役 500px/s/40% 口径)。I3 关机流程正规化:berryctl power + 确认对话框 + PSCI SYSTEM_OFF/RESET 全链 + 宿主 berry OFF 键改走 guest 优雅关机(现为 ACPI 硬按+5s 宽限,`device.rs:242`)。I4 真值接入:simbattery 通道(PM-16 sim 设备族)→launcher/systemui 消费,电池图标随注入变;时钟 RTC(goldfish-rtc 或 virtio-rtc)→CLOCK_REALTIME。

## 7. 推荐案与资产来源
