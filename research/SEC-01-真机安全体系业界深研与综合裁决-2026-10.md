## 一、执行摘要（15 条硬结论）

1. **三段论结构成立，但业界是四段**：SMMU/IOMMU + 运行期硬件缓解 + 度量启动三段被 Android/Apple/Fuchsia 独立收敛验证（ADR #22/#23/#24 无需推翻）；业界普遍还有第四段——**认证绑定与密钥服务**（KeyMint/fxfs-crypt/SEP），BerryOS 三段论没有这一段，v2+ 需要给「密钥服务」一个结构位置。【证-结构·SEC-2/4/7】【推-落点】
2. **「后补 ≠ 自动生效」是八维共同的第一元教训**：Linux IMA 2005 年入主线、主流发行版至今默认不开【SEC-3】；RPMB 子系统八年才进 Linux 主线、Android HAL 七版重写【SEC-4】。推论：**接口位 day-one 埋，实现可以等**——留缝成本近零，后补要动 ABI/boot 两端。【证】
3. **verified boot 结构直接采 AVB 兼容 vbmeta**：256B 头 + hash/hashtree/chained 三描述符 + rollback index 数组 + 锁定态机，avbtool/U-Boot 生态免费拿；BerryBoot v3+ 消费面照抄槽位，不自造格式。【证-SEC-1/5】
4. **A/B 与防回滚是耦合设计**：槽状态三字段（priority/tries_remaining/successful_boot）+「标 SUCCESSFUL 后才更新 rollback 元数据」的次序纪律——ADR #47 L0 的启动计数回退设计必须把这两件一并纳入，否则 v4 接防回滚时引导链重写。【证-SEC-1】
5. **解锁面必须 day-one 设计**：Tivo 教训（verified boot 与用户所有权是政治问题）+ BootHole→BlackLotus 教训（签名有效 ≠ 无漏洞、吊销滞后）——`berry.verifiedbootstate=green|…` 等价标记 + 「解锁即擦用户数据」语义从 v1 就进遥测/设计。【证-SEC-1】
6. **TEE 定位 = 客户端非业主**：v1/v2 不建 TEE、不占 EL3（Fuchsia 同态度）；但 SMC conduit 分派表（OEN 段 allowlist）、boot_state 证明锚、DMA VMO `secure:bool` 属性位这些**客户端接口位**要 day-one 埋——seL4 的教训是「内存模型没有 secure 轴、事后加 = API 重做」。【证-业界·SEC-2】【推-定位】
7. **度量链双路选主**：手机 rich 档走 TPM 2.0 兼容面（swtpm + tpm-tis-device 在 QEMU 现成可验）、手表低功耗端走 DICE（UDS→CDI 逐层递推，最小实现一把 HMAC）；**共用 handoff 测量清单 TLV，只换派生引擎**。token 直接采 EAT（RFC 9334）/CBOR + PSA 形态，不自造格式。【推-基于 SEC-3 证据】
8. **keystore 的 wire 面 day-one 定形**：KeyMint 的 tag 编号表 add-only、SecurityLevel 三档（Software/TE/StrongBox）是 API 一等字段、keyblob 不透明出参、版本绑定棘轮——这是 Android 七版重写换来的接口教训；berry-ksproto 协议 crate 先立 wire 面，后端软桩→硬件逐步换、协议零漂移。【证-SEC-4】
9. **RPMB 归属裁定**：帧驱动 = 持证应用（驱动模型 #46 同链），auth key 持有与 HMAC = keystored（进程级隔离 = 无 TEE 时代「安全侧最小近似」）；**L0 启动计数与未来 rollback index 统一走 CounterBackend 抽象**（read/increment/compare_and_set），QEMU 后端宿主文件、真机换 RPMB/eFuse 零重构。【推-SEC-4/7】
10. **不追 seL4 式全内核形式化验证**：~20 人年 + ~20 万行 Isabelle + 跨切面改动永久 ~32% 税，且 verified 有范围限定（IOMMU 长期缺口、boot 排除、按配置成立）；ADR #26「IPC 协议 + 能力规则 TLA+/模型检查」是务实折中，**维持**；QNX 教训反过来用——认证贵在流程证据，ADR/测试台账 day-one 攒最便宜（本仓库已在攒）。【证-SEC-5】
11. **能力系统的真正漏洞在校验代码**：Zircon CVE-2022-0882（handle 0 绕过检查）——模型再干净，一行 `!= INVALID` 就能掀翻；handle 0 = INVALID 立约 + 能力拒面遥测 + 授予记录一等化（谁/何时/哪类服务/经谁路由），成本近零、day-one 落。【证-SEC-5】
12. **SMMU 是不可拖的顶线且无参考可抄**：seL4 证明至今把 IOMMU 留作缺口——v2 的 per-device domain 是自研负担，按人力预留而不是等参考实现；QEMU 验证面 = 双后端（`-machine virt,iommu=smmuv3` 仅盖 PCI + virtio-iommu-pci，本机 QEMU 11.0.3 实测可实例化），内核 domain 抽象一套、两个后端。【证+推-SEC-5/6】
13. **PAC/BTI/MTE 不是同一个开关**：BTI 自包含、零 ABI 影响，先开；PAC 需 key 编排，次之；MTE 需 `-machine virt,mte=on` 机器级选项 + 分配器中心点改造（async 先行 ~93% UAF 检出、最坏 6.64x 减速）——ADR #23「源码零改动」对 MTE 不成立（→冲突 C4）。【证-SEC-6】
14. **盘上加密格式的天花板与时间窗**：Android FDE 已死（13 删代码）→ FBE per-file + metadata 双层是十年收敛终态；`fileencryption=` 类参数 **first-format-only、不可 OTA 改**——现代 FS inode 16B nonce + u8 class 域与 mkimage 密钥材料分区槽位是「现在不埋、将来最贵」的两处盘格式缝。【证-SEC-7】
15. **全 Rust 方向被曲线验证 + 供应链时钟在走**：Android 内存安全漏洞占比 2019 76% → 2025 <20%（~0.2 漏洞/MLOC、~4% unsafe）；度量先行（先建 unsafe 台账基线才有曲线）；crates.io 三连击（2025-09/2026-05/2026-08）后 Trusted Publishing + cargo-audit/deny 是标配；**EU CRA 全面适用 2027-12-11**——给安全叙事定了外部时钟。【证-SEC-8】

## 三、差距分析（三档）

### 3.1 已对齐（确认不用动）

- **全 Rust（ADR #18）**：方向被 Android 曲线验证（硬结论 15）；本仓 unsafe 收敛纪律 + host 测试文化是安全资产。
- **用户态驱动 + 纯能力（ADR #12/#2/#46）**：与 DriverKit 掉头、Treble 十年补课同向；vblk/vnet 现役 = 爆炸半径已按能力钉死。
- **SMMU 头等设计（ADR #22）**：踩在业界前沿（seL4 都还没盖住 IOMMU）；「每设备一 domain + 授权 VMO 区间 + fault 异常通道」与 Zircon/seL4 机制同构。
- **#47 四层刀法的 user/ 永不动底线 + 启动计数回退**：与 ChromeOS verified boot 的变砖免疫同构，方向对（缺的是三字段/防回滚耦合，见欠账）。
- **#26 TLA+/模型检查折中**：seL4 成本数字（硬结论 10）反过来确认这是对的量级。
- **确定性验证文化（smoke 标记/金丝雀/对拍）**：QNX 教训的「流程证据」面，本仓天然在攒——将来无论 CRA 叙事还是认证叙事都是现成底座。
- **零分区 + 命名空间卷（#45/#6）**：与 Fuchsia FVM 同向；盘格式自由度反而是 FBE 后补的**优势**（趁 FAT 阶段把缝埋进将来的现代 FS 设计，无存量盘包袱）。

### 3.2 欠账（按期列出）

**v2（原盒：SMMU + PAC/BTI/MTE + devmgr + IRQ→channel）**：
- SMMU domain + DMA VMO 绑定（原盒内）；QEMU 双后端验证支线（smmuv3 / virtio-iommu-pci）；devmgr 授权协议带「可否被 IOMMU 圈禁」字段（不可圈禁 fail-closed）。
- BTI→PAC→MTE 分刀序（MTE = 分配器中心点刀，见冲突 C4）。
- **建议加件（待 C1 拍板）**：keystored 软桩 + berry-ksproto 消费面；认证绑定链最小闭环（锁屏口令→scrypt→CE/DE 双域解锁）；FAT 阶段整卷元数据加密层（可降 v2.5）；job/policy 位图进 SpawnSpec；SMC 分派表 + teed 骨架。
- 探测 loud 面：boot 期 CPUID/SMMU 探测进 smoke 断言（缺席必须 loud，防静默降级）。

**v3（度量链完整 + 远程证明探索）**：
- 度量链落码：BerryBoot `br entry` 前度量下级、handoff 测量清单 TLV、内核消费；swtpm 独立 smoke 相。
- 双路选主落地（TPM 2.0 兼容 / DICE——待 C2 拍板）；EAT/CBOR token；测量槽位编号表执法。
- FBE 密钥派生绑度量 + **前向密封**（预封到 A/B 下一 slot 预期度量——SKP 教训，与 #47 咬合，漏了则每次 OTA 毁钥匙）。
- RKP 式短命证书模型（不搞产线长命设备证书）。

**v4+（签名 + 反回滚 + 硬件根）**：
- BerryBoot 消费 AVB vbmeta；防回滚三档后端按真机 SoC 定（QFPROM 熔丝 / RPMB / SE）；rollback index 走 CounterBackend 真后端。
- 解锁面（状态机 + 擦数据语义 + 遥测）；AAVMF `SECURE_BOOT_ENABLE=TRUE` 自建固件作 QEMU 验签前置。
- 硬件根替换软件桩：RPMB/eFuse 接管计数器、StrongBox 分级第二 keystored 实例（同协议不同 SecurityLevel）。
- 远程证明 = 度量链 + EAT token + RKP 短命证书的整链。

### 3.3 不需要（明确不抄的，说明为什么）

- **自建 TEE OS / 占 EL3**：v1/v2 无需求、QEMU 建模弱（无 TZASC）；Fuchsia 态度 = TEE 是外设/固件厂商资产；若 v4 真要岛内 OS，L4 家族（sepOS/sel4-tee）路线届时评估——列实验轨道非产品依赖【SEC-2/4】。
- **seL4 式全内核形式化验证**：20 人年 + 32% 永久改动税，单人项目结构性不可付；#26 折中已定。
- **FDE（块层整盘加密）**：Android 十年补课刚删干净的方向——密钥粒度天花板锁死「认证前系统不能活」，不碰。
- **CC EAL 认证追赶**：EAL4+ 区分的是流程证据不是攻破难度（SUSE Linux 也拿到）；除非 v2 工业端出现采购门槛——那是 #39 重议触发器的事，不是现在的债。
- **Linux 二进制兼容面 / TEE 面的 Linux 兼容**：#14 既有裁决，安全面无例外。
- **绕能力模型开特权 syscall**（用户态直发 SMC、内核 RPMB 知识等）：违 #2 纯能力，一切经服务协议 + 内核受控桥。
- **签名生态自造**（自制签名格式/token 格式）：AVB vbmeta + EAT/CBOR + PSA 形态全部采兼容面，生态工具免费。

## 四、综合裁决建议

### 4.1 v1 已对齐确认清单

ADR #22（SMMU 头等）、#23（三扩展目标 day-one、Phase 推迟——仅措辞见 C4）、#24（度量链、信任根派生自度量非硬编码特权）、#26（TLA+ 折中）、#46（DMA 三铸件）、#47（L0 计数回退 + user/ 不动）**全部确认，不需要推翻**；v1 桩位策略（三扩展暂关、SMMU 探测、度量留桩）与「QEMU 先行」现实一致。本报告全部增量建议都是**加缝/加件**，不是改骨架。

### 4.2 v2 原盒之外的加件评估（任务点名三件 + 两件顺带）

| 件 | 建议 | 理由 |
|---|---|---|
| **RPMB 用户态驱动接口位** | **留缝，不实现** | v2 仍是 QEMU-only，RPMB 帧协议（512B 大端帧 + HMAC）无验收面；要落的是归属裁定入册（帧驱动 = 持证应用、HMAC = keystored）+ CounterBackend trait + RPMB 帧格式作块服务 wire 参照——真机世代接帧驱动时协议零漂移 |
| **fTPM/keystore 软桩** | **加（分两半）** | wire 面（berry-ksproto 纯函数 crate）**day-one 就立**（硬结论 8：七版重写教训 = wire 面一次性设计）；keystored 软桩 v2 落——认证绑定链最小闭环（SEC-7）与 swtpm 度量锚消费（SEC-3 §5）都需要一个持钥进程在位；SecurityLevel=Software 起步，真机换后端零协议改 |
| **FBE 密钥层级预留** | **缝 day-one、实现分层** | 盘格式缝（inode 16B nonce + u8 class 域 + mkimage 密钥材料分区槽）**现在埋**——first-format-only 是最贵的后补雷（硬结论 14）；认证绑定链 + CE/DE 双域语义 v2 随 keystored 落（Direct Boot 教训：认证前系统要能活）；完整 per-file FBE 等现代 FS（#27），FAT 阶段最多整卷元数据加密层（可降 v2.5） |
| **job/policy 位图（SEC-5）** | **加缝** | SpawnSpec 预留 policy 字段（W^X 执法 / 对象创建白名单 / 违规 kill-deny）+ critical 标志（父死陪葬）——Zircon job policy 的接口位，v2 消费；现在只是 struct 字段位 |
| **时间/应答权对象化（SEC-5）** | **加缝** | thread/process 预留 budget/period 字段位（恒 0 = 不启用）+ IPC 会话 reply 权槽——MCS 十年补课的教训：第一版不埋，日后补要动 ABI |

### 4.3 v3 度量链细化（DICE vs PCR + QEMU 可执行路径）

**两路取舍对照**（综合裁决：双路、共用测量清单）：

| 维度 | TPM 2.0 兼容面（PCR） | DICE |
|---|---|---|
| 适合端 | 手机 rich 档（有 fTPM/外挂 SE 位） | 手表低功耗端（无 TPM 位） |
| QEMU 可验性 | swtpm + tpm-tis-device 现成 | 纯软件（KDF/HMAC 可 host 单测） |
| 生态互操作 | TPM2_Quote/PCR 远程验证方现成 | Android 已用（attestation CDI）、轻量 |
| 实现体量 | 依赖 TPM 栈（TSS） | 一把 HMAC + 逐层递推 |
| 密钥供给 | RKP 式短命证书成熟 | CDI 派生天然无长命证书 |

- **裁决**：手机 = TPM 2.0 兼容、手表 = DICE；两路共用 handoff 测量清单 TLV + 槽位编号表，只换派生引擎——派生函数签名参数位 day-one 留（SEC-4 缝 4）。**此建议修订安全设计 §4「QEMU 用虚拟 TPM」的单路口径 → 冲突 C2。**
- **QEMU 可执行路径**（SEC-3 §3.7 命令照抄）：`swtpm socket --tpmstate dir=… --ctrl type=unixio,path=… --tpm2` + QEMU `-chardev socket,id=chrtpm,path=… -tpmdev emulator,id=tpm0,chardev=chrtpm -device tpm-tis-device,tpmdev=tpm0`——独立 smoke 相（同 smoke-x86 形态，不进主 smoke）；度量事件流语义对齐 TCG EventLog（append-only：event 描述 + digest）。
- **token 形态**：EAT（RFC 9334）/CBOR、接口参考 PSA `initial_attest_get_token(challenge)`（同步、带 challenge 防重放）；密钥供给从第一天按 RKP 思路（设备只产公钥、签名方隔离），避免工厂私钥债。
- **RootOfTrust 结构直接抄 Android 四字段**（verifiedBootKey/deviceLocked/verifiedBootHash/bootState）——生态工具可复用；`boot_state` 块是 #47 boot slot 与 #24 度量链的交汇点，day-one 记录（SEC-2 缝 3）。

### 4.4 v4+ 签名/反回滚/远程证明路线形态

- 签名 = BerryBoot 消费 AVB 兼容 vbmeta（四描述符 + rollback index 数组 + 锁定态）；mkimage 分区布局现在留 LBA 位；.bap manifest 加签名字段复用 berry-manifest 解析器骨架；**#56 已拍的三值版本域 + key-lineage 预留就是 anti-rollback 的 manifest 面**（核对项：v4 消费时无需再改格式）。
- 反回滚 = NV 计数器两值比较语义（TF-A AUTH_METHOD_NV_CTR 可照抄）+ 存放后端三档按 SoC 定（QFPROM/RPMB/SE）；比较语义与存放位置解耦，接口位 = `get_rollback_counter(slot)`。
- 远程证明 = 度量链 + EAT token + RKP 短命证书整链；DRM 类（Widevine L1）判给 teed + 厂商 TEE 集成，不自研。

### 4.6 优先级排序与验收线（QEMU 能验 vs 真机才能验）

| 批次 | 内容 | QEMU 能验 | 真机才能验 |
|---|---|---|---|
| **P0（v1 末，★ 项）** | 全部产链缝/协议 crate wire 面/文档冻结/遥测台账/CI 三件 | manifest.txt 对拍、ksproto host 测（家族先例）、拒面遥测落环、audit/deny CI 红 | — |
| **P1（v2 首刀）** | handoff 结构位、vmo_pin/PMT、policy 位、budget/period 位、探测 loud 面 | 探测 loud 进 smoke；新字段 no-op 回归零扰动（既有五相 smoke 全绿 = 验收线） | — |
| **P2（v2 主刀）** | SMMU domain（smmuv3 + virtio-iommu-pci 双后端）、BTI→PAC→MTE async、devmgr、keystored 软桩、认证绑定链（若 C1 拍 A） | 越界 DMA 被 SMMU 拦 + fault 异常通道上报；`-cpu max`/`mte=on` 下标记断言；软件 keystore 全链（wrap/unwrap/derive + 计数限速拒绝路径） | 硬件防回卷强度、RPMB/eFuse 真后端、SEP 类密钥不出域 |
| **P3（v3）** | 度量链落码、swtpm 相、EAT token、DICE 手表线、FBE 派生绑度量 + 前向密封 | swtpm extend/读 PCR 对拍；度量不符拒解封、计数回卷拒服务（拒绝路径全验）；前向密封跨 slot 演练（OTA 模拟） | 真 SoC boot ROM 信任锚、fTPM in TEE、防物理回卷 |
| **P4（v4+）** | vbmeta 消费、反回滚真后端、解锁面、远程证明整链 | AAVMF SECURE_BOOT_ENABLE=TRUE 自建固件下的验签/拒签；rollback 拒旧镜像 | QFPROM 烧丝量产流程、Titan M 类 SE、RKP 生产服务 |

**排序原则**：P0 全部近零成本且互不阻塞（可随 M-GUI 间隙逐件落）；P1 是「动 ABI 前最后一批发缝」；P2 按 C1 拍板定盘子大小；P3/P4 吃真机窗口（P8）的件都在 QEMU 先验接口形状与拒绝路径。**分栏的元原则**：凡「拒绝路径/接口形状/算法层」QEMU 全验；凡「物理不可逆（熔丝）、硬件边界（TZASC/SEP）、真实攻击者持续性」必须留到真机窗口——QEMU 绿 ≠ 安全，只 = 接口位没埋错。

## 五、冲突项单列（C1–C4，供拍板）

**C1：v2 盒子扩件 vs 小步纪律（挂 ADR #20/#22）**
- 现状：安全设计 §6 v2 原盒 = 切 `-cpu max` + 开三扩展 + SMMU domain + MTE slab；驱动模型 v2 = devmgr 最小面。SEC-4/7 建议追加 keystored 软桩 + 认证绑定链 + FAT 元数据加密层。
- 路线 A（推荐）：v2 扩为「原盒 + keystored 软桩 + 认证绑定链」（元数据加密层降 v2.5）——密钥服务是三段论缺的第四段，越晚立越贵；keystored 是 SEC-3/4/7 三个维度的共同依赖件。
- 路线 B：v2 严守原盒，密钥面 v3 前置设计——盘子不膨胀，但认证绑定链要等一个整版。
- 综合员倾向 A。

**C2：度量根单路 vs 双路（挂安全设计 §4/ADR #24）**
- 现状：§4 现文「累加到 secure element（QEMU 用虚拟 TPM；真机用硬件）」隐含 TPM 单路；SEC-3 建议双路（手机 TPM 2.0 兼容 / 手表 DICE，共用测量清单）。#24 原文「每级 hash 记 secure element」两路均满足，属设计文档修订级。
- 路线 A（推荐）：修订 §4 为双路选主 + 测量清单为单一事实源——手表线 ADR #39 定位下 DICE 结构性必要。
- 路线 B：维持 TPM 单路，DICE 列 v3+ 扩展。

**C3：TEE 立场成文（挂安全设计/驱动模型）**
- 现状：现行文档引 Fuchsia 参考、未明示业主/客户立场；SEC-2/4 裁定「不建 TEE、不占 EL3、BerryOS = secure world 客户端、keystored = 进程级最小近似，全 Rust TEE OS 仅列 v4+ 实验轨道」。
- 路线 A（推荐）：负面清单 + 客户端定位写进安全设计（改动小、与 QEMU 现实一致）。
- 路线 B：保留「远期自建 TEE OS」开放表述——风险 = 真机选型时造成业主幻觉。

**C4：ADR #23「源码零改动」措辞 vs MTE 真实侵入（挂 ADR #23/安全设计 §3）**
- 现状：#23 现文「切 `-cpu max` 时一次性开，仅 target-feature，源码零改动」；SEC-6 实测 MTE 需 `-machine virt,mte=on` 机器级选项 + 分配器中心点（libc tag 钩子、内核 slab 单一入口）才真生效，PAC 亦需 key 编排小刀——「零改动」仅对 BTI 严格成立。
- 路线 A（推荐）：修订 #23 为三档措辞（BTI≈零改动 / PAC=key 管理小刀 / MTE=分配器刀，v2 分刀落）。
- 路线 B：维持原文——风险 = v2 开窗时 MTE 工时被系统性低估。
