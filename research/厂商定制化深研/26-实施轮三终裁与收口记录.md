## §1 案一（查询面双件制）终裁：修改后收编

红蓝方向一致（收编），攻防合流后裁定：

1. **版本身份归 version VMO 轨**（红 A2 + 蓝归并案一致）：sys/info 不承载版本族键；VMO 轨 = 描述轨平台子面。
2. **sys/info 收缩为产品身份件**：OEM/产品维度键（蓝案键位表裁剪）；应用侧 v1 读取路径 = `.berryver` 文件读（G0 fs=[rootfs] 过渡态覆盖）。
3. **uname 旧债先还**（红 A2 现行犯：berry-libc sys.rs 硬编码 "0.1" vs v0.2.0）：随本收编刀修，值源 = .berryver。
4. **探测轨（试连）降为语义预留位**：连接原语在 svcmgr 端点直递下不存在（红 A1），v1 不宣称；可见性依赖 v3 命名空间如实记。
5. **载体**：#83 设计文档升版 §查询面节（不另立 ADR）；宣称绑闸 C（SDK 外发前）。

## §2 案二（安全快道）终裁：打回重研（采红队）

红蓝冲突处（红：打回 / 蓝：维持+补强）裁定从红队——四个结构性缺陷不因蓝队补强消解：

- B1 地板反噬为伪证（整树回退携带旧 lane 值必被地板挡）；
- B2 lane_revision 偏序/累积未定义；
- B3 carried 段原验签续用与 D9 槽身份绑定直接冲突（跨槽重放正是 D9 立法要杀的形态）；
- B4 Tier 1 回放执行者/场地/时机三无着落 + 「组合未经联测」死因复活。

**保留蓝队两件为重研输入**：security_level ≡ 版本管理标准 §1 安全级轨（四消费面同名同值、单源 abi.toml [platform] 物理预留位、u32 同宽）；整编队 security_level 声明义务（缺省继承不回退）。

**期间安排**（红队建议采纳）：案甲不动；security_level 字段位维持 #82 原语义「随首个安全公告裁」（19 号读作案二预内定属立法爬升，纠正）；重研 = 定向三题窄稿（地板次序重立 / lane 语义+段签名一体裁随 #77 裁 / 回放执行形态三定），随 #77 或 OTA 开刀窗启动。

## §3 SDK-2 签名链选型终裁：自研优先

采 24 号裁决包 + 保守合规取向：

1. **自研 ed25519/SHA-512-256 优先**——保 user/ workspace 零外部依赖纪律（31 crate 先例）；dalek 虽 BSD-3 相容（许可证非障碍，24 号双源核）但破纪律先例 + curve25519-dalek 依赖树 + cpufeatures none target 编译面风险。
2. **P0 首刀解耦**（24 号溢出预案为正路）：信封 TLV/账本 TOML/selftest 骨架先行合入（对选型零敏感）；原语向量门（RFC 8032 + Wycheproof）不过不合入。
3. **fallback 触发器**：自研原语两周内未过 Wycheproof mixed-order 门 → 重议外购（届时需实测 aarch64-unknown-none 试编 + 破纪律 ADR）。
4. **开工前终核三条**（24 号 §4.2 检查单）随开工令强制引用——P0 合入 = 闸 B 触发 = Q6 账本 schema 重议窗关闭。
