## §2 两项深挖：BCTS 红单根因（P0）与同帧在场清单

### 2.1 头号缝隙：slice 推荐值 × INTENT 标记 × BCTS 判定单（P0）

- **现象**：`bcts-run.sh --image acme-rich.img` → `FAIL: 镜像腿标记 240s 未到齐，缺：bare-24`。markers.sh 第 24 项 = `INTENT ok`（`tools/markers.sh:16` 数组序）；serial 内该标记零出现，且先打出一行断言消息 `it_probe: 时间帽计数须 ≥2（slow send 降级 + CH4b 结算封顶）`（`/tmp/drill44/boot/serial-acme-probe.log:218`）。
- **根因（算术 + 源码双证）**：INTENT 验收司机 `task_intent_probe` 睡 `8 * slice_ns` 等全链落定（`kernel/src/main.rs:3552`）——设计假设 8 片 ≥ 被测者 it_slow 的 200ms 睡（`main.rs:3520` 附近「睡 200ms（超每跳预算 50ms）」）：10Hz 时 8×100ms=800ms ≥ 200ms ✓；**250Hz 时 8×4ms=32ms < 200ms**，1000Hz 时 8ms 更短——司机早醒，it_slow 的 send 侧降级（budget_capped 第二源）尚未发生，`assert!(intent_budget_capped_total() >= 2)`（`main.rs:3596`）失败 → 探针任务死 → `INTENT ok` 永缺席。切片换算 62.5MHz/250=250000 与 eco 行互证。
- **隔离证明（三臂最小盘）**：default（无 params）/250/1000 三盘唯一差 = `etc/boot-params.toml`——default 臂 INTENT ok 在（7.709s），250/1000 臂双缺（§3 表）。非镜像内容问题、非 OEM 件问题，纯 slice 参数 × 测试时序耦合。
- **为什么至今没被咬**：42 号七靴验 bootparams 消费面只断言 eco 行/ktest done/零漂移（INTENT ok 不在其断言面）；17 号三档实验走 GUI marker 链（FBW→LAUNCH v=），ktest 相只读到 ktest done；40 号产线 product.toml **没开 bootparams**。四轮验证各自绿、合在一起才红——正是跨线缝隙的形态。
- **影响定性**：17 号 §4 推荐一（desktop 产品默认 250）+ G5 产品链（OEM 投放件）+ BCTS 镜像腿（bare 相 32 add-only 合同）三者今日互斥：**OEM 按平台推荐值配置，就拿不到 BCTS 判定单**（缺任一 bare 标记即 FAIL）。40 号「零针脚拿到判定单」的结论在 250 档不成立。
- **修窗归属（只报）**：调度线 owner——探针等待改墙钟（如固定 ≥250ms）或事件驱动（等 it_slow 入睡而非睡 N 片）；BCTS 侧标记合同不动（add-only 纪律正确）。修前 OEM 侧唯一绕道 = 退 10Hz 出认证镜像（丢推荐值收益）——不可接受，故 P0。

## §5 总账与判定

- **跨线期末考成绩**：四线十六能力 = **14 绿 1 红 1 缺**——红 = slice 250 × INTENT × BCTS（§4-1，修窗在调度线）；缺 = boot splash 未合主干（§4-2，修窗在 ux-unify 线）。其余全部一次跑通且互相咬合（bootparams 250 被 vgpu 后端 boot 消费、reap/rect 行在 OEM 镜像复现、真时钟链 RTC ok → clock 行、装载守卫吃 OEM 自有件、VBS 三方闭合）。
- **OEM 体验（可感度）**：定义站顺滑（lite→check→emit 三段各秒级，全键位一次过）；签名链站两处卡（鸡蛋循环 ~60s + 陈旧 berry-sign ~60s——都是「跨工具/跨时序」摩擦非工具本身难用）；组装站提取器与 CWD 两处小卡（~30s）；BCTS 站被 manifest 名先咬一口再吃红单。**T0→镜像 291s raw**（40 号 224s——全键位超集 + 新缝隙摩擦；一次成型估 ~40s）；镜像→boot 全标记 30s；镜像→BCTS 判定 243s（红）。
- **「组装不 fork」纯度**：全程零平台源码改动、零 git 写、OEM 投放物全在 /tmp（1 清单 + 5 app 源 + 2 资产 + 2 键 + 1 锚 + 1 条目提取）；工具族七件全消费、无一件需改才能走通（缝隙全是「多一步/旧一点」不是「走不了」，除 §4-1 的判定单）。
- **对 40 号结论的修订**：「零手工针脚 + OEM 拿到 BCTS 判定单」在**不含 bootparams 的配置**下维持成立；含 sched_slice_hz≥125（推荐档 250/顶格 1000）时判定单不可得——产线成线的适用域须加此注记，直到 §4-1 修复。
