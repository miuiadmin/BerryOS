## §2 实现正确性审查（逐项）

### 2.1 fe 域算术（fe.rs，5×51 limb）

- **乘法进位链/模约简**：mul（fe.rs:162-207）= 标准 donna 系 5×51 学乘 +
  19× 折叠 + 双轮进位；输入界（limb < 2^52）与 u128 累积界（< 2^111）推导
  成立。**独立对拍**：全 limb 最大装载（0xFF×31+0x7f，f1 = 2^255-1 ≡ 18
  mod p）自乘 = 324（python `f1*f1 % p`，LE `4401…00`）——实测相同；连乘
  百次 == 定长幂（幂自证）过；debug 构建（溢出即 panic）下 38 测 + 11 探针
  全程无溢出炸——进位链边界实证收口。
- **to_bytes 条件减 p**（fe.rs:56-96）：+19 溢出位判 q 的顶进位丢弃法，注释
  推导正确；`is_ge_p`（:122-129）limb 形 p = [2^51-19, 2^51-1 ×4] 自顶比较，
  仅归一态使用——from_bytes 出口天然归一 ✓。
- **边界**：p-1 收/规范形稳定、p 与 2^255-1 拒（`from_bytes_strict`，
  fe.rs:46-53）、-1 的懒约化表示（16p-1 中间态）规范形回 p-1——主刀测试 +
  本审计 python 对拍双向核过。RFC 8032 §5.1.3 步 1「resulting value >= p,
  decoding fails」语义逐句对上。
- 指数常量（p-2 = 7f…eb、(p-5)/8 = 0f…fd、p-1 = 7f…ec）：python 重算一致。

### 2.2 ge 点运算/解压缩（ge.rs）

- **完备加法**（ge.rs:67-79）与 RFC 8032 §5.1.4 公式逐项对（A/B/C=2dT1T2/
  D=2Z1Z2/E~H 及 x3..z3 排布全同；C 写作 `tt.mul(&D).add(&tt.mul(&D))`
  = 2dT1T2 ✓）；「完备」前提（a=-1 平方、d 非平方）由
  `constants_self_proof` 测试运行时自证（D = -121665·121666⁻¹、d^(p-1)/4 ≠ 1）。
- **解压缩三拒收面逐类验**（ge.rs:135-161 vs RFC §5.1.3）：
  ①y ≥ p 拒——本审计独立扫频 y = p, p+1..p+15、2^255-1、bit255 置位全拒，
  y=p-1 收（恰界下）；②非平方拒（v·x² ∉ {u, -u}）——主刀扫频 + 向量门；
  ③x=0 ∧ sign=1 拒（identity 带符号位例）——主刀钉板 + RFC 附录 A
  `decode_base`「x.iszero() and xs!=x.sign()」逐句同。
  常量 D/SQRT_M1/BX/BY/BT limb 值与 donna 系已知值一致且有运行时自证回算
  （B 压缩形 == 5866…66）。
- **低阶点语义（与 F1 相关的边界）**：identity（0100…00）是合法曲线点，
  decompress 收（RFC 语义正确——低阶点不属解析拒收面）；用 identity 顶替
  真公钥验真签名 → verify 拒（方程不过，本审计探针实证）。**但** fixture 的
  acceptable 小阶/混阶例是与各自公钥方程精确一致的签名——见 §3.3/F1。

### 2.3 sc 标量算术（sc.rs）

- **设计偏离已声明**：24 号 §3.8-D3 建议 ref10 逐字移植，主刀改自研 MSB 移位-
  条件减约减器（sc.rs:4-15 头注如实记理由）——偏离声明在册，非隐瞒。
- **reduce512**（sc.rs:74-90）：不变式「轮首 acc < L ⇒ 移位后 < 2L+1 ⇒ 条件减
  后 < L」推导成立（L < 2^253，无 4-limb 溢出）；掩码选择 `sel4(borrow^1,…)`
  语义核对正确。**边界独立对拍（任务书执法点）**：输入全 0xFF（2^512-1）→
  python `(2**512-1) % L` 逐字节同；2^512-2 / 零 / L / L-1 同法全过；
  另 6 组 python 随机（seed 0xA101）`x % L` 与 `(a·b+c) % L` 全过。
- **sc_muladd**（sc.rs:107-139）：512 bit 学乘 + 加 c + 归约；「a 可为 clamped
  任意 256 bit、无 <L 前置假设」实证——clamp 最大形（f8ff…ff7f，即
  0x7fffff…fff8）× (L-1) + (L-1) python 对拍过。尾进位 `while carry != 0`
  见 §4/F2。
- **sc_is_less_l**（sc.rs:142-149）：自顶字节比较，==L → false（不小于）；
  S=0 收（0 < L，RFC §5.1.7 range「0 <= s < L」语义正确——RFC 对编码方另用
  0 < S < L-1（§3.1），验签侧无 S>0 要求，两处不混）。

### 2.4 ed25519 verify/sign（ed25519.rs）

- **expand/clamp**（:34-45）：a[0]&=0xf8 / a[31]&=0x7f / a[31]|=0x40 逐位 =
  RFC §5.1.5（低 3 清、bit255 清、bit254 置）= 附录 Python
  `a &= (1<<254)-8; a |= (1<<254)`。
- **sign**（:55-81）：r = SHA-512(prefix‖M) mod L → R=[r]B → k = SHA-512(R‖A‖M)
  → S = (r+k·a) mod L——与 §5.1.6 逐步同；确定性 nonce 核实见 §4.2。
- **verify**（:84-113）与 RFC 8032 §5.1.7 逐句对：
  - 步 1 三方解析：A/R decompress 失败拒（y≥p/非平方/x=0∧sign）；S 段
    `0 ≤ S < L` 越界拒（sc_is_less_l）——「including S being out of range」
    （§3.4/§5.1.7）执行 ✓；
  - 步 2：k = SHA-512(Renc‖pk‖msg)，哈希输入用**原始编码字节**（非重编码）——
    与 §6 官方 Python 参考 `sha512_modq(Rs + public + msg)` 同；
  - 步 3：**cofactorless** `[S]B == R + [k]A'`——RFC §5.1.7 原文明示
    「It's sufficient, but not required, to instead check [S]B = R + [k]A'」
    （rfc-editor.txt :764），且 RFC §6 官方参考实现即用此形。模块头
    （ed25519.rs:11-16）引用正确、方向正确（比 8· 形更严——对小群**残差**），
    但其对 acceptable 类的覆盖面推断有误差，见 F1。
  - dom2 = 空（PureEdDSA）✓。
- **S 段越界独立扫**：L / L+1 / 2^256-1 全拒；S=L-1（真值外）收解析但方程
  必拒——实测拒 ✓；R 段 y=p 拒 ✓。

### 3.2 独立抽 5 条向量手工重算（openssl CLI，命令与输出）

工装：DER 包装（pub SPKI `302a300506032b6570032100`‖32B；priv PKCS8
`302e020100300506032b657004220420`‖32B seed），`openssl 3.6.4`。三面：

```text
# 验签面（官方 sig）
$ openssl pkeyutl -verify -pubin -keyform DER -inkey v2.pub.der -rawin \
    -in v2.msg -sigfile v2.sig
Signature Verified Successfully          ← TEST 2/3/1024/SHA(abc) 四条同
$ (v1=TEST 1 空消息) … -in v1.msg -sigfile v1.sig
pkeyutl: Could not allocate 0 bytes for oneshot sign/verify buffer
                                         ← CLI 0 字节缺陷，实测复现

# 重签面（seed → sig，比官方向量；确定性 nonce 跨实现证据）
$ openssl pkeyutl -sign -inkey v2.priv.der -keyform DER -rawin -in v2.msg \
    -out v2.resig && cmp v2.resig v2.sig → 逐字节相同（TEST 2/3/1024/SHA(abc)）

# 公钥派生面（seed → pk）
$ openssl pkey -in v1.priv.der -pubout -outform DER | tail -c 32 | xxd -p
d75a980182b10ab7…707511a  == 官方 pk（5/5 全同，含 TEST 1）
```

结论：**5/5 三面闭环**——TEST 1 的验签/重签面被 OpenSSL CLI 0 字节缺陷挡
（主刀 vectors.rs:16-18 注记**属实**，非托词），其 sig 值由 RFC 两源 + dalek
TESTVECTORS 首行（直抓核对：`9d61…7f60:d75a…511a::e556…100b:`）+ 自研
verify 三源互证。另做随机双向 fuzz 10 轮（我签→openssl 验 / openssl 签→
我验 / 双实现签名逐字节比）全过——确定性 nonce 双实现一致是重签面最强的
一条证据。

## §4 安全声明诚实性

### 4.1 常数时间注记（发现 F2，低）

- 声明原文（ed25519.rs:23-26）：「常数时间**风格**（**秘密相关分支为零**：
  标量位经掩码选择、约减条件减经掩码；解压缩/S 越界检查分支于公开输入），
  未做侧信道审计，不用于在线敌手环境」。fe/ge/sc 模块头同款注。
- 逐项核：fe add/sub/mul/sq 直线码 ✓；`ct_select`/`ct_eq`/`ct_neg_if` 掩码 ✓；
  `scalar_mul` 256 轮双-常加 + `ct_select`（ge.rs:94-102）✓；`reduce512`
  512 轮定长掩码条件减 ✓；`pow` 定长平方-乘 + ct_select（指数公开常数）✓；
  verify 全路径只碰公开输入（无秘密可泄）✓。
- **例外（F2）**：`sc_muladd` 加 c 后的进位传播 `while carry != 0 &&
  k < 8`（sc.rs:130-135）——循环次数由秘密派生数据（a·b+c 的高位进位链）
  决定，是**秘密依赖分支**，与「秘密相关分支为零」一句冲突。泄露面评估
  （推断，量级）：每次 sign 约 0–3 bit 关于 a·k+c 的 bit 256+（S 与 k 公开、
  a/prefix 秘密）；sign-only、当前威胁模型（离线验签/平台签发，P3 前不涉
  在线敌手）下实际可忽略——声明的兜底句（「未做侧信道审计」）覆盖此缺口，
  但「分支为零」四字过宽。低危，建议姊妹刀顺手改为定长 4-limb 进位传播。
