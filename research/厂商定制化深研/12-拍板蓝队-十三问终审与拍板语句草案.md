## §1 终审框架（判据一屏）

1. **证据复核四问**：①10 号给的选项后果是否如实；②「最强反论」是否真是最强（有无更强反论被略）；③有无漏第三案（本稿逐问做过第四案检索，见各条「漏案检查」）；④建议倾向的证据链是否闭环（每个倾向都能走通「底稿证据 → 结构约束 → 代价机制」）。
2. **改判判据**：仅当 10 号的载体/内容会导致「拍板落空」——空转、无宿主、错过唯一窗口、或与已核事实冲突——才改判；不为改而改。本文两条改判均属此类。
3. **裁定语句三硬性**：主语明确（平台/OEM/认证方/组装器/appd…）；可执行（无「视情况/酌情/适时」）；重议触发器是**新证据事件**而非「有人想重议」。
4. **对抗纪律的自检挂钩**：每条复核都先做「攻击」（找反例/找冲突/找更优解），再做「辩护」（若 10 号站得住，写明为什么站得住，不和稀泥）；攻不动的才维持。

## §2 Q1–Q13 逐条终审

### 2.1 Q1 OEM 身份发放机构与规则

**证据复核**：
- 选项后果与反论**如实**：星状三理由（16B 姓氏帽算术 / 信任不传递与「永不引 X.509 链」同哲学 / 父倒子不连坐）在 09 号 §2.2 全维表齐全；「Android 无身份层也跑起生态」作为星状最强反论成立，但**它不是最强**——最强是「平台注册处 = 身份瓶颈单点」（05 号 §5-N6/§6-1），10 号已列入证据栏，未降格，合格。
- **漏案检查**：任务点名的「星+委托」混合案——OEM 前缀自分配 + 平台副署（每笔分配平台在账本副署锚定）。复核结论（推断）：该案与案 C 在信任结构上**等价**（最终锚定权都在平台），差异仅在命名形态（前缀 vs 元数据）；而前缀形态额外付出 16B 容量（`acme-` 吃 5B）且制造「委托可传递」的观感——**被案 C 严格支配，不构成独立第四案**。真正的第四案「纯树+平台否决权」被 09 号 §2.2 信任语义行否决（账本 anchor 链 = 链式信任回潮）。无漏案。
- 证据链闭环判定：闭环。算术约束（berry-manifest :484/:650-661，两源）+ 哲学约束（SDK-2 §二 X.509 禁令）+ 案例对照（Apple Team ID 两源：SDK-2 §三 + wf verdicts D1，09 号 §2.2 记两处一致）。09 号 §7.1-1 的诚实边界（「≤3 家 OEM 时此选择无意义」）已由 V4 的低成本预埋对冲。
- **蓝队攻击一处**：案 C 的滑坡风险（元数据被游说升格为真实委托）在 09 号只有纪律句（§2.4-4「信任不随新字段传递」），没有落到执法面。**辩护升级**：把「issued_by/kind 永不进入任何信任判定路径」写成 #77 的立法句，且 boot 对账（09 号 §2.3-2 的三条机器判据）只读 lineage 不变量不读元数据——滑坡从此需要改 ADR 而不是改游说对象。

> **拍板语句草案**：
> **Q1 裁定**：平台为 OEM/ODM/开发者 lineage 的唯一分配机构（星状），多级层级关系降级为账本元数据（kind/issued_by），且**永不进入任何信任判定路径**（boot 对账与验签只读 lineage 不变量，不读元数据）。依据：09 号 §2.2 全维表（16B 帽算术 / 信任不传递 / 不连坐；berry-manifest :484/:650-661）+ SDK-2 §二 X.509 禁令 + 05 号 §5-N6；边界：不裁发放运营规则（注册流程/审核字段/命名占用仲裁——归治理文档，首 OEM 接触前完成）；integrator lineage 归品牌商、ODM 不出现在信任面（09 号 §2.3-3）照采；重议触发：①单家 OEM 赞助的 ODM 数量使平台注册吞吐成为**实测**瓶颈 ②首份 OEM 合同坚持要求子分配权并以合作相胁；载体：并入 **#77**（账本 schema 随其落册，09 号 §2.4-3「不另开通道」），发放运营规则归治理文档。

**压力测试**：错误最早暴露 = 首家大 OEM/ODM 集群谈判（渠道权力诉求被拒 → 合作降级）或平台注册吞吐瓶颈；代价为商业级摩擦（N4 面风险，本就「架构管不到」），账本本身无损。方向性不对称（推断）：若星状错了，加子分配语义只需元数据升格，账本数据零迁移；若树状错了，要拆已发信任链——**星状是回退便宜侧**，选错可挽回性高。

### 2.2 Q2 产品配置层形态

**证据复核**：
- 三半径论证（消费/治理/写入，08 号 §2.4）如实且成立；C 案（cargo feature）与 P2 公理的正面冲突如实。
- **漏案检查**：「合一但拆两个物理文件（schema 级 include）」——复核为 A 案的装饰性变体（override 语义下 OEM 只写覆盖值，纯参数产品本就得到极小清单），不构成独立案。
- **蓝队攻击两处，均立**：①**双主风险的具体死法**——OEM 覆盖某参数后，上游为安全改该参数缺省（thermal/PM 帽类），OEM 旧覆盖**静默钉死**安全修复。10 号只记了「双主风险」一般形，未给分类处置。已有先例可依：ADR #68「KC-P1..P5 kill criteria 不可关闭」+ 04 号 §5 行 4 同族（两源）——**参数应分「自由覆盖/受限覆盖（安全类）」两档**。②**早引导攻击面**：参数子表进内核引导读取路径（08 号 §6-Q3 的 INITRD 定址段选项），OEM 可写数据首次进入 boot 关键解析面——解析必须定界（定长头/有界循环）。08 号未处理此面（推断，机制细节属 #83 设计文档）。
- 证据链闭环：闭环（08 号 §2.4 + RFC-0215 同构 + P2）；01 号 §1.1「参数表机制面未见实现【待核实】」如实保留。

> **拍板语句草案**：
> **Q2 裁定**：平台将 ADR #42「启动配置参数表」与产品清单一并立法为**同一件**：落点 = 产品清单 `[platform.boot] params` 子表，缺省值归上游（编译期常量仍是缺省）、清单只存覆盖值（override 语义）；cargo feature 永不参与产品差异。**蓝队补强两条**：①参数分两档——自由覆盖档与受限覆盖档（thermal/PM 帽、kill criteria 类安全参数不可覆盖或受限覆盖，ADR #68「不可关闭」同族纪律），键分类随 #83；②params 子表是内核引导路径唯一可读的产品清单片段，其解析面必须定界（定长/有界），机制选型（INITRD 定址段 vs fw_cfg 新键，08 号 §6-Q3）随内核读取刀。schema 分级（01 号 §5-Q3 就此关闭）：platform 键变更走 L2/api-diff（章程 §六），product 键 add-only 随组装工具版本化，两面未知键一律硬拒。依据：08 号 §2.4 三半径 + 04 号 P2 + RFC-0215（经 08 号转引）+ ADR #68；边界：不裁参数键集、不裁读取机制选型；重议触发：①首个真实产品清单发现 params 子表表达力不足 ②内核引导读取与 handoff/度量链设计冲突；载体：**ADR #83**。

**压力测试**：最早暴露 = ①内核引导读取 params 的实现刀（解析面定界若缺，此处显形）②上游首次改安全类缺省而某 OEM 恰有覆盖（双主风险首个实例）。代价：安全类覆盖若未受限，安全公告被 OEM 旧值静默钉死（高）；解析面未定界，早引导攻击面扩张（中）。两处已前置补强；残余风险 = 键分类遗漏，靠首个真实产品清单对拍兜底。

### 2.3 Q3 产品包签名形态

**证据复核**：A/B/C 后果与反论如实（B 与增量更新冲突、C 使 V3/V8 悬空——两处反论都是结构性的，不是偏好）。
- **漏案检查**：「A + OEM 镜像级整体签名（双保险）」——复核为冗余：镜像完整性已由**平台签名的中心清单（vbmeta 式）+ OEM 委托段**承担（09 号 §1.2-插入点 B，AVB chain partition 同构），再加 OEM 对自己未逐字节生产的镜像签名只添仪式不添安全（推断）。驳回，无漏案。
- 证据链闭环：闭环（04 号 §3.1 + 09 号 §1.5/§2.3 + SDK-2 §五镜像签名先例，三源）。09 号 §7.2-2 的叙事滑坡风险（完整性账被讲成安全性账）应随裁定挂到 Q10 披露位。

> **拍板语句草案**：
> **Q3 裁定**：产品包（清单+资产+白名单）走 `.sig` 信封、由 OEM integrator 钥签；最终镜像完整性由平台签名的中心清单（含 OEM 委托段）与度量链承担，**不设 OEM 级镜像整体签名**；度量链对闭源件只作完整性账不作安全性账（认证叙事纪律随 Q10 披露位执法）。依据：04 号 §3.1 + 09 号 §1.5/§2.3/§1.2-插入点 B + SDK-2 §五；边界：不裁中心清单/委托段字段级格式（随 #77）；重议触发：①编队 OTA 首实现发现委托段语义不足以表达多 OEM 编队 ②首个真实组装上度量链重组对账不可复现；载体：原则进 **#83**（依据栏显式引用 #77 的 Q1 裁定），信封/清单字段细节归 **#77**。

**压力测试**：最早暴露 = 编队 OTA 首实现（委托段/双段验签歧义）或首个组装期白名单校验。若错（确需镜像级签名），回退 = 中心清单 add-only 加一层 OEM 签名段（推断，周级代价）；**最晚重议点 = 首个编队 OTA 实现合入前**（之后改 = 更新协议 break + 全量重刷，09 号 §5.4）。

### 2.4 Q4 BCTS 执法位

**证据复核**：A/B/C 如实；07 号 §8.1 的自警（「只抄 freeze/thaw 而无 tier 政策，冻结的可能是空集」）被 10 号如实收进 A 的反论——这是全套决策包里少见的「源头自警如实传递」，合格。
- **蓝队攻击一处，立**：C 案反论「门禁依赖 V13 落地，门禁晚于清单工具则空转」是真的，但 10 号没给解——其实解就在它自己的证据栏里：**工程种子挂 smoke/abi-check 现役轨道**（01 号 §1.6）。裁定应把 v0 门禁宿主**钉死**在现役 just 配方树，berry-assemble 成型后迁移——空转期归零。
- **漏案检查（此为 10 号真漏项）**：04 号 §7-Q4 原文三问中的「**谁跑**（OEM 自测+平台裁决 vs 第三方测评）」在 10 号的三个选项里没有对应裁定点——选项只裁了执法位与节奏。蓝队补裁：OEM 自测 + 平台裁决，工具与测试集开源免费（CTS 模式，07 号 §6-12 + 04 号 §4.1 两源）；「结论位」挂 OEM lineage 与信任账本。第三方测评不进 v1 裁定（认证信用为零期无第三方可托，06 号 §5.3），留重议触发。

> **拍板语句草案**：
> **Q4 裁定**：BCTS 立为独立于 G0–G5 的认证套件：工件 = 随上游版本冻结的测试件（冻结/回放制），认证 = 用设备声称兼容版本的冻结件在其上回放；覆盖策略 Tier 1 先行（在野回归 = 用例欠账记账）；**v0 执法宿主 = 现役 just 配方树**（smoke/abi-check 轨道），berry-assemble 成型后迁移门禁——门禁不依赖任何未开工件。谁跑 = OEM 自测 + 平台裁决；工具与测试集开源免费可自测，「BerryOS 兼容」结论由平台签发并挂 OEM lineage 与信任账本；认证元数据（含 Q10「含闭源件」披露位）随认证结论同定义。依据：07 号 §6-1/6-4/6-5/6-7/6-12 + 04 号 §4.1 + 01 号缺口 4 + 05 号 N5；边界：不裁发布节奏数值（每 minor/每 major，随 #84 立项稿）、不裁商业模式条款、不裁申诉流程（07 号 §8-5 自认缺运营面）；重议触发：①首 OEM 要求第三方测评背书 ②冻结件维护成本超 CI 预算 ③门禁向 berry-assemble 迁移期出现执法空窗；载体：**ADR #84**（依赖 #82 能力基线、#83 槽位合同面先行）。

**压力测试**：最早暴露 = #84 落库后**首个冻结件发布**（冻结件数量/覆盖率报表立即可见空集风险）；门禁宿主若未钉死，空转期 = berry-assemble 未落地窗口（本裁定已消除）。代价：BCTS 空转 = 认证形同虚设，首 OEM 自测即测出；「平台裁决」公信力在认证信用为零期无外部对拍——**本稿最弱一处**（§5-1），只能靠冻结件 hash 钉快照（07 号 §6-7 防特调结构性）部分对冲。

### 2.5 Q5 治理杠杆形态

**证据复核**：A/B/C 后果如实（02 号 §3.2 反垄断、04 号 §3.4「三者缺一则 fork 无代价」两源）；「B/C 延后至首 OEM 接触前再裁」的时点判断与 05 号 N4 一致。

### 2.12 Q12 跟版义务 SLA

**证据复核**：两维拆分（机制维/N 值维）正确；「现在拍 N = 伪精确」（07 号 §5.2 窗口数学：N×发版周期 ≥ 生态最大迁移周期，两边都是变量）如实。
- **蓝队攻击两处，均立**：①**延后的隐性碎片化**——N 留到「首 OEM 合同」再裁，逐家议价必然产出逐家 N，制度还没起跑就碎片化。解 = **公式现在裁、数值延后、多 OEM 统一值**。②**隐藏前提未落册**——D2 判据的执行点在编队检查（09 号 §3.2 D2「设备编队检查」），而编队 = 案甲（一次 L1 槽翻转，09 号 §5.1 案甲表明示「跟版义务的 OTA 面执法——D2 判据在此生效」）；10 号 §2.12 没把案甲带进裁定——若案乙（分刀）日后复活，D2 失去执行点。案甲应随 #77 与 Q12 同刀落一句。这是本终审发现的唯一**裁定缺项**。
- 「warned 期只警告不回退」10 号留给治理文档——蓝队认为原则可现在裁（expired 才触发回退），执行时机（编队节奏）才留后。

> **拍板语句草案**：
> **Q12 裁定**：跟版义务机制维 = 账本/索引字段执法（last_revision/cert_status + D1–D4 状态机，随 #77）；**隐藏前提一并落册：平台工件与 OEM 三包编队 = 一次 L1 槽翻转（09 号 §5.1 案甲），D2 的执行点在编队检查**；N 值公式现在裁、数值延后：N × 上游 minor 发版周期 ≥ OEM 最大迁移周期（6–12 个月，04 号 §8.2-2），数值于首个 minor 发版节奏确立后、首份 OEM 合同签署前必裁，且**多 OEM 统一 N 值**（不逐家议价）；停更处置采案 b（替换面回退，依赖 V8 回退位），**回退触发点 = cert_status 转 expired，warned 期只警告不回退**（原则今裁），expired 后的编队执行时机随 #77/OTA 设计。依据：09 号 §3.1–§3.3 + §5.1 + 07 号 §5.2 + 02 号 §2.2（缺跟版执法 = 版本碎片）；边界：不裁 N 数值、SLA 合同条款、摘牌后存量设备应急通道（09 号 §6-Q12）；重议触发：①首批 OEM 跟版失败率系统性偏高（窗口过紧误伤）②发版节奏变更使公式失衡 ③trivial 刷新包成为主流合规策略（字段天花板暴露，BCTS 实质性跟版加重）；载体：机制并入 **#77**（含案甲一句），N 值与 SLA 合同延后（治理文档）。

**压力测试**：最早暴露 = 首个 minor 发版节奏确立 + 首个长周期 OEM 机型触发 D1 首转 warned/expired；若 N 公式错（窗口 < OEM 周期），首批 OEM 制度性 expired = **认证体系信誉首战失利**（不可逆的声誉部分）。「公式今裁+统一值」把「伪精确」与「逐家议价碎片化」两个失败模式同时关掉。

## §5 反面自检（蓝队自己的弱点，如实写）

1. **最弱裁定 = Q4「谁跑」补判**：认证信用为零期的「平台裁决」没有外部对拍（06 号 §5.3：工业客户第一句是「谁认证过你」）；若首 OEM 不信任平台自裁，该裁定会被商务现实改写。本稿只能裁形态、裁不了信用——此弱点的缓解（冻结件 hash 钉快照的防特调结构性）只能覆盖「裁决是否可复现」，覆盖不了「裁决者是否可信」。
2. **两条改判存在过度收紧倾向的可能**：把负面承诺写进 #82（Q5）给未来商业杠杆立法加了一道 ADR 翻案成本（虽低但非零）；披露位前移到 #84（Q10）假设首批认证早于治理文档发生——若实际顺序相反，改判无增益。主会话若认为「连负面承诺都不该现在表态」，Q5 可退回 10 号原案，代价（谈判立场真空）自担。
3. **压力测试的时间窗多为类比推断**：Q8「开放后 1–2 季度」、Q9「6–12 个月」、Q10「P8 后首 SoC 厂」均从底稿案例归纳，非 BerryOS 实测——可作风险排序参考，不可当承诺。「最早暴露点」的可信度排序：Q6/Q3（机制性，高）> Q12/Q11（事件性，中）> Q8/Q9/Q10（类比性，低）。
4. **未审区声明（任务边界）**：本稿只终审 10 号 §2 十三问；§1 预埋清单（V1–V16/W/X 档）与 §3 路线图本身未做对抗终审。若主会话对 §1 改判（如砍 V12/V14 或推迟 V13），Q2/Q8 的载体是否仍成立需复核——V13 是 Q4 门禁迁移与 Q2 清单实装的宿主，**砍 V13 = Q4 的 berry-assemble 迁移与 Q2 的消费面同时悬空**（蓝队提示，此为跨块咬合点）。
5. **裁定语句的「立法句化」风险**：本稿多处把底稿「缓解建议」硬化为裁定内容（Q1 立法句/Q6 两步发布/Q11 阀门/Q12 公式）——这些是蓝队基于结构推论的增量，**未经两轮底稿原始作者复核**；主会话采纳时应视为「更强草案」而非「已验证结论」，逐条可退回 10 号原强度。
