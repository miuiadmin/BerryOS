## §1 案 c 实施复核（六项实跑）

### 1.1 独立进程性（不占 svcmgr 帽）✅

- **svcmgr 零链 berry-crypto**：`user/bins/svcmgr/Cargo.toml` 全依赖表九件（berry-sys/loader/exec/blkproto/netdproto/manifest/psproto/guiproto/appproto），`grep -c berry-crypto` = **0**——验签本体不进单体，案 c 载体裁决字面兑现（§1.3.4「本 crate 不链 berry-crypto」，svcmgr main.rs :5720 头注同文）。
- **spawn 面零新 ABI**：守卫经 `spawn_rootfs_elf`（berry-exec lib.rs :398）+ env gift `berry_handle_duplicate(H_ROOTFS, RIGHT_READ|RIGHT_TRANSFER)`（main.rs :5762——TRANSFER 位与 2abcfed RIGHT_TRANSFER 全生态执法互咬，缺位即 `sig dup` 降级）；berry-verify 侧 `berry_channel_recv` 收 argv blob + gift[4]（main.rs :307-325，gift 布局 = spawn 契约前缀四槽 + extras[0]）——合同双侧同改义务互指（两文件头注）。
- **帽分离实证**：svcmgr 平像 126,976B（31 页）= 轮十在册现役值**同尺寸**（守卫入末页 slack，§1.2）；berry-verify 为 rootfs ELF 进程，走 ELF 映射路径——该路径内核侧唯一映幅帽 = `ELF_MAP_MAX` 16MiB（berry-spawngeo lib.rs :34，与内核 VMO_MAX_SIZE 同值双侧同步）；`USER_CODE_MAX` 128KiB 只在 flat 路执法（kernel/src/user.rs :1765-1768 assert + elf2flat `--max`，justfile :82）——「不占 svcmgr 帽」结构性成立。
- **措辞对账（观察）**：34 号附记②「rootfs spawn 面无 128KiB 帽」= 内核实际；设计 §1.3.4-②「独立进程各享 USER_CODE_MAX 128KiB 帽」= 概念性表述（该帽不绑 ELF spawn 路径）。结论两读皆成立：berry-verify 映幅顶 26,741B ＜ 128KiB ＜ 16MiB。记 §4-P2b 修词建议。

### 1.2 svcmgr 守卫段增量实测（≤1KB 红线）✅——/tmp 隔离树 A/B 双构建

方法：user workspace 全量拷贝 /tmp（排除 cargo-target），B 变体把 `p3_sig_guard` 函数体摘除为立即 return（调用侧/签名/ABI 零动，退出语义 = 缺席分支等价），双 target 隔离构建（`aarch64-unknown-none --release -p svcmgr`，RUSTFLAGS="" 正典链）：

| 量 | A（守卫在） | B（摘除） | 增量 |
|---|---|---|---|
| .text | 67,700B | 66,784B | **+916B** |
| .rodata | 28,136B | 28,048B | **+88B** |
| .data/.bss | 2,392 / 20,192B | 2,392 / 20,192B | 0 |
| ELF | 103,728B | 103,728B | 0（段内吸收） |
| flat 平像（elf2flat --max 131072） | **126,976B** | **126,976B** | **0 页** |

- **判：+916+88 = +1,004B ≤ 1,024B 红线**（余 20B，2% 余量——贴线过）。平像零页增：守卫代码落既有末页 slack（.text 末页余 1,932B ≥ 916；.rodata 末页余 2,744B ≥ 88），故 126,976B 与轮十在册值同尺寸——**尺寸墙余量未被动用**。
- **产物复现链**：A 变体 ELF（103,728B/.text 67,700/.rodata 28,136）与工作树 `user/cargo-target/.../svcmgr` 逐段相等；flat 与 `kernel/src/userbins/svcmgr.bin`（126,976B，22:48 产）同尺寸——工作树产物 = HEAD 源正典构建。守卫字符串族（`sig ok/bad/hang/nosvc/nopk/dup/spawn` + `bin/berry-verify` + `etc/trust-pk` + `.bap.sig`）在 svcmgr.bin 内偏移 68k/78k 段全数定位——**守卫确已编入现役内嵌像**。
- 附：kernel ELF（隔离重建）内 `sig ok`/`bin/berry-verify` 字串在席——内核 include_bytes 面同步。

### 1.3 berry-verify 尺寸复测（26729B 数字复现 + 红线对照）✅/⛔

- **数字逐字复现**：正典链重建（`RUSTFLAGS="" cargo build --release -p berry-verify --target aarch64-unknown-none`，同 `just build-user` :51-56 清旗手法）→ PT_LOAD filesz = 24,308 + 2,421 = **26,729B**，与申报**逐字相等**；重建 ELF 与工作树产物（22:32，31,192B）**逐字节相同**——「26,729B」= 映幅（两 PT_LOAD 文件域和），口径与 link-user.ld :4「映幅…≤10KB 红线执法」自洽。
- **红线对照**：26,729 ＞ 10,240（**2.61×**，KiB 口径）＞ 10,000（**2.67×**，十进制 KB——任务书口径）。10KB 红线在册唯一锚 = `user/bins/berry-verify/link-user.ld` :4（任务书口，仓内无第二源）——超线成立，**blocked 上报合规**（附数字齐全）。
- **量级解剖（记档）**：hello 同链对照映幅 285B（文件 4,736B）——berry-verify 26,729B 全量为自链 berry-crypto（ed25519 验签 + SHA-512/256 + 信封/账本解析）+ berry-manifest + berry-loader cpio 步进 + syscall 面的独立运行时。设计 §1.3.4-②「验签最瘦 +1,772B 量级」是**内联增量**口径（复用单体已链代码）；独立进程 = 全量携带——两口径不同数，设计档未注明区分（记 §4-P2b 附带）。
- **构建坑（实咬）**：不清 RUSTFLAGS 直跑 cargo build（吃到根 .cargo/config.toml 的 `-neon` 旗）→ 映幅 29,824B（+3,095B 整数回退代码）。`just build-user` 已显式清旗；直跑构建面需自觉——berry-verify 头注/build.rs 未记此坑（hello 同链先例只在 justfile :51-56 注）。记 §4-P3b。
