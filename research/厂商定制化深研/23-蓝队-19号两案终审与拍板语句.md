> **查询面裁定**：平台将开发者运行时能力查询面立为**双件制 + 版本轨让位**：①**描述轨·产品子面** = `sys/info` 静态件——组装器（V13 管线步⑧）从产品清单 + 板表 + locale 键生成，住系统树随槽整树验签，消费 = 文件读（零新 IPC、零新常驻服务、零 syscall 增量，nr_ceiling=45 预算不动）；键位 = `schema`/`product.name·vendor·board`/`platform.arch·feature_level·build_type`/`locale` 族/`platform.security_level`——**版本族键（platform_revision/semver/构建标识）不进 `sys/info`**。②**描述轨·平台子面** = version VMO 轨（`kernel/src/sysver.rs` 内核编译期成像 + 第 9 插 READ 只读交付；rootfs `.berryver` 构建烙印）——管「平台是什么版本」；三方联动（manifest PR ≡ VMO level ≡ .berryver level）即版本事实的机器对账闭环；应用侧读取路径 v1 = `.berryver` 文件读，SDK 不推荐按版本分支（FINGERPRINT「勿解析」纪律，SDK-2 §三）。③**探测轨** = `berry_feature_query` 能力式试连：特性存在 = 服务/协议入口在应用命名空间可连，返回布尔不返回版本号；探针语义 = 此刻可连性快照非承诺；探针词表单源于 abi.toml/清单 schema 生成器、永不发明第三套名、add-only；v2 按需拉起立法时补「探针连接不触发拉起」。

> **重议触发**（均为事件）：①首个第三方 SDK 三轨并消费出现「该信谁」歧义（文档分类纪律失效实测）；②v2 动态信息需求迫使 `sys/info` 静态语义稀释（§3-1 同款）；③`eco: VER mix` 在野发生率超遥测阈值（对账面自身不稳）或 v2 沙箱收紧后 `.berryver` 应用不可读且无替代版本读取路径。
> **载体**：**#83**（`sys/info` schema 节 + V13 步⑧生成步 + 本稿 §2.2 修订版键位表）+ **SDK-2 §三升版**（探针细化两句 + `.berryver` 读取 API 归 L2）——前置 = **#83 落册恢复刀**（§1 现场快照：落册现不存在于任何 ref，恢复重放骨架 = 21 号 §4.4 + 本稿拍板语句）。

## §3 题二终审：安全快道案二（19 号 §2）

### 3.1 证据复核

**（a）引用如实性**：案甲基线（09 号 §5.1 :318–:334，本轮重读）——「一次 L1 槽翻转/案乙中间态 = 02 号 §2.2 版本碎片结构源/D2 判据在编队检查生效」三要素与 19 号 §2.1/§2.3 转述**逐条一致**；响应时钟账的三个锚（04 号 :329 OEM 6–12 月、07 号 :293 N 窗口数学、02 号 :25/:110 18 个月回传延迟）**全部实存**；#82 :215 `security_level` 预留位原句「正交于功能版本的安全补丁轨道雏形，启用随首个安全公告裁」**现场重锚一致**（19 号引 :214 系一行漂移）；Q12 案甲一句在 :284 在册。Mainline/ChromeOS DLC/Windows CU 三样本转述如实（Windows CU 本轮独立复验，§2.1-a 表）。**判：如实。**

**（b）漏案检查（本案有一件真漏案）**：

- **Apple Rapid Security Responses（RSR）**——唯一与案二同题的在野实例：安全快道绕过年度功能列车单独发版、可整队回退（Apple 明文「may remove Rapid Security Responses」机制）。且**首个 RSR (b)（2023-05-31 发，06-01 即撤回——Safari 无法载站）同时是反论①「快道质量门不足」的最强实证**：单方出件 + 无灰度兜底的首次实弹即翻车。**待核实（单源缺一）**：本轮 web_search 故障（401）+ 直抓三次未落地（Apple 支持页重定向/404/octet-stream），按公开常识登记，仅作反论侧强化——**裁定链在 RSR 缺席下仍闭环**（三在册样本已足支撑共性三条）。若主会话采纳 RSR 为证据，须先补两源。
- Linux stable 分支（安全补丁不随功能列车的服务分支——`abi_neutral` 纪律的先祖形态）：相邻样本，非漏（Windows CU 行已覆盖「质量轴独立」同构），记档不采。
- Android 月度安全公告节奏：响应时钟实证已被 02 号 18 个月数据覆盖，不重复采。
- **判：RSR 补登（反论侧），无改变结论的立法级漏案。**

**（c）最强反论复核**：19 号 §2.4 四条反论（快道行为变化无灰度兜底/双轴版本语义复杂/OEM 件 CVE 不受益/安全补丁 × 替换件交互回归）**如实且覆盖主要面**——反论①恰是 RSR 实证的方向（漏案补登强化它而非推翻裁定：Apple 翻车后未废 RSR 而是修复重发——快道模式可存活，质量门必须硬，与本案「Tier 1 回放 + 违中立纪律强制走整编队」的对策同构）。**未列的两条**：

1. **第五反论（治理面）：平台单方出件权 × OEM 责任主体冲突**——快道 = 设备内容变更未经 OEM 参与认定；重监管域（06 号 v2 工业 RT/车轨 SEooC 责任分层）下结构不可接受，移动域亦有运营商认证设备先例。**补强**：边界加「重监管域 carve-out——v2 工业 RT 入场时快道治理重裁（该域禁用或加 OEM 确认位听证）」。
2. **第六反论（对账面）：整编队不带 security_level 声明的单调复位**——快道抬 lane_revision 后跟一次整编队（不带声明/带低值）再跟快道，boot 单调列无法判定回退与否（误拒或漏放）。19 号 §2.5 配套①只写了「boot 对账加 lane_revision 单调列」未写整编队义务。**补强**：整编队平台段同样必带 security_level 声明，缺省 = 继承活跃槽值且不得回退（§3.2 第 7 条）。

### 3.2 补强③：快道版本语义对齐案——`security_level` × `platform_revision`≡level 关系字段化

**缝隙识别**：19 号与 `docs/版本管理标准v1.0.md` 同日（2026-11-10）成文互未引用，各立了同一根安全轴——19 号 `security_level`/`lane_revision`（sys/info 键 + 更新包键），标准 §1「安全级」轨（:17：单源 = `tools/abi.toml` 预留位、整数 SPL 同构、正交于功能版本、消费面 = BCTS 承诺面 + OTA、**启用随首个安全公告**——与 #82 :215 预留位三处同触发器）。且 abi.toml 现无该物理键（本轮实测：`[platform]` 仅 `level = 1`，:29）——标准的单源位是纸面预留。**关系字段化七条（蓝队合流案，供 V7 前半刀收编）**：

1. **同名同值律**：`security_level`（#82 :215 预留名）≡ `[security_fastlane].lane_revision`（19 号 §2.5 OTA 键）≡ manifest `security_level` 列 ≡ `sys/info platform.security_level` 键——同一轨道（标准 §1 安全级轨）的四个消费面，一处改名四处同笔。
2. **单源律**：号源 = `tools/abi.toml [platform] security_level`（物理预留位，v0 恰 1 占位）——**随 V7 前半刀同笔落位**（标准 :17 既书「单源 = abi.toml 预留位」，19 号未落物理位——本条补齐）；安全分支构建时抬号，G-ver-1 执法扩第二臂（security_level 只增不减，启用时立——标准执法列恰留此位）。
3. **正交律**：`platform_revision`≡level（功能轴，7775ccf 单源律既立）与 `security_level`（安全轴）**独立单调、互不推导**——标准 §2 :33 走速表既书「安全补丁集：level 不动、安全级 +1」；快道 = 安全轴 +1 且功能轴不动，整编队 = 功能轴可动且安全轴可同笔 +1。
4. **等值门**：19 号 `platform_revision_unchanged`（bool 断言键）升级为**值比对执法**——快道目标槽 PR == 活跃槽 PR（7775ccf 后 PR 单源 = abi.toml level，比对确定可行）；落位 = berry_assemble 装配门加等值臂（`validate_platform_revision` :368/:481 反回滚两臂同款形态）+ 更新服务安装期比对，不等即整包拒装（loud）。
5. **同宽律**：`security_level` 取 **u32**——与 manifest PR 列同宽（`tools/mkimage.py` :86 `MANIFEST_PR_W = 10`，u32 全域）；修正 19 号 §1.4/:73 与 §2.5/:161 的 u16 建议（同族同宽成本为零、异宽的解释成本永续）。
6. **VMO 不承载律**：version VMO 结构与 `SYSVER_HDR_VER` 不动（`kernel/src/sysver.rs` :35–:36「结构布局变更才 +1」）——安全轴随编队翻转，非内核构建身份；混入 VMO 会使每次安全编队强耦合 hdr_ver/结构变更，且 OEM carried 段无对应物。查询面投影 = `sys/info` 键 + manifest 列 + boot 对账单调列。
7. **两通道统一律（蓝队新增）**：整编队更新包平台段同样必带 `security_level` 声明，缺省 = 继承活跃槽值、不得回退——否则「快道→整编队→快道」交错序列的单调对账无法闭合（§3.1-c 第六反论的对策）。

**配对律衔接**：标准 §1 :20「一次可发布产物 = 五元组各取一值（系统版本 (level, 安全级, 构建标识, 包集)）」已含安全级——**无须扩元组**；快道编队 = 五元组中仅安全级与构建标识动、level 不动、OEM 包集（carried 段）不变——配对律即快道的合法性表述。

## §5 反面自检（蓝队自己的弱点，如实写）

1. **未见红队稿**：并行隔离是任务书纪律，代价是本稿无法对红队攻击面预辩护——两稿冲突处归主会话终裁；本稿拍板语句应视为「更强草案」而非「已验证结论」（12 号 §5-5 同款自认），逐条可退回 19 号原强度。
2. **`.berryver` 应用可读性是推断**：归并案应用侧读取路径依赖 v1 G0 `fs=["rootfs"]` 过渡态（应用规范 §2.1 :71）；v2 沙箱收紧后 `.berryver` 可见性未立法——届时若无替代路径（VMO 直达或 sys/info 回补版本键），版本读取面悬空（已列为题一重议触发③的前身）。
3. **RSR 单源待核实**：三次直抓未落地（重定向/404/octet-stream），按公开常识登记——若主会话采纳为立法证据须先补两源；本稿裁定链已按「RSR 缺席仍闭环」构造（§3.1-b）。
4. **探针时序补句可能过度前置**：v1 boot 序（服务先于 app 拉起）使时序问题不尖锐，v2 才实弹——主会话可判「v2 再说」退回；蓝队坚持写入的理由是 SDK 文档一旦外发，探针语义就是合同面，后补即破坏「SDK 冻结 = 承诺冻结」纪律（版本管理标准 §4）。
5. **§1 现场快照的边界**：对「恢复叙事与树不符」的判定基于 123 refs + 11 worktrees + 工作区的全扫描与 `git log --all -S` 双探针；若恢复存在于本仓之外的备份介质（未推送 worktree 快照/本地文件），本判定不改——以仓内可追溯性为准绳（21 号 §2.2 同款立场：主张须仓内有对证）。
6. **压力测试时间窗多为类比推断**（12 号 §5-3 同款）：题二错法 A 的「数小时级回退」系 RSR 类比、错法 C 的声誉账系 Tizen 类比——可作风险排序参考，不可当承诺。
