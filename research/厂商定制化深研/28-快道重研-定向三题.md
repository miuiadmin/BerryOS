## §2 题一：地板次序重立（B1 正面解）

### 2.1 形式化：状态机与不变量

基元（零新机制起点）：槽对 {A,B}，active 槽由 priority 派生（更新与OTA :39）；每树 T 双轴向量 (PR(T), SL(T))——PR≡level 单源（7775ccf 三方联动），SL = 安全轴（26 号 §2 保留件）；持久计数 floor_pr（现役 rollback index，只绑平台镜像槽——09 号 :360）与 floor_sl（快道新增，19 号 :170 配套②）。

**扩充状态机**（对齐 Android 型 :39 + 健康标记，快道只加一级 SOAKING）：

```text
EMPTY → STAGED（备槽落树 + §7.5-③ commit 全量重验过）
      → ACTIVATING（priority 高 + tries_remaining=N，翻指针）
      → HEALTHY（新系统自检过 ≡ SUCCESSFUL——:39 markBootSuccessful）
      → SOAKING（boot 计数 k < K，或未逢「下一 lane 抬升事件」）   ← 快道新增
      → CONFIRMED（浸泡期满；floor_sl := SL(本树)）

回退合法性（ptr 翻回旧槽）: 目标树 T′ 合法 ⟺ PR(T′) ≥ floor_pr ∧ SL(T′) ≥ floor_sl_eff
  floor_sl_eff = floor_sl_prev（本槽 SOAKING 期，地板尚未吸收本树值）
              | floor_sl     （本槽 CONFIRMED / 无快道在途）
  （ACTIVATING/HEALTHY 期沿用既有回退自由窗——:40 原文，不动）
```

**不变量组**：

| # | 不变量 | 与现役关系 |
|---|---|---|
| I-PR | floor_pr 只认平台镜像槽、SUCCESSFUL 后才抬、只增不减 | 现役原样（09 号 :360 + 更新与OTA :40）——快道不动 |
| I-SL-1（轴分离） | floor_sl 与 floor_pr 独立比较、合取执法；任一轴抬升不波及另一轴 | 23 号 §3.2-3 正交律的执法面表述 |
| I-SL-2（滞后吸收） | floor_sl 吸收新树 SL 的时点 = CONFIRMED（非 SUCCESSFUL） | **快道对 :40 契约的唯一修改**——PR 半边照旧，SL 半边延后一个浸泡窗 |
| I-SL-3（单调） | floor_sl 只增不减（CounterBackend） | 19 号 配套② + :44 |
| I-SL-4（重制通道） | SL 声明值 ≥ floor_sl 的任何平台签名树可装（含同 lane 重制树） | 依赖题二 L1（内容寻址）——见 §2.3 |

B1 两受害形态在此框架下显形：**形态一**（坏快道）——F 本身坏，SUCCESSFUL 后旧案下回退被 I-SL 挡（只能前滚 F′ 走同一套未实证质量闸，22 号 §3.1「失败遏制不对称」）；**形态二**（功能回归劫持）——M 吸收 F 后 SL 更高，回退 M→F 违地板（22 号 §3.1 推演「常态恰是反噬成立的情形」）。

### 2.2 候选案

| 维度 | 案 α：SL 地板浸泡延迟 | 案 β：内容寻址 lane + 同 lane 重制树 | 案 γ：紧邻一格豁免 |
|---|---|---|---|
| 机制 | I-SL-2（floor_sl 滞后一个浸泡窗）；窗度量 W1 = boot 计数 K（CounterBackend 已有 L0 启动计数面，:44）或 W2 = 「下一 lane 到达」（版本当时钟同族，SDK-2 v1.2 :92–93） | lane(T) := max{T 所含安全公告的公告序}；同 lane 重制树 = SL 同值、非安全内容不同的树（M′ 修 M 功能 bug）恒过 I-SL-4 | I-SL 修改：允许 target = 紧邻前一代树且 SL ≥ floor_sl−1（天然限深 1——双槽里旧槽树就是紧邻前代） |
| 解决形态 | 形态一（窗内回退自由 = 快道自带快回滚——行业表原意兑现） | 形态二（回不去时走重制前滚，内容保全+地板不破） | 形态一（= α 的 W2 参数化特例：窗恰一代） |
| 行业锚 | Windows 质量更新卸载窗（时间窗形态）；DLC 自带 A/B（19 号 :127–:129 三样本 + 22 号 §3.1 二次引用，仓内两源） | Windows CU 累积替换 + Mainline「不引入新 API」（重制 = 累积语义的安全轴镜像，02 号 :188） | DLC A/B 的 BerryOS 直译——另一格就是另一槽，翻回旧槽 = 物理快回滚 |
| 成本 | 状态机加一级 + 计数比较器（compare_and_set 已有，:44）——零新机制 | 公告序注册表（OQ-2 治理缺口）+ 平台重出树的天级时钟 | 最小——豁免半句 |
| 主要反论 | 扩大防降级敞口：窗内可退恰一代安全内容（离线持盘/强制回退攻击） | 重制是前滚不是回退——回归速度从分钟级（翻指针）变天级（重出件）；注册表未立则退化 | 敞口同 α 且永久（无窗关闭）；「紧邻前代」代数记录在连续两次快道后退只能到 F1，语义需注记 |

**组合判**：α(W2) ⊇ γ（一代窗就是 γ，γ 可不单独立——作为 α 的窗参数首选）；β 与 α 正交（β 管「CONFIRMED 后回不去怎么办」，α 管「多久内回得去」）。建议 **α+β 组合**，γ 并入 α 作 W2 默认参数。

### 2.3 命题裁定：「功能轴回退可吸收快道内容而不违地板」

- **原命题 P**（19 号 :170 配套②字面）：「功能轴回退不受安全地板反噬」——**证伪**。反例：常态序列 F(SL 6)→CONFIRMED→M(SL 7，吸收 F 且含新安全内容 C7)→CONFIRMED→回退 M→F 违 I-SL-1（6 < 7）。吸收是必然（M 不含 F 修复则 M 装不进——22 号 §3.1 同推演），故反例即常态。且该阻挡是**正确行为**：F 树缺 C7，回退即丢已确认安全修复——正是地板立法目的（更新与OTA :66「回退只许回到未被安全公告否决的版本」）。P 仅在 M 无新安全内容时偶然为真（此时 M.lane = F.lane，回退恒过门）。
- **改写命题 P′（可证真）**：「功能轴回退**不丢安全内容**」——功能回归的手段从「回退到旧树」改为「前进到含同一安全内容集的树」（同 lane 重制树），则安全内容零丢失 ∧ 地板零违背。
- **定理（推断级——状态机推演）**：在 L1（内容寻址+继承不重记）与 §2.1 不变量下，P′ 成立 ⟺ 回归目标 T′ 满足 SL(T′) ≥ floor_sl。构造性证明 = 重制树存在性：组装器确定性（V13 已落）使平台可对任一（lane 值， 功能版本）组合出树，故 T′ 恒可构造。∎ 前提假设：历史安全内容的物料可复取（公告→补丁集→工件账，OQ-2）——**未解前此构造是假设不是事实**，P′ 相应降级为「平台构建纪律保证」非机器可验。
- **裁决建议**：19 号 配套②在 V7 前半刀收编时按 P′ 语句改写；P 原句作废依据 = 本节反例 + 22 号 §3.1（两源同向）。

## §3 题二：lane 语义 + 段签名一体裁（B2+B3，随 #77 预备案）

### 3.1 B2 候选裁定语句：lane_revision 偏序/累积

**语句 L1（内容寻址累积案——建议）**：

> 「`security_level` 执法对象 = 树的安全内容集，非树的代数：lane(T) := max{T 所含安全公告的公告序}（内容寻址，全序）；**快道工件集强制累积**（F_{i+1} 安全内容 ⊇ F_i——平台单源全量重发安全子集，Windows 月度累积同构，19 号 :129）；**整编队继承不重记**（M 含快道已发内容时 M.lane = max(既有 lane， M 新增公告序)，同内容双计数禁止）；**`scope` 降纯元数据**（不参与地板与偏序——单地板单轨，`"critical"` 分级预留撤销，分级即双轨双地板、偏序问题复发〔22 号 §3.2-③〕）。」

- 最强反论：①**公告序注册表是隐含前提**（「公告→序」全序账，Android SPL 对应物——22 号 §3.2 末段「全新治理面，零设计」；#82 :217 只留字段位）——L1 的机判性押在 OQ-2 上；②累积强制 = 每次快道全量重发安全子集，包体积随内容积累线性增长（推断——v0 白名单 = 内核镜像 + berry-sys/libc 级库〔19 号 :163〕，MB 级；实测账 OQ-4；超阈退「累积声明+差量传输」，挂 v2 增量闸门三条件家族〔SDK-2 v1.2 §四 :79–82〕，不进 v1）；③偏序被消解而非解答——若未来出现第二公告渠道（OEM 自发安全公告）偏序复活；关死句：「OEM 件安全公告不进平台 lane」（OEM 件 CVE 责任边界 = OEM，19 号 :151 反论③）。

**语句 L2（代数单调案——备选/过渡）**：

> 「`security_level` = 平台安全轴单调代数号：每次安全出件 +1，不承诺内容包含；累积与吸收 = 平台构建纪律，不进协议执法面；整编队不带新安全内容时不 +1（继承当前值）。」

- 最强反论：代数与内容脱钩 → 设备端只能信声明（无法机判「声明 7 的树真含 C7」）——快道核心承诺从「安全水位单调」退化为「号单调」；同 lane 重制树在 L2 下无身份（两树同号无从区分谁含 C7）——遥测/attest 面答不出「这台设备有没有补 C7」；账本侧 `last_revision` 见证（SDK-2 v1.2 §五 :88–91）对齐的也是版本序不是内容。L2 价值仅在零注册表依赖——作 OQ-2 未解时的过渡形态（§2.4 反论②同款降级路径）。

### 3.2 B3 候选裁定语句：carried × D9 相容裁

冲突复述（22 号 §3.3）：D9 =「L0 slot 条目与 L1 树清单的签名消息设计时即绑槽与树身份」（架构决策 :267；源头动机「跨槽重放（A 槽签名条目挪进 B 槽）签名拦不住」，更新与OTA :106–111）；carried = OEM 段活跃槽原段整段引用、原验签续用（19 号 :166）——活跃槽携带进备槽新树，字面命中 D9 要杀的形态。

**语句 R1a（段身份白名单案——建议）**：

> 「OEM 段签名域绑**段身份**（段内容 hash + integrator lineage），不绑槽/树身份——段是内容寻址自认证单元；L1 树清单（平台段）签名消息绑**组合式树身份**（平台工件清单 + 允许携带的 OEM 段 hash 白名单——白名单源 = 签名索引 `last_revision` + 产品包清单派生〔SDK-2 v1.2 §五 :88–91 + V13 组装段 hash 产物〕）；设备端执法 = 活跃槽 OEM 段 hash ∈ 白名单，否则整包拒装、退整编队。D9 句 L1 半边同步改写：『签名消息绑树身份（组合式）与段身份集；槽身份由 L0 slot 条目绑（原句 L0 半边不动）』。」

- 最强反论：①**白名单的平台知识义务**——须持续知道全部在野段 hash（索引 `last_revision` 完备性押在 OEM 编队注册纪律上；OEM 未注册段 = 白名单外 = 快道拒装——行为正确但快道覆盖面打折）；②**「组合式树身份」必须诚实措辞**——树 root 含设备各异的 OEM 段，平台实际签的是「白名单 × 平台工件集」承诺而非具体整树预签；推荐单包带全集白名单（白名单是数据不是签名域差异，包数不随段版本爆炸——推断），#77 改写句不得宣称「整树预签」；③**重放残面**：白名单内旧段可装入新树——旧段版本回退无设备端执法位（SDK-2 账本水位是包钥身份面〔§三 :63 gen_max/ver_max〕，不覆盖 L1 树内系统段）；补丁半句候选 =「白名单随 lane 单调（只吸收不吐出）」或 boot 对账加段列（19 号 配套① lane_revision 单调列同刀）——OQ-3。

**语句 R1b（设备端拼装案——备选）**：

> 「平台包不含 OEM 段引用；设备端更新服务从活跃槽字节级克隆 OEM 段进备槽，按『平台段清单 ∪ 段自验签』双路验签；D9 改写同 R1a。」

- 最强反论：平台签名见证面不含 OEM 段选择——拼装内容由设备状态决定，段替换攻击（同 lineage 旧段重放）无白名单拦截，比 R1a 弱一档；优点仅平台零白名单知识义务。R1b 实质 = R1a 把白名单从「平台签」降为「设备自认」，快道承诺强度同步降。

**语句 R2（快道禁 carried 案——不采，列作边界揭示）**：

> 「快道包只含平台安全工件，OEM 段不进快道树（备槽 = 平台安全子集 + OEM 段运行时克隆），或更彻底：平台安全件走独立换树通道。」

- 最强反论：后半句 = 19 号 §2.3 案三（槽级独立），已被判死（多通道多时刻 = 案乙中间态放大，19 号 :140 引 09 号 :329）；前半句 = R1b 换述。R2 价值仅在揭示 carried 的全部麻烦源于「快道树必须完整」——判不采。

### 3.3 建议倾向：L1 + R1a，随 #77 一刀裁

理由：①**窗口经济性**——Q3 信封/清单格式窗开到 P3 前（架构决策 :301），D9 句改写与 [security_fastlane] 八键落位同刀，零在野成本；②**白名单源已在册**——V5 索引八字段与 V13 组装段 hash 两件都已落（架构决策 :246–247 V4/V5 行 + 24 号 §4.4 boot 对账三判据）；③**同构贯穿**——lane 寻址公告序 / 段寻址内容 hash / 树寻址段身份集×平台段，内容寻址一词一义，与题一 β、题三第一层共用地基；④R1a 反论②的诚实措辞已预写，防 #77 落册时话术通胀。风险登记：OQ-3 段级防回退若裁「必须有」，R1a 加白名单单调半句即可（零新机制）。

## §4 题三：回放执行形态三定（B4）

### 4.1 三定候选矩阵 + 成本

19 号 原承诺 =「编队期对在册替换件执行 Tier 1 ∩ 受影响面子集回放」（:151/:167）；22 号 §3.4 判其空心：平台编队手里没有 OEM 替换件（逐 OEM、可闭源）、设备侧 staging 机制全仓无设计、BCTS v0 门禁宿主 = host 侧 just 配方树跑不了硬件绑定替换件（架构决策 :278 Q4 两源）。候选矩阵：

| 形态 | 执行者 | 场地 | 时机 | 联测强度 | 成本 | 判 |
|---|---|---|---|---|---|---|
| M1 平台编队回放（19 号 原案） | 平台 host | host/QEMU | 发版前 | 真回放、仅官方面 | 低 | 无 OEM 替换件——空心点即此 | 照原样不可行 |
| M2 OEM 参与回放 | OEM 侧 | OEM host | 发版前 | 真联测 | 高 + OEM 动作 | 响应时钟回退到 OEM 组织成本（04 号 :329 + 07 号 :293 两源：6–12 月）——快道卖点没了；违「OEM 零动作」 | 否 |
| M3 设备装前 staging | 更新服务（设备侧） | staging 区/备槽 | 装前（翻指针前） | **真回放**（唯一能跑硬件绑定替换件的形态——真硬件在设备上） | 新 staging 机制（第三方服务在备槽上下文运行——全仓无设计）+ 每台设备每快道运行成本 | v2+（随 L1 实板，更新与OTA §7 :98；设计前置 OQ-6） |
| M4 认证资产复用 | 平台 host（①②臂）+ 设备更新服务（③臂） | host 构建侧 + 活跃槽 | 发版前（①②）+ pre-SUCCESSFUL（③） | 合同面机判 + 案例面静态比对 + 观察窗 | 低-中（三层全在册或近在册，§4.2） | **建议 v1** |
| M5 BCTS 冻结件回放 | 平台 host | just 配方树（BCTS v0 宿主） | 发版前 | 只覆盖官方面 | 低 | Tier 1 下限 = smoke 88 标记件（架构决策 :81 + `tools/bcts/frozen/bcts@0.toml` :19 两源）——M4 ①层的官方面子集，不独立成案 |

**三定（M4 形态）**：执行者 = 平台 host（静态两臂）+ 设备更新服务（观察窗臂）；场地 = host 构建侧 + 设备活跃槽（健康标记前的首 boot 窗）；时机 = 发版前（①②臂）+ 装后翻指针前的自检窗（③臂）。

### 4.2 案乙死因正面解：联测面最小集

死因原文：「平台新版+OEM 旧件的组合未经联测即上设备」（09 号 :329）。快道 carried 组合与之同构（22 号 §3.4 联测悖论——OEM 零动作 = 无人联测过该组合）。正面解 = 把「联测」拆成三层**可降级面**，各层找「不需要 OEM 件在场」的执法点：

1. **第一层·合同面机判（发版前，平台 host）**：快道白名单工件 × 在册槽位合同的 op 集不变性比对——`abi_neutral` 断言（19 号 :164）的落地形态。abi 单源（`tools/abi.toml` 五面同源生成）使「快道工件动了哪些在册 syscall/wire 面」构建期可机判；OEM 件不需要在场，需要的是**合同**（Q8 槽位合同四件套是平台立法，架构决策 :217）。残差：合同保真 ≠ 行为保真——语义合同内的实现漂移交给第二层。
2. **第二层·案例面静态比对（发版前，平台 host）**：替换件 conformance 案例的**静态适用性比对**（22 号 §3.4 修法原文）——本次快道影响的 op 集 ⊆ 该槽位认证期已测 op 集（conformance 用例集 = Q8 四件套之一；认证面 =「OEM 自测 + 平台裁决」，架构决策 :81/:315 两源）。资产复用逻辑：认证期已把「替换件 × 官方平台」案例面联测过一轮，快道只须证「变更不逃逸出已测案例面」，组合联测的**增量风险**被压缩到「新平台内容 × 案例未覆盖角」。影响 op 集算法（推断）：cve_refs（19 号 :165）→ 补丁触及工件 → 依赖它的 op 集；v0 白名单只含内核+libc，影响面 ≈ 全 op 集 → v0 直接退化为「全案例面比对」= Tier 1 全集——反而最简。
3. **第三层·pre-SUCCESSFUL 观察窗（装后翻指针前，设备）**：L0 健康标记机制既有（更新与OTA :39–:40）——快道把「健康」标准加深一层：快道树首 boot 自检含白名单工件对应面的冒烟子集（Tier 1 下限 = smoke 88 标记件族，同 M5 两源）。窗内失败 = 回退自由（:40 既有）+ 题一 α 浸泡窗再延一段——三层闸与题一共享失败遏制工具。

三层全部「OEM 零动作」。M3 真回放是第四层（v2+ 选项）——唯一覆盖「硬件绑定替换件行为面」的形态，但机制成本最高（OQ-6）。

### 4.3 快道质量闸真实强度重述（22 号 §3.4 修法要求）

降格后（M4）快道质量闸 = **合同面机器保真（强——单源可机判）+ 案例面冻结复用（中——认证期资产，静态比对非实测）+ 观察窗在野兜底（弱——失败遏制靠回退自由+浸泡窗）**。与案甲真联测的差 = 「新平台内容 × 替换件」的**实测交互**层——该残差无法静态消除，处置 = 暴露时回退（题一 α/γ）或前滚重制（题一 β）。文案纪律：#77/V7 落 `[security_fastlane].replay_tier` 键时语义注必须全文写「Tier 1 ∩ 白名单工件回放（官方面）+ conformance 案例静态适用性比对（组合面）+ pre-SUCCESSFUL 观察窗（在野）」——不得再以「Tier 1 回放」一语带过。

### 4.4 验证路径

1. **桌面推演科目三**（与 §2.5/§3.4 合成一个推演脚本）：三层闸 × 首个安全公告推演（23 号 边界既载——RSR 首例翻车为必含科目）。
2. **#84 断言清单补行**：19 号 §2.6 两条落成 M4 形态 + 新增第三条——「Tier 1 ∩ 白名单工件回放全绿」「manifest 列 ↔ sys/info 键一致」「conformance 案例覆盖 ⊇ 快道影响 op 集（第二层进 BCTS 断言）」。
