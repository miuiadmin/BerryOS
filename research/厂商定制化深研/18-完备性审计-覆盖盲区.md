## §0 摘要（一屏版）

- **总判定：立法包主体覆盖厚实，十必查维度无一威胁 #82 立法正确性（P0 = 零），但存在 3 件 P1 真空白——全部集中在「产品内容域」与「生命周期域」的边角，且全部落在 #83/#77 承接件开刀之前还有窗口的时点上。** 已覆盖 4 项（维 9/10/2 主体/增补 B）、明确排除或延后在案 3 项（维 1 立法面/维 2 商业面/维 7 停更半）、真空白 6 项（维 3 i18n、维 6 开发者查询面、维 8 机制半格、维 4 可拍板不适用、维 5 轻空白、维 1 残余 NOTICE 半格）。

- **P0 = 零的论证（审计时点结论）**：#82 已裁的不可逆面（禁改面枚举/三包轨道/负面承诺）与空白维度零交集；两处真不可逆点（Q6 账本 = SDK-2 P0 前、Q3 信封 = 首编队 OTA 前）不涉空白维度；product 清单 `schema=1` + add-only 使 i18n 键后补机制可行（12 号 §2.7 压力测试原文「schema=1 升版 add-only 加键可救」，代价 = 清单返工周级）。**时点敏感**：若 #83 落稿时 P1 ①②未先补，键位与查询面被 schema 定形卡进 v2 改刀，届时性质升格为 P0。

## §1 方法与「应有全景」维度框架

### 1.1 判定三值与核销方法

每个维度按三值判定，判定值必须落到锚点：

- **已覆盖**：系列内有针对该维度的研究段落或机制设计（给稿号 + 行号）；「研究过但不深」不算覆盖，降级为部分覆盖并在该维度内分面判定。
- **明确排除**：系列内或 #82 节有在案的裁定——明确延后、明确不适用、或明确「无技术载体不预埋」（给裁定锚点）。排除是有意的、留痕的，与「从未被想到」性质不同。
- **真空白**：关键词组全量扫描零命中或仅样本顺带提及，且无任何裁定留痕。真空白再分：**需补研究**（给规模）/ **可拍板不适用**（给理由，但须登记重议触发器防丢）/ **v2+ 自然覆盖**（给自然承接的既有刀位）。

核销方法：十六文件逐维度关键词组全量 grep（词组清单与命中账见 §1.3），命中处逐条回读上下文判「研究/顺带/零相关」；不抽样。仓内引用给路径 + 行号；外部对照一手优先。

## §2 十必查维度逐判

### 2.1 维度 1：平台对 OEM 的授权与许可证条款 —— **部分覆盖 + 明确排除；残余真空白半格（NOTICE 义务）**

**证据面已覆盖（质量不低）**：Apache-2.0 边界的核心命题已被研究——04 号 :120/:183（「Apache-2.0 允许任何人 fork——『永不 fork』不可能由许可证执法，只能由认证+签名链+商标组合执法」）；01 号 :163/:167（「BerryOS 兼容」判定权无成文、分支回流无 upstream-first 契约，两处如实登记缺口）；行业样本三家：02 号 :158/:166（CTS 通过 = Play/GMS/Android 商标许可前提；Google 拒绝许可旧版本 = 商业杠杆强制版本代谢）、05 号 :87（MeeGo 许可政策：UX 层宽松 + API 库 LGPL 防碎——唯一把定制自由度写进许可证设计的样本）、:97（Tizen Flora License：专利许可只授予认证平台）。OEM 闭源件的技术政策由 Q10 分层裁定（含 license 字段披露，04 号 §7-10、#82 :281）。

**立法面明确排除**：Q5 裁定「不裁商标立法、运营主体、费率；余延后至首 OEM 接触窗（治理文档）」——负面承诺（不设商业准入）已进 #82 :228–:229/:276；10 号 X5「治理三题无技术载体，预埋是错误的解法」（10 号 :160）。**这是有意排除且留痕，不是盲区。**

**残余真空白（半格）**：Apache-2.0 的 NOTICE/归属义务对 OEM 发行镜像的合规要求——OEM 镜像内含 Apache-2.0 工件（内核/服务/资产），按许可证须随镜像携带 LICENSE/NOTICE 文本；08 号 §3 组装管线九步（:314–:331）产物清单 = 镜像 + manifest.txt + 组装日志三件，**无许可文本汇集步**；全系列 `NOTICE` 零命中。规模：非研究题，是工程遗漏——**澄清即可**（P2）：V13（berry-assemble）实施时管线补「⑩ LICENSE/NOTICE 汇集步」或在 #83 升格文档补一行，文本形态 = `out/<name>.img 同级产 <name>.notices（Apache-2.0 §4.1/§4.2 汇集文件，组装日志记录来源）`。

### 2.2 维度 2：OEM 商店/分发渠道 —— **已覆盖（信任机制面）+ 明确排除（商业面）；运营规则 v2+**

机制面比任务书预估的厚：09 号 :16 OEM 插入信任链五插入点含「OEM 源」；:55 专行「D OEM 源 ⑧ OEM 运营自己的商店/源——OEM 源钥 + 镜像内置 OEM 源静态实例（SDK-2 §五同构）」；:115/:183 三钥分立（integrator 包钥/OEM 源钥/烧钥决策各自独立轮换——「通道可换而身份不可换」）。v1 分发现实已立法在案：01 号 :80（官方源钥出厂预装随镜像、sideload = 未知来源开关、产品镜像默认关）、:82（OEM 应用商店 = 未来「源」的运营方，v1 镜像内置官方源静态实例，**在线源 v2 再议**）。商业面 Q5 负面承诺明确不设官方源独占/商店准入（#82 :228）。

**残余**：OEM 源的运营规则（多源并存时优先级/源内容责任/摘牌设备源失效）——09 号 §6-12 已把「v2 在线源落地前摘牌无在线通道」列为开放问题在册。判定：**v2+ 自然覆盖**（v1 连在线源都不存在，研究无消费者），P2 登记，承接刀位 = v2 在线源设计。

### 2.3 维度 3：i18n/区域化 —— **真空白（P1，需补研究：单 agent 半天）**

三源判空白：①product 清单 17 键逐键全查（08 号 §2.2 :267–:282）：`product.name/vendor/board` + `platform.arch/feature_level/build_type/boot.kernel/boot.params.*/storage.image_size_mib` + `product.apps.preset/priv_grants` + `product.branding.*/branding.tokens.*` + `product.defaults.launcher/scheduler.*` + `product.services.replace.*`——**无任何语言/时区/区域/监管域键**；未知键硬拒（V12）下 OEM 对区域差异**零表达力**。②全系列关键词组零命中（§1.3 维 3 行），唯一顺带 = 03 号 :142 Windows OOBE 骨架描述（「语言→区域→网络→EULA」屏序——恰恰证明 Windows 把区域配置视为 OOBE 合同一部分，采证时未追问 BerryOS 对应物）。③一手补采（本轮）：Fuchsia `sdk/fidl/fuchsia.hwinfo/hwinfo.fidl`（main 快照）`ProductInfo` 表 **day-one 含 `language`（字段 2）/`regulatory_domain`（字段 3，`fuchsia.intl.RegulatoryDomain`）/`locale_list`（字段 4）**——即 03 号重点对标的 Fuchsia 产品配置面本有此维度，第一轮采证（product bundle codelab/platform_settings.rs）漏采了 hwinfo 面（推断：codelab 双键结构足够支撑当时命题，i18n 键未进入采证清单）。

**为什么不是 P0**：`schema=1` + add-only 使键后补可行（12 号 §2.7 压力测试：「schema=1 升版 add-only 加键可救（08 号 §2.1），代价 = 首穿产品清单返工（周级）」）；v1 无 OEM 消费者。**为什么是 P1**：#83 开刀在即，键位一次到位比 schema=2 返工便宜；且时区/区域键与 `platform.boot.params`（内核消费）还是 `product.defaults`（用户态消费）的归属切分，牵动 #83 的双键分界设计——这是设计输入不是事后补丁。**补研要素**：规模 = 单 agent 半天；输入锚 = 08 号 §2.2 逐键表 + 03 号 §3.1（Windows OOBE/unattend intl 段）+ Fuchsia hwinfo.fidl（本轮已采）+ OH i18n 部件（可 web_fetch gitee）；产出形态 = 键位建议表（locale_list/timezone/regulatory_domain 候选键 + 归属双键哪侧 + 消费方清单 + 是否 v1 预埋空骨架），供 #83 落稿收编。

### 2.4 维度 4：各国准入认证（CCC/FCC/CE/GCF）—— **真空白但可拍板不适用 v1（P2，登记重议触发器）**

全系列零命中（§1.3 维 4 行）。06 号覆盖的是**功能安全族**（ISO 26262/SEooC/TÜV ASIL 认证，03 号 :121 亦同），电信/无线电/市场准入是另一族，任务书判断正确——从未被看一眼。**可拍板不适用的理由**：①v1 主验 QEMU virt、真机 P8 = 开发板，AGENTS 冻结常量无蜂窝/无线电硬件路线；②准入认证（CCC/FCC/CE/GCF）法定主体是整机厂（OEM），OS 平台在此族的义务面 = 提供区域参数配置位（如无线电区域功率表——对照 Fuchsia `regulatory_domain` 恰是一手补采命中的字段），而该面已并入维度 3 的键位补研；③v2 工业 RT 路线的认证族是功能安全（06 号 §7-6 已预留），不是电信族。**登记要求（防丢）**：一行重议触发器，建议文本形态 = `区域合规配置面（对照 Fuchsia regulatory_domain）：首个带无线电/蜂窝硬件的真机或穿戴产品立项时重议`——落点 = #83 落稿时的重议触发节或本系列 README 18 号行备注（由主会话裁）。

### 2.5 维度 5：遥测/隐私的 OEM 面 —— **真空白（轻，v2+ 自然覆盖 + P2 登记）**

已有面全部是平台侧：系统应用「遥测削至近零」义务（01 号 :63、04 号 :218）、abi_revision 仅作遥测/门槛统计不执法（07 号 :308、09 号 :211/:353「事实字段不执法」）。OEM 面零研究：OEM 预装/替换件可否采数据、平台遥测数据 OEM 可否消费、隐私合规（GDPR/个保法）责任归谁——全系列零命中；04 号 :267 OOBE 行仅一句「隐私声明/监管文案面随分发执法（应用规范 §10.3）」。**判定 v2+ 的理由**：平台自身遥测近零立法在先，「OEM 遥测」无现实流量可管；数据外发能力的授权面（G1/G2 弹窗、位置/传感器词表）已列 v2 预埋（01 号 :128），OEM 边界可同刀定义。**P2 登记一行**：`OEM 件遥测/数据外发边界：随 v2 能力词表（sensor/位置/logs）开刀同刀立法，防「能力基线」（04 号 §4.3）把遥测写成无主词`。

### 2.6 维度 6：开发者感知 OEM 差异（能力探测/查询面）—— **真空白（P1，需补研究：单 agent 半天）**

Q7 裁定的 `feature_level` 是**组装期**产品清单键（08 号 :271 消费方 = 组装器，用于预装最小集对账），不是运行时查询接口；Q8 槽位开放序、Q10 披露位（「含闭源件」）都是认证/组装面元数据。**第三方开发者运行时感知设备差异**（这台设备有没有某槽位替换/某能力/某档位）全系列零研究（§1.3 维 6 行）：现役机制下开发者只能靠装载期词表拒载试错（appd loud 拒，01 号 :128）。行业对照（一手补采）：Fuchsia `hwinfo.fidl` 同时定义 `Device`/`Product`/`Board` 三个 `@discoverable` 协议（`GetInfo()` 运行时可查 serial/语言/区域/板名/架构）——运行时硬件/产品信息查询是 Fuchsia SDK 的 day-one 组成；Android 的 `PackageManager.hasSystemFeature`/`Build` 是同题另一族先例（行业常识，未在本系列采证，补研时补锚）。

**为什么是 P1**：①档位与槽位开放是 #82/#83 的核心输出，若开发者无查询面，「BerryOS 兼容」对第三方 = 黑盒试错——恰是 07 号研究 CTS/SDK categories 时该追问而未追问的接口面（推断：07 号聚焦分发面 categories，运行时探测面不在其题）；②查询面若做，载体（sysinfo 常驻服务？manifest 声明面？）牵动 #83 的清单键设计与能力词表，与维 3 同刀最省。**补研要素**：规模 = 单 agent 半天；输入锚 = 08 号 §2.2 + 04 号 §4.3 能力基线 + Fuchsia hwinfo（已采）+ 07 号 §2；产出形态 = 查询面载体建议（服务/manifest 双案）+ `feature_level`·槽位开放集·闭源披露位三者的运行时可见性矩阵，供 #83/SDK 面收编。

## §5 反面自检（本审计自己的弱点，如实写）

1. **「应有全景」的量尺风险（推断）**：六域框架由样本反推 + 行业常识合成，未经第二人对抗——「应有」判得偏宽则空白虚高（如维 5/增补 C 对 v1 而言确属过早）；本稿已把「研究完备性判定」与「v1 功能必要性判定」分开表述，P2 的 v2+ 分级即为此对冲，但读者不应把 P2 件读成「BerryOS 缺陷」。
2. **关键词法的盲区**：grep 同义异名无法穷尽（如「多语言」「本地化设置」等口语变体未逐词扫）；已用每维度 5–11 个词组交叉且命中处逐条回读，残余风险 = 某维度以完全意外的措辞被研究过而被误判空白——对 P1 三件已用精读复核（08 号全键表/09 号全编队节逐行），P2 件接受此残余。
3. **单轮无对抗**：本稿未经红队轮，尤其「P0 = 零」依赖「add-only 可救」推断（锚 12 号 §2.7 原文）——若 schema=1 首版语义即错（Q7 残余风险），键位后补代价高于周级；建议主会话把 §4.2 边界条件随 G1/G2 补研一并复核。
4. **Fuchsia hwinfo 单源**：本轮一手补采仅 main 快照一源（gitiles 直抓成功，fuchsia.dev 渲染页 404），FIDL 字段演化史未核——标注待核实；但其在本稿仅作「Fuchsia 产品配置面存在 i18n/查询维度」的存在性证明，字段细节留给 G1/G2 补研两源核验。
