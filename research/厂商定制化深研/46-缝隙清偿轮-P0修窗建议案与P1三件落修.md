## §4 P0 修窗建议案：INTENT 等待窗 × slice 档（三案利弊 + 推荐 + owner 裁决锚）

### 4.1 冲突复述与修窗边界（44 号 §2-1 / 45 号 §3 双证沿用）

- **机理（算术 + 源码）**：INTENT 验收司机 `task_intent_probe`（`kernel/src/main.rs:3543-3604`）睡 `8 × slice_ns` 等全链落定（`:3550-3555`，`slice_ns = slice_cycles() × 1e9 / cntfrq`）——设计隐含假设 10Hz（8×100ms=800ms）；被测者 `it_slow` 睡 **200ms 墙钟**（`:3519-3523`，`thread_sleep(now + 200_000_000)` 绝对期限）后 send CH6 触发 send 降级。250Hz 时 8×4ms=32ms、1000Hz 时 8ms，均 < 200ms——司机早醒，`intent_budget_capped_total() >= 2`（`:3596`，慢 send 降级是第二源）与 `intent_borrows() >= 3`（`:3592`，slow 第三次结算同在 200ms 后）双断言炸 → 探针任务死 → `INTENT ok` 永缺席 → `tools/markers.sh:16` bare 数组第 24 项缺 → `--image` FAIL（240s 未到齐）。三臂隔离（default/250/1000 唯一差 = boot-params）与 std 盘 PASS 对照已闭环（44 号 §2-1）。
- **修窗边界**：归 kernel 域 owner（本稿只落案零碰 kernel）；**BCTS 侧标记合同不动**（bare 相 add-only 纪律正确——44 号裁定沿用）；修前 OEM 侧唯一绕道 = 退 10Hz 出认证镜像（丢推荐值收益，不可接受，故 P0）。
- **在树先例（裁决的关键裁据——链内已有两种正确等待形态）**：①**墙钟绝对期限**：`it_slow` 的 200ms 睡（`:3521`）与 `it_sinkB` 的 `wait_one(CH6, READABLE, now + 100s)`（`:3469-3475`，注释原文「4-2 阻塞链复用，**不赌时序**」；同款 100s 期限另两处 `:2469`/`:2575`）；②**事件驱动**：`it_sinkB` 以 `wait_one(CH6 READABLE)` 阻塞等 slow 睡足发出（`:3470-3476`）才走后续。探针的 8×slice 计数是 INTENT 链内**唯一「以片数代时间」的等待**——其设计注释自认「slice_ns 换算同 waker2——clock 域确定性」（`:3548-3549`），确定性真，但窗长随 slice_hz 缩放 = 隐含 10Hz 假设的债。

### 4.2 三案

| 案 | 形（改哪） | 利 | 弊 |
|---|---|---|---|
| **a 等待改墙钟** | 探针等待窗一处（`:3550-3555`）：`now + 8*slice_ns` → `now + max(8*slice_ns, 400_000_000)`（400ms = 2× 被测事件，量纲同 it_slow 墙钟） | 一行改（P0 最快解）；时钟域既有（NR_THREAD_SLEEP 绝对期限——it_slow/it_sinkB 同款）；**10Hz 臂行为恒等**（max 取 800ms，default 谱系/`INTENT ok` 7.709s 在案值零回归，standard.img PASS 基线不动）；250/1000 档 400ms ≥ 200ms+2× 裕度，TCG 重载下安全 | 魔数对（it_slow 200ms 改则 400ms 跟改——常量成对维护）；仍是「等足够久」启发式非真同步；+368ms 标记延迟（250 档 32→400ms，对 240s 判定窗可忽略） |
| **b budget_capped 改比例** | 断言阈值随 slice_hz 折算（如 hz≥125 时 `borrows>=2`/`budget_capped>=1`——两断言都须放宽，§4.1 算术） | 零等待面改动（纯断言参数化） | **在推荐档位永久弱化验收面**——slow send 降级路径（INTENT 语义半边）在 250/1000 档从此不被断言，恰是生产品牌配置失去覆盖，与 bare 相 add-only 合同精神相悖；不修根因（窗 < 事件时刻，探针仍早醒只是不再喊）；阈值折算表 = 新的档位耦合面（未来 200ms→500ms 又要再折算）；「测试在推荐配置下比默认配置松」的反模式 |
| **c 探针改事件驱动** | 形一：探针 `wait_one(CH6, READABLE)`（it_sinkB 同款）+ 结算尾步；形二（推荐形）：条件轮询循环——「三计数器阈值齐 ∧ 四睡眠者在 SLEEPQ」才出循环，墙钟兜底帽（it_sinkB 100s 同量级） | 真同步零窗假设（任何 slice_hz/任何被测时长自适应）；标记提前（INTENT ok 紧跟链尾，非固定 800ms——10Hz 臂缩短是行为变化，须记谱系）；对未来改参（200ms→任意）鲁棒；「四者在席」入循环条件可同时消 saw_slow 结算竞态 | 改造面大于一行（循环 + SLEEPQ 探查 + 帽）；探针从纯观察者变链参与者——形一与 it_sinkB 竞态 CH6 消息/信号（多等待者唤醒语义归 owner 域知识）；结算竞态须显式处理（slow send 后未及 block_current 时 saw_slow 可缺——形二以条件收编）；INTENT 链拓扑与探针角色语义变化须过调度线自审 |

### 4.3 推荐 + owner 裁决锚

- **推荐**：**a 为首刀**（解 P0 燃眉：一行、时钟域既有、10Hz 臂零扰动、default/standard 基线不回归）；**c 为正形**（登记调度线后续窗——ktest 面下次翻新或 #84 BCTS 深化窗顺手落，形二优先）；**b 否决**（弱化验收面，与 add-only 合同精神相悖）。若 owner 只采一刀：采 a。
