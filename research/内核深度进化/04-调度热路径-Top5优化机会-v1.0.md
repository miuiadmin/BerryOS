## 结论速览

一句话判词：BerryOS 调度热路径的**结构性设计面已经过硬**——Σvruntime 增量账本把 EEVDF 的 avg 从 O(n) 全环扫描压到 O(1)（`sched/src/runqueue.rs:33-61`）、唤醒链有 P1 无等待者 O(1) 门 + P2-1 同键链扫描（`sched/src/sched.rs:2244-2339、2341-2394`）、锁族是 TTAS + 位感知退化 + tick 面非阻塞 try 形（`sched/src/spin.rs:41-75`、`sched/src/sched.rs:547-568、710-719`）、band 扫描有武装计数门、deadline 扫描有 DL_ON_RING 计数门（`sched/src/runqueue.rs:108-115`）——多处已是「优化后形态」。剩余 Top-5 不在数据结构选型，而在**恒定冗余与诊断残留**：每个 syscall 的 SVC 尾检查点恒付一次全局原子 RMW + 一对 RQ 锁原子 + 一圈 O(n) 探峰扫描；切换热路径每 100 次付 PRINT_LOCK + 串口行 + 三锁三全环走查对账；最热计数器（SWITCHES 族）是跨核共享原子、每 switch 两次同 cache line RMW；band 任务每授片付一次 u128 软除法、每 tick 四次 CNTVCT 读；偷取空手形态付三段锁 + 两圈环走查。五项全部不动 ABI 与调度语义面。

## 机会一（pick 链）：SVC 尾检查点探峰瘦身——len 门、双圈合一、计数移窗

**现状证据**。`preempt_checkpoint`（`sched/src/sched.rs:174-182`）在三个面被高频调：① 每个 SVC 派发尾无条件调用（`arch/aarch64/src/syscall.rs:82-86`，接线 `kernel/src/main.rs:2372`）；② send/recv 段出口检查点（`kernel/src/syscall.rs:3438-3442、3626-3628`）；③ UART RX 与同槽 IRQ 臂（`arch/aarch64/src/trap.rs:615-631`）+ `print_window_exit`（`sched/src/sched.rs:210-215`）。每次执行 = `irq_save` + `disable_irq` + `preempt_count` 读 + **`PREEMPT_CKPT_HITS` 全局原子 fetch_add**（`sched/src/sched.rs:178`，计数点在 try_preempt 之前、锁窗外）+ `try_preempt` 全量（`sched/src/sched.rs:3127-3185`）：RQ 锁 CAS 取放一对（`rq_lock`/`rq_unlock`，:3148、3160）+ `has_eff_above_filtered` 一圈 O(n) 环扫（:3150 → `sched/src/runqueue.rs:437-463`）；命中更高者再 `pick_next_filtered` 第二圈 O(n) 扫描（:3151 → `sched/src/class.rs:461-492`）。

**热点机理**。g3-1b 注自证「现役 SVC 全程 IRQ 屏蔽 ⇒ 单核 rq 状态窗内不可变 ⇒ 探峰恒空 = 纯空探」（`sched/src/sched.rs:166-167`）——即**常态每次系统调用都在为一次注定落空的探峰付全局原子 + 锁对 + 全环扫描**；g3-1c 域解蔽后它才真承重，届时成本结构不变、频率照旧。全局 `PREEMPT_CKPT_HITS` 与 `SWITCHES` 同族跨核 RMW（双核各自每 syscall 摸同一 cache line，推断：SMP 参与态下争用随 syscall 频率线性涨）。双圈扫描在命中形态翻倍（探峰一圈 + 出选一圈扫同一环），`on_sgi_resched` 已用 `rq().len() >= 2` 先门免扫（`sched/src/sched.rs:4134`）而 try_preempt 没有同款门。

**方案三件套**（全部零语义变化）。① len 门：`try_preempt` 在取锁前加 `rq().len() <= 1` 早退——cur-in-ring 不变式（Running 常驻环，`sched/src/class.rs:50-52`）下 len ≤ 1 ⟹ 环上只有 cur 自己 ⟹ 必无更高者；len 是 AtomicUsize Relaxed 免锁读（`sched/src/runqueue.rs:160-162`），单任务/空环常态（svc 返回后探峰的绝大多数形态）整段跳过锁对与扫描。② 双圈合一：`scan_filtered` 的 `ScanAcc` 本就追踪最高带 `best_eff`（`sched/src/class.rs:445-460` 注），导出「best_eff 是否严格高于阈值」一个布尔即把 has_eff_above + pick 合成一圈（消费点仅 try_preempt 一处；幻影出选防线语义逐位保持）。③ 计数移窗：`PREEMPT_CKPT_HITS` 的 fetch_add 移到 len 门之后（或并入机会三 per-CPU 化），空探不再摸全局行。

**风险与守卫**。len 门依赖 cur 在环：null cur 已有早退（:3141-3143）；park 派发态不经 try_preempt。ktest FAST L0-L4 与 fa_ping 的 `ckpt>=1` 断言（`kernel/src/main.rs:4261-4262`）是行为守卫——计数移窗后真探形仍计数，断言面不破（断言语义 = 至少一次真探）。判分：影响大（每 syscall 恒定、确定性）×可行性极高（三小刀、判例全在仓内）→ **Top-1**。

## 机会二（switch 面）：bring-up 诊断退役/降频——%100 串口行、integrity_check、hb/stuck

**现状证据**。切换热路径上挂着三件诊断。① `bump_switches`：十一个切换原语位共享递增，每 100 次切换跨点即 `print_lock_raw` + 五次 UART 调用拼 `switches=N kl=M` 行（`sched/src/sched.rs:56-77`，`SOAK_PRINT_EVERY=100` :59）——PRINT_LOCK 是 TTAS 自旋锁，切换点可能在 IRQ 上下文（tick 抢占支 :4011、SGI :4155），打印窗口整段撑大 IRQ 屏蔽窗；自注「bring-up 诊断（G1）」（:58）。② `integrity_check`：每 100 切换跨点在 tick 抢占支/idle 强制让点支执行（`sched/src/sched.rs:4017-4019、4074-4076`），本体 = 双核 RQ 锁 + SQ 锁三段取放 + 双环全走查（ring_check 步数/Σvruntime/DL 三重对账）+ SLEEPQ 全走查（:3369-3431）——O(两环 + 睡眠队) 全在 IRQ 窗内。③ hb 心跳与 stuck 扫描：par 门内每 500/2500 tick 一次（:3857-3914），频率低但同属「定谳后随探针一并退役」声明面（:32、36、773）。

**热点机理**。金丝雀打印的设计前提是「两任务分时 → 计数持续涨」的 bring-up 语境；在 IPC ping-pong / soak 形态下切换频率高出几个量级（fastpath 直切臂自注「IPC ping-pong 最热切点」，:3168-3170），每 100 切换一次的串口行 + 全量对账成为**周期性 µs 级尖峰**（推断：按 PL011 逐字符 FR 轮询 + DR 写、~17 字符/行、TCG 下每次跨点 ≥ 数 µs；真机更贵）。integrity_check 的三段锁在 SMP 参与态下还会与对核 pick/steal 争用（RQ 锁窗内走查，:3385-3399），把对核的出选延迟一并拉高。三者都已在注释里声明退役计划（「诊断面，定谳后随探针一并退役」:32、36、`sched/src/spin.rs:15-18`），属**该删未删**。

**方案**。判例分层退役：① switches 金丝雀行 → 编译期 feature（`cfg` 门）或 `SOAK_PRINT_EVERY` 抬到 soak 专属档（G1 里程碑已过，smoke 断言若依赖该行则改读 `switches()` 计数器——watchdog 已有只读访问器 :2009-2016，打印与断言可解耦）；② integrity_check → 降频（每 N 万切换）或移到 idle_loop 低频段（CPU0 空闲时做对账，不在抢占 IRQ 窗内）+ feature 门；③ hb/stuck/spin_bark/EAS 决策日志随 S-6 定谳结论一次性退役（同一批「探针」族）。watchdog 依赖的计数器面（SWITCHES/SWITCHES_TT/USER_KILLS）保留，只动打印与走查。

**风险与守卫**。退役后失去「环分裂静默失联」的在线对账（复盘雷 2 的确诊机制）——保留 ktest 侧 ring_check 全量跑（ktest 本就直调，`kernel/src/ktest.rs` RING 族），线上降频而非全删即两全。判分：影响大（IRQ 窗周期尖峰 + SMP 锁争用放大）×可行性极高（删/门代码，设计意图已在注释）→ **Top-2**。

## 机会三（switch 面）：全局共享计数器 per-CPU 化——SWITCHES/SWITCHES_TT/PREEMPT_CKPT_HITS/IRQ_TICKS

**现状证据**。四个最高频计数器全是全局 `static AtomicU64`：`IRQ_TICKS`（`sched/src/sched.rs:26`，每 tick 每核 fetch_add :3748）、`SWITCHES`（:30，**每 switch** fetch_add :57——十一位共享口径）、`SWITCHES_TT`（:2007，每任务↔任务 switch fetch_add :2064）、`PREEMPT_CKPT_HITS`（:172，每检查点 fetch_add :178）。SMP 参与态下双核对同一 cache line 做_RELAXED RMW：忙对稳态（两核各跑一个分时任务）下每 tick + 每 switch×2 + 每 syscall 至少四次跨核行乒乓（推断：Relaxed 不省 coherence 传播，MESI 独占权每次 RMW 都要迁移；行内多计数器同驻加剧）。

**热点机理**。这是 SMP 经典反模式：计数本身无序角色（注释自证「Relaxed 无序角色、仅计数」，:25、2178），却把最热路径（switch/ tick/syscall）串行到同一行。仓内已有两个正面判例：`LB_TICKS` 用 `[AtomicU64; 2]` per-CPU 分行（:2179-2180，注释「偷到 CPU1 的子在其上跑、tick 记到 c1」）；`WaitBucket` 用 `align(64)` 逐桶防伪共享（:2265-2268）。per-CPU 基建现成——`SmpCpu` 块经 TPIDR_EL1 寻址（`current_slot`/`preempt_count_slot`/`last_vct_slot` 全套访问器，:91、122、`sched/src/class.rs:131-136`），`note_switch_cpu`/`note_tick` 本就是 per-CPU 独占写（:1541、3751）。

**方案**。四计数器迁 `[AtomicU64; 2]`（或 SmpCpu 槽），写侧按 `cpu_id()` 写本核槽（Relaxed 不变），读侧求和——读者面窄且全在诊断/断言：`switches()`（watchdog，:2009）、`switches_tt()`（G1.5 遥测分母断言，:2014）、`preempt_checkpoint_hits()`（fa ktest 尾，:185）、IRQ_TICKS 无 pub 读者（模块内诊断）。两槽 `align(64)` 分行。顺手项：`bump_switches` 的 `%100` 判定改读本核槽，跨点语义不变（打印频度按全局和，读时求和即可）。

**风险与守卫**。读侧求和是快照语义（两核和有 ns 级非原子窗）——断言面全是 ≥/持续增长型（watchdog「冻结在某值」、G1.5「tel ≥ switches_tt」配平断言需改为各自求和同窗快照），无等值比较依赖即可安全。判分：影响中高（SMP 稳态主力路径的行乒乓）×可行性高（判例同文件、读者面窄）→ **Top-3**。

## 机会四（RQ 账本/记账）：band 授片与 tick 的 u128 除法缓存 + CNTVCT 单读线程化

**现状证据**。`TaskClass::grant_cycles` 的 Band 臂每调用一次 `quantum_cycles()`（`sched/src/class.rs:877-882` → :573-575）→ `ns_to_cycles`（:103-109）= `(ns as u128) * f / 1_000_000_000`——**u128 乘除**，AArch64 上 128/64 除法走软件例程（推断：无硬件 128 位除指令，`__udivti3` 量级数十 cycle）。消费面 = `sched.rs` 全部八个授片点（:1531、1714、2774、3162、4004、4147、4458、4496——yield/exit/block/try_preempt/tick/SGI/park 派发/idle 派发）+ `FairBand::tick` 的 `rearm_vd`（:763-765）与 `arm`（:586-591，被 `period_check` :624-629 与 `consume` :605-618 各调一次）。CNTVCT 读同族冗余：一次 `FairBand::tick` 内 `peek_tick_delta`（:127-142，读 1 次）+ `Fair.tick`（:266，读 1 次 + last_vct 写）+ `period_check(hal::timer::cntvct())`（:776，读 1 次）+ `consume` 内部（:606，读 1 次）= **每 tick 四次计数器读**（自注承认 peek 与 Fair.tick 是「只读孪生……微秒以下」差距，:122-127）。

**热点机理**。四带全开后（`sched/src/class.rs:495-513`，LC/BG/UTILITY/INTERACTIVE 现役集 0x01-0x04），每个带任务的每次切换授片与每 tick 记账都付软除法 + 四次 sysreg 读。ns→cycles 的输入全是常量（表行 quantum_ns/latency_target_ns 固定、cntfrq 启动后恒定），**结果在整个运行期不变**——每次重算纯浪费。且武装槽里已经躺着答案：`FairBand::arm` 把 `quantum_cycles()`/`period_cycles()` 算好写进槽的 quota/period（:590 → `sched/src/band.rs:121-152`，quota 即 quantum_cycles、period 即 period_cycles），只是 grant 路径不读它。

**方案**。① 授片直读镜像：`grant_cycles` Band 臂改「武装槽 quota 直读（一次普通 load，冷配置字段）+ 未武装才现算」——新增 `band::quota_cycles_of(band) -> Option<u64>` 读 `BANDS[band].quota`（static mut 冷字段，读写本就全在屏蔽窗契约内，`sched/src/band.rs:57-67`）；`rearm_vd`/`arm` 同改。② now 线程化：`FairBand::tick` 入口读一次 CNTVCT，作参数传 `peek_tick_delta`（改 `peek_tick_delta_at(now)`）、`period_check(now)`、`consume(delta, now)`——四次读归一，`Fair.tick` 的 last_vct 基准读保持原位（它是写点）。单核/未武装负载零漂移（unit 臂走 `slice_cycles()` 缓存 static，`arch/aarch64/src/timer.rs:244-247`，本就零除法）。

**风险与守卫**。镜像一致性：configure 重配会改 quota——重配面本就要走「先 unthrottle_all 清残留再 configure」契约（`sched/src/band.rs:115-118`），grant 读槽自然跟随新值，无漂移面；ktest BANDM4 的 M4G 数值断言（`class.rs:114-116` 注）是钉板。判分：影响中（带任务每片每 tick 恒定、确定性）×可行性高（槽内已有答案 + 参数直传）→ **Top-4**。

## 机会五（enqueue 锁）：偷取三段锁两圈走查与排水锁的空态瘦身

**现状证据**。`try_steal_one`（`sched/src/sched.rs:4337-4440`）每次探测三段锁 + 两圈全环走查：① 本核 RQ 锁短窗内**整圈环走查数带分布**（:4348-4372，逐节点 `band_of_task` → `class_of_task` 查表）；② 远端 RQ 锁窗整圈 victim 扫描（:4378-4409）；③ 摘环后回插本核再取本地锁（:4432-4436）。触发面 = 每次 `park_recheck` 空手后（:4241）+ `idle_loop` 每 pass 出选 None 后（:3484）+ tick 定时拉取门（:3944-3949）。`reap_drain`（:1833-1865）每次调用无条件取放 REAPQ 锁（TTAS CAS 对 :1840-1841、1854-1855）——即使队空；调用面 = **CPU0 每次 `yield_now` 切回尾**（:1574-1576）+ idle_loop 每 pass（:3464、3534）。`REAPQ_LEN` 是 `static mut usize`（:1787），无免锁读门。

**热点机理**。空手偷取是常态形（对核环上无 eligible 或本核不空）：此时 ① 的带分布走查照付整圈锁 + 整圈扫——而本核环空的形态下分布恒 (0,0)，带判据退化为「不密集 → 见首即定」（自注 :4279-4281「空环〔idle 偷取常态〕= 0>0 假」），整圈走查是白付；② 的远端扫描在空手形态也是白扫但必要（探测语义）。排水侧：yield 是服务循环主力原语（console/svcmgr 每轮消息处理至少一次），每次都为一支大概率空的队付锁对。三段锁 + 两圈扫 × park 环每醒一次 = 空转核的固定税（推断：TCG 双核 idle-heavy 形态下 park_recheck 频率随 SGI 唤醒走，每次 ≥ 三对 CAS + O(n)×2 节点访存）。

**方案三刀**。① 空环早退：密度快照前加 `rq_of(me).is_empty()`（或 `len()==0` Relaxed 读）→ (0,0) 直落，免本核锁与整圈走查——空手形态锁段从三降到二、走查从二降到一；② REAPQ 免锁门：`REAPQ_LEN` 升 `AtomicUsize`，`reap_drain` 入口 Relaxed 读零即返（push 侧先持锁后写计数不变，锁交接即可见性边界——WAIT_HASH 同论证 :2330-2331），yield 尾与 idle 每 pass 的空队成本从 CAS 对降为一次 load；③ 密度账本化（中档）：per-RQ `int_count/util_count` 两计数器在 `link_back`/`unlink` 原语层随 `DL_ON_RING` 先例维护（`sched/src/runqueue.rs:96-108`），偷取密度快照从整圈走查降为两次 load——需处理在环改档（intent 结算借入改档 `sched/src/sched.rs:1394-1409`）时的重登，复杂度集中在账点收口。

**风险与守卫**。①的语义等价：非空环仍走原走查（分布真值）；②的单核行为逐位不变（锁内判据外提为读门，空返路径本就无副作用）；③有 DL_ON_RING 的「账点挂结构原语层防漏账」完整判例（block/steal 直调 unlink 不经类层）。ktest SMP/偷取族与 smoke-smp 相 3 的 LB 金丝雀是行为守卫。判分：影响中（空转/服务循环常态路径）×可行性高（①②小刀、③有判例）→ **Top-5**。

## 附记一（推断·正确性缺口，优先级高于全部性能项）：S5-c 逐任务 deadline 预算解冻在生产出选路径不可达

`lazy_unthrottle_deadlines`（`sched/src/class.rs:173-199`）——S5-c 逐任务 deadline 预算的**唯一解冻点**——只被 trait `Fair::pick_next` 调用（:251）；而生产代码的全部八个出选点都走 `pick_next_filtered`（`sched/src/sched.rs:1497、1688、2737、3151、3476、3972、4135、4207`），后者**不含**该调用（`sched/src/class.rs:424-440`），trait `pick_next` 的调用面全在 ktest（`kernel/src/ktest.rs` POLICY/PV3/PBS/DV/RING2 族等）。`Fair::tick` 的 `throttle_admissible` 置 HELD_THROTTLE（:324-331）在生产可达；`band_period_sweep` 只管带级限流（intent 带），不碰逐任务 deadline 位。推断结论：生产（非 ktest boot）中 deadline 任务预算耗尽被限流后，无任何路径解冻——`DL_ON_RING` 计数门与账本（`sched/src/runqueue.rs:84-115`）在生产也成死账面；deadline 任务可经 `sys_sched_setattr` policy=3 进入生产（`kernel/src/syscall.rs:1627、1653-1654`）。修法一行级：把 `lazy_unthrottle_deadlines(rq)` 调用搬进 `pick_next_filtered` 头部（`dl_on_ring()==0` 早退已具备，v1 常态全员 fair 零成本——门语义自证 :164-169）。此为调用面静态分析推断，未实测复现；建议先落一条 ktest/生产双面钉板再修。
