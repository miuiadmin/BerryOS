一句话说明：对 01 号审计册唯一余项「机会 3（进程退出页面回收，1–2 周件）」做立项前只读研究——核对 base（wip/sched-1.1@2561255b4）退出链现状与审计册证据的漂移，并盘点 `wip/base-overhaul` 线 F1-1/F1-2 已交付的同题实现；结论：**机会 3 在本 lane（W3）不可立项**——其主体已被 owner 的 base-overhaul 线以更彻底的形态（AddressSpace 对象化＋两阶段退出拆表＋ObjRef map_refs）实现并验收，W3 重复立项必然双线对撞；本册 01 号 Top-5 至此四落一判（机会 3 = 由 F1-2 承接，不另立项），01 号审计面闭。

## 证据面（2026-11-19 直核）

### ① base 线现状（机会 3 的「债一/债二」仍在）

- 债一（进程退出整档泄漏）：`kernel/src/handle.rs:381-408` drain 对 `refs==1 && (any_mapped() || demand_mapped())` 的 VMO 整对象跳过递减——base 线原样（本工作树直读）。
- 债二（表树帧不回收）：`kernel/src/vmar.rs` `Vmar::Drop` 只注销 DEMAND_ROOTS 槽＋放 demand 钉，自述「v1 不回收表树帧」；`kernel/src/process.rs:32-33` 明文「L1 表树帧在 v1 不回收」——base 线原样。
- 即：审计册 §③ 债一/债二的**证据描述在 base 线仍然成立**，01 号机会 3 的立项动机没有被 base 线自身的演进而消解。

### ② base-overhaul 线已交付同题实现（决定性）

- commit `9f113a65d`（2026-11-18，miui，在 `origin/wip/base-overhaul`，**不在** wip/sched-1.1）：「kernel/mm: F1-2 两阶段退出自动拆页表、页表帧全回收与废除 leak 分支」。
- 实现面（git show 直读）：`proc.aspace.teardown()` 阶段一（pt_lock 内置 torn_down、全树清叶、untrack_map/untrack_demand/release_map、单次按 ASID TLB 失效、L3/L2/L1 页表帧 100% 归还＋释放 ASID）→ 阶段二 `ht.drain()`（**彻底删除 leak=true 分支**）；`ObjRef` 升级 64 位组合原子态（低 32 refs＋高 32 map_refs）根除跨进程 UAF；配套 `ht_drain_assist_below` 创建侧内联助推排水。
- 前序 `F1-1`（AddressSpace 对象化、层级 vmarface 区间树、对象内嵌 pt_lock、DEMAND_ROOTS 收口）同线落地（`.agents/notes/implemented/2026-11-18-f1-1-…md`、`f1-2-…md` 在案，注意：**该 notes 属 base-overhaul 线合入时带入**，与本 base 树的 aspace.rs〔137 行、无 teardown〕不同体）。
- 验收（笔记自述）：ktest `test_f1_2` 连续生灭 2000 子进程 `mm::allocated_pages()` 逐页归零、父先子后反向生命周期 0 泄漏——恰是审计册机会 3 第三步「进程面 churn 金丝雀」的验收形态，且更严。

### ③ 结构对撞判（为什么 W3 不能立项）

- 机会 3 三步改法（drain 前整树 unmap 扫 → mapcnt 归零正常递减销毁 → Vmar::Drop 补表树回收）与 F1-2 的两阶段销毁**作用于同一批文件同一批不变量**（handle.rs drain、vmar.rs Drop、process.rs 退出链）；两线并行实施必然在 `HandleTable::drain` 的 leak 分支、Region 生存期政策、DEMAND_ROOTS 注销序上语义冲突。
- base-overhaul 的实现还顺带解决了机会 3 方案里挂账的 SMP 面（map_refs 原子化）与父先子退出 UAF（机会 3 原方案未覆盖）——W3 即使做完也是劣化版重复。
- 结论：机会 3 的正确归宿是 **base-overhaul 并回流 base 时整体承接**，W3 lane 零动作。
