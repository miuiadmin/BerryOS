# BerryUI 三方控件体系对照（Android / iOS / OpenHarmony）

Type: survey
Status: current
Updated: 2026-11-15

## 1. 范围与方法

本文对照 Android（View/Material 与 Jetpack Compose Material 3）、iOS（UIKit/SwiftUI/Human Interface Guidelines）与 HarmonyOS/OpenHarmony ArkUI 的官方控件目录，为 BerryUI 公共组件面的下一阶段补齐提供依据。事实全部来自官方文档的归纳摘要，未复制长 proprietary 文本；每条来源 URL 均在 2026-11-15 验证可达（HTTP 200，或经 Apple 文档 JSON 数据端点确认页面存在；docs.openharmony.org 在本网络不可达，改引 gitee.com/openharmony/docs 官方仓 master 原文，与 docs.openharmony.org 版本页一一对应）。

BerryUI 现状读自工作区源码 [../user/berry-ui/src/sdk.rs](../user/berry-ui/src/sdk.rs) 与 [../user/berry-ui/src/widgets.rs](../user/berry-ui/src/widgets.rs)，规格背景见 [../docs/BerryUI-F4组件第一版-v1.1.md](../docs/BerryUI-F4组件第一版-v1.1.md)、[../docs/BerryUI-F2核心盘点-v1.0.md](../docs/BerryUI-F2核心盘点-v1.0.md) 与 [../docs/BerryUI-SDKS0ControlSpecAPIGovernance-v1.0.md](../docs/BerryUI-SDKS0ControlSpecAPIGovernance-v1.0.md)。

## 2. BerryUI 公共面现状

F4 组件共 13 个：`Scaffold`（`new` / `new_light_safe` / `with_back` / `with_back_safe`；`safe_top` / `safe_bottom` 为 Room 遮挡快照的原始像素，body 高度自动扣减）；`AppBar`（legacy 彩条标题栏或 56dp light 现代导航栏 `effective_px(224)`，可带返回按钮）；`Button`（label + InteractionState，无强调档位）；`IconButton`（48dp 命中面 / 24dp 视觉，`on_primary` 变体）；`Card`；`ListItem`（title/detail/selected）；`ListTile`（leading icon + title + detail + trailing，48dp 行高）；`ListDetail`（双 pane flex 权重布局）；`Switch`（ROLE_TOGGLE，Click 翻转视觉态）；`TextField`（单行：selection/caret/水平滚动/`shrink_to_width`/`request_focus`/`sync`；Password 明文不入语义树）；`ScrollView`（纵向拖拽，`sync_bounds`/`scroll_by`）；`EmptyState`；helper 函数 `column` / `row` / `text`（Title/Body/Caption）/ `icon` / `divider`。

F2 核心能力：ViewKind = Text/Panel/Row/Col/Rect/Circle/Icon/Clip/Grid（`GridProps` 已有但无 widget 包装）；flex（FlexSpec/FlexEntry）与 BoxConstraints；SemEntry 语义侧表（roles：button/text/list-item/toggle；actions：ACTIVATE/ADJUST/FOCUS/TEXT_EDIT；states：CHECKED/DISABLED）加 A11yRegion 往返；Theme 全 token 体系（Spacing/Radius/Stroke/Typography/TextScale/Density/ColorScheme 与对比度工具）；`slot_variant(basis_w, threshold)` 的 Compact/Expanded 自适应判定（显式局部基准，不读全局屏，见 [../docs/BerryUI-L1LocalConstraintsAdaptiveSlot-v1.0.md](../docs/BerryUI-L1LocalConstraintsAdaptiveSlot-v1.0.md)）；`focus_key_intent` / `key_route` 键路由仲裁；TextInputKind = Text/Number/Password、`ime_overlap_px`（见 [../docs/BerryUI-GUIT1TextFieldFoundationBeforeIME-v1.0.md](../docs/BerryUI-GUIT1TextFieldFoundationBeforeIME-v1.0.md)）；NAV_ICON_BACK/HOME/TASK（含 active 变体）三键系统导航图标。

架构纪律：组件全部为 Plain Data 加 `&mut Ui<N>` 引擎门面、返回稳定 NodeId，业务状态归 app；新增类型进入 `sdk` 再导出前必须满足 Plain Data、host 值级测试、no_std 零分配三关。

## 4. 缺失清单（三端都有、BerryUI 公共面没有）

选择类：Checkbox、Radio（Group）、SegmentedControl。值调节类：Slider、Stepper。反馈类：ProgressIndicator（任何形式）、LoadingIndicator、Toast/Snackbar、按压反馈。导航呈现类：Tabs、BottomNav、FAB。浮层类：AlertDialog、Sheet、DropdownMenu/ContextMenu（全部卡在无 overlay 层）。输入类：TextArea 多行、SearchField、TextField 的 label/supporting/error、键盘附件。集合类：Section/ListItemGroup、Grid widget 包装、横向滚动、加载更多钩子、Refresher、swipe actions。令牌类：Badge、Chip。选择器类：TextPicker、DatePicker、TimePicker。系统类：SafeInsets 统一结构、断点常量、SEM_STATE_SELECTED、位图 Image 节点。

## 5. 实施路线

P0（引擎前置）：其一，overlay 覆盖层——对话框、菜单、toast、sheet 四类组件的共同门槛，建议 Room 顶层区加 BerryUI 层号；其二，ViewKind::Image 位图节点；其三，SEM_STATE_SELECTED 语义位。

P0（组件，产品壳可用性优先）：Checkbox、RadioGroup、Slider、ProgressIndicator 加 LoadingIndicator、Tabs 加 BottomNav、AlertDialog、Toast、Section/ListItemGroup、SearchField、Grid widget、SafeInsets 加断点常量、加载更多钩子、Button emphasis 档。

P1：SegmentedControl、Stepper、Chip、Badge、TextPicker、DatePicker（紧凑形态）、Sheet（detents）、DropdownMenu 与 ContextMenu、swipe actions、TextArea、Refresher、横向滚动、按压缩放反馈、滚动隐藏栏、NavStack helper、手势 helper、SEM_ACTION_ADJUST 落地、Large AppBar。

P2：FAB、NavigationRail 与 Drawer、Swiper 分页、瀑布流、Gauge/DataPanel/Rating、拖放、CalendarPicker、视频 surface、tooltip、RichEditor、分栏容器与侧栏、PC 多窗。

新组件一律遵守 sdk.rs 冻结三关：Plain Data、host 值级测试、no_std 零分配。

结构性结论：BerryUI 的语义树与显式安全区、断点纪律已比三端更统一；最大缺口不是组件数量，而是 overlay 覆盖层——Dialog、Menu、Toast、Sheet 四类全部被它卡住，应作为 P0 引擎项排进 F 系列规格。
