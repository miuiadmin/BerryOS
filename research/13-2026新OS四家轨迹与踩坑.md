## 1. 四家轨迹叙事

### 1.1 astrid（811c · 2026-02→11 · 多人 + Copilot 署名 · 存活）

- 节奏：2–3 月高峰（92/148）→ **4 月 11c** → 5 月起稳定 ~100/月至今；全程无 >7 天空窗。
- **4 月"低谷"实为深水攻坚**：当月 11 个 commit 全是 Layer 4/5 principal 隔离与能力/组执法（`feat(kernel,core): management IPC for agent lifecycle, quotas…`、`Layer 5 — capability/group enforcement`、`Layer 4 principal scoping`）——单 commit 重量高峰，非衰退（4 月 commit 语义抽样）。

## 2. 踩坑金矿（swift-os NOTES.md 实录，三坑全录）

1. **连续分配低区越界（mm 域）**：单页 PMM 分配低区有界，但**连续分配走全物理区**——EL1 栈/ELF staging/DMA 解引用返回的 PA 超 identity map 范围，与进程 TTBR0 用户 VA 重叠，`trap_return` 在 `0x80014000` fault。修法：连续分配同样受低区界，**宁可返回失败也不给不可达指针**；并写对抗性分配器测试（预留全部低帧复现越界、验证有界失败与精确边界成功）。
2. **errno ABI 断层（兼容层域）**：内核返回 `EADDRINUSE=98`，目标 newlib 头定义 `112`——nginx `-t` 认不出裸内核值，拒掉合法配置。修法：C/newlib bind shim 定向翻译 + `socketprobe bind-errno` 探针把「目标宏实际值」纳入对拍；**内核 errno 编号与原生 syscall 结果不变**（翻译只发生在 shim 层）。
3. **元数据写穿缺失（FS 域）**：`vfsChmod` 只改内存 VFS 节点，重挂载后私钥 `0600` 回退到创建模式。修法：写穿到 inode mode 字段后再更新 VFS 节点，I/O 失败返 EIO 而非假成功；两 boot 测试从「只查内容」扩为**同查 mode 0600/0700**。

## 3. 交叉发现

1. **「内核稳、外围热」是微内核普适规律**：astrid（kernel 869 vs capsule 1396）、Veda（kernel 541 vs libraries 2017）两家独立实证——与 BerryOS 现状同构，可作架构健康正向指标。
2. **commit 频率 ≠ 健康度**：astrid 4 月 11c 是深水攻坚；TrustOS 2 月 170c 是死亡前高峰——语义重量 > 数量。
3. **单人项目三种命运**：死亡（TrustOS：多架构扩张 + 营销代偿）、转低频（swift-os：诚实收口）、转折中（Veda）。团队项目（astrid）穿越低谷。
4. **AI 辅助开发已是常态且署名化**：astrid 作者表 Copilot、TrustOS copilot-worktree、swift-os M0 scaffolding 内含 CLAUDE.md——BerryOS 的 AGENTS/门禁体系是同潮流的系统化形态。

## 4. 对 BerryOS 的教训映射

| 他们的坑 | BerryOS 对应域 | 既有防线 | 补强建议 |
|---|---|---|---|
| 连续分配低区越界 | `mm/` 连续物理分配 vs identity map 边界 | unsafe 全域 + 页表域规则（规则/02） | **对抗性分配器 ktest**：预留低帧复现越界形态（低成本高价值） |
| errno ABI 断层 | berry-sys/libc 兼容层 | abi-check 四面单源对拍（号位对拍，**非 errno 值域对拍**） | **errno 值域探针**：兼容层把目标 libc 宏实际值纳入对拍（shim 层翻译，内核值不动） |
| 元数据写穿缺失 | FAT 写路径 | `FAT写路径原子性评估` 已做 | 重挂载后 mode/权限回归测试形态（两 boot 同查内容+权限） |
| 多架构扩张死亡 | x86_64 线 | **冻结常量纪律**：x86_64 只做最小集兼容验收——TrustOS 反证该纪律正确 | 保持；警惕任何"顺手铺第三架构"提议 |
| 营销代偿期 | — | — | 自警信号：README/宣传类 commit 密度上升 = 主线热情衰减的先行指标 |
| 深水沉默期 | G 线/S 线 | `docs/阶段沿革.md` 流水 | 深水期以沿革记录进度，不以 commit 频率自评健康 |

## 5. 结论

四家没有一家复制 BerryOS 的「系统级门禁 + 决策留痕」开发方式（他们的踩坑记录形态是散落日志或 commit message，BerryOS 是雷册判例库三处一动）。三个工程坑（分配器越界/errno 断层/写穿缺失）BerryOS 都有对应域，其中 **errno 值域探针与对抗性分配器测试是低成本高价值的直接补强**（已入 12 号吸收路线图 P1 池，建议随对应域下一刀落地）。单人项目死亡模式（多架构扩张 + 营销代偿）反向验证了 BerryOS 冻结常量与最小集纪律的工程正确性。
