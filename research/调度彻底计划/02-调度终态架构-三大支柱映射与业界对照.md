## 0. 一页结论

1. **调度终态 = 四层框架，不是四套调度器**：机制内核（冻结面）/ 注入面（窄腰 ABI）/ 策略面（可插拔全谱）/ 观测面（host 钉板横切）——前三层在册（白皮书 §2 四层图与本文 §3 同构），第四层（观测面外迁）是 W3 外迁族的终态方向，且与业界同向：Zircon 已把调度核心拆成 environment-agnostic 的 `libsched`（内核外可测试 + fuzzer，一手核验见 §1.3），BerryOS 的 W3-Q53 `berry-ringface`（runqueue 侵入式环接线律单源 + host 14 测）与之同构。
2. **三大支柱共用一条机制链**：class 链 rt > deadline（EDF）> fair（EEVDF）> idle + 三槽 RCU 策略表 + EM 能量表 + intent 查表键——支柱差异全部落在「表的参数」（IntentProfile 按设备档位选表）与「表的来源」（advisor/AI/角色表/启动配置）上，不落在机制分叉上。这是 capacity 抽象（`docs/调度器设计-v1.1.md:63-69`：一条路径三端通用）与 intent=查表键（ADR #42 第一段零新层级）的必然推论，业界对照后仍然站得住（§2 总判词）。
3. **业界五家终态判读**：Linux 从「一个公平算法」走向「EEVDF 底座 + sched_ext 生态」双轨（sched_ext 生态 2026 年已 12k 行级项目在跑、ABI 明示无稳定性保证）；Zircon 缩编后收敛为单一带宽模型（firm 保底 + flexible 分剩余，2024 版权一手核验）；QNX APS 是分区预算的量产活证（client-pays 消息记账 + 满载正确性目标，7.1 文档 2026-03 仍在更新）；Zephyr 证明可插拔的正确位置是就绪队列数据结构（编译期三选一）而非策略；Android 的真终态在 framework 层后台治理（freezer/lmkd/hibernation/内存守护族），内核算法面与主线 Linux 同源。
4. **AI 支柱的诚实终态**：ADR #21 修订（2026-10-16 D5）已把 AI 从「身份支柱」降级为「机制预留 + 遥测优先实验轨道 + kill criteria」（`docs/AI调度设计-v1.0.md:11`）；任务书的「三大身份支柱」措辞与现行 ADR 的张力如实记录、归主会话拍板。业界 2026 证据支持 BerryOS 形态：LAVD 的 criticality 推断（唤醒 × 等待 / 运行时长）已量产化且将部分回上游 EEVDF，其「eventual enforcement（贵记账移出热路径）」与 BerryOS 慢循环/事件驱动记账同构（§1.1）。
5. **v2 工业 RT 是第四支柱候补，不是新机制**：QNX 血统的分区终态 = band（intent 键 CBS 包络）+ RT 静态池 + admission（ΣU ≤ 0.95 显式含 band 项）三件已在册立缝；APS 与 band 的真正差异只有「分区对象化（动态成员/继承树）」，v2 若需硬隔离再升格，键位（`Process.band_id` 记账）已预留（§2.4）。
6. **先进性对账**：七件「现在立缝」全部已在册（trait 冻结/intent 编码冻结/EM 表形状/观测面外迁/绝对截止时间重编程/单比较器/三槽 RCU+shadow 双轨——最后一件是四业界参照的空白，白皮书 §10 对标表）；三件渐进各有 kill criteria 在册（EAS 选核算法随真机/band 执法凭入场券/AI 学习策略 v4+），与业界节奏一致而非落后。本件新钉两条「缝要现在留」：EEVDF 睡眠任务的 lag 衰减语义（Linux 用 deferred dequeue + VRT 衰减防作弊，BerryOS 在册文档无对应条款——建议补决策位）与 util 信号的跨核迁移组合语义（Linux PELT 可组合、BerryOS per-CPU EWMA 不可组合——band/均衡维度化前补决策位）（§4）。

## 1. 业界终态对照（一手核验）

每家四问：机制精髓 / 适用前提 / BerryOS 已取 / 未取。外部断言给 URL；仓内引用给路径+行号。

### 1.1 Linux：EEVDF 底座 + sched_ext 生态双轨

**机制精髓**（一手：kernel.org 文档四篇 + LWN 两篇，见 §5）。其一，EEVDF 自 6.6 合入后成为 fair 类唯一主线：lag ≥ 0 才 eligible、eligible 内选最早虚拟截止期（VD）；睡眠任务的 lag 用「deferred dequeue + 基于虚拟运行时间的衰减（VRT）」处理，防止任务靠短睡重置负 lag 作弊；`sched_setattr()` 允许任务请求自定义时间片——短片即天然获得更早 VD，latency-nice 语义经此兑现（EEVDF 官方文档，docs.kernel.org/scheduler/sched-eevdf.html）。其二，EAS（能效调度）只在非对称拓扑启用（对称 SMP 明示不支持）：能量模型（EM）由独立框架维护、调度器只读；唤醒时 `find_energy_efficient_cpu()` 用 `compute_energy()` 模拟迁移前后总能耗择优；任一核超最高容量 80% 即整域 overutilized、EAS 退场负载均衡回归；且「唯一合理的搭档 governor 是 schedutil」（能量预测与频率请求一致性要求，docs.kernel.org/scheduler/sched-energy.html）。其三，schedutil 的信号栈：PELT 是 y^32 = 0.5 的 EWMA（最近 32ms 贡献一半）且**数学上可组合**（ewma(A)+ewma(B)=ewma(A+B)，任务迁移时可重合成）；util_est 出队时锁峰防 DVFS 回落；uclamp 聚合；目标频率公式 `f = min(f_max, 1.25·u·f_max)` 留 25% 余量（docs.kernel.org/scheduler/schedutil.html）。其四，sched_ext：BPF 程序集实现调度器、DSQ（全局/每核/自定义）队列模型、任何错误或 runnable 停滞即整核回退 fair 类、**ABI 明示无稳定性保证**（docs.kernel.org/scheduler/sched-ext.html）。其五，2026 年生态：LAVD（sched_ext 系最著名者）已从游戏扩展到服务器（42 名开发者 900+ 提交约 12000 行，单源 LWN）——核心 heuristic：criticality ∝ 等待频率 × 唤醒频率 / 平均运行时长，且 criticality 可继承（向它阻塞的与阻塞它的两个方向传播）；截止期除以 criticality（越关键越提前）；锁持有者永不抢占；不用 IPI 强抢而是缩短目标时间片让其自然让出；per-L3 域一个派发队列；「turbulent/steady CPU」分类放置；启动时把 EM 分析成「负载级 → 该用哪些核」查表；cgroup 限制走 eventual enforcement（不做单期节流、让长期均值平衡，贵记账移出调度关键路径）；未来方向 GPU 调度（LWN 1097209，2026-10-07）。

**适用前提**：GPL 宏内核（策略进内核合法）；BPF/verifier/JIT 整套基建；EAS 依赖 DT/OPP 注册的 EM 与 schedutil 独占搭配；生态侧靠上游主线承诺与 LWN 级公开评审兜底。

**BerryOS 已取**：EEVDF 语义自研落 fair 类（`docs/调度器架构白皮书-v1.0.md:50`，与 6.6+ 同代语义）；EM 表形状同 Linux 口径（kHz/mW/capacity 三元组、容量 1024 同尺度，`docs/调度器设计-v1.1.md:341`）；overutilized 80% 门控（阈 819 = 域最高容量 80%，`docs/调度器设计-v1.1.md:358-363`）+ 机会主义纪律（超载即退化普通负载均衡，与 Linux 同款，`docs/调度器设计-v1.1.md:329`）；util EWMA 作 PM 调频信号（schedutil 同构 `f ≈ util × fmax / capacity`，但**调度路径零频率写点、裁决单点归 PM 服务**，`docs/调度器设计-v1.1.md:355`——这是比 Linux 更激进的机制/策略切分）；sched_ext 的契约面（有界动作集 + 失效回退 + 热切换思想）经 SCHED-01 裁决「借契约不借实现」吸收（`research/SCHED-01-调度之王业界深研与综合裁决-v1.0.md:3`）。

**未取**：BPF 载体本身（no_std 无 verifier/watchdog 二路径问题，SCHED-01:3）；PELT 的可组合性（BerryOS util 是 per-CPU 不可组合 EWMA——任务跨核迁移后新核需重学，【推断】该差异在 2 核档影响有限、4 核+ 与 band 维度化时需语义决策，见 §4-9）；EEVDF 睡眠 lag 的 deferred dequeue/VRT 衰减（BerryOS 在册文档未见对应条款，见 §4-8）；EAS 的对称拓扑明示禁用条款（BerryOS 用 capacity 全等即退化 no-op 的同构表达，无禁用条款——语义等价但少了「何时该关」的文档化判据，【推断】可在 EAS 文档补「对称域自动失效」一句）；1.25 频率余量与 IO-wait boost（PM governor 的参数域，v3 随 M3 落）。

### 1.2 Android：内核同源 Linux，真终态在 framework 后台治理

**机制精髓**（一手：source.android.com 2026-11 实拍）。内核面 EAS 与主线 Linux 同源演进（内核文档见 §1.1，Android 侧无独立算法文档——`source.android.com/docs/core/perf/eas` 已 404，EAS 专页在 AOSP 文档重组中移除，【事实】）。Android 的差异化终态在 framework/daemon 层后台治理族：cgroup 抽象层（`/docs/core/perf/cgroups`）、cached apps freezer（冻结缓存应用省电）、lmkd（低内存杀）、app hibernation（休眠未用应用）、memory limiter、system memory budgets、process memory guardian daemon（PMGD）、memory management daemon（MMD）、NPU manager——2026 年 AOSP 性能目录在册的完整清单（source.android.com/docs/core/perf 实拍目录）。TopHat（任务书点名）：官方文档路径 404（`/docs/core/perf/tophat`、`/docs/core/perf/tophat-scheduler?hl=en` 均不存在）、android-mainline 内核树 `kernel/sched/` 目录无 tophat 文件、全树 grep "tophat" 零命中（android.googlesource.com 实拍）——**【未证实】**：仅能确认其未进 AOSP 主线内核与官方文档面，「Android 17 轻量调度器实验」之说不可作论据。

**适用前提**：Google Play 治理权 + GKI（通用内核镜像）约束下厂商只能 hook 不能 fork；十亿级设备的遥测与 A/B 基建。

**BerryOS 已取**：后台限制的思想经应用模型线承接——freeze 原语（token 化、上限 64、嵌套，`docs/调度器架构白皮书-v1.0.md:50`）已是墓碑前一档（调点 D12，`docs/调点调度-v1.1.md:666-684`）且 freeze-first 消费位已落（ADR #42 追记 2026-11-08，tomb_selftest）；intent 六档分带与 Android cgroup 分带同构（ADR #42 四路量产证据之一，`docs/架构决策.md:51`）；「应用 hint、系统仲裁」共同答案（SCHED-01:7）。

**未取**：framework 层 app standby buckets/电池白名单类治理面（归应用规范线与 appd，调度面只供 intent/freeze 原语）；cgroup freezer 形态本身（BerryOS freeze 是 handle/token 原语非 cgroup——Zircon task_suspend token 判例更干净，SCHED-01:12）；cached-apps-freezer 的「缓存进程冻结」产品语义（freeze 原语之上的策略，归 appd）。

### 1.3 Zircon：单一带宽模型 + host 可测核心（缩编后的收敛）

**机制精髓**（一手：fuchsia.googlesource.com 主线 2026-11 实拍）。新调度核心 `zircon/kernel/lib/sched`（README 版权 2024）：① **单一带宽模型**——每线程一个 activation period（周期），期内工作量分 firm（firm capacity，期内保证）与 flexible（flexible weight，按权重分剩余带宽、由 firm 利用率因子缩放）两部分；被阻塞线程在当期内**保留 firm demand**（快速解锁不挨罚，期过才释放）；② **选线程**——恒选「最早完成时间」者，平手取更早开始时间，再平手取地址（不应跨次持存的微小偏置）；③ **抢占时点** = min(当前线程期结束、当前线程容量耗尽、会更早完成的候选线程开始时间、最早被阻塞 firm demand 释放点) 四项；④ **WAVL 树**（`fbl::WAVLTree` + `WAVLTreeBestNodeObserver` 子树最小值观察者）承载就绪队列，键 = (start time, 线程地址)；⑤ **environment-agnostic**——「首要目标是内核调度，但刻意保持环境无关以便在非内核测试环境演练」，配 run-queue-fuzzer 与全套 host 测试（libsched README + run-queue.h 一手）。

**适用前提**：微内核（策略不入内核，无 policy service 概念）；对象/能力体系承载 profile；缩编后小团队维护——从 fair+deadline 两类收敛为单一带宽模型，是人力约束下「一个模型管全部」的设计（因果【推断】：收敛形态与团队规模缩编的时间耦合，未有一手自述佐证）。

**BerryOS 已取**：host 钉板测试面同构（W3 外迁族把判序/形状纯函数外迁 host 测试，Q53 `berry-ringface` runqueue 接线律单源 + host 14 测，git `5b8e8af8` 在册——与 libsched 的 environment-agnostic 理念同构，殊途同归）；单比较器纪律（每类单一排序键、选任务与抢占检查同源，`docs/调度器架构白皮书-v1.0.md:50`——与 libsched「earliest finish time 单键」同构）；blocked 保留 demand 的思想在 BerryOS 的对应物是「intent 借入 reply 即回退 + 每消息重导」（`docs/调度器设计-v1.1.md:87`），语义近似但机制不同。

**未取**：firm/flexible 统一带宽模型——BerryOS 是 class 链（deadline 类 ≈ firm 的 OS 级形态、fair 类 ≈ flexible 的加权形态）+ band 层级，数学上可映射但结构上分立（【推断】等价表述：Zircon 把两类焊进一个 RunQueue、BerryOS 用两层拓扑表达——BerryOS 形态对「RT 屏蔽 AI」「带间严格序」这类治理不变量更可执法）；WAVL+子树观察者数据结构（BerryOS 侵入式环 + EEVDF 段扫描 + O(1) 增量账本，`docs/调度器设计-v1.1.md:397-401`——已把扫描量压到 O(n)，结构不同性能同量级）；Zircon 缩编的元教训（策略面越薄越经得起人力波动）反过来印证 BerryOS 机制/策略分离的中心（`docs/架构综合纲领.md:55-64`）。

### 1.4 QNX：APS 分区——v2 工业 RT 路线的血统源

**机制精髓**（一手：QNX SDP 7.1 文档实拍，页脚「Page updated: March 12, 2026」）。Adaptive Partitioning（APS）是**可选线程调度器**：按分区保证 CPU 吞吐的最低百分比（budget），设计目标是两件事——满载条件下仍正确运转 + 防不重要/不可信应用垄断系统。「adaptive」指分区成员动态：可动态把应用启动进分区；子线程/子进程自动继承创建者的分区；**默认情况下 send-receive-reply 消息的接收方在处理该消息期间跑在发送方的分区里**——驱动/文件系统等资源管理器自动把 CPU 时间（不含开销）记到客户端账上；控制面 = `aps` 命令行工具或 `SchedCtl()`，另有独立的分区安全页与调试页（APS User's Guide，Thread Scheduler Details 节一手）。SCHED-01 附录 A 的在册裁决维持：QNX 8.0 是否整体移除 APS 仍【未证实】（我方 8.0 文档路径 404 无法核，7.1 文档 2026-03 仍在更新是活证）；APS 的死因判例（策略焊进热路径、每次决策扫全部分区、分区硬上限 8）与活面（窗口/借用/偿还语义）沿用 SCHED-01:10 的两分。

**适用前提**：消息传递架构（client-pays 记账依赖 send-receive-reply 的同步语义）；宏内核 RTOS；SMP；安全/认证驱动的工业场景。

**BerryOS 已取**：QNX 三件套照搬（只在竞争时执行 / 空闲预算 loan / 整数微记账 16×16 缩放，`docs/调度器设计-v1.1.md:136`）；client-pays 记账（intent 随消息传播「账记客户端」，`docs/调度器设计-v1.1.md:87`）；预算包络词汇表对齐但「只借词汇、不借结构」（`docs/AI调度设计-v1.0.md:86`——APS 把策略焊进调度热路径而被作者亲手砍掉的判例是 BerryOS 快慢分离的反面教材，同文件 :76）。

**未取**：分区对象化（动态成员树/继承/命名分区为一等 OS 对象）——BerryOS band 的键是 `intent_effective` + `Process.band_id` 记账（`docs/调度器设计-v1.1.md:371`），非对象；`SchedCtl()` 式 per-process 控制 API；分区安全页对应的「分区权限模型」（BerryOS 用 Job 级 SET_POLICY handle 承接，能力而非分区）。v2 工业路线的升格差异详见 §2.4。

### 1.5 Zephyr：可插拔的正确位置——数据结构而非策略

**机制精髓**（一手：docs.zephyrproject.org latest 实拍，2026-11-12 生成）。调度算法本体固定（静态优先级 + 同优先级 FIFO + 抢占/协作两态 + 可选时间片），**可插拔的是就绪队列数据结构**，编译期 Kconfig 三选一：`SCHED_SIMPLE`（无序链表，常数极小省约 2KB 代码，适合 ≤3 个就绪线程）、`SCHED_SCALABLE`（红黑树，干净扩展到数千线程）、`SCHED_MULTIQ`（每优先级一链的教科书多级队列，O(1) 但 RAM 大且与 deadline 排序/SMP 亲和不兼容）；wait_q 抽象与调度器共享同一套后端选择；`CONFIG_SCHED_DEADLINE` 在同静态优先级内按 EDF 排序；per-thread 时间片 + 到期回调（中断上下文里可调优先级/再切片/挂起）。

**适用前提**：MCU 资源约束（代码尺寸/ RAM 以 KB 计）；静态系统（编译期已知线程集）；安全认证场景。

**BerryOS 已取**：「形状先行、实现后补」的同构纪律（EM 表形状先落算法留 M2/真机——ADR #53 砍实现不砍协议位，`docs/调度器设计-v1.1.md:329`）；表示法纪律（数据结构先定形、字段进 TCB，`docs/调度器设计-v1.1.md:139`）。

**未取**：编译期三选一形态本身——BerryOS 的插拔轴是**运行时策略数据**（三槽 RCU 换表、空表等价接口缺席），比 Zephyr 的编译期队列算法选择更强：换表不换内核、不重编译、不重启；MCU 档整体被身份排除（Curia 迁移前 AGENTS 身份节：「穿戴同族可落，MCU 档排除」，git `725e5554` 直核）——BerryOS 因此不必做代码尺寸级裁剪终态。

## 2. 三大支柱终态映射

总判词先行：**三大支柱不是三套机制，是同一机制链的三组参数来源**。省电 = IntentProfile 表 + EM 表 + PM governor（表的内容偏能效）；AI 原生 = advisor/AI 实验轨道（表的生成器更聪明）；PC 高性能 = capacity 全等拓扑 + spread 偷取 + 管家核（表的适用域与消费点不同）。任何「为某支柱加一条机制分叉」的提案都过排除 8 问第 1 问（轴 + PICK，`docs/架构综合纲领.md:133`）。

### 2.1 省电：tickless 全谱 + PM 三期后 + em 模块终态

**tickless 全谱（内核面，已立法）**：第一层 tickless idle（runqueue 空不收周期中断，M1a 已落）；第二层**绝对截止时间重编程纪律**（定时器永远编程到绝对到期时刻、以硬件计数器现读重算，绝不「上次值 + 周期」外推——FreeRTOS 停止-补偿法自认漂移是反面，`docs/调度器设计-v1.1.md:162`）；第三层深睡三件套（超时任务冻结 / 唤醒延迟预扣 exit_latency / latency QoS 排除过深档位，v2+ 设计位，`docs/调度器设计-v1.1.md:167`）；第四层 PM 三期立法（ADR #66-68：L1 berry-thermal 边界 / L2 挂起停钟 + SLEPT 双钟 / L3 KC-P1..P5 + 豁免位 + SDK 六面契约，`docs/架构决策.md:3` 头注在册）。终态图景：空闲谱系（WFI → 深睡）的档位选择全部归 PM 服务（用户态策略），调度器只供给 util 信号与唤醒事件、绝不写频率（`docs/调度器设计-v1.1.md:355` 红线）。

**em 模块的终态**：形状已冻结（`EmPoint{freq_khz, power_mw, capacity}` 三元组、每域 ≤4 点严格升序、域 ≤2、capacity 与 Topo 同尺度 1024），QEMU virt 默认表在册，真机 DT/OPP 解析后整表覆盖重注册走同通路（「填充路径今日即明日」，`docs/调度器设计-v1.1.md:339-346`）。终态判词：**em 是数据面不是算法面**——compute_energy/FEuC 选核算法随 M2 与真机落地（白皮书路线图，`docs/调度器架构白皮书-v1.0.md:108`），届时 BerryOS 的 EAS 放置形态 = placement 三值 hint（无意见/偏小核/偏大核）+ overutilized 门控 + 能量比较三件的组合，与 Linux `find_energy_efficient_cpu()` 的差异只在：Linux 把算法焊在内核唤醒路径、BerryOS 的算法可以（且应该）先在用户态 advisor 影子轨道上跑，赢过零假设再 PROMOTE 进放置列——这正是「EAS 式能效放置在 BerryOS 的形态」的答案：**算法可插拔、能量表冻结、门控机会主义**。

**省电支柱的机制清单收口**：timer 原语 slack+policy 三元组（唤醒合并的第二杠杆，`docs/调度器设计-v1.1.md:155`）+ intent 的 timer_slack 列（LC=0 exact 逃生舱 day-one）+ slice 周期数记账（DVFS 上线后时间片不随频率漂移，`docs/调度器设计-v1.1.md:77`）——三件都是「省电与调度在机制层汇合」的既定缝；其中 timer slack 是**已承诺未落码**的硬缺口（01 号 §1.2 对账：`grep slack kernel/src/ sched/src/` 零命中，设计 v1.1 L155 需改口或补刀），省电支柱定稿时必须显式清偿。现状接缝同步（01 号总判）：PM 研究三期收官而 **berry-power 服务实体未建**、util EWMA 信号暂无消费者（「调度-PM 契约空转」）——终态图里 PM governor 是承重墙、现状里它还是图纸，这是省电支柱最大的单件欠账。

### 2.2 AI 原生：intent 第二段 M4 + 带 ×4 + policy_bind v3 + 实验轨道

**措辞张力（如实记录）**：任务书与 AGENTS 身份节（Curia 迁移前版）把「AI 原生调度」列为身份支柱；ADR #21 修订（2026-10-16 D5）已将其降级为「机制预留 + 遥测优先的实验轨道 + kill criteria」，理由是端侧学习型调度零确证生产先例 + ghOSt 迁往 in-kernel BPF 的自我否定（`docs/AI调度设计-v1.0.md:11`）。本件按 ADR 现行法写作：**AI 支柱的终态 = 机制在位 + 轨道在跑 + 判据在册，AI 本身可被 kill 而支柱不塌**——接口保留、遥测优先、A/B 判定可撤，这恰是「一开始做最好」的正确形态：后悔药（kill criteria）也是 day-one 设计的一部分。

**终态四件套**：① **intent 第二段（M4/v3）**——class_fair 按 intent 实例化 ×4 带（0x01 LC/0x02 交互/0x03 工具/0x04 后台；0x05 维护编码冻结不启用）+ 带间严格序 + 每带预算包络 + deadline-server 式兜底，凭 v1 遥测入场券入场，「扁平 EEVDF + latency-nice 是 band 必须打败的零假设，证据不足则查表键即终态」（ADR #42，`docs/调度器设计-v1.1.md:133-139`）；② **注入面门控两段态**——现行已落 RIGHT_MANAGE 三门控（0x83 auth 参数改 Process handle + RIGHT_MANAGE，安全修复六十五轮，负例 H8-H11 在册），Job 级 SET_POLICY handle 语义仍挂 v2（01 号 §1.4 对账：v1.2 §10 设想的 Job 级形态被 RIGHT_MANAGE 形先行落，不同形）；telemetry_open 映射 v3（`docs/AI调度设计-v1.0.md:128`）；③ **实验轨道闭环**——SHADOW_COMMIT 起双轨 → 负载累积对账 → policy_ab_eval 判定（<0.1 转正 / >0.5 降级 / 其间 HOLD）→ PROMOTE/DEMOTE，判定线与 ADR #21 kill criteria 同源（`docs/调度器设计-v1.1.md:307-318`）；④ **动作空间四类封顶**（放置/频率热限 hint/包络内权重/EPP 二值，没有第五类；band/intent 不入动作空间——ADR #21 修订 + #42）。

**业界 2026 对照的新证据**：LAVD 量产化验证了「唤醒/等待信号推断」路线——BerryOS (B) 分类器的 LAVD 式推断（`docs/AI调度设计-v1.0.md:108`，lat_cri 同构）不再是实验性押注；LAVD 的 criticality 继承（向被阻塞者与阻塞者双向传播）与 BerryOS PI × intent 联动（`docs/调度器设计-v1.1.md:87`）同构但 BerryOS 有每跳预算帽 50ms + 累计封顶 400ms 的界——比 LAVD 更可审计；LAVD eventual enforcement（账移出热路径）与 BerryOS 事件驱动记账 + 慢循环重算同构。**差异判词**：LAVD 是 12k 行的 in-kernel BPF 单体，换策略 = 换内核态程序；BerryOS 是内核 716 行策略面（policy.rs，`wc -l` 实测）+ 宿主侧确定性 advisor——可测试性、可回退性、可审计性占优，代价是 expressiveness（BPF 能写任意数据结构）——但「动作空间四类封顶」的战略裁决本来就放弃了 expressiveness 换保守性，两者自洽。

**平台分层终态不变**（`docs/AI调度设计-v1.0.md:94-101`）：手表不上（单核近最优、模型能耗净负）、手机轻量 advisor、PC 完整 advisor 跑管家核 ~10ms。

### 2.3 PC 高性能：SMP 终态拓扑 + per-CPU runqueue + divergence + 吞吐

**SMP 终态拓扑（v1.4 蓝图在册，刀序现状 2/6 落）**：现行 2 核档——全局单策略表 + ACTIVE AtomicU32 全局发布 + gen 全局单调（GEN_NEXT 锁内 fetch_add，天然成立）；**per-CPU 读者快片 4 核+ 复议**；写者锁 4 核+ 反噬的 kill criteria = SMP 线冻结 2 核档并文档化（`docs/调度器SMP部署设计-v1.0.md:102-108`、:154-155）。刀序 SMPD-0..5 实况（01 号 §1.6/§2.2 对账，两源核验）：**SMPD-3 band 全局原子账 ✅**（1869412f：CONSUMED/DEADLINES 升 [AtomicU64;8]，fetch_add 单赢家 + CAS 防双翻；子项 nuance——lazy pick 执法未升，现行仍是 throttle_all 环扫置位，`sched/src/band.rs` L61-62 注记）；**SMPD-4 divergence per-CPU 分账 ✅**（078073be：DIVERGENCE/EVAL 从全局单 AtomicU64 → [CountSlot;2] per-CPU 64B 对齐）+ SMPD 双核终验 ✅（60 ok）；**SMPD-0 ⬜**（唯一硬阻塞 = X-6 刀① 0x24 表批 SMP soak 楔死 fix-or-withdraw 待裁）；**SMPD-1/2/5 ⬜**（SMPBENCH/POLICY-S/公平性验收 + CI 议程——代码零命中）。SMP 三虫（vruntime 账本 RMW/dpg_press 降软/REAPQ 容量）已全根治（01 号 §1.6：沿革一百八十七/一百八十八/一百九十）。

**per-CPU runqueue 终态**：`PER_CPU_RQ:[Runqueue;2]` + wake 路由（归属核直路：服务根恒家核防协议断供、计算线程 spread=true 直路副核）+ 偷取判据「本核近空闲 len ≤1 且对核显著更重、只偷 spread=true」+ SLEEPQ 归属核单点武装（迟醒界 ≤1 slice）（`docs/调度器SMP部署设计-v1.0.md:95-101`）。EEVDF lag 有界跨核成立进公平性验收（per-thread lag 排序不因核数发散，:136-137）。

**divergence 终态（已落）**：对账计数 per-CPU 分账（每核写本核槽、64B 对齐防伪共享——HDR CpuHdr 同款纪律）+ 读时合并（分子分母同源合并、Σ 恒立对拍）+ 轨道切换两槽同批置零（POLICY_LOCK 窗内原子）（`docs/调度器SMP部署设计-v1.0.md:115-122`，SMPD-4 落地 078073be）——「写方限本核零争用」是 BerryOS 观测面纪律在策略对账面的复用。

**吞吐类终态**：PC 表追加 capacity 放置 hint 列（v2+，`docs/调度器设计-v1.1.md:128`）；管家核（housekeeping core）承载完整 advisor（`docs/AI调度设计-v1.0.md:100`）——**本件建议**在 Topo/capacity 表立「reserved core」缝（§4-10）；并发路线已双立法——否决 BKL（细粒度锁 + 全可抢占分阶段 + lockdep，ADR #69）与 async 内核（维持全同步 no_std，ADR #70，`docs/架构决策.md:77-78`）；热路径现行基线 **pick = 26 周期 / freeze = 5 / billing = 1 / 公平 spread = 0**（`tools/sched_baseline.json` git tracked，七十六轮全量重测口径；01 号 §1.1 对账：白皮书/设计 v1.1 的 21cy 是 11-08 时点数，SLEEPQ per-key 后全量重测 22→26，归因同键链初始化 +4cy——外宣数字待升版刷新）。

### 2.4 +v2 工业 RT：APS 分区 + EDF——QNX 血统的 BerryOS 形态

**已立缝三件**（无需新机制）：① RT 路径静态池（RT/deadline 任务 TCB/runqueue 节点/消息缓冲走构造期预算分配的静态池，INTEGRITY-178「内核零动态分配」模式；分配器留内核服务 fair——静态池是旁路不是替换，`docs/调度器设计-v1.1.md:90-94`）；② admission control（EDF + budget/period + 预算执法 + ΣU ≤ 0.95 准入，且 admission 公式显式含 band 预算项否则 deadline 满额时兜底必违约，M5 补写，`docs/调度器设计-v1.1.md:203`）；③ APS 三件套 + client-pays（§1.4 已列）。freeze_clock 默认 PAUSE、RT/deadline 显式 CONTINUE（调点 D9，`docs/调点调度-v1.1.md:666-684`）——工业场景的时钟语义已裁。

**终态升格路径（v2 若需硬分区隔离）**：band（intent 键 CBS 包络；全局原子账已随 SMPD-3 升——1869412f，lazy pick 执法子项未升、现行 throttle_all 环扫，`sched/src/band.rs` L61-62 注记）→ 分区对象化（动态成员/继承树/命名分区）——差异清单收口：APS 有而 band 无的只有「分区是一等 OS 对象」这一件；band 有而 APS 无的是「不焊热路径 + AI 不可触 + 入场券纪律」。键位已预留：`Process.band_id` 记账（sched 不反向依赖内核的 crate 边界纪律，`docs/调度器设计-v1.1.md:371`）。判词：**BerryOS 的分区终态 = band 的对象化升格，不是 APS 的移植**——QNX 血统取的是词汇（预算包络/竞争时执行/loan/整数记账）与记账模式（client-pays），结构上把 APS 的死因（策略焊热路径）从设计里剔除（SCHED-01:10 判例 + `docs/AI调度设计-v1.0.md:86`）。

```text
│   · Job 级 SET_POLICY（v2）/ freeze token / timer slack / bootparams    │
├────────────────────────────────────────────────────────────────────┤
│ ① 机制内核（EL1，冻结面——SchedClass trait 签名一字不改）               │
│   class 链：rt > deadline(EDF+ΣU≤0.95) > fair(EEVDF×N 带) > idle     │
│   三槽 RCU 快照 + shadow 双轨 + divergence / hazard-lite / 写者锁    │
│   band CBS 8 槽（默认全关）/ freeze / PI 捐赠 + intent 随消息传播      │
│   tickless（绝对截止期重编程）/ capacity 拓扑 / EM 表 / util EWMA     │
│   per-CPU runqueue + 偷取 + SGI / HDR per-CPU 双路                    │
├────────────────────────────────────────────────────────────────────┤
│ ⓪ 观测面（横切全层，host 钉板终态——W3 *face 族把判序/形状纯函数外迁）  │
│   telemetry 切换/唤醒双环 · HDR 897 桶 · per-app stats 查询面         │
│   五仪表盘（advisor/policy_ab_eval/sched_perf_analyze/starvation_    │
│   check/sched_dashboard）· *face 纯函数 host 单测（ringface/wakeface…）│
│   口径纪律：QEMU 趋势 → 真机分位（p50/p99/p99.9 门禁随 RM 线）          │
└────────────────────────────────────────────────────────────────────┘
```

四层判词：**机制内核是冻结面**（trait 签名 + class 链 + 原语集，业界五家对照后无一件需要返工）；**注入面是窄腰**（全部策略经数据表/声明进内核，无第二语义域——#58 单一词汇表的立法精神）；**策略面全谱可插拔且可崩**（与 PM 同级同模式，ADR #21/#28 降级保活）；**观测面是终态增量**——W3 外迁族（Q47-Q59：pi/ringface/waitobj/dpg fastpath 等调度纯面 host 钉板化，git 在册 Q53/Q55/Q59 等）把「内核调度逻辑只能在整机里测」的业界常态翻转为「判序单源 + host 单测 + 内核消费壳」，与 Zircon libsched 的 environment-agnostic 收敛同向（§1.3）——这是 BerryOS 在观测维度上的业界领先件，建议在终稿（本系列定稿文档）中与 shadow 双轨并列陈述。

### 4.2 缝要现在留（本件新钉，渐进实现但缝先立）

8. **EEVDF 睡眠任务的 lag 语义**：Linux 主线用 deferred dequeue + VRT 衰减防「短睡重置负 lag」作弊（EEVDF 官方文档，§1.1 一手）；BerryOS 在册文档（设计 v1.1/白皮书/调点系列）未见对应条款【事实核：全文无 deferred dequeue/衰减表述】。建议：在 v1.4/真机相给 fair 类补「睡眠任务 lag 处理」决策位（三选：入队即衰减 / 保留 / 完全重置——各自作弊面与公平面写清），不需要现在实现，但要在设计文档立法占位，防实现时随手选了可作弊档。标注：本行为本件建议，非在册裁决。
9. **util 信号的跨核迁移组合语义**：Linux PELT 数学可组合（ewma(A)+ewma(B)=ewma(A+B)，任务迁移重合成，§1.1 一手）；BerryOS util EWMA 是 per-CPU 不可组合（α=1/8 移位，`调度器设计-v1.1.md:348-356`）——任务迁到新核后该核 util 需重学。2 核档影响有限【推断】，但 SMPD-3 band 全局原子账与 M1b 均衡器 band 维度化都会读 util 做口径，建议在均衡器设计里补「迁移任务的 util 结转」决策位（选项：不结转/新窗起学/按 EM 容量比折算）。标注：本件建议。
10. **管家核（reserved core）的 Topo 缝**：PC 完整 advisor 跑管家核已在册（`AI调度设计-v1.0.md:100`），但 Topo/capacity 表无保留核字段——建议 v1.4 SMP 相给 Topo 立 reserved 标志位（housekeeping 中断/advisor 钉一个核、LB/偷取/放置全绕行），与 LAVD「turbulent/steady CPU」分类（§1.1 一手）同构但更彻底。标注：本件建议。
11. **工业 RT 的分区对象化键位**：`Process.band_id` 记账已是键（§2.4）；建议 v2 立法时只做「band → 分区对象」升格案（动态成员/继承树），不新开第二套分区机制——缝已天然在位（intent_effective + band_id 双键），本件仅确认无需预埋更多。

### 4.3 渐进（kill criteria 在册，不提前缴税）

- **EAS 选核算法**（compute_energy/FEuC）：随 M2 与真机；「形状在、算法留」+ placement 打不过零假设即退役（ADR #53 + 白皮书:108-109）。
- **band 执法并线**：入场券（过载尾延迟差/饥饿计数/整带功耗杠杆实测）不过则查表键即终态（`调度器设计-v1.1.md:137`、`调度器SMP部署设计-v1.0.md:160-163`）；SMPD-3 全局原子账先做、超卖窗上界进断言。
- **AI (A) 学习策略**：v4+；M4 kill criteria（可复现 A/B 无可测尾延迟/能耗收益 → 永久 hint-only）在册（ADR #21 修订）。
- **4 核+ SMP**：per-CPU 读者快照 + 写者锁形态复议；反噬则冻结 2 核档并文档化（`调度器SMP部署设计-v1.0.md:154-155`）。
- **深睡三件套 / berry-power 服务实体 + PM 共享环接线 / Job 级 SET_POLICY**：分别随 PM v2+/M3/Job 对象落（白皮书:111 治理面路线）；门控现状 = RIGHT_MANAGE 三门控已先行落（01 号 §1.4），Job 树语义挂 v2；berry-power 未建是「调度-PM 契约空转」接缝的本体（01 号三大接缝之二），定稿时须给服务实体一个刀位。
