### 2.3 桥数学复算——过，表达力边界如实钉板不藏

`pct_of_ma = ma×100_000/cap_uah`、`ma_of_pct = pct×cap_uah/100_000`（charge.rs:107-130），µAh↔mA 的 C 率基（1C = 设计容量数值 mA）量纲自洽（4800 mAh：pct_of_ma(2400)=50、ma_of_pct(50)=2400 恰还原，实跑测试钉板 charge.rs:391-392）；双向 floor ⇒ 往返只收紧（pct→ma→pct 全域 ≤ 原、mA→pct→mA 在 <1C 域 ≤ 原——本复核按不等式复推成立，host 性质测试 :405-441 六容量全域扫描钉板）；中间量 u64（`ma as u64 × …`），野容量上界不溢出（:397）。**表达力边界**：≥1C 电流 pct 面读 100=不限（C 率域上界即「不再限流」），超域往返放宽到哨兵——这是 #68 冻结形表达不了的域，恰为 F1 裁 mA 的实证面，测试显式钉板（:432-439）而非回避。`ChgErr::BadCap`（容量 0 无据拒，:77-78）与拒面零副作用（:351-373）齐。低电预充 2400mA=0.5C 与 dry-run 复算闭环见 §4。

## 3. slackface 判定律（复核面二）

### 3.1 三律正确性——过（独立复推）

设计承诺原文：§3.8 :155「timer 原语带 slack+policy 三元组（学 `zx_timer_set`，v1 day-one）」（[调度器设计-v1.2](../../docs/调度器设计-v1.2.md)——时点行号 :155 为 v1.1 文本位），01 号对账缺口 #9「代码零命中」（[01 号](01-调度现状全景与在途线收编.md) :30/:222）。落地面 = 判定律纯函数四件（`user/berry-slackface/src/lib.rs:34-63`）：slack 域六档映射/聚合分桶/三律/policy 三元组。本复核独立复推三律（不依赖落件者证明）：输入按 deadline 稳定排序（lib.rs:205）后贪心开桶，进桶判据 `d_j ≤ min_e`（:230）；归纳不变量 **`max_d ≤ min_e`** 恒成立——开桶时 `max_d = d_0 ≤ d_0+s_0 = min_e`，入桶者 `end_j = d_j+s_j ≥ d_j ≥ max_d`（扫描序保证 d_j 非降）且 `d_j ≤ min_e`（判据），故 `min_e' = min(min_e, end_j) ≥ max_d' = max(max_d, d_j)`。于是 `fire = max(max_d, floor_align(min_e, grid))`（:218）落在 `[max_d, min_e]`：L1（fire ≥ max_d ≥ ∀d_i，永不提前）与 L2（fire ≤ min_e ≤ ∀(d_i+s_i)，不越任何成员预算）无条件成立；L3（fire − d_first ≤ min_e − d_first ≤ s_first，桶跨度有界、松弛按原始锚点计）随之。网格对齐只降不升、落穿 `max_d` 钳回（律赢于对齐）与 :218 一致。`laws_hold`（:264-289）把三律做成可复用断言面，host 测试逐桶对拍。边界拒面：往昔锚点（deadline < now）/预算 u64 溢出整批拒 `None`（:196-201，测试 :570-591 含 d==now 闭边界与 u64::MAX 恰点），空输入 = 合法平凡件。

### 3.2 与设计 §3.8 和 Linux 的对照——过，边界诚实

**对 §3.8 的兑现范围**：slack 域映射 =「intent 的 timer_slack_ns 列的执行载体」语义面（LC=0 exact 逃生舱 = §3.8 :126/:146 冻结语义，lib.rs:89-91）；coalesce 分桶 =「唤醒合并（省电第二杠杆）的内核机制」的判定律面。**未落面如实记**：`zx_timer_set` 形三元组（deadline, slack_amount, slack_policy）的 syscall/ABI 面（lib.rs:10-13/:299-302 自注「同语义异形，接线窗定 ABI」）、内核定时器路径落线、bootparams 第三键解析——kernel/src 与 sched/src grep `slack` 本轮后仍零命中（实测）。判定：判定律纯面对 §3.8 的语义承诺成立且可测，但「v1 day-one」承诺的机制面未清偿——[调度彻底计划](../../docs/调度彻底计划-v1.0.md) 裁十债一（:82）/CP-11（:107）仍开，本件是其单源先导（「查表键先于消费者落地」同款纪律，先例 sched/src/intent.rs:5 在册）。落件者笔记与 crate 头注均如此口径，无虚报。
**Linux 对照五条**（lib.rs:22-29，落件者标「man7 PR_SET_TIMERSLACK(2const)，2026-11 取证」）：①每线程 default/current 双值、init 缺省 50000ns；②「只迟不早」（never expire early）；③分组动因 = minimizing CPU wake-ups；④RT 线程免 slack；⑤fork 继承/execve 保留——按本复核知识面五条均与 man7 该页一致；L1 late-only 同构、LC=0 与 RT 免 slack 同位成立。CENTER 形（±双向，Zircon 有）裁留窗、取 LATE 单形的理由（双向放大最紧成员违 L2 纯度）在笔记 Alternatives 记账——裁量合理。

### 3.3 交互零牺牲实证与聚合收益复算——过

零牺牲口径精确：L2 推论 = 桶醒点永不越任何成员**自身预算**（INT 成员钉桶于其 +10ms 内、LC 成员钉于 deadline 恰点）——不是「零顺延」而是「零外加牺牲」，crate 注（lib.rs:48-51）措辞与此一致无夸大。钉板测试：混桶 INT 钉顶 + 更晚 BG 不进 INT 桶（`tightest_slack_caps_bucket` :466-487）、LC 单发恰点/搭车零顺延/更晚者另桶（`lc_exact_never_deferred` :491-521）、MAINT 开桶吞 BG 的 L3 有界（`anti_starvation_span_bounded` :526-547）。聚合收益复算：10 定时器散布 100ms 窗全 INT 档——手算轨迹逐桶复现 b1{5,12}@15/b2{18,25}@28/b3{31,40}@41/b4{47,55}@57/b5{63,70}@73ms，5 桶降比 50%（`coalesce_benefit_ten_timers` :429-447），且该例贪心即最优（{12,18,25} 共桶需 fire≥25 与 fire≤22 同时成立，矛盾——更密装箱不存在）；33% 截断向零例（:450-460）整数算式对。数值口径 = 构造数值例非 benchmark 主张，标注诚实，数值合理。

### 3.4 零依赖镜像对拍——零漂

三镜像逐值对拍单源：①slack 六档 `SLACK_*_NS`（lib.rs:91-103）↔ iprofile 手表表 `timer_slack_ns` 列（`iprofile/src/lib.rs:102` 表、:113/:125/:136/:147/:158/:170 六值）——50ms（:60 `SLACK_INTERACTIVE_DEFAULT_NS`）/0/10ms/50ms/500ms/10s（:64 `MAINTENANCE_SLACK_NS`）逐值相等；②编码冻结 0x00..=0x05 ↔ `intface/src/lib.rs:42-56`（`slack_for_intent` :108-118 直映、保留域 None 与 `intent_valid` 同律，`policy_triple_valid` :319-323 同执法）；③slice 域 [16,1024] ↔ `kernel/src/bootparams.rs:62-63`。G5「两键之第三键补全」框架成立——`sched_slice_hz`（bootparams.rs:237）/`intent_default`（:243）两键在册、`timer_slack` 键不存在（=本件提议的补全位，非既有事实误引）。同步义务注集中在 lib.rs:65-72，解禁改 path 依赖留窗记账。任务书括号序（MAINTENANCE 中）与单源实序（MAINT 最宽）的差异由落件者自标「数值推断标注①」并从单源——一事实一归属，处理正确（lib.rs:74-76/:101-103）。
