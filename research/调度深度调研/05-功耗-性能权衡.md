## §0 结论速览

1. **总判词：省电机制链「第一杠杆已兑现、第二杠杆悬空、承重墙还是图纸加固中」**——tickless 谱系（oneshot + 绝对截止重编程 + 深/浅 park + idle_loop 停泊补）机构全在位且 OFF 态 QEMU CPU 已实测降到 0.65%（bare）/0.50%（GUI 形）（[12 号](../调度彻底计划/12-终窗复核.md):9，60s 窗，两源：实现者自报 0.22%+0.04% 同判读带）；timer slack（省电第二杠杆 = 唤醒合并）判定律纯面已建而内核接线零命中（本轮 grep 两源，§1.3）；PM governor（终态图景承重墙）从「服务实体未建」推进到「双服务骨架 + 预拉段 + 四 crate 联合场景」但仍未挂接真通道——调度→频率链九环中生产侧与消费侧数学各自钉板，中间的传输通道与内核聚合点是全链最窄的两处断点（§2）。
2. **功耗面五件盘点：tickless（已通）/ idle 停泊（已通，含 QEMU 险径在册）/ slack（骨架，CP-11 债一）/ PM 双服务（骨架，CP-08/CP-10 窗）/ 频率帽（纯面完备，内核聚合点未建）**——逐件机制态·消费态·缺口见 §1 五表；其中频率帽三源聚合（thermal/schedhint/lowbatt 取 min）与充电票 mA 域终裁（F1 已裁 mA 直连无桥）在 host 纯面全部穷举钉板，但「唯一合法帽书写面」的内核执法位（ADR #66 ②）仍是注释锚非代码（[04 号](../调度彻底计划/04-PM双服务骨架复核.md):33）。
3. **DVFS 协同九环链：三环已通（tick 记账 / EWMA 折叠 / 消费侧频率映射）、两环骨架（通道 ABI 形态待裁 / berry-power 裁决机）、四环未接（通道本体 / 内核聚合点 / 改频原语 / 真 OPP 表）**；schedutil 的 BerryOS 形态 = 同构公式 `f ≈ util × fmax / capacity` 而无 1.25 余量、无 util_est 锁峰、无 uclamp 聚合（uclamp 全仓零消费——本轮 grep 实证）、单频域取 max 的保守侧口径；「slice 周期数记账」已落（DVFS 上线后时间片时长不随频率漂移——省电线与性能线的汇合点，设计 §3.5，2b-4 已落）是 BerryOS 比 Linux 文档口径更早兑现的一件（§2.4 对照五点）。
4. **EAS 就绪度判词：数据面三件全在（EM 表形状 / util EWMA / overutilized 门控），算法面两形分离（sched 侧零算法 · berry-em 纯面已备），消费面三路全未接（唤醒 / 迁移 / spawn 选核不读 placement）**——与 Linux `find_energy_efficient_cpu()` 的差距不是表形状而是「谁在唤醒路径消费能量比较」；berry-em 已把 compute_energy（域级 OPP 由 max_util 定 + sum_util × power/capacity 线性摊能）与两段选核最简形钉板为 host 纯函数（CP-09 前置件），Linux Example 2 逐数对拍在测；对称拓扑无收益的 K3 kill criteria 压力真实在册（§3）。
5. **功耗度量：QEMU 期能测四件（vCPU CPU% 代理 / icount 指令数确定性通道 / 唤醒率足迹 / host 纯面数学对拍），缺三件（功耗计物理量 / 能耗 A/B 判据载体 / icount→功耗的模型桥）**——KC-P2「固定基线 A/B 能耗收益 95% CI 下界 <3%」（ADR #68）在功耗计缺席期无测量载体，这是省电支柱所有 kill criteria 的共同空白；idle 测量纪律三则（串口静默+vCPU halted 双条件 / QMP thread-id 采样 / 背景负载窗标注）已随 06/11/12 号成文（§4）。
6. **深度 idle 三层谱系中调度器角色递进：浅 park 调度器是「下次醒点唯一裁决者」（nearest_deadline 供 oneshot 武装）、深 park 调度器是「尽空判定者」（rq 空 + SLEEPQ 空才 mask）、suspend 调度器是「冻结执法者」（freeze 机器复用 + PSCI 降级兜底 + 双钟记账面）**——PSCI 三档现实表（TCG susp=0 实测 / KVM 待 spike / 真机 v2）与 PWRDEG 真冻结证据链（degrade/freeze_ok/auto_thaw 三计数恰 +1）在册；深睡三件套（超时冻结 / exit_latency 预扣 / latency QoS）仍为 v2+ 设计位（§5）。
7. **风险面两条在册：QEMU wfi 的结构性自旋险径（pending-but-masked + wfi = vCPU 满速空转，最小内核 v3 形 99.8%/99.9% 实测）当前不触发但病理态可达**（修窗件 3 低优在册）；**EWMA 深睡稀释语义在长睡窗下的失真面**（elapsed 摊大 → busy 占比被稀释落底）是设计选择而非缺陷——但「醒后突发负载首窗欠频」的代价面未入遥测（推断，§5.4）。

### 1.2 idle 停泊（深/浅 park 谱系 + per-CPU 统计）

- **两档停泊形态**（idle_loop 内 [sched.rs](../../sched/src/sched.rs):3134-3168 SMP / :3170-3207 单核）：`nearest_deadline()` Some → 浅 park（`arm_at(d)` oneshot + wfi）；None → 深 park（`mask` + masked-wfi 三步闭环——wfi 全程 PSTATE.I=1，醒于 GIC pending 线而不服务，醒后 enable 即取中断再 disable 回环顶）。
- **masked-wfi 三步闭环**（Linux arm64 cpu_do_idle 同款）：[kernel/src/main.rs](../../kernel/src/main.rs):4990-5060（CPU1）与 [sched.rs](../../sched/src/sched.rs) idle_loop（CPU0）双点在册（[06 号](../调度彻底计划/06-idle满核归因.md):11）。
- **per-CPU park 统计**：`note_park_cpu()`（S-5a 面，本核独占写）——停泊频度的观测面（[sched.rs](../../sched/src/sched.rs) idle_loop 内调用）。
- **IDLE_TASK 语义**：current 恒 IDLE_TASK 不置 null（block/exit 的 pick-None 臂与 on_irq_tick 判据依赖，[sched.rs](../../sched/src/sched.rs) idle_loop 头注）；idle tick 不入 util 账（§2 生产侧 is_idle 门）——idle 时间是低 util 信号本身。

**缺口**：①QEMU 险径在册——pending-but-masked 中断 + wfi = TCG/HVF 早退忙旋（v3 形 99.8%/99.9%，`-d int` 零已取异常 = 纯 QEMU 侧转），当前树不触发（正常 tick 路径 CNTV 到期即取走），修窗件 3 低优（[06 号](../调度彻底计划/06-idle满核归因.md):101）；②干净 park 两加速器都让出（v1/v4 = 0.0% 硬零）——QEMU 侧 idle 测量的可信度基座已定标（:60-63）。

### 1.5 频率帽（三源聚合 + 唯一书写面纪律）

- **档位表**：低电帽 ≤15% → 500kHz、深亏预充 ≤10% → 2400mA 票（[berry-power lib.rs](../../user/bins/berry-power/src/lib.rs):85-88，PolicyParams 推断标注——Android 低电警告档同档位初值）；热档帽 `LEVEL_FREQ_CAP_PCT = [none, 70, 45, 25]`（[berry-thermal lib.rs](../../user/bins/berry-thermal/src/lib.rs):98-99，04 号 §3.1 转引）。
- **消费态**：dry-run 诊断行 `cap=400000kHz@src1 … eff=125000khz`（schedhint 帽 400kHz 压过 schedutil 请求 125MHz 的 min 联测，[04 号](../调度彻底计划/04-PM双服务骨架复核.md):88 逐项复算全对）＋pm-integration 场景 A/B/C 三链；**内核侧零消费**——`grep -rniE "freq_cap|FreqCapAgg|聚合点" kernel/src/` 零命中（本轮实测；04 号 §2.1「内核聚合点本体与写通道 op 未立法未建」两源）。
- **缺口**：①内核聚合点本体 + 写通道 op（ADR #66 ②「唯一合法帽书写面」的内核执法位）+ last-writer 保持语义（帽不自动解除）须随聚合点立法（[04 号](../调度彻底计划/04-PM双服务骨架复核.md):124）；②thermal pct→kHz 桥（pm-integration 桥 1，推断标注「桥非裁决、接线刀裁走后退役」，[09 号](../调度彻底计划/09-icount与PM联合复核.md):57）；③RT 存在即被钉 MAX 频率是电池杀手的防线（uclamp 列）——**设计在册而消费零命中**（§2.3）。

### 2.2 频率帽在链中的位置

帽不在频率映射环内而在其外：`eff = min(schedutil_req, aggregate(caps))`——governor 意图（req）与可写频率（eff）分离，「帽不新开通道」（ADR #66 ②）。这条纪律的直接含义：**热限频与低电限频不需要调度器知道**——调度器照常产 util 信号，帽在 PM 侧收口。对调度器的唯一反向影响是 slice 周期数记账（§2.4-⑤）：改频后时间片换算随新频率走，调度行为不漂移。

### 2.3 uclamp 的「设计在册·消费零命中」状态

IntentProfile 八列中 `uclamp_min/uclamp_max`（0..1024，喂 PM/DVFS，[iprofile/src/lib.rs](../../iprofile/src/lib.rs):82-84）与设计条款「deadline/RT 任务也查此表（EPP/uclamp 列）——RT 存在即被钉 MAX 频率是电池杀手（Linux uclamp 之前 SCHED_FIFO 的教训）」（[调度器设计](../../docs/调度器设计-v1.2.md):132）都在册；但 `grep -rn uclamp sched/src/ kernel/src/ user/bins/berry-power/` **零命中**（本轮实测——只有 iprofile 表定义自身）。即 RT 钉频防线目前只有表列没有执法路径；该防线兑现依赖 CP-08 通道 + CP-10 governor 服务两刀（推断：uclamp 聚合点应在 berry-power 侧实现，sched 只经 IntentProfile 查表出值——与 Linux uclamp 在 governor 侧聚合同构）。

### 5.2 PSCI 三档现实表与断言链

- **探测**：boot 期 `probe()`——PSCI_VERSION 正向对照（conduit 活证）+ PSCI_FEATURES(SYSTEM_SUSPEND)（[psci.rs](../../arch/aarch64/src/psci.rs):102-134）；EFI/EL2 门住不发 HVC。
- **三档**：TCG virt = susp=0（FEATURES 返 -1，本刀实测）/ KVM = 待 spike（预期 susp=1）/ 真机 = 待硬件 v2（[psci.rs](../../arch/aarch64/src/psci.rs):6-8；[PM仿真S3断言实施设计](../../docs/PM仿真S3断言实施设计-v1.0.md) §2 三档表）。
- **PWRDEG 真冻结证据链**：ktest 断言 degrade/freeze_ok/auto_thaw 三计数恰 +1（[kernel/src/ktest.rs](../../kernel/src/ktest.rs):5925-5964）；真 SYSTEM_SUSPEND 断言归独立 KVM/真机 spike 相。
- **调度角色深析**：suspend 的降级路径**原语级复用 freeze 机器**（S3 freeze 的 precheck/freeze/thaw 全套写点照走）——深睡与冻结共享同一执法原语，这是「深睡前冻结超时任务」三件套第一件的现役雏形；EL0 深睡入口随 PM-03 挂起原语刀另裁（syscall.rs:2304 头注「零 syscall 号——本刀只立机制面」）。

### 5.3 挂起期双钟（ADR #67）与深睡三件套

- **双钟**：MONO 挂起停（程序时间观：超时/动画/重试无跳变）/ SLEPT 连续（记账口径：维护窗判定 / idle 世代 / 能耗归因）；slept_ns/suspend_count 记账面先行（KC 刀 1 已收口，[01 号](../调度彻底计划/01-调度现状全景与在途线收编.md):142），累加硬件载体（always-on 域计数器 vs RTC 差补）挂 KVM spike 回填后裁（ADR #67，[架构决策](../../docs/架构决策.md):75）。
- **深睡三件套（v2+ 设计位未落）**：①超时任务冻结（深睡前摘链冻结、深睡期零定时器中断——L3 降级路径已具雏形）；②唤醒延迟预扣（选档先扣 exit_latency、deadline 减去它才允许进）；③latency QoS（服务声明可容忍唤醒延迟、PM 排除过深档位）（[调度器设计](../../docs/调度器设计-v1.2.md):168）。**三件套归 PM 服务策略面**（档位选择全归 PM，调度器只供给 util 信号与唤醒事件）——berry-power 挂接前无承载实体。
- **调度器在深睡谱系的总边界**：tickless 管「空闲不白醒」（L1/L2），三件套管「深睡不误事」（L3），两层合起来才是省电主力（设计 :168 判词）。

### 5.4 util 信号与深睡的交互（推断面如实标）

深睡长 gap 后首窗 elapsed 摊大 → busy 占比被 idle 稀释 → EWMA 自然落底（idle 路径无需专门翻窗，[util.rs](../../sched/src/util.rs):15-17 头注）——这是设计选择（深睡后从低频起步省电）；其代价面「醒后突发负载首窗欠频」（EWMA 需 ~5.2 窗半衰期爬回）未入遥测、无对账面（推断——Linux 用 util_est 锁峰部分缓解此面，BerryOS util_est 未取，02 号 :30）。DVFS 上线后此面将成可观测议题，建议随 CP-08 接线刀把「深睡醒后首窗 util/req」进遥测（本件建议，非在册裁决）。

1. **CP-08 通道形态建议快裁**：共享环 vs 快照 VMO 是全链最窄断点（§2 环 4），且阻塞 CP-10（governor M3 兑现）与 KC 消费闭环——开放问题 8 已建议「CP-08 前裁、PM 线刀 2 排期即立项」（[调度彻底计划](../../docs/调度彻底计划-v1.0.md):204）。本件补充：无论何形，`ingest_window/ingest_sample` 双输入口已把消费侧解耦（通道换形零改 berry-power 数学面）——裁形态的风险面比表象小。
2. **F2（sim 流消费切分）应在 berry-thermal 接线前裁**：同一 UART1 流三方主张未合流（§1.4），berry-thermal 输入接线（04 号 §6-7）一开即撞——建议与 CP-08 同窗。
3. **uclamp 执法路径建议随 CP-10 显式立刀**：RT 钉频防线（§2.3）目前只有表列；governor 服务本体建时若不接 uclamp 聚合，deadline/RT 任务上线（M5）即裸奔 MAX 频率——与设计 :132 条款自相矛盾的风险窗在 CP-10 与 CP-14（admission）之间。
4. **功耗代理指标建议进 smoke**：demo-face OFF 态 0.65% 已是可复现的稳定锚（12 号）——「OFF 态 idle CPU <5%」断言（06 号修窗件 1 的验收线）建议随 svcmgr 门闭合升格为常驻 smoke 相（推断：需 berry CLI/QEMU 采样工具面配合，owner 域）；icount 基线建议增「OFF 态稳态窗指令数」项作唤醒率回归防线（本件建议）。
5. **berry-em 与 sched/em.rs 的双表现状**：QEMU_VIRT_DUAL 镜像靠测试钉值同步（[berry-em](../../user/berry-em/src/lib.rs):59-62 同步义务）——CP-09 接线时建议顺手改 path 依赖单源（slackface 镜像路线的教训已在头注 :21-23 自载「镜像 = 自造第二事实源」）。
