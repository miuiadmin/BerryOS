## 一、现役 SMP 面全审计（代码态）

总判语：SMP 机制面呈「数据面已原子化、验证面未建、执法面半开」三层态——三件套+band 原子账+divergence 分账三件并发基建已落且经双核终验（60 ok），但专属验收相（SMPBENCH/POLICY-S/BAND-S）代码零命中，band 执法默认全关。以下按八个子面逐项审计。

### 1.1 per-CPU runqueue 与结构锁

- **队列本体**：`static mut PER_CPU_RQ: [Runqueue; 2]`（`sched/src/sched.rs:229`），定长数组按核分诊，单核形态（gate 恒关）`cpu_id()` 恒 0 → `[0]` 行为等价旧全局队列（`sched.rs:227-228` 注——零漂移根基）。
- **per-queue 自旋锁**：每 Runqueue 自持 `SpinLock`（`sched/src/runqueue.rs:66`，crate 内 TTAS——先 CAS 入主、失败转廉读自旋，`sched/src/spin.rs:41-62`）；取放经 `rq_lock_of`/`rq_unlock_of` 统一持有位记账（HELD_RQ0/HELD_RQ1，`sched.rs:643-651`）。锁窗纪律：IRQ 屏蔽窗内取放、不可重入、持窗禁切换（`spin.rs:8-11`）。
- **免锁读字段**：`len: AtomicUsize`（跨核 place/integrity 读不撕裂——c-2b slice 3 原子化，`runqueue.rs:31`）；`sum_vruntime: AtomicU64` 多写者 RMW——tick 免锁窗与对核锁窗 link/unlink 并发写，写侧 fetch_add/fetch_sub 防 load+store 丢更新（SMP 相真 bug 修，沿革一八五；`runqueue.rs:40-50` 字段注 + `sched.rs:3412-3419` 调用点注）。
- **全局计数门**：`DL_ON_RING: AtomicU32` 全局单原子（非 per-RQ——设计取舍「保守方向多扫不漏扫」，`runqueue.rs:83-107`）；双 RQ 锁窗多写者真 RMW。
- **锁序立法**：七层冻结序 SQ > RQ0 > RQ1 > REAPQ > 表（KL 最内），切换舞蹈「放」内→外、「取」外→内（`sched.rs:381-433`）；一切多锁位点恒升序前缀 ⇒ 跨核 ABBA 不可能（`sched.rs:385-386`）。svc 分类表锁序（§A112 ABBA 预拦截）另在册。

### 1.2 放置路由与跨核唤醒

- **place 静态度判据**（`sched.rs:752-763`）：①内核任务（ttbr0==0）恒 CPU0；②boot 裸表用户进程（pinned==0）恒 CPU0；③单核形态恒 CPU0；④不可铺核（spread==false）恒 CPU0（服务根/svcmgr/pager 恒家核防协议断供）；⑤可铺核任务本核优先 + 深度失衡 K=2（本核 len ≥ 对核 len+2 → 改道对核）——判据全静态度，**永不读对核 park 态**（F-E6/F-A3 纪律，`sched.rs:736`）。
- **enqueue_with_kick**（`sched.rs:774-791`）：RQ 窗内目标核环接线，SGI 戳留窗外（MMIO 非阻塞）；发送判据 = `cpu != cpu_id() && par_enabled()` 两静态度——「目标核队列真有货」由路由/归属恒真保证，这是 SGI 发送面成立的前提（生产发送面自 S-3b 起非零）。
- **wake/expire 再入队回 home 不改道**（防 sleeper 被唤醒方弹核，`sched.rs:750-751`）；home_cpu 唯二写点 = place（spawn）与偷取随迁（`sched.rs:833`）。

### 1.3 偷取（负载均衡初版）

- **try_steal_one**（`sched.rs:3785-3848`）：本核 pick None 后扫对核环，F-E2 双过滤（①ttbr0!=0 有表才偷——无表内核任务永不跨核；②非 Running 态）+ spread==true 门；只偷首 eligible 单任务。
- **锁形特则**：「只持远端」四步——远端窗扫描+摘环 → 放远端 → 无归属窗（home 随迁独占写）→ 回插本核再取本地，**绝不双持**（`sched.rs:3781-3784`）——双队列锁序特则构造性不触发。
- **三个触发点**：①idle_loop 本核出选 None（`sched.rs:3136`）；②park_recheck 本核无货（`sched.rs:3739`）；③on_irq_tick 定时拉取——slice 燃尽支「本核 len≤1 且对核显著更重（theirs≥mine+2）」才拉（S-6 ②，`sched.rs:3503-3529`），单向拉 + 迁移粘性 = 无乒乓。
- **S-6 收敛实绩**：三修（arm_slice 单调夹取/显式可迁移面/spawn 先簿记后入环）后矩阵对称 3370:3375≈1:1（修前 22:1）——部署设计 §1 在册（`docs/调度器SMP部署设计-v1.0.md:37-39`）。

### 1.4 park 环与 idle（CPU1 park 形态）

- **副核 park 环**：副核无任务时切回 `sec_park_ctx` 空哨兵（CURRENT=null）；block/exit/yield 三切点 + park 派发位共四 park 语境切换位（`sched.rs:42-47` 注、`sched.rs:1303-1316`/`1446-1457`/`2459-2478`）。
- **park_recheck**（`sched.rs:3693-3761`）：SGI 醒与 CNTV 醒经 eret 回 park 环收敛单路径承接——本核出选（RQ 窗内置 Running 防偷屏障）→ 偷取 → 皆空回环。
- **idle_loop 双核分支**（`sched.rs:3105-3169`）：reap_drain → 本核出选 → 偷取 → 皆空深/浅 park（`nearest_deadline` 有值 arm_at / 尽空 mask）+ masked-wfi 三步闭环（丢唤醒窗收口）。单核分支同形下放（06 号修窗件后 idle 停泊 OFF 态 QEMU CPU 0.65%——01cd881b2 提交信息单源，06 号研究件在册互证见 `research/调度彻底计划/06-idle满核归因.md`）。
- **nearest_deadline**（`sched.rs:3931-3939`）：SQ 锁窗内读**全局** SLEEPQ 队头——两核对同一 deadline 双 arm = 至多一次冗余醒，锁内 expire 串行无撕（`sched.rs:3148-3151` 注）。注意：部署设计 §3「SLEEPQ 归属核单点武装」（`docs/调度器SMP部署设计-v1.0.md:99`）是子案规则③④的设计口径，代码现状 = 全局 SLEEPQ + 双 arm 冗余醒——设计文与代码有口径差，归属核单点武装未实装（推断：差异源于子案描述的是「插入核武装」的理想形，现状以「冗余醒有界」代替）。

### 1.5 SGI 面

- **SGI_RESCHEDULE 收端**：副核收 SGI → eret 回 park 环 → park_recheck 读本核队列出选（`sched.rs:769-770`）。
- **on_sgi_resched**（`sched.rs:3610-3654`）：仅 CPU0 进（副核被 gate 挡在锁窗外零共享触达，`sched.rs:3613`）——CPU0 快速重调度（同 eff 也切），解「唤醒延迟不对称」（TCG 有效 tick ≈ SLICE_HZ/2 → 最长整片，`sched.rs:3589-3599`）；SGI 不进 tick 槽纪律（无 rearm/无片记账/无 expire——tick 语义面不稀释）。
- **禁切窗闭门**：preempt_count>0 时 tick/SGI 双门都早退（`sched.rs:3431-3433`/`3626-3628`）——严格更高 eff 出窗检查点直切（µs 级）、同 eff 落下个 tick（errata m2 分档）。

### 1.6 band 全局原子账（SMPD-3 已落）

- **两热字升原子账**：`CONSUMED/DEADLINES: [AtomicU64; 8]` 全局一份（`sched/src/band.rs:70,77`）；消费 fetch_add（Relaxed 纯计数）+ 首越线单赢家判定（prev < quota ≤ prev+cycles 全局恰一次 true，`band.rs:172-181`）；翻期 CAS 防双翻（只有翻中旧值的核兑现清账，`band.rs:226-229`）；发布序 = 清账先行 + CAS(Release)，读侧 Acquire 配对见新期必见新账（`band.rs:216-225`）。
- **未竟子项**：throttled 镜像位仍 static mut 单核写（`band.rs:61-62` 注「SMP lazy-pick 执法刀（SMP §3）再升 AtomicBool」）；现行执法 = throttle_all/unthrottle_all 环扫（`band.rs:241-293`），且 band 默认全关（quota/period=0 → consume 恒 false 零扫描，`band.rs:12-15`）——入场券未过执法不并线。
- **超卖窗**：清账-翻序间他核 fetch_add 的落账归属 = 翻期边界固有竞态，上界每核一份 delta——断言归 BAND-S 相（`band.rs:196-199` 注）。

### 1.7 divergence per-CPU 分账（SMPD-4 已落）与 SMP 三件套

- **分账**：`DIVERGENCE_PER_CPU/EVAL_PER_CPU: [CountSlot; 2]`，CountSlot 64B 对齐防伪共享（`sched/src/policy.rs:653-662`，`#[repr(C, align(64))]` + const 断言尺寸对齐双执法）；写方限本核（cpu_id 索引）零跨核争用、读时合并求和（`policy.rs:724-743`）；轨道切换清零在 POLICY_LOCK 窗内两槽同批（`policy.rs:747-752`）——SMPD-4 机制件完整（078073be 落码，54fc9b64 双核终验 60 ok——git 与 01 号研究件 §1.6 两源）。
- **三件套**：①SHD_WHERE AtomicU8（写侧槽写→fence(Release)→store(Release)/读侧 Acquire，`policy.rs:534`）；②hazard-lite——`HAZARD: [AtomicU32; 2]` 每核发布在读槽号 + active_snap() 验证环（load→store hazard→fence→复读验证，`policy.rs:222-248`）+ publish() 避让扫描（跳过 active∪HAZARD，「3 槽 2 核恒有空闲」expect 执法，`policy.rs:190-211`）；③POLICY_LOCK 写者自旋锁五入口全串行（`policy.rs:157-173`）。**shadow 侧 hazard 未覆盖**——见 §五.1。
- **gen 全局单调**：全局单表 + ACTIVE 全局发布即现状形态，per-CPU 读者快照未做（2 核档远程读可受、4 核+ 复议——调点 v1.3 §4 与部署设计 :102-108 两源同口径）。

### 1.8 抢占面与遥测

- **per-CPU preempt_count** + 检查点族（g3-1d 真探形，`sched.rs:108-149` 批）+ print_window preempt 包络对（`sched.rs:205-215`）。
- **遥测 per-CPU 面**：hdr.rs `PER_CPU_HDR: [CpuHdr; 2]`（写方限本核 + merged_percentile 跨核合并读，`sched/src/hdr.rs:19-33,63-65`）；util.rs `UTIL_EWMA/UTIL_ACCUM/UTIL_WINDOW_START: [AtomicU?; 2]` per-CPU EWMA（`sched/src/util.rs:38-42`）——均为 per-CPU 单写者纪律（写本核槽读时合并，Linux this_cpu_ops 同形，见 §三业界对照）。

## 三、4/8 核扩展瓶颈（lock 粒度/缓存行/总线争用）+ 业界解法

### 3.1 代码证据：五类瓶颈

**瓶颈一：定长 2 的硬编码全面冻结**。`PER_CPU_RQ: [Runqueue; 2]`（`sched.rs:229`）、`Topo.capacity: [u32; 2]`（`runqueue.rs:461`）、`HAZARD_CPUS = 2`（`policy.rs:135`）、`RECON_CPUS = 2`（`policy.rs:651`）、UTIL_NR_CPU/HDR_NR_CPU（util/hdr 同款）、`LB_TICKS[cpu_id]`——扩 4/8 核是「每一处数组 + `1 - me` 二元假设 + `min(N-1)` 收敛」的系统性改造，不是单点扩容。在册口径：不提前缴 4 核+ 复杂度税（计划排除项 L25）；写者锁 4 核+ 反噬 → kill criteria = SMP 线冻结 2 核档并文档化（部署设计 :154-155）。

**瓶颈二：「对核」二元假设泛化失效**。place K=2 与定时拉取均读 `rq_of(1 - me)`（`sched.rs:757,3507`）——8 核下「对核」无意义，需要偷取目标选择（scan 哪个核）与多核失衡度量。业界解法 = 调度域层级：Linux 每个 CPU 有 base sched_domain，经 ->parent 成层级，balance 在 sched_group 之间逐级进行（sched_balance_domains 从 base 向上迭代、sched_balance_rq 找 busiest group 再找 busiest runqueue、双锁搬移——[sched-domains 文档](https://docs.kernel.org/scheduler/sched-domains.html)）；BerryOS 对应物 = 「域内偷取优先、跨域次之」的两层偷取序（推断，最小形详 §四）。

**瓶颈三：全局单锁/单原子的总线争用**。SQ（SLEEPQ 全局单锁——`sched.rs:3931-3939` 锁窗读全局队头）、REAPQ、POLICY_LOCK（写者全局单锁）、DL_ON_RING（全局单原子 RMW，双 RQ 锁窗多写者 `runqueue.rs:107`）、band CONSUMED[i]（同带 8 核 fetch_add 同 cache line，`band.rs:172`——执法全关故当前冷）。2 核下 TTAS 自旋窗短（KL 全量在场过渡态恒零争用先例 §A108）；4/8 核下热点收敛于 SQ 与 DL_ON_RING。业界解法两层：①per-CPU 化（写本核读时合并——Linux this_cpu_ops 明文「Bouncing cache lines can be avoided if multiple processors concurrently go through the same code paths」，代价 = 读总值需 Σ 求和，[this_cpu_ops 文档](https://www.kernel.org/doc/html/latest/core-api/this_cpu_ops.html)）；BerryOS 已在 hdr/divergence/util 三面落同形，DL_ON_RING 可循 per-RQ 分账 + 惰性合并（推断，收益窗口在 8 核）；②排队锁——争用 cache line 弹跳是自旋锁的根本痛点（每次取锁尝试都要把锁行搬到本核），MCS 锁以 per-CPU 排队节点让自旋完全 CPU-local，qspinlock 压回 32 位单字 + per-CPU mcs 数组 + pending 位（VFS/ext4 强争用磁盘基准提升最高 116%——[LWN: MCS locks and qspinlocks](https://lwn.net/Articles/590243/)）。BerryOS TTAS 在 2 核档够用（spin_bark 看门狗 + 2^23 自旋上限已设防，`spin.rs:50-59`）；8 核若 SQ 成热点，换 MCS 形是先例在册的刀（推断，触发条件 = spin bark 频发或 soak 出现锁热尾延迟）。

**瓶颈四：伪共享（false sharing）**。SpinLock 本体是 1B AtomicBool 无对齐填充（`spin.rs:28-30`）——SQ/REAPQ/RQ0/RQ1 四锁若静态相邻落同一 cache line，双核互斥操作互弹对方行。对照正面先例：CountSlot 64B 对齐（`policy.rs:653`）与 CpuHdr 64B（hdr.rs）已成纪律。Linux 教训同向：per-CPU 结构内两字段同 cache line、一个远程写一个本地 RMW 即出问题，「should be taken that such simultaneous accesses to data within the same cache line are avoided」（this_cpu_ops 文档「Remote access to per cpu data」节）；且「remote write will evict the cache line from the processor……its performance and hence the wake up times will be affected」——远程写直接伤唤醒延迟，推荐改走 IPI。BerryOS 行动项（推断，低悬）：给 SpinLock 加 `#[repr(align(64))]` 或静态声明处手工填充，一次审计四处锁 + ELAPSED 类全局原子行布局（nm 反查地址相邻性即可验证）。

**瓶颈五：TCG 双核非确定性放大**。跨核时序断言全状态谓词化已在册（部署设计 :149-151）；soak 失败须三连复现才立案——8 核下交错空间指数放大，此纪律是验收面成立的前提而非可选项。

### 3.2 结论

2→4/8 核的本质税不在数组扩容（机械但直接），而在三件结构性事：①「对核」二元假设 → 拓扑层级化（§四）；②全局单锁/单原子热点 → per-CPU 分账或排队锁（业界两件解均有在册先例可循）；③伪共享审计（一次 nm 布局核查 + 对齐补齐）。在册 kill criteria（冻结 2 核档）是诚实退路，不建议提前缴税——与计划排除项一致。

## 四、拓扑感知：EM 有形状、sched 不消费

### 4.1 代码证据：形状与消费的断裂

- **EM 侧有形状**：`EmDomain { cpu_mask: u32, points }`（每性能域 = 同频簇一张 {freq, power, capacity} 升序点表，Linux EM 同口径——`sched/src/em.rs:5-7` 头注 + `em.rs:32-35` re-export）；QEMU virt 默认表 = 单域 cpu_mask=0b11 三点（`em.rs:102-111`）。**cpu_mask 就是拓扑形状**——域归属位掩码。
- **sched 侧不消费**：Topo 只有平坦 `capacity: [u32; 2]`，无域/簇字段（`runqueue.rs:455-462`）；place() 只读队列长不读 capacity（`sched.rs:746-762`——「v1 pick 不读 nr_cpus，放置路由读队列长，纯账面真化」`sched.rs:722-723` 注自认）。
- **仅有的两个 EM 消费点都硬编码域 0**：①overutilized 判定 `em_max_capacity(0)`（`util.rs:121`）；②placement_hint 的 overutilized 门控间接经 ①（`policy.rs:462`）。多域拓扑下两处语义即错。
- **placement 三值词汇已冻结但只存不路由**：0=无意见/1=偏 little（CPU0）/2=偏 big（CPU1）（`policy.rs:447-452`）；apply 顺带写 Task.placement_hint 双门（placement≠0 && par_enabled，`policy.rs:421-423`）；「唤醒选核的真消费随 SMP 路由接」——三路（唤醒/迁移/spawn）均未接（调点 v1.3 §6 :120 与部署设计 :95-101 两源）。

### 4.2 Linux cluster 对照

Linux 的拓扑感知 = 三层结构咬合：①sched_domain 层级（SMT→MC（=cluster/LLC）→DIE→NUMA），base domain per-CPU 无锁更新，arch 可以 sched_domain_topology_level 数组覆盖默认层（[sched-domains 文档](https://docs.kernel.org/scheduler/sched-domains.html)）；②capacity 非对称检测——建域时发现异构则 SD_ASYM_CPUCAPACITY flag 设在「span 所有唯一容量值的最低层」（[sched-capacity 文档](https://docs.kernel.org/scheduler/sched-capacity.html) §4）；③EAS 的 performance domain——EM 框架维护 pd 功耗表，调度器建域时挂 pd 链表到 root domain，RCU 保护，find_energy_efficient_cpu 在每个 pd 找最高 spare capacity 核再算能量（[sched-energy 文档](https://docs.kernel.org/scheduler/sched-energy.html) §3-§4）。overutilized 80% 阈值 + root domain 级标志（「单核饱和即全域 EAS 失效」）——BerryOS any_overutilized 同形已落（`util.rs:124-129`）。

### 4.3 BerryOS 最小形提案（推断，设计建议）

关键机会：**不新建拓扑真源，让 EmDomain.cpu_mask 成为唯一拓扑事实**（一事实一归属——AGENTS 纪律在调度内部结构的落法）。最小形三刀：

1. **Topo 加一个字段**：`llc_mask: u32`（或直接暴露 `em_cpu_domain(cpu) -> usize` 查询桥，数据留在 EM 表）——place/偷取/迁移的「同域优先」判据单源于此。不改 Runqueue 结构、不加锁。
2. **偷取两层序**：try_steal 的 victim 扫描先同域后跨域（同 LLC 偷取缓存代价近零，跨域偷取付远端缓存重填）——Linux MC 域内平衡先于 DIE 域的精神，BerryOS 以「扫描顺序」而非「域结构」实现（8 核下 1-me 泛化为「同域邻核列表 → 跨域列表」两段扫）。
3. **overutilized/placement 消费去硬编码**：`em_max_capacity(0)` → `em_max_capacity(domain_of(cpu))`——本域容量比本核 util，这才是 Linux「per-domain 容量基准」的口径。

时机判断（推断）：QEMU virt 无论 2 核还是 8 核都是单簇对称（TCG 建模不了大小核，`em.rs:99-101` 自认「只验机制不验收益」），拓扑感知的真消费窗口在真机/大小核（EAS compute_energy 留 M2/真机，`em.rs:8-9`）——与 EM 算法面同窗兑现，不建议在 v1.4 SMPD 收官前插入；但 4/8 核扩容刀若先来，llc_mask 字段应随扩容刀同批落（否则「对核」泛化无判据可依）。

## 五、双核终验后竞争面审计

基线：54fc9b64（2026-11-11 双核终验 60 ok + SMP ok + BAND-K/SHD-K/DV-K/DL-K 全绿——git 提交信息与 01 号 §1.6 :69 两源）之后，HEAD 上的 sched/ 落件仅 01cd881b2（调度终窗·idle 闭合+M4 骨架）与 afd68392a（docs）；其余 sched 提交（cp11 timer slack/P2-2 退出异步化/W3-Q26/Q53/Q82 外迁/bfb8a4fe6 smp terminate defer）经 `merge-base --is-ancestor` 逐笔实测均 **NOT-IN-HEAD**（base/hermes lane 在途，不入本审计基线，列 §5.4 备忘）。

### 5.1 shadow 侧 hazard-lite 缺口（最重要发现）

`policy.rs:530-532` 代码自认：「②hazard-lite 槽回收 shadow 侧未覆盖（active 侧见 HAZARD）——shadow 槽数据的跨核读写仍靠现状串行，留后续刀」；`policy.rs:512-513` 同：「shadow 读（shadow_gen/对账）与 shadow 换表的跨核并发仍靠现状串行」。具体竞态（推断，机制推演）：shadow 读者（shadow_reconcile——apply 热路径每调一次，`policy.rs:701-729`；shadow_gen——bind_gen_shadow 的陈旧拒收读）经 shadow_snap() Acquire 读 SHD_WHERE 后解引用槽——**无验证环**（active_snap 的 load→store→verify 环只在 active 侧，`policy.rs:222-248`）；写者 bind_gen_shadow 持 POLICY_LOCK 写 `SHD[WHERE ^ 1]` 非活跃槽再翻转（`policy.rs:568-591`）——若写者背靠背两次换表，第二次可覆写读者刚经旧 SHD_WHERE 进入的槽，读者窗内读到半新半旧（撕裂）。量级评估：数据面偏差（divergence 计数失真或 shadow_gen 读旧值致误拒收），**非 wedge 非 UB 级死锁**——单槽发布序（槽写→fence→翻转 Release / 读侧 Acquire）保证「见新槽号必见新槽内容」三件套①仍立，缺的是「读者进窗后槽不被立即复用」的回收半边。双核终验 60 ok 未触发 = 终验载荷无背靠背 SHADOW_COMMIT 序列（推断）。行动项：SMPD-2（POLICY-S）设计换表金丝雀时**必须**先补 shadow 侧验证环（把 active_snap 的 verify-loop 复用到 shadow_snap——两读者一个写者，改动面小），否则金丝雀测的是缺口不是协议（推断：这是 SMPD-2 刀单的隐含前置，建议升格为显式子项）。

### 5.2 已知残留竞态窗（终验时在册，复核仍在）

- **sum_vruntime 二元组撕裂**：走查侧（ring_check/dl_on_ring_walk 持锁）与对核免锁 tick 的（vruntime, 账本）二元组写可 ns 级撕裂——「理论假阳性窗 ≪ 丢更新窗三个量级，实测未见」（`runqueue.rs:47-50` 字段注自认；丢更新本体已由 RMW 根治，沿革一八五）。残留可受。

- **band throttle_all 只扫调用核 rq**（推断，机制推演）：consume 单赢家语义下恰一个核收到 crossed=true 并 throttle_all **本核** rq——对核环上同带任务在该窗口不受限流，直至对核自身 consume/period_check。lazy pick 执法（SMPD-3 余项）正是此窗的解：选核路径读账判超额，不依赖环扫。同为执法全关掩护下的已知洞。

## 六、结论与建议（供 02/03 号与刀单维护者）

1. **SMPD 铁门不动摇**：SMPD-0 唯一阻塞 = X-6 fix-or-withdraw 仓主裁决（外部），可并行的只有 SMPD-1 host 预研（hdrface 数学已备）与 SMPD-2 设计稿——且 SMPD-2 设计稿应把 §5.1 shadow 验证环列为显式前置子项（本报告唯一机制级建议）。
2. **4/8 核不提前缴税**：五类瓶颈中「对核泛化」依赖拓扑字段（§四 llc_mask），其余四类（数组扩容/全局锁/per-CPU 化/伪共享对齐）都有在册先例与明确刀形；kill criteria（冻结 2 核档）保持。
3. **拓扑最小形定锚**：EmDomain.cpu_mask 作唯一拓扑真源 + Topo 挂 llc_mask + overutilized 去域 0 硬编码——三小刀，与 4/8 核扩容刀或 EAS M2 同窗，不单开线。
4. **文档回填义务**（随 SMPD-0 收口一并）：部署设计 §1 三处现状过时（01 号 §1.6 已列）；本报告新增两处口径差——SLEEPQ 归属核单点武装（设计文 :99）vs 全局双 arm（代码现状）；§四 EM 消费点硬编码域 0。
