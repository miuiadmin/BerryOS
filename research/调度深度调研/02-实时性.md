## 结论速览

一句话判词：BerryOS 的实时性是「结构先行、数字在册、论证半程」——deadline 机制（EDF 带序＋CBS 预算＋ΣU≤0.95 准入）已真落码且数学单源 host 钉板，中断→任务 2000cy worst 的分段分解与 icount 确定性通道构成可信的测量底座；但「全系统延迟上界」还差四件：长屏蔽窗（SVC 主体）无全量表、PI 形 C 无界、忙核唤醒粒度仍是 tick、多核跨核上界未测。v2 工业 RT 的路线裁决（裁七：band 对象化升格而非 APS 移植）在册且血统清晰，与 QNX 8.0 砍 APS 的死因判例互为印证。

## ① deadline 带代码态 / 抢占点覆盖率 / 中断到调度延迟链

### 1.1 deadline 带的代码态：不是独立 class，是 Fair 环内的顶带

架构图与代码现实的第一落差：设计文档的 class 链（class_rt > class_deadline > class_fair > class_idle）是目标形态（`docs/调度器设计-v1.2.md`:27-34），代码现实是**单一 Fair 类实例**（`static RR: Fair`，`sched/src/sched.rs`:235；`RoundRobin` 只是 `Fair` 的兼容别名，`sched/src/class.rs`:70-71），deadline 是 Fair 环内按优先级带实现的一个档：判据 = `prio_effective >= PRIO_DEADLINE`，常量 1000 单源在 berry-sliceface（`sched/src/class.rs`:84-89；`sliceface/src/lib.rs`:107-109）。

EDF 语义靠三条机制组合达成，逐条有代码锚：其一，**带间严格优先**——S2a 形（`PURE_EEVDF=false`，`sched/src/class.rs`:61-68）下单圈扫描先选最高 `prio_effective` 带，deadline 带（≥1000）恒先于 fair 出选，PI boost 即时生效；其二，**带内即 EDF**——带内比较键 `(vdeadline, vruntime)`，而 deadline 任务的 `vdeadline` 是手动设置的绝对截止期：enqueue 不覆盖（`sched/src/class.rs`:183-186 注「1.1/S5：deadline 任务不覆盖 vdeadline」）、fair 片耗尽重臂资格把它排除（`fair_rearm_vd` 非 deadline 才重臂，`sched/src/class.rs`:266-270），于是带内序 = 最早绝对截止期优先；其三，**CBS 同形预算执法**——slice 即预算（spawn 时由 `preempt_threshold` 承载）、周期存 `duration_hint_ns`，tick 内 `throttle_admissible` 三与门置 `HELD_THROTTLE` 冻结（`sched/src/class.rs`:271-283），周期到由 `lazy_unthrottle_deadlines` 在 pick_next 顺带扫中解冻＋重臂＋replenish（`sched/src/class.rs`:127-153），`DL_ON_RING` 全域计数门使无 deadline 任务时零扫描（`sched/src/class.rs`:118-129）。重臂与 replenish 数学（`period_due`/`replenish`）单源在 berry-sliceface、host 钉板（W3-Q11，`sched/src/class.rs`:73-82, 147-173）——「判定律先 host 后内核」纪律在 deadline 面已兑现。

准入控制已真落码：0x3C `sched_setattr` → `sa_check` 纯判定面（berry-safeck）——policy=3（deadline 档）必须同时携带 BUDGET 位，`Σ(C_i/T_i) + 新申请 ≤ 3891`（Q12 定点，1.0=4096，即 1.0−0.05 reserve = 0.95），超载 `-EBUSY` 诚实拒（`safeck/src/lib.rs`:145-176；锚点向量钉板 `safeck/src/lib.rs`:451-472）；全局记账面 = `DL_TOTAL_UTIL_Q12` 原子快照，setattr 成功尾一次退旧累新防泄漏（`kernel/src/syscall.rs`:2409-2412, 2449-2460）。里程碑在册：S5 deadline「EDF + budget/period + 预算执法 + admission ΣU≤0.95」smoke PASS（`docs/调度器设计-v1.2.md`:258）；`berry_sched_attr` 带 size 尾零前向兼容（Linux sched_attr 同款，`kernel/src/syscall.rs`:2382-2406）。

空缺面如实：class_rt 与 class_idle 未建（M5）；deadline-server 式兜底与「admission 公式显式含 band 预算项」都是 M5/CP-14 待办（`docs/调度器设计-v1.2.md`:212；`docs/调度彻底计划-v1.0.md`:110——不补写则「deadline 满额时兜底必违约」）；M4 带实例 `FairBand` 是骨架——全方法委托 unit `Fair`、行为逐位一致、带参数只落字段（`sched/src/class.rs`:473-560）；deadline 任务豁免 band 级执法（环扫跳过，HELD_THROTTLE 一消费者一位，`docs/调度器设计-v1.2.md`:384）；RT/deadline 对 AI 一律屏蔽（`docs/调度器架构白皮书-v1.1.md`:50；`docs/调度器设计-v1.2.md`:275）。RT 静态池（RT/deadline 的 TCB/runqueue 节点/消息缓冲走构造期预算分配、旁路 buddy/slab）是设计位零代码（`docs/调度器设计-v1.2.md`:91-95，M5 兑现）。

### 1.2 抢占点覆盖率：检查点族已全覆盖唤醒出口，但「主体可抢占」只有两个解蔽域

切换原语位全景在册十一个（`sched/src/sched.rs`:42-44 bump_switches 注）：yield/exit/block 三函数的直切臂＋park 切点＋tick 抢占＋SGI resched 直切＋try_preempt 直切＋park/idle 两派发位；切换原语入口配平断言（`preempt_count==0` 才许切）覆盖八入口（yield_now/exit 族/block_current/try_preempt/on_sgi_resched/park_recheck/on_irq_tick 抢占支/dispatch_from_idle，`docs/G3全抢占实施设计草案-v1.0.md`:110）。per-CPU `preempt_count` 基座＋`preempt_checkpoint()` 助手（irqsave 包络＋计数==0 探峰＋try_preempt）是 G3-1a/1b 落物（`sched/src/sched.rs`:108-182）。

直切判定语义三档并存，各自有门：`try_preempt` = 出选者 `prio_effective` **严格更高**才切，且先经 `has_eff_above` 只读探峰防幻影出选（4-6 教训：出选不切 = 游标白耗一格、结构性饿死，`sched/src/sched.rs`:2768-2842）；`on_sgi_resched`（CPU0 快速重调度）= `len()>=2` 轮转门——同 eff 也切，比探峰门更激进，G3-2 段②复核后保留（`docs/G3全抢占实施设计草案-v1.0.md`:137-148）；tick 抢占 = slice 燃尽轮转，`preempt_count>0` 时本 tick 不切、落下个 tick 重探（`sched/src/sched.rs`:3421-3433）。

唤醒→直切面的覆盖结论（G3-2 段②定谳）：**同核半已全覆盖**——syscall 语境的七处唤醒调用面全部落在 SVC 派发尾检查点（g3-1b 落点①，`svc_exit_class` 毕零锁点全量探峰）之下，故 wake→run 上界 = 唤醒方 syscall 出口；fastpath send 叠加例外①直切；tick 超时面由 tick 抢占支承接；UART RX 唤醒走 trap 臂 post-EOIR 检查点（`docs/G3全抢占实施设计草案-v1.0.md`:147, 151；`arch/aarch64/src/trap.rs`:571-590）——v1 旧契约「不立即抢占，醒者等 tick/yield ≤1 slice」已随 G3-2 退役（`arch/aarch64/src/trap.rs`:578-580 原注即盲源自认）。跨核半 = SGI kick＋副核 park 环天然直切（park_recheck 出选即上 CPU），保留轮转门无语义变更（`docs/G3全抢占实施设计草案-v1.0.md`:137-139）。

但「syscall 主体中途可抢占」的解蔽域只有两域：console 写（`with_print_lock` 窗从 irqsave 换 preempt 计数包络＋出口按 DAIF 分诊检查点，`sched/src/sched.rs`:189-215；µs 级窗，`sched/src/sched.rs`:3426）与 pipe 拷贝（send/recv 原子段 `PreemptSpan` 守卫＋拷贝段 `irq_window` 局部解蔽＋段出口检查点，`kernel/src/syscall.rs`:2966-3004, 3272-3281, 3466-3470）。vmo 族的解蔽被 §A126 判死：vmo 十一号 = TABLE 类，包络内探峰（rq_lock 不退化）与解蔽（tick 的 expire_timeouts 物理取 SQ 于 KL 下）都是七类锁序逆序违约，故保持全屏蔽（`kernel/src/syscall.rs`:269-273；`docs/G3全抢占实施设计草案-v1.0.md`:118）。禁切窗全表五层：SVC 硬件 DAIF 窗（入口硬件置 PSTATE.I、handler 全程不解蔽——E0 纪元刻意保留的免锁根基，`docs/G3全抢占实施设计草案-v1.0.md`:108, 22）、`preempt_count` 计数窗、结构锁窗（RQ/SQ/REAPQ 窗内禁切换）、IRQ handler 本身（PSTATE.I=1 不可嵌套）、内核任务 `klock_enter` 直调窗。

覆盖率判词：以 G3 关卡口径（2026-11-05 收官，低尾延迟＋无 PI 死锁＋trace 双跑＋soak 全要件复验，`docs/G3全抢占实施设计草案-v1.0.md`:249-259），BerryOS 现实形态 = **检查点式抢占＋有限域解蔽**，不是任意安全点可抢占；P-B（preempt-on-wake 通用化）已随 G3-1/G3-2 转 default（`docs/G3全抢占实施设计草案-v1.0.md`:231），E2 逐域下放（P-C）未启归 v2。对实时性的含义：唤醒延迟上界已从「最长整片」缩到「唤醒方 syscall 出口」（G3 §2 P-B 目标，`docs/G3全抢占实施设计草案-v1.0.md`:50），但被中断任务的响应延迟仍受最长全屏蔽 syscall 段支配（见 1.3 尾与 ⑤ 缺口一）。

### 1.3 中断→调度延迟链：逐段代码锚与 R3 分解

链路全形（CNTV 定时器路，代码逐段可指）：

1. 硬件 IRQ → 异常向量（current-EL SPx / lower-EL 两臂）→ 保存 TrapFrame（`arch/aarch64/src/trap.rs`:280-302）。
2. `exception_irq` 入口：lockdep IRQ 地板快照 → GIC IAR ack → spurious 早退 → 唤醒源存入（`arch/aarch64/src/trap.rs`:538-554）。
3. CNTV（INTID 27）臂：`timer::handle` 先行 rearm（电平触发铁序——CVAL 按绝对截止时刻重编程，去活电平）→ `gic::end`（EOIR）→ 经 `IRQ_DISPATCH` 函数指针槽派发 `on_irq_tick`（`arch/aarch64/src/trap.rs`:559-569；`arch/aarch64/src/timer.rs`:184-191；EOIR-before-dispatch = ADR #32 防 GIC 优先级泄漏，`docs/调度器设计-v1.2.md`:227）。
4. `on_irq_tick`：par gate 早退 → `expire_timeouts`（SQ 窗内升序队列头未到期即早停，`sched/src/sched.rs`:2844-2869）→ `RR.tick` 记账（免锁——Σvruntime 账本 RMW 化，`sched/src/sched.rs`:3412-3420）→ slice==0 且 `preempt_count==0` → RQ 窗 `pick_next_filtered` 出选＋状态定形 → 授片（rearm 已在 IRQ 入口覆盖）→ `set_current` → `context_switch` 纯叶子 asm（`sched/src/sched.rs`:3539-3580；asm 形态 = ADR #30，`docs/调度器设计-v1.2.md`:222）。
5. 分段成本（R3 定谳，两源：`docs/阶段沿革.md`:5669-5671 ＋ `docs/系统优化路线图-v1.0.md`:40）：固定开销 300cy（向量＋帧＋GIC＋timer）＋ context_switch 135cy（FPSIMD 全量）＋线性增长项 pick +15cy/任务＋expire +80cy/到期者 → **基线 ≈830cy（550ns @A72-1.5GHz）、worst ≈2000cy（1.3µs）**。

三条关键旁路（非定时器唤醒的直切路径）：UART RX（SPI33）→ `rx_irq` 排空 FIFO 去活电平 → EOIR → woke 则 `SVC_EXIT_CHECKPOINT` 检查点（严格更高 eff 直切，`arch/aarch64/src/trap.rs`:571-590）；IPC fastpath send → `fast_wake_locked` 定点唤醒 → SQ 窗闭 → `try_preempt` 直切（`kernel/src/syscall.rs`:3224-3236）；跨核入队 SGI → CPU0 `on_sgi_resched` 快速重调度（不再等整 tick，`arch/aarch64/src/trap.rs`:617-624）。

idle/park 形态的两分口径（对唤醒延迟至关重要）：runqueue 空时按 `nearest_deadline()` 用 `arm_at` **oneshot 精确武装到最近到期时刻**、尽空则 mask CNTV ＋ masked-wfi 深睡（丢唤醒窗三步闭环收口，`sched/src/sched.rs`:3147-3168, 3184-3199；`kernel/src/main.rs`:5102-5164）——空闲核的超时唤醒是 deadline 精确的；但**忙核**（有任务在跑）上超时扫描只在 tick 跑（`expire_timeouts` 唯一驱动 = on_irq_tick，`sched/src/sched.rs`:3088-3091 注「tickless 精确 arm 到最近 deadline 留后」），唤醒粒度 = 1 slice（名义 100ms、TCG 实效 ≈200ms，`sched/src/sched.rs`:3426；R-1 实测短档 p50 被粒度支配，见 ②）。

中断响应上界的真实约束（推断，证据链在册）：SVC 主体 DAIF 屏蔽期间 IRQ pending 被推迟到 eret 后才受理，故「中断→任务」最坏延迟 = **最长全屏蔽 syscall 段 ＋ 2000cy 链**；除 send/recv 拷贝段局部解蔽外，其余号全程屏蔽（`kernel/src/syscall.rs`:269-273, 2989-2997），而最长段的全量表未成册——这是当前延迟上界论证的最大空白（详见 ⑤ 缺口一）。

## ② WCET 逐段 cycles（R3 ＋ icount ＋ 基线族）

R3 三路最坏上界主表（两源：`docs/阶段沿革.md`:5666-5683, 5725-5731 ＋ `docs/系统优化路线图-v1.0.md`:36-43，git 锚 91ce41c2 七十七轮）：

| 路 | 基线 | worst | 分解与条件 |
|---|---|---|---|
| 中断→任务 | ≈830cy（550ns @A72-1.5GHz） | ≈2000cy（1.3µs） | 固定 300cy＋ctxsw 135cy（FPSIMD 全量）＋pick 15cy/任务＋expire 80cy/到期者 |
| IPC fastpath | 典型 600-1200cy | ≈6.6k cy | 大头 = 跨 AS context_switch（640B）；slowpath worst = 1 slice 等待 = 100ms（内核执行仅 ~8.5k <1%） |
| PI 反转 | 形 A 单跳 ≈200ms | 链式 ≤8 跳 ≈800ms＋ΣCS | 形 B（runnable 受捐）已修（42a794e0）；形 C（Event/WAIT_ANY）无界，v2 再议 |

注意三点口径：其一，「IPC slowpath 1 slice 上界」是**条件上界**——依赖接收者优先级严格更高（`docs/阶段沿革.md`:5676）；其二，PI 形 A 的 200ms/800ms 数值两源在册但推导链未入册（推断：量级与 slice 相关，无逐段分解）；其三，2000cy 的分解里 135cy FPSIMD 项**已经过时**——FPSIMD lazy save 已于 2026-11-14 落地（X6 裁决书 P3-5 裁 GO，推翻 S4「无条件全量」；`fp_needed` 静态分诊：非 FP 任务快路径跳过 528B 拷贝，裁决书估 context_switch ~135cy → ~10-15cy 约 10×，`docs/X6批供与FPSIMD裁决书-v1.0.md`:36-50, 83；`arch/aarch64/src/task.rs`:65-79；实施笔 `.agents/notes/implemented/2026-11-14-fpsimd-lazy-save-dual-path.md`）——推断：非 FP 任务的中断→任务 worst 已低于 2000cy，但 R3 分解未随刀重测，引用需带时点。

微基准基线（git-tracked，`tools/sched_baseline.json` 2026-11-15 实读；两源：`docs/调度器架构白皮书-v1.1.md`:77-89）：pick=22cy（n=1000）/ freeze=6cy（n=200）/ billing=1cy / policy 注入 base=7/empty=7/full=9（**注入绝对开销恒 2cy**）/ wake p50=63cy、p99=63cy（n=128）。基线链带时点：21（2026-11-08 专项）→ 26（SLEEPQ per-key 同键链 +4cy）→ 22（现行 CI 基线，f7b5970a 刷新；`docs/调度器架构白皮书-v1.1.md`:89；`docs/调度器设计-v1.2.md`:425）；文档在册 freeze=5（`docs/调度器设计-v1.2.md`:419，11-08 时点）vs json 现值 6——引用一律带时点。真机验收线在册：pick <5µs@1k 任务（kill 线）/ freeze <5ms / billing <1µs（`docs/调度器设计-v1.2.md`:418-420 ＋ `docs/调度器架构白皮书-v1.1.md`:81-83，两源）；IPC fastpath <1200/<500 cycle（`docs/路线图-v1.2.md`:111）。IPC 实测：FAST rt_ticks=2737、direct 128/128 = 100% 直切率（`docs/阶段沿革.md`:5655 ＋ `docs/系统优化路线图-v1.0.md`:20，两源）。

## ③ 优先级反转 PI 面（berry-piface ＋ kernel/src/pi.rs）

双面结构：`piface`（berry-piface）= PI 捐赠图**纯函数面**（W3-Q5，host 可测钉板 18 测）——`donor_edge` 资格判（五拒：纯睡 / WAIT_ANY 哨兵 / 只等用户位 / 非 channel 对象 / peer 缺失；配对律：等 WRITABLE → recv peer 腾位、等 READABLE → send peer 灌入、双位并集）、`PI_MAX_HOPS=8` 轮帽、`HolderFace` 持有面抽象、`propagate` 不动点传播钉板（`piface/src/lib.rs`:1-31, 51-116）；`kernel/src/pi.rs` 的 `donor_edge` 机械壳**消费同一函数**（零第二实现，改 crate 语义 = 改内核行为；`kernel/src/pi.rs`:59-64, 209-246）。传播循环本身因零分配纪律留在 kernel（IRQ 屏蔽热路径不可建快照 Vec），crate 以同构钉板钉其语义（`piface/src/lib.rs`:10-11）。

机制形态：**全图重推、零增量簿记**——每次 SLEEPQ 变更（block 睡下后 / wake 摘队后，`set_sleepq_hook`）＋ handle close 后从零推导：清零趟（SLEEPQ 在队者＋本核 RQ 在环者）→ 不动点迭代 ≤8 轮（每轮沿捐赠边传播一跳，`d_eff` 实时读 `pi_inherited` 防链截死一跳）→ 尾趟刷 `prio_effective`（公式 = `max(base + 策略权重, pi_inherited)`，与 policy::apply 同一双写点；`kernel/src/pi.rs`:24-47, 89-200）。**P2 门控**（daa5ef7e）：双计数（等派生位睡眠者数 / pi≠0 睡眠者数）双零即整体跳过——常态零捐赠下 O(n²) 重推坍缩为 2 原子读（`kernel/src/pi.rs`:30-33, 100-102；`docs/IPC设计-v1.0.md`:118）。

三形覆盖现状：形 A（持有者在睡）PI 覆盖，单跳 ≈200ms / 链式 ≤8 跳 ≈800ms＋ΣCS；形 B（持有者 runnable，教科书 Mars Pathfinder 形）已修——recompute 三趟扩（清零含 RQ＋不动点含 RQ 受捐＋尾趟刷 RQ `prio_effective`），共享表护栏（`proc_tag==0` 的 runnable 者不受捐，防 boost 喷洒塌平全环优先级——fa 对实证 pong(32) 一睡全环喷到 32），42a794e0 落地、J8/J8b 新测试全绿（`kernel/src/pi.rs`:15-22, 110-171；`docs/系统优化路线图-v1.0.md`:41；`docs/阶段沿革.md`:5685-5689）；形 C（PI 禁用 / Event / WAIT_ANY 多源等待）**无界**，唯一逃生 = 超时——P3-4 v2 设防在册（`docs/系统优化路线图-v1.0.md`:222-229）。

边界与残留（如实）：Event 等待不构成捐赠边（无 peer 结构、signal 方多方，v2 再议；`piface/src/lib.rs`:64-65）；SMP 残留——RQ 扫描只罩本核环，对核环上的持有者需远核 RQ 锁（SQ→双 RQ 升序合法），v2 议（`kernel/src/pi.rs`:41-42）；轮帽到顶按已达 boost 处理不 panic（syscall 边界纪律，持有环在 max 语义下单调有界不发散，`kernel/src/pi.rs`:44-47）；冻结语义 = 受捐方唤醒离队时 boost 冻结随行带进 runqueue（4-3a pick 消费）、下次入睡被重推清零回落（「reply 即回退」的无 reply 等价物），长跑不睡者 boost 挂着——QNX 语义本就如此，v1 接受（`kernel/src/pi.rs`:35-40）；R3 定谳「形 B 关闭后 PI 面最后无界残余 = 形 C」（`docs/系统优化路线图-v1.0.md`:224）。验收面：PI ok 三任务链（pi_client(32)/pi_server(0)/pi_probe 字段断言）＋ PI-K 八用例（单跳判别/rights 门控两向/链式两跳/持有环收敛/11 节点链轮帽截断/哨兵与 Event 跳过/冻结随行回落）（`docs/IPC设计-v1.0.md`:118）；**「三任务链 client 唤醒延迟上界」的 G 卡用例留正式关卡未跑**（`docs/IPC设计-v1.0.md`:118 尾注）——PI 面有结构验收、缺延迟实测验收。

## ④ v2 工业 RT：QNX APS → band 对象化差距

目标在册（两源：`docs/路线图-v1.2.md`:45 ＋ `research/调度彻底计划/03-彻底计划骨架-刀序里程碑验证体系-v1.0.md`:90）：v2 攻工业 RT = cyclictest 级验收对齐 6.12 PREEMPT_RT 同数量级（µs 级软实时有条件可行）；**可证明 WCET / DAL A 不进承诺**。无悔件（PI、fastpath 分层、RT 静态池）已落设计位随 P4/M5 兑现。

QNX APS 事实底座（`research/06-QNX-Neutrino.md`:69-74, 113, 133-136）：APS（6.4/7.1）按线程组保证最低 CPU 百分比（100ms 平均窗口计量），分区数上限 8——官方解释 = **每次调度决策要扫描全部分区**（700MHz x86 上调度操作可达每秒 5 万次）；自适应性 = 空闲预算按策略分发 / LIMIT_CPU_USAGE 超借上限；critical budget 临界预算＋临界优先级（耗尽即 bankruptcy 处置）；管理面 = `aps` 工具＋`SchedCtl(SCHED_APS_*)`。**8.0 移除 APS**（两源一手：官方 IDE 文档 "QNX OS 8.0 does not support adaptive partitioning"，https://www.qnx.com/developers/docs/8.0/com.qnx.doc.ide.userguide/topic/APS_view.html ；QNX 员工论坛答复 post122632 "it doesn't fit with the new scheduler design"，https://community.qnx.com/sf/go/post122632 ）；确定性缺口由第三方 MotionWise Schedule 扩展包补位。SCHED-01 判例：**APS = 第一 kill criteria 判例**（策略焊进热路径、每次决策扫全部分区、分区硬上限 8；`research/SCHED-01-调度之王业界深研与综合裁决-v1.0.md`:28, 44；7.1 文档 https://www.qnx.com/developers/docs/7.1/com.qnx.doc.adaptivepartitioning.userguide/topic/about_howtouseguide_.html ）。

BerryOS 裁决（裁七，`docs/调度彻底计划-v1.0.md`:76）：**v2 工业 RT = band 的对象化升格，不是 APS 移植**——取 QNX 血统的词汇（预算包络 / 只在竞争时执行 / 空闲预算 loan / 整数微记账）与记账模式（client-pays 消息记账），结构上把 APS 的死因（策略焊进热路径）从设计里剔除。差异清单收口（`research/调度彻底计划/02-调度终态架构-三大支柱映射与业界对照.md`:122）：**APS 有而 band 无的只有「分区是一等 OS 对象」一件**（动态成员 / 继承树 / 命名分区）；band 有而 APS 无的是「不焊热路径＋AI 不可触＋入场券纪律」。键位已预留双键：`intent_effective`＋`Process.band_id`（`docs/调度器设计-v1.2.md`:382）。

现状盘点——已在册的件：band CBS 8 槽骨架（quota/period CBS 同形＋整数微记账＋事件驱动周期翻转，默认全关与接口缺席逐位等价；`sched/src/band.rs`；`docs/调度器设计-v1.2.md`:376-383）；band 热字全局原子账（SMPD-3 已落码 1869412f：fetch_add 单赢家＋翻期 CAS 防双翻）；admission ΣU≤0.95 已落（S5）；QNX 三件套词汇已列（`docs/调度器设计-v1.2.md`:137）。

差距清单（band → 分区对象 / v2 RT 的真实缺口，按刀序排）：

1. **分区非一等 OS 对象**：无动态成员 / 继承树 / 命名分区——band 只是 intent 键的查表行（裁七升格案的改造面）。
2. **band 执法未并线**：入场券（v1 遥测实证＋loadgen＋尾延迟断言＋空闲核金丝雀）未过，默认全关；现行执法 = throttle_all 环扫，lazy pick 执法（选核路径读账判超额）仍留 SMP 部署刀（`sched/src/band.rs` L61-62 注；`docs/调度器设计-v1.2.md`:385）。
3. **deadline-server 式兜底未实装**：FairBand 与 Fair 行为逐位一致（M4 骨架）；「每带都要包络」防中间带饥饿的设计未生效（`docs/调度器设计-v1.2.md`:137；`sched/src/class.rs`:495-511）。
4. **admission 公式不含 band 预算项**：deadline 满额时兜底必违约——CP-14/M5 补写（`docs/调度器设计-v1.2.md`:212；`docs/调度彻底计划-v1.0.md`:110）。
5. **RT 静态池零代码**：设计位在（§3.7，INTEGRITY-178「内核零动态分配」模式），M5 兑现；RT class_rt 未建。
6. **PI 形 C 无界**：Event/WAIT_ANY 面无 PI，P3-4/CP-17（`docs/系统优化路线图-v1.0.md`:222-229）。
7. **SMPD-0/1/2/5 未动**：多核基线钉板 / 跨核唤醒基准 / 跨核换表一致性 / 公平性验收全部未开（git 1869412f/078073be/54fc9b64 两源实测，`docs/调度彻底计划-v1.0.md`:210）——工业 RT 的多核面地基未打。
8. **验收体系未真机化**：CP-17 的 R-1 bench-rt 三档 δ 真机相＋CP-18 真机 HDR p50/p99/p99.9 门禁（`docs/调度彻底计划-v1.0.md`:118-119）。

CP-17 刀面在册：RT 静态池＋PI 形 C 设防＋FPSIMD lazy（`research/调度彻底计划/03-彻底计划骨架-刀序里程碑验证体系-v1.0.md`:90）——注意 FPSIMD lazy 已于 2026-11-14 提前落地（见 ②），CP-17 开刀时该项应改「已兑现」（推断：刀单需随迁）。裁七重议触发器在册：QNX APS 8.0 存废证实（已证实，见上）或工业 RT 需求提前 → 升格案窗口提前（`docs/调度彻底计划-v1.0.md`:190）——前者已成立，升格案的技术前提仍是差距 1-5。

## ⑤ 延迟上界论证能力：数学在册什么、经验在册什么、缺什么

**数学论证在册（可给闭式或条件上界的八件）**：①admission Σ(C_i/T_i) ≤ 0.95——EDF 单处理器利用率充分条件＋5% reserve，Q12 定点实现＋边界向量钉板（`safeck/src/lib.rs`:171-176, 451-472）——deadline 任务的系统级可行性数学；②CBS 预算执法——单任务每期至多 budget、超支 throttle 到下期，坏任务被节流而非破坏别人（`sched/src/class.rs`:271-283；`docs/调度器架构白皮书-v1.1.md`:50）；③PI 链式有界——≤8 跳轮帽＋max 语义单调有界（`kernel/src/pi.rs`:44-47），形 A 上界 ≤800ms＋ΣCS；④IPC slowpath 1 slice 上界（条件：接收者优先级严格更高，`docs/阶段沿革.md`:5676）；⑤中断→任务分段线性模型（300＋135＋15n＋80m）；⑥intent 传播三道帽（8 跳 / 每跳 50ms / 链累计 400ms，超顶降级不传播——seL4 Johnston 2022 失控服务链判据，`docs/IPC设计-v1.0.md`:39-42, 120）；⑦band CBS 包络数学（quota/period）——形状在、执法未并线；⑧EEVDF lag 有界——在册为 CP-07 验收线（「EEVDF lag 有界跨核成立」）但未验（`docs/调度彻底计划-v1.0.md`:98）。公平性实测 spread=0（`tools/sched_baseline.json`）。

**经验论证在册（测量面五件套）**：HDR 897 桶双路直方图（保守上界分位）＋R-0/R-1/bench-lat 三路延迟基准（唤醒等待 / cyclictest oversleep / wake→run 双路）＋icount 确定性通道（五跑 prove verdict=exact、L2 逐值精确相等——「同指令流必同数」的强可复现性）＋基线 git-tracked 带时点链＋soak 常驻尾延迟帽执法（G3-5c 帽 24561/62184750 进 12 拍执法跑）。口径纪律自洽：QEMU 只报功能 / 顺序 / 相对趋势，绝对分位与功耗属真机（`docs/调点调度-v1.3.md`:248-249；`docs/调度彻底计划-v1.0.md`:23 原则⑦）。

**缺口清单（按对「全系统延迟上界」的阻碍排序）**：

1. **长屏蔽窗无全量表（最大空白）**：SVC 主体除 console/pipe 两域外全程 DAIF 屏蔽（`kernel/src/syscall.rs`:269-273；`docs/G3全抢占实施设计草案-v1.0.md`:108），中断响应上界 = 最长全屏蔽段＋链路 2000cy，但 per-syscall 屏蔽段长度未成表；icount 通道（B-2）与六项原语代理已具备，扩到 syscall 全号是纯工程量（推断：以 `--icount` 收割每号往返指令数代理即可立表）。
2. **形 C 无界**：Event/WAIT_ANY 面反转无界，唯一逃生 = 超时（P3-4，v2）；且 PI 面的「三任务链 client 唤醒延迟上界」G 卡用例留正式关卡未跑（`docs/IPC设计-v1.0.md`:118）——结构验收有、延迟实测无。
3. **忙核唤醒粒度 = tick**：`expire_timeouts` 只在 tick 跑、忙核无 arm-to-nearest-deadline，R-1 实测 δ=¼slice 档 p50=5367438cyc ≈ 0.86 slice（名义 100ms、TCG ≈200ms）——对 µs 级软实时目标是数量级不符的最大单项；idle/park 形已用 `arm_at` oneshot 精确武装（`sched/src/sched.rs`:3152-3158），忙核补齐是明确改造点且 R-1 即验收面（`docs/基准与压力测试设计-v1.0.md`:350-352）。
4. **多核跨核上界未测**：SMPD-1 跨核唤醒基准未建；TCG 下 SGI 路 p50≈10.5M cyc 被宿主 vCPU 调度主导，内核机件下界只见 min≈18187cyc（`docs/G3全抢占实施设计草案-v1.0.md`:203）——跨核唤醒的内核侧上界当前**不可测**，须等 SMPD-0 基线＋真机。
5. **R3 数字时点化未刷新**：FPSIMD lazy（2026-11-14）改了 context_switch 分解的 135cy 项，中断→任务 worst 未重测；引用须带时点（基线链 21→26→22 的漂移史已是先例）。
6. **admission 不含 band 项**：deadline 满额＋band 兜底并线后若无 band 项，兜底必违约（CP-14 补写）。
7. **无静态 WCET 工具链**：循环界 / 屏蔽段 / 锁持有段无静态分析面；论证形态 = 测量＋结构不变量（lockdep 七类全序＋持有链、preempt_count 配平断言、金丝雀），非形式化验证——「WCET 可证明 / DAL A 不进承诺」正是对此的诚实立法（`docs/路线图-v1.2.md`:45；`docs/调度彻底计划-v1.0.md`:118）。

**论证能力总评**：「分段测量＋结构不变量＋条件化上界」三层体系已成型，在册数字均可复现、带时点、两源（或标注单源）；对齐 6.12 PREEMPT_RT 数量级的 µs 级软实时，现有路径可信但差三件硬前提（屏蔽窗全量表、忙核定时粒度、多核面）；对可证明硬实时（DAL A）明确不承诺——与路线图立法一致，不是欠账。

## ⑥ 对位建议（不推翻在途刀序，仅收口建议）

其一，CP-14（admission 显式含 band 项＋超支三档处置＋SET_POLICY 门控）是实时性面最近的刀，建议把「PI 三任务链 G 卡延迟用例」一并收编——结构验收已全、只差延迟实测（`docs/调度彻底计划-v1.0.md`:110；`docs/IPC设计-v1.0.md`:118）。其二，CP-17 开刀时建议增列「屏蔽窗全量表」子件（syscall 全号 icount 化或 lint 面）——这是中断上界论证的最大空白且载体已在（B-2 通道），纯工程量（推断：一至两刀量级）。其三，忙核 arm-to-nearest-deadline 是 µs 级软实时的先决改造，挂优化议程或 CP-17 前置（R-1 即现成验收面）。其四，R3 三路数字建议随 FPSIMD lazy 关账刷新一版（P3-5 尾款），否则 2000cy 的引用会系统性高估现状。
