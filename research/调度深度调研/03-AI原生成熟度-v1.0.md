## §0 结论速览

1. **总判词：管道建成早于水——注入机制面（AI 调度的「机制预留」半）已超额落地，语义消费面（「AI 真正改变调度行为」半）几乎全部待接。** 0x83 policy_bind 六 op＋三槽 RCU＋shadow 双轨＋divergence per-CPU 对账＋±64 三点夹紧＋RIGHT_MANAGE 门控全部在码且 QEMU/host 双面钉板（[kernel/src/syscall.rs](../../kernel/src/syscall.rs):2625-2800、[sched/src/policy.rs](../../sched/src/policy.rs) 全文）；而 intent 六档至今在调度器内部的硬消费点为零——latency_nice 列无人读、`Task.epp` 单写零读（本轮 grep 实测：写点恰 [policy.rs](../../sched/src/policy.rs):414 一处、sched 域读点零）、M4 带骨架运行面零可达（[12 号复核](../调度彻底计划/12-终窗复核.md):72 全仓普查）。这不是债务堆积，而是 ADR #42「查表键先于消费者落地」＋裁六「入场券未过不并线」两条立法的**主动形态**——但意味着「AI 原生」当前的兑现度 = 机制在位＋轨道在跑的前半句，判据在册的后半句还缺第一份样本（§3）。
2. **intent 消费链九环盘点：四环已通（编码冻结 / 消息传播 / 遥测落盘 / 权重·EPP 注入）、三环骨架（IntentProfile 查表 / M4 带实例 / band CBS 预算）、两环未接（latency_nice 与 timer slack 的内核消费、telemetry_open 用户态映射）**——逐环证据见 §1.1 总表；已通环里唯一「注入真实改变出选」的动作只有 ③权重与 ④EPP（且 EPP 也只是落 TCB 字段），①placement 半接（TCB 落点＋读出口在、选核三路未接），②频率 hint 按裁十债二根本不走 policy 表（归 PM 面，PM 服务本体未挂接）。
3. **策略注入就绪度：机制面就绪度高于设计文档的记载**——代码已带 RIGHT_MANAGE 能力门（arch-r2 收口，[syscall.rs](../../kernel/src/syscall.rs):2707-2725），而《策略服务用户指南》与《调度器设计》v1.2 仍写「v1 无 handle 门控」（[策略服务用户指南](../../docs/策略服务用户指南-v1.0.md):41、[调度器设计](../../docs/调度器设计-v1.2.md):316）；《AI调度设计》§3 的「共享环」传输表述也已被裁十债二「0x83 16B×≤128 直传、不建共享环」终裁取代而代码即直传形态（[调度彻底计划](../../docs/调度彻底计划-v1.0.md):82）。三处文档漂移是 CP-01 重锚的现成对象（§2.4）。v3 剩余工作量五件：telemetry_open 0x84 消费路径、per-thread 键、band 位写路立法、Job 级 SET_POLICY 门控、注入传输表述改口（§2.3）。
4. **kill criteria 证据状态：判官工具齐、判据数字零样本。** 判据在册（M4 前可复现 A/B 无可测尾延迟/能耗收益 → 永久 hint-only，ADR #21 修订，[架构决策](../../docs/架构决策.md):30）；divergence 双计数＋per-CPU 分账、policy_ab_eval 判定器（阈值 <0.1 PROMOTE / >0.5 DEMOTE）、HDR 897 桶、advisor 确定性生成、AIDEMO 端到端活证全部在位；但**首份真实 A/B 对照报告未产出**（CP-06 未动）、负载驱动 harness 未建（调点 v1.2 遗留）、SMP A/B 形态未裁、能耗收益属真机门控（第二级特征 QEMU 无意义，[AI调度设计](../../docs/AI调度设计-v1.0.md):54）。关键 nuance：divergence 率是「决策一致率」代理判据，不是「尾延迟/能耗收益」本体——kill criteria 的真判据链（HDR A/B 对照）尚未闭合过一次（§3.4）。
5. **业界新范式判词（2026-11-15 一手直取）：LAVD 量产化验证了 (B) 分类器路线，但形态与 BerryOS 相反。** LAVD 已从游戏扩展到服务器（42 名开发者、900+ 提交、约 12000 行，LWN 单源），核心 = criticality ∝ 等待频率×唤醒频率/平均运行时长＋双向继承、EM 启动期分析成「负载级→核集」查表、cgroup 限流走 eventual enforcement（贵记账移出热路径）；它宣布将部分回上游 EEVDF。ghOSt 仓已 404（本轮直取），佐证「Google 亲手否定常驻用户态代理形态」判词。learned index 一脉（Kraska 2018）的「索引即模型」恰是 BerryOS 反方向：查表即策略——用确定性小表换可审计性（§4.5 差异五点）。
6. **路线图主链（§5）：入场券判定刀 → CP-12 band 并线（或「查表键即终态」关账分支）→ CP-13 分类器 v3（只对 UNSPECIFIED 定档）→ CP-14 admission/SET_POLICY/stats → CP-06/CP-15 kill criteria 复核关账 → CP-16 (A) 学习策略（复核不过则永久不开）。** 当前全链位置：M4 骨架已落（2026-11-15，HEAD 01cd881b2），入场券四件（v1 遥测/loadgen/尾延迟断言/空闲核金丝雀）在册未判，SMPD-0/1/2/5 未动是链上最硬的外部阻塞。
7. **身份支柱措辞张力仍未消：对外 README 仍宣称「AI-native by construction」**（[README.md](../../README.md):5/:23），与 ADR #21 降级（机制预留＋实验轨道＋kill criteria）的措辞差归 owner 拍板（调度彻底计划开放问题 9，[调度彻底计划](../../docs/调度彻底计划-v1.0.md):205）——机制面零改动，纯措辞对齐。

### 1.2 已通环补充：注入真实改变行为的唯一路径

- v1 现役注入链完整形态：policy 表（key = `Task::proc_tag`）→ pick 出选后 `apply`（[policy.rs](../../sched/src/policy.rs):391-424）→ `prio_effective = max(prio_base + 夹紧权重, pi_inherited)`（:411，与 PI 捐赠同公式）＋ EPP 直赋（:413-414）＋ placement 落 TCB（:421-423，双门 `placement≠0 && par_enabled`）。「注入真实改变出选」自 4-3a 起是断言不是口号——ktest `POLICY ok` 空表等价（12 轮逐项全等）＋对照表用例 eff=32 者独占出选（[AI调度设计](../../docs/AI调度设计-v1.0.md):118 v1 落地注记；[policy.rs](../../sched/src/policy.rs):11-14 模块注两源）。
- intent 与 policy 两轴的交点在宿主侧不在内核：advisor 读遥测行的 `intent=` 字段生成建议（[tools/advisor.py](../../tools/advisor.py):51-66 规则族——intent∈{1,2} ＋16、intent==5 −8、wake>100 ＋8、policy==3 RT 屏蔽、key==0 哨兵跳过），内核侧两轴互不感知——这正是 ADR #21「band/intent 不入 AI 动作空间」带内纪律的形态（[policy.rs](../../sched/src/policy.rs):271-273 注）。
- 应用模型侧已有第一个 intent 消费位（本表之外）：freeze 单轴消费表 freeze 级首消费位已落（tomb_selftest freeze-first，`FROZEN ok n=1`，ADR #42 追记 [架构决策](../../docs/架构决策.md):51；`WAKE ok n=1` 随 AM-1.5 落）——属 AM 线非调度器内部，如实分账。

### 1.3 消费面总判词

intent 的「机制承重」全部落地（编码冻结、传播、帽、遥测、查表数据、带参数行），「行为承重」零并线——每一条行为消费（latency_nice、EPP、slack、带选择、band 执法）都有明确的入场券/接线窗立法在先（[调度器设计](../../docs/调度器设计-v1.2.md):134-139 第二段、[调度彻底计划](../../docs/调度彻底计划-v1.0.md):74 裁六），且全部预留窗都有注释锚（[class.rs](../../sched/src/class.rs):527-534 工厂窗、[sched.rs](../../sched/src/sched.rs):1112-1117 spawn 窗、[band.rs](../../sched/src/band.rs):12-15 执法窗）。**「查表键先于消费者落地」不是口号而是可验证的结构事实：九环中每一环的未接都有 host 钉板面先行（intface 18 测 / iprofile 23 测 / slackface 12 测 / bandface 6 测，[12 号复核](../调度彻底计划/12-终窗复核.md):10）**——这是 BerryOS 与「先写调度器后补测试」路线的结构差。

### 3.4 状态判词与一个关键 nuance

**证据状态一句话：kill criteria 从 2026-10-16 立法至今零次真实复核——判官工具（divergence 计数、ab_eval、HDR）全部在位，但一次都没开庭。** 关键 nuance：divergence 率是「shadow 会做的 ≠ active 做了的」**决策一致率**，不是「尾延迟/能耗收益」**性能差**——policy_ab_eval 的 PROMOTE/DEMOTE 阈值是升级工作流的代理判据（决策一致性 ≠ 收益），kill criteria 的真判据（可复现 A/B 可测尾延迟/能耗收益，95% CI 口径对齐 KC-P2/ADR #68）需要 HDR A/B 对照报告承载，这条链的第一环（CP-06 首份报告）未动。**当前没有任一证据项指向「该 kill」或「不该 kill」——证据面空白而非证据面不利**，与「轨道在跑、判据在册、样本为零」的 day-one 设计自洽（裁五）。

## §4 调研④：业界新范式（sched_ext / LAVD / learned index）与 BerryOS 定位差异

### 4.1 LAVD：分类器路线的量产活证，形态与 BerryOS 相反（一手直取 2026-11-15）

来源：[LWN.net 1097209](https://lwn.net/Articles/1097209/)（Jonathan Corbet，2026-10-07，Kernel Recipes 2026 报道；LAVD 规模数字为该文单源）。

- **规模与演化**：2023 年为 SteamOS 游戏 stutter 起家 → 服务器负载（Meta 内部探索使用）→ 未来方向 GPU 调度；42 名开发者、900+ 提交、约 12000 行代码（单源如实标注）。
- **核心启发式（与 BerryOS (B) 分类器同族）**：criticality ∝ 等待频率 × 唤醒频率 ÷ 平均运行时长；criticality **双向继承**（向它阻塞的与阻塞它的两个方向传播）——与 BerryOS PI × intent 联动同构，但 BerryOS 有每跳 50ms＋链 400ms 的显式界（[调度器设计](../../docs/调度器设计-v1.2.md):87），比 LAVD 更可审计（02 号:104 判词同向）。
- **决策面**：截止期除以 criticality（越关键越提前）；锁持有者永不抢占；不用 IPI 强抢、缩短目标时间片让其自然让出；per-L3 域一个派发队列；按 weight（工作量）而非任务数均衡；turbulent/steady CPU 分类放置；cache warmness 衰减决定迁移。
- **能效面**：启动期把内核 EM 分析成「负载级 → 该用哪些核」查表——**与 BerryOS EM 表形状（kHz/mW/capacity 三元组，[调度器设计](../../docs/调度器设计-v1.2.md):350-357）＋查表取向同构**，LAVD 是它在 BPF 侧的量产印证。
- **cgroup 限流**：新库 scx_cgroup，模型 = **eventual enforcement**（单期不节流、长期均值平衡）——贵记账移出调度关键路径，与 BerryOS 事件驱动记账＋慢循环重算（band.rs 绝不复活周期 tick）同构。
- **回上游**：Min 确认将尝试把部分想法上馈 EEVDF——「BPF 生态孵化 → 主线 fair 底座收编」的单向阀。

### 4.2 sched_ext：整核热切换的契约面（一手直取 2026-11-15）

来源：[docs.kernel.org scheduler/sched-ext.html](https://docs.kernel.org/scheduler/sched-ext.html)（7.4.0-rc2 文档树）。

- BPF 程序集定义整个调度器类，可随时动态开关；**任何错误 / runnable 停滞 / SysRq-S 即整核回退 fair 类**——「失效回退」契约与 BerryOS「AI 崩 → 内核回退启发式」同源思想。
- `SCX_OPS_SWITCH_PARTIAL` 支持部分切换（仅 SCHED_EXT 策略任务）；bypass 模式（加载/卸载/错误恢复期 5ms 缺省片）；子调度器（`CONFIG_EXT_SUB_SCHED`）——生态仍在加表达能力。
- **ABI 明示无稳定性保证**（「The APIs provided by sched_ext to BPF schedulers programs have no stability guarantees」）——BerryOS 冻结面「原地升版不翻契约」（[调度器设计](../../docs/调度器设计-v1.2.md):60/:429）的对照面。

### 4.3 ghOSt 终局：用户态代理形态的自我否定（一手取证）

- github.com/google/ghOSt 本轮直取 **HTTP 404**（2026-11-15）——仓已删除或私有化。这与仓内判词「Google 正把 ghOSt 迁往 in-kernel BPF，等于亲手否定常驻用户态代理形态」（[AI调度设计](../../docs/AI调度设计-v1.0.md):11；SCHED-01:9 同判）方向一致；仓删除这一事实本身是比转述更强的旁证（注：404 也可能为改名/私有化，归属判断仍以 LWN/kernel 生态报道为准——本条如实记取证方法）。
- 对 BerryOS 的含义分层：被否定的是「**常驻用户态代理做逐决策**」形态（ghOSt 的 per-CPU agent 每次调度参与），不是「策略在用户态」本身——BerryOS 慢/快循环切分（用户态只做 10-100ms 慢循环重算表、快路径零参与）恰是 ghOSt 死因的结构规避（[AI调度设计](../../docs/AI调度设计-v1.0.md):23/:27-37）。

### 4.4 learned index 一脉：BerryOS 取其问法、弃其答案

来源：[arXiv:1712.01208](https://arxiv.org/abs/1712.01208)（Kraska et al.，「The Case for Learned Index Structures」，2017-12 提交 / 2018-04 v3）。

- 核心命题「索引即模型」：B-Tree/Hash/BitMap 都可换成学习型模型，实测 NN 比 cache-optimized B-Tree 快至多 70%、省一个量级内存——「核心组件可否被学习模型替换」的问法源头。
- BerryOS 的 IntentProfile / IntentBand / EM 查表是**同一问法的反方向答案**：结构（表）不用模型，模型（advisor）只产表——查表即策略、模型不在热路径。这与 learned DVFS / learned scheduling 研究线（[AI调度设计](../../docs/AI调度设计-v1.0.md):142「思路」引用）的关系是：**v4+ (A) 路线若开，学的是「表的参数」不是「调度器结构」**——动作空间四类封顶不因模型到场而放宽（[架构决策](../../docs/架构决策.md):30）。
- 定位差异【推断】：端侧（手表/手机）算力与能耗预算下，learned 结构的推理开销-vs-收益比劣于服务器端——BerryOS 平台分层（手表不上 advisor，[AI调度设计](../../docs/AI调度设计-v1.0.md):98）隐含此判断。

### 4.5 BerryOS 定位差异判词（五点）

1. **插拔轴不同**：sched_ext 插拔「程序」（BPF 整核）、Zephyr 插拔「队列」、QNX APS 插拔「调度器」；BerryOS 插拔「**策略数据**」（三槽表换表）——最粗粒度、最稳、no_std 可行（02 号 §4.1；[调度彻底计划](../../docs/调度彻底计划-v1.0.md):66 裁二）。
2. **可 A/B 性是结构差异不是工程差异**：影子双轨＋并行对账＋对账驱动自动升级判定在 Linux sched_ext / ghOSt / Zircon / Xen credit 四家参照中均为空白（[白皮书](../../docs/调度器架构白皮书-v1.1.md):93-103 对标表；02 号:84 以 2026-10 LAVD 新证据复核维持判词）；LAVD 的 eventual enforcement 演化反向趋同「可 A/B、可回退」形态。
3. **表达力换取保守性是自觉裁决**：BPF 能写任意数据结构 vs BerryOS 四类动作封顶＋16B×≤128 直传——「动作空间的保守性就是系统的保守性」（[AI调度设计](../../docs/AI调度设计-v1.0.md):46）；内核 ~750 行策略面（policy.rs 本轮实测 752 行）＋宿主侧确定性 advisor 的可测试/可回退/可审计占优（02 号:104 差异判词）。
4. **分类器两线并存的自我定位**：LAVD criticality 推断量产化验证了 (B) 路线可行性（[调度彻底计划](../../docs/调度彻底计划-v1.0.md):72 裁五引），BerryOS 分类器（CP-13，只对 UNSPECIFIED 定档、独立内核裁决通道、错只错一档）比 LAVD 的全量推断更保守——推断是兜底不是主路径（[AI调度设计](../../docs/AI调度设计-v1.0.md):108）。
5. **与上游关系**：BerryOS 不追 sched_ext ABI（不稳定性保证与冻结面哲学冲突），但持续吸收其契约面（有界动作集、失效回退、热切换思想——SCHED-01 裁决「借契约不借实现」，02 号:28）；重议触发器 5 挂「LAVD/sched_ext 若把影子双轨＋A/B 判定变上游标配，裁三判词重述」（[调度彻底计划](../../docs/调度彻底计划-v1.0.md):187）。

## §6 风险与开放问题（AI 原生成熟度视角）

1. **「机制在位、样本为零」的叙事风险**：对外 README 的 AI-native 宣言（[README.md](../../README.md):5/:23）与 ADR #21 降级的张力（开放问题 9，[调度彻底计划](../../docs/调度彻底计划-v1.0.md):205）——在 CP-15 出果前，「AI 原生」的可辩护表述 = 机制预留＋遥测优先＋实验轨道＋kill criteria（机制面零改动，纯措辞）。
2. **kill criteria 复核点未锚**（开放问题 3，:199）：「M4 前」若不锚 CP-13 前，分类器上线后复核就带沉没成本——建议采纳「分类器是最后一个无收益也可上线的 AI 件」锚点【推断：同计划建议】。
3. **能耗半句在真机前原理性不可测**（§3.3）——若 M4 窗口（CP-12/13）先于真机相（CP-18）完成，CP-15 复核只能裁尾延迟半句，能耗半句的 kill/豁免须预立口径【推断】。
4. **divergence 率代理判据的误用风险**：PROMOTE 阈值 0.1 是「决策一致」不是「收益为正」——若把 ab_eval 输出直接当 kill criteria 证据会系统性误判（§3.4 nuance）；建议 CP-06 报告模板把两者分列【推断】。
5. **intent 传播通胀单点风险（设计自载）**：高频公共服务被 LC 客户端触达后整条链向顶带收敛——计数器（borrows/infl/hop_cap/bud_cap）是可观测信号，但 M4 前无带间执法面，通胀只观测不治理（[调度器设计](../../docs/调度器设计-v1.2.md):87 自载「最大单点风险」）。
6. **文档漂移三处（§2.4）**——CP-01 重锚时的最小清单，均为文档落后于代码方向，修文档不修代码。
