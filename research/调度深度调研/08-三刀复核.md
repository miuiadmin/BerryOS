## §1 刀① shadow hazard 验证环——复核通过

### 1.1 代码面核验(只读)

协议与先例的比对结论 = **逐位同律**:`shadow_snap` 的验证环([sched/src/policy.rs:543-561](../../sched/src/policy.rs))走 `SHD_GATE.reader_enter`(load(Acquire) 活跃槽 → hazard[cpu] store(Release) → fence(Acquire) → 复读验证未翻转、翻了换槽号重发),与 `active_snap` 先例(policy.rs:229-259)同一形态;写侧 `bind_gen_shadow`(policy.rs:579-601)持 POLICY_LOCK 窗内 `pick_write` 避让「活跃 ∪ hazard」(:589)→ 槽写 → `publish`(fence(Release) + 翻转,:599),同 active 侧 publish 先例。协议判定律单源 `berry-polface::HazardGate`([polface/src/lib.rs:365-433](../../polface/src/lib.rs)):三公共方法(`reader_enter` :386 / `pick_write` :406 / `publish` :429)零 unsafe,裸指针 SAFETY 全在消费侧挂——crate 边界纪律成立。旧 `SHD_WHERE: AtomicU8` 删除无残留(import 表已清);`SHD` 双槽→三槽(policy.rs:531)同 SNAPS 几何,「活跃 1 + hazard 收敛 ≤2 恒有空闲」论证复核成立;`promote` 在锁窗内经 `shadow_snap` 验证环「首验即过」的论证复核成立(单写者持锁时活跃位无翻转面);`shadow_reconcile`(policy.rs:713 起)与 `shadow_gen`(:562-568)的 SAFETY 注均随新协议改写,无陈旧表述残留。协议正确性推演:读者先发 hazard 后读数据、写者先读 hazard 后写槽,定序配对使在窗读者的槽永不被复用;读者出窗不清位的简化只多避让不损正确性(陈旧位护得更久,安全方向)。

### 1.2 host 竞争测试真跑实录

`cargo test -p berry-polface` **18 测全绿**(14 存量零漂移 + 4 新)。竞争两测本复核各 3 连跑:V6-c 正向(polface:797,两写者 Mutex 串行 × 3000 轮背靠背双换 + 两读者紧循环)三跑分别 **505347/525469/583182 读、11999/11994/11998 次换表穿越,零撕裂零回退**;V6-d 负对照(polface:935,同载荷复刻修复前双槽 XOR 协议)三跑各捕 **135/69/117 次撕裂**——载荷灵敏度实证,正向绿是协议承压不是载荷不足。V6-a 避让确定性律(polface:739,含陈旧位避让与 cpu 钳位)与 V6-b 满覆盖 canary(polface:764,should_panic 过)均绿。

### 1.3 QEMU 面

### 1.4 残留与注意(不返工理由)

## §2 刀② 忙核 oneshot 三件套——复核通过(δ 塌缩实测)

### 2.1 代码面核验(只读)

三件套落点与任务书/实施笔记逐位对上:件一 = `on_irq_tick` expire 后收紧([sched/src/sched.rs:3406-3423](../../sched/src/sched.rs),`tighten_deadline(nearest_deadline(), armed)` :3421);件二 = 超时唤醒出口检查点(:3436,`expired && preempt_count()==0` 才 `try_preempt`——G43 防 PRINT_LOCK 窗,同 slice 燃尽支门);件三 = `block_current` 忙核授片臂收紧(:2491-2507,SQ 窗内直读队头)。收紧律单源 [sched/src/oneshot.rs:32-37](../../sched/src/oneshot.rs):仅 nearest 严格早于 armed 才收紧,永不推迟。三个机制关要本复核逐一实证:①**S-6 夹取保收紧**——`arm_slice`([arch/aarch64/src/timer.rs:147-156](../../arch/aarch64/src/timer.rs))「cur > now && cur < want 即 return」,后续任何授片臂不会把件一/件三已收紧的更早截止推走,tick 处理器一切后续路径带收紧值离场的论证代码级成立;②**件三无自死锁**——`block_current` 的 SQ 窗(:2428 取锁)在收紧点(:2501)仍持,直读队头免 `nearest_deadline`(sched.rs:3985,自带 sq_lock)同核重锁;③**idle/park 零改**——git diff 证 sched.rs 仅三 hunk(block_current/expire_timeouts/on_irq_tick),idle_loop 与 secondary_main park 环一字未动,timer.rs 仅模块头文档;RR.tick 实耗记账未涉(class.rs 零 diff,早 tick 不多扣片为存量行为)。`expire_timeouts` 改返 bool(sched.rs:2870)签名变化消费面唯一(on_irq_tick :3406),空转 tick 零成本跳过属实。

### 2.2 host 律钉板 + QEMU smoke

`just test-oneshot` **7 测全绿**(t1-t7:无到期保持/严格早即收/同值幂等/永不推迟/过期头即醒/极值域/单调律全域抽查)。QEMU 三相:裸相单核 32 标记全绿且忙环舰队全程 kl=0(switches 金丝雀 3500 次连续,刀②代码在忙核热路径连续承压);DEMO=off 相(`opt/berry/demo-face,string=off`)ktest done + 活金丝雀正常推进——两个定时内核任务间 runqueue 反复腾空,idle_loop/park 循环实走(推断:park 计数器仅 soak 相打印,本相以「零 panic + 活性正常 + 该路径零 diff」三证收口);SMP 双核绿(§1.3 同跑)。

### 2.3 R-1 δ 观测(本复核唯一新增实测,验收面兑现)

官方口 `bench.py --rt` 被 QEMU 守卫拦(在场 6 实例均他会话长跑 GUI 相,帽 900s 等空不现实)——改**手工同形直跑**(裸内核 + `-fw_cfg name=opt/berry/rt,string=1`,与 bench.py run_rt 同 QEMU 形态,timeout 150s):`RT ok n=96` 全采,三档 BENCHRT:

| 档 δ(cyc) | 旧 p50(首验收实录,[docs/基准与压力测试设计-v1.0.md:346-352](../../docs/基准与压力测试设计-v1.0.md)) | 本复核 p50 | p99/max | 塌缩倍数 |
|---|---|---|---|---|

判读:旧值三档平坦在 ≈3.5-5.4M cyc(≈0.56-0.86 slice)是「唤醒粒度 = 1 tick」的签名;新值塌到 ≈1.6-2.1×10^5 且不再与 slice 尺度挂钩——粒度地板已除。场景正主性:rt_probe 以 **prio 8** spawn(kernel/src/main.rs:1798)对 prio 0 忙环舰队共存(日志舰队字母与 BENCHRT 行交错),件二「严格更高 eff 片内直切」场景即被此测。残留 ≈2×10^5 cyc 高于实施方推断的 10^3-10^4 量级——推断:宿主 6 QEMU 实例负载下 vCPU 被宿主调度推迟主导(TCG 墙钟噪声只增不减,02 号 §② 同款污染实录),机制下界需静窗复测;但 16-33× 塌缩与签名消失在负载口径下已充分定谳。
