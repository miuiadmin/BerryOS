## §1 六面 Top-3 发现与对 CP-01..CP-19 的影响

六面构成(推断,按四分册材料正交分解):SMP 并发面 / 实时性面 / AI 原生与策略注入面 / 业界演化面 / 能效 PM·EM·拓扑面 / 观测·测试·文档面。每面 Top-3,共 18 条;每条给锚与 CP 影响。总影响判定:**无一条推翻在册刀,无一刀可删;七刀建议修订,五处建议新增子件**——详 §1.7 汇总表。

### 1.1 SMP 并发面(01 号主承重)

1. **shadow 侧 hazard-lite 验证环缺口是全体系唯一机制级真缺口**:`policy.rs` 代码自认「hazard-lite 槽回收 shadow 侧未覆盖——shadow 槽数据的跨核读写仍靠现状串行,留后续刀」(本轮复抽 [policy.rs](../../sched/src/policy.rs) SHD_WHERE 注,01 号 §5.1 两源);机制推演 = 写者背靠背两次换表可覆写读者刚进入的槽,双核终验 60 ok 未触发的原因是终验载荷无背靠背 SHADOW_COMMIT 序列(01 号推断,分册标注)。**影响:CP-04 必须修订**——换表金丝雀若含 SHADOW_COMMIT op,该缺口是第一现场,不补环则金丝雀测的是缺口不是协议(01 号 §五.1 行动项)。
2. **双核终验后竞争面呈「一真缺口 + 三已知有界窗 + 一阻塞楔死」结构,无无主新增竞争面**:sum_vruntime 二元组撕裂(≪ 丢更新窗三个量级)、band 超卖窗(上界每核一份 delta)、throttle_all 只扫调用核 rq、SLEEPQ 全局双 arm 冗余(至多一次冗余醒)——四件各有归口相(BAND-S/POLICY-S)或有界可受;HEAD 新落件(M4 骨架/idle 闭合)守住「骨架不实装、单核分支隔离」纪律(01 号 §5.2-§5.5)。**影响:CP-02/CP-05 维持**——阻塞归因收窄为 X-6 一项(SMP 三虫已根治,01 号 §二.1),BAND-S 相断言清单不变。
3. **4/8 核五类瓶颈全部在册有解,唯一结构性依赖是拓扑字段**:定长 2 硬编码、「对核」二元假设、全局单锁热点(SQ/DL_ON_RING)、SpinLock 1B 无对齐伪共享、TCG 非确定性放大(01 号 §3.1);业界解法两层均有在册先例(per-CPU 分账同形 hdr/divergence 已落、MCS/qspinlock 判例在册)。**影响:CP-19 修订**——llc_mask 随扩容刀同批落、SpinLock 对齐审计升格低垂子件(详 §3)。

### 1.2 实时性面(02 号主承重)

1. **deadline 机制真落码且数学单源,但「全系统延迟上界」论证差四件硬前提**:EDF 带序 + CBS 预算 + ΣU≤0.95 准入全部在码(02 号 §1.1,锚 class.rs/safeck.rs);缺口 = 长屏蔽窗无全量表(SVC 主体除 console/pipe 两域全程 DAIF 屏蔽)、PI 形 C 无界、忙核唤醒粒度仍是 tick、多核跨核上界未测(02 号 §⑤ 缺口清单)。**影响:CP-17 修订**(增列子件、删已兑现项)+ **CP-14 修订**(PI 三任务链 G 卡延迟用例收编——结构验收全、延迟实测零)。
2. **忙核唤醒粒度 = 1 tick 是 µs 级软实时目标数量级不符的最大单项**:R-1 cyclictest 实测 δ=¼slice 档 p50=5367438cyc ≈ 0.86 slice(单源实录,02 号 §②),idle/park 形已用 arm_at oneshot 精确武装而忙核 expire_timeouts 只在 tick 跑——同构机制补齐即塌缩该档。**影响:CP-17 前置位(或优化议程独立小刀)**,R-1 即现成验收面。
3. **测量底座可信但覆盖面窄**:icount 确定性通道五跑 verdict=exact、L2 逐值精确相等,但六项全是内核原语,不是 syscall 全集;FPSIMD lazy(2026-11-14 落地)已改 context_switch 135cy 项,R3 三路数字未随刀刷新,引用会系统性高估现状(02 号 §② 尾)。**影响:CP-17 修订**(屏蔽窗全量表子件 + R3 刷新尾款)。

### 1.3 AI 原生与策略注入面(03 号主承重)

1. **「管道建成早于水」——intent 六档在调度器内部硬消费点为零**:latency_nice 列无人读、Task.epp 单写零读、M4 带骨架运行面零可达(03 号 §1.1 九环表,本轮 grep 两源);这是 ADR #42「查表键先于消费者落地」+ 裁六「入场券未过不并线」的主动形态,不是债务。**影响:CP-12 维持**(入场券判定刀前置单列不变),CP-11 维持(IntentProfile 落表仍是第一消费窗)。
2. **注入机制面就绪度高于设计文档记载,三处文档漂移均为「文档落后于代码」**:RIGHT_MANAGE 门控已全 op 收口而文档仍写「v1 无门控」;placement 已半接而指南仍写「暂无消费」;共享环表述已被直传终裁取代([策略服务用户指南](../../docs/策略服务用户指南-v1.0.md):41、[调度器设计](../../docs/调度器设计-v1.2.md):316、[AI调度设计](../../docs/AI调度设计-v1.0.md):42,03 号 §2.4 表)。**影响:CP-01 修订**——重锚清单从三处扩容(加 01 号 SLEEPQ 口径差、02 号 R3 时点、README 措辞,共七处,详 §3)。
3. **kill criteria 判官工具齐、判据数字零样本,且存在代理判据误用风险**:divergence 率是「决策一致率」不是「尾延迟/能耗收益」本体,policy_ab_eval 阈值(<0.1/>0.5)是升级工作流代理;首份真实 A/B 报告(CP-06)未动,能耗半句真机前原理性不可测(03 号 §3.3-§3.4)。**影响:CP-06 修订**(报告模板分列两类判据)+ **CP-15 修订**(能耗半句 kill/豁免口径预立)。

### 1.4 业界演化面(04 号主承重)

1. **十裁无一件被推翻,四处收窄/补强**:EEVDF 稳定成熟期(lag 管理官方自认未定稿——缝一紧迫性下调、占位义务不变);EM 运行时化与三槽 RCU 同构(裁三获新判例);QNX 8.0 文档面 APS 缺席证据链闭合(触发器 8 收窄);Android 800 vendor hooks 半数在调度器(裁二「策略落表不落码」获最强对照系)(04 号 §0)。**影响:CP-09 修订**(EM cost 派生列/artificial EM 注意项)、计划 §6.1 触发器 8 修订(详 §3)。
2. **sched_ext 子调度器骨架入主线,bypass 继承设计值得 band 降级形态对齐**:子调度器按 cgroup 嵌套、故障时任务归父收养(LWN 1056014,04 号 §1.4);band 层失效/超卖时应回落扁平 fair 而不是全局 FIFO。**影响:CP-05/CP-12 修订**(BAND-S 相与 M4 验收线各加一句话条款)。
3. **LAVD 量产化验证「推理收敛成查表」形态,其工具缺口恰是 BerryOS 观测面强项**:EM 启动期查表、eventual enforcement、回馈上游 EEVDF 计划(LWN 1097209);LPC 2025 揭示「高层 FPS 视图↔微观 trace 缺关联、无可复现游戏基准集」(LWN 1051430,04 号 §5.3)。**影响:CP-07 维持 + 观测面投入维持**(裁四获间接佐证);gamesuite 式基准集不立缝(loadgen 帧循环形态已在 CP-12 验收线)。

### 1.5 能效 PM·EM·拓扑面(01 号 §四 + 02 号 + 04 号 §1.5/§2 交叉直补)

1. **EM 有形状、sched 不消费,且仅有的两个消费点硬编码域 0**:EmDomain.cpu_mask 就是拓扑形状而 Topo 无域字段、place 只读队列长;overutilized 判定 `em_max_capacity(0)` 多域下语义即错(01 号 §4.1)。**影响:CP-09 修订 + CP-19 修订**——最小形三刀(EmDomain.cpu_mask 单源 + Topo 挂 llc_mask + 去域 0 硬编码)与 4/8 核扩容刀或 EAS M2 同窗,不单开线。
2. **PM 面是三大接缝中最大空转机制,且 util 信号无消费者**:调度器只产信号(util EWMA/placement hint/EM 数据面)而 berry-power/berry-thermal 双服务骨架未挂接(02 号 §③ 引设计 v1.2 :188-190;03 号 §2.2 动作②同判);裁九「berry-power 必须立项」维持。**影响:CP-08/CP-10 维持**(外部 PM 线排期,无新证改判)。
3. **EM 运行时换表与 artificial EM 是新判例不是新债**:Linux em_table_alloc/update/free 三件 RCU 换表(04 号 §1.5)与 BerryOS「整表覆盖重注册走同通路」同构;热耦合 EM 更新真机期才议(归 CP-18)。**影响:CP-09 修订**(派生列加法不动 EmPoint 形状)、CP-18 维持。

### 1.6 观测·测试·文档面(01/02/03 号交叉直补)

1. **SMP 专属验收相零命中是验证面最大空白**:SMPBENCH/POLICY-S/BAND-S 三相代码 grep 零命中(01 号 §二 实测),双核终验 60 ok 是通用相非专属相——「已落码·余验收」两刀(CP-05/CP-06)的验收面完全未建。**影响:CP-03/CP-04 维持铁门,但预研面可先行**(hdrface 数学已备,01 号 §二.2)。
2. **host 钉板面是结构强项但 PI 延迟实测与 fuzzer 两处缺位**:判定律单源 face 族(intface 18/iprofile 23/slackface 12/bandface 6,03 号 §1.3)对拍 Zircon libsched 存续先例;PI 三任务链 G 卡用例未跑、策略注入 fuzzer 未建(挂 CP-13)(02 号 §③/03 号 §3.3)。**影响:CP-13 维持 + CP-14 修订**(G 卡收编)。
3. **文档族「全清」但漂移在积累,漂移方向全部是文档落后于代码**:文档族五件(白皮书 v1.1/设计 v1.2/调点 v1.3/SMP 部署设计 v1.0/计划 v1.0)覆盖完整,但 03 号漂移三处 + 01 号 SLEEPQ 口径差与 EM 域 0 硬编码 + README「AI-native by construction」(本轮复抽 [README.md](../../README.md):5/:23)与 ADR #21 降级的张力,共七处待重锚。**影响:CP-01 修订**(清单扩容,详 §3)。

### 2.2 领先项清单(单列,均有业界空白判据)

1. **可 A/B 性(三槽 RCU + shadow 双轨 + divergence 对账)**:Linux sched_ext / Android / Zircon / QNX / seL4 / L4Re 六家参照均无「影子双轨并行对账 + 对账驱动自动升级判定」([白皮书](../../docs/调度器架构白皮书-v1.1.md):93-103 对标表 + 03 号 §4.5-2 复核维持)。
2. **intent 每消息粒度传播**(三道帽 8 跳/50ms/400ms + client-pays 记账):四家微内核/宏内核参照中唯一「每消息粒度的轻量借入」(04 号 §6.4 表)。
3. **策略落表不落码的定制化通道**:对 Android 800 vendor hooks(近半在调度器)与 QNX APS 死因的双方判例(04 号 §2/§4)。
4. **host 钉板观测面(face 族判定律单源)**:对 Zircon libsched 的 environment-agnostic 存续先例同构且更深(host 测试义务层制度化,裁四)。
5. **确定性注入链(advisor 同输入同输出 + ±64 夹紧 + RT 屏蔽)**:对学习型生态「黑盒策略不可审计」的结构优势(03 号 §1.2/§4.5)。

落后面的一句话总账:**全部落后项都已有刀在册且依赖清晰**(CP-09 能效/CP-17 硬 RT/CP-19 拓扑/CP-12-13 AI 消费),没有「无刀可挂」的落后;真正的风险不是代差是排序——详 §4。

## §4 最紧迫三刀(数据说话)

排序依据:每刀的「数据缺口 × 下游解锁刀数 × 改动面」三乘积(推断口径,数据全部在册)。刀外第一阻塞仍是 X-6 fix-or-withdraw 仓主裁决(1 项卡 CP-02→03→06→15 四刀,01 号 §二.1)——那是外部裁决不是刀,不在三刀之列但排名先于一切。

**第一刀:shadow 侧 hazard 验证环补齐(CP-04 显式子项,升格独立预研)。**
数据:双核终验 60 ok 的载荷无背靠背 SHADOW_COMMIT 序列(01 号 §5.1 推断),即现有绿灯对缺口零覆盖;shadow_reconcile 是 apply 热路径每调一次的读者(policy.rs:701-729,01 号锚),写者背靠背两次换表即出撕裂窗。改动面:active_snap 的 verify-loop 复用到 shadow_snap,两读者一写者(01 号 §5.1「改动面小」)。不补的代价:CP-04 金丝雀上线即测缺口不测协议,整刀验收作废;且这是全体系唯一机制级真缺口(§1.1-1)。**唯一不等 SMPD-0 的机制刀**(host 面可先行,QEMU 相随绿门)。

**第二刀:忙核 arm-to-nearest-deadline(挂 CP-17 前置或独立小刀)。**
数据:R-1 cyclictest 实测 δ=¼slice 档 p50=5367438cyc ≈ 0.86 slice(单源实录,02 号 §②)——唤醒粒度被 tick 支配(名义 100ms、TCG ≈200ms),对 µs 级软实时目标是数量级不符;idle/park 形同构机制(arm_at oneshot)已在码(sched.rs:3147-3168,02 号锚),忙核只欠 expire_timeouts 的 oneshot 驱动(02 号 §1.3 尾「留后」注)。验收面现成:R-1 三档 δ 即其塌缩判据(02 号 §⑥ 其三)。这是「µs 级软实时」路线图承诺([路线图](../../docs/路线图-v1.2.md):45)的最大单项缺口,且不依赖任何外部裁决。

**第三刀:屏蔽窗全量表(syscall 全号 icount 化,挂 CP-17 或独立小刀)。**
数据:中断→任务 worst = 最长全屏蔽 syscall 段 + 2000cy(02 号 §1.3 尾),但 per-syscall 屏蔽段长度无表——中断上界论证的最大空白;icount 通道确定性已证(五跑 verdict=exact、L2 逐值相等,02 号 §②),六项原语代理在([bench_baseline_icount.txt](../../tools/bench_baseline_icount.txt)),扩到全号是纯工程量(02 号推断:一至两刀量级)。配套:R3 三路数字随 FPSIMD lazy 刷新一版(2000cy 分解的 135cy 项已过时约 10×,02 号 §② 尾)——不刷则所有引用系统性高估。

三刀共同点:**全部零外部依赖、全部有现成验收面、全部是「论证能力」而非「新机制」**——与终判(§5)一致:下一阶段的瓶颈不在机制在证据。
