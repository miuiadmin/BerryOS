## 1. 2026 全场图景：三个判断

**判断一：「OS」语义已分裂，头部全是用户态。** 星数前列（openfang 18,242★ / aos-ce 8,458★ / compozy 2,854★）全部是 Agent 运行时而非内核；真内核新项目星数低一个量级（astrid 10,291★ 是例外，且它当前形态也是宿主运行时，方向才是独立 OS——astrid README）。**内核级 AI 原生位全场空缺**：唯一尝试 agentic-native 内核的 Veda 仅 102★ 且处早期（Veda README）。

**判断二：能力模型收敛为行业共识。** astrid 的 capsule/principal + ed25519 令牌（astrid book/security）、swift-os 的 principal+capability 掩码（"never uid == 0"，swift-os README）、Veda 的 consent 门（Veda ARCHITECTURE）——与 BerryOS「能力即权限」同一设计语言；差异在层级：全部做在运行时/服务层，唯 BerryOS 做进内核态 handle。

**判断三：AI 写 OS 已有实证闭环。** ember 汇编 OS 全部代码由 Claude 写、人验真机（ember README）；vib-OS 自称 vibecoded（vib-OS README）。BerryOS 的机器门禁体系（G0–G5 + smoke + abi-check）是同类生产力的系统化放大。

## 2. 四家深读摘要

### 2.1 astrid——「哑内核」哲学的最完整论述（规范书 foundations/kernel-is-dumb.md）

- `Kernel` 结构体字段即边界清单：只有消息总线、注册表/存储、安全基础设施、VFS 四类；**没有** LLM 句柄/对话历史/prompt 模板（kernel-is-dumb.md §What the Kernel Owns）。
- 业务逻辑不进内核三理由：① 内核解释事件 = schema 变更要发内核版；② 内核原生跑，智能进内核即**逃出沙箱**（不能热更/不能被能力约束/不能同机制审计）；③ capsule bug 崩 capsule，内核业务逻辑 bug 污染全体 principal 共享状态（kernel-is-dumb.md §Why No Business Logic）。
- 代码级执法：`#![deny(unsafe_code)]`；`INTERNAL_SUBSCRIBER_COUNT=5` 由 debug_assert 在 boot 钉死（kernel-is-dumb.md §Enforcement）。
- 两层安全分立：管理 API 每请求 `authorize_request`——fail-closed、无 default-allow 分支、profile 解析失败即拒；**IPC 总线本身不设 ACL**，capsule 自治授权（§Mental Model）。总线公平 = per-principal FIFO 子队列 + deficit round-robin（astrid-events/bus.rs，经 book 转引）。
- 审计链：**授权与拒绝都写** ed25519 链式签名 append-only 日志（kernel-is-dumb.md §What the Kernel Owns）。

### 2.2 Veda——BerryOS 模块表的近亲 + 同意机制最深（documentation/ARCHITECTURE.md）

- 内核模块表与 BerryOS 近逐项对应：VMO/handle/channel/port/interrupt 对象/hardware 资源即授权/syscall 号型单源独立 abi 库/virtualization（hypervisor + 驱动 VM）/percpu/ChaCha20/ACPI/initrd loader（ARCHITECTURE §The kernel）。
- 并发路线：全内核 **BKL（MCS 队列锁）**——内核单线程化、操作短、按 CPU 请求序公平交接，等待者各旋自己的字（§Concurrency）。与 BerryOS「细粒度锁分阶段爬升」是路线分歧。
- 同意机制三件：① consent **by identity**——需同意的动作只有 shell 能批、只有 Settings 能改 agent 设置；② 锁屏抑制监听；③ **presence 语义**——用户说话算在场（防闲置锁），电视/旁人/提醒触发对话不算（§The voice agent）。
- agentapp 协议 describe/state/invoke：应用声明 typed actions，agent 走与键鼠**同一代码路径**，非屏幕抓取（同节）。

### 2.3 swift-os——「自有 ABI、无 Linux 二进制」的真机兑现（README）

- Embedded Swift freestanding（`aarch64-none-none-elf`）写真内核；每进程一 AS 真 MMU 隔离 + principal/capability 掩码。
- 自有 POSIX-like ABI、静态链接、无动态加载器；内核 TCP/IP（sans-IO 协议核）+ TLS；SMP `-smp 4` + 跨核 TLB shootdown。
- **三层 FS：不可变签名只读 base + tmpfs + fsync 持久 /data（能背 SQLite）**。
- 真机兑现：Hetzner ARM VM 跑 nginx HTTPS + Node.js 24.16（自研 ABI + 内核网络栈）。

### 2.4 TrustOS——unsafe 边界纪律同道 + 真机 GPU（README）

- 一人 264K 行 no_std Rust，零 C 零 blob，**unsafe 只在 MMIO 边界**（与 BerryOS unsafe 全域铁律同口径）。
- 真机从零点亮 AMD GPU（GMC/VM/SDMA 固件、ring buffer）；内核内音频合成器。
- **Remote-first 调试三通道**：framebuffer/内核日志/shell 全走 UDP（netconsole 6666 / shell 7777 / screencap 7779）。

## 3. BerryOS 先进性对照（七点，证据注前文）

1. **内核级 AI 原生全场唯一**：三层模型（内核快循环查表 / 用户态慢循环 / 共享环原子换表，AI调度设计 §2）——2026 无等价物。
2. **「有/无 AI，pick_next p99 相等」不变量**（AI调度设计 §5）：QNX APS 之死的产品化规避（出处：报告 06 + 本文 §1）。
3. **护栏八条内核硬线**：RT/deadline 屏蔽、pledge 单调收窄、intent 只降不升、band 预算不可触碰、越界拒收保留旧值（AI调度设计 §5）——比 astrid ACL / Veda consent 更深一层（内核态执法）。
4. **能力委托链审计**：SET_POLICY 可 duplicate 收紧/close 吊销、设置服务可列「谁把调权能力给了谁」（AI调度设计 §3/§4）。
5. **G0–G5 系统级验证工程**：五相 smoke + abi-check 四面对拍 + docs_guard + writable-globals + lockdep——全场唯一系统级门禁体系（对照 openfang 1,767 单元测试）。
6. **遥测两级分层纪律**：QEMU 可靠级 / 真机门控级，分类器只准用第一级（AI调度设计 §4）。
7. **决策工程**：64 ADR + 排除 8 问 + 雷册判例库——决策可追溯性超过 astrid book（规范完备 ≠ 决策追溯）。

## 4. 差距（诚实清单）

| 差距 | 证据 | 严重度 |
|---|---|---|
| QEMU→真机鸿沟 | swift-os 真机 nginx / TrustOS 真机 GPU 已过此关；BerryOS 未出发（功耗/GPU/USB 全未验） | 高 |
| 现代存储形态 | swift-os 签名 base 分层（OTA 回滚安全）vs BerryOS FAT MVP | 中 |

| 单人巴士系数 | TrustOS 单人 264K 行可行先例；BerryOS 文档/判例资产是最佳恢复锚 | 中 |

## 6. 结论

BerryOS 占据内核级 AI 原生独有生态位，设计完备度与工程纪律领先；差距集中在真机兑现与生态冷启动，均有已验可借路径。路线稳健性来自三不赌对冲 + 分阶段门禁；前瞻性来自内核 AI 位空窗与 intent 语义期权。**最优先行动 = 真机预研立项。**
