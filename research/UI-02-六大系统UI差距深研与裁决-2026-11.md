# UI-02 六大系统 UI 差距深研与裁决（2026-11）

Type: survey
Status: current
Updated: 2026-11-15

一句话说明：以四路对标数据（OpenHarmony/HarmonyOS 深研 + iOS + ChromeOS/Fuchsia + OH 规格面基线）与仓内[十四维盘点](../.agents/research/2026-11-15-UI现状十四维盘点.md)为底，对六系统（OpenHarmony、HarmonyOS、iOS、ChromeOS、Fuchsia、BerryOS）出 14×6 差距矩阵与逐维三件裁决（根因、六波覆盖度、最小刀法），专节审六波盲区七项与反超点四项，供六波续刀与波 5 核账吸收。

## 问题

owner 要求以综合裁决人身份回答四问：①14 维 × 六系统，BerryOS 每维差在哪、差多少（A 追平 / B 部分差距 / C 结构性缺位）；②每维差距的根因是机制缺还是工程量缺、[六波方案](../.agents/plans/2026-11-15-体验大改造六波实施方案.md)哪刀盖住、最小补齐刀法是什么；③六波没盖到的盲区（点名七项：CJK 与国际化、无障碍消费端、暗色模式、断点折叠自适应、动画深度、预览热重载、真 alpha 合成）各给严重度与归波建议；④哪些维我们不差或反超（点名四项：boot 事件驱动进度、tickless 省电位、damage 局部重画、微内核隔离对 UI 稳定性），要求诚实不吹。

## 结论

### 总裁决

- 14 维无一 A：按六系统第一梯队口径，BerryOS 现状 5 维 B（二组件、四手势、十一性能、十三设计文档、十四特色）、9 维 C（一声明式、三动画、五输入法、六多窗合成、七无障碍、八主题暗色、九自适应、十国际化字体、十二开发工具）。但 9 个 C 要劈成两半：约半数是本轮产品边界内的刻意窄化（五 ASCII 软键盘、九单形态单窗、十限 ASCII 硬约束、八 token 先行），六波收尾后可小刀转 B；真缺口是三（弹簧与中断恢复）、七（a11y 消费端）、十二（预览热重载）与六的现状档（blit-at-SUBMIT 兼容档，波 3 在途）。
- 差距重心不在件数：41 kind 加 19 配方对约 70 件目标已是工程量问题（波 2 五批接线已证明批产能力），真正没立项的是四个机制面（弹簧物理、a11y 消费端、暗色成系统、预览热重载）加一个资产面（CJK 字形）——其中弹簧与 a11y 消费端是六系统全部成体系、而 BerryOS 零命中的两块。
- 六波覆盖度总判：波 2/波 3 盖住件数、输入焦点协议与带合成三大主干；盲区七项中六项在六波里无刀（CJK 与真 alpha 仅在波 5 挂账移交、暗色与弹簧与预览热重载与 a11y 消费端完全无刀、断点折叠仅旋转挂账），详见专节三。
- 反超点四项中，boot 事件驱动进度与 tickless 是结构性领先（设计或架构层面的「别人没有」），damage 与微内核隔离是同构纪律下的更彻底形态而非独有物——四项都要诚实读落地状态，见专节四。

### 二、逐维裁决三件（根因 / 六波覆盖 / 最小刀法）

- 维一 声明式与状态管理：根因 = 机制缺（绑定语法面从未立项；但引擎侧失效粒度三层递进与 S7 ChangeMask 实验轨说明「属性级失效」的机制已备，缺的是把它开成开发者面；ADR #52 Msg-only 零闭包是防 alloc 的有意窄化，属裁决不属欠账）。六波覆盖 = 没盖（六波全走命令面）。最小刀法 = 不做宏绑定，走「差量描述」等价物：desc DSL 本就可序列化（TLV 双入口），先把 S7 ChangeMask 转正、dep.rs 边表从记录改消费，形成「外部提交描述 diff、引擎算最小失效」的声明式等价闭环；开发者面声明式语法缓立项。
- 维二 组件：根因 = 工程量缺（渲染接线、TLV 批次、pattern 配方族已证明批产能力；差额件与 v1 降解面是刀数问题）。六波覆盖 = 盖住大半（波 2 五批接线加 pattern 19 族；Dialog/Menu/Toast 归波 3 berry-appshell；Qr/Canvas 占位与焦点环原语无刀）。最小刀法 = 波 5 核账后补「降解面清零刀」：Qr 真编码（纯算法件）、Canvas 位图面、焦点环原语、per-node 圆角收样式系统；[组件清单](../docs/UI组件清单与实施规划-v1.0.md) 状态列同步回填。
- 维三 动画：根因 = 机制缺（AnimProp 恒五属性、Easing 四档，弹簧物理参数与速度续接从未进面；Q16.16 定点域下离散弹簧解算可行，不是做不到）。六波覆盖 = 没盖（六波无弹簧刀；SwipePager 吸附为固定 QuadOut 240ms）。最小刀法 = anim.rs 加 SpringProp 定点解算（质量-刚度-阻尼离散积分、初速度入参、目标变化时以当前状态重起算即天然得「中断恢复」）+ SwipePager 松手速度接入弹簧——两刀覆盖 OH springMotion 与 iOS interpolatingSpring 的主干，收益波及全部按压回弹与翻页场景。
- 维四 手势与输入：根因 = 工程量缺为主（referee 状态机、轴锁、速度环、重采样终跳皆工程级扎实；长按双击是状态机扩展、捏合旋转是多指几何，无架构障碍）。六波覆盖 = 盖一半（波 2 输入焦点协议只管焦点与注入，未扩手势）。最小刀法 = hit.ts referee 加 LongPress/DoubleTap 计时态（纯状态机、零协议改动）+ 捏合走既有 PTR_MAX 槽位加几何 Msg；组合手势代数（OH/iOS 的三模式）暂缓，单窗应用场景弱。
- 维五 输入法：根因 = 结构性缺位且是刻意窄化（本轮 ASCII 硬约束是上游前提，CJK 字形不在档；但 preedit/候选窗协议连 ASCII 阶段也未定义）。六波覆盖 = 盖一半（波 3 softimed QWERTY-lite + OP_INPUT_INJECT 与真实输入同面；preedit/候选窗/CJK 明确移交）。最小刀法 = 波 3 落地后加「IME 协议二代」刀：preedit 组合文本态进 input 侧表、候选窗走 SERVICE 层窗（与 softimed 同层）、set_input_text 扩组合语义；CJK 依赖维十字形刀先行。
- 维六 多窗口与合成：根因 = 工程量缺为主（带合成 v1 方案已定：缓存 SYSTEM/SERVICE 带、按层序重放；blit-at-SUBMIT 是过渡兼容档非终态；pending 帧状态机与 SERVICE 建窗执法是小改不是重构）。六波覆盖 = 盖住（波 3 带合成 v1 + 沉浸旗 + I2 返回键路由 + launcher 双窗化）。最小刀法 = 波 3 实施时同批把 wm_layer_known 执法扩到 SERVICE、present 补 pending 帧状态机；真合成 v2（图层属性 diff 面）挂 virtio-gpu 后端时机，与 GUI-02 预留的 commit 缝对齐。
- 维七 无障碍：根因 = 结构性缺位（消费端是系统服务大件——朗读引擎、TTS、焦点走查器，不是引擎侧表能顺手带的；六系统全部有消费端，连「平台不背 UI」的 Fuchsia 都把 a11y manager 做成带屏产品必选组件）。六波覆盖 = 没盖（六波零 a11y 刀；波 4 应用自写 role 只是数据面）。最小刀法 = 最小消费闭环刀：a11y_iter 已有，写一个焦点走查器（随焦点移动串口/日志播报 role + label）进 berry doctor 或 gallery 验证面，先把「侧表到消费」链路点亮；真 TTS 挂真机音频面立项，建议归波 5 后专项。
- 维八 主题暗色：根因 = 工程量缺为主（token 双档在册、paint 改查表是接线活；动态取色是机制缺但 OH 也没有、iOS 独一档，不必追）。六波覆盖 = 盖一半（波 2 落主题 token 常量单源；暗色切换入口与 paint 双档查询无刀）。最小刀法 = 三小刀：Tokens::pick 接进 launcher/settings 消费、paint 固定色板豁免清零改查 token、settings 加暗色开关（boot 模式开关先例同形）；dark 档 brand_pressed 同值未区分顺手修；动态取色明示不做，与 OH 同立场。
- 维九 自适应：根因 = 机制缺加产品裁剪（单形态单窗是本轮产品边界，断点体系无第二消费者；但 SwipePager 页宽冻结建树时、viewport 变更需重 attach 是真机制债）。六波覆盖 = 没盖（波 5 仅旋转自由化挂账）。最小刀法 = 先还机制债：viewport 变更事件 + SwipePager re-attach（几行级）；断点体系缓立，待第二形态（横屏或桌面窗）立项时按 OH 双轨（栅格 + mediaQuery）或 iOS size class 单轨选型，不提前铺。
- 维十 国际化与字体：根因 = 结构性缺位（字形资产与 i18n 框架双缺；但 genhdfont.py 管线已证明能从 Noto Sans CJK 光栅化，通路现成）。六波覆盖 = 没盖（六波硬约束本轮限 ASCII；波 5 仅挂账移交）。最小刀法 = CJK 刀三件：字模生成器扩 GB2312 一级常用 3755 字（2-bit 灰度与 1-bit 描边二选一，rootfs 32MiB 帽需先核体积）、metrics 比例宽扩 CJK 等宽档、TextBuf 64B 扩容（UTF-8 下中文一行二十余字已爆）；i18n 框架（locale/字符串表）无第二语言消费者，挂 v2。
- 维十一 性能与掉帧：根因 = 不构成根因性差距（单窗 CPU 合成语境下帧纪律成体系且可测；缺的是消费收口与变帧率，后者在无 LTPO 面的模拟器上无收益）。六波覆盖 = 盖一半（波 2 遥测随控件面扩大；GUI-9 遥测消费收口挂账未排刀）。最小刀法 = telemetry 帧环倒 dump 进 berry doctor（boot 毫秒时间线同批）；TCG/HVF 双档验收（六波风险节已立）之外加 RUN 内低动效档开关，作为慢速档观感兜底。
- 维十二 开发者工具：根因 = 机制缺（预览热重载需要进程架构与工具面支持；但 desc DSL 可序列化是天然优势——TLV 描述流本可从外部进程喂，不用等于浪费）。六波覆盖 = 没盖（六波只有 gallery/golden/berry shot 回归面，无迭代体验面）。最小刀法 = 最小静态预览器刀：host 侧工具读 TLV 文件、复用 gallery 离屏管线出 PNG，零新机制；热重载等价物 = 文件监听重读重渲，挂 tools/berry 一刀。对标 Xcode 四模式画册不做，先解决「改一个控件要看效果必须起整机」的痛点。
- 维十三 设计系统文档：根因 = 工程量缺（GUI-11 硬数值表已采齐、theme.rs 常量在册、OH ux-design 骨架现成，拼装即可）。六波覆盖 = 盖一半（波 5 对标矩阵终审逐行核账，但「收敛成 BerryOS HIG 成文档」无刀）。最小刀法 = 波 5 核账同批立《BerryOS HIG v0.1》：应用规范 §3.5 + GUI-11 表 + 四路调研素材拼装、以 OH ux-design 目录为骨架（动效/栅格/组件逐件/统一交互四部），十页级起步，不等设计语言成熟。
- 维十四 特色：根因 = 不构成差距（特色维度各家长相不同，不必逐项对齐；boot 真事件进度是反超点，见专节四；分布式明示不做——仓内 UI 面零命中且无场景）。六波覆盖 = 盖住（波 1 开机双模式 + 胶囊算法；卡片 elevation 数据面已在）。最小刀法 = 无新刀；dim_accent 与卡片 elevation 收编 pattern 面与波 2 主题刀同批。

### 三、六波盲区专节（六波没盖到的七项）

- CJK 字体与国际化：严重度高——中国用户场景的硬门槛，TextBuf 64B 连一行中文提示语都放不下，ASCII 硬约束解除日即断供；六波仅波 5 挂账移交、无刀。建议归波：波 5 后专项「CJK 一刀」（维十最小刀法三件），i18n 框架挂 v2；字形资产先行，因为它同时解锁维五 IME 二代。
- 无障碍消费端：严重度高——侧表数据面已建而消费端零，投入处于沉没状态；六系统全部有消费端，此维是 BerryOS 唯一「生产面成体系、消费面为零」的劈叉。建议归波：新开专项（不塞进六波）；最小消费闭环（焦点走查器）可与波 4 应用 role 全量登记同批，真 TTS 挂真机音频面。
- 暗色模式：严重度中——token 双档在册、只差接线与切换入口，工程量小而用户可感知度高；六波无刀。建议归波：并入波 4 前后的「主题收编刀」（paint 色板豁免清零同刀，维八三小刀）。
- 断点折叠自适应：严重度低——单窗单形态产品边界内无消费者，机制债仅 SwipePager 重 attach 与旋转挂账；六波波 5 已挂账旋转。建议归波：维持波 5 挂账，rotate 随 WM_GETINFO 几何协商先行；断点体系待第二形态立项，不提前铺（OH 断点双轨与 iOS size class 的选型留到那时）。
- 动画深度（弹簧与中断恢复）：严重度中高——按压回弹、翻页吸附、跟手流畅感的主观质感主力，OH 与 iOS 都把「速度续接」做成一级 API 面，是体验分水岭；六波无刀。建议归波：波 2 与波 3 之间插「弹簧小刀」（anim.rs 定点弹簧 + SwipePager 接初速度，维三两刀），收益覆盖波 3/波 4 全部翻页与按压场景，越早插越省返工。
- 开发者体验（预览热重载）：严重度中——六波靠 VNC 截图走批可行但慢；TLV 可序列化是现成预览通路，不利用是浪费；六波无刀。建议归波：波 5 收尾后 tools 面「静态预览器刀」（host 离屏渲染 PNG + 文件监听重渲），零新机制。
- 真 alpha 合成：严重度中——按压遮罩目前靠 20% 预混色、圆角边缘与波 3 带缓存带的层间过渡都吃真 alpha；波 5 仅挂账移交。建议归波：波 3 带合成 v1 实施时同刀评估（FillRect alpha 变体 + 合成序），QEMU TCG 下 CPU 混合成本实测超帽则把波 5 挂账升格为独立刀，不拖到 GPU 后端。

### 四、不差或反超的专节（诚实不吹）

- boot 事件驱动进度：设计层反超、落地在途。业界证据（[BOOT-01](BOOT-01-启动视觉与事件驱动进度业界深研-2026-11.md)）：Windows 并行化后自认线性百分比无法定义而退到无进度 spinner；OH bootevent 锚点体系完整但未折算成进度条；AOSP 自己也只有约 25-30 个可见锚点。BerryOS 的 26 格事件词汇表（boot 事件细化刀 6 为唯一权威）+ P_tgt 事件目标值 + 一阶惯性追逐 TAU=600ms + 单调不减 + 90% 封顶揭幕，是六系统中唯一「真事件驱动 + 显示端整形」双全的设计，且微内核每服务一事件可做到 30-50 个事件点、粒度超 AOSP。诚实面：该设计停在 rescue/ux-splash 分支半成品，主树现状是 EFI 残屏静止数十秒；Apple 的跨持有者背缓冲交接与 Android 的三件套揭幕是量产成熟实现，BerryOS 合并前只算纸面反超。
- tickless 省电位：结构性领先，UI 侧有同构延伸。Linux 出生 16 年才补 NO_HZ（2007），微内核谱系电源全体留白（seL4 零贡献、MINIX/HelenOS/Genode 空白，见 [PM-03](PM-03-Linux电源机制与微内核归属-v1.0.md) 与调研谱系），BerryOS NO_HZ day-one（空闲 mask CNTV + WFI、one-shot 编程到下一事件）站在正确一边。对 UI 的意义在 GUI 层同构延伸：三态停帧 + IDLE 撤软 vsync 定时器 + idle 票 sticky + 无 damage 不提交零票（[GUI-06](GUI-06-低功耗渲染策略.md)、[GUI-09](GUI-09-综合裁决建议.md) 立法），OH 侧只有「动画静默 2000ms 强降 Idle」的同向补丁。诚实面：QEMU 无能耗面，验收代理只能用指令数与唤醒计数（idle 实测 0.65%/0.50% 在册）；且曾定谳 tickless 机构被 boot 演示忙环结构性饿死、现役实为 10Hz 周期 tick，修窗（演示面门控）后才恢复可达——「机构在位、可达性靠纪律」的教训要长期记住；无 LTPO 逐动画帧率面（OH expectedFrameRateRange），真机前无场景。
- damage 局部重画：同构纪律、更彻底的库级形态，不是独有物。DamageSet K≤8 定容合并（L 形角交拒并判定式单源、Σ×1.25 浪费帽、满 8 最小包络）+ 遮挡剔除保守少记 + overdraw 2.5× 预算 + boot 胶囊条只写条区与百分比格——把 damage 做成零 alloc 纯函数可测件，且 guifbd CPU blit 直接吃 damage 裁剪。业界同构：Wayland surface damage、GUI-02 证实三方系统收敛于「脏区矩形集 + 一提交」，OH/HWC 走图层缓存直显是另一条资源路线。诚实面：BerryOS 无 GPU 合成，damage 是 CPU blit 的生命线而非先进性资本；GPU HWC 通路下 damage 语义被图层缓存替代；「无 damage 不提交」在 Fuchsia present credits 与 squashing 有同构物，不独有。
- 微内核隔离对 UI 稳定性：机制在位、验证未采。BerryOS 的 guifbd（呈现）/gui-wmd（窗口策略，ADR #61）/launcher/应用分进程 + svcmgr 监督重启，意味着应用崩溃丢一层不拖垮合成、UI 服务可崩可热换（GUI-05 形态 B 表的失败隔离列）；Fuchsia 先例把同一结构做成产品纪律——a11y manager 与 text_manager 独立组件、input-pipeline 是唯一可直读驱动的组件（RFC-0096 防键盘记录）、hit test 归合成侧（防 clickjacking 的结构性保证）。诚实面：BerryOS 的隔离是架构红利未兑现成验证故事——监督重启对 GUI 服务的实效零故障注入证据、wmd 单车位 TABLE_WAIT 多客户端语义波 3 动手前才核、a11y 与 IME 还在引擎侧表与规划稿（Fuchsia 已是独立组件）；「隔离对 UI 稳定」目前是可论证的架构性质，不是已度量的运行性质。

- 六系统口径为「外部五系统 + BerryOS 现状列」；差距等级评的是 BerryOS 对六系统第一梯队，不是对某一家的距离——B 级不指明追谁，C 级也不意味着按 OH 全量重造（多数 C 的最小刀法在裁决节给了窄刀）。
