## §0 一页结论（土话直答）

1. **内核省电是地基，不是房子。** tickless、intent、调度优化只解决「CPU 自己不白烧」；
   真正的电大头在外面：显示（GUI-06 归口）、蜂窝尾能（LTE 传输能耗 **48.2% 是拖尾**，
   PM-05 §2.1）、N 条应用心跳（PM-01 §2.3）、后台乱醒（PM-01 §2.1）。地基打好了没人盖房子，
   整机待机功耗一分不降。
2. **全系统省电 = 机制 + 治理 + 契约 + 归因，四层缺一不可。** 现役四大系统独立收敛到同一个形状：
   中央电源服务持状态机，进深态靠投票仲裁，性能期望靠带反馈的 hint，一切以归因为闭环验收
   （PM-06 §2.1 四家并置互证）。任何一层缺位，其他三层白干——Android 归因工具迟到六年，
   滥用就野蛮生长六年（PM-01 §2.4）。
3. **触摸响应功耗的答案：「按下费电买响应、平时逐级归零」。** 触摸芯片本身是小头（10–50mW 级），
   贵的是它牵动的整条链：AP 唤醒 + 提频脉冲 + 提刷新率。机制清单与 BerryOS 落点见 §4（引 PM-04）。
4. **演化规律想明白了，核心三条：形状决定命运**（API 形状即滥用面，wakelock 无限租约 =
   十五年对抗面）；**默认值即生态**（默认批处理/默认冻结，例外走权限）；**度量先于治理**
   （能量化才可治理，Android 2025 年才把 wakelock 罚则出 beta）。
5. **BerryOS 的机会是一次性的：** v1 无 fork、无历史二进制、自有 ABI——应用契约可以 day-one 定对，
   这是 Android 用 15 年、7 代系统逐步赎回的东西（PM-01 §1.5/1.6），**过期作废**（PM-02 §4 前置对齐）。
   唯一真正的敌人是「先给方便后收回」的诱惑。
6. **（v1.1 增）治理三边界已立法：** 热归 berry-thermal 独立服务、帽走同一聚合点（ADR #66）；
   挂起期主钟停+SLEPT 双钟、POSIX 映射显式（ADR #67）；AI 票受 KC-P1..P5+豁免位护栏、
   SDK 六面零新 syscall、充电控制永不设键（ADR #68）。协议位表 v1.0 十位 → v1.1 十一位（新增 P11 充电限值票）。

## §1 三问直答

### Q1「内核省电了、调度也优化了，用户态/launcher/SDK/GUI/多应用/基带显示信号触摸多媒体网络 GPS 全在跑，整套系统的省电怎么把控？」

**直答：靠「一个中枢 + 四层分工 + 契约先行」。把控的不是每个外设，是三样东西——醒着的时长、
醒的频率、醒着时的功率，外加一把「不可测=不可治」的归因尺子**（PM-05 §1.1 统一心智模型）。

- **谁把控**：一个用户态中央电源服务（本报告裁决合一定名 **berry-power**，含电源域租约面，
  见 §2-L1 与 §5 裁决 1）。Linux 桌面的反面教材：没有单一中枢，logind 只握 sleep 仲裁一小块，
  UPower/各 DE/内核 governor 各自为政（PM-06 §1.3）；Windows S3/S0ix 双模型分裂十年骂名（PM-06 §1.1）。
- **先看电费单——整机功耗大头盘点**（跨 PM-04/05/06 + GUI-06 合成，量级证据均在分报告）：

| 大头 | 量级/机理 | 归口报告 | 确定度 |
|---|---|---|---|
| 显示+背光 | 视频场景占整机 38–68%；120Hz 恒开多耗 10–30%/1–2h | GUI-06 §3（归口引用） | 高 |
| 蜂窝尾能 | LTE 传输总能耗 **48.2% 是拖尾**（传完 ~11.6s 高功率态、基线 ~1W）；发 1KB 心跳 ≈ 买 12J 拖尾 | PM-05 §2.1 | 高（MobiSys 实测） |
| 应用心跳×N | 无统一推送时每 app 一条长连接；微信心跳 5→20+ 分钟信令减 ~80%（反之白烧）；弱信号 PA 顶格再翻倍 | PM-01 §2.3 / PM-05 §2.1 | 高/中 |
| 后台乱醒 | stuck wakelock 后台长持锁挡深睡（官方判档 1h/24h，2025 罚则收紧 2h/24h）；50Hz 传感器不批量 = 每秒吵醒 AP 50 次 | PM-01 §2.1 / PM-04 §5.1 | 高 |
| 交互链起振 | boost 窗内频率地板远超实际需求（brute-force）；扫描 ~100mA 级/次 | PM-04 §2 / PM-05 §2.3 | 高/中 |
| 触摸芯片本身 | 10–50mW 级（小头） | PM-04 §1.1 | 低（行业口径） |

  **读法：内核省电（L0）只直接管最后一行之上的 CPU 份额；前四行全靠 L1 服务 + L2 契约 + L3 硬件域。**
- **怎么把控**：四件套收敛形态——状态机（ACTIVE→DOZE→SUSPEND）、投票/票据仲裁
  （block/delay 两档 + 断线自动回收）、hint 会话（{target_ns, actual_ns} 带反馈）、
  三层归因计量（模型表/轨级实测/时间记账）（PM-06 §2.1/§6.1）。**四家独立演化收敛于此，不是巧合。**
- **生态怎么把控**：靠 SDK 契约 day-one 定死（§5.2 逐项裁决表）。统一推送单长连接、定时三档、
  传感器 batching、长时任务白名单——这些不是功能，是**功耗机制**：FCM 把 N 条心跳租约合并成 1 条
  （[官方 Doze 文档](https://developer.android.com/training/monitoring-device-state/doze-standby)，高）；
  中国缺统一推送 → 微信占中移动 60% 信令只贡献 10% 流量（PM-01 §2.3，中）。
- **怎么验收**：归因先于治理——内核 wakeup 记账面（谁唤醒了谁、耗了多少）第一刀就落，
  「无主唤醒 = smoke 失败」；QEMU 只能验软件纪律（能耗代理断言），物理功耗靠真机功耗计（铁律 11）。

### Q2「触摸响应功耗这种到底怎么弄？」

**直答：三句话。① 触摸芯片本身是小头，省电主战场在它牵动的整条交互链（AP 唤醒/提频/提刷新率）；
② 按下那一刻「费电买响应」——touch boost 是止痛药不是治愈，参数化石锤 40ms 窗 + 150ms 重触发限频；
③ 平时「逐级归零」——控制器扫描分档、传感器 FIFO 批量、帧循环停帧、AP suspend。**

- 具体机制全集见 §4（引 PM-04 全文）：微软 HID 四态契约、手势唤醒域、三代 touch boost、
  userActivity 状态机（INDIRECT 剔除防自续命）、触摸×LTPO 联动（触摸票压过光照降级）、
  传感器 batching（240→24 中断/秒）、AOD 出帧责任搬出 AP。
- BerryOS 落点一句话：**内核只留「交互脉冲」原语（参数全在用户态策略服务），走 intent 0x02
  单轴注入；提频与提帧同源单脉冲；SDK 帧预算表补功耗列，把「省电换延迟」明码标价**（PM-04 §8）。

### Q3「各大系统的演化规律、经验教训、历史包袱——我们想明白了吗？」

**直答：想明白了。六家演化史 + 两条通用判别式收进 §3 一张表；最要紧的规律是
「权力下放容易、回收极贵」与「缺席的通道必被民间自建」。我们的诚实清单：
最可能重蹈的辙不是技术坑，是「契约窗口错过」——ABI 形状一旦定错，后续只能走 Android 的
否决层路线（Doze 式「无视层」叠在已下放权力之上），复杂度永久化**（PM-01 §3.2-3/R7，高）。

增量核证（本报告新增，分报告未含）：Android 16（2025）JobScheduler 配额优化**连前台服务与
用户手动豁免面也开始吃配额**——官方原文「Prior to Android 16 there was no execution limit when
the app was running a foreground service or the user unrestricted the app battery」
（[power-details](https://developer.android.com/topic/performance/power/power-details#changes-a16)、
[behavior change](https://developer.android.com/about/versions/16/behavior-changes-all#job-quota-opt)，高）。
收权 15 年后仍在继续，且已收到「豁免面」本身——**「给了再收」没有终点站**，这是对 BerryOS
day-one 契约路线最有力的实证背书。

## §2 全系统省电分层模型（四层职责表）

> 心智模型统一为「电源域 + 租约 + 尾能 + 计量」（PM-05 §1.3）：一切机制都是这四样的实例。
> 分层判据 = 微内核五原则（铁律 1）：内核只留机制，策略与服务全在用户态，硬件面走能力授予。

| 层 | 职责（管什么） | 各家放哪 | BerryOS 建议放哪 |
|---|---|---|---|
| **L0 内核机制层** | idle 入口（tickless/WFI）、定时器栈与 slack、唤醒记账、性能域/频率寄存器、挂起四原语（停钟/CPU 上下线/唤醒 IRQ 编程/遥测导出） | Linux 全在内核（20 年把 PM 策略长进内核搬不出来，PM-03 §7-6）；Fuchsia 只留四原语（[RFC-0230](https://fuchsia.dev/fuchsia-src/contribute/governance/rfcs/0230_suspend_to_idle)，高） | **已有**：tickless G1、slice 周期记账、intent 传播五件套、WAKE_RING 遥测（盘点 §1.1）。**补**：wakeup 记账面（per-source 归因，§5 刀 1）、timer slack 档、深睡三件套挂 v2+（ADR 在册）、**thermal pressure 等价物**（帽/注闲生效时 utilization·容量记账同步打折——sched-1.2 议题，PM-07 §4-4）、**停钟原语细节**（ADR #67）。策略一个不进内核 |
| **L1 用户态电源治理服务层** | 系统电源状态机、投票/票据仲裁（block/delay）、电源域拓扑与租约、维护窗/桶位配额、频率帽、交互态状态机 | Android：PowerManagerService+Doze+桶位（分散补丁 15 年）；iOS/macOS：powerd 中枢 + 2013（Mavericks）能效栈一套落齐（[Apple PDF](https://www.apple.com/media/us/osx/2013/docs/OSX_Power_Efficiency_Technology_Overview.pdf) 覆盖 App Nap/Timer Coalescing，高；powerd 内部细节中，PM-06 §1.2）；Windows：Power Manager+DRIPS+activator 票据；Linux：碎片化无中枢；Fuchsia：SAG+PowerBroker（仲裁器不做策略只做拓扑，[官方](https://fuchsia.dev/fuchsia-src/concepts/power/intro)，高） | **合一的 berry-power**（裁决见下）：持四件套——状态机 ACTIVE/DOZE/SUSPEND、power_assert 票据、hint 会话泛化、三层归因（PM-06 §6.1）+ 电源域 handle/lease 四元组（PM-05 §4.1）。PM governor（M3）是其频率策略面，不另立山头 |
| **L2 SDK·应用契约层** | 后台模型、推送、定时三档、传感器 batching、长时任务白名单、manifest 能力位、事件订阅租约 | iOS：从不给予（挂起+枚举白名单+系统排期）；Android：给了再收（wakelock/闹钟/服务/广播四大滥用面逐一收回，PM-01 §1.6）；OH：出生即收紧（通用锁 API 10 废弃、四通道+配额+处罚，PM-02 §2.9/2.10） | **day-one 定死**（§5.2 逐项裁决表）：无裸 wakelock、推送单通道、定时三档+配额、订阅带 TTL、长时任务 reason u8+系统校验、默认冻结非杀。落点 = berry-sys ABI + berry-manifest + SDK 三口透传（#58） |
| **L3 硬件低功耗域层** | 触摸控制器四态、DDIC AOD 自持、sensor hub/低功耗 DSP、modem 自治状态机、音频 offload、USB 按口挂起 | 微软 HID 四态契约（[官方](https://learn.microsoft.com/en-us/windows-hardware/design/component-guidelines/touchscreen-power-management)，高）；Android CHRE（[官方](https://source.android.com/docs/core/interaction/contexthub)，高）；DDIC AOD 专利族（PM-04 §4.2） | v1 QEMU 无此域——**契约先行**：驱动服务 manifest 申报电源域/档位/唤醒延迟/依赖边；手势下载+假唤醒抑制+不读自回落进驱动契约；hub 域 API 留版本域不预实现（PM-05 §4.5） |

**每层缺位会怎样**（跨域互证）：缺 L0 = 白烧（tick 风暴）；缺 L1 = 各服务各自为政、
深态永远进不去（Linux 现状）；缺 L2 = Android 命运（15 年收权 + 保活军备竞赛）；缺 L3 =
AP 永远睡不死（第三方 AOD 用 wakelock 烬 AP 反面教材，PM-04 §4.2）；
**缺归因 = 四层全部盲调**（Android 归因迟到六年教训）。

**裁决 1（合一 vs 分立）**：PM-05 提 `pm_broker`（电源域仲裁）、PM-06 定 `berry-power`
（状态机中枢）——本报告裁决**合为一个服务的两张面**：状态机/票据/hint/归因是服务本体，
电源域拓扑（element 注册+lease+SetLevel）是其对驱动服务的域表接口。理由：Linux「无单一中枢」
是反面教材（PM-06 §5-8）；Windows「两台状态机」是十年骂名（PM-06 §5-2）；
微内核天然可以 day-one 指定唯一中枢。PowerBroker「仲裁器不做策略、只做拓扑一致性」的定位照抄。
**v1.1 注记（#2）**：Fuchsia 把仲裁（broker）与策略（cpu-manager）分家后协调层看不到性能意图、
hint 无对应物（PM-08 §8 P2 行）——合一裁决加固，**hint 面必须留在 berry-power 本体**，不随域面拆出。

**裁决 1b（热治理与充电服务边界，v1.1 新增 #3/#27 → ADR #66）**：**berry-thermal 独立常驻服务
（与 berry-power 同级）**——订阅驱动自报 trips（`{sensor_id, kind, temp_mc, trips[{level,
threshold_mc, clr_mc}]}`，中断优先+轮询兜底）→ step_wise 查表+迟滞仲裁（PID over EM 留 v2）→
三类输出：频率帽写请求 / 充电限流票 / thermal_level 档位；**帽不新开通道**（汇入 berry-power
同一内核聚合点取 min，对调度器=系统态叠加票只叠加）；失败隔离=「热服务亡→帽保持」（安全侧保持
限频）+ critical trip 内核短链关机兜底（独立于用户态存活）；JEITA 充电温区五档=第一张系统热表
（硬安全约束优先于性能热档）；charge_current_limit 票（P11 电流版）由 berry-thermal 出票。
同族第三服务 **chargerd**（PM-14 §4.1：与 berry-power/berry-thermal 同级——电池驱动唯一客户端 +
BatteryInfo 暴露 + ChargeLimitArbiter 最少者赢 + governor 指数退避监督 2s→60s）。

**berry-power 通道 op 面**（同步 channel、C-ABI；服务面 op 不占 ~35 syscall 预算，PM-06 §6.1）：

| op | 语义 | 对应现役先例 |
|---|---|---|
| `POW_OP_SET_MODE` | 请求状态机迁移（带 reason）；显示服务 power·mode op 在此归一 | logind sleep 仲裁 |
| `POW_OP_ASSERT` | 持票 `{kind: block\|delay, reason, lease_ns}` → 票据句柄（=能力） | Windows activator + logind inhibitor |
| `POW_OP_RELEASE` | 还票；**断线自动回收**（失败隔离：持有者崩溃不泄漏票） | Fuchsia power broker LeaseToken 语义（FIDL 句柄，非 zx 内核对象） |
| `POW_OP_QUERY` | 枚举在持票据 + 现态 + 各态驻留时长（点名「谁拦着睡」） | SleepStudy 可观测面 |
| `POW_OP_HINT_SESSION` | `{target_ns}` 建会话 → `{actual_ns}` 回报 | ADPF hint session（#53 环泛化） |

**遥测最小字段集**（三层归因的数据面；v1.1 定案 #5/#14/#26）：per-source **七字段**
`{id, name, first_signal_ts, last_signal_ts, last_ack_ts, count, flags}`（Fuchsia WakeSourceReport 直抄）
+ **持有者归因超集**（uid/服务名，强于 Fuchsia 只有 koid→驱动名；名字在 platform-bus 侧翻）
+ 两个崩溃签名断言（「该睡不睡 N 周期=测试失败」/挂起回调环检测）+ 与 A4「无主唤醒=失败」绑定；
per-UID（CPU 时间/唤醒次数/票据持有时长/**无票活动计数=泄漏探测器**，batterystats 同型）；
per-session（DOZE/SUSPEND 驻留占比 + 进深态失败次数 + 最后否决票 reason，DRIPS 同型 KPI）；

**跨系统规律十条**（合并 PM-01 §3.3 R1–R8 + PM-03 §7 + PM-06 §5，全部有源）：

1. 权力下放容易、回收极贵（每份「自由」用否决层+权限+配额+度量四件套赎回，历时 5–15 年）。
2. 形状决定命运（API 形状即滥用面）。3. 默认值即生态（默认批处理/默认冻结，例外走权限）。
4. 度量先于治理（能量化才可治理；罚则是契约的执法部分）。
5. 缺席的统一通道必被民间自建（无推送→N 条心跳；无归因→野路子诊断）。
6. 收权必先给出路（例外通道成对出现，否则「闹钟不响」级用户回归逼平台回退）。
7. 固定心跳是待机头号敌人；定时器精度必须分层（交互精确、后台宽松）。
8. 隐式链路省电机制坑多（PSR 闪烁、TWT 兼容性同构）——省电机制必须显式化进契约。
9. 策略进内核/仲裁器 = 换了地方的宏内核（QNX APS 判例，17 号 §5-3）。
10. 跨所有权的省电动作必须协议协商（fast dormancy 信令风暴被网络反制，PM-05 §2.1）。

**BerryOS 最可能重蹈的辙（PM 特化诚实清单，接 18 号 §5.2 通用版，本报告只补省电线）**：

1. **契约窗口错过 = Android 命运**：berry-sys ABI 冻结时若漏了 B1/B3/B5/B8 四件（唤醒窗口/三档定时/
   订阅租约/能力类别），后面每一条都只能走「否决层」补课——这是唯一不可逆的坑（R1/R7）。
2. **归因后置 = Battery Historian 六年空窗重演**：若 wakeup 记账面不先落，「谁耗的电」在用户/
   开发者之间永远是罗生门，一切省电机制无法验收（R5）。
3. **保活军备竞赛窗口期**：多应用生态成形前若默认冻结+统一推送没到位，头部 app 自建长连接一旦
   成为事实标准就再也收不回（R3/R8，中国生态十年教训）。
4. **「太早优化外设」之祸**：QEMU 无真外设，若先写实现不先冻契约，真机接入日=契约重定日——
   顺序必须是「契约冻结 → sim-modem 压测 → 真机计量先行」（PM-05 §4.5）。
5. **中枢膨胀之祸**：berry-power 若把策略（频率算法/桶位 ML/维护窗口径）长进仲裁面，就是换了
   地方的宏内核（QNX APS 判例）——仲裁器只做拓扑与记账，策略全在可插拔面（铁律 2/12）。

### 5.1 v1（QEMU 窗口）：机制面预留的协议位/接口缝清单

### 5.3 绝不踩坑清单（反面清单，供评审 checklist；v1.0 十条 → v1.1 十六条 #16/#30）

1. 不做任何形式的全局开关（定时器精度/帧率/频率）——Windows 30 年教训。
2. 不让 GUI/网络/FS 各自协商电源态——状态机唯一持有者 berry-power，其余只投票。
3. 不承诺 per-app 实测毫安时——轨级实测+时间记账+模型分摊是物理上限，叙事按估算口径。
4. 不给 AI 直接设频设帧率通道——现役 ML 实绩全部收敛在「预测准入」（Adaptive Battery 出口是桶位非频率）。
5. 不做 DAM 式两代应用模型分裂——挂起/降档语义对全部 app 一套（无历史包袱是唯一窗口）。
6. 不做隐式链路省电——任何「软件不感知的链路层自作主张」必须以状态+事件暴露（TWT/PSR 同构坑）。
7. 不让归因后置——归因面与机制面同刀落地（Battery Historian 迟到六年的教训）。
8. 不在生态成形后再收权——「先给方便后收回」= Android 命运的唯一入口。
9. 不做模型值冒充实测值——归因输出必须区分 measured/modeled（AOSP 假表教训）。
10. 不给普通 app 心跳/保活/扫描原语——省电契约的执法部分从 SDK 面就不存在，而非存在但劝阻。
11. 不做热治理黑箱——档位→动作表可 dump、决策可审计，对抗厂商 override 放水（Android thermal 只读且文档口径打架的教训，PM-07 §3-3）。
12. 不做第二套治理数值源——遥测/文档/策略表单一权威源且可互相核验（Android 三处文档配额口径打架、源码才是真值，PM-11 §3-3）。
13. 不让仿真专用分支进主线——sim 设备与真机共用同一 guest 接口（仿真绿传递律，PM-10 §3-8）。
14. 不做 PD/快充协议本体进 OS——消费协商结果快照+角色事件即可，600 行固件逻辑收益为零（PM-14 §4.5/PM-15 §4.5）。
15. 不做 app 侧充电控制 API——两大平台一致「面不存在」；限充是用户设置不是应用能力（P11 单向棘轮，ADR #68）。
16. 「无 API 也是 API 形状」入评审 checklist——面不存在优先于面存在但受限（执法成本维度，PM-15 §4.5）。

**规律 → 机检断言映射**（把 §3 十条规律折成 G0–G5 可执行面，AI 测试友好化支柱的 PM 展示位）：

## §7 开放问题与后续建议

**开放问题**（按风险排序）：

1. **pushd 的云端对端**：单长连接的省电机理依赖「云到端一条路」，自建推送云 vs 接第三方 vs 仅本地批处理——涉及运营主体，架构报告无法独裁，需产品层裁决（影响 P4 契约的云侧字段）。
2. **per-app 能耗账的标定路径**：L1 模型表参数无真机前只能用公开 datasheet 值占位（明知占位、显式标注 modeled）；第一块真板「先接计量再接功能」（PM-05 §4.5-3）。**【v1.1 部分收窄 #22】**：measured/modeled 纪律+A/B 官方方法论收窄标定歧义；真机计量部分仍开。
3. **维护窗/Doze 语义在无 GMS 生态的形态**：维护窗口径（Android 无官方数字、实测递减）需在 sim-modem 上自定标——建议做成策略表项并进遥测对比。**【v1.1 关闭 #19】**：sim-modem 自定标基线表 12 项初值已定（全部 Android 生产默认+出处，PM-11 §2.4）；策略表项全遥测导出对比自定标。
4. **桶位规则版 vs ML 版**：v1 规则式（现役 ML 只做准入且出口是桶位，Adaptive Battery 同构）；ML 分桶挂 AI 实验轨道 + kill criteria（M4 前无可测收益→永久 hint-only，铁律 13）。**【v1.1 收紧 #21】**：v1 规则式不变；ML 分桶挂实验轨道受 KC-P1..P5 判据+豁免位前置（ADR #68）。
5. **真机硬件契约验证**：触摸控制器四态/手势下载/DDIC AOD/LTPO×亮度耦合在 QEMU 全不可验——驱动 manifest 契约先冻结，验证留真机线。
6. **多窗 vote DoS**（GUI-06 开放问题 6）：单 GUI 进程阶段不可达，多窗刀（v2+）前必须裁限额。
7. **挂起期间时钟语义**：Fuchsia 定 monotonic 暂停；BerryOS 需在挂起四原语刀内同步裁决（应用时间观一致性）。**【v1.1 关闭 #20 → ADR #67】**：主钟停+显式 SLEPT 连续钟+POSIX 映射显式声明已立法（slept_ns/suspend_count 记账面先行，累加载体挂 sim-S3 回填）。

**【v1.1 #23】**开放问题 1/5/6 保持开放：1 待产品层裁决（pushd 云端）；5 押后清单与契约冻结路径见 PM-10 §4.4（真机线）；6 归 GUI 多窗刀（v2+）。
