## §0 一页结论（土话直答）

**充电子系统的行业终态一句话：算法和安全兜底全在硬件，OS 只做三件事——诚实汇报、限值仲裁、状态机联动。**

1. **硬件拥有计算**：CC/CV 充电曲线、JEITA 温区分档、USB-PD/私有快充协商、SoC 估计（Impedance Track/ModelGauge）全部活在充电 IC、PD 控制器固件和 fuel gauge 芯片里；保护 IC + CID/PTC 是独立于 OS 的硬件安全底线。OS 侧**写不出也更不该写**这 600 行状态机（§2.1/§2.2/§2.3）。
2. **OS 的职责收敛为三件**：① 汇报——BatteryInfo 类契约（Fuchsia 15 字段已成事实标准，PM-08 §6）；② 仲裁——各方（用户 80% 开关/热服务限流/电池健康/自适应充电）投票限充电，**充得最少者赢、只许收紧不许放宽**（Fuchsia ChargeLimitArbiter 原文 "the vote that charges least wins"，高）；③ 联动——插电是电源状态机一等输入（Android 官方原文：连接充电器即退出 Doze）、低电触发省电档迁移、关机充电是独立最小系统模式（§2.7）。
3. **业界最大的坑是契约缺席**：Android 至今**没有公开的充电限值 API**（Android 14 只加了只读 cycle count），于是 Samsung 85%、Pixel 自适应、Apple 80% 各自为政——BerryOS「应用契约 day-one 定对、窗口一次性」在此域再次成立（§2.4/§4）。
4. **假关机是物理不是 bug**：低温内阻骤增 × 负载瞬间压降 → 未到 0% 即保护性关机，回暖即恢复；batterygate（Apple 2017 性能降频丑闻）的根因链正是「老化电池峰值功率不足 → 意外关机」。关机决策必须带**电压滞后带**且与 UX 展示解耦（§2.5）。
5. **BerryOS 落法**：用户态 `chargerd`（电池/充电驱动唯一客户端 + 限值仲裁器 + BatteryInfo 暴露）+ P11 充电限值票协议位 + BatteryInfo 增量字段（cycle/soh/charge_limit/measured 标注/JEITA 档）+ sim-battery 三场景断言，接缝归 berry-power（状态机）与 berry-thermal（限流动作）——与 PM-00 四层模型同构（§4）。

## §1 主线全景：从 CC 线到用户开关的六层

| 层 | 内容 | 载体 | OS 可见面 |
|---|---|---|---|
| L0 物理/协议 | Type-C CC 附件检测、Rp/Rd 电阻定角色、DRP 双角色翻转；USB-PD Source Capabilities→Request→Accept 协商、PPS 可编程电压、EPR 240W | PD 控制器芯片（CC 线上 BMC 编码） | 协商**结果**（charge_source + 电压/电流档），不参与状态机本体【高，§2.1】 |
| L1 充电 IC | 预充/CC/CV 三段、涓流终止、安全计时器；硅内 JEITA 温区分档；电荷泵降压升流、双电芯串联 | 充电管理 IC（BQ25xxx 类）+ 固件 | 目标电流/电压限值寄存器 + 状态/故障位【高，§2.2】 |
| L2 电池包 | 保护 IC（过充/过放/过流/短路，MOSFET 切断）+ 电芯内 CID（压力断路）/PTC（热敏限流） | 电池包硬件，独立于 SoC | 只读故障/健康位；**不可编程**【高，§2.6】 |
| L3 计量 | fuel gauge 芯片自算 SoC/SoH（库仑计+OCV 校正+学习周期），OS 读寄存器 | 计量 IC（BQ27xxx/MAX17xxx 类） | SoC/电压/电流/温度/循环数快照【高，§2.3；PM-05 §2.8】 |
| L4 OS 服务 | 电池/充电驱动 → chargerd（唯一客户端）：派生 charge_source、暴露 BatteryInfo watch、ChargeLimitArbiter 汇票、监督 governor 子组件 | 用户态服务（微内核下全用户态） | 本报告主题【高，§2.4/§2.7】 |
| L5 治理/UX | berry-thermal 限流票、电池健康降档、自适应充电（闹钟/AI 预测 80% hold）、用户 charge limit 开关、低电省电档、off-mode 关机充电 | chargerd governor + berry-power + 设置 UI | 用户可见契约【高/中，§2.4/§2.5】 |

**「插着充电器」在系统电源状态机里是什么角色**（必答清单收口，详细证据 §2.7）：三重身份——
① **状态迁移触发器**：Android 官方原文「When the user wakes the device by moving it, turning on the screen, or **connecting a charger**, the system exits Doze」——插电 = 强制退出深闲态；App Standby 同样「plug in 即释放」。
② **调度策略输入**：充电态是 JobScheduler/BGTaskScheduler/work_scheduler 的排期条件（PM-01/PM-02 已载）；插电时维护窗全开、网络配额解锁——「充电 = 燃料无限，耗电约束让位于时机约束」。
③ **挂起豁免面**：Fuchsia F29 起 Battery Manager 在充电期间**阻塞系统挂起**（PM-08 §6）；off-mode 充电则是独立最小系统（§2.7）。

## §2 关键事实与证据

### 2.1 USB-PD 协商与 Type-C 角色机（必答 1）

| 事实 | 证据 | 确定度 |
|---|---|---|
| PD 协商四步：Source 广播 Source Capabilities（能力表）→ Sink 评估发 Request → Source Accept/Reject → 电功率合同成立；系统电源变化可重发能力表 | [USB-IF 官方培训 D2T2-1](https://www.usb.org/sites/default/files/D2T2-1%20-%20USB%20Power%20Delivery.pdf) | 高 |
| PPS（可编程电源）：SPR 档内 20mV 电压步进 / 50mA 电流步进，让手机旁路内部 DC-DC 直充（按电芯电压实时要电压），是 PD 系内「直充」标准位 | [TI SSZTD49 设计指南](https://www.ti.com/document-viewer/lit/html/SSZTD49) | 高 |
| EPR（扩展功率，PD 3.1 引入）：28/36/48V@5A 上限 240W；进 EPR 模式需先 EPR Mode Enter 握手（EnterMode/ExitMode 消息对），高压才解锁 | [TI SSZTD49](https://www.ti.com/document-viewer/lit/html/SSZTD49) + USB-IF 同上 | 高 |
| Type-C 附件检测走 CC 线（非 VBUS）：Rp/Rd 电阻区分 Source/Sink，DRP 口在两角色间周期翻转直到对端锁住；eMark 线缆经 CC 广播载流能力 | [USB Type-C Spec R2.0 官方 PDF](https://www.usb.org/sites/default/files/USB%20Type-C%20Spec%20R2.0%20-%20August%202019.pdf) | 高 |
| 角色三轴独立：电源角色（Source/Sink/DRP）× 数据角色（DFP/UFP/DRD，DRD 即 OTG）× 附件方向；PD 的 Power Role Swap 与 Data Role Swap 是**独立的消息**，可分开换 | [Renesas USB PD Engineer School Part 3](https://www.renesas.com/en/support/engineer-school/usb-power-delivery-03) | 高 |
| OTG 供电角色切换 = 数据角色翻成 DFP + 电源角色翻成 Source（给外设供电）；USB-IF FAQ 特意澄清 Type-C DRP（数据）≠ PD DRP（电源），文档界最易混的一对词 | 同上 + USB-IF FAQ | 高 |

**对 BerryOS 的含义**：协商状态机本体（PD policy engine / device policy manager）属 L0/L1 固件；OS 消费的是稳定结果快照——`charge_source{none,usb_std,usb_cdp,usb_pd,dc,wireless}` + 协商到的电压/电流档 + 角色事件（attach/detach/role_swap）。**OS 不应重实现 PD 状态机，但要暴露角色变化事件**（OTG 翻转 = 电源域拓扑变更，PM-05 §4.2 已裁归 pm_broker/berry-power 域面）。

### 2.2 充电策略：CC/CV、多节串联、JEITA、快充生态（必答 2）

| 事实 | 证据 | 确定度 |
|---|---|---|
| 锂电充电三段：深放（<~3.0V）先**预充/涓流**（~0.1C）→ **CC 恒流**（0.5–1C，电压爬升）→ 到截至电压（~4.2V/cell）转 **CV 恒压**，电流锥削至额定的 ~3–5% 终止，安全计时器兜底 | [battery.mba 充电曲线](https://www.battery.mba/resources/lithium-ion-charge)、[Grepow 三阶段](https://www.grepow.com/blog/what-are-the-3-stages-of-lithium-battery-charging.html) | 高 |
| JEITA 温区五档：COLD/COOL/NORMAL/WARM/HOT；10–45°C 全速、0–10°C 降流（防析锂）、45–60°C 降压降流、>60°C/<0°C 停充——**现代充电 IC 在硅内实现该表**，OS 侧只是「知道当前档 + 可再收紧」 | PM-07 §2（[TI slyt365](https://www.ti.com/lit/pdf/slyt365)、[JEITA 官方指南 PDF](https://home.jeita.or.jp/upload_file/20210407112651_JbDgUSWGiB.pdf)）——本篇不重写 | 高 |
| 多节串联：百瓦级快充普遍双电芯串联（每节减半电压/充电 IC 压差减半）+ 电荷泵（约 2:1 降压升流），SuperVOOC 2.0（10V/6.5A=65W）为公开代表 | [cnblogs 快充协议全景](https://www.cnblogs.com/lijin-note/p/18828385)、[CSDN 协议对比表](https://aiot.csdn.net/6a82d0ac10ee7a33f29c19ae.html) | 中（厂商公开资料一致，未逐家核官方） |
| 私有快充三代形态（只扫描不深挖）：高压小电流（QC 200mV 步进/华为早期 FCP 9V2A）→ 低压大电流（VOOC 5V4–5A，手机端发热小）→ 电荷泵+双电芯（SCP 新版 5V8A、SuperVOOC 10V→泵后 5V8A） | 同上两源 | 中 |
| UFCS 融合快充：信通院+华 OV 米牵头，TTAF 083-2022 规范；截至 2025-09 认证 233 款（62 手机/89 充电器）；UFCS 2.0 到 40W，厂商互授权意向书已签——**中国的协议碎片收敛尝试** | [充电头网 UFCS 详解](https://www.chongdiantou.com/archives/339364.html)、[UFCS 认证数](https://www.ufcs.com/17981.html) | 中 |

**含义**：协议碎片（PD/PPS/QC/SCP/VOOC/UFCS）是**线缆+充电器+终端三方握手**的事，全部在充电 IC/PD 控制器里消化；OS 唯一必须稳定暴露的是「当前实际充电档位 + 可请求的目标限值」。BerryOS **不实现任何快充协议本体**——v1 QEMU 期无此硬件面，真机期它也是驱动/固件边界外的事。

### 2.3 SoC/SoH 估计与 fuel gauge 分工（必答 3，扩 PM-05 §2.8）

| 事实 | 证据 | 确定度 |
|---|---|---|
| 库仑计（安秒积分）短期准、OCV（开路电压）长期准，混合算法主流；SoC 精度典型 ±5%，满充容量需**学习周期**（完整充放+静置）校准 | PM-05 §2.8（[ADI fuel gauge 词条](https://www.analog.com/en/resources/glossary/battery-fuel-gauge.html)、[Battery University](http://www.batteryuniversity.com/article/battery-fuel-gauge-factual-or-fallacy)）——不重写 | 高 |
| TI 两条算法线：Impedance Track（在线测内阻 Ra 表更新）与 CEDV（10 点 OCV 表 + 放电末端电压补偿）；Qmax（化学容量）只在学习周期里更新——**SoH = FCC/design 的减损跟踪** | [TI sluaar3 白皮书](https://www.ti.com/lit/pdf/sluaar3) | 高 |
| Maxim/ADI ModelGauge 系同构：库仑计 + OCV 复位 + 周期性容量再学习，防止漂移 | [ADI SoC/SoH 技术文](https://www.analog.com/en/resources/technical-articles/a-closer-look-at-state-of-charge-and-state-health-estimation-tech.html) | 高 |
| **分工终态：硬件自己算 SoC/SoH，OS 读寄存器**。BQ27xxx（系统侧/host-side gauge）把 SoC/FCC/循环数做成寄存器值；OS 侧估算只存在于无 gauge 的低成本板（用 power_profile 模型，PM-05 §2.8 已载 Android 教训） | TI sluaar3 + PM-05 §2.8 | 高 |
| Android 14（API 34）才把 `EXTRA_CYCLE_COUNT` 加进 `ACTION_BATTERY_CHANGED` 粘性广播——只读健康面晚到了十几年，且设备可返回 -1 | [BatteryManager.EXTRA_CYCLE_COUNT 参考](https://learn.microsoft.com/en-us/dotnet/api/android.os.batterymanager.extracyclecount?view=net-android-35.0) | 高 |

**含义**：BerryOS 把 gauge 芯片当黑盒算法引擎，契约面只加 PM-12 P8 已裁的 `measured/modeled` 标注位——**OS 不重算 SoC，只标注读数的来源**（寄存器直读 vs 无 gauge 板的模型估计），归因诚实优先于精度。

### 2.4 充电 UX 契约（必答 4）

| 系统 | 机制 | 口径 | 确定度 |
|---|---|---|---|
| iOS 优化充电 | 学习惯常作息，充到 80% 后**hold**，临近起床时间才充满 | [Apple 官方支持页 108055](https://support.apple.com/en-us/108055) | 高 |
| iOS 充电上限 | iPhone 15+ 用户开关：80–100% 每 5% 一档 + 自适应档；同页含温控暂停说明 | 同上 | 高 |
| Pixel 自适应充电 | 闹钟驱动预测：插电（晚 9 时后）+ 闹钟（晨 5–10 时）才激活，80% hold 到闹钟前；新版本转「Google AI 预测长充电段」 | [Google 官方支持页](https://support.google.com/pixelphone/answer/6090612)、[9to5Google 机制文](https://9to5google.com/2020/12/29/pixel-adaptive-charging) | 高（机制）/中（时窗数字） |
| Android 公开 API | **无公开充电限值 API**——Samsung「Protect battery」85%、各厂商私有设置；app 只能读（Android 14 加只读 cycle count） | [Reddit OnePlus 讨论](https://www.reddit.com/r/oneplus/comments/11rndhj/is_it_possible_to_limit_charging_till_85_or_90)（无公开 API 的反证）+ 上行 EXTRA_CYCLE_COUNT | 中-高 |
| Fuchsia | ChargeLimitArbiter 汇 governor 票，**"the vote that charges least wins"**（充得最少者赢）； governors 独立子组件、指数退避监督（2s→60s）；驱动断连重连 1s→60s | [Fuchsia battery-manager README](https://fuchsia.googlesource.com/fuchsia/+/refs/heads/main/src/power/battery-manager/) | 高 |
| 夜间涓流本质 | CC/CV 末期电流锥削 + 80% hold = 让电芯少在高压区停留（老化主要发生在高 SoC 段），非独立涓流模式 | battery.mba（§2.2 同源）+ Apple 108055 表述 | 中（机理归纳） |

**三条契约级教训**：① 充电限值是**用户主权开关**，不是 app 可写项——Android 无标准 API 的碎片化是反面教材；② 限值有**两级语义**：硬上限（用户 80%）与 hold-到-时刻（自适应），Apple 两者都做成显式 UI；③ 预测型 hold 的输入（闹钟/作息）是典型 AI 轨道素材但**出口只能是限值票**（铁律 3「AI 只投票」在此域同构）。

### 2.5 临界电量行为链（必答 5）

| 环节 | 事实 | 证据 | 确定度 |
|---|---|---|---|
| 极低电量保留面 | iOS 电量耗尽自动关机后进 **Power Reserve 模式**，Find My（BLE/UWB）与快捷交通卡仍可用约 5 小时——「关机」不是断电而是进保留态 | Apple 社区与媒体口径一致（如 [Apple 社区讨论](https://discussions.apple.com/thread/255543953)）；未取到官方 5h 页 | 中 |
| 假关机（低温） | 低温电解液内阻骤增：空载电压正常、一加载即瞬间压降触发低压保护关机——**剩 20–40% 也可能关机**，回暖恢复；-5°C 实测耗电为 20°C 的 1.7 倍 | [知乎低温关机解析](https://zhuanlan.zhihu.com/p/27614809004)、[搜狐科学实验](https://www.sohu.com/a/57039826_216273) | 高（机制）/中（数字） |
| 关机电压滞后 | 关机阈值与重启阈值分离（负载下压降关机 vs 空载回升可开机）——重启判定必须留滞后带，否则「关了又开又关」振荡 | 低温关机维修文归纳（知乎同上） | 中 |
| 老化×低温复合 | batterygate：老化电池+低温+低 SoC 时峰值功率不足 → 意外关机；Apple 2017 起隐藏式 CPU 降频防关机 → 被发现后道歉+$29 换电池+ Battery Health UI（最大容量%/峰值性能管理开关） | [Apple 官方性能页](https://support.apple.com/en-us/101575)、[Wikipedia Batterygate](https://en.wikipedia.org/wiki/Batterygate) | 高 |
| 低电省电档 | iOS 低电模式 20% 触发、充到 80% 自动退出；Android Battery Saver 同构（PM-02 §2 已载不重写） | PM-02 | 高 |

**含义**：① 关机决策不能只看 SoC——**电压 sag + 温度 + SoH 三输入**，且带滞后带；② 「关机」在契约上应是**可选保留态**（保留 BLE 定位/交通卡），这要求最小可存活域 day-one 规划（与 PM-00 L3 低功耗域、PM-05 §4.5 hub 域同族）；③ 峰值功率不足的 UX（降频 vs 关机）是诚实性议题——batterygate 的错不在降频在隐瞒。

### 2.6 电池安全与归属（必答 6）

| 层 | 机制 | 载体 | 确定度 |
|---|---|---|---|
| 一级（电子） | 保护 IC + MOSFET：过充（~4.25V/cell 切断）、过放、过流、短路——**独立于 SoC/OS 通电即工作** | 电池包 PCB | 高（[BU-304](http://www.batteryuniversity.com/article/bu-304-why-are-protection-circuits-needed)、[EL-CELL](https://www.el-cell.com/how-does-a-protection-circuit-work-in-a-lithium-ion-battery)） |
| 二级（机电） | CID（电流中断装置：内压永久断路）、PTC（高温阻值跃增限流）、泄压阀——电芯内部，最后防线 | 电芯本体 | 高（同上） |
| 硅内 JEITA | 充电 IC 温区分档降流/停充，不依赖软件 | 充电 IC | 高（PM-07 §2 TI slyt365） |
| 软件责任 | 温区表之上的**再收紧**（热服务限流、用户 80%、健康降档）；**无任何「放宽」路径**——软件单向棘轮 | OS | 高（各层证据合成 + PM-07 裁决 8 同向） |

**归属裁决**（BerryOS 视角）：安全兜底永远在 L2 硬件（OS 死机充电仍安全）；OS 的全部职责是**收紧**与**上报**（故障位透传、JEITA 档暴露、限值仲裁只减不加）。这条「只许收紧不许放宽」应写成 chargerd 的接口不变量——**不存在任何 raise-current/raise-voltage 的 ABI 位**。

### 2.7 状态机联动与 off-mode 充电（必答 1 后半）

| 事实 | 证据 | 确定度 |
|---|---|---|
| Android Doze 进入条件 = 静止+灭屏+**未充电**；「moving it, turning on the screen, or **connecting a charger**」任一即退出（官方原文）；App Standby 插电即释放 | [Android 官方 Doze 文档](https://developer.android.com/training/monitoring-device-state/doze-standby)（本篇 WebFetch 原文核验） | 高 |
| 充电态是任务排期一等条件：JobScheduler 充电条件、iOS BGProcessingTask 可要求充电、鸿蒙 work_scheduler 充电类型条件 | PM-01 §1/PM-02 §2（已载不重写） | 高 |
| off-mode（关机）充电：Android 13+ 若支持，health HAL 服务二进制本身进 charger 模式跑充电动画（`/system/bin/charger` 独立充电器程序弃用中）；最小系统环境 | [Android system health 官方文档](https://source.android.com/docs/core/perf/health) | 高 |
| Fuchsia：Battery Manager 是电池/充电驱动**唯一客户端**，governors 不直连驱动；状态缓存服务下游（governors 不加总线读）；F29 起充电期阻塞挂起 | [battery-manager README](https://fuchsia.googlesource.com/fuchsia/+/refs/heads/main/src/power/battery-manager/) + PM-08 §6 | 高 |
| Fuchsia 仿真路径：无真电池设备上 Battery Manager 暴露 `fuchsia.power.battery.test.BatterySimulator` 模拟电池数据；Sorrel 板例外（驱动直出 BatteryInfoProvider 绕过 manager） | 同上 README | 高 |

## §3 教训与坑

| # | 坑 | 证据 | 对 BerryOS |
|---|---|---|---|
| 1 | **充电限值 API 缺席 → 厂商碎片**：Android 无公开 API 十余年，Samsung 85%/Pixel adaptive/一加长期没有，跨品牌体验不可移植 | §2.4 | day-one 冻结 charge-limit 契约（用户开关只进系统设置，app 只读） |
| 2 | **把 gauge 智能当 OS 算法做**：无 gauge 板用 power_profile 模型兜底，填错值全错（Android 耗电排行失真史，PM-05 §2.8） | PM-05 | OS 不算 SoC；契约带 measured/modeled 位（PM-12 P8） |
| 3 | **假关机当软件 bug 修**：低温内阻骤降是物理，回温自愈；错误归因会带偏关机阈值 | §2.5 | 关机决策三输入（电压 sag/温度/SoH）+ 滞后带；sim-battery 造同场景 |
| 4 | **batterygate 隐瞒式降频**：防意外关机的性能管理本身正当，不可披露才是灾难 | §2.5 | SoH/峰值功率约束进遥测与 UX 可见面（对齐 PM-07「一切降档必须上报」） |
| 5 | **off-mode 充电被当普通 boot**：关机充电是独立最小系统（health HAL charger 模式），完整系统起不来时它必须仍工作 | §2.7 | chargerd 设计须支持降级最小形态（无 berry-power/无 FS 时仍出充电 UI 骨架） |
| 6 | **PD 状态机进 OS**：重实现协议层（能力表/重协商/EPR 握手）是把 600 行固件逻辑搬进内核/服务，收益零 | §2.1 | OS 只消费协商结果快照 + 角色事件 |
| 7 | **Sorrel 式捷径绕过治理**：驱动直出 BatteryInfo 省了 manager，但限值仲裁与监督面就没了 | §2.7 | thin path 可留给无治理需求的最小板，但只要有限值票就必须过 chargerd |
| 8 | **充电限值多源打架**：用户 80%、热限流、健康降档同时在场，谁赢不明确就互相覆盖 | §2.4 | 显式仲裁语义：充得最少者赢（Fuchsia 同构），且只许收紧 |

## §4 BerryOS 启示（可执行面）

### 4.1 chargerd 职责面（用户态服务，与 berry-power/berry-thermal 同级）

| 职责 | 形状 | 依据 |
|---|---|---|
| 驱动唯一客户端 | 电池/充电驱动（gauge + charger 两类）只对 chargerd 开 channel；governors 不直连驱动（Fuchsia 明文） | §2.7 |
| BatteryInfo 暴露 | watch 回调 + 缓存快照服务下游（下游不加总线读）；charge_source 变化事件携带 P1 wake lease 接力（抄 PM-08 §6 baton 语义） | §2.7 + PM-08 §6 |
| ChargeLimitArbiter | 收票→**取充得最少者**→写充电驱动限值寄存器；票面 `{limit_pct, reason:u8, holder}` | §2.4 |
| governor 监督 | governor 为子服务：崩溃指数退避重启（2s→60s），不影响电池信息面可用性 | §2.7 |
| 只收紧不变量 | ABI 无任何放宽位；仲裁输出 ≤ 硬件/JEITA 当前档 | §2.6 |

**不做**：SoC 算法（L3 硬件）、PD/快充协议（L0/L1 固件）、热降档决策（berry-thermal）、状态机迁移决策（berry-power）、温度表本体（电池驱动自报）。

### 4.2 电池信息契约（BatteryInfo v1 = Fuchsia 15 字段 + 增量）

- **基底直接抄**：PM-08 §6 已核的 15 字段（level_percent、level_status(含 LOW/CRITICAL)、time_remaining、remaining_charge_uah、full_capacity_uah、present、平均充电电流、temperature_mc、timestamp、battery_spec 设计容量…）。
- **增量五件**（PM-14 新裁）：

| 字段 | 形状 | 依据 |
|---|---|---|
| `cycle_count: u32` | 硬件报，无则 -1/None | Android 14 EXTRA_CYCLE_COUNT 教训（§2.3） |
| `soh_percent: u8` | FCC/design 派生，gauge 直报优先 | §2.3 |
| `charge_limit: {pct: u8, holder: limit_source}` | 当前生效限值 + 归属（user/thermal/health/adaptive）——仲裁结果对外可见 | §2.4 仲裁透明 |
| `meter_source: measured\|modeled` | PM-12 P8 已裁，此处落位 | PM-12 §2 |
| `jeita_zone: u8` + `shutdown_imminent: bit` | 温区档（驱动自报表的当前档）；临界预警位（低电迁移链输入） | §2.5/§2.6 |

### 4.3 协议位与接缝（延续 P1–P10 命名空间，add-only）

| 位 | 形状 | 接缝 |
|---|---|---|
| **P11 充电限值票** | `CHG_OP_VOTE_LIMIT{limit_pct, reason:u8}` / RELEASE / QUERY；仲裁=最少者赢；holder 断线自动撤票（同 P1 语义） | chargerd 持有；berry-thermal（PM-07 裁决 8 的 charge_current_limit 即此票的电流版）、电池健康 governor、adaptive governor、用户开关四方 |
| **charge_source 事件进 berry-power** | attach/detach/role_swap = 状态机输入事件：强制退出 DOZE 等价态 + 维护窗全开；OTG 翻转走电源域拓扑变更（PM-05 §4.2） | berry-power（状态机唯一持有者，PM-00 裁决 1） |
| **低电迁移链** | soc≤阈值(20%)→power_save 建议票；≤5%→critical 档+关机倒计时；`shutdown_imminent`→保留态预案（BLE 定位/交通卡最小域） | berry-power 档位 + PM-00 L3 低功耗域预留 |
| **充电期挂起策略** | 显式位：充电中阻挂起（Fuchsia F29 同构）或允许挂起（off-mode 由最小系统接管）——进 P9 挂起档表同域 | PM-11/P9 |

### 4.4 sim-battery 契约要点（喂 PM-16）

PM-10 §4.2 已定骨架（原子快照寄存器组 + 版本号递增，禁止多写拼装）。PM-14 增补：

1. **字段面**对齐 4.2 契约全集（含增量五件）+ charge_source 枚举 + 角色事件注入位。
2. **三场景断言**（挂 G0–G5 smoke）：
   - **A-CHG1 可观察性**：注入充电状态变化 → watch 回调 + charge_source 事件进 berry-power（一次注入必达，无顺序敏感）；
   - **A-CHG2 限值仲裁**：注入两票（user 80% + thermal 60%）→ 生效 charge_limit=60 且 holder=thermal；撤 thermal 票 → 回 80%——**只收紧可回弹、放宽仅因更严票撤销**；
   - **A-CHG3 低电迁移**：注入 soc 递减序列 → power_save/critical 档按序迁移；注入「低温 sag」快照（soc=35% 但电压塌）→ 关机决策带滞后带不振荡。
3. **off-mode 形态**：sim-battery 在最小系统（无 berry-power）下 chargerd 仍能出充电状态面——监督退化断言。

### 4.5 v1 排序（QEMU 窗口）

契约与断言先行（0 硬件依赖）：BatteryInfo v1 冻结 + P11 票位 + sim-battery 三断言 + berry-power 接缝事件——真机期才接 PD/charger IC/gauge 驱动。**充电域没有任何理由进内核**（无启动关键路径、无热路径），全用户态落位即微内核五原则的标准应用。
