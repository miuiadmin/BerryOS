# 刀 1 前置方案 B：归因完备面（2026-11-07，v1.0）

> 立场设定：**归因完备面**——宁可多花协议位，也要让 per-source 记账与持有者归因一步到位；
> 动态注册（驱动 manifest 进内核登记）优先；导出通道按最完备遥测形态设计（允许新号，附预算对账）。
> 刀 1 = 内核 wakeup 记账面（PM-00 落地刀 1：per-source 唤醒归因 + 无主唤醒 = smoke 失败）。

## §0 裁决一页（土话直答）

1. **源 id**：内核双段铸造——编译期静态段（定时器/UART/SGI 等内核自源）+ 运行期动态铸造段
   （驱动 manifest 经 berry-power 登记进内核槽表）；id→人读名映射**全在用户态**（berry-power 持
   manifest 名表），内核只存 32bit 名字哈希（`name_id` 同源）。「无主唤醒」内核可判：判据 =
   登记与存活，不依赖名字。
2. **导出通道**：新号 **0x64 `telemetry_open(kind, options) → VMO 快照句柄****——快照烘焙成只读
   VMO，读面全部复用既有 `vmo_read`/`vmar_map`；另有 **0x88 `pm_wake_src_register` 冻结预留**
   （在册未实现恒 -ENOTSUP，0x85 同款模式）。
3. **预算对账**：35 = abi.toml stage="v1" 行数（`nr_total` 生成器校验）；39 = abi_gen 全 stage
   常量（35 v1 + 4×"1.1"）；38 = syscall.rs `reg()` 数（0x85 未挂）。三个口径各自为真、缺的是
   单源对账。修法 = `gen_abi.py` 增发 `nr_defined` 与 `nr_ceiling=45`（ADR #11 上限）机器断言
   + 陈旧头注机器再生。刀 1 后：defined 41 / registered 39 / nr_total 35 不变 / 距帽余 4。
4. **小项③**：WakeRec 32B→**40B**（趁零消费者窗口扩 `src:u16 + flags:u8 + owner:u32`）**加**
   per-source 不淘汰计数器组（48B×32 槽静态表，P10 七字段+持有者归因超集）——环看模式、计数器
   做对账，两者都做。
5. **小项④**：记账时间戳照旧 CNTVCT 原始周期（公约 5）；SLEPT 域以 `flags` 时域位 + 快照头
   `slept_ns/suspend_count` 字段 day-one 定型（挂起刀前恒 0，挂起刀只写值不改 ABI）。

## §2 问①：源 id 铸造与名字映射归属

### 2.1 取舍表

| 候选 | 利 | 弊 |
|---|---|---|
| A 内核静态表（编译期枚举写死） | 零运行时成本；id 天然跨 boot 稳定；day-one 可穷举（QEMU 源仅 4 个） | 用户态驱动永远进不来——每新设备 = 内核重编译，违背「驱动全在用户态」五原则；归因面停在 QEMU 玩具档 |
| B 纯运行时铸造（谁先来谁先得） | 灵活；内核不认识设备类型 | id 随注册顺序漂移——跨 boot 不可比，遥测断言与 smoke 全部失去稳定键；「无主」判定仍需另一套存活追踪 |
| C 驱动 manifest 注册（登记进内核槽表） | 与 #43/#55 应用模型同构（manifest 声明能力）；名字映射天然落用户态；真机驱动与 QEMU 内核源同一套账 | 需要内核←用户态登记面（协议位 +1）与能力门控；登记面今天没有消费者（berry-power 未落） |

### 2.2 终选：**双段铸造 = A(内核静态段) ∪ C(manifest 动态段)**，名字映射全用户态

- **静态段（1..=15）**：内核自源编译期铸造进 const 初始化槽表——`1=WS_TIMER(CNTV27)`、
  `2=WS_UART_RX(33)`、`3=WS_SGI_RESCHED`、`4=WS_SGI_TLB`、`5=WS_IPC(同步信号伪源)`、
  6..=15 预留。const 初始化 ⇒ 零 boot 时序问题（早于 telemetry::init 的首笔唤醒也有归属）。
- **动态段（16..=1023，wsid u16 上限内）**：运行期单调铸造、**永不复用**；登记面 = 0x88
  `pm_wake_src_register`（冻结预留，见 §3.3）；驱动在 berry-manifest 声明
  `wake_sources: [{name, class, flags}]`，由 berry-power/appd 翻译登记——内核永不认识「驱动」
  与「应用」（#43），只见到「一个名字哈希 + class + 持有者域」。
- **幂等键 = name_hash（FNV-1a-32，`name_id` 同源）**：驱动重启重登记返回同 wsid——id 稳定性
  由名字而非顺序承重（回应 B 的漂移弊）。
- **id→人读名映射全在用户态**：内核槽表只存 `name_hash:u32`；berry-power 持 manifest 名表反查。
  Fuchsia koid→驱动名同样在 platform-bus 侧翻（PM-08 §8 P10 同构先例）——机制（id/存活判定）在
  内核、命名与治理（策略）在用户态，正落 PM-12 §3.2 既裁。

### 2.3 登记槽形状（P10 七字段 + 持有者归因超集，静态 .bss ≈1.5KB）

```rust
#[repr(C)]                     // 48B/槽 × WS_SLOTS(32) —— 不淘汰的记账面
struct WsSlot {
    wsid: u16,                 // 0 = 空槽；1..=15 静态段；16.. 动态铸造
    class: u8,                 // 1=IRQ 2=SGI 3=IPC 4=KERNEL(其他内核源)
    flags: u8,                 // bit0 ORPHANED；bit1 UNMONITORED(P1 预留)；余预留
    owner: u32,                // 持有者域 id（= Task.pinned，billing 同轴；0 = 内核自持）
    name_hash: u32,            // 名字本体在用户态；无主判定不依赖它
    count: AtomicU64,          // 唤醒计数（记账面——不随 trace_off 关）
    first_ts: AtomicU64, last_ts: AtomicU64,     // 首次/最近信号 vct（原始周期）
    last_ack_ts: AtomicU64,    // 最近 ack vct：IRQ 类 = EOIR 点；IPC 类 = 被醒任务首切点
}
```

P10 对表：{id ✓, name（用户态+hash ✓）, first_signal_ts ✓, last_signal_ts ✓, last_ack_ts ✓,
count ✓, flags ✓} + **owner**（Fuchsia 只有 koid→驱动名、应用侧无归因——我们的超集，PM-08 §8
原文自认此弱项）。ack 语义：IRQ 类在 `gic::end` 点戳（IRQ 延迟归因）；IPC 类借 `Task.wake_vct`
戳接力——on_switch 钩子见 `next.wake_vct != 0` 即回填该源 ack 并清戳（G3-4a 戳「不随遥测关」
先例，零新 TCB 字段）。

### 2.4 「无主唤醒」内核可判——三类定义 + 判定机制

归因通路的接线（不改 sched 公共 API）：

- 新增 HAL 回调槽 `set_irq_source_hook`（lib.rs 三槽反转同款）；`exception_irq` 在
  `acknowledge` 后立即调 kernel 实现 = `wsid 查表 + 置 per-CPU 归因标 ws_cur + first/last_ts`；
  handler 退出前清标。IRQ 窗内的唤醒（timer 扫睡客、uart RX wake_matching）在标有效期内。
- 同步信号路径（channel_send/object_signal 在 SVC 语境唤醒对端）不经 IRQ：`ws_cur==0` 时
  on_wake 现场取 `current_pinned()`（发送者即原因持有者，billing 同轴）+ `src=WS_IPC`。
- 持有者存活：进程退出路径（`exit_current_with` drain 钩子先例）扫槽表，owner 命中 →
  `ORPHANED` + owner 清零。O(32) 稀有事件，热路径零成本。

三类无主（各配独立计数器，A4 断言的谓词源）：

| 类 | 定义 | 判定机制 |
|---|---|---|
| A | IRQ 无注册源（id 不在任何槽） | 查表 miss → `irq_unattributed++`（沿用 trap.rs 未知源 loud 前 4 次打印） |
| B | 源在但持有者已死 | wake 落在 ORPHANED 槽 → `orphaned_wake++`（环内 flags 标记，src 保留可追尸） |
| C | 唤醒链断在内核 | on_wake 时既无标又取不到同步归因（结构性 bug）→ `chain_break++`，环内 src=0 |

内核判定**只用登记与存活**，永不需要名字——名字缺席不构成无主（这是把映射放用户态仍可判的
关键）。归因守恒：新增**不随 trace_off 关**的总账 `WAKE_ACCT_N`，恒等式
`Σ_ws count + Σ ownerless(ABC) == WAKE_ACCT_N`（每笔唤醒恰入一账）。

### 2.5 预辩

- **「微内核极简，名字表进内核才一步到位」**——机制/策略二分是 PM-12 §3.2 既裁；内核留 32bit
  哈希已让无主判定自足，名字是展示与治理面。给内核塞字符串表才是对极简原则的背叛。
- **「manifest 登记让内核依赖用户态服务」**——方向反了：登记是内核暴露的登记面（0x88 冻结），
  berry-power 未落时内核静态段自足（刀 1 纯内核面纪律不破，PM-12 §3.2）；动态段激活是驱动刀
  的事，激活前 0x88 恒 -ENOTSUP。
- **「双段太复杂」**——静态段是 const 数据不是机制；动态段是同一张槽表的高位区间。复杂度
  花在唯一值钱的地方：真机驱动与 QEMU 内核源共用一套账、一套断言。

## §3 问②：遥测导出通道形状

### 3.1 取舍表

| 候选 | 利 | 弊 |
|---|---|---|
| ① 新号 `telemetry_open` → 快照 VMO（复用 vmo_read/vmar_map 读面） | 一号一面；读面零新号（对象几何走既有 VMO 通路）；只读权利位天然表达「策略服务零书写面」；berry-sys 镜像 +1 函数 | 需内核侧「烘焙快照进 VMO」小机制（约几十行：建 VMO + seqlock 逐条一致拷贝） |
| ② 新号 `telemetry_read(buf)` 纯拷贝 | 实现最简 | 裸指针出参绕开对象模型；每次全量拷贝无版本锚；与「将来 telemetry_open 映射」注记相悖 |
| ③ 既有通道复用（内核任务经 channel 推送） | 零新号 | 环数据经 IPC 拷贝中转 = 铁律 7 明禁形态；需常驻内核生产者任务，热路径加锁面 |
| ④ 服务轮询共享 VMO（live 映射内核静态环） | 零拷贝最完备 | 内核静态内存→VMO 后备机制不存在（pager 面方向相反）；seqlock 读者纪律要泄漏给用户态；v1 无此 VM 机器，新建 = 大件 |

### 3.2 终选：**候选①**（`0x64 telemetry_open(kind, options) → Handle`，实装）

- 语义：open 时在 seqlock 读者协议下烘焙**一致性快照**（逐条一致——per-ring 版本校验同
  `wake_ring_peek`；跨段联合读不保证全局一致，快照头带 generation，消费方按代处理，写进接口
  契约防误用）到新建 VMO；授 `READ|MAP|INSPECT|DUPLICATE`，**永不授 WRITE/SET_POLICY**。
- 快照形状（`#[repr(C)]`，day-one 定型，add-only）：头 `TelSnapshotHdr {magic,version,cntfrq,
  flags(bit0=trace_off),gen,boot_vct,slept_ns,suspend_count,ncpu,容量三元组,ownerless[3],
  acct_total}` + 载荷 `WsSlot[32] + WakeRec 环×2 + SwitchRec 环×2 + 直方图/计数器族`。
  v1 kind=0（ALL 全量）；未知 kind → -ENOTSUP；options≠0 → -EINVAL（options 纪律）。
- 轮询节奏归 berry-power（策略用户态）；快照 ≈7KB memcpy，v1 规模下成本可忽略。
- v2 演化留位：kind 参数 add-only——将来 `LIVE_MAP`（候选④的机器落地后）不破签名。

### 3.3 预算对账（35 在册 vs 39 定义 vs 38 注册 + 0x85 处置）

三口径澄清（各真各账，病根是无单源对账）：

| 口径 | 值 | 含义 | 执法现状 |
|---|---|---|---|
| 35 | abi.toml `nr_total` | stage="v1" 行数（含 0x85/0x86/0x87） | gen_abi.py 校验 ✓ |
| 39 | abi_gen.rs 常量数 | 35 v1 + 4×stage"1.1"（0x3C-0x3F sched-1.1） | 无执法 |
| 38 | syscall.rs reg() 数 | 39 − 0x85（在册未实现） | 无执法 |

**0x85 处置：不是违例，是模式。** `berry_attest` 在册未实现恒 -ENOTSUP 是 SEC-01 件 11 的
设计（防 ABI 冻结后挤号）；行动项仅两个：① ktest B 段「在册未实现真号」样本挂上（note 已
挂账未兑现）；② abi_gen.rs 头注「v1 35 号在册、34 已实现」陈旧手写句改由生成器再生——三口径
单源化。**AGENTS「v1 35 在册」在其自身口径下仍为真，不回写。**

刀 1 加号与帽：**0x64 telemetry_open**（stage"1.1"，implemented=true——0x62/0x63 已被 v2
timer 预留，0x64 顺延空闲且语义归「时间/观测」组）；**0x88 pm_wake_src_register**
（stage"1.1"，implemented=false 冻结预留——0x85 同款，签名 day-one 定型：
`pm_wake_src_register(name:*const u8, len:u32, class:u8, flags:u16, reserved:u64) -> u16`，
reserved 恒 0 留咬合未来的驱动 IRQ 句柄面）。账面变化：defined 39→**41**、registered 38→
**39**、nr_total 35 不变；新增生成器断言 `nr_defined ≤ nr_ceiling=45`（ADR #11 ~30–45 窗，
余 4）。**从此挤帽先过机器，不过人心。**

### 3.4 预辩

- **「挤预算」**——41≤45 且落生成器执法；0x64 之后读面零新号（vmo_read/vmar_map/duplicate
  全复用）；0x88 冻结不实装不占实现面。真正贵的是「驱动刀来了才发现号位没留」——0x85 预留位
  存在的意义正在于此，0x88 是同一课的预习。
- **「快照拷贝违铁律 7（共享环禁 IPC 拷贝）」**——铁律禁的是环数据经 IPC 通道中转（服务中介
  拷贝）；telemetry_open 是 syscall 直出 VMO、消费方映射自读，恰是铁律 7 的正解形态。
- **「刀 1 纯内核面，定义用户态接口是越界」**——PM-12 §3.4-4 禁的是**依赖**不是**预留**；
  自有 ABI「应用契约 day-one 定对，窗口一次性」是冻结常量原文。通道形状不今天定，telemetry.rs
  「将来 telemetry_open 映射」注记就得一直空悬。

## §4 小项③：WakeRec 扩字段 + per-source 计数器组（都做）

```rust
#[repr(C)]                     // 32B → 40B（零消费者窗口——telemetry_open 未落、berry-sys 无镜像）
pub struct WakeRec {
    pub vct: u64, pub since_vct: u64, pub wait_obj: u64,
    pub task_id: u32,          // 被唤醒任务 name hash（原样）
    pub src: u16,              // wsid；0 = C 类无主（smoke 失败谓词）
    pub reason: u8,            // 原样（Pending=0 不可达纪律不动）
    pub flags: u8,             // bit0-1 时域位（§5）；bit2 orphan 标记；余预留恒 0
    pub owner: u32,            // 唤醒原因持有者域 id（IRQ 类=槽 owner；IPC 类=发送者 pinned；0=内核自持）
    pub _pad2: u32,            // 对齐预留恒 0
}
```

- 环 64 槽×2 核 ×40B ≈5KB：仍静态预储，环看**模式**（风暴形状/延迟分布），计数器组做**对账**
  （不淘汰总量）——PM-12 §3.3-3 的「环+计数器」判在此扩成超集：per-source × per-holder 的
  group-by 在环内一遍扫完、零跨表 join（归因完备面的直接红利）。
- `owner` 与 billing `domain_id` 同轴（Task.pinned）——回应 PM-12 §3.3-7「防三本账」：唤醒账
  与 intent 消费账共享同一域 id 键，berry-power 侧并表零翻译。

## §5 小项④：记账时间戳用钟（SLEPT 域预留怎么留）

- **本体不变**：环/槽内时间戳照旧 CNTVCT 原始周期（公约 5——换算归消费方，快照头给 cntfrq）。
- **SLEPT 预留三件**（全部 day-one 定型、挂起刀前零值零成本）：
  ① `WakeRec.flags` bit0-1 时域位：00=运行态观察（MONO 域）；01=挂起唤醒边界事件（SLEPT 域，
  挂起刀启用）；10/11 预留。
  ② 快照头 `slept_ns/suspend_count` 字段：挂起四原语刀落地时只写值不改 ABI。
  ③ PM-11 双钟命名纪律传导：SDK 侧 `clock_now(MONO|SLEPT)` 不复用 CLOCK_MONOTONIC 名——内核
  记账面不预支命名，快照头字段名直接用 SLEPT。
- 真机/QEMU 边界照 PM-10：TCG 无 PSCI SYSTEM_SUSPEND——SLEPT 位在 QEMU 恒 00/0 值，KVM 相
  才可验（开放问题 #6 维持）。

## §6 与 berry-power 用户态服务接口草图

```rust
// —— berry-sys 镜像新增（两端 #[repr(C)]，SchedAttr 56B const assert 同款）——
pub const TEL_KIND_ALL: u64 = 0;                       // add-only 词表
pub fn telemetry_open(kind: u64, options: u64) -> Status /* x0=Handle */;
pub fn pm_wake_src_register(name: *const u8, len: u32, class: u8,
                            flags: u16, reserved: u64) -> Status /* x0=wsid */; // 0x88 冻结，恒 -ENOTSUP

// —— berry-power 轮询环（治理侧；刀 1 不依赖它存在）——
loop {
    let h = telemetry_open(TEL_KIND_ALL, 0)?;          // 快照 VMO
    let snap: &TelSnapshot = map_read_only(h)?;        // vmar_map 既有号
    debug_assert_eq!(snap.acct_total,
        snap.ws.iter().map(|s| s.count).sum::<u64>() + snap.ownerless.iter().sum::<u64>()); // 归因守恒复验
    for s in snap.ws.iter().filter(|s| s.wsid != 0) {  // P10 七字段 + owner
        let name = self.name_table.lookup(s.name_hash) // manifest 名表（appd 供给）
            .unwrap_or_else(|| format!("ws-{:08x}", s.name_hash));
        self.emit_wake_metric(name, s.owner, s.count, s.first_ts, s.last_ts, s.last_ack_ts);
    }
    if snap.ownerless.iter().any(|&c| c != 0) { self.alarm("ownerless wakeup"); }
    drop(h); self.sleep(POLL_INTERVAL);                // 节奏 = 策略，归用户态
}
```

登记方向（驱动刀激活后）：驱动 manifest `wake_sources` → appd 校能 → berry-power 调 0x88
（内核铸 id 返 wsid）→ berry-power 名表 `{name_hash → (wsid, 驱动名, 服务名)}`。内核只见
哈希与域 id。

## §8 反面清单（本方案明确不做）

- 不记物理量（功耗/温度数值——sim/真机计量另行，PM-10 三层模型）。
- 不给 berry-power 或任何用户态**书写面**（快照 VMO 永不授 WRITE；0x88 是登记不是控制）。
- 名字表、治理策略、轮询节奏一律不进内核。
- 不建 live 映射 VM 机器（kind 留位，v2 再裁）；不建内核遥测生产者任务（铁律 7）。
- 不动 `nr_total=35` 的 v1 冻结口径（AGENTS 不回写——1.1 号走 stage 标签 + 全量帽执法）。

## §9 开放风险

1. **ws_cur 标的内存序**：KL 纪元内零成本；c-2 拆 KERN_LOCK 后 per-CPU 标与环写序需重审
   （f4 F10/F11 配对先例）——写进刀 1 设计文档「拆锁重审清单」。
2. **0x88 形状与未来 IRQ 句柄面的咬合**：reserved 参留了缝，但驱动刀若引入「IRQ 句柄即登记」
   语义，0x88 可能降级为内部翻译面——接受一次形状重裁（冻结的是号位不是实现）。
3. **环 64 槽风暴下淘汰快**：对账不依赖环（计数器组不淘汰）；环淘汰后 mask 型断言沿用现有
   「未淘汰期才验」先例。
4. **BILLING_SLOTS=8 满表覆写最小槽**的丢账坑在 WsSlot 不存在（槽不覆写、动态段满 → -ENOMEM
   loud），但 berry-power 名表无界——manifest 侧需限额（驱动刀议题）。
5. **QEMU 无真实设备唤醒源**：A 类无主只能靠 sim 设备族后挂（PM-10 §4.2）；刀 1 期 A/C 类
   靠 ktest 内部注入兜底，A4 全量执法等 sim 线。
6. **快照「逐条一致」语义**易被消费方误当全局一致——接口契约文档必须显式写「跨段联合读按
   generation 处理」，并给 SDK 侧复验断言样板（§6 debug_assert）。
