# 刀 1 前置方案（2026-11-07）——方案 A：内核极简面

> 参赛倾向：内核极简——复用 WAKE_RING 既有形状、源 id 静态穷举、导出**零新 NR_**。
> 输入：PM-12 §3.3 前置清单 #1–#5/#7；实查证据 = `kernel/src/telemetry.rs:276-398`、
> `kernel/src/abi_gen.rs`（39 定义）、`kernel/src/syscall.rs`（38 注册）、
> `kernel/src/user.rs:1874-1882`（G1.5 断言样板）、`arch/aarch64/src/trap.rs:538-636`
> （IRQ 臂全表）、`arch/aarch64/src/gic.rs`、PM-08 §8 P10、PM-10 §4.1 A4、PM-11 §4.1。

## 0. 一句话骨架

源 id = **abi.toml 单源的 add-only 静态枚举**（内核只存定宽 id，id→人读名映射归用户态）；
「无主唤醒」= **IRQ 到达却零唤醒 / 未知 IRQ 号**两类内核可判计数器，smoke 断言归零；
导出 = **刀 1 零通道**（验收走内核 watchdog 断言 + boot 尾单行打印，G1.5 同构），
用户态导出通道**预裁**为 `vmo_create` 新 options 位（内核静态区只读镜像 VMO）——
不开新 NR_，35 预算一个号都不花；0x85 维持哑位不动，只修帐不修法。

## 1. 硬前置 ①：源 id 铸造与名字映射归属

### 1.1 候选取舍表

| 候选 | 谁铸造 id | 利 | 弊 |
|---|---|---|---|
| A1 内核静态穷举表 | 编译期常量（abi.toml → abi_gen → berry-sys 三端同源） | id 跨 boot/跨版本天然稳定；热路径零查表（match 即值）；QEMU virt 唤醒源封闭可穷举（PM-12 §3.1：CNTV + PL011 SPI33 + SGI） | 加源要动 ABI 单源（add-only，号冻不死） |
| A2 运行时铸造 | 内核运行时分配递增 id | 表面灵活 | id 顺序随使能次序漂移，跨 boot 不稳定，恰毁「稳定 id」目标；内核长驻动态表 = 状态面+淘汰策略，违极简 |
| A3 驱动 manifest 注册 | 用户态驱动经 manifest/通道申报后内核发号 | 贴 v2 用户态驱动现实 | v1 无用户驱动 IRQ 面（PL011/CNTV 皆内核消化）；注册即新 syscall/协议位；id 稳定性依赖注册顺序或又一张映射表——绕回原题 |
| A4 Fuchsia 式 koid 中介 | 内核对象号间接归因 | 持有者粒度细 | 需要 InterruptAttributor 之类的第二张表在内核翻名——PM-08 §8 明言名字在 platform-bus（用户态侧）翻，内核背表是被反证的 |

### 1.2 终选：A1，三个部件各归其位

1. **铸造**：`tools/abi.toml` 增 `[wake_sources]` 段（单源纪律既有管线 `just abi-gen`/
   `abi-check` 直接执法），生成内核 `abi_gen.rs` 常量；berry-sys 落地时从同一 toml 出
   用户侧常量——id 铸造 = 编译期，无人「运行时发号」。初版枚举（add-only，预留 0x00
   哨兵与 0x7F 未知）：

   ```text
   0x00 SRC_NONE（哨兵：写点清后值，进环即写路径 bug）
   0x01 SRC_KERNEL_BOOT（boot 期非 IRQ 语境直接唤醒；BLOCK_BOOT_DONE 后冻结）
   0x02 SRC_TIMER（CNTV PPI：tick/deadline 到期）
   0x03 SRC_UART_RX（PL011 RX，GIC ID 33）
   0x04 SRC_SGI_RESCHED
   0x05 SRC_SGI_TLB
   0x06 SRC_IPC（SVC/线程上下文唤醒：channel send / event signal 等）
   0x7F SRC_UNKNOWN（未知 IRQ 源——只进 IRQ 级计数器，永不进环）
   ```

2. **id→人读名映射：归用户态**（berry-power 持表；berry-sys 发布生成枚举做兜底名，
   服务 manifest overlay 做 fancy 名）。铁律 2「机制内核/策略用户态」+ Fuchsia 反证
   （名字只在 platform-bus 翻）。内核永不存字符串——连 `name_id` FNV 哈希都不为源名做。
3. **持有者归因（PM-08 超集项）**：内核记**机械事实**——该源最近一次实际唤醒的任务所属
   pid（唤醒链 IRQ→wake_matching→task→owner process 全在内核手上，零策略）；「源该归
   哪个服务」的语义映射归 berry-power。v2 用户驱动接管 IRQ 时，投递通道的对端天然给出
   持有者 pid——静态枚举 + 投递语境归因这个组合可平滑延伸，不需要 manifest 注册面。

### 1.3 「无主唤醒」的内核可判定义（三分类，逐类给断言，见 §7）

| 类 | 定义 | 内核怎么判 |
|---|---|---|
| 无主-1 未知源 | IRQ 号落 `exception_irq` 未知臂（trap.rs:610 loud `irq? id=` 分支） | IRQ 级计数器 `unknown_irq++`（计数进静态表，打印让位纪律不变） |
| 无主-2 零唤醒到达 | 已知源 IRQ 到达、`wake_matching` 回报 n=0（事件无人等） | 各源槽 `no_waiter` 计数（RX 无 console 等待者即典型） |
| 无主-3 链断在内核 | 源触发、唤醒链路未落到任何用户任务（唤醒目标 = 无属主内核上下文） | v1 任务生死绑进程（exit 钩子 drain），此类按构造为空——**立断言证明其为空**（boot 后 `SRC_KERNEL_BOOT` 计数冻结不再涨），不建判定机械 |

守恒式把三类全兜住：**Σ 各源 wake 计数 == telemetry::wake_total()**（每次 on_wake 恰
计一源；SRC_NONE 到达 on_wake = 写路径 bug，按负延迟同款 panic 执法）。

### 1.4 预辩

- **「静态枚举不可扩展」**：扩展单位 = 一次 add-only 编译期变更 + 三端同源再生成；运行时
  铸造（A2）才是真不可扩展——id 稳定性恰恰只有编译期能给。Linux wakeup source 也是
  devicetree/编译期静态集。新 SoC（真机期）= 新枚举值，预算帽内（u8，预留 0x07–0x7E）。
- **「IPC 源一把抓太粗」**：源记的是**直接触发上下文**（诚实记录）；哪个通道被谁等已在
  `wait_obj` 字段。传递归因（发送者又是被谁唤醒的）是 v2 实验轨道题，Fuchsia 也没做。
- **「无主-3 不建机械是回避」**：为按构造不可能的类建判定面 = 复杂度买保险；断言其为空
  （boot 后 KERNEL_BOOT 冻结）比运行时查「进程死没死」更强——后者在任务生死绑进程的
  v1 内核里是永真假问。

## 2. 硬前置 ②：遥测导出通道形状

### 2.1 候选取舍表

| 候选 | 形状 | 利 | 弊 |
|---|---|---|---|
| B1 新 NR_TEL_OPEN | 新号映射环给 trace/策略服务 | 接口显式 | +1 NR_（39→40）；新对象类型/权利面/锁类审计全套随之而来；telemetry.rs 注记只说「将来」 |
| B2 vmo_create 新 options 位 | `VMO_OPT_TELEMETRY`（bit1）创建内核静态区只读镜像 VMO，右强制 READ\|MAP\|INSPECT | 零新号；走 ADR 11「object_* 泛型合并压数」原文精神；options add-only 是 ABI §8 正规扩面（VMO_OPT_DEMAND bit0 先例）；权限面天然收口 | commit 路径要认「内核 .bss 别名页」特型（一次性，页对齐约束见 §6） |
| B3 内核任务经 channel 推送 | 内核侧生产者任务轮询环再 send | 复用 IPC | 内核常驻任务 = 策略进内核 + 拷贝路径（违铁律 7 共享环禁 IPC 拷贝）；凭空多一个内核消费者 |
| B4 服务轮询新查询单号（如 info 类） | 每次调用 copy_out 快照 | 实现最薄 | 64 槽环靠拷贝快照必然撕裂/丢条；仍是 +1 NR_ |

### 2.2 终选：分两步走——刀 1 零通道，用户态导出预裁 B2

- **刀 1 本刀：不建任何用户态通道。** 验收主体本来就是内核断言（PM-10 A4 通道列的就是
  WAKE_RING 归因面；G1.5 样板 user.rs:1874-1882 同构可扩）+ boot 尾 `WAKESRC ...` 单行
  ASCII 打印（R-0 直方图行同款落点契约：watchdog 单次、写在 exit_current 之前恰一次）。
  PM-00 §7-1 已裁刀 1 不依赖任何服务存在——berry-power 未落不阻塞，硬给刀 1 配消费者
  是为导出而导出。
- **用户态导出（berry-power 刀）预裁 B2**：`vmo_create(VMO_OPT_TELEMETRY, 0)` 返回内核
  遥测区只读镜像 VMO（尺寸内核定死 8KiB 两页；权利强制只读、不可 WRITE/TRANSFER 收窄）。
  内核侧唯一机械前置 = 把导出对象（环 + 计数器组 + 头）归置进页对齐静态段
  （`#[repr(align(4096))]`）——**ABI 形状（记录布局 + seqlock 读协议）day-one 冻结，
  内存摆位是内核内部事，后挪不动 ABI**。直映零拷贝：seqlock 读者协议跨 EL 成立（奇偶
  校验不依赖特权级），映射页 AP_RO。
- 不选 B1 的理由：预算帽 45 现用 39 余 6，但每开一号的隐性成本（锁类分类、ktest 真号
  样本、handle 面、文档）远超一个 options 位；B2 余量留给真正无家的语义。

### 2.3 「35 在册 vs 39 定义/38 注册」对账与 0x85 处置（修帐不修法）

实查口径：**39 个 NR_\* 定义**（abi_gen）= v1 冻结 35（含 0x86/0x87/0x21——A7-4/G4-2
均在册计数内）+ 1.1/S1 追册 4（0x3C–0x3F）；**38 注册实现**（install() 实数）；唯
**0x85 `berry_attest` 定义未挂**——派发回落 HAL 默认 `-ENOTSUP` 永不 panic。abi_gen
头注「1.1/S1 在册未实现」行已陈旧（S1 收口后 0x3C–0x3F 皆有真 handler），这是文档漂移
不是 ABI 漂移。处置三件（全文档面，零代码零号）：

1. abi_gen.rs 头注更正为分层口径「39 定义 / 38 注册 / 1 哑预留」；
2. AGENTS.md 冻结常量行同步（v1 35 在册 → 「在册 39 = v1 35 + 1.1/S1 4，实现 38，哑预留 1」）；
3. 预算执法口径立法：**NR_\* 定义总数 ≤ 45 为帽；哑预留位必须有 ADR/SEC 出处**
   （0x85 出处 = SEC-01 §4.5 件 11，在册合法）——预留位保持哑位（不显式注册 -ENOTSUP
   handler：HAL 默认槽已给同语义，显式注册反烧一个 reg 槽并暗示语义在途）。

本方案对预算的净影响见 §8。

### 2.4 预辩

- **「没 syscall 导出 = 断言自嗨」**：刀 1 的判据主体是 smoke FAIL 门（PM-00 §6 归因守恒
  + 无主=失败），断言在内核 watchdog 与 syscall 无关；导出是给 berry-power 的**读面**，
  其形状已冻结、落地是 berry-power 刀里 1–2 天的机械活，不欠 ABI 债。
- **「options 位复用是隐式多态」**：ABI §8 options 纪律本就是为 add-only 语义扩面设的
  （VMO_OPT_DEMAND 先例创建即改对象属性）；镜像 VMO 是「对象几何/内容」家族的自然成员，
  非多态滥用。
- **「0x85 不动是回避」**：0x85 是**合法在册哑位**，问题只在文档口径漂移；改派号或回收
  才是破坏 add-only 冻结面。修帐 + 立预算执法规则，比动 ABI 强。

## 3. 顺带裁决 ③：WakeRec 扩字段 vs per-source 计数器组——两件都要，分工不同

- **环（明细/看模式）**：保持 32B 不变，`source_id: u8` 吃掉 `_pad` 首字节（PM-12 §3.3-3
  原案）——`{vct(8) since_vct(8) wait_obj(8) task_id(4) reason(1) source(1) _pad(2)}`，
  `size_of == 32` 断言续立在册。
- **计数器组（对账/不淘汰）**：环 64 条即淘汰，守恒与无主判定必须落在只增计数器上。新建
  `WakeSrcRec`（`#[repr(C)]`，P10 七字段整段抄 + 持有者超集，64B/槽 × 16 槽 ≈ 1KiB 常驻
  .bss）：

  ```text
  id:u16 flags:u16 | count:u64 wakes（=P10 count） | irq_count:u64 到达
  no_waiter:u64 零唤醒到达 | first_ts:u64 last_ts:u64 last_ack_ts:u64（P10 三 ts）
  last_woken_pid:u32 ts_domain:u8 _pad[3]        // 64B 整
  ```

  写法 = 纯原子（fetch_add/fetch_min(first)/fetch_max(last)/fetch_or(flags)，
  WAKE_HIST 五计数器同款纪律）；`flags` add-only：bit0=定时器类（slack 可合并）、
  bit1=外设线、bit2=SGI 内部、bit3=曾零唤醒（sticky 无主嫌疑）、bit4=SLEPT 域事件（v2）。
  `name` 字段刻意不进内核（§1.2-2）；`last_ack_ts` v1 记 post-EOI 戳（与 signal 同窗，
  差近零）——字段语义 day-one 冻结，v2 用户驱动 IRQ 到位后 ack 才真有间隔，届时不用改形。
- 账本关系（PM-12 §3.3-7）：唤醒账、IRQ 到达账、intent billing 账**同一导出页、同一 seq、
  同一 ts 域**——单账本多视图，聚合归 berry-power；防安卓三本账各自演化的关键是单一
  事实源，不是把三视图压成一张宽表。

## 4. 顺带裁决 ④：记账时间戳用钟 + SLEPT 域预留

- **钟**：照旧 CNTVCT 原始周期数（公约 5：内核不做 ns 换算，消费方持 CNTFRQ 自换）；
  唤醒延迟、first/last/ack 全同域可比。
- **SLEPT 域预留（零成本三件）**：① `WakeSrcRec.ts_domain: u8`（v1 恒 0 = MONO/CNTVCT，
  断言执法）；② 导出页头预留 `slept_ns: u64` 镜像槽（v1 恒写 0；PM-11 §4.1「唤醒路径
  累加」随挂起四原语刀落，届时填真值 + resume 事件标 domain=1，布局不再动）；③ flags
  bit4 = SLEPT_EVENT 预留。规则成文：**ts_domain≠0 的记录，消费方须先加 slept_ns 偏移
  再与 domain=0 记录比较**——主钟暂停语义（PM-11 裁 A）从 day-one 就在 ABI 里留了位。

## 5. 写点接线（本刀全部代码面，三处小改）

1. **IRQ 臂挂源语境**：per-CPU `CURRENT_WAKE_SRC: AtomicU8`（S4-b 计费槽同款先例）。
   `exception_irq` 各臂 ack 后 store 对应源、臂尾 store SRC_NONE（清场——臂后 SVC 上下文
   的唤醒归 IPC）。IRQ 不嵌套（全程 PSTATE.I=1）保证写读窗封闭；boot 期单核顺序安全。
   未知臂：`unknown_irq` 计数 + 置 SRC_UNKNOWN（只到计数层）。
2. **on_wake 扩展**：读 `CURRENT_WAKE_SRC` 得 source（SRC_NONE 到达 = 写路径 bug，
   按负延迟同款 panic）；WakeRec 带 source 进环 + 对应槽原子计数 + `last_woken_pid`
   = 被唤醒任务属主 pid。热路径增量 = 1 load + 数个 fetch_*，零分配纪律不破。
3. **零唤醒到达计数**：各 IRQ 臂已知源处，wake 回报 n=0 时 `no_waiter++`（rx_irq_notify
   已回报 bool、tick 臂同位可取）——这是无主-2 的唯一写点。

## 6. 与 berry-power 用户态服务接口草图（berry-power 刀消费，本刀只冻形状）

```text
内核导出页（8KiB 两页，页对齐静态段；内核唯一写者，用户只读）:
  [头 64B] magic 'BTEL' | ver | ncpus | ts_domain_cur | ring_len | rec_size
           | src_count | global seq | wake_total 镜像 | slept_ns(v1=0)
  [环区 4KiB] per-CPU WakeRing × 2（64×32B；seqlock 协议原样）
  [源表 ~1KiB] WakeSrcRec × 16
  [尾垫] 保留 add-only

berry-sys（生成自 abi.toml [wake_sources]）: WAKE_SRC_* 常量 + 读协议文档
berry-power 落地时:
  h = vmo_create(VMO_OPT_TELEMETRY, 0)        // 只读镜像 VMO，无新号
  vmar_map(...)                                // AP_RO 映射
  loop { 头 seq 快照→读计数→重读 seq 对账（seqlock 同内核读者协议）}
  消费: id→名（berry-sys 兜底名 + manifest overlay）| Σ count == wake_total 外判
       | unknown/no_waiter ≠0 → 上报记账（执法仍归 smoke，服务只看不罚）
```

## 7. 可立即开写的验收断言（G1.5 样板同构，挂 watchdog + smoke）

1. **形状**：`size_of::<WakeRec>() == 32` 续立；`size_of::<WakeSrcRec>() == 64` 新立；
   `wake_check()` 扩一条——环内 source ∩ {NONE, UNKNOWN} = ∅（哨兵/未知进环即 FAIL）。
2. **归因守恒**（PM-00 刀 1 原判据）：Σ 源表 wake 计数 == `telemetry::wake_total()`
   （boot 尾 watchdog 断言 + smoke 稳态窗复断）。
3. **无主 = smoke 失败**：BLOCK_BOOT_DONE 门后稳态窗 `unknown_irq == 0` ∧ 控制台交互
   相内 `SRC_UART_RX.no_waiter == 0` ∧ `SRC_KERNEL_BOOT` 计数冻结（无主-3 空类证明）。
4. **boot 双路径归因**：G1.5 既有 Signaled|Timeout 双覆盖断言升级为「双覆盖且两路径源
   均 ∈ {TIMER, IPC, UART_RX}」——非 UNKNOWN 即过。
5. **钟域**：v1 全量记录 `ts_domain == 0`（断言）；`slept_ns` 镜像 == 0。
6. **打印面**：boot 尾单行 `WAKESRC timer=N uart=N ipc=N boot=N unknown=0 spurious=N
   no_waiter=N`（纯 ASCII、uart 直写、恰一次，R-0 行同款纪律）。
7. **二跑规律**（PM-10 §4.1）：连跑两轮 smoke，源集合恒等（静态枚举不变性）。
8. **ktest 纯函数面**：源枚举 ↔ u8 编码往返；flags 位 add-only 检查（未知位不炸）。

## 8. 对 35 syscall 预算的影响（汇总）

**零号消耗**：不新增、不回收、不改派任何 NR_\*。定义数维持 39（帽 45，余 6），注册数
维持 38。唯一 ABI 面动作 = `vmo_create` options bit1 `VMO_OPT_TELEMETRY` **预裁在册**
（本刀只写进 abi.toml 注释与设计文档，不实现——实现随 berry-power 刀）。预算口径按
§2.3-3 立法修正后，「35 在册」表述与实查 39/38 不再打架；0x85 维持 SEC-01 哑位。

## 9. 开放风险与依赖

- sim 注入面（PM-12 §3.3-6）：A4 稳态窗「可控注入唤醒」依赖 sim 设备族后挂——本刀
  验收只覆盖 boot + 既有控制台交互相，注入相留位不阻塞。
- B2 镜像 VMO 的 commit 特型（内核 .bss 别名页）是 berry-power 刀的唯一非机械件，
  页对齐归置若与 SPL011/热路径冲突需回裁 B1（kill criteria：镜像实现超一周或引入
  页表特例 > 10 行）。
- SGI_TLB/RESCHED 无 wake 语义差异（bank 边沿 vs 电平）已按「到达即计数」处理，若
  副核 park 环语义变化需复核 no_waiter 口径。
- 源枚举冻结进 abi.toml 后，新源（真机期）走 add-only 再生成——三端同步靠 `abi-check`
  门禁执法，勿手改生成物。
