# BerryOS 省电现状与缺口盘点（PM 系列第 0 路）

> 调研日期：2026-11-07 · 版本 v1.0。方法：**本地读仓盘点（不联网）**——grep 仓内 docs/ + research/ + kernel/arch 代码，
> 逐条带出处（文件名:行号或 §节）。确定度图例：**高** = 决策已落 ADR 或代码已落（行号在册）；**中** = 设计位/协议位在册但实现未落。
> 本报告在 PM 系列中的分工：**PM-00 为地基**——盘点仓内已有省电资产（内核机制 / 协议位 / 调研覆盖），标出 6 路外部调研的

## §0 一页结论（TL;DR）

1. **内核侧地基厚**：tickless/idle（G1）、slice 周期数记账（DVFS 预埋）、intent 第一段 + 消息传播五件套、策略注入桩 +
   空表等价断言、遥测双环（切换/唤醒）全部已落代码；深睡三件套/PM governor/EPP/timer slack 是在册设计位。
2. **GUI 侧缝已裁未落**：ADR #53 六件 + C1 per-surface 帧率意图位全在册，但 guiproto damage 协议窗口仍开着（锚点 GUI-2/4）。
3. **协调者缺位**：PM governor 服务（M3）未落，导致 GUI 六件里的 PM 共享环无对端；系统级电源状态机、外设电源域/时钟门控、
   多应用后台预算（类 Doze）在仓内零覆盖——这是 PM 系列外部调研的主战场。
4. **演化教训通用面已覆盖**（17/18 号报告，引用不重复）；省电专题演化史（wakelock/PM QoS/runtime PM/iOS 治理）是空白。
5. **铁律 14 条**在 §3——任何综合建议不得违反带内投票、共享环、砍实现不砍协议位、v1 单核等冻结项。

## §2 gaps：对照用户三问的缺口

### (a) 整套系统（用户态服务/多应用/GUI）的整体省电协调——缺「协调者」与「外设面」

1. **PM governor 服务本体未落**：共享环、改频原语、governor 只有设计位（`docs/调度器设计-v1.0.md:169-181`；`docs/路线图-v1.0.md:123` 明示未落）——「谁聚合 intent/负载/帧态 → 定频定档」的执行者缺位，GUI 六件里的 PM 共享环因此无对端。
2. **无系统级电源状态机**：suspend/resume 全局状态、熄屏链路（power·mode op 只有 NORMAL/DIM/AOD/OFF 四枚协议枚举，无系统侧状态机与迁移条件）、深睡三件套挂 v2+——熄屏后「哪些外设该关、谁持有唤醒源」无任何文档。
3. **外设省电压根零覆盖**：基带/GPS/传感器/NIC/多媒体 codec 的电源域、clock gating、使用计数 refcount、按需开关契约——`docs/驱动模型设计-v1.0.md` 全文无功耗面（仅 :77 共享环性能纪律一句）；net/fs 设计文档同。**PM 系列外设路的最大空白。**
4. **多应用生态省电协调缺设计**：后台任务预算/闹钟与推送代理（集中闹钟合并唤醒）/批处理窗口（类 Doze/JobScheduler/后台任务预算）——应用模型只有「墓碑候选 = appd 消费 intent+遥测」一句（`docs/应用模型设计-v1.0.md:182`），无协调服务形态。
5. **唤醒源治理只有观察面**：WAKE_RING 能看醒因（`docs/AI调度设计-v1.0.md:115`），但「唤醒归因→阻断深睡的 PM QoS/wakeup source 模型、idle 时谁还在周期醒」的机制与策略均无位。
6. **量化验证路径缺口**：QEMU 只能验软件纪律（能耗代理断言，`docs/架构决策.md:62`）；µA 级真机功耗计只在真机线一句带过（`docs/路线图-v1.0.md:143`，SoC 未选型）——「省电收益拿数字说话」目前无路可走。
7. **按-app 能耗账未落**：能耗账（DVFS 档位×时长，PM 记账）挂 v3 随 M3（`docs/AI调度设计-v1.0.md:60`）——多应用「谁耗的电」对账面缺。

### (b) 触摸/交互功耗——有单点设计位，无系统化契约

8. touch-boost 注入面 + GUI-4 PM 交互脉冲在册，但**衰减窗定值/策略归属 v3 未定**（`docs/应用模型设计-v1.0.md:247`）；「即到即派低延迟模式留位（可弃 batching 省电收益的逃生门）」（`docs/GUI里程碑规划:94`）——**延迟与省电的交换从未被系统性对账**（帧预算表 `应用模型:219-223` 只有时间列无功耗列）。
9. 交互起振的省电代价已有遥测位（停帧→交互 1–2 帧额外延迟，`docs/GUI里程碑规划:82`），但**起振提频窗的成本-收益模型、触控期帧率-频率联合策略**（GUI-06 §2.2/§4 素材在）未折成 BerryOS 契约——PM 交互路应把「交互功耗」从 GUI-06 素材 + 注入面现状拉成完整提案。

### (c) OS 演化规律/历史包袱——通用面已覆盖，**省电专题史缺**

10. 17/18 号报告覆盖通用八类坑 + 初衷/成活率（应引用不重复）；但**电源管理子系统的演化史无系统报告**：现有仅零散证据点——Linux NO_HZ 16 年债与微内核电源留白（`research/调研报告/18:140`）、FreeRTOS 停止-补偿漂移（`docs/调度器设计-v1.0.md:162`）、Linux RT throttling 20 年坑（:136）、Wear OS AOD 管线照跑教训（`research/GUI-06` §6.2）。**Android wakelock 十年之乱、PM QoS/autosleep/wakeup source 演化、iOS/watchOS 电源治理形态、ACPI/设备电源模型（runtime PM）** 等专题均未调研——PM 演化路的核心空白。
11. **历史包袱对照的正面清单缺**：18 号 §5.2 诚实列了 BerryOS 最可能重蹈的辙，但省电线只点了「谱系空白=差异化」；「别人电源面踩过的哪些坑我们 day-one 免修、哪些会原样再踩（多应用互相抱锁唤醒、后台生态博弈恶化省电）」无对照表。
