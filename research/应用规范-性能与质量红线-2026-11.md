## 2. Core App Quality（developer.android.com/quality）
- 2024-09-19 改版为四支柱：**Core value / User experience / Technical quality / Privacy and security**；"Good→Great"表：技术质量 Good=在用户设备上正常运行，Great=充分发挥高端设备能力。https://developer.android.com/quality
- **Technical quality**（https://developer.android.com/quality/technical）条目化：
  - Form factors：每个支持的形态遵循功能+技术指南；跨形态 **continuity**（文件/设置同步、进度保存）。
  - Stability：监控崩溃/ANR/LMK；**GWP-ASan**、Kotlin 空安全、后台任务 API；vitals 每日报告（数据足时每小时）；超坏行为阈值 → 可发现性受限 + 商店页警告。
  - Performance-启动/加载：最小化启动到首次交互时间；**baseline profile + reportFullyDrawn**（应用）、**Game State API**（游戏）；减小包体。
  - Performance-渲染（应用）：**"多数应用应以 60fps 运行，无丢帧/延迟帧"**；JankStats 监控。
  - Performance-渲染（游戏）：**核心游戏循环最低 30fps；高帧率目标 60fps+**（视电池/温度/画质权衡）；ADPF、Game Mode API、frame pacing、Android Performance Tuner。
  - Battery/Network：菜单/加载场景降帧率降刷新率；Game Mode API。
  - App size：最小化；Play 会按大小优先建议卸载；AAB + Play Feature/Asset Delivery。
  - App freshness：定期更新、最小化更新体积、in-app updates。
  - Healthy releases：分阶段测试与发布（phased rollout）、远程配置解耦。
- **User experience**（https://developer.android.com/quality/user-experience）条目：标准组件/edge-to-edge/画中画/Sharesheet/备份恢复；本地化、无障碍、build-for-billions、深链直达；视觉与工艺（原创风格/动效）；变现（付费预期前置、广告时长频次尺寸成比例、防误触）。
- **Core value**（https://developer.android.com/quality/core-value）：内容与功能深度、形态因子、营销资产、用户指标（评分/参与/留存为价值度量；获客指标不算）。

## 4. Android 启动指标（TTID/TTFD/三态/基准口径）
来源：https://developer.android.com/topic/performance/issues/launch-time
- **TTID**（time to initial display）：显示应用 UI 首帧所需时间；含冷启动进程初始化、冷/温启动 activity 创建、首帧显示。**框架对每个应用自动上报**；Logcat `Displayed` 行（示例 3s534ms）；`adb shell am start -W` 可测。
- **TTFD**（time to full display）：应用对用户可交互；= TTID + 首帧后异步加载的主内容（网络/磁盘）；**系统不能自动判定，需应用调 `reportFullyDrawn()`**，否则不上报；在系统测得 TTID 前调用则 TTFD=TTID；后台线程未完成可延迟（FullyDrawnReporter）。
- 三态定义：**冷启动**=进程从零创建（开机后首次/被杀后）；**温启动**=冷启动子集（进程在但 activity 需重建，如返回键退出后再进）；**热启动**=activity 全部驻留内存仅切前台（部分被 trim 的对象需重建；屏显行为同冷启动——渲染完成前显示空白屏）。官方建议：**一律按冷启动假设做优化**。
- ART 用 TTID/TTFD 数据为后续启动预编译代码。
- **Baseline Profiles**：首启即 AOT 编译指定路径；"避免解释+JIT，代码执行速度**提升约 30%**"；"许多应用优化后测得约 30% 性能提升"；**Startup Profiles** 为编译期 DEX 布局优化（区别于 Baseline Profiles 的设备上优化）。https://developer.android.com/topic/performance/baselineprofiles/overview
- **Macrobenchmark**：基准测试方法论（Startup timing/帧时长等），当前页 https://developer.android.com/topic/performance/benchmarking/macrobenchmark-overview （旧 /topic/performance/macrobenchmark 已 404）。

## 6. HarmonyOS 应用质量测试标准
- **DevEco Testing 性能基础质量测试**（https://developer.huawei.com/consumer/cn/doc/harmonyos-guides/performance-testing）五大类指标：
  - 响应时延：点击响应时延（点击离手→界面变化）、滑动响应时延（毫秒）。
  - 完成时延：加载完成时延（首页铺满→占位符全加载完）、点击完成时延。
  - 卡顿：最大丢帧（动效内连续丢帧最大数，次）、卡顿率（累计丢帧时间/动效时长，ms/s）。
  - 音视频：起播时延（离手→首帧）、视频卡顿（**卡顿时长 >100ms 计 1 次**）。
  - 黑白块：启动白屏时长（启动动效开始→白屏消失）、滑动占位符加载指数（ms/s）。
- **检测标准三档**：极优体验（可选，最严）/ 较好体验（默认）/ 一般体验（默认，"感知明显、需重点关注"）；**各档具体毫秒值未在公开文档公布——未核实**（仅报告内标注）。
- 任务参数：遍历时长默认 1 小时、最大 120 分钟；冷启动重复执行计启动次数；指标监控 CPU+内存固定采集，GPU/网络/电量/温度可选；**后台负载测试**=后台态 CPU 负载与内存占用（默认开）。
- **上架预检（本地）**（…/harmonyos-guides/publish-testing）："基于**鸿蒙应用上架质量标准**构建"，覆盖兼容性/功耗/性能/UX/稳定性五专项，HarmonyOS 5.0+，最多 3 台同型设备并发；**数值标准未公开——未核实**。
- **应用稳定性体验建议**（https://developer.huawei.com/consumer/cn/doc/doccenter-architecture/experience-suggestions-stability，2026-09-29 更新）条目（类型均为"规则"，无数字）：应用崩溃（无闪退）/应用卡死/内存泄露/Native 层内存越界/资源过载（内存、CPU、存储、FD）/分布式协同业务成功率/故障自恢复。
- **应用审核指南**（https://developer.huawei.com/consumer/cn/doc/doccenter-submission/50104）：3.1 "需能正常安装、启动、卸载，**不得出现运行时崩溃、闪退、无响应**或其他功能异常"；2.13 不得未经授权强制启动系统服务（蓝牙/GPS 等）；7.9 非必需不得自启动/关联启动其它应用（5 种违例情形列举）；鸿蒙版本质量"**不低于其他版本**"；游戏启动页信息停留 **≥2s**。无量化的崩溃率/帧率/耗电数值。
- 冷启动 ≤2s、滑动 ≥55fps 等流传数值：**未核实**（未在任何官方公开页命中）。
- OpenHarmony 应用性能文档（[OH] zh-cn/application-dev/performance/，60+ 篇：冷启动提速/丢帧卡顿/首帧冗余/长帧优化等）为优化指南，**无数值红线**；目录见 gitee.com/openharmony/docs/tree/master/zh-cn/application-dev/performance。

## 9. 游戏类专项（Google Play Games Level Up guidelines）
来源：https://developer.android.com/games/guidelines （"Revamped Level Up guidelines"）
- 准入性质：**全部 UX guidelines 为加入 Level Up 计划的必要条件**；质量基准以**滚动 28 天**数据执法，且只计"近 28 天 ≥1500 会话"的已批准机型集合。
- **稳定性**：
  - `LU-ST-GAA`（参考测试机型）：崩溃率 **<1%**、ANR 率 **<2%**。
  - `LU-ST-GAB`（4GB+ RAM Android 设备）：崩溃率 **<2%**、ANR 率 **<3%**。
  - 无豁免。
- **性能 `LU-PR-GAA`**：参考机型上主动玩法场景默认目标 60fps：**平均 ≥55FPS；P90（低 10%）≥50FPS；P99（低 1%）≥30FPS**；排除加载/闪屏/下载/大厅/菜单/过场。豁免：EAA 其他移动平台不支持 60FPS 的游戏；EAB 用 HWUI/Composer 渲染的；EAC 仅交互时出帧的；EAD 平板/折叠免（散热与高分辨率）。
- **内存 `LU-MM-GAA`**：**2027 年 2 月起** Play 强制游戏满足动态内存（匿名 RSS+swap）/位图/代码优化的坏行为阈值（同 §1.1/1.3；阈值细节页 [SG]/answer/17492799）；达标是 Level Up 资格前提。无豁免。
- **Vulkan `LU-VK-GAA`**：`DEQP≥20240301` 的更新驱动设备上，Unity 2023+/UE 4.25+ 必须 **Vulkan 为主图形 API**（GLES 残留 <10% 帧可接受）；Unity Built-in RP 可走 ANGLE 过渡，**截止 2027-09-30**；其余引擎必须 Vulkan 或启用 ANGLE。
- 配套（quality/technical 页）：Play as you Download、Game Mode API、ADPF、frame pacing、Android Performance Tuner、ASTC 资产。
- vitals 侧游戏专用：Slow Sessions（20/30FPS 两口径，§1.2）；游戏内存阈值表高于应用（§1.3）。
