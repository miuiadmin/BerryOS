## 一、定谳：「一次设计最强」= 半对半

| 类别 | 事项 | 判定 |
|---|---|---|
| **能一次做对** | 资源模型细粒度（day-one） | ✅ Android 十五年四轮返工反证 |
| **能一次做对** | 废弃纪律（day-one，存量为零时立法成本最低） | ✅ Camera 废弃 12 年 16 级仍在出厂 |
| **能一次做对** | 行为变更双轨制（target 门控 + 渠道杠杆） | ✅ 复核实锤（史实六点逐字核过） |
| **能一次做对** | 错误即数据（枚举+附因+两舱） | ✅ gRPC/MCP/RFC 9457 三源同向 |
| **能一次做对** | 小冻结面 | ✅ **已裁**（ADR #55），本轮复核确认+加严边界 |
| **不能一次做对** | 高层用例抽象（Fragment 教训：平台只冻原语） | ❌ 放可独立 semver 的库里滚 |
| **不能一次做对** | UI 范式（只能并行+桥；生态成型前是唯一免桥窗口） | ❌ 且 BerryOS 正处窗口内 |
| **不能一次做对** | 分发政策（随生态调） | ❌ 但分发**基建**（签名/升级/回滚）是空白须排刀 |

**赢家公式：冻结小而对的原子核 + 把演化纪律当基础设施（不是发布装饰）+
高层抽象放库里滚。** BerryOS 的结构性优势：生态存量为零——历史平台每条
「事后补不动」的纪律，此刻立法成本都趋近于零；这个窗口用一次少一次。

## 二、五条可一次做对的原则（SDK-2 立法输入 A 组）

> 三条经对抗复核（判定均为「成立但需修正表述」），下列为修正后表述的收拢版。

### 原则 1 ｜ 资源模型第一版就细粒度，且预留合法广域通道

- **史实**：Android 2008 无权限自由读写 → 2009/API4 权限化为全盘语义 →
  2019 scoped storage + 逃生门 → 2020 无视 flag 且 WRITE 归零 → 2022
  READ_MEDIA 三拆 → 2023 部分照片访问——十五年四轮返工每轮全生态买单；
  Android 11 一边封逃生门一边被迫新造 MANAGE_EXTERNAL_STORAGE 全盘门
  （缺通道则粗权限必以特殊门还魂）。iOS 14 同病平行；Chrome File System
  Access（对象/目录级授予）是正面反例。
- **原则**：① 资源访问 API 第一版契约以**对象/树 handle 为唯一单位**，
  manifest 只声明所需能力类别，**禁止任何「全类别资源」原语**（all-files 式），
  berry-sys 亦不得封装聚合权限；② day-one 为文件管理器/备份类合法广域用例
  设计**用户显式逐树授权通道**；③ 「收紧不构成行为变更」精确化：收紧只缩小
  授权域、不改 API 契约与编程模型——应用零代码迁移，但须优雅处理句柄缺失/撤销。
- **落点**：已定面 = ADR #45 零分区四棵树沙箱（本课是它的十年尺度反证支撑）、
  能力即权限内核态 handle（天然无批量授权原语）。【立】SDK-2 定 manifest
  能力声明面细则（归属 ADR #59 三域内随刀定，勿与签名词表 security 域混置）。

### 原则 2 ｜ 废弃纪律趁存量为零的第一天立法

- **史实**：Android 官方 ABI 政策原文即「deprecated but aren't removed」——
  android.hardware.Camera 自 API 21（2014）废弃至今 12 年、历经 16 个 API
  level 仍未移除；Fragment（2011）同理。反例：Apple 靠中心化审核对 UIWebView
  限期移除成功（2020 双死线）；Android 对 Apache HttpClient 只能做到按
  targetSdk 门控移出 boot classpath，物理回收做不到。
- **原则**：① 公共 API（berry-sys/berry-gfx/berry-ui）废弃必须同时登记
  **「废弃于/移除于」双版本号 + 官方迁移文档，无移除版本的 deprecation
  不许合入**；② 移除按 ADR #56 三值版本域门控 + mkapp 编译期执法——
  target 不达标的旧包**工具期即拒**，兼容问题永不进运行时；③ **全静态链接
  加重税**：废弃 API 编进已发布 .bap 即成 OS 永不可回收的静态安全面
  （比 Android 动态框架更无解），故移除窗口必须关在编译期；④ 不触碰
  abi.toml 35 号 syscall 冻结面——立法点仅限库 API 与协议 op 语义面。
- **落点**：已定面 = 三值版本域（ADR #56 + SDK-1a 已进 mkapp）。【立】SDK-2
  现无任何废弃条款（已核空白），应随刀落册。

### 原则 3 ｜ 行为变更双轨制，杠杆内置于分发链

- **史实**（复核逐字核过六点）：uses-sdk 三元组 2009/API4 确立；targetSdk
  语义官方原文「system doesn't enable any compatibility behaviors」；
  API 26 后台限制仅 target≥26 生效；2018-08 Play 硬门槛 target 26+；
  2026-08-31 现行门槛新包 target API 36+、存量低报包对新设备新用户隐藏。
- **原则**：① 兼容性语义类变更（后台/省电策略、存储与权限语义、调度默认值）
  一律挂 manifest `[compat].target` 自报值**分档生效**（低报=旧语义）；SDK-2
  只需立「服务语义变更必须声明生效轨」的纪律；② **安全/隐私修复类变更对
  所有已装载包即时生效、不设 target 豁免**（Android "all apps" 轨先例）——
  否则低报 target = 永久豁免安全修复；③ appd/分发面必须握 **target 门槛杠杆**
  （新包上架门槛随年度 SDK 抬升、存量低报包对新用户降可见性），否则 target
  分布冻结、兼容垫片永不可撤。ABI 冻结（abi.toml）与语义演进（target 门控）
  两层分开立法不变。
- **落点**：已定面 = `[compat].target` 字段与三值链执法（ADR #56/SDK-1a）。
  【立】双轨纪律条款 + 【依赖】渠道杠杆依赖分发链基建（§五空白面①）。

### 原则 4 ｜ 错误是数据不是字符串

- **史实**：gRPC status/details、MCP 错误负载、IETF RFC 9457
  （Problem Details）三源同向：跨边界错误 = 稳定机器枚举 + 结构化附因。
- **原则**：自有 ABI 与 IPC 错误路径立法为「**枚举 + 附因结构**」
  （坏参数位 / 缺能力名 / 可重试位），并把「调用方改参数可自纠」与
  「请求结构坏了（协议错）」分成两类返回；**裸字符串错误不许穿过服务边界**；
  smoke/host 测试对错误面双读（人读+机读）断言。
- **落点**：已定面 = POSIX errno 语义保留、bsh --json。【立】35 syscall +
  berry-sys 自有 ABI 错误域、IPC 拒因面——与 SDK-4 已拍板的拒因三元组
  （行/列+期望+修法）同族，可并刀。

### 原则 5 ｜ 小冻结面（已裁，本轮复核确认 + 加严边界）

- **史实**：Win32 三十年不死=冻结面小+承诺铁的护城河；seL4 证明小 API
  可验证红利真实但复杂度只是转移不是消失；iOS 教训：兼容是三份合同
  （二进制 ABI / 源码 / 模块格式），冻结错层就锁死演化。
- **原则**：冻结面 = 仅 35 syscall（C-ABI）+ wire 格式（ADR #55 两冻结面），
  **勿升格**为「SDK 全冻结」——Rust crate 源码层保持可演化（SemVer 管），
  这是 iOS 三份合同课的直接应用：我们只冻二进制 ABI 层。
- **落点**：全部已定，无新立法。本条是**防回撤**确认（防未来有人提议
  扩大冻结面）。

## 三、三件不可一次做对（防过度设计清单）

1. **高层用例抽象**：Fragment 为解某个设备形态赶工进平台，永远拆不掉；
   正解 = 平台只冻结能力原语，用例层放独立 semver 版本化库（可出 2.0、可替换），
   库命名空间从第一天与平台命名空间分离。ADR #51（berry-gfx 冻结语义子集 /
   berry-ui 用例层独立版本化）已是此分层，SDK-2 照此口径审每个新 API 归属。
2. **UI 范式**：对存量生态换范式只能并行 + 双向桥，永远别宣布替换；但全新
   表面可以首日只开新范式——**BerryOS 生态成型前全域都是全新表面，这是
   Apple 从未有过的免桥窗口，用掉不再来**。⚠️ 别把 ADR #51 三档后端误读为
   「双范式」——那是单范式多实现，正是「实现可换、语义唯一」的正解。
3. **分发政策**：门槛/审核/抽成随生态调，不预设；但分发**基建**（.bap 签名/
   验签、升级/回滚协议、来源验证）是工程空白必须排刀（§五空白面①）——
   原则 3 的渠道杠杆以它为前提。

### 演化纪律（6）

| 课 | 判词 → 落点 |
|---|---|
| API 面积=入口×权限矩阵，非 syscall 个数 | 审查 35 个是否含 object_get_info 式泛型分派入口与 handle rights 单调递减——新对象类型只增数据不增入口语法【立·abi 复核】 |
| Fuchsia RFC-0190：单源 IDL 十年教训 | 常量层已单源（abi.toml 四产物）；原型层 berry_* 手写双镜像=挂账（§五空白面④），CI 加「无手写副本」守卫 |
| Hyrum 法则 | 契约文档必须二分「承诺/显式不承诺」：错误码映射次序、TLV 拒绝报错文本、调度延迟形态、QEMU 行为全列入「不承诺」面+防依赖措施 |
| never break userspace 是单向门，逃生门须在冻结前装进二进制 | manifest distribution 域加 target-ABI-revision 字段（生态为零时装机成本为零）【立·SDK-2】 |
| 软迁移不 scale：版本协商+准入制弃用是基础设施 | 同原则 2/3 合流：API level 进 manifest + appd 定义 target 门控行为 |
| seL4：小 API 红利真实但复杂度只是转移 | 35 syscall 小面使「全 ABI 模型检查/穷举测试」可行——G0–G5 红利同源；复杂度转移到 SDK，故 SDK-2 不是配套是主战场 |

### AI 原生（6）

| 课 | 判词 → 落点 |
|---|---|
| 接口即数据：机器可读 schema 是 agent 时代入口 | 每个系统面（syscall/IPC 消息/工具 verb/文档页）从单一 schema 源生成 Rust 绑定+人读文档+LLM tool 定义三出口（#48 同向）【立·SDK-4】 |
| 错误即数据 | → 原则 4 |
| MCP 模板：发现/schema/行为注解/双舱错误/人在环 | agent 面（SDK-4 四 verb/devmgr 活儿清单/设备壳）照 MCP 形态模板；注解是提示非担保，安全执法在授权层 |
| 约束解码反向要求：AI 填的字段=封闭枚举/有限文法 | 凡 AI 参与读写的字段（intent 词表/smoke 判定/dump 语义角色）一律封闭值域——#58 intent 六档已是范本 |
| 类型化不透明 ID（Stripe 前缀自报类型） | dump/遥测/bsh --json 所有 ID（handle/进程/surface/channel）统一类型化前缀，禁裸整数——LLM 张冠李戴只在语法护栏前必然被拦【立·SDK-1 DFX】 |
| 无障碍树被 agent 复用为 UI 的 API | 语义面=agent 面：berry-ui 控件语义角色+可达名+状态进 dump 树，注入以语义角色为锚、坐标只作对拍真值（SDK-1 已裁方向，无障碍语义树为其超集） |
