## 1. 2025 段新深读

### 1.1 moss-kernel（1,967★ · Rust · 2025-11 · Linux 兼容内核）——BerryOS 反面路线的正面样本

- **Linux 二进制兼容**：109 个 Linux syscall、fork/execve/clone 全套、ptrace（可跑 strace）、动态链接 ELF——跑起 Arch Linux AArch64 用户态（README Features）。这是 BerryOS 明确不走的路线（自有 ABI + 不跑 Linux 二进制 + v1 无 fork）——但它的存在证明 Rust 内核做 Linux 兼容在 2025 已可行。
- **async/await 内核核心**：所有非平凡 syscall 为 async 函数；**编译器强制「自旋锁不得跨睡眠点持有」**——用类型系统消除一类内核死锁；`.interruptable()` 组合子让信号打断等待 future（README Async Core）。**执法在编译期，不是运行期**——与 BerryOS lockdep（运行时执法）是两种执法哲学。
- EEVDF + SMP + IPI 任务迁移（README Process Management）。
- **libkernel 主机测试策略**：架构无关库 + 230+ 测试在 x86 host 验证 AArch64 逻辑（页表解析在 host 测）+ usertest 运行时验证——与 BerryOS `test-host` + smoke 双层同构。

### 1.2 urthr（Zig · RPi5 原生 · 真机 CI 先例）——对 BerryOS 真机线情报价值最高

板级支持矩阵（README Features 表，实证摘录）：

| 项 | RPi5 | RPi4B | QEMU virt | Q35 |
|---|---|---|---|---|
| GICv2 | **o** | **o** | -（v3） | - |
| SDHC | **o** | x | x | x |
| xHCI / PCIe | o | x | o | x |
| PSCI | **o** | **x** | o | - |
| SMP | o | o | o | o |
| PL011 | o | o | o | -（16550） |
| Cadence 千兆网卡 / RP1 南桥 / VideoCore FB | o | -（FB o） | - | - |

**三条直接修正/证实 BerryOS 真机预研（24 号吸收路线图 P0-a proposal）的事实**：
1. **RPi4B 与 RPi5 都是 GICv2**——证实 `gic.rs` 复用判断；
2. **SDHC 只在 RPi5 成熟、RPi4B 的 SD 通道无人铺**——proposal 原判「RPi4 资料多」在 SD 存储通道上不成立，RPi5 反而有完整先例（SDHC/PCIe/xHCI/网卡/RP1 南桥全套 Zig 实现可参照语义）；
3. **PSCI 只有 RPi5 有**（RPi4B 无——SMP 启动 4B 须 spin-table）——proposal 前置雷 6 在 RPi5 上自动消失。
- CI 形态：Build RPi5 + Runtime Test RPi4b 的 GitHub Actions 徽章（README 头部）——**构建与真机运行时测试分离的 CI 先例**，直接可抄给台阶二。

### 1.3 VibeOS（1,541★ · C · 2025-12 · "completely vibecoded with Claude Code"）

- 全程 Claude Code 写的 AArch64 hobby OS，有桌面截图；README 自述「**并非都能跑，有些甚至没测过，但大多数能跑**」（README 开篇）——AI 写 OS 的 2025 形态：产能惊人、**零门禁**。
- 与 2026 的 ember/vib-OS 构成演化线：AI 写 OS 从「猎奇样本」（VibeOS）到「工程闭环」（ember 人验真机）——BerryOS 的机器门禁体系是这条线的第三阶段（AI 写 + 机器验）。

### 1.4 kristos（214★ · Zig · 2025-01 · Bun 作者 Owen（Kristoffer）的学作）

跟做《Operating System in 1000 lines》完成除磁盘 IO 外全部（README Status）；Zig 版本敏感（0.13.0，0.14 需改一行）——名人学作，语言生态观察样本，无架构借鉴点。

### 1.5 简评两件

- **robonix**（410★ · Rust · syswonder）：机器人 agentic OS（具身智能体运行时）——具身 OS 线 2025 年起势，与 BerryOS v1 移动档不交叠，v2 工业 RT 的远期参照。
- **securix**（1,155★ · Nix · 法国政府 cloud-gouv）：NixOS 安全衍生——「OS 治理/合规形态」样本，非内核。

## 3. 对 BerryOS 的新启示（吸收路线图增量）

1. **P0-a proposal 事实修正（重要）**：台阶二目标板 **RPi4 → RPi5 翻案候选**——GICv2 两板同（复用不变）、SDHC/PSCI/PCIe/xHCI/网卡/RP1 全套先例在 RPi5（urthr），RPi4B 反而 SD/PSCI 双缺。原拒 RPi5 的理由（「BCM2712 陌生」）被 urthr 实证推翻一半——设备树资料已有活样本。修正走提案修订（proposal 翻 Status 或新开），交仓主裁。
2. **真机 CI 形态**（urthr）：构建板卡镜像与真机运行时测试分成两条 GitHub Actions——P0-a 台阶二的 CI 设计直接参照。
3. **编译期执法哲学**（moss）：「编译器禁止持自旋锁跨睡眠点」把一类死锁从运行时检测（lockdep）升到编译期消除——BerryOS 全同步 no_std 内核不采用 async，但「用类型系统消灭违规类别」的思路可立 ADR 议题（如：handle 权限位类型化、lockdep 热路径子集编译期化）。
4. **host 测试架构特定逻辑**（moss libkernel）：页表解析等 AArch64 逻辑在 x86 host 单元测——与 BerryOS test-host 同构互证，方向正确无需改。
5. **EEVDF 主流确认**（moss/Linux/BerryOS 三点）：S2a 选型无回归风险。

## 4. 结论

2025–2026 两年合流后全景判断不变且加强：**内核级 AI 原生位仍然空缺**（两年 34,000+ 命中无一占用）；BerryOS 的差异化位置随 Agent OS 内卷而更稀缺。新增两项可执行收获：**真机目标板事实修正（RPi5 优先候选）**与**真机 CI 形态先例**——两者都直接喂给 P0-a。
