## §1 二轮后的总判断

1. **GUI-13 的“大方向”仍成立**：

   ```text
   不按设备名分支
   WindowMetrics / InteractionProfile / WindowPolicy / UsagePolicy 分解
   一个 BerryUI core + form packs + Canvas/Immersive 逃生门
   宿主授予显示与输入语义
   ```

2. **GUI-13 的执行建议过早**。二轮发现 P5a 所需的 SYSTEM-layer / safe inset 并不是“已有字段填值”这么简单；当前还存在系统角色不可达、系统层可伪造、全局涂刷未授权、damage 越窗、AVOID_SYS buffer 合约错位等问题。

3. **metrics 不是单纯 UI 输入，而是窗口权威、事件协议、状态保持与安全边界的交叉点**。GUI-13 低估了 configure/event/push 架构。

4. **P6a 组件焦点/导航仍是低风险高价值项**，可以与安全加固和 metrics 研究并行推进；但焦点本身也要拆成窗口激活、组件焦点与 exclusive/top-resume 三层。

5. **P5b display metadata 暂缓**。当前 EFI GOP 只有启动期几何；没有 density、refresh、rotation、hotplug 或第二显示真源。提前实现会制造“假真值”。

6. **form packs 在 focus/text/navigation core 缺失前只是 taxonomy**。说“有 watch pack / TV pack”不能替代可运行的核心能力。

7. **车载形态可能不是 app 自绘 surface，而是系统渲染模板**。Android Car App Library 的模式是 app 提交模板状态，宿主按驾驶分心规则渲染；这会改变 Berry Automotive 的所有权假设。

## §3 OS 内部机制证据

### 3.1 Android：window metrics 与 configuration 是两条相关但不同的真值链

Android 当前 window size class 官方阈值：

```text
width
  Compact     <600dp
  Medium      600..839dp
  Expanded    840..1199dp
  Large       1200..1599dp
  Extra-large >=1600dp

height
  Compact     <480dp
  Medium      480..899dp
  Expanded    >=900dp
```

官方同时说明：

```text
多数 app 先看 width class
嵌套组件不应隐式依赖全局显示尺寸
size class 不是 isTablet 逻辑
```

重要修正：`WindowMetrics.getBounds()` 的 bounds **不扣除 WindowInsets**；app targetSdk >=35 后 `Configuration.screenWidthDp` 也转向不排除 insets 的口径；同一 Android 15 设备上，不同 targetSdk 可并存两种基准。也就是说，Android 的主流 size class basis 是 raw window bounds，而不是 GUI-13 假设的“safe 后可用区”。

这带来一个必须显式裁决的问题：

```text
Berry size class basis:
A. raw window bounds
B. bounds - persistent insets
C. 双值同时暴露，由 adaptive shell 选择
```

raw bounds 的优点是系统栏显隐不导致 class 抖动；post-inset 的优点是更接近“实际可用内容区”。二轮不裁决，只记录为 D1。

### 3.2 Android insets：类型与输入语义远超四向 padding

Android WindowInsets 至少区分：

```text
statusBars
navigationBars
captionBar
systemBars
displayCutout
ime
systemGestures
mandatorySystemGestures
tappableElement
systemOverlays
```

并派生不同安全区：

```text
safeDrawing
safeGestures
safeContent
```

注意 Android `systemBars` 是聚合词：statusBars + captionBar + navigationBars + systemOverlays，排除 IME。Berry 若把 SystemBars 与 SystemOverlays 建成并列 kind，是刻意简化，不是与 Android 一一对应。

关键语义：

```text
systemGestures：简单 tap 仍可达，但系统手势优先
mandatorySystemGestures：不可抢占
tappableElement：tap 可达区域
systemOverlays：不可隐藏的系统覆盖，如车载控制
ime：瞬态遮挡，且可带动画 source/target
```

因此 Berry 不能只冻结一个 `padding[4]`。至少要拆：

```text
persistent occlusion
transient IME occlusion
gesture exclusion
tappable exclusion
unhideable system overlay
display cutout/shape
```

即使 v1 只生产 0 值，也应使用 typed add-only 词表，避免后续破坏性拆分。

### 3.3 Flutter insets 代数

Flutter `MediaQueryData` 有三通道：

```text
padding
viewPadding
viewInsets
```

官方公式：

```text
padding = max(0, viewPadding - viewInsets)
```

含义：

```text
viewPadding：持续系统遮挡
viewInsets：键盘等瞬态完全遮挡
padding：扣掉瞬态遮挡后的有效安全区
```

`SafeArea` 的关键不是“加 padding”，而是：

```text
消费对应 padding
向下重作用域子树 MediaQuery
嵌套 SafeArea 不双扣
```

对 Berry 的修正：SafeArea/KeyboardAvoider 必须定义“环境重作用域”规则，而不是只在组件外扩。

### 3.4 Apple：形态是 trait/policy，不是另一套窗口系统

Apple HIG 官方 JSON 中可见：

```text
macOS：自由窗口、菜单栏、快捷键、精确指针、可记忆窗口位置
watchOS：Digital Crown、complication、AOD、极短交互
tvOS：focus system 是导航本体
visionOS：Shared Space / Full Space，窗口是可迁移 plane
iPhone Duo：外屏 compact、内屏 regular，铰链影响内容空间
```

同时 UIKit 的 trait 系统是 aspect-scoped push：

```text
registerForTraitChanges 只观察列出的 traits
traits 可能多次变化后才更新 view，需要合并
```

这支持“拆分 metrics snapshots”而不是一个巨大 Environment 订阅对象。

### 3.5 Windows：per-window DPI 与 host suggested rect

Windows Per-Monitor V2 语义：

```text
WM_DPICHANGED 推送到窗口
lParam 带 suggested size/position
app 预期重新定位和 resize
当前窗口 DPI 总等于最后一次 WM_DPICHANGED
```

PMv2 自动处理非客户区、对话框、常见控件位图；子 HWND 也会收到 DPI 变化。

教训：

```text
DPI 是 per-window 动态状态
迁移显示器时 scale 变化是事件，不是启动常量
Windows 是 fire-and-forget suggested rect：app 不应用就视觉错尺寸，但没有协议 ack/error；真正强制 serial+ack 的是 Wayland
```

### 3.6 Wayland：configure/ack 是双缓冲协议

xdg-shell 关键语义：

```text
configure 是 compositor 建议
client 不得立即应用为最终提交状态
ack_configure 必须在下次 commit 前
多个 configure 可合并，只需 ack 最后一个
ack 未发送过的 serial 是协议错误
width/height 为 0 表示 client 自选尺寸
wm_capabilities 必须在首次 configure 前告知
```

对 Berry P7 的教训：

```text
resize 不能只是 WM_SET 单向写
需要 serial + ack + last-one-wins + stale-ack 拒面
```

### 3.7 Fuchsia：layout scale 与 sampling scale 分离

Flatland ViewportProperties 区分：

```text
logical_size：布局与 clip 边界，变化时 client 应 re-layout
device_pixel_ratio：buffer 采样尺度，变化时可只 realloc buffer
```

并且 display 未连接时部分信息可能不存在。

对 Berry 的教训：

```text
scale_permille 不能同时无差别驱动布局、采样与资产选择
需要区分 layout scale / raster scale / font scale
可能需要 unknown/absent 状态，而不是默认 1000
```

### 3.8 多显示与输入路由

Android 将 touch 设备按物理端口绑定 display；Wayland 以 wl_seat 表达多输入座，capabilities 是完整集合推送；Fuchsia 的 touch/mouse source 也按 viewport 关联。

Berry 当前 inputd：

```text
单显示几何
单 pointer stream
ABS_MT 忽略
EV_REL 忽略
device_id 语义弱
```

多形态协议至少不能把“输入设备 → 目标 display”烧死为唯一屏幕。

## §4 框架内部机制证据

### 4.1 约束协议比全局 size class 更根本

Flutter 布局铁律：

```text
Constraints go down.
Sizes go up.
Parent sets position.
```

Compose 两层规则：

```text
window size class 只在 app/content 根层使用
嵌套组件使用实际拿到的 constraints
BoxWithConstraints 会把组合推迟到布局期，官方明示有成本
```

Slint 展示了无 callback 的声明式约束传播：

```text
min/max/preferred 默认子→父推导
多余空间按 stretch 分配
```

Compose FlexBox 则提供无断点的 wrap/grow/shrink：

```text
小组内自适应可用 flex/wrap
整体布局用 Grid
大数据用 lazy 容器
```

Berry 当前 `Constraints` 枚举已有：

```text
Viewport
Tight
Loose
Infinite
```

但 `relayout()` 明确只实现 Viewport，其余档 debug_assert。GUI-13 的 P5 只给 size class，不给局部约束模型，仍无法做出真正的自适应组件。

### 4.2 局部容器断点有反馈环风险

ArkUI GridRow 支持：

```text
BreakpointsReference.WindowSize
BreakpointsReference.ComponentSize
```

官方警告：ComponentSize 的 `onBreakpointChange` 回调里不要动态修改同一容器的 padding/margin，否则可能形成：

```text
容器尺寸变化 → breakpoint 变化 → padding 变化 → 容器尺寸再变化
```

Berry 未来局部断点必须内置护栏：

```text
回调内禁止改本容器几何
或状态变更推迟到下一布局轮
layout dump 输出触发来源
```

### 4.3 逻辑坐标与取整锚点

React Native 的关键规则：

```text
JS/布局保持浮点
只在设置原生根几何时取整
取整相对 root，而不是每层 parent，避免累积误差
```

Flutter `devicePixelRatio` 可为 3.5 等非整数值。

GUI-13 只定义了：

```text
1 lp = physical_px * 1000 / scale_permille
```

但没有回答：

```text
逻辑坐标是整数还是定点数？
何时取整？
边框/分隔线在 1.5x、2.5x 下如何稳定？
```

这是 D2 决策，不是实现细节。

### 4.4 TextScaler 不是 font_scale 标量

Flutter 已弃用 `textScaleFactor`，改为：

```rust
TextScaler::scale(font_size) -> scaled_size
```

原因是为非线性字体放大做准备：

```text
大字号在大放大档下增长更少
不同字号可有不同映射
支持 clamp 作用域
```

Berry 当前是 4 个 bitmap 字号档，更不能只做 `font_scale_permille * size`。合理方向是：

```text
TypographyScaler：
  输入语义字号 + density + 用户字级 + a11y 需求
  输出可用 FontSize 档或目标物理尺寸
```

### 4.5 焦点模型需要完整语义

Compose 焦点体系给出可复制矩阵：

```text
1D Tab：视觉顺序，环绕
2D directional：几何最近，不环绕
点击清除焦点，下次 Tab 从头/默认项开始
FocusGroup 进入时选择几何最近的子项
FocusRestorer 记录列表/分组离开前焦点
文本框：
  单行 Tab 移焦
  多行 Tab 插入制表符
  方向键先移动光标到边界再交出焦点
```

Flutter 还有：

```text
navigationMode = traditional | directional
读屏/a11y 模式可改变焦点遍历策略
```

Berry P6a 不能只做 `focus_next`；至少要拆：

```text
FocusOrder1D
FocusGeometry2D
FocusGroup
FocusRestorer
TextFocusBehavior
A11yNavigationMode
```

Compose 还区分普通容器与虚拟容器：

```text
LazyColumn/LazyRow/LazyGrid 天然是 focus group
普通 Row/Column 需显式 focusGroup + focusRestorer 才具备离开/恢复语义
```

BerryUI 未来虚拟列表不能只复用普通 Row 的焦点序。

### 4.6 IME 原语还不完整

egui/winit 侧 IME 事件族包括：

```text
Preedit { text, active_range }
Commit(String)
DeleteSurrounding { before, after }
```

Berry P0 目前有：

```text
phase
purpose
cursor_cp
text
```

缺少：

```text
preedit active range
surrounding text 删除
caret/selection rect 上报
IME 显隐动画 source/target
```

这不是马上扩 wire 的理由，但 P6b 前必须补规格。

### 4.7 状态保持要分三层

Android/Compose 状态层级：

```text
本地持久化
ViewModel/内存态
rememberSaveable/瞬态 UI 恢复
```

Compose list-detail 的关键规则：

```text
expanded → compact：保留 detail，隐藏 list
compact 无选中 → expanded：显示 list + 占位 detail pane
compact 有选中 → expanded：恢复 list + detail，并标出当前选择
```

`rememberSaveable` 只覆盖瞬态恢复；用户从 recents 上划彻底关闭 app 时不保留。Berry 需要区分内存态、瞬态恢复与持久化三层。

Back 行为也有多档：

```text
PopUntilScaffoldValueChange
PopUntilContentChange
PopUntilCurrentDestinationChange
PopLatest
```

Berry 需要显式定义：

```text
resize/rotate 时哪些状态内存保留
进程重启时哪些状态持久化
多窗实例各自保存什么
```

## §5 Berry 当前代码的对抗审计

## 5.1 高置信 blocker

### B1 System role 生产不可达

`surface_mode_production_policy()` 无条件调用：

```text
surface_mode_req_app_valid(&req)
```

该函数要求：

```text
role == SURFACE_ROLE_APP
```

因此即使 session 以 `WM_CLIENT_SYSTEM` 连接，也无法获得 P0 System role。P0 的 `SURFACE_ROLE_SYSTEM` 在生产路径是死词表。

代码锚点：

```text
user/berry-guiproto/src/surface.rs:277
user/berry-guiproto/src/surface.rs:284
```

### B2 SYSTEM layer 可由 APP session 自报

`WmTable::create()` 直接保存：

```text
layer: req.layer
```

没有检查 session client_type。APP session 可以创建 `WM_LAYER_SYSTEM` 窗口，从而：

```text
获得更高 hit-test layer
影响 AVOID_SYS 窗口有效几何
成为 desktop miss 的 system sink
```

代码锚点：

```text
user/bins/gui-wmd/src/table.rs:329
user/bins/gui-wmd/src/table.rs:347
```

### B3 client_type 是自声明

`WM_CONNECT` 的 client_type 来自请求帧；wmd 只检查值域，不验证系统特权。第一个声明 SYSTEM 的 session 还会成为 `system_slot()`。

这意味着 B2 不只是词表漏洞，而是权限模型漏洞。

### B4 surface_id=0 是未授权全局涂刷原语

`submit_composite()` 对 `surface_id == 0` 直接允许全屏提交，不检查 client_type。任何 session 都可以画满整个屏幕，绕过窗口 owner、layer 与 z。

代码锚点：

```text
user/bins/gui-wmd/src/relay.rs:289
```

### B5 damage 只按屏幕裁剪，不按窗口裁剪

`copy_rect()` 只 clamp 到全屏；client 提供越窗 damage 且 VMO 足够大时，可以画到别的窗口区域。

必须改为：

```text
damage ∩ own window rect
越界拒绝或裁剪
```

代码锚点：

```text
user/bins/gui-wmd/src/relay.rs:231
user/bins/gui-wmd/src/relay.rs:322
```

### B6 AVOID_SYS 与 Room buffer 合约错位

当前存在三套半实现：

```text
WmTable：AVOID_SYS 窗口 eff geometry 被 SYSTEM 窗口裁剪
Room：按请求的全屏尺寸分配 frame VMO
Compositor：按 eff geometry 推导 src_stride
```

举例：

```text
请求 APP 窗口 800×600@(0,0) + AVOID_SYS
SYSTEM top bar 800×30
WmTable eff = (0,30,800,570)
Room buffer stride = 800*4，高度 600
Compositor src_stride = 800*4，src_h = 570
```

结果：

```text
内容行错位
底部行丢失
水平裁剪时行 skew
无错误、无事件
```

这是当前潜在 bug，不只是 P5 设计缺口。

### B7 配置事件架构缺失

`WM_TABLE_WAIT` 是单车位，且被 inputd 占用：

```text
later WAIT 会 preempt earlier WAIT
app 没有 push channel
Room 不轮询 table
```

同时 wmd `wait_many` 已恰好用满 16 handles：

```text
broker + push + 7 sessions × (WM RPC + input) = 16
```

因此以下需求都被同一个架构阻塞：

```text
inset change
resize/rotate/density change
IME push
multi-display migration
configure/ack
```

### B8 Room 是单窗固定映射

`AppRoom` 当前有：

```text
一个 window: u16
一个 frame_vmo
固定 FRAME_VA
固定 FONT_VA
```

多窗/resize 需要：

```text
VA allocation table
buffer lifecycle
per-window state
per-window surface grant
possibly buffer pool
```

这不是“重构一下 Room”能覆盖的小改。

### B9 Compositor 无 occlusion/z 语义

wmd compositor 目前：

```text
一个全屏 VMO
按提交顺序拷贝 damage
不按 layer/z/窗口遮挡裁剪
```

多窗重叠时会互相污染。现有全屏 mobile 单 app 形态可接受，PC/多窗不行。

### B10 BerryUI 局部 constraints 未实现

`Constraints::Tight/Loose/Infinite` 已有词表且带 w/h 载荷，但 `relayout()` 只支持 Viewport；非 Viewport 走 `debug_assert!`，release guest 下会静默按 Viewport 保守处理。

这阻塞：

```text
局部自适应容器
list-detail 宽度分配
wrap/flex
嵌入式 pane
```

### B11 density 真值分裂

当前至少有：

```text
BerryUI: w>=1000 && h>=1800 → Product @3x，否则 Compact @2x
launcher: big = w>=600 && h>=1800，用于 phone 布局/资产分支
inputd: 800×600 bootstrap geometry，后由 wmd 快照替换
```

launcher 的 big 不完全等同于 density，但说明“同一屏幕该按什么档适配”没有单源。

### B12 launcher 归属裁决不能被静默推翻

既有 GUI-8 裁决四-e：

```text
状态栏/壁纸/桌面 = launcher 进程内容
非 wmd SYSTEM 层
```

GUI-13 的 P5a 前置 0 实际上会推翻或部分推翻该裁决。必须显式写迁移案，不能当作实现细节。

### B13 SYSTEM session 没有字形供给策略

`WM_CONNECT` 目前只给 APP session 随行私有 font VMO；SYSTEM session 没有等价字形供给。未来状态栏、IME 候选窗或系统 UI 若使用 BerryUI，将出现“系统表面无字体”的供给缺口。若系统 UI 继续由 launcher 自绘，也必须显式记录该裁决，而不是让 System role 隐含无字体。

### B14 parent/group 可跨 session

`WM_CREATE` 只验证 parent 是否在册，未验证 parent 属于当前 owner。任意 session 可以把窗口挂到其它 session 的窗口下。popup/transient role 落地前必须先决定：

```text
parent 必须同 owner？
跨进程 popup 是否需要对方/系统授权？
group 的所有权与生命周期？
```

### B15 CREATE/SHOW/refocus 对 layer 不可见

P3 的“SYSTEM 层不抢焦”只体现在 `focus_from_pointer()`；但：

```text
CREATE 无条件 focus = Some(new_id)
SET_F_VIS SHOW 无条件接焦
refocus_after_removal 在任意 layer 中选表序最末可见窗
```

因此真实 SYSTEM 窗口一旦创建/显示，会自动持有 focus。若该窗无 Keyboard 合约，按键以 `reason=class` 拒收；若未来协商 Keyboard，则可能直接收键。P4 文档中的 SYSTEM 不抢焦边界在此路径上是层盲的。

## §6 关键决策重开

## D1 size class basis

候选：

```text
A. raw window bounds
B. bounds - persistent insets
C. 同时暴露 raw bounds 与 usable bounds
```

证据：

```text
Android 当前主流：raw bounds
Flutter SafeArea：局部消费 padding
系统栏隐藏时 post-inset basis 会抖动
```

未裁决。推荐后续规格同时暴露 raw/usable，并给 `WindowSizeClass::from_bounds(basis)` 明示 basis，不给隐式全局函数。

## D2 逻辑坐标与取整

候选：

```text
A. 继续物理像素布局，只用 scale 计算 size class/theme
B. 引入 f32 logical 坐标
C. 引入 i32 milli-logical 定点坐标
```

约束：

```text
BerryUI no_std / zero alloc
现有 AST 尺寸是 u32 物理像素
RN 教训：只在 root 取整
```

低风险路线是 A 作为第一阶段；若未来转 B/C，必须重冻结 AST 尺寸语义。

## D3 inset 模型

最小候选：

```text
InsetKind
  SystemBars
  DisplayCutout
  Ime
  SystemGestures
  MandatorySystemGestures
  TappableElement
  SystemOverlays
  Waterfall
  ImeAnimationSource
  ImeAnimationTarget

InsetValue
  left/top/right/bottom
```

并区分：

```text
view_padding：持续遮挡
view_insets：IME 等瞬态遮挡
effective_padding = max(0, view_padding - view_insets)
```

不要求 v1 全部生产；但词表应 typed add-only。SafeArea 的组件级放置也要裁决：Flutter 建议包 Scaffold body 而不是整个 Scaffold，因为 AppBar 会自行消费顶 inset；Berry 的 AppBar/launcher 状态栏同样需要“谁自消费 inset”的规则。

## D4 SYSTEM privilege

候选：

```text
A. client_type 检查
B. per-boot system capability token，类似 P1 escape seed
C. svcmgr 建立专用 system broker endpoint
```

最低要求：

```text
APP session 不得创建 SYSTEM layer
APP session 不得提交 surface_id=0
SYSTEM role 只给真实系统宿主
client_type 不再可信自报
```

## D5 occlusion contract

候选：

```text
A. shrink bounds：
   系统区把窗口有效几何裁小
   app buffer/layout 使用 eff bounds
   safe inset 仅表示窗口内遮挡

B. edge-to-edge + insets：
   窗口保持请求 bounds
   可画到系统区下
   app 用 safe insets 避让内容
   SYSTEM window overlay 在上

C. 双模式：
   AVOID_SYS 表示 shrink；默认保持 raw bounds + insets
   但当前默认重叠像素仍是提交顺序决定，尚不构成 edge-to-edge 合约
   双模式必须先定义像素/遮挡真值
```

现代工业趋势偏 B，但不能在不修 B1/B4/B5/B6 的情况下实施。

## D6 config event

候选：

```text
A. per-session event queue + existing channel poll
B. 新 event channel（受 wait_many 帽限制）
C. 全局 multicast table wait（需重设计单车位）
```

事件内容：

```text
serial
bounds
scale
insets
posture
display id
cause: resize/rotate/density/inset/ime
```

Slint 平台契约还要求后端在窗口创建后立即派发一次 `ScaleFactorChanged`，用于设定初始 scale。对应 Berry：spawn 时的初始 viewport/scale 也必须走同一条 Room→UI 初始化通道，而不是只处理“变化”。

app→host 的 geometry request 也必须是可拒绝请求，而非命令；Apple `requestGeometryUpdate` 以异步 error handler 回报结果。host→client resize 则需要：

```text
ack serial
last-one-wins
stale ack 拒面
```

Fuchsia 会在 child 第一次 Present 前交付 LayoutInfo，使首帧可用正确 bounds/scale/insets。Berry R3 的目标应是 spawn 时先 pull-once 初始 config，再进入 push/poll 更新，避免新 surface 用占位 metrics 渲染。

## D7 focus 三层拆解

```text
1. window activation / seat focus
2. in-tree component focus
3. top/exclusive arbitration
```

例子：

```text
两个可见 app 都可 resumed/active
只有一个 window 拥有 keyboard focus
camera/mic 等 exclusive resource 需要 top arbitration
```

P3/P4 已有第一层的早期形态；P6a 是第二层；第三层暂缓但词表别混淆。

## D8 typography scaler

```text
输入：
  semantic token
  layout density
  user font scale
  a11y needs
输出：
  FontSize 档或目标物理尺寸
```

不做单一线性 `font_scale` 字段。

## D9 Automotive ownership

候选：

```text
A. app surface + UsagePolicy 限制
B. host-rendered templates
```

Android Car App Library 证明安全关键形态更偏 B。Berry 至少要保留：

```text
template state
system renderer
distraction policy
```

这条可能改变 app/sdk 边界，需单独研究。
