### 1.2 华为 Push Kit 数值补充（HarmonyOS 版）
- 消息体 4KB 不含 token；单次 REST 请求最多 1000 个 Push Token（超限错误码 80300010）。[MIR] 频控FAQ
- 卡片刷新消息：卡片已上架 2 条/天/卡片，未上架 5 条/天；实况窗：每设备 10 次/5 分钟、60 次/小时（出行打车与赛事比分 30 次/5 分钟、180 次/小时）。[MIR] 频控FAQ
- 频控回执：102=现网管控频控，256=超场景化频控/超测试限额。[MIR] 频控FAQ
- Android 侧（HMS Core Push）：2023-03-31 起统一"消息自分类"，逾期未接入一律默认资讯营销（每日限 2 或 5 条）。[HW] /consumer/cn/doc/hmscore-common-Guides/push_notice-0000001529940921
- 通知样式规范：文本最多 3 行；大图标建议 <128×128（>49152 像素不展示）；禁伪造他应用/隐藏 icon/强制置顶（语音通话等 8 类进行中通知例外）/重复内容/标题正文重复。[MIR] spec
- 使用基本原则：HarmonyOS 应用推送必须经华为官方消息推送平台下发；上架应用市场且用推送行为者适用《Push Kit 接入规范》。[MIR] spec

### 1.3 小米推送数值补充（2026 新规后）
- 公信消息单日总量公式：HyperOS/MIUI 安装且通知开启数 × 倍数；有新闻证 3 倍/无 2 倍；送达量计额，错误码 200001（exceed quota）/200002（too frequent）；quota 查询 API 限 1 次/秒。[MI] pId=1656
- QPS 分级（按通知开启数）：≥1000 万→3000；≥500 万→2500；≥100 万→2000；≥10 万→1000；<10 万→500；1 请求最多 1000 目标设备。[MI] pId=1656
- 模板化：2026-12-31 前未完成私信模板接入将影响私信消息下发；订阅消息仅 8 专属类目（资讯订阅/直播预约/活动预约/赛事预约/作品预约/游戏内动态提醒/上线提醒/商品预约），同日"个人订阅"通道关停。[MI] pId=1656
- Voip Service Kit（音视频通话拉起）需邮件申请（政企通信/纯 IM/客服/告警类），15 个工作日答复；不定期合规核查。[MI] pId=1656

### 1.4 vivo 数值补充

## §2 统一推送联盟 / UnifiedPush

### 2.1 统一推送联盟→统一推送工作委员会（信通院/TAF 体系）

- 2025-05-13 时隔一年半发文：以"身份 ID"为基础推进全场景统一推送；设备 ID 与身份 ID 割裂被列为最大障碍；依据国家数据局《可信数据空间发展行动计划（2024-2028 年）》启动 ID 互联互通标准制定。ithome 852/629

### 2.2 UnifiedPush（国际开源规范，非信通院体系）
- 开源去中心化推送规范：应用→distributor→服务器，无特权服务、最小权限，面向 de-Googled Android 与 Linux。https://unifiedpush.org/
- Android distributor：Sunup、ntfy、Conversations(XMPP)、NextPush、gCompat-UP（借道 Google 服务）；Linux：KUnifiedPush（KDE）。规范含 Android/D-Bus 定义。unifiedpush.org
- 支持应用 40+：Tusky、Element、FluffyChat、Molly、Tuba 等（Fediverse/IM 为主）；资金：NLnet NGI Zero（欧盟 NGI 资助）+COVESA。unifiedpush.org
- 与中国联盟无组织关系；两者均主张"应用免自建长连接"。

## §3 账号服务与设备标识

### 3.1 Sign in with Apple（App Review Guidelines 4.8 Login Services，2024 后现行措辞）
- 原文要点：使用第三方/社交登录（Facebook Login、Google Sign-In、Log in with X、Sign In with LinkedIn、Login with Amazon、WeChat Login 举例）建立用户主账号的应用，必须同时提供满足以下三条件的"等价登录服务"：①仅收集姓名与邮箱；②允许用户保留邮箱私密；③未经同意不得收集应用内交互用于广告。（已不再点名"必须 Sign in with Apple"，Sign in with Apple 是满足三条件的现成选项。）https://developer.apple.com/app-store/review/guidelines/
- 豁免（无需提供另一登录服务）：仅用自家账号体系；替代应用市场及其市场专属登录；教育/企业/商业应用要求既有账号；政府或行业背书的公民电子身份；特定第三方服务客户端且必须登录该第三方账号（邮件/社交等）。同上
- 第一轮已采：ATT/IDFA（拒绝后 IDFA=0，未弹窗即追踪拒审 5.1.1）；本档补 IDFV 官方页：https://developer.apple.com/documentation/uikit/uidevice/identifierforvendor

### 3.2 Google Sign-In / 账号政策
- 无类似 4.8 的"提供第三方登录即必须提供 Google 登录"强制条款；使用 Google Sign-In 须遵守 Google API Services User Data Policy 与 Google Sign-In 品牌规范（按钮样式/配色/文案）。https://developers.google.com/identity/branding-guidelines
- 账号删除（User Data 政策，2023-04-05 公告）：允许创建账号的应用必须在应用内且通过 web 资源两路径提供账号删除请求；web 链接须填入 Data safety 表单（Play 展示"数据删除"徽章）。https://support.google.com/googleplay/android-developer/answer/13327111 · https://support.google.com/googleplay/android-developer/answer/13411745
- Google Play Console 开发者验证要求（组织/个人身份信息展示于商店）。https://support.google.com/googleplay/android-developer/answer/10788890

### 3.3 华为账号登录规范（中国区/鸿蒙生态）
- 应用侧（华为应用市场审核要求）：应用支持用户使用第三方账号登录时，需提供华为账号登录选项；登录场景三点全满足时华为账号登录为必选（华为开发者联盟 FAQ 官号转述官方细则，三点原文未直抓到官方页，未逐字核实）。https://segmentfault.com/a/1190000047408644 · https://bbs.itying.com/topic/6823e079062dc60098c25291
- 元服务侧（官方细则原文）：①构建账号体系须使用华为账号静默登录；②关联既有账号可申请获取手机号；③登录界面可自行设计。https://developer.huawei.com/consumer/cn/doc/atomic-guides/account-guide-atomic-detailedrules
- 华为账号能力档：普通登录/一键授权登录/静默登录三档；AGC 配置 Client ID + 公钥指纹（SHA256）绑定包名。（官方+uni-app 接入文档转述）

- IDFA：iOS 14.5+ 需 ATT 弹窗（第一轮已采 https://developer.apple.com/documentation/apptrackingtransparency）。

- OAID（中国信通院/TAF 口径，T/TAF 095—2023《移动智能终端补充设备标识规范》，2023 版替代 2020/2021 版；起草：信通院+小米+维沃+欧珀+华为+荣耀等）：
  - 标识体系：UDID（设备唯一，不可关闭不可重置）/OAID（开放匿名设备标识符，"可连接所有应用数据，可用于广告等业务"）/VAID（开发者匿名，同一开发者应用间）/AAID（应用匿名，清除数据即重置）；四者之间不存在映射关系。http://taf.org.cn/upload/AssociationStandard/TTAF%20095—2023%20移动智能终端补充设备标识规范.pdf
  - OAID 开关：终端应提供开/关（总开关+宜支持单应用）；关闭后不返回或仅返回全 0/空值，告知关闭态时返回重置后的新值；单应用关闭只返回全 0/空值。标准 6.2.4
  - OAID 重置：用户手动重置应重置；恢复出厂可重置；允许特殊情况重置；重置后旧值不可关联。标准 6.2.3
  - 适用与豁免（范围条款原文）："本文件规定了…功能要求、接口要求以及安全要求，个别条款不适用于特殊行业、专业应用，其他终端也可参考使用。本文件适用于各种制式的移动智能终端的开发。"标准第 1 章
  - 统一调用 SDK（移动安全联盟 MSA 体系）2025-08 升级 v2.8.0（新增科大讯飞平板包）。https://www.toutiao.com/article/7548010408755249698/
  - 强制性国家标准《智能终端匿名标识符数据安全技术要求》立项推进中（工信部项目建议书）。https://wap.miit.gov.cn/cms_files/filemanager/1226211233/attach/20261/e85bb0619d5343cc80325454603c28bd.pdf
  - 行业归口：行业标准《移动智能终端补充设备标识技术要求》由中国通信标准化协会归口、工信部主管。https://std.samr.gov.cn/hb/search/stdHBDetailed?id=2F7B4471A6FEF3B1E06397BE0A0A6557

- 《App 违法违规收集使用个人信息行为认定方法》（网信办等四部门 2019）：22 条情形含 SDK 维度（未逐一列出第三方 SDK 收集项即"未明示"）。http://www.cac.gov.cn/2019-12/30/c_1578375159509308.htm
- 《互联网广告管理办法》（市场监管总局令 72 号，2023-05-01 施行）：弹窗广告确保一键关闭、不得以欺骗误导方式点击、广告具有可识别性。全文 https://www.samr.gov.cn/cms_files/filemanager/1647978232/attach/20234/W020230320579023662253.pdf · 公报 https://www.gov.cn/gongbao/2023/issue_10506/202306/content_6885261.html
- SDK 双方义务要点（现行规范叠加态）：App 提供者为个人信息处理者、SDK 为受托处理/共同处理者——App 须在隐私政策逐一披露 SDK 及目的；SDK 须最小化收集并可独立行权响应；厂商侧执法口径（MIIT 164 号令）第一轮已采。
- 厂商广告平台：华为鲸鸿动能（流量变现）、小米营销/OPPO 营销/vivo 营销——开发者接入需企业资质+广告类目审核（各平台接入页，未逐项核实细则）。
- 关联事实：小米推送将"动态关闭率"与推送额度挂钩（§1.3），营销骚扰直接降低到达配额。

## §8 应用更新服务与热更

### 8.1 自更新 vs 商店更新
- Google Play（Device and Network Abuse 政策原文）："An app distributed via Google Play may not modify, replace, or update itself using any method other than Google Play's update mechanism. Likewise, an app may not download executable code (such as dex, JAR, .so files) from a source other than Google Play." 例外：运行于虚拟机/解释器并间接访问 Android API 的代码（如 WebView/浏览器中的 JavaScript）不受限；解释型语言运行时加载（JS/Python/Lua 等，非随包分发）不得允许潜在违反 Play 政策的行为。https://support.google.com/googleplay/android-developer/answer/16559646
- Apple（2.5.2 原文）："Apps should be self-contained in their bundles…may not download, install, or execute code which introduces or changes features or functionality of the app"（教育类教编程应用在代码可查看编辑等限定下例外）——iOS 全禁自更新与可执行代码下载。https://developer.apple.com/app-store/review/guidelines/
- 华为应用市场（审核指南 3.12 原文）："应用不能自动更新（即从您的或其他第三方的网站下载可执行组件）"。https://developer.huawei.com/consumer/cn/doc/50140
- 小米/OPPO/vivo/应用宝：商店审核规则同样要求更新走商店（未核到逐字条款，未核实；华为条款可作国产商店通行口径样例）。

### 8.2 热更新边界
- dex/JAR/.so 热更：Google Play 明文禁止（8.1 原文）；iOS 同禁（2.5.2）；华为以"可执行组件"表述同禁。
- JS/资源热更：Google Play 允许（解释器例外条款，须防政策规避）；Apple 对 WebView 内 JS 放行、原生功能变化仍受 2.5.2 约束。
- HarmonyOS：RN 热更存在合规实践（审核红线=功能安全/数据安全/系统兼容，二手分析口径；官方未见"热更"专章，未核实到原文）；华为 Push Kit 后台消息明确可用于"告知应用更新配置参数"。[MIR] Push Kit 简介
- 各店"禁 dex 热更"逐字条款：仅 Google Play 原文可及；国产各家未见公开专条（未核实）。

## §9 深度链接与归因面

### 9.1 验证机制（第一轮基础 + 本轮补充）
- Android App Links：http/https + autoVerify + /.well-known/assetlinks.json（SHA256 指纹）；A14 起隐式 intent 只达 exported（第一轮已采 https://developer.android.com/training/app-links）。
- iOS Universal Links：AASA（apple-app-site-association）+ associated domains entitlement（第一轮已采）。
- 华为 App Linking（AGC 增长服务）：跨平台深链（Android/iOS/Web/帖内），"未安装→AppGallery 下载→安装后仍直达指定内容"（延迟深链）；长/短链、链接前缀（drcn.agconnect.link 域）、"应用链接+元服务链接"两类；提供点击/拉起数据统计；接入=AGC 开通+SDK+申请链接前缀。https://developer.huawei.com/consumer/en/agconnect/App-linking/ · codelab https://developer.huawei.com/consumer/en/codelab/AppLinking/index.html
- 小米：未检索到公开的厂商级深链验证服务（快应用支持 deeplink 拉起；HyperConnect 应用接力为系统级"接力"而非域名验证深链，未核实）。
- "国民深链生态"：未见国家级统一深链标准落地；统一推送工委会 2025 年启动的 ID 互联互通标准（§2.1）是最接近的跨厂商标识/触达标准化动作。
- 延迟深链服务供给：厂商侧=华为 App Linking、Google Play（非中国）；三方商业=AppsFlyer/Adjust/Branch 等（未采细则）。

### 9.2 归因要求事实
- Apple：AdServices（Apple Search Ads 归因）与 AdSupport（IDFA）双框架；ATT 拒绝后 tracking 域名请求失败（第一轮已采）。
- Google：Play Install Referrer API 为安装归因官方通道（第一轮已采 https://developer.android.com/google/play/install/installreferrer）。
- 华为：App Linking 链接数据（点击/拉起）为官方归因面；OAID 为中国广告归因主标识（§3.4，可关闭可重置）。
