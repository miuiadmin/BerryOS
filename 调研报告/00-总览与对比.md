## 1. 报告导读

- **[01-RT-Thread.md](01-RT-Thread.md)** —— 国内装机量最大的开源 RTOS（25 亿台、830+ 软件包），宏内核起家、RT-Smart 扩展为混合内核。价值在 O(1) 位图调度器、`mm_aspace` 缺页回调骨架、PM 计数投票三件套；反面是驱动进内核与全局对象命名。
- **[02-openEuler.md](02-openEuler.md)** —— 华为系宏内核 Linux 发行版，本体与 BerryOS 不同类；真正价值在四条侧线：PREEMPT_RT 包级交付、混合关键性 MICA 框架、A-Tune AI 自调优引擎（用户态离线 profile 制，已近维护态）、UniProton 轻量 RTOS（实证做了 tickless 与 SMP）。
- **[03-OpenHarmony内核.md](03-OpenHarmony内核.md)** —— 三内核矩阵（LiteOS-M / LiteOS-A / Linux）。LiteOS-M 的 tickless 是 day-one 内生设计（单次触发 + 75% 精度裕量 + DVFS 换算记账）；LiteOS-A 的每核 runqueue + 两级位图 + EDF 是教科书级 SMP 实时调度；"微内核"宣传与开源现实的落差是最大警示。
- **[04-seL4与L4家族.md](04-seL4与L4家族.md)** —— 唯一端到端形式化证明的内核（~10 syscall、IPC 413 cycle、超硬件极限仅 10-20%）。fastpath/slowpath 分层、notification 语义、MCS 调度上下文（CPU 时间即能力）是机制级金矿；untyped 全用户态分配与 GPL 许可是不可搬的边界。
- **[05-Zircon-Fuchsia.md](05-Zircon-Fuchsia.md)** —— BerryOS 的直系参照（务实派对象内核 + handle+rights + VMO/Vmar + channel/port）。新挖出 libsched 带宽模型（firm/flexible 统一 + WAVL + 簇感知 stealing）、Job 策略树、Port 背压常数、合并退出快路径；devfs 目录命名空间正被官方迁移否定。
- **[06-QNX-Neutrino.md](06-QNX-Neutrino.md)** —— 商用微内核硬实时标杆（2.55 亿车载）。同步消息复制 IPC + 消息驱动优先级继承 + resmgr 路径挂载 + always tickless；APS 分区调度是 BerryOS AI 护栏的直系原型，其 8.0 被砍（策略焊进热路径）又是最重要的反面教材。闭源，仅文档可引。
- **[07-工业级三强-VxWorks-Integrity-PikeOS.md](07-工业级三强-VxWorks-Integrity-PikeOS.md)** —— 安全关键 RTOS 商业范式：ARINC 653 静态窗口、INTEGRITY 无动态分配内核、PikeOS 分区+人格、BAM 带宽监控；核心教训是"认证证据即商品"与静态化换确定性的代价。
- **[08-FreeRTOS-ThreadX.md](08-FreeRTOS-ThreadX.md)** —— 两个 MIT 单核小内核：FreeRTOS 的五段式 tickless idle（期望空闲/门槛/入睡三查/压表补偿/补 tick）是 BerryOS NO_HZ 最直接的可抄链路；ThreadX 的确定性纪律（每 API 有界、preemption-threshold、控制块前缀 ABI）与 FreeRTOS 的 queue 统一原语各自成章。
- **[09-Zephyr.md](09-Zephyr.md)** —— 社区动能最强的开源 RTOS：tickless 三函数契约 + 超时队列五后端、可插拔调度（编译期 choice + 4 操作窄接口）、PM 窄契约 `next_state(cpu,ticks)` + 延迟 QoS；全局就绪队列 + 单锁与 270 个 CVE 是反面。
- **[10-其他微内核-MINIX3-HelenOS-Genode.md](10-其他微内核-MINIX3-HelenOS-Genode.md)** —— 微内核"服务器社会"三种命运：MINIX 3（死，但 RS 监督-重生闭环是教科书）、HelenOS（学术长寿、命名分层精细）、Genode（AGPL 商业存活，资源配额随会话走的架构级创新）。
- **[11-Rust系OS四家.md](11-Rust系OS四家.md)** —— Rust OS 工程事实：Hubris（生产级静态消息内核，监督重启协议 + generation 计数）、zCore（Zircon 语义安全 Rust 复刻，`hal_fn_def!` 宏 + syscall 层零 unsafe）、Redox（scheme/URL 十年不塌）、Theseus（intralingual，已停更）、ArceOS（组件化组装）。

## 3. 按 BerryOS 四支柱横切分析

### 3.1 微内核路线：IPC 语义与成本，谁家最务实

业界 IPC 谱系（报告 04/05/06/10/11）：**纯同步**一端是 seL4 endpoint（fastpath 413 cycle、超硬件极限仅 10-20%，报告 04）与 Hubris 会合式（投递即 `NextTask::Specific` 直切，报告 11）；**同步+复制+优先级联动**是 QNX（小消息故意拷两次——"拷两次快过改页表"是官方白纸黑字，且消息驱动优先级继承在 send 时刻提升，报告 06）；**异步信令**是 seL4 notification（二元信号量数组）与 Zircon port（带背压常数，报告 04/05）；**共享内存**则由 Zircon VMO 与 Hubris lease（内核仲裁租借而非拷贝，报告 11）承载。

**最务实的是 QNX**：连接即 FD 消灭一层翻译、resmgr 把写驱动降维成填 POSIX 函数表、45 年量产验证——但它用 procnto 折衷（进程/路径管理与内核同地址空间）换性能，恰是 BerryOS 要避开的失败域（报告 06 警示 1）。**seL4 证明机制极简的上限**（快与可证明兼得），代价是复杂度转嫁给用户态初始化（报告 04 不足 4）。BerryOS 的 Zircon 务实派选择（内核有对象/分配器、channel+port+共享内存三件套、路径式命名空间在用户态 namespace 服务）在两者之间，本次调研没有发现推翻该决策的证据；需要补课的是 QNX 的优先级继承语义与 seL4 的 fastpath 分层（见 §5 行动 4）。

### 3.2 省电：tickless 谁最成熟，BerryOS 还缺什么

微内核/学术圈在省电上普遍留白（seL4 无电源管理、MINIX/HelenOS/Genode 均无可抄，报告 04/10），成熟的 tickless 全部在 RTOS 圈：**LiteOS-M 是 day-one 设计**（无周期 tick，`OsSchedSetNextExpireTime` 取 min(最近超时,时间片终点) 重装载 + 75% 裕量，报告 03）；**FreeRTOS 是机制/策略分离教科书**（期望空闲计算在 tasks.c、压表补偿在 port.c weak 函数、入睡前三查，报告 08）；**Zephyr 是契约级设计**（内核-驱动三函数契约 + 超时队列五后端 + elapsed 单调不变式 + sloppy 停摆，报告 09）；**QNX 8.0 全程 tickless**（tick 只是 1kHz 概念，报告 06）。RT-Thread 的"睡前停 tick、醒来补账"是反面（报告 01）。

BerryOS 已落地的 NO_HZ day-one（空闲 mask CNTV + wfi，one-shot 到下一事件）机制上优于补偿式，站在 LiteOS-M/Zephyr/FreeRTOS 三家肩上（报告 03/08/09 佐证）。**还缺四件**：① 入睡前三查护栏（FreeRTOS，报告 08）；② 每次以绝对截止时间重编定时器、拒绝累积补偿漂移（报告 08 反面教训）；③ DVFS 感知的时间片周期数记账与调频换算（LiteOS-M `OsSchedTimeConvertFreq`，报告 03）；④ 深睡前冻结任务超时链 + 用户态 PM 服务的窄契约（LiteOS-M 冻结、Zephyr `next_state(cpu,ticks)` + 延迟 QoS，报告 03/09）。

### 3.3 AI 调度：业界现状与 BerryOS 内核第一类 ABI 的价值与风险

**现状：没有一家把 AI 做进调度决策通路。** 最接近的 openEuler A-Tune 是用户态离线/半在线调优——决策终点是配置文件与 profile 切换，粒度系统级、时机运维节奏，且已近维护态（约一年无实质提交，报告 02）；EulerCopilot/Agent Infra 是 LLM 运维助手方向（报告 02）。传统内核侧最接近"策略注入"的是 Zircon `zx_object_set_profile`（传参进内核算法，报告 05）与 Zephyr 的编译期 Kconfig choice（运行时不可换，报告 09）——都不是运行时策略替换。

对 BerryOS 有用的三块拼图（报告 04/06）：**seL4 MCS 的调度上下文把 CPU 时间本身做成能力**（内核只做 refill 预算机制，预算怎么配是外部输入）——内核第一类 ABI 的最纯结构样例；**QNX APS 的预算包络+突发借用+RT 豁免+越值处置**——护栏词汇表现成（报告 06）；**Genode 的建议+协商式护栏**（AI 对调度只有建议通道，越权动作在 ABI 层不存在，报告 10）。**风险同样明确**：APS 因策略焊进调度热路径（每次决策扫描全部分区、上限 8、与轮转打架）而被作者亲手砍掉（报告 06）——BerryOS"机制在内核 O(1)、策略（含 AI）在用户态慢循环、快路径开销与策略复杂度无关"必须列为不可妥协验收线；A-Tune 的教训是只做参数推荐价值感知弱、难持续投入（报告 02），BerryOS 必须让 AI 成为调度路径常态参与者而非旁路工具。

### 3.4 高性能：SMP/每核 runqueue/负载均衡，可插拔策略谁做得最好

三种 SMP 形态（报告 03/05/09）：**每核 runqueue**——LiteOS-A `g_schedRunqueue[CORE_NUM]` + 两级位图 + 亲核掩码内联过滤 + lockdep，40 行内完成选核选任务（报告 03）；**全局就绪队列**——Zephyr 单把 `_sched_spinlock` + mask 过滤，PIN_ONLY 每核队列是事后补丁（报告 09，反面）；**单核思维上 SMP**——FreeRTOS 默认 `RUN_MULTIPLE_PRIORITIES=0` 压制并行度（报告 08，反面）。负载均衡与能耗感知的标杆是 Zircon：簇感知延迟 work stealing（低于簇均值-阈值才触发）+ 性能/功耗标度映射 DVFS 频点入选核判据（报告 05）。QNX 佐证微内核上全可抢占（窗口数百纳秒）可达（报告 06）。

**可插拔策略做得最好的是 Zephyr 的"接口收窄"**——调度核心只依赖 `_priq_run_add/remove/best/yield` 四个操作，数据结构编译期五选一（报告 09）；但其策略运行时不可换、MULTIQ 与 DEADLINE 互斥暴露组合爆炸。Theseus 的并列策略 crate 是 BerryOS trait 设计最直接的同类项，但只到编译期 cfg（报告 11）；MINIX 把调度策略放用户态服务器则探到了延迟税的下界（每决策一条 IPC，报告 10）。**结论：运行时可注册的 trait 策略对象 + Zephyr 式窄接口在 23 个系统中是空位**，正是 BerryOS 的差异化组合；统一底座可选 Zircon libsched 带宽模型（firm capacity + flexible weight，报告 05）。

## 5. 给 BerryOS 的 Top 10 行动建议（自 Phase 2b 起排序）

1. **Phase 2b 用户进程第一步：对照 zCore 形状实现内核对象与 handle 表**——`KObjectBase` + `Rights` bitflags + 进程挂 handle 表 + 复制只允许收窄（参考 11/05 号报告；zCore MIT 可对照代码形状），同步冻结 TCB 前缀 ABI：上下文切换 asm 只依赖固定偏移字段并注释声明（08 号 FreeRTOS/ThreadX 共同纪律）。
2. **VMO/Vmar 用 RT-Thread `mm_aspace` 骨架 + zCore 三后端**——`rt_varea+mem_obj+on_page_fault` 的"区域对象+缺页回调+后端"形状（01），paged/physical/slice 三后端与 COW 父子链（05）；v1 先做匿名 VMO，用户态 pager 接口预留。
3. **syscall 层三分层**——v1 坚持 ~26 个 `object_*` 合并（学 seL4 ~10 调用的极简方向与 FreeRTOS queue 统一原语，04/08）；每个 bos_* 配独立 verify 函数做 handle 类型/权限先行校验（Zephyr z_impl/z_vrfy 自动生成纪律，09）；补 Zircon 式 `*_HANDLE_CLOSE_THREAD_EXIT` 合并退出快路径（05）。
4. **channel IPC 落三条 QNX/seL4 机制**——① 发送者优先级继承且在 send 时刻提升（06）；② 通道三队列语义：Send 按优先级 FIFO / Receive LIFO / Reply 无序（06）；③ fastpath/slowpath 分层：同核直切短路径 + 检查链逐条短路（04，只借机制不抄 GPL 代码）。
5. **失败隔离落地为 Job 树 + 用户态监督服务**——Zircon Job Policy 15 条件×Kill/Exception 动作 + `critical_to_job`（05）；监督服务抄 MINIX RS 全闭环：心跳 2×period 判死 + 二进制指数退避 + 恢复脚本钩子 + replica 换壳（10）；重启语义学 Hubris：generation 计数让陈旧句柄可检测、阻塞方收可识别错误码、重启用同一条 init 代码路径（11）。
6. **tickless idle 立即补强（Phase 2a 底子上小改）**——补入睡前三查（pending ready/yield pending/pended tick，08）；坚持绝对截止时间重编 CNTV、拒绝 FreeRTOS 式累积补偿（08 反面）；把时间片改成 LiteOS-M 式周期数记账+调频换算，为 DVFS 预埋（03）。
7. **用户态 PM 服务按窄契约设计**——内核在共享环上只问一句 `next_state(cpu, ticks_left)`（09）；睡眠档计数投票聚合 + per-device 挂起钩子长在服务里（01）；进低功耗前预扣 exit_latency、登记唤醒延迟 QoS（09）；深睡前冻结任务超时链（03）；PM 崩溃内核降级保活（04 反面佐证 seL4 无 governor 亦存活）。
8. **调度策略 trait 接口收窄到 4 操作并运行时注册**——`add/remove/best/yield` 窄接口（09），class_rt/class_fair/class_deadline/class_idle 运行时注册（Theseus 并列 crate 的运行时化，11）；EDF 用 32 位半模无符号减法比较器 + INT32_MAX/2 钳位（09）。
9. **AI 调度 ABI 用现成词汇表定义护栏**——预算包络+突发借用+RT 豁免+越界处置四件套直接引用 QNX APS 边界条件定义（06）；CPU 时间做成可配置预算的机制原语（seL4 SC/refill，04）；RT 屏蔽用 ThreadX preemption-threshold 语义（08）；服务时间计费给触发方（QNX 分区继承，06）；遥测环背压参照 Zircon Port 全局 16K/每端口 2048（05）；验收线：快路径开销与策略复杂度无关（06 APS 之死）。
10. **v2 SMP 与可观测性双预备**——每核 runqueue 两级位图 + 亲核掩码内联过滤（03）+ 簇感知延迟 work stealing（05）+ 以 Zircon firm/flexible 带宽模型作 class_deadline/class_fair 统一底座（05）；基准学 sel4bench 公开可复跑（04），trace 静态点零成本关闭（01/08），调试走"全静态符号 + dump 即全貌"（11 humility 思路），并做"一份定义生成 #[repr(C)] 结构+文档+测试桩"的单一事实源（04 bitfield 思路）。

## 6. 明确不学清单

**协议洁净（GPL/AGPL/MPL 不进，只看思路）**
- seL4 内核代码一个字不进（GPL-2.0-only，04）；Linux/openEuler 内核补丁（GPL，02）与 Genode 代码（AGPL，10）零复制；Hubris 现行 MPL-2.0——语义可借、文件不搬（11）；rCore-Tutorial-v3 为 GPL-3.0 只看思路，zCore（MIT）才可对照形状（11）；`参考源码/README.md` 的 hubris/rCore 许可证标注应按 11 号报告修正。

**架构方向（违背 Zircon 务实派中心 / v1 约束）**
- 不学 RT-Thread"驱动/FS/网络进内核镜像"与全局对象命名空间（01）——RT-Smart 做了 MMU 隔离仍被这两点钉死。
- 不学 QNX procnto 把进程/路径管理塞进内核地址空间（06）；不学 Qnet 式"一种 IPC 统管一切"（透明分布式消息已死，06，对应架构综合纲领排除第 4 问）。
- 不学 seL4 untyped 全用户态内存分配（初始化器复杂度反噬，04）；不把形式化验证写进 BerryOS 承诺（04 证明追不上特性）。
- 不学 LiteOS-A 的 203 syscall 大接口面与 fork/clone（03）——v1 ~26 syscall + 无 fork 是既定边界；也不学 openEuler 把调度补丁直接长在 CFS 内核锁上（02）。
- 不学 Zephyr Kconfig 式第三套配置语言（cargo feature + 类型系统足够，09）；不学其全局就绪队列 + 单把调度锁（09）与 FreeRTOS `RUN_MULTIPLE_PRIORITIES=0` 的单核思维（08）。
- 不学 devfs 目录式设备命名空间（Zircon 官方正在迁移否定它，05）；v1 不上组件框架全套 manifest/resolver/runner（05）。
- 不学 ARINC 653 MAF 静态窗口（与 NO_HZ 直接冲突，07）；不为认证提前缴税，只学其可追溯性习惯（07）。

**机制取舍（与四支柱或软实时定位冲突）**
- 不学 MINIX 把调度策略放用户态服务器（每决策一条 IPC 的延迟税，10）——BerryOS 内核内 trait 插拔是更优点。
- 不学 Hubris"无动态任务/无 MMU/syscall 误用即 fault"全套（BerryOS 是动态进程通用 OS，11）；不学 ThreadX/Hubris 同级不轮转（PC 公平性需要，08/11）。
- 不学 Theseus 全盘 intralingual 与在线演化当 v1 目标（11）；不学 zCore futures 全内建（徒增调试面，11）；不学 Redox relibc 负担与"一切皆 fd"过度统一（11）；不学 HelenOS 十架构广度（ARM64 打穿再说，10）；不学 ArceOS unikernel 默认形态（无进程隔离与能力模型冲突，11）。
- 不学 FreeRTOS/RT-Thread 的 tickless 累积补偿（漂移，08/01）；不学 APS 把预算策略焊进调度热路径（06）。
- **表述纪律**：不学 OpenHarmony"微内核宣传与架构脱节"（03）——BerryOS 文档始终如实描述内核形态与阶段（关卡 G0-G5 纪律正是制度性防御）。
