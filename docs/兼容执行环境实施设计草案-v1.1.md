### 0.1 三条设计公理

1. **纯洁 = 零生态语义，不是零新增代码。**
   内核可以长 S1–S4 这类通用机制；不能长 Linux syscall 表、Binder、ART、Android HAL、
   Wine、GPU 厂商 ioctl。评审问句：**换一个生态，内核要不要改？**
2. **通用能力 = 用户态可组合的执行环境原语。**
   `受限执行态 + 异常通道 + 命名空间/pager + VM/vCPU/stage-2/vGIC/IOMMU + Job/遥测`；
   它们同时服务插件沙箱、调试、容器、RT、安全隔离，不是兼容专用。
3. **性能/功耗最大化 = 按 workload 选底座，不是一招通吃。**
   CLI 不上 VM；APK 用 Android 整机（原生内核/框架）；Linux GUI/exe 用会话 microVM；
   低内存设备用单 Linux VM + 容器。一个 UI，多种 profile，策略在用户态。

### 0.2 最终裁决

| # | 裁决 | 理由 |
|---|---|---|
| D1 | 内核只加 S1–S4 + IOMMU/Job/遥测 | 纯洁 + 通用；生态语义全在用户态/访客 |
| D2 | T2 只做 Linux CLI，不做 APK/GUI | 无 GPU/Android 负担；CLI 近原生、最省电 |
| D3 | APK = T3-A Android 整机 guest | Android 自己的内核/框架/Binder/SELinux；gfxstream 解决单 GPU |
| D4 | Linux GUI/exe = T3-L 会话 microVM | 按会话起停；Venus/native GPU；Hangover/FEX 跑 exe |
| D5 | 6GB 设备 = T3-U 单 Linux VM + 容器 | WSL2/Waydroid 形；内存最省；兼容/隔离弱一档 |
| D6 | VMM 不自研：crosvm/libkrun 打底 | crosvm 同时跑 ARCVM/Crostini；多 hypervisor；gfxstream |
| D7 | 手机不追单 GPU 直通 | 宿主自己要用 GPU；gfxstream/Venus/厂商虚拟化是正路 |
| D8 | 省电靠冻结/快照/推送代理 | 常驻 Android VM 是待机灾难；没有魔法 |

### 0.3 被排除的选项

| 选项 | 为什么排除 |
|---|---|
| **Asterinas 式 Linux-ABI 内核** | 兼容/性能最强，但内核变 Linux，违反“微内核纯洁”；除非改身份 |
| **T2 APK** | 要么用户态重写 Android/GPU（工作量不亚于 T3，性能更低），要么内核沾 Android 语义 |
| **手机单 GPU 直通** | 宿主自己没 GPU；只能 gfxstream/Venus/厂商 GPU 虚拟化 |
| **常驻 Android VM** | 待机灾难；必须冻结/快照 + 宿主推送代理 |
| **Microdroid/AVF 跑 APK UI** | 官方明确不支持 Graphics/UI；只做安全旁路 |
| **一个万能容器/monolith** | 三个生态的 bug 和维护税相乘 |
| **gVisor 跑 APK** | GPU 支持目前 NVIDIA 专用，移动 GPU 无；且无 Android 框架 |
| **WASI/unikernel 跑存量** | 面向新应用/单应用 VM，不解决 APK/exe 二进制 |

### 0.4 成功判据

> 内核换生态不改；同一 `compatd` 按 profile 拉起 T2/T3-A/T3-L/T3-U；
> 20 个 APK、10 个 Linux/exe、50 个 CLI 在同机基线上达到 §10 目标；
> 待机 ≤1.2× 原生 Android；所有“兼容/高效/省电”话术有数据。

## §1 总体架构

### 1.1 一个内核，四种底座

```
┌──────────────────────────────────────────────────────────────────┐
│ compatd / 商店 / 兼容矩阵 / 遥测 / 策略 / 更新 / 用户 UI           │
├────────────────┬────────────────┬────────────────┬───────────────┤
│ T2 CLI         │ T3-L Linux     │ T3-A Android   │ T3-U 低内存    │
│ 用户态 ABI     │ 会话 microVM   │ 整机 Android   │ 单 Linux VM    │
│ 无 VM          │ muvm 形        │ ARCVM 形       │ WSL2 形        │
│ Starnix 形     │ Venus/native   │ gfxstream      │ 容器 + Wine    │
├────────────────┴────────────────┴────────────────┴───────────────┤
│ VMM/GPU：crosvm / libkrun · gfxstream / Venus / native context    │
│ Hypervisor：KVM / Gunyah / GenieZone / Halla / pKVM 或 BerryOS S4 │
├──────────────────────────────────────────────────────────────────┤
│ BerryOS 微内核：S1–S4 + IOMMU/Job/遥测（零生态语义）               │
└──────────────────────────────────────────────────────────────────┘
```

### 1.2 各 Profile 的职责

| Profile | 跑什么 | guest/形态 | GPU | 生命周期 | 性能/功耗定位 |
|---|---|---|---|---|---|
| **T2** | Linux CLI | 无 VM；受限线程 + syscall tap | 无 | 进程/Job | CLI 近原生；最省电 |
| **T3-A** | APK | Android 整机（AOSP/LineageOS） | gfxstream | 常驻/冻结 | APK 兼容/性能最优；内存大 |
| **T3-L** | Linux GUI/exe | Linux 会话 microVM | Venus/native | 按会话起停 | 启动快、隔离好；功耗中 |
| **T3-U** | APK + Linux | 一个 Linux VM + Android 容器 + Wine | guest Mesa/Venus | 常驻/冻结 | 内存最省；兼容/隔离弱一档 |

### 1.3 为什么不是“一个运行时”

- **APK 要 Android 的原生内核/框架**：Binder、zygote、SELinux、HAL、SurfaceFlinger 都在
  Android guest 里最顺；塞进 Linux 容器会多一层 binder/ashmem/gralloc 适配，兼容/性能都受损。
- **Linux GUI/exe 要 GPU/显示**：T2 做不了 GPU（要么重写 Linux DRM/厂商 ABI，要么污染内核）；
  常驻大 Linux 又浪费内存/启动；会话 microVM 是折中。
- **低内存设备要退路**：T3-A + T3-L 在 6GB 上太紧；T3-U 用共享 Linux 内核换内存。
- **一个 runtime 全包** = 把三种取舍强行统一，最后在每个场景都不是最优。

### 1.4 Profile 选择矩阵

| 设备/场景 | CLI | Linux GUI/exe | APK | 备注 |
|---|---|---|---|---|
| 6GB 手机 | T2 | T3-U | T3-U | 单 Linux VM + 容器；冻结 |
| 8GB 手机 | T2 | T3-L | T3-A | 默认；同一时间一个前台 |
| 12GB+ 手机 | T2 | T3-L | T3-A | 性能档；可并行更多 |
| PC x86 | T2/原生 | T3-L 或原生 | T3-A | dGPU 可选 passthrough |
| PC ARM | T2 | T3-L | T3-A | exe 走 Hangover/FEX |
| 工业/无 GUI | T2 | — | — | CLI/服务；不装 VM |

选择规则：
1. 无 GPU/无 Android → T2；
2. 有 APK → RAM ≥8GB 用 T3-A，否则 T3-U；
3. Linux GUI/exe → RAM ≥8GB 用 T3-L，否则 T3-U；
4. 同一时间只让一个重 profile 前台，其余冻结；
5. 用户可在“性能/省电”曲线里调，默认平衡。

### 1.5 产品分层话术

| 标签 | 含义 | 对外话术 |
|---|---|---|
| Native | 原生 BerryOS 应用 | 原生 |
| T2 | Linux CLI 兼容 | 兼容（轻量） |
| T3-A | Android 整机兼容 | 兼容（Android 应用） |
| T3-L | Linux GUI/exe 会话兼容 | 兼容（桌面应用） |
| T3-U | 低内存兼容 | 兼容（省内存） |
| Experimental | Wine/驱动/未验证 | 实验 |

**禁止**：没有同机基线就说“原生级/零损耗/所有应用都能跑”。

### 2.2 S1 受限执行态（最关键、最小）

#### 状态机

```
Normal ──thread_set_foreign──> ForeignReady
ForeignReady ──svc──> ForeignRequest ──wake runner──> ForeignBlocked
ForeignBlocked ──thread_foreign_resume──> ForeignReady
ForeignReady ──thread_clear_foreign──> Normal
任意态 ──线程退出/被杀──> Dead（容器死，内核无恙）
```

#### 运行形状

- **线程级**：同一进程可有 Normal 线程（运行时）与 Foreign 线程（Linux 二进制）。
- 内核在 SVC 入口**先查 `Thread.foreign`**：
  - Normal：现有 berry 派发，零改动；
  - Foreign：保存 x0–x7/PC/SP/SPSR 到内核私有帧，把请求写到共享页，置 `REQUEST`，
    唤醒 runner；本线程阻塞；
  - runner 在 Normal 态收请求，读共享页，执行 Linux 语义（可再调 berry syscall），
    写回结果，调 `thread_foreign_resume`；内核恢复寄存器，`eret` 回 EL0。
- **两种部署**：
  - **Isolated（默认，沙箱）**：runner 独立进程；Foreign 线程在另一地址空间；
    共享页对 Foreign 线程**只读**；runner 崩 = 容器死，内核无恙。
  - **InProcess（快模式，仅受信工具）**：同进程；共享页可写；无安全边界；
    manifest `trusted=true` 才允许，**不得默认开启**。
- **快路径**：每容器一个专用 runner 线程，与 Foreign 线程同核绑定；
  SVC 入口直接切 runner（seL4 direct-switch 形）；稳态避免全局调度器。
  批量/合并留 S1-b（先通后优）。
- **撞号**：Linux 与 berry 都用 `svc #0`；不改 immediate，按线程人格解释（§11.6）。

#### 不变量（ktest 逐条钉）

1. Foreign 线程**永远不能**走 berry 派发；x0 伪造合法 berry 号也只能转发。
2. `Thread.foreign` 只能由内核在 set/clear 中改；用户态写内存/共享页不能改。
3. Isolated 下共享页对 Foreign 线程只读；内核只从 trap frame 取寄存器，不信任共享页。
4. trap 路径**零分配、零 copy_from_user、零持锁睡眠**；锁在唤醒 runner 前收口。
5. runner 死/端点关：Foreign 线程 `-EBADF`/被杀；容器整体回收，不影响其他容器。
6. Native 线程行为与未启用 S1 时逐位等价（空策略等价测试同款）。

#### 共享页布局（草案，cache-line 对齐）

| offset | 字段 | 方向 | 说明 |
|---|---|---|---|
| 0x000 | `seq` u32 / `state` u32 | 内核↔runner | seqlock；IDLE/REQUEST/RESULT/FAULT |
| 0x008 | `nr` u64 | 内核→runner | Linux syscall 号（x8） |
| 0x010 | `args[6]` u64 | 内核→runner | x0–x5 |
| 0x040 | `ret` i64 | runner→内核 | 返回值 |
| 0x048 | `pc/sp/spsr` u64 | 内核→runner | 现场 |
| 0x060 | `far/esr` u64 | 内核→runner | fault 现场 |
| 0x070 | `flags/tid/owner` u64 | 双向 | 版本、线程 id、容器 id |
| 0x080 | 保留到 0x100 | — | 未来扩展；未知位拒绝 |

#### 测试面

- `FRGN ok`：Foreign 线程 `write(1,"x",1)` 经 runner 回显；Native 金丝雀同时跑。
- 逃逸株：伪造 x0=`process_exit`；写共享页 `state`；直接 `svc` 到非转发入口；
  runner 被杀；均只死容器。
- 性能株：空 syscall p50/p99；同核 vs 异核；批量开关。

### 2.3 S2 异常通道

- **对象**：`ExceptionChannel`（每线程一个先做；进程级后加）。
- **创建**：`thread_create_exception_channel(thread, options, out)`；持 `MANAGE`；
  深度预分配（建议 8）；满时**杀线程并置 overflow 计数**（fail loud，不静默丢）。
- **消息**：`{thread handle, type, pc, sp, far, esr, regs[31], arch, flags}`；
  类型 = `FAULT`（EL0 abort）/ `TRAP`（BRK/UNDEF）/ `FPE` / `SIGNAL`（可选）。
- **消费**：`exception_recv`（阻塞/超时）；`exception_resume(thread, action)`：
  `CONTINUE`（重试/跳过）、`TERMINATE`、`SIGNAL`（交给 runner 合成）。
- **信号合成**：runner 映射 SIGSEGV/SIGBUS/SIGFPE/SIGTRAP；有 handler → 改 PC/栈 +
  `CONTINUE`；无 handler → `TERMINATE`。
- **打断阻塞 syscall**：线程进入可中断等待时，内核把 runner 的 `interrupt_event`
  挂入 `wait_many`；runner 置位 → 内核返回 `-EAGAIN`，runner 映射 `-EINTR`。
  不新增“信号”内核语义。
- **不变量**：满不阻塞 fault 路径；无通道/无人收 = 杀线程；通道只能 MANAGE 创建；
  跨进程收消息走 channel handle 迁移。
- **测试**：四类异常；handler 恢复；无 handler 死；阻塞 read 被打断；runner 崩；通道满。

### 2.4 S3 命名空间 + pager

- **命名空间**：`namespace_open(path)` 拿节点 handle；`namespace_mount(server, path)`
  把服务挂到路径；进程持 root handle，路径解析从 root 开始。
- **T2 使用**：runner 建私有 namespace：`/` = rootfs，`/proc`、`/sys`、`/dev` 由 runner
  生成只读视图；`/svc/fs` 等 berry 服务按需挂载。禁止 ambient path；
  `..`/symlink 逃逸由解析器逐段校验 + root handle 门控。
- **T3 使用**：访客 Linux 自带 namespace；宿主只需把 rootfs 镜像/9p/virtio-fs
  挂进访客，不需要宿主 namespace 参与 Android/Wine 语义。
- **pager**：0x21 已落；T2 的 demand paging/COW 用 pager 实现。
  **APK 的 COW 在 Android guest 内核内，不要求宿主 COW**；
  宿主 COW 只服务 T2 大进程 fork（S1-b）。
- **测试**：`SBX ok`——root 逃逸、`..` 逃逸、symlink 逃逸、mount 权限、只读视图；
  pager 缺页风暴 + 递归帽（沿用 G4 防线）。

### 2.5 S4 VM 面

#### 对象与操作（草案）

| 对象 | 操作 | 说明 |
|---|---|---|
| `Vm` | create/destroy；map/unmap memory slot；set dirty log | stage-2 地址空间；memslot ≤64 |
| `Vcpu` | create；set/get regs；run；inject irq；set vtimer offset | 一 vCPU 一线程；WFI 让出 |
| `Vgic` | create；inject；set active/priority；maintenance | GICv2 先（QEMU virt），GICv3 后（真机） |
| `Vtimer` | create；set offset；arm；read | CNTVOFF_EL2/CNTHCTL_EL2 |
| `IommuDomain` | create；map/unmap；attach/detach device；fault 读 | SMMUv3；GPU/设备直通 |

#### 关键约束

- **stage-2 只做映射，不做策略**；内存 slot 由 VMM 决定；脏页日志供快照/迁移。
- **vGIC 先 v2 后 v3**：QEMU virt 用 GICv2 先通；真机 GICv3 另刀，不在首刀混。
- **vtimer**：每 vCPU 一个 offset；guest 读 CNTVCT 看到虚拟时间；物理 IRQ 注入。
- **PSCI**：S4 在 EL2 捕获 `hvc/smc` 并 exit 给 VMM；VMM 处理 `CPU_ON/OFF`、
  `SYSTEM_OFF/RESET`；不把 PSCI 策略塞内核。
- **virtio 全在用户态**：queue 内存在 VMO；doorbell 用 Event；IRQ 用 `vcpu_inject_irq`；
  内核不含 virtio 设备语义。
- **IOMMU**：每设备一个 domain；只放行被授权 DMA VMO 的物理区间；fault 走异常通道。
  GPU 直通必须有 SMMU；没有 SMMU 不做直通。
- **快照/冻结**：stage-2 脏页 + vCPU 寄存器 + 设备状态；VMM 负责，内核只提供脏页日志。
- **首刀范围**：1 vCPU、GICv2、vtimer、stage-2、MMIO exit、PSCI、WFI；SMP/GPU/SMMU 后置。

#### 测试

- `VM ok`：最小 guest 打印后 PSCI shutdown；`VML ok`：Linux 内核启动到 console；
  `VMM ok`：virtio-blk/console/net/input 各一次往返；`GPU ok`：gfxstream/Venus 三角形；
  `PWR ok`：冻结/恢复 + 待机功耗。

### 2.6 Job/配额/遥测

- **Job 树**：每容器/VM 一个 Job；子进程/线程/通道/VMO 挂 Job 下；Job 死 → 子树回收。
- **quota**：CPU、内存、进程/线程数、fd、磁盘、网络带宽；超限 `-ENOMEM`/`-EBUSY`/`-EACCES`。
- **OOM**：Job 内选 victim（最大 RSS/最低 intent），杀进程并记遥测；不 panic。
- **冻结**：Job 级 freeze/thaw；T3 的 VM 冻结由 compatd 编排（VMM 收 freeze），
  内核只提供 Job 状态与调度门控。
- **遥测**：每 Job 的 syscall、缺页、IPC、VM exit、GPU 提交、帧时间、功耗代理；
  沿用现有遥测环，新增兼容维度计数器。
- **依赖**：T2 沙箱**必须先有 Job v2**；当前 `process_create job=0` 是已知豁口。

### 2.7 反垃圾合同（内核准入清单）

**允许进内核**（且必须通用）：

- 能力/handle、channel、VMO/Vmar、pager、异常通道、受限执行态、
  Vm/vCPU/stage-2/vGIC/vtimer、IommuDomain、Job/配额、遥测、IRQ/MMIO handle。

**禁止进内核**（出现即打回）：

- Linux syscall 号/结构体/errno 语义、`/proc` `/sys` 内容、bionic/ART/Binder/ashmem、
  Android property/SELinux/HAL、Wine/Win32/PE、GPU 厂商 ioctl、文件系统格式、
  网络协议栈、设备树解析策略、任何“生态 if”。

**评审问句**：这个改动换一个生态还要不要？要 → 用户态；不要 → 才配进内核。

### 2.8 内核预算（量级）

| 件 | 量级 | 备注 |
|---|---|---|
| S1 | 1–2k 行 | 人格状态/共享页/入口 |
| S2 | 0.5–1k 行 | 异常通道/恢复 |
| S3 | 1–2k 行 | namespace/pager 扩展 |
| S4 | 10–20k 行 | vCPU/stage-2/vGIC/vtimer/IOMMU；可借厂商 hypervisor 降载 |
| Job/遥测 | 1–2k 行 | 复用现有 |

> 若 S4 超出预算：优先用厂商 hypervisor（Gunyah/GenieZone/Halla/pKVM）或 crosvm 的多后端；
> 不要为“纯自研”把主线拖死。

## §3 T2：Linux CLI

### 3.1 进程模型

- 每容器一个 runner 进程（Isolated）；内部一个调度线程 + Foreign 执行线程池。
- Foreign 线程由 runner 经 `process_create`/`thread_create` 创建；入口是 Linux ELF。
- runner 持容器能力：namespace root、fs 端点、net 端点、console、Job；
  **不持** GPU/Android/宿主管理能力。
- 崩溃语义：runner 死 = 容器死；Job 回收；compatd 重启。

### 3.2 syscall 覆盖（三级，不按号数刷）

| 层 | 内容 | 验收 |
|---|---|---|
| T0 启动 | `read/write/openat/close/fstat/mmap/mprotect/munmap/brk/exit/exit_group/clock_gettime/getpid/getuid/rt_sigaction/rt_sigprocmask/set_tid_address/set_robust_list/execve` | `LNX ok`（busybox） |
| T1 CLI | `fork/vfork/clone/wait4/pipe2/dup3/fcntl/ioctl/getdents64/statx/readlinkat/unlinkat/renameat2/mkdirat/futex/epoll_*/ppoll/eventfd/timerfd/socket/connect/getsockname/getrandom` | `GCC ok` + 50 工具 |
| T2 长尾 | `io_uring`（可拒）/`netlink`/`inotify`/`fanotify`/`ptrace`（受信）/`seccomp`/`prctl`/`sched_*` | 现探现补，矩阵记录 |

- 未实现号返回 `-ENOSYS`（Linux 语义），**不是** `-ENOTSUP`；runner 记 trace。
- 参数校验：用户指针界检；不信任 Linux 结构体布局；按目标 arch 的 ABI 抄。
- `svc` 撞号：内核按线程人格截流；runner 正常态发 berry syscall（§11.6）。

### 3.3 fd/信号/fork/epoll//proc/loader

- **fd 表**：runner 自管 Linux fd → berry handle/服务会话映射；`dup/dup2/fcntl` 只改映射；
  `close` 释放；`fork` 复制表（或共享 + 引用计数）。
- **信号**：S2 异常通道 + runner 合成；`rt_sigaction`/`rt_sigprocmask` 在 runner；
  阻塞 syscall 用 `interrupt_event` 打断。
- **fork**：`process_create` + VMO 复制 + 寄存器弹床；首版整副本（CLI 可接受），
  S1-b 引入 COW（pager 写时复制）；`vfork/posix_spawn` 快路径。
- **epoll**：runner 侧聚合器；`wait_many` n≤16 分批；大量 fd 用轮询线程 + 就绪缓存；
  必要时扩 `wait_many` 上限或加通用 `WaitSet`（S3 扩展，不在首刀）。
- **/proc /sys**：runner 生成只读视图（cpuinfo/meminfo/self/status/mounts）；
  不真实暴露宿主；足够 glibc/coreutils 启动；矩阵记录不兼容项。
- **loader**：静态 ELF 先通；动态 glibc 需 `ld.so` + TLS + `auxv` + `vDSO` 桩；
  `GCC ok` 是自举闭环，不是终点。

### 3.4 沙箱

- Isolated 默认；runner 独立进程；Foreign 线程独立 AS；内核强制人格；共享页只读。
- 能力最小化：每容器 namespace root + 指定服务端点；不继承 compatd 管理能力。
- Job/配额：CPU/内存/进程/fd/磁盘/网络；fork 炸弹/磁盘填充/内存耗尽有上限。
- 过滤：runner 可对 Linux syscall 做 allow/deny（策略来自 manifest）；不依赖内核 seccomp。
- 逃逸测试：直接 SVC、改共享页、ptrace runner、继承 fd、`/proc` 逃逸、mount 逃逸。
- **诚实边界**：InProcess 模式没有沙箱；只用于系统自带/签名工具。

### 3.5 快路径/性能

- 同核专用 runner 线程；SVC 直接切；共享页 seqlock；无锁/无分配 trap。
- 常见 syscall（read/write/clock/getpid/futex）走短路径；fs/net 才跨服务。
- 批量：`readv/writev`、`sendmmsg`、`epoll_wait` 一次多事件；首版不引入 `io_uring`。
- 目标：空 syscall p50 <2µs / p99 <10µs（真机标定）；`git status` ≤1.5×；
  `gcc -O2` ≤1.3×；启动 ≤50ms；内存 ≤30MB/容器。

### 3.6 边界

- 只做 CLI/headless；不做 GPU/Android/Wine。
- 需要 GUI/GPU 的 Linux 程序 → T3-L；需要 APK → T3-A/T3-U。
- T2 不承诺“所有 Linux 程序”；矩阵内 50 个 CLI 是首批目标。

### 3.7 验收

`FRGN ok` → `LNX ok` → `GCC ok` → `SBX ok`；50 个真实 CLI 通过率 ≥70% 才继续扩。

## §4 T3-A：APK 的 Android 整机

### 4.1 guest 形态

- **guest = Android**（AOSP 或 LineageOS 类），不是“Linux + Android 容器”。
- 内核/用户态：Android Common Kernel + Android framework + Binder/zygote/SELinux/SurfaceFlinger。
- 镜像：system/vendor 分开；无 GMS；预装最小 WebView；APK 安装走签名校验。
- 版本：Android 大版本 + 安全补丁；独立于 BerryOS 更新；可回滚。
- 许可：AOSP Apache/BSD；vendor blob 单独合规；不含 Play 服务。

### 4.2 VMM/设备

- VMM 首选 **crosvm**：ChromeOS 的 ARCVM/Crostini/TerminalApp 实证；Rust；BSD-3；
  多 hypervisor（KVM/Gunyah/GenieZone/Halla）；virtio-gpu 2D/3D（virglrenderer/gfxstream/vulkano）。
- 设备：virtio-blk/fs/console/net/vsock/input/snd/gpu；PSCI；DTB 由 VMM 生成。
- 网络：NAT/桥接；每 app 网络策略；DNS；不暴露宿主服务。
- 存储：system/vendor/data 分盘；data 加密；快照/回滚。
- 显示：guest SurfaceFlinger → gfxstream/virtio-gpu → 宿主合成；零拷贝 buffer；vsync 透传。
- 输入/音频：virtio-input/virtio-snd；宿主 inputd/audiod 后端；低延迟线程。
- 摄像头/传感器/电话：首版不做；矩阵标“不支持”；后续宿主 RIL/相机桥另立 ADR。

### 4.3 GPU：gfxstream

- **gfxstream** 把 GLES/Vulkan 命令从 guest 流式转发到宿主 GPU；
  不需要把手机唯一 GPU 直通给 guest；宿主 UI 仍可用 GPU。
- 优点：单 GPU 可行；兼容 Android GLES/Vulkan 栈；Cuttlefish/Android 虚拟设备验证。
- 代价：命令流/序列化开销；性能 50–95% 视负载；游戏低于 UI。
- 备选：厂商 GPU 虚拟化（SR-IOV/厂商 hypervisor）→ 接近原生；需 SoC 合作。
- **禁止**：手机单 GPU 直通（宿主失去 GPU）；PC 第二块 dGPU 才可 passthrough。

### 4.4 生命周期/省电

| 态 | 行为 |
|---|---|
| `PREPARED` | 加载镜像/内核，不跑；内存预留可回收 |
| `RUNNING` | 前台 APK；vCPU 绑 1–2 核；gfxstream/显示/音频接通 |
| `FROZEN` | 无前台 N 分钟；vCPU 停、设备停、balloon；待机接近宿主 |
| `SNAPSHOT` | 冻结到磁盘/RAM；恢复 300–800ms；zygote 预热 |
| `STOPPED` | 用户退出；释放内存；data 保留 |

- **推送代理**：宿主侧保持网络；通知只唤醒宿主 UI，不唤醒 guest；用户点开才恢复。
- **禁止常驻后台**：Android 后台服务/JobScheduler/wakelock 必须被策略限制；
  默认只允许前台 + 用户白名单。
- 目标：待机 ≤1.2× 同机原生 Android；前台 UI/视频 ≤1.1×；冷启 ≤1.5×/800ms；
  jank ≤1.5×；内存 guest ≤3GB、总 ≤4GB（待真机标定）。

### 4.5 兼容边界

- **能跑**：大多数 UI/2D/普通 3D 应用；无 GMS 依赖的国内应用优先。
- **可能跑不了**：Play Integrity/银行/支付风控、游戏反作弊、Widevine L1、
  依赖 GMS/Google 登录、依赖电话/短信/摄像头/传感器的应用。
- **不承诺**：所有 APK；只承诺矩阵内 100 个应用。
- 失败分类：GPU、Binder、SELinux、services、attestation、DRM、anti-cheat、input、
  audio、network、crash、perf、unsupported-syscall、other。

### 4.6 安全

- VM 边界 + stage-2；设备直通走 SMMU；virtio/gfxstream 设备模型 fuzz。
- Android guest 内 SELinux + app sandbox；宿主不挂载用户 home；网络默认 NAT。
- gfxstream 把命令交给宿主 GPU 驱动，宿主驱动是攻击面；不暴露原始 GPU ioctl；
  对 guest 命令做白名单/边界检查。
- 不承诺绕过 Play Integrity/DRM/反作弊；检测是产品边界，不是技术 bug。

### 4.7 验收

`VM ok` → `VML ok`（Android 内核启动）→ `VMM ok`（设备）→ `GPU ok`（gfxstream 三角形）
→ `APK ok n=20`（20 个应用矩阵）→ `PWR ok`（冻结待机）。

## §5 T3-L：Linux GUI/exe 的会话 microVM

### 5.1 会话模型

- **按会话起 microVM**：打开 Linux GUI/exe 时起一个 microVM；窗口全关后冻结/销毁。
- 一个 microVM 内可跑多个 GUI 程序（muvm 的 guest server 形）；
  不是“每个应用一个 VM”（太重），也不是“常驻一个大 Linux”（太费）。
- 根文件系统走 `virtio-fs`/9p 共享，宿主只读 base + 每会话 overlay；
  用户数据独立盘；快照/恢复。
- 内存按需分配 + balloon + free page reporting；CPU 绑性能核（前台）或能效核（后台）。

### 5.2 VMM/rootfs

- VMM 首选 crosvm（与 T3-A 共用设备模型）；轻量备选 libkrun/muvm（更小、嵌入形态）。
- guest 内核：标准 Linux + virtio（blk/fs/net/input/snd/gpu/vsock）；
  不需要 Android binder/ashmem。
- rootfs：Debian/Ubuntu slim（glibc）或自定义最小根；Wine/Wayland/X11 按需；
  与 T2 共用同一套 CLI 包（T2 跑子集，T3-L 跑全量）。
- 启动：冷启 1–3s；snapshot 300–800ms；桌面会话可预热。

### 5.3 GPU/显示/输入/音频

- **GPU**：virtio-gpu + Venus（Vulkan）/virglrenderer（GL）；或 native context
  （libkrun/muvm 形，适合需要 4K 页/低开销的游戏）；PC dGPU 可 passthrough。
- **显示**：guest Wayland/X11 → virtio-gpu → 宿主合成；零拷贝 dma-buf/fence；
  vsync/frame timing 透传；全屏可直扫。
- **输入**：virtio-input/宿主 inputd 注入；触摸/键盘/鼠标；焦点归宿主 compositor。
- **音频**：virtio-snd 或宿主 audiod；低延迟线程；不经过 VMM 大锁。

### 5.4 exe：Wine / Hangover / FEX

| 场景 | 方案 | 说明 |
|---|---|---|
| PC x86 | 原生 Wine | x86 不需要 ISA 翻译；DXVK/Proton；反作弊/内核驱动不支持 |
| PC ARM | Wine + FEX/Box64 | 50–80% 性能；轻量工具/部分游戏 |
| 手机 ARM | **Hangover** + FEX | 只模拟 Windows 应用，Win32/Wine 边界跳出；非模拟部分近原生 |
| 手机 ARM 备选 | Wine + FEX/Box64 | 整栈模拟，性能更低；仅作 fallback |

- Hangover 的要点：模拟器只覆盖应用本身；一旦进入 Win32/Wine syscall，
  就在原生 ARM64 上执行；ARM64EC + FEX；不需要 32 位 Unix 库。
- 目标应用：老式 Win32 工具、纯 CPU 小软件、部分 GDI/游戏；不承诺 Office/Adobe/3A/反作弊。
- 手机 exe 是长尾，不是主卖点；重 Windows 应用走 PC 或云串流。

### 5.5 生命周期/省电

| 态 | 行为 |
|---|---|
| `STARTING` | 起 microVM，挂 rootfs/overlay，预热 |
| `RUNNING` | 前台窗口；GPU/音频接通；CPU 性能核 |
| `FROZEN` | 窗口最小化/无焦点 N 分钟；vCPU 停，内存可 balloon |
| `SNAPSHOT` | 保存会话；下次 300–800ms 恢复 |
| `STOPPED` | 窗口全关；销毁；数据盘保留 |

- 同一时间只让一个重 profile 前台；T3-A 与 T3-L 互斥/冻结。
- 目标：冷启 ≤1.5s；snapshot ≤800ms；UI 80–95%；GPU 50–80%；内存 0.5–1GB；
  空闲接近宿主。

### 5.6 边界

- 不做 Android；不做电话/摄像头/传感器。
- 不做“所有 Linux GUI”；先支持 Wayland/X11 常见工具、Wine 目标列表。
- 不做“Wine 全兼容”；反作弊/内核驱动/DRM 是产品边界。

### 5.7 验收

`VML ok`（Linux guest）→ `VMM ok`（virtio/GPU）→ `GPU ok`（Venus/native 三角形）
→ `WINE ok`（notepad + 一个真实应用）→ `PWR ok`（冻结/恢复）。

## §6 T3-U：低内存 fallback

### 6.1 WSL2/Waydroid 形

- **一个 Linux utility VM** 跑标准 Linux 内核；Android 作为容器（binder/ashmem/
  namespaces/SELinux）；Wine 直接跑在同一 Linux 里。
- 这是 WSL2（轻量 utility VM + 容器）与 Waydroid（Linux namespace 容器）的组合。
- 优点：一个内核、内存最省；Linux/Wine 共享；Android 容器成熟度尚可。
- 缺点：Android 容器需要 binder/ashmem/gralloc/SELinux 适配；隔离弱于 T3-A；
  gfxstream 在容器里更难，GPU 多用 guest Mesa/Venus；兼容性低于 T3-A。

### 6.2 何时用

- 6GB 及以下手机；内存优先于兼容性。
- 低端 PC/ARM 板；只跑轻量 APK + Linux 工具。
- 作为 T3-A/T3-L 的降级路径：启动失败/内存不足时切换。

### 6.3 代价

- APK 兼容性：T3-A > T3-U；游戏/DRM/反作弊更差。
- 隔离：VM + 容器，但 Android 与 Linux 共享内核；一个内核漏洞影响两边。
- 更新：Linux 内核/Android 容器/Wine 三者版本耦合；矩阵要更细。
- 性能：容器开销低，但 Android 图形栈不如整机 guest 顺。

### 6.4 验收

`VML ok`（Linux utility VM）→ `APK ok n=`（容器内 10 个应用）→ `WINE ok`
→ `PWR ok`；内存基线 ≤ T3-A 的 60%。

## §7 VMM/GPU/Hypervisor

### 7.1 crosvm vs libkrun

| 维度 | crosvm | libkrun |
|---|---|---|
| 语言/许可 | Rust / BSD-3 | Rust + C API / 许可以仓库为准 |
| 定位 | ChromeOS VMM；ARCVM/Crostini/TerminalApp | 可嵌入 VMM 库；muvm/krunkit |
| Hypervisor | KVM/Gunyah/GenieZone/Halla | KVM/HVF/WHP |
| virtio-gpu | 2D/3D：virglrenderer/gfxstream/vulkano | Venus/native context |
| Android guest | ✅（ARCVM/Cuttlefish） | 非主目标 |
| Linux guest | ✅（Crostini） | ✅（muvm） |
| 体量/移植 | 大；Linux 沙箱/minijail 重 | 小；易嵌入 |
| 建议 | **T3-A 首选；T3-L 可共用** | **T3-L 轻量备选/参考** |

> 许可以仓库 LICENSE 为准；本文不替代合规审计。

### 7.2 多 hypervisor / 厂商虚拟化

- crosvm 已支持 KVM/Gunyah/GenieZone/Halla；手机 SoC 若有厂商 hypervisor，
  优先借它，省掉 S4 的 10–20k 行。
- pKVM/AVF 是 Android 的保护 VM 路线；适合安全旁路，不是 APK UI 主路。
- 若厂商 hypervisor 不对第三方 OS 开放：回退 BerryOS S4（EL2/stage-2/vGIC/vtimer/SMMU）。
- **决策门**：M4 前做厂商接口可行性；不可行就按 S4 排期，不赌。

### 7.3 GPU 模式矩阵

| 模式 | 手机 | PC | 性能 | 宿主 UI | 用在哪 |
|---|---|---|---|---|---|
| **gfxstream** | ✅ 单 GPU 可行 | ✅ | 50–95% | 是 | T3-A Android |
| **Venus/virgl** | ✅ | ✅ | 50–80% | 是 | T3-L Linux |
| **native context** | ✅（libkrun/muvm） | ✅ | 更高 | 是 | T3-L 游戏/低开销 |
| **passthrough** | 通常不可（单 GPU） | ✅ dGPU | 原生 | PC 是 | PC 游戏/重载 |
| **software** | ✅ | ✅ | 低 | 是 | 2D/CI/兜底 |

- 手机默认 gfxstream/Venus；厂商 GPU 虚拟化时才谈“接近原生”。
- 不为“直通”牺牲宿主 UI；PC 第二块 GPU 例外。

### 7.4 显示/输入/音频

- 宿主 compositor 是唯一显示主人；guest 渲染到 buffer；零拷贝 dma-buf/fence。
- vsync/frame timing 透传；guest 的 present 与宿主合成对齐；避免多一帧。
- 输入走宿主 inputd；焦点/命中归 compositor；guest 只收事件。
- 音频走 virtio-snd/宿主 audiod；实时线程；避免 VMM 锁。
- 全屏 guest 可直扫（direct scanout）；窗口态走合成。

### 7.5 快照/冻结

- 需要：vCPU 寄存器、stage-2 脏页、设备状态（virtio queue/irq）、显示/音频状态。
- VMM 负责保存/恢复；内核只提供脏页日志和 vCPU 状态。
- 目标：T3-A 恢复 300–800ms；T3-L 300–800ms；失败回退冷启，矩阵记一次。
- 快照要版本化；guest 内核/镜像升级后旧快照失效。

### 7.6 移植到 BerryOS S4

- 先在 Linux/KVM 上跑通 crosvm/libkrun + guest + gfxstream/Venus；
  再把 VMM 的 hypervisor 后端换成 BerryOS S4。
- 需要 S4 提供：vCPU run/exit、stage-2 map/unmap/dirty、vGIC inject、
  vtimer offset、PSCI 捕获、MMIO exit、IRQ 注入、SMMU domain。
- VMM 的 virtio/gfxstream/显示/输入/音频代码尽量不改；只换后端。
- 如果 crosvm 的 Linux 沙箱层太重：只借设备模型/gfxstream，VMM 自研薄壳；
  或直接用 libkrun 的嵌入形态。

## §8 Profile 策略与功耗

### 8.1 选择矩阵

| 设备 | 默认 | APK | Linux GUI/exe | CLI |
|---|---|---|---|---|
| 6GB 手机 | T3-U | T3-U | T3-U | T2 |
| 8GB 手机 | T3-A + T3-L | T3-A | T3-L | T2 |
| 12GB+ 手机 | T3-A + T3-L | T3-A | T3-L | T2 |
| PC x86 | T3-A + T3-L | T3-A | T3-L/原生 | T2/原生 |
| PC ARM | T3-A + T3-L | T3-A | T3-L | T2 |
| 无 GUI 设备 | T2 | — | — | T2 |

### 8.2 前台/后台/冻结

- 同一时间只让一个重 profile 前台；另一个 FROZEN。
- T3-A 常驻但冻结；通知走宿主代理；用户点开才恢复。
- T3-L 窗口全关 → SNAPSHOT/STOPPED；不保留空转 Linux。
- T2 无 VM；空闲阻塞，不轮询。
- Job 级 freeze/thaw；PM governor 协调 CPU/GPU/显示。

### 8.3 CPU/GPU/热

- vCPU 绑核：前台绑性能核；后台绑能效核；避免与宿主关键线程抢核。
- big.LITTLE：重载上大核，轻载上小核；热阈值触发降频/迁移。
- GPU：gfxstream/Venus 有 CPU 序列化开销；空闲时停 GPU；显示自刷新。
- 热：Android VM 游戏是热源；温度墙触发降帧/降分辨率；矩阵记录。

### 8.4 功耗目标（待真机标定）

| 场景 | 目标（相对同机原生 Android） |
|---|---|
| T3-A 待机（FROZEN） | ≤1.2× |
| T3-A 前台 UI/视频 | ≤1.1× |
| T3-A 游戏 | ≤1.3× |
| T3-L 空闲（STOPPED/FROZEN） | 接近宿主 |
| T3-L 前台 UI | ≤1.2× |
| T2 CLI | 接近原生 Linux |
| 冷启/恢复 | ≤1.5× / ≤800ms |

### 8.5 性能/省电曲线

- 提供“性能/平衡/省电”三档：
  - 性能：VM 常热、vCPU 多、GPU 高帧；
  - 平衡：前台热、后台冻结；
  - 省电：按需起 VM、快照恢复、限制后台。
- 三档都用同一 profile；区别是生命周期/配额/频率，不是内核分支。

## §9 安全

### 9.1 威胁模型

| 威胁 | 边界 | 防线 |
|---|---|---|
| 恶意 Linux 二进制 | T2 runner | 独立进程/AS + 内核强制人格 + 能力最小化 + Job 配额 + 逃逸测试 |
| 恶意 APK | T3-A VM + Android sandbox | stage-2 + SELinux + SMMU + gfxstream 校验 + 矩阵 |
| 恶意 exe | T3-L VM + Wine prefix | VM 边界 + prefix 隔离 + 不直通宿主 fs |
| 被攻破的 guest | T3 | SMMU + virtio 校验 + 最小设备模型 + 不共享宿主 GPU 驱动 |
| 被攻破的 VMM | 宿主用户态 | 最小权限 + Job + 崩溃隔离；VMM 是 TCB，需审计 |
| DoS | Job | 配额 + OOM victim + 速率限制 |
| 侧信道 | 共享硬件 | 不承诺完全消除；敏感场景不共享核/缓存 |

### 9.2 T2 边界

- 内核/runner 是 TCB；Foreign 线程不可信；InProcess 只给受信工具。
- 能力最小化 + namespace + Job + 过滤；逃逸测试进 CI。
- 诚实：InProcess 没有沙箱；manifest 标 `trusted=true`。

### 9.3 T3 边界

- 内核/VMM 是 TCB；guest 不可信；Android guest 内 SELinux 是第二边界。
- 设备直通必须 SMMU；没有 SMMU 不做直通。
- virtio/gfxstream 设备模型 fuzz；MMIO/描述符越界 fail loud。
- 宿主不挂载用户 home；网络默认 NAT；数据盘加密。

### 9.4 GPU/gfxstream

- gfxstream 把命令流交给宿主 GPU 驱动；宿主驱动是攻击面。
- 不暴露原始 GPU ioctl；命令白名单/边界检查；guest 不能直接 DMA 宿主内存。
- passthrough 才用 SMMU；gfxstream 不需要设备直通，但需要严格的命令校验。
- 安全不等于性能；gfxstream 的隔离弱于 passthrough，强于“直接把 GPU 给 guest”。

### 9.5 pKVM/AVF 安全旁路

- AVF/pKVM 提供 protected VM；Microdroid 是 mini-Android；官方明确**不支持 Graphics/UI**。
- 用途：敏感原生计算、密钥、支付风控等；**不是 APK UI 主路**。
- 若未来需要“安全兼容”，可把敏感 workload 放 pVM；UI 仍走 T3-A。

### 9.6 逃逸测试（必须进 CI）

- T2：直接 SVC、改共享页、ptrace runner、继承 fd、`/proc` 逃逸、mount 逃逸、
  `..`/symlink、fork 炸弹、磁盘填充、内存耗尽、网络扫描。
- T3：virtio 畸形 descriptor、MMIO 越界、PSCI 非法参数、stage-2 越界、SMMU fault、
  gfxstream 命令注入、guest 内核 CVE 样本（受控）。
- 结果：只死容器/VM；宿主无 panic；遥测留痕；矩阵记 failure_class。

### 9.7 不解决（诚实清单）

- Play Integrity/SafetyNet、银行/支付风控、游戏反作弊、Widevine L1；
- 厂商 GPU 驱动 blob 的漏洞/许可；
- 侧信道（Spectre 类）不承诺完全隔离；
- VM/容器可被检测；不提供“反检测”；
- 电话/短信/摄像头/传感器首版不支持。

## §11 ABI/协议

### 11.1 新增对象/操作（编号待定）

> 只列语义；`abi.toml` 立项时按现有编号段分配。未知位拒绝、出参预清零、no-panic 照旧。

| 域 | 操作（草案） | 说明 |
|---|---|---|
| S1 | `thread_set_foreign(thread, runner_end, shared_vmo, flags)` | 启动前；持 MANAGE |
| S1 | `thread_foreign_resume(thread, ret, flags)` | runner 回写；内核校验状态 |
| S1 | `thread_clear_foreign(thread)` | 回 Normal；仅 MANAGE |
| S2 | `thread_create_exception_channel(thread, options, out)` | 0x41 在册；语义细化 |
| S2 | `exception_recv` / `exception_resume` | 可复用 channel；专用 op 可选 |
| S3 | `namespace_open` / `namespace_mount` | 0x81/0x82；v3 |
| S4 | `vm_create/destroy`；`vm_map/unmap`；`vm_set_dirty` | memslot ≤64 |
| S4 | `vcpu_create/destroy`；`vcpu_regs`；`vcpu_run`；`vcpu_inject_irq` | 一 vCPU 一线程 |
| S4 | `vgic_create/inject`；`vtimer_create/set` | 先 v2 后 v3 |
| S4 | `iommu_domain_create`；`iommu_map/unmap`；`iommu_attach` | SMMUv3 |
| 支撑 | `job_create`；`job_set_quota`；`job_kill`；`job_stats` | Job v2 |
| 支撑 | `telemetry_open` / 兼容计数器 | 现有遥测扩展 |

### 11.2 S1 共享页

- 见 §2.2；整页 4KiB，前 0x100 使用，其余保留零。
- Isolated：Foreign 只读；runner 读写；内核只写 trap 帧。
- InProcess：双方读写；无安全边界；`trusted=true` 才允许。
- 版本：`flags` 高 16 位版本，低 16 位特性；未知特性拒绝。

### 11.3 VM exit / PSCI / vGIC / vtimer

- **exit reason**：`MMIO`、`PSCI`、`WFI`、`IRQ`、`HYPERCALL`、`SHUTDOWN`、`FAIL`。
- **vGIC**：GICv2 首刀；LR/APR/EOI 维护；GICv3 另刀（ICC_* 系统寄存器）。
- **vtimer**：CNTVOFF_EL2/CNTHCTL_EL2；虚拟 IRQ；每 vCPU offset。
- **PSCI**：S4 捕获 `hvc/smc` 并 exit 给 VMM；`SYSTEM_OFF` → 停 VM；`CPU_ON` → 起 vCPU（SMP 后置）。
- **virtio**：queue 内存在 guest 内存（VMO）；doorbell 用 Event；IRQ 用 `vcpu_inject_irq`。

### 11.4 virtio/gfxstream/Venus

- virtio 设备在 VMM 用户态；内核不含设备语义。
- gfxstream：guest 侧 GLES/Vulkan → 命令流 → 宿主 GPU；VMM 负责通道/资源。
- Venus：virtio-gpu Vulkan 命令流；Linux guest 用 Mesa Venus；宿主 virglrenderer。
- native context：libkrun/muvm 形；更接近直通；按 SoC/驱动评估。
- 所有 GPU 资源走 dma-buf/fence；生命周期由 VMM 管；guest 不能直接拿宿主 GPU handle。

### 11.5 错误/版本

- 复用 `BERRY_ERR_*`：`-EINVAL`、`-EACCES`、`-EBADF`、`-EBUSY`、`-ENOMEM`、`-ENOTSUP`。
- 不轻易加新错误码；配额超限先用 `-EBUSY`/`-ENOMEM`，矩阵可区分。
- 结构体：`in_size/out_size`；未知尾部零；`offset_of!` 钉板；padding 清零。
- 版本：对象 `get_info` topic + 共享页/VM exit 结构版本；add-only。

### 11.6 `svc #0` 撞号（Q1 定谳）

- Linux 与 BerryOS 都用 `svc #0`；**不改 immediate**，按线程人格解释：
  - Normal：x0 = berry 号，现有派发；
  - Foreign：x8 = Linux 号，x0–x5 = 参数；内核截流，不查 berry 表。
- 人格由内核持有；`thread_set_foreign` 需 MANAGE；用户态不能写。
- 测试：Foreign 伪造 x0=0x33（process_exit）→ 只转发；Native x8 乱写 → 仍按 x0。
- 这避免 ABI 存量重编；代价是 S1 入口必须最早分支。

## §12 实施拆步

### 12.1 双线并行

- **T2 线**：M1→M2→M3→M4；不依赖 S4，可独立交付 CLI。
- **T3 线**：M5（Linux/KVM 兼容栈）→M6（S4/厂商）→M7（T3-A）→M8（T3-L）→M9（T3-U）。
- **先 Linux/KVM，后 BerryOS S4**：Android/Linux/GPU/Wine 的兼容面先在 Linux/KVM 上跑通，
  再换 S4 后端；S4 不阻塞兼容线。

### 12.2 M0–M9

| 步 | 时间 | 内容 | 验收 | 依赖 |
|---|---|---|---|---|
| **M0** | 2–4 周 | 规格冻结：本文 + ADR；profile 矩阵；VMM 选型；镜像基线；标记注册 | 评审过；CI 骨架 | 无 |
| **M1** | 2–3 月 | S1/S2 内核最小面：foreign 状态 + 共享页 + 异常通道 | `FRGN ok`；逃逸株全红 | M0 |
| **M2** | 3–4 月 | T2 runner v0：静态 ELF + T0 syscall + fd/loader | `LNX ok`（busybox） | M1 |
| **M3** | 4–6 月 | T2 CLI：T1 syscall + 信号 + epoll + /proc + fork | `GCC ok` + 50 工具 | M2 |
| **M4** | 3–4 月 | T2 沙箱：Job/配额/namespace + 逃逸测试 | `SBX ok`；逃逸 0 | M3 |
| **M5** | 4–6 月 | Linux/KVM 兼容栈 spike：crosvm + Android + gfxstream；crosvm/libkrun + Linux + Venus；20 APK + 10 Linux/exe | 数据表；VMM 选型 | M0 |
| **M6** | 4–6 月 | S4 最小面（或厂商 hypervisor）：vCPU/stage-2/vtimer/GICv2/PSCI | `VM ok`；`VML ok` | M5 |
| **M7** | 4–6 月 | virtio/显示/输入/音频/gfxstream/Venus；T3-A Android 产品 | `VMM ok`；`GPU ok`；`APK ok n=20` | M6 |

| **M9** | 3–6 月 | T3-U fallback + profile 策略 + 冻结/功耗 + 100 app 矩阵 | `PWR ok`；待机 ≤1.2× | M7/M8 |

### 12.3 关键路径

1. **M0 先定 VMM/GPU 路线**：crosvm 优先；libkrun 备选；厂商 hypervisor 可行性并行。
2. **M5 是 T3 的 gate**：gfxstream/Venus 性能不达标 → 改 profile/GPU 策略，不硬推。
3. **M6 用 S4 或厂商 hypervisor**；不可行就降级 T3-U/PC-only。
4. **M7/M8 可并行**：T3-A 与 T3-L 共用 VMM/显示，但 guest 镜像/Android 栈不同。
5. **M9 才做三 profile 合流**；不要一开始就做“大一统”。

### 12.4 kill criteria

| 线 | 触发 | 动作 |
|---|---|---|
| T2 | 50 工具通过率 <70%，或常用负载 >2×，连续两里程碑 | 冻结 T2 CLI，转 T3-L/T3-U；保留已落地面 |
| T3-A | 20 app 可用 <60%，或 gfxstream 帧 <50% | 切 T3-U 或 PC-only；不硬推手机 |
| T3-L | 10 应用 <60%，或冷启 >1.5s 且 snapshot 无效 | 退回 T3-U/单 Linux VM |
| VMM | crosvm 移植连续两周期 >20% 主线 | 换 libkrun/厂商 hypervisor 或 PC-only |
| S4 | 连续两周期 >20% 主线，或 M6 两轮不过 | 冻结 S4；T3 只留厂商 hypervisor/PC |
| 功耗 | 待机 >1.5× 原生，冻结优化无效 | 取消常驻，改按需 VM；矩阵标红 |
| 内核 | 反垃圾合同出现违反 | 打回重设计，不合入 |

### 12.5 团队量级

- T2/runner：3–5 人；
- VMM/GPU/Android：6–10 人；
- 内核 S1–S4/IOMMU：3–5 人；
- 测试/矩阵/功耗：2–3 人；
- 合计 10–15 人，2–3 年量级；不要用一个内核团队顺带做。

### 12.6 不做清单

- 不做 T2 APK；不做手机单 GPU 直通；不做常驻 Android；不做 Microdroid UI；
- 不做万能 monolith；不整搬 crosvm 的 Linux 沙箱层；不把 Linux/Android/Wine 塞内核；
- 不在没有同机数据时承诺“原生级”。

| `FRGN ok` | Foreign syscall 往返 + Native 金丝雀 | ktest/boot |
| `LNX ok` | 静态 busybox 输出与宿主逐字节对拍 | QEMU |
| `GCC ok` | T2 内 gcc 编译 hello.c，产物再跑 | QEMU |
| `SBX ok` | 沙箱逃逸矩阵全红/全拦 | QEMU |
| `VM ok` | 最小 guest boot + PSCI shutdown | QEMU |
| `VML ok` | Linux/Android guest 到 console | QEMU |
| `VMM ok` | virtio blk/console/net/input 往返 | QEMU |
| `GPU ok` | gfxstream/Venus 三角形/帧对拍 | QEMU/真机 |
| `APK ok n=` | Android 应用数（profile 字段区分 T3-A/T3-U） | 真机/QEMU |
| `WINE ok` | Wine/Hangover 目标应用 | PC/真机 |
| `PWR ok` | 冻结/恢复 + 待机功耗 | 真机 |

### 13.2 ktest（内核）

- S1：状态机、人格不可篡改、共享页只读、native 等价、runner 死回收。
- S2：通道创建/满/收/恢复、四类异常、无通道杀、阻塞打断。
- S3：namespace 逃逸、mount 权限、pager 缺页/递归/死锁。
- S4：stage-2 映射/越界、vCPU regs、vtimer、GIC 注入、PSCI、MMIO exit。
- Job：配额、OOM、freeze、回收、统计。
- 每个新对象：坏 handle/类型/权限/未知位/出参预清零，全套负向。

### 13.3 host/QEMU/真机

- **host**：runner syscall 表纯函数、ELF 解析、矩阵生成、manifest、VMM 设备模型单测。
- **QEMU**：T2 CLI 全链、S4 最小 guest、virtio、显示；`-icount` 相对基线。
- **真机**：功耗、帧、热、待机、恢复；同机 Linux/Android 对照。
- **fuzz**：S1 共享页、S2 异常消息、S4 MMIO/virtio descriptor、gfxstream 命令边界、
  Android binder 边界。
- **soak**：T2 长跑、T3 冻结/恢复循环、内存泄漏金丝雀。

### 13.4 兼容矩阵

- 固定 app 集（先 20，后 100）；每版跑；红项不静默。
- 矩阵入仓/入 CI 产物；产品页可查；失败类可归因。
- 新 rootfs/guest/Android/Wine 版本必须跑回归；回滚保留旧矩阵。

### 13.5 CI

- `just build/check/smoke` 不变；新增 `smoke-compat`（可慢跑/夜跑）。
- QEMU 功能门与真机性能门分开；性能门不做绝对时间，用同机基线/icount。
- 矩阵/功耗报告作为 CI artifact；趋势线不倒退。

## 附录 B：版本记录（v1.0 → v1.1）

## 附录 C：业界证据（2026-11 抓取）

- **crosvm**：ChromeOS 的 VMM；同时跑 Linux（Crostini）与 Android（ARCVM）；
  多 hypervisor（KVM/Gunyah/GenieZone/Halla）；virtio-gpu 2D/3D 支持
  virglrenderer/gfxstream/vulkano；TerminalApp on Android。
  <https://github.com/google/crosvm>
- **gfxstream**：Graphics Streaming Kit；把渲染 API 从 VM guest 流式转发到宿主；
  用于 Android 虚拟设备/Cuttlefish/Goldfish。
  <https://github.com/google/gfxstream>
- **muvm**：在 microVM 里跑程序；一个 microVM 内可跑多个 GUI 应用；
  支持 FEX/Box 跑 x86。
  <https://github.com/AsahiLinux/muvm>
- **libkrun**：可嵌入的 VMM 库；KVM/HVF/WHP；virtio-gpu 支持 Venus/native context；
  muvm/krunkit 使用。
  <https://github.com/containers/libkrun>
- **FEX-Emu**：ARM64 上跑 x86/x86-64；API 转发到宿主库；代码缓存；支持 Wine/Proton。
  <https://github.com/FEX-Emu/FEX>
- **Box64**：ARM64 上跑 x86_64 Linux 程序；DynaRec 比解释器快 5–10×。
  <https://github.com/ptitSeb/box64>
- **Hangover**：ARM64 Wine 跑 x86/x86_64 Windows 应用；只模拟应用本身，
  在 Win32/Wine syscall 边界跳出；ARM64EC + FEX。
  <https://github.com/AndreRH/hangover>
- **Android AVF**：pKVM protected VM；crosvm；Microdroid。
  <https://source.android.com/docs/core/virtualization>
- **Microdroid**：mini-Android in pVM；明确不支持 Graphics/UI。
  <https://source.android.com/docs/core/virtualization/microdroid>
- **Fuchsia Starnix**：用户态运行未修改 Linux 程序；用户态 Linux ABI。
  <https://fuchsia.dev/fuchsia-src/concepts/starnix>
- **gVisor**：systrap 用 seccomp RET_TRAP 截 syscall，2023 起替代 ptrace；
  GPU 支持目前 NVIDIA 专用。
  <https://gvisor.dev/docs/architecture_guide/platforms/>
  <https://gvisor.dev/docs/user_guide/gpu/>
- **Asterinas**：Rust 写的 Linux 兼容内核；framekernel；0.19（2026-10）上 AArch64/DRM。
  <https://github.com/asterinas/asterinas>
- **WSL2**：轻量 utility VM 跑 Linux 内核；发行版作为容器。
  <https://learn.microsoft.com/en-us/windows/wsl/about>
- **Waydroid**：Linux namespace 容器跑 Android；依赖宿主 Linux 内核。
  <https://github.com/waydroid/waydroid>

> 本文的“目标”是工程预算，不是对外承诺；落地前用 spike 数据复核。
