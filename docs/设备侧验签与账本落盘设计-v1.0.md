### 1.2 boot 期：BerryBoot 消费 V10 sig_slot（§2 设计位 → P3 实施路径）

**现状**：handoff v2 头 176B 已含度量/签名槽三字段（`meas_root[32]` @128 + `sig_slot_off/len`
@160/@168，`kernel/src/handoff.rs` :104-106，双侧镜像 + 偏移表 assert :137-139）；**预留位不
启用——BerryBoot 恒写全零，v1 无消费者**（同文件 :30-33 头注；ADR #82 附录一 V10 行：已落
2026-11-11，闸位 = 结构冻结/真机烧录前）。

**实施路径四步**（推断——P3 立法时收口，前两步随闸 E 定形）：

1. **sig_slot 几何定形**：`off/len` 的偏移基（相对内核镜像装载窗 or 平台签名清单件本体）、
   双零 = 未占用语义（照 `gop_*`/`cmdline_*` 的 pa=0 ∧ len=0 双字段同判律，handoff.rs :18）——
   现役仅「零值缺席语义」在册，非零指向域随闸 E 前立法。
2. **签名数据格式**：平台签名中心清单（Q3 裁定不设 OEM 镜像级签名，#82 附录二 Q3）；平台段
   签名消息绑**组合式树身份**（平台工件清单 + OEM 段 hash 白名单——#77 R1a 语句照录 :228；
   白名单源三件 = 签名索引 `last_revision` + 产品包清单派生 + V13 组装段 hash 产物）。与快道
   lane 语义（L1 内容寻址累积）正交：lane 管安全公告水位，清单管完整性见证。
3. **验证与态汇成**：BerryBoot 验签 + 度量累积（槽 1-3，安全与硬件隔离 §4.2）→ 汇成
   `berry.verifiedbootstate` 单一四态标记（verified/self-signed/unverified/failed =
   GREEN/YELLOW/ORANGE/RED，OTA §2.1-4 :45）→ 进 handoff/boot 标记面 → 下游（keystored
   证明、盘加密密钥绑定、遥测）第一天可消费，**不需要内核 ABI 再开洞**（同句原文）。
4. **失败态处置**：RED = 真机路拒跳或警告屏，QEMU 路占位（OTA §2.1-4 原文）；失败隔离原则
   不采「不开机」默认（应用规范 §11.2 同哲学——boot 期例外：禁改面件验签失败属完整性破坏，
   拒跳是设计位语义）。

> **G11 内核签名归属 v1 裁定追记**（38 号 §4，轻追记不升版——OTA §3.1 追记先例；**推断**
> 标注，正式随 #77 真签刀与闸 C/E 立法）：组镜方（平台或 OEM 集成者）持钥签 KERNEL.ELF
> 并自携 TRUSTPK（mkimage `--sign-key/--trust-pk` 产线半边，`tools/mkimage.py` P3 注记段
> 同笔裁定）；烧录锚（真机不可变信任根）随闸 E/Q1 的 0xDA 密钥材料分区（mkimage 件 4
> 预留槽）立法。

**meas_root 全零 = 未度量**的消费路径见 §四。

### 1.3 装载期：svcmgr/appd 对 .bap+.sig 验签

#### 1.3.1 插入点（三消费路径，守卫单源）

现役 .bap 装载路径三处解析（svcmgr 为并行 lane 占用件，行号 = 2026-11-11 直核，开刀重数）：

| 路径 | 锚点 | 现役守卫链 |
|---|---|---|
| boot 批 | 走查收集 `app/*.bap`（:1914-1936，AppSlot 记几何）→ 批拉起循环（:1997 起，`APP ok n=` :2035） | bap_scan（:5469）→ `berry_manifest::parse`（:5731）→ type/id/entry 三守卫 → compat min → net 词拒 → ui_face → spawn |
| SPAWN RPC | `app_serve_spawn`（:7010，裁决二「守卫单源」:5743 注——与 boot 批同走 app_launch 守卫） | 同上单源 |
| selftest 直查 | `selftest/APPTOMB.bap` cpio 直查（:6087-6113） | bap_scan + parse + tomb guard（测试夹具面） |

**P3 插入位 = `app_launch` 守卫链的 manifest 解析后、type 守卫前**（推断）：此处 manifest 的
`[security]` 三键（profile/key_lineage/sec_integrator，V3 已三键化——berry-manifest lib.rs
:897）已可读，.sig 信封的 lineage 回声对账
（信封 lineage == manifest key_lineage，berry-sign 验签序第 3 步）才能执法。守卫单源纪律不变：
三路径共用同一装载验签函数（裁决二字面落实）。SHA256SUMS 的 v1 现状照录：**只记账在场不读
内容不验摘要——「真执法点 = v2 安装期签名验证，挂账 O4」**（main.rs :5521-5523）——P3 即该
挂账的兑现位：.sig 验签过 = 完整性+来源双账立，SHA256SUMS 保持记账不升级（信封 bap_digest
已覆盖全字节摘要，双验冗余）。

伴生件定位：走查收集 `app/<ID>.bap` 时同步收集 `app/<ID>.bap.sig` 几何（同前缀伴生条目，
推断——信封是分离件，SDK-2 §三 :51；rootfs cpio 内以同名+.sig 后缀共置，mkapp 产面对应
`<out>.bap.sig` 命名直映）。bap_digest = SHA-512/256（.bap 全字节）装载期二次流式读
（STEP_WIN 步进复用、rootfs VMO 只读——berry-exec/d-1b 流式先例；不走查顺带累积，防
收集与验签两条读路径漂移——推断，实施刀定）。

#### 1.3.2 装载策略表（全签关门前后 / sideload / 无签名处理）

策略表 = 镜像内数据件 `etc/load-policy.toml`（暂名，推断；berry_assemble 组装产物——与
`etc/orchestr.toml`〔槽位合同 §5.2 暂名〕同居 rootfs 只读区）。三档：

| 档 | sideload | require_sig | 无 .sig 处理 | 未知 lineage 处理 | 适用镜像 |
|---|---|---|---|---|---|
| `dev` | on | off | **降级装载 + loud 行**（`eco: app <id> unsigned`——失败隔离家族） | TOFU 首见记录后装载 | dev 镜像（构建期预开，拍板④；smoke/selftest/host 注入链不卡门） |
| `product-open` | off | off | 降级装载 + loud 行 | **拒载 + 显式错误**（`eco: app <id> unknown-src`） | 产品镜像·关门触发器**前**（生态为零期，存量无签包照载） |
| `product-locked` | off | on | **拒载 + 显式错误**（`eco: app <id> nosig`） | 拒载（同上；system/oem-system 锚除外） | 产品镜像·关门触发器**后**（§三） |

- 无签名处理二选一（任务书问句）：**拒载 or 降级 = 档位函数**——`product-locked` 恒拒载
  （SDK-2 §九 :133「关 = 拒装 + 显式错误」字面）；dev 档降级（开发链不卡门，§〇 拍板④）；
  `product-open` 档降级但 loud（诚实可见，不留静默通道）。
- **防剥离护栏与档位无关、恒执法**（SDK-2 §三 :63 ①）：账本 per-app 记录在案的已签 id 再见
  无 .sig = 拒载（全档同拒——剥离是攻击不是兼容态）。
- 水位恒执法（同上 ②）：gen 回降拒（`check_gen` 单源，ledger.rs）；ver 回降拒（freshness
  ver_max，SDK-2 §四 :74-75）。**账本不可用（未落盘/损坏）期间**：验签照做（锚定公钥来自
  bootseed 只读区仍可验），水位跳检 + **诚实声明「回放防护未生效」可见**（§三 :63-64 原文；
  eco 观测行族，非标记族——不 gate smoke）。
- 降级行形态：`eco_app` 家族（≤24B 行窗，main.rs 现役同款）；拒载不 trap（单 app 坏不连坐，

|---|---|---|---|
| bootseed（初始信任账本） | rootfs 只读区 `etc/trust-ledger.toml`（暂名，推断——mkcpio 装配条目，`etc/orchestr.toml` 同居先例） | ledger.rs TOML 源形态直用（P0-1 解析器零新格式；schema=1 + 四字段占位 v1 恒空） | 构建期（berry_assemble 产物；官方 `system` 锚从 source-keys.txt 派生或独立维护——开放问题 Q3） |
| 增量账本（设备态） | FAT 卷 `LEDGER/`（8.3 短名约束同 /SOURCE/ 推断） | 同 TOML 形态 + per-app/per-source 记录（同库不同键，SDK-2 §五 :98） | appd（svcmgr 账本模块）经 fsmgr（fsproto RPC）——「账本落盘 = appd↔fsmgr 接线」（§六 :109 原文） |

- **TOFU 首见记录**（dev 档）：装载期首见未知 lineage 的合法 .sig → 记 `{pk, anchor_type=tofu,
  gen_max=gen, ver_max=ver}` + per-app `{锚定公钥, 来源=sideload|builtin, boot 计数, 版本水位}`
  + per-source `{指纹, 代际, pending 钥}`（§五 :98 字段照录）。首见即锚——此后同 lineage 换
  钥走轮换链机器裁决（零用户指纹比对，§二 :35-37）。
- **写路径纪律**：单写者 appd；bootseed 恒只读（镜像重刷才换代）；增量账本写-刷次序随 L1
  掉电安全族（树数据 flush 先于指认，D5 同精神）；**RAM-only 降级**（fsmgr 无 FAT 卷——裸跑/
  rootfs 相无 vblk）= 账本驻 RAM 不落盘 → 每次重启回 bootseed 初值 + 「回放防护未生效」可见
  （TOFU 记录丢失 = 重见即再记，幂等无害；水位回初值 = 回放窗口重启后重开——诚实降级接受，
  真机面随 CounterBackend/RPMB 收口，§五-Q1）。
- **卸载 = 显式信任重置**：账本该 lineage 条目删 + 墓碑宽限记录（SDK-2 §四 :72-73）；v1 升级
  = 卸载重装语义不变（拍板②）。
- **Q6 冻结轨尊重**：anchor_type 枚举/条目字段 add-only（闸 B 后改 = 全量账本迁移，#77 :236）；
  per-app/per-source 记录键**不在 Q6 冻结面内**（同库不同键），但其字段表冻结点 = P3 合入前
  （开放问题 Q5）。

## 二、P3-0 host 可验最小件设计（本轮不实施，给 tools/ 的实施规格）

### 2.1 形态裁决：决策函数进 lib、tools 只编排

三条硬约束定形态：①**单解释器纪律**——账本 TOML/信封 TLV 的语义判断不落 Python 第二份
（对照反面：gensourceindex `check_index_version` 是 Python 镜像 + 同步义务注记 :72-74——水位
比较这类**单函数**可镜像，装载决策这种**组合语义**不可）；②**设备侧可逐字消费**——berry-sign
bin 的验签组合逻辑本就欠「上移 lib」一笔（lib.rs :34-36 既定义务）；③**tools/ 零三方依赖**
（gensourceindex/berry_assemble 同纪律）。故 P3-0 = 三件：

| 件 | 落位 | 内容（推断——实施刀定名定形） |
|---|---|---|
| 件一：admit 决策模块 | `user/berry-crypto/src/install.rs`（暂名） | 纯函数 `admit(bap_digest 摘要面, sig_opt, anchors, policy, records) -> Verdict`，`Verdict ∈ {Allow{注记}, Reject{SigErr/LedgerErr/PolicyErr}, Mutate{ledger', records'}}`；no_std 零分配家族形态；§1.3 策略表三档 + 验签序五步 + 防剥离 + 水位 + TOFU 全在此单源 |
| 件二：berry-sign 子命令 | `berry-sign admit <policy.toml> <ledger.toml> <dir>`（暂名） | host 暴露：目录内 `*.bap`+`*.bap.sig` 逐件裁决，stdout 决策行 + 增量账本 emit（canonical TOML，parse∘emit 幂等钉板——ledger.rs :42-44 既有承诺） |
| 件三：模拟器 | `tools/p3sim.py` | 场景编排器：布景（mkapp+berry-sign **测试钥现签现验**，钥落 /tmp 不落仓——main.rs :9-10 纪律）→ 调件二 → 断言；`--selftest` 零构建依赖自检（gensourceindex :23 先例） |

### 2.2 验收判据（P3-0 Definition of Done）

1. 正样例：bootseed system 锚 + 官方件 .sig → Allow，水位不降。

## 三、关门触发器实施面（SDK-2 §八 + #77 全签执法）

立法面已决：**触发条件 = ①外发决定反转，或 ②首个第三方 .bap 在野——先到即关门，此后无签
包拒载**（SDK-2 §八 :123-125；#77 裁决三句 3 + 重议触发器 :235）。实施面两半：

### 3.1 机器判据（可观测事件，非意愿——重议触发器纪律同源）

- **①外发决定反转**：治理/立法事件，判据 = 反转决议落册（ADR/架构决策.md 数据行）本身——
  非遥测可测，观测点 = 落册 commit（推断：治理事件的机器观测面就是版本库事实）。
- **②首个第三方 .bap 在野**：机器可观测，两探针（先到即中）：
  - 探针 A（源侧）：官方源签名索引出现首条锚不属于官方件/oem-system lineage 的条目——执法
    点 = `gensourceindex --verify` 产线（索引八字段含 key_lineage，与 bootseed 锚集对账）。
  - 探针 B（镜像侧）：berry_assemble 组装期发现 rootfs-manifest `app/*.bap` 条目其 .sig 信封
    lineage ∉ 镜像在册锚集——执法点 = V15 白名单校验同族扩展（步②，九型拒面先例）。
- 判据输出 = 一行关门标记（berry_assemble 报告 loud），**不自动改档**——档位翻转走镜像
  构建参数（下节），关门标记只是把「错过不可补」的窗口论据（§八 :125）变成机器事实。

### 3.2 触发后镜像变化（四件，全部构建期/装载期既有面扩展）

## 四、与 V10 槽 / meas_root 度量链的衔接

### 4.1 meas_root 全零 = 未度量：消费路径

- **语义单源**：全零 = 未度量（handoff.rs :104 注 + :30-33 头注「meas 全零 = 未度量」）；
  零值缺席语义 = pa/len 双字段共同判定律的度量族形态（:18）。
- **消费决策表**（推断——下游统一问「今天有没有被度量过」，不问度量值本身）：

| meas_root | sig_slot | boot 汇成态 | 下游语义 |
|---|---|---|---|
| 全零 | 双零（现状恒真） | `unverified`（ORANGE） | keystored/盘加密按未验证态自持；遥测如实记——**QEMU v1 全部落此行**（诚实基线，无假绿） |
| 非零 | 双零 | `verified` 的度量半边（完整性账立、签名账缺） | 度量链对账可做（§4.2），签名见证缺席如实记 |
| 非零 | 非零 | 四态全判定可用 | 签名+度量双账闭环（真机终态，闸 E 后） |

- 装载期 appd 不直接消费 meas_root（槽 4 是 appd 自收集面，见下）；meas_root 的消费者 =
  BerryBoot 汇成 verifiedbootstate 后的**下游服务**（keystored 证明、盘加密绑定——OTA
  §2.1-4）。P3-0 host 件不含此面（真机件），但 §4.1 决策表进设计册防两刀各说各话。

### 4.2 槽 4（.bap manifest 集）与装载验签的次序

度量槽位表槽 4 = `.bap` manifest 集（全部 app manifest，**按 app id 升序**逐条累加，收集者
= appd 收集/装载时——安全与硬件隔离 §4.2 :80；累加语义 :84「重放清单即重建全部累加器」）。
P3 后的装载期次序（推断）：**先验签后入槽**——`.bap+.sig` 过 admit 门 → manifest 进槽 4 累加；
拒载件不入槽（度量账 = 实际装载面，与 `APP ok n=` 谓词同口径）。次序理由：槽 4 恒不绑密钥
解封（§4.2 :86「槽 4 随 app 装卸翻面、恒不绑」），先签后度零密钥面代价；反序（先度后验）
会让度量账包含拒载件——对账语义漂移。boot 对账三判据（09 号 §2.3-2 :143）消费同一 manifest
集：系统件 lineage ∈ {integrator} ∪ {官方}、白名单能力键 ⊆ G2/G3 词表、白名单签发者
lineage == 产品包 lineage——P2 已立（静态面），P3 设备侧装载执法与之共数据源。

### 4.3 闸位时序（防两刀抢闸）

闸 C（首个编队 OTA 实现合入前）= Q3 信封 + L1/R1a 车道/段签名格式冻结——**P3 合入即触**：
装载验签消费信封 v1 字节形，P3 合入后改信封 = 在野验证器语义漂移（两步发布纪律激活，
ledger.rs :24-27）。闸 E（handoff/boot 结构冻结/真机烧录前）= §1.2 前两步定形死线。两闸
之间 = 本档 §1.3/§1.4 的设备侧实施窗（QEMU 可验，不待真机）。

## 五、开放问题与重议触发器

### 5.1 开放问题（不替拍板）

- **Q1 密钥存储硬件面**：设备侧锚/水位的抗离线篡改住址——QEMU 期 = bootseed 只读区 + RAM
  （诚实降级，§1.4）；真机 = CounterBackend（read/increment/CAS，OTA §2.1-3——后端 QEMU
  软件桩→RPMB/eFuse 换芯零协议改）+ mkimage MBR 密钥材料分区预留槽（D8，`tools/mkimage.py`
  :26-28 type 0xDA 16MiB）。归 P8/闸 D 前裁。
- **Q2 OEM 段验签分治**：R1a 设备端执法（活跃槽 OEM 段 hash ∈ 白名单，否则整包拒装退整编队
  ——#77 :228）的**白名单设备侧来源与更新面**（三源：签名索引 last_revision / 产品包清单
  派生 / V13 组装段 hash 产物——谁是设备侧唯一事实源）随首个编队 OTA 实现立法（闸 C）。
- **Q3 bootseed 生成归属**：gensourceindex 从 source-keys.txt 派生 vs berry_assemble 独立
  步产物——涉官方锚与源钥是否同源同换代，随 P3 开刀裁。
- **Q4 策略表落位**：`etc/load-policy.toml` 暂名 + berry_assemble 参数形态 vs #83 product
  清单正式键——后者动 #83 定稿面须升版，随 P3 开刀一并裁（#83 重议触发器「首个真实产品
  清单表达力不足」可挂此）。
- **Q5 per-app/per-source 记录 schema 冻结点**：不在 Q6 冻结面（同库不同键）但同为持久结构
  ——建议钉 P3 合入前终核（Q6 教训的姊妹动作）。
- **Q6 unsigned 索引的设备侧语义（2026-11-11 题面翻新）**：轮十已实装索引签名面——
  `sign_index()` 真签（`--sign-key` opt-in，gensourceindex :296-333；berry-sign
  sign-raw/verify-raw 独立合同 + RFC 8032 §7.1 官方向量钉板），`just sign-user` 已接旗标
  产真签名索引（justfile :381）；unsigned 形保留为兼容面（缺 `--sign-key` 路）——原问
  随之聚焦：设备侧对 unsigned 索引 = 拒 or 诚实降级可见（unsigned 兼容面须可过 dev
  smoke）？随 #77 后续附则或 P3 开刀裁。
- **Q7 设备侧常时性审计**：ed25519 模块现声明「常数时间风格、未审计、不用于在线敌手环境」
  （lib.rs :31-33，P3 兑现面）——装载期验签的敌手模型（本地拼盘攻击者非在线侧信道）下是否
  足够，P3 开刀时评估。
- **Q8 无签名 .bap 的 `product-open` 档去留**：若 P3 落地时关门触发器已先中（生态仍为零但
  判据误中风险存在），`product-open` 档是否还值得存在——保守案 = P3 直接双档（dev/locked）。
