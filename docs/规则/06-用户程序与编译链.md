# 06-用户程序与编译链

> 一句话定位：动 用户程序/asm 模板/libc/stdio 面/.bap/rootfs 前先读本文。判例全文 → docs/雷册-判例库.md（瘦行行尾锚点直达）；设计文档见文末「深读」。

## 域铁律

> agentsOwn.coding 编码铁律在本域只载「用户态服务 / 工具」半；内核 / HAL / 引导（`#![no_std]`）半归 `01-内核编码.md`。

**用户态服务 / 工具**

- 服务 `#![no_std]` 起步；高层工具可上 `std`。
- 跨 syscall 的函数返回 `Result` + 显式错误码，绝不 panic（内核态 panic = 系统停）；跨 syscall 结构体加 `#[repr(C)]`，与 `berry-sys` 镜像同步。

## 判例瘦行

- **asm 模板纪律三则**：①spawner 的 `movz x4, #<len>` 必须精确等于子模板字节数——改模板后重数指令（每行字符串 = 1 指令 ×4B）；拷多带尾零垃圾、拷少截尾，两种错都静默；ktest `svc6` = nr+6 参共 7 形参——5 参 syscall 末尾补 0 占位；②svc 后复用参数寄存器先想清值——派发只回写 x0，x1..x6 保留的还是你传的参数（vmo_read 后拿缓冲地址用 x2、x3 是 offset=0）；③`adr` 取同页内嵌数据仅限同页（±1MiB、不跨模板边界），与「局部数字标号 + movz 绝对地址」拷贝安全约定同源。先问：len 常量重数了吗？svc 后寄存器装的还是参数值吗？adr 出同页了吗？ → 雷册 §A23/24/26/§B13
  - §B13 蒸馏补入：asm 模板换轨编译产物时，重试形态（自旋 vs 阻塞）是契约的一部分——逐发送点核对 asm 标号 EBUSY 分支去向（`b Nb` 回环自旋 vs clock+wait 阻塞），不能按家族归纳（console 饱和窗口内阻塞者会被自旋友商抢槽饿到超时）。先问：换轨前端口的 EBUSY 分支走向核对了吗？
- **用户程序编译链两则（G-eco-a）**：①stable 免 nightly——builtin `aarch64-unknown-none` + build.rs 绝对路径注入 `link-user.ld`（0x1000 基址=USER_CODE_VA）+ `-zmax-page-size=4096`（rust-lld 默认 64K）；std 面走 musl；`elf2flat.py` `--max` 是单页墙执法点；②`kernel/src/userbins/*.bin` 是 gitignored 产物——`include_bytes!` 直嵌，缺产物 = 裸 cargo build 编译期炸响；just build/check 已挂 build-user 补产；改源在 `user/bins/*`。先问：link-arg 用绝对路径了吗？改的是源还是平像产物？ → 雷册 §A48-49/§B12
  - §B12 蒸馏补入：builtin target 是 G-eco-a 决策，勿回退 custom target；`-zmax-page-size=4096` 必带（否则 0x1000 基址表达不了）；缺产物 = 裸 `cargo build` 编译期炸响是设计如此（loud 非静默回退）；`just build-release` 同挂 build-user 补产。先问：裸 cargo build 前编译产物在位吗？
- **用户模板尾部内嵌数据（`.ascii` banner 等）后必须 `.balign 4`**：`UserProcess::build` 断言模板长度 4 字节倍数——banner 9 字节直接 boot 期 KERNEL PANIC（4-2a）；长度恰为倍数也保留该行（纪律一致性）。先问：模板改完后长度是 4 的倍数吗？ → 雷册 §A30
- **两遍构建 + rerun-if-changed 全列纪律（G-eco-b）**：`include_bytes!` 内嵌平像由 pass 1 产出（`user/userbins/` 中转区），单遍 workspace 构建无顺序保证；build.rs 须显式 rerun-if-changed 盖 link-user.ld + 自身源 + 全部 staged 平像——任何 rerun-if 指令都替换 cargo 默认全量重编，漏列 = 改了子程序、内核还嵌旧字节静默上线。先问：每个被内嵌的产物都在 rerun-if-changed 清单上吗？ → 雷册 §A53
- **elf2flat 平像页补零——磁盘 .bin 是页倍数（G-eco-b/D3）**：铺平 PT_LOAD 后补零盖 .bss 并取整到页；`vmo_write(len)` 传平像全长（含补零，零字节无害）。`--max` 是墙执法点：svcmgr `--max 131072`（= D3 `USER_CODE_MAX` 128KiB），单页 bin `--max 4096`；多页 spawn 的 sp 读 `UserProcess::stack_top` 字段（data/stack 随 code 页数上移），别读单页常量。先问：多页 spawn 的栈顶是从字段算还是沿用单页常量？ → 雷册 §A54
- **模板握手信号用专用位、清位豁免——模板不烤调度时序假设（P5-0）**：一次性无确认 signal 与对端多段前置窗口天然竞速，别把调度时序当契约；修法 = 握手专用位 U4=1<<38 + 全部清位掩码豁免该位（`#0xFFFF`→`#0xFFBF`）+ observed 断言前 `bfc x8,#38,#1` 掩掉——任意相位皆成立。现役用户位：1<<32 哑Event / 1<<33 SLEEP_OBJ / 1<<34 ktest·AI_EV_DONE / 1<<35 U3 / 1<<36 E_rel / 1<<37 U2 / 1<<38 U4 / 1<<39 RX Event——新增用户位前先查碰撞。先问：模板里烤了调度时序假设吗？新用户位查过碰撞吗？ → 雷册 §A61/§B18
  - §B18 蒸馏补入：死状双相位——早到被清位抹掉→空等超时 / 意外命中→严格断言炸——修法必须做到任意调度序都成立。
- **editor 控制字节（0x03 等）落在 ESC 序列中间态必须「复位状态机后落下处理」，不得静默吞掉（C-4b）**：ESC 状态机 esc=1（已见 ESC）/esc=2（CSI 参数区）中收到 0x03——既非参数字节（0x30..=0x3f）也非 final（0x40..=0x7e），按「序列内无关字节」吞掉 = Ctrl-C 在 CSI 窗内失效（真终端语义 = 序列作废、控制键照常生效）。修法 = 两态都先复位再走普通键路径（作废当前行直达 Interrupt）。先问：这个字节落在序列中段时真终端会怎么处理？ → 雷册 §A103
