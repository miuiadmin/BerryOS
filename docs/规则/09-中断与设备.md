# 09-中断与设备

> 一句话定位：动 中断/GIC/PL011/virtio/netd 拓扑 前先读本文。判例全文 → docs/雷册-判例库.md（瘦行行尾锚点直达）；设计文档见文末「深读」。

## 域铁律

本域主轴是**硬件序**——MMIO 宽度与寄存器字节口径、EOIR 前后序、DMA 队列生命周期、仿真器/真机差异，正确性一律由硬件行为裁定（细则见「判例瘦行」）。本域没有独立的铁律正文，规则密度集中在判例；旧 B 行编号已作废，独有细节蒸馏归并如下（B19/B20 细节蒸馏入下列铁律条目、编号作废，不设独立 B 段）：

- **SPI target 不可省**：PPI 段只读的惯例不可照搬——SPI 段 ITARGETSR 复位 0 = 静默不投任何核，不真写 target 则 pending 挂着无人收（完全静默）；新 SPI 源走 `gic::enable_spi` 一次齐。
- **tick 槽只对 CNTV**：授片（slice 记账）与 CVAL 绝对编程是挂钩的——新源进 tick 路径会把两者脱钩。
- **丢字面分仿真与真机**：FEN=0 深 1B 下 QEMU 唯一丢字向量 = 内核环满 lost，overrun 丢字是真机才有的面。
- **FEN=1+RT 中断未验证**：勿盲开。

## 判例瘦行

- **中断源纪律**：①GIC SPI ITARGETSR 复位 0=静默不投核——走 `gic::enable_spi` 一次齐；②电平去活在 EOIR 前（RX drain 到 RXFE；CNTV rearm 同）；③`exception_irq` 按 INTID 分流、加 match 臂；tick 槽只对 CNTV；④FEN=0 深 1B：QEMU 唯一丢字向量=环满 lost、按打字速率消费；⑤FEN=1+RT 勿开；⑥rx_irq/rx_init 尾 ICR 勿清 RXIC（0x7ef 非 0x7ff）：INT_RX 仅 count==1 置位、锁存被抹即挂死；⑦console spawn arg 满→新 handle 走静态槽（RX_EV_H/RX_EV_REF，retain 永不 release）。先问：EOIR 序/INTID 分流/ITARGETSR target 核对了吗？ → 雷册 §A62-65
- **virtio/net 三则（P6 A-7）**：①virtio-net VERSION_1 按 12B 剥 vnet_hdr——不协商 MRG_RXBUF(1<<15) 则驱动 legacy 10B 排头、QEMU 仍剥 12B = TX 斩头 2B、SLIRP 静默丢包（10s 帽假超时）；②解析长度权威在报文自身域不在线宽——SLIRP 把 42B ARP 补到 64B：权威 = ARP hlen/plen、IP total_len，恰长执法每帧必拒；③瞬态 virtio 退出必须 STATUS=0 复位撤队列（reset_device）——DRIVER_OK 的 rx avail 挂 DMA 页，宿主写者（SLIRP 周期 IPv6 RA）即静默腐化；refute 前提不跨设备类。排障 = filter-dump pcap 三分。先问：线上帧长与 guest 对得上吗？设备类有宿主写者吗？ → 雷册 §A80-82
- **EL0 读 CNTVCT 需 CNTKCTL_EL1.EL0VCTEN=1（复位 0 = EC=0x18 陷阱，B-1）**：没开 = user_fault_exit 静默杀（退出码 0 + 无 EOF）；EL2 场另需 CNTHCTL_EL2.EL0VCTEN。先问：新用户态代码读系统计数器，这扇门开了吗？ → 雷册 §A9
- **virtqueue used ring 的 idx 在 used_off+2——used_off 本身是 flags 位恒 0（P6 A-3）**：`get_u16(ring, used_off)` 读的是 flags（无 EVENT_IDX 协商时恒 0）→ poll 永不前进恒假超时；berry-virtio 的 `used_idx()`（=used_off+2）才是 idx。诊断同源原则：写 poll/诊断前先对齐同一 API——差一个偏移的两次「同一缓冲读」会制造「内存视图分裂」假象；纯函数 crate 的正确 API 在册就别手写偏移。先问：poll 与诊断打印用的是同一个 API 吗？ → 雷册 §A72
- **PL011 寄存器偏移按 TRM 字节口径：FR = 0x018——「FR@0x06」是字索引误当字节偏移（V-0b）**：读 0x0900_0006 落在 RSR/ECR（只读恒 0）→ TXFE 轮询永等不到 = 静默死转。单一事实源 = `arch/aarch64/src/uart.rs` 的 `UART_FR=0x018`。取证范式：`-gdb tcp::1234` 不带 `-S` 放跑到挂死后 lldb attach 读 PC/LR，LR−装载基址对回反汇编 `bl` 返回地址即定位；LLVM 把 `(fr&0x80)!=0` 编成 `ldrsb`+`tbz #31`（测 bit7 非 bit31）。先问：这个偏移是字节口径还是字索引换算的？ → 雷册 §A91
- **boot DAIF「屏蔽窗」= 三处约定合力（A105）**：①boot.rs `.Lat_el1` 统一 `daifset #0xf`（EL1 直入路原本继承 QEMU reset 解蔽——仅 EL2 eret 路屏蔽）；②task_entry_trampoline 起步 `daifclr` 是真任务正当设计，但 enable_irq 前经它执行的 ktest 乒乓对会把解蔽态带回切出者（DAIF 不入 TaskContext——切回继承对端终态，兼违 switch `PSTATE.I==1` 不变式）；③ktest 两 ping 对起手 `disable_irq()` 复蔽。观测 = `kern_lock::irq_enabled()` 锚点直读（六锚定界法）。先问：enable_irq 前新增执行上下文，DAIF 终态落窗哪侧、会不会传染回切出者？ → 雷册 §A105
