# 03-系统调用-ABI 与系统调用

> 一句话定位：动 syscall 号/ABI 面/abi.toml/berry-sys/ktest 样本 前先读本文。判例全文 → docs/雷册-判例库.md（瘦行行尾锚点直达）；设计文档见文末「深读」。

## 域铁律

本域成文铁律收敛为 syscall 边界的 **C-ABI 约定与单源守卫**；错误自理 / 不可抢占 / 退出链等判例纪律见下节瘦行。

### C-ABI 约定（两端皆 Rust）

- **边界形态**：syscall 边界用 **C-ABI 约定**——Rust ABI 不稳定，故 syscall 入口/数据结构用 `extern "C"` + `#[repr(C)]`；内核与用户态都是 Rust，无跨语言 FFI 风险。
- **公共 ABI 镜像同步**：公共 ABI（`berry_*` + 结构）一律 `#[repr(C)]`，内核与 `berry-sys` 镜像同步（详 `docs/系统调用ABI设计-v1.0.md`，abi.toml 单源）。
- **单源守卫口径**：`just abi-check` = ABI 单源守卫——gen_abi.py --check 逐字节比对 abi.toml 三面产物；忘再生成/手改即 FAIL（挂 build/check/smoke 前置）。`just abi-gen` = ABI 再生——abi.toml → 内核/berry-sys abi_gen.rs + 文档 marker 块；改 ABI = 改源 → abi-gen → diff 随源入册。
- **跨边界数据所有权**：Rust 侧绝不持有跨 syscall 边界的引用生命周期假设；跨越边界的数据按拥有的/复制的传递。
- **SVC 寄存器映射**：x0 = 号、x1..x6 = 参、返回只回写 x0——与下节 §A55 瘦行同源展开，berry-sys 已按此镜像。

### ABI 轨道（level 与号表冻结联动）

- **平台 API level 单源**：BerryOS 平台 API level 轨道单源 = `abi.toml` `[platform]` `level`——单调只增，不兼容变更必须 +1。
- **level 与号表冻结承诺联动**：level 是对外承诺的**名字**，syscall 号表冻结三值（`nr_total` 37 在册 / `nr_defined` 41 含 1.1 常量层 / `nr_ceiling` 45 号面帽上界）是承诺的**内容清单**——名字单源在 `[platform]`，内容单源在号表，同守 abi.toml 一处；v0.2.0 起 boot banner 带构建标识（版本 + git 哈希 + dirty 位），轨道身份现场可查。

## 判例瘦行

- **进程退出链四则**：①`task_exit_hook` 四步 mark_exited → `wake_matching(TERMINATED)` → drain 子表 → release 钉住，序不可换——release 先于 drain = UAF、drain 先于 wake = 等待者见已清表；drain 仅 pinned 表（pinned=0 直通）；映射中 VMO 的 Box 不可放（Drop 只泄漏帧）→ any_mapped 整对象泄漏兜；`process_start` 至多一次（双检 → -EBADSTATE）；②exit 族先 `send_stdout_eof()`（零长 EOF）再 `berry_process_exit`——颠倒 = EOF 永不到达；③`-> !` 号（0x33/0x36）切走不归——回写 x0 不可达、尾勿排死码；④`reap_drain` 只在 idle_loop 顶 + yield_now 尾消费——自旋任务推迟回收（cap 32）；ktest 期勿断言回收数。先问：退出动表/放引用序对吗？EOF 先行了吗？ → 雷册 §A66-69
- **libc 桩/ABI 对真身抄（C-2a）**：①结构体布局对目标 arch 真 ABI 抄、不跨 arch 平移——x86_64-musl 与 aarch64-musl（asm-generic：st_mode@16/st_nlink@20）字段序不同、总尺寸可同 128B；读侧偏移才是事实源、写侧自洽证明不了；布局处放 `const _: () = { assert!(offset_of!(…) == …) }` 编译期钉板、钉全字段；桩签名对 libc crate 真原型抄——出参桩参数位对齐（get*_r 真原型 5 参、result 落 x4）；②errno 档位跟上游消费面白名单走、不直觉给 ENOSYS——「正确 errno」由调用方的错误分类代码定义：is_xattr_unsupported 只吞 ENOTSUP/EOPNOTSUPP(95)，ENOSYS(38) 即误诊；POSIX 声明 ssize_t 的桩必须 `-> isize` 全宽写 -1（c_int 只写 w0、x0 高半为零 → std 误判成功 set_len(0xffffffff) 野读）。先问：抄的是目标 arch 真身吗？errno 对过调用方白名单吗？ → 雷册 §A92/94
- **syscall 边界无 panic**：跨 syscall 的 Rust 函数返回 `Result`/状态码，绝不 panic（内核态 panic = 系统停）。 → 雷册 §A3/§B3
- **3-1 起 syscall 错误一律错误码自理、永不杀调用者**：未知/越界/未实现编号 → `-ENOTSUP`，坏 handle → `-EBADF`，EL0/EL1 同权（ABI §8.0「永不 panic」的内核执法）；杀只留给 CPU 故障（D-abort/I-abort/BRK 走 `user_fault_exit`）。用户页 AP=0b01 且未设 UXN = **用户页当前可执行**（NX/只读档留 v2）。先问：这个 syscall 失败路径返回错误码还是杀调用者？ → 雷册 §A14
- **syscall 主体不可抢占 = v1 免锁根基**：SVC 异常入口硬件置 DAIF 屏蔽 IRQ 且 handler 全程不解蔽 → 引导表/对象访问单核串行；**任何新 syscall handler 不得解蔽 IRQ、不得忙等跨任务**（3-3 拆 per-process 表前都靠这条；3-4a 已拆 per-process 表，跨表访问仍全靠它串行）。先问：新 handler 解蔽 IRQ 或忙等跨任务了吗？ → 雷册 §A19/§B5
- **spawn 族两参数两义**：`process_start` 第 5 参 = 句柄迁移（内核 take 消费、父侧永不 close——bootstrap 握手链），`thread_start` 第 4 参 = 裸 usize 原样送子入口 x0；裸标必须 <0x1_0000（句柄 gen≥1 恒 ≥0x1_0000，两值空间永不碰撞）。先问：这个 spawn 参数内核侧走「对象迁移」还是「原样 x0」？ → 雷册 §A132
- **0x21/0x23 供给「全局取货+身份验」是单供给者契约——第二供给者并发上线必须让位（X-3c）**：mux 的恒唤自愈只在你**是唯一供给者**时成立；双供给者并发 = 热转环永远先赢 pager 键竞速、反复偷走对方武装槽（错配 EINVAL 唤醒→重武装→再偷），对方阻塞收货饿死（boot 序四标记 420s 连坐缺席实录）。修 = 让位闸（对方自供期间零供给调用）+ 活跃轮让步睡。先问：这个「阻塞收货+全局取货」syscall 现在有几个并发调用方在抢键？ → 雷册 §A140
- **`vmo_create` v1 上限 32MiB（`VMO_MAX_SIZE`，C-2c 起 16→32）**：巨 size 的 `Vec` 分配 abort 是 EL0 可触发 panic（违 ABI §8.0），故超限先拒 -ENOMEM——新 syscall 凡按用户 size 做分配的都要照此设上限。先问：这个 syscall 按用户 size 分配前设上限了吗？ → 雷册 §A20
- **SVC 寄存器映射：x0 = 号、x1..x6 = 参、返回只回写 x0（G-eco-b）**：dump 里 x1..x3 即 wait_one 的 (handle, signals, deadline)；berry-sys 已按此镜像。诊断用户态死亡先按寄存器反推卡在哪个 syscall 的哪个参数，再按 dump 顺序对时间线。先问：死因能从寄存器反推到具体 syscall 参数吗？ → 雷册 §A55
- **syscall handle 出参宽度 = 4 字节（`copy_out_u32`，G-eco-c）**：ABI §8 冻结 handle=u32——内核写 handle 出参一律 `copy_out_u32`（`kernel/src/syscall.rs`），按 u64 写 8 字节会砸穿调用方 4 字节槽的邻接局部；asm 模板手排槽碰巧免疫——编译用户程序 = ABI 宽度类 bug 的检测器。非 handle 出参（ns/size/vaddr/nbytes/idx/observed = usize）仍 8 字节：宽度跟 ABI 类型走，不跟「凑巧能跑」走；同族 ABI 面：真实链接器 PT_LOAD 不页对齐（RO 段与 text 共享页）——解析器不收页对齐，消费端页铺平单 VMO 消化。先问：这个出参宽度是按 ABI 类型定的吗？ → 雷册 §A57/§B16
