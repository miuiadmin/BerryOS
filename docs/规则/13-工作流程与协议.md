# 13-工作流程与协议

> 一句话定位：动 引入参考/加依赖/开工流程 前先读本文。判例全文 → docs/雷册-判例库.md（瘦行行尾锚点直达）；设计文档见文末「深读」。

## 域铁律

本域承载开工全套纪律：三条设计总原则 + 七条工作方式 + 排除 8 问准入门 + 改动前清单 + 参考项目协议矩阵；判例瘦行收敛于文末专节（多会话协作/构建取证类），约束以本文铁律为准。

### 设计总原则

1. **人无我有，人有我强**：别人验证过的优点学过来、踩过的坑绕开。证据库 = `research/`；借鉴任何参考前先过 `docs/架构综合纲领.md` 排除 8 问，防杂糅。
2. **AI 友好化**：AI 是系统一等公民——不止 AI 原生调度（`docs/AI调度设计-v1.0.md`），一切接口对 AI 可读、可推断：ABI 单一事实源生成（`docs/系统调用ABI设计-v1.0.md` §8）、结构化 tracing（`docs/可观测性设计-v1.0.md`）、语义化错误码、机器可读文档。
3. **AI 测试友好化**：为"以后都是 AI 测软件"的时代预埋基建——测试基建是产品的一部分：确定性可复现（同输入同输出）、可编程故障注入、机器可读遥测/断言、QEMU 自动化关卡（`docs/测试策略-v1.0.md` G0–G5）；目标 = AI agent 独立跑测试、读结果、报 bug。

### Claude 在本仓库的工作方式

1. **先查参考**：涉及某子系统（IPC、调度、页表…）先看 `reference/` 是否已有对照项目，参照成熟实现再写。
2. **小步提交**：OS 调试极难，每个改动小且可独立验证；能在 QEMU 跑通的里程碑单独成一个提交。
3. **不污染内核态**：内核 `#![no_std]`，禁用 `std`/`alloc`；用内核自有的分配器/日志；新增 crate 前确认 `no_std` 兼容。
4. **协议洁净**：主参考是 **Rust OS**（Redox / Theseus / zCore，MIT 可对照）；hubris = **MPL-2.0 语义可借、文件不搬**；rCore-Tutorial = GPL 只看思路；参照 seL4/Zircon/Linux（C/C++/GPL）时只看思路、不复制实质代码。本仓库许可证 Apache-2.0（ADR #37）。
5. **架构无关优先**：新功能先写成架构无关 Rust，确实需要特权指令时再落到 `arch/aarch64/` 并留好接口。
6. **博采众长不杂糅**：中心 = **可注入的「机制/策略分离」+ 硬件信任边界**；借鉴任何参考前先过 `架构综合纲领.md` 的**排除 8 问**门——轴取舍/许可边界/适用前提/验证关（G0–G5）任一不过即拒，八问全文在彼处。
7. **改了约定就更新规则单源**：新增目标架构、改变语言边界、确定构建命令时，回写 `AGENTS.md` 对应速览节（2026-11-01 入口整改起单源；`CLAUDE.md` 是 `@AGENTS.md` 导入指针，不另行维护）；**但历史/沿革类内容（阶段进展、标记流水账、战役复盘）只写 `docs/阶段沿革.md` 等文档，勿回写入口文件**——入口每轮全文注入 AI 上下文，只承载「当前状态 + 铁律路由」。

### 排除 8 问（借鉴准入门）

问句清单（全文与判例 → `docs/架构综合纲领.md` §4；任一不过即拒——见上节第 6 条）：

1. 轴 + PICK？——落在矛盾矩阵哪一轴？该轴 PICK 是不是它？
2. 冲突中心？——与「机制/策略分离 + 硬件信任边界」冲突吗？
3. Theseus 仅进程内？
4. IPC 不统管？
5. seL4 只锁不变量？
6. hubris 静态只借 boot 层？
7. GPL 不进？
8. 哪关 G0–G5 验证？——找不到关卡 = 范围泄漏。

### 改动前清单

- [ ] 是否查过 `reference/` 里对应参考项目的成熟实现？
- [ ] **借鉴是否过了「架构综合纲领.md」的排除 8 问**？（中心=可注入机制/策略分离+硬件信任边界；找不到 G0–G5 关卡=范围泄漏）
- [ ] 这个功能属于内核还是用户态服务？（默认用户态）
- [ ] 是否把架构相关代码收敛到了 `arch/`？
- [ ] 是否避开了 GPL 传染？（参照 GPL 代码只看思路，不复制实质代码）
- [ ] 改动是否能在 QEMU 上独立验证、小步提交？
- [ ] 是否需要回写 `AGENTS.md` 速览节（新增架构 / 改语言边界 / 确定构建命令——单源；`CLAUDE.md` 是导入指针不载规则）？**阶段进展/标记沿革只写 `docs/阶段沿革.md`，勿回写入口文件**（入口每轮全文注入 AI 上下文）。

### 验证门模板（HDAE 六步，借 Ginux 2026-11）

大型/高风险改动（新子系统、SMP/锁/内存/ABI/安全面）按六步落证据；轻改至少 Verify → Regress。

1. **Verify**：定位现状与不变量，写清“现在到底发生什么”。
2. **Reproduce**：先造最小确定性失败/负向用例；不可复现的批评只记录、不直接改。
3. **Specify**：写目标不变量、失败语义、验收判据（对应 G0–G5 哪一关/哪个 smoke 标记）。
4. **Implement**：只做满足该门的最小改动；不夹带重构。
5. **Regress**：跑负向用例 + 既有全量门；负向用例保留为回归。
6. **Review**：证据落文件/日志，停人审；不接受“作者自测即通过”。

纪律：一次只开一个门；不降低既有 G0–G5/smoke 门；不特判 benchmark；完成后停，不自动开下一门。映射：机器门 = G0–G5/smoke 标记，人审门 = 里程碑验收。

### 可写全局清单（借 Ginux writable-globals）

- `tools/writable_globals.py` 扫描 `kernel/ mm/ sched/ ipc/ arch/` 的 `static mut`（排除 `kernel/src/ktest.rs` / `kernel/src/bench.rs`），与 `tools/writable_globals.txt` 精确对拍。
- 新可写全局必须入册并选 owner group（`boot`/`arch`/`page-table`/`scheduler`/`ipc`/`telemetry`/`other`）；`--update` 只补缺失/删陈旧，保留人工 group。
- 挂 `just check` 与 CI；单跑 `just writable-globals`。首版 57 条 = 2026-11 基线（当前 59，含 SMP 新静态），新增/删除必须同刀改清单。

### 参考项目与协议矩阵

总纲：不复制 GPL/AGPL/MPL 文件进自研内核——主参考用 Rust OS（Redox/Theseus/zCore），hubris 只借语义（旧判例 B11 蒸馏并入本节，编号作废）。

- **Ginux（Apache-2.0，x86-64 模块化单体，2026-11 本地快照 `reference/ginux`）**：只借 domain/capability/boot authority/IOMMU 测试/HDAE 方法；内核内 VFS/网络/OCI/crypto 与 Linux ABI 全量是反面教材；详见 `research/Ginux-调研-2026-11.md`。**不是微内核、不是 aarch64、无 GUI/AI 调度**，不整搬内核代码。

- 优先对照 **Rust OS（MIT，语言匹配）**：Redox、Theseus、zCore；rCore-Tutorial=GPL 只看思路。
- hubris = **MPL-2.0**：监督重启等语义可借、文件不搬。
- seL4 / Fuchsia Zircon 作**思路参考**（C/C++，机制通用，不复制代码）；seL4 内核 **GPL-2.0-only，代码一字不进**。
- 其余 GPL/AGPL 项目（Linux、xv6、Genode）同样只看思路、不复制代码，防协议传染；本仓库许可证 **Apache-2.0**（ADR #37）——逐项目对照详表见 `reference/README.md`。

## 判例瘦行

（旧 B11 已作废编号、独有细节蒸馏并入上文「参考项目与协议矩阵」总纲行。判例新增/更新仍走 `docs/雷册-判例库.md` 单一事实源。）

- **共享入口文件整文件 `git add` 前逐 hunk 查归属**（justfile/CI/AGENTS 类多会话共笔面）：pathspec 提交不豁免 hunk 级检查——混入兄弟 WIP hunks = 半刀夹带（提交面引用未提交资产，干净检出断链 + 抢刀两代害）；非本刀 hunk → awk 抽 hunk + `git apply --cached` 选择性暂存。先问：`git diff` 每个hunk 都是我的吗？ → 雷册 §A125
- **兄弟全文件 Write 扫荡吞未提交编辑——工作树非事实源**：主树落大块第一步 = 权威副本快照（~/.k3-receipts/）+ `git add`；兄弟活动窗后 re-grep 关键标记；提交显式 pathspec + 提交前 grep 验内容（index 混兄弟 WIP）。worktree 隔离实际靠 env CARGO_TARGET_DIR 显式重定向（检出 config 无 target-dir 行——忘 export = 静默回写共享 target）。先问：这个未提交改动的事实源在工作树、index 还是权威副本？ → 雷册 §A133
- **构建指纹双证 + 变体尺寸执法——两案并存非一案**：陈旧产物 no-op 假绿（指纹 = Compiling 行 + mtime 双证；实证形 ry8D79/MdG8Xe ovfl=0 假败快红）≠ 越帽门 miss 烧帽（RCjWfp：变体越 ROOTFS_MAX 32MiB = fw_cfg 静默拒收无成因行）；烧帽档取证先扫 ROOTFS/横幅类系统行再读尾；变体手术后 VSZ ≤ 33,554,432B loud 拒跑。先问：这次跑的输入有「在场证明」吗——尺寸、横幅、自证行？ → 雷册 §A134
- **击杀哨宽模式跨会话误杀——哨只钉死自己栈的私有路径特征**：击杀/清理类哨与脚本的模式绝不许含 qemu-system-aarch64/端口段等通用词（多会话共享 QEMU 场，通用词 = 把兄弟合法工作拉进火力圈）；重试型 smoke 会把单杀放大成连环杀，杀后再现先验重试上游再定「新泄漏」；给过兄弟「直接清不问」授权后自己更不能挂自动杀。先问：模式每一段都只匹配我自己的栈吗？ → 雷册 §A138
- **共笔竞态 sweep 失——异步 lane 大提交整卷带走工作树未提交改动**：收口 `git add` 空手/产出零 trace 消失/index staged 他方删除三脸同根（共笔工作树 + 异步提交窗口交错 + 整 index commit 默认形零归属检查）；①收口前 `git log --oneline -1 -- <path>` 逐文件核最近提交归属，非己即重做或让号；②一律 `git commit -- <pathspec>` 路径式，绝 `git add -A`/整 index commit；③agent 产出落盘后立即收口，窗口不隔夜；④stash/rebase 舞蹈后必 `git status` 复核工作树与 index 双态。先问：这个文件的最近提交是我吗？index 里有没有别人的 staged？ → 雷册 §A146
