# 02-内存与页表-内存与地址空间
> 一句话定位：动 内存/页表/VMO/地址空间/分配器 前先读本文。判例全文 → docs/雷册-判例库.md（瘦行行尾锚点直达）；设计文档见文末「深读」。

## 域铁律

### 高半/低半内存模型

2b-1 起内核主体链在高半：VMA = `KERNEL_VA_BASE` + LMA 镜像，符号/PC 显示 `0xffffff80…`。跨半引用受 ADRP ±4GB 硬约束、双向坑——低半 `.text.boot` 引用不了高半静态量（4 张 boot 表放 `.bss.boot` 低半），高半代码取低半符号地址（哪怕只 cast 取值）同样越界断链。2b-2 起低半退役——MMIO（GIC/UART）一律走高半别名（`KERNEL_VA_BASE + PA`），PA 直访必 fault（唯一例外 = boot asm 开 MMU 前早期打印）；空表 `NULL_L1` 放高半 `.bss`，TTBR0 写入按 VMA−基址折算 PA。布局守卫 = `size.py --assert-flip`。

## 判例瘦行

- **高半布局纪律（2b-1/2b-2）**：内核主体链在高半（VMA = `KERNEL_VA_BASE` + LMA 镜像，符号/PC 显示 `0xffffff80…`）；**ADRP 只有 ±4GB、双向坑**——低半 `.text.boot` 引用不了高半静态量（4 张 boot 表放 `.bss.boot` 低半）、高半代码取低半绝对符号同样越界（mm.rs 导入 `__kernel_end` 运行时减基址）；低半已退役——MMIO（GIC/UART）一律走高半别名（`KERNEL_VA_BASE + PA`），PA 直访必 fault（唯一例外 = boot asm 开 MMU 前早期打印）；空表 `NULL_L1` 放高半 `.bss`，TTBR0 写入按 VMA−基址折算 PA。先问：跨半引用 ADRP 够得着吗？MMIO 走高半别名还是 PA 直访？ → 雷册 §A10-11
- **用户页表叶必须 nG=1，全量失效用 `tlbi vmalle1is`**：`tlbi aside1*` 按号失效**够不着 global 项**（boot 块描述符全 nG=0）——用户叶不标 nG 则同 VA 映射跨 ASID 经 TLB 泄漏；退役/回卷清 global 项只能全量 `vmalle1is`（`aside1all` 不是真实指令）。先问：要失效的项里有没有 nG=0 的 global 项？ → 雷册 §A12
- **`FrameAllocator::alloc()` 返回 PFN 不是 PA**（PA = pfn << PAGE_SHIFT），且帧内容不保证干净（buddy 只管元数据）——新页先清零再用。 → 雷册 §A17
- **3-2 起映射中 VMO 的「销毁性 close」拒 -EBUSY、别名 close 放行**：仅 refs==1（本次 close 会 drop 对象）且 mapcnt>0 才拒；dup 出的别名 close 不死对象、正常放行（refs≥2——存活句柄钉住它）——写成「映射中一律拒」会误伤合法别名链（RO dup→close RO）。decommit 同理拒映射中页；`Vmo::Drop` 对映射中页只泄漏。先问：这次 close 会销毁对象吗（refs==1 且 mapcnt>0）？ → 雷册 §A18/§B6
- **内核堆大对象 = 单块连续 buddy 块（heap.rs 整页路径，`2^order` 对齐）**：>16MiB 量级一次性分配在碎片化地形结构性失败（EFI 路固件保留区 + init blob 自占下 21.3MiB rootfs 的 order-13 块不可得；fw_cfg 冷启 RAM 完整属侥幸可达）。boot 期大缓冲优先**借用已在 DRAM 的源**（handoff/dtb 零拷贝 `RootfsBuf::Borrowed`）或逐页 VMO commit（物理不连续无碍）。先问：给这条路径写大 `Vec` 前问过内存地形吗？ → 雷册 §A21
- **分配器空闲头索引不得用全窗线性扫——「某阶有无空闲头」由镜像布局掷骰（K-1）**：某阶空不空由保留前缀 k=`__kernel_end>>12` 的奇偶（镜像是否跨页）决定——让内核镜像恰好跨页的无害 commit 都在重掷骰子；线性扫对空阶付 O(num_pages) 保证失败页扫（buddy `find_free_head`），单点基线对「布局敏感的双峰指标」无守护力（icount L2 精确相等门禁才显形）。修法 = **每阶位图 + 摘要位图两级索引**（置/清位 O(1) 维护摘要，查询 = 摘要字扫 + `trailing_zeros`，最小页号优先与线性扫同一 host 对拍钉板——`bitmap_index_matches_linear_scan`）；**禁止**用死垫/链接脚本钉 k 奇偶或放宽容差治标。先问：失败路径的代价是否与容量线性、是否被纯布局参数翻转？ → 雷册 §A95/§B28
- **低半 boot 代码的常量在 release 下可 ADRP 引高半 `.rodata.cst16` 越界断链——debug 绿不代表 release 绿（K-2）**：release（fat LTO+O3）可把 `.text.boot` 填表循环（`build_boot_pt` 类）折叠成常量池（匿名 .LCP 符号，`#[link_section]` 钉不住），ADRP ±4GB 跨高半即断链（池收高半而 `.text.boot` 在低半）；debug 保留标量循环故绿（opt=1 走 movz/movk）。修法 = 表写入 **volatile 标量逐写**（`(&raw mut …).write_volatile`）——禁绝向量化/常量池化，boot 常量钉低半；守卫 = `just build-release` 挂 CI。先问：低半 boot 代码 release 下会池化吗？ → 雷册 §A97/§B30
- **高半 Rust 直取低半符号地址 = ADRP 越 ±4GB 断链（2b-1 第三形态，S-1）**：高半代码 `&__smp_sec_entry` 式引用低半 `.text.boot`/`.bss.boot` 符号（哪怕只 cast 取值）即发 ADRP——R_AARCH64_ADR_PREL_PG_HI21 out of range 断链。两法：入口 PA 经链接脚本 `.rodata` 指针字 `QUAD(secondary_entry)` 递送（`ldr =` 取字免 ADRP）；低半待写静态量挪高半 `.bss`、boot asm 按 PA=VMA−基址 写。守卫 = `size.py --assert-flip`。先问：高半代码引用低半符号地址了吗？ → 雷册 §A100
