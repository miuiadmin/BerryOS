## 域铁律

### FS/盘面写序：FAT 覆写 commit 13 写序 + 毒环自愈

- 覆写 commit 落盘序冻结为 ⓪-⑧（①②④⑧ 纯内存步；盘写只有 ③ 数据扇区 → ⑤ 双 FAT → ⑥′ 根扇区，⑦ 回读对账）——共 13 次扇区写 RPC + 1 次回读。「FAT 先于根」是单调收敛方向，但只以 fat.rs 语句序存在、无运行时执法（smoke 掉电相对 ⑤/⑥′ 对调全绿），动写序 = 动掉电安全面。
- 毒环 = 掉电落在 ⑤-⑥′ 窗（FAT 已写、根未写）：盘面 `root.first` 指旧簇而 `FAT[旧簇]=Free`，无守卫时每次重试 commit 精确重演同环——结构性死循环、非一次性损伤；守卫 = ④ 释放旧链时「∈ 新链的簇跳过释放」，恢复 boot 一次 commit 自愈，正常路径构造性零行为漂移。
- 掉电模拟 = SIGKILL 直杀 QEMU + `cache.writeback=off`（只覆盖扇区间撕裂；扇区内撕裂 = 真机面）；验收 = smoke 掉电相三 boot 双面不变量——自然采样 ×2 + `pwrcls --poison` 确定性注入 + 毒环盘全链重跑：guest 标记全绿 ∧ 宿主盘面终验 clean。
- v1 残余面如实入册：新文件簇泄漏（⑤ 后 ⑥′ 前掉电）、FAT1 永不回读、无 journaling/fsck——本刀是「序设计 + 最小守卫」路线，不是日志路线。

## 判例瘦行

- **console 通道公平性三则（雷 2）**：①打印一律阻塞形态：EBUSY → clock_read + wait_one(console, WRITABLE, now+10s) → 重发（-ETIMEDOUT 重臂）——纯自旋 send 长跑饱和饿死（永不出 runqueue、环序冻结）；②wait_many 恒满足项（对端永不满 → WRITABLE 恒真）使服务永不入睡 = drain 相位钉死 RR 环——条件化入列（仅 plen>0）；③asm 模板换轨时重试形态（自旋 vs 阻塞）是契约——逐发送点核对 EBUSY 分支去向（`b Nb` vs clock+wait）；TCG 饱和窗整圈轮转 16×200ms、三场竞速即耗尽 10s 帽。先问：打印点 -EBUSY 阻塞等 WRITABLE 吗？等待项稳态恒满足吗？（svcmgr 豁免已 P5 A-2 撤销——send_spin 全量 → send_retry；② 的终态 = 填槽序末位者结构性饿死） → 雷册 §A50-52
- **时限帽按 RPC 成本模型定值（P6 A-6）**：TCG 单次串行扇区 RPC ≈ 0.8s（两层同 prio channel 往返 + vblk poll 1ms 睡 tick 粒度醒）——估链路时长勿拿 syscall cycle 外推；fs 写收侧帽 90s（16KiB worst ≈ 22 次仍 4x 余量）、分片 PUT 与 TRUNC 同帽（跨名 PUT 隐式重跑整链 commit）；DEADLINE_ROOTFS=300s 按「boot ~90s + FATW ~15s + T-d ~20s + 余量」；服务慢 ≠ 服务死（超时打 unreachable 时 fsmgr 仍在 commit）——真挂死交外层 smoke 帽兜底。先问：收侧帽覆盖服务端 worst 路径成本了吗？时限按 RPC 成本模型算了吗？（旧 10s 收侧帽即曾对 TRUNC 整链 commit 结构性误杀——本条的直接由来） → 雷册 §A76-77
- **调试槽 0xFE/0xFF 已退役（4-5a）**：回落 -ENOTSUP（ktest A 段断言 -95）；用户打印一律 `channel_send(endU)` 经 console 服务落串口（-EBUSY/-EAGAIN 全参重建立重试）；新内核侧调试直接 uart 打（EL1 语境），勿复活调试槽。先问：这个打印走 console 通道还是 uart？ → 雷册 §A36
- **std 程序 bare `abort` 静默死 = libc 桩被启动关键路径判死（G-eco-d d-1c）**：std `sys::init`→`sanitize_standard_fds` 先 `poll(3)` 验 fd 0/1/2，非 EINTR 失败直接 `libc::abort()`——不走 panic、零文案。新桩若可能被 std 启动路径引用，先查 std 对失败是否 abort，能谎报成功就谎报。排障：bare `abort` 先 grep berry-libc 自家打印认领；audit 构建（strip=false）+ llvm-objdump 找 `bl abort` 调用点。先问：新桩在 std 启动路径上失败会触发 abort 吗？（谎报口径 = fd 恒有效语义；或改真实现） → 雷册 §A56
- **std 程序栈按程序面给 + 映像/栈之间必设保护页（G-eco-d d-3c）**：栈页不足时下行栈会静默扎进映像 RW 页腐化 .bss，死状与死因南辕北辙。修法：`spawn_rootfs_elf` 栈页数参数化（hexyl 32 页 = musl 128KiB 默认）+ `stack_va = base+len+PAGE_SIZE` 隔保护页——栈穿 = 干净 D-abort，dump SP/FAR 直指祸首。先问：给这个程序的栈够用吗？映像与栈之间有保护页吗？（伴生纪律：多分片用户输出不可直接当 smoke 标记——>192B 经 console 通道分片会被稳态矩阵插花撕行；私有 stdout 通道收齐 + 零长 EOF + 宿主基准逐字节比对后才打单消息原子标记，`HEXYL ok` 模式；正主瘦行在 `07-测试与冒烟.md` §A60） → 雷册 §A59/§B17
- **常驻服务的 wait 超时是正常空闲、不是链断（P6 A-3）**：服务端 wait 帽到点 -ETIMEDOUT 必须重臂续等，只有非 -EAGAIN 错码才自陷（真链断 loud）；链断判定交给发问方的 roundtrip 超时——服务端超时自杀 = 早夭 + 下游连坐；等数据的超时是心跳，不是死线。先问：这顶帽子等的是「数据」还是「活性」？（连坐实例：echo 一死 svcmgr 稳态循环跟着死） → 雷册 §A71
- **常驻子勿 reap + recv 容量富余 + 随行 handle -EBUSY 分流**：常驻子 `ChildHandles` 不进 reap——reap 首步 wait 30s 帽必超时（未确认退出绝不 unmap/close；有界泄漏换免白等）；服务端 `channel_recv` 收口容量按「协议定值 + 富余」，`nh != 协议值 → ST_BAD`——恰量收的 -EINVAL 误入链断 trap 杀服务；回收随行 handle 撞 -EBUSY（销毁性 close 拒映射中 VMO）降级 ST_BAD 勿 trap，随行必须 dup 别名；严格串行 RPC 应答帽超时不重发（重发 = 重复写，v1 无请求序号防重）。先问：坏 client 能杀服务端吗？ → 雷册 §A74
- **内核杀（process_terminate/异常杀）不走 libc exit 族 = 收集方永远收不到零长 EOF（C-4b）**：EOF 约定只挂 libc `exit/_exit/abort`（`send_stdout_eof`），`process_terminate` 内核直收口——被杀者 stdout 无终点消息，只等 EOF 必挂。修法 = 前台收集 wait_many 挂 **TERMINATED 项**收口（数组序即命中序：EOF 已排队时 READABLE 恒先于 TERMINATED；`killed=true && eof=false` 合法终态，`!o.eof && !o.killed` 警告门）。先问：收口挂 TERMINATED 项还是赌超时？（v1 channel 无对端关闭检测，EOF 语义补全挂 v2） → 雷册 §A102
