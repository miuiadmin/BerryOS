# 14-版本管理

> 一句话定位：动 版本号/升版/打 v* tag/新 crate 入 workspace 前先读本文。裁决正身 = docs/版本管理标准v1.0.md（ADR #85 五轨道与执法门）；workspace 统一方案 = docs/全局版本号治理方案-v1.0.md。

## 域铁律

版本号三轨各有主、L-SYS 全仓同值、动号必须有因——违反任一条即回改，不开例外口子。

### 1. 三轨版本体系

| 轨 | 管什么承诺 | 单源 | 当前值 |
|---|---|---|---|
| **L-ABI** | 平台 ABI 兼容（不兼容变更才 +1，兼容新增不动） | `tools/abi.toml` `[platform]` level | level 1 |
| **L-SYS** | 系统里程碑身份（0.x 期无稳定承诺） | Cargo workspace 版本（根为基准） | 0.2.0 |
| **L-APP** | 应用自有版本（记录/分发，不参与兼容判定） | `.bap` manifest | 各自 |

（三轨与标准五轨道的映射：L-ABI = 平台 level 轨、L-SYS = 系统版本轨、L-APP = 生态包轨；构建标识/安全级两轨归标准管，本文不重复。）

### 2. L-SYS 统一规则

- 全仓 workspace 版本**同值**——根 / user/ / drivers/ 三继承 workspace、bootloader/berryboot 与 bootloader/berrydump、user/bins 31 个 musl 链独立件、arch/x86_64（x86 移植独立小工作区），当前一律 `0.2.0`；升版同批动，禁单边漂移。
- 有 `[workspace.package]` 的 workspace（根 / user/ / drivers/）：member 一律 `version.workspace = true` 继承，升版只改 workspace 根一处。
- 无继承段的独立小工作区（bootloader 两处 / user/bins 31 musl 件 / arch/x86_64）：字面版本同值（berry-efi 被 berrydump 跨工作区 path 依赖，字面值零歧义；musl 件 std 程序不可入 none-target 主 workspace——成员化结构性不可行），升版逐 crate 手同步（注释锚「L-SYS」可 grep 定位全量字面位）。

### 3. 升版规则

- **minor +1**：须有可独立验证的里程碑（G 关卡过 / 域收官 / 不兼容 syscall 变更——后者另须 L-ABI level +1 同批）。
- **major +1**：仅 SDK 冻结日——三同步门（系统版本 1.0.0 / level 冻结 / syscall 号表承诺全兑现，同批同 commit，缺一不成立）。
- 其余改动不动号：走速决策表（标准 §2）——迭代烧哈希不烧号。

### 4. 消费面同值对拍

boot banner（`env!("CARGO_PKG_VERSION")`）/ sysver VMO（kernel/src/sysver.rs，boot 第 9 插 0x0001_0009）/ uname（`BERRY_UNAME_RELEASE` 烙印）/ `.berryver`（tools/mkcpio.py 读根 Cargo.toml）——四面必须同值；smoke banner 门与 `eco: VER mix` 哨兵执法，偏差即红。

### 5. 禁止项

- workspace member **禁手设字面版本**偏离所在 workspace——`version.workspace = true` 是唯一合法形态。
- 例外仅两类：上游锁定家族（hexyl 0.17.0 / uu 家族锁步上游——独立 workspace 非成员，天然不继承）；未收编独立小工作区台账（只减不增，现状 0.1.0）——tools/berry（host 工具链）与 berry-ksproto（兄弟 WIP 占用域，占用刀收编时随刀升）。user/bins 31 musl 件与 arch/x86_64 已升 0.2.0 字面同值出账（2026-11-12）。
