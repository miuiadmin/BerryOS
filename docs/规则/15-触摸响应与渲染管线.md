# 15-触摸响应与渲染管线

> 一句话定位：动 输入收割/帧循环/damage/呈现路径（gui-inputd→launcher/berry-ui→guifbd）前先读本文。裁决正身 = docs/触摸响应设计-v1.0.md（延迟分解 + A′/B′/C′ 优化方案）；GUI 线总序 = docs/GUI里程碑规划-2026-10-v1.0.md。

## 域铁律

触摸响应 = 事件驱动帧循环 + 精确 damage + 即时呈现，vsync 只锁呈现不锁渲染——违反任一条即回改，不开例外口子。

### 1. vsync = 呈现闩锁，不是渲染闸门（iOS 同款）

- 触摸/输入事件到达 → **立即唤醒帧循环** → 同一迭代内渲染 + 提交（launcher wait_many 睡事件不睡拍——事件到达即醒即渲）。
- **禁止把 input pump 挂到 vsync 拍上**（Android Choreographer 反例：输入排队到下一 vsync 拍的 doFrame 才消费，白白多吃一拍内在延迟）。
- guifbd **blit-at-SUBMIT 保持**：渲染完就呈现（SUBMIT 应答即 latch），vsync（软 vsync SOFT_VSYNC_NS）只作呈现时基/遥测口径/hdi VBLANK_WAIT 服务面，不挡任何渲染与提交。

### 2. 触摸→光子延迟预算 ≤ 1 帧（16.7ms @ 60Hz）

| 段 | 预算 | 承载机制 |
|---|---|---|
| inputd 收割（设备→泵） | ≤1ms | 常备 armed INPUT_POLL 的 serve_poll 1ms 步进收割（POLL_STEP_NS） |
| channel 传递（inputd→消费端） | ≤0.5ms | channel READABLE 唤醒 wait_many |
| pump + 标脏 | ≤0.1ms | referee + press_react 表驱动（零闭包零分配） |
| 渲染 + SUBMIT（小 damage） | ≤10ms | 增量 paint + blit-at-SUBMIT 裁剪 blit |

- 违反预算时**先查呈现路径成本**（FULL blit 整屏像素拷贝 / px() 抽样 vmo_read / SUBMIT→FRAME_CALLBACK→RELEASE 串行 RPC 往返 / 阻塞 RPC 挡在 SUBMIT 前），**不是调度等待**——G3 全抢占 + preempt-on-wake 下 IPC 唤醒已即时，调度等待恒 0ms。

### 3. 首触不放大 damage

- `wake()` **不因输入事件无条件置 FULL 整屏**——条件化 FULL（damage 空集才置）已是引擎现状，embedder 义务 = **wake 后置于 pump_input**（先让 press_react 标出精确按压矩形，再判兜底）。
- press_react 已标精确按压矩形（set_props 同帧生效 / widget 臂 damage_rect）——**直接用**，别再叠 FULL（FULL 后 add no-op，精确矩形会被整屏语义吞掉）。
- 仅「确无任何 damage」时才兜底 FULL（保「不欠拍」帧节奏契约）。

### 4. 视觉优先于动作

- 阻塞 RPC（APP_SPAWN 等）**排在 SUBMIT 之后**——用户先看到按压反馈（PRESSED_BG 帧），spawn 后台进行。
- 帧循环迭代内的动作面（spawn/持久化/网络）一律记账延后到呈现完成之后执行，回执记账与诊断路径保持不变。

### 5. 重采样目标保持新鲜

- pump_input 的重采样目标 = **本帧渲染时刻推出的拍点**（`next_vsync_tick(now) − RESAMPLE_LATENCY_MS`，target_from_expected 单源推导）。
- **禁止用上一帧的 expected**（最多陈旧一个 period；idle 长睡后再用远古 expected，重采样跨度帽 >20ms 直接拒采、外推帽失义，拖跟手感全丢）。
