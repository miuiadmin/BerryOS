# 11-构建与产物-构建与产物纪律

> 一句话定位：动 构建脚本/target dir/产物字节/零漂移 前先读本文。判例全文 → docs/雷册-判例库.md（瘦行行尾锚点直达）；设计文档见文末「深读」。

## 域铁律

本域的存在理由 = **零漂移**：同输入同产物字节（abi.toml 三面产物逐字节一致、整盘镜像同输入同字节）——改构建脚本、target 配置、产物链的任何东西，都以不破坏这条为前提。

### 产物与路径

- **产物不在 `./target`**：本机全局 `~/.cargo/config.toml` 设 `target-dir=~/.cargo-target`（sccache + 共享 target）——内核 ELF 与用户态产物全部落这里，别在仓库目录下找。
- **路径解析单一事实源 = `tools/paths.sh`**：justfile / smoke.sh / CI 同源取路径，内部 `cargo metadata` 动态取真实路径——脚本里无需也不应硬编码 target 路径。
- 共享 target dir 的跨 worktree 污染面与三步纪律（worktree 独立 `CARGO_TARGET_DIR` / 回主树先 touch 改动面 / size.py 核 ram_total 指纹）→ 判例瘦行 §A96/§B29。

### 构建命令注释（口径冻结）

```bash
just build          # = cargo build（内核 ELF，target=aarch64-unknown-none）；先自动跑 build-user 补产物
just build-user     # G-eco：用户程序编译 → 平像 + mkapp 打包 .bap + mkcpio 产 rootfs.cpio（run-rootfs/smoke rootfs 相输入）
just build-release  # K-2 release 链接守卫（挂 CI，只构建不跑）：abi-check + build-user + cargo build --release + size.py --assert-flip——release 独有断链形态（fat LTO ADRP 引 .rodata.cst16 越 ±4GB）此前 CI 零覆盖
just abi-check     # ABI 单源守卫：gen_abi.py --check 逐字节比对 abi.toml 三面产物；忘再生成/手改即 FAIL（挂 build/check/smoke 前置）
just abi-gen       # ABI 再生：abi.toml → 内核/berry-sys abi_gen.rs + 文档 marker 块（改 ABI = 改源 → abi-gen → diff 随源入册）
just image          # V-3 单口整盘镜像 → out/berryos.img（MBR + FAT16 96MiB + 0xDA 预留槽 + 四件套，同输入同字节）+ 侧产物 manifest.txt（SHA-256 清单 v0 冻结）；--key-hash 只落 manifest
just test-host      # host 单元测试主入口（不依赖 QEMU）；mkapp 门禁自检 + mkfat --check-fixture 挂前置；台账 → 雷册 §C
```

### 前置（macOS，一次性）

```bash
brew install qemu just                          # qemu-system-aarch64 + just（brew 的 qemu 一包含全 arch 的 qemu-system-*）
rustup target add aarch64-unknown-none          # stable，拉预编译 core（无需 nightly/build-std）
rustup target add x86_64-unknown-none           # P7-x0 起 x86_64 最小集（stable 预编译 core，免 nightly）
rustup target add aarch64-unknown-linux-musl    # 用户态 std 面（stdhello/bsh/uu 家族与 .bap 应用同链——musl target + berry-libc shim + berry-ld；开发者文档 docs/应用开发指南.md）
```

> 固化口径（单行版）：**前置（macOS，一次性）**：`brew install qemu just` + `rustup target add aarch64-unknown-none`（stable，无需 nightly/build-std）；另需 `x86_64-unknown-none`（x86_64 最小集）与 `aarch64-unknown-linux-musl`（build-user 用户态 std 面：bsh/uu 家族与 .bap 同链）——均 stable 预编译 core。

## 判例瘦行

- **共享 target dir 跨 worktree 构建污染——指纹不区分来源、后建者胜（K-1）**：主树与 worktree 共用 `~/.cargo-target` 时，cargo 对「跨 worktree 同路径依赖包」指纹不足——worktree build 后回主树 build 可能链到旧 rlib（莫名 E0061、同 commit 重建字节抖动类灵异多半同源）。纪律：跨树构建后回主树先 touch 改动面源码再 build；worktree 构建一律独立 `CARGO_TARGET_DIR`；跨树/复算 bench 前用 `tools/size.py` 核 ram_total 指纹再下结论。先问：这个产物/基线来自哪棵树的 target dir？ → 雷册 §A96/§B29
  - §B29 蒸馏补入：worktree 独立 `CARGO_TARGET_DIR` 有 `.k2-target` 先例；核指纹完整命令 = `tools/size.py $(bash tools/paths.sh kernel)` 看 ram_total——确认测的是哪个内核再下结论。先问：这个 worktree 的 CARGO_TARGET_DIR 独立吗？
  - §B29 时序踩踏形态（GUI-5，2026-11-03）：共享 target dir 还有**并发写**面——验证脚本长窗（QEMU ≈4.5 分钟）后才 stat 的产物文件可被兄弟会话构建实时覆盖 → 对拍假 FAIL（镜像/guest 无辜）。纪律：验证脚本读共享产物的读点前移到产物刚产出时点（smoke-image.sh 基线入口快照先例）；跨会话写共享 target dir（build/build-user/check/test-host 全算）点火前 sock 通告 + 避让他人 QEMU 窗。先问：这个文件在我读完之前，窗口内会不会被并发构建换脸？ → 雷册 §B29 第二条
- **上游 crate 纯 doc 注释也会移动 musl fat-LTO 下游产物字节——「零漂移」断言按 target 面分账（SDK-1b）**：`//!` 头注进 crate metadata，musl 链下游产物（ELF/.bap/rootfs.cpio）字节随动 = **预期非缺陷**；none 面（内核内嵌平像）恒定 = **执法面**；Cargo.toml 纯元数据键不进编译。漂移归因须二分（逐 crate 还原头注定位动因）而非整树 stash 赌运气（会踩坏 abi-check 三面一致性等守卫）。先问：该加性面进不进 crate metadata、下游走哪条 target 链？ → 雷册 §A104
