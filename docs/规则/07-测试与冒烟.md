## 域铁律

本域的存在理由 = **可复现**（设计总原则 3「AI 测试友好化」：确定性可复现、同输入同输出、机器可读遥测/断言、QEMU 自动化关卡 G0–G5）——测试基建是产品的一部分，不是附属品。

### 单一事实源与活版纪律

- **标记清单单一事实源 = `tools/markers.sh`**（S-5 测试基建收尾刀起双数组单源——smoke.sh/smoke-smp.sh source 消费，smoke-image.sh ECO 族硬拷贝须连改）：改标记 = 改 `tools/markers.sh` 同步——勿只改文档、勿只在别处另立断言。
- 标记沿革逐字归档 → `docs/阶段沿革.md`；**标记语义注解与命令注释全文快照已冻结在 `docs/雷册-判例库.md` §C**——本文只留活版纪律与相构成，勿在本文复制逐标记语义。
- host 测试总口径以 `just test-host` 输出为准；逐 crate 台账与沿革 → 雷册 §C。
- 测试三入口：`just smoke`（QEMU 无人值守冒烟，CI 同款）+ `just test-host`（host 单元，不依赖 QEMU）+ QEMU 集成 `ktest` 框架（见 `docs/测试策略-v1.0.md`）。

### APP vs APPUI 计数语义（n 分母不同；OEM 对拍勿误判丢件）

- `APP ok n=` 的 n = 装载数：app 批每槽「拉起 ∧ 退出真码 0」全过才打，n == 收集槽数（`user/bins/svcmgr/src/main.rs:2040-2049`；行号 2026-11-12 现场重锚，开刀时重数）。
- `APPUI ok n=` 的 n = 有 [ui] 资产声明且全验过的 app 数：ui_decl>0 且 ui_ok==ui_decl 才打（`main.rs:2051-2061`）；无 [ui] 声明且包内零 ui 条目 = UiFace::Absent，不计入 decl（三态定义 `main.rs:5602-5610`）——标准 rootfs 恒 APP n=10 / APPUI n=9（APPQUIET 无 [ui]；TERMINAL 刀 2026-11-17 槽位 9→10 滚新），两 n 差是 ui 形态差不是丢件。执法锚（刀 A `89fb060ba` 双路已锁）：smoke-image.sh ECO 族与 markers.sh ROOTFS_MARKERS 主路均已锁 `APP ok n=10`/`APPUI ok n=9`（通配后门全收口）；加/减应用槽六处随动契约以 tools/smoke-image.sh 注释为单源。
- OEM 定制镜像对拍的期望值按各 app 的 ui 形态分别定，勿拿 APP 的 n 硬套 APPUI（38 号 §4 G14 实咬：对拍器初版硬编码 n=9 误红一次）；谓词语义全文（icon/views 对账、与 APP 独立判）→ 雷册 §C。

- **满载通道断言面须打到被测面——业务进度入心跳 + 被杀零容忍 + 时序下界（S-5e）**：调度观测面（sw/park/pages）在载荷线程被杀（舰队缩水）或业务恒败（svc 恒败自旋保可运行）时全绿穿过——心跳带 churn=（业务成功计数）严格递增 + boot 基线扣除后新增 kill 零容忍（rogue 矩阵预期杀不算）+ 均拍 ≥40s 下界（帽只防慢不防快）；谓词措辞随实测口径（在席 ≥57% 非满载）。先问：载荷业务完全死掉时，哪条断言会红？ → 雷册 §A124
- **等待远界对「首个事件」单独标定（G3-5c FM-16）**：首事件常带启动后置（基线落稳态窗/预热窗/握手窗/boot 尾结算），按稳态节拍外推的「N 拍裕量」必短——soakmon 首拍有意后置 300s vs 触发远界按稳态拍距标 180s = 双 Timeout PANIC。修 = 对首事件求 gap 数学上界再加裕量（480 = 上界 300 + 60%）。先问：这个超时的裕量数的是稳态节拍还是首个事件的实际网格？ → 雷册 §A129
