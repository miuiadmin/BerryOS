# 并行开发轨道-v1.0

> **版本**：v1.0（2026-11-09 立稿）
> **定位**：8 条无冲突并行开发轨道的拆分依据、范围盒、验证面、冲突治理与推进节奏。
> **输入**：路线图-v1.0（M-VM 三站 + ADR #39–41/49）、仓库模块行数盘点（2026-11-09）、
> 自动化流水线在飞件（W1-Q7/W2-Q11 系 PR）。
> **原则**：按「模块 + 验证面」切轨——每轨触不同文件集、不同 QEMU 目标/端口段，
> 接口冻结带（abi.toml 单源）内不私改；「能拆多少拆多少」的上限 = CI 验证带宽 ×
> 接口冻结带维护成本 × review 带宽，8 条是甜点而非天花板。

## 二、冲突治理三规则

1. **ABI/接口冻结带**：syscall 扩号一律走 abi.toml 单源（v1 41 号在册，计数随 add-only 滚新——`tools/abi.toml` `nr_total` 单源为准）+ ADR，
   轨道内不得私改内核接口；轨道 7 只在轨道 2 冻结的命令需求清单之后动刀。
2. **验证面隔离**：每轨独立 QEMU 目标（aarch64/x86_64）或端口段；CI 按 PR 标签
   分派 runner（`track-mg1` / `track-cli` / `track-x86` …），同轨串行、异轨并行。
3. **不混树纪律**：SMP 刀（轨道 3）与 M-VM 刀（轨道 1/2/5）不混树提交
   （路线图既有裁决，直接沿用）。

## 三、CI 带宽与 runner 布局

- 自托管 runner（Actions 对 self-hosted 免费）：当前 69.165.65.30 服务器
  （Debian 11 x86_64 8 核、TCG 无 KVM）两实例（srv1-linux-x64 / berry-linux-x64-1）
  ——**须收敛为标签分派**（每轨标签 → 固定 runner），避免同机双 run 抢 CPU
  导致 TCG 时序帽假红（2026-11-09 实证：双 run 并行时 rootfs 相 600s 帽爆）。
- 单次四相冒烟 20–40 分钟（TCG）；8 轨全开时 CI 排队成瓶颈 → 扩容姿势 =
  加机器横向扩（runner 免费），不是加压单机。
- 同机并发面：smoke 端口 18080-83 已 netns 隔离（unshare -Urn，2026-11-09），
  但 CPU 仍是共享资源——并发 run 数 ≤ ⌊核数/4⌋。

## 四、推进节奏（先 4 后 8）

- **第一批（即刻）**：轨道 1（M-G1 主线）+ 2（CLI）+ 4（x86 最小集）+ 6（测试扩容）
  ——零交集、验证面天然隔离，跑两个开发周期确认无互撞。
- **第二批**：轨道 5（Fusion 驱动，V-5a 实证先行）+ 7（libc 扩号，等轨道 2 需求
  清单冻结）+ 8（文档，随时可开）。
- **常设慢线**：轨道 3（SMP，每周期 ≤1 刀）。
- 每轨出件走 PR + 对应 CI 标签；合并节奏沿用小步提交（能在 QEMU 独立验证的
  里程碑单独成提交）。

## 五、kill criteria

- 任一轨道连续两周期阻塞他轨（接口冻结带争议 / CI 排队 >2h）→ 降级串行。
- 轨道 4 触发 ADR #41 盒外范围（SMP/APIC/ACPI/PCIe）→ 自动冻结回 ARM64 单线。
- 轨道 5 触发路线图 Fusion kill criteria（连续两周期 >50% 主线工时）→ 冻结顺延。
- CI 假红率（帽爆/端口撞）>20% → 先修 CI 地基再继续并行扩容。
