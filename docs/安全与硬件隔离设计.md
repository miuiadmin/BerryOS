# 安全与硬件隔离设计

> 能力模型（`能力模型设计.md`）只管**运行期**的资源访问。本文件补三段硬件级隔离：**DMA（IOMMU/SMMU）、运行期内存安全（ARM PAC/BTI/MTE）、启动期信任（度量启动）**。
> 决策依据见 `架构决策.md` #22、#23、#24。

## 1. 为什么能力模型不够

纯能力只校验"你有没有这个 handle 的权限"。但三类攻击它管不住：

1. **DMA 攻击**：用户态驱动能指挥设备 DMA，绕过 CPU 页表，直接读写任意物理内存——能力形同虚设。
2. **运行期内存破坏**：内核 `unsafe` 区（页表/上下文切换）一旦被 ROP/JOP/UAF 打穿，能力检查可被绕过。
3. **启动期篡改**：内核镜像/bootloader 被换，运行期能力规则全是空中楼阁。

→ 分别由 SMMU、ARM 安全扩展、度量启动兜住。

## 2. IOMMU / SMMU（能力安全的硬件后盾，决策 #22）

- **每个设备一个 SMMU domain**，绑定其被授权的物理区间（= 它能 DMA 进的那些 VMO 的物理页）。
- 用户态驱动经 Resource handle 拿到设备 MMIO + 一个**锁页/连续的 DMA VMO**；SMMU 只放行该 VMO 区间，越界 DMA 被 SMMU 拦截并上报（ faults → 异常通道）。
- 与内存管理（`内存管理设计.md` §6 DMA VMO）联动：DMA VMO 带 `CONTIGUOUS` + 锁页（不可换出），物理地址交给设备；SMMU domain 由内核在 map_device_memory 时建。（v1 已落形态 = 纯 VMO 无 IOMMU：vmo_get_phys 查页后备、无 IOMMU 披露面 v1 接受——`驱动模型设计.md` §2；CONTIGUOUS+锁页+SMMU 绑定仍 v2/v3）
- **热插拔/解绑**：驱动崩 → Job 回收其 handle → 内核拆 SMMU domain → 设备无法再 DMA。
- **编排方 = devmgr**（`驱动模型设计.md` §2，ADR #46——IOMMU DMA 圈是三铸件之一）：给哪个设备铸/拆 domain 由 devmgr 走应用链编排；本文件只管内核侧 domain 机制。

> 没有 SMMU，"用户态驱动 + 纯能力"就是不成立的；这是 Zircon/seL4 都重度依赖的件。

## 3. ARM 安全扩展（运行期，决策 #23）

| 扩展 | 防什么 | day-one 怎么用 |
|------|--------|----------------|
| **PAC**（指针认证，ARMv8.3） | ROP（返回地址/函数指针被篡改） | 内核指针签名/校验，target feature 开 |
| **BTI**（分支目标识别，ARMv8.5） | JOP（跳到非法落点） | 代码段标记合法落点 |
| **MTE**（内存标签，ARMv8.5） | UAF / 越界 / 双释放 | 内核堆 slab 打标签，访问校验 |

- **目标 day-one 开**（`-Z target-feature=+pauth,+bti,+mte` 或 target.json），`unsafe` 区显式管理。**Phase 0/1 推迟**：QEMU `-cpu cortex-a72` 是 ARMv8.0、无此三扩展（开了也只是 NOP/陷入），Phase 1 仍保持 cortex-a72；待 **v2** 切 `-cpu max`（ARMv8.5+）时一次性开，**源码零改动**（切换点见 `路线图.md` v2、`tools/`）。
- MTE 对内核堆（slab 分配器）尤其值钱（深度打标签见 §6 v2）：每块分配一个标签，越界/UAF 立即触发。
- 这些是**硬件加速的运行期安全网**，与 Rust 编译期安全互补（Rust 管 borrow，PAC/BTI/MTE 管 unsafe 区与攻击面）。

## 4. 安全 / 度量启动（启动期信任，决策 #24）

```
ROM(根) ─度量─▶ bootloader ─度量─▶ kernel ─度量─▶ 关键服务
                    │               │              │
              每级把下级 hash 累加记入 secure element / TPM
```

- **度量链**：每级引导在跳转前度量下级镜像 hash，累加到 secure element（QEMU 用虚拟 TPM；真机用硬件）。
- **信任根派生自度量**：初始能力包（`能力模型设计.md` §5 bootstrap channel）的合法性由"度量结果符合预期"保证，**不是硬编码"init 是特权进程"**。
- **远程证明**（v3+）：设备可向验证方出示度量摘要，证明运行的是未被篡改的内核 + 服务集。
- **回滚保护**：secure element 存单调计数器 / 反回滚计数，防刷入旧（已知漏洞）镜像。

## 5. 与其它子系统接口

- **能力模型**：SMMU domain、度量信任根 = 能力的硬件后盾。
- **内存管理**：DMA VMO（CONTIGUOUS/锁页）+ SMMU；MTE 给 slab 打标签。
- **驱动**：用户态驱动经 Resource + SMMU 安全用 DMA。
- **引导加载器**：度量链落在此。
- **AI 调度**：无关——AI 只在 fair 类内调策略，不碰安全隔离。

## 6. 阶段化目标（对照 `架构决策.md` #20）

- **v1**：PAC/BTI/MTE **暂关**（cortex-a72 无扩展，见 §3；切 `-cpu max` 时开）；SMMU **探测**（识别有无）；度量启动留桩。
- **v2**：切 `-cpu max`、开 PAC/BTI/MTE target-feature；SMMU domain 建立 + DMA VMO 绑定；MTE 给内核堆打标签。
- **v3**：度量链完整（bootloader 度量 kernel）；远程证明探索。
- **v4+**：安全启动闭环（签名 + 反回滚）。
