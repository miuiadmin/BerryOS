# 可观测性设计（Tracing）

> 现代 OS 的命门：**问题不可见就不可修**。本文是 day-one 内置 tracing 的设计——不是只为 AI 的遥测，是**通用诊断**。
> 决策依据见 `架构决策.md` #25。与 AI 遥测（`AI调度设计.md` §4）共享环基座，但通道分离。

## 1. 目标

- **低开销**：tracepoint 在关闭时近零成本（编译期 + 运行期双重开关）。
- **高保真**：关键路径（syscall 进出、调度切换、IPC、缺页、IRQ、上下文切换）全程可观测。
- **不阻塞**：per-CPU 无锁环形缓冲，单写多读，绝不在热路径等锁。
- **可消费**：用户态 trace 服务订阅 → 过滤 → 落盘 → 导出（chrome://tracing 格式可视化）。

## 2. 静态 tracepoint

```rust
// 内核侧宏（编译期决定是否编入；运行期 per-category 开关）
trace!(sched, "switch: {} -> {}", prev.name(), next.name());
trace!(ipc,  "send: ch={:#x} bytes={}", ch, n);
trace!(mem,  "fault: vaddr={:#x} kind={:?}", vaddr, kind);
```

- 类别（category）：`sched / ipc / mem / irq / syscall / boot / cap`。每类独立开关。
- 关闭时：宏退化为 no-op（编译期剔除），运行期也可整类关。
- 参数零分配：直接编码进环（定长头 + 内联参数），不走堆。**事件记录结构是内核↔用户公共 ABI**：`#[repr(C)]` + 定长头 + 内联参数（决策 #18 C-ABI 边界）；trace 服务经 mmap 共享环或 `trace_*` syscall 批量读取消费（v2）。

## 3. per-CPU 无锁环形缓冲

- 每个 CPU 一个环，单生产者（该核内核态）→ 多消费者（trace 服务）。
- 与 AI 遥测**共享环基座**（同一种 ring 实现），但**不同通道**：
  - **trace 通道**：全量事件流，诊断用，体积大、可丢（环形覆盖）。
  - **telemetry 通道**：聚合特征（util/唤醒/cache），AI 用，体积小、保序。
- **stats 与环同源两视图**：per-process 快照账（CPU/内存/能耗，`AI调度设计.md` §4 资源账）是环与 metrics 的**聚合视图**——v2 stats 查询面从既有数据聚合而来，不建第二套采集。
- 跨核不抢锁：每核写自己的环，trace 服务按核轮询。

## 4. 用户态 trace 服务

- 订阅：指定 category + 过滤谓词（如"只看 pid=X"）。
- 落盘：环形 → 文件（经 `/svc/fs`——路径式挂载随 v2 落，`文件系统设计.md` §6）。
- 导出：转 **chrome trace event** JSON，浏览器可视化时间线。
- 控制：`trace_start / trace_stop / trace_set_category`（少量 syscall，v2）。

## 5. metrics / counter

- per-subsystem 计数器：IPC 数、缺页数、调度切换数、channel 满/空次数、context-switch 开销累加。
- 这些是**长期趋势**（健康度、回归基准），区别于 trace 的**瞬时事件流**。
- AI 服务与 trace 服务都消费 metrics。

## 6. 与性能/纪律

- **trace 是热路径的一部分**：tracepoint 实现必须零分配、无锁竞争、关闭时零成本——否则它自己变成延迟源（讽刺）。
- 关键路径的 tracepoint 在 CI 里**默认关**，只在诊断/基准时开。
- G3 关卡（低尾延迟）必须在"trace 开"和"trace 关"两套都过，证明 trace 无劣化。

## 7. 阶段化目标

- **v1**：静态 tracepoint 宏 + per-CPU 无锁环 + 最少类别（boot/sched/mem）。哪怕没 trace 服务，先把环和点埋下。——**2026-10 落地注**：实际形态 = `telemetry.rs` 静态预储**双环**（切换环 3-4c + 唤醒环 4-0，零分配热路径）+ ktest/watchdog 机器断言消费 + intent/标注来源/通胀计数器遥测落盘（ADR #42）；tracepoint 宏、chrome 导出与 trace 服务未落（仍挂 v2）。
- **v2**：用户态 trace 服务 + 导出 chrome 格式；全类别；metrics 框架。
- **v3**：与 AI 遥测通道整合；远程采集（网络服务）。
