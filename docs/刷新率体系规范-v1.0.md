# 刷新率体系规范（v1.0）

Type: standard
Status: current
Updated: 2026-11-15
Version: 1.0.0

一句话说明：立法 BerryOS 显示刷新率体系——60/120Hz 基准、30Hz 降探、240/480 高刷、165/180 测试档与 LTPO 可变刷新率的档位模型、率通路协议、软面板设备、投票-仲裁-执行、呈现语义、内核时间底座与应用面规则。依据与外部证据 = [`research/2026-11-15-刷新率体系研究.md`](../.agents/research/2026-11-15-刷新率体系研究.md)（survey，本规范只立规则不重复论证）；决策登记 = `架构决策.md` #65。

## 1. 范围与术语

适用于 guifbd 呈现服务、软面板设备、berry-guiproto 协议、内核定时底座、berry-ui 及一切提交帧的 GUI 应用。术语：**刷新率**（面板每秒扫描次数，Hz）与**帧率**（应用每秒产帧数）严格分开；**拍点**（vsync 时刻序列）；**档位**（面板可运行的一个刷新率值）；**呈现**（一帧对用户可见的瞬间）；**latch**（帧内容被锁进呈现通路不再可改的时刻）；**LTPO**（低漏电混合背板，1-10Hz 档的物理前提）；**LFC**（低帧率补偿——内容帧率跌破下限时整数倍重发上一帧）；**停帧**（无内容变化时零出帧零唤醒，面板内容自保持）；**Tiered 面板**（离散档位表形态——手机 LTPO OLED 主流形态）与 **FreeRange 面板**（连续区间形态——VESA Adaptive-Sync/eDP VRR 形态）；**变节拍 per-frame**（每帧呈现间隔独立可变、panel follows host——§7-P6）。

## 2. 总则（三条铁律）

- **R1 率通路单源**：刷新率数值全系统只能有一个源——面板能力宣告。fw_cfg 只许传值不许造值；任何件禁自造 Hz 或周期硬编常量；唯一豁免 = 本规范 §3.4 的档位周期表 const 单源。客户端帧钟参数必须由服务端下发注入，不得本地默认顶替服务端真值。
- **R2 呈现锁拍**：帧的可见时刻必须锚定拍点序列（目标拍点 = target_present_ns 向上取整到拍点；FreeRange per_frame 面板上锁拍实例化为逐帧变节拍，§7-P6）；体系阶段 v2 起 latch-at-vsync 为默认呈现语义，v1 的 blit-at-SUBMIT（SUBMIT 处理内同步呈现）法定为过渡态 Legacy-Present，须在 v2 收敛。一切时序断言锚 guest 单调钟的 presented_ns 序列，禁以宿主观测为准。
- **R3 单一仲裁**：全局刷新率由 guifbd 内仲裁器单点裁决；应用投票是 advisory 输入不是指令；仲裁器必须总有输出（无票也有平台默认档）；仲裁目标值只能落在面板能力宣告的率域内——Tiered 面板 = 档位表选档，FreeRange 面板 = 区间内连续取值。

## 3. 档位体系

### 3.1 基准与产品档（Tiered 形态默认宣告表）

基准档 = 60 与 120（owner 2026-11-15 裁决）。产品档全表：

| 档位 Hz | period_ns | 480 基频分频比 | 族 | 首启阶段 |
|---|---|---|---|---|
| 30 | 33_333_333 | 16 | 产品·降探 | v1 |
| 60 | 16_666_667 | 8 | 产品·基准 | v1 |
| 120 | 8_333_333 | 4 | 产品·基准 | v1 |
| 240 | 4_166_667 | 2 | 产品·高刷 | v2（仿真）/v3（硬件） |
| 480 | 2_083_333 | 1 | 产品·高刷 | v2（仿真）/v3（硬件） |
| 165 | 6_060_606 | 非整除 | 测试 | v2 |
| 180 | 5_555_556 | 非整除 | 测试 | v2 |
| 1 | 1_000_000_000 | — | LTPO·AOD | v3 |
| 10 | 100_000_000 | — | LTPO·降探 | v3 |

模型 = 基频整数分频（Android 15 ARR 蓝本：面板跑在 TE 基频的整数分频档上）：产品档全体整除 480Hz 基频，24/30/60fps 内容全部整数倍均匀呈现、零 judder；165/180 对 24fps 非整除（165/24 = 6.875），法定为**测试档**——只用于混合 cadence 稳健性测试（§10-T5），仲裁器在非测试模式禁选测试档。

### 3.2 率域模型归面板（Tiered / FreeRange 二类）

率域是面板能力的一部分，由面板设备宣告（§5），软件不自造档、不硬编集合。两类同日立法、同批支持：

- **Tiered（离散档位表）**：手机 LTPO OLED 主流形态——面板驱动 IC 只认厂商品控验证过的离散扫描时序，未验证间隔有闪烁/伽马漂移风险；Apple ProMotion 全档恰为 240 基频整除集、Samsung「1-120Hz」是区间营销档位离散，皆此物理与品控约束，非软件选择。软面板 Tiered 模式按 §3.1 全表宣告（按首启阶段分批开启）；真 LTPO 面板按规格书宣告（LTPO 档的有无、min/max 都以面板为准）。
- **FreeRange（连续区间）**：`{min_hz: u16, max_hz: u16, granularity_hz: u16（默认 1Hz）, per_frame 位}`——VESA Adaptive-Sync / eDP VRR 形态（PC 显示器 48-144Hz 区间任意间隔逐帧变即此类）：区间内任意刷新率合法；per_frame 位开启时逐帧间隔独立可变（§7-P6），即「1 到 N 随便可变」的逐帧形态。仿真 FreeRange 宣告 1-480Hz 全连续；真机落地路径 = DP/HDMI 自适应同步外显与 eDP VRR 面板（v3+）。

软件契约一律连续：仲裁器内部以 0.01Hz 精度持有理想连续值，面板边缘量化——Tiered 取宣告档（整数倍优先，§6-A3/A4），FreeRange 取区间钳制 + 粒度对齐。省电大头在降档：30Hz 降探与停帧（§6-A7）是低功耗主战场，240/480 是流畅度上限位，优先级立法为降探先于拉高。

### 3.3 AOD 与电源模式

POWER_MODE 四值已立法（`berry-guiproto`：NORMAL=0 / DIM=1 / AOD=2 / OFF=3）。AOD 1Hz 是组合拳（1Hz 档 + 精简帧 + OLED 黑底 + 低功耗驱动），归电源态机不归帧循环；DIM = 仲裁偏好整体降一档（§6-A5）；OFF = 面板下电。AOD/OFF 实装归 v3。

### 3.4 档位周期表单源

period_ns 表值 = round(1e9/hz)，全仓唯一 const 表（落点 = 软面板模块），一切换算查表，禁各处自算除法（舍入漂移 = 两件各算各的 1ns 差，累积出相位劈叉）。FreeRange 连续域：表内 Hz 查表，表外 Hz 由软面板模块的单点换算函数统一承担（同 round 半取整）——换算单源归面板，面板模块之外仍禁自算。现存三处 16_666_666 硬编（guifbd `SOFT_VSYNC_NS`、launcher `VSYNC_NS`、berry-ui `DEFAULT_VSYNC_PERIOD_NS`）收敛义务：前两者废除；后者降格为「无服务端信息时的回退缺省」并在注释钉明。表值 16_666_667 与旧值差 1ns，无感知迁移。

## 4. 率通路（协议链）

五段贯通，add-only 纪律（ADR #60 ⑥：禁改既有变体定长）：

1. **fw_cfg**：`opt/berry/display=WxH[@Hz]`——@Hz 可选，缺省 60；值域 = 面板档位表全集（产品∪测试∪LTPO）；非法值 loud 回退 60 并打诊断行（禁静默）。内核解析处现状 `s.split('@').next()` 丢率域，收敛义务 v1。
2. **boot info VMO**：display 域尾插 `refresh_hz: u16`（add-only，不重排既有六域）。
3. **软面板持有真值**：guifbd 软面板模块（§5）持有档位表与当前档；boot 率域是它的初值输入。
4. **协议查询**：新增 hdi 域 `OP_PANEL_CAPS = 0x44`（hdi 域下一空位；不塞 present GETINFO 保留位——Q2 裁弃先例），应答携 `{ caps 版本, 档位数 N, 档位表 [hz u16, period_ns u32, class u8]×N, rate_model 位（0=Tiered, 1=FreeRange）, min_hz u16, max_hz u16, granularity_hz u16, per_frame 位, vrr 三态, hold 位, self_refresh 位, beat 归属位, 当前 current_hz u16, 当前 period_ns u32, 当前 phase_ns u32 }`（Tiered 面板 min/max = 档位表首尾语义；FreeRange 面板 = 区间边界）；hdi 域版本随之抬升。
5. **客户端注入**：berry-ui 连接后以 PANEL_CAPS 应答调 `set_vsync(period_ns, phase_ns)`（双参既有签名，语义正好落位）；首个 vblank 事件后相位精化。客户端禁缓存跨档位切换的查询结果——订阅变更事件重取。

## 5. 软面板设备（时序权威）

guest 侧帧时钟的唯一权威，QEMU ramfb 零时序语义（维护者口径）+ 宿主采样节拍 30Hz 编译常量 + virtio-gpu 无 vblank 事件三重排除后的法定出路：**guest 自合成帧时钟，升格为设备语义**。v1-v2 以 guifbd 内软面板模块实现，真硬件期换面板驱动、接口不变（一事实一归属：时序权威从服务私有常量升格为设备）。

接口四件：

- **能力面**：§4-4 的 PANEL_CAPS 应答。
- **事件面**：vsync 事件载荷法定三元组 `{ seq: u64, ts_ns: u64, refresh_ns: u32 }`（帧计数器 + 单调时间戳 + 当前周期；VRR 切档后旧 refresh_ns 立即失效）；经既有 REG_VBLANK/VBLANK_WAIT 通道投递。
- **控制面**：模式三值——FREE（自由时钟，默认）/ HOST_LOCK（宿主锁拍，真硬件 TE 对齐用，v3 留位）/ DETERMINISTIC（可复现测试模式：同输入序列产出同 (seq, ts_ns) 序列，逐位相等）。FREE/DETERMINISTIC 的 current_hz 值域随面板宣告：Tiered = 档位表；FreeRange = 区间内任意整 Hz（连续可变即此实现，1-480 仿真全连续）；FreeRange 且 per_frame 位时为逐帧驱动时钟（§7-P6），无均匀周期概念。切档请求为仲裁器内部动作：请求新档 → 生效延迟内旧周期继续 → ACK 携 `{ effective_ns, new_refresh_ns }`；生效窗内丢 1 个 vblank 合法（遥测计账）。
- **故障注入面**（fw_cfg 旋钮 `opt/berry/panel-fault`，测试专用）：丢帧率、相位抖动 ns 幅度、切档丢帧数。

## 6. 投票与仲裁

### 6.1 票面（wire 既有，12B）

`[op][sticky u8][intent u8][rsv][min_hz u16][max_hz u16][preferred_hz u16][rsv×2]`——intent 字节值域 = berry_intent 六档（ADR #58：Unspecified=0x00 / LatencyCritical=0x01 / Interactive=0x02 / Utility=0x03 / Background=0x04 / Maintenance=0x05）；幂等、无应答。现状服务端只记账不裁决（guifbd「仲裁策略挂 GUI-6+」注），收敛义务 v1.1。

### 6.2 Intent → 档位偏好映射（法定表）

| Intent | 偏好档 | 语义 |
|---|---|---|
| LatencyCritical | 能力产品档最高 | 指笔/手写类，最高优先 |
| Interactive | 120 基准 | 滚动/拖拽/动画 |
| Utility | 60 基准 | 一般 UI |
| Maintenance | 30 | 后台整理 |
| Background | 30 或停帧候选 | 不可见/空闲 |
| Unspecified | 不贡献偏好，只贡献 min/max 钳制 | 未声明 |

### 6.3 仲裁规则（编号可引）

- **A1 票生命周期**：非粘滞票随下一张票或连接关闭失效；sticky 票跨内容变化存活、断连即撤；断连撤票即时重仲裁。
- **A2 全局区间**：`G = [max(所有票 min_hz ∪ {平台底线 30}), min(所有票 max_hz ∪ {面板 max_hz})]`；`G_min > G_max` = 无解 → 取安全档 60（或面板能力内最近基准档）+ 遥测告警，禁空转不裁决。
- **A3 候选集**：Tiered 面板 = 产品档 ∩ G；测试档仅 DETERMINISTIC 测试模式可入候选；候选空 → 区间内向 60 侧最近档钳制。FreeRange 面板 = 连续区间 `[max(G_min, 面板 min_hz), min(G_max, 面板 max_hz)]`，无测试族概念（区间内任意值合法；混合 cadence 应力改用任意奇值如 26Hz 跑 §10-T5）。
- **A4 选档**：Tiered：最高优先 Intent（§6.2 序）的 preferred_hz 命中候选 → 直选；未命中 → 取 ≥ preferred 的最小候选档；preferred 超过候选上限 → 候选最高档。同优先级多票取 max(preferred_hz)；平局取高档（交互流畅优先）。FreeRange：preferred 在候选区间内直取 preferred 本身（内容锁相由连续/逐帧节拍保证，无需整数倍）；越界取区间最近侧钳制。仲裁内部以 0.01Hz 精度持有理想值，出面时按面板粒度对齐（Tiered = 档位表，FreeRange = granularity_hz）。
- **A5 迟滞非对称（升快降慢）**：升档判据连续 2 拍成立即执行；降档判据须连续满足 `T_DOWN_DWELL_MS = 1000`（可配）才执行。DIM 模式 = 整体偏好降一档后走同一规则。
- **A6 触摸加速**：inputd 触摸事件 → 立即升到 `min(120, G_max)` 基准档，超时窗 `T_TOUCH_BOOST_MS = 500`（可配）无新触摸则回落正常仲裁；boost 不越 G_max、不选测试档。
- **A7 静止停帧**：无票（或全部票 Intent ∈ {Background, Unspecified}）且无 damage 且无 armed 呈现 → 停帧（撤 vsync 定时、零唤醒、面板内容自保持）；任一条件破除即恢复当前档。guifbd 零唤醒不变量（serve deadline = min(下次拍点, 10s)，无 armed 无 parked 零调度）法定为此条的实现基线。
- **A8 LFC**：面板 vrr_capable 且 `max_hz ≥ 2×min_hz` 才启用；内容帧率跌破 G_min 时整数倍重发上一帧；条件不满足则禁用并遥测告警（否则振荡）。per_frame 模式（§7-P6）下 LFC 语义天然内含——min_interval 门控即下界、超 max_interval 由面板自刷新/重扫兜底，无需显式重发。实装归 v2。
- **A9 切档执行**：仲裁决定 → 软面板切换请求（§5 控制面），生效延迟 = 目标档 2 帧；生效前旧周期继续、已 latch 帧按旧拍点呈现；生效 ts 后旧 refresh_ns 失效。切档窗丢 1 vblank 合法（§5）。
- **A10 预告消费**：SUBMIT 的 `target_present_ns`（u64）与 `rate_hint`（u8，Hz，0 = 无预告）从「显式忽略」转为 notifyExpectedPresent 语义：预告呈现间隔密集（< 当前档周期）且最高优先 Intent 非背景类 → 提前完成升档决策，消「升档迟一帧」；30Hz 降探后的首帧延迟由此压界。v1 现状忽略两域是收敛负债，v1.1 清偿。
- **A11 平台兜底**：无任何票时——交互活跃 = `min(120, 面板产品档上限)`，无交互 = 60，静止 = 停帧（A7）。单一全屏票不得钉死全屏：全屏应用票受平台政策开关钳制（默认生效但上限 = 产品档，禁选测试档）。

### 6.4 多客户端

v1 单活跃客户端（blit-at-SUBMIT 单客户端约束承袭）；多客户端刀起票合并按 §6.3 原样扩到票集合（A2/A4 已按集合书写），窗口面积加权不做（v1 不引入，重议触发 = 多窗 SYSTEM 合成落地后实测振荡）。

## 7. 呈现语义

- **P1 Legacy-Present（v1 现状，法定过渡）**：SUBMIT 处理内同步呈现；帧率上限 = 流水线尾延迟倒数。只许存在于 v1-v1.1，v2 收敛。
- **P2 latch-at-vsync（v2 默认）**：SUBMIT 携 target_present_ns → 帧在 ≤ target 的最近拍点呈现；双缓冲默认、管线深度策略每应用可调（延迟 = 级数 × 最长级；深度 1 为延迟最优极端，升档流畅与降延迟的取舍归应用声明）。
- **P3 呈现回执**：新增 present 域 `OP_FRAME_TIMING = 0x07`（present 域下一空位；FRAME_CALLBACK 16B 定长禁改——add-only 纪律），应答 `{ frame_token u32, presented_ns u64, seq u64, refresh_ns u32, flags u8 }`；FRAME_CALLBACK（token 终态阻塞回执）保留不变。berry-ui jank/deadline_miss/spinup_late 遥测的合法消费者 = 本回执（现状遥测无消费者，v1.1 清偿）。
- **P4 断言锚**：一切时序断言锚 guest 钟的 presented_ns 序列（§5 事件面同源时基）；宿主观测（截图、VNC 帧）不作时序证据。
- **P5 PREPARE/COMMIT**：既有 hdi 两 op（进槽/提交到目标时刻）为 P2 的执行面留位，v2 随 latch 一起实装语义；v1 仍为空壳合法。
- **P6 变节拍呈现（FreeRange per_frame，v2）**：panel follows host——每帧拍点独立 = `max(上一扫描开始 + min_interval_ns, target_present_ns)`；帧就绪即触发扫描，无均匀周期假设，presented_ns 序列即节拍真相（vblank 事件 refresh_ns 逐帧可变）；内容低于面板 min 率时帧间隔自然拉开（内含 LFC，A8），超 max_interval 无新帧 → 面板自刷新/重扫上一帧，停帧语义（A7）不变。这是「1 到 N 随便可变」的逐帧形态，也是延迟下界形态（帧就绪即上墙，仅让 min_interval）。

## 8. 内核时间底座

- **K1 忙核高精度定时**：超时摘除不得只靠 10Hz slice tick——授片处取 min(最早超时, 片终点) 的既有承诺（timer.rs 自注）落地为义务；预算 = 忙核上任绝对定时唤醒误差 p99 ≤ 500µs（真机）/ ≤ 2ms（TCG）。现状忙核 sleep 最迟 100ms（TCG 约 200ms）才醒，比 60Hz 帧间隔粗一个量级，是体系最硬缺口，v2 清偿。
- **K2 定时 slack 与唤醒合并**：定时器可携 slack_ns，内核同窗合并唤醒；默认 slack 50µs，拍点类定时（vsync/帧循环）slack = 0，LTPO 低档期聚合窗可配（默认 1ms）——降档省电的一半在少醒，散布定时聚合是停帧之外的第二战场。
- **K3 时基唯一**：全系统唯一时基 = CNTVCT（62.5MHz）换算的单调纳秒；EL0 直读合法（CNTKCTL.EL0VCTEN 已开）；`sys_clock_read` 为规范读入口；跨件比对时序必须同源此钟。
- **K4 帧线程调度带**：帧循环/呈现线程推荐入 EDF deadline 带（sched policy=3，period = 当前档周期，budget = 渲染预算），随档位切换同步改 period；v1 推荐级、v2 起法定。

## 9. 应用面规则

- **AP1 投票是 advisory**：应用不得假设投票必胜、不得为提频空转刷票；每窗口或声明票或显式 Unspecified，禁隐式默认顶档。
- **AP2 固定时步**：动画/物理仿真与渲染解耦——仿真 dt 恒定（基准 1/120s，不随档位变），渲染按拍点插值；60→120→LTPO 切档动画时长不变（时长不变性是验收项 §10-T5）。
- **AP3 时长整帧量化**：动效时长按当前档量化为整帧数（250ms → 60Hz 15 帧 / 120Hz 30 帧），禁小数帧尾抖。
- **AP4 帧回调 Choreographer 形**：帧回调附本帧 deadline_ns 与预期呈现拍点（OP_FRAME_TIMING 订阅）。
- **AP5 刷新率查询与订阅**：经 PANEL_CAPS 查、经 vblank/切档事件订阅；禁硬编、禁缓存跨切换结果（§4-5）。
- **AP6 可复现性**：DETERMINISTIC 模式下同输入序列 → 同帧序列；frame seq 全链路贯穿（app 产帧号 = guifbd presented seq），AI 测试回放可断言（§10-T6）。

## 10. 测试与验收门

- **T1 仲裁决策表**：host 单测钉板票组合 → 期望档全分支（Intent×sticky×区间冲突×触摸窗×DIM），每条 A 规则至少一正一负例。
- **T2 回放门**：DETERMINISTIC 模式同输入序列 → (seq, ts_ns) 序列逐位相等。
- **T3 拍点误差门**：presented_ns 序列统计——60Hz 拍点间隔误差 p99 ≤ 500µs（TCG ≤ 2ms）、120Hz ≤ 250µs（TCG ≤ 1ms）；jank 遥测消费后此门自动化。
- **T4 切档平滑门**：切档窗丢 vblank ≤ 1、seq 无重复无跳号、生效 ts 前后周期值与 ACK 一致。
- **T5 混合 cadence 门**：Tiered 测试档 165/180 下 AP2 固定时步动画时长不变、无累计漂移（非整除分频的应激测试即测试档存在的意义）；FreeRange 变体：per_frame 下 26fps 非整除内容率逐帧锁相零 judder、时长不变。
- **T6 seq 贯穿门**：app 帧号 = FRAME_TIMING 回执 seq = vblank 事件 seq，全链路一号到底。

## 13. 适用边界

本规范立法目标态；现状三无（无通路/无锁钟/无仲裁）的实证与外部依据归 survey，各条「收敛义务」的执行归刀谱。仿真判决限 QEMU ramfb 与 virtio-gpu 现行规范（QEMU 侧未来新增带时序语义的显示设备不改变软面板的权威地位——HOST_LOCK 是它的对接口）。外部数据（省电比例、人因阈值）为厂商口径与社区实测，非 BerryOS 实测。主树 guifbd 三文件重构后，本规范引用的现状锚点（SOFT_VSYNC_NS 等私常量名）按概念迁移不按文件形态。
