# BerryOS 版本管理标准

Type: standard
Status: current
Updated: 2026-11-10
Version: 1.0.0

一句话说明：五条版本轨道各管一个承诺，构建标识管唯一性——**改承诺才动号，每次构建动哈希；哈希永不当版本用，版本永不当迭代号用**。本标准是全系统版本行为的唯一裁决（调研依据 → `research/VER-01`；首档落地 → 沿革一七六/一七七）。

## §1 五轨道总表

| 轨道 | 单源 | 形态 | 管什么承诺 | 消费面 | 执法 |
|---|---|---|---|---|---|
| **系统版本** | 根 `Cargo.toml` `[workspace.package]` | SemVer `MAJOR.MINOR.PATCH`（0.y.z = 开发期无承诺） | 整机产物的里程碑身份 | boot banner、git tag `v*`、镜像命名 | G-ver-2/3/4 |
| **平台 API level** | `tools/abi.toml` `[platform]` | 单调整数（初值 1） | 应用可见 ABI 的兼容承诺——**不兼容变更 +1，兼容新增/内部重构不动** | berry-sys 常量、svcmgr 装载检查、`.bap` `min_level`、mkapp 打印 | G-ver-1/5 |
| **构建标识** | `kernel/build.rs` 运行时取 git | `<short-hash>[-dirty]`（无 git = `nogit`） | 唯一定位一次产出（崩溃归因/对账）——**无兼容语义、不参与比较** | boot banner、smoke 日志头、kfile 对拍显式化 | G-ver-2 |
| **安全级** | `tools/abi.toml` 预留位（启用随首个安全公告） | 整数（SPL 同构） | 安全补丁集身份——正交于功能版本 | BCTS 承诺面（ADR #82）、OTA | 启用时立 |
| **生态包** | 各 crate `Cargo.toml` / `.bap` manifest | SemVer | 包间依赖与产物记录 | mkapp 打包行、cargo、（v2）包管理 | SemVer 自律 |

**配对律**：一次可发布产物 = 五元组各取一值（`系统版本 (level, 安全级, 构建标识, 包集)`）；跨轨道组合合法性由配对裁决（v1 = 系统版本 + level 二元组够用；v2 OEM 三包四层扩全元组，VINTF 同构、BCTS 只测承诺面）。

## §2 走速决策表（动什么 → 动哪个号）

| 改动 | 系统版本 | level | 构建标识 | 备注 |
|---|---|---|---|---|
| 内部重构/优化/测试/文档 | **不动** | 不动 | 动（每 commit） | 迭代烧哈希不烧号——号段永远够 |
| syscall 加号（add-only、stage 内） | 不动 | 不动 | 动 | nr_defined 37→41 余量内，属内容清单非承诺变更 |
| syscall 语义不兼容变更 / 删号 | minor +1 | **+1** | 动 | level 是对外承诺的名字（规则/03「ABI 轨道」节） |
| 兼容的新 API 面（新协议 crate/新口） | minor +1 | 不动 | 动 | 首例：app-2 三口未 + level |
| 里程碑（G 关卡过 / 域收官） | **minor +1 + tag** | 按需 | 动 | tag = 该里程碑的可引用锚 |
| 承诺不变的修复集发版 | patch +1 | 不动 | 动 | 0.x 期少用；1.0 后常规 |
| SDK 冻结 | **1.0.0** | **冻结** | 动 | 三同步门（§4） |
| 安全补丁集 | patch +1（1.0 后） | 不动 | 动 | 安全级 +1（启用后） |

0.x 期 minor 烧快是**正确信号**（每跳 = 真里程碑）；到 0.99 直接跳 1.0（SemVer：1.0.0 = 公共 API 冻结起点，恰为我们 SDK 冻结日）。禁止为「感觉该升了」动号——表中左列无对应行的改动一律不动。

## §3 执法面（硬门，全机器）

- **G-ver-1（level 单调）**：`tools/gen_abi.py --check` 对比 git HEAD 的 `[platform]` level——**只增不减**；减号即红。selftest 钉形状（≥1 整数、bool/缺段拒）。
- **G-ver-2（banner 一致）**：banner 版本串编译期取 `env!("CARGO_PKG_VERSION")`（同源保证）；smoke 裸相首行断言 banner 形态 `BerryOS boot <semver> (<ident>)`——形态缺即红。
- **G-ver-3（tag 一致）**：`v*` tag 指向的提交，其 banner 版本必须等于 tag 名（`just ver-check` 验收脚本）；不一致即红。
- **G-ver-4（发版净树）**：打 `v*` tag 时工作树必须 clean——banner 含 `-dirty` 的提交禁止打版本标。
- **G-ver-5（装载门）**：`min_level > 平台 level` 的 `.bap` 拒装载（svcmgr `lvl min` 降级行，已执法）。

新门挂载：G-ver-1 进 abi-check（既有五面单源检查顺带）；G-ver-2 进 smoke 首行；G-ver-3/4 进 `just ver-check`（发版前手跑；脚本门已轻挂 CI fail-fast 位——沿革一八一复审：秒级零 QEMU 带宽例外，QEMU 类门仍不挂）。

## §4 升 1.0 三同步门

SDK 冻结日：系统版本 → `1.0.0`、平台 level → 冻结值（此后 +1 仅随不兼容变更，且必须 minor +1 同批）、syscall 号表 → 37 实现全兑现承诺面。三者同批同 commit，缺一即 1.0 不成立。

## §5 v2 预留（不在 v1 执法）

- OEM 配对矩阵：三包四层（ADR #82）按五元组配对，BCTS 扩版本配对断言。
- LTS 轨道：届时按生态压力裁（单仓单链默认单轨滚动）。
- CalVer 发版轨（YY.MM）：1.0 后若需时间感知再加，兼容承诺仍只挂 level。

## §6 边界与豁免

- **不管**：文档版本（`docs/` 自有 `名-v主.次` 制度）、沿革条号/ADR 号/判例号（过程标识非产物版本）、Cargo 生态 crate 内部 0.y.z（SemVer 自律域）。
- `nogit` 标识产物**不得**对外发布（无归因能力的构建仅限本地调试）。
- 本标准自身演进：原地改 + `Version` 递增（MAJOR = 不兼容、MINOR = 兼容新增）；调研与提案链 → `research/VER-01`。
