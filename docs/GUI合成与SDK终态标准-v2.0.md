# GUI 合成与 SDK 终态标准（v2.0）

Type: standard
Status: current
Updated: 2026-11-18
Version: 2.0.0

一句话说明：本标准定义 BerryOS 全项目跨模块及面向第三方应用开发者的图形显示合成、色彩与文字排版、响应式 UI 设计系统、应用 SDK 契约、无缝启动体验与模拟器交互的最高现行规范。

## 背景

早期过渡架构在多客户端并发隔离、离屏窗口合成、Alpha 混合画质、多语种字体排版、高分屏密度自适应及模拟器帧率上存在系统性局限（事实诊断见 [GUI 与 SDK 及启动模拟器全栈深研](../.agents/research/2026-11-18-GUI与SDK及启动模拟器全栈深研.md)，架构取舍见 [图形合成与 SDK 及模拟器终态架构裁决](../.agents/notes/proposed/2026-11-18-图形合成与SDK及模拟器终态架构裁决.md)）。本标准与底座 [微内核与全栈底座彻底重构规格](../.agents/plans/2026-11-18-微内核与全栈底座彻底重构规格.md)、[显示与加速体系设计](显示与加速体系设计-v1.1.md)、[刷新率体系规范](刷新率体系规范-v1.0.md) 及 [桌面沉浸式设计规范](桌面沉浸式设计规范-v1.0.md) 共同构成用户面与开发者面的权威契约。

## 适用范围

- **适用对象**：`berry-compositor` 显示与窗口合成服务、`berry-gfx` / `berry-text` / `berry-ui` / `berry-sdk` 客户端框架、`softimed` 输入法服务、`berryboot` / `bootsplashd` / `berry-shell` 启动与桌面壳层、`tools/berry` 宿主模拟器，以及所有官方与第三方 `.bap` GUI 应用。
- **与模块设计的边界**：本标准规定跨进程协议不变量、视觉/坐标/色彩公共度量、应用生命周期与 SDK 对外契约；各子系统内部数据结构、锁与算法实现分别归属 [compositor 总体设计](../.agents/plans/compositor/design.md)、[ui-sdk 总体设计](../.agents/plans/ui-sdk/design.md)、[desktop-boot 总体设计](../.agents/plans/desktop-boot/design.md) 与 [emulator 总体设计](../.agents/plans/emulator/design.md)，不在此重复双写。

## 契约

### 一、会话隔离与窗口表面协议铁律

1. **严禁跨进程共享客户端通道（Session-per-Client）**：任何 GUI 客户端、输入法与桌面壳层必须经由 `ProcessArgs v2` 授予的能力工厂铸造独占 `SurfaceSession` 通道连接合成器；严禁将同一客户端 `Channel` 端点的 `SEND | RECV` 副本分发给两个进程。客户端终止触发 `SIGNAL_PEER_CLOSED` 时，合成器必须在单帧周期内自动回收其全部窗口、交换链映射与焦点状态。
2. **按需尺寸交换链与显式栅栏同步（Swapchain & Fence）**：
   - 客户端表面缓冲 VMO 尺寸必须严格匹配合成器 `Configure` 下发的窗口目标像素宽高，严禁非全屏组件强制分配整屏分辨率缓冲；
   - 表面采用 2 或 3 槽交换链轮转，合成器侧仅以只读权限（`UserRo`）映射客户端 VMO；在某缓冲槽被合成器 `release_event` 显式释放前，客户端严禁原地覆写该槽像素（零画面撕裂契约）；
   - 无内容变更时严格执行三态停帧（`RUN → SETTLE → IDLE`），`IDLE` 态禁止提交空脏区帧或维持轮询定时器。
3. **单跳定向输入与唯一键盘焦点**：一切指针事件由合成器按实时场景图命中与窗口逆变换折算为目标表面局部坐标后单向投递（按下后粘滞捕获直至抬起或 `Cancel`）；一切物理键盘按键与输入法 `Preedit/Commit` 事件 100% 仅投递给当前唯一获焦表面，后台失焦窗口零输入可见性。

### 二、色彩、抗锯齿渲染与全球化文字契约

1. **一等预乘 Alpha 色彩模型**：全图形栈标准像素格式为 32 位小端预乘 `BGRA8888 / RGBA8888`（各色彩通道值 `<= Alpha`）；所有圆角、斜线、图标缩放、阴影与半透明图层必须具备 8-bit 覆盖率抗锯齿与 Porter-Duff `SrcOver` 混合能力，淘汰全管线 1-bit 透明键退让假设；应用图标资产包格式（`BYI2`）必须完整保留 8-bit Alpha 通道。
2. **UTF-8 多语种与矢量字体渲染**：UI 引擎与终端组件必须原生接受合法 UTF-8 字符串（废除仅限 ASCII `32..=126` 约束），通过共享只读系统矢量字库与 8-bit 灰度抗锯齿字形缓存渲染拉丁、符号及中日韩（CJK）字符，遵循 Unicode 断行与标点避头尾规则。
3. **端到端输入法（IME）交互**：所有可编辑文本组件获焦时必须声明输入类型并实时上报光标屏幕包围盒，完整支持 `Preedit` 组合态高亮、选词 `Commit` 上屏及软键盘动态升降时的安全区平滑避让。

### 三、虚拟像素（`vp`）、沉浸式安全区与响应式设计系统

1. **唯一几何度量单位 `vp`**：SDK 公开 API、标准组件内在几何、圆角、字号与布局间距一律使用与物理分辨率解耦的逻辑单位 `vp`（`px = round(vp * density_q8 / 256)`，手机 1080×1920 基准档 `density = 3.0` 即 `360×640vp`）；严禁在组件库或业务代码中硬编码未乘密度的物理像素值；可点击/可触控热区的最小物理/逻辑下限不得低于 `44vp × 44vp`。
2. **Edge-to-Edge 全屏贯通与动态 `Insets` 避让**：
   - 应用窗口默认延伸至屏幕四边物理边界（顶栏与底部手势条背景透明直透，桌面视觉细则遵守 [桌面沉浸式设计规范](桌面沉浸式设计规范-v1.0.md)）；
   - 合成器通过 `Configure` 与 `DisplayMetricsChanged` 动态下发唯一权威四边安全区 `Insets { status_top, nav_bottom, cutout_left, cutout_right, ime_bottom }`，严禁客户端或服务端跨文件硬编码系统栏像素高度；
   - 状态栏前景符号必须随底层窗口顶部区域亮度自动切换深浅反色，保证对比度恒 `>= 4.5:1`。
3. **三档响应式布局与免重启热切屏**：应用布局必须基于 `Compact (< 600vp)`、`Medium (600..840vp)`、`Expanded (>= 840vp)` 宽度断点与弹性约束构建；当屏幕旋转、分屏或切换显示档位触发 `DisplayMetricsChanged` 时，应用必须在原组件树上动态重排提交新尺寸交换链，严禁要求重启进程或整机。
4. **物理连续动效与可中断性**：页面转场、软键盘升降、抽屉弹出一律采用与刷新率解耦的物理弹簧模型（携带手势松手初速度，支持运动途中随时被新触摸手势抓回或重定向目标 `retarget` 连续过渡，零位置/速度阶跃）；遵守用户级「减弱动态效果」无障碍偏好。

### 四、应用 SDK、生命周期与全栈返回契约

1. **零样板异步单环模型**：GUI 应用统一通过 `berry-sdk` 的 `#[berry_sdk::app]` 与基于内核 `Port` 的 `AppLoop` 编写，支持在同一非阻塞事件循环内挂载任意数量自定义 IPC 通道、高精度定时器与异步 I/O 任务；文件读写、网络传输与子进程等待严禁阻塞 UI 渲染主线程超过 `8ms`。
2. **分级返回协议（Predictive Back）**：系统返回动作（侧滑边缘手势或导航栏返回键）严禁由桌面直接向窗口发送外部强拆 `DESTROY`；必须遵循「收起软键盘 → 关闭系统浮层 → 应用内导航栈/弹窗消费 `BackGesture` 后退 → 根页面窗口平滑缩回桌面图标并转入后台冻结」的四级契约。
3. **后台冻结与墓碑无感恢复**：应用退入后台失焦后必须响应 `appd` 生命周期指令：在 `Freeze` 前停止一切动画与重绘，在 `Tombstone` 回收前将页面栈与 `Signal` 持久态序列化至 `≤ 64KiB` 状态容器，保证用户从多任务视图重新点开时无感还原现场。
4. **开发者友好打包与强制签名门禁**：源码态 `manifest.toml` 允许标准 TOML 注释与排版，由打包工具编译为包内规范清单并附带 Ed25519 分离签名；生产态 `appd` 对缺签名或验签失败的 `.bap` 包 100% 拒载。

### 五、开机引导与宿主模拟器体验契约

1. **零黑屏零测试污染启动**：从 UEFI 固件首屏点亮品牌徽标、早期用户态 `bootsplashd` 60Hz 局部增量平滑进度条，到 `compositor` 交叉溶解揭幕桌面，全链路不得出现全屏清黑闪烁或静止假死；一切内核与用户态自检代码严禁在生产默认启动路径执行。
2. **宿主模拟器高帧率与亚秒级速启**：桌面交互开发模式下宿主模拟器采用共享内存纯脏区驱动 + 宿主 GPU（`wgpu`）呈现，帧率上限对齐客机面板档位（60–120fps+），静默停帧态宿主空载 CPU 占用 `< 2%`；支持同构架构硬件加速（HVF/KVM/WHPX）与 Golden Snapshot `< 500ms` 秒级唤醒。

## 版本与兼容

- **MAJOR（2.0.0）**：确立每客户端独立会话交换链、8-bit 预乘 Alpha、全 `vp` 响应式组件树与 `ProcessArgs v2` 能力注入，不向后兼容 v1 过渡期的共享 `WMD_CLI_DUP` 单队列、`SYS_SURFACE_ID=0xFFFF` 全屏直刷与 1x 固定像素 `ViewKind`。
- **MINOR**：向后兼容新增标准组件、新增主题语义 Token、新增 `berry-guiproto` v2 扩展消息或模拟器生产力桥接通道。
- **PATCH**：契约措辞澄清、性能阈值校准与文档链接维护，不改变任何二进制协议或 API 签名。

## 适用边界

- 机器检查（`check-docs.mjs` 与 `docs_guard.py`）仅校验本标准的头块、版本前缀与索引完整性；协议安全性、渲染像素精度、帧率预算与无泄漏不变量分别由 `*face` 宿主机性质测试、BCTS 兼容性套件、golden 像素哈希门禁及 HVF/KVM 实机压测强制执法。
