## 0. 为什么要有这套东西

**测量是优化的前提，测试是系统的镜子**——没有基线数字，任何「变快了/
变慢了」都无法证明；没有严格断言，性能劣化会被「smoke 照样绿」掩盖。
业界的分层参照：

| 层 | 考什么 | 别人的代表 |
|----|--------|-----------|
| 功能正确性 | 行为对不对 | Linux LTP/selftests/KUnit、seL4 sel4test、Zircon core-tests |
| 压力/稳定性 | 长跑/耗尽/风暴下不崩不漏 | stress-ng、hackbench、soak test、内存 churn |
| 性能基准 | 微基准（单操作）+ 宏基准（整体） | **lmbench**（30 年标准）、seL4 sel4bench、Phoronix |
| 实时性 | 唤醒→运行延迟分布（p99/最大） | **cyclictest**（PREEMPT_RT 验收标杆） |
| 鲁棒性/安全 | 畸形输入/故障注入/越权 | syzkaller、fail-injection（挂 v2，`测试策略-v1.0.md` §6） |

BerryOS 现状（2026-10-25）：功能层厚（五跑 smoke + host 326 测 + ktest +
smoke-x86/smoke-image 两独立关卡，确定性设计是强项）；性能/压力/实时三层
此前只有种子（fa_ping/fa_pong IPC 周期对、遥测环、switches 金丝雀、
`just size`）——**本设计把这三层从零补成体系**。

微内核界的头条数字 = IPC 往返延迟（L4 家族横评 30 年打的都是它）；
BerryOS 的宣称维度（`优化议程-v1.0.md` §4）= IPC 延迟 / 尾延迟 / 隔离 / 启动 /
空载零唤醒——**每个宣称维度都必须有对应的基准项**，否则宣称即空头支票。

## 2. 测量口径纪律（三条铁律）

1. **CNTVCT 原始周期数，不换算 ns**。TCG 下 CNTV 推进 ≈ `CNTFRQ/2`
   （`测试策略-v1.0.md` §2 已知坑）——绝对值只做**同机同 QEMU 的相对比较**；
   换算成 ns 是假精确，跨机器（本地 mac vs CI ubuntu）绝对值不可比。
2. **确定性归确定性，统计归统计**。泄漏金丝雀（帧水位/handle 槽位精确
   归位）是确定性断言 → **严格执法**（≠0 即 panic，进「主干永远绿」红线）；
   计时数值是统计量 → 只做宽松因子门禁（拦数量级劣化），**禁止**在非
   `-icount` 下做紧数值断言（`测试策略-v1.0.md` §7 时序断言纪律）。
3. **机器可读，AI 可消费**（设计总原则 3）。一切输出行有稳定格式
   （`BENCH,<name>,<iters>,<cyc_per_op>`），基线是纯文本进 git，diff 即
   演进史——AI agent 能自己跑、自己比、自己报「这次退步了」。

## 3. B-0：内核微基准（已落地）

**位置**：`kernel/src/bench.rs`，`ktest::run()` 之后、`timer::init`/
`berry_sched::init` 之前的干净窗口——单线程、IRQ 屏蔽、分配器已活、
零调度噪声。**每次 boot 都跑**（金丝雀是红线不是可选；基准顺带收割）。

**六项基准**（`BENCH,<name>,<iters>,<cyc_per_op>` 行 × 6 + `BENCH ok n=6`）：

| name | 测什么 | iters |
|------|--------|-------|
| `cntvct_pair` | 测量基线：cntvct 读对 + 循环骨架开销（其余项减它 = 净成本） | 4096 |
| `frame_alloc4k` | buddy 单页分配+释放往返（最小阶全链） | 1024 |
| `frame_alloc64k` | order-4（16 页连续块）分配+释放——拆块/合并路径 | 256 |
| `vmo_commit1p` | 单页 VMO 全生命周期：create+commit（含 4KiB 清零）+drop | 256 |
| `vmo_rw4k` | 已提交页 4KiB write+read 往返（syscall 拷贝成本下界） | 128 |
| `handle_evt` | Event 经 handle 表全生命周期：insert+get（查表热路径）+close | 1024 |

**不测什么（边界）**：EL0 视角的 syscall/IPC 往返（含 SVC 陷阱开销）内核内
测不了——留 B-1 用户态基准程序（rootfs 生态，fa_ping/fa_pong 的编译化
升级）；缺页处理延迟要 demand paging（v2+）；SMP 扩展性要 G2。

## 4. S-0：churn 泄漏金丝雀（已落地，随 B-0）

**原理**：分配器对账口径 `mm::frames().allocated_pages()`（B-0 新增——
按块头 `2^order` 累计，尾页 TAIL/保留页 RESERVED 不计）+ handle 表
`used_count()`。反复创建/销毁后**精确归位**：

| 金丝雀 | 模式 | 断言 |
|--------|------|------|
| frame | 混合阶 0/2/4 交错分配、逆序释放 × 64 轮 | 每轮水位 == 基线 |
| vmo | 64KiB VMO create+commit+write+drop × 64 轮 | 每轮水位 == 基线（Vmo::Drop 还帧链） |
| handle | 私有表 32 槽 insert/close × 64 轮 | used_count 0↔32 精确翻转；帧水位恒等 |

**首跑实录（方法论价值）**：handle 金丝雀首版假阳性 +1 页——预热轮缺位
（首轮 slots Vec 懒增长合法向堆要一页）。修法 = 预热一轮再取基线。
教训：**水位断言的基线必须取在「所有一次性分配已发生」之后**；
真泄漏是每轮 +N，一次性 +1 是懒分配——量纲可分辨，别急着当 bug 报，
也别放过。

**输出**：`BENCHCHURN ok frame=0 vmo=0 handle=0`（状态谓词——三项严格
断言过了才打；≠0 即已 panic，见 smoke 红线）。

## 5. 门禁分级（G 线）

| 级 | 什么 | 挂哪 | 执法 |
|----|------|------|------|
| **L0 严格** | churn 金丝雀 = 0、`BENCH ok n=6` 到齐、`BENCHXH ok` 六面耗尽/复位对账（S-2——行在 = smoke grep；任一断言破 = 打印前 panic）、`BENCHWAKE` 形状断言（行在 = smoke grep；n>0、min≤max = 打印前 panic 执法；负延迟 = on_wake 写点 panic——R-0）、`B1 ok n=4` 格式断言收口（B-1——bsh 断言破 = 不打标记，行在 = smoke grep） | `just smoke`（每 boot 必跑） | panic / FAIL——进「主干永远绿」红线 |
| **L1 宽松** | 六项内核数值 + 四项 EL0 数值（`--el0`）≤ 基线 × 3（拦数量级劣化） | `just bench`（手动/可选 CI 夜跑） | bench.py 退 1 |
| **L2 紧**（B-2 ✅） | 六项 -icount 指令数代理对拍 `bench_baseline_icount.txt`：ICOUNT_TOL=0.0 = **逐值精确相等**（证明 verdict=exact 定标；若漂移重证明得 drift 则降 ±5% 双侧带——双向漂移都 FAIL，变快同样是异常） | `python3 tools/bench.py --icount` / `just bench-icount` | bench.py 退 1 |

L1 因子 3.0 的依据：TCG 计时 run-to-run 实测漂移 ~±10%（五跑定标），
3x 拦「算法回退/误入慢路」类数量级劣化而绝不误伤噪声。紧门禁（L2）
**必须**先证明 -icount 下逐值稳定（六项 (iters,cyc) 逐项相等）才准上
——证明义务在提案方。

**L1 历史宽松基线注记（K-1 处置刀定案）**：`frame_alloc64k` 的 vanilla
基线 6034 是慢带时代（B-2 立档时 buddy 空扫潜伏病未愈）实测入册的，K-1
修复后现值 ≈15——3x 门 ≈18,102 对「回归到 ~6k 慢带」**结构性无效**
（慢带恰在门内）。该指标的权威守卫 = **icount L2 精确相等门**（基线 33，
任何指令流变化即 FAIL——K-1 期间慢带内核 29,127 一跑即被抓住）；vanilla
门对它只拦比慢带更差的劣化。其余五项基线均快带立档，无此注记必要。

**基线管理**：`tools/bench_baseline.txt` 进 git（**双段**：B-0 裸 CSV 段 +
B-1 `BENCH1,` 前缀段，行前缀区分互不 wipe）；刷新流程 = 改内核/改 bench1 →
`python3 tools/bench.py [--el0] --update`（**只刷本段、另一段原样保留**）→
diff 随源入册（**漂移须在 commit message 里给归因**——「为什么变快/变慢」
是演进史的一部分）；基线缺席 = 对拍跳过（首跑只出表），不算过门禁。

## 7. 设计公约（六把挂账刀共用）

以下七条是 B-1/R-0/R-1/S-1/S-2/B-2 落刀时**必须遵守**的公约（多数是既有
Gotcha 的再引用——违反任何一条都会重踩已归档的雷）：

1. **标记 = 状态谓词，非竞速结果**（4-5a 铁律）。每个新标记先答：这是状态
   谓词还是竞速结果？统计数值（p50/cyc_per_op）**永不**当 smoke 标记——
   smoke 只断「行在、格式对、形状恒真」（如 p50 ≤ max、n > 0）。
2. **确定性归确定性，统计归统计**（§2 铁律 2 的刀级细化）：确定性断言
   （水位归零、错误码精确、oversleep ≥ 0）进 smoke L0；数值只进 `just bench`
   L1 宽松因子。**禁止**在非 -icount 下做紧数值断言。
3. **内核常驻/基准任务睡眠面零受捐**：①`spawn_with_tag` 私有表（4-5 PI
   错捐雷）；②睡眠面判据 = `pi::donor_edge` 摸不到你——**私有表内单哑
   Event 的 wait_one 用户位等待**（ai_probe 在册形态，4-6）与 **共享表上
   wait_many 哨兵 + 哑 Event 对照项**（console 形态，4-5a）皆合法，直睡
   channel 派生位才违规；③新用户位**先登记 `kernel/src/main.rs` 的
   `USER_SIGNAL_BITS`**（现役至 1<<39 RX Event；R 线起用 1<<40 起，逐位
   递增）。
4. **输出行机器可读 + 单行 ≤192B**：单消息原子（>192B 经 console 分片会被
   稳态矩阵撕行，d-3c 雷）；每行一个 CSV 形态 `TAG,k1=v1,k2=v2`，AI 可消费。
5. **TCG 半率口径**：δ/时长一律用 **CNTVCT 周期数**定义（不走 ns 换算——
   `sys_clock_read` 的 ns 是 CNTFRQ 名义换算，TCG 下失真 2×；换算舍入还会
   污染 oversleep 精度）；ns 只在展示层。
6. **boot 窗口纪律**（bench.rs 窗口 = ktest 后、timer/sched init 前）：单线程
   + IRQ 屏蔽 = 该窗口内做资源耗尽/全帧占用是安全的（无并发分配者）；
   但任何需要睡眠/调度的基准（R-1/S-1 心跳）必须做成 sched init 后的
   内核任务（fa_ping 同型），不得塞 boot 窗口。
7. **kill criteria 全线继承**：新增基准使 boot 开销 >5s 或 smoke 五跑总时长
   劣化 >10% → 削迭代数或挪专属通道（`just bench-*` 族）；测试基建不许
   拖累「主干永远绿」的周转。

## 8. B-1：EL0 用户态基准（已落地 2026-10-26）

**目标**：EL0 视角的 syscall 真路径成本——SVC 陷阱、handle 查表、权利检查、
用户缓冲拷贝。内核内测不了异常级往返（B-0 边界），这是补上它的刀。

**形态**：`user/bins/bench1/`（stdhello 同链 std 面，栈 32 页——run_capture
口径，见落地实录）编译入 rootfs；bsh 内建命令
`bench1`（u2/u3_selftest 同型）：bsh 经 `berry-exec::SpawnSpec` spawn
bench1.elf，`stdout` 传**私有通道对端**（d-3c 收集面——BENCH1 行逐行收齐
格式断言后才打标记；全表 relay console 只是化妆面）。

**四项基准**（bench1.elf 内联，单进程自足——vmo/channel 经 syscall 自造，
**零新管道**）：

| name | 测什么 | iters | 形态 |
|------|--------|-------|------|
| `sys_null` | `clock_read` 往返 = SVC 陷阱 + 派发 + 最薄 handler 全链下界 | 4096 | t0/t1 夹 N 次调用 |
| `sys_vmo_rw4k` | syscall 面 4KiB vmo_write+read = 查表 + 权利 + 用户缓冲拷贝全链 | 128 | 自建 VMO commit 后循环 |
| `ipc_enqueue8` | 自持双端 channel：send×8 填满（慢路入队）+ recv×8 排空 | 128 | 无等待者——纯 enqueue/dequeue 成本 |
| `evt_signal` | `object_signal`(用户位) + `object_wait_one` poll 命中 | 1024 | 用户位对象操作对 |

**输出**：每项一行 `BENCH1,<name>,<iters>,<cyc_per_op>`（≤192B 单消息原子）
→ 全部过格式断言后 bsh 打原子标记 **`B1 ok n=4`**。计时基准同 B-0 口径
（CNTVCT 周期，TCG 半率，相对比较）。

**边界（v1 不测什么）**：**fastpath 往返**（有阻塞等待者的唤醒+直切链）需要
双任务——v1 单线程/进程，单进程结构性打不出；内核侧已有 fa_ping/fa_pong
IPC 周期对覆盖机制面，EL0↔EL0 fastpath 往返留 **B-1b**（svcmgr 造 channel
对 + 双 spawn 的管道面，随 appd 演进）。上下文切换成本被 ipc/RT 线间接覆盖。

**门禁与基线**：`tools/bench.py` 扩 `--el0` 模式（run-rootfs 形态 QEMU +
echod 免挂——B-1 无网络面）收割 BENCH1 行；基线 = `bench_baseline.txt` 同
文件**双段**（B-0 段 + B-1 段，行前缀区分），刷新流程同款。smoke 侧只挂
`B1 ok n=4` 存在断言（rootfs 相 27→28，**两标记表同步纪律**）。

**依赖**：无（SpawnSpec.stdout/args、bsh spawn、std musl 产链全在册——
无 elf2flat，见落地实录）。

**落地实录（实现取舍，与设计表的差异注记，2026-10-26）**：

- **产链走 std musl 面，无 elf2flat**：`user/bins/bench1/`（stdhello 同链
  ——berry-libc shim + berry-ld 剥 musl crt；std ELF 本体直进 cpio，
  设计表的 elf2flat/8 页栈描述按在册产链修正）。**栈 = run_capture 口径
  32 页**（uu 家族定值）：复用 bsh 既有 spawn 路径零新代码 + d-3c std 栈
  机器 32 页实踩背书——设计原文「栈 8 页」弃用（取舍：零新面优先）。
- **计时 = EL0 直读 `mrs cntvct_el0`**（镜像 arch/aarch64 timer.rs 形态，
  公约 5 落地）；**边界**：EL0 读 CNTVCT_EL0 需 CNTKCTL_EL1.EL0VCTEN=1
  （EL2 场另需 CNTHCTL_EL2.EL0VCTEN）。落地实录（首跑实踩）：复位 0 =
  EL0 读即 EC=0x18 陷阱 → user_fault_exit 静默杀（**fault 杀码 0 + 无
  EOF**——「code=0 eof=false len=0 跑完却零输出」死状，排障靠串口
  EXCEPTION dump 定位）——**kernel timer init 显式开 EL0VCTEN**（Linux
  同款 enable，RMW 保位、只开虚拟计数器位）为 B-1 前置修复随刀入册；
  run-el2 裸跑（virtualization=on）无 rootfs 不触本程序（文档化边界）。
- **evt_signal 用户位 1<<32 不登记 USER_SIGNAL_BITS**：Event 为进程私有
  （自造、仅自 wait、随进程销毁）——无跨任务等待面/碰撞面，ktest 瞬态位
  先例同理（登记义务约束内核任务等待面）；不占 R 线 rt_probe 预留 1<<40。
- **ipc_enqueue8 拓扑**：send 走 A 端、recv 走 B 端（S-2 xh_chan_full 同款
  ——自持双端无等待者 = 纯 enqueue/dequeue 慢路成本）；载荷 8B = S-2
  XH_MSG 同值。vmo 项 commit 前置（未提交页读写 = 错误码，S-2 在册语义）。
- **输出纪律**：每项跑完**立即** println（增量输出——bsh collect 10s 活动
  帽按包刷新，批量打会静默 >10s 断链）；bsh 侧格式断言（行数恰 4 + 名字-
  iters 字面常量对拍 + 行 ≤192B + cyc 可解析非零 + eof/dropped/code 干净）
  **全过后才 relay**——每行单次 println（~35B 单消息原子，HEXYL ok 化妆面
  模式；bench.py --el0 从串口收割 relay 面），**禁止四行拼一串打**（>192B
  分片撕行，d-3c 雷）。**cyc 数值零断言**（公约 2——统计归统计）。
- **bench.py --el0 形态**：run-rootfs 形 QEMU（-fw_cfg rootfs，无盘无网，
  echod 免挂——B-1 无网络面）等 `B1 ok n=4` 收割 BENCH1 行；帽 300s（与
  smoke DEADLINE_ROOTFS 同口径）；基线双段（B-0 裸 CSV / B-1 带 BENCH1
  前缀行），`--update` 任一模式只动本段、另一段 load 回读往返保留（P6 A-5
  基准漂移雷——读写两侧同形双正则）；BENCH_RE/BENCH1_RE 逗号锚定互不误配。
- **kill criteria 预判**：1 spawn（≈4.5s TCG）+ ~8.6k SVC（四项 iters 合计
  ≈1-5s）——smoke 五跑中 4 跑带 rootfs 各 +5-10s，总量 <10% 劣化界，不触
  发削迭代；sys_null 4096→2048 的预授权削减备用。

## 9. R-0：WAKE_RING 消费直方图（已落地 2026-10-26）

**目标**：唤醒延迟分布是低功耗定位（手机/手表等移动端）的生命线指标（`优化议程-v1.0.md` §4 尾延迟）。
生产端 4-0 已落（`telemetry.rs` WAKE_RING：`WakeRec{vct, since_vct,
wait_obj, task_id, reason}`，延迟 = vct − since_vct，环形 64 条 + 
`wake_span()/wake_last()` 消费 API）——本刀只做**消费端**。

**形态定案：增量分桶，不动写点**。`on_wake` 内追加 O(1) 增量更新（零分配
纪律不破）：静态 `log2` 延迟桶数组（64 桶覆盖 2^0..2^63）+ 精确 min/max +
总数 + Signaled/Timeout 分计数。环形 64 条保留（最近明细，供未来
telemetry_open 映射）。**为何不用环形重算分位数**：环只盖最近 64 条，
boot 全程分布会丢头——增量桶全程覆盖且 O(1)；精确 p50/p99 从桶只能给
**桶界**（指数粒度）——够看形状；精确分位数留给 R-1（采样集小可全排序）。

**打印点**：watchdog `G1.5 ok` 断言后（稳态矩阵已跑、样本已积累）boot 尾
一次：`BENCHWAKE n=<total> min=<cyc> p50=<桶界> p90=<桶界> p99=<桶界>
max=<cyc> sig=<n> tmo=<n>`（一行 ≤192B）。

**门禁**：smoke 裸相挂 `BENCHWAKE` **形状断言**——落地形态：行在 = smoke
grep；**n>0、min≤max = 打印前严格断言 panic**（撕裂安全——快照读序纪律见
`telemetry::wake_hist`：n 先读保证桶和 ≥ n、min 先于 max 读保证序不变）；
**负延迟/时钟倒走 = bug = `on_wake` 写点严格断言 panic**（盖全历史，比
wake_check 的环内 64 条更全）。桶界保守上界 2^(idx+1) 可高于精确 max
（如全样本落单桶时 p50=上界 > max 精确值）——p 链不做排序断言；数值 L1
归 bench.py 收割同表。裸相 24→25（两标记表已同步）。

**依赖**：无（最小刀——内核增量桶 + 一行打印 + smoke 标记）。

## 10. R-1：cyclictest 式 oversleep 基准（已落地 2026-10-26）

**目标**：调度延迟的直接量——请求睡 δ、实测醒，oversleep = 醒时刻 − 请求
时刻的分布。cyclictest 是 PREEMPT_RT 的验收标杆，BerryOS 低功耗端定位同款
生命线（交互唤醒 p99 的机器可读形态）。

**形态**：内核任务 `rt_probe`（ai_probe 形：boot 侧 `spawn_with_tag` 私有
表，表内仅一个哑 Event；prio 24 中档——被饿本身就是待测的调度延迟，不抬高
也不委屈）。睡在**永不置位的哑 Event 用户位**（1<<40，登记
USER_SIGNAL_BITS；用户位等待 → `pi::donor_edge` 解引用安全，4-3b 纪律）。
`object_wait_one` deadline=绝对周期时刻 → 到点 -ETIMEDOUT 醒 →
oversleep = wake_vct − deadline_vct（**δ 直接用周期数定义，不走 ns 换算**
——换算舍入会污染被测量，公约 5）。

**三档 δ × 采样**：δ ∈ {¼ slice（1.5625M cyc）、1 slice（6.25M）、
4 slice（25M）} × N=32——短档量定时器精度、长档量轮转排队尾。

**输出**：每档一行 `BENCHRT,delta=<cyc>,n=32,p50=<cyc>,p99=<cyc>,max=<cyc>`
（32 样本内存排序，精确分位数——与 R-0 桶界互补）+ 收尾 `RT ok n=96`。

**耗时与通道**：TCG 半率 1 slice ≈ 200ms 实时 → 全程 32×(50+200+800)ms
≈ 34s——**不进 smoke**（公约 7 kill criteria 预罚），专属 `just bench-rt`
（= build + bench.py --rt：裸跑 QEMU 等到 `RT ok` 收割，帽 120s）。

**断言**：oversleep ≥ 0 严格（负值 = 提前醒 = 再睡循环破损 bug）；分布数值
只出数不设紧门禁（统计归统计）。rt_probe 跑完自然退出（exit 钩子/REAPQ
在册面），非常驻。

**依赖**：无（wait timeout 路径 4-1 已阻塞化；WAKE_RING 顺带记 Timeout 唤醒
——R-0 的 tmo 计数与 RT 线互为旁证）。

**落地实录（实现取舍，与设计表的差异注记，2026-10-26）**：

- **fw_cfg 具名项门控 `opt/berry/rt`（设计缺口闭合一一「不进 smoke」需要
  机制不是自律）**：设计 §10 只写了走专属通道，没写 rt_probe 在普通 boot
  里如何缺席。落地形态：`bench.py --rt` 专递 `-fw_cfg
  name=opt/berry/rt,string=1`，内核 boot 侧 `fwcfg::find_file` 命中才
  spawn（rootfs 探测同款先例；string backing 也登记 FILE_DIR，内容永不
  读）。缺席侧实抓验证：裸跑 12s 采样 BENCHRT/RT ok 恒缺、裸相标记全在、
  AIDEMO/BENCHWAKE 数值与在场 boot 同量级——run/smoke/smoke-image/EFI
  四路零扰动（EFI 路无 fw_cfg 具名文件天然缺席）；smoke.sh 一字未动。
- **prio 24 → 8（首跑实踩 panic，设计原文偏离）**：设计原文「prio 24
  中档」在 16（fa/ai ping）与 32（fa/ai pong）之间——但 24 > 16 意味着
  rt 醒来会抢占 ai_ping 的 IPC 往返测量窗：一次 rt 醒（双上下文切换 +
  PI 全图重推）即把 AIDEMO 的 rt2 顶到 rt1×4（首跑实录 rt1=1912
  rt2=7548），撞「注入后 bench RT 同量级 2x」容差断言 → boot panic →
  RT ok 永缺失。修法 = **prio 8**：全体常驻（矩阵/console/watchdog/
  EL0 用户，全 0）之上、瞬态 boot bench 对（16/32）之下——结构性排除
  整类干扰（对 16/32 永让位：测不到它们、也污染不到它们）；稳态
  （bench-rt boot 在 0..24 之间无任务）唤醒测量与 24 恒等，「被饿本身
  就是待测的调度延迟」语义反而更真（8 对 16/32 风暴真实让位、对常驻
  真实抢占）。当日旁证：AIDEMO rt1 两形态均 ~11-12k 量级（run-to-run
  波动主导，rt_probe 在场非其来源）。
- **漏整周期再锚（cyclictest overrun 形；首跑实踩纯绝对递推被否）**：
  v1 唤醒粒度 = 1 tick（超时扫描 `expire_timeouts` 只在 tick 跑，无
  arm-to-nearest-deadline）→ δ=¼slice 档在粒度之下：纯绝对周期递推
  （`deadline += δ` 每轮）每轮 lag 增 (slice−δ)、32 轮累计成**线性阶梯**
  ——首跑实录 p50=95M/max=193M 随样本序线性涨，量出的是**漂移**不是
  **延迟**（对调度器的错误指控：同 boot 的 4·slice 档 p50=4M 才是真实
  唤醒延迟）。修法 = oversleep ≥ δ（下轮 deadline 已成过去 = 结构性
  追不上）时重锚 `deadline = 醒时刻 + δ`（cyclictest 对 missed period
  的 overrun 处理同形）；漏周期样本的 oversleep 仍按原 deadline 记账
  （迟到的账记在迟到者头上，不因再锚抹零）。修后三档 p50 全落
  sub-slice（δ=1562500→p50=5367438、δ=6250000→p50=3786375、
  δ=25000000→p50=3498625——首验收实录，周期数口径；δ/p50 显式标注，
  防「x/y」被读作 p50/p99 的倒挂误读）——
  **短档的诚实答案 = v1 唤醒粒度 ≈ 1 tick**；
  arm-to-nearest-deadline（优化议程候选）落地后 tier-1 应塌缩，本基准
  即其验收面。
- **睡点直调 `berry_sched::block_current` 绕过 SVC 面**（设计原文
  「`object_wait_one`」的落地修正，公约 5）：deadline 参数本来就是
  CNTVCT 周期——SVC 的 ns→vct 折算被绕过（换算舍入不污染被测量）；
  包络纪律 task_sleeper 同款（disable → block → 续行 IRQ 仍屏蔽 →
  **屏蔽窗内读 wake_vct** → enable）。
- **哑 Event 用户位 1<<40 已登记 `USER_SIGNAL_BITS`**（R 线逐位递增
  起点，现役最高位）；纯用户位等待 → `pi::donor_edge` 返回 None（零
  受捐面）；`spawn_with_tag` 私有表 → 无跨表错捐（4-5 纪律）。私有表 +
  Event 随任务退出不回收（`Box::leak` 惯例——单表单对象有界泄漏，
  换零 close/生命周期耦合；非常驻任务，一次性）。醒因断言 = 恒 Timeout
  （哑 Event 无人 signal；非 Timeout = 跨表 wake 面破损，bug 路径）。
- **非锚定收割**（B-1 教训同族，首跑实证）：rt（prio 8）醒来抢占 prio 0
  矩阵任务的逐字符打印流——BENCHRT 行实测落进 40KB 巨行中段（tier-3
  行首与矩阵 B 流直接拼接），`^` 行锚定恒漏收；`RT ok n=` 与
  `BENCH ok n=` 字面互非子串（B-0 通道零误配）。bench.py `--rt` 为独立
  `run_rt()`（不复用 run_once 的 mode 分支——收割面/一致性校验不同构，
  B-0/B-1 两通道零回归优先）。
- **只出表无基线，`--rt` 独立通道——`--update`/`--el0`/`--factor` 组合一律
  拒绝**：oversleep ≥ 0 严格断言内核 panic 执法（L0）；分布数值不进任何
  门禁（统计归统计，公约 2）。`--update` 误触 save_baseline 会按双段前缀
  逻辑污染 bench_baseline.txt；`--el0`/`--factor` 不进 --rt 早退分支，
  静默忽略 = 用户要的通道/门禁凭空蒸发（`--el0 --rt` 实际只跑 RT、B-1
  静默缺席且退出码 0——三镜审查实抓），故组合直接拒绝、不静默忽略。
- **耗时实录**：boot 头 ~2.7s（全程标记过完）+ 三档采样 ≈18.5s ≈ QEMU
  22s 到 RT ok（帽 120s，5x 余量）；`just bench-rt` 全链 25.7s（含
  build）。BENCHWAKE 快照在 boot 尾、rt 绝大多数样本在其后（tmo 计数
  仅收先前十余次）——R-0/R-1 数据面基本不重叠，互为旁证的挂钩留消费侧。

## 11. S-1：soak 长跑（已落地 2026-10-26）

**目标**：≥1h 稳态跑不崩不漏不静默——churn 金丝雀的长时间维度（S-0 是
64 轮微观，S-1 是小时级宏观）。

**形态**：内核常驻任务 `soakmon`（ai_probe 形：私有表 + 表内哑 Event
1<<41 用户位 wait_one timeout 到点重臂——活性心跳不是死线，超时重臂
纪律；常驻不退出）每 **60s** 打一心跳。心跳行：

```
SOAK t=<分钟序号> sw=<切换总数> pages=<allocated_pages> lost=<RX丢字>
```

四个字段全是**现成计数器**（switches 金丝雀同源 / B-0 对账口径 / console
环 lost）——零新内核状态。

**宿主工具**：`tools/soak.sh <分钟数>`——run-rootfs 形态 QEMU + 串口落盘，
轮询断言：①心跳序号严格 +1（丢心跳 = 静默死）；②sw 严格递增（调度活着）；
③pages ∈ [首拍值, 首拍值+64]（+64 帽 = 懒增长容忍量，持续上涨 = 真泄漏）；
④lost 恒 0（无输入面丢字 = console 环健康）。任一断言破 = FAIL 留全日志。
`just soak` recipe 单口。**不进 CI 主线**（小时级），周跑或手跑。

**边界**：v1 soak 盖「稳态矩阵 + 常驻服务」面；用户态服务 churn（spawn/exit
风暴）随 B-1b 管道面后再入列。QEMU SIGTERM 刷盘纪律（P6 A-6）：soak.sh
退出前 kill + wait + sleep 3。

**依赖**：R-0 落后一起定标（心跳里的 wake 旁证字段可扩）。

**落地实录（实现取舍，与设计表的差异注记，2026-10-26）**：

- **fw_cfg 具名项门控 `opt/berry/soak`（「不进 CI」需要机制不是自律——
  R-1 先例直接继承）**：soakmon **常驻不退出**，比 rt_probe 一次性采样更
  强——无门控 = 每次常规 boot 永久多一个任务（runqueue/PI 图节点 + 私有
  表/Event 泄漏 + 每 60s vct 一次 prio-8 抢占唤醒）+ 交互 boot 串口每拍冒
  一行。落地：`soak.sh` 专递 `-fw_cfg name=opt/berry/soak,string=1`，
  内核 boot 侧 `find_file` 命中才 spawn（rt 块同款位置/同款私有表 + 哑
  Event 形态）；**rootfs+soak 双具名项同 boot 首例**（fw_cfg FILE_DIR 多
  项按名走查，首跑实证无冲突）。**门控自证行 `SOAK gate on`（对抗审查
  finding 2 修正）**：spawn 后同块打一行（行在 ⟺ soakmon 已 spawn），
  soak.sh boot 守卫收它——键名两侧漂移在 boot 期 loud 而非等首拍帽超时；
  缺席侧抽查随之从「短窗等首拍缺席」（首拍潜伏 5 周期 ≈300-600s wall，
  首版 150s 抽查窗 < 3 周期首拍时刻 ≈182s——SOAK 恒缺证明不了门控在工作，
  空调无效验证）改为短窗 grep 本行。缺席侧抽查实录：run-rootfs 形态
  （不递 soak 项）采样 150s——`SOAK gate on`/`SOAK t=` 恒缺、既有标记全
  在——run/smoke/smoke-image/EFI 四路零扰动（EFI 无 fw_cfg 具名文件天然
  缺席），`tools/smoke.sh` 一字未动。
- **首拍潜伏 5 周期（设计缺口闭合——pages 窗口 vs boot 尾部瞬态；对抗
  审查 finding 1 由 3 周期加到 5）**：设计断言「pages ∈ [首拍值, 首拍值
  +64]」是单侧窗，但无潜伏的首拍落在 60s vct（本机实测 ≈60s wall）<
  smoke 实测全链 ~190s wall——boot 尾部帧回收瞬态（walk 子进程映像/栈
  unmap 真还 + REAPQ 内核栈 dealloc）在首拍后退出 → pages 下穿首拍 = 假
  FAIL。3 周期首拍本机实测 ≈182s wall，首验日志里恰贴 walk 尾部末段
  （SOAK t=1 紧随 CD ok 落地）——宿主负载拉伸指令驱动的尾部而计数器驱动
  的首拍不动（历史两机实测速率 0.5×/1.0× 与指令吞吐无关互证），基线可落
  回收瞬态中段；且尾部在四覆盖标记到齐后仍延续数十秒（U1 九 spawn 一段
  实测 +~40s / U2/U3/B1 子进程映像与栈回收在其后），300s 只是标记帽不是
  尾部帽。5 周期（首拍 ≈300-600s wall）对 300s 最坏链 ≥1.6x 裕量，基线
  必落稳态之后；t 仍从 1 起，断言保持设计原文形状、宿主零状态（未走
  「宿主 t=2 向下重定基线」备选——弱化窗语义，次选）。落地：deadline
  绝对网格 `t0+(n+4)*period`（n 从 1 起）。绝对网格另带漂移自校正
  （每拍独立锚定，不随醒来时刻累积），60s 周期 >> 1 tick 唤醒粒度，R-1 式
  漏整周期再锚结构性不发生。
- **prio 8（R-1 同构）**：全体常驻（全 0）之上——心跳到点立即抢占打出，
  「心跳在 = 调度活」语义干净；瞬态 boot bench 对（16/32）之下——boot 窗口
  零干涉（结构性让位的免费保险）。
- **心跳行收割两向量（漏任一侧 = 断言假阴性且静默）**：① soakmon(8) 到点
  抢占 prio-0 矩阵任务的逐字符打印流 → SOAK 行嵌 ABAB 巨行中段（必然）→

## 12. S-2：资源耗尽行为（已落地 2026-10-26）

**目标**：ABI §8.0「永不 panic」的边界测试——资源到顶时错误码回、不 panic、
不死锁、可恢复。syzkaller 式鲁棒性的最小确定性子集（模糊面挂 v2）。

**形态**：bench 窗口内核侧（公约 6——单线程 IRQ 屏蔽，全帧耗尽瞬态无并发
分配者，安全）；全部**确定性严格断言**、全部便宜（秒内）→ **进 smoke 裸相
L0**。

| 面 | 操作 | 断言 |
|----|------|------|
| frame_exhaust | `alloc_order` 高阶→低阶循环到 Err（空闲区全吃光）→ 全量释放 | Err 非 panic；释放后水位精确归位 |
| vmo_cap | syscall 面 `vmo_create(32MiB+1)` / 边界 `create(32MiB)`（不 commit 不吃帧）+ 对象层直调边界 | 超帽 -ENOMEM（C-2c 在册）；边界成 |
| handle_fill | 私有表 insert×4096 → 全 close（v1 表无硬帽，真帽 = 堆；4096 轮盖「错误码回 + 可回收」语义） | 全程无 panic；used_count 0↔精确翻转；帧水位恒等 |
| chan_full | 自持双端 send×8 成、第 9 条 -EBUSY（CHAN_DEPTH=8 在册）→ recv×8 排水 → 再 send 成 | 错误码精确；**恢复面**（排水后可再用） |
| chan_drain | 空队 recv -EAGAIN（在册） | 错误码精确 |
| 复位对账 | 全部面跑完 `allocated_pages()` 恒等 | S-0 同口径金丝雀 |

**输出**：`BENCHXH ok frame=1 vmo=1 handle=1 chan=1`（状态谓词——全过才
打；boot 输出序在 `BENCHCHURN ok` 之后、`BENCH ok n=6` 之前）。裸相再 +1
（25→26，两标记表同步）。

**落地实录（实现取舍，与设计表的差异注记）**：

- **收集槽 = 定长数组（`[(pfn, order); 512]` 栈上 8KiB），不用 Vec**——
  风险注记预判的「耗尽期间隐式分配」被直接结构性地排除：耗尽路径零分配。
  上界口径：QEMU 直载路径空闲区 1–2 段、EFI handoff 31 段图残余 ~200 块
  ——512 = 2x 余量；溢出 panic（届时按降级注记改 order-13 形态）。设计表
  原文「≈3 万次 alloc」按 order-0 逐页估算——实现改**高阶先吃**（空闲区
  按 2^order 整数倍逐级分解，高阶先行收集块数最少），语义等价（高低阶
  全吃光）且快一个量级；耗尽中加一道**中途对账**（水位 = 基线 + 累计
  页数——任何阶的错账当场现形，不等释放后才发现）+ 量级下限 ≥16MiB
  （防「耗尽几个零散小块也算过」的空心绿）。
- **vmo_cap 双层验证**：尺寸帽是 **syscall 层**私有帽（`sys_vmo_create`
  帽检先于出参/入表 = 超帽调用零副作用）——超帽断言走 SVC 真路径（错误码
  经 ABI 派发面回）；对象层 `Vmo::create` 无帽，32MiB 结构性成功（页记账
  Vec ≈144KiB 走堆、零帧），对象层直调只验边界成功面。帽值引用
  `syscall::VMO_MAX_SIZE` 单源常量（本刀转 pub(crate)），不写裸数字。
- **handle_fill 复用 churn_handle 预热先例（一般化）**：4096 槽的 `ObjRef`
  Box slab 页（G0 政策：slab 页永不还 buddy）+ slots Vec 懒增长全部**预付
  在全局基线之前**——真轮纯复用，水位恒等断言才不被一次性分配污染
  （S-0 首跑 +1 页假阳性教训的直接应用）。
- **复位对账结构（本刀的关键设计）**：窗口内三个**永久性**帧效应全部预付
  在全局基线之前——①通道对端点队列（`ChannelEnd::pair` 互 retain →
  close 不 drop，队列 Vec ≈2.7KB/端 = 1 页/端永不还，channel.rs 环泄漏
  安全向政策）；②handle 面 slab 页（见上）；③BOOTSTRAP_HT 槽位 Vec 残余
  增长（ktest 期已基本定型）。基线后六面只做「吃光 → 全量归还」的自愈
  往返，末尾水位恒等。通道对在**对账之后**才 close（环对象互钉不 drop
  ——close 零帧变化，ktest H4 清场同款）；预热 handle 表也活到对账之后
  （其 slots Vec 大块早还 buddy 会把水位打到基线之下、恒等断言反手误伤）。
- **chan 两面走 SVC 真路径**（EL1 tag==0 → BOOTSTRAP_HT，ktest H4 同路；
  耗尽/恢复错误码经 ABI 派发面回，非直调内核函数）——chan 复用预热轮造
  的那对端点，send/recv 路径零分配（队列预储、无随行 handle），水位恒等。
- **伴生修复（对抗审查实抓，随本刀入册）**：vmo_cap 面②首次踩亮存量雷
  ——`heap.rs` 大对象 dealloc 沿用 2b-1 之前的「VA==PA」过期前提，把高半
  direct map VA 直接当 PFN 还帧，buddy 按越界 PFN 返 Err 又被 `let _ =`
  吞掉 → 32MiB VMO 页记账 Vec（每只 36 页）静默漏帧，boot 必 panic 于
  复位对账。修法：dealloc 侧 `virt_to_phys(ptr) >> PAGE_SHIFT` 折回 PA +
  free 失败 loud 打印不吞错（违 loud-not-silent 纪律正是该雷静默存活的
  原因）。该路径此前从未被执行（既有大 Vec 只增不缩），修复后所有
  >2048B 堆块 drop 真还帧——「已落地」表述以本伴生修复随刀入册为前提。

**风险注记**（设计期预判，落地后存档）：frame_exhaust 全帧占用期间 bench
窗口自身若需隐式分配（堆增长等）会瞬时 Err——落地形态以定长收集槽数组
结构性排除（见上），未触发降级路径。

**依赖**：无（错误码全在册，零新 syscall；ktest `svc4`/`svc6` SVC 外壳
转 pub(crate) 供 bench 复用）。

## 13. B-2：-icount 确定性通道（已落地 2026-10-27）

**目标**：把计时从「统计量」升「确定量」——L2 紧门禁（±20% 乃至精确相等）
的前置证明通道。

**形态**：`tools/bench.py --icount`——QEMU 追加 `-icount shift=1,sleep=off`。
语义变化三条（设计内明示，防误用）：①CNTV 推进绑指令数（虚拟时钟）→
「周期数」变成**指令数代理**，与实时通道（TCG 半率）**基线不可比、分文件
立**；②boot 时序全变（tick/看门狗节奏漂移）→ 该通道**只跑 bench 收割**，
不用于功能面；③确定性来源 = 同指令流同虚拟时钟。

**证明协议（L2 开门前置，义务在提案方）**：`--icount --prove` 连跑 5 次，

漂移谱、降 L2 = ±5%，禁用精确相等。「逐字节相同」只对 BENCHWAKE 整行
