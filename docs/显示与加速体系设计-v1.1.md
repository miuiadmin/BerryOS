## 1. 目标与原则

**目标一:模拟器是给开发者用的,性能=能用。** 验收口径不是「能显示」,是 1080P@60 满帧下的交互流畅加上 CLI 可复现(`--json`/shot/串口标记面全绿);「看图式」演示档不被接受为达标。

**目标二:1080P 初始不妥协。** 打开 `berry shell`(双击/无参同入口)即 1080P:入口层(desktop 档+auto accel)、档位层(render=panel 零 letterbox)、窗口层(初始=panel 逻辑尺寸 1:1)、布局层(vp 断点档)四层共同兑现,单层不成体系(03 号 §1.1)。方向定谳(v1.1 回填):desktop 档 = **1080×1920 竖屏**(owner 2026-11-13 裁六翻案终裁,`tools/berry/src/profile.rs:30-41` owner 注「竖屏 1080P 手机主形态——不做低清/横屏妥协」,render=panel 1:1 零 letterbox 同守)。

**目标三:GPU 加速 day-one 档位,Mac 先行。** 后端兑现序列 = soft(永久 CI 基线)→ virtio-gpu 2D(模拟器加速档)→ native Vulkan(真机档),已在册([GUI 里程碑规划](GUI里程碑规划-2026-10-v1.0.md):187);本定稿兑现第二档——显示链 GPU 化(收帧 damage 化+宿主 wgpu/Metal 呈现),Mac 先行落在 HVF+Metal 链,Linux 同构受益(KVM/DMABUF 升级缝)。「GPU 加速」语义三段(v1.1 按 10/13 号澄清,管道不是画笔):**渲染段**(算像素)100% 留 guest CPU——virtio-gpu 2D 命令集 14 条全是资源管理/传输/呈现通知,零画图原语,2D 档结构性不可卸载(10 号 §1);**传输段**(搬像素)已兑现五个数量级降载(稳态 2.1KB/s vs 旧盲轮询 115MB/s,12 号 §0-2);**合成呈现段**(上屏)QEMU 侧增量自动在场(09 号 §4)、宿主 GPU 自 β-1 始参与——加速档的准确说法 = 显示通道加速,真 GPU 渲染住第三档 Vulkan(13 号 §1 三段表)。

**目标四:双加速器体系。** TCG=CI/关卡/截图确定性基线(同输入同输出),HVF=桌面/交互开发默认档(快+真计时器),各司其职、互不取代([开发体验](开发体验.md) §0/§2 在册口径;CI 宿主结构性只能 TCG,`.github/workflows/ci.yml:39` self-hosted linux-x64)。

**原则(用户铁律,裁决冲突时的上位依据)**:①不打补丁,从底层系统框架设计——对旧病灶的惯性补丁(如窗口 0.9 因子)随根因消除而退役,不做叠床架屋式最小修;②一开始做最好最优秀——加速档按终态架构(零拷贝共享图+GPU 合成)设计、按可达路径(增量矩形先行)渐进;③Mac 先行;④模拟器给开发者用(1:1 所见即客机像素,调字体/量布局/抓截图不撒谎)。

## 2. 分层架构(三层职责与契约)

目标态链图(virtio-gpu 2D 加速档;现役 ramfb 链与 fallback 关系随注):

```
[宿主层] berry 壳(tools/berry,ADR #62 宿主自持窗口)
  winit 窗口 + wgpu/Metal 呈现:共享图→MTLTexture 一次 DMA 上传 →
    单 pass 采样缩放合成(letterbox/整数/任意比)→ 工具栏层 GPU 合成 → 上屏;
    截图 = 纹理 readback(QMP screendump 退二线)
  收帧:β-1 D-Bus p2p Listener.ScanoutMap/UpdateMap(共享图 fd + 纯 damage 矩形)= 终态
        (macOS 六环节全链本机实收,11 号 §2——v1.1 立为 Mac 呈现终态通道,13 号 §3);
        β-0 VNC 增量矩形 = 过渡(QEMU 侧增量自动在场,09 号 §4;VNC 出口 30ms 刷新
        定时 = 33fps 结构硬顶,12 号 §0-4);ramfb 轮询 pread = 现役,随刀退役为
        fallback 探测面(壳半 B1-b 未落——双通道并存付双份,12 号 §3.3)
  输入:VNC loopback(过渡)→ D-Bus Mouse/Keyboard/MultiTouch(终态)
  「宿主拖窗 = 纯宿主 scale,永不改客机分辨率」在本层执法
      │
[虚拟化层] QEMU 单进程(壳编排 argv)
  accel:TCG(cortex-a72 确定性仿真)/ HVF(-cpu host 真执行)
    —— choose_accel:deterministic→TCG;macOS ARM auto→HVF(qemu.rs:39-77)
  显示设备:-device virtio-gpu-device 2D(资源/scanout/flush)⇄ -device ramfb(静态兜底)
        (guest 半已消费;berry CLI 宿主接线未挂设备,见 §4 刀 5 状态注)
  显示导出:-display dbus,p2p=on(终态)/ -vnc(过渡);
    fw_cfg 具名键族 opt/berry/{display,accel,rtc}(qemu.rs:253-265)
      │
[guest 层]
  berry-gpuproto crate(协议编解码,纯函数零分配,host 单测先行——02 号 §3.2 原名
    berry-virtio-gpu,落地定名 berry-gpuproto;已落,08 号六验+29 测)
  guifbd 进程内后端:PREPARE→ATTACH_BACKING(mem_entry 表,INDIRECT 描述符)/
    SUBMIT damage K≤8→TRANSFER_TO_HOST_2D+RESOURCE_FLUSH(逐矩形;v2 起 per-rect
    包络+异步化提交,853ac85c——16 号定标 reap 0.111-0.137ms)/
    SET_SCANOUT(运行态几何);ramfb 后端降 fallback(boot 探测选路;已落,09 号判过)
  gui-wmd 窗口策略(ADR #61)+ GETINFO 协商 + density 事件流;
  berry-gfx soft 后端(永久 CI 基线,与加速档双后端像素对拍)
```

**宿主层职责**:QEMU 进程编排与 accel 选择;自持窗口与 GPU 呈现;收帧通道与输入注入;截图/CI 面。**宿主层契约**:Frame 载荷 = {几何, 像素或共享图引用, damage 集}——呈现只消费 damage,不放大为全帧([berry 设备壳设计草案](berry设备壳设计草案-v1.0.md) §5.3 已预留字段位);传输可换(VNC/D-Bus/未来 DMABUF)与呈现解耦,换传输不动呈现;非 TCG 档一律注 `opt/berry/accel` 键(判例门控契约,内核直启路径同补);shot/deterministic 强制 TCG,确定性面永不因加速档漂移。

**虚拟化层职责**:CPU/内存虚拟化与显示设备/显示导出。**虚拟化层契约**:guest 页粒度零约束——stage-2 按宿主页映射,guest 4K 自由(01 号 §2 定谳);virtio-gpu 2D 命令即答无 fence(used ring 收割即背压);damage 端到端保真(TRANSFER_TO_HOST_2D 行循环 + FLUSH∩scanout 求交,无全帧放大);scanout 几何随资源(≥16×16 即 modeset),config events+CONFIG_GEN 构成宿主→guest 通知通道(02 号 §3.1/§5)。

**guest 层职责**:virtio-gpu 驱动与显示服务链。**guest 层契约**:HDI 契约不动,换实现不换契约(ADR #50,架构决策.md:59);damage K≤8 与「无 damage 不提交」端到端立法(guifbd 段③已立,加速档同守);boot 探测选后端(virtio-gpu 主/ramfb 兜底),console 路与 FBW/FBSERVE/GFXF 标记面零演进污染;density 进事件流——几何热变时随 scanout 事件下发,禁消费端静态推导(03 号 §3.2)。

**跨层不变量三条**:①宿主拖窗=纯宿主 scale(letterbox 等比缩放+输入坐标反算),永不触发客机分辨率变更——Android 模拟器/QEMU GTK 双先例(03 号 §4);②显示几何单源——数值只在家一处(官方档表/product.toml),fw_cfg 串/info VMO/GETINFO/窗口初始/布局换算全链派生零手抄(03 号 §5);③确定性基线不可让——TCG+soft 是 CI/关卡/截图唯一基线,HVF/virtio-gpu 是叠加加速面,永不反噬基线(规划 :187)。

## 3. 裁决集(十裁,每裁给依据与反论)

**裁一(慢根因与解药)**:用户体感慢的根因 = 渲染链(guest CPU 软光栅 + 宿主全帧搬运/标量转换/CPU 合成),非 CPU 虚拟化档位;性能解药 = virtio-gpu 2D 加速档,HVF 是地基不是药。依据:01 号 §1.2(用户会话 HVF 真跑通仍慢,三层实锤)+ §3.3(四段链解剖)+ 02 号 §1(定量:每变化帧 ≥4 次全帧级 CPU 遍历,静止帧仍 1 次全帧读,`tools/berry/src/display/ram.rs:136-158` 先读后验)。反论:「换上 HVF 就快」已被用户会话实证证伪;「宿主带宽不够」被实测否(59.6GB/s vs 满帧 497.7MB/s,占用 0.83%,02 号 §1);「HVF 一律快」被 soak 反转否(HVF ≈5× 慢于 TCG,机制未定谳,01 号 §3.2)。

**裁二(双加速器分职)**:TCG=CI/关卡/截图确定性基线(结构性唯一),HVF=桌面/交互开发默认;不做全 HVF 化,不在 HVF 上追加投入「修慢」。依据:开发体验.md §0/§2 在册口径;ci.yml:39 x86 宿主无 HVF;01 号 §4(CI 全 TCG 结构性+HVF 三缺口)。反论:「CI 也上 HVF 提速」——宿主不可能,且确定性是 AI 测试友好前提;「HVF 下跑全量 ktest」——FPSR/PP-4 已门控、DPG 断言(kernel/src/dpg.rs:719,v1.0 时点——现漂移 :774)未门控,修完三缝前 HVF 档语义 ≠ TCG,只能作已知缺口挂账。

**裁三(16K 不做)**:guest 保持 4K 页(`mm/src/va.rs:14` PAGE_SIZE=4096);HVF 对 guest 页粒度零约束,16K 迁移无任何模拟器侧动因。依据:01 号 §2 三源定谳(QEMU v11.0.3 源码 stage-2 按宿主页 + Apple hv_vm_map 官方文档 + 4K 镜像在 16K 宿主满负荷实跑)。反论:「对齐宿主 16K 免罚」无任何证据;全量账 = 2-4 周量级 + user ABI 0x1000 基址硬断裂(01 号 §2.4,推断);真机 16K 页硬件目标立项时带 ADR 重开。

**裁四(宿主呈现 = 案 β)**:加速档宿主呈现 = 壳自持窗口 + QEMU 显示导出 + 宿主 wgpu/Metal 合成;案 α(QEMU 自带窗口)出局,案 γ(virgl 3D 全管线)远期观察,vhost-user-gpu 出局。依据:02 号 §2 本机实证(`-display help` 仅 none/curses/cocoa/dbus;`-display cocoa,gl=on` 拒答无 GL;virtio-gpu-device 在列而 vhost 族 0 命中)+ ADR #62 壳面不可丢(工具栏/截图/注入/--json)+ ADR #51 自研栈不引 Mesa(架构决策.md:60)。反论:α——Mac 构建实证无 GL 无 virgl 且丢整个壳面;γ——guest 需 Gallium 级栈违 #51,另有 aarch64 史坑;vhost-user-gpu——QEMU 官方明言不支持 MMIO,而 BerryOS 是 virtio-mmio 路线。

**裁五(传输两步走)**:β-0(VNC 增量矩形)过渡档,β-1(D-Bus p2p Listener/UpdateMap 共享图纯 damage)终态。v1.1 三条翻案:①β-1 全链 macOS 本机实证——p2p 免 daemon/QMP 喂 fd/RegisterListener/ScanoutMap 共享图 mmap 实收/UpdateMap/输入反走六环节全通(11 号 §2),memfd→mac = mkstemp 匿名文件+MAP_SHARED 语义完整(11 号 §2.3)——02 号 §6 降档线「D-Bus Map 不可用→锁 β-0」**不触发、退役**;②β-0 过渡档定位取得法源:VNC 出口 30ms 刷新定时 = 33fps 结构硬顶,与 flush 粒度无关(12 号 §0-4)——60fps 目标下 β-0 结构性不够,且 QEMU 侧增量已自动在场(09 号 §4);③β-1 立为 Mac 呈现终态通道,VNC 降为诊断通道(`-display dbus`+`-vnc` 同挂合法,13 号 §3 终裁)。依据:02 号 §2/§6 原设计 + 11/12/13 号实证收口。反论:「直上 β-1」的原风险(macOS 无 memfd)已闭账;「VNC 永久」——编码路径与拷贝缺位是结构性上限且 33fps 硬顶新证,终态在 β-1。

**裁六(1080P 定调·v1.1 方向翻案)**:desktop 档 = **1080×1920 竖屏**,render=panel 零 letterbox;窗口初始 = panel 逻辑尺寸 1:1(base_window_factor 的 0.9/0.55 因子与 0.9 屏幕钳制全部退役——刀 1② 未落,`tools/berry/src/window.rs:202-243` 因子仍在树);横屏 1920×1080 形态自此无档承接,产品若需横屏随触发器⑦同窗定夺。依据:owner 2026-11-13 终裁竖屏——`tools/berry/src/profile.rs:30-41` desktop 档 1080×1920+owner 注「竖屏 1080P 手机主形态(owner 2026-11-13 裁定:初始分辨率即 1080P、竖屏 + 底部导航键,不做低清/横屏妥协)」;v1.0 所引 main.rs:701-702 横屏入口注为同日早三分钟旧注,现漂移至 `tools/berry/src/main.rs:886-890` 仍未清(刀 1 对账收尾件);01 号实测用户在跑会话即竖屏几何,与终裁同向;重议触发器 8(方向翻案)首用即本案。翻案不变量:档位值翻转而体系不变——零 letterbox/1:1 窗口/vp 断点照用,零 letterbox 性能账(8.29MB/帧 ×60 ≈ 0.5GB/s,ramfb 路可承受)与开发者 1:1 语义原样成立(03 号 §1 四层体系不受方向影响)。反论:「0.9 因子防小窗」是历史补丁,病灶(物理像素口径)已除,与方向无关;「横屏桌面语义」——owner 终裁在前,竖屏 + 底部导航键即桌面主形态。

**裁七(分辨率两相位)**:初始态(profile/product 单源 → boot 静态链一次分发)与运行态(virtio-gpu SET_SCANOUT 事件流:events_read+CONFIG_GEN+EDID)分治;ramfb fallback 路维持静态几何语义。依据:03 号 §4 + 02 号 §5(scanout 几何随资源,三层静态自然消解为动态);01 号 §3c(Android 模拟器/QEMU GTK 双先例)。反论:「拖窗跟随分辨率」——成熟竞品不做且违不变量①;「永远静态」——档位热切换免重启与真机面板枚举需要运行态,现役换分辨率需整机重启是已钉痛点。
