## 1. 版本定位与范围

### 1.1 一句话

**1.1 不做「任何东西可调度」，做「可证明的全序链 + 干净的策略边界」。**

「调度之王」的衡量标准不是粒度最细或 API 最多，而是对任何资源都能回答：
谁、凭什么、拿多少、上限多少、谁批准、何时失效。1.1 交付其中能证明、
能测试、能回滚的最强一档。

### 1.2 1.1 交付 / 非目标

| # | 交付 | 说明 |
|---|---|---|
| W1 | 单比较器规格 + S2 EEVDF | 每 class 一个比较器；`pick`/`preempt` 同源；lag/VD |
| W2 | `sched_attr` + 4 个 syscall | 0x3C–0x3F：set/get/suspend/yield；flags 决定字段生效 |
| W3 | token freeze（进程 + 可选线程） | `SuspendToken`；三重正交；单线程需 `FREEZE_READY` 自证 |
| W4 | 饥饿界离线检查器 | 输入/公式/证书；文档数字与证书差 ≤1% |
| W5 | 受益者记账（S4） | `billing_token` 随消息；CPU 时间记受益者 |
| W6 | 域预算 + 准入（S5，含最小 deadline class） | 只对 LC/deadline；fair 永不拒 |
| W7 | 1.1 验收套件 | host property + ktest + smoke；真机分位基线 |

**非目标（1.1 明确不做）**：

- 不做 per-handle 硬预算、不做 borrow/lend、不做 band 预算包络（1.2）；
  域预算/准入在 S5，只对 LC/deadline。
- 单线程 freeze 只做 opt-in + 用户态 quiesce 自证；跨进程用户锁不在保证范围。
- 不做 AI 慢环、不做学习型调度（1.2/S6）。
- 不做指令级/syscall 级调度（永远不做，只配调试器）。
- 不改 `SchedClass` trait、不改 intent 词汇表；`tools/abi.toml` 只在 S1 动。

### 1.3 与 v1/v2/v3、M0–M5 的关系

| 版本 | 内容 | 与 1.1 的关系 |
|---|---|---|
| v1 / M0+M1a | 单核 RR + tickless + PI + intent 预埋 | 1.1 的起点 |
| **1.1 / S0–S5** | 单比较器 + EEVDF + ABI + freeze + 记账 + 最小 deadline class + 预算/准入 | 本文 |
| 1.2 / S6 | 策略服务 + shadow + 回滚 + band/AI | 1.1 之后 |

**关键**：1.1 不跳级。S2（EEVDF）之前不做 band；S3（freeze）之前不承诺
freeze 语义；S4（记账）之前不罚；S5（预算）之前不对外说「预算」。

### 1.4 1.1 成功标准

| 维度 | 标准 | 证据 |

### 1.5 拍板原则（2026-11-06）

1. **能力取最强档，机制不叠加**：一个需求一个机制；禁止第二套排序键、第二套
   intent、第二套冻结协议。
2. **不以尾延迟/可验证性换功能数量**：任何新机制必须带 kill criteria 与
   离线可复现证书；过不了门就降级，不硬上。
3. **不能证明的「强」降实验轨**：学习型调度、在线 AI 调权、单线程无自证冻结，
   一律不进 1.1 出口。
4. **四类直接拒绝**：pager 冻结、指令级调度、无界不公平、per-handle 硬预算。
   不是「做不到」，是「做了会让整机不可用/不可证明」。

### 2.3 五条硬结论

1. **公平与硬上界必须分开买**：EEVDF/weight 给比例，SC/CBS 给上界；混写会得到
   「看起来都有、实际都无」的承诺。1.1 做比例 + 显式 freeze + 软预算，不做硬实时。
2. **粒度不是越细越好**：Linux 6.12 基片 750µs，自定义下限 100µs；再细主要买
   开销，不买确定性。1.1 的「细」体现在唤醒即抢占、事件记账、每消息 intent，
   不是指令级调度。
3. **freeze 是准静止流程，不是开关**：cgroup.freeze 要等 `frozen=1`；Android
   缓存在 10s 后冻、冻前 GC；冻结持有内核锁/PI 边的任务会死锁。1.1 用 token +
   安全点 + 三重正交谓词。
4. **策略在用户态、快路径在内核**：ghOSt 死于每决策跨态 + 专用核；sched_ext
   赢在上游 + 安全网 + 热切换。1.1 不做 AI，只保留遥测与慢环接口。
5. **证据要降级**：Meta p99 −28%/3.28MW 无一手来源（可查的是 ~1000 台、+3.5%
   吞吐）；proxy execution 6.13 只有 preparatory changes；QNX 8.0 移除 APS 未核到
   8.0 页面。以上不得进 1.1 对外材料。

## 3. 设计总览

### 3.1 三层分离

| 层 | 是什么 | 不是什么 |
|---|---|---|
| 执行实体 | 线程（`Task`） | 进程/Job/句柄本身不能被 CPU 调度 |
| 分配域 | Job→Process→Thread 的容器（1.1 只有 Process） | 不是执行上下文，不参与 `pick_next` |
| 权限与记账 | handle 上的 `SET_POLICY` / `MANAGE` / `INSPECT` 权 | 不是调度单位 |

结论：**「任何东西可调度」只能是「任何资源可被域契约约束」**；把 VMO/Channel
做成可 `pick` 的实体，会在 `pick_next` 里引入第二套对象生命周期，直接违反
微内核「机制极简」。1.1 的句柄级只到「权限 + advisory」，不做硬预算。

### 3.2 域树（1.1：容器 + 记账，S5 起 LC/deadline 执法）

- 结构：root → system → app → process；深度 ≤4；节点句柄发现，不做路径解析。
- 1.1 落 `weight / intent / account` 三个字段；S5 起对 LC/deadline 执法预算，
  **fair 只记账、永不拒**。
- 子树配额求和 ≤ 父、域内线程共享契约、跨域只经 channel/notification：
  三条不变式写成 ktest，不写成文档承诺。
- 为什么不是 cgroup：cgroup 用路径/文件系统发现；BerryOS 没有全局路径，
  域树用 handle 发现，挂到哪个父节点是授权行为，不是 mount 行为。

### 3.3 受益者付费账户（1.1 记账，S5 起对 LC/deadline 罚）

- `billing_token` 随消息头传播（与 intent 的 min 重导同构）；谁受益谁付账。
- S4 只记 `charged_ns / borrowed_in_ns / lent_out_ns / unpaid_ns`，进 telemetry；
  S5 起对 LC/deadline 欠费可罚；**fair 不罚、不拒、不调度**。
- 服务端底薪来自全局单池、work-conserving，不按域累加；按域累加会让空载也
  抽干带宽，admission 永远失败（S5 实现时同刀验证）。
- 无受益者记 system；IRQ/内核公共记 system；账户不建第二数据库（#45）。

### 3.4 与 AI / PM 的边界

- AI/PM 都是用户态慢环（10–100ms），共享环注入；1.1 只留接口与遥测，不接 AI。
- RT/deadline 类屏蔽 AI；AI 动作空间仍四类封顶（放置/频率 hint/包络内权重/EPP）。
- 快路径 `pick_next` 只读一次策略快照，零分配，绝不调 AI；有/无 AI 的 pick p99
  必须相等（1.1 只断言空表等价，1.2 再验有表）。

## 4. 单比较器

### 4.1 接口约束

`SchedClass` trait 签名**一字不改**（`enqueue/dequeue/pick_next/tick/priority`）。
比较器不是 trait 方法，而是 crate 内的一张**纯函数表**：

```rust
// 草案：不放 trait，避免冻结签名变更；按 ClassId 分派。
fn order_key(t: &Task) -> OrderKey;
fn preempts(cand: &Task, cur: &Task) -> bool; // 必须等价于 cand.key < cur.key
```

`pick_next` 返回 `order_key` 最小的 eligible 任务；`try_preempt` 只在
`preempts(cand, cur)` 为真时切换。两处若出现第二个键，视为设计违约。

### 4.2 比较器表（v1 过渡 + 目标）

| class | eligible | 主键 | 次序（tie-break） | 抢占条件 |
|---|---|---|---|---|
| critical-deadline（M5） | capacity 未耗尽 | 绝对截止期 | 截止期→task_id | 更早截止期 |
| deadline（1.1 最小 / M5 完整） | capacity 未耗尽 | 绝对截止期 | 截止期→task_id | 更早截止期 |
| fair（S2a 已落） | 带内 lag 近似 | `prio_effective` 降序 → `VD` | VD→vruntime→首见 | 同带 VD 更早 |
| fair（S2b 目标） | `lag>=0` | `VD` | VD→vruntime→task_id | VD 严格更早 |
| RR（已退役，仅回滚） | 恒真 | `prio_effective` 降序 | 同值→入队序 | 严格更高 |
| idle | 仅无其他可跑 | — | — | 不抢占 |

**class 链**是唯一的跨类规则：`critical-DL > DL > fair > idle`。高类空才轮到
低类；低类不得因权重/VD 越过空的高类（高类非空时低类不参与比较）。

**确定性**：S2a 同键按「head 侧首见」保序（游标推进 = 等权 FIFO 轮转）；
S2b 目标键序为 `task_id`。两者都**禁止指针地址**；同一输入重复 `pick` 必须
同结果（除游标推进外无副作用）。

### 4.3 `pick` / `preempt` 同源不变量

- **P1** `pick_next` 不摘除任务：runnable 常驻环；只有 `block`/`exit` 离环。
- **P2** 当前任务也在环上；`pick` 允许选中自己（tick 自耗合法）。
- **P3** **禁止幻影出选**：先 `peek_min` 只读判断，确认要切才 `pick`；
  「pick 了又不用」会消耗 head 相位，结构性饿死（现行 `has_eff_above` 防线，
  S2b 换成同键 `peek_min`）。
- **P4** `try_preempt` 的候选集与 `pick_next` 的 eligible 集必须同源；
  多对象等待（`WAIT_ANY`）不得改变排序键。
- **P5** `order_key` 只读 TCB 字段，零分配、零锁、不碰用户指针。
- **P6** 同一 `task_id` 在一个环上至多出现一次；`enqueue` 幂等断言。
- **P7** `priority()` 只决定 class 链位置，不参与类内排序。

### 4.4 S2a/S2b 换序的迁移规则

**S2a（已落）**：保留 `prio_effective` 严格带序，带内按 EEVDF
`(eligible, VD, vruntime)` 选；`try_preempt` 仍严格更高带才切（PI 语义零扰动）。
**S2b（待）**：去掉带序，改为纯 `(lag, VD)`；`try_preempt` 换同键 `peek_min`；
ktest 的 `POLICY`/`PRIO` 断言改为「同 weight 下 VD 序」金样。

S2 之前，RR 仍是唯一实现；**「单比较器」是形状约束，不是要求现在重写
`class.rs`。**

### 4.5 验收（S0 写规格，S2 执行）

| 编号 | 断言 | 形态 |
|---|---|---|
| CMP-1 | 任意 3 个任务的全序满足反对称/传递 | host property test |
| CMP-2 | `pick_next` 返回值 == 全集中 `order_key` 最小者 | host |
| CMP-3 | `preempts(a,b) == (key(a) < key(b))` | host |
| CMP-4 | 同输入重复 pick 同结果（游标推进除外） | host |
| CMP-5 | 1k 任务 pick 不分配、不取锁 | QEMU/ktest |
| CMP-6 | `pick` 后未切换次数 == 0 | 计数器 |

## 5. 进程级 token 冻结

### 5.1 冻结单位：默认进程，单线程需自证

用户态锁（pthread mutex、futex、共享内存里的自旋锁）内核看不见。冻结单线程
时，若它正持有一把用户锁，同进程其他线程会永久等锁；内核无法检测，也无法
安全回滚。**cgroup freezer 与 Android freezer 都以「整组/整进程」为冻结单位**，
不是巧合。

1.1 规则（最强档，但不假装内核能看见用户锁）：

- 默认冻结单位 = **Process（含其全部线程）**；域级递归冻结 v2。
- 单线程 freeze 是 **opt-in**：调用方先 `sched_setattr(thread, FREEZE_READY)`
  自证「已把用户锁放到安全点」，再 `process_suspend(thread, SINGLE_THREAD)`；
  无自证 → `-EBUSY`。内核只验证自证位，不验证用户锁。
- 跨进程共享内存里的用户锁不在 1.1 保证范围；`FREEZE_READY` 的语义是
  「应用自担」，不是内核担保（D8，见 §9）。

### 5.2 状态机

```
RUN|BLOCKED --suspend()--> FREEZING --(all threads safe)--> FROZEN
FROZEN --last token close--> THAWING --(requeue)--> RUN
FREEZING --timeout / abort--> RUN（回滚，不留半冻）
```

- `Blocked` 与冻结**正交**：阻塞线程被冻时仍记 Blocked，但**移出睡眠队列**；
  thaw 时按保存的剩余预算重插。
- `suspend_depth: u8` 由 token 计数维护；`FROZEN` 要求 depth>0；depth 上限 8。
- 进程退出时强制清 depth、token 变 dead，再走既有退出路径（不复活）。
  `process_terminate` 与自退出同收口；终止优先于冻结，不产生「冻着的死进程」。

### 5.3 token 对象

冻结寿命由 **SuspendToken** 句柄持有，不用布尔：

| 项 | 规则 |
|---|---|
| 对象类型 | `ObjType::SuspendToken = 12`（已拍板；`handle.rs` 现有 1–11） |
| 权利 | `DUPLICATE / TRANSFER / INSPECT`；持有即冻结权，不需 MANAGE |
| 创建 | `process_suspend(target, options, *token)`；target = Process 或 Thread，需 **MANAGE** |
| 解冻 | `handle_close(token)` 减一层；最后一层归零 → THAWING |
| 共享 | `handle_duplicate` 复制 token；所有副本关闭才解冻 |
| 持有者死亡 | 句柄表 teardown 关闭全部 token → **auto-thaw** |
| 目标死亡 | token 标 dead；close 幂等；对目标 `sched_getattr` 返回 `-EBADSTATE` |
| 上限 | 每 target depth 8；超限 `-EBUSY` |

**为什么不是布尔**：布尔 API 无法表达「两个监督者都要求冻结」，也无法在
持有者崩溃时自动解冻；Zircon `task_suspend` 的 token 语义是产业验证过的形状。

### 5.4 安全点

冻结只在**安全点**落地，不在任意指令处停：

```
safe_point(task) :=
    preempt_count() == 0
 && task.held_locks == 0        // 内核结构锁持有位（u8，HELD_*）
 && task.svc_mask == 0          // 不在 SVC 窗
```

- 请求时先做**静态检查**（held_locks / svc_mask / PI / in_flight）；不满足 →
  **`-EBUSY`**，不进入 FREEZING，不产生 `freeze_pending`。
- **类型检查**：`SINGLE_THREAD` 只收 Thread handle，且 `FREEZE_READY=1`；
  默认模式只收 Process handle；类型/标志不符 → `-EINVAL`；无自证 → `-EBUSY`。
- 1.1 目标只能是 Ready/Blocked（非当前）：检查通过即就地冻结，同步返回 FROZEN。
  `freeze_pending` 只保留给 v2 的 SMP/自冻路径，1.1 不产生。
- 动态落冻点只有两处：**返回用户态前**（eret trampoline）与
  **`block_current` 入睡前**。这两处天然不在内核临界区，不需要新 `in_kernel` 字段。
- 当前任务自冻：`process_suspend(self)` 在 1.1 **返回 `-EINVAL`**；自冻走 v2
  深睡协议。请求者只能是另一个持 MANAGE 的进程（appd/监督者）。
- SMP（v2）：向目标核发 SGI，目标在安全点 ack；超时 `-EBUSY` 并回滚。

### 5.5 三重正交谓词（任一命中即 `-EBUSY`）

- **PI 边**：`pi_inherited != 0` 或新增只读谓词 `pi::on_donation_edge`（S3 前置件）。
  理由：冻住受捐 server 会把 client 的 boost 钉死；冻住 donor 会让 server 等不到唤醒。
- **在飞义务**：`task.obligations != 0`（PAGER_REPLY / IPC_REPLY）。
  理由：冻住 pager 会让缺页者永久阻塞；冻住 reply 方会让调用链悬挂。
  - pager 角色（持久义务）：`process_suspend` 前扫目标 handle 表——持 demand
    VMO 且带 `SET_POLICY` 的槽 > 0 → `-EBUSY`（D6）。扫描派生而非 sidecar
    计数：close/take/drain/handle 迁移天然随表走，无漏减/UAF。
    不依赖瞬时 in_flight。
- **内核派生位**：`wait_signals & (SIGNAL_READABLE|SIGNAL_WRITABLE) != 0`。
  理由：`pi::donor_edge` 会解引用 `wait_obj`；冻住带派生位的 channel 端点会破坏
  「真 ObjRef」不变量（规则 04 §A40）。

`obligations` 是新增的 u8 位图（S3 前置件）：`PAGER_REPLY=1<<0`、`IPC_REPLY=1<<1`；
置位点 = pager supply 进入 / channel reply 挂起；清零点 = 完成或回滚。
**没有这个位图，三重谓词无法在内核侧成立**，1.1 必须把它列为 S3 前置件。

### 5.6 冻结动作（FROZEN 落地时）

1. 从 runqueue 摘除（若 Ready/Running）；Running 在安全点切走。
2. 从睡眠队列摘除（若 Blocked）；保存 `remaining_ns`。
3. `lag = 0`（不结转信用；thaw 后重新 eligible）。
4. 预算/refill 清零；周期 deadline 重锚 `now + period`；一次性等待保留
   `remaining_ns`（`freeze_clock=PAUSE` 默认）。
5. `frozen_since = now`；`frozen_usec` 开始累计；发一次 telemetry 事件。
6. 内存/handle **不释放**；fatal signal 仍可投递（冻结不是安全边界）。

### 5.7 解冻动作（THAWING→RUN）

1. 重新入环一次（幂等断言：不得重复 enqueue）。
2. `lag = 0` barrier：不允许用冻结期攒信用换 CPU（防止「冻 10s 回满血」）。
3. 预算从 `now` 起新周期；**禁止结转**冻结前的剩余。
4. Blocked 者按 `remaining_ns` 重插睡眠队列；到期补发一次，不静默丢。
5. 唤醒只发一次；多线程进程逐线程入环，不搞惊群。

### 5.8 IPC / 信号 / 计时语义

| 场景 | 语义 |
|---|---|
| 已入队消息 | 保留；冻结者 thaw 后照常 `recv` |
| 同步 `send` 到冻结对端 | 有界等待（1 slice）后 `-EAGAIN`；不引入 `EDEADLK`（ABI 无此码） |
| 异步 notification | 保持 pending；thaw 后投递 |
| fatal signal | 仍可投递；冻结不阻止 kill |
| `wait` 超时 | `PAUSE`：剩余时间冻结；`CONTINUE`：照走，thaw 后可能立即超时 |
| 周期 deadline | 重锚 `now+period`；miss 计数，不静默补 |
| 内存压力 | freeze 不回收；要回收走墓碑/kill，不走 freeze |

### 5.9 freeze vs tombstone vs kill

| 动作 | 状态 | 内存 | 恢复 | 用途 |
|---|---|---|---|---|
| freeze | 全线程/单线程停 | 保留 | 快（重新入环） | 深睡/调试/生命周期第一档 |
| tombstone | 进程死、状态存 | 释放 | 重新启动 + 读档 | 应用生命周期（#43，用户态） |
| kill | 进程死 | 释放 | 无 | 故障/策略 |

**1.1 把 freeze 作为生命周期的一档（Q12=B）**：失焦可先 freeze（RAM 保留、
快恢复），内存压力再落 tombstone（存档+杀）；由 appd 决定，内核不自动接。
**freeze 不等于墓碑**：tombstone 仍负责存档与跨 boot 语义，freeze 不存档、
不跨 boot（C4 的边界按此改写）。

### 5.10 错误码与权限

| 返回 | 场景 |
|---|---|
| `-EINVAL` | options 非法 / target 类型不符 / 自冻 / depth 非法 |
| `-EACCES` | 无 target **MANAGE** |
| `-EBADF` | 坏 handle / 类型不符 |
| `-EBADSTATE` | 目标已退出 / 已 dead |
| `-EBUSY` | 三重谓词 / depth>8 / 无 `FREEZE_READY` / SMP 超时 |
| `-EAGAIN` | 同步 send 命中冻结对端（调用方可重试） |
| `-ENOTSUP` | `INCLUDE_CHILDREN` 等 v2 选项 |

`process_suspend` 是**同步**的：返回时目标已 FROZEN，或返回错误且未冻结。
1.1 单核下目标只能是 Ready/Blocked（非当前），同步可保证；SMP 的 IPI 等待
放 v2。

### 5.11 遥测

`freeze_state / suspend_depth / frozen_usec / freeze_pending_age_ns /
freeze_abort_reason / token_holder_pid` 进现有 telemetry 环；不建第二数据库
（#45）。`FREEZE ok` / `FREEZE_BUSY ok` / `AUTO_THAW ok` 三个 ktest 标记。

### 5.12 安全边界

- token 只能由 `process_suspend` 创建，不能伪造；创建要 target MANAGE，
  持有即冻结权；可 `duplicate` 共享、可 `close` 吊销。
- `FREEZE_READY` 是**应用自证**，不是安全边界：恶意应用只能坑自己；
  跨进程用户锁不在保证范围（D8）。
- 防 freeze DoS：每 caller 活跃 token 上限 64（启动配置），超限 `-EBUSY`；
  被冻目标数/时长进审计。
- 目标表 pager_load>0 直接拒；token 持有者退出由句柄表 teardown auto-thaw；
  目标退出则 token 变 dead，close 幂等。

## 6. 饥饿界离线检查器

### 6.1 定位

上界**不能由 per-handle attr 在线导出**：weight 只在当前可运行集分份额，
class 链上层饱和可把 fair 压到 0。检查器是**配置期离线工具**，内核只做
单调收窄 + 计数；文档里的界必须由同一工具复现。

### 6.2 输入

```json
{
  "slice_ns": 100000000,
  "classes": [
    {"name":"fair","weight":100,"tasks":[{"id":1,"weight":100},{"id":2,"weight":100}]}
  ],
  "system_reserve": 0.05
}
```

### 6.3 公式

- **同 class 同 band、无更高类**：任务 i 的最大连续不服务
  `B_i = (Σw / w_i − 1) × slice`；等权 n 任务退化为 `(n−1)×slice`。
  这是工程近似上界；严格界需按 EEVDF lag 定义推导，S2 复核。
- **有更高类**：`B_total = B_fair + B_upper`；`B_upper` 取高类最长连续忙期。
  若高类利用率 `U_upper ≥ 1 − δ`，**无有限界**，检查器返回 `unbounded` +
  原因，文档不得写「有界」。
- **deadline/LC（EDF 形状）**：`C=budget_ns`、`T=period_ns`；可行性用
  `Σ(C_i/T_i) ≤ 1 − system_reserve`；需要响应时间时用 demand-bound function，
  不用固定优先级 RTA。
- **freeze**：显式冻结是**界外**的行政停摆；`B` 只对非冻结任务成立。
  冻结 server 导致 client 等，不算调度界，算外部故障。

### 6.4 输出证书

```json
{"bound_ns": 100000000, "assumptions": ["no higher class","weights stable"],
 "unbounded": false, "formula": "fair_eq_weight", "inputs_hash": "..."}
```

CI 比对：`docs/` 里的数字与证书差 >1% 即 FAIL；`unbounded` 不得写成
「有界」。证书进 `tools/` 纯函数 crate 的 host 测试，不跑 QEMU。

### 6.5 1.1 范围

- S0–S4 只有 fair + idle；RR 过渡期 `B=(n−1)×slice`，`slice_ns=100ms`。
- S5 加 LC/deadline 的利用率检验与准入；band/RT 的公式先写进接口，实现随 1.2/M5。
- 检查器**不替代** admission：准入在域挂载时做，运行期只 enforce（S5）。

## 7. ABI 契约（S1 冻结）

### 7.1 syscall 面（4 号，S1 冻结）

| 号 | 名字 | 作用 |
|---|---|---|
| 0x3C | `sched_setattr` | declare/update：weight/policy/intent/reserve/cap/deadline/budget/period |
| 0x3D | `sched_getattr` | query：effective（declared/consumed 走 telemetry/S4） |
| 0x3E | `process_suspend` | 冻结 Process/Thread，出 token 句柄；options bit0 = `SINGLE_THREAD` |
| 0x3F | `thread_yield` | 主动让出当前时间片；无 handle，等价内核 `yield_now` |

`process_suspend` 的 `options`：bit0 = `SINGLE_THREAD`（只收 Thread，需
`FREEZE_READY`）；bits1+ 保留，置位 → `-ENOTSUP`（`INCLUDE_CHILDREN` v2）。
解冻 = 既有 `handle_close(0x01)`，不新增 `process_resume`（避免两条路径）。
`thread_yield` 只让出当前片，不改队列/权重/预算；无其他可跑时立即返回 0。
0x38/0x39 保留原名，未来 `thread_set_priority` 作为 `sched_setattr` 的薄包装，
不破坏旧调用。

### 7.2 `sched_attr`

```c
struct berry_sched_attr {
    uint32_t size;        // == sizeof，或更大且尾部全 0
    uint16_t version;     // 1
    uint16_t flags;       // 未置位=继承；bit0 weight / bit1 intent / bit2 policy /
                          // bit3 freeze_clock / bit4 FREEZE_READY /
                          // bit5 reserve(min/max) / bit6 deadline / bit7 budget(period)
    uint32_t weight;      // bit0：1..10000
    uint8_t  policy;      // bit2：1 fair / 2 rr / 3 deadline / 4 idle
    uint8_t  intent;      // bit1：berry_intent 0x00..0x05（0x00=UNSPECIFIED）
    uint8_t  freeze_clock;// bit3：0 PAUSE / 1 CONTINUE
    uint8_t  reserved0;   // 必须 0
    uint64_t min_ns;      // bit5：fair reserve floor
    uint64_t max_ns;      // bit5：fair cap
    uint64_t deadline_ns; // bit6：LC/DL 相对截止（≤period）
    uint64_t budget_ns;   // bit7：LC/DL 预算（C）
    uint64_t period_ns;   // bit7：LC/DL 周期（T）
};
```

- `size < sizeof` → `-EINVAL`；`size > sizeof` 且尾部非 0 → **`-E2BIG`**
  （S1 在 `abi.toml` 新增；Linux 同款前向兼容语义）。`size > 256` 直接拒。
- `version != 1` → `-ENOTSUP`；未知 `flags` 位（bit8–15）→ `-EINVAL`。
- **字段生效由 flags 决定**：未置位 = 继承（含 0 值）；置位后按域解释，
  `intent=0x00` 是 UNSPECIFIED 而不是「继承」。`flags=0` 且其余全 0 =
  **清除 Thread 的显式覆盖**（回到 Process 默认）；对 Process 则回到系统默认。
- `reserved0 != 0` → `-EINVAL`；`bit3` 的 `freeze_clock ∉ {0,1}` → `-EINVAL`。
- `bit0`：`weight==0` → `-EINVAL`；`bit1`：`intent>0x05` → `-EINVAL`；
  `bit2`：`policy ∉ {1,2,3,4}` → `-EINVAL`（#58 六档不扩）。
- `bit5`：`min_ns<=max_ns`；只对 `policy=1/2` 有效，配 `policy=3` → `-EINVAL`；
  1.1 只存不执法，1.2 起 fair 包络。
- `bit7`：`budget_ns>0`、`period_ns>0`、`budget_ns<=period_ns`、`policy=3`；
  **`policy=3` 必须置 bit7**。`bit6` 可选：置位时 `deadline_ns>0` 且
  `deadline_ns<=period_ns`；未置位默认 `deadline_ns=period_ns`。
- `bit4`：只对 Thread 有效；置位 = 应用自证「用户锁已到安全点」；内核在 thaw
  时**自动清位**，下次单线程冻结必须重新自证。对 Process 置位 → `-EINVAL`。
- `policy=3` 在 S5 启用；`policy=4` 只允许 system 域，普通进程 `-EACCES`。
- `sched_getattr`：`size<sizeof` → `-EINVAL`；`size>sizeof` 时内核写满
  `sizeof` 并把尾部清零；`size>256` → `-EINVAL`。返回 **effective** 值；
  `flags` 只标有效字段，不标来源；declared/source 走 telemetry/S4。
- S1 只存；S2 起 fair 消费 weight/intent；S5 起 LC/deadline 消费
  budget/period/deadline，**fair 忽略 budget/period/deadline**。
- S5 设置 `policy=3` 时按 §6.3 做准入；`Σ(C_i/T_i) > 1 − reserve` →
  `-EBUSY`，且不改变旧值（事务性）。

### 7.3 权限矩阵

| 操作 | 对象 | 权利 | 自己 | 别人 |
|---|---|---|---|---|
| `sched_setattr` | Thread/Process | `SET_POLICY` | 允许 | 需 `SET_POLICY` |
| `sched_getattr` | Thread/Process | `INSPECT` | 免费 | 需 `INSPECT` |
| `process_suspend` | Process/Thread | `MANAGE` | 1.1 拒绝（`-EINVAL`） | 需 `MANAGE` |
| `thread_yield` | 当前线程 | 无 | 允许 | — |
| `handle_close(token)` | SuspendToken | 持有即可 | — | — |

Process 上的 attr 是该进程所有线程的默认值；Thread attr 覆盖默认。`sched_getattr`
对 Thread 返回继承 + 覆盖后的 effective 值，不回写默认。`FREEZE_READY` 是对
Thread 的自证位，设置它需要该 Thread 的 `SET_POLICY`。

### 7.4 事务性与失败语义

- `sched_setattr` 全成功或全失败；失败不得留下半套字段。
- 对 FROZEN 目标：`sched_setattr` 允许，只改声明、thaw 后生效；`sched_getattr`
  返回冻结前的 effective；`FREEZE_READY` 由内核清位。
- `process_suspend` 失败必须回滚：不留下 `freeze_pending`、不泄漏 token。
- 日志进 telemetry：`generation / actor / target / reason`，可追责。
- **新增 `-E2BIG`（-7，S1 入 `abi.toml`）**；其余复用
  `-EINVAL/-EACCES/-EBADF/-EBADSTATE/-EBUSY/-EAGAIN/-ENOTSUP`。
  若未来要 `EDEADLK`，单独 ABI 刀。

### 7.5 S4 消息头与账户（S4 冻结）

S4 的「受益者付费」需要一个内核内部消息头字段，不是用户 wire：

```c
struct berry_msg_billing { uint64_t domain_id; uint64_t charged_ns; }; // 16B
```

- `channel_send` fastpath 快照发送者 `domain_id`（零分配）；`recv` slowpath
  把该 id 设为「当前账单域」，server 运行时长记到 client。
- reply/abort/timeout 回退到 server 自己的域；无受益者记 system。
- 共享内存不自动传播；`channel_create` 预留 opt-out 位，S4 不启用。
- 头长大 16B 是内核内部布局，不是跨版本 wire；与 `MsgIntent` 同头共存。
  inline 上限仍 256B，+16B 从 payload 扣；超长数据走共享 VMO 不变。

### 8.3 1.1 出口（五条硬门）

1. **功能门**：EEVDF + attr + freeze + 记账/预算全链在 `smoke`/`smoke-smp`
   可跑，空策略逐位等价，`abi-check` 零漂移。
2. **证明门**：CMP-1..4 host property 全绿；饥饿界证书与文档差 ≤1%；`unbounded`
   场景有明确标记。
3. **性能门**：真机切换 p99 ≤ 基线 +5%；记账开销 <1%；freeze p99 <5ms、
   thaw 漂移 <1ms（阈值均为【推】的自定门）。
4. **预算门**：LC/deadline 在 90% 利用率返回 `-EBUSY`；70% 负载 miss <0.1%；
   fair 类 p99 回退 <2%。
5. **安全门**：PI/pager/派生位三类故障注入全 `-EBUSY`；token 持有者死亡
   auto-thaw；freeze/thaw 事务回滚 100%。

### 8.4 改动面（实施契约）

| 面 | 文件 | 改动 |
|---|---|---|
| 比较器 | `sched/src/class.rs` | `order_key`/`peek_min`/RR 回退；`pick` 与 `preempt` 同键 |
| TCB | `sched/src/task.rs` | `freeze_state/depth/freeze_ready/obligations` 字段 |
| 调度原语 | `sched/src/sched.rs` | 安全点、`freeze_current`、thaw、auto-thaw 钩子 |
| PI | `kernel/src/pi.rs` | `on_donation_edge` 只读谓词（`donor_edge` 语义不变） |
| 进程/句柄 | `kernel/src/process.rs`、`handle.rs` | `HandleTable::pager_load`（demand+SET_POLICY 扫描）；`ObjType::SuspendToken=12` |
| syscall | `kernel/src/syscall.rs` | 0x3C–0x3F；`-E2BIG` 分支 |
| IPC 头 | `kernel/src/channel.rs` | `MsgBilling` 16B；send 快照/recv 结算 |
| 遥测 | `kernel/src/telemetry.rs` | freeze/account 计数器与环字段 |
| ABI | `tools/abi.toml` + 生成物 | 4 号 + `E2BIG`；`abi-check` 逐字节 |
| 测试 | `kernel/src/ktest.rs`、`tools/smoke.sh` | `FREEZE*`/`STARVE_BOUND`/`ATTR` 标记 |
| 文档 | 本文 + ABI/设计/索引 | 已同步；S1 后再刷一次 |

**零行为变更纪律**：S1 只加号，不改旧号语义；S2 保留 `sched=rr` 回退；S3 关闭时
`process_suspend` 返回 `-ENOTSUP`；S5 关闭时只记账不 throttle。

### 8.5 回滚方案

| 里程碑 | 回滚 | 影响 |
|---|---|---|
| S1 ABI | 新号未使用即无行为；`sched_attr` 保留 ENOTSUP | 零 |
| S2 EEVDF | 启动参数 `sched=rr` 回 RR | 性能回退，无 ABI 变 |
| S3 freeze | `freeze=0`；已冻结 token 全部 auto-thaw | 语义回退 |
| S4 记账 | `billing=0` 停写账户 | 遥测缺一段 |
| S5 预算 | `budget=0` 只记账不 throttle | 无 admit/无罚 |

## 9. 决策与冲突

### 9.1 已拍板（D，2026-11-06）

| 编号 | 问题 | 裁定 |
|---|---|---|
| D1 | 正式名 | **「调点调度 1.1」**；文件路径 `docs/调点调度-v1.1.md` 不变 |

| D3 | freeze 单位 | **进程默认 + 单线程 opt-in**；单线程需 `FREEZE_READY` 自证 |
| D4 | token 对象 | **`ObjType::SuspendToken = 12`** |
| D5 | size 超界错误码 | **新增 `-E2BIG`**（S1 入 abi.toml） |
| D6 | pager 冻结 | **不可冻**（pager 是缺页链外部执行者，冻它=整机不可推进） |
| D7 | `thread_yield` | **加 0x3F**（4 个 syscall） |
| D8 | 跨进程用户锁 | 单线程必须 quiesce；进程级不保证；文档写明风险 |
| D9 | `freeze_clock` 默认 | **`PAUSE`**；RT/deadline 显式 `CONTINUE` |
| D10 | Meta 数字 | **降【未证实】**；可查的只有 ~1000 台、+3.5% 吞吐 |
| D11 | #20 基线追认 | **ADR #64**（不篡改 #20）；freeze 与 pager/PI 相交 |
| D12 | freeze 生命周期 | **作为墓碑前一档**；appd 决定；tombstone 仍负责存档/跨 boot |

**拍板口径**：每项取「最强但可证明」档；四类拒绝见 §1.5。D6 是唯一主动收窄：
pager 冻结不是能力，是可用性自杀。

## 10. 风险与 kill criteria

| # | 风险 | 后果 | Kill / 缓解 |
|---|---|---|---|
| R1 | 把「任何东西可调度」做成「任何东西一个 API」 | API 爆炸、不可验证 | 超过 4 个 syscall 或 attr 字段失控 → 回退单 attr |
| R2 | freeze 当零成本开关 | 持锁冻死锁、丢唤醒 | p99>5ms 或丢唤醒>0 → 降级仅深睡 |
| R3 | 把公平宣传成时限 | 对外承诺违约 | 文档写「比例，不保证时限」 |
| R4 | 预算=准入混写 | 过载时既不保公平也不保时限 | S5 只对 LC/deadline 准入；fair 永不准入 |
| R5 | 账户只记不罚 | 白嫖、欠费无界 | S4 只记账；S5 欠费>10% 加罚（仅 LC/deadline） |
| R6 | 域树越深越好 | pick 与缓存成本 | depth>4 或 pick>5µs@1k → 扁平化 |
| R7 | 把 sched_ext 搬进内核 | GPL + 验证面灾难 | 只借契约；BPF/verifier 不进内核 |
| R8 | 用未证实数字背书 | 评审被一手来源打穿 | Meta/APS/proxy 数字降级或撤回 |
| R9 | 只在大核测 | 小核 p99 崩 | 小核 ≥2 配置进验收 |
| R10 | AI 动作扩权 | 违 #42 带内纪律 | 越权 → 停实验，回 hint-only |

**不做清单**：指令级调度 / 每对象一个 runqueue / 策略进 `pick_next` /
per-handle 硬预算 / 布尔 freeze / 冻结 PI donor/pager / thaw 结转预算 /
reserve 按域累加 / 用 QEMU 数字报 p99.9 / 第二套 intent 词汇表。
