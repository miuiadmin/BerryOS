# 调度器与电源管理设计

> 版本：**1.1**（v1.1）｜2026-11-08

> BerryOS 用**一个调度器内核**同时服务两类极端场景。本文是单一事实来源，`AGENTS.md` 速览与 `docs/规则/04-调度与IPC.md` 域铁律是本文的摘要。v1.1 增量：在调点调度 1.1（EEVDF 基线，见「调点调度 1.1–1.3」节）之上收录 **1.2/1.3 全部落地增量**——S6 策略服务（三槽 RCU 换表 / shadow 双轨道 / 0x83 六 op / A/B 升级 / SMP 三件套）、EAS 能效、band 层级预算、HDR 测量基础设施与热路径优化（文末「策略服务（S6）」起五节 + 里程碑表 S6/EAS/SMP 行）。

## 1. 目标与约束

| 场景 | 平台 | 关键诉求 |
|------|------|----------|
| 可穿戴 / 手机 | ARM 大小核、单/少核、电池 | 省电、低唤醒延迟、DVFS、深睡 |
| 桌面 / 服务器 | x86_64 / ARM64 对称多核 | 高吞吐、低尾延迟、多核扩展 |

**已定策略：双线并行** —— 省电路径与多核性能路径同时作为一等公民推进，接受更高复杂度，不分先后。

**核心原则：机制进内核、策略可插拔、把"算力不对称"抽象掉、电源管理做成用户态服务。**

## 2. 总体架构

```
            ┌──────────────────────────────────────────┐
用户态 Rust  │  PM 服务：DVFS governor / 热管理 / 休眠策略 │
            │  AI 调度服务：工作负载分类 → 放置/优先级策略 │
            │   ▲ 遥测(共享环)   ▼ 策略注入(共享环,SET_POLICY)│
────────────┼──────────────────────────────────────────┼───
内核态 Rust  │  调度器核心：每核 runqueue + class 派发框架  │
            │   ├─ class_rt       实时（★ AI 不得干涉）   │
            │   ├─ class_fair     EEVDF, 吞吐/公平        │
            │   │  (v1/v2 单实例·intent=查表键;           │
            │   │   M4 起 ×N 带实例, 见 §3.8 / ADR #42)   │
            │   ├─ class_deadline 媒体截止期（★AI不得干涉）│
            │   └─ class_idle     进 idle 状态            │
            │  capacity / 负载均衡 / tickless / 安全护栏   │
            └──────────────────────────────────────────┘
```

**职责切分（微内核硬约束）**
- 不可委托、留内核：上下文切换、runqueue、定时器/tick、idle 入口、改频原语、capacity 拓扑。
- 可委托、推用户态：DVFS 算法、热管理策略、休眠决策、调度策略调参。

理由：调度在中断/缺页时也要跑、每秒千次、不容 IPC 延迟 → 机制必须在内核；而策略重、可调、可崩 → 推用户态，崩了内核降级保活。

## 3. 调度机制（内核 Rust）

### 3.1 每核 runqueue + 派发框架
- 每个 CPU 一个 runqueue，热路径几乎不加锁。
- 派发循环：按 class 优先级链查 `pick_next()`，高优先级类（rt/deadline）先空才轮到 fair。
- 上下文切换是固定原语，与策略解耦。

### 3.2 可插拔调度类
每个 class 实现统一接口，启动时按平台注册默认 class 集：

```rust
trait SchedClass {
    fn enqueue(&self, t: &mut Task, rq: &mut Runqueue);
    fn dequeue(&self, t: &mut Task, rq: &mut Runqueue);
    fn pick_next(&self, rq: &Runqueue, topo: &Topo) -> Option<&mut Task>;
    fn tick(&self, t: &mut Task, rq: &mut Runqueue);
    fn priority(&self) -> i32;   // class 间优先级
}
```

### 3.3 capacity 不对称抽象（统一三端的关键）
- 每个 CPU 一个 `capacity`(0..1023) 与 `max_freq`：
  - PC：全 1023（对称）→ 不对称代码退化为 no-op。
  - 手机 big.LITTLE：big=1023 / mid≈700 / little=300。
  - 手表：单核 ≈300。
- energy-aware 放置：小背景任务→小核；突发 perf 任务→大核。对称 PC 看到全相等 → 退化成普通负载均衡。**一条路径三端通用**。
- 拓扑/capacity 由 `arch/<arch>/` 启动时填表，核心逻辑架构无关。

### 3.4 负载均衡 / work stealing
- 空闲核定时或被唤醒时从忙核拉任务；考虑 capacity 与能耗（不在小核堆满）。
- PC 多核吞吐主力；手表 1–2 核时近乎零开销。

### 3.5 裁决补注（2026-10-15 战略裁决）
- **fair 类底座写定 EEVDF**（非 CFS）：M4 实现时直接按 EEVDF 语义（虚拟截止期 + lag 排序）落，避免「先 CFS 后 EEVDF」的返工；Linux 6.6+ 仅作思路（GPL）。
- **时间片周期数记账（DVFS 预埋）**：slice 以**周期数**而非绝对时间记账，随当前频点换算（LiteOS-M `OsSchedTimeConvertFreq` 式，调研 03 号）——否则 DVFS 上线后时间片实际时长随频率漂移，省电线与性能线在此汇合。**已落地（2b-4，2026-10）**：`slice_left` 存周期数、tick 以 CNTVCT 增量扣减（表示法字段同步进 TCB）。
- **SMP 锚点**：v1 全程单核贯穿 MVP，不为「将来多核」提前缴复杂度税；per-CPU runqueue 数据结构 day-one 按每核数组写（G1 已如此），但锁与均衡逻辑 G2 才进（关卡顺序即纪律）。
- **intent 两段式（2026-10-16 调度架构裁决，ADR #42）**：EEVDF 底座之上叠 intent 维——**公平是机制默认，intent 是策略输入，叠加永不替代**。v1/v2 intent 仅是 u8 查表键（零新层级机制）；M4 起 class_fair 按 intent 实例化 ×4 带 + 预算包络，凭 v1 遥测入场券。完整裁决、编码冻结与 IntentProfile 见 §3.8。

### 3.6 优先级继承联动（与 `IPC设计-v1.0.md` §2.1 配对 · D4 无悔项）

- **TCB 双优先级**：`base`（策略设定）/ `effective = max(base, 继承来源)`。调度决策（pick_next、队列位置）一律看 `effective`。
- **boost 即重排**：IPC 侧发起/解除捐赠时，按 `effective` 重排所在 runqueue——boost 一个阻塞链上的 server，等于让整条链以 client 的优先级跑完，这正是微内核软实时确定性的来源（QNX 消息驱动 PI 语义）。
- **传播有界**：阻塞链深度上限（如 8 层），到顶按已达 boost 处理；boost 是临时态，解除即回落 `base`，不污染 fair 类的权重/lag 记账（EEVDF 记账跟 `base`，排队跟 `effective`）。
- **RT/deadline 类**：不参与继承捐赠的「降级」方向——低优先级来源永不拉低 RT 任务；RT 任务作为发送者照样捐赠（它阻塞在服务上是实时系统最经典的反转点）。
- **intent 随消息传播（PI × intent 联动 · ADR #42 五件套，**已随 4-3c 落地**——`sched/src/intent.rs`，细节见 `IPC设计-v1.0.md` §2.1 拆步表注记）**：client 的 `intent_effective` 随 channel 消息头（`MsgIntent{intent, hop, acc_ns}`）传播给 server——`intent_effective = min(declared, msg_intent)`（u8 越小档越高，语义 max），**每消息重导**（临时 override，绝不永久改 server 声明档，XNU requested/effective 分离；弱消息自然回落 = reply 即回退的无 reply 等价物）；**账记客户端**（QNX 分区记账模式），但结算全在 slowpath（recv 时），send fastpath 只做一次快照**零记账**；**每跳执行预算帽 50ms + 累计时间封顶 400ms**（seL4 Johnston 2022：仅限跳数不够，失控服务链能吃光调用方预算），超顶降级为不传播并打 trace + 计数；**channel 级 opt-out** 逃生门（`channel_create` options bit0，系统服务/看门狗类 server）；**共享内存 VMO 不自动传播** + **值通胀计数器进遥测**（每消息重导下通胀不单调，但未声明 0x00 借出最强档仍会推高——计数器是它的可观测信号；§3.6 的 8 层限的是阻塞链深不是消息链——高频公共服务被 LC 客户端触达后整条链向顶带收敛是本设计最大单点风险）。五件套并入本捐赠框架不另起第二套。
- 阶段化：字段已随 2b-4 落 TCB（base/effective 双优先级 v1 恒等）；语义随 P4 channel；验收用例见 `IPC设计-v1.0.md` §2.1（三任务链唤醒延迟上界）。

### 3.7 RT 路径静态池化预留（v2 工业 RT 预埋 · D4 无悔项）

- **RT class 不进 buddy/slab**：RT/deadline 任务的 TCB、runqueue 节点、消息缓冲走**构造期预算分配的静态池**（INTEGRITY-178「内核零动态分配」模式，12号 §3.2）；分配器本身留内核服务 fair 路径——静态池是**旁路**不是替换。
- 理由：动态分配的页缺失/合并/锁竞争是 WCET 的直接威胁；微内核下 RT 路径 = 调度 + IPC fastpath（§IPC 7）+ 唤醒，三处都零分配才能给出可测的最坏延迟。
- v1 零成本：仅此设计位；实现随 M5（RT/deadline class）落地，静态池容量进启动配置（平台分层填表）。

### 3.8 intent 两段式（ADR #42，2026-10-16 调度架构裁决）

**裁决一句话：公平是机制默认，intent 是策略输入。** 公平提供可证明的比例份额与兜底（信任锚——EEVDF 本身是加权公平数学、sched_ext 失效回落宿主公平调度器、Zircon 底座即比例份额），intent 提供工作负载知识（策略大脑——Android cgroup 分带 / XNU QoS / Windows EcoQoS / QNX 分区 / Meta sched_ext 软分区 p99 -28%，量产证据全在公平底座上叠 intent 层）；两者叠加、永不替代。BerryOS 不做的是「无工作负载知识的裸公平作为唯一策略」，不是公平本身——band 内 EEVDF + 预算包络 = CBS/GRUB 分层公平数学，「抛弃公平」叙事与要建的机器南辕北辙。

#### 第一段（v1/v2：零新层级机制，~80% 收益）

intent = u8 查表键，直驱既有参数轴（无带间选择器、无预算记账——不为 band 提前缴复杂度税）：

- **TCB 增量**（P3 早期独立小步，内部层 UNSTABLE 窗口）：
  ```rust
  pub struct Task {
      // 既有（2b-4 已落）：prio_base / prio_effective / duration_hint_ns
      //                   / epp / preempt_threshold / slice_left(周期数)
      intent_declared: u8,   // 创建时声明，0x00=UNSPECIFIED；pledge 只降不升
      intent_effective: u8,  // = min(declared, msg_intent)（u8 越小档越高，语义 max）；
                             // 每消息重导（4-3c 已落）——reply 即回退的无 reply 等价物
      intent_hop: u8,        // 借入来源跳数（转发快照 +1；4-3c 已落）
      intent_since: u64,     // 借入生效时刻（纳秒，vct 域）——每跳预算判定源
      intent_acc: u64,       // 链累计持有时长（纳秒）——累计封顶判定源
  }
  ```
- **IntentProfile 映射表**（纯数据、按设备档位选表、与 capacity 轴正交；启动配置加载，支持运行时更新 + 模型不可信回退保守通道——宁可不省、不可错放；XNU `qos_policy_params` 四轴表同构）：
  ```rust
  struct IntentProfile {
      latency_nice: i8,       // EEVDF 虚拟截止期偏移（负 = 更早截止期）；v1/v2 唯一硬效应列
      weight_floor: u32,      // AI ④类动作的带内包络（min/max 夹紧）
      weight_ceiling: u32,
      epp: EppHint,           // perf / efficiency
      uclamp_min: u16,        // 0..1024，喂 PM/DVFS
      uclamp_max: u16,
      timer_slack_ns: u64,    // LC=0（exact 逃生舱 day-one 保留：闹钟/心率告警绝不顺延）
      maintenance_eligible: bool,
      // PC 表追加列（v2+）：capacity 放置 hint；手表表无此列（单核无选位）
  }
  ```
- **deadline/RT 任务也查此表**（EPP/uclamp 列）——RT 存在即被钉 MAX 频率是电池杀手（Linux uclamp 之前 SCHED_FIFO 的教训）；**RT 屏蔽 AI ≠ RT 免治**。

#### 第二段（M4/v3：band 层级，凭证据入场）

- **三层拓扑写死**：class 链（rt/deadline）> band 严格序 > 带内 EEVDF。band 仅是 fair 类内部再分层，RT/deadline 在 band 之外语义不变；media/音频 CPU 供给走 class_deadline，intent 查表只管软参数。
- **每带预算包络 + deadline-server 式兜底**：兜底流量以预留带宽的截止期方式尽早服务、不吃周期末尾剩饭（Linux RT throttling 950ms/1s 的 20 年坑，6.12 起自己迁离）；**每带都要包络**（带间饥饿的真正受害者是中间带不是底带）。QNX 三件套照搬：只在竞争时执行（本带超支且别带有就绪线程且有预算才禁跑）/ 空闲预算 loan / 整数微记账（16×16 缩放乘法免内核除法）+ **事件驱动虚拟时间记账**（上下文切换 + 定时器事件时结算，绝不复活周期 tick）。
- **入场券（先建后上）**：v1 遥测实证（饿死事件计数 / 过载尾延迟差 / 整带功耗杠杆）+ loadgen 合成负载 + 尾延迟断言 + 「有任务可跑但核空闲」金丝雀**已建成**。扁平 EEVDF + latency-nice 是 band 必须打败的零假设（Linux 主线就是它）；band 只在两件 weight 做不到的事上有净收益——**预约语义**（过载防饿死硬保底）与**整带功耗杠杆**（background 挂起阀门），两场景都在极端负载才兑现，日常与参数用法行为不可区分。证据始终不满足则单实例 + 查表键即终态（不是债务，见重议触发器）。
- **`SchedClass` trait 签名零改动**：band 化 = 同一 trait 按 intent 实例化 N 份 + 带间一层选择器；严格序映射到既有 `priority() -> i32`；数字不写死进本文档，进启动配置参数表（同 RT 静态池容量先例）。
- **v2 均衡器（M1b）预埋 band 维**：busiest 度量数据结构留 band 维注释（表示法纪律：形状现在定、实现 M4 补），否则 M4 加 band 后 N 维全返工；跨带偷取裁定「**仅向下偷**」（idle 核可服务任意带，核内严格序不变）。

#### 编码冻结（`berry_intent`，`#[repr(C)]`，随 ADR #42 冻结；判别 `intent_valid` 已随 4-3c 落进 `sched/src/intent.rs`，入口治理随声明入口 syscall）

| 值 | 档 | 语义 |
|----|----|------|
| 0x00 | UNSPECIFIED | **XNU 式最高可用档**：「未声明」不是「声明了低档」——不设限，可被 manifest 角色表（P3）/ (B) 分类器（M4）定档，**pledge 豁免**；过载降级做护栏 |
| 0x01 | LATENCY_CRITICAL | 需 **Job 级授权**（manifest/特权，XNU 禁裸 QoS 同构）；timer slack=0 exact；AI 屏蔽 |
| 0x02 | INTERACTIVE | 交互 |
| 0x03 | UTILITY | **推断缺省落点** |
| 0x04 | BACKGROUND | maintenance_eligible 门控 |
| 0x05 | MAINTENANCE | **编码冻结、v1 不启用**（用户裁决 2026-10-16） |
| 0x06..0x0F | 保留 | 内核拒绝；未知值 `-EINVAL`（与 options 纪律一致） |

- **入口治理**：intent 声明权 = 创建者 / `SET_POLICY` 持有者；应用线程只能降不能升到高带；运行时紧急晋升由既有内核防饥饿 boost 承担（boost 是临时态不是改声明，与单调收窄零冲突）。
- **遥测落盘（v1 day-one）**：intent + 标注来源（声明/角色表/推断）+ 值通胀计数器进遥测通道——字段要有消费者与测试覆盖；M4 映射表与入场券的依据来自实测（Meta 的表来自生产 A/B），不是拍脑袋。
- **timer 原语带 slack+policy 三元组**（学 `zx_timer_set`，v1 day-one）——intent 的 timer_slack_ns 列的执行载体，也是省电第二杠杆（唤醒合并）的内核机制；比 Linux 事后打补丁干净。

## 4. 省电路径（tickless + idle）

### 4.1 Tickless（NO_HZ）—— 续航第一杠杆
- 每核动态 tick：runqueue 空的核**不收周期定时中断**，把下次定时器编程到"有活到达 / 最早截止期"。
- 双线并行的硬要求：从 day-one 就走真省电路径，不是后期打补丁。
- **绝对截止时间重编程（纪律，非可选 · 12号报告 §2.3/§10.3）**：定时器**永远编程到绝对到期时刻**——唤醒后以硬件计数器（CNTV/CLOCK）的当前读数重算，取 `min(最早超时事件, 当前任务时间片终点) − 安全裕量` 重装载；**绝不**基于「上次编程值 + 周期」外推。反面是 FreeRTOS 停止-补偿法（睡前停 tick 醒来补账），官方自认「必然带来内核时间与日历时间漂移」；正面先例是 LiteOS-M `OsSchedSetNextExpireTime` 按绝对到期时刻重装载。手表闹钟/健康采样对长期走偏敏感——累积漂移是日历级事故，这条纪律等价于「不许降级回补偿式」（与重议触发器中 tickless 条款互为表里）。

### 4.2 Idle 状态 / C-states
- runqueue 空且无 pending → `class_idle` 接管 → 进最深可用低功耗状态（ARM: WFI 及更深；x86: C-state）。
- 唤醒延迟与省电深度的权衡由 PM 服务定（用户态策略）。
- **深睡档三件套（v2+，设计位先记 · 12号 §2.3）**：① 超时任务**冻结**（LiteOS-M `OsSchedFreezeTask` 式：深睡前把超时任务摘链冻结，深睡期间**零定时器中断**，醒后按绝对时刻补齐调度）；② **唤醒延迟预扣**（Zephyr PM：选睡眠档时先扣 exit_latency， deadline 减去它才允许进）；③ **latency QoS**（服务声明可容忍唤醒延迟，PM 排除过深的档位）。tickless 管「空闲不白醒」，三件套管「深睡不误事」——两层合起来才是省电主力。

## 5. 电源管理服务（用户态 Rust）

### 5.1 governor 职责
- 订阅利用率（PELT/util_est 风格）→ 算目标频率（schedutil 风格：util→freq）。
- 决定簇（cluster）频率、热限频、休眠/唤醒策略。
- 可加载不同 governor：`watch`（激进省电）/ `perf`（跑分）/ `balanced`。

### 5.2 内核 ↔ PM 通信（低延迟硬约束）
- **共享环形缓冲**传利用率事件与设频请求；**禁止通用 IPC 消息拷贝**（否则吃延迟）。
- 内核侧只暴露最小钩子；频率变更由内核原语执行（写时钟 / 调压器寄存器）。

### 5.3 容错
- PM 服务崩溃 → 内核保住上次频率继续跑，监督重启服务。调度不依赖 PM 在线。

## 6. 每任务能效/性能 hint（EPP 风格）
- 每个任务带 hint：`perf`（大核 + 高频）或 `efficiency`（小核 + 低频）。
- UI/音频/传感器 = perf；同步/备份 = efficiency。
- PC：hint 映射到 boost 选择；手机：映射到大小核 + DVFS；手表：影响频率。

## 7. 诚实的代价 / 取舍
- tickless + 不对称感知 + 可插拔类 + 用户态 PM = **显著复杂度与调参面**。这是跨手表→PC 不 fork 的代价。
- PM 拆用户态是真红利，但通信必须共享环/零拷贝，否则延迟劣化。
- 双线并行意味着两条线都要有 QEMU 验证用例：多核 `virt` 机型（性能线）+ 单核低功耗场景（省电线）。

### Phase 2a 实现纪要（M0 + M1a，2026-08 已落地，过关卡 G1）

§3.1/§3.2 的前瞻设计在 Phase 2a 落地为可跑代码。关键实现点（源码 `sched/src/{sched,class,runqueue,task}.rs` + `arch/aarch64/src/{lib,task,trap,timer}.rs`）：

- **上下文切换 = 纯叶子 asm**（ADR #30）：`switch(prev,next)` 无 prologue，只存 x19–x30+sp、载入、`mov sp`、`ret`。纯叶子保证「存的 SP == `load_frame` 所需 SP」，使 switch 能安全发生在 IRQ 中段——切回时经 `exception_irq` 回退到 `load_frame`→`eret` 回被中断 PC。
- **runqueue 持裸指针**：侵入式环形链表存 `NonNull<Task>`，runqueue **不拥有**可变 `Task`。`pick_next(&Runqueue)` 返回 `Option<&mut Task>` 由指针派生（`unsafe { &mut *p.as_ptr() }`），不经 `&Runqueue` 借用——故能在 `&Runqueue`（冻结签名）下旋转游标（`Cell` interior mutability）并返回可变引用（plan Bug 5）。
- **RoundRobin 先行**（G0/G1 默认 class）：`pick_next` 旋转游标、不摘除任务（runnable 常驻环）；`tick` 饱和递减 `slice_left`；`RR_QUANTUM=1`（每 tick 切一次，最公平、便于压测）。
- **IRQ 驱动抢占（无 yield）**：CNTV timer slice 到 → `exception_irq`（EOIR 之后）→ 经 fn 指针槽调 `on_irq_tick` → `RR.tick(current)` 减时间片 → 归 0 则 `pick_next`，若 `Some(next)!=current` 则 `switch`。两忙循环任务 `A`/`B` 在 slice 下交替，**全程无 `yield` 调用** = 里程碑「两个内核任务在定时器上分时」。
- **fn 指针槽倒置**（ADR #31）：HAL 持 `IRQ_DISPATCH: Option<fn>`，boot 时内核注册 `sched::on_irq_tick`。HAL 不依赖 berry-sched，编译期解环。
- **EOIR-before-dispatch**（ADR #32 / Bug 1）：`ack → timer::handle(rearm) → EOIR → dispatch`。switch 永不跑在「IRQ 已 ack 未 EOIR」窗口，避免 GIC 优先级泄漏致后续 IRQ 饿死。
- **switch 仅在 PSTATE.I=1**（ADR #33 / Bug 2）：协作 `yield_now`/`exit_current` 均 `disable_irq`→switch→`enable_irq`；IRQ 路径硬件入口已屏蔽。switch 无需自重入保护。
- **trait 校对**：§3.2 的 `trait SchedClass` 与实现 `sched/src/class.rs` 一字一致（冻结守约，签名未改）。

**实测**（G1 出口）：200s soak 稳定 1000+ 切换、A/B 近平衡、零崩溃；`just run-el2`（EL2→EL1 eret）同样通过。QEMU TCG 下 CNTV tick ≈ SLICE_HZ/2（见 `测试策略-v1.0.md`）。FPU 面（ADR #34）：reset 隐式依赖已消除——boot 已显式写 `CPACR_EL1.FPEN=0b11`（2026-10-15 落）；陷+按需保存（`FPEN=0b00` + q 入 TaskContext）待首个 FP 用户出现时落地。

## AI 原生调度（详见 `AI调度设计-v1.0.md`，决策 #21）

调度器的**策略层**被设计成 **AI 原生**：内核留第一类接口，让用户态 AI 策略服务经共享环**干涉** `class_fair` / 后台类的放置与优先级，并可下发 **per-cluster 频率 hint**（频率由 PM 服务裁决/执行，见下方「安全护栏」与 `AI调度设计-v1.0.md` §10）。它是 `class_fair` 的策略源之一，与 PM governor 同级同模式。

- **慢/快循环切分（命门）**：快路径 `pick_next` 查「策略表」快照（μs、零分配、**绝不调 AI**）；AI 服务 10–100ms 慢循环重算表。
- **RT / deadline 类屏蔽**：AI 一律不得干涉，软实时确定性不容 ML 方差。
- **安全护栏**：防饥饿 / 热硬限 / 越界拒收，**内核强制**（AI 提议、内核处置）。
- **容错**：AI 服务崩 → 回退启发式（EAS + capacity），调度**不依赖 AI 在线**（同 PM 服务模式）。
- **平台分层**：手表不上 AI（单核已近最优，模型能耗净负）；手机轻量 advisor；PC 完整 advisor 跑专用管家核。
- **阶段**：v1/v2 埋遥测 + 注入留桩；v3 启发式分类 advisor（(B)路线，随 G4–G5 开发）；v4+ 设备端学习策略（(A)路线，G5 之后）。**AI 调度质量是 G5 之后的增强、不作关卡通过条件**；但 **AI 护栏不变量**（RT 屏蔽、越界拒收）须随调度器正确性一起验证（见 `测试策略-v1.0.md` §8）。

## 策略服务（S6，调点调度 1.2）

§2「机制进内核、策略可插拔」的用户态兑现：0x83 `policy_bind` 注入协议 + 快路径查表快照 + shadow 双轨道升级路径 + SMP 安全三件套。实现 = `sched/src/policy.rs`；使用面（六 op 详参 / 工具链 / 工作流）= `策略服务用户指南-v1.0.md`。

### 三槽 RCU 原子换表（ACTIVE + gen 世代 + O(1) 黄金比散列）

- **快照化**：策略表不持 `&'static [Entry]` 热路径线性扫——`bind` 把表语义映射进 `Snap`（256 定长桶 + gen + count），经 `publish` 原子换入三槽轮转区 `SNAPS[3]`；**槽一经发布内容不再改写**（RCU 式换表，写者只写非活跃槽）。
- **ACTIVE AtomicU32 发布序**：值域 = 槽号 0..=2 或 3 = 哨兵空表（OFF/回退态指向 `EMPTY_SNAP`）；写侧「槽写完 → fence(Release) → ACTIVE.store(Release)」、读侧 Acquire——**见槽号必见槽内容**；决策路径（apply/weight_of）每次调用取一次快照指针、窗内不换（RCU 读临界区形态）。
- **O(1) 黄金比散列**：`bucket_of = key × 0x9E3779B97F4A7C15 >> 56`（乘 2^64/φ 取高 8 位 = 桶号）——键位（指针/标签）分布不均也摊平；开放寻址线性探测 ≤ 8 步（PROBE_MAX），插入与查表同一探测序列 → 查表遇空槽早退可靠；单表 ≤ 128 条（TBL_MAX，装载因子 ≤ 50%——聚簇概率上界）。
- **gen 世代陈旧拒收**：COMMIT 须严格大于 active 世代、SHADOW_COMMIT 严格大于 shadow 世代，违反 → `-EAGAIN` 且对应谱系快照未动——写者重放/乱序到达的旧表不得覆盖新表（gen 对齐 ADR #28）。
- **空态等价不变量**：未绑（哨兵）或空表（count==0）→ `apply` 两次分支即返、**零写入**，与「接口缺席」逐位等价（ktest `POLICY ok` 断言，非口号）。
- **weight 包络 ±64 三点执法**：handler 表解析夹紧 / build_snap 夹紧 / apply·weight_of 消费点再夹紧——注入数值无论多大，生效权重恒在 [-64,+64]，只单调收窄、无提权路径；合成公式 `prio_effective = max(prio_base + weight, pi_inherited)`（与 §3.6 PI 捐赠同公式双写点）。
- **拒收入账四计数**：key0 哨兵丢弃 / TBL_MAX 截尾 / 探测窗满 / 越包络被夹——静默处置有账（`reject_stats()`，自 bind 单调累计）。

### Shadow 双轨道（bind_gen_shadow / promote / demote / divergence 对账）

- **双轨道隔离的结构性保证**：`ACTIVE` 值域只有 0..=2/哨兵 → 快路径经 `active_snap()` 永远只达 `SNAPS`/`EMPTY_SNAP`，shadow 双槽（`SHD[2]`）对快路径**不可达**——非口头约定，是地址空间上无别名；shadow 表**只算不用**：每次 pick 对同一 key 双表各算一份决策，差异只计数、永不应用。
- `bind_gen_shadow`：写 `SHD[SHD_WHERE ^ 1]`（非活跃槽）→ 翻转 `SHD_WHERE` 发布；**ACTIVE 不动**。
- `promote`：shadow 读 + `Snap` 按值 ~4KiB 受控拷贝 + `publish` 单条 Release store 原子转正；**active gen := shadow gen**（此后 active 侧陈旧拒收比照该值）；shadow 空（gen==0）→ 拒绝转正（syscall 面 `-EBADSTATE`）。
- `demote`：`ACTIVE` 打回哨兵——读路径立即回落空表（等价「接口缺席」态）；**shadow 表保留**可再次 PROMOTE 复转正（降级态偏差从零观测）。
- **divergence 对账**：`apply` 每调一次、shadow 谱系非空时对同一 key 双表各算一份消费点决策（夹紧权重 + EPP），**weight 或 EPP 任一差异**只计数不应用（shadow 侧零 TCB 写、零表写）；`shadow_eval_count` = 分母（对账期内 shadow 决策评估次数）、`divergence_count` = 分子（shadow 会做的 ≠ active 做了的）；**轨道切换（promote/demote）自动清零**——对账期与轨道绑定，读数即当前对账期。

### 0x83 `policy_bind` 六 op

| op | 名称 | 参数 | 语义 |
|----|------|------|------|
| 1 | COMMIT | tbl/count/gen | 整表提交为 **active** 快照，立即参与调度决策 |
| 2 | STATUS | 三出参 | 双谱系世代（单读窗打包无撕裂）+ 调用者自身键 + divergence 双计数 |
| 3 | PROMOTE | 无 | shadow → enforced 原子转正；active gen := shadow gen；对账清零 |
| 4 | DEMOTE | 无 | enforced → shadow 降级：active 回空表、**shadow 保留**；对账清零（幂等） |
| 5 | UNBIND | 无 | 解绑回「接口缺席」哨兵态（拆除/对照测试用；幂等） |
| 6 | SHADOW_COMMIT | tbl/count/gen | 表形同 COMMIT，换表对象 = **shadow 谱系**（只算不用） |

- 公共收表面：单表 ≤ 128 条超限 `-E2BIG`（诚实拒收不静默截断）；`copy_from_user` 整表拷入后逐条解码（无 TOCTOU）；`_rsv≠0` / epp_flags 未定义位 → `-EINVAL`；0 键哨兵、重复键（first-wins）、桶溢出由 build 语义丢弃不报错。
- `PolicyEntry` 16B `#[repr(C)]`（key@0 / weight@8 / placement@12 / epp_flags@13 / _rsv@14）——**偏移即 ABI**，berry-sys const 断言钉板两端一致。
- v1 无 handle 门控（系统全局单通道，`auth` 预留传 0）；SET_POLICY 门控随 Job 对象落地后收紧（v2 遗留件）。

### A/B 升级判定（divergence 率 → PROMOTE / DEMOTE / HOLD）

四步工作流：**SHADOW_COMMIT 起双轨 → 跑代表性负载累积对账 → 评估 → PROMOTE/DEMOTE**；候选表生成 = `tools/advisor.py`（telemetry → PolicyEntry 整表出，同输入同输出可 diff 审计）。

| divergence 率（divergence/eval） | 判定 | 语义 |
|----------------------------------|------|------|
| < 0.1 | **PROMOTE** | 决策高度一致，shadow 表可转正 |
| > 0.5 | **DEMOTE** | 分歧过大，shadow 表不可信，回观察态 |
| 其间 / eval == 0 | **HOLD** | 证据不足，继续累积对账期样本（无样本诚实透出） |

- 判定器 = `tools/policy_ab_eval.py`（阈值可覆盖；窗口化 `--delta` 取首尾差——轨道未切换时更准）；性能验收 = `tools/sched_perf_analyze.py`（pick < 5µs / freeze < 5ms / billing < 1µs，JSON PASS/FAIL）。
- 升级判据与 ADR #21 kill criteria 同源（可复现 A/B 可测收益）；QEMU 看功能/顺序/相对趋势、分位出真机（调点调度 1.1 §8.2 口径继承）。

### SMP 三件套（调点调度 1.3 §4–§5）

- **① SHD_WHERE 原子化**：`static mut` → `AtomicU8`——写侧「槽写 → fence(Release) → store(Release)」发布序 / 读侧 Acquire，见新槽号必见新槽内容；单核无重排面 = 零行为变化。
- **② hazard-lite 槽回收**：`HAZARD:[AtomicU32;2]` 每核发布在读槽号；读者协议（`active_snap()`）= load ACTIVE → store hazard(Release) → fence(Acquire) → **复读 ACTIVE 验证环**（翻转则换槽号重发再验——经典 hazard pointer 验证环，lite 在结构（固定位/无回收回调），不在省略验证）→ 稳定返指针；写者 `publish()` 扫描避开 active ∪ HAZARD。**「3 槽 2 核恒有空闲」**（读窗串行形态下两核 hazard 收敛同槽 → 阻塞集 ≤ 2），满 3 即 expect 响——协议违约当场抓住（wedge 优于静默跨核腐坏）；单核 HAZARD[1] 恒哨兵 → 写者扫描恒让过。
- **③ POLICY_LOCK 写者锁**：`AtomicBool` CAS 自旋锁，五写者入口（bind / bind_gen / bind_gen_shadow / promote / demote）全串行——「gen 检查 + 写入」等复合临界区原子化（两核写者交错会造成 gen 倒灌/旧表覆盖新表）；错误路径同解锁防泄漏；锁序钉「表/KL」档、禁嵌 RQ/SLEEPQ（KL-first 锁序不可破）；单核 CAS 首试即成零行为变化。
- 未竟（v1.3 骨架口径）：shadow 双槽侧 hazard 覆盖、跨核换表等价断言（LB 金丝雀「换表窗零丢片/零双跑」）、各核见表 gen 漂移合法窗观测——随 smoke-smp 扩展相承接。

## EAS 能效（调点调度 1.3）

Linux EAS 同款**机会主义纪律**：能量账只在系统有余量时算，超载即整域让位回普通负载均衡。v1.3 落的是**形状与信号**（placement 消费 + EM 表 + util EWMA + overutilized 门控），选核算法（compute_energy/FEuC）留 M2/真机——ADR #53「砍实现不砍协议位」，kill criteria 退路保住。

### placement 第一消费者（三值 0/1/2 + overutilized 门控）

- `policy.rs placement_hint()` pub fn：O(1) 读活跃快照透传 `SnapSlot.placement`；**三值词汇**：0 = 无意见 / 1 = 偏 little / 2 = 偏 big。
- 消费点 = `apply()` 顺带消费（`placement≠0 && par_enabled()` **双门**——gate 关时连 TCB 都不写，空表等价纪律延伸到放置面）+ Task 加 `placement_hint: u8` TCB 落点。
- **overutilized 门控最前短路**：任一核饱和 → 恒 0（hint 失效 = 回退无 hint 默认行为）——饱和系统里能量/放置比较失真（所有候选都「贵」），热路径顺带省一次快照读。
- placement 是**建议不是约束**（hint-only）：LB 失衡可无视、违反不记 divergence；唤醒/迁移/spawn 三路之争先收为 apply 路径（谱系最小），选核处真消费随真 SMP 相。
- 验收：PLACEMENT ok 五分支（PL-1~5：空表 / 命中 little / 命中 big / 未命中 / 接口缺席）。

### EM 表形状（`sched/src/em.rs`）

- `EmPoint{freq_khz, power_mw, capacity}`——Linux EM 同口径（kHz / mW；capacity 与 `Topo.capacity` 同尺度，1024 = 域内最高频点满格）。
- `EmDomain{cpu_mask, points[4]}` 点表按频率**严格升序**（入口收口不变量；EM_POINTS_MAX=4、EM_DOMAINS_MAX=2——真机大小核 2 域即满配）。
- `em_register` 形状护栏：域号在册 / 点数 1..=4 / cpu_mask 非零 / 频率严格升序；**拒收零写入**（已 valid 域保持旧表）；重注册 = 整表覆盖（真机 DT/OPP 解析后换占位表同通路——填充路径今日即明日）。
- 查询面：`em_valid / em_domain / em_max_capacity / em_min_power`。
- **QEMU virt 默认表**（单域 CPU0-1 三点）：250MHz/5mW/cap 400 · 500MHz/15mW/cap 750 · 1000MHz/50mW/cap 1024。
- **零算法**：compute_energy/FEuC 不落仓库——验收 EM ok 四段（未注册 / 默认表逐位对拍 / 六种拒收+零写入 / 双域+重注册换表）。

### 簇 util EWMA（`sched/src/util.rs`，per-CPU / α=1/8 / is_idle 门 / PM 频率信号）

- per-CPU（`UTIL_NR_CPU=2` 定长口径）util EWMA，**0..=1024 与 Topo.capacity/EM 同尺度**（1024 = 满格）。
- **α=1/8 移位**（`EWMA_ALPHA_SHIFT=3`，`ewma += (raw−ewma) >> 3`）——no_std 零浮点零除法（内核禁 FP 纪律）；半衰期 ≈ 5.2 窗。
- **实际 elapsed 分母**（非名义窗长）：`raw = min(accum×1024/elapsed, 1024)`——tick 间隔 > 窗长（SLICE 100ms > 窗 10ms）时采样跨度诚实；深睡长 gap 后首窗 elapsed 摊大 → idle 自动稀释落底（idle 路径无需专门翻窗）。
- **is_idle 门**：`IDLE_TASK` 上的 tick 不计——idle 时间是低 util 信号本身，不是运行时间；空窗折叠低 util 样本（EWMA 随空闲衰减）。
- 接线：`Fair::tick` accumulate + window check（100Hz 窗 ≈ 10ms，窗长按 CNTFRQ 运行时换算不硬编码）。
- **PM 频率信号（红线）**：schedutil 同构 `f ≈ util × fmax / capacity`——调度器只出 util/placement hint，**调度路径零频率写点**，频率裁决单点归 PM 服务（berry-power）；PM 共享环 ABI 未接（EWMA 信号暂无消费者，环订阅 = 扩窗候选）。
- 验收：UTIL ok 九段（未启态 / 开窗 / 满载首折 / 连续收敛 / 半载 / idle 稀释 / 饱和 / 独立 / 真接线证活）。

### overutilized 回退（阈 819）

- `OVERUTIL_THRESHOLD=819`（域最高容量 80%）+ `overutilized(cpu) / any_overutilized()`。
- **EM 未注册 → cap=1 → 阈 0 → 任何非零 util 即 over**——保守正确：无 EM 无 EAS 据。
- 验收：OVERUTIL ok 四段（阈下 / 越阈 / hint 失效 / 恢复）。
- **Linux EAS 同款机会主义纪律**：超载即退化纯负载均衡、能量账只在有余量时算——§3.3「energy-aware 放置」的守门条款。

## 层级预算（band，ADR #42 第二段最小面）

- `sched/src/band.rs`：静态 8 槽 `BandBudget` 表（`BAND_SLOTS=8`；带词汇 0x00–0x05 + 余量——现役 0x01–0x04，0x05 MAINTENANCE 冻结，0x00 UNSPECIFIED 默认带不设包络）。
- **CBS 同形**（同 S5-c 逐任务 deadline 预算）：`BandBudget{quota, period, consumed, deadline, throttled}`——每期至多 quota CPU 时长，超了等下期。
- **整数微记账**（QNX 三件套之一）：CNTVCT 周期数整数累加，无小数无换算堆。
- **事件驱动周期翻转**：`period_check` 对 CNTVCT 一比较、消费点顺带调（`throttle_all` 超支即禁跑整带）——**绝不复活周期 tick**。
- **intent 即带键**（band 不加 attr 字段，#58 不扩档只查键）：任务侧读 `intent_effective`（§3.6 调度决策一律看 effective），进程侧 `Process.band_id` 记账（sched 不反向依赖内核——同 `proc_tag` 的 crate 边界纪律）。
- **默认全关**：槽初值 quota/period=0 = 该带不设包络——`consume` 恒 false、`throttle_all` 零扫描，与接口缺席逐位等价；执法开关在启动配置 `configure`，`SchedClass` trait 签名零改动、数字不写死进本文档。
- **与 S5-c HELD_THROTTLE 的关系（一消费者一位）**：deadline 任务（`prio_effective ≥ PRIO_DEADLINE`）被 RT/deadline 屏蔽不变量豁免——band 环扫均跳过；其 `HELD_THROTTLE` 位**只归 S5-c 逐任务执法**（`class.rs::tick` 置 / `lazy_unthrottle_deadlines` 清），带级执法永不触碰；fair 任务的 THROTTLE 位同理只归 band——「FROZEN(bit6) 与 THROTTLE(bit7) 分立」双位纪律的位内版本。
- 未竟（v1.3 骨架口径）：band 全局原子账（跨核一份原子计数 + lazy pick 执法——选核时读账、不即时回冲）仍单核形态；入场券（v1 遥测实证 + loadgen + 尾延迟断言 + 空闲核金丝雀）未过前 band 执法不并线——扁平 EEVDF + latency-nice 仍是必须打败的零假设。

## 测量基础设施（HDR 直方图 + 唤醒延迟基准）

### HDR 1024 桶直方图（`sched/src/hdr.rs`）

- **形状**：对数线性桶（Gil Tene HDR 同构幂次桶）——**28 八度 × 32 子桶 + 1 溢出防御位 = 897 实桶**（值域 1..2^28 ticks，@62.5MHz CNTVCT ≈ 4.29s 封顶）；每八度 32 子桶 ⇒ 相对精度 ≈ 1/32（≈1.5 位有效数字，p99 粒度够用）；桶形状编译期钉板（897 桶 / `Hdr` 3616B / `CpuHdr` 7232B——dump/导出面 `#[repr(C)]` day-one 定型的 ABI 基线）。
- **热路径**：`record` 一次 CLZ 定八度 + 移位取子桶 + `fetch_add`——零分配零 panic；分位入参**整数千分比**（p99.9 → 999）——内核禁 FP（aarch64 none 构建 `-fp-armv8,-neon`）。
- **per-CPU 64B 对齐**：`CpuHdr` 按 cpu_id 槽化、64B 对齐（A72 cacheline）防跨核伪共享，双路（switch_lat + wake_lat）；**写方限本核零争用**；跨核合并 = 桶位直和、零栈副本。
- **并发纪律**：全原子无 `static mut`；写序 = 桶/极值在前、N 的 Release 递增**最后** ↔ 读者 N 的 Acquire 读**最先** ⇒ Σ桶 ≥ N 恒立，分位累计秩扫描必达不耗尽。
- 分位返回 = 命中桶**保守上界**（与真值差 < 桶宽 ≈ 3% 相对误差）；溢出桶 → `u64::MAX` 哨兵——命中即响亮，不假稳（「长尾进溢出桶 = p99 假稳」的反面）。
- 与 telemetry R-0 的 64 桶 log2 唤醒直方图**并存不替代**：看形状靠 R-0（粗粒度），收分位靠 HDR（三路基准 p50/p99/p99.9 门禁判据数字的收割载体）。
- 验收：HDR ok 四段（形状锚 / 1..100 分位 / 钳位失真 / per-CPU 隔离+合并）。

### 唤醒延迟基准（cyclictest 口径 / 绝对 deadline 锚）

- `test_hdr_wake` 方案 A 忙等（cyclictest 口径简化）：**绝对 deadline 锚不 drift**（与 §4.1 绝对截止时间重编程同源纪律——绝不基于「上次编程值 + 周期」外推）+ 128 轮 ~1ms 间隔 + `record_wake_lat` 单参 API + `merged_percentile` 全链。
- 断言面确定性（**接线形状执法非数值门禁**，QEMU 双跑绿）：total==128 + per-CPU 隔离 + p50≥min≥1 + p99≥p50——**HDR 首个真实消费者**。
- 留 boot 刀（方案 B）：boot 序列真 sleep/wake（`sched::init` 后 spawn 内核任务 + `on_irq_tick` 唤醒 + WAKE_RINGS 同灌 HDR）；IPC 往返 / 调度切换两路的真机相未开。
- 门禁化未竟：绝对数（板间不可比）vs 相对门（A/B 比值 + 同机配对）未裁；真机红 CI 先按手跑单设计（接口留、实现未动）。

## 热路径优化（O(4n)→O(n) 三连）

`pick_next` 原四圈 O(n) 扫描（avg_vruntime 全环求和 / 带段 1 / 带段 2 / lazy_unthrottle 扫描）经三刀并一圈：

- **① avg_vruntime O(1)**：`Runqueue` 加 `sum_vruntime: AtomicU64` 增量账本（`ring_check` 对账执法）——账点三处闭环：`link_back` ＋（enqueue 的 avg clamp 在 link 前，入账即 clamp 后终值）/ `unlink` −（**挂结构原语层**——steal 路径直调 `src.unlink` 不经类方法也入账）/ `Fair::tick` 随 vdelta ＋（**在环门控**——IDLE_TASK 永不在环、idle tick 不入账）；`avg_vruntime` 改 O(1) 直除 sum/len，空环 None 与旧 u128 扫描逐位一致（溢出界：vruntime 增速 ≤ CNTVCT ⇒ u64 饱和需 ~9e3 年 @62.5MHz）。
- **② lazy_unthrottle 门控**：`DL_ON_RING` 计数挂结构原语层（block/steal 绕 dequeue 也入账）——**无 DL 任务零扫描**。
- **③ 段合并单圈**：带段 1+段 2 合并单圈三分支（更高带 → 重置 / 同带 → EEVDF / 低带 → 跳过）——首见保序 + `PURE_EEVDF` 开关语义逐位等价。

实测（QEMU virt/A72/TCG，n=1000）：

| op | 优化前 | 优化后 | 验收线 | 余量 |
|----|--------|--------|--------|------|
| pick | 27cy | **21cy**（−22.2%） | < 5µs（@1k 任务，kill 线） | 14× |
| freeze | 15cy | **5cy**（−66.7%） | < 5ms | 62500× |
| billing | 1cy | 1cy（地板维持） | < 1µs | 62× |
| FAIR fairness | spread=0 | spread=0（完美等分保持） | — | — |

- 总计：pick_next **O(4n) → O(n)**（扫描量 −75%）；DL-K / CMP-K / FAIR-K(spread=0) 全绿。
- policy 注入 delta 28.5% = 分母塌缩所致（base 27→7cy），**绝对注入开销仅 2cy**——PP-4 门 <50% 绿（有/无表 pick 开销与策略复杂度无关的实测形态）。
