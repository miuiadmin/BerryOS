## §2 缺口分析：为什么现在没有 epoll 等价

1. **n≤16 墙**（#2）：事件循环的等待集无界（echo server 连接数不定；Node/libuv 单进程可等数千 fd）。内核栈上定长数组是 v1 no-panic 纪律的产物——升 n 是内核 ABI 面（`WAIT_MANY_MAX` 双侧同步 + 栈帧扩容），非零成本。
2. **阻塞 RPC 模型墙**（#9）：现行 TCP = 一连接独占 netd 会话的同步 ROUNDTRIP 链——「等数据」与「占服务」耦合。事件循环需要「等多源、单点醒」的解耦：就绪通知与数据搬运分离。
3. **两张皮墙**（#14/#15）：epoll ABI 语义（fd + 事件位 + LT/ET）与内核对象面（handle + signal 位 + 全满足集回写）之间没有映射层；socket fd 本身也不存在（无 socket ABI）。

**关键洞察（本稿设计轴）**：epoll 的本质不是 fd，而是**「就绪集的集中等待 + 边缘通知的分批收割」**。BerryOS 已有的原语恰好够搭：wait_many 全满足集回写 = 免费 LT；WAIT_ANY 哨兵 = 免费边沿聚合；poll-first = 免费非阻塞探测。缺的只是「>16 路的分批调度」与「TCP 会话的就绪通知位」——都是用户态工程，零新内核面。

## §3 设计

### 3.1 刀1 聚合器：`berry-poll` 纯库 crate（进程内，零新服务）

**形态裁定：链接库，不是服务进程**。理由：①epoll 语义进程内（每事件循环私有等待集），服务化徒增 RPC 跳数（P6 A-6：TCG 单跳 ≈0.8s——聚合器在等待热路径，不可加跳）；②等待对象是调用方私有 handle（channel/event），跨进程传 handle 还要 gift 链——复杂度反噬；③微内核纪律「能用户态就用户态，能库就不服务」。

```
berry-poll（纯函数 + std 用户态，host 可测）
┌────────────────────────────────────────────┐
│ PollSet::new()                              │
│   .add(handle, mask) -> idx/err             │  就绪集注册（handle 有效即够——wait 不查权利 #7）
│   .remove(handle)                           │
│   .wait(timeout) -> &[(idx, observed)]      │  阻塞多路等待（任意 N 路）
│                                             │
│ 内部：批 = ceil(N/16)，每批一个 wait_many     │
│   ① drain 就绪缓存（上轮未报完的 LT 尾巴）    │
│   ② 全批 poll-first 一圈（deadline=0，#3）   │
│      → 有命中：返回命中集，剩余批就绪项入缓存  │
│   ③ 全空：批 0 wait_many(slice) 醒后回 ②    │
│      （slice = min(timeout 余量, 轮转片)）    │
│   ④ 到点：返回空（ETIMEDOUT 语义）           │
└────────────────────────────────────────────┘
```

- **LT 语义免费**：wait_many 回写全满足集（#4）——未消费就绪项下轮 poll-first 自然再报（LT 补报合规：epoll_wait 本就允许部分返回）。
- **分批重验的唤醒延迟**：N≤16 退化单批直等（零开销）；N>16 最坏 = (批数-1)×轮转片——**这就是 kill criteria 的 3× 之源**，轮转片实施期定标（候选 50-200ms，TCG 实测后钉）。
- **服务侧聚合 Event 建议**（架构位，非刀1 范围）：通知源服务（netd/fsmgr/console）可为每客户端置一个聚合 Event（多会话共用一位）——等待集从「每会话一项」缩到「每服务一项」，单批即纳。echo server 验收（A2-3）若走此形，>16 批路径属压力面而非常规路径。库对两种形态无偏好（都是 add(handle)）。
- **消费者纪律立册**（P5 A-2 恒满足项教训的库版）：`add` 前问——这项在稳态会不会恒满足？恒满足项不入等待集（条件化入列是调用方责任，库文档头注立法）。
- host 测试面：批切分/缓存吃尽/poll 命中截断/空集拒/容量帽/idx 稳定性（remove 后复用槽的语义钉板）——纯函数面（wait_many 以 trait 注入假实现，零 QEMU）。

### 3.2 刀2 TCP 会话化 + listen/accept + 非阻塞

**netdproto 会话模型迁移**（主工程量）：单会话 ST_BUSY → **会话表**：

- op 头扩 session_id（u32；session 0 = 默认会话——**现行 op 序零漂移**，`TCPS ok` 既有断言不动）。
- 新 op：`OP_TCP_LISTEN`（port → listen 会话）/ `OP_TCP_ACCEPT`（listen 会话 → 新数据会话；非阻塞语义 = 无挂起连接时 ST_EAGAIN 而非阻塞等待）/ `OP_TCP_POLL`（会话 → 就绪位：可读字节数/可写/断开）。
- 会话容量帽常量双侧同步（三纪律照旧；候选 8 会话——echo server 串行验收 2 连接 + 余量）。
- **就绪通知**：ACCEPT/POLL 是拉模型（事件循环轮询）；推模型（netd 给客户端 Event 置用户位）留 v2——聚合器等 POLL 节拍 Event 或纯 poll 轮转均可跑通验收（串行非竞速面，轮询无伤）。

**berry-tcp 扩服务端半边**（纯函数面，host 可测）：

- `State` 扩 `Listen`/`SynRcvd`；`listen()` 构造 + `on_seg` 被打开分支（SYN→SYN|ACK、ACK→Established）+ accept 队列（容量帽，满则 SYN 丢弃——TCP 规范行为）。
- 客户端面零改动（open/send/close/on_seg 原语义钉板——30 测只增不减）。

**vnet 面**：会话表驱动 + hostfwd 入站（QEMU `-netdev user,hostfwd=tcp::PORT-:PORT`——宿主连 guest listen 口；echod.py 同款宿主对拍源形态反转）。hostfwd 建模风险：QEMU 版本差异 → 刀2 首跑 `-object filter-dump` 取证（A-7 先例）。

### 3.3 范围盒裁定（fd 化深度）

**A2 只做到「会话对象 + 就绪位 + 非阻塞语义」，不做 socket ABI**：`socket`/`bind`/`listen` libc 桩与 fd↔会话映射挂 A3（POSIX 原语批）/A4（sysroot 交叉面）。理由：A2 验收（echo server 事件循环）用 `berry-poll` + netdproto 直连即达；socket ABI 是兼容面工程，塞进 A2 会把「事件循环可用」这个内核能力验收稀释成 libc 桩海。epoll 三桩（#14）保持 ENOSYS——A4 对表时以 berry-poll 语义为蓝本生成。

### 3.4 echo server 验收（A2 整卡收口）

guest 内 echo server（`berry-poll` + netd listen 会话 + ACCEPT/POLL/ROUNDTRIP 轮转）→ 宿主 python 逐连接串行对拍：连接 1 write 载荷 → 读回逐字节同 → 断开；连接 2 同款（不同载荷/长度，≤128B 面 #10）。**串行 = 状态谓词，零竞速**（4-5a 铁律）。smoke 挂线：run-rootfs 扩 echod 同款起/收对（新端口，避开 18080）+ `EVS ok` 类标记（标记名实施期定，子串防撞对表在册标记）。

## §5 风险与 kill criteria

- **kill（在册原文）**：聚合器 p99 唤醒 > 直等 3× → 改内核扩 n 上限方案（`WAIT_MANY_MAX` 升档：栈帧扩容至 n=64/128 定档或堆版本——ABI 双侧同步 + ktest B 段样本面随之）留档重议，不硬扛用户态分批。bench 通道 **A2-3 已裁：B-2 -icount**（L2 紧门禁先例——指令数代理免疫 TCG 时序噪声），bench 随推模型消费方（v2/A3+）落地时执行（v1 无热路径消费方，见 §7 追记）。
- **wait_many 哨兵恒 slowpath**（#8）：echo server 串行验收对延迟不敏感；p99 面按 slowpath 成本实测再判——不预设乐观。
- **hostfwd 建模风险**：QEMU 11.0.3 SLIRP 入站转发首跑验证（filter-dump 取证）；不通则降级 guest-to-guest（vnet 双会话自连——纯 guest 面也可达验收语义，宿主对拍降为自环对拍，留档降级形态）。
- **会话化兼容面**：session 0 默认会话保 `TCPS ok` 原语义——若实测断言仍漂（op 字节面变化），smoke 断言随刀更新且**有意漂移留档**（A1-3b `HANDOFF ok ver=0→1` 先例）。
- **不做什么**：不做完整 epoll ABI（§3.3）；不做 io_uring 等价；不做 ET（边沿触发）模式——LT 全满足集语义已够 A2-A6 消费面（libuv 默认 LT 兼容）；不碰 abi.toml（零新 syscall——聚合器纯用户态、netdproto 是 RPC 协议非 syscall 面）；不做 demand paging/线程池（A3 面）。
