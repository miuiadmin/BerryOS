# SDK-2 分发与签名链设计草案 v1.0

> **性质**：.bap 完整性→签名→升级/回滚→渠道门槛的分发基建设计**草案**——三决策点开放待用户拍板（§六），拍板后升设计定稿。
> **溯源**：SDK-03 §三.3/§五空白面①（与 SDK-02 结论 8-⑤ 互证的两线同报空白）+ 原则 3 渠道杠杆依赖；PWA 两版并存更新模型（Web 课）。
> **状态**：草案 · 未开工 · **决策点待拍板**——本档不预设商店政策/审核/抽成（SDK-03 §三不可：分发政策随生态调）。
> **基座**：.bap/mkapp/appd 应用模型（冻结）· ADR #59 manifest v2 security 域（profile/key_lineage 两键预留壳）· SHA256SUMS 现役完整性 · ADR #56 三值版本域。

## 一、现状与缺口

| 件 | 现状 | 缺口 |
|---|---|---|
| 完整性 | SHA256SUMS 第三条目 | 仅防传输损坏，不防篡改 |
| 签名 | 无 | 无签名/验签/来源验证 |
| 升级 | 无 | 无协议/无原子切换/无回滚 |
| 渠道 | 无 | 无 target 门槛/无可见性策略 |

## 二、支柱 1｜签名（决策点 1：密钥体系）

- **签名块**：分离式 `app.bap.sig`（不内嵌载荷——.bap 载荷格式是冻结面
  L1，内嵌即改冻结格式；分离式零触碰）。签名对象 = .bap 全字节摘要 +
  manifest 关键域（身份/版本/词表/security）摘要。
- **算法**：ed25519（候选——Rust 生态纯实现成熟、签验快、无参数选择坑；
  对比 RSA-pss/ECC-p256 备选，倾向 ed25519）。
- **密钥体系三选项**：
  - **案 A｜TOFU + 轮换**（推荐 v1 起步）：首次安装信任 on first use，
    key_lineage（ADR #59 已预留 1..=16B [a-z0-9-] 壳）承担密钥轮换链
    ——同 lineage 新钥可换旧钥，跨 lineage 换钥须用户确认。零中心基建，
    无商店阶段即可用。
  - **案 B｜中心 CA**：平台根钥签发开发者钥。安全性最强、可吊销，但要求
    注册/审核基建——商店时代的事。
  - **案 C｜混合**（推荐终态）：v1 案 A 起步，商店上线后升 A+CA 双验
    （CA 签的免 TOFU 提示，无 CA 签的走 TOFU）——案 A 的数据结构与
    案 B/C 前向兼容。
- appd 装载期验签：验签不过 = 拒载（显式错误，错误域附因给「哪个环节坏」：
  摘要不符/钥不识/lineage 断链）。

## 三、支柱 2｜升级与回滚（两版并存原子切换）

PWA service worker 生命周期模型移植（SDK-03 Web 课）：

1. **两版并存**：新版下载 + **验签通过前**，旧版继续服务（不中断）。
2. **原子切换**：验签+manifest 校验全过后一次性切激活指针（appd 侧
   per-app 激活版本指针，切换 = 单指针写）。
3. **可回滚**：旧包保留 N 版（N=2 起步），激活失败（启动崩溃/墓碑）自动
   降级回上一激活版 + 遥测上报。
4. 增量更新（delta）：**v1 不做**（整包替换；.bap 本就小）——列为 v2
  候选，不进本刀（决策点 2：确认 v1 整包即可）。
5. 卸载 = 激活指针删除 + 包数据树回收（四棵树沙箱内，随 appd 墓碑机制
   既有纪律）。

## 四、支柱 3｜渠道门槛（对接双轨设计）

- 上架/分发门槛：`target ≥ 当年 SDK 下限`（Play 政策对应物）——依赖
  分发面存在；无商店阶段先做**装载警告 + 遥测统计**（双轨设计 §五），
  数据到位后再立硬门槛。
- 来源记录：安装来源（channel id）进 per-app 元数据，为可见性策略
  （低报包对新用户隐藏）预留数据面。
- 自建分发 v1 形态（决策点 3）：**源列表 + TOFU**（类 APT/信号协议风格：
  用户添加源 = 信任该源钥；源内包全验签）——零中心基建可用；商店形态
  （若做）为独立后续案，本档不展开。

## 五、manifest v2 distribution 域衔接

现役三域扩展后 distribution 域聚集：`abi_revision`（双轨设计 §二）+
`source_channel`（来源记录）+ 升级协议参数（检查间隔/回滚保留数）。
security 域：key_lineage 从预留壳转实用（签名块引用同一 lineage）。

## 六、开放决策点（待用户拍板）

| # | 决策 | 推荐 |
|---|---|---|
| 1 | 密钥体系：A TOFU / B 中心 CA / C 混合 | **C**（v1 按 A 落地，结构前向兼容） |
| 2 | 增量更新 v1 是否做 | **不做**（整包；.bap 小） |
| 3 | 自建分发 v1 形态：源列表+TOFU / 直连 sideload 单包 | **源列表+TOFU**（sideload 为退化情形） |

## 七、验收线（拍板后随刀定）

1. app.bap.sig 生成/验签 host 测（含篡改/断链/换钥三负样例）。
2. 两版并存 + 原子切换 + 自动回滚的 appd 侧用例（host 测模拟激活失败）。
3. 装载警告 + abi_revision 分布遥测可见。
