## §0 定位与读法

**三件套分工**（一事实一归属）：`应用模型设计-v1.0.md` = 为什么这样设计（架构论证）；**本文 = 必须遵守什么**（规范条文 + 对标依据）；`应用开发指南.md` = 怎么打包跑起来（开发者操作手册，字段速查单一事实源仍归 berry-manifest + mkapp）。本文不复制字段全表与构建咒语，只立规范。

**适用对象**：一切 `.bap`（含预装系统应用——§11 只加严不豁免）、以及未来经兼容层安装升格的外来应用（存储 §5 同一管理面）。CLI 裸进程（bsh gift 授能）与内核/服务的 ELF 不走本规范——边界见 `应用模型设计` §0.1 三个诚实边界。

**标注体系**（每条规范必居其一）：

| 标注 | 含义 |
|---|---|
| 【现役】 | 已落地且已有执法位（ smoke/mkapp/appd 在跑） |
| 【v1 立法】 | 本规范新增条文，随最近一刀落执法（§15 附刀序） |
| 【v2 预埋】 | schema 位已留或将随刀留（add-only，ADR #59 纪律）；v1 不承诺行为 |
| 【v2+ 远期】 | 终态方向记录，不构成任何版本承诺 |
| 【不做】 | 明文拒绝 + 理由（对标三择一裁决的第三档） |

**总原则四条**（全文的裁决依据，冲突时以此为准）：

1. **一格式一扇门**：GUI/CLI/服务/驱动/未来形态不是多种包，是同一 `.bap` × `type` 词表 × `capabilities` 能力集的形态谱（ADR #55）；任何「系统应用专用格式」= 击穿能力模型第一性，禁。
2. **能力即权限、handle 是唯一机制**：权限 UI（弹窗/picker/设置页）是 handle 交接的化妆面，永不新增第二种权限机制（能力模型 §8）；对标中一切「权限」概念都翻译成「何种 handle、谁签发、何时回收」。
3. **声明必须在装载期被强制**：HarmonyOS 大量字段靠上架审核兜底、端上不校验是反面教材（对标底稿三号坑 7）；BerryOS 无商店红利可吃，manifest 声明 → appd 全量静态校验一处报全，声明了拿不到 handle 即空头支票（现役纪律）。
4. **别人有的三择一**：v1 落 / v2 预埋位 / 立法不做——没有第四态（「没想到」不算状态）；§14 矩阵是全量对账面。

## §1 应用形态与包结构规范

### 1.1 形态谱（type 词表）

| 形态 | type 值 | 状态 | 对标 |
|---|---|---|---|
| 通用应用（含 GUI/headless 由能力集决定） | `"app"` | 【现役】唯一合法值，其他值 berry-manifest/mkapp 硬拒 | HarmonyOS bundleType 缺省 app 同构 |
| GUI / headless / daemon 分档 | `gui`/`headless`/`daemon` | 【v2 预埋】词表已注（应用模型 §3），随多 app 并存刀 add-only 入表 | module.json5 type 同构；v1 克制 = 反面对标（60+ ext 类型是 15 年沉积） |
| 驱动 | `"driver"` + `[hw]` 节 | 【v2 预埋】随 devmgr（ADR #46） | 驱动 = 持证应用，.ko 式版本地狱禁入 |
| 桌面卡片 / 输入法 / 分享目标 / 壁纸 | type 词表新值 + `[[extension]]` 节 | 【v2+ 远期】ExtensionAbility 等价物；v1 只留 `views/` 资源位与 `provides` 语义槽（应用模型 §8.2） | Apple App Extension / HarmonyOS ext / Windows shareTarget |

**规范条文**：新形态一律 = 词表新值 + 新节，**永不第二容器**；v1 manifest 未知节/未知键一律硬拒（现役）——「词汇缺席优于半吊子」。

### 1.2 容器规范（.bap v0/v1 现行 + 上架素材 v2）

- 容器 = cpio(newc)，条目集 `{manifest.toml, bin/<名>, SHA256SUMS, icons/*.byi?, views/*?}`；`bin/` 恰一枚、ELF64 魔数、musl 静态链（berry-libc + berry-ld）。【现役】
- **包体帽 4 MiB**（BAP_MAX，走查几何界防几何炸弹）；超帽拒打包。增量更新 50 MiB 闸门三条件【v2 预埋】（分发签名链 §四）。对标：元服务 ≤10MB/分包 ≤2MB、Instant App ≤15MB——BerryOS 无免安装形态，【不做】（静态 ELF 天然「下载即用」，无需第二分发档）。
- **图标资产**：staging PNG 源（8-bit RGB/RGBA、非隔行、每维 ≤1024、w×h ≤65536、≤4 件）→ mkapp 就地编码 BYI1（RGBA u32 RLE）入包、源不入包；RGB565/1bpp 枚举位留而不启。【现役】
- **图标源规格**【v1 立法】：桌面图标源 **108×108**（OH 对齐），有效内容居中、四周 ≥18px 留裁切裕量（系统统一蒙版/圆角属 v2 壁纸抬帽同刀；对标：Android 自适应图标 108dp 安全区 66dp、iOS 1024 方图系统裁、OPPO 512 直角系统蒙版——共识 = **应用供内容、形状归系统**）。
- **上架素材**【v2 预埋】：发布面（镜像内置源/未来商店）要求图标直角原图 + label + 截图 + 隐私声明 URL；数值档（图标尺寸上限/截图张数）随分发面立项定死入 ADR，禁中途漂移（App Clip 10→15→100MB 反例）。

### 1.3 manifest 三域演进（ADR #59 既定，本规范补字段语义）

- **词表域**（capabilities 及一切声明面）：v1 现行字段集见指南 §6（单一事实源）；v2 扩展 = `[[grants]]` 结构化申请（§2.4）+ `requires_caps`（能力集标签）+ `[[intents]]`（§9.2）+ `[[widget]]`（§7.4）。
- **security 域**：`profile`/`key_lineage` 现为预留壳；v1.1 分发签名链已定语义 = key_lineage 身份别名（Apple Team ID 同构），轮换链进 `.sig` 信封。【v2 预埋·设计定稿】
- **distribution 域**：`abi_revision`（构建工具自动打戳，禁手写——HarmonyOS minAPIVersion「手配无效」同款纪律）+ `source_channel`（来源记录：镜像预装/sideleload/未来商店）。【v2 预埋】
- **id 形态**：v1 短 id（≤24B）；v2 反域名（`com.example.notes`，安装即命名空间）——两态共存过渡细则随 apps/ 树刀裁。【v2 预埋】

## §2 能力（权限）规范

> 权限的 BerryOS 翻译总纲：**一切「权限」= 何种 handle、谁签发、何时回收**。对标五系的权限面在本节逐项落位。

### 2.1 能力分级四档（保护级别对齐）

| 档 | 对标 | 授予方式 | 词表例 |
|---|---|---|---|
| **G0 通用** | Android normal / HarmonyOS system_grant / UWP uap:Capability | 安装期 appd 自动授（manifest 声明即得，无需弹窗） | `console`、`fs=["rootfs"]`(v1 过渡态)、`net=["client"]`(v2) |
| **G1 敏感** | dangerous/user_grant/UWP broker 首问 | 运行期首用弹窗（display/input/camera/mic/位置/通讯录/日历……） | v2：`camera`、`mic`、`location`、`contacts`、`calendar` |
| **G2 受限** | signature/ACL/rescap | 声明无效——须系统签名 manifest 或商店签发授权节（一条申请通道，ACL 双轨漂移禁入） | `filemgr`/`backup` purpose、屏幕捕获、后台豁免位 |
| **G3 特权** | priv-app/vendorPrivileged/system_core | 仅系统应用；镜像内**签名白名单**（§11.2），构建期校验 + boot 对账 | display 管理、设置写、包管理、电源投票 |

**规范条文**【v1 立法（表）/v2 落地（G1/G2 弹窗与授权节）】：级别判定表内置于 appd（开发者只写「服务名 + 档位」，永不接触三张级别长表——HarmonyOS 反面）；G1 以上申请**缺 reason 即拒装**（安装期 schema 校验，不学 iOS 运行时崩溃兜底）。

### 2.2 授权时效三态 + 撤销（时间语义）

对标收敛：Android「while-in-use / only-this-time / auto-reset」、iOS「仅本次（次日清零）/使用期间/始终」、ColorOS「仅本次允许/仅前台允许/每次询问」三系同构——**时间语义是 10 年后补的洞，BerryOS v1 一次定齐**【v2 预埋·语义 v1 立法】：

| 时效 | 语义 | 能力模型实现 |
|---|---|---|
| `always` | 持续授权 | 授权集常驻（appd per-app 能力表） |
| `session`（=while-in-use/仅前台） | 前台会话期有效 | handle 带会话租约：失焦/退后台 → appd 回收（close → 下次调用吃 DEAD） |
| `once`（=仅本次） | 单次使用 | 一次性 handle：目标操作完成或进程退出即失效 |

- **撤销 = close handle**（结构性断电，能力模型 §8 现役纪律）；设置页一切开关最终都走这一条路。
- **闲置自动重置**【v2 预埋】：长期未用应用自动回收 G1 授权 + 退出 boot 白名单（对标 Android auto-reset/ColorOS 智能权限推荐；时限初值 90 天，策略表可调）。
- **拒授权不退出**【v1 立法】：拒绝只降级对应功能；「拒绝即退出/拒绝后高频重弹」= 违规（工信部 164 号文⑤ + OPPO 审核规范同款）；appd 对「拒绝后高频重弹」静默封堵（弹窗计数进遥测）。

### 2.3 数据访问通道（picker 即权限）

- **用户显式逐树/逐文件授予** = 广域需求的唯一正门（SDK-2-资源 §三 已立法）：文件管理器/备份类走 `purpose` 类目 + 首访问逐树授权；发放的仍是**一组树 handle**，非类别令牌。【v2 预埋·设计定稿】
- **系统 picker**（照片/文件/联系人）【v2】：数据不离开所有者进程，picker 发一次性只读 handle——PHPicker/PhotoPicker/PhotoViewPicker 三系共识，「选择器即权限」。
- **安全控件**【v2+ 远期】：SaveButton/PasteButton 等价物 = GUI 点按一次生成一次性 handle，免弹窗（HarmonyOS 安全控件对标）。
- **禁全类别原语**【v1 立法·执法面在册】：all-files/all-media/all-devices 式入口永不出现（SDK-2-资源 §一，CI grep 守卫）；scoped storage 十年返工课从结构上免疫。

### 2.4 `[[grants]]` 申请节（词表域 v2 草案——对标 requestPermissions 三要素）

```toml
[[grants]]                    # v2 词表域示意（字段名随 SDK-2 定稿；v1 capabilities 平面键继续有效）
cap     = "camera"            # 服务名+档位（G1）
reason  = "拍摄照片"           # 必填文案：G1/G2 缺 reason 拒装（多语种 v2+）
scene   = "shoot"             # 触发功能（OPPO「目的+功能」二维声明对标；截图佐证属商店面 v2）
timing  = "session"           # always | session | once（§2.2 三态）
```

- 权限组 = **服务域**分组弹窗（相机/麦克风/位置/通讯录/日历各一组）；组内合并一窗，位置例外逐档展示（Android/HarmonyOS 同例）。
- **位置双档**【v2】：`location = "coarse" | "fine"`——一服务两档输出（coarse ≈5km 模糊，HarmonyOS 口径），授权 UI 选档、可只授模糊；不是两个权限字符串。
- **能力使用审计**【v2】：每次授予 handle 带 reason code 写审计日志（Apple required-reason API 制度化对标）；委托链（duplicate/transfer）全程可记账——设置服务能列「谁把什么给了谁」（应用模型 §8.2 既有立法）。

### 2.5 现役能力词表（v1 诚实账）

| 键 | 值域 | 授能 | 状态 |
|---|---|---|---|
| `console` | bool | true → stdout 授 console handle；false → appd 私有采集对（EOF-only） | 【现役】 |
| `fs` | 恰 `["rootfs"]` | fs 四元 gift；**v1 = 全卷读写删（与 bsh 同权，无 per-app 隔离）——过渡态，诚实声明** | 【现役】 |
| `net` | 恰 `["client"]` | 装载 loud 拒（`eco: app <id> net unserved`）——词表先行、服务面挂账 | 【现役·拒】 |
| `display`/`input`/`fs=["$appdata"]`/`background` | — | 词表位（应用模型 §3 v2 目标态） | 【v2 预埋】 |
| `timer`/`push`/`background`/`sensor` | — | 电源 SDK 能力位（ADR #68 ④；wake 位默认零配额，ADR #67） | 【v2 预埋·已立法】 |

### 2.6 替身数据通道（空白返回）【v2 预埋·语义 v1 立法】

对标：ColorOS 隐私替身（空通讯录/模糊片区/空白剪贴板，应用无感知）+ 小米空白通行证——**「不给权限就不给服务」类应用的对冲件**（监管 164 号文⑤反面对象的治理答案）。

- **语义**：用户可对单应用选择「替身」档——数据服务返回**空白或虚拟树**，应用无感知正常运行；纯能力模型实现 = **颁发假 handle**（contacts/location/clipboard 服务各出替身端点，句柄真、数据假），成本低于 Android 方案一个量级。
- **授予 UI 三选**：真授权 / 替身 / 拒绝（G1 弹窗同款三态位；替身选择与用途时间线均入 §10.2 行为记录）。
- **立法位**：替身档先覆盖 contacts（空白树）/location（§2.4 coarse 档已有——替身 = 恒 coarse + 随机化）/clipboard（空白串）；camera/mic 不做替身（传感器无法伪造输入流，诚实边界）。
- 执法位：数据服务（替身端点）+ 设置页（开关与展示）+ appd（授予记录）。

## §3 UI / 界面规范

> 设计系统基线 = OpenHarmony 官方常量（ADR #63 样式抄数不抄码）；本文立「应用必须遵守」的硬指标，风格指南（色板全表/组件库）随 berry-ui 成熟单独立档。

### 3.1 几何与布局基线【现役·GUI-8 装配】

- 基准画布：**360×640vp @3x = 1080×1920**（OH phone 档）；一切几何经 GETINFO 协商，**禁硬编分辨率**（裁决 D，违者审查打回）。
- 系统区：状态栏 **44vp** 顶部常驻（时钟 + signal/wifi/battery，左 signal/wifi 右 battery/clock——OH StatusbarConfig 官方序）；内容避让 = wmd 避让区（ADR #61）。
- 桌面：**5×4 网格、item 80vp、gap 16px、首行 top 162px、左右 padding 24vp**；常驻 Dock **4 位**（1002×234、radius 66、底缘保留 45vp）、顺序 Contacts→Photos→Settings→MMS。
- launcher 布局模型：4 页 × 12 格（PAGE_MAX=4 / CELL_MAX=48 权威定谳）、LAYOUT.JSN 2048B 单簇近原子、canonical 形字节级冻结（berry-layout）。

### 3.2 触控与可读性硬指标【v1 立法】

| 指标 | 数值 | 对标依据 |
|---|---|---|
| 触控目标 | **≥44×44 px**（视觉可小、命中区不缩）；建议 48 | iOS 44pt / Android 48dp 交集取下限，桌面 item 80vp 富余 |
| 文本对比度 | 小字 **≥4.5:1**、大字（≥24px 或 ≥19px 粗体）**≥3:1** | WCAG AA / Android 同款 |
| 非文本 UI 对比 | **≥3:1**（图标/控件边界） | WCAG / M3 配对约束同款 |
| 动效时长 | 微交互 100–250ms、转场 250–400ms；TCG 滑动 <10fps 降步进翻页（kill 线现役） | Material/OS 通行区间；降级预案 = GUI-8 裁决 D |
| 最小可读字号 | **≥12px**（对应字阶下限，Windows 12px 同款） | 三系字阶下限交集 |

### 3.3 图标与资产【现役 + v1 立法补条】

- 桌面图标链：PNG 源 108×108 → mkapp BYI1 → launcher 按 162px 目标几何采样（现役 genohicons 管道）；系统应用图标取 OH 官方仓 Apache-2.0 资产（ADR #63，来源/SHA 记 `第三方资产清单`）。
- **label**：≤32B 可打印 ASCII（现役）；CJK 显示名【v2】随真字体刀（GUI-2 段④）解禁——字节数帽不放宽，编码面随刀裁。
- **系统统一蒙版/圆角**【v2】：应用只供内容、形状归系统（三系共识）；BYI1 抬帽刀同场。
- **启动画面**【v2 预埋】：`[ui] splash = {icon, bg}` 单轨制（简易/增强双轨互踩是 HarmonyOS 反面）；v1 现实 = spawn 即全屏独占、系统壳先播过渡动画（display 直驱，应用模型 §4.1）——「不闪白屏」由系统兜底，应用零义务。
- **壁纸**：官方源预采样 135×240 + SmoothArgb/ScaledArgb 全屏放大（现役）；位图通道抬帽挂 v2。

### 3.4 主题、字体与无障碍

- **深色模式**【v2 预埋】：语义色 token（背景/前景/分隔线/强调）day-one 进 berry-ui 词表闭集（u16 原子 id 表，GUI-6 立项注记）；**禁硬编码两套黑白**（HIG 同款禁令）；应用侧只需消费语义 token，系统切肤全树生效。
- **字体**：思源黑体（OFL 1.1，ADR #63 钦定）；宿主构建期烘位图档、设备零 FreeType/零运行时光栅化（省电纪律）；ASCII 32×48 档现役，CJK 常用字（≈3500 字）随 GUI-2 段④。
- **字阶缩放**【v2+】：Display/Title/Body/Caption 四档起步（对齐三系字阶骨架）；适老化大字档（工信部 200 号文）随无障碍刀。
- **无障碍**【v1 立法·机制在册】：a11y role/label 值域已立法（GUI-6 ⑦ TLV 侧表，launcher 骨架 18/32 槽在用）；读屏 = GUI-9 dump 语义树（稳定 NodeId + 语义角色）——**无障碍是上架门槛而非附加项**（三系共识）；「可自动化」与「无障碍」同一扇门（应用模型 §8.4 输入不可区分性）。

### 3.5 官方 UI 栈与动效（应用怎么调 UI）【v1 立法】

> 姐妹篇 = `应用API全景-v1.0.md` §4（可用面盘点）。本节立规范：**官方内置 UI 框架存在且唯一**，应用 GUI 一律经它，不出现第二官方框架（永不引入第二一等语言/第二 UI 体系，ADR #55 纪律的 UI 面）。

- **栈构成**：berry-ui（声明式视图树——ADR #52 自研，UiMain API 群：add/set_props/set_text/invalidate/set_a11y + IconSource/TextMetrics 供件槽）+ berry-gfx（pass 形态 WebGPU 语义子集，ADR #51）+ 协议 crate（guiproto/wm 域）。官方样例 = berry-launcher（五模块全模式可抄）。【现役】
- **框架是库不是层**：berry-ui/berry-gfx 随应用静态链接、semver 自演进（ADR #55）——公开 API 面随 SDK-2 冻结；弃用走章程双版本纪律。
- **声明式双入口**：Rust builder 与文本 DSL（`views/*.bui`）共享同一 TLV AST 单源（C2 拍板；manifest `[ui].views` 位现役）——DSL 产物是数据非代码，AI 生成面同链。
- **官方动效**【v1 立法·数值已采齐】：官方动效库 = berry-ui anim（定点缓动现役：QuadOut/CubicOut；物理回弹随 v2）+ **动效 token 闭集**（时长档 + 缓动曲线进 u16 词表，与样式原子同链 mkapp/ABI 单源执法）；token 数值源 = `GUI-11-设计系统硬数值token表`（M3 16 档 duration + 9 条 easing 精确 bezier / OH hover250·press250·click200 / WinUI 167·250·333ms 四家已采齐）；应用可自定义曲线但**不得冒用官方 token 名**，系统级转场（窗口/返回）token 系统独占。
- **禁令**：应用不得绕过 berry-ui 直接写 framebuffer（surface handle 经 wm/present 域授予——能力模型结构性保证，非政策禁令）；不得自绘系统 UI 区域（状态栏/Dock——wmd 两层窗立法，ADR #61）。

## §4 生命周期与后台执行规范

### 4.1 生命周期分级（在册立法，本节立应用侧义务）

`active → freeze（v2 内核原语已随调点 1.1 S3 在册）→ tombstone → not running`（应用模型 §4.1 + ADR #64）。应用侧规范条文：

1. **pause(save) 契约**【v1 立法·app-1 落地】：收到 pause 消息须在**10s 内**完成状态序列化并退出（state blob ≤64KiB，appd 执法超帽拒收）；超时 = 监督杀 + fault 槽 + 代号 +1 重启（ADR #28）——**墓碑 pause 超时 v0 口径 = 不重启**（app-1 落地注：策略性墓碑超时 ≠ 崩溃语义，处置 = 监督杀 + `eco: tomb` 降级行 + 不入墓碑表，代号 +1 重启仅适用崩溃监督——草案 v1.2 §4 显式偏差）。对标：iOS Suspended 无通知被杀、UWP Suspending deadline——BerryOS 选**显式协议**（消息 + 超时 + 重启），墓碑后 relaunch 读档复活。
2. **EOF 先行 + 退出码语义**【现役】（指南 §7）；GUI 应用退出 = 回桌面（v1 全屏独占窗语义）。
3. **收尾超时帽**：reap 30s 绝对帽归 svcmgr/appd 域内消化（GUI-8 裁决二③）——应用不得假设「挂着不死」。
4. **前台/后台判定**：焦点真值 = gui-wmd 权威窗口表（ADR #61）；失焦即 `session` 时效 handle 回收点（§2.2）。
5. **lifecycle API 承载**【v1 立法·app-1/app-2 已落地】：应用**不直接操作 lifecycle channel**——协议消息由 berry-libc lifecycle 面封装（注册 pause 回调 / 写 state blob ≤64KiB / relaunch 读 state handle 三口，对标 UWP Suspending(deadline+deferral)/iOS scene 回调的「框架代收、应用只写业务」形态）；未注册回调的应用 = 默认可杀可墓碑（零义务起步，能力递增）。**三口签名速查**（形态照 app-2 草案 §2.2/§5；C ABI 冻结挂 SDK-2）：`lifecycle_register(cb) -> LcReg`（cb: Option<extern "C" fn(ev: LcEvent)>，单槽覆写、cb=None 注销）/ `state_save(payload: &[u8]) -> LcSave`（库代盖 32B 头 + CRC32，payload 帽 64KiB−32B）/ `state_restore(buf: &mut [u8]) -> LcRestore`（Fresh/Restored(n)/BadFmt 三分型归库）——配套机械件 `lifecycle_poll()`/`lifecycle_beat()` 为三口的 dispatch/节拍载体（**非第四第五口**；送达语义 v1 = 显式 poll、永不自动，GUI 泵点位契约随 SDK-2 主循环模板执法）。

### 4.2 后台执行模型（v1 立法总纲 + v2 落地）

对标裁决：Android FGS 14 类型 + 6h 池 + 3min 超时是**十年补课的形状**，HarmonyOS 长时任务按业务命名（DATA_TRANSFER/VOIP/星闪…）**枚举无限生长**——BerryOS 取「**资源证据**」模型【v1 立法】：

- **长时后台 = 持有资源证据**：`background` 能力声明（ADR #68 已立法）的词表 = 封闭资源枚举 `{audio_stream, location_stream, transfer, device_session}`（音频流/定位流/传输/设备会话）——每类绑定**系统可感知证据**（持音频输出 handle / 持定位流 handle / 传输进度通知在册 / 持设备会话 handle），枚举封闭、资源开放；与常驻通知绑定（§6.3），用户可感知可关。
- **短时任务配额**【v2 预埋·数值 v1 立法】：后台宽松窗口 初值 **单次 3 分钟、日累计 10 分钟、低电量单次 1 分钟**（HarmonyOS 定值直接对标；策略表可调 + 遥测导出，ADR #68 ⑥ 不承诺面纪律）；超时不自停 → 挂起。
- **延迟任务/代理提醒**【v2】：定时器归系统服务（timer 能力位 + wake 配额，#67/#68）——**应用死了提醒仍在**（代理提醒是纯能力模型的自然推论）；配额对标（单应用有效提醒 ≤30）。
- **保活禁令**【v1 立法·不做】：无保活 API、无「常驻后台自由态」；豁免位 = ADR #68 ① manifest 豁免白名单（系统应用限定，§11.3）——「AI 票护栏先于 AI 票」同款，「豁免先于任何后台请求」。
- **后台弹窗禁令**【v1 立法】：后台（失焦）拉界面禁止；承接面 = 通知/实况窗（HarmonyOS/292 号文同款）；弹窗必须经系统 UI 服务渲染（ColorOS 底稿启示 11——系统层天然管控点）。
- **PC 档分岔**【v2+ 远期】：桌面形态「最小化即工作」的心智不可用移动式冻结硬切（Windows 底稿启示 3）——QoS 分级节流（intent 降档 + EPP，现役机制）替代冻结作为第一级；冻结上收仅限电池压力。窗口/任务栏声明面（多窗/标签/固定/Snap 等价物）随 PC 壳另立规范。

## §5 自启动与关联启动规范

> 现实基线：v1 rootfs 静态 cpio、无运行期增删通道——自启动面 = boot 批（appd 扫描全量拉起，`APP ok n=` 谓词）。本节立的是**目标态规范**，v1 现役位如实标注。

### 5.1 开机自启动【v1 立法总纲 + v2 落地】

- **boot 白名单制**：boot 常驻资格 = 镜像内**签名白名单**（§11.2 与系统特权同表同刀）；三方应用 boot 自启 = `autostart` 能力声明（必要条件）+ 用户在设置逐应用授予（充分条件）——**默认关**（HarmonyOS「三方只能查询、系统应用才能改」+ ColorOS 默认关 + 164 号文⑥三系收敛）。【v2 预埋】
- **用户开关语义**【v1 立法】：单一心智「能力授予」，不做自启动/关联启动/后台弹窗三开关分立（HarmonyOS 反面：用户两极化全关/全开）；开关 = §2.2 时效三态同款 UI。
- **stopped-state 等价物**【v2】：禁用/强停的应用不再进 boot 批、收不到任何事件投递，直至用户显式再启（Android force-stop 同款）。
- **PC 档分岔**【v2+】：startupTask 语义——首次运行才激活、用户禁用后**不可编程复活**（MSIX 同款铁律）；自启动在桌面是用户明示的期望，OS 只登记 + 可禁 + 记「启动影响」。

### 5.2 关联启动（链式唤醒）【v1 立法·机制红利】

- **能力图天然切断**：拉起 B 需持 B 的启动 handle，而该 handle 只能由用户操作或系统服务（appd）派生——应用间无「隐式唤醒」路径可走（对标底稿三号 D 节推论）；`provides` 语义声明（§9.2）是唯一注册面。
- **记账与拦截记录**【v2】：跨应用唤起尝试全量记账（谁→谁、何时、结果），设置页可查（ColorOS 关联启动「拦截记录」的用户价值点）；SDK 等内嵌组件的关联启动须用户自主选择（292 号文明文）。
- **唤醒类入口**：timer/push 能力位（#68）+ wake 配额（#67 默认零配额）——「被系统唤醒」是系统意图执行，不是应用权利（iOS 口径采纳）。

### 5.3 睡眠态策略【v2 预埋】

睡眠时段按应用断网 + 冻结为默认（ColorOS 睡眠待机优化对标）；豁免 = 显式白名单（用户可见，非 AI 黑箱）——与 PM 省电三件（ADR #66–#68）同链，配额走票不走走后门。

## §6 通知规范

> v1 现实：无通知服务。本节 = day-one 立法位（「砍实现不砍协议位」惯例，裁决 G 同款）——manifest 位与协议 crate 位先留，notifyd 随 GUI-9/v2 落地。

### 6.1 模型【v1 立法】

- **通知 = 系统能力 + 投稿制**：应用持「发通知」handle 向 notifyd 投稿；**通知 handle 归通知服务**——应用退场不影响已发通知（HarmonyOS slot 模型采纳；Android 渠道由应用创建是反面——控制权倒挂）。
- **档位三档制**【v1 立法】：`social`（社交通信：横幅+铃声+锁屏）/ `service`（服务提醒：横幅或状态栏）/ `silent`（内容更新：仅通知中心）——HarmonyOS 6 档压缩、Android 渠道无限列表拒绝；档位入 manifest `[notifications]` 节【v2 预埋】，授权时展示、用户终局控制。
- **通知点击直达**【v1 立法】：点击 → 目标 handle 直达目标界面，**禁中转提权**（Android 12 trampoline 禁令同款）。
- **全屏通知**【v2】：仅来电/闹钟两场景（Android 14 同款收紧）；「紧急穿透勿扰」档【v2+】须 G2 级授权 + 人工审批（Apple criticalAlert 双层对标）。

### 6.2 常驻通知与长时任务绑定【v1 立法】

持 §4.2 资源证据的后台运行**必须**带常驻通知（进度/状态），用户划掉通知 = 收回后台资格（close handle 链）——HarmonyOS 长时任务同款；传输类首次进度 10 分钟未更新即取消（HarmonyOS 定值直接对标）。

### 6.3 实况窗（进行时任务形态）【v2+ 远期】

胶囊/卡片/锁屏实时形态（外卖/导航/打车），生命周期随任务、不持久化；「2h 无更新自动降级普通通知」状态机直接复用（HarmonyOS Live View 对标）；数量与频控配额（24 条/5 条/每 5 分钟 10 次）随 notifyd 立项定死入 ADR。

## §7 桌面与启动器规范

### 7.1 现役契约【现役·GUI-8】

- 应用枚举/启动：`APP_LIST`（分片流，id/label/icon blob）/ `APP_SPAWN` RPC（svcmgr 常驻 app 域；app_launch 全守卫单源）；`APP_EVENT` op 留位（.bap 增删推送，v2 /apps 树前提）。
- 点击 → spawn → **全屏独占窗**起步；回桌面 = 应用退出/失焦（规划 §3）。
- 布局持久化跨 boot（FAT + berry-layout canonical）；变体写自检 + 读失败回默认重写自愈。

### 7.2 桌面交互规范【v1 立法（v1 范围盒内）/ v2 高级面】

| 面 | 规范 | 状态 |
|---|---|---|
| 图标点击防抖 | 点击 → spawn 回执前忽略重复点击（挂账件，落码义务） | 【v1 立法】 |
| 滑动翻页 | ≥500px/s 或位移 >40% 判翻页（SwipePager 现役判据）；页指示器必配 | 【现役】 |
| 长按菜单/卸载交互 | 长按 → 菜单（卸载/信息）→ 确认对话框 → appd 删树；**卸载必经确认 + 可见后果**（删除数据范围明示） | 【v2】（OH AppMenu→installer.uninstall 同构） |
| 文件夹/拖拽编辑/角标 | — | 【v2+】（附录 B 砍单维持） |
| 最近任务 | mission 快照列表 | 【v2】 |

### 7.3 卸载语义【v1 立法·v2 落地】

卸载 = 删树 + 回收全部 handle + 清授权记录 + 墓碑清（407 号文第七条：附属资源/配置/用户数据文件一并可清；**系统升级不得复活已卸载应用**）；写进 `user/` 的文件留下（已是用户的——存储 §4 在册）。卸载事务 = appd↔fsmgr 协同（HarmonyOS 反面：目录种类多语义细）。

### 7.4 桌面卡片（widget）【v2+ 远期·立法位】

- 声明形：`[[widget]] { grid = [2,2], entry = "views/card.bui", refresh = "daily50" }`——**格数元组**而非像素（HarmonyOS supportDimensions 7 档对标：1×2/2×2/2×4/4×4 起步四档）；渲染 = launcher 持 berryui 解释器（**widget 进程不必活**——Android RemoteViews + iOS WidgetKit 共识，受限声明式 UI）。
- 刷新配额 day-one 立法：每卡每日 ≤50 次、最短间隔 5 分钟（HarmonyOS 硬数字直接对标）；两轨制 = 定时刷新（配额）+ 代理推送（走通知 handle），**禁五套机制并存**（HarmonyOS 反面坑 6）。

## §8 数据与存储规范

在册基座引用（`存储布局与沙箱设计-v1.0.md` §2–§4，本节只立应用侧条文）：

1. **两类目录纪律**【v1 立法】：应用私有树收敛为 `data/`（持久）+ `cache/`（可驱逐可清，**应用必须可重建**）两类——HarmonyOS el1/el2/files/temp/haps 多目录反面；「清理契约」随 fsmgr v2 落地（cache 超配额系统清）。
2. **产出归用户**：下载/导出写 `user/main/` 对应目录，凭用户授权 handle——拉完归用户，卸载不清（在册）。
3. **备份**【v2+】：appd 持句柄的系统服务；初值参照 ≤25MB/app（Android Auto Backup）+ 排除规则进 manifest（cache 恒排除）；端到端加密随 keystored。
4. **剪贴板**【v2】：系统服务持有、应用**默认无 handle**；读取 = 一次性 handle（PasteButton 安全控件 or 显式授权）；读取提示默认开（ColorOS C13–C14 全形态演进终点）+ 按应用禁读 + 读取历史可查；「剪贴板劫持」（监听触发悬浮窗）列恶意行为拒装（OPPO 审核规范同款）。
5. **数据加密档**【v2+】：容器加密四档（Complete/UnlessOpen/UntilFirstAuth/None——iOS 数据保护类平移）随盘加密刀。
6. **per-app 共享**【v2+】：组能力 token（appd 签发 + 成员签名链核验——App Group 对标），比 entitlement 更显式。

## §9 跨应用互操作规范

### 9.1 服务发现与调用

- 路径式命名空间 `/svc/...`（决策 #6）+ channel 能力门控（在册方向）；**枚举应用/服务本身 = 显式 handle**（Android Package Visibility 十年收紧课：默认最小化从 day-one 起）。
- **隐式路由 = appd 意图路由表**【v2】：「意图名 → 已授权服务 handle」代查转发，天然带权限过滤（Want 隐式机制的能力化转译）；handler 须预注册唯一或用户固定默认（隐式多候选混乱反面）。

### 9.2 声明式意图（`provides` → `[[intents]]`）【v2 预埋·方向 v1 立法】

- v1 在册：`provides = ["search", "play"]` 语义声明槽（应用模型 §8.2）；v2 扩为 `[[intents]] { verb, entity_schema, entry }` 结构表——**静态 manifest 字段、编译期可查、安装期可验、系统可索引**（Apple App Intents + HarmonyOS Intent Kit 双系收敛证据：静态注册赢、运行时 donate 输）。
- 与 intent(u8) 调度（ADR #42/#58）正交互补：调度 intent 管「多重要」，声明意图管「能做什么」——AI 面的消费入口（Agent 查 manifest 知接口，同一扇门纪律 §8.3）。
- **v1 只开放固定动词集**（open/view/share/pick/search 起步五动词），不做自由 schema（HarmonyOS 意图审核 3 工作日人工 = schema 治理成本警示）。

### 9.3 深链与分享【v2 预埋·立法 v1】

- **只做验证版深链**：包身份 ↔ 域名绑定（assetlinks/AASA 同构：`/.well-known/berry-apps.json` + 签名指纹），验证后免歧义直达；**自定义 scheme 不给隐式路由地位**（URL scheme 冲突无仲裁是三系共同反面）。
- **分享 = 系统面板单例**【v2】：share 目标注册（`[[intents]]` verb=share），系统面板统一呈现——禁三方自绘分享列表（Android 官方同款明令）、禁应用互相拉起。
- **输入法**【v2+】：type 词表新值 + 专用服务 handle（**仅系统可 bind**——Android BIND_INPUT_METHOD signature 级同构）；键盘进程系统所有、app 只收提交结果（iOS 同款隔离），旁路采集 = 拒装级违规。

## §10 隐私与安全规范

### 10.1 信任与完整性链（设计定稿引用）

- 签名：分离式 `.sig` 信封（ed25519 + SHA-512/256）、key_lineage 身份别名、信任账本全机器裁决、换钥重叠双签窗（`SDK-2-分发与签名链设计-v1.1.md` 全文引用）。sideload = 系统开关（产品镜像默认关、dev 镜像预开）；**全签关门触发器**已立法（外发反转或首个在野包，先到即关门）。
- 度量：`.bap` manifest 集进度量链（`安全与硬件隔离设计` §4，按 app id 升序累加）；镜像内置官方源静态实例 + 签名索引。
- 进网/出厂一致性【v2+】：预装清单做成镜像内签名字段，appd 校验（407 号文第六条义务）。

### 10.3 监管合规底线【v1 立法·随分发面执法】

### 10.4 开屏与广告行为规范【v1 立法】

对标：工信部 292 号文（开屏弹窗「找得到、关得了」——明显有效的关闭按钮；开屏**不得**整屏图片/视频作跳转链接）+ OPPO 审核规范广告条款（禁摇一摇高灵敏度误导跳转、禁「信息窗口关不掉」、禁锁屏广告、广告须标识）。

1. **弹窗必经系统 UI 服务渲染**【结构性执法点】：应用级模态/开屏/确认框一律经系统弹窗服务（wmd 系统窗面）呈现——系统天然获得「关闭按钮必须在、必须真关」的执法位；绕行（自绘满屏伪装系统弹窗）= 恶意行为清单项拒装。v1 承接面 = wmd 两层窗；全量弹窗服务随 v2。
2. **开屏约束**：开屏画面关闭按钮恒在、关闭即进应用主体（禁「跳过」假按钮）；整屏可点击跳转禁止（点击区域 ≤ 明确标识的按钮）；开屏时长计入启动指标（§13 口径）。
3. **摇一摇/误触类**：传感器触发跳转默认禁（加速计阈值触发广告 = 拒审项，OPPO 2026-10 版同款）；v2 随 sensor 能力位落地「传感器用途对账」（声明 reason ≠ 广告跳转即拒）。
4. **广告标识**：广告内容须可辨识（标识位 + 来源 app id）；儿童类目禁行为广告（适老化 200 号文同款禁令对齐）。
5. 执法位：wmd 弹窗服务（1）+ 商店审核 v2（2–4）+ §10.2 行为时间线（3 的检测面）。

## §11 系统应用特殊规范（当前主战场）

### 11.1 定义与同格式铁律

**系统应用 = 预装于镜像（boot rootfs / v2 sys+apps）、由系统集成者签名、持 G2/G3 能力白名单的普通 `.bap`**。同格式同门同规范——本节只加严、永不豁免 §1–§10 任何一条（HarmonyOS 同格式正确面 / Android priv-app 双轨反面；监管趋势「谁预置谁负责」不豁免预装应用，269 号文 + 164 号文⑤⑥）。

### 11.2 特权白名单机制【v1 立法·v2 落地】

- 镜像内**签名白名单清单**（`priv-grants.xml` 等价物，Android privapp-permissions 同构）：`{app_id → [G2/G3 能力键]}`，随镜像签名分发；**构建期校验 + boot 对账**，未列而申请 = **拒授 + eco 行 loud 降级**（不采 Android「不开机」——失败隔离原则下系统应用降级运行优于拒绝启动，与 `APPUI ok` 独立判同哲学）。
- 特权能力永不进 G0/G1 词表——升级路径只有「系统签名 + 白名单」一条（ACL 双轨漂移禁入，§2.1）。

### 11.3 基本功能软件最小集（269 号文映射）【v1 立法】

| 269 号文四类 | BerryOS 对应 | 可卸载性 |
|---|---|---|
| 操作系统基本组件 | **SETTINGS**（设置）、**FILES**（文件管理） | 不可卸载（可停用） |
| 保证硬件正常运行 | **CAMERA**（多媒体摄录）、**PHOTOS**（图库） | CAMERA 不可卸载；PHOTOS 可卸载（同一功能至多一个不可卸载——269 号文仲裁规则直接采用） |
| 基本通信应用 | **BROWSER**；CONTACTS/MMS 为占位（v1 无电话硬件，真机刀转正 DIALER/SMS role） | BROWSER 可卸载（保留系统浏览器能力位） |

- **现役七系统应用**（BROWSER/CAMERA/CONTACTS/MMS/FILES/PHOTOS/SETTINGS + APPDEMO/APPQUIET 演示件）恰好落位——269 号文最小集是现役清单的合规注脚，非新裁。
- 预装元数据义务（407 号文第六条）：名称/功能描述/卸载方法/开发者/权限列表及用途 = manifest 强制字段 + appd 详情页展示【v2】；系统应用更新 v1 随镜像、v2 独立换树（versionCode 高即覆盖）。

### 11.4 系统应用义务清单【v1 立法·现役纪律成文】

1. `console = false`（串口纪律——现役七件同款）；输出走结构化遥测/日志面。
2. 遥测削至近零（分发签名链 §五同款纪律）；崩溃走监督重启（launcher 先例：一次重启帽 + eco 行 loud），不得申请豁免监督。
3. 能力最小集：白名单授什么用什么；**禁「以防万一」式全量申请**（appd 对账断言进 smoke）。
4. UI/无障碍/资源配额规范全量遵守；**系统应用不得豁免任何用户可见管控**（设置页同款展示其能力使用）。
5. 后台豁免位（#68 ①）仅限白名单系统应用（launcher/display/inputd 族），豁免清单公开常量（Apple 双标准争议的反面）。

## §13 DFX / 测试与验收规范

1. **装载谓词**【现役】：`APP ok n=`（装→起→真退出→reap 真码 0 全槽过）+ `APPUI ok n=`（资产面对账，与启动成败独立判）。
2. **GUI 交互链**【现役·GUI-8】：`LAUNCH ok` / `PAGE ok n=2` / `CLICK ok n=1`（真链 virtio-tablet→inputd→launcher→APP_SPAWN）/ `LAYOUT(W) ok`（跨 boot 布局）。
3. **像素级验收**【现役·SDK-1 方向】：黄金图逐字节对拍（TCG + 固定 profile）+ 截图服务 + dump round-trip 注入（GUI-9）；时钟漂移以 `time="fixed"` 相处理。
4. **能耗断言**【v1 立法·GUI-9 面】：IDLE 注入零事件时帧循环唤醒计数恒 0（「无 damage 不提交」不变量）；系统应用稳态 icount 入档（B-2 通道）。
5. **崩溃报告**：eco 降级行 + 死因/退出记录（app-1 起弃「墓碑记录」措辞——防 Android tombstone 崩溃转储义撞名；BerryOS 墓碑 = pause(save)→relaunch 读档复活谱系〔应用模型 §4.1/草案 v1.2 术语注〕）+ 代号重启链（#28）；ANR 等价 = 收尾超时监督杀——**确定性状态谓词，不赌竞速**（全 smoke 惯例）。
6. **每系统应用验收模板**【v1 立法】：① 启动标记 + 退出码 0；② `[ui]` 资产三件对账；③ 能力最小集断言（申请 = 白名单 ⊕ 用途，appd 对账）；④ 崩溃→重启→功能恢复；⑤ 配额红线（内存/栈深/树规模实测入档——GUI-8 §6 帽表先例）。
