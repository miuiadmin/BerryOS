> 同路径）；盘 = `tools/mkfat.py` 默认 1MiB 平盘（2048 扇区，卷 @LBA16）。

## 0. 结论速览

| 问题 | 答案 |
|------|------|
| 单次覆写 commit 是否有掉电毒化窗？ | **有**——④ 旧链释放与 ⑥′ 根写入之间存在「FAT 已写、根未写」窗，盘面 = 毒环态 |
| 毒环态的后果（无守卫时）？ | 文件首簇可读、后续簇 Bad；**每次重试 commit 重演同环**（结构性死循环，非一次性损伤） |
| v1 修复面 | commit ④ 守卫：∈ 新链的簇跳过释放（归属已转新链）——恢复 commit 自愈毒环 |
| smoke 关卡 | 阶段 7 三 boot：自然采样 ×2 + `pwrcls --poison` 确定性注入 + Boot C 毒环盘全链重跑终验 clean |
| QEMU 模拟的粒度边界 | **扇区间撕裂**（writeback=off 下已完成扇区已落宿主、在途蒸发）；扇区内撕裂 = 真机面，本相不覆盖 |
| v1 接受的残余面 | 新文件簇泄漏（⑥′ 前掉电：链在 FAT、根无槽）、FAT1 永不回读、无 journaling——见 §5 |

## 1. commit 写序与撕裂前缀表

`commit(n11, data)` 的落盘序列（fat.rs ⓪-⑧；staging PUT ①② 只进内存，
首个盘写从 ③ 起）：

| 步 | 动作 | 盘写扇区数（RW.TXT 3000B = 2 簇） |
|----|------|-----------------------------------|
| ① | 旧链 collect（内存） | 0 |
| ② | 新链分配（fat2 内存副本） | 0 |
| ③ | 数据扇区落盘 | 8（2 簇 × 4 扇区） |
| ④ | 旧链释放（fat2 内存） | 0 |
| ⑤ | 双 FAT 全扇区落盘 | 4（2 副本 × 2 扇区） |
| ⑥′ | 根扇区落盘（整扇区写回） | 1 |
| ⑦ | 根扇区回读对账 | 0（读） |
| ⑧ | 安装内存态 | 0 |

共 **13 次扇区写 RPC** + ⑦ 回读 1 次 = 14 次串行扇区 RPC（TCG 下每次
≈0.8s ≈ 10s 窗口）；staging 阶段（③ 前）另有 ≈16 次 PUT ≈13s。掉电落在任一前缀后，盘面状态：

| 掉电点 | 盘面（RW.TXT 视角） | pwrcls 分类 | 后果 |
|--------|---------------------|-------------|------|
| ③ 中途 | 数据簇新旧混杂；FAT/根全旧 | clean（旧链完好） | 无——旧文件照读，新数据丢 |
| ③ 后 ⑤ 前 | 数据新、FAT/根旧 | clean | 无——旧链照指旧簇、旧簇数据完好（③ 写新簇，与旧链构造性不相交），旧文件照常读出；重试 commit 幂等 |
| ⑤ 中途 | **FAT 半新**（新链已立 + 旧链已释放）；根旧 | poison（旧首簇所在 FAT 扇区已写）/ clean（未写） | **毒环窗**——见 §2 |
| ⑤ 后 ⑥′ 前 | FAT 全新；根旧 | poison | **毒环窗** |
| ⑥′ 后 | 全新 | clean | 无——掉电前后语义等价 |
| 新文件（无旧链）任意点 | ④ 空转；⑤ FAT 先于 ⑥′ 根 | noent / clean | 无毒环面（结构性） |

**为什么 ⑤-⑥′ 窗是毒环**：覆写路径 ② 分配时旧链仍标记（防重用）→ 新链
取**新簇** c_new；④ 释放旧链 c_old；⑤ 把「c_new 成链 + c_old 全 Free」写进
盘面 FAT；掉电时根仍指 c_old。盘面 = `root.first = c_old` 而
`FAT[c_old] = Free`。

## 2. 毒环的力学（为什么是循环而非一次性损伤）

恢复 boot 后 fsmgr 重读盘 FAT/根，重试 commit（同一 PUT）：

1. **① collect 走旧链**：从 `root.first = c_old` 起步——push c_old 后查
   `FAT[c_old]` = Free → 止步。`old_chain = [c_old]`（**首簇进链、链后续
   不可达**）。
2. **② 升序分配**：`find_free_cluster` 从 2 升序——smoke 负载（单文件
   覆写、无更低 Free 洞）下 c_old 是全盘**最低的 Free** → 新链头必复用
   c_old（三镜 M1 穷举核验的复用力学前提即此负载形态）。**一般负载下
   更低位可有他文件释放的 Free 洞**（c_old 非最低）→ c_old 可被中段
   复用或完全不复用——守卫按 **∈ 新链成员制**设计（`chain.contains`，
   非头部特判），三种复用形态（头部/中段/不复用）恢复终态皆 clean，
   自愈性不依赖头部复用。
3. **④ 无守卫时**：旧链 [c_old] 无条件释放 → `FAT[c_old] = Free`——把
   自己刚分配的新链头打掉。⑤ 写盘、⑥′ 根仍指 c_old（同值）→ **盘面回到
   毒环态**。
4. 读侧：文件读簇 0 直取 `root.first`（`nth_clus n=0` 不验 FAT）成功，
   簇 1 起走 FAT 撞 Free → Bad——**半文件**死状。

每次重试精确重演 1-3：**commit 语义在毒环盘上不收敛**。这就是 B4 修复的
对象——④ 守卫「∈ 新链的簇跳过释放」把第 3 步变成空转：新链头 = c_old ∈
chain → 不释放 → ⑤ 写出的 FAT c_old 成链 → ⑥′ 根指 c_old（原值）→
盘面 clean，**一次 commit 自愈**。正常路径 old_chain ∩ chain = ∅ 构造性
成立（② 只配 Free 簇、旧链此刻仍标记）——守卫零行为漂移。

host 钉板（`user/berry-fatfs`，27→31 测）：`torn_fat_poison_window_primitives`
（毒环基元三态 + `find_free_cluster == Some(3)` 复用必然性）、
`torn_fat_midchain_free`（中链 Free 态语义）、`torn_fat_value_domain_honesty`
（畸形值诚实拒）、`torn_fat16_poison_twin`（FAT16 同型面）。

## 3. QEMU 掉电模拟的粒度边界

`tools/smoke.sh` 阶段 7 用 **SIGKILL 直杀 QEMU** 模拟掉电，配合
`cache.writeback=off`：

- **已覆盖**：扇区间撕裂——writeback=off 下 guest-已完成的扇区写已同步落
  宿主盘，被杀时在途请求蒸发。盘面 = 13 写序列的某个**前缀**，与真机
  「掉电在 N 个扇区写之间」同形。
- **不覆盖**：扇区内撕裂（单 512B 写写到一半）——QEMU 块层单扇区写原子，
  真机 DMA/FTL 下存在半扇区面（FAT 镜像两副本 + 保留扇区校验是 v2+ 日志
  FS 的防御对象）。**本评估的所有结论以「扇区写原子」为前提**。
- SIGTERM 不用于掉电模拟（优雅退会补完在途写，且死后仍刷盘数秒——那是
  持久化相的纪律，不是掉电语义）。Boot C 终验用 SIGTERM + wait + sleep 3
  取盘，因为终验断言的是「guest 全链跑完后的稳态盘面」，非撕裂面。

## 4. smoke 阶段 7 的关卡设计

三 boot 链（独立盘 `disk.pwr.img`，无 netdev——vnet 无 net 槽 trap 干净
自死，NET 族标记自然缺席不设门；bsh 的 fat→fatw→df 相邻链不依赖 net）：

| Boot | 时点 | 断言 |
|------|------|------|
| A | `FAT ok` +18s SIGKILL（fatw 新文件窗：staging 13s + commit 10s） | 按终局日志相分两档（状态谓词，不赌 kill 落点）：FATW ok 未见 → ∈ {noent, clean}——**粗检 canary**（执法「根在场而 FAT 撕裂」类现序下不可达态；对 ⑤/⑥′ 写序回归零证伪力，§6）；已见（快机进覆写面）→ ∈ {clean, poison}（同 B 口径） |
| B | `FATW ok` +15s SIGKILL（DF resize commit 窗 [+3,+25]s） | 采样 ∈ {clean, poison}——**整扇区 FAT 写的负向断言**（midchain/malformed = 扇区原子性假设破） |
| B 后 | `pwrcls --poison` | 注入后分类必 poison（确定性注入替代概率撞窗——自然采样撞毒环窗 ≈ commit 窗 4/13 占比，不可依赖） |
| C | 毒环盘全链重跑（FS/VIRTIO/VBLK/BLKD/FAT n=5000/FATW n=3000/DF/CD） | **双面不变量**：guest 标记全绿（恢复 commit 走通）+ 盘侧 `pwrcls` 终验必 clean（标记绿而盘面毒 = 恢复链假绿，单面测不出；**FAT0 侧**——FAT1 分歧不在 oracle 面，§5.2） |

设计原则映射（`测试策略.md`）：A/B 采样是**状态谓词断言**（合法集枚举；
Boot A 按 kill 时相分两档后不再隐含时序前提），不是竞速；C 的毒环注入是
**可编程故障注入**（确定性、每轮必达）；pwrcls 输出 `PWR cls=<state>
first=<n> size=<n>` 机器可读。已知缺口如实入册（§6）：A/B kill 前无活
性复验（无输出挂死与合法采样不可区分——switches= 金丝雀每 50 切一行
≈10s，窗内零增长断言在慢机上假红，故不做）；⑤/⑥′ 写序无运行时执法。

## 5. v1 接受的残余面（如实记载，不装看不见）

1. **新文件簇泄漏**：新文件 commit ⑤ 后 ⑥′ 前掉电——FAT 里立了链、根无
   槽指向 → 簇永久泄漏（无 fsck/扫描回收）。1MiB 盘 506 簇，泄漏 2 簇/次
   撞窗；v1 接受（smoke Boot A 的 noent 态即此面的可见形态）。
2. **FAT1 永不回读**：⑤ 双 FAT 同写、FAT1 不读不核（mkfat 双副本同写惯例
   的信任延伸）。若撕裂恰好落在 FAT0 与 FAT1 写之间 → 副本分歧无人发现。
   v1 读路径只走 FAT0，分歧无消费面；v2 FS 起引入副本互核/日志。
3. **无 journaling/无 fsck**：本刀只修「毒环不收敛」这一**结构性死循环**，
   不提供掉电后的一致性恢复工具。撕裂前缀表中 clean 的各行本就幂等安全，
   poison 行经 ④ 守卫可自愈——这是「序设计 + 最小守卫」路线（提前写好
   FAT 再写根 = 单调收敛方向），不是日志路线。**写序本身无运行时执法**：
   ⑤FAT 先于 ⑥′根 只以 fat.rs 语句序存在——阶段 7 三 boot 对「⑤/⑥′
   对调」回归全绿（两序的撕裂盘面同分类 poison，Boot C 恢复对两序同收敛），
   该性质目前只靠人读代码维持，执法面见 §6 未来刀。
4. **resize 半程态**：DF 3000→2048→3000 是两次独立 commit——若掉电在两次
   之间，盘面 = 2048B 版 RW.TXT（clean），非撕裂（每次 commit 自身原子到
   §1 表的语义）。smoke Boot B 采样窗覆盖此面。
