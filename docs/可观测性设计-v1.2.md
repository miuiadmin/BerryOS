# 可观测性设计（Tracing 与在机诊断）

Type: standard
Status: current
Updated: 2026-11-20
Version: 1.2.0

> 现代 OS 的命门：**问题不可见就不可修**。本标准规定 BerryOS 内置遥测环、内核日志快照与低开销追踪契约；决策依据见 [架构决策](架构决策.md) #25，崩溃黑匣子契约见 [cbox 总体设计](../.agents/plans/cbox/design.md)，硬件 PMU 采样与 `traced` Perfetto 守护进程见 [devtools 总体设计](../.agents/plans/devtools/design.md)，纯终端在机实时观测与交互调试工具链（`btop / lscap / btrace / bdbg / cboxctl / dmesg -w`）见 [cli-suite 总体设计](../.agents/plans/cli-suite/design.md)。
> **v1.0.1 修订（2026-11-18）**：升格 Curia `Type: standard`；对齐现役 `0x84 telemetry_open` 内核日志快照、双静态无锁环与 `TRACE_CAP = 0.0` 零劣化门禁现状，并锚定微内核能力内省（`lscap`）与系统调用/IPC 追踪（`btrace`）演进接口。

## 1. 目标与核心不变量

- **低开销**：追踪点在关闭时近零成本（编译期剔除 + 运行期单条位测试门控），绝不在内核热路径引入堆分配或全局锁竞争。
- **高保真**：覆盖系统调用进出、调度切换、IPC 收发、缺页供给、中断响应与能力门控拒绝六大关键路径。
- **不阻塞**：采用每 CPU 静态预分配无锁环形缓冲（单核写、用户态诊断服务异步读），环形写满按策略覆盖旧记录并递增 `dropped` 计数，永不阻塞内核执行流。
- **人机双面可消费**：既支持导出 Perfetto / Chrome Trace 时间线供可视化剖析，也原生支撑终端内 `dmesg`、`btop`、`lscap`、`btrace` 实时交互排查与 `--json` 结构化读取。

## 2. 追踪分类与公共记录契约

```rust
// 内核与系统服务追踪点概念形态（编译期 + 运行期类别掩码双门控）
trace!(sched, "switch: {} -> {}", prev.name(), next.name());
trace!(ipc,   "send: ch={:#x} bytes={}", ch, n);
trace!(mem,   "fault: vaddr={:#x} kind={:?}", vaddr, kind);
```

- **标准类别（Category）**：`sched / ipc / mem / irq / syscall / boot / cap`。每类对应独立掩码位，支持按类别动态启停。
- **C-ABI 稳定记录头**：跨内核与用户态边界的事件与统计快照统一采用 `#[repr(C)]` 定长结构（含单调 `CNTVCT` 时间戳、CPU 号、类别与内联载荷，见 [架构决策](架构决策.md) #18）。

## 3. 双通道环形缓冲与资源快照同源模型

- **每 CPU 无锁环基座**：与 [AI 调度设计](AI调度设计-v1.0.md) §4 共享同一套无锁环形基座，按用途物理分道：
  - **trace 通道**：高频细粒度事件流（现役已实装调度切换环 `SwitchRec` 与唤醒归因环 `WakeRec`），体积大、允许满环轮转覆盖；
  - **telemetry / klog 通道**：聚合指标（每核利用率 EWMA `0x40 sched_util_snapshot`、意图档位直方图、通胀计数）与内核诊断日志环（经 `0x84 telemetry_open` 导出，供 `bsh` `dmesg` 读取）。
- **单源快照导出**：面向终端监控与内省工具的内存账本（`MemstatRec`）、进程线程运行账（`ProcStatRec`）及进程能力句柄拓扑快照（`CapInfoRec`）统一从内核既有账本聚合只读导出，禁止建立重复记账源；终端工具面规格见 [cli-suite 总体设计](../.agents/plans/cli-suite/design.md)。

## 4. 守护进程与在机诊断出口

- **常驻追踪总线（`traced`）与日志隔离**：系统守护进程诊断流与启用后的事件环由用户态 `traced` 统一收割落盘或转发给订阅者（如 `dmesg -w`），禁止后台服务直接涂写前台交互终端（见 [pty 总体设计](../.agents/plans/pty/design.md)）。
- **在机全栈排障三视图**：
  - **状态面（`btop / free / lscap`）**：实时观测每核负载、物理页去向以及任意进程的能力句柄、Rights、Badge 与 Channel 对端连接图；
  - **轨迹面（`btrace / berry perf`）**：实时拦截解码目标进程 `berry_*` 系统调用与 Channel RPC 协议帧，或经硬件 PMU 采集全栈火焰图（见 [devtools 总体设计](../.agents/plans/devtools/design.md)）；
  - **事后面（`cboxctl / ramoops`）**：排液解码用户态/内核态异常寄存器账本与跨热复位持久黑匣子（见 [cbox 总体设计](../.agents/plans/cbox/design.md) 与 [hal 总体设计](../.agents/plans/hal/design.md)）。

## 5. 版本与兼容

- **MAJOR**：不兼容修改已上线遥测系统调用（`0x40`、`0x42`、`0x84`）参数或破坏既有 `#[repr(C)]` 记录二进制头部偏移。
- **MINOR**：在 `0x84` 或 `/svc/proc`、`/svc/trace` 下新增操作码、新增追踪类别与 `--json` 导出字段。
- **PATCH**：性能基线注记更新、文档说明与跨模块引用维护。

## 6. 适用边界

- **热路径零劣化硬约束**：关键路径追踪开关默认关闭时必须满足 `bench_baseline_icount` 与 `bench_baseline_icount_traceoff` 门禁（`TRACE_CAP = 0.0` 零泄漏断言，详见 [G3 全抢占实施设计草案](G3全抢占实施设计草案-v1.0.md) §8）。
- **权限门控**：读取全机内核日志、跨进程追踪或导出他人能力表须持有对应受控能力（如 `/svc/trace`、`/svc/proc` 或 `ProcessDebugCap`；内核侧能力收口见 [ipc 总体设计](../.agents/plans/ipc/design.md)），普通沙箱进程禁止越权窥探全局遥测流。
