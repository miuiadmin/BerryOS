## 1. 版本定位与范围（S6 = 策略服务 + shadow + 回滚 + band/AI）

- 一句话候选：1.2 不做「AI 会调度」，做「策略可上线、可证伪、可撤销」——
  把 1.1 留下的慢环接口变成有生命周期、有护栏、有回退链的用户态策略服务。
- 核心问题：S6 与 v3/M4 门的对应关系怎么写死——band 化与 (B) 分类器同窗
  （ADR #42），1.2 出口含不含分类器服务首形，还是只铺轨道？
- 核心问题：入口条件（v1.1 §8.1：1.1 预算可复现 + AI 有可测收益）由谁、
  用什么负载、在哪个口径下复核？策略服务未建时「AI 有收益」以什么为准
  （4-6 B 半最小演示 / shadow 预跑）？
- 非目标继承：per-handle 硬预算、第五类动作、学习型策略（v4+）、改
  `SchedClass` trait、intent 词汇表扩档——逐条重申还是引用 1.1 §1.5/§10。

## 2. 现状与接口起点（policy.rs 实况）

- 已落·机制面（首刀/二刀）：三槽 RCU 快照 + O(1) 黄金比散列（publish/
  active_snap/lookup_o1；bind/unbind 签名零改动）+ gen 世代观察 +
  bind_gen 陈旧拒收（`gen <= 当前` 拒）——PV3-K 五段全绿，AIDEMO ok
  改经 O(1) 新路活证。
- 已落·通道面（S6-b/c/d）：0x83 syscall COMMIT + shadow 双轨道
  （bind_gen_shadow/promote/demote，SHD-K 五段）+ berry-sys wrapper +
  policydemo——端到端注入链（用户程序→svc 0x83→Snap→apply）打通。
- 已落·性能口径（PP-K）：未绑/空表/满表 128 条三态差测——空表等价 ✓ +
  有表 avg 趋势门（<20% 千分比，QEMU 金丝雀）；真机 p99 待 HDR 基建。
- gap 余项：per-thread 键（proc_tag 为内核态指针无用户态查询面，demo 暂
  用 FIXED_KEY=1 验机制）/ SET_POLICY 门控（需 Job 对象 = v2）/ STATUS
  op（键查询出口：STATUS 或 sched_getattr 扩展）。

## 3. 设计总览：慢环/快环三层与既有底座的关系

- 三层（快循环查表快照 / 慢循环服务重算表 / 遥测环回流）落到 1.2 的模块
  与 crate 边界：`sched/src/policy.rs`、共享环、用户态服务、PM 同级同模式。
- 核心问题：策略服务在进程拓扑上挂哪（svcmgr 拉起？Job 树 + 监督者？），
  与 PM governor、appd 的职责分界各一句话是什么？
- 核心问题：v1.1「单比较器」纪律（§4 禁第二套排序键）与 band 带间严格序
  如何相容——band 是 class 链下 fair 内合法再分层，还是违约？判定写进本节。
- 欠账显式化：有/无 AI 的 pick p99 必须相等——1.1 只断言空表等价，1.2 验
  有表（快路径开销与策略复杂度无关的实测形态）。

## 4. 策略服务生命周期

- 状态机骨架：cold（启发式独跑）→ bind（订阅遥测 + 发首表）→ shadow /
  active → 僵死或崩溃 → 监督重启回 cold；调度绝不依赖策略服务在线。
- 核心问题：表龄 watchdog 的阈值（几个慢循环周期）与计时者（内核还是
  监督者）；判僵死后自动回退启发式 + 告警的完整链路。
- 核心问题：崩溃重启后的状态恢复边界——重新订阅遥测、重算首表，还是
  续用旧表？gen 世代计数（对齐 ADR #28）跨重启怎么续、陈旧注入怎么拒？
- 平台分层验收档位：手表不跑 advisor（band 单核退化为 IntentProfile
  查表）、手机轻量、PC 管家核——1.2 在哪几档出证据？

## 5. 注入 ABI：共享环 + policy_bind(0x83)

- 已落（S6-b 最小版）：sys_policy_bind(0x83) COMMIT op——16B ABI 条目
  copy_from_user → 校验 rsv/epp_flags/条目数 ≤128 → weight clamp ±64 →
  bind_gen 陈旧拒收；其余 op 返回 -ENOTSUP；字面量 0x83 注册（v3 常量
  不在 abi_gen 层）。PBS-K 四段（合法/陈旧双拒/超限截尾/夹紧）全绿。
- 用户态契约：berry-sys PolicyEntry 16B 字段偏移钉板（key@0/weight@8/
  placement@12/epp_flags@13）+ berry_policy_bind wrapper + OP_COMMIT/
  POLICY_EPP_* 常量；policydemo 验 gen 重试协议 + 同 gen 重放 -EAGAIN。
- 留 S6-e：BIND/STATUS/PROMOTE/DEMOTE/UNBIND ops（内核 shadow 谱系接口
  已备——bind_gen_shadow/promote/demote，SHD-K 全绿，只欠 0x83 op 面与
  STATUS 键查询）。
- 契约起点（已裁，本文版本化）：共享环形缓冲传输（现 16B 直传暂代）、
  换表事务化 + gen 陈旧拒收（已落）、复用 `RIGHTS_SET_POLICY` 不新开
  特权类（门控需 Job 对象 = v2）。
- 核心问题（余）：SMP（v2 线）下原子换表靠双缓冲指针还是 seqlock？
  per-thread 键迁移与「只能调自己 Job 树下任务」授权语义怎么随键走？

## 6. 四类动作空间落地（放置/频率/权重/EPP——没有第五类）

- 逐类落点：①放置 hint（单核仅落字段不消费，SMP 才消费——1.2 验什么）；
  ②频率/热限 hint 走 PM 服务裁决、不经调度路径（PM 未到窗时落到什么
  程度）；③包络内权重微调（min/max 夹紧，内核执法不信任注入方自律）；
  ④EPP 二值。
- 核心问题：「没有第五类」的结构保证——表格式上就不存在第五种字段，还是
  靠 apply 侧白名单？band/intent 不入动作空间（ADR #42）的执法点在哪？
- 核心问题：RT/deadline 类屏蔽 AI 的实现位（表过滤还是 apply 前置谓词），
  与 S5 准入 / 预算执法怎么互不干扰？
- 越界处置语义：超界拒收 + 记日志 + 保留上次有效值——「上次有效值」跨
  换表 / 跨回退怎么定义，才不变成隐形状态累积？

## 7. band 层级与每带预算包络（ADR #42 第二段）

- 机制清单（已裁，本文只版本化）：class_fair ×4 带实例（0x01–0x04，
  0x05 冻结）+ 带间严格序 + 每带预算包络 + deadline-server 式兜底 +
  QNX 三件套（只在竞争时执行 / 空闲预算 loan / 整数微记账）+ 事件驱动
  虚拟时间记账（绝不复活周期 tick）；trait 签名零改动，数字进启动配置。
- 核心问题：入场券（v1 遥测实证 + loadgen + 尾延迟断言 + 空闲核金丝雀）
  的通过线与复核者；零假设（扁平 EEVDF + latency-nice）必须在哪组负载上
  被打败才准并 band？
- 核心问题：带内 EEVDF 与 1.1 S2 的 lag/VD 怎么衔接（lag 按带内算还是
  全局算）？饥饿界检查器（1.1 §6，接口已留 1.2）公式怎么扩带维？
- 核心问题：S5 准入公式何时显式含 band 预算项（M5 设计债，否则 deadline
  满额时兜底必违约）——1.2 先写接口还是直接执法？

## 8. shadow 模式与 shadow→active 升级路径

- shadow 定义候选：策略服务照常读遥测 / 算表 / 写环，内核只记录不 apply
  ——决策流可与基线对照、对运行为零影响（等价性可断言）。
- 核心问题：对照面怎么建——同负载时分复用（A/B 轮转）还是影子双算？
  QEMU 只看功能 / 顺序 / 相对趋势、分位出真机的口径（1.1 §8.2）怎么落？
- 核心问题：升级判据 = 可复现 A/B 可测收益（与 ADR #21 kill criteria
  同源）——尾延迟 / 能耗各设多少门槛、几个负载、复现几次算数？
- 核心问题：谁有权拍 active（启动配置 / Job MANAGE / 运维面）？active 后
  再降回 shadow / hint-only 的触发条件与自动性？
- shadow 评估自身的观察者效应（评估 harness 扰动机）怎么隔离？

## 9. 回滚安全与降级链

- 三层回退链：服务崩溃→启发式；表龄超阈→watchdog 自动回退 + 告警；
  权限吊销（`close` SET_POLICY handle）→注入通道关闭——每层的触发者、
  生效时延、可观测信号成表。
- 核心问题：回退瞬间的语义——在飞任务当片跑完还是立即重算 effective？
  回退不破坏 PI 捐赠合成（4-3b：`apply` 与 `refresh_effective` 同公式
  双写点）怎么断言？
- 核心问题：「回退 = 回到 1.1 行为」的逐位等价怎么测（`POLICY ok` 扩展：
  active→unbind→基线全等）？
- band 回滚：`band=0` 启动参数回扁平 fair？部分带执法的中间态允不允许？
- 审计：谁在何时把系统带入 / 带出 active（gen / actor / reason 进
  telemetry，对齐 1.1 §7.4 口径）。

## 10. 安全护栏与权限（内核强制不变量）

- 不变量清单版本化（源 = `AI调度设计-v1.0.md` §5 全表）：RT/deadline
  屏蔽、单调收窄（注入序列不得扩权）、防饥饿内核兜底 boost、热硬限、
  Job 级权限边界、越界拒收、intent 只降不升、band 预算本体 AI 不可触。
- 核心问题：每条不变量的执法点 + 测试形态（ktest 标记 / 故障注入 /
  property）——哪些进 smoke，哪些真机门控？
- 核心问题：注入权委托链（`duplicate` 收紧 / `close` 吊销 + 审计，
  `能力模型设计-v1.0.md` §4）在 1.2 落到什么深度？
- 与 v1.1 R10 联动：AI 动作越权 → 停实验回 hint-only 的判官与执行位。

## 11. ABI 契约与版本纪律

- 核心问题：0x83/0x84 进 `tools/abi.toml` 的时点与 `abi-check` 锁法；
  ADR #21 修订「实验轨道不立运行时 ABI」与 S6 立注入协议的关系怎么表述？
- v1.1 欠账激活：`sched_attr` bit5 reserve(min/max)「1.2 起 fair 包络」

- 环槽 `#[repr(C)]` day-one 定型纪律（同 telemetry 环先例：静态预储、
  零分配写入）；band 不加 attr 字段（intent 即带键）。
- 兼容红线：已发 35+ 号零语义漂移、0x38/0x39 保留、intent 六档不扩
  （#58）——1.2 漂移清单目标 = 空。

## 12. 里程碑与验收（S6 拆步）

- 实况刀序（沿革 2026-11-07 六条，独立可验各成提交）：首刀 ✅ policy.rs
  三槽 RCU + O(1) 黄金比散列（PV3-K 五段）→ 二刀 ✅ gen 观察 +
  bind_gen 陈旧拒收（PV3-4 解封）→ 三刀 ✅ S6-b 0x83 COMMIT + PBS-K
  四段 → 四刀 ✅ PP-K 性能验收（空表等价 + 有表 avg 趋势）→ 五刀 ✅
  S6-c shadow 双轨道 + PROMOTE/DEMOTE（SHD-K 五段）→ 六刀 ✅ S6-d
  berry-sys wrapper + policydemo 端到端链。
- 未竟（原 a–f 候选重排）：telemetry_open(0x84) 消费面映射（原 S6-a）；
  0x83 op 面 BIND/STATUS/PROMOTE/DEMOTE/UNBIND（现 S6-e）；启发式
  advisor 服务首形 + 表龄 watchdog（原 S6-c）；shadow 评估 harness

- 核心问题：band 与策略服务两条线谁先谁后、哪些可并行？入口条件未过时

## 14. 风险与 kill criteria

- 风险表起点：策略服务抖动（高频换表→快路径快照失效）；shadow 评估扰
  机器（observer effect）；band 打不过零假设；有表 pick p99 退化；AI
  收益不可复现；borrow/lend 借尸还魂；护栏执法点自身变成第二策略源。
- kill criteria 版本化：ADR #21——M4 前可复现 A/B 拿不到可测尾延迟 / 能耗
  收益 → AI 永久降 hint-only（接口保留）；band 败给零假设 → 不并或撤；
  有表 p99 相等破 → 回 1.1 形态。
- 核心问题：每条 kill 的判据数字、判官（谁跑 A/B、谁签收益单）、时限与
  复核节奏；降级后接口保留形态（hint-only 长什么样）。
