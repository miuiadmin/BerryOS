## 一、product 清单 v1 schema 全量

### 1.1 双键结构与分界（Q7 载体）

一款产品一份 `product.toml`（暂名；随产品包 `.sig` 信封分发，Q3——清单即信封内容物，信封/委托段字段细节归 #77）。双键分界 = **承诺面与自由面**（#82 裁决「platform 键 schema 归 L2 承诺、变更走章程 §六 api-diff；product 键 add-only 随组装工具版本化」）：

- **`[platform]`（合同面）**：每个枚举/开关对应平台侧行为合同——feature_level 决定预装最小集与能力基线（应用规范 §11.3；Q7：v0 只 `rich` 一档在册，轴=形态档，与 AGENTS.md「移动 rich 首发/穿戴同族/MCU 排除」同轴）；build_type 决定 sideload/调试面收窄；boot.params 键集是内核消费的冻结词表；storage 键决定组装器产物几何与 FS 档位执法。
- **`[product]`（自由面）**：集成者自由——装什么（预装集）、长什么样（品牌）、缺省什么（launcher/调度策略表初值/区域化初值）、换什么（替换声明）。schema 只做结构校验不做行为承诺。

分界依据采 Fuchsia platform/product 双键（Fuchsia platform 键 schema 化进 `platform_settings.rs` 源码执法，经 03 号 §1.2 两源转引）与 AUTOSAR「语义约束随格式同发」（06 号 §1.2 转引）；判据一句话——**该键翻值会不会改变平台侧承诺行为**：会 → platform；只改产品呈现/内容 → product。

### 1.2 顶层形状（v1 全量示例）

```toml
# product.toml（暂名）——一款产品一份；随产品包 .sig 信封分发（Q3）
schema = 1                        # 清单 schema 版本（u32，add-only；V12）

[product]                         # —— 自由面：产品定义 ——
name    = "berry-qemu-rich"       # 产品名（镜像命名 out/<name>.img）
vendor  = "berryos"               # 集成者 lineage（对接 SDK-2 信任账本，Q1/#77）
board   = "qemu-virt"             # 板级引用（板表 = 平台仓数据文件，v0 单值）

[platform]                        # —— 合同面：平台档位（枚举/开关，schema 执法）——
arch          = "aarch64"         # {aarch64, x86_64}（x86_64=最小集）
feature_level = "rich"            # {rich}（v0 唯一在册；骨架 add-only，Q7）
build_type    = "eng"             # {eng, userdebug, user}——user 型收窄见 §1.3
sideload      = false             # user 型下必须缺省或 false（SDK-2 §五姿态继承）

[platform.boot]
kernel = "KERNEL.ELF@sha256:<64hex>"   # 平台工件逐字节锚（度量链对账）
[platform.boot.params]                 # ADR #42 启动配置参数表落点（Q2，§1.6）
# sched_slice_hz = 64                   # 例：只写覆盖值，缺省归上游
# intent_default = "utility"            # 例：六档词表内（ADR #58）

[platform.storage]
image_size_mib       = 96         # 现役值（justfile:1117 `--size-mib 96`）
rootfs_split_mib     = 32         # 现役 --split 32（justfile:376）
min_power_atomicity  = "p0"       # FS 掉电原子性最低档（词表 {p0,p1,p2}，
                                 #   v1 只 p0 可组——p1/p2 词表先立、值域收窄，
                                 #   §2.4；08 号 §6-Q11 收宽先例的采纳形）

[product.apps]                    # —— 自由面：预装集 ——
preset = [                        # rootfs app/ 条目；≤ APP_SLOTS 项（现役 9，
  "app/SETTINGS.bap", "app/FILES.bap", "app/PHOTOS.bap", "app/CAMERA.bap",
  "app/CONTACTS.bap", "app/MMS.bap", "app/BROWSER.bap", "app/APPDEMO.bap",
  "app/APPQUIET.bap"]             #   berry-manifest:120 本文直核）
[product.apps.priv_grants]        # 特权白名单 {app_id → [G2/G3 能力键]}（§11.2）
issued_by = "berryos"             # V8：签发者 lineage 子字段（白名单「谁预置谁
                                 #   负责」的机器对应物，应用规范 §11.4）
# org.oem.pushsvc = ["net:server", "push:send"]     # 例

[product.branding]                # —— 自由面：品牌资源 ——
wallpaper = "assets/wallpaper.byi"
icon_mask = "assets/mask.byi"
[product.branding.tokens]         # 语义 token 数值覆盖（基线 6；可改数值不得删
# accent = 0x3D5AFE               #   token；未知 token 名硬拒）

[product.defaults]                # —— 自由面：缺省与策略初值 ——
launcher = "bin/berry-launcher"   # Q13 过渡值：bin/ 路径 v1 合法；转正 .bap 后
                                 #   收 app/ 路径（随 v2 /apps 同刀）
[product.defaults.scheduler]      # 策略表初值（intent 档位/PM 表/配额）
# latencynice = [0, 4, 8, 12, 16, 20]

[product.defaults.locale]         # —— i18n/区域化缺省（18 号 G1 补空白，§1.5）——
languages           = ["zh-Hans-CN"]   # 语言列表（有序；首项=系统语言）
timezone            = "Asia/Shanghai"  # IANA tz ID；缺省 "UTC"
region              = "CN"             # ISO 3166-1 alpha-2（文化区域）
regulatory_domain   = "CN"             # 监管域初值（同码异义，合规面，§1.5）
calendar            = "gregory"        # v0 唯一在册历法（词表 add-only）
first_day_of_week   = "mon"            # {sun,mon,tue,wed,thu,fri,sat}
hour_cycle          = "h23"            # {h11,h12,h23,h24}（BCP 47 hc）
temperature_unit    = "celsius"        # {celsius, fahrenheit}

[product.services.replace]        # —— 替换声明（接 §2 槽位合同）——
# svc-fs = "app/org-oem-myfs.bap"      # 例；每条携带官方回退引用（V8）：
# svc-fs = { path = "app/org-oem-myfs.bap", fallback = "official" }
```

### 1.5 i18n/区域化键组（18 号 G1 补空白收编；`product.defaults.locale`）

18 号 §2.3 判定：product 清单 17 键无一键涉语言/时区/区域——未知键硬拒下 OEM 对区域差异**零表达力**；且键位归属牵动双键分界，是 #83 的设计输入而非事后补丁（`research/厂商定制化深研/18-完备性审计-覆盖盲区.md:83-85`）。本节即其「键位建议表」的定稿落体。**全组归 product 自由面**（§1.1 判据：区域化初值不改变平台承诺行为，是产品出厂缺省、用户后续可改）；唯一例外候选 = `regulatory_domain`（合规属性，v2 无线电硬件入场时是否升 platform 键 → §7.2 触发器③，18 号 §2.4 建议原样收编）。

### 1.6 与 ADR #42 启动配置参数表的合一形态（Q2 裁定字段级落体）

ADR #42 立法「数字进启动配置参数表不写死」（`docs/架构决策.md:51` 决策行原文），但机制面形态（谁写、内核哪里读）未实现（01 号 §1.1 核，08 号 §2.4 转）。#82 附录二 Q2 裁定合一（`docs/架构决策.md:273`）。本节落字段级形态：

1. **落点**：参数表 = `[platform.boot]` 节 `params` 子表（TOML 形 `[platform.boot.params]`）。**override 语义**：缺省值归上游（编译期常量仍是缺省）、清单只存覆盖值——OEM 不写该键即自然跟随上游新缺省（RFC-0215 structured config 同构，经 08 号 §2.4/12 号 §2.2 转引：https://fuchsia.dev/fuchsia-src/contribute/governance/rfcs/0215_structured_config_parent_overrides ）。
2. **覆盖三档**（Q2 蓝队补强①「安全类参数受限覆盖」的细化）：每词表行携带 `override_class`：
   - `free`（自由覆盖）：调度切片/IntentProfile 缺省档等策略参数；
   - `restricted`（受限覆盖）：thermal/PM 帽类——可覆盖但值域收窄（不得越安全上界；词表行内嵌 [min,max] 或枚举子集）；
   - `locked`（锁死不可覆盖）：KC-P1..P5 kill criteria（ADR #68「不可关闭」同族）、#82 附录二 Q2 点名的安全参数类——组装器对 locked 键的出现即拒（一行理由非零退）。
3. **词表 v1 最小集**（词表本体 add-only、未知键硬拒；新键进词表走 #83 后续升版）：

   | 键 | 类型 | 档 | 缺省归属 | 消费方 |
   |---|---|---|---|---|
   | `sched_slice_hz` | u32 ∈[16,1024] | free | 编译期常量（现役 SLICE_HZ，TCG 注记见 AGENTS 常用命令节） | 内核 sched 早期 |
   | `intent_default` | 六档词表（ADR #58） | free | `utility`（推断：现役缺省档待内核读取刀核 sched/src/policy.rs 实值） | 内核 sched |
   | （restricted/locked 行示例）`thermal_cap_*`/`kc_*` | — | restricted/locked | — | 词表行随 PM/thermal 域刀增补 |

4. **解析面定界**（Q2 蓝队补强②）：params 子表是内核引导路径唯一可读的产品清单片段——组装器序列化为 **INITRD 定址段 `boot/params.bin`（暂名）：定长头（magic+count+总长）+ 定长 TLV 条目（键 id u16 词表化、类型 u8、值定宽）+ 有界循环（count 帽 32）**；内核启动期一次读取、超界即弃段用缺省（loud 诊断行）。fw_cfg 新键为备选机制（08 号 §6-Q3 原开放项），**机制选型（INITRD 段 vs fw_cfg）随内核读取刀裁**——本文定稿推荐 INITRD 段（零新装载机制，消费半径论证见 08 号 §2.4 三半径：INITRD 正是组装器产物，justfile mkimage --initrd 现役链路）。与 V10 的关系：params 段走 INITRD 不经 handoff；但内核引导读取与度量链（V10 meas_root，#82 附录一 ：249）在 boot 早期路径相逢——冲突即 §7.2 触发器②。
5. **治理半径**：params 词表与 platform 键同一 L2 执法面（Q2 裁定「分两套必漂移」）；词表宿主 v1 = 本节表（立法即词表），生成器实装后收编进 slots.toml 单源族（§2.2）。

### 1.7 build_type 收窄面与 schema 升级纪律

- **收窄面**（W7，v2 成文）：v1 立法面仅 sideload（user 型必 false）；userdebug/user 的调试面收窄清单（哪些诊断面/开发工具键被禁）随首个 user 型镜像需求立法——Fuchsia `platform_settings.rs` 收窄先例可参照但键集须本土化（08 号 §6-Q6 原样保留为 §7.3 开放问题④）。
- **schema 升级**：`schema = 1` 起步；升版唯一方向 add-only（加键/加枚举值），任何删键/改义走章程 §三废弃纪律（N=3 窗口）；Q7 复核机制——每个新档位值入场时，已发档位的语义冻结复核一次（12 号 §2.7 硬化进裁定）。

## 二、槽位合同四件套规范

### 2.1 四件套结构定义

每个可替换槽位一份合同，合同 = 四件套（08 号 §1.1 下沉，#82 裁决「任何槽位对 OEM 开放的充分条件 = 四件套全绿」）：

| 件 | 内容 | 机器形态 |
|---|---|---|
| ① 能力清单 | 该槽位被授予的 handle 全集（设备能力/MMIO 窗/端点/资源池）+ 授能路径（谁铸、何时授、如何回收） | 合同 `[capabilities]` 节；对照驱动模型 `[hw]` 节（`docs/驱动模型设计-v1.0.md:25-41` 本文直核）与 svcmgr gift 链现役实践 |
| ② wire op 表 | 该槽位必须实现的 op 全集：op 号、请求/应答字节布局、随行 handle 数、错误码域、per-interface version | 从协议 crate 单源对账（生成器实装前手写+断言）；L1 add-only 纪律绑定 |
| ③ 语义合同 | 时延义务（如有）/错误码语义/失败隔离义务/并发模型/帽常量（不得收窄） | 合同 `[semantics]` 节；conformance 用例的断言来源 |
| ④ conformance 用例集 | 每合同一组：合法 op 序列、非法 op 拒绝、帽执法、语义断言 | 用例 id 进合同；实现进 BCTS L1（冻结件回放制，#84；v0 门禁宿主=现役 just 配方树，Q4） |

为什么是四件（推断，锚 06 号 §1.2/§1.5）：「机器可校验语法 + 机器可校验语义 + 任意工具可消费」是合同区别于惯例的最低结构（AUTOSAR 三件套）；BerryOS 替换发生在运行期服务进程，语义漂移风险更高，故多出第四件 conformance——**在 conformance 用例存在之前，任何槽位不得实际对 OEM 开放**（08 号 §7.2 设计前提，Q8 动态开放序的结构根据）。

### 2.2 slots.toml 单源设想（照 abi.toml 先例；生成器降 B 档如实记）

**单源** = `tools/slots.toml`（暂名；或每槽位一文件 `tools/slots/<slot-id>.toml`，取舍见 §7.3-①），生成四面：

```
tools/slots.toml（单源，手改这里）
  ├── ① docs/槽位合同-<id>.md        —— L2 承诺面文档（人读+评审）
  ├── ② 协议 crate 断言              —— 每槽位 const assert/锚点（钉 op 号与帽常量）
  ├── ③ conformance 用例骨架         —— BCTS L1 用例枚举骨架（id/分组/断言点）
  └── ④ BCTS 覆盖率清单条目          —— PlaSA 同构：每槽位 op 全表（未测面报表数据源）
```

先例（事实）：`tools/abi.toml:1-27` 五面生成 + `just abi-check` 逐字节守卫挂 build/smoke 前置（本文直核头注：「五面同源 ⇒ 漂移按构造不可能」；改 ABI 流程 = 改本文件 → `just abi-gen` → 提交）。**如实记（#82 附录一 V14 终态）**：四面**生成器降 B 档**——触发条件 = 第三个槽位立项；v0/v1 两实例合同**手写**（本文 §2.4/§2.5 即手写合同 v0 全文，届时可平移迁入生成器）；语义合同（③件）本就无法从 crate 单源生成，须手写 + conformance 执法——「合同四面里有一面半是人写的」这个事实使 slots.toml ≠ 完全机器执法，宣称「合同机器可校验」时须限定为①②件 + ③件枚举字段（08 号 §7.5 诚实面照录）。`just slots-check`（暂名）挂 build 前置随生成器落地。

### 2.3 L1/L2 归档位（V14 归档位随本节落册）

对照章程 §一分级（L0–L4）与 07 号 §6-9 分类执法链：

- **②件（wire op 表）→ L1**：wire 协议 add-only + per-interface version（guiproto 现役 `VER_*` 常量族四域全=1，`user/berry-guiproto/src/lib.rs:319-325` 本文直核）——本就在册，合同把散装 const 升格为有承诺文档的合同面。
- **①③④件（能力/语义/conformance）→ L2**：公开库 API 同级承诺 + N=3 废弃窗口；语义合同变更（如掉电原子性档位定义改动）走章程 §三。
- **未进合同的槽位内部细节 → L3/L4 零承诺**：BCTS 不测（04 号 §4.2 原则 1 防伪契约）。

> 归档位立法句（供 #83 落册刀抄送章程 §一注记，P1-1 修法位 = `docs/API治理章程-v1.0.md` §一表下）：「槽位合同②件（wire op 表）归 L1；①③④件（能力清单/语义合同/conformance 用例集）归 L2（ADR #82 V14；两实例手写合同 v0 随 #83 设计文档 §2）」。

### 2.4 实例一：`svc-fs`（fsmgr 位）合同 v1

现役事实基座：fsmgr = RAM-fs + FAT12 经 vblk 的用户态服务；协议 = berry-fsproto 10 op 严格串行 RPC（`user/berry-fsproto/src/lib.rs:70-88` op 常量段、:91-103 ST_* 六值域，本文直核）；消费者 = bsh/fsclient/libc（端点经 svcmgr gift[3] 直递，svcmgr 预拉段 fsmgr 现势 :1305 起，08 号 §4.1 行号表）。

```toml
[slot.svc-fs]                       # 槽位 id（命名规范 §2.6）
title     = "文件系统服务（fsmgr 位）"
interface = "berry-fsproto"         # 协议 crate = ②件单源指向
ver_min   = 1
consumers = ["bsh", "berry-fsclient", "appd(v2)", "launcher"]

[slot.svc-fs.capabilities]          # ① 能力清单（现役 svcmgr 预拉段成文化）
blk_endpoint = "optional"           # vblk 客户端端点（gift[3]；缺席 = RAM-only 降级）
console      = "required"           # stdout（诊断行）
mmio         = "forbidden"          # FS 服务不得持 MMIO 窗——块设备归 drv.disk 位
appdata_tree = "required(v2)"       # $appdata handle 授予链（ADR #45，v2 消费）

[slot.svc-fs.ops]                   # ② wire op 表（10 op 全实现，一个不可少）
1..10 = "PUT/TRUNC/GET/LIST/LOOKUP/MKDIR/UNLINK/READDIR/STAT/STATFS（fsproto:70-88）"

[slot.svc-fs.semantics]             # ③ 语义合同
rpc_model     = "strict-serial"     # 一请求一应答、队列深 1、无乱序死锁面
error_domain  = "ST_OK=0..ST_EXISTS=5（fsproto:91-103）"
caps_frozen   = "CHUNK=192/NAME_MAX=48/PATH_MAX=128/PATH_DEPTH_MAX=8/FILE_SIZE_MAX=16KiB/FILE_COUNT_MAX=9"
                                    # 帽=合同下限，替换实现不得收窄（可抬上限）
mount_semantics = "single-volume"   # 单卷挂载 + 根不可写（读面三 op 白名单空路径=根寻址）
statfs_honest  = true               # 卷级几何真值义务（21B 应答五字段为真值非估计）
power_atomicity = "declared-level"  # 掉电原子性三档：p0=none（FAT12 MVP 现役）/p1=metadata
                                    #   （掉电后卷必可挂载）/p2=data（已应答写存活）；
                                    #   实现自声明、不得低于镜像清单 min_power_atomicity
                                    #   （组装期执法，零运行时成本；可加 p3 不改 p0-p2 义）
failure_isolation = "degrade-not-halt"   # 服务崩 → 消费者端点 DEAD → 降级（fs 缺席
                                    #   = bsh 三元 gift「fs not available」不死 shell）

[slot.svc-fs.conformance]           # ④ 用例集（id 骨架；实现进 BCTS L1，#84）
suite = "bcts-l1-fsproto-v1"
cases = ["roundtrip-all-10-ops", "illegal-op-reject", "cap-enforcement",
         "blk-absent-degrade", "power-atomicity-level"]
```

合同要钉死的三个语义面：**op 全集不可裁剪**（增量自由度只有加新 op（L1 add-only，自 11 起编号）与实现质量）；**挂载语义三条**（单卷模型 v1/根不可写/STATFS 真值义务；多卷=v2 提案接 namespace v3，`docs/IPC设计-v1.0.md:56-63`）；**掉电原子性档位**（现役 = p0 无保证，诚实披露非缺陷——「FAT12 写路径无 journal」为推断（08 号待核实项：立法前须对 `user/bins/fsmgr` 写路径逐行核实）；现在立法的理由：档位枚举 add-only，现代 FS 替换实现自带 p1/p2 时无需改合同）。

### 2.5 实例二：`drv-display-backend`（HDI 位）合同 v1

现役事实基座：HDI 域 = guiproto 四 op（**系列惯称「三口 reg_vblank/prepare/commit」，wire 实为四 op**：REG_VBLANK=0x40/VBLANK_WAIT=0x41/PREPARE=0x42/COMMIT=0x43，`user/berry-guiproto/src/lib.rs:80-86` 本文直核；ADR #50 裁决行的「三口」为立法时惯称，合同以源码四 op 为准）；第一实现 = guifbd 内 ramfb 软 vsync 退化形（SOFT_VSYNC_NS=16_666_666≈60Hz，`user/bins/guifbd/src/main.rs:78` 本文直核；「hdi 域四 op 退化形（软 vsync；wire 零改动）」经 08 号转引）；第二后端 virtio-gpu 在排（ADR #51 后端序列）；ADR #50 立法「换实现不换契约」「像素格式烧进常量 = 移植性死刑禁」。

```toml
[slot.drv-display-backend]
title     = "显示驱动后端（HDI 位）"
interface = "berry-guiproto/hdi"    # hdi 域（op 0x40..0x43）
ver_min   = 1                       # VER_HDI = 1（guiproto:323）
consumers = ["guifbd(合成器)", "gui-wmd(中继,ADR #61)"]

[slot.drv-display-backend.capabilities]
mmio_window = "board-dependent"     # 板级 MMIO 窗 VMO（virtio-gpu 需要；ramfb 不需要）
buffer_vmos = "required"            # PREPARE 随行 1 buffer VMO handle
event       = "required"            # REG_VBLANK 随行 1 Event handle
console     = "forbidden"           # 后端不持 console——诊断走合成器

[slot.drv-display-backend.ops]      # ② wire op 表（4 op 全实现）
0x40 = "REG_VBLANK  req 4B + 1 Event handle → rep 1B"
0x41 = "VBLANK_WAIT req 4B（阻塞）→ rep 16B [st][r][seq u32][ts_ns u64]"
0x42 = "PREPARE     req 20B + 1 buffer VMO → rep 4B [st][slot u8]（slot<2）"
0x43 = "COMMIT      req 12B [slot][r][target_ns u64] → rep 1B"

[slot.drv-display-backend.semantics]
vsync_cadence   = "declared"        # 周期自声明（合同义务不是「必须 60Hz」）
seq_monotonic   = true              # ① seq 严格单调增，每 vsync 恰 +1
ts_honest       = true              # ② ts_ns=名义 vsync 点（滞后追赶跳过已过点，不补偿
                                    #   积压——不得伪造未来时刻）
signal_on_vsync = "edge"            # ③ Event 每 vsync 沿 signal 一次；无 vsync 不虚假
                                    #   signal（零唤醒不变量）
format_negotiation = "getinfo-bits + prepare-value"
                # 协商在 present 域 GETINFO format_bits 位域；hdi PREPARE 携带值非位域，
                #   不在协商集 → ST_UNSUPPORTED。合同钉死：后端必须至少支持 XRGB8888
                #   （ramfb fmt=1 基线）；其余格式可选声明（扩充零合同变更）
prepare_lifecycle = "server-exclusive"   # PREPARE→COMMIT 间 buffer 采样权归服务端
tear_free       = "required"        # COMMIT 原子换帧（真后端）或整帧拷贝（软后端）
failure_isolation = "degrade-not-halt"   # 后端崩 → DEAD 降级，不得打穿内核（ADR #12/#46）

[slot.drv-display-backend.conformance]
suite = "bcts-l1-hdi-v1"
cases = ["reg-vblank-edge-signal", "vblank-wait-seq-monotonic", "prepare-slot-cap",
         "prepare-format-unsupported", "commit-atomic-present"]
```

钉「诚实」而非「频率」的理由（推断，锚 ADR #53）：把「必须 60Hz」写进合同会排除软实现与 59.94/90/120Hz 真面板；钉三条不变量（seq 单调/ts 诚实/沿信号），任何频率实现合法而消费侧假设被保护——第一实现即退化形是合同的资产：软 vsync 已跑通「wire 四 op 与 vsync 物理源解耦」，virtio-gpu 接入时合同零改动（#50「换实现不换契约」的机制兑现路径）。

### 2.6 共性钉子与命名规范（含 X1 例外动作）

| 钉子 | svc-fs | 显示后端 | 执法点 |
|---|---|---|---|
| op 全集不可裁剪 | 10 op 全实现 | 4 op 全实现 | conformance roundtrip + 组装期 version 对账 |
| 帽常量不得收窄 | CHUNK 等 6 顶 | HDI_SLOTS_MAX=2 | 协议 crate 断言（生成物②） |

| 实现自声明档位 | 掉电原子性 p0-p2 | vsync 周期 | 组装期清单校验（步②） |
| 能力面最小 + 禁持清单 | MMIO 禁持 | console 禁持 | 授能链（svcmgr gift / devmgr v2） |

**槽位 id 命名规范与 `/svc` 路径映射（X1 例外动作，一行立法）**：id = `<层>-<名>` 连字符串（层 ∈ {svc, drv, app}；如 `svc-fs`、`drv-display-backend`）；**映射规则 = `/svc/<名>`**（`svc-fs` ↔ `/svc/fs`，`docs/IPC设计-v1.0.md:58` 现役规划形态即其未来形）——day-one 钉死，namespace v3 落地时端点名直译为路径，零重命名。只钉名不建机制（X1 边界原文）。

### 6.1 双件制与版本轨让位总形（裁定 ①②）

描述轨按**信息主权**分两子面（23 号 §2.2 案 C「吸收让位」——归并发生在描述层内部：平台子面 × 产品子面；19 号 §1.5 三层模型不动）：

- **平台子面 = version VMO 轨**（版本身份单源真值）：`kernel/src/sysver.rs` 编译期 `env!/cfg!` 常量成像（BVER magic/hdr_ver/level/semver/flags/git-ident/rustc，布局合同 :9–:21，字符串段 ≤128B 编译期 assert）+ boot fb GOP 相位经 svcmgr 表第 9 插 `0x0001_0009` READ 只读交付（权限在 handle 不在对象、内核不留柄）+ rootfs 根条目 `.berryver` 构建烙印（`tools/mkcpio.py` :275–:291，单行 `<git-describe>|level <N>|v<semver>`，构建期生成不走 manifest 表）。**三方联动**：manifest PR ≡ VMO level ≡ .berryver level（PR 列缺省单源读 `tools/abi.toml [platform].level`，`tools/mkimage.py` :150–:174——CLI 覆盖位已删除断链注入口封死）= 版本事实的机器对账闭环。管「平台是什么版本」——VMO 在禁改面内编译期成像，OEM 无任何单改点。
- **产品子面 = `sys/info` 静态件**（§6.2 键位表）：组装器（V13 管线步⑧生成步）从产品清单 + 板表 + locale 键生成，住系统树随槽整树验签，消费 = 文件读——零新 IPC、零新常驻服务、零 syscall 增量（nr_ceiling=45 预算不动，07 号 §5.1 纪律）。管「这台设备是什么产品」。

分界判据（一句话）：**平台编译面事实进 VMO——内核是禁改面同二进制，OEM 产品异构它结构性不知道；产品组装面事实进 `sys/info`——恰是内核编译期成像管不到的**。据此**版本族键（platform_revision≡level/semver/构建标识）不进 `sys/info` 键表**（裁定 ①）：VMO 轨已在树、对账已机器化（`eco: VER` 哨兵——svcmgr ver_check 读 VMO 前 128B 与 `.berryver` 烙印三元组对拍，全等打 `ok`/任一不等打 `mix`，`user/bins/svcmgr/src/main.rs` :684–:687/:2335；`tools/smoke-image.sh` :458–:473 双门：`eco: VER ok` 在席 + `mix` 命中即红）——`sys/info` 复制版本键 = 制造第四源（22 号 A2），一事实一归属。诊断消费读 `.berryver` 同样可达（FINGERPRINT「勿解析」纪律——版本键本就「可见·不推荐」）。

### 6.3 uname 值源单源化（旧债修复登记，裁定 ③——**随本升版同刀已修，2026-11-11**）

- **现行犯**（22 号 A2 实锤）：`user/berry-libc/src/sys.rs` :293 `UNAME_RELEASE = "0.1"` 硬编码，vs 根 workspace 已 v0.2.0（根 `Cargo.toml` :7 `[workspace.package].version` + git tag `v0.2.0` 两源核）——现役 app 面版本查询已漂移一个版本；libc-uname 是 VMO/.berryver 之外的第三路查询面，「版本查询面无单源消费纪律」病的现行犯。
- **修法（已落）**：**构建期烙印**——`option_env!("BERRY_UNAME_RELEASE")` → const（cargo env → 静态常量，零运行时面、零初始化序问题；kernel `sysver.rs` :43–:46 `option_env!` match 同款先例）；未注入时回退根 `[workspace.package].version` 现值 `"0.2.0"`（berry-libc 住 user/ 独立 workspace 无根版本常量可继承，自身 `CARGO_PKG_VERSION`=0.1.0 是 crate 版本非系统版本，不可用）。**取舍记录**：运行时读 rootfs `.berryver` 被否——libc 常量面引入文件 IO 依赖（uname 须在任何 fs 可用前可用）。**与 rootfs 烙印同源同值**：`.berryver` semver 段读根 `Cargo.toml [workspace.package].version`（`tools/mkcpio.py` :326 `_berryver_sources` 每次归档现取），uname 回退值 = 同文件同键现值。**两源对拍一致性 = 推断，以构建链为证**：同文件同窗构建同值（2026-11-11 实测：musl target rlib 烙印 `0.2.0` = `.berryver` 现值 semver 段 `v0.2.0`；`BERRY_UNAME_RELEASE` 注入实测可覆盖）；跨窗混合构建由 `eco: VER mix` 哨兵拦 VMO × `.berryver` 面。
- **防漂移缺口如实记**：回退值是根 workspace 版本的**手工镜像**——根 workspace 升版时回退值随 `.berryver` 同笔更新（或构建链注入 `BERRY_UNAME_RELEASE` 覆盖）；VER 哨兵三元组（VMO × `.berryver`）**不含 uname 面**，uname 漂移无机器执法——升版同笔义务 + 缺口登记在案（SDK-2 §四「无手写副本」纪律对版本查询面的适用，22 号 A2 修法句的落体）。

### 6.4 探测轨 = 语义预留位（v1 不宣称，裁定 ④）
