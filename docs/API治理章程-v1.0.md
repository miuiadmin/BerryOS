# API 治理章程 v1.0

> **性质**：BerryOS 全部对外 API 面的治理总纲（立法档）。
> **溯源**：2026-11-07 用户批「落成设计文档」——依据 `research/SDK-03-系统API历史教训与一次设计定谳-v1.0.md` §二/§六 A+D 组；史实论证不重复，见 SDK-03。
> **状态**：设计定稿 · 未开工 · 预 ADR（落册点见 §八）——执法基建随 SDK-2 落地，落地前本章程为评审依据。
> **效力范围**：syscall（abi.toml）/ 服务 wire 协议 / 公开库 API（berry-sys/libc/gfx/ui 及协议 crate 族）/ 工具 CLI 与输出（mkapp/berryctl/bsh）。

## 一、兼容承诺分级（唯一口径）

| 级 | 面 | 承诺 | 演进方式 |
|---|---|---|---|
| L0 | 37 syscall C-ABI（abi.toml 单源；2026-11-10 勘误：原「35」为成文快照口径漂移，单源以 tools/abi.toml 为准——ADR #82 联动勘误） | **永久冻结**，永不破坏 | 只加号不回收（ADR #55 两冻结面之一） |
| L1 | 服务 wire 协议 | add-only + per-interface version | 字段只加不改义；msg_type 只加新号（ADR #54/#59） |
| L2 | 公开库 API（crates.io 发布族） | semver + **保 N 版废弃窗口**（N=3 起步，见 §三） | 废弃须走 §三全流程 |
| L3 | 系统内部 API（crate 私有/跨 crate pub(crate)） | **明写不保证**，零承诺 | 自由 |
| L4 | 工具输出/文档措辞 | 无兼容承诺，但变更须过 §六 api-diff 通告 | 「承诺/不承诺」二分标注（§五） |

冻结面 = L0+L1（ADR #55 两冻结面）。**勿升格**：Rust crate 源码层不冻结
（iOS 三份合同课：只冻二进制 ABI 层，源码层靠 semver 演化——SDK-03 原则 5）。

## 二、行为变更双轨制（细则 = SDK-2-双轨与演化纪律设计）

1. **兼容语义轨**：后台/省电策略、存储与权限语义、调度默认值类变更，
   一律挂 manifest `[compat].target` 分档生效（低报=旧语义）。
2. **安全隐私轨**：安全/隐私修复对**所有已装载包即时生效，不设 target 豁免**
   ——低报 target ≠ 永久豁免安全修复。
3. **渠道杠杆**：分发面握 target 门槛（新包上架门槛随年度 SDK 抬升）——
   依赖分发链基建（SDK-2-分发与签名链设计）。

## 三、废弃纪律（L2 面全流程）

1. **登记双版本**：废弃 API 必须同时登记「废弃于 X / 移除于 Y」两个版本号
   + 官方迁移文档。**无移除版本的 deprecation 不许合入**（CI 挡）。
2. **移除门控**：移除按 ADR #56 三值版本域（min/target/compile）生效——
   target 不达标的旧包**工具期即拒**（mkapp 编译期执法），兼容问题永不进运行时。
3. **静态链接加重税**：废弃 API 编进已发布 .bap 即成 OS 永不可回收的静态面
   ——移除窗口必须关在编译期，无运行时兼容垫片。
4. **保留窗口**：废弃到移除 ≥N 个 minor 版（N=3 起步；HDI 先例留 4 版，取 3
   因生态为零可紧后放宽，放宽易收紧难）。
5. **例外面**：abi.toml syscall（L0）不适用废弃——只加不删；wire（L1）op
   语义面按同流程走 per-interface version。

## 四、三条硬纪律（违者评审即挡）

1. **v1 只有一个应用模型**（.bap/mkapp/appd）。任何换代必须自带自动迁移
   路径（编译期或工具链级）；做不到迁移就不许换代（Windows 重写循环病）。
2. **永不引入第二一等语言公民**。全 Rust 单语言是先天优势；未来任何语言
   绑定一律为生成物、非第一公民；POSIX 兼容层保持薄适配、不得长成平行世界。
3. **禁静默重定向、禁静默降级成功**。能力缺失即显式失败（可测错误码）；
   不造「技术上可达、政策上封禁」的灰色 API 层——边界即能力，机器可查。

## 五、承诺/不承诺二分（Hyrum 纪律）

契约文档必须二分标注。**默认不承诺面**（防依赖，变更不构成 breaking）：
错误码→errno 映射次序、TLV 拒绝报错文本、调度延迟形态、遥测字段次序、
QEMU 仿真行为、工具输出的人类可读措辞。对不承诺面的防依赖措施：
机器消费一律走结构化出口（--json/schema 导出，见 SDK-2-错误域与机器可读面设计）。

## 六、变更流程与 CI 执法

1. 任何 L0–L2 面变更 PR 必附：**api-diff**（abi-check/协议 crate 黄金字节对比）
   + ChangeLog 条目 + （涉废弃）迁移文档链接 + （涉行为变更）生效轨声明。
2. CI 门禁：abi-check 三面逐字节 / api-diff 非空必须有人工批复标记 /
   废弃无移除版本即挡 / 「全类别资源原语」grep 守卫（SDK-2-资源与能力模型）。
3. **仅成文不执法 = 没有**：本章程每一条都必须对应可执行门禁或评审检查项，
   落地清单随 SDK-2 开刀排期。

## 七、新 API 归属判据（原语 vs 用例）

每个新 API 入册前答一问：**这是能力原语还是用例便利？**
原语 → 平台/协议面（按 L0–L2 分级）；用例 → 独立 semver 版本化库
（berry-ui 式），库命名空间与平台命名空间从第一天分离（Fragment 事故防，
ADR #51 分层既定）。判不定 → 先入库不放平台。
