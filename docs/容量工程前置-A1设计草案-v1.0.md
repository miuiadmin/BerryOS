三源装载路径现状（`kernel/src/main.rs:52-68` `RootfsBuf`）：

- **路径 A fw_cfg 整读**：逐 selector 读入堆 `Vec` → `RootfsBuf::Owned`（**单块连续**——冷启 RAM 完整属侥幸可达，main.rs:47 注释原话）；
- **路径 B handoff/dtb 借片**：`RootfsBuf::Borrowed` 零拷贝直用固件/DTB 钉住的 DRAM 区（碎片免疫）；
- **路径 C VMO 逐页 commit**：`kernel/src/vmo.rs:3-4`——commit 立即逐页出帧清零，**物理不连续无碍**（C-2c「两路碎片免疫」之一；eager VMO commit 即全量——demand 页 G4-1 起另路供给）。

## §2 三堵墙：40MB+ blob 为什么现在装不进

1. **帽墙**：五处 32MiB 级同口径（#1/#2/#4 + MAX_ORDER 恰 32MiB）——80-120MB 静态全族直接 -ENOMEM / boot 拒收。
2. **地形墙**（结构性，最硬）：内核堆大对象 = 单块连续 buddy 块（§1 #8）。40MB = order 15 > MAX_ORDER 13 → **结构性不可分配**，与碎片无关；即便 21.3MiB（order 13）在 EFI 地形（固件保留区 + blob 自占）也已实踩不可得（C-2c smoke-image boot panic 实录）。**升 MAX_ORDER 治不了这墙**——只要「大 blob = 堆单块」的形态不变，升到 order 15 只是换个更大的骰子（冷启侥幸 ≠ 结构保证）。
3. **装载墙**：rootfs 递送 = 单 cpio 单 blob 单文件（fw_cfg 具名文件 / handoff 单 `init_blob(pa,len)`）；BerryBoot FAT 整档读入也是单缓冲假设。

**关键洞察（本稿设计轴）**：`Vmo::commit` 是**逐页**出帧（每页 order-0 分配），**根本不受 MAX_ORDER 约束**——受约束的只是「堆单块 `Vec`」形态（fw_cfg 整读、boot 期大缓冲）。所以 A1 的正解不是升阶，而是**把大 blob 的装载形态从「堆单块」迁到「VMO 逐页」**，帽随之分家（§3）。

## §3 设计：帽分家 + 装载路径迁移

### 3.1 帽分家（各帽不再同口径联动）

| 常量 | 裁定候选 | 理由 |
|------|----------|------|
| `VMO_MAX_SIZE` | 32 → **128MiB** | blob 装载新家（V8 静态 80-120MB + 余量）；帽的本质 = 防巨 size 分配 abort，而 VMO 内部逐页 commit 无单块压力 → 升帽低风险。`vmo_cap` 边界测试随值平移（bench.rs:423 面②） |
| `ROOTFS_MAX` | 语义拆分：**单卷帽 32MiB 不动** + 新增**总量帽 128MiB** | 单卷帽继续护住「暂存缓冲 = 堆单块」的面（§3.3 分卷后每卷仍走堆暂存）；总量帽才对齐 rootfs 整体 |
| `MAX_ORDER` | **不动（13）** | 单块需求面随装载迁移逐步消失；升阶只放大 buddy 元数据与碎片骰子（K-1 教训：布局敏感指标别再掷骰） |
| BerryBoot init 帽 | 32MiB → **单段帽**（随 handoff 分段升级，§3.3；数值 8-32MiB 实施期定标） | 与 handoff blob 描述符数组配套 |
| 盘容 | 48 → **96MiB**（rootfs 40MB+ 时；`mkimage.py` 已参数化，justfile 传参即可） | 盘容是产链参数非内核常量，随 rootfs 实长走 |

### 3.2 大 blob 装载的新形态：VMO 逐页拼装

内核侧目标形态（三源归一消费面不变——`ROOTFS ok` + `ROOTFS vmo=` 行照打）：

```
源（fw_cfg 具名文件 ×N / handoff 分段数组）        内核                          用户态消费
┌─────────────────────────────┐     ┌──────────────────────┐     ┌──────────────────┐
│ 卷0 ≤32MiB ─┐               │     │ 逐卷：堆暂存 ≤8MiB    │     │                  │
│ 卷1 ≤32MiB ─┼─ 顺序分块读 ──┼──▶  │  chunk → vmo_write ──┼──▶  │ 单一 VMO 视图     │
│ 卷N ≤32MiB ─┘               │     │ （顺序 offset 递增）  │     │（berry-exec/     │
└─────────────────────────────┘     └──────────────────────┘     │  svcmgr 零改动）  │
                                    堆峰值 = 单 chunk（8MiB）     └──────────────────┘
                                    非全 blob —— 地形免疫
```

- **fw_cfg 路**：data 口顺序读天然支持续读（selector 选定后 offset 持续推进）——按 chunk（≤8MiB）循环「读 chunk → `vmo_write` 到递增 offset → 清 chunk 复用」，堆峰值 = 单 chunk。多卷 = 多具名文件 `opt/berry/rootfs0..N`（fw_cfg FILE_DIR 自描述，无新机制）。
- **handoff 路**：`BerryHandoff` v0 单 `(init_pa, init_len)` → **v1 加分段描述符数组**（pa/len 列表，BerryBoot `AllocatePages` 逐段申请——每段 ≤8-32MiB，绕开「固件给不出 40MB 连续段」的地形风险）。`HANDOFF_VERSION` 0→1 版本门控，内核 v1 缺席回退 v0 语义（boot 协议是仓内版本化面，非 abi.toml 冻结面——不触保留门 C）。内核侧逐段借片 → 逐页拷入 VMO（借片段只读、生命期随 handoff 页——与现 `Borrowed` 同纪律）。
- **dtb 路维持现状**（真机 Linux 协议面，v1 QEMU 不达）。

### 3.2.1 A1-3b 实施预稿：handoff v1 + fw_cfg 多卷（2026-10-29，基于 HEAD d82ea00 三源实读）

前置事实（kernel/src/handoff.rs · arch/aarch64/src/fwcfg.rs · bootloader/berryboot/app/src/lib.rs:898-1009 实读）：

- `BerryHandoff` v0 = 112B 冻结（双镜像 const assert 执法）；`probe` 拒 version≠HANDOFF_VERSION → **v1 必须同刀双侧**（§3.2 已裁）；旧内核见 v1 handoff = 不认领 → ROOTFS absent 降级非炸——fail-safe 由现 probe 语义天然保证。
- fwcfg API 现面 = `find_file`（FILE_DIR 逐名）+ `read_to`（**恰全长整读**，`buf.len()==size` 强制）——无续读面；data 口 = selector 选定后顺序流（无 seek；discard 前进 O(n²) 禁）。既有探测具名项（rt/soak）零关联。
- BerryBoot init 段 = SFS Open INITRD.BIN → GetInfo → 帽 32MiB → AllocatePages **单块** → 循环 Read → `init_blob_*`（@80/@88）。**盘面零改动**：INITRD.BIN 仍是单文件，分段只是内存分配侧形态（smoke-image 盘 canon 零漂移）。

**handoff v1 布局（128B 头 + 同页描述符数组）**：

```
@0..@111   v0 前缀逐字段不动（v0 读者按 version 分派，不读后缀）
@112  init_segs_pa:    u64   描述符数组 PA（= handoff 页内 @128 自相对；0=无）
@120  init_segs_count: u32   段数（0=无 INITRD；1..=32 合法）
@124  _r1:             u32   保留零
@128  描述符数组（随 handoff 同页）：N × { pa: u64, len: u64 }（16B/段，8 对齐）
```

- 版本语义：version=1 时 `init_blob_*`（@80/@88）**置零不读**——分段数组是唯一 init 事实源；version=0 恒旧 112B 形。**双向兼容**：新内核认 version≤1（v0 走 `init_blob_*` 原路——旧装载器照跑）；旧内核见 v1 → absent 降级（loud，定向验）。
- 段约束：pa 4KiB 对齐（AllocatePages 出品）+ len>0 + 段区落 [RAM_BASE,RAM_TOP) + Σlen ≤ 总量帽 128MiB + count ≤ 32（32×16B+128B=640B < 4KiB——handoff 单页自含，无第二块分配）。
- BerryBoot 装载改造：INITRD.BIN 单文件**目标段 8MiB** 循环「AllocatePages(EfiLoaderData) → 循环 Read 填满段 → 记描述符」；alloc 失败折半重试（8→4→2→1MiB 地板——固件碎片地形免疫，§2 地形墙的装载器侧执法）；EOF 即止。终段 GetMemoryMap 语义不变（各段页进图非 Conventional → V-1b pass2 reserve 自动保，原理直迁）。

**fw_cfg 多卷面（内核侧）**：

- 发现序：`opt/berry/rootfs0..9`（单数字后缀即够——10 卷 × 单卷帽 32MiB ≫ 总量帽 128MiB，帽先绑定；`ROOTFS_NAME` 同位扩 `rootfs_name(i)` 单一事实源）。**优先序：rootfs0 在位 → 多卷路；否则 `opt/berry/rootfs`（旧名单）→ 单卷整读原路**。两名并存在位 = rootfs0 优先（多卷是权威形态，旧名忽略）。单卷帽 32MiB、总量帽 128MiB——§3.1 帽分家的执法点。
- 顺序分块读：fwcfg 新增顺序续读面（`read_to` 整读保持不动）；单次 selector 选定后 data 口天然顺序推进——**逐 chunk（4MiB，order 10）读出 → `vmo_write(offset 递增)`**，堆峰值 = 单 chunk。
- **重装恒等对拍入冒烟**（§5 风险执法点）：chunked 读出全量 == 整读基准（同 entry 双路或宿主侧 cmp）。

**内核消费面（三源归一口径不变）**：拼装终点 = 单一 VMO（Σ ≤ 128MiB，A1-2 帽内）→ cpio walk 视图不变（berry-exec/svcmgr 零改动）；`ROOTFS ok src=` / `ROOTFS vmo=` 行文案零漂移。handoff 路源已在 DRAM 高半别名，逐 chunk 暂存可缩到 64KiB 量级（更低调堆峰）。

**justfile/smoke 挂线**：build-user 产链 mkcpio `--split 32`（rootfs 现值 ≈27.9MiB → 恰 1 卷，与单档字节恒等——行为等价过渡）；run-rootfs / smoke rootfs 相传 `rootfs0..N` 多 `-fw_cfg`（多卷主路执法）；**旧名单回退执法**保留一 boot 传 `opt/berry/rootfs` 单名（单卷整读原路不死）；smoke-image 零盘面改动。

**验收线（A1-3 整刀）**：40MB+ blob（尾部放大件凑量）经 fw_cfg 多卷与 handoff v1 两路各跑通 `ROOTFS ok` + 生态接续 + 重装恒等对拍 + 旧名单回退 boot + v0/v1 双向混跑（新内核×v0 装载器照跑 / 旧内核×v1 → absent 降级）+ smoke canon 零漂移。

### 3.3 分卷产链（mkcpio 侧）

`tools/mkcpio.py --split <MiB>`：单 rootfs.cpio → `rootfs0.cpio/rootfs1.cpio/…`（**卷边界只切字节流，不做条目对齐**——cpio walk 是流式格式，TRAILER!!! 只在末卷；berry-exec `cpio_names`/svcmgr 消费面在「内核拼装成单一 VMO」之后，**用户态零改动**）。`justfile` run-rootfs/smoke 相随之传多 fw_cfg 文件。

## §5 风险与 kill criteria

- **VMO 逐页 commit 的 boot 期成本**：40MB = 10240 页 ×（出帧 + 清零 + 映射）。TCG 下 boot 走查本就分钟级，增量可 absorbed；但若 A1-3 实测拼装 >60s（TCG）→ 改 chunk 清零惰化（commit 时只出帧不清零、写入页随写清——需核 vmo.rs 清零语义是否被消费者依赖，C-2c「新页先清零再用」纪律对齐）。
- **fw_cfg 顺序续读假设**：QEMU fw_cfg data 口 offset 推进是行为事实（G-eco 实证），非规范承诺——A1-3 首跑需验证 chunked 读出字节与整读一致（对拍断言入冒烟）。
- **handoff v1 兼容面**：BerryBoot 与内核同仓同刀提交，无跨版本混跑；v0 回退分支保留一档（`HANDOFF_VERSION` 门控天然）。
- **kill**：若 A1-3 两路（fw_cfg/handoff）拼装在地形实验中均无法稳定（如 fw_cfg chunked 读实测不成立且 handoff 分段被固件分配器碎片卡死）→ 降级方案 = rootfs 瘦身线（.bap 资源外置盘卷、按需加载）替代单 blob 增长——此为 A5/A6 排刀重议信号，非本卡内硬扛。
- **不做什么**：不升 MAX_ORDER（§2 论证）；不做 demand paging（ADR #20 v1 排除，A3 才开范围盒）；不做 cpio 条目级分卷（流式切割已够，条目对齐是伪需求）；不动 abi.toml（零新 syscall——拼装全在内核装载路径内部）。
