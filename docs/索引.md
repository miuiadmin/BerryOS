## 维护规则

1. **新文档落库** → 本文对应分类加一行（文档 + 标签 + 一句话定位），头部总数与分类计数随行同动。
2. **文档落地/冻结/归档** → 更新对应行的标签后缀；归档移动文件时须同步全文交叉引用（[阶段沿革.md](阶段沿革.md) 是最大入链枢纽，7 条入链）。
3. **阶段进展详史** → 追加到 [阶段沿革.md](阶段沿革.md) 末尾追记区，勿回写 CLAUDE.md/AGENTS.md。
4. **引用路径统一带 `docs/` 前缀**（CLAUDE/AGENTS/各文档互引一致）。
5. **文档版本化**：设计/实施/规划/调研/验收类统一 `<名>-v<主>.<次>.md`（例：
   `兼容执行环境实施设计草案-v1.1.md`）；文件名与抬头 `版本：主.次` 双标；主版本 =
   不兼容/替代，次版本 = 兼容迭代；升版即改名并同步本表与全部引用；旧版不并行留副本
   （git 历史），确需归档放 `docs/归档/`；存量文档下次大改时迁移，不强制一次性重命名。
   入口/索引/规则/ADR/判例库/归档不在此列。
6. **归档纪律与死链豁免边界**（2026-11-09 明文化，W2-Q9；此前只散见于各清理刀 commit message）：六区中
   **时点性档**——标签为 `归档-历史记录` / `盘点-复盘` / `审查报告` / `裁决-决议·已吸收` 者（时点快照
   2026-11-09 共七件：阶段沿革 / 战略裁决-2026-10-15 / Phase4·P6 收官盘点 / 战役复盘-2026-10 /
   审查报告 ×2）——正文里的旧文件名引用（如 `调度器设计-v1.0.md`，后已升版改名）是**落笔时点的史实**，
   **免于死链清理**：改了反而篡改「当时引用的是什么」的记录。边界三条：① 豁免只覆盖时点档自身正文；
