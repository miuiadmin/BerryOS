# AI 工程面设计（开发期 AI：驱动工坊 + 移植工位）

> 回答两件事：**AI 开发驱动，系统在哪支撑（§3 驱动工坊）；AI 移植软件，系统在哪支撑（§4 移植工位）**。
> 核心论点：对开发期 AI 的支撑**不是「把 AI 装进系统」，是三样公共底座——机器可读的活儿清单、机器可读的操作说明、确定性考场**。AI 在系统外干活（外部模型 + 工位应用），BerryOS 的结构性优势（驱动 = 用户态应用、能力钉死爆炸半径、QEMU 确定性验收）让「AI 大胆试错」第一次变得安全：写坏死自己、炸不穿内核、考卷零 flaky。**考试不变，考生可以不是人。**
> 挂钩：`架构决策.md` #48（本文索引）+ #38（三不赌——不赌 AI 理解任意语义 / 不作系统支柱 / 不挤占正确性预算；本文原样遵守：AI 是系统外的考生，不是系统组件）+ #46（devmgr = 活儿清单的数据源）+ #44（manifest 机器可读 = AI 友好化的包格式面）；`应用模型设计.md` §8（运行时 Agent 面——本文是它的**开发期对偶**，「Agent = 普通应用、零特权 API」纪律两处共用）；`测试策略.md`（考场纪律的出处）；`优化议程.md` ②③（本文是它们的 AI 消费者面，不新开主线）。

## 0. 两张脸：运行时 Agent 面 vs 开发期工程面

AI 与 BerryOS 的关系是一扇门的两面——用电脑的 AI（运行时）与造软件的 AI（开发期）：

| 维度 | 运行时 Agent 面（`应用模型设计.md` §8） | 开发期工程面（本文） |
|---|---|---|
| AI 在哪 | 系统内的普通应用（Agent） | 系统外的模型 + 工位应用（普通应用） |
| 干什么 | 用电脑：操作应用 / 调配资源 / 替人操作 | 造软件：写驱动 / 移植上游程序 |
| 系统给什么 | 语义树 / 输入注入 / 按-app 资源账 | 活儿清单 / SDK 面 / 确定性考场 |
| 共同纪律 | **「只有 AI 能调」的接口不存在**——Agent 与工位都走人类应用同一套机制，同一扇门、同一把能力锁 | |

两面互不越界：§8 不给 Agent 任何特权，本文也不给 AI 任何「快速通道」——它产出的驱动和程序，过与人写的**同一份**验收线。

## 1. 为什么 BerryOS 结构性适合（别人 AI 写驱动是裸奔，我们这里是进考场）

| 面 | Linux 上的 AI 驱动开发 | BerryOS 上的 AI 驱动开发 |
|---|---|---|
| 交付物 | .ko 装进内核（与内核版本锁死） | .bap 应用（#46：驱动 = 持证应用） |
| 写错的代价 | 内核态 panic / oops = 全机死 | 用户态 G1.5 = **只死自己**（每 boot 的现役矩阵实证） |
| 爆炸半径 | 全内存 | manifest 能力表钉死（MMIO 窗 / IRQ / DMA 区间；IOMMU #22 兜 DMA） |
| 反馈回路 | 真机 / kselftest，慢、人读 | QEMU 确定性标记：同输入同输出，秒级、机读、零 flaky |
| 材料 | 散落的文档 / 邮件列表 / 内核源码 | ABI 单源生成 + 协议 crate + manifest 模板 |

现役证据（考场的已建部分）：vblk / vnet = 完整用户态驱动（`VBLK ok` / `NET ok`）；hexyl 0.17.0 = 上游未改动移植（`HEXYL ok`，输出与宿主基准逐字节全等）；40 标记四跑 smoke = 机器可读验收线。**这些本来是给人建的基础设施，恰好也是 AI 需要的全部**——设计总原则 #2/#3（AI 友好化 / AI 测试友好化）的兑现点。

## 2. 三公共底座（「系统天然在哪支撑」的答案）

两个工位共用三样底座——这也是本文唯一的系统面增量主张，且全部「对人同样有用」：

### 2.1 机器可读的活儿清单（devmgr AI 面）

「哪台设备没驱动」必须是一份结构化清单，而不是人的记忆：devmgr 枚举 DTB → 未认领资源池 → 导出**设备任务书**（一台一条：总线 / 地址窗口 / compatible / 中断 / 现役驱动有无）。现状：`kernel/src/dtb.rs` walker 现役；枚举→池→匹配随 devmgr v2（`驱动模型设计.md` §2）——本文增量只是池子的**导出格式**（一个既有功能的新消费面，不是新服务）。v1 期间的现实替代：QEMU 板卡清单 + 本文档族（AI 已可开工，vblk 就是样例卷）。

### 2.2 机器可读的操作说明（SDK 面）

AI 最怕的是过时文档——我们的答案是**文档即生成物**：

- **ABI 单源**：`tools/abi.toml` → `gen_abi.py` 三面生成 + `--check` 机器守卫（改 ABI 忘再生成 = FAIL）——编号 / 位 / 码 / 宽度永远与内核同源，AI（和人）不可能读到过时 syscall 表。
- **符号面**：berry-sys raw 绑定 + berry-libc shim（d-0 审计 189 符号全在册）——见 §4 砖①（要补的是三态可见性）。
- **协议 crate 家族**：loader / fsproto / blkproto / netproto / virtio / fatfs「解析器即产品」（零分配零 unsafe + host 测试全盖）——AI 消费即得测试面，这是「SDK 不只是头文件」的现役形态。
- **manifest 模板**（#44 TOML）= 工程第 0 块砖：申请什么能力、提供什么服务，声明式可机读。

### 2.3 确定性考场（AI 的反馈回路）

同输入同输出是 AI 迭代回路的地基（噪声反馈 = 学习失效）：

- **确定性标记**：smoke 的整条纪律谱系（「标记不得建立在竞速上」/ 状态谓词 / 回声歧义消除 / 金丝雀三验）就是给机器阅卷立的规——40 标记四跑全绿 = 可机判的对错。
- **崩溃报告**：异常 dump（寄存器 / EC / FAR / SP）+ 遥测环已是机器可读雏形；hexyl 栈溢出破案（下行栈静默扎进映像 RW 页腐化 .bss，死状 casa UNDEFINED 与死因南辕北辙；修法加保护页后栈穿才成干净 D-abort，dump SP/FAR 直指映像上方保护页）就是 AI 读 dump 能干的活的人肉预演——当时 dump 不直指死因、需跨步推理，恰是「AI 读 dump 破案」的有力例证。欠结构化格式（优化议程 2.2 杀手锏）。
- **syscall 踪迹**：sys-tag 过滤踪迹（A-2 排障三轮实绩，一次性仪表未入库）≈ strace 等价物思路，常驻面化随可观测性 v2 trace 服务（`可观测性设计.md` 已排期全类别含 syscall + 过滤谓词——雏形的自然归宿）。

## 3. 工位一：驱动工坊（AI 开发驱动）

工位本体 = **普通应用**（接 AI API 的工具型应用，自己也要过 manifest 能力门控）。**出网通路现状缺失（诚实对账）**：vnet 仅 ARP/ICMP 瞬态探针、socket 族 ENOSYS、TLS 无议程行——v1/v2 期间 AI 在宿主侧跑（BerryOS 只当考场，§2.1 的 v1 现实替代）；工位本体（v3+）落形前置 = 最小 TCP/IP 栈（P6 议程）就位，或改走宿主中转 / 本地模型形态（不经系统内出网）。流水线五步：

| 步 | 内容 | 备注 |
|---|---|---|
| 1 领活 | 读 devmgr 未认领池设备任务书；**人喂硬件描述进料**（datasheet 寄存器表 / 公开规范） | 进料是人的活——见下方诚实边界 |
| 2 生成骨架 | manifest（`type=driver` + `hw.match` + 能力申请表）+ 消费协议 crate；轮询版先行 | IRQ→channel v2 前不依赖（vblk 同款轮询） |
| 3 考试 | 确定性 QEMU 跑 smoke 式标记；失败喂回 dump / 遥测 / 踪迹，改完重考 | 同输入同输出 ⇒ 重考必可达、无 flaky |
| 4 上岗 | **人按「安装」**（责任锚点）→ appd 装载 .bap → devmgr 认领设备 | 分支键 = 任务书「现役驱动有无」（§2.1）：**有**（替换 / 升级现役）走**影子模式**——候选与现役**离线对拍**（同一输入集先后喂两版、比对输出，非同时挂设备——不碰 `驱动模型设计.md` §2「认领即独占」），全等才转正；**无**（首装设备，未认领池主活源）验收即步 3 考场（确定性标记 + 写读回自洽对拍，vblk 模式）+ 真机面留人工确认点 |
| 5 运行兜底 | 崩 = 代号热换重启（优化议程 3.1；#28 / #46 应用链）；unsafe 配额进遥测（优化议程 3.2） | AI 写的驱动与人类写的走同一条监督链 |

**诚实边界（不赌 AI 万能，#38 同款纪律的工程化）**：

- AI 强项 = **模式驱动**的外设（规范公开、参考实现多：virtio 类 / USB 类 / I2C 传感器）；弱项 = errata / 未公开硬件 / 精细时序。设计答案 = 进料 + 影子模式，**不是「等 AI 变强」**。
- boot 关键三件（GIC / timer / 早期 UART，#12 豁免）不是工位对象——AI 写的是外设驱动：数量最大、模式化最强、崩了最不致命的那批，恰好也是微内核最该外提的那批。
- 考试不因考生是 AI 放水：确定性标记、基准对拍、能力门控一样不少——**考不过就退回重学**。

## 4. 工位二：移植工位（AI 移植软件）

G-eco 五步手工流程（hexyl 已走通）的模板化 + AI 化。四块砖：

| 砖 | 现状 | 欠件 |
|---|---|---|
| ① 靶面覆盖表 | **缺——本文最大增量**。berry-libc 符号面（189 符号审计）+ ABI 单源合并成机器可读**三态表**：真实现 / 桩 / 缺失，附已知雷注记 | 生成脚本 + `--check` 机器守卫（`mkfat --check-fixture` 同款纪律：改 shim 忘重产 = FAIL）。poll 桩曾致 std 静默 abort（d-1c 实踩）——桩与真实现的边界对 AI（和人）不可见，就是没有这张表的代价 |
| ② 构建 + 运行回路 | 已有：`just build-user` → rootfs.cpio → smoke 四跑 | cargo generate 移植模板（优化议程 2.1）= hexyl 知识沉淀：musl target + shim + CRT0_SEED + 栈页参数化 + 基准对拍验收 |
| ③ 崩溃报告 AI 可读 | 雏形：dump 寄存器 / EC / FAR / SP | 结构化格式 + 映射布局快照（优化议程 2.2 杀手锏）——「报错直接喂 AI 可定位」 |
| ④ syscall 踪迹 | 无留存实物——A-2 排障一次性 sys-tag 仪表（三轮定位，代码未入库） | 常驻面化（strace 等价物）——随可观测性 v2 trace 服务（`可观测性设计.md` 已排期，见 §2.3） |

流水线：上游 repo → 覆盖表查缺口（缺什么桩一目了然）→ 交叉编译 → QEMU 跑 → 读标记 / dump / 踪迹 → AI 改（补 shim / 调栈页 / 加桩）→ 迭代到绿 → 入 rootfs / 打 .bap。**上游逐字未动**（hexyl 纪律）——适配全在 shim 与配置侧。

## 5. 红线：与既有决策的对齐

- **vs #38 三不赌**：①不赌 AI 理解任意语义——工位只接「有确定性考卷的活」（驱动 / 移植都有机器可判的对错）；②AI 不作系统支柱——工位是普通应用，缺了系统照跑，底座对人同样有用（**AI 只是第一消费者**，这是不违 #38 的关键）；③不挤占正确性预算——v1 零代码增量、v2 底座件不单独立项：两件挂既有议程原行（2.1 / 2.2），两件随既有窗口顺带产出（devmgr v2 / libc 收口），踪迹常驻面化随可观测性 v2 trace（见 §6）。
- **vs §8 Agent 面**：零特权 API 纪律两处共用；本文不新增任何「只有 AI 能调」的接口——活儿清单 / 覆盖表 / dump / 踪迹对人类开发者与 CI 同样是资产。
- **考试权威**：AI 产出过与人写的同一份验收线（确定性标记 / 逐字节基准对拍 / 能力门控），**不设快速通道**；人按「安装」= 责任锚点。
- **安全**：AI 生成代码不是特权代码——manifest 能力表照申请、unsafe 配额照计、（v2）签名度量照走。恶意 / 劣质产出的最大攻击面 = 它申请到的那扇窗，圈死在设备地址范围。

## 6. 阶段化目标

| 时点 | 内容 | 验收 |
|---|---|---|
| v1（现状） | **零代码**。本文 = 既有资产的 AI 视角盘点（SDK 面 / 考场在跑；踪迹法已验证——一次性仪表，未留存） | 无——这是「人无我有」的宣称面，不是工程承诺，不占工时 |
| v2 | 底座件五件：devmgr 未认领池导出面（随 `DEVMGR ok`）、靶面覆盖表 + `--check`（随 2.4『POSIX 库收口』窗口）、dump 结构化（议程 2.2）、移植模板（议程 2.1）、syscall 踪迹常驻面化（随可观测性 v2 trace 服务） | dump 结构化挂议程 2.2、移植模板挂议程 2.1 原行验收；导出面随 `DEVMGR ok` 顺带产出、靶面覆盖表 + `--check` 随 2.4 收口窗口新增（守卫挂 just test-host，非 smoke 标记）；踪迹挂可观测性 v2；**本文不新立 smoke 标记** |
| v3+ | 工位应用本体（驱动工坊 / 移植工位）——**实验轨道，不进承诺**（落形前置另含最小 TCP/IP 栈或宿主中转 / 本地模型形态，见 §3 出网对账） | kill criteria：确定性考场反复不过且无人进料补强 → 工位永久停「辅助位」（人可用 AI，验收照旧），不立项系统集成 |
