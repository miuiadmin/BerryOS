# 开发体验设计（Mac 上的运行与日常开发循环）

> 回答三件事：系统在 Mac 上**怎么跑/怎么"装"**、日常开发循环长什么样、哪个 Phase 解锁哪种体验。
> 里程碑挂钩 `路线图.md`（P4 G-eco 生态关 / P5 交互 shell / P6 挂载镜像）；用户程序 ABI 见 `系统调用ABI设计.md` §8（`berry-sys` 镜像）；测试基建见 `测试策略.md`（G0–G5 串口断言）。本文是体验路线，不是新架构决策。

## 0. 事实与原则

- **Mac 上"装" = 虚拟机，且只有虚拟机**。Apple Silicon 锁死第三方 OS 启动链，双系统不可能；但 M 系芯片与内核同为 AArch64，**同架构虚拟化不是模拟**——QEMU `--accel hvf`（≥7.0，brew 版即含）下接近原生速度执行。
- **交叉编译永远在宿主侧**。Redox 的 `x86_64-unknown-redox` 先例；Linux 发行版同样宿主交叉构建。**自托管（系统内跑 rustc）不是 v1 目标**，Redox 走到那步用了近十年。
- **TCG 与 hvf 双模式并存，各司其职**：关卡测试（G0–G5）固定 TCG（行为可复现、`cortex-a72` 固定型号）；交互开发用 hvf（快 + 真计时器）。
- **AI 测试友好化的落点**（设计总原则 #3）：整条循环 = 纯 CLI 可复现——`just smoke` 无头拉起 QEMU → 串口按 smoke 标记断言。AI agent 能独立改码、跑测试、读结果、报 bug，全靠这条循环不依赖任何 GUI。

## 1. 运行/安装四级阶梯

| 阶梯 | 形态 | 需要什么 | 对应 Phase |
|------|------|----------|-----------|
| **L0（现状）** | `-kernel` 直加载 ELF，串口=屏幕 | 已在用（`just run`） | P0–P2 ✅ |
| **L1 rootfs 递送** | `-fw_cfg name=opt/berry/rootfs,file=rootfs.cpio` 具名文件：启动白拿一包文件进内存，**零块设备驱动**就有文件系统 | ELF 加载器 + cpio 解包（berry-loader）+ fw_cfg FILE_DIR（已落）；DTB `chosen` 路径仅真机/Linux boot 协议（`dtb::boot_probe` 预埋） | P4 ✅ 已收官（G-eco 关的载体，rootfs 相 smoke 标记；生态验收程序 = hexyl 非 ripgrep——`HEXYL ok` 终验） |
| **L2 fat:rw** | QEMU 把 Mac 一个目录**伪装成 FAT 硬盘**：宿主改文件即时生效，guest 立即可见 | FAT（MVP 本来就是）+ **第一个 virtio-blk 用户态驱动**（`驱动/` 练手首作）+ FS 服务 | P6（`virtio-blk` + 挂载镜像本就是 P6 里程碑） |
| **L3 自举镜像** | 真磁盘镜像 + 自家引导加载器（`引导加载器/` 目录留位）——"装系统"的实感 | 引导加载器 + 分区表 + 镜像打包脚本 | P6+ |

L2 命令形态（落到 justfile 后即 `just dev`）：

```bash
qemu-system-aarch64 -M virt --accel hvf -kernel berryos.elf \
  -drive file=fat:rw:用户态/rootfs,format=raw,if=none,id=hd0 \
  -device virtio-blk-device,drive=hd0 -serial stdio
```

**日常开发长期停在 L2**：编辑即生效、不用重打镜像。UTM 等 GUI 只是 Virtualization.framework 的壳，可作演示；自动化与测试必须走 QEMU CLI。

## 2. hvf 与 TCG 双模式

- **hvf 的两个收益**：① 近原生速度（同架构直执）；② **真计时器**——CLAUDE.md「Gotchas」记录的 TCG 下 CNTVCT 推进 ≈ CNTFRQ/2（实测抢占率减半）在 hvf 下不存在，slice 率为真值。
- **切换纪律**：hvf 默认 `-cpu host` ≠ `cortex-a72`，ID 寄存器类数值（如 ASIDBits，TCG virt 实测 =16）可能不同——**一律运行时读 ID 寄存器，禁止写死**；首次切换与每次 CI 都先跑全量 smoke 再认绿。
- **不取代 TCG**：关卡基线（`测试策略.md`）固定 TCG 报数，保证"同输入同输出"的可复现性（AI 测试友好化的前提）；hvf 只是交互体验层。

## 3. 日常开发循环（P5 后的全貌）

```
Mac 终端                                BerryOS 串口 shell（同窗分屏 / tmux）
──────                                 ──────────────────────
$ vim 用户态/hello/src/main.rs          berry> ls /bin
$ just build-user                       hello   shell   ls
   (cargo build --target
    aarch64-unknown-berry)                berry> run hello
                                       Hello from BerryOS!
$ git commit ...                        berry> berryctl test run G3
                                       ... ok
```

- **交叉编译 target**：builtin `aarch64-unknown-none`（no_std 程序）+ `aarch64-unknown-linux-musl`（std 面，hexyl 经此）——自定义 target（`aarch64-unknown-berry`）已弃（G-eco-a 免 nightly 路线，见 CLAUDE.md）；`berry-sys` 镜像见 `系统调用ABI设计.md` §8.3–8.4；常量层已单源生成（abi.toml）。
- **移植软件路径**：P4 G-eco 关硬验收 = **未经修改的第三方 Rust 程序**交叉编译跑通（已兑现：hexyl 0.17.0 上游逐字未动，`HEXYL ok` 终验；ripgrep 级后续）→ P5 POSIX 库收口后 musl 系 C 程序可批量移（stdhello/std 面已通）。
- **交互前置**：P5 shell 需要 PL011 **RX 中断** + 行编辑——串口双向打通是 P5 第一刀。

| 命令 | 状态 | 内容 |
|------|------|------|
| `just run / run-el2 / run-release / check / clean` | ✅ 现有 | TCG 直加载 |
| `just smoke` | ✅ 现有雏形 | 无头跑 + 串口标记断言（P6 A-6 起四跑：裸相 23 / rootfs 相 21 / RX 相 44 / 持久化相 44） |

| `just test` | 未设（挂账） | 全量关卡断言入口（现由 `just smoke` 承担；AI agent 入口 = smoke） |

## 5. 三级火箭（"真正开发的真正时刻"）

1. **能跑外来的程序**（P3 末–P4，G-eco 关）：在 Mac 编译、BerryOS 里运行的第一批第三方程序——**系统从 demo 变成平台**的临界点。
2. **交互 shell + 文件系统**（P5 里程碑原文"UART 上交互式 shell"；PM 服务改频同点兑现；P6 挂镜像读写文件补全体验）——日常开发循环（§3）全貌成真。
3. **自托管**：远期探索，不进承诺。

## 6. 已知坑

- **vvfat（`fat:rw:`）是仿真层**：读多写少的开发循环没问题；重写负载下偶发不一致。**关键验证/发版回归必须用打包好的 raw FAT 镜像**跑一遍，日常热循环才用 fat:rw。
- QEMU ≥11 不带 `-bios`（virt 直加载）；halt 后 `Ctrl-A X` 退出——沿用 CLAUDE.md 既有坑位。
- **initrd/rootfs 递送**：QEMU 非 Linux ELF `-kernel` 直加载下 `-initrd` 整体不加载、RAM 内无 DTB（G-eco 四层实证，详见 CLAUDE.md Gotchas）——blob 走 fw_cfg 具名文件 `opt/berry/rootfs`；DTB `chosen` 起址路径仅真机/Linux boot 协议生效（`dtb::boot_probe` 预埋，届时按 chosen 节点取、勿写死地址——QEMU 版本间放置策略有变过）。
