## 1. 概述

BerryOS 是一个全 Rust 微内核操作系统（内核 Meihe，ARM64 首发，QEMU virt 主验证），覆盖穿戴、手机到桌面。调度器主线是**机制进内核、策略可插拔**：上下文切换、运行队列、时间片等不可委托的原语留在内核；"谁优先、放到哪个核、加多少权重"全部做成可注入、可评估、可撤销的用户态数据。核心创新是把灰度发布方法论带进内核调度——候选策略先在影子轨道并行运行、逐次对账分歧、通过 A/B 判定才转正。这一闭环在四个业界参照系统中均为空白（对标见 §10）。

## 2. 架构总览

系统分四层，快路径与慢路径严格分离：

```text
策略层（用户态）  策略服务（启发式 advisor / AI，10–100ms 慢循环重算策略表）
                  PM 电源服务（DVFS / 热管理 / 休眠——频率的唯一裁决者）
                    ▲ 遥测（共享环）        ▼ 策略表注入（syscall 0x83）
──────────────────────────────────────────────────────────────
调度核（内核态）  快路径：每核 runqueue → 调度类派发 → pick_next
                  类优先级：rt > deadline（EDF）> fair（EEVDF）> idle
                  策略面：三槽 RCU 快照 + shadow 双轨 + freeze + 准入控制
EAS 能效层        placement 建议 · EM 能量模型 · util EWMA · overutilized 门控
──────────────────────────────────────────────────────────────
测量层（横切）    HDR 延迟直方图 · 唤醒延迟基准 · 仪表盘五工具
```

命门是快慢分离：热路径每次选任务只读一份不可变快照表，微秒级、零分配、绝不调用任何用户态服务；策略服务崩溃时内核回落启发式继续调度，调度正确性不依赖任何服务在线。

## 3. 核心创新（业界领跑四件）

### 3.1 Shadow 双轨道策略评估

候选策略表提交到影子（shadow）谱系后"只算不用"：每次调度决策对同一任务键在活跃表与影子表各算一份。隔离是结构性的——发布指针的取值域不含影子槽，快路径在地址空间上就够不到影子数据，这是结构保证而非口头约定。对比之下，Linux sched_ext 换策略只能整核切换，无并行评估轨道。

### 3.2 Divergence 对账

两份决策的差异只计数、永不应用（影子侧零任务写、零表写）。对账指标为分歧率 = 分歧次数 / 影子评估次数；轨道切换（转正或降级）自动清零，读数永远属于当前对账窗口，不被历史样本污染。

### 3.3 A/B 升级判定闭环

四步工作流：SHADOW_COMMIT 起双轨 → 跑代表性负载累积对账 → 评估 → PROMOTE / DEMOTE。判定线：分歧率 < 0.1 转正、> 0.5 降级、其间或零样本 HOLD（证据不足不硬判）。候选表由确定性工具生成——同输入同输出、可 diff 审计；判定脚本在宿主侧独立运行，阈值可覆盖。

### 3.4 Band 层级预算包络

任务按 intent（创建时声明的工作负载档位：交互、工具、后台、维护等六档，单字节编码）归带，每带一份 CBS 形状的 quota/period 预算：每期至多消耗 quota CPU 时长，超支整带禁跑至下期。实现上全整数微记账、事件驱动周期翻转（不复活周期 tick），默认全关、逐带开启；deadline 实时任务豁免，永不因带预算违约。

## 4. 调度核心

fair 类底座是 EEVDF（虚拟截止期 + lag 排序的公平算法，与 Linux 6.6+ 同代语义，实现自研）。媒体与软实时走 deadline 类：EDF（最早截止期优先）+ 预算执法 + 准入控制——总利用率 ΣU ≤ 0.95，坏任务被节流而非破坏别人。freeze 是进程级冻结原语：令牌上限 64、支持嵌套、单线程冻结需自证就绪、与用户态 pager 协同。比较器纪律：每类单一排序键，选任务与抢占检查同源。RT 与 deadline 类对 AI 策略一律屏蔽——软实时确定性不容机器学习方差。

## 5. 策略服务

内核接口是 0x83 号 syscall `policy_bind`，六个操作码：

| op | 名称 | 语义 |
|----|------|------|
| 1 | COMMIT | 整表提交为活跃快照，立即参与调度决策 |
| 2 | STATUS | 单次读回双谱系世代 + 调用者自身键 + 分歧双计数 |
| 3 | PROMOTE | 影子表原子转正（约 4KiB 受控拷贝 + 单条发布） |
| 4 | DEMOTE | 活跃表降级回空表，影子表保留（可再次转正） |
| 5 | UNBIND | 解绑回"接口缺席"态（对照测试用，幂等） |
| 6 | SHADOW_COMMIT | 整表提交到影子谱系（只算不用） |

换表走三槽 RCU：槽写完 → 释放栅栏 → 单条原子发布，读者见槽号必见槽内容。表定位用 O(1) 黄金比散列（乘 2^64/φ 取高位做桶号），键分布不均也摊平；单表上限 128 条，超限诚实拒收。世代号严格递增，重放的旧表被拒收。注入权重经三点夹紧恒在 ±64 包络内——只单调收窄、无提权路径。空表与"接口缺席"逐位等价：策略面开销与策略复杂度无关（实测注入绝对开销 2 个 CPU 周期）。端到端工作流：遥测 → advisor 出候选表 → SHADOW_COMMIT → 对账 → policy_ab_eval 判定 → PROMOTE / DEMOTE。

## 6. SMP 安全

多核下策略表一致性由三件原语保证。其一，发布指针与影子槽位全部原子化：写侧"写完 → 释放栅栏 → 发布"、读侧获取语义装载——见新槽号必见新内容。其二，hazard-lite 槽回收：每核发布正在读的槽号，读者走"装载 → 登记 → 栅栏 → 复读验证"的经典验证环，写者发布前扫描避开全部在读槽；三槽两核恒有空闲，协议违约当场 fail-fast 而非静默跨核腐坏。其三，写者锁把全部五个写入口串行化，防止两核写者交错造成世代倒灌或旧表覆盖新表。单核形态下三者全部退化为零开销。

## 7. EAS 能效

能效层由四个信号组成。placement：策略表可给每个键三值放置建议（无意见 / 偏小核 / 偏大核），仅建议不强制，负载均衡可无视。EM 能量模型：每域至多 4 个频点的"频率–功耗–算力"三元组表，是能量比较的数据面。util：每核指数加权滑动平均（α = 1/8 纯移位、零除法零浮点，0..1024 与算力同尺度），是 PM 调频的输入信号。overutilized 门控：任一核超过最高容量 80%，整个域即退回普通负载均衡——能量账只在有余量时算，与 Linux EAS 同款机会主义纪律；能量模型未注册时保守回退（任何非零负载即视为过载）。频率裁决单点归 PM 服务，调度路径零频率写点。

## 8. 性能

实测环境 QEMU virt / Cortex-A72 / TCG，n = 1000 轮：

| 指标 | 优化前 | 优化后 | 验收线 | 余量 |
|------|--------|--------|--------|------|
| pick_next（选下一任务） | 27 周期 | **21 周期**（−22%） | < 5µs @1000 任务 | 14× |
| freeze（冻结原语） | 15 周期 | **5 周期**（−67%） | < 5ms | 62500× |
| billing（记账） | 1 周期 | 1 周期 | < 1µs | 62× |
| 公平性（双任务差） | spread = 0 | spread = 0 | — | — |
| 策略注入绝对开销 | — | 2 周期 | 有/无表开销差 < 50% | 绿 |

选任务的扫描复杂度从 O(4n) 降到 O(n)（扫描量 −75%）：增量账本把全环求和变 O(1) 直除、无 deadline 任务时零扫描、双段合并单圈。诚实声明：以上为仿真器功能与相对趋势口径；绝对分位数（p50/p99/p99.9）证据面属真机阶段。

## 9. 测量基础设施

延迟分布用 HDR（高动态范围）直方图：28 个八度 × 32 子桶共 897 桶，值域约 4.3 秒封顶，相对精度约 1/32；热路径一次前导零计数 + 原子加，零分配；分位数入参用整数千分比——内核全程禁浮点。每核直方图按 64 字节缓存行对齐防伪共享。唤醒延迟基准采用 cyclictest 口径：绝对截止期锚（不外推、零漂移）、128 轮采样直灌直方图。宿主侧五件仪表盘工具：advisor（遥测 → 候选策略表，确定性生成）、policy_ab_eval（分歧率 → 判定）、sched_perf_analyze（性能验收 JSON 判定）、starvation_check（饥饿界检查）、sched_dashboard（遥测汇总与基线回归检测）。

## 10. 与业界对标

| 系统 | 策略形态 | 影子双轨 | 并行对账 | 自动 A/B 判定 | 层级预算 |
|------|----------|----------|----------|----------------|----------|
| Linux sched_ext | BPF 程序，仅整核切换 | 无 | 无 | 无 | RT throttling |
| Google ghOSt | 用户态策略，不进快路径 | 无 | 无 | 无 | — |
| Zircon | fair + deadline 固定类 | 无 | 无 | 无 | deadline 期限 |
| Xen（credit） | 固定算法 | 无 | 无 | 无 | cap 上限 |
| **BerryOS** | 用户态注入 + RCU 原子换表 | 有 | 有 | 有 | band CBS 包络 |

对标结论出自四系统横评调研（8 个维度、40 条来源核验、17 项红队攻击）：影子双轨 + 并行对账 + 对账驱动的自动升级判定，四家均为空白。

## 11. 路线图（v1.4+ 方向）

- **SMP 余项**：影子槽的 hazard 覆盖、跨核换表等价断言（换表窗零丢片 / 零双跑金丝雀）、各核见表世代漂移的合法窗观测。
- **EAS 选核算法**：compute_energy 能量比较随 M2 与真机落地——当前刻意"形状在、算法留"。
- **band 执法并线**：先过实测入场券（过载尾延迟差 + 饥饿计数）；扁平 EEVDF 是必须打败的零假设，证据不足则查表键形态即终态。
- **真机证据面**：HDR p99 分位门禁、真睡眠/唤醒基准（boot 钩子已留）。
- **治理面**：SET_POLICY 能力门控（随 Job 对象）、PM 共享环接线（util 信号的首个消费者）。
- **AI 策略演进**：启发式 advisor（现行）→ 设备端学习策略（v4+）；一切候选都经影子轨道入场，kill criteria 在册可撤。

## 附：名词速查

| 术语 | 一句话 |
|------|--------|
| EEVDF | 虚拟截止期公平调度算法，Linux 6.6 起 CFS 的后继；BerryOS fair 类底座 |
| EDF | 最早截止期优先，软实时/媒体任务的排序规则 |
| RCU | 读-复制-更新：读者无锁、写者整表原子替换的并发模式 |
| EAS | 能量感知调度：系统有余量时按能耗选核 |
| CBS | 恒定带宽服务器：按 quota/period 封顶的预算执法形状 |
| intent | 任务创建时声明的工作负载档位（六档，单字节） |
| band | fair 类内部按 intent 的分层，每层一份预算包络 |
| shadow | 影子策略轨道：并行计算、只算不用 |
| divergence | 影子与活跃决策的分歧计数（对账指标） |
| gen（世代号） | 策略表版本号，严格递增，防重放旧表 |
| HDR 直方图 | 对数分桶的延迟分布，兼顾动态范围与精度 |
