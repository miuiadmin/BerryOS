## 一、定位与分级（测什么、不测什么）

### 1.1 一句话定位

BCTS = 把「平台对 out-of-tree 组装者的兼容承诺」变成可执行回放执法的认证套件——
**测的是承诺，不是实现质量**。病根直指 01 号缺口 4：冻结面只防「改不动」，不防
「fork 后自行漂移」；没有 CTS/认证，冻结承诺对树外厂商无从谈起（01 号 §3-4，:151）。

### 1.2 与 G0–G5 的关系：独立认证套件，非替代

Q4 裁定原文：「BCTS 立为独立于 G0–G5 的认证套件」（12 号 §2.4，:77；#82 附录二同句）。
两者分工与三条纪律：

| 维度 | G0–G5 关卡 | BCTS |
|---|---|---|
| 主体 | 本仓自身演进的开发关卡（`docs/测试策略-v1.0.md:22-28`） | 面向任意组装者（OEM/ODM/自组装）的承诺执法 |
| 测试形态 | 活树、CI 常驻（`just smoke`/`test-host` 现役轨道） | 冻结件、回放态（§二） |
| 判定语义 | 「本仓实现跑对」 | 「任意组装兑现承诺」 |

- **不替代**：G 关卡不过 ≠ BCTS 免测；BCTS 全绿 ≠ G 关卡免测——各管一段，互不豁免。
- **不重复立法**：断言资产共享——现役 smoke 断言冻结化 = 同一 `tools/markers.sh` 单源
  （规则/07:11）的两套消费语义（活树 CI 判定 vs 冻结回放判定），不另立断言树。
- **执法位不同**：G 关卡挂本仓 CI；BCTS v0 挂现役 just 配方树（§4.2），V13 后挂组装门禁。
  07 号 §7-9（BCTS 与 G 关卡执法位关系）由此在设计层收口，残余随 V13 迁移窗口复核。

### 1.3 承诺面口径：只测 L0/L1/L2（对接 API治理章程）

分级唯一口径 = `docs/API治理章程-v1.0.md` §一（:10-16）：

| 级 | 面 | 承诺 | 进 BCTS |
|---|---|---|---|
| L0 | syscall C-ABI（abi.toml 单源，v1 37 号在册、nr_ceiling=45） | 永久冻结、只加号不回收（ADR #55） | ✅ Tier 1 |
| L1 | 服务 wire 协议 | add-only + per-interface version（ADR #54/#59） | ✅ Tier 2 |
| L2 | 公开库 API（berry-sys/libc/gfx/ui 及协议 crate 族） | semver + N=3 废弃窗口 | ✅ Tier 3 |
| L3/L4 | 系统内部 API / 工具输出 | 零承诺 | **不进**（测零承诺面 = 制造伪契约；Hyrum 纪律同构，04 号 §4.1-1，:194） |

「不测什么」与「测什么」同权：L3/L4 不进 BCTS 是防 CTS 式无限膨胀的正条款，非省略。

### 1.4 认证构成：BCTS 过 + 能力基线核

认证 = 两条腿（04 号 §4.5-1，:240）：**BCTS 过**（承诺面行为兼容）+ **能力基线核**
（没砍面，§6.2）——只过 BCTS 不核基线 = 允许「子集设备」；只核基线不过 BCTS = 允许
「面上齐全、行为漂移」。四门槛收编（04 号 §4.5）：

1. **技术门槛**：已开通 Tier 全绿（§3.4 分阶段口径）+ 能力基线十条断言全过。
2. **身份门槛**：OEM lineage 在册（Q1 星状分配，#77 承接）+ 签名链负样例全拒。
3. **可复现门槛**：同工件同清单重组镜像 hash 一致 + 度量链可由公开工件重建。
4. **跟版门槛**：Q12 N 窗口（N × 上游 minor 发版周期 ≥ OEM 最大迁移周期），超窗由
   账本 cert_status 执法（架构决策.md:283）——数值归治理文档，本稿不重复立法。

## 二、冻结件回放制（机制核心，07 号 §6-1）

### 2.1 冻结与工件形态

- **工件 = 冻结测试件，不是活测试树**（07 号 §6-1，:316；抄 Fuchsia CTF freeze/thaw）：
  每个上游发版时点把当版测试集冻结成带版本号的工件 `bcts@<platform_revision>.toml`
  ＋ 内容 hash。
- **hash 钉在 abi 冻结快照同一快照点**：abi.toml 每次变更出 `abi@<short-sha>.toml` 快照
  （SDK-2 双轨 §四，:47-56）——BCTS 工件记录其锚定的 abi 快照 sha，L0 面版本与测试件
  版本同点冻结（07 号 §6-1 原文「把 BCTS 工件 hash 钉在同一个快照点上」）。
- **分发形态（设计值）**：工件进仓 `tools/bcts/frozen/`——git 仓即分发渠道（开源免费的
  最简形态）；托管位（CIPD 式）v2 再议（§7.2-1）。
- **发布后只读**：冻结件不可改；缺陷修复 = 新 sha 重新签发 + 旧件作废登记（add-only
  台账）——CTF milestone 分支 cherry-pick 重出 CTF 同构（07 号 §1.5-5，:110）。

### 2.2 回放语义

认证某设备 = 用「设备声称兼容的版本」的冻结件在其上回放（07 号 §6-1，:316）：

- **声称位** = 镜像 `manifest.txt` 的 `platform_revision` 列（V9，架构决策.md:248）。
  回放前对账「镜像声称版本 == 冻结件版本」，不符 = 拒起（版本可判定性是测试工件的
  一等要求，RFC-0015 原则 4，07 号 §1.5，:91）。
- **判定式** = 观测标记 ⊇ 冻结清单全集（一条不少）。多打的活树新标记不算 fail
  （新断言属开发轨道，不属承诺面判定）。
- **v0 回放对象** = 组装镜像（QEMU virt 基线跑通，AGENTS.md:10 主验位）；真机回放
  随 P8（闸 D）。真机证据 v1 定位 = 结果包附加材料而非门禁（推断，待窗口）。

### 2.3 freeze/thaw 纪律：活树/冻结双轨

两轨并存（07 号 §6-5，:320），职责严格分置：

| 轨 | 清单来源 | 跑在哪 | 拦什么 |
|---|---|---|---|
| 活树版（立即） | `tools/markers.sh` 单源 | 本仓 CI 常驻 | 新变更的**即时**破坏 |
| 冻结版（随版本滚入） | `bcts@<ver>.toml` 冻结件 | 新平台/认证回放 | 对**旧承诺**的破坏 |

thaw 侧义务：main 最新平台必须能跑通上一版冻结件（软过渡要求，07 号 §1.5-4/:105）——
「精确模拟组件用旧 SDK 构建、以预编译形态跑在新平台上」的场景。**认证永不回放活树**：
活树绿不是兼容证据，只是开发自证。

### 2.4 版本绑定的机器表达

1. 冻结清单文件名带 `platform_revision`（§4.1 schema 同字段冗余自证）。
2. 镜像侧声称位 = V9 `platform_revision` 列（mkimage 侧产物，闸 C 前落）。
3. abi 快照 sha 联锁（§2.1）。
4. Tier 2 起测试包名带版本尾缀（`_api$N` 式，CTF 包名绑定同构，07 号 §1.5-6，:111）
   ——v0 不做（v0 无 harness 包面，测试件即标记清单）。

### 2.5 发布节奏（设计值，ADR 窗口终裁）

Q4 边界明留「发布节奏数值随 #84 立项稿」（12 号 §2.4，:77）——本稿设计值：
**每 minor 一冻，major 全量重发**。依据：Q12 N 公式以 minor 发版周期为基
（架构决策.md:283）；Fuchsia milestone ≈6 周节奏同构（07 号 §1.5-5，:110）。
首个 minor 发版节奏确立前，以「首个带 platform_revision 的发版」为首次冻结点。

## 三、Tier 政策（防空集的正面解）

### 3.1 空集自警与其解法

07 号 §8.1（:348）自警原文：「抄机制容易，抄到同等覆盖率难；BCTS 若只抄 freeze/thaw
结构而无 tier 政策配套，**冻结的可能是空集**」。12 号 §2.4（:72）确认此自警如实传递。
正面解三件，缺一即空集风险回归：

1. **Tier 分级 + 每 Tier 最小件数下限**（机器执法，§4.4 空集守卫）。
2. **「在野回归 = 用例欠账」记账**（RFC-0141 法则二直采，07 号 §1.5，:102）。
3. **覆盖率报表**按 L0/L1/L2 机器可读清单计算（PlaSA manifest 同构，07 号 §6-2，:317）
   ——L0 清单 = abi.toml（现役）；L1/L2 清单 = V14 归档位（#83 拍板时落，架构决策.md:253）。

### 3.2 三 Tier 定义与最小件数下限

| Tier | 承诺面 | v0/v1 形态 | 最小件数下限（机器执法） | 开通条件 |
|---|---|---|---|---|
| 1 | L0 syscall 面 ＋ 装载谓词 | 现役 smoke 断言冻结化 ＋ abi-check 五面逐字节 | **88 标记件**（口径见下） | 本稿开工即通（v0） |
| 2 | L1 wire 契约 conformance | 槽位合同四件套之④用例集 | 每开放槽位 ≥ 合同④件全集；每对外 L1 接口五类用例各 ≥1（注 a）；计数随 #83 落数 | #83 落册 ＋ 首槽开放（Q8） |
| 3 | L2 行为面 | berry-sys/libc/gfx/ui 行为 ＋ 三 host 门禁 | N=3 窗口内存续 L2 API 每 API ≥1 断言（推断）；门禁恒在（注 b） | Tier 2 后随 V13；全覆盖同刀 |

- 注 a（Tier 2 五类用例）：合法 op 序列/非法 op 拒绝/version 协商/错误域/超时失败隔离
  （04 号 §4.2 L1 行，:205）；槽位合同载体 = 用例 id 进 `tools/slots.toml`（暂名），
  实现进 BCTS L1（08 号 §1 表④，:35）。开放条件全句 = Q8「四件套全绿才开」
  （架构决策.md:279）。
- 注 b（Tier 3 三 host 门禁）：三值版本域执法（mkapp 编译期）＋ 产品清单 schema 校验 ＋
  组装确定性（同输入同 hash）（04 号 §4.2 L2 行，:206）。

**Tier 1 下限 88 的口径与实测**：裸相 32（`MARKERS`）＋ rootfs 相 54（`ROOTFS_MARKERS`）
＋ RX 注入专属 2（`RX_MARKERS`：`SIMBAT ok seq=`/`PWRKEY unowned n=`）= 88——本稿
2026-11-10 对 `tools/markers.sh` 数组长度机器实测。两源交叉：04 号 §4.1（:198）
「smoke 86 基础标记（boot 32 ＋ rootfs 54）」＋ 规则/07 相构成表（:20/:22 同数）——
基础集 86 三源一致；RX 2 = markers.sh 实测 ＋ 规则/07:23 逐段描述。取宽口径 88 的
理由：`just smoke` 八跑是回放执行单元（规则/07:23），冻结件按执行单元整体冻结。
其中「L0 syscall 面」对应裸相 boot 链标记族（`SYSCALL ok`/`ktest done` 等）＋
abi-check；「装载谓词」对应 appd 装载链（`APP ok n=`/`APPUI ok n=`——
`docs/应用规范-v1.0.md:382` 现役定义：装→起→真退出→reap 真码 0 全槽过）。
EFI 相（smoke-image，32＋39）与 smoke-x86（7）为独立关卡（规则/07:27），v0 不并入
冻结集，列 Tier 1 完全体扩充候选（随首个 OEM 镜像回放需求裁）。

**Tier 轴说明**：Fuchsia tier 轴 = 覆盖政策渐进（RFC-0141）；BerryOS 在册裁定轴 =
承诺面分级（Tier 1/2/3 ↔ L0/L1/L2，与章程 §一对齐）。「Tier 1 先行」（12 号:77）
语义 = v0 只开通 Tier 1——政策面（变更伴随用例/全覆盖计划）作为横切纪律保留（§3.3），
不与面轴混编，防二义。

### 3.3 横切记账纪律（跨 Tier 生效）

1. **在野回归 = 用例欠账**：认证设备在野回归 → 必有一个缺失的 BCTS 用例 → 变更作者
   负责（RFC-0141 法则二直采，07 号 §1.5，:102）。
2. **compat 轨登记联动**：凡 `docs/API行为变更登记表.md` 登记条（双轨 §一）引发的
   语义变更，登记条须带 BCTS 用例号——Tier 2 起挂 CI；v0 先记账不挡合入（推断，待窗口）。
3. **新 L0 号准入**：设计值 = 新 syscall 号入册须附 Tier 1 用例位（smoke 族新增标记即
   天然满足）；词表预算审计（剩 8 号，37/45）另册——07 号 §7-4 的收口提案。

### 3.4 开通时点与认证的分级兑现

Tier 1 = 本稿开工；Tier 2 = 随 #83（配置簇）；Tier 3 = 随 V13。认证签发门槛 =
**已开通 Tier 全绿 ＋ 未开面过渡口径**：未被替换的面由官方实现自证（上游过全量
一次），OEM 增量件/已开放槽位替换件全测——基础件/扩展件分离（07 号 §6-11，:326：
总成本 ∝ Σ基础件×1 ＋ ΣOEM×增量，04 号 §8.1-2 契约负担转嫁的结构解）。

## 四、v0 实施规格（现役宿主钉死）

### 4.1 测试清单文件格式（冻结标记集清单）

`tools/bcts/frozen/bcts@<platform_revision>.toml`，TOML 全文示例：

```toml
# BCTS 冻结测试件清单（发布后只读；作废走台账 add-only）
schema = 1                        # add-only；未知键硬拒（berry-manifest 同族纪律）
suite = "bcts"
platform_revision = 0             # u32 域 [0,4294967295]（V9 同源词表、mkimage 同款；PR≡平台 level，示例取首冻件实值 0）
frozen_at = "<上游发版 commit sha>"
abi_snapshot = "abi@<short-sha>.toml"   # hash 钉同一快照点（§2.1）
abi_snapshot_hash = "sha256:…"
tier1_floor = 88                  # 空集守卫下限（§3.2）；条目数 < 此值 = 拒发拒跑

[[marker]]                       # Tier 1：现役 smoke 断言冻结化
id = "bare-01"
expect = "BerryOS boot"          # 元素内不含引号/右括号（markers.sh 单源约束沿袭）
phase = "bare"                   # bare | rootfs | rx
tier = 1
source = "tools/markers.sh@<sha>"

[[host_gate]]                    # host 面执法点（同点冻结）
id = "abi-check"
cmd = "just abi-check"
tier = 1
```

字段纪律：`schema` add-only ＋ 未知键硬拒；`platform_revision` = **u32 整数**（域
[0, 4294967295]，V9 同源词表、PR≡平台 level——`tools/mkimage.py:152-173/:212-217` 与
runner parse_frozen `tools/bcts-run.sh:120-122` 双侧同口径执法；v1.0 示例曾以带点字符串
示意，即 21 号 P2-7 点名的口径差，本版统一整数形）；`tier1_floor` 进工件本身（守卫不依赖
外部常量——单源自证）；marker 条目 = 冻结件的最小单元，删除 = 破冻（须走作废重发）。

### 4.2 runner 与宿主

载体 `tools/bcts-run.sh`（开工刀，闸位见 §4.5）。算法五步：

1. **解析清单**：`BCTS_FROZEN=<file>` 指定 → 回放态（冻结件对账）；缺省 → 活树自检态
   （清单取 `tools/markers.sh` 单源——freeze/thaw 双轨的活树轨，§2.3）。
2. **空集守卫**：清单条目数 < `tier1_floor` → loud 拒（防假绿；`tools/markers.sh` 尾部
   非空断言同族精神）。
3. **复跑全相**：与 `just smoke` 同入口调 `tools/smoke.sh`（八跑全相，构建依赖同源
   `just build`）——**v0 宿主钉死现役 just 配方树**（12 号 §2.4 蓝队补裁，:73/:77：
   「工程种子挂 smoke/abi-check 现役轨道……门禁不依赖任何未开工件」）。
4. **对账**：观测标记 ⊇ 冻结清单全集 ＋ `just abi-check` 前置同跑（Tier 1 host 门禁）。
5. **产结果包**：结果 ＋ per-boot 日志（`SMOKE_KEEP_LOG=1` 轮转产物）＋ 清单/镜像 hash
   ——hlkx 式 submission package 雏形（07 号 §6-7，:322），§5.2 认证提交件的本体。

### 4.3 新配方 `just bcts`（已落库，2026-11-11）

```just
# ---------- 已立法 · ADR #84（2026-11-10 落册）：BCTS v0 回放（冻结标记集清单对账）----------
# 宿主钉死现役配方树（#82 附录二 Q4 裁定）：复用 build + smoke.sh 全相，
# 零未开工件依赖；berry-assemble（V13）成型后迁组装门禁。
# 缺省 = 活树自检态（清单取 markers.sh 单源）；BCTS_FROZEN=<bcts@*.toml>
# 进回放态（冻结件对账）。清单条目数 < tier1_floor = 空集守卫 loud 拒。
# 独立关卡不并入主 smoke（规则/07 独立关卡纪律同族）。
bcts: build
    {{BASH}} tools/bcts-run.sh
```

### 4.5 迁移路径与闸位

v0（现役 just 配方树）→ v1（V13 berry-assemble 组装管线门禁，08 号 §3.1 步②同位）。

## 五、认证：元数据、流程与承诺

### 5.1 认证元数据 schema（含 Q10 披露位）

`berry-cert@<lineage>-<device>.toml`（签发物；schema add-only、未知键硬拒）：

```toml
schema = 1
device = "…"                        # 机型标识（OEM 自报 + 裁决核）
oem_lineage = "…"                   # Q1 星状分配；信任账本键（#77 承接）
platform_revision = 0               # 声称兼容版本 = 回放冻结件版本（u32 整数，V9 同源词表——对账 V9 列）
bcts_artifact = "bcts@0.toml"
bcts_hash = "sha256:…"
tiers_passed = [1]                  # 签发时已开通且全绿的 Tier 集
[caps_baseline]                     # 能力基线核（§6.2 十条逐条）
items_passed = 10
[closed_parts]                      # Q10 披露位（首批认证即在位，12 号:144）
contains_closed = false             # 「含闭源件」；true 时 items 不得为空
items = []                          # 闭源件五字段披露（与 V6 mkapp [blob] 声明同源）
[repro]                             # 可复现门槛（04 号 §4.5-3）
image_hash = "sha256:…"
measurement_rebuilt = true          # 度量链可由公开工件重建
[submission]                        # 执行留痕（hlkx 同构，07 号 §6-7）
logs_hash = "sha256:…"
signed_by = "oem-integrator"        # OEM integrator 钥（Q3 信封同钥族）
```

归属纪律（一事实一归属）：认证**状态机不在本 schema 立账**——cert_status/last_revision
单源 = 信任账本/签名索引（V4/V5，随 #77）；本 schema 只携结论快照 ＋ 账本指针。
`closed_parts.items` 只汇总不重立账，五字段事实源 = mkapp `[blob]` 声明（V6）。
Q10 披露位是「盖公章」话术滑坡的机器面防线（09 号 §7.2-2 判定，经 12 号:141 转引），
随 #84 落库、首批认证即带——对外话术纪律归治理文档（12 号 Q10 改判原文）。

### 5.2 OEM 自测 ＋ 平台裁决流程形态

Q4 补裁原文（12 号:74）：谁跑 = OEM 自测 ＋ 平台裁决；第三方测评不进 v1 裁定
（认证信用为零期无第三方可托），留重议触发。五步形态：

1. **取件**：OEM 从公开仓取冻结件 ＋ runner（开源免费，§5.3）。
2. **自测**：组装镜像 → `BCTS_FROZEN=<bcts@R.toml> just bcts` 回放 → 结果包
   （结果 ＋ 日志 ＋ 镜像 hash ＋ 度量链重组证明）→ OEM integrator 钥签提交。
3. **平台裁决**：复跑对账（同输入同 hash 重组）＋ 冻结件 hash 核 ＋ 基线核 →
   签发/驳回。裁决时限与申诉流程 = 开放问题（07 号 §8-5 自认缺运营面，§7.2-2）。
4. **结论落账**：认证标记挂 OEM lineage 与信任账本（治理结论，04 号 §4.5-5）。
5. **跟版**：Q12 N 窗口内完成跟版；超窗 cert_status 转 expired（账本执法，#77 承接）。

### 5.3 开源免费承诺

工具与测试集**开源免费可自测**（Q4 裁定，架构决策.md:275；Android CTS 模式——
07 号 §6-12，:327 ＋ 04 号 §4.1，:193 两源）。「BerryOS 兼容」**结论位**由平台签发
并挂 lineage/信任账本——结论位不是商品，商业条款（跟版 SLA/费率/商标）不进技术
立法（Q4 边界）。v1 治理杠杆仅认证标记 ＋ 信任账本两件纯技术件，平台明确不设
官方源独占/商店准入类商业准入（Q5 负面承诺，架构决策.md:228-229）。

### 5.4 信用弱点的诚实陈述

12 号 §5-1 自认最弱一处：「OEM 自测 ＋ 平台裁决」在认证信用为零期**没有外部对拍**
（06 号 §5.3「谁认证过你」）——本稿只能落形态，落不了信用。冻结件 hash 钉快照的
防特调结构性只覆盖「裁决是否可复现」，覆盖不了「裁决者是否可信」。缓解 = 结果包
全留痕 ＋ 复跑对账公开可验；根解 = 重议触发器 ①（第三方测评背书）或生态信用积累。

## 六、防特调与能力基线

### 6.1 防特调条款（结构性而非流程性，07 号 §6-7，:322）

1. **测项清单与测试工件均由上游签发、版本冻结、hash 钉快照**——OEM 无测试编写权，
   「测什么」不由被测者定（抄 CTF freeze/thaw 深层性质 ＋ HLK playlist 官方发布）。
2. **旧冻结件回放新组装**——特调任何当版行为都会被上一版冻结件抓住（时间差是
   结构性防线：OEM 拿到的测试永远滞后于其可动的行为面）。
3. **测试执行留痕**：结果包 = 结果 ＋ 日志 ＋ 度量链重组证明一体签名提交
   （hlkx submission package 同构，HLK step 8）。
4. **裁决复跑对账** = 同输入同 hash（可复现门槛联动）——「为通过测试而特调」的
   路径只剩「真的把行为改对」一条。

### 6.2 能力基线清单（不得砍面；04 号 §4.3 十条，:212-223 收编）

| # | 基线（不得砍/不得改） | 核验位 |
|---|---|---|
| 1 | L0 syscall 全集实现（在册 37 号、nr_ceiling=45 只加不删；禁「支持 30 个号」子集设备） | Tier 1 ＋ abi-check |
| 2 | L1 已发布接口全集（替换实现须说全量契约，禁「实现 fsproto 的一半」） | Tier 2 conformance |
| 3 | 最小系统应用集与卸载语义（SETTINGS/FILES/CAMERA 不可卸载、分发渠道不可卸载） | Tier 1 装载谓词族 |
| 4 | 能力词表不裁剪不私扩（G0 词表全网一致；特权只走系统签名＋白名单一条路） | 基线核（认证元数据） |
| 5 | 系统应用义务不可豁免（console=false/遥测近零/能力最小集/不豁免用户可见管控） | 基线核 |
| 6 | GUI 语义 token 闭集与官方 token 名保留（OEM 可改数值、不得删 token/冒用官名） | Tier 3 |
| 7 | 存储语义（零分区＋四棵树＋user/ 永不动＋树即登记簿；盘布局自由、归属语义不变） | Tier 3 ＋ 重组对账 |
| 8 | intent 词汇表冻结（OEM 调档不造词，0x06..0x0F 保留拒绝） | Tier 1 标记族（INTENT ok） |
| 9 | 签名链与度量结构（.sig 信封语义/账本水位/TLV 槽位表 add-only/四态语义不可变造） | 身份门槛 ＋ 可复现门槛 |
| 10 | 不承诺面保持自由（**反向基线**：调度延迟形态/errno 映射次序等 OEM 可调，BCTS 不锁） | 本表自身（防伪契约反向滥用） |

第 10 条与 §1.3 同源：基线防「砍面」，反向基线防「锁面」——两向都是承诺纪律。

## 七、重议触发器与开放问题

### 7.1 重议触发器（均为可观测事件，非意愿）

在册三条（Q4 裁定，架构决策.md:275）：

1. 首 OEM 要求第三方测评背书。
2. 冻结件维护成本超 CI 预算。
3. 门禁向 berry-assemble 迁移期出现执法空窗。

本稿新增两条（待 ADR 窗口确认）：

4. 首个冻结件发布时覆盖率报表显示 Tier 2 面零覆盖且 #83 未落册 → Tier 政策空转听证
   （12 号 §2.4 压力测试：最早暴露点 = #84 落库后首个冻结件发布，:79）。
5. BCTS harness 面（Tier 2 起）自身遭遇跨版本兼容破坏 → 测试专用 API 面
   （compat_test 档）单独立法提前（07 号 §6-10，:325）。

### 7.2 开放问题（不替拍板）

1. **冻结工件分发形态**：进仓（本稿设计值）vs 独立托管；OEM 自测执行环境（QEMU virt
   基线）由谁定义、真机面何时进门禁（07 号 §7-1 残余）。
2. **认证运营面**：谁审、审多久、申诉流程（07 号 §8-5 自认缺；Windows 五工作日是
   唯一锚点，未经一手核验费率）。
3. **商业模式条款**：商标授权关系与认证运营主体（04 号 §4.5-5；Q4 边界外）。
4. **测试专用 API 面**：BCTS harness 协议（启动被测服务/注入通道/收集断言）自身的
   兼容承诺单独立档（07 号 §6-10）——v0 无此面，Tier 2 起需要。
5. **新 L0 号准入挂钩**：§3.3-3 设计值是否升格为词表预算执法（07 号 §7-4）。
6. **Tier 2/3 数值下限的落数时点**：依赖 #83 槽位合同与 V14 清单（架构决策.md:253）。
7. **跟版 N 值**：首个 minor 发版节奏确立后、首份 OEM 合同签署前必裁（Q12 已裁公式，
   数值归治理文档）。
