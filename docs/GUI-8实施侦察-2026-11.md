## §3 六维详录（锚点均为 main @f888406 实读；gui3 树锚点已标注）

### 3.1 窗口与输入（launcher 拿到的输入已是路由后的 PointerEvent）

- 输入路由两跳：跨窗 hit test 归 gui-wmd（ADR #50「屏上有什么只在合成侧」防 clickjacking）；
  进程内命中 + 手势 referee 在 berry-ui hit.rs 现成（node_at topmost + per-pointer_id
  referee 产 Press/Drag/Release/Click/Cancel，Msg-only 零回调）。
- 输入协议（guiproto input 域，已冻结可消费）：INPUT_SUBSCRIBE（BATCHED/IMMEDIATE）/
  INPUT_POLL 可阻塞批拉 ≤3；PointerEvent 定长头 32B + 采样历史（CNTVCT 口径/整数物理像素
  Y 向下/pressure 毫单位）；「推送」一律建模为阻塞应答、零服务端主动 send。
- GUI-4 草案 §5.3 明文：input 域客户端端点经 gift 交付的消费者 = gui-wm——launcher
  不直连 inputd。
- gui-inputd 段② 收官于 gui3（1023072）：svcmgr 预拉 + boot 自验 + extras 交付（bsh
  inputpoll 走 libc input_h() 槽 hs[7]，客户端帽 35s > 服务端 POLL 帽 30s 纪律）+
  QMP input-send-event 注入往返 INPUTP ok n=3。
- ADR #58（gui3）：调度意图唯一词汇表 = berry_intent 六档（sched/src/intent.rs 冻结）；
  「两套并存终止期限 = GUI-8 桌面收官，SCENE 直通退役」——launcher 是归一词汇表第一个
  真实消费者；SDK 透传三口已预埋（spawn options 低 8 位/CHAN_OPT_NO_INTENT/
  pthread_attr intent 位，v1 内核只收 0）。
- ADR #60（gui3，GUI-6 冻结面）：容量帽一次到位 MAX_NODES 256→512 / CAP 512→1024 /
  DESC_MAX 4096→8192；「launcher 树规模实测立项时同步」= GUI-8 义务；MeasCtx 2KB +
  old_abs 16KB 栈面审计进验收（launcher 是 musl 用户程序嵌 berry-ui，栈预算直接吃这条）。

### 3.3 spawn 与应用生态（v1 无常驻 appd spawn RPC）

- 现状：.bap 拉起唯一路径 = svcmgr boot 批 app_launch（bap_scan → manifest 双守卫 →
  compat/net 拒 → ui_face → fs 四元授能 → spawn_rootfs_elf → 阻塞 collect_eof+reap）。
  svcmgr 全部 RPC 面只有 psproto 三 op——「点击图标 → 请 appd 拉起」通道今天不存在。
- 可复用原语：spawn_rootfs_elf + SpawnSpec 11 字段 + reap（bsh 同链）；cpio_find/
  cpio_names 枚举 app/ 直达。**reap 内嵌 wait 30s 绝对帽**——GUI app 常跑分钟级，
  launcher 须先自行 wait(child.hp, TERMINATED, 长帽) 再 reap（瞬回）。
- app_launch 守卫链是 svcmgr 私有（写在 main.rs 二进制 + static mut 窗，未抽 crate）——
  launcher 直行 spawn 就得复刻，或 GUI-8 抽共享 crate（触 svcmgr 改刀，与 0c 在途面
  冲突待查，见 §6）。
- fs 授能串行约束：fsproto 严格串行无请求号，双读者 = 应答偷取；launcher 给 app 授 fs
  词时，launcher 自身（布局持久化）与 app 的读者互斥必须进设计；现役解法 =「授出去的
  端点 dup 一份子自持 + 父收口后再用」。
- boot 批与 launcher 按需的模型冲突：boot 批全量拉起会把 GUI app 在桌面出现前跑完退出
  （app_launch 阻塞 reap 真码 0 才计入 APP ok）——boot 批对 GUI 类 app 的处理（跳过/
  留给 launcher）需裁决，且动 APP ok 语义 = 动 smoke 标记契约。
- display 能力词：[capabilities] v1 恰 console/fs/net；berry-manifest 测试以 display=true
  钉住「unknown key 硬拒」。GUI app 被拉起后如何拿到显示/输入面（扩词表 add-only 双侧
  同步 vs launcher gift 直授 via extra_gifts vs 等 GUI-5 wmd 窗口面）待与 GUI-5 联动裁。
- .bap 增删事件：扫描/记账全就位、推送零机制；且 v1 rootfs = 静态 RAM cpio，运行期无
  增删物理通道（安装 = v2 /apps 树）——GUI-8 落「boot 枚举 + 事件通道占位」还是全量
  事件面待裁。label 消费 = launcher 直读 manifest Ui。
- berryctl gui 落 GUI-9/SDK-1 不在 GUI-8 刀内；但布局 JSON 按「可序列化描述结构」定形
  （GUI-9 注入器复用位）。

### 3.4 持久化与布局 JSON（全链就绪，唯缺解析器与 schema）

- 唯一跨 boot 可写落点：FAT12 卷根 8.3 大写名单文件。`.JSON` 四字符扩展名装不下 →
  **LAYOUT.JSN** 形；根目录 16 项余量充裕；FAT 无删除（v2）→ 布局文件生命周期 = 只覆写
  不可删，覆写幂等已证（B4 三 boot）。
- 写路径契约现成：std File::create+write+drop 自动获得「PUT 累积 + close TRUNC commit」，
  无需新 fs 面；跨名写自动先 commit 旧槽。
- **≤2048B 单簇帽推导**（侦察期推导，实施设计须追认）：单簇文件掉电窗终态 = 旧版全文/
  新版全文/缺席三态（读簇 0 直取 root.first 不验 FAT，半文件死状结构性不可达）——布局
  JSON 钉 ≤2048B = 白赚构造性近原子。协议帽 FILE_SIZE_MAX=16KiB/CHUNK=192/簇 2KiB。
- 仓内 JSON 解析器真值 = 零（全代码 grep 仅 berryctl 注释 + host Python json）。刀形 =
  新纯函数 crate（暂名 berry-json/berry-layout）：零分配零 unsafe 零依赖、输入只借用、
  no_std + host 测挂 just test-host——berry-manifest 家族第 8 例（loader/fsproto/virtio/
  blkproto/fatfs/netproto/netdproto/tcp 之后）。
- schema 六律（manifest/mkapp 先例蒸馏）：① 显式版本域 + 未知版本 loud 拒 + 键 add-only；
  ② canonical 键序发射（smoke 跨 boot 逐字节对拍前提）；③ 语法子集冻结到字节级（LF-only/
  纯十进制/限可打印 ASCII，布局值域本就窄：app id [A-Za-z0-9._-]、页/行列数字）；
  ④ 帽常量 crate 单源 + host 工具镜像双侧同步；⑤ 失败降级 loud（拒 + 回落默认布局 +
  eco 诊断行，绝不半接受）；⑥ 确定性输出（同布局同字节）。
- 数据模型参照已钦定：OpenHarmony LNCH 逐格一行（typeId/page/row/column/keyName UNIQUE）
  + JSON 主存——「数据模型照抄，介质换 FAT + JSON」。布局文件只存排布不存资产
  （图标/label 从 appd 资产面取）——schema 更小更稳。
- fs 通道单活跃客户拓扑（本维唯一悬而未决）：现役装配 = svcmgr 持 fs_a → dup 交 bsh →
  spawn 后关 fs_a_h 使 bsh 成唯一读者；launcher 若长驻持 fs 端（布局读写），与 bsh 的
  并存/让位装配序必须在 svcmgr gift 装配面裁决。
- mkfat 默认盘不预置 LAYOUT.JSN（预置破「默认盘字节零漂移」须重产 fixture）；不预置则
  launcher 首写建文件（缺席 = 默认布局），smoke 断言取后者更简。

## §4 待裁清单（按阻断度排序；裁者 = GUI-8 设计草案立稿时——**已裁毕**：草案 §3 裁决书承袭编号逐条落判 2026-11-03，四段已全落 2026-11-03..06，本节转为史实留档）

1. **裁决一（验收面结构性）**：「跨 boot 保布局」与 GUI 目验不能同路——EFI 路无 virtio
   面（smoke-image/run-efi 均钉死不挂 virtio-blk，FAT 写走 vblk RPC）。两择：a) 布局
   持久化以 headless selftest 挂 rootfs 相/持久化相（复用「不重造盘复用已写盘 + 跨 boot
   读回断言」方法论，FBW/FATW 各守一路的现役结构，零新面）；b) 给 EFI 路开可写面
   （动 EFI 断言面形制 + 无 virtio 先例）。侦察倾向 a。
2. **裁决二（spawn 转发路径）**：launcher 直用 berry-exec 自翻 manifest（复刻/抽取
   app_launch 守卫+授能面）vs 给 svcmgr 加常驻 spawn RPC（psproto 扩 op 或新协议 crate，
   单线程架构插入点要评估）vs 混合（boot 批收窄 + launcher 按需）。连带：boot 批对 GUI
   类 app 的处理 + APP ok 语义联动。
3. **裁决三（布局 schema）**：版本域形态（单 schema_version vs 对齐 ADR #56 三值域）+
   执法位（设备端拒旧 vs 宿主编译期查）；≤2048B 单簇帽是否钉为 schema 硬帽；canonical
   发射器放 launcher 内嵌还是独立 crate + host 门禁（AI 生成面会复用，宜独立 crate）。
4. **裁决四（拉起与拓扑）**：launcher 由谁拉起（svcmgr 预拉 guifbd 同款）+ gift 清单
   （rootfs RO + fs 端 + present/hdi/input 端）+ fs 单活跃客户的让位序 + 监督重启链
   由谁执掌（裁决 E 兑现件）。
5. **等 0c 冻结联动裁**：状态栏/壁纸归属（launcher 进程内 vs gui-wmd 系统窗——规划 §3
   倾向 launcher 内）；display 能力词 vs GUI-5 窗口面；「失焦」感知机制（全屏独占窗
   时代如何观测）；多 surface 同席 surface_id 分配。
6. **壁纸形态**：BYI1 65536px 帽装不下 800×600——纯色/程序化（FillRect 现成）/自定义
   资产通道/launcher 自解（无缩放约束连带）。
