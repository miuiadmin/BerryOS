## 一、执行摘要

**总路线 = 「WebGPU 形态原生 API（berry-gfx）+ vello 生态光栅后端 + 信号驱动保留树 UI + vsync 锚定帧调度 + 停帧优先低功耗」五层一体的全 Rust 原生栈**，以「像素永不过 IPC、damage 一等公民、**API 语义与遥测骨架 day-one、机制分刀落地**（对抗校验修正：不喊『全部机制 day-one』——v1 只含子集，映射表见 §三）」为三条铁律，分 v1（QEMU ramfb 软渲染）/ v2（virtio-gpu）/ v3（真机 tile GPU）三档推进，每档为上档留零 API 破坏的升级缝。

六条裁决的落点：**最先进** = vello sparse strips（硕士论文实证大形状超过 Skia/Cairo）+ Google Graphite 官方路线图同向 tile/compute 光栅；**移动端** = tile GPU 语义（render pass/load·store/带宽=功耗）+ ambient 双态 + 输入重采样预测进 API 第一性概念；**安卓教训 + 低功耗** = 12 条机制清单（§三）语义/骨架先行 + 停帧优先三件套；**API 兼容** = WebGPU 语义原生采用 + 三条兼容层执法（§二轴二）；**开发套件** = HTML 形态 DSL + 信号核 + AI 友好三件套（机器可读 schema/金样语料/官方 skill 文件）。

## 二、五轴定案

### 轴一：渲染核心 = 自持编码层 + vello 生态（spike 过门定后端）

**定案**：berry-gfx 自持 display list 编码层（学 WebRender 三段管线中间表示），光栅后端可整体替换。**v1 后端主从关系（对抗校验修正）：依赖审计 spike 过门才定 vello_cpu 为默认后端；spike 不过则内联 sparse strips 思想自研子集**——论文优势证据集中在「大形状」负载，UI 主负载恰是小形状/圆角矩形/字形密集区间，且其线程池形态在 musl 子集上未审计（多线程在 v1 单核零收益）。编码层 v1 操作集只覆盖 fbcon 六原语超集 + 文本 glyph-run 位（防过度设计）。v3 升 vello_gpu（wgpu）。

**文本栈拆三刀定序（对抗校验修正——原文全生态直依改分刀）**：skrifa 灰度字形（无 ICU4X 依赖）先行 → harfrust shaping（HarfBuzz 官方 Rust 移植）独立审计 → parley/ICU4X 单独立项**出完体积账**再定（ICU4X 是文本栈依赖不是 vello_cpu 依赖——归属修正，防 vello spike 过门而文本栈账爆表的假绿灯）；CJK 断行可先简单规则过渡。目标态全生态：skrifa 解析光栅 + fontique 枚举回退 + harfrust shaping + parley 布局断行 + glifo glyph-run，灰度 coverage atlas + fractional positioning。fbcon 点阵降为 boot/诊断层与字形单源。

**第一前置刀 = FPU/FPSIMD 上下文保存（ADR #34 trap+lazy-save）**：现状 boot 写 CPACR_EL1.FPEN=0b11 且 TaskContext 只存整数——今天任何任务用 SIMD 都在跨任务静默串味，这是硬门不是优化项；该刀 ADR 需带 trap+lazy-save（首 FP 用户出现才付保存成本）vs 全量保存的量化对比。

**否决**：Skia/rust-skia（C++ 巨库几十 MB + 源码构建 18 分钟起 + feature 裁剪困难 + 本仓无 C++ 用户态工具链——Graphite 方法论 Recorder 分离/启动期全量预编译全盘吸收，实体永不引入）；tiny-skia 当主引擎（作者自定位研究项目、单线程、无文本、ARM 慢 1-3x——留作对照基准）；Flutter Impeller（C++/Flutter 绑定不可依赖；「一切 shader 离线编译、运行时零编译」立法全盘吸收——安卓 shader 编译 jank 的根治法）；WebRender（MPL-2.0 只借语义不搬文件：display list→scene→frame 三段管线、tile/picture 缓存、合批+深度剔除、合成器交接）；makepad（渲染层与 widget 框架强耦合，留作开发套件形态参照）；google/forma（已归档 + 移动 GPU 翻车公开样本）；Blend2B（C++/zlib + JIT，留作 CPU 对拍基准）；llvmpipe/lavapipe（**结构性论据（对抗校验修正）：LLVM JIT 依赖树 + musl 子集 std 无法承载运行时代码生成**；host 侧对拍工具另论）；自研六原语当渲染核心（撑不起「最先进」——无路径/抗锯齿/合成/文本，等于重造 vello 已解决的问题；六原语只留 boot/诊断层）。

依据：github.com/linebender/vello、LaurenzV/master-thesis、blog.google/chromium/introducing-skia-graphite-chromes、docs.slint.dev 四后端矩阵。

### 轴二：渲染 API = WebGPU 语义原生子集 + Magma 模式内核面

**定案**：应用面 API 取 WebGPU 形态语义子集（device/queue/texture/render pass），**CPU 软渲染实现是第一实现而非回退实现**——语义在软渲染档就钉死，硬件后端换实现不换 API。语义子集的**边界清单（哪些 WebGPU 概念进 v1、哪些 v2/v3）随 GUI-2 ADR 落纸**（对抗校验补——防「子集」无限膨胀成全量）。呈现层按 compositor 模型自有原语（surface/buffer-queue/acquire/present + present mode immediate·mailbox·FIFO + damage + presentation-time 反馈，Wayland 十年验证的最小完备集）；渲染 API 本身不含屏幕概念。

内核/服务面按 Fuchsia Magma 模式映射：GPU 代码零进内核、持证 GPU 服务进程 = MSD 等价物（驱动=持证应用）、buffer=VMO、fence 走协议层、feed-forward IPC（服务永不阻塞客户端——**写成显示服务协议的可测断言**，服务端 wait 帽=心跳非死线，echo 服务 Gotcha 同法）、错误按连接收敛 device-lost。

**「兼容 ≠ 好适配」执法三条**：(1) WebGPU 兼容 = **语义形态亲和：概念/命名 1:1 对齐，教程与 AI 语料直接可用（对抗校验修正——原「wgpu 生态可直接对话」超卖：真 wgpu 应用需 WGSL 编译器/bind group/完整纹理特性枚举，CPU 语义子集承载不了任何真实 wgpu 程序）；真生态互操作的唯一路径 = v3 把 wgpu 本体（wgpu-hal 自研后端）跑起来，量级差按 v3 承诺管理**；(2) Vulkan 兼容只到 wgpu-hal/ash 层（v3 移植者在 HAL 层适配，不承诺跑 Vulkan 二进制——「不跑 Linux 二进制」立场的延伸）；(3) GLES 永不写原生驱动，兼容走 ANGLE 式翻译层（远期）。**原生路径 = berry-gfx + 自研后端；兼容层永远在翻译层/HAL 适配层，不在原生路径内部。**

**fence 语义（对抗校验修正——原「timeline semaphore 可直接铺在 event/wait_many 上」过强）**：仓内 Event 是位掩码单次置位语义，timeline 需要单调计数值序；v2 fence ADR 定原语形态 = 「共享内存单调 seq 号 + Event 唤醒 + 超时回退」组合，timeline 语义铺在协议层；生产者假死等多久、谁有权宣告缓冲可用，一并入 ADR。

**ABI 单源（对抗校验修正）**：display list 序列化与语义树 schema **不进 abi.toml**（那是 syscall 冻结面的唯一事实源，节奏不同会绑死两套版本纪律）——同一生成工具链、不同 schema 源文件（tools/gfx_abi.toml、tools/ui_schema.toml），版本化纪律分开表述。

**否决**：Vulkan 直出应用 API（产业实际 = Vulkan 底座 + 受控上层，应用直写验证/安全成本极高）；自有孤立抽象（生态零承接、AI 语料零覆盖，违裁决 ⑤）；载入 Mesa/GL 翻译层/Vulkan ICD 实物（无 Linux ABI、无 C++ 工具链、31 号 syscall 撑不起——结构性不适）；glow/GLES 栈（无 EGL/GL 环境无处落）；应用直写裸 framebuffer（违分层铁律——GUI-1 的 fb 授能只到显示服务为止）；「画完立刻 blit」式 present（无 present mode/无时序反馈，帧节奏退化为应用职责——安卓 Butter 前史）。

依据：khronos.org/blog/vulkan-is-now-the-official-graphics-api-of-android、fuchsia.dev Magma design、docs.vulkan.org tile_based_rendering_best_practices（Mali 16×16/Adreno FlexRender/PowerVR TBDR 全 tile 系）、wayland.freedesktop.org。

### 轴三：UI 框架 + 开发套件 = 保留树 + 信号核 + HTML 形态 DSL

**定案**：三件套。v1：berry-ui 保留树（GUI-3 骨架不变）+ berry-signal 纯函数 crate（TC39 Signals 语义：State/Computed/依赖收集/push-dirty pull-eval，**故意不含 effect**——调度权归帧循环；依赖收集**零堆分配**照遥测环纪律立规矩、host 测钉板）+ 布局移植 Taffy（flexbox+grid，MIT 可内联，GridLayout 退为 flex-wrap 特例；**过 crate 预检**：Taffy 内部 f32 运算在 host 金样对拍容忍 ULP 级漂移，断言策略先定）。

**三层管辖权显式裁决（对抗校验补）**：模型归属 MVU 可序列化状态树（可测试/可热迁/可快照）、失效归属信号核、遍历归属 Xilem 式 id-path + &mut 下传——一句话写死防「两套状态路径并存的缝合怪」；v1 验收件加三层并发钉板用例（如 SwipeView 拖动中异步数据到达 + 动画进行中）。语义树 day-one 第一类（一棵树三消费：无障碍/UI 测试断言/AI agent 检查，schema 版本化，源文件见轴二）。

v2：**HTML 形态外部 DSL**（语法靠近 HTML/JSX，事件/状态层用原生概念 channel/signal/intent）双执行档：开发态解释器热换（秒级、状态保留，slint-interpreter 形态）、发布态 AOT 编译进 .bap。**转译定位（对抗校验修正——原「HTML/JSX 无损转译」结构性不成立：HTML 绑定层是任意 JS 表达式 + CSS 全集）= 结构子集定向转译 + 转译器输出覆盖率报告（未映射节点显式列出）**；「HTML 作 LLM 枢轴语言」策略本身成立（WebSight 200 万对语料、Design2Code、v0/Figma Make 全 HTML 输出），不靠「无损」撑腰。语法借 Web 语料 = 能兼容；运行时是原生信号驱动保留树 = 原生适配——裁决 ⑤ 的 DSL 版执行。工具链 = LSP + live preview + 检查器（视图树/语义树/信号图 JSON over channel，复用遥测环/psproto 形态）+ Figma 插件导出 + 截图→HTML→DSL 转译桥；grammar/schema 与解释器同 commit 纪律，四层对拍金样（DSL→视图树→语义树→像素）定为发布门槛。AI 友好三件套随 DSL 交付：机器可读 grammar/schema、金样语料库（兼作回归测试）、官方 AI skill 文件。

**否决**：Slint 本体（GPL-3.0/royalty-free 双轨且免费面不含嵌入式商用——仓内纪律禁入；其四后端矩阵取舍表与工具链打法免费借用）；egui/立即模式、Bevy ECS UI 作应用框架（每帧全重建与移动省电对立、布局/文本/IME 面浅——立即模式仅保留一个合法生态位 = 系统内部调试叠加层，不进产品面）；proc-macro 唯一路线（借用检查器报错面向 Rust 专家非设计师）；Makepad 内嵌 DSL（字段失配运行时 panic、id!() 写错静默空句柄——工具链脆弱面实证）；setState 式子树重建（粒度最粗的浪费形态）；Cassowary 约束布局（性能代价大，只配进设计工具自由排版）；自研布局单算法（flexbox 是 Web 背景开发者与 LLM 最熟悉面）；JS/ArkTS 语言前端（已裁）。

依据：github.com/tc39/proposal-signals（Angular/Vue/Solid/Preact/Svelte/Qwik 共同背书）、raphlinus.github.io/ui-architecture、slint.dev、huggingface.co/blog/design2code、zed.dev/blog（GPUI 生产级参照）。

### 轴四：响应性能架构 = 安卓教训语义/骨架先行

**定案**（12 条完整清单 + 三档映射见 §三）：vsync 单一时钟源 + 相位化回调序（INPUT→ANIMATION→TRAVERSAL→COMMIT）+ app/compositor 相位错开（QEMU 期软 vsync 时基起步，DispSync 模型思想）；UI 线程与渲染线程分离（UI 线程只录 display list、像素生产全在渲染线程、纯属性动画 RT 直驱——**软渲染时代就按此分层**，未来接 GPU 不换架构）；像素永不过 IPC（buffer = VMO 句柄 + 槽位号 + 元数据 + fence，**每帧跨进程调用 ≤1 次只传元数据** + 一帧内事务合并）；合成器多图层模型（overlay 式直通 + 遮挡感知 + latch 超时不阻塞应用）；FrameTimeline 双时间线遥测 + 责任归因（写入遵守遥测环**零分配零切换**纪律，帧 token/双时间线字段用预储槽）；背压与缓冲深度自适应（双缓冲起步懒扩 + buffer stuffing 检测）；输入 vsync 对齐 + 重采样 + 预测 API + unbuffered 通道；输入通道独立不与 UI 串行争锁（控制类字节落状态机中段必须复位后照常处理——本仓 editor 0x03 落 CSI 中段 Gotcha 完全同型，输入子系统一并立法）。

**「每帧禁 channel」的论据口径（对抗校验修正——原引「TCG 单次串行 RPC ≈0.8s」失真：那是 fs→vblk→设备多跳扇区链的链路成本，不是裸 channel 往返，fastpath 验收线 <1200 cycle）**，真实三件依据：① 结构性——channel inline ≤256B/深 8 装不下 1.83MB 像素（800×600×4）；② 环境性——TCG 多跳调度等待昂贵（P6 A-6 成本模型的本义）；③ 纪律性——IPC 设计 §7 决策 #5 明文「热路径走共享环」且点名「块/net/图形」统一 SPSC。结论保留但放宽：「每帧 ≤1 次元数据提交」是预算纪律；真机档 channel 控制面合法、TCG 档控制面走 SPSC+Event。

**否决**：无 vsync 锚的定时器动画（Butter 前史，相位漂移 jank 之源）；单线程 UI+渲染（实测 76ms 触摸→呈现中 RenderThread 仅 7ms、最大头是主线程 21ms 等待 + 首帧错过一拍 vsync 50ms——**大头不在绘制**）；恒定 triple buffer（多一帧输入延迟 + 滋生 buffer stuffing）；每帧 channel 传像素（TCG 必死 + 装不下）；合成器阻塞应用侧（SFCpuDeadlineMissed 型整机掉帧——合成路径必须有不依赖应用配合的时限）；固定 ms 阈值 jank 判定（跨刷新率不可复用——按预期时间线偏差 + 帧号连续性断言，同「smoke 标记不得建立在竞速上」纪律）；全量重建/动画中 measure·layout（View 原罪 double taxation）；GC 类停顿（Rust 生而免疫，但立**帧路径零分配**纪律）。

依据：source.android.com/docs/core/graphics/implement-vsync、androidperformance.com Perfetto 实录、perfetto.dev frametimeline。

### 轴五：低功耗 = 停帧优先 + AI 调度协同

**定案**：停帧优先三件套 day-one：无变化不产生帧（渲染任务完全挂起而非降帧轮询，最后帧保留——与 tickless 同构，**帧驱动是显示系统的周期 tick 必须 day-one 消灭**）+ damage 一等公民（present(buffer, damage_clips[]) 从 v0 起带脏区——**「无 damage 不提交」直接写进 GUI-1 的 present 协议首版**，对抗校验补）+ 合成结果缓存复用（输入代际号 + damage 空集判定跳过整次合成——软件层 PSR 等价物）。**软 vsync 发生器按需起振（对抗校验补的显式不变量）：无注册回调者即停，写进显示服务协议 + smoke 断言（稳态下定时器唤醒计数为 0）——否则周期定时器把 tickless 偷偷请回来。**

interactive/ambient 双态会话（归 PM 服务执法非应用自觉：帧率帽 1Hz→每分钟、低色深、防烧屏周期偏移、on-pixel ratio ≤15% 同量级、违例可拒）；帧率投票 + vsync 档位契约（ARR 约数分频语义 + notifyExpectedPresent 同构）；多层 overlay 式合成模型（API 按 layer list 设计，软件实现起步、DPU/HWC 接入零 API 破坏）。

**ADPF 同构渲染 hint 回路接 AI 调度（对抗校验补边界）**：帧预算 target vs 实际耗时 actual 上报 → **复用现有 berry_intent 档（0x01 LC/0x02 交互）+ EPP 组合表达，任何扩表过 ADR #42 冻结边界裁决（0x00–0x05 已冻结、0x06..0x0F 保留拒绝）** + 场景事件 Increase/Reset/Spike（动画开始/结束/静止）+ idle 停帧时**整条撤声明（intent 和 EPP 都撤**——只撤 intent 会留半条回路）。与 ADR #42「intent=策略输入、凭遥测入场、带内干涉」严丝合缝，帧 pacing 遥测作 M4 带宽调度入场券。提交通道 SPSC 共享环非逐帧 RPC（IPC 设计 §7 立法的第一真实消费者）；功耗遥测面（脏区面积/层数/合成路径 SW·HW/帧率档/背光档）进遥测环。

**否决**：降帧跑完整管线（停帧+保留 > 稀疏重绘 > 连续低帧率重绘——Wear AOD 冻结帧 vs 管线照跑的教训）；60fps 常流 + 应用自律省电（帧驱动与 tickless 对立）；恒定帧率不投票（ARR 约数分频 + 满足各方约束的最低档才是移动端正解）；逐帧 channel RPC 提交；AI 直接设频率/选帧率档（违带内干涉纪律——AI 只在 intent/EPP 档位表内选、凭帧 pacing 遥测入场）；overdraw 默认不设防（合成器内建遮挡感知 + 开发态 overdraw 可视化计数器）。

依据：developer.android.com/training/wearables/always-on（ambient 数字齐全：AMOLED 全亮静态 300-400mW vs AOD mW 级）、source.android.com arr/performance-hint-api/hwc、docs/IPC设计.md §7。

## 四、分阶段路线

**v1（QEMU ramfb 软渲染期）**：FPU/FPSIMD ctx 前置刀（GUI-0，或并入 GUI-2 前段）；GUI-1 fb 授能收口（在途——present 协议首版就带 damage 语义）；berry-gfx 编码层 + 后端 spike（vello_cpu 过门才定，备胎内联自研）；软 vsync（clock_read + thread_sleep 绝对时刻重臂，零新内核机制）+ Choreographer 帧循环 + 单 GUI 进程 UI/渲染双线程（T-1 线程面已可用）+ display list 录制/回放 + 脏区合并；berry-signal + Taffy + 语义树常驻；DFX 三件 + FrameTimeline 骨架；**测试底座随 GUI-2 首刀先立：QEMU ppm screendump 端到端像素对拍 + golden image 回归（对抗校验补——「AI 测试友好化」支柱在 GUI 面的落点）**；icount 量帧成本（wall-clock 只观察不断言）；停帧 + damage + 合成缓存。留缝 = 后端中立 trait、render pass/load·store/damage/present mode 语义 day-one 在场（CPU 实现可忽略其优化但语义必须在场，否则换硬件后端 = 破坏性 API 改版）、display list 序列化 schema（gfx_abi.toml 独立源）、intent/EPP 编码位、SPSC 共享环、双缓冲 flip 语义 API（ramfb 后端 memcpy 降级实现）。

**v2（virtio-gpu 期）**：**首刀 = virtio-gpu 2D vs ramfb 直写 icount 定标刀（对抗校验补——数据决定 2D 档是性能件还是纯语义件；AAVMF+TCG 下 2D flush 吞吐未实测，若 flush 路径成本高则 2D 档只给干净双缓冲语义）**；自研用户态 virtio-gpu 驱动（berry-virtio 框架 + vblk/vnet 先例，三档：2D 资源模式宿主无关（macOS 开发机可跑）→ Linux 宿主 virgl → Venus/rutabaga 远期跟踪，Venus 先决条件 QEMU≥9.2+hostmem/blob 写进里程碑）；独立合成器服务裁决（前置门槛 = 跨进程共享 VMO 零拷贝首消费验证 + SPSC 共享环先立；**窗口协议以 GUI-5 gui-wmd 在册设计为必要输入显式衔接**）；fence ADR + buffer collection 协商（format+modifier+usage 三元组，AFBC modifier 位留位）；vello_cpu 多线程吃 SMP（S 线）；输入重采样/预测 + 帧率投票 + ambient 双态 + timer slack；DSL 解释器 + LSP + live preview + Figma/HTML 桥。

**v3（真机移动 GPU 期）**：vello_gpu（wgpu）+ Vulkan 后端（真机或 Venus）——**真 wgpu 生态互操作在此档（wgpu-hal 自研后端），前面档次的「WebGPU 兼容」只是语义形态亲和**；wgpu 寄宿成本专项 spike（std 面/T-1 线程面/ash 加载/surface 钩子：「wgpu-hal 加自研后端 vs 自建 WebGPU 形态 API」）；Impeller 式离线管线编译立法（shader 随系统镜像/应用包预编译、帧内零编译停顿）；ADPF 式 workDuration 申报接 AI 调度实装；硬件 vsync + 真 present mode + front buffer 直通 + unbuffered dispatch；PSR（软件 dirty 纪律是其前置）/DPU overlay/硬件 cursor/LTPO ARR/面板能力谱系枚举（刷新率/双稳/全刷新周期/burn-in 风险/on-pixel 功耗不对称——AMOLED 黑省电 vs LCD 黑白一样费，ambient 策略按能力自动选）+ partial update 面板原语（e-ink/memory LCD 的 update-vs-stream 统一缝）；Subsecond 式热补（需内核配合：代码页重映射 + 能力模型下 W^X 裁决，够格立 ADR）+ 完整 CJK 文本栈。

## 五、风险与开放问题

**综合报告自带 8 项**：① vello_cpu 依赖审计（已升格为带 kill criteria 的正式门，见轴一）；② FPU ctx 刀排期（硬门）；③ 软 vsync 反馈源（ramfb 无 TE——定时器时基起步、时序断言走 icount 通道 B-2 先例）；④ fence 微内核等价物（v2 ADR，见轴二）；⑤ damage 跨进程信任（见下补漏 ③）；⑥ 128MB 帧缓冲预算（1.92MB/帧双缓冲宽裕，字体/图标缓存须过 32MiB VMO 帽 + 大块连续 buddy 陷阱——逐页 commit + LRU 限帽）；⑦ wgpu 寄宿成本（v3 前专项 spike）；⑧ CJK 文本闭环（harfrust 只管 shaping，中文断行/竖排/回退链无成熟 Rust 方案验收——移动端主战场硬需求，单独立项）。

**对抗校验补漏 9 项（遗漏面回填）**：
1. **色彩管理/色深留位**（五轴与仓内规划全文零提及 sRGB/Display-P3/HDR、传递函数、10-bit）——移动端广色域近端默认，不留 color space/格式枚举概念位 = v3 面板接入时又一次破坏性改版（与 render pass 语义必须 day-one 的论证完全同构）；修法零成本：v1 格式枚举 + surface color space 元数据位。
2. **字体资产与授权账**——CJK 字库单款 5-20MB（Noto Sans CJK OTF 约 16MB）对 48MiB 盘 + 21.5MiB rootfs 是硬冲突；OFL 授权嵌入条款、subset/按需分片、运行时字形 atlas 内存帽全没算——「先算账再选型」强制适用。
3. **GPU/显示安全越权面**——damage 申报信任（恶意申报小脏区实写大区域的服务端校验）、图层内容窥探、截屏/录屏能力授予与隐私指示器（类比摄像头/麦克风指示器；截屏能力在 GUI 规划附录 B 有，应回填衔接）。
4. **IME/文本编辑协议留缝**——组合态/preedit 显示/候选窗定位是 v1/v2 文本编辑组件的 API 面问题；不留缝 v3 补 IME = 破坏性改版；至少 day-one 在文本组件 API 留组合态回调位。
5. **多显示与热插拔/DPI 谱系**——外接屏/折叠双屏/密度变化的资源再生与布局重算；面板谱系要加几何/密度/色域维度。
6. **窗口管理面衔接**——五轴默认「每 surface 一层」但没轴 owns 窗口协议；GUI-5 gui-wmd（两层窗/Z 序/避让/WindowInfo 推送）已在册，v2 独立合成器裁决时显式衔接。
7. **GUI 资产/缓存字节级预算表**——图标/图层缓存/字形 atlas/帧缓冲池在 32MiB VMO 帽 + 单块连续 buddy 陷阱下的具体账，随决策落纸。
8. **无障碍消费端归属**——语义树 day-one 只覆盖生产者侧；消费侧（屏幕阅读器/显示缩放/高对比度）+ RTL 布局镜像与本地化资源限定词（parley bidi 只解决文本不解决 UI 镜像）应在路线图点名挂账。
9. **GUI 测试基建**——QEMU ppm screendump 端到端像素对拍 + Noop 式录命令流断言 + golden image 回归，随 GUI-2 首刀先立（已并入 §四 v1）。

## 七、决策点（需用户拍板，附推荐）

1. **原生 API 形态**：berry-gfx 取 WebGPU 形态语义子集（**推荐**——教程/AI 语料/工具链公共语言白得，CPU 实现为第一实现）vs 自有孤立抽象。影响全部下游 API 面与 SDK，越早定越好。
2. **vello 依赖策略**：先跑依赖审计 spike（musl 子集 libc 面实测 + ARM64 NEON 对拍 Blend2D/tiny-skia + 小形状 UI 负载对拍），过门才定直接依赖 vello_cpu，不过内联 sparse strips 自研子集（**推荐 = spike 后定，主从关系见轴一**）。
3. **Skia 依赖否决确认**（用户点名问过）：**推荐永不引入**——C++ 工具链缺失/体积几十 MB/构建链 18 分钟起三重结构性不适；Graphite 与 Impeller 方法论全盘吸收。
4. **FPU/FPSIMD ctx 刀排期**（ADR #34 trap+lazy-save 落地）：一切浮点渲染数学/SIMD 光栅/物理动画的硬前置——**推荐作为 GUI-0 插在 GUI-2 前**。
5. **DSL 语言载体**：HTML 形态外部 DSL（**推荐**——LLM 语料最佳覆盖 + 解释器热重载 + 设计师免借用检查器）vs Rust 宏 rsx 唯一路线 vs 双轨（宏先行 DSL 后补）——v1 末拍板，决定 SDK 主交付物形态。
6. **独立合成器服务（SurfaceFlinger 形态）拆分时点**：v2 裁决还是继续单进程内嵌——前置门槛 = 跨进程共享 VMO 零拷贝首消费验证 + SPSC 共享环落地；berry-gfx/berry-ui API 面无论迟早都从第一天按可拆分形态设计。
7. **intent 档位表边界**：显示/渲染会话**复用现有 0x01/0x02 档 + EPP 组合**（推荐）还是开新档（如 INTERACTIVE_FRAME）——ADR #42 冻结段的扩表裁决，影响 AI 调度接入面。
8. **virtio-gpu 2D vs ramfb 直写定标刀排期**：icount 通道对拍两者 flush/呈现成本——决定 v2 显示后端默认与双缓冲语义落点（**推荐 = v2 首刀**）。

## 八、对抗校验结论摘要

22 条裁决：**sound 13 / risky 7 / wrong 2**。两处 wrong（「wgpu 生态可直接对话」超卖、「HTML 无损转译」超卖）均已内联修正——两者都是把「语料亲和」卖成「生态互操作」，恰是裁决 ⑤ 要防的兼容幻觉。risky 7 处（vello_cpu 主从关系、文本栈拆刀、fence 协议层化、0.8s 引用口径、「全部 day-one」措辞、三层管辖权、abi.toml 分文件）全部回填正文。总评：五轴主体架构经得起推敲——GPU/显示零进内核、像素永不过 IPC、停帧+damage+合成缓存、SPSC 图形通道（IPC §7 明文点名）、Magma 三件套映射、FPU 前置刀（硬门非优化）全有仓内资产或先例可挂；未发现违宪建议（GPL/Slint 处置、WebRender 只借语义、MPL 不搬文件、无 C++ 工具链现实、内核零新增面全部干净）。
