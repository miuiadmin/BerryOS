# 文件系统设计

> FS 全是**用户态服务**（微内核硬约束）。**FAT 仅 MVP**；目标现代 FS（CoW + 日志 + 校验）。
> 决策依据见 `架构决策.md` #27、#15。与 IPC（`/svc/fs`）、内存（文件背靠 VMO + pager）、能力（fd/handle）联动。上层布局（分区 / 目录 / 沙箱 / 程序形态）见 `存储布局与沙箱设计.md`（ADR #45）——本文管 FS 引擎，那边管目录布局与归属语义。
> **2026-10-30 追记**（SEC-01 day-one 缝冻结 2026-10-30——件 18/19；SEC-02 A3 文档冻结）：§3.1 盘上格式安全域冻结——现代 FS inode 16B nonce + u8 class 域 / fsmgr 永不持根密钥 / 挂载参数格式域·策略域分立；§6 增 v2.5 行（与 `安全与硬件隔离设计.md` §6 v2.5 同档）。first-format-only：域现在埋、算法后补。

## 1. 分层

```
用户进程 ─open/read/write─▶ POSIX 库 ─▶ Channel IPC ─▶ /svc/fs
                                                         │
                                          ┌──────────────┴──────────────┐
                                          VFS（路径/fd/挂载/缓存）        │
                                          └──────────────┬──────────────┘
                                              具体 FS 服务：FAT / 现代 FS
                                                         │
                                                  块设备服务（virtio-blk）
```

- **VFS**（用户态）：路径解析、fd 句柄、挂载表、页缓存。是 `/svc/fs` 的内核。
- **具体 FS**：FAT（MVP）/ 现代 FS（目标），各自一个服务，挂到 VFS。
- **块设备**：virtio-blk（QEMU）→ 真实驱动；DMA 经 SMMU（见 `安全与硬件隔离设计.md`）。

## 2. MVP：FAT（互操作优先）

- 只读 + 读写；镜像可挂、可读写、可与宿主互操作。
- 用途：跑通"端到端读写文件"这一集成里程碑（路线图 MVP 拆解第 6 步），**不追求先进**。
- 明确：FAT 无崩溃一致、无校验、无大文件优化——**只是起步**。（修订 2026-10-28，
  B4 掉电安全首刀已把「崩溃一致 = 无」收窄为「覆写 commit 毒环窗已修（④ 守卫
  自愈）+ 新文件窗结构安全 + 残余面四条如实入册」——commit 写序、撕裂前缀表与
  QEMU 扇区间粒度边界详见 [FAT写路径原子性评估-2026-10.md](FAT写路径原子性评估-2026-10.md)。）

## 3. 目标：现代 FS（对标 ZFS / bcachefs / APFS）

| 特性 | 为什么 | 对标 |
|------|--------|------|
| **写时复制（CoW）** | 快照、瞬间克隆、避免损坏原数据 | ZFS / bcachefs / APFS |
| **日志 / 事务** | 崩溃一致（断电不丢元数据） | ext4 journal / ZFS ZIL |
| **数据 + 元数据校验** | 静默腐烂（bit rot）可检测/修复 | ZFS / bcachefs |
| **大文件 / 稀疏文件** | 跨平台（PC 大存储、虚拟磁盘） | 通用 |
| **权限 → 能力映射** | 文件权限是能力的一种投影 | Fuchsia（能力即 fs 权限） |

- 自研 or 选型：MVP 之后**优先评估** bcachefs 思路 / Fuchsia blobfs+minfs / Redox redoxfs，避免重造。
- **数据完整性是硬目标**：校验 + CoW 不是 nice-to-have，是"跨平台 + 可信存储"的刚需。

### 3.1 盘上格式安全域冻结（SEC-01 day-one 缝冻结 2026-10-30——件 18/19）

加密参数是 **first-format-only 决策**：一经首格式写入盘上、不可 OTA 改（Android `fileencryption=` fstab 旗标官方结论——盘上加密格式演进只能换盘重格；Apple day-one 派 17 年未推翻骨架的反面印证）。故本节三件全部是**格式/接口位冻结**——「域现在埋、算法后补」，加密执法随 v2.5/v4 落（`安全与硬件隔离设计.md` §6 v2/v2.5 档；该文件 §4.2 测量槽位表同批冻结）：

1. **现代 FS inode 加密域（件 18，ADR #27 展开）**：现代 FS（§3 表，v4）的 inode 布局 day-one 冻结含两域——
   - **16B per-file nonce**：文件创建时随机生成、写入 inode、永不复用（同 inode 号重建也不复用——nonce 是 per-file key 派生的 KDF info；fscrypt v2「inode 16B nonce 存 xattr + HKDF-SHA512 派生」同型，APFS per-file key 同型）。
   - **u8 保护类（class）域**：保护类编号，Apple Data Protection Class 语义的 BerryOS 化（锁屏即丢 / 首认证后常驻 / 只缠设备 UID 明赚快速擦除等类语义——类词表 v2 认证绑定链（CE/DE 双域）时再扩；DE/CE 二分是从 boot 时序倒推的架构约束，不是密码学需要）。域位先冻结、恒 0 = 未加密。
   - **FAT 无处可放、不硬塞**——FAT 阶段加密走整卷元数据加密层（v2.5，见 §6 与安全设计 §6 v2.5；dm-default-key 同型）。
2. **fsmgr 永不持根密钥（件 19）**：**密钥托管者与 FS 进程分离**（Fuchsia fxfs-crypt「crypt 服务持密钥、解锁时递 handle 给 Fxfs」同型——微内核生态里最贴 BerryOS 形态的参考；Android vold/KeyMint 分离、QNX 第三方 master key 同型）。fsmgr 只收**会话句柄与派生结果**，永不接收裸根密钥。密钥托管者 = keystored（安全设计 §4.1/§6 v2 软桩——WRAP/UNWRAP/DERIVE(label, context) 三 op；fsmgr 经 ksproto 严格串行 RPC 会话取派生密钥，协议 crate（user/berry-ksproto）已随 SEC-02 立骨架——GEN/ATTEST/COUNTER 三 op wire 冻结 + 严格串行会话机 + host 测（psproto/netdproto 家族第三席）；WRAP/UNWRAP/DERIVE 密钥托管 op 与 keystored 服务端本体随 v2 扩）。盘上密钥材料住独立密钥分区（不与数据同生死、必须放未加密区——Android /metadata 16MB 独立分区同型；mkimage MBR 第二分区项预留 = SEC-01 件 4，兄弟刀）。
3. **挂载参数两域分立（件 19）**：加密/格式类挂载参数显式分两域——
   - **格式域**（first-format-only + 版本号）：加密模式 / 密钥粒度 / class 词表版本等**定义盘上格式**的参数，首格式后不可改；V-2「簇数=版本域单一事实源、BPB fstype 串不读」同哲学——格式域带版本号作单一事实源。
   - **策略域**（可 OTA 切换）：性能开关 / 行为档——如内联加密加速（Android `inlinecrypt` 可 OTA 切换 vs `fileencryption` 不可的官方分界，正是两域分立的业界现成对照）。策略域不进盘格式。

> 来源：SEC-01 §4.5 件 18/19；`research/sec-notes/SEC-7-磁盘与文件加密.md` §3.1/§3.6（nonce/KDF 细节）、§4-2（first-format-only 教训）、§5 动作清单 B/C/E、工程坑「挂载参数与盘格式纠缠」。

## 4. 文件 = VMO（与内存管理联动）

- 打开文件 → 内核建一个 VMO 背靠该文件内容；`mmap` = 把该 VMO 映射进进程 Vmar。
- **缺页由 FS pager 填**：读到缺页 → 内核通知 FS 服务（经 Event/共享环快路径）→ FS 读块填页 → 回复 → 建映射。
- 这正是 `内存管理设计.md` §4 用户态 pager 模型——FS 是最常见的 pager。
- 写回：脏页由 FS 服务择机刷盘（写时复制 / 日志保证一致）。

## 5. 块设备 / DMA

- virtio-blk（QEMU `virt`）→ 真实块驱动。
- DMA 缓冲 = 锁页/连续 VMO，经 SMMU domain 限定（设备只能 DMA 进授权区间）。
- 块设备授权链（MMIO 窗/IRQ→channel/DMA 三铸件）与 vblk 现役实例见 `驱动模型设计.md` §2。

## 6. 阶段化目标

- **v1**：无盘 FS（bootfs/rootfs 内存镜像即可，参考 Fuchsia bootfs）。P6 A-1 已加 RAM-fs 最小读写面（2026-10）：fsmgr 服务（tmpfs 语义，8 文件 × 16KiB 帽）+ berry-fsproto 串行 RPC 协议 + bsh `>`/cat/ls——tmpfs-before-disk 先行；P6 A-3~A-6 已落（2026-10）：virtio-blk 用户态驱动（A-3）+ vblk 常驻块设备服务（A-4，`BLKD ok`）+ FAT12 只读底座（A-5，mkfat 确定性卷 + berry-fatfs，`FAT ok`）+ FAT 落盘读写 fat:rw（A-6，staging+commit 两段写，`FATW ok`）。**C-0 目录面已收官 2026-10-23（M-VM B 线第一刀，五刀）**：fsproto v2 路径面（NUL 分段 ≤8 段 ×NAME_MAX=48，+LOOKUP/MKDIR/UNLINK/READDIR/STAT 五 op，协议 18→31 测）+ berry-fstree RAM overlay 平面表升树（17 测）+ berry-fatfs 子目录链读面（DirKind::Dir + mkfat `--fixture` 专列 DATA/NOTE.TXT，`--check-fixture` 守卫扩，16 测）+ bsh 迁同路不长第二套（cat/ls/`>` 多段 + mkdir/rm/带参 ls 内建，全走既有 fs_rpc 会话机；`DIR ok n=` rootfs 相第 22 标记；smoke 四跑→五跑，新 FAT 子目录相独立盘 fixture 模式——默认盘字节零漂移硬线不破）；**诚实缺口**：FAT 子目录写面 v1 缓做（MKDIR/UNLINK 纯 RAM 面、FAT 文件删除留 v2）、`>` 多段目标构造性只落 RAM 树、引号/空白路径留 v2。**C-1 libc 文件面已收官 2026-10-23（M-VM C 线，五刀）**：berry-fsclient 纯函数 crate（fd 表=libc 侧客户端游标[裁决 1] + resolve_path 相对名挂 CWD + 严格串行 RPC 会话机，23 测）→ berry-libc 文件面真实现（fd 3+ open/close/read/write/lseek/stat/opendir/readdir + chdir/getcwd；写通道 commit 点=close[裁决 2]——write 走 PUT 累积 staging、close 发 TRUNC(size)；errno 双层映射 FsErr→errno 归 libc）→ stdhello `File::*` 往返自验（`FILE ok` rootfs 相第 23 标记）→ bsh 全量迁 libc 文件面（自有 fs RPC 会话机 ~300 行退役；errno→旧文案零漂移映射；fsmgr READDIR 根并合——RAM 根 + FAT 未影子名 overlay 全景）→ cd/pwd 内建（`CD ok` rootfs 相第 24 标记 + RX 段 f `cd d1`/`pwd`→`/d1` 防回声注入断言，47 合相）；**空路径串（nlen=0）= 根寻址立法**（刀 5 实测逼出：fsmgr READDIR 根并合是刀 4 服务半边，fsproto encode 层发不出根请求——chdir("/") 是首个消费者；修法 = 读面三 op LOOKUP/STAT/READDIR 专属放行 + parse 白名单对偶，写面拒空钉死；fsmgr STAT 根=(TYPE_DIR, overlay 项数)/LOOKUP 根=OK，root_overlay 单一实现与 READDIR 同源）；host 255→280（fsclient +23 / fstree 17→18 / fsproto 31→32）、rootfs 相 22→24、RX 45→47 六段。
- **v2**：`/svc/fs` 路径式挂载（当前 FS 能力经 svcmgr 直递 channel gift，未走命名空间）——FAT 只读→读写已随 P6 A-5/A-6 提前落定（上行），本行剩命名空间面。
- **v2.5**（SEC-01 day-one 缝冻结 2026-10-30——件 18/19，详 §3.1；与 `安全与硬件隔离设计.md` §6 v2.5 同档）：FAT 阶段整卷元数据加密层 + keystored 密钥会话面（fsmgr 永不持根密钥）+ 挂载参数格式域/策略域分立；现代 FS inode 16B nonce + u8 class 域格式现在冻结（v4 首格式即含），加密执法随后补。
- **v3**：VFS 完整（多挂载、fd、页缓存）；FS pager 填页打通。
- **v4**：现代 FS（CoW + 日志 + 校验）——自研或选型落地。
