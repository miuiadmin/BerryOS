# 策略服务用户指南

> 版本：1.0 ｜ 日期：2026-11-07 ｜ 定位：S6 策略服务的使用面——内核 0x83 `policy_bind` 带内注入（berry-sys 镜像）+ 宿主工具链（advisor / policy_ab_eval / sched_perf_analyze）+ A/B 升级工作流与四条护栏。面向用户态策略写者与 A/B 升级操作者；机制设计归 [AI调度设计-v1.0.md](AI调度设计-v1.0.md)（ADR #21）与 [调点调度-v1.2.md](调点调度-v1.2.md)（S6），本文只写怎么用。

## 一、快速开始

用户程序设置自己的策略权重，三步：先对账（自己是几号键、现在第几代），再构造 16B 条目，最后携新世代号整表提交。

```rust
use berry_sys::*;

fn boost_myself() -> Result<(), Status> {
    // ① 对账：双谱系世代 + 自身策略键（一次调用读全）
    let mut packed = 0u64;
    let mut self_key = 0u64;
    let s = berry_policy_status(&mut packed, &mut self_key);
    if !is_ok(s) {
        return Err(s);
    }
    let active_gen = packed & 0xFFFF_FFFF; // bit 0-31 = active gen（bit 32-63 = shadow gen）

    // ② 构造条目：给自己加权 +16（内核侧夹紧 ±64）
    let tbl = [PolicyEntry {
        key: self_key, // v1 key = Task::proc_tag；内核任务/boot 期 = 0（哨兵键，注入即弃）
        weight: 16,
        placement: 0,
        epp_flags: 0, // 不带 EPP 覆盖；POLICY_EPP_HAS | POLICY_EPP_VAL = Perf 档
        _rsv: 0,      // 非 0 → -EINVAL
    }];

    // ③ COMMIT：gen 须严格大于当前活跃世代，否则 -EAGAIN（重读 STATUS 携新 gen 重试）
    let s = berry_policy_bind(0, POLICY_OP_COMMIT, tbl.as_ptr(), 1, active_gen + 1, 0);
    if is_ok(s) { Ok(()) } else { Err(s) }
}
```

三点语义：

- **整表提交 = 全量换快照**，不是增量合并——新表整体替换旧表；`count = 0`（空表）也是合法提交（「接口在位、表空」）。
- 提交成功即生效：调度器每次 pick 出选后按 key 查表，命中则改写 `prio_effective`/EPP，未命中或空表 = 零写入（与接口缺席逐位等价）。
- v1 **无 handle 门控**（系统全局单通道，`auth` 预留传 0）；SET_POLICY 门控随 Job 对象落地后收紧。

## 二、API 参考

### 2.1 berry_policy_bind —— 0x83 六 op

```rust
pub extern "C" fn berry_policy_bind(
    auth: Handle,          // v1 预留不消费，恒传 0
    op: u64,               // 1 COMMIT / 2 STATUS / 3 PROMOTE / 4 DEMOTE / 5 UNBIND / 6 SHADOW_COMMIT
    tbl: *const PolicyEntry, // op=1/6：表首址
    count: u64,            // op=1/6：条目数（0 = 空表合法）
    gen: u64,              // op=1/6：世代数
    rsv: u64,              // 全 op 面保留 0，非 0 → -EINVAL
) -> Status                // 0 = Ok，负 = 错误码
```

berry-sys 当前只导出 `POLICY_OP_COMMIT` / `POLICY_OP_STATUS` 两个命名常量，op 3–6 以字面量传递（随需求补包装）。未定义 op → `-ENOTSUP`。

| op | 名称 | 参数（p1/p2/p3） | 语义 | 返回 |
|----|------|------------------|------|------|
| 1 | COMMIT | tbl / count / gen | 整表提交为**活跃（active）**策略快照，立即参与调度决策 | 0；陈旧 gen → `-EAGAIN` |
| 2 | STATUS | 三出参（见 §2.2） | 双谱系世代 + 调用者自身键 + 对账双计数一次读全 | 0；写出失败 → `-EFAULT` |
| 3 | PROMOTE | 无（传 0） | shadow → enforced 原子转正；active gen := shadow gen；对账计数清零（新对账期） | 0；shadow 从未绑定 → `-EBADSTATE` |
| 4 | DEMOTE | 无（传 0） | enforced → shadow 降级：active 回空表，**shadow 表保留**可再次 PROMOTE 复转正；对账计数清零 | 恒 0（幂等） |
| 5 | UNBIND | 无（传 0） | 解绑回「接口缺席」哨兵态（active 清空；拆除/对照测试用） | 恒 0（幂等） |
| 6 | SHADOW_COMMIT | tbl / count / gen | 表形同 COMMIT，换表对象 = **shadow 谱系**（只算不用，active 不动） | 0；陈旧 gen（比照 shadow 世代）→ `-EAGAIN` |

COMMIT / SHADOW_COMMIT 公共收表面：

- 单次表 ≤ 128 条（`TBL_MAX` 限流）：超限 → `-E2BIG`，诚实拒收、不静默截断。
- 内核 `copy_from_user` 整表拷入后逐条解码（无 TOCTOU）；拷页失败 → `-EFAULT`。
- `weight` 内核侧夹紧 ±64（包络执法，不信任注入方自律）。
- 0 键（哨兵）、重复键、桶溢出由内核 build 语义丢弃（重复键 first-wins），**不报错**。
- 条目 `_rsv ≠ 0` 或 `epp_flags` 未定义位（bit2..）非 0 → `-EINVAL`（调用方可清零修复）。
- **gen 陈旧拒收**：COMMIT 要求 gen 严格大于 active 世代，SHADOW_COMMIT 要求严格大于 shadow 世代；违反 → `-EAGAIN`，对应谱系快照未动，重读 STATUS 后携新 gen 重试。

错误码速查：

| 错误码 | 值 | 触发面 |
|--------|-----|--------|
| `BERRY_ERR_E2BIG` | -7 | 单次表 > 128 条 |
| `BERRY_ERR_AGAIN` | -11 | gen ≤ 比照世代（COMMIT 比 active、SHADOW_COMMIT 比 shadow） |
| `BERRY_ERR_FAULT` | -14 | 表拷入失败；STATUS 出参写出失败 |
| `BERRY_ERR_INVALID_ARG` | -22 | `rsv ≠ 0`；条目 `_rsv ≠ 0` 或 `epp_flags` bit2.. 非 0 |
| `BERRY_ERR_BAD_STATE` | -37 | PROMOTE 时 shadow 从未绑定（shadow gen == 0） |
| `BERRY_ERR_NOT_SUPPORTED` | -95 | 未定义 op |

### 2.2 berry_policy_status —— op=2 三出参

```rust
pub extern "C" fn berry_policy_status(packed: *mut u64, self_key: *mut u64) -> Status
```

内核 op=2 有三个出参位（p1/p2/p3）；berry-sys wrapper 当前暴露前两个（p3 恒传 0 = NULL 跳过）：

| 出参位 | 内容 | 位布局 | 必填 |
|--------|------|--------|------|
| p1 `packed` | 双谱系世代，单读窗打包（双谱系无撕裂） | bit 0-31 = active gen，bit 32-63 = shadow gen（各截低 32 位） | **必填**（内核无条件写出，NULL → `-EFAULT`） |
| p2 `self_key` | 调用者自身策略键（v1 key = `Task::proc_tag`）——表里给自己加权前先对账「我是几号键」 | 整值 | 可选（0 = NULL 跳过） |
| p3 divergence | 对账遥测双计数（A/B 评估面） | bit 0-31 = divergence_count，bit 32-63 = shadow_eval_count | 可选（0 = NULL 跳过）；**wrapper 未暴露**，暂经串口遥测消费（见 §3.2） |

p3 两个计数器的语义：`shadow_eval_count` = 对账期内 shadow 决策评估次数（分母，shadow 谱系非空时的每次调度 pick）；`divergence_count` = 其中「shadow 会做的 ≠ active 做了的」次数（分子，weight 或 EPP 任一差异）。promote/demote 轨道切换自动清零——**读数即当前对账期**。

### 2.3 PolicyEntry（16B，`#[repr(C)]`）

| 字段 | 偏移 | 类型 | 说明 |
|------|------|------|------|
| `key` | 0 | u64 | 策略键 = `Task::proc_tag`；0 = 哨兵键（注入即弃）；重复键 first-wins |
| `weight` | 8 | i32 | 权重微调，内核夹紧 [-64, +64]；合成公式 `prio_effective = max(prio_base + weight, pi_inherited)` |
| `placement` | 12 | u8 | 放置意见（S6 四类动作空间之一）；字段与内核存储在位，当前消费点 = weight/EPP，placement 暂无消费 |
| `epp_flags` | 13 | u8 | bit0 = `POLICY_EPP_HAS`（带 EPP 覆盖，bit1 才有意义）；bit1 = `POLICY_EPP_VAL`（0 = Efficiency / 1 = Perf）；bit2.. 未定义（非 0 → `-EINVAL`） |
| `_rsv` | 14 | u16 | 保留 0；非 0 → `-EINVAL` |

偏移由 berry-sys const 断言钉板（key@0 / weight@8 / placement@12 / epp_flags@13 / _rsv@14），内核按 LE 字节流手工解码——**偏移即 ABI**，两端 `#[repr(C)]` 保证布局一致。

## 三、工具链

三个宿主侧工具（`tools/`，均为确定性、非交互、exit code 契约风格）。

### 3.1 advisor.py —— telemetry → 策略建议

启发式策略生成器：遥测进、PolicyEntry JSON 出。同输入同输出（无随机、无时钟），可 diff 审计——shadow 评估的前提。

```bash
python3 tools/advisor.py --demo                            # 固定样本自验（stderr 打输入，stdout 出表）
qemu ... 2>&1 | python3 tools/advisor.py                   # QEMU 串口遥测实时消费
echo '[{"key": 7, "intent": 1, "wake": 50}]' | python3 tools/advisor.py --json
# 输出: [{"key": 7, "weight": 16, "placement": 0, "epp_flags": 0, "_rsv": 0}]
```

输入两形态自动识别（`--json` 强制 JSON）：① QEMU 串口遥测行（`tele:` 开头、k=v 空格分隔，只认带 `key=` 的 per-task 行，同 key 取最后一条 = 最近读数）；② JSON 数组/单对象。字段缺省：intent/policy/wake 缺省 0，键别名 wake/wake_count/wakes。

规则（逐条独立触发、效果叠加，「公平默认、只叠加」）：

| 规则 | 触发条件 | 动作 |
|------|----------|------|
| 交互型加成 | intent ∈ {1, 2}（前台/交互族） | weight +16 |
| 批处理降权 | intent == 5（maintenance） | weight −8 |
| 高唤醒加成 | wake > 100（严格大于） | weight +8 |
| RT 屏蔽 | policy == 3（deadline 档） | 不建议（§3.4 护栏） |
| 哨兵键跳过 | key == 0（内核任务） | 不建议 |

护栏：weight == 0 的任务不入表；headroom 准入 Σ|weight| 严格 < 64（|weight| 降序贪心、key 升序 tie-break，超预算弃收并在 stderr 记 note，留叠加余量）；输出按 key 升序（diff 友好），字段名与序镜像内核 `PolicyEntryABI`，可直接映射为 COMMIT 表。

exit 0 = 有产出（空表 `[]` 亦合法）；1 = 输入无可用记录。

### 3.2 policy_ab_eval.py —— divergence 率 → PROMOTE/DEMOTE/HOLD

shadow 对账读数 → 升降级判定。divergence 率 = divergence_count / shadow_eval_count（对账期内「shadow 会做的」≠「active 做了的」决策频率）。

```bash
echo '{"divergence": 3, "eval": 120}' | python3 tools/policy_ab_eval.py
# {"divergence_rate": 0.025, "recommendation": "PROMOTE", "threshold": 0.1}
qemu-run.log | python3 tools/policy_ab_eval.py --delta     # 窗口化：首尾差（轨道未切换时更准）
```

输入两形态自动识别：① JSON 计数对（键别名 divergence/divergence_count、eval/shadow_eval(_count)，或单键 `packed` = 内核 op=2 p3 原始 u64 代为拆包）；② QEMU 串口载体行——`PERF policy divergence=11 eval=12` / `STATUS ...` / `STATUS packed=0x...`。多样本默认取**最后一条**（= 最近对账期读数）。

判定阈值（`--promote` / `--demote` 可覆盖）：rate < 0.1 → **PROMOTE**（决策高度一致，可转正）；rate > 0.5 → **DEMOTE**（分歧过大，shadow 表不可信，回观察态）；其间 → **HOLD**（证据不足，继续累积对账期样本）；eval == 0 → HOLD（对账期无样本，率不可算，诚实透出）。输出单行 JSON `{"divergence_rate", "recommendation", "threshold"}`（HOLD 时 threshold = null）。

exit 0 = 有判定；1 = 无可用样本。

### 3.3 sched_perf_analyze.py —— 性能验收

策略注入后的性能回归验收：解析串口 `PERF <op> avg=<cycles> n=<count>` 行，按 QEMU virt CNTFRQ 62.5 MHz 换算纳秒，对照验收线（[调点调度-v1.1.md](调点调度-v1.1.md)）：

| op | 验收线 | 出处 |
|----|--------|------|
| pick | < 5µs（@1k 任务） | §10-R6 kill 线 |
| freeze | < 5ms | §8.3-3 性能门 |
| billing | < 1µs | §8.1-M1.1-4 记账开销 < 1% × 100µs slice |

```bash
qemu ... | python3 tools/sched_perf_analyze.py    # 或 --demo
# JSON 报告（逐项 avg_cycles/avg_ns/limit_ns/pass/margin）+ 末行 PASS/FAIL 汇总
```

exit 0 = 全过；1 = 有未达项或无 PERF 行。策略表命中路径（查表 + 改写 TCB）计入 pick 开销——换表前后各跑一遍对拍。

## 四、A/B 升级工作流

候选策略表先上 shadow 轨道双轨观测，证据充分再转正；分歧过大则降级回观察态。四步：

**① 启动 shadow（SHADOW_COMMIT）**——advisor 产出（或手写）候选表，携新世代提交到 shadow 谱系：

```rust
let mut packed = 0u64;
let mut self_key = 0u64;
berry_policy_status(&mut packed, &mut self_key);
let shadow_gen = (packed >> 32) & 0xFFFF_FFFF;   // 比照对象 = shadow 世代（与 active 无关）
berry_policy_bind(0, 6 /* SHADOW_COMMIT */, cand.as_ptr(),
                  cand.len() as u64, shadow_gen + 1, 0);
```

shadow 表**只算不用**：每次 pick 对同一 key 双表各算一份决策，差异只计数、永不应用——active 决策零改动，系统行为不受影响。

**② 观察对账（STATUS 读 divergence）**——跑代表性负载，让对账计数累积。用户态 wrapper 暂未暴露 p3 出参，宿主侧消费串口遥测行（`PERF policy divergence=N eval=M` 或 `STATUS packed=0x...`）。注意：轨道切换（promote/demote）自动清零双计数——每期读数都从轨道切换点起算，勿跨期混读。

**③ 评估决策（policy_ab_eval）**——对账期样本喂评估器：rate < 0.1 → PROMOTE；rate > 0.5 → DEMOTE；其间 → HOLD（继续累积，回到 ②）。窗口化评估加 `--delta`。

**④ 执行升级（PROMOTE / DEMOTE）**——

```rust
berry_policy_bind(0, 3, core::ptr::null(), 0, 0, 0);   // PROMOTE：shadow → active 转正
// -EBADSTATE = shadow 从未绑定（gen==0）——漏了 ①，先 SHADOW_COMMIT
berry_policy_bind(0, 4, core::ptr::null(), 0, 0, 0);   // DEMOTE：active 回空、shadow 保留，回观察态
```

PROMOTE 成功即轨道切换：active gen := shadow gen，对账计数清零——此后 active 侧 COMMIT 的陈旧比照即该值。DEMOTE 后 shadow 表保留，修正候选表后可再 SHADOW_COMMIT → PROMOTE 复转正。全量拆除（如验收收尾）用 UNBIND（op=5）。

## 五、护栏

四条不变量，前两条工具与内核双侧执法，后两条内核侧收口：

**weight 包络 ±64**——内核三点执法：handler 表解析夹紧（COMMIT/SHADOW_COMMIT）、快照构建夹紧（build_snap）、消费点夹紧（apply/weight_of）。注入数值无论多大，生效权重恒在 [-64, +64]，只单调收窄、无提权路径。工具侧自限更紧：advisor 保证 Σ|weight| 严格 < 64，给后续叠加留余量。

**RT/deadline 屏蔽**——advisor 规则 4：policy=3（deadline 档）任务绝不进建议表（AI 调度设计 §3.4：RT 类屏蔽 AI 微调）。deadline 档行为由 EDF + 预算执法 + admission（下条）独立决定，屏蔽在建议生成侧源头切断。

**gen 世代拒陈旧**——COMMIT 要求 gen 严格大于 active 世代、SHADOW_COMMIT 严格大于 shadow 世代：写者重放/乱序到达的旧表不得覆盖新表；拒收返回 `-EAGAIN` 且对应谱系快照未动。PROMOTE 后 active gen = shadow gen，两侧世代的比照关系随之更新。

**ΣU ≤ 0.95 admission**——deadline 档准入（`berry_sched_setattr` 0x3C，policy=3 须同时置 budget）：Σ(C_i/T_i) + 新申请 ≤ 1 − 5% 固定 reserve（Q12 定点：1.0 = 4096，上限 3891）。超载 → `-EBUSY` 诚实拒收，不静默丢帧；全局原子累计，覆盖/清除旧值时相应回退。策略服务不触碰此面——deadline 预算的合法性由 admission 独立执法，与策略表互不绕过。

## 六、跨特性协作示例

三个特性同台的最小集成样例（伪代码聚焦协作形态，完整语义见各节引用；注入面在 guest 内——0x83 是 SVC，宿主侧只产出调用计划）。

### 6.1 advisor 驱动的自动调优

```bash
# 完整管线：QEMU telemetry → advisor → shadow 注入计划 → 对账评估 → 转正
qemu-system-aarch64 ... 2>&1 | tee /tmp/tele.log | python3 tools/advisor.py | \
  python3 -c "
import json, sys
tbl = json.load(sys.stdin)  # advisor 整表出（key/weight/placement/epp_flags/_rsv）
# 0x83 是 guest 内 SVC：此处产出调用计划，由 guest 侧注入器执行（伪代码）
print(f'berry_policy_bind(0, 6 /* SHADOW_COMMIT */, tbl, {len(tbl)}, shadow_gen + 1, 0)')
"
python3 tools/policy_ab_eval.py < /tmp/tele.log   # 同一份遥测：rate < 0.1 → PROMOTE（op=3，§四④）
```

一句话：advisor 把串口遥测**整表**变成候选（不是逐条），SHADOW_COMMIT 起双轨对账、评估达标后 PROMOTE 转正——§四 A/B 工作流的自动化形态，一份 `tele.log` 同时喂建议与评估两端。

### 6.2 freeze + policy 联合管控

```rust
use berry_sys::*;
// 冻结后台整进程（0x3E，options=0；token 存活期 = 冻结期，close 即解冻）
let mut token: Handle = 0;
berry_process_suspend(bg_proc, 0, &mut token);   // 后台退场：彻底退出 pick 面
// 给前台加权（0x83 op=1；fg_key 来自遥测/STATUS 对账——v1 key = proc_tag 不可合成）
let fg_entry = PolicyEntry { key: fg_key, weight: 32, ..Default::default() };
berry_policy_bind(0, POLICY_OP_COMMIT, &fg_entry, 1, active_gen + 1, 0);
// active_gen 读自 berry_policy_status（§一①）；陈旧 gen → -EAGAIN 拒收
// 窗口结束：berry_handle_close(token) 解冻后台；UNBIND（op=5）拆表回哨兵态
```

一句话：freeze 是硬隔离（退出调度），policy 是软微调（仍公平 pick、只改 `prio_effective`）——一冻一提一步到位，解除也对称（close token / UNBIND）。

### 6.3 deadline + policy RT 屏蔽

```rust
use berry_sys::*;
// deadline 档：policy=3 须同时置 budget/period（ΣU ≤ 0.95 admission，超载 -EBUSY）
let mut dl = SchedAttr {
    flags: SCHED_FLAG_POLICY | SCHED_FLAG_BUDGET, policy: 3,
    budget_ns: 2_000_000, period_ns: 10_000_000, ..Default::default()
};
dl.size = core::mem::size_of::<SchedAttr>() as u32;
dl.version = 1;                        // size/version 必填（ABI §7.2）
berry_sched_setattr(dl_thread, &dl);   // 0x3C：EDF + 预算执法接管
// 此后遥测行带 policy=3 → advisor 规则 4 直接 skip（RT 屏蔽），永不进建议表
```

一句话：任务一经 `sched_setattr` 进 deadline 档即脱离策略微调射程——advisor 源头屏蔽（规则 4），行为由 EDF + admission 独立执法（§五护栏 2/4 合龙）。
