# AI 同意面设计（Consent Surface）

> 版本：**1.0**（v1.0）｜2026-11-08

> 同意面 = AI 权限的「用户可见审批层」：内核 SET_POLICY 能力管「能不能」，本设计管「用户知不知道、批没批」。
> 语义底稿 = `research/21-Veda-consent机制深读.md`（Veda 为 GPL-3.0-only：**语义可借、代码一字不进**，规则 13 同口径）。
> 挂钩：`能力模型设计-v1.0.md` §8（唯一机制纪律）、`AI调度设计-v1.0.md` §3/§4 末条（SET_POLICY 委托）、
> `应用模型设计-v1.0.md` §3/§8（manifest 落点与 Agent 面）、`可观测性设计-v1.0.md`（trace 基座）。

## 0. 定位：用户可见的审批层，不是第二套权限

- **两层分工**：能力面管「能不能」——handle 有无 + rights 门控，内核执法（`能力模型设计-v1.0.md` §1/§7）；
  同意面管「用户知不知道、批没批」——风险档分类 + 审批状态机 + 台账，用户态执法。与 AI 调度权限节的分工：
  那边管「策略注入的内核权限」（`RIGHTS_SET_POLICY` / Job 级作用域，`AI调度设计-v1.0.md` §3），
  这边管同一委托在用户眼前的审批面。
- **唯一机制纪律不破**（`能力模型设计-v1.0.md` §8）：同意面不是第二种权限机制——审批的一切后果最终
  落实为 handle 的交接与收回（授予 = `duplicate` 收紧后递 handle；常开 = 委托；收回 = `close`）。
  同意面是「handle 交接的化妆面 + 状态机」，不是新权限位。
- **三原则对齐**：
  - 人无我有/人有我强：以「可撤销性 × 影响范围」为判据轴（§1），比「风险概率」更可判定；
    且 consent 面三底座（capability / trace / manifest）day-one 内核级原生在册（research/17 号对照映射）。
  - **AI 友好化 = 审批不挡正常流**：Routine 静默零打扰；审批异步——Pending 即回执、结果以 notice 补达，
    会话不阻塞（21 号 §2）；审批面缺席时 fail-closed 但系统照常可用（§2 headless 降级）。
  - **AI 测试友好化 = 审批状态机可测**：状态迁移全枚举、每档处置确定性、trace 事件可断言——
    ktest/smoke 确定性状态谓词（POLICY 空表等价同款模式，`能力模型设计-v1.0.md` 3-4c 落地记录）。
- **诚实定位**：v1 无 GUI 审批面——GUI-8 桌面（berry-launcher）已落但无审批组件，agent 服务未建；
  本文是 **v2 蓝图**，v1 可先落的两件（manifest 风险档声明格式 + trace 审计事件词汇）见 §5。

## 1. 风险三档分类学

**判据轴 = 可撤销性 × 影响范围，不是概率风险**（21 号 §1；Veda `agent.rs:33-46`、`AGENT.md:113-117`）——
可判定性优先：每条判据都能在动作执行前机械回答。三值有序枚举：

| 档 | 判据（可撤销性 × 影响范围） | 处置 | always allow |
|---|---|---|---|
| Routine（低） | 只读或易于撤销；影响限本动作对象 | **静默执行 + 台账** | 无需（免问即免授） |
| Sensitive（中） | 改动或发送要紧之物；可撤销但已有代价 | **首次显式审批 + 台账** | 仅此档可常开 |
| Destructive（高） | 不可撤销，或影响超出本对象（弃工作/全系统） | **每次显式审批 + 台账** | 永不可常开 |

判据细则（Veda 判例语义；BerryOS 动作词表 v3 定稿时按同轴重裁定）：

- **粒度到操作语义，不到文件语义**：删除可从回收站恢复 = 中档、清空回收站 = 高档；写新文件 = 低档、
  替换已存在 = 中档；不替换目标的 copy/move/rename = 低档（21 号 §1，`tools.rs:308-329`）。
- **自反与批量放大**：断网类 = 中档（可能断掉 agent 自己）；忘一条 = 低档、一次忘多条 = 高档；
  重启/关机/杀任务 = 高档（21 号 §1）。
- **分类前置纪律 made-definite**：调用先钉死成确定形态（id 清单/目的地预演）再定档——审批单展示的
  参数即执行参数，防「批准 A 执行 B」的语义 TOCTOU（21 号 §1/§5.2 第 2 条，落地形态见 §3）。
- **参数依赖的风险不运行时猜——双动作拆分**：save（只覆写自己存的）/ save_as（可覆写任何文件）
  分档同法声明（21 号 §1/§6）。
- **档位来源静态优先**：Veda 应用风险档纯自报、消毒不改报的档（21 号 §6 信任边界）；BerryOS 档位
  对照 manifest 静态声明裁定，系统函数走服务侧集中静态表——自报只作降级参考，不作授权依据。
- **与 intent 六档正交**：intent/band 是调度侧分级（ADR #42），Risk 三档是动作侧分级——两表不合并
  （21 号 §5.1 末行）。

## 2. 执行链：发起 → 拦截 → 审批 → 执行 → 审计

五段对照 Veda（21 号 §2），BerryOS 形态 = **双钩子**：

```
钩子一（委托时刻——事前总授权）：
  用户 ─审批面→ 授予 SET_POLICY 委托（dup 收紧 + 委托链审计入账；注入权也是能力，AI 调度 §4 末条）
钩子二（首次越档动作——事中拦截）：
  Agent 动作 ─分类步→ 越出已授权档？否 → 静默执行 + trace 记账；是 → Pending（绝不先跑）→ 审批 UI
```

- **发起**：Agent = 普通应用（`应用模型设计-v1.0.md` §8.1，manifest 上限封顶 handle 集）；动作调用走
  typed action 协议（channel；v3——Veda agentapp describe/invoke 的对应物，21 号 §5.2 末段）。
- **拦截**：同意面服务（用户态）在分类步先 made-definite 再定档（manifest 声明档 + 系统函数集中表）；
  需要审批的动作**绝不先跑**（21 号 §2 拦截纪律）。
- **审批 UI 挂桌面 shell**：审批端点 channel 的 handle 在装配时定向只交接给 berry-launcher
  （GUI-8 现役桌面 = 桌面 shell 形态，`GUI里程碑规划-2026-10-v1.0.md` GUI-8 行）——「只有 shell 能答审批」
  的结构等价物，且 handle 不可伪造比名字查证更省（21 号 §5.1 第 2 行）。headless/无桌面形态降级 =
  越档动作 fail-closed（默认拒 + 台账），Routine 静默照旧——审批面缺席时系统仍安全可用。
- **审批异步不挡流（AI 友好化）**：Pending 即回执「等待审批」，结果以 notice 补达，会话不阻塞
  （21 号 §2）；TTL 过期即失效（Veda 常量 180s——只借「有时效」语义，定值随实施裁定）。
- **执行**：批准后以原参数重放；拒绝/过期 = 不执行 + notice；已启动的被打断后跑完不假装没发生，
  动了要紧之物的**事后告知**（RanAnyway 语义，21 号 §2/§5.2 第 4 条）。
- **审计 = trace 环事件 + 计数面 + 并账**，三层：
  1. 事件词汇：trace 新增 `consent` 类别五事件（request/approve/decline/expire/ran_anyway）——挂
     可观测性 trace 通道（`可观测性设计-v1.0.md` §2 类别表 add-only 扩一，现有七类不动）。
  2. 计数面：复用 P1-a 拒收入账四计数模式（`sched/src/policy.rs:670-701`：静态 `AtomicU64` +
     Relaxed 纯统计 + 快照读出口 + 决策路径零新增写面）扩出同意面计数组——五事件各一计（与事件
     词汇同名），审批与护栏生效频率可量化。
  3. **并账不建新账**：「何时批准了什么档的动作」并进委托链审计同一账本（21 号 §5.2 第 8 条）——
     Veda 无 append-only 审批账本是其已记录缺口（21 号 §2/§6），勿照抄其分散记录。

## 3. 九条语义增量的落地形态

逐条：Veda 语义（21 号 §5.2）→ BerryOS 载体（能力模型 / AI 调度 / trace）→ 阶段挂点（v2/v3）。

| # | Veda 语义 | BerryOS 载体 | 挂点 |
|---|---|---|---|
| 1 | 三档分类学与判据语义 | 动作风险档词表：manifest 声明（§5 v1 格式）+ 系统函数集中静态表 | v2 词表 / v3 消费 |
| 2 | made-definite-before-classified | typed action 协议：定档前参数钉死（id 清单/目的地预演） | v3 |
| 3 | always allow 仅中档 + 授权以声明源为根 + 读回白名单 | SET_POLICY 委托生命周期：授予即 handle 交接；随声明消失失效；内核账本不可种植 | v2（委托链） |
| 4 | 审批时效与打断语义 | 审批状态机：TTL / 打断 / 事后告知 notice | v3 |
| 5 | 双动作拆分模式 | typed action 词表纪律：参数依赖的风险拆成两个不同档位的声明动作 | v3 |
| 6 | 无人值守会话禁自唤醒 | agent 服务会话类型标记：提醒触发的会话禁 timer set 类动作（防 notice 自循环） | v3 |
| 7 | 注入防护三件 | agent 服务 prompt 卫生：自述标「它自己的话」/ notice 剥 `[System]` / information-never-instructions | v3 |
| 8 | 持久审计账本（补 Veda 缺口） | trace `consent` 事件 + 同意面计数组 + 并入委托链审计账本 | v2 词汇 / v3 账本 |
| 9 | 逐路径校验含不可信恢复目标 | 文件 agent 面路径四查：回收站记录当不可信输入校验（21 号 §4） | v3 |

三条展开（其余按表直落）：

- **第 3 条生命周期**：与能力模型「权限只能收紧不能放宽」（§1）同型——always allow 的 BerryOS 形 =
  用户把收紧后的 handle 委托给 Agent（`AI调度设计-v1.0.md` §4 末条）；manifest 撤声明或应用下架 →
  对应委托自动失效（授权不能脱离声明源存活，21 号 §3）；种植数据授不出权——账本在内核 handle 表，
  用户态写不进（21 号 §5.1 第 5 行：BerryOS 比 Veda 的 permissions.json 白名单更强）。
- **第 7 条边界**：注入防护属 agent 服务实现面纪律，不进内核、不设特权 API
  （`应用模型设计-v1.0.md` §8.3「不设 Agent 特权 API」）。
- **非增量件已有归属**（21 号 §5.2 末段）：agentapp 三动词 → berryui typed action 协议（P2）；
  锁屏抑制 + presence 语义 → 移动档交互（P2）；`display::user_active` 独占授权 → 专属 handle 单发——
  均不在本设计重复立项。

## 4. 与既有面的边界表（一事实一归属）

| 事实 | 归属 | 本设计只做 |
|---|---|---|
| 「能不能」（handle 有无 / rights 门控 / 内核执法） | 能力模型 §1/§7/§8 | 引用不重述；审批后果落实为 handle 交接 |
| 策略注入的内核权限（SET_POLICY / Job 作用域 / 护栏拒收） | AI 调度 §3/§5 | 只消费「注入权也是能力」事实（其 §4 末条） |
| 委托链审计「谁把能力给了谁」 | AI 调度 §4 末条 / 应用模型 §8.2 | 把「何时批了什么档」并进同一账本 |
| manifest 形态与 `[capabilities]` 安装期授权 | 应用模型 §3 | 只加风险档声明节（add-only），字段全表归属不动 |

| Veda 语义论证与 GPL 许可纪律 | research/21 号 | 只引结论，论证与出处不复制 |
| 判例 | docs/雷册-判例库.md | 同意面暂无在册判例（2026-11-08 检索实证）；新判例走三处一动合同 |

## 5. 阶段化目标（诚实差距）

**v1 无 GUI 审批面，本设计是 v2 蓝图**：berry-launcher 桌面（GUI-8）已落但无审批组件，agent 服务未建，
审批链 v1 不实施。v1 可先落两件（零依赖，格式与词汇先行）：

1. **manifest 风险档声明格式**：manifest schema add-only 扩节——动作名 → 三档词表（串形 ↔ 有序
   u8 1/2/3，对齐 Veda Risk 枚举序）；执法 = berry-manifest 白名单 + mkapp 规范形门禁（应用模型 §3
   现役执法对）。v1 收格式不消费（运行时消费者 v3 才出现）；「未知节/未知键一律拒」现行纪律下扩节
   即立法动作，须随 berry-manifest 测试面同刀。目标态形（2026-11-08 实施裁定：节名 [agent-actions]，键 kebab-case，值三档字符串）：

```toml
[agent-actions]          # 动作风险档声明（add-only；v1 收格式不消费）
open = "routine"         # 动作名 → routine|sensitive|destructive（有序 u8 1/2/3）
save = "sensitive"       # 与 provides 语义槽（应用模型 §8.2）同面演进
empty-trash = "destructive"
```

2. **trace 审计事件词汇**：`consent` 类别五事件定名 + 同意面计数组形状（四计数模式同形）；词汇与
   ABI 形状 day-one 定型，对齐遥测环 `#[repr(C)]` 纪律（可观测性 §2）。v1 只定词汇，环与消费面按
   可观测性 §7 阶段走。

| 时点 | 内容 | 验收 |
|---|---|---|
| v1（先行两件） | manifest 风险档声明格式 + trace `consent` 事件词汇 | berry-manifest host 测试 + mkapp 门禁过；词汇表按本文 §2 定稿 |
| v2 | 同意面服务骨架 + 钩子一（SET_POLICY 委托面 + 委托链并账 + always-allow 生命周期）+ 审批 UI 挂 berry-launcher + 三档词表 | 审批状态机迁移枚举断言 |
| v3 | 钩子二（首次越档拦截）+ typed action 协议 + made-definite/双动作拆分 + TTL/打断/事后告知 + 注入防护 + 禁自唤醒 + 路径校验 | 状态机全迁移 + 台账对账断言；零授权态等价 |

零授权态等价是本设计的机器断言口径：未委托时 Agent 可用行为与无同意面逐位相同（POLICY 空表等价的
动作侧同构，「AI 不在线时等价于纯启发式」同句式）。
