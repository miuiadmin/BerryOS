# 能力模型设计（Capability Model）

> 决策依据见 `架构决策.md` #2、#3、#28。本文件展开"纯能力 + Zircon 内核态 handle=(对象, 代号)"。

## 1. 立场

- **纯能力**：访问任何资源（内存/线程/端点/IRQ/设备/命名空间）都必须持有一个对应 handle；内核无全局 UID、无 suid、无全局权限位。
- **对象在内核**：每个能力指向一个内核对象（Zircon 务实派），对象有引用计数与生命周期；用户态只见一个整数 handle。
- 权限只能**收紧**不能放宽。

## 2. handle = (对象, 代号) + 权限

```
RIGHTS_READ | RIGHTS_WRITE | RIGHTS_EXECUTE      /* 内存对象 */
RIGHTS_MAP | RIGHTS_DUPLICATE | RIGHTS_TRANSFER | RIGHTS_INSPECT   /* 通用 */
RIGHTS_SIGNAL                                    /* Event/通知 */
RIGHTS_SEND | RIGHTS_RECV                        /* Channel 端点 */
RIGHTS_MANAGE | RIGHTS_SET_POLICY                /* 资源/调度管控 */
```

- `duplicate(h, rights)`（= seL4 **mint** 的权限收紧侧）：新 handle 权限 ⊆ 原（防提权，永不增权）。
- `transfer`：handle 随 IPC 消息移动，发送方失去。
- 权限交集规则：派生能力 = 父能力 ∩ 请求权限。

**handle 表示与代号（决策 #28，借鉴 hubris generation 协议）**：
- handle = `(槽位号, 代号 gen)`。槽位号是 per-process handle 表索引；代号在该槽位回收重用时**单调递增**。
- **服务监督**：对象/服务死亡 → 旧代号作废；调用方拿旧代号调用 → 内核返 **`DEAD`**（区别于"从来无效"的 `BAD_HANDLE`）→ 调用方重试/降级（无缝对接 AI/PM 崩→启发式降级保活）。
- 与 seL4 mint/revoke 分工：**代号 + DEAD 管"死活感知"**，**mint 降权 / revoke 子树回收管"权限派生"**（见 §4）——互补不替代。
- **v1 预留**：handle 位域从 v1 起预留代号字段（即便 DEAD 检测延后启用），避免日后破坏已发布的 handle ABI（见 `系统调用ABI设计.md` §8.1）。

## 3. 内核对象类型

| 对象 | 说明 | 主要权限 |
|------|------|----------|
| Process | 地址空间 + handle 表容器 | MANAGE |
| Thread | 可调度执行流，挂 Process。**intent 声明权（ADR #42）**：= 创建者 / `SET_POLICY` 持有者；`LATENCY_CRITICAL` 需 **Job 级授权**（manifest/特权）；应用线程只能降不能升到高带（pledge 单调收窄） | MANAGE / SET_POLICY |
| VMO | 虚拟内存对象（见内存管理设计） | READ/WRITE/MAP |
| Vmar | 虚拟地址区间 | MAP/MANAGE |
| Channel | 同步消息端点（见 IPC 设计） | SEND/RECV |
| Event / EventPair | 信号/通知 | SIGNAL/WAIT |
| Interrupt | IRQ 对象 | SIGNAL/WAIT |
| Resource | 设备 MMIO/IO 授权 | MAP |
| Timer | 定时器 | SIGNAL |
| Job | 进程组/资源限额/监督容器；quota 结构预留 **energy 维 reserved 字段**（战略裁决 F3）。**与 band 预算的关系（ADR #42）**：band 预算 = 调度带宽包络（CPU 时间份额，调度器执法）；Job energy quota = 能耗总量上限（监督者执法）——正交叠加、互不替代 | MANAGE |

## 4. handle 表与生命周期

- 每进程一张 handle 表，handle = (槽位号, 代号)；槽位回收重用时代号单调递增（决策 #28）。
- 引用计数：`dup` 增、`close` 减；进程退出内核自动回收其全部 handle。
- 跨进程传递：经 Channel 随消息迁移（内核改挂归属，权限收紧）。
- **撤销（= seL4 revoke 子树回收）**：Job 沿树批量回收子进程 handle（失败隔离/资源管控）。
- **代号作废（= hubris DEAD）**：对象/服务死亡 → 旧代号作废，旧代号调用返 `DEAD`（见 §2）。撤销管权限回收、代号作废管死活感知，两者互补。

## 5. 引导：第一个能力从哪来

内核无全局特权，一切能力**递归派生**自引导包：

1. 内核启动第一个用户态进程（bootfs loader / init）。
2. 通过**引导通道（bootstrap channel）**传初始能力包：
   - root Job、root Vmar（init 的地址空间根）
   - bootfs VMO（内含初始可执行镜像）
   - root namespace handle（命名空间根）
   - 几个 Channel（kernellog、panic 等）
3. init 拿到 root namespace → 挂载/派生服务 → 把 handle 派生给各服务/进程。

> 无"特权进程"概念；init 的权力完全来自引导包里能力的递归派生。

## 6. 失败隔离（纯能力的自然结果）

- 服务崩溃 → 其 Job 监督者回收它持有的所有 handle（IRQ/VMO/Channel 一并失效）→ 重启时重新派生。
- 能力随进程死亡而失效 → 崩溃服务无法继续访问资源，天然防泄漏。

## 7. 与其它子系统接口

- **syscall**：几乎每个 syscall 首参是 handle，内核查表→校验类型+权限→执行（见 `系统调用ABI设计.md`）。
- **IPC**：Channel 传递 handle = 能力流动（见 `IPC设计.md`）。
- **内存**：VMO/Vmar 经 handle 持有与共享（见 `内存管理设计.md`）。

## 阶段化目标（v1 基线，对照 `架构决策.md` #20）

- **v1**：handle 表（位域预留代号字段，决策 #28）+ 基础对象（Process/Thread/VMO/Vmar/Channel/Event）；`close/duplicate/replace`（handle 迁移经 `channel_send`，见 `系统调用ABI设计.md`）；**引导通道传初始能力**（信任根 = 引导包，见 §5；运行期无特权进程）。（G0–G1）
- **v2**：Job 树 + 撤销（revoke 子树回收）；权限位全量。（G2–G3）
- **v3**：代号作废 + DEAD 检测启用（服务监督）；完整派生 / 审计。（G3+）

### 3-0 落地记录（2026-10）

`内核/src/handle.rs`：handle 位域（低 16 位槽号 + 14 位代号，bit31 预留类型编码；槽 0 恒空 = `BERRY_HANDLE_INVALID`）、rights 12 位 + `RIGHTS_SAME` 哨兵、错误码（`ERR_BAD_HANDLE`/`ERR_ACCESS_DENIED`/`ERR_INVALID_ARG`/`ERR_NO_MEMORY`，ABI §8.2 数值）、`KernelObj` 壳（v1 先 Vmo/Vmar）+ `ObjRef` 引用计数（最后 close 释放 = 本模块唯一 unsafe 释放点）、`HandleTable::{insert/duplicate/close/replace/get}`。

语义要点：**权限在 handle 不在对象**（每槽自带 rights）；duplicate 只紧不松（空/提权 → `ACCESS_DENIED`，`SAME` = 原全集）；close 后槽位代号 +1（旧值不复活；gen 耗尽拒用防回卷复活）；replace 先验两值保原子（任一无效表不动）。门控顺序 = 查表→类型→权限（§7，类型不符按 `BAD_HANDLE`）。v1 裁剪：对象销毁不回收物理页（统一随 3-2 `vmo_decommit` 落地）；`RIGHT_DUPLICATE` 位已定义暂不执法（Zircon 同款）。

验收：ktest `HANDLE ok`（七组用例：三门控放行 / 类型与权限拒绝面 / dup 收紧与提权拒 / close 后引用共享 / 槽位重用代号 +1 / replace 原子搬迁 / 坏 handle 面 0+野值）+ `just run`/`run-el2`/`smoke` 12/12 全绿。

### 3-1 落地记录（2026-10）

**syscall ABI 骨架**：`内核/src/syscall.rs`（语义层）+ HAL `syscall.rs` 重构（`install` 注册口，同 IRQ 槽反转）。

- **v1 27 号全部在册**（NR_* 常量组，编号对齐 ABI §4）；3-1 实现 4 个：`handle_close`(0x01)/`handle_duplicate`(0x02)/`handle_replace`(0x03)（经 3-0 `HandleTable` 门控——**syscall 全链路能力检查首次打通**）+ `clock_read`(0x61)（MONOTONIC 纳秒；先商后余防 ticks×1e9 中间溢出）。其余槽 HAL 默认 `-ENOTSUP`。
- **政策切换（撤 2b-4「畸形号杀」）**：未知/越界/未实现号一律 `-ENOTSUP` 存活、EL0/EL1 同权、绝不 panic——对齐 ABI §8.0。`exception_sync_el0` 的 SVC 分支无条件返回；杀只留给 CPU 故障（D-abort 等）。
- **引导表雏形**：全局单表 `BOOTSTRAP_HT`（原预告 3-2 拆表——实际后延：3-3 仍单表，3-4a 才拆 per-process 表、本表降格内核侧表）。并发边界：表变更仅 EL1 ktest/boot 期（IRQ 未开）；EL0 路径纯查表拒（无有效 handle 可写）。
- **copy_out 种子**：out 参数界检回写——用户区 `[0x1000, 2^39)` 经当前 TTBR0（调用者自身表）；内核高半区**仅 EL1 调用方**（SPSR.EL 判别；EL0 传内核指针一律拒——防伪造内核写）。3-2 扩全量 copy_from/to_user。
- **调试槽重排**：`NR_DEBUG_ECHO`=0xFE / `NR_DEBUG_PUTCHAR`=0xFF（非 ABI，P4 退役）；原 0x61/0x62 临时槽让位真号。
- **用户矩阵改板**：`user_good` 改 `clock_read` 两次单调性自检 + 'u'；`user_rogue_svc` → `user_abuser`（**真号 + 垃圾 handle 滥用**：`handle_close(0xDEAD_BEEF)` → -EBADF 存活 + 打 'S' 金丝雀）；watchdog 断言杀数==1（只 rogue_ptr 死）。
- 验收：ktest `SYSCALL ok`（echo / 未知号 -ENOTSUP / clock 单调 / handle 门控四断言）+ `G1.5 ok (rogue dead, abuser alive, canaries alive)` + `run`/`run-el2`/`smoke` 12/12。

### 3-2 落地记录（2026-10）

**VMO/Vmar syscall 全量门控 + 跨界拷贝**：9 号全实现（create/commit/decommit/read/write + map/unmap/protect/allocate，ABI §4 0x11–0x19）。

- **rights 矩阵**：`vmo_create` 授 READ|WRITE|MAP|DUPLICATE；boot root Vmar 授 MAP|MANAGE|DUPLICATE；`vmar_allocate` 子 Vmar 承父 handle rights 全集。操作面：commit/decommit/write 需 WRITE、read 需 READ、map/unmap 需 Vmar MAP（map 另需 Vmo MAP|READ|WRITE——可读映射须句柄 READ，防经映射逃逸读，3b3 M6 修）、protect/allocate 需 MANAGE。map 的 rights 参数 v1 须恰为 READ|WRITE（外位 -EINVAL、缺 WRITE -ENOTSUP——只支持 UserRw 映射，UserRo 留 v2）。
- **copy_from/to_user**：EL0 指针界检 `[0x1000, 2^39)` + 逐页走查**当前 TTBR0**（= 调用者自身表）验 AP 位，校验后直拷（256B 栈分块）；EL1 调用方走高半直映。**无 TOCTOU**：SVC 入口硬件置 DAIF + handler 不解蔽 → syscall 主体不可抢占（单核），表与对象免锁。
- **悬空 PTE 防线（mapcnt 三件套）**：Vmo 每页映射计数（map 时 +1、unmap 经 Region 存的 Vmo 指针 -1）；**销毁性 close（refs==1）遇映射未解除 → -EBUSY**（先 unmap 再 close 最后一个；**别名 close 放行**——对象不死，存活句柄钉住它）；decommit 拒映射中页（-EBUSY）；`Vmo::Drop` 对映射中页只泄漏不归还（安全方向）。replace 拒绝面同 close（h 侧销毁性才拒，保「任一拒绝表不动」原子性）。
- **no-panic 防线**：`vmo_create` size 上限 16MiB（超限 -ENOMEM——巨 size 的 Vec 分配 abort 是 EL0 可触发 panic，违 ABI §8.0）；对象取用一律 Option/Result，无 unreachable。
- **首能力（§5 实证）**：`user_good` 的 root Vmar 由 boot 插入 `BOOTSTRAP_HT`（MAP|MANAGE|DUPLICATE），handle 经 spawn arg → 入口 x0 交给用户——**Phase 3 里程碑完全体**：`user_good` 一次性验收链 `create→commit→write→map@0x5000→VA 读写→read 别名回读→close 拒(-EBUSY)→dup RO 写拒(-EACCES)→别名 close 放行→unmap→decommit→close` 全绿（链只跑一次：14 位代号经不起循环 create/close 耗 gen）；任一步错 → 自陷被杀 → watchdog 错杀断言 FAIL。
- **watchdog 升级**：`berry_sched::last_killed()` 断言**杀的是 rogue_ptr**（kills==1 但死 good/abuser ≠ PASS——3-2 调试期该盲点真实放过一次错杀，修法即此）。
- **UserProcess 拥有关系**：三 Vmo（code/data/stack）由结构体泄漏持有——Vmar Region 存 Vmo 对象指针（unmap 回调 mapcnt 要求对象存活）；good 的 root Vmar `take()` 走进引导表，rogue/abuser 的留结构体内。
- 验收：ktest `SYSCALL ok`（E 段：参数面/读写往返/错误映射/vmar 全链/allocate）+ `G1.5 ok`（含错杀断言）+ `run`/`run-el2`/`smoke` 12/12 + `test-host` 11 绿。

### 3-3 落地记录（2026-10）

**process/thread 最小对象**：`内核/src/process.rs` + `syscall.rs` 三号（0x31/0x32/0x34）；ABI §8.3 原型随落地修正（见下）。

- **对象模型（v1 最小面）**：Process = root Vmar 的壳（`NonNull<ObjRef>` 钉住 + ttbr0/asid 快照）；Thread = 未启动执行流描述（entry/sp 由 `process_start` 填——首线程启动路径，Zircon 同形），`started` 前不进调度器。**对象间钉住**：Thread 钉 Process、Process 钉 root Vmar、`process_start` 成功后再替运行中的任务钉一次 Process（v1 任务不退出永不释放）——`ObjRef::retain/release` 与 handle 计共用同一归零释放点（Drop 链不回表、无重入）；持有者关光 handle 后被引用对象仍存活，无悬空。
- **`process_create` 双出参（ABI §8.3 v1 修正，Zircon `zx_process_create` 同形）**：`(*process, *vmar)`——父进程必须拿到子地址空间根才能映代码/栈，单出参无法装配子进程。出权：process = MANAGE|DUPLICATE，root Vmar = MAP|MANAGE|DUPLICATE（与 boot root 同面）。
- **v1 参数面（诚实豁口）**：`job` 恒 0——**进程创建权未设防**（无 Job 对象前无「在谁之下建」的授权载体，Job 落地 v2 后收紧为真门控）；`process_start` 的 `bootstrap` 恒 0（per-process handle 表落地前无「handle 移入子进程固定槽」载体，子入口 x0=0）。
- **门控**：`thread_create` 需 process **MANAGE**；`process_start` 需 process+thread 各 **MANAGE** + 归属校验（thread 非该 process 的 → -EACCES）+ 参数面（entry=0/sp 未 16 对齐/bootstrap≠0 → -EINVAL）+ 状态面（已启动 → -EBADSTATE）。错误码自理、永不杀调用者（§8.0）。
- **表边界**：引导表仍是全局单表（3-2 决策延续）——**3-3 不拆 per-process 表**：3-4 channel 的 handle 迁移才是拆表硬前置；v1 子进程 handle 暂与父共享名字空间（诚实记录，非长期语义）。
- **ktest F 段**（对象面/错误面——ktest 在 `berry_sched::init` 之前跑，start 成功路径会 spawn 故不在此验）：双出参非零 + 类型断言、job≠0/options≠0 -EINVAL、thread_create 类型门控/坏 handle -EBADF、process_start 参数面 -EINVAL、跨进程归属 -EACCES、清场覆盖钉住释放链（close 线程→释放 Process 钉住→close 进程→释放 Vmar 钉住）。
- **验收（拆步表「用户进程创建第二个进程」）**：第 4 个 EL0 进程 `user_spawner`——经真 syscall 全链 `process_create`（双 handle）→ `vmo_create`(0x2000)/`commit`/`write`（写入**内嵌在自身代码页**的子代码字节，`adr` 同页自相对取址、模板搬迁安全）→ `vmar_map` 映进子空间（代码@0x1000 + 栈同 VMO 第二页）→ `thread_create` → `process_start`；子进程 `user_child` 打 'C'、spawner 打 's'，与 A/B/u/S 六执行流分时；watchdog 错杀断言不变（kills==1 且只 rogue_ptr）。
- 验收：ktest `SYSCALL ok`（E+F 段）+ `G1.5 ok` + `run`/`run-el2`/`smoke` 12/12 + `test-host` 11 绿。

### 3-4a 落地记录（2026-10）

**per-process handle 表 + bootstrap 迁移转正**：3-3「恒 0」过渡约定退役（ABI §8.3 随改）。

- **表拆分**：`Process` 自有 `ht: HandleTable`（出生为空——一切能力由父进程授入，§4/§5）；boot 手搭用户进程（`UserProcess`，无 Process 对象）各挂一张 `Box::leak` 常驻表；`BOOTSTRAP_HT` 降格为**内核侧表**（ktest EL1 测试面 + 未来 init 的表雏形）。
- **派发载体 `Task::proc_tag`**：`进程调度` crate 存不透明 usize（0 = 内核任务/boot 期），语义归 `内核` crate——syscall 层解释为该任务所属进程的表指针（`caller_table`：EL1 → 内核侧表，EL0 → tag 查表，tag==0 → -EBADF）。crate 边界干净（sched 不反向依赖内核）。tag 来源仅两处（leak 表 + `Process::ht`），Box'd ObjRef 地址稳定、运行中任务钉住 Process → 表与任务同寿。
- **迁移原语 `take`/`insert_ref`**（handle.rs）：take 摘槽、代号 +1（原值立即作废）、**refs 不变**（引用令牌迁移非销毁——映射中 VMO 照样可迁，EPTE 防线仍由最终 close 把守）；insert_ref 把已 Boxing 的 ObjRef 落进目标表新槽。消费者：`process_start` bootstrap（本步）、`channel_send` handle 随消息迁移（3-4b）。
- **bootstrap 迁移转正（Zircon `zx_process_start` 同形）**：非 0 时从调用者表 take → insert 进子进程表 → 子入口 x0 = 子表内新 handle 值。原子性：take 失败（-EBADF）子表不动；insert 失败（表满，v1 不可达）回滚重插调用者表（handle 值或变——代号推进，语义存活）。ktest F3 的 `bootstrap≠0 → -EINVAL` 面改**垃圾 bootstrap → -EBADF**。
- **ktest G 段**（表对象面）：两表隔离（他表 handle 必 -EBADF）/ take 后原值作废 / insert_ref 新值三门控可查 / close 迁移值即最终 close（refs 未增）/ process_create 出的子进程出生自带空表（父 handle 不可见）。
- **验收（拆步表「子进程凭自己表里的 handle 读出父进程赠予的 VMO」）**：spawner 建**礼物 VMO**（1 页，写 USER_MAGIC 魔数）→ `process_start(…, bootstrap=礼物)` → 迁移后 spawner `close(原值)` 必 -EBADF（发送方失去自证）；`user_child` 拿入口 x0（子表 handle）节流后 `vmo_read` 出魔数比对（低 32 位，w 寄存器比对）→ 打 'C' 进稳态循环。链断 → 自陷被杀 → watchdog 错杀断言 FAIL（调试期实抓一次：模板复用错寄存器 x3（syscall offset 参数）当缓冲指针 → 野读 0 地址被杀 → `杀数 2 > 1` panic——防线按设计工作）。串口 'C'/'s' 不变（smoke 12 标记零改动）。
- 验收：ktest `SYSCALL ok`（E+F+G 段）+ `G1.5 ok` + `run`/`run-el2`/`smoke` 12/12 + `test-host` 11 绿。

### 3-4b 落地记录（2026-10）

**channel 三号 + handle 随消息迁移**：`内核/src/channel.rs`（对象）+ `syscall.rs` 0x51/0x52/0x53（ABI §8.3 原型随落地补 v1 语义注记）。

- **对象模型**：`ChannelEnd { peer: Option<NonNull<ObjRef>>, queue: Vec<Message> }`——`channel_create` 一次建一对、`pair()` 互指**互钉**（各 retain 对端：本端活 ⇒ 对端对象必活，防 send 走 peer 悬空）。消息 = inline 字节（≤256）+ 随行 handle 令牌（≤4，`(NonNull<ObjRef>, Rights)`）；队列深度 8（有界性 = send -EBUSY 来源）。`Option` peer 是关键修：**未配对端点 Drop 不碰任何指针**——create 第二端入表失败的回滚 close 走 None 分支（若用 dangling 占位，回滚会 release 野地址）。
- **send 原子序**（任一步失败 = 调用者表零变化）：参数上限（nbytes>256/nhandles>4 → -EINVAL，no-panic 前置）→ 门控 RIGHT_SEND → 对端满检（-EBUSY）→ 随行值拷入 + **全量预检**（`HandleTable::alive` 探活 + **数组内重复值拒 -EINVAL**——先 take 会作废后值、回滚也换值，预拒保原子）→ 载荷拷入（-EFAULT）→ 全量 take（v1 不可达防御面，回滚重插）→ 压对端队列。take/insert_ref 不动 refs——令牌随槽迁移。
- **recv 原子序**：门控 RIGHT_RECV → **空队先检**（-EAGAIN 在任何用户内存读之前 = 空时零 fault 面）→ pop 消费 → 容量 in-out 读入（不足 → -EINVAL）→ 载荷拷出 → 令牌 `insert_ref` 入调用者表（新值收集）→ 回写 handles 数组/实际 nbytes/nhandles。任一中途失败 → `recv_rollback`：take 回已入表的令牌 + 消息 `push_front` 压回**队首**（FIFO 不能从队尾补回）。
- **能力随消息跨表迁移（§4 实证）**：发送方 `take` 出表（close 原值必 -EBADF）、接收方 `insert_ref` 落**自己的**表（新值必变）——与 3-4a bootstrap 迁移同一对原语，通道即第二个消费者。
- **v1 泄漏政策（安全方向，诚实记录）**：① 对端互钉成环——两端 handle 全关也不释放；② 消息中未收割的令牌随队列泄漏（refs 不减）；③ 对端关闭检测不做（需 DEAD 检测，v3）——send/recv 对死端表现如常。三者皆「泄漏不悬空」，v3 DEAD 检测 + Weak peer 收口。
- **ktest H 段**（对象面八组）：create 双端非零/可门控、空 recv -EAGAIN、send→recv 往返 + 再收 -EAGAIN、参数上限 -EINVAL（257B/5 handle/容量不足 + 补容后同消息完好）、深度 8 满 → 第 9 条 -EBUSY、RO 端（仅 RECV）send -EACCES、**handle 迁移**（send 后原值 -EBADF、recv 新值可 `vmo_commit` 使用）、**send 原子性**（[活值, 死值] → -9 且活值仍在表；[同值, 同值] → -22）。
- **验收（拆步表「两进程交换一句消息」）**：spawner/child 改板——spawner `channel_create` 建对 → `send(PING + 礼物 VMO handle)`（**能力经消息进子进程的端点队列**，close 礼物原值必 -EBADF）→ `process_start(…, bootstrap=end1)`（端点本身再经 3-4a 迁移进子表，close 原值必 -EBADF）；child 凭**自己表里**的端点首链 recv 出 PING+礼物 → `vmo_read` 魔数比对（双重迁移闭环）→ 稳态收 PING 回 REPLY 打 'C'；spawner 稳态发 PING、收 REPLY 验魔数打 's'（非阻塞双侧容忍 -EAGAIN/-EBUSY，无死锁）。串口 's'/'C' 交替 = 消息往返活证；链断 → 自陷被杀 → watchdog 错杀断言 FAIL。
- 验收：ktest `SYSCALL ok`（E+F+G+H 段）+ `G1.5 ok` + `run`/`run-el2`/`smoke` 12/12 + `test-host` 11 绿。

### 3-4c 落地记录（2026-10，Phase 3 收官）

**event 三号 + 遥测环 + 空策略表等价测试**。前半（AI 策略注入留桩，44e5988）：`进程调度/src/policy.rs`（词汇表 = §2 四类动作封顶：①放置 hint ③包络内权重微调（内核 clamp ±64 执法）④EPP 二值；②频率走 PM 不入表）+ `RoundRobin::pick_next` 出选后查表钩子；后半（本批）：event 对象 + 三号 syscall + 切换遥测环 + ktest I/POLICY 段。

- **event 对象**（`内核/src/event.rs`）：`Event { signals: u64 }` 纯位掩码——无队列/无对端/无钉住，最简内核对象。`event_create(0x54)`：options 恒 0（非 0 → -EINVAL）、授 **SIGNAL|DUPLICATE**（持有者可置/清位、可复制给同伴；等待方 dup 到无 SIGNAL 即可查——wait 不需权利位）。
- **object_signal(0x06)**：`signals = (signals & !clear) | set` 一条原子（IRQ 屏蔽下单核串行）；门控 RIGHT_SIGNAL；v1 仅 Event 可 signal（thread/process 信号面随后续步）。
- **object_wait_one(0x04) = poll-only**：非阻塞查一次——命中（`current & signals != 0`）→ `*observed = current`（**全满足集**，Zircon `zx_object_wait_one` 同形）返 0；未命中 → -EAGAIN。**`deadline ≠ 0` 一律 -ENOTSUP**（阻塞等待排队留 P4——v1 syscall 主体不可抢占的免锁根基下没有安全睡眠路径，诚实缺口按号拒而非静默忙转）；0x05 wait_many 仍 -ENOTSUP（ktest B 段未实现样本 0x04→0x05）。等待不需权利位（12 位 rights 表无 WAIT 位，持有 handle 即可查）。
- **ktest I 段**（六组）：create options 拒/正常建 + rights 三门控可查、poll 未命中 -EAGAIN + deadline≠0 -ENOTSUP、signal 置位 → wait 命中回写全满足集（0b0110 非 0b0010）、请求未置位 -EAGAIN + 清位后原位 -EAGAIN、**权利面**（dup 收紧到仅 DUPLICATE → signal -EACCES / wait 照常可查）、类型/野值门（VMO handle 与 0xDEADBEEF 一律 -EBADF）+ 清场后 close 原值 -EBADF。
- **遥测环**（`内核/src/telemetry.rs` + `进程调度/src/sched.rs` 切换钩子）：`set_switch_hook` 槽（boot 期注册，模式同 HAL install 反转——crate 边界干净）；三切换位（yield/抢占/exit）在 `CURRENT = next` 后、`context_switch` 前发射 `(prev, next, SwitchKind)`。环 = **静态预储 64 × SwitchRec**（`#[repr(C)]`：vct/prev/next/kind/idle_next——ABI 形状 day-one 定型），写入**零分配**（try 化批「IRQ 热路径零分配」纪律不破）；任务 id = 名字 FNV-1a-32 稳定哈希；idle 判据 = `kstack.is_none()`。**消费路径留 v3**（`telemetry_open` 映射环给 trace/AI 策略服务）；v1 读点 = watchdog 存活断言：`telemetry::total() ≥ switches()`（环计全三型切换、SWITCHES 只计抢占）+ 环内 vct 旧→新单调（`check()`）——随 `G1.5 ok` 每次过关前自证。
- **空策略表等价测试**（ktest `POLICY ok`，smoke 第 13 标记）：本地 `Runqueue` + `RoundRobin` + 三任务（proc_tag 7/8/9 = 策略表 key 域）12 轮 pick 记录（选中者, prio_effective, epp）——**A** 未绑基线 / **B** 绑空表 → 序列逐项全等（接口在位 + 表空 = 零写入 = 与接口缺席逐位等价，「AI 不在线时等价于纯启发式」的机器断言非口号）/ **C** 绑对照表（p7 权重 +32、EPP=Perf）→ **字段必须真变**（apply 反向控制，防留桩成死代码的假等价）且**选人序列不变**（RR 不看优先级 = v1 护栏：注入面只写 TCB 表示法字段，绝不碰机制决策）/ 收尾 unbind（smoke 稳态全程未绑——等价性延续到真实调度路径）。进程调度 crate 无 host 测试面（HAL aarch64 asm），QEMU ktest 是唯一家。
