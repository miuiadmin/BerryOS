# 文件系统设计

> FS 全是**用户态服务**（微内核硬约束）。**FAT 仅 MVP**；目标现代 FS（CoW + 日志 + 校验）。
> 决策依据见 `架构决策.md` #27、#15。与 IPC（`/svc/fs`）、内存（文件背靠 VMO + pager）、能力（fd/handle）联动。

## 1. 分层

```
用户进程 ─open/read/write─▶ POSIX 库 ─▶ Channel IPC ─▶ /svc/fs
                                                         │
                                          ┌──────────────┴──────────────┐
                                          VFS（路径/fd/挂载/缓存）        │
                                          └──────────────┬──────────────┘
                                              具体 FS 服务：FAT / 现代 FS
                                                         │
                                                  块设备服务（virtio-blk）
```

- **VFS**（用户态）：路径解析、fd 句柄、挂载表、页缓存。是 `/svc/fs` 的内核。
- **具体 FS**：FAT（MVP）/ 现代 FS（目标），各自一个服务，挂到 VFS。
- **块设备**：virtio-blk（QEMU）→ 真实驱动；DMA 经 SMMU（见 `安全与硬件隔离设计.md`）。

## 2. MVP：FAT（互操作优先）

- 只读 + 读写；镜像可挂、可读写、可与宿主互操作。
- 用途：跑通"端到端读写文件"这一集成里程碑（路线图 MVP 拆解第 6 步），**不追求先进**。
- 明确：FAT 无崩溃一致、无校验、无大文件优化——**只是起步**。

## 3. 目标：现代 FS（对标 ZFS / bcachefs / APFS）

| 特性 | 为什么 | 对标 |
|------|--------|------|
| **写时复制（CoW）** | 快照、瞬间克隆、避免损坏原数据 | ZFS / bcachefs / APFS |
| **日志 / 事务** | 崩溃一致（断电不丢元数据） | ext4 journal / ZFS ZIL |
| **数据 + 元数据校验** | 静默腐烂（bit rot）可检测/修复 | ZFS / bcachefs |
| **大文件 / 稀疏文件** | 跨平台（PC 大存储、虚拟磁盘） | 通用 |
| **权限 → 能力映射** | 文件权限是能力的一种投影 | Fuchsia（能力即 fs 权限） |

- 自研 or 选型：MVP 之后**优先评估** bcachefs 思路 / Fuchsia blobfs+minfs / Redox redoxfs，避免重造。
- **数据完整性是硬目标**：校验 + CoW 不是 nice-to-have，是"跨平台 + 可信存储"的刚需。

## 4. 文件 = VMO（与内存管理联动）

- 打开文件 → 内核建一个 VMO 背靠该文件内容；`mmap` = 把该 VMO 映射进进程 Vmar。
- **缺页由 FS pager 填**：读到缺页 → 内核通知 FS 服务（经 Event/共享环快路径）→ FS 读块填页 → 回复 → 建映射。
- 这正是 `内存管理设计.md` §4 用户态 pager 模型——FS 是最常见的 pager。
- 写回：脏页由 FS 服务择机刷盘（写时复制 / 日志保证一致）。

## 5. 块设备 / DMA

- virtio-blk（QEMU `virt`）→ 真实块驱动。
- DMA 缓冲 = 锁页/连续 VMO，经 SMMU domain 限定（设备只能 DMA 进授权区间）。

## 6. 阶段化目标

- **v1**：无 FS（bootfs 内存镜像即可，参考 Fuchsia bootfs）。
- **v2**：FAT（只读起步 → 读写）；`/svc/fs` 挂载。
- **v3**：VFS 完整（多挂载、fd、页缓存）；FS pager 填页打通。
- **v4**：现代 FS（CoW + 日志 + 校验）——自研或选型落地。
