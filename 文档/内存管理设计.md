# 内存管理设计

> 决策依据见 `架构决策.md` #4、#9、#10、#29。本文件展开"VMO + 用户态 pager + 每进程独立 AS"（VMO 5 类后备见 §2）。

## 1. 三层结构

1. **物理内存（PMM）**：buddy 分配器，管全部物理页，基础页 4KB（后期支持 64KB/2MB 大页）。
2. **内核虚拟**：direct map（整段物理内存线性映射到内核固定 VA）+ 内核代码/数据/堆/每核栈。内核随时能按物理地址访问任意页。
3. **用户虚拟**：每进程独立页表（ASID），由 **VMO + Vmar** 构造。

## 2. VMO（内存对象，内核态）

- 内核对象，背靠若干物理页（可连续、可按需）。
- 操作：`create / commit（提交页）/ decommit / read / write / map（映到 Vmar）/ share（传 handle）`。
- 引用计数：多进程共享同一 VMO；可选 copy-on-write。
- **pager 集成**：VMO 可标"按需/可换出"，缺页时内核通知该 VMO 绑定的 pager 服务（经 Event/共享环），由用户态 pager 提交/换出/读盘填页。
- **VMO 后备来源（5 类枚举，决策 #29，借 Redox grant）**——`vmo_create` 的 options 区分：

  | 后备类 | 说明 |
  |--------|------|
  | **物理页（匿名）** | 默认：commit 提交物理页，可 CoW |
  | **共享（shared）** | 多进程映射同一物理页集，零拷贝 |
  | **MMIO** | 映射设备寄存器区（配 Resource/SMMU，见 §6） |
  | **跨 AS（external）** | 物理页归属另一地址空间/对象，本 VMO 引用 |
  | **文件映射（fmap / pager-backed）** | 缺页由用户态 pager 从文件填页（见 §4） |

  PageInfo 引用计数统一管这 5 类；CoW 写时按页迁移到 shared（Redox 成熟参考）。显式区分后备来源比单一 VMO 精细，直接落 `内存管理/`。

## 3. Vmar（地址区间）

- 每进程一个 **root Vmar**（覆盖其整个用户 VA）。
- `map(vmar, vmo, vaddr, rights)` 把 VMO 映射进某区间；支持 ASLR 随机化。
- `unmap / protect / query`。

## 4. 按需调页路径（用户态 pager）

```
CPU 缺页 → 内核查 Vmar 映射
        → VMO 该页未提交 → 内核向 pager 服务发缺页事件（VMO handle + 偏移）
        → pager commit/读盘填页 → 回复
        → 内核建立映射 → 恢复线程
```

- 内核**不自己换页、不读盘**（纯微内核）；策略全在用户态 pager 服务。
- pager 持 VMO 的特定权限（pager/SET_POLICY），是普通用户态服务，可换、可崩（崩则该 VMO 的页暂不可用，但系统其它部分不受影响）。
- 缺页快路径零分配，经 Event/共享环，避免尾延迟。

## 5. 内核 VA 布局（ARM64）

- 高位一半内核、低位一半用户。
- **内核 direct map**：全部物理内存线性映射到内核一段 VA（内核访问任意物理页 = 加偏移）。
- 内核：代码/数据、slab 堆、每核栈、per-CPU 数据、异常向量表。
- 用户：`0 .. USER_LIMIT`，per-process 页表 + ASID。

## 6. 大页 / DMA

- **大页**（2MB/1GB）后期用，降 TLB miss（PC 大内存/高吞吐）。
- **DMA**：连续物理页 VMO（`CONTIGUOUS` 标志）+ 锁页（不可换出）；驱动用户态服务映射后交给设备。

## 7. 与能力的关系

- VMO / Vmar 都是内核对象 → 有 handle、权限（`READ/WRITE/MAP` 等）、可共享传递。
- 用户态拿内存的**唯一正规途径**：`create`/收到 VMO handle → 映射到自己的 Vmar。无"隐式"内存访问。

## 8. SMP / 抢占注意

- 页表修改需 TLB shootdown（跨核失效），用 IPI；全可抢占下页表锁要细。
- per-CPU buddy free-list 减少锁竞争（配细粒度 SMP）。

## 9. 参照

- VMO/Vmar：Zircon（`zx_vmo_*` / `zx_vmar_*`，BSD/MIT）。
- 用户态 pager：seL4 pager 模型（思路）。

## 阶段化目标（v1 基线，对照 `架构决策.md` #20）

- **v1**：PMM buddy + 内核 direct map + 每进程页表；VMO/Vmar 的 `create/map`；**不做 demand paging**（启动时全映射，pager 接口留空）。这是避开"pager × 抢占 × 细锁递归死锁"的关键。（G0–G2）
- **v2**：用户态 pager（`supply_pages`）；大页；TLB shootdown。（G3–G4）
- **v3**：换出 / CoW / DMA 连续 VMO / IOMMU。（G4+）
