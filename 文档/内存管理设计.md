# 内存管理设计

> 决策依据见 `架构决策.md` #4、#9、#10、#29。本文件展开"VMO + 用户态 pager + 每进程独立 AS"（VMO 5 类后备见 §2）。

## 1. 三层结构

1. **物理内存（PMM）**：buddy 分配器，管全部物理页，基础页 4KB（后期支持 64KB/2MB 大页）。
2. **内核虚拟**：direct map（整段物理内存线性映射到内核固定 VA）+ 内核代码/数据/堆/每核栈。内核随时能按物理地址访问任意页。
3. **用户虚拟**：每进程独立页表（ASID），由 **VMO + Vmar** 构造。

## 2. VMO（内存对象，内核态）

- 内核对象，背靠若干物理页（可连续、可按需）。
- 操作：`create / commit（提交页）/ decommit / read / write / map（映到 Vmar）/ share（传 handle）`。
- 引用计数：多进程共享同一 VMO；可选 copy-on-write。
- **pager 集成**：VMO 可标"按需/可换出"，缺页时内核通知该 VMO 绑定的 pager 服务（经 Event/共享环），由用户态 pager 提交/换出/读盘填页。
- **VMO 后备来源（5 类枚举，决策 #29，借 Redox grant）**——`vmo_create` 的 options 区分：

  | 后备类 | 说明 |
  |--------|------|
  | **物理页（匿名）** | 默认：commit 提交物理页，可 CoW |
  | **共享（shared）** | 多进程映射同一物理页集，零拷贝 |
  | **MMIO** | 映射设备寄存器区（配 Resource/SMMU，见 §6） |
  | **跨 AS（external）** | 物理页归属另一地址空间/对象，本 VMO 引用 |
  | **文件映射（fmap / pager-backed）** | 缺页由用户态 pager 从文件填页（见 §4） |

  PageInfo 引用计数统一管这 5 类；CoW 写时按页迁移到 shared（Redox 成熟参考）。显式区分后备来源比单一 VMO 精细，直接落 `内存管理/`。

## 3. Vmar（地址区间）

- 每进程一个 **root Vmar**（覆盖其整个用户 VA）。
- `map(vmar, vmo, vaddr, rights)` 把 VMO 映射进某区间；支持 ASLR 随机化。
- `unmap / protect / query`。

## 4. 按需调页路径（用户态 pager）

```
CPU 缺页 → 内核查 Vmar 映射
        → VMO 该页未提交 → 内核向 pager 服务发缺页事件（VMO handle + 偏移）
        → pager commit/读盘填页 → 回复
        → 内核建立映射 → 恢复线程
```

- 内核**不自己换页、不读盘**（纯微内核）；策略全在用户态 pager 服务。
- pager 持 VMO 的特定权限（pager/SET_POLICY），是普通用户态服务，可换、可崩（崩则该 VMO 的页暂不可用，但系统其它部分不受影响）。
- 缺页快路径零分配，经 Event/共享环，避免尾延迟。

## 5. 内核 VA 布局（ARM64，Phase 2b 起实装）

39-bit VA（T0SZ=T1SZ=25）：低半 `[0, 0x80_0000_0000)` = 用户；高半 `[0xFFFF_FF80_0000_0000, 2^64)` = 内核（ADR #36，canonical TTBR1，**非**过渡式身份共存）。

- **内核高半基址 `KERNEL_VA_BASE = 0xFFFF_FF80_0000_0000`**（39-bit VA 高半的底）。
- **一条规则贯穿全内核**：`phys_to_virt(pa) = KERNEL_VA_BASE + pa`。`内存管理/src/va.rs` 是唯一交换点（Phase 1 已预埋），2b-1 只改这一个函数 + 重链。含义：
  - **direct map 即全物理空间**：RAM `[0x4000_0000, 0x8000_0000)` 与设备 MMIO（UART `0x0900_0000`、GIC `0x0800_0000`）统一映到 `KERNEL_VA_BASE + pa`——内核访问任意物理页/寄存器 = 加偏移，无第二套窗口。
  - 内核镜像 VMA = `KERNEL_VA_BASE + 0x4000_0000`，LMA 仍 `0x4000_0000`（链接脚本 `AT()`）。
  - TTBR1 表与现行 boot 表**同构**：L1[0] → 设备 2MiB 块、L1[1] → RAM 2MiB 块——只是挂到 TTBR1、按 KVA 索引。
- 无独立 vmap 窗口、无 KIMAGE 专属区（128MiB RAM 规模下 direct map 全覆盖即够；细粒度 vmap/大页是 v2+ 的事）。
- **TCR 不变**（39-bit、TG0/TG1=4KiB）；TTBR0 腾空给用户（每进程页表 + ASID）。

### 5.1 高半翻转拆步（Phase 2b 落地路径；S4 裁决「准备→切 TTBR1→逐进程页表」，每步独立可启动、可单独回退）

| 步 | 内容 | QEMU 可见验证 | 回退 |
|---|---|---|---|
| **2b-0 准备** | 建独立 TTBR1 内核表（高半 RAM+MMIO 块映射），TTBR0 暂留身份表；内核仍跑低地址 | 内核自校验：读 `KERNEL_VA_BASE+pa` RAM 别名处的魔数成功；既有 smoke 全绿 | 撤 TTBR1 写入即回退 |
| **2b-1 切 TTBR1（命门）** | 链接脚本 VMA=高半 / `AT(0x4000_0000)`；`.text.boot` 留低半（VMA=LMA）跑 EL 检测/清 bss/建表；开 MMU（TTBR0=身份、TTBR1=内核表）后 `br` 跳高半入口、换高半 SP；`phys_to_virt` 翻为加基址 | `just run` / `run-el2` 全链路标记**照旧**——外部行为零变化是本步验收线 | revert 链接脚本 + mmu.rs（单提交） |
| **2b-2 逐进程页表 + ASID** | 帧分配器出页做每进程 L1；ASID 分配（见 §5.2）；switch 写 TTBR0+CONTEXTIDR + `tlbi aside`；**低半身份表退役**（TTBR0=空用户表）；GIC/UART 的 MMIO 访问从 PA 常量改走 `phys_to_virt`（gic.rs/mmio 调用点，机械改动） | 内核建两张"用户"页表互切、各自映射一页可读写（仍 EL1 测试任务）；低半地址访问必然 fault 是**正向**断言 | 保留身份表分支开关 |
| **2b-3 匿名 VMO/Vmar** | `create/commit/map/unmap/protect/allocate`（决策 #4/#29 物理页后备先行）；map 即填用户页表 | 内核任务经 VMO 映射读写一页 | — |
| **2b-4 首个 EL0 + G1.5** | EL1→EL0 下降（SP_EL0 + `eret`），首用户进程；**出口关卡 G1.5**（野指针/越界/垃圾 handle → 仅该进程死，内核与金丝雀无恙）；表示法字段随本步落 TCB（duration-hint / EPP / 周期数 / preemption-threshold / PI base·effective 双优先级，见 `调度器设计.md` §3.6） | 用户进程跑飞仅自身死、`switches=` 金丝雀照跑 | — |

**已识别坑（动手前先读，均来自现状代码核对）**：

- **VMA≠LMA 调试地狱**：反汇编/符号表显示高半地址、实际加载在低半——以 `readelf -l`（p_vaddr ≠ p_paddr）为准；QEMU `-kernel` ELF 按 **p_paddr** 落内存（2b-1 首提交时在 smoke 里加程序头断言防漂移）。
- **早期 asm 绝对寻址**：`.text.boot` 必须 VMA=LMA 留低半，否则 MMU 未开时取/跳符号地址即死；清 bss、建表全用 PA 侧地址。
- **ADRP ±4GB 双向限制（2b-1 实测新增）**：PC 相对 ADRP 跨不了低↔高半，两个方向都炸——(a) 低半早期代码引用高半静态量 → 4 张 boot 表移入 `.bss.boot`（VMA==LMA），`build_boot_pt`/`enable_mmu` 进 `.text.boot`（其调用的 paging 描述符助手须 `#[inline(always)]`，非内联 call 到高半 .text 会在开 MMU 前 fault）；(b) 高半代码 ADRP 取低半绝对符号地址同样越界（`R_AARCH64_ADR_PREL_PG_HI21 out of range`）→ mm.rs 导入高半 `__kernel_end` 运行时减 `KERNEL_VA_BASE`，asm 里用 `ldr =`（绝对值装载，无范围问题）。
- **镜像布局 → `.data/.bss` 零拷贝（2b-1 实测新增）**：VMA = KERNEL_VA_BASE + LMA 使所有主体段落在直映区——QEMU 按 p_paddr 落内存、高半直映同一物理页，boot 期**无需任何数据搬迁循环**（只清 .bss）。
- **双别名窗口纪律**：2b-0 ~ 2b-2 之间 UART/GIC 同时存在低半与高半两个映射——同一时刻只经一个别名访问（现状 gic.rs 直用 PA 常量，跳高半后改走 `phys_to_virt`；切换点前后 `isb`）。低半退役后问题消失。
- **boot 栈**：早期沿用镜像内低半 PA 栈，跳高半入口后换 `__stack_top`（高半符号）——切换点前后不混用。内核任务/用户任务栈此后经堆分配（heap 已走 `phys_to_virt`，`内核/src/heap.rs:60` 核对过，零改动）。
- **TLB**：G1 单核无 shootdown，但 2b-2 起 switch 必带 `tlbi aside1, asid`（按 ASID 失效）防旧用户映射跨进程泄漏——列入 G1.5 验收项。

**落地记录（2026-10）**：2b-0、2b-1 已完成并过 smoke（8/8 标记 + switches 金丝雀严格递增 + 程序头断言）。与表列计划的偏差/补充：
- 链接脚本用**每段显式 `AT(段起 - KERNEL_VA_BASE)`**（不依赖单点 `AT(0x4000_0000)` 的 LMA 计数器语义），主体 VMA 呈镜像布局 → 零拷贝（见 ADRP/零拷贝两坑）。
- va.rs 交换点实现为**运行时注入**：`set_kernel_va_base`（`rust_main` 首行注入 `KERNEL_VA_BASE`）而非编译期常量——bos-mm 保持架构无关，x86_64 最小集注 0 即恢复恒等行为（ADR #41）。
- smoke 程序头断言已固化：`工具链/size.py --assert-flip`（boot 段 vaddr==paddr、主体 vaddr−paddr==KERNEL_VA_BASE、paddr 全在 RAM、e_entry 低半）。

### 5.2 ASID（随 2b-2）

- 位数运行时探测：`ID_AA64MMFR0_EL1.ASIDBits`（0=8 位 / 2=16 位）；QEMU cortex-a72 实测值进关卡记录。
- 分配：v1 轮转计数器，回卷时全量 `tlbi aside1all`（进程数个位数，成本无关紧要）；v2 再换分代位图。

## 6. 大页 / DMA

- **大页**（2MB/1GB）后期用，降 TLB miss（PC 大内存/高吞吐）。
- **DMA**：连续物理页 VMO（`CONTIGUOUS` 标志）+ 锁页（不可换出）；驱动用户态服务映射后交给设备。

## 7. 与能力的关系

- VMO / Vmar 都是内核对象 → 有 handle、权限（`READ/WRITE/MAP` 等）、可共享传递。
- 用户态拿内存的**唯一正规途径**：`create`/收到 VMO handle → 映射到自己的 Vmar。无"隐式"内存访问。

## 8. SMP / 抢占注意

- 页表修改需 TLB shootdown（跨核失效），用 IPI；全可抢占下页表锁要细。
- per-CPU buddy free-list 减少锁竞争（配细粒度 SMP）。

## 9. 参照

- VMO/Vmar：Zircon（`zx_vmo_*` / `zx_vmar_*`，BSD/MIT）。
- 用户态 pager：seL4 pager 模型（思路）。

## 阶段化目标（v1 基线，对照 `架构决策.md` #20）

- **v1**：PMM buddy + 内核 direct map + 每进程页表；VMO/Vmar 的 `create/map`；**不做 demand paging**（启动时全映射，pager 接口留空）。这是避开"pager × 抢占 × 细锁递归死锁"的关键。（G0–G2；高半翻转→EL0 的五步拆步见 §5.1）
- **v2**：用户态 pager（`supply_pages`）；大页；TLB shootdown。（G3–G4）
- **v3**：换出 / CoW / DMA 连续 VMO / IOMMU。（G4+）
