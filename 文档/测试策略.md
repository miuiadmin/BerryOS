# 测试策略

> 高并发 + 全可抢占 + 细粒度锁内核，**测试比功能本身更难**。本文件是命门。
> 对照 `架构决策.md` #20 分阶段基线：v1 单核跑对，再逐层开。

## 1. 核心原则：关卡式验证（gate）

每一层稳定前**不开**下一层。跳关 = 把并发 bug 叠加，无法定位来源。

```
单核无抢占  →  单核+抢占点  →  双核 SMP  →  多核+全抢占  →  demand paging  →  DVFS/EAS
   G0            G1              G2           G3              G4              G5
```

## 2. 关卡清单

| 关卡 | 通过标准 | 手段 | 状态 |
|------|----------|------|------|
| G0 单核无抢占 | 内核不崩溃；打印/分配/缺页自洽 | QEMU `-smp 1` + 断言 | ✅ 已过（2026-08） |
| G1 单核+抢占点 | 长跑无死锁/竞态 | 压测 + KASAN 类 | ✅ 已过（2026-08） |
| G2 双核 SMP | 负载均衡对、TLB shootdown 对、无竞态 | `-smp 2` + 并发压测 | 待办 |
| G3 多核+全抢占 | 低尾延迟、无优先级反转死锁 | 延迟基准 + lockdep | 待办 |
| G4 demand paging | pager 递归不爆、无死锁 | 缺页压测 | 待办 |
| G5 DVFS/EAS | 频率/放置策略对、省电可量化 | 负载画像 + 功耗计（真机） | 待办 |

**G0/G1 实测出口标准（2026-08 已过）**：
- **G0**：`just run` 串口依次 `GIC ok / FRAME ok / HEAP ok / SYSCALL ok`（MMU 身份映射、buddy/slab 堆、异常向量、GICv2、CNTV tick 往返、SVC syscall）；`brk` → panic dump 可读可恢复（ELR+=4）。`just run-el2`（EL2→EL1 eret）同样通过。
- **G1**：两忙循环任务 `A`/`B` 在 CNTV timer slice 下稳定交替（**纯 IRQ 驱动抢占，无 `yield` 调用**）；`switches=N` 金丝雀持续增长（200s soak 稳定 1000+ 切换、A/B 近平衡、零崩溃）。
- **已知非内核因素（勿被误导）**：QEMU TCG（`virt` / `cortex-a72`）下 `CNTVCT` 实测推进速率 ≈ `CNTFRQ/2`——`SLICE_HZ=10` 配置正确（`freq=62.5MHz`、`slice=6.25M`），但观测到的抢占率是干净的 ~5Hz（200s→恰 1000 切换）。**非内核 bug**；真机或加 `-icount` 应为 10Hz。看 tick 率别被这 2× 误导。

## 3. 检测手段

- **断言优先**：内核全程 `assert`；freestanding 下自实现 `panic` + 栈回溯（寄存器/PC dump）。
- **KASAN 类**（v2 起）：地址消毒——`-fsanitize=kernel-address` 或自实现红区/越界检测。
- **lockdep 类**（v2 起）：记录锁获取顺序，检测潜在死锁。**对细粒度锁至关重要**，是 #7 的配套。
- **竞态注入**：随机化调度点/延迟（类 ThreadSanitizer / shuttle），主动暴露竞态。
- **覆盖率**：gcov 式覆盖统计，保证热路径（IPC/send/recv、缺页、调度）被压到。

## 4. 测试分层

| 层 | 内容 | 跑在哪 |
|----|------|--------|
| 单元 | buddy 分配器、handle 表、权限交集、IPC 序列化 | **host（macOS）**，不依赖 QEMU |
| 内核内 | `ktest` 框架，启动时/syscall 触发跑内核用例 | QEMU |
| 集成 | 内核 + 用户态测试进程，端到端（syscall→IPC→FS） | QEMU |
| 回归 | 每里程碑一组用例 | CI |

## 5. CI / 本地化

- 本地 `just test` = host 单元 + QEMU 集成。
- CI（GitHub Actions，macOS + Linux runner）：编译 + QEMU 跑 + 看断言退出码。
- **合并前必须过当前关卡**；不允许"先合再说"。

## 6. Fuzzing（v2+）

- **syscall fuzzer**：随机合法/非法 syscall 序列，找崩溃/能力越权（呼应纯能力——越权就是漏洞）。
- **IPC fuzzer**：畸形消息/handle/权限组合。

## 7. 性能基准（软实时验收）

软实时的"尽力低延迟"必须**可量化**，否则没法验收：
- IPC 往返延迟 p50/p99。
- 上下文切换开销。
- 缺页处理延迟。
- SMP 扩展性（核数 vs 吞吐曲线）。

阈值随阶段设；G3 关卡用延迟 p99 做门禁。

## 8. AI 调度测试（v3+，见 `AI调度设计.md`）

**AI 不进 G0–G5 正确性关卡**——它是 G5 之后的能效/性能增强，不是正确性前置条件。单独测三件事：

| 测什么 | 通过标准 |
|--------|----------|
| 遥测正确性 | 内核写的 util/唤醒/cache 计数与实际一致（对照基准负载画像） |
| 护栏越界 | AI 下发超界参数（碰 RT 类、超热限、越 Job）→ 内核**拒收**、不崩、保留上次有效值 |
| 崩溃降级 | 杀掉 AI 服务 → 内核**回退启发式**继续调度、无死锁；监督重启后恢复 |

- **RT 屏蔽专项**：AI 服务尽力"干涉" rt/deadline 任务，断言这些任务的调度**零变化**。
- **策略注入 fuzzer（v3+）**：随机策略表项，找护栏漏洞与饥饿路径。

## 9. 形式化验证（决策 #26）

务实派放弃了 seL4 式**全证明**，但不能没有安全网。**证明**与**测试**互补——测试找 bug，证明排除**整类** bug。

| 先做（性价比高） | 模型/工具 |
|------------------|-----------|
| **能力派生 / 权限交集规则** | TLA+ / Alloy：`dup` 必 ⊆ 原、`transfer` 后发送方失权、Job 撤销闭包 |
| **IPC channel 状态机** | TLA+：send/recv 在满/空/关闭各态无死锁、无丢 handle |
| **调度护栏不变量** | 模型检查：AI 越界必被拒、RT 类零干涉、无饥饿 |
| **锁顺序 / 死锁不变量** | TLA+ + loom：细锁获取序无环、临界区不嵌套违例（决策 #7 配套） |

- 目标**不是**证明整个内核，而是把最易错、最难测的**并发协议与安全规则**形式化。
- 与 G0–G5 关系：测试验证"实现跑对"，形式化验证"规约本身对"——两者都过才算稳。
- Rust 并发模型检查可在 host 跑：`loom` / `shuttle`（主动暴露竞态的并发模型检查器），与 §3 的"竞态注入"互补。
- **内存安全交给 Rust 类型 + unsafe 收敛**（决策 #18）：把锁纪律 / 资源占有编码进类型系统（如 `LockGuard` 借用约束、owned vs `&mut` 区分、`#[repr(C)]` 锁定跨边界布局），静态排除一类误用——这是形式化的另一半，与 TLA+ / loom 的「机制不变量」各司其职。
