# 测试策略

> 高并发 + 全可抢占 + 细粒度锁内核，**测试比功能本身更难**。本文件是命门。
> 对照 `架构决策.md` #20 分阶段基线：v1 单核跑对，再逐层开。

## 1. 核心原则：关卡式验证（gate）

每一层稳定前**不开**下一层。跳关 = 把并发 bug 叠加，无法定位来源。

```
单核无抢占  →  单核+抢占点  →  [G1.5 隔离]  →  双核 SMP  →  多核+全抢占  →  demand paging  →  DVFS/EAS
   G0            G1                          G2           G3              G4              G5
                                        （G-eco 生态关与 G4–G5 并行推进，不阻塞主线）
```

## 2. 关卡清单

| 关卡 | 通过标准 | 手段 | 状态 |
|------|----------|------|------|
| G0 单核无抢占 | 内核不崩溃；打印/分配/缺页自洽 | QEMU `-smp 1` + 断言 | ✅ 已过（2026-08） |
| G1 单核+抢占点 | 长跑无死锁/竞态 | 压测 + KASAN 类 | ✅ 已过（2026-08） |
| **G1.5 用户态隔离**（战略裁决新增，P2b 出口） | 用户进程跑飞只死自己：写野指针/`brk` → **仅该进程终止**，内核与其余任务无恙；syscall 层错误（未知号/坏 handle）一律错误码返回、**不杀**（3-1 政策）；PMU/遥测计数不串任务 | QEMU：恶意用户程序矩阵（跑飞/越权/能力滥用） | ✅ 已过（2026-10；PMU 计数项随遥测环 Phase 3 补验） |
| G2 双核 SMP | 负载均衡对、TLB shootdown 对、无竞态 | `-smp 2` + 并发压测 | 待办 |
| G3 多核+全抢占 | 低尾延迟、无优先级反转死锁 | 延迟基准 + lockdep | 待办 |
| G4 demand paging | pager 递归不爆、无死锁 | 缺页压测 | 待办 |
| G5 DVFS/EAS | 频率/放置策略对、省电可量化 | 负载画像 + 功耗计（真机） | 待办 |
| **G-eco 生态**（战略裁决新增，P4 起与 G4–G5 并行） | **未经修改的第三方 Rust 程序**（`ripgrep`/`hexyl` 级别）交叉编译后在 BerryOS 跑通 | 第三方 crate 样例矩阵（CI 常驻，新版本自动加样） | 待办 |

**G0/G1 实测出口标准（2026-08 已过）**：
- **G0**：`just run` 串口依次 `GIC ok / FRAME ok / HEAP ok / SYSCALL ok`（MMU 身份映射、buddy/slab 堆、异常向量、GICv2、CNTV tick 往返、SVC syscall）；`brk` → panic dump 可读可恢复（ELR+=4）。`just run-el2`（EL2→EL1 eret）同样通过。
- **G1**：两忙循环任务 `A`/`B` 在 CNTV timer slice 下稳定交替（**纯 IRQ 驱动抢占，无 `yield` 调用**）；`switches=N` 金丝雀持续增长（200s soak 稳定 1000+ 切换、A/B 近平衡、零崩溃）。
- **已知非内核因素（勿被误导）**：QEMU TCG（`virt` / `cortex-a72`）下 `CNTVCT` 实测推进速率 ≈ `CNTFRQ/2`——`SLICE_HZ=10` 配置正确（`freq=62.5MHz`、`slice=6.25M`），但观测到的抢占率是干净的 ~5Hz（200s→恰 1000 切换）。**非内核 bug**；真机或加 `-icount` 应为 10Hz。看 tick 率别被这 2× 误导。（2b-4 起时间片按**周期数**记账——CNTVCT 增量即 slice 消耗，TCG 的 2× 效应原样继承，行为与 tick 计数版一致：一次 slice 一换。）
- **G1.5（2026-10 已过，P2b 出口；3-1 改板）**：首批 EL0 用户进程三角色矩阵——`user_good`（数据页 canary + `clock_read` 两次单调自检 + putchar 打 'u'，全坏则自陷）与 `user_rogue_ptr`（读未映射 0x4000_0000 → D-abort(lower) EC=0x24）与 `user_abuser`（原 rogue_svc；**3-1 改板**：真号 `handle_close` + 垃圾 handle 0xDEAD_BEEF → -EBADF **存活**，打 'S' 金丝雀——未知号/坏 handle 一律错误码自理，撤 2b-4「畸形号杀」政策，对齐 ABI §8.0「永不 panic」）。rogue_ptr dump + `kill` 后**只死自己**；watchdog 内核任务断言杀数==1 且 putchar/switches 金丝雀仍涨 → 打 `G1.5 ok`（smoke 固化标记）；此后 A/B/u/S 四方照常分时。`just run-el2` 同过。PMU/遥测计数不串任务一项待 Phase 3 遥测环落地后补验。

**并发长跑纪律（G2–G4 的实施方式，战略裁决 §5-⑧ 操作化）**：粗锁清算与放宽抢占是单体内核最长的战役（BKL 15 年、Giant 7 年——进化史 12/13 号），三条纪律全程有效：
1. **语义等价小步**——每步只把粗锁换成「等价语义的更细锁」，主干随时可发布（FreeBSD 5.0 大爆炸发布、主干瘫痪近三年是反面）；
2. **激进配置常驻 soak、逐块转正**——G3（全抢占）起，激进配置（全抢占 + 细锁全开）作为常驻压测配置持续跑 soak，暴露问题后逐块合入默认配置（PREEMPT_RT 二十年上游化模板）；
3. **少发明新同步原语**——RCU 社区消化近十年，小团队撑不起一个需要十年教育的原语；读多写少路径 day-one 按「读侧无原子、无屏障」设计（per-CPU 遥测环即此纪律的产物）。

## 3. 检测手段

- **断言优先**：内核全程 `assert`；freestanding 下自实现 `panic` + 栈回溯（寄存器/PC dump）。
- **KASAN 类**（v2 起）：地址消毒——`-fsanitize=kernel-address` 或自实现红区/越界检测。
- **lockdep 类**（v2 起）：记录锁获取顺序，检测潜在死锁。**对细粒度锁至关重要**，是 #7 的配套。
- **竞态注入**：随机化调度点/延迟（类 ThreadSanitizer / shuttle），主动暴露竞态。
- **覆盖率**：gcov 式覆盖统计，保证热路径（IPC/send/recv、缺页、调度）被压到。

## 4. 测试分层

| 层 | 内容 | 跑在哪 |
|----|------|--------|
| 单元 | buddy 分配器、handle 表、权限交集、IPC 序列化 | **host（macOS）**，不依赖 QEMU |
| 内核内 | `ktest` 框架，启动时/syscall 触发跑内核用例 | QEMU |
| 集成 | 内核 + 用户态测试进程，端到端（syscall→IPC→FS） | QEMU |
| 回归 | 每里程碑一组用例 | CI |

## 5. CI / 本地化

- 本地 `just smoke`（QEMU 无人值守冒烟，`工具链/smoke.sh`：boot 标记断言 + `switches` 金丝雀严格递增）+ `just test-host`（host 单元）。
- CI（GitHub Actions `.github/workflows/ci.yml`，ubuntu runner）：`cargo build --locked` + 同一入口 `工具链/smoke.sh`。
- **主干可发布红线（战略裁决）**：main 上构建 + 冒烟**永远绿**。大爆炸重写全部翻车（Multics/Longhorn/Hurd），活下来的都是「主干随时可发布」（调研 17 号 §4）——CI 是这条红线的机械化执行，不是装饰。
- **合并前必须过当前关卡**；不允许"先合再说"。

## 6. Fuzzing（v2+）

- **syscall fuzzer**：随机合法/非法 syscall 序列，找崩溃/能力越权（呼应纯能力——越权就是漏洞）。
- **IPC fuzzer**：畸形消息/handle/权限组合。

## 7. 性能基准（软实时验收）

软实时的"尽力低延迟"必须**可量化**，否则没法验收：
- IPC 往返延迟 p50/p99。
- 上下文切换开销。
- 缺页处理延迟。
- SMP 扩展性（核数 vs 吞吐曲线）。

**day-one 代理指标（省电线，战略裁决）**：
- **idle residency 占比 + 每秒唤醒数**——tickless 是否真在省电的直接读数；每次内核改动都看一眼，不许等到 G5 才第一次量。
- **交互唤醒 p99**——体感代用指标。

**时序断言纪律**：一切 wall-clock 计时断言一律加 `-icount`（确定性虚拟时钟）跑——QEMU TCG 下 CNTV 实测 ≈ `CNTFRQ/2`（见 §2），非 `-icount` 的时序断言不可靠，只可用于"在增长"类弱断言（金丝雀即此类）。

**band / intent 附加断言（ADR #42，G3–G5 附加项——不改关卡通过条件，随 M4 band 化启用；断言基建先于 band 合入）**：
- **带严格序尾延迟断言**：loadgen 过载合成负载下，验收口径 = **尾延迟（p99 + 1%-low）+ 吞吐双指标**——band 化收益在尾延迟不在吞吐（Meta p99 -28% 是过载竞争场景；EEVDF 纯吞吐可能 1–2% 回退），只测吞吐会漏判。
- **兜底预算可观测性**：每带预算消耗 / 空闲 loan / 兜底服务时刻进遥测——deadline-server 式兜底兑现 = 兜底流量不吃周期末尾剩饭。
- **「有任务可跑但核空闲」金丝雀**：Wasted Cores（EuroSys'16）教训——组调度/分层交互正是 CFS 十年该 bug 的历史温床；金丝雀 M4 前建好，band 合入即生效。
- **有/无 AI `pick_next` p99 相等**：带 band 维度重跑（§8 不变量）。

## 8. AI 调度测试（v3+，见 `AI调度设计.md`）

**AI 不进 G0–G5 正确性关卡**——它是 G5 之后的能效/性能增强，不是正确性前置条件。单独测三件事：

| 测什么 | 通过标准 |
|--------|----------|
| 遥测正确性 | 内核写的 util/唤醒/cache 计数与实际一致（对照基准负载画像） |
| 护栏越界 | AI 下发超界参数（碰 RT 类、超热限、越 Job）→ 内核**拒收**、不崩、保留上次有效值 |
| 崩溃降级 | 杀掉 AI 服务 → 内核**回退启发式**继续调度、无死锁；监督重启后恢复 |

- **RT 屏蔽专项**：AI 服务尽力"干涉" rt/deadline 任务，断言这些任务的调度**零变化**。
- **策略注入 fuzzer（v3+）**：随机策略表项，找护栏漏洞与饥饿路径。
- **遥测 schema 两级分层（战略裁决）**：**第一级（QEMU 可靠）**= util / 唤醒模式 / 切换计数 / 运行时长分布——虚拟环境即可信，**v3 分类器只准用第一级特征**；**第二级（真机门控）**= cache miss / 能耗计数 / 温度——QEMU 数值无意义，只记录不作决策输入。此纪律保证分类器在无真机时即可开发验证，也不会到真机才发现跑不了。

## 9. 形式化验证（决策 #26）

务实派放弃了 seL4 式**全证明**，但不能没有安全网。**证明**与**测试**互补——测试找 bug，证明排除**整类** bug。

| 先做（性价比高） | 模型/工具 |
|------------------|-----------|
| **能力派生 / 权限交集规则** | TLA+ / Alloy：`dup` 必 ⊆ 原、`transfer` 后发送方失权、Job 撤销闭包 |
| **IPC channel 状态机** | TLA+：send/recv 在满/空/关闭各态无死锁、无丢 handle |
| **调度护栏不变量** | 模型检查：AI 越界必被拒、RT 类零干涉、无饥饿 |
| **band / intent 不变量**（ADR #42） | 模型检查：任意带等待时间上界（预算包络兑现）、intent 传播有界性（跳数 + 累计时间双封顶）、值通胀可观测（链上 intent 单调不降事件计数） |
| **锁顺序 / 死锁不变量** | TLA+ + loom：细锁获取序无环、临界区不嵌套违例（决策 #7 配套） |

- 目标**不是**证明整个内核，而是把最易错、最难测的**并发协议与安全规则**形式化。
- 与 G0–G5 关系：测试验证"实现跑对"，形式化验证"规约本身对"——两者都过才算稳。
- Rust 并发模型检查可在 host 跑：`loom` / `shuttle`（主动暴露竞态的并发模型检查器），与 §3 的"竞态注入"互补。
- **内存安全交给 Rust 类型 + unsafe 收敛**（决策 #18）：把锁纪律 / 资源占有编码进类型系统（如 `LockGuard` 借用约束、owned vs `&mut` 区分、`#[repr(C)]` 锁定跨边界布局），静态排除一类误用——这是形式化的另一半，与 TLA+ / loom 的「机制不变量」各司其职。
