# 架构决策记录（ADR）

> BerryOS 的单一事实来源。每条决策含理由 + 替代项。创始日期：2026-08-04；#37–#38 增补：2026-10-15（战略裁决，见 `战略裁决-2026-10-15.md`）；#39–#41 增补：2026-10-15 第二批（三端可行性裁决 D1–D3，见同文件 §8，输入=12号报告）。
> 详细设计见各自文档；本表是索引与依据。

## 决策总表

| # | 决策点 | 选择 | 理由（一句话） | 替代项（未选） |
|---|--------|------|----------------|----------------|
| 1 | 内核哲学 | **Zircon 务实派** | 内核有对象/分配器，SMP/DVFS 工程友好，契合"灵活调度+省电+多核" | seL4 极简（电源/SMP 极难） |
| 2 | 权限模型 | **纯能力** | 所有资源访问经能力，安全/可委托/可审计，无全局 UID | 混合 / 进程级句柄表 |
| 3 | 对象/句柄 | **Zircon 内核态 handle** | 内核拥有对象生命周期，handle 带权限+引用计数，与哲学一致 | seL4 CSpace 槽（太繁） |
| 4 | 内存对象 | **VMO** | 内核对象背靠物理页，可共享/映射/按需填充，配用户态 pager | frame 能力（与务实派冲突） |
| 5 | IPC | **全支持**（同步 channel + 异步通知 + 共享内存） | 覆盖所有场景；快路径+解耦+零拷贝各司其职 | 仅同步 / 仅异步 |
| 6 | 服务发现 | **路径式命名空间**（Plan9/Fuchsia） | 可用性最好，挂载与服务发现统一 | 纯能力传递 / broker |
| 7 | SMP 并发 | **细粒度锁（从第一天）** | 满足多核性能线；风险高，需配套可抢占与纪律 | 大内核锁（后期返工） |
| 8 | 内核抢占 | **全可抢占（目标）** | 最低尾延迟，配细粒度锁；实施分阶段（先抢占点后全抢占） | 不可抢占（延迟差） |
| 9 | 按需调页 | **用户态 pager 服务** | 内核不换页/不读盘，纯微内核；策略可换 | 内核自换页（违背微内核） |
| 10 | 地址空间 | **每进程独立 AS（ASID）** | 标准模型、隔离强、能移植软件 | SASOS（兼容性灾难） |
| 11 | syscall 表面 | **中等偏上（~30–45）** | 对象生命周期+同步+内存/线程+pager/futex/异常；用 `object_*` 泛型合并压数；FS/网络走 IPC。具体编号见 `系统调用ABI设计.md` | seL4 极简 / 宏内核丰富 |
| 12 | 设备驱动 | **用户态为主，启动关键暂留内核** | 契合纯能力；GIC/timer/早期 UART 先留内核，后期外提 | 严格全用户态 / 内核驱动 |
| 13 | 启动 | **QEMU 直加载（`-kernel`），协议后期选** | Mac 上最快到首屏，零 bootloader 折腾 | stivale2/U-Boot（起步多一层） |
| 14 | 软件兼容 | **自有 ABI + POSIX 兼容库** | 能移植 C 程序，不背 Linux 二进制包袱 | 仅原生 / Linux 二进制兼容 |
| 15 | MVP FS | **FAT** | 简单、可互操作、资料多 | 自研日志 FS / 只读 ext |
| 16 | 实时性 | **软实时** | RT/deadline 调度类尽力低延迟，够手表/手机 | 硬实时（需 WCET，极难） |
| 17 | 调度 | **双线并行**（省电+多核性能） | 见 `调度器设计.md` | 单线 |
| 18 | 语言 | **全 Rust（内核 + 用户态）** | 内存安全是 2026 内核刚需；Rust `no_std` 在 aarch64 成熟；主参考 Redox/Theseus/rCore/hubris 全 Rust 且协议宽松。`unsafe` 收敛到页表/上下文切换/MMIO/分配器/硬件原子操作。**syscall 边界仍用 C-ABI 约定**（Rust ABI 不稳定），两端皆 Rust | C 内核（已弃：内存安全代价过大，违背"先进"定位）/ 全 C |
| 19 | 首批架构 | **ARM64**，预留 x86_64/RISC-V（2026-10-15 修订：x86_64 最小集提前启动，见 #41） | 见路线图 P7 跨平台验证 | — |
| 20 | 开发分阶段基线 | **v1 = 单核 + 抢占点 + 无 demand paging + 最小能力/IPC**，逐版推向满配 | 满配复杂度过高（pager × 全抢占 × 细锁的递归死锁），单人项目必须分阶段爬升；详见各设计文档「阶段化目标」节与 `测试策略.md` 关卡 | 一步到位满配（风险不可控） |
| 21 | AI 原生调度 | **内核留第一类接口让用户态 AI 策略服务干涉调度（放置/频率/优先级）**；慢/快循环切分、RT 屏蔽、安全护栏、平台分层；(B)启发式分类先(v3)→(A)学习策略(v4+) | 见 `AI调度设计.md`。AI = 又一种可插拔策略，沿用"机制在内核、策略推用户态" | ML 进内核（违背微内核）/ 无 AI 接口（后期 retrofit 极痛） |
| 22 | 硬件隔离（IOMMU/SMMU） | **头等设计**：用户态驱动的 DMA 经 SMMU 限定在授权 VMO 物理区间内 | 否则驱动可 DMA 攻破任意内存，纯能力形同虚设。是能力安全的硬件后盾 | 软件 DMA 保护（不可靠，绕过页表） |
| 23 | ARM 安全扩展 | **目标 day-one 开 PAC/BTI/MTE**；Phase 0 用 cortex-a72（ARMv8.0，无此三扩展）先关，切 `-cpu max` 时一次性开（仅 target-feature，**源码零改动**） | 防运行期内存安全攻击（ROP/JOP/UAF/越界），对 `unsafe` 内核区尤其值钱 | 仅依赖语言安全（不够：unsafe 区 + 硬件攻击面） |
| 24 | 安全/度量启动 | **度量链 ROM→boot→kernel，每级 hash 记 secure element** | 能力只管运行期；启动期信任由度量链补。信任根派生自度量，非硬编码特权进程 | 信任 bootloader（不安全） |
| 25 | 可观测性 | **内置 tracing day-one**（静态 tracepoint + per-CPU 无锁环 + 用户态 trace 服务） | 现代 OS 命门，retrofit 极痛；与 AI 遥测共享环基座、通道分离 | 仅 printk（诊断力不足） |
| 26 | 形式化验证 | **至少给 IPC 协议 + 能力规则做 TLA+/模型检查** | 务实派放弃了 seL4 式全证明，需补一处形式化作安全网（证明 vs 测试互补） | 纯测试（高并发可抢占内核不够） |
| 27 | 文件系统 | **FAT 仅 MVP；目标现代 FS（CoW + 日志 + 校验，对标 ZFS/bcachefs/APFS）** | FS 是用户态服务可换；现代 FS 是数据完整性/跨平台的刚需 | 停在 FAT（无崩溃一致/校验，数据不安全） |
| 28 | 能力撤销 / 服务监督协议 | **`handle=(obj, gen)` + 代号 + `DEAD` 错误码**（借鉴 hubris generation 协议） | 服务/能力可崩可热换是微内核的命；旧代号调用返 `DEAD`→调用方重试/降级，无缝对接 AI/PM 崩→启发式降级保活；与 seL4 mint/revoke 互补（监督用代号、权限派生用 rights 收窄） | 模糊重启（调用方分不清死掉的旧代与新代）/ 仅靠 rights 回收 |
| 29 | VMO 后备来源 | **采纳 Redox grant 5 类枚举细化 VMO**（CoW / 共享 / MMIO / 跨 AS / 文件映射） | 显式区分后备来源比单一 VMO 精细；PageInfo 引用计数 + CoW→shared 迁移有成熟参考（Redox，MIT） | 单一 VMO（粒度粗，CoW/共享/MMIO 混在一起难实现） |
| 30 | 上下文切换 asm 形态 | **纯叶子 `global_asm!`**（无 prologue，只 `mov sp`）：存 x19–x30+sp 到 `*prev`、载 `*next`、`ret` | 纯叶子 → 存的 SP 恰是 `load_frame` 所需 SP（无自身栈帧介入）；抢占路径切回时经 `exception_irq` 回退到 `load_frame`→`eret` 回被中断 PC。偏移靠编译期 `size_of`/`offset_of` 断言锁定（`架构相关/aarch64/src/task.rs`） | 带函数 prologue 的 switch（栈帧记账复杂、抢占路径 SP 不变量难守） |
| 31 | HAL→scheduler 调用方式 | **HAL 持 `static Option<fn(&mut TrapFrame)>` 派发槽**，boot 时内核 `set_irq_dispatch(sched::on_irq_tick)` 注册 | HAL 是叶子 crate，正向依赖 sched 会成环（HAL→sched→HAL）；函数指针槽反转依赖方向，HAL 永不知 scheduler 之名，编译期解环（`架构相关/aarch64/src/lib.rs`） | HAL 直接依赖 bos-sched（循环依赖）/ 重切 crate 边界 |
| 32 | IRQ 派发时序 | **`exception_irq` = `acknowledge → timer::handle(rearm) → gic::end(EOIR) → dispatch`**（EOIR 在 switch 之前） | 若 switch 跑在 ack 与 EOIR 之间，IRQ 在 GIC 保持 active（优先级未降），电平触发的 CNTV 下次发不出来 → 后续 IRQ 饿死。EOIR-before-dispatch 保 IAR-before-EOIR 不变式且 switch 时 GIC 已静默（Bug 1） | dispatch 在 EOIR 前 / EOIR 在 switch 后（优先级泄漏） |
| 33 | switch 的中断屏蔽不变式 | **承载不变式：`switch` 永不在 `PSTATE.I=0` 时到达**；`yield_now`/`exit_current` 均 `disable_irq`→switch→`enable_irq`；IRQ 路径硬件入口已屏蔽 | 若 timer IRQ 在 switch 存完 prev、未载 next.sp 之间打到中间栈 → 状态损坏。统一屏蔽使 switch 无需自重入保护（Bug 2） | switch 内部自屏蔽/可重入（复杂、难证） |
| 34 | FPU / q 寄存器处理 | **目标 `CPACAR_EL1.FPEN` 陷 FP 到 EL1**（stray FP 用 → `exception_sync` EC=0x07 可见，而非静默串味 q 寄存器）；v1 内核任务 FP-free，首个 FP 用户出现时再加保存 | `TaskContext`+`TrapFrame` 只存整数；不陷则 stray FP 静默串味、跨任务腐坏。陷让它**可见**（Bug 3）。**过渡（2026-10-15 落）**：boot 已显式写 `CPACR_EL1.FPEN=0b11`——消除 reset 值隐式依赖（CI QEMU 8.2 reset=架构值 0，编译器 SIMD memset 即 EC=0x07 fatal；本地 QEMU 11 reset 宽容才一直没炸）。编译器生成 SIMD 属合法内核代码，陷+按需保存（FPEN=00 + q 入 TaskContext）归 Phase 2b 首个 FP 用户出现时 | 默认保存 q 寄存器（v1 无 FP 任务，纯浪费）/ 不陷不存（静默串味，隐患） |
| 35 | idle 任务上下文初始化 | **idle = `rust_main` 的活上下文**（boot 栈 `__stack_top`）：不分配新栈、`ctx` 留零，首切出时由 switch 覆盖为活的 callee-saved + boot 栈 SP（惰性捕获） | boot 时 idle 就是当前活上下文，另配栈纯属浪费且多一次无谓切换；惰性捕获让首切出自然定型（Bug 4） | 给 idle 也 `new_kernel` 配独立栈（多余分配 + bootstrap 复杂） |
| 36 | Phase 2b 内核地址布局 | **翻高半**（canonical TTBR1 内核 / TTBR0 用户），**非**过渡式身份映射共存 | 身份映射只是 Phase 1 bootstrap 临时态；每进程独立 AS（决策 #10）要求 TTBR0 走用户低半、内核驻高半。过渡共存留双重映射的维护债与安全面，一次性翻干净 | 过渡式身份+高半共存（双重映射、债）/ 永身份映射（无法支持每进程独立用户 AS） |
| 37 | 仓库许可证 | **Apache-2.0**；GPL/AGPL 代码零进入，参考实现只借思路 | 无 LICENSE 的公开仓库 = 默认保留所有权利，他人不可合法使用、贡献不可复用，开源地板缺失（调研 17/18 号：法律/组织决定的权重超过多数技术决策）；Apache-2.0 与 Rust 生态惯例一致、含专利授权 | MIT（无显式专利授权）/ GPL（传染，吓退商用与生态） |
| 38 | AI 三不赌（负面 ADR） | **不赌**：① AI 理解任意代码语义（TeachingOS/AI-agent-OS 路线）；② agent 并列成系统支柱；③ v1/v2 期任何 AI 特性挤占调度器/IPC 正确性预算 | 外部调研实证：AIOS 系项目死于「AI 必须理解一切」的强假设；agent 负载尚无稳定形态（等 IPC/调度/内存就绪后作第一等遥测对象，不写死支柱）；内核正确性是 BerryOS 唯一护城河，AI 是其上的增强层（战略裁决 F 组） | 把 AI 做进内核决策通路（ML 方差 vs 软实时）/ 以 AI demo 为里程碑 |
| 39 | v1 主战场 | **手表/穿戴 rich 档（MB 级内存）ARM64 单线走到底**；v2 攻工业 RT；x86 长期 = 兼容验收目标（XNU 同源分端模式：同一内核源、分端用户态） | 驱动面最小；tickless/EPP/capacity 差异化在手表端真实可兑付（Linux NO_HZ 16 年 / PREEMPT_RT 20 年补课债是楔子）；三端同时开工 40 年无小团队先例（含 Google 级 Fuchsia）。战略裁决 D1（12号报告 §0/§7.3） | 三端同时开工 / MCU 档起步（见 #40） |
| 40 | MCU 档（KB 级内存） | **v1 排除**；BerryOS 覆盖面 = MMU 设备（MB 级内存起）。未来确有需求再评估独立静态 profile（BerryOS-M：cargo feature 编译期裁剪 + 全静态分配 + Cortex-M 架构线，按百 KB 级预期管理） | 动态内核（buddy/slab + 动态能力表 + VMO/channel 动态对象）与 KB 级静态世界根本错配，裁剪=第二个内核；Tock 192KB vs Zephyr 8KB、OpenHarmony 另造 LiteOS-M 而非裁剪同内核。战略裁决 D2（12号 §2） | 裁剪同一内核覆盖 KB 档（无先例）/ Kconfig 双形态分叉（RT-Smart 反面） |
| 41 | x86_64 最小移植 | **提前启动 QEMU x86_64 单核最小集**（串口 + 定时器 + 异常向量 + 上下文切换 + SVC 入口），验证 HAL 分层与架构无关性（zCore `hal_fn_def!` 先例）。**范围盒子（防端口税）**：SMP/SIPI、APIC、ACPI、PCIe、任何驱动、第二套真机 HAL 全不在盒内；kill criteria 见重议触发器 | 推翻战略裁决 §3-⑧（ARM64 守到 G3）与 §5-⑦（不写第二架构 HAL）——D3 拍板；与 S6「v1 单核贯穿 MVP」不冲突（最小集本就单核）；HAL 分层越早被第二架构验证越好。战略裁决 D3（12号 §4） | 维持 ARM64 单架构到 G3 后（原裁决）/ 全量 x86 移植（端口税失控） |

## 重议触发器（2026-10-15 战略裁决增补）

> 调研 15/17 号结论：**被推翻最多的恰是创始人最骄傲的机制，且触发器几乎都是可维护性/可验证性而非性能**。对策不是不骄傲，而是给每个骄傲机制预先写好「什么证据出现才允许重开」——触发条件不满足时，重议请求直接关闭，避免无限翻案（Linux 教训）与情绪化改向。

| 机制 | 现状 | 允许重开的最小证据 |
|------|------|--------------------|
| **纯叶子 asm 上下文切换**（#30） | 已过 G1，soak 200s 零崩溃 | EL0 用户进程 + 信号/异常投递路径实现时，发现叶子形态无法表达（如需要 FPU/加密扩展上下文切换的栈帧行为）；届时优先「仍纯叶子 + 分段保存」而非带 prologue |
| **SchedClass 运行时可插拔 trait**（§调度器设计 3.2） | RoundRobin 先行，trait 已冻结 | 同一内核二进制内注册第二策略（EEVDF）时若出现借用/别名无法表达 → 只许改实现不许改 trait 签名；签名变更须配迁移说明 + 全部既有 class 同步改完才可合入 |
| **capacity(0..1023) 抽象**（统一三端） | v1 单核尚未吃到红利 | v2 SMP 时若对称平台上 per-CPU capacity 查表开销在 fastpath 可测（>若干 cycle）→ 改编译期常量化，抽象语义不动 |
| **tickless day-one**（NO_HZ） | G1 已落地（空闲 mask CNTV + wfi） | 仅当 QEMU/真机出现 one-shot 重编无法表达的硬件约束（如 tick device 缺陷）才允许降级补偿式，且必须记录漂移实测数据 |
| **x86_64 最小移植分支**（#41） | 范围盒子内推进（QEMU 单核最小集） | **kill criteria（自动触发，冻结分支回归 ARM64 单线，非重议事项）**：x86 分支连续两个提交周期占用 >20% 主线工时；或 Phase 2b（高半翻转/每进程页表）进度因此停摆 |
| **MCU 档排除**（#40） | v1 零投入 | 重开证据：出现**真实** KB 级设备需求（客户/产品线落地），且接受付第二条静态 profile 产品线成本（BerryOS-M 独立立项评估，非裁剪现内核） |
| **自有 ABI + POSIX 薄库，不跑 Linux 二进制**（#14，反转触发器预写） | v1 基线；G-eco 关未开 | 重开证据：G-eco 第三方样例持续因「非 POSIX / 非 Linux」不可移植、且用户态薄库确无解。**重开也只许用户态兼容服务 / VM 内嵌真内核**（WSL2 判例）——内核 syscall 翻译层一票否决（NT 子系统六连败 + WSL1，进化史 14 号；细则见 `系统调用ABI设计.md` §8.0） |

**通用纪律**：任何重议先过「排除 8 问」（`架构综合纲领.md`）+ 写明触发证据，ADR 表同步更新——决策可改，改的过程不可省。

## 备注：风险最高的三项

> **总对策**：决策 #20（分阶段基线）是下述风险的统一缓解——v1 不碰 demand paging / 全抢占 / EAS，先把单核 + 抢占点 + 最小能力/IPC 跑正确（见 `测试策略.md` 的关卡 G0–G5）。
> **决策 #18（全 Rust）**进一步把 #7/#8 的并发内存安全风险从语言层卸下（编译期 borrow check + `unsafe` 收敛到小核）。
- **决策 7（细粒度锁）+ 8（全可抢占）**：死锁/竞态面大。对策：先抢占点+细锁跑通，逐步放宽；早期重度依赖 QEMU + lldb 与并发测试。
- **决策 6（路径式命名空间）**：要 namespace 服务 + mount 模型，是服务发现里最重的。对策：先用能力传递跑通，namespace 作为其上的可用性层分阶段加。
- **决策 9（用户态 pager）**：缺页路径经 IPC，延迟敏感。对策：pager 用共享环/事件快路径，内核缺页处理零分配。
