# BerryOS 开发路线图

> 宏观开发路线：按依赖顺序分阶段，每阶段以"能在 QEMU 跑通并观察到"的里程碑收尾（呼应"小步提交、QEMU 验证"原则）。
> 调度器内部 M0–M5 见 `调度器设计.md`，贯穿本图的 Phase 2 / 5 / 6。

> **文档导航**：本图回答"什么时候做"；**决策的单一事实来源**是 `架构决策.md`（ADR 索引 + 设计文档索引全在那）；**借鉴任何参考前**先过 `架构综合纲领.md` 的排除 8 问（综合中心 = 可注入的机制/策略分离 + 硬件信任边界）。13 份设计文档的清单与依赖见 `架构决策.md` 末尾索引。

## 依赖关系总览

```
P0 地基与引导
  └─ P1 内存与异常
       └─ P2 调度与任务
            └─ P3 能力与系统调用   ┐ 微内核定义性层
                 └─ P4 IPC 与服务框架 ┘ （P3/P4 紧耦合）
                      ├─ P5 用户态生态（含 PM 服务）
                      └─ P6 持久化与外设（FS/网络/驱动）
                           └─ P7 跨平台验证（x86_64 / RISC-V）
                                └─ P8 硬件落地
```

**能力(P3) 与 IPC(P4) 是微内核的定义性层，彼此紧耦合。** 这两层接口一旦定稳，上层服务就能独立并行推进。

> **P3/P4 实际需合并开发**：init 要靠 bootstrap channel 拿初始能力，而 channel 是 P4 对象（鸡生蛋）。解法——bootstrap channel 是内核特供的**简化通道**（非完整 Channel 对象，仅供启动期递能力），P3 与 P4 同期落地、互相校准接口。

## 端定位（2026-10-15 三端可行性裁决，ADR #39–#41，输入=12号报告）

**同一内核源、分端 sequencing（XNU 模式）**——三端「各自」都有先例，「同时开工」40 年无小团队先例：

- **v1 主战场 = 手表/穿戴 rich 档（MB 级内存）ARM64 单线走到底**（ADR #39）：驱动面最小，tickless/EPP/capacity 差异化在此端真实可兑付。
- **MCU 档（KB 级）v1 排除**（ADR #40）：覆盖面 = MMU 设备（MB 级起）；未来确有需求再评估独立静态 profile（BerryOS-M，百 KB 级预期），不裁剪现内核。
- **v2 攻工业 RT**：cyclictest 级验收对齐 6.12 PREEMPT_RT 同数量级（µs 级软实时有条件可行）；可证明 WCET / DAL A 不进承诺（12号 §3）。无悔项（PI、fastpath 分层、RT 静态池）已落设计文档，随 P4/M5 兑现。
- **x86_64 = 长期兼容验收目标 + QEMU 最小集提前启动**（ADR #41，推翻「ARM64 守到 G3」旧裁决）：范围盒子 = QEMU x86_64 单核最小集（串口+定时器+异常向量+上下文切换+SVC 入口），验证 HAL 分层；SMP/APIC/ACPI/PCIe/驱动不在盒内。kill criteria：连续两提交周期 >20% 主线工时或 Phase 2b 停摆 → 自动冻结回归 ARM64 单线。
- **性能宣称按维度**（12号 §9，不许泛化）：可赢 = IPC 延迟 / 尾延迟 / 故障隔离 / 启动 / 空载零定时器唤醒；明示放弃 = 服务器极限吞吐、GPU、驱动覆盖广度、桌面 GUI 通用性、多架构 day-one。

## 硬关卡：先单核正确，再开 SMP（呼应分阶段基线 #20）

细粒度锁 + 全可抢占的并发 bug，在多核上根本无法定位来源。**每开一层并发前，必须在更低的层先跑正确**：

- 单核 + 无抢占跑通（关卡 G0）→ 才开抢占点（G1）→ 才开 SMP（G2）→ 才开全抢占（G3）→ 才开 demand paging（G4）→ 才开 DVFS/EAS（G5）。
- 任何里程碑默认 `-smp 1` 先过；多核用例是**单独的关卡**，不是顺带做的事。
- 详见 `测试策略.md` 的 G0–G5（每关是一组确定性的正确性测试 + 一个回归基线）。

## 各阶段

### Phase 0 — 地基与引导
- Rust no_std 内核目标（`aarch64-unknown-none`）、linker script、构建系统（`cargo` + `just`）、QEMU virt 启动脚本。
- ARM64 启动：boot 第一步 `global_asm!` 里 `mrs CurrentEL` **检测当前 EL，按需从 EL2 降到 EL1**（QEMU `virt` 默认进 EL2，不是 EL1）→ 早期 Rust → UART（PL011 @0x09000000）输出。
- **已知坑**：别假设 EL1；EL2/EL1 检测与降级（关 MMU/cache、写 `sctlr`、`eret` 到 EL1）是 P0 第一行就要处理的事。
- **里程碑**：`just run` → QEMU 打印 "BerryOS boot"。
- 目录：`工具链/` `引导加载器/` `架构相关/aarch64/` `内核/`
- **现状（2026-08）**：✅ **Phase 0 已完成**。工作区编译通过（stable Rust + `aarch64-unknown-none`）；QEMU 首屏已验证——`just run`→`1BerryOS boot`（默认起始 EL1），`just run-el2`→`21BerryOS boot`（EL2→EL1 eret 降级路径）。PAC/BTI/MTE（决策 #23）Phase 0/1 推迟——cortex-a72 无扩展，v2 切 `-cpu max` 时开（见 `安全与硬件隔离设计.md` §3/§6、`工具链/`）。
- ✅ `CLAUDE.md` / `AGENTS.md` 的"构建与测试"一节已回填真实命令（`just build/run/run-el2/run-release` + 工具链前置）。

### Phase 1 — 内存与异常
- 页表（ARM64 stage1）、内核虚拟映射、内核 VA 布局。
- 物理页帧分配器（buddy）、内核堆（slab 风格）。
- 异常向量表、GIC 驱动、generic timer。
- **安全扩展开关（决策 #23，修订）**：Phase 1 继续 `cortex-a72`（ARMv8.0，无扩展）+ stable Rust + 捆绑 core，**不切** `-cpu max`、**不开** PAC/BTI/MTE——推迟到 **v2**（届时切 `-cpu max` + 上 nightly/build-std + 自定义 target.json，**源码零改动**；BTI 标记异常向量合法落点、MTE 给 slab 堆打标签随 v2 落地）。见 `安全与硬件隔离设计.md` §3/§6。
- **里程碑**：干净处理定时器中断与一次 syscall trap；能分配/回收页。
- 目录：`内存管理/` `架构相关/aarch64/` `内核/`
- 前置设计：内存管理设计（内核 VA 布局 / 页表分层）。
- **现状（2026-08）**：✅ **Phase 1 已完成（过关卡 G0）**。QEMU `virt` 上：开 MMU（身份映射，TTBR0==TTBR1==BOOT_L1，39 位 VA，T0SZ=T1SZ=25）、buddy + slab 分配器（开 `alloc`）、异常向量（VBAR_EL1，current-EL SPx）+ panic dump（file:line:col + 消息，brk 可恢复）、GICv2（GICD/GICC，IRQ27=CNTV PPI 电平触发，IAR-before-EOIR）+ CNTV timer IRQ（干净 tick 往返）、SVC syscall 派发（`object_*` 合并，v1 ~26）。`just run` 串口依次 `GIC ok / FRAME ok / HEAP ok / SYSCALL ok`；`just run-el2`（EL2→EL1 eret）同样通过。PAC/BTI/MTE 仍推迟到 v2（决策 #23，cortex-a72 无扩展）。

### Phase 2a — 内核线程 + 上下文切换 + 调度器（接 `调度器设计.md` M0 + M1a）
- task/thread 结构、每核 runqueue（侵入式 `NonNull<Task>` 裸指针）、上下文切换（**纯叶子 asm**，架构相关/aarch64/）、可插拔 class 框架（`SchedClass` trait **冻结**，RoundRobin 先行）。
- tickless idle（M1a，NO_HZ day-one）：runqueue 空 → mask CNTV + WFI；有活 → arm slice。
- IRQ 驱动抢占（关卡 G1）：CNTV timer slice 到 → `on_irq_tick`（经 fn 指针槽派发，EOIR 之后）→ `tick` 减时间片 + 归 0 则 `pick_next` + `switch`。
- **里程碑**：两个内核任务在定时器上分时（**纯 IRQ 驱动，无 yield**）。
- 目录：`进程调度/` `内核/` `架构相关/aarch64/`
- **现状（2026-08）**：✅ **Phase 2a 已完成（过关卡 G1）**。两忙循环任务 `A`/`B` 在 CNTV timer slice 下交替（无任何 `yield` 调用），`switches=N` 金丝雀持续增长（200s soak 稳定 1000+ 切换、A/B 近平衡、零崩溃）；`just run-el2` 同样通过。机制在内核、策略可插拔；`SchedClass` 冻结合约（§3.2）与实现 `进程调度/src/class.rs` 一字一致。Phase 2a 的 7 项架构裁决见 ADR #30–#36。

### Phase 2b — 地址空间 + 首个 EL0 用户进程
- 内核高半翻转（canonical TTBR1 内核 / TTBR0 用户，**非过渡式身份共存**——裁定见 ADR #36）：脱离当前身份映射。
- 每进程独立页表 + ASID 分配。
- 匿名 VMO / Vmar：create / commit / map / unmap / protect / allocate（决策 #4 / #29）。
- EL1→EL0 下降：建首张 user 页表、装 TTBR0、drop 到 EL0 跑用户代码。
- **出口关卡 G1.5（隔离，战略裁决新增）**：用户进程跑飞/写野指针/`brk` → **仅该进程死**，内核与其余任务无恙；PMU/遥测计数不串任务。隔离是 AI 遥测可信的前提。
- **表示法字段随 2b 落地**（后续 Phase 公共底座，避免返工）：Task 带 duration-hint 与 EPP 字段；时间片改**周期数记账**（LiteOS-M `OsSchedTimeConvertFreq` 式换算——DVFS 后时间片实际时长不随频率漂移）；preemption-threshold 字段进 TCB（ThreadX 语义，v3 AI 护栏词汇）。
- **里程碑**：跑起首个 EL0 用户态进程。
- 目录：`内存管理/` `进程调度/` `架构相关/aarch64/` `内核/`
- 前置设计：`内存管理设计.md` §5（内核 VA 布局 / 高半翻转五步拆步 §5.1 / ASID §5.2）。
- **现状（2026-10）**：✅ **Phase 2b 已完成（2b-0 ~ 2b-4 全落地，出口关卡 G1.5 已过）**——2b-0：TTBR1 指向独立内核表 `KERNEL_L1`（与身份 L1 共享同一对 L2：描述符输出 PA、与走查起点无关），boot 串口新增 `KVA ok`（RAM 魔数 + GIC PIDR2 双别名自校验）。2b-1：内核主体重链高半（镜像布局 VMA=KBASE+LMA → `.data/.bss` 零拷贝；`.text.boot` + 早期栈 + `.bss.boot`（4 张 boot 表）留低半；`phys_to_virt` 翻为加基址，va.rs 运行时注入）——外部行为零变化验收线达成（`just run` / `run-el2` / `smoke` 全绿，smoke 新增程序头断言 `size.py --assert-flip`）。2b-2：**每进程页表 + ASID + 低半退役**——`AsidAllocator`（轮转，ASID 0 保留，回卷→全量失效；实测 QEMU virt/cortex-a72 ASIDBits=16 位）+ 用户三级页表 + 调度器切任务时按需写 TTBR0/CONTEXTIDR/`tlbi aside1is` + 低半身份表退役（TTBR0←空表 + `tlbi vmalle1is`）+ GIC/UART MMIO 全改走高半别名。验收：ktest `ASPACE ok`（两用户表同 VA 互相隔离、切回数据保留、低半读期望故障正向断言），A/B 忙循环任务带上各自 AS 跑（每次打印先读私有页断言隔离——抢占下持续金丝雀）。2b-3：**匿名 VMO/Vmar**——`Vmo`（create/commit/read/write，物理页后备、commit 立即出页清零）+ `Vmar`（root 覆盖 `[0x1000, 2^39)` 留 0 页 NULL 保卫；map 即填用户页表（walk L1→L2→L3 缺表按需建）；unmap/protect 改叶 + 按 ASID 失效；allocate 切子 Vmar 共享表根）；MiniAspace 填表改走正式路径。验收：ktest `VMO ok`（六操作 + 经 VMO 映射读写一页 + unmap 后读 fault / RO 写 fault 期望故障 + 子 Vmar 越界/重叠拒）；smoke 标记 10/10。2b-4：**首个 EL0 + G1.5（收官步，两提交）**——(a) TCB 表示法字段 + 时间片**周期数记账**（slice_left 存 CNTVCT 周期、tick 按增量扣减）；(b) EL1→EL0 下降（`TaskContext::new_user` 弹床 x19=entry/x20=arg/x21=sp0 → trampoline 解蔽 DAIF、装 SP_EL0/ELR/SPSR=EL0t、`eret`）+ lower-EL 向量 0x400/0x480（帧宏 `*_el0` 仅 sp 槽差异=存取 SP_EL0；IRQ 复用 `exception_irq` 含抢占 switch）+ 用户页 AP=0b01 + 三用户进程矩阵（`user_good` 打 'u'/echo 往返/数据 canary；`user_rogue_ptr` 读未映射 0x4000_0000；`user_rogue_svc` 越界 nr）——两个 rogue 各自 dump 后经 HAL `user_fault_exit` 函数指针槽只死自己（v1 政策：EL0 畸形 syscall=杀），watchdog 断言杀数==2 且金丝雀仍涨 → 打 `G1.5 ok`（smoke 第 11 标记）；A/B/'u'/switches 全程不受扰，`run-el2` 同过。**下一步 Phase 3 能力与系统调用**。

### Phase 3 — 能力与系统调用（微内核定义性层，前置设计文档）
- capability 表（Zircon 式 handle 槽位表）、mint / derive / revoke、能力传递。
- 系统调用 ABI（Rust↔Rust，C-ABI 约定），所有 syscall 经能力检查。
- **出口增项（战略裁决）**：遥测环 instrumentation 落地（util/唤醒基础计数写环）；**空策略表等价测试**——注入接口存在但表为空时，调度行为与无接口版本逐位等价（证明「AI 缺席零影响」不是口号）。
- **里程碑**：用户态进程能调用一个能力门控的内核操作。
- 目录：`内核/` `架构相关/aarch64/`（syscall 入口） `用户态/`（libc stub）
- 前置设计：能力模型设计、系统调用 ABI。

### Phase 4 — IPC 与服务框架（微内核定义性层，前置设计文档）
- 同步消息传递（seL4 风格）+ 异步通知（notification）。
- 经能力的共享内存授权（grant）。
- 服务管理器 / init、服务注册与发现。
- **出口增项（战略裁决）**：AI 最小演示——遥测环上跑一个离线策略调 EPP/放置，并**证明快路径开销与策略无关**。**滑移出口**：若届时 IPC/调度未稳，此项顺延为 P5 第一项，不重开 P4、不阻塞主线。
- **G-eco 生态关（战略裁决新增，与 G4–G5 并行推进，不阻塞主线）**：硬验收 = **未经修改的第三方 Rust 程序**（`ripgrep`/`hexyl` 级别）交叉编译后在 BerryOS 上跑通。没有一个内核死于 IPC cycle 数——全部死于没人给它写程序（调研 18 号）。
- **里程碑**：两个用户态服务交换消息；服务管理器拉起一个服务。
- 目录：`进程间通信/` `内核/` `用户态/`
- 前置设计：IPC 设计。

### Phase 5 — 用户态生态
- libc 子集（Rust）、syslib、能力库。
- PM governor 服务（调度器 M3，共享环 + 改频）、framebuffer/console 驱动服务。
- **AI 调度服务**（见 `AI调度设计.md`，决策 #21）：v3 先上启发式工作负载分类 advisor（注入/遥测/护栏打通）；v4+ 演进到设备端学习策略。**RT/deadline 类始终屏蔽**。
- shell + 基础命令。
- **里程碑**：UART 上交互式 shell；PM 服务据负载改频。
- 目录：`用户态/` `驱动/`

### Phase 6 — 持久化与外设
- 块设备驱动服务 + virtio-blk。
- FS 服务（VFS + FAT；现代日志 FS 是 MVP 之后目标，见决策 #27）。
- virtio-net + 最小 TCP/IP 栈服务。
- **里程碑**：挂载磁盘镜像、读写文件；网络 ping 通。
- 目录：`驱动/` `文件系统/` `网络/`

### Phase 7 — 跨平台验证（"跨平台"在此被证明）
- HAL 移植到 x86_64（或 RISC-V）：启动、MMU、中断、syscall、上下文切换。
- 验证 capacity / tickless / IPC 抽象在新架构成立。
- **2026-10-15 修订（ADR #41）**：x86_64 的 **QEMU 单核最小集**（串口+定时器+异常向量+上下文切换+SVC 入口）提前启动、与 ARM64 主线并行（范围盒子 + kill criteria 见「端定位」节）；本 Phase 仍是**全量**验证——MMU/中断模型/驱动模型在新架构完整成立，不在最小集盒内。
- **里程碑**：同一内核在第二个架构的 QEMU 启动。
- 目录：`架构相关/x86_64/`（新增）

### Phase 8 — 硬件落地
- 真实 ARM64 板（树莓派 4/5 或手表 SoC）、真实驱动。
- **SoC 选型（待拍板，12号 §10.9）**：按**驱动面最小**原则选手表端真实 SoC，并配真机功耗计里程碑——QEMU 验证不了 µA 级深睡电流（nRF52832 System OFF 标称 0.3µA vs 板级实测 1.4–5.2µA，差 5–15 倍）。
- 真实硅上的电源管理、休眠 / 唤醒。
- **里程碑**：真实硬件启动、测续航。

## MVP 拆解（"能读写文件"终点）

读写文件是整套架构的端到端集成测试，路径长，拆成沿途有正反馈的子里程碑：

1. **P0 跑通**：QEMU 打印 "BerryOS boot"。
2. **首个 EL0 用户进程**：内核拉起一个用户态进程并跑代码。
3. **能力门控 syscall**：用户进程经 handle 调一个内核操作。
4. **服务间 IPC**：两个用户态服务经 Channel 交换消息。
5. **命名空间 + FS 服务**：`/svc/fs` 挂载，FAT 镜像可读。
6. **读写文件**：用户进程 `open/read/write` 经 POSIX 库 → `/svc/fs` → FAT 镜像。

## 可并行的工作
- P5 / P6 在 P4 之后可多线并行（不同服务独立开发）。
- 调度器省电线（M1a / M3）与性能线（M1b / M4）按 `调度器设计.md` 并行；AI 调度服务（v3+，见 `AI调度设计.md`）是第三条策略线，与 PM 服务同级并行。
- 设计文档可与任意 Phase 并行产出。
- **SMP 是 v2 的锚点（战略裁决）**：v1 全程单核（`-smp 1`）贯穿 MVP，单核代码不为「将来多核」提前缴复杂度税——G 关卡顺序（G1.5→G2）就是这条纪律的制度化。
