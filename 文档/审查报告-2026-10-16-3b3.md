## ✅ 确认高危 4 条（对抗验证零推翻）

### H1. `Vmar::new_root` 帧耗尽 panic——3-3 起已成 EL0 可触发的内核停机点

- **位置**：`内核/src/vmar.rs:109-110`（`zero_frame(fa).expect("Vmar root: 无空闲帧")`）；EL0 调用方 `内核/src/syscall.rs:646`（`sys_process_create`，两维度独立命中同一根）。
- **失败场景**：任意 EL0 进程循环 `vmo_create(≤16MiB)`+`vmo_commit` 抽干 buddy 池（QEMU -m 128M 约 8 轮，该路径干净返 -ENOMEM），随后一次 `process_create` → new_root 取 L1 帧失败 → `expect` panic → `panic=halt` 整机停。无特权、无门控（job==0 恒过——创建权豁口 3-3 自认）。
- **违什么**：vmar.rs:13 模块自述「全 API 返回 Result」、ABI §8.0「永不 panic」、CLAUDE.md 钦定「syscall 边界无 panic」。讽刺点：紧邻的 insert 失败分支（-ENOMEM + 注明泄漏）遵守纪律，唯 new_root 在其之前裸奔；同文件 :312 对 NoFrames 本就有优雅映射先例。
- **修法**：`new_root` 签名改 `Result<Self, VmarError>`；syscall 折 `-ENOMEM`；boot/ktest 调用方（aspace.rs:52 / user.rs:572 / ktest.rs:191/894）`.expect` 带注释保留（可信语境）。**随修复批落地。**

### H2. syscall 链堆分配失败 = 内核 panic（系统性族）+ vmo_create 防线注释算术错

- **位置（根）**：`内核/src/heap.rs:63-75` 大对象路径 `alloc` 失败返 `null_mut` → 全仓无自定义 `alloc_error_handler` → alloc crate 默认 panic。
- **族点全集**（830e7fb）：`Vmo::create` 两笔 `vec!`（vmo.rs:54-55）、`Vmar::new_root`（并入 H1）、`HandleTable::new` 的 `with_capacity`、`insert` 的 `Box::new(ObjRef)`（handle.rs:260）、`alloc_slot` 尾插 `push`（:460）、`vmar` 的 `regions.push` 两处（allocate/map）、`spawn_user` 的 16KiB 栈 `vec!` + `Box::new(Task)`（task.rs:133-137/:148）、**3-4b 新增**：`sys_channel_send` 的 `Message` 双 `Box::from`（syscall.rs:919-921，在全量 take **之后**——失败即 panic 且调用者表已不可复原）、`ChannelEnd.queue` push 增长。
- **注释算术错**：`syscall.rs:147-149` 声称「页记账 ≈10B/页、上限内 Vec ≤40KB 恒可分配」——实际 `Vec<Option<usize>>`(16B) + `Vec<u16>`(2B) = **18B/页**，16MiB VMO ≈ **72KiB**；且「恒可分配」不成立：堆后备就是全局 buddy 池，EL0 可先抽干/碎片化再触发（该上限只封单笔尺寸，封不住共享池耗尽后的同款 abort）。
- **裁决**：全量 try 化（见上）。**随 try 化批落地。**

### H3. handle 表代号耗尽槽永久堵死插入 + 两条泄漏/不回滚

- **位置**：`内核/src/handle.rs:448-477`。
- **堵死**：`alloc_slot` 永远返回最低空槽但不跳 `next_gen > GEN_MASK` 的槽——任一槽 gen 用满（16383 次重用，公开 ABI 路径 `vmo_create→handle_close` 循环即达）后该槽虽空却永远过不了 `take_gen`，此后 insert/duplicate/replace 一律 -ENOMEM，65535 个备用槽形同虚设。
- **insert 泄漏**（:257-266）：先 `Box::into_raw(Box::new(ObjRef))` 后 `alloc_slot()?`/`take_gen(slot)?`——任一失败整块 Box（含 Vmo 记账 Vec，上限内 ≈72KiB）泄漏；堵死后**每次尝试都再泄一块**。
- **duplicate 无回滚**（:271-283）：`refs += 1`（:278）在 alloc 之前，失败后引用计数永不回滚——对象永不释放（比泄漏更硬）。
- **假声明**：handle.rs:465「14 位 ≈ 1.6 万次重用，v1 实际打不满」、syscall.rs「v1 不可达，安全向」×3 处——可达性论证错误，是跳过清理的 load-bearing 借口。
- **3-4a 缓解说明（如实）**：per-process 表把半径从全系统缩为单进程——仍是必修（自废 + 持续泄漏，最终仍可达内核堆耗尽 = H2 的 panic）。
- **修法**：alloc_slot 跳过 gen 耗尽槽；insert 重排「先占槽后装箱」；duplicate 重排「先分配后 +1 refs」。**随修复批落地。**

### H4. process_create 经 new_root 的 expect（同 H1 根，独立验证）

unrev-new 维度独立发现并完整验证（可达链：trap.rs:325 `exception_sync_el0` EC 0x15 → dispatch → NR_PROCESS_CREATE 已注册、无特权门；耗尽可由 EL0 驱动且存活可观测）。与 H1 合并处置，不重复修。
