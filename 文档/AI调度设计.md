# AI 原生调度设计

> BerryOS 的调度器被设计成 **AI 原生**：内核机制留出第一类接口，让用户态 AI 策略服务**干涉**任务放置、频率与优先级。
> 决策依据见 `架构决策.md` #21。本文是 AI 支柱的单一事实来源；机制基座见 `调度器设计.md`。

## 0. 定位与路线

- **不是把 ML 焊进内核**；是把"可插拔策略"升级为 **AI-ready**。AI 就是又一种（更聪明的）策略服务，落在用户态，与 PM governor 同级同模式。
- **两条路线都要、分阶段**（决策已定）：
  - **(B) 语义/启发式工作负载分类**（v3 先落地）：识别 CPU-bound / IO-bound / 交互突发 / 媒体 / 后台同步等类，每类套预设策略。先把**注入 / 遥测 / 护栏**三件套打通。
  - **(A) 设备端学习策略**（v4+）：小 NN / RL 学每任务能耗-性能曲线、预测突发，联合优化放置+改频。
- **内核 hooks 对两种一致**：现在设计接口，两种策略都不吃亏。

## 1. 核心论点与硬边界

- AI = 可插拔策略；**机制在内核（Rust），策略（含 AI）推用户态 Rust 服务**（沿用 `调度器设计.md` 既有决策）。
- **命门：慢/快循环切分**。调度每毫秒甚至更频发生，AI 推理动辄几 ms，**绝不能上热路径**。AI 只做慢循环顾问。

## 2. 三层模型

```
 快循环（内核态 Rust，μs 级）       慢循环（用户态 Rust AI 服务，10–100ms）
   pick_next() 查「策略表」快照        读遥测环 → 推理/分类 → 重算策略表
   O(1)、零分配、绝不调 AI              经注入环下发新参数
         ▲                                │
         │  只读快照（原子换表）          │  写策略表
         └────────────────────────────────┘
   遥测环 ◀── 内核每核写 util / 唤醒模式 / cache miss / 能耗计数 / 尾延迟
```

- 快路径开销恒定：查一张小表，**与"有没有 AI"无关**。AI 不在线时表为空/默认，等价于纯启发式。
- 慢循环周期随平台：PC ~10ms（管家核），手机 ~50ms，手表**不跑**（见 §7）。

## 3. 策略注入 ABI（AI → 内核）

- **传输**：**共享环形缓冲**（同 PM 服务，禁通用 IPC 消息拷贝，否则吃延迟）。内核侧**原子换表快照**，快路径只读。
- **内容**：
  - **per-task**：placement hint（目标核/簇）、EPP（`perf`/`efficiency`）、优先级权重、唤醒预测（预先拉到某核）。
  - **per-cluster**：目标频率 hint、热限频 hint（**由 PM 服务裁决/执行**，见 §10）。
- **权限**：复用既有 `RIGHTS_SET_POLICY`，**不新开特权类**。AI 服务持 **Job 级 `SET_POLICY` handle**，作用域受能力约束（只能调自己 Job 树下的任务）。

## 4. 遥测 ABI（内核 → AI）

- **传输**：共享环，内核每核写出。
- **内容**：per-core util、per-task 唤醒模式 / 运行时长分布、cache miss 率、能耗计数、尾延迟采样。
- **关键纪律**：这条管道 **v1/v2 就埋好** instrumentation（哪怕先不接 AI）。事后 retrofit 极痛，且遥测同时是 profiling / 调试 / 性能基准的副产品收益。

## 5. 安全护栏（内核强制，AI 越界即拒）

"干涉"不是"失控"。**AI 提议，内核在包络内处置**：

| 不变量 | 内核强制的硬线 |
|--------|----------------|
| **RT / deadline 类屏蔽** | `class_rt` / `class_deadline` **AI 一律不得干涉** —— 软实时确定性不容 ML 方差 |
| 防饥饿 | 任意任务在低权重停留不超上限（内核兜底 boost） |
| 热硬限 | 频率不超热包络（PM 服务与 AI 同受） |
| 权限边界 | AI 只持 Job 级 `SET_POLICY` handle，越 Job 即拒 |
| 越界处置 | 参数超界 → 内核**拒收**、记日志、保留上次有效值 |

> RT 路径的确定性是护栏的基石：AI 只在 `class_fair` / 后台类内调权重与放置。

## 6. 容错与冷启动（同 PM 服务模式）

- AI 服务**崩溃 → 内核回退启发式**（EAS + capacity 抽象），调度**绝不依赖 AI 在线**。
- **引导期 / 冷启动**：AI 还没起来，全程跑启发式默认。AI 是增强，不是依赖。
- 监督重启：AI 服务挂在 Job 下，崩了监督者重启、重新订阅遥测、重算策略表。

## 7. 平台分层（呼应省电 + PC 性能）

| 平台 | AI advisor | 理由 |
|------|-----------|------|
| 手表（单核小电池） | **不上** | capacity 抽象在单核已近最优；模型能耗净负 |
| 手机（大小核） | 轻量 advisor | 重点放大小核放置 + DVFS |
| PC（对称多核） | 完整 advisor | 跑**专用管家核**（housekeeping core），~10ms 重算，主线核零干扰 |

## 8. 两条路线（B 先、A 后，hooks 一致）

### 8.1 (B) 语义 / 启发式分类（v3）
- 工作负载分类器：CPU-bound / IO-bound / 交互突发 / 媒体 / 后台同步等类。
- 每类套**预设策略**（放哪个簇、什么 EPP、什么 freq 曲线）。
- 可解释、可调、无训练管线负担 —— 先把注入 / 遥测 / 护栏三件套跑通与验证。

### 8.2 (A) 设备端学习策略（v4+）
- 小 NN / RL 策略：学每任务能耗-性能曲线、预测突发、联合优化放置 + 改频。
- 需遥测落盘 + 离线训练 + 在线推断三件套。
- RT 仍屏蔽；只在 fair / 后台类生效。

## 9. 阶段化目标（对照 `架构决策.md` #20 / #21）

- **v1 / v2**：埋遥测 instrumentation（util / 唤醒 / cache 基础计数写环）；策略注入接口**留桩**（内核查空表 → 等价于无 AI）。（关卡 G0–G3）
- **v3**：(B) 启发式分类 advisor 服务上线；注入 / 遥测 / 护栏打通；**护栏不变量**（RT 屏蔽、越界拒收）随 G4–G5 调度器正确性一起验证（但非关卡通过条件，见末条与 `测试策略.md` §8）。
- **v4+**：(A) 学习策略；管家核；完整离线训练管线。（G5 之后）
- **AI 不进任何正确性关卡**：它是 G5 之后的性能 / 能效增强，不是正确性前置条件。

## 10. 与其它子系统接口

- **调度器**：复用 `SchedClass` trait / capacity / EPP / per-CPU runqueue（见 `调度器设计.md`）。AI 是 `class_fair` 的策略源之一。
- **能力**：AI 服务持 Job 级 `SET_POLICY` handle（见 `能力模型设计.md`）。
- **IPC**：注入 / 遥测走**共享环**，不走 channel（见 `IPC设计.md`「低延迟硬约束」）。
- **syscall**：注册 / 绑定策略通道用少量控制 syscall（`policy_bind` / `telemetry_open`，v3，见 `系统调用ABI设计.md`）。
- **PM 服务**：AI 与 PM 是同级策略源——AI 管"放哪/什么权重"、并**提议**频率/热限 hint，PM **裁决并执行**频率/休眠；两者都经共享环、都可崩、内核都降级保活。

## 11. 代价与风险（诚实）

- **推理延迟 vs 调度频率** → 慢 / 快循环切分是**硬约束**，不是优化项。
- **AI 自身能耗** → 手表净负，平台分层；推理批处理 + 随 tickless 睡。
- **软实时方差** → RT 屏蔽（§5）。
- **训练管线** → 工程量大，v4+ 才碰。
- **范围纪律（最重要）**：AI 是**最后一轨**，hooks 现在就设计、模型后到；**绝不许它把 v1 范围往后拖**；G0–G5 正确性关卡一寸不让。
- **越界 / 失控** → 护栏在内核，AI 提议、内核处置。
